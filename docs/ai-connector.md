# AI接続口（`lifeplan mcp`）の接続のしかた

ファイナンシアの AI接続口は、FPのPCの中だけで動く MCP サーバーです（設計記録 [0015](decisions/0015-ai-connector-mcp.md)）。
AIのアプリ（Claude のアプリ〔Claude Desktop〕・Claude Code・Codex）が `lifeplan mcp` を起動し、**標準入出力だけ**で話します。ネットワークの口は開けません。

> アプリの画面では、世帯の一覧のいちばん下の「AI との接続」（事務所全体の設定。既定はオフ）で使うかどうかを決め、**「AI のアプリに登録する」のボタンで、
> AI のアプリの設定に登録します**（下の「0. ボタンで登録する」。設計記録 0228）。手で書きたいときは「手動で登録する」の「文面をコピー」で、
> 本物の場所の入った文面をクリップボードに写し、下の2〜4のとおり書きます（接続口の場所は画面では伏せます）。

## 0. ボタンで登録する（アプリの画面。0228）

事務所の設定の AI の区画の「AI のアプリに登録する」に、「Claude」と「Codex」の行の状態（登録済み・未登録・場所が古い・このPCに見つかりません）と
ボタンが出ます。**「登録する」を押したときだけ**アプリが書き込みます（アプリの更新のときに勝手には書きません）。

「Claude」の行は、チャットのアプリ（Claude Desktop）と Claude Code の2つの書く先をまとめた行です。**1回押すと両方に登録**し、行には
「チャット（アプリ）: 登録済み／Claude Code: 登録済み」のように2つの状態が並びます。「登録を外す」も1回で両方を外します（0228 の追記 2026-11-20）。

| 行 | 書く先 | 登録のしかた | 気をつけること |
|---|---|---|---|
| Claude | チャット（アプリ） | 設定のファイル（Mac `~/Library/Application Support/Claude/claude_desktop_config.json`、Windows `%APPDATA%\Claude\claude_desktop_config.json`）の `mcpServers` に `fprise-lifeplan` を足す | **Claude のアプリを完全に終了してから**押します。起動中は、このファイルには書きません（下の「Claude のアプリが起動中のとき」）。Linux には Claude のアプリがありません |
| Claude | Claude Code | `claude mcp add --transport stdio --scope user fprise-lifeplan -- <接続口の絶対パス> mcp` を呼ぶ（設定のファイルは直接書かない） | `claude` コマンドが見つからないときは、この側は登録しません（手動で登録する手順に戻ります）。状態は `~/.claude.json` を読んで見ます |
| Codex | Codex | `~/.codex/config.toml`（`CODEX_HOME` があればその下）に `[mcp_servers.fprise-lifeplan]` を足す | パソコン用の Codex（アプリ・ターミナル）です。アプリと CLI は同じファイルを使います。コメントやほかの行はそのまま残ります。ブラウザの ChatGPT は接続できません |

- **Claude のアプリが起動中のとき**: 押すと Claude Code の側だけ登録し、行に「Claude のアプリが起動中のため、Claude Code の側だけ登録しました。」と出ます。Claude のアプリは終了するときに設定のファイルを書き直すので、起動中に書き込んだ登録は消えてしまうためです（0015 の追記）。チャットでも使うときは、Claude のアプリを完全に終了してから、もう一度押します。起動中かどうかは、押したときに確かめ直します（Mac は `Claude` という名前のプロセス、Windows は Claude のアプリの場所にある `claude.exe` があるか。確かめられないときは、起動していないものとして進めます）。
- **片方しか無いとき**: `claude` コマンドが無ければチャット（アプリ）の側だけ、Claude のアプリが無ければ Claude Code の側だけ登録し、そのことを行に出します。どちらも無ければ「このPCに見つかりません」と出て、ボタンは出ません。
- **Gemini**: 今は一覧に出していません。Gemini のアプリがパソコンの中の接続の道具（標準入出力で話す MCP サーバー）に対応したら足します。
- 書く前の設定のファイルは、アプリのデータの場所の `ai-app-backups/`（Mac `~/Library/Application Support/com.fprise.lifeplan/ai-app-backups/`）に、AI のアプリの名前と日時をつけて控えます。元に戻したいときは、その控えを元の場所に写します（アプリには「元に戻す」のボタンはありません。0228 の4）。
- ほかのサーバーの設定・ほかの欄は変えません（JSON は元の文をそのまま写し、`fprise-lifeplan` の所だけを足す・直す・外します）。すでに登録があれば、場所（`command`）と引数だけを直し、自分で足した欄（`env` など）は残します。
- 設定のファイルを読めないとき（コメントの入った JSON・`mcpServers` が表でない など）は書きません。「手動で登録する」の文面で手で足してください。
- **場所が古い**: アプリを別の場所に入れ直した・動かしたときは、登録した場所と今の場所が違うので「場所が古い」と出ます。「場所を直す」で今の場所に書き直します。
- Mac で dmg から直接開いた・ダウンロードのフォルダのまま開いたアプリ（一時的な場所で動いている）は登録できません。「アプリケーション」フォルダに入れてから開き直します。
- 「登録を外す」で、`fprise-lifeplan` の所だけを外します。
- 開発用のビルドは、製品の登録を上書きしないよう `fprise-lifeplan-dev` という名前で登録します（作業フォルダの指定 `LIFEPLAN_RUNTIME_DIR` も入ります）。

## 1. 作る

配布用のアプリ（インストーラーで入れたもの）では、接続口はアプリと同じフォルダに入っているので、作る必要はありません
（Mac は `Financia.app/Contents/MacOS/lifeplan`、Windows はインストール先の `lifeplan.exe`、Linux の deb は `/usr/bin/lifeplan`。アプリと同じ版で、アプリと同じ名前で署名しています。0015 の追記 2026-11-19）。
開発用に手元で作るときは次のとおりです。

```sh
cd engine && npm ci && npm run build && cd ..   # 計算エンジンと制度データ・対応範囲の一覧（engine/dist）
cd app && npm ci && npm run build:explain && cd ..   # 数字の根拠の読み方・プランの動かす項目・見本の名前と目印・差し替えられる文と欄の一覧・表示の設定の一覧（crates/lifeplan/dist/explain.js・plan.js・samples.json・texts-catalog.json・terms-catalog.json・fields-catalog.json・display-catalog.json。0183・0195・0199・0212・0213）
cargo build --release -p lifeplan               # → target/release/lifeplan（Windows は lifeplan.exe）
target/release/lifeplan --version
```

以下の `<接続口の絶対パス>` は、`target/release/lifeplan` の絶対パス（例: `/Users/you/Projects/fprise-lifeplan/target/release/lifeplan`）に置き換えます。
設定の名前は **`fprise-lifeplan`**、引数は **`mcp`** の1つだけです（0015 の10）。

## 2. 手で書く: Claude Code

```sh
claude mcp add --transport stdio --scope user fprise-lifeplan -- <接続口の絶対パス> mcp
claude mcp list        # fprise-lifeplan が Connected になる
```

外すときは `claude mcp remove --scope user fprise-lifeplan`。

## 3. 手で書く: Claude Desktop

**Claude Desktop を完全に終了してから**（メニューの「終了」。ウィンドウを閉じるだけでは足りません）、設定ファイルを編集します。
Claude Desktop は終了するときに設定ファイルを書き直すので、起動中に書き足すと消えます（0015 の追記）。

- Mac: `~/Library/Application Support/Claude/claude_desktop_config.json`
- Windows: `%APPDATA%\Claude\claude_desktop_config.json`

`mcpServers` に `fprise-lifeplan` だけを足します（ほかのサーバーの設定は消さない）。

```json
{
  "mcpServers": {
    "fprise-lifeplan": {
      "command": "<接続口の絶対パス>",
      "args": ["mcp"]
    }
  }
}
```

保存してから Claude Desktop を起動し、道具の一覧に `fprise-lifeplan` が出ることを確かめます。
使い方の例（下の「使い方の例（プロンプト）」）は、Claude Desktop の接続口のプロンプトとして選べます。
ワンクリックで入る拡張（MCPB）は、今は用意していません（0228 の2）。

## 4. 手で書く: Codex

Codex は `~/.codex/config.toml`（`CODEX_HOME` があればその下）に足します。

```toml
[mcp_servers.fprise-lifeplan]
command = "<接続口の絶対パス>"
args = ["mcp"]
```

### 引数の名前（知らない名前は断る。0015 の追記）

- 引数の名前は下線で区切ります（`plan_changes`・`from_year`・`at_ages`）。答えの `planChanges`・`keyFigures` のような書き方とは違います。
- どの道具も、入力の形（JSON Schema。どれも `additionalProperties: false`）に無い名前の引数を受けません。黙って捨てて基本の数字を返すことはせず、その呼び出しは何もしないで、知らない名前・近い名前・使える名前を返します（例「planChanges（plan_changes のことですか）」）。振る項目 `vary`・境目探しの条件 `condition`・プランの変更の1件（`plan_changes` の中）の名前も同じです（例「vary.itme（vary.item のことですか）」「plan_changes[0].vlaue（plan_changes[0].value のことですか）」）。プランの変更の1件の `note`（`propose_scenario` の `changes` から写したときの理由）は受けて、計算には使いません。
- 比較の通り（`compare`・`chart`・`table` の `variants` の1件）の中の知らない名前は、今までどおりその通りだけ計算せずに同じ書き方の理由を返し、ほかの通りは計算します。
- `compare` などで基本の世帯を `base: {...}` に包んで書くと断ります（基本の世帯と基本に当てる変更は、引数の一番上に書きます）。

### 頼み方の例

AI に次のように頼みます（道具の名前は書かなくても、AI が選びます）。

- 「この接続口で何ができる？例を見せて」
- 「fprise-lifeplan の見本の世帯で、子育て中の世帯を見せて」（`list_sample_households` の `tags`）
- 「salariedCoupleTwoKids で、物価上昇率を 1% にしたら老後の金融資産はどう変わる？」
- 「salariedCoupleTwoKids で、働く最後の年齢を 60〜65歳で振ったら、金融資産がいちばん少ない年はどう変わる？」（`list_plan_items` → `calculate` の `plan_changes`）
- 「sampleSingle20s と sampleCoupleNoKids の、65歳・90歳の時点の資産を比較して」（`compare`）
- 「salariedCoupleTwoKids で、働く最後の年齢を63歳にする・生活費を月25万円にする・NISA を月3万円にする、の3つを並べて」「sampleCoupleNoKids と salariedCoupleTwoKids と sampleSingle20s を比較して」（`compare`）
- 「salariedCoupleTwoKids で、働く最後の年齢を60〜70歳で1歳ずつ変えたら、95歳の時点の資産と資産が尽きる年はどうなる？」（`sweep`）
- 「salariedCoupleTwoKids で、生活費は月いくらまでなら最後まで足りる？」「何歳まで働けば足りる？」（`find_threshold`）
- 「salariedCoupleTwoKids で、変動金利の上がり方を3通り（今のまま・10年で+1%・10年で+2%）にして比較し、グラフにして」（`list_plan_items` の「金利の見込み（変動金利）」→ `chart`）
- 「同じ3通りで、住宅ローンの利息の合計と、10年後の金利を並べて」（`compare` の `keyFigures.loanInterest`・`diff.loanInterest` と `series` の `loanRate`。0205）
- 「salariedCoupleTwoKids で、退職を60・65・70歳の3パターンにして、金融資産と年間収支をグラフにして」（`chart` の `series` に `financialAssets`・`net`。0207）
- 「子の進路を今のまま・すべて公立・中学から私立の3パターンにして、教育費の推移と支出の内訳をグラフにして」（`list_plan_items` の子ごとの「進路の型」→ `chart` の `series` に `expenseEducation`、`charts` に `expenseBreakdown`。注に「第1子の進路の型 中学から私立」のように進路の違いが出る。0207・0211）

ほかのライフプランソフトとの違いを聞いたとき、AI はファイナンシアの側を対応範囲の一覧と道具の答えで確かめた事実だけで答え、ほかのソフトのことは推測で断定しません（接続口の説明 INSTRUCTIONS に書いてあります。0199）。

**お客さまの世帯の数字をブログ・セミナー・SNS に使うとき**（0199）: 接続口は止めませんが、AI が次の3つを一言添えます。FP も公開の前に確かめてください。

1. 年齢・年収・資産の数字を丸める（例: 年齢は「30代」、年収は50万円単位）
2. 家族構成と珍しい条件（職業・地域・珍しい制度）の組み合わせで人が分かりそうなら、変える
3. お客さまに一言ことわる

見本の世帯・架空の世帯の数字には要りません。

### 顧客のフォロー（まとめて渡した世帯の要約。0248）

FP が世帯の一覧で区分（A 顧問契約など）や番号で絞り込み、「選んだ世帯をまとめてAIに渡す」で渡した世帯（1件ずつ渡した世帯も同じ）を、1回で見渡すための道具です。使い方の例（プロンプト）`follow_up_clients` が、この頼み方の型です。

- `summarize_shared_households`: 渡されている世帯の1世帯1行の要約を返します（読むだけ）。`share_ids`（50件まで）を書くとその世帯だけ、省くといま渡されている世帯すべて（仮名の順に50件まで。超えると `truncated` に件数が出ます）。
- 1行の項目: `shareId`・`alias`（仮名）・`basis`（渡された理由）・`category`（区分の記号 `code` と事務所の区分の名前 `name`。区分なしは `null`）・`lastMeetingOn`（前回の面談の日。面談の履歴〔0182〕の日付だけ）・`meetings`（面談の記録の数）・`lastSnapshotMonth`（最後の控えの年月）・`nextReviewMonth`（その1年後。画面の面談の準備の「次の面談の目安」と同じ考え方）・`reviewDue`（今月が目安の月を過ぎたか。控えが無ければ `null`）・`recheckMarks`（「次回確かめる」の印の数）・`depletion`（資産が尽きる年と本人の年齢。尽きなければ `null`）・`minimum`（金融資産がいちばん少ない年と額）・`notices`（計算のお知らせの件数）・`ok`。主な数字は `calculate` の `keyFigures` と同じ数え方（画面と同じ計算の前の処理を適用し、年金の見込みは計算しない）です。
- 読めない世帯（期限切れ・取り消し後・渡していない共有 ID）は、その行だけ `ok: false` と `error`（`EXPIRED`・`REVOKED`・`NOT_SHARED` など）、計算できない世帯は `ok: false` と `calcError` を返し、ほかの行はそのまま返します。
- FP がメモと面談の履歴も渡した共有（0249）だけ、行に `notesExcerpt`（前回の面談の決めたこと60字・次までにやること80字までの抜き出し。名前を伏せて `client_text` に包む）が入り、記録の項目に `meeting.excerpt` が足されます。
- 返さないもの（印の無い共有）: 面談の履歴の文（話したこと・決めたこと・FP のメモ）・メモ・「次回確かめる」の印の見出し・顧客番号・内部ID・お名前（ファイナンシアはお名前・メールアドレスを持ちません。0012）。連絡の文の下書きは宛名を空けて作り、宛先は FP がアプリで出る「顧客番号 → 仮名」の対応（まとめて渡した後の画面・共有中の帯）と自分の台帳で入れます。AI からメールは送りません。
- 読むたびに、世帯ごとの「AIに渡した記録」に道具の名前 `summarize_shared_households` で残ります（項目は縮約版の項目に `followup.category`・`followup.lastMeetingOn`・`followup.meetings`・`followup.lastSnapshotMonth`・`followup.recheckMarks` を足したもの。指紋にも要約の材料が入ります）。

### 不具合を調べて報告をまとめる（0234）

FP が「この世帯の計算がおかしい」「計算できない」と言ったときの進め方です。使い方の例（プロンプト）`report_issue` が、この頼み方の型です。

- `get_error_log`: アプリのエラーの記録（この PC のアプリのデータの中だけにある。画面の想定外のエラー・本体の命令の失敗・計算できなかったとき・本体の想定外の停止）を新しい順に読みます（`limit` は 1〜100、既定30）。残っているのは日時・回数・版・OS・画面（タブの名前）・操作・種類・削った文だけで、お客さまの名前・金額・生年月日・メモ・ファイルの場所・世帯を識別する値は入っていません（文の中の日本語・数字・引用符の中・場所はアプリが … # <場所> に伏せます）。アプリが起動していて AI接続がオンのときだけ読め、読めないときは FP に「要望・不具合を送る」の「エラーの記録」を写して貼ってもらいます。世帯の中身ではないので「AIに渡した記録」には残らず、アプリのエラーの記録に読まれた回数が残ります。消す・送る道具はありません。
- 調べ方: `check_inputs`（入力の確かめ）・`calculate`（おかしい行と年の数字）・`explain_value`（数字の根拠）で、「入力が原因（ここを直せば戻る）」か「計算の仕組みの不具合の疑い」かを見立てます。推測で決めつけず、根拠の道具の答えを示します。入力が原因なら、`calculate` の `changes` で直したときに戻ることを確かめます。
- 再現は、見本の世帯（`get_sample_household`）の `input` に変更を足して `calculate` で確かめます。お客さまの値は使いません。見本で再現できず実際の値が要るときは、そう書いて FP の判断に任せます。
- `draft_issue_report`: `summary`*・`diagnosis`*（`input`・`calculation`・`unknown`）・`evidence`*（1〜20件）と、`screen`・`row`・`when`・`expected`・`actual`・`fix`・`sample_household_id`・`reproduce_changes`・`reproduce_steps`・`reproduced`・`error_log_lines` から、決まった見出しの報告の文（`text`）を返します。FP の送り方は文に入れず `howToSend` で返します（文はフォームの内容の欄に貼る物なので。0259）。共有の ID の形の値は伏せ、年・月・日のそろった日付には注意（`cautions`）を添えます。文を返すだけで、送らない・フォームを開かない・URL に載せません（フォームの URL に入るのは今までどおり受付番号・版・OS だけ。0087 の6）。
- `propose_issue_report`（0259）: FP が話した要望・不具合・質問を、アプリの「送る報告の確認画面」に承認待ちで出します。`items`*（1〜20件）の1件ごとに `kind`*（`bug`＝不具合・`request`＝要望・`question`＝質問）・`screen`（どの画面か: 入力・結果・資産と負債・万一のとき・提案書・事務所の設定・保存・AI 接続・URL で答えるヒアリング・その他・分からない）・`text`*（内容。不具合を調べた件は `draft_issue_report` の `text` をそのまま）。**話された内容を1件ずつに分けてまとめ、まとめて1回で渡します**（同じことは1件にまとめる）。空の報告・空の件・知らない種類は断ります（1件12,000文字・合わせて40,000文字まで。送っていない報告は3回分まで。同じ並びは1回分にまとめる）。アプリが起動していて AI接続がオンのときだけ使えます（世帯を渡していなくてよい。出せないときは、FP に「要望・不具合を送る」の「報告の文を書いて送る」に貼ってもらう案内を返します）。この道具は何も送らず、フォームも開きません。FP が画面で件ごとに確かめて直し・外し、「送る」を押したときだけ、アプリが全件を1つの文（頭に受付番号・アプリの版・OS・件数、件ごとに番号・種類・どの画面か）にまとめてクリップボードに写し、既定のブラウザでフォームを1回だけ開きます（隠れた欄は受付番号・版・OS と AI 経由の印 `via=ai`。文は URL に入れません）。FP がフォームの内容の欄に貼り付けて送ります。アプリは件ごとに名前・金額・電話番号・メールアドレス・住所・生年月日らしい所に印を付けて知らせます（消すかどうかは FP が決める）。世帯の中身ではないので「AIに渡した記録」には残りません。

### 画面の操作の手引き（0227）

FP が「〇〇するにはどこを押す？」のように画面の操作を聞いたとき、AI が推測で手順を作らないよう、画面の操作の手引きを同梱しています。

- 正本は `docs/app-guide/NN-<画面>.md`（画面ごと・やりたいことごとの短い節。書き方は `docs/app-guide/README.md`）。接続口のビルド（`crates/lifeplan/build.rs`）がそのまま埋め込みます。世帯の情報は含まないので、アプリが起動していなくても・AI接続がオフでも使えます。
- `search_app_guide`（`query`・`limit`）は、問いに近い節の id・題・画面・要点を返します（探し方は対応範囲の一覧と同じ2文字の並びの重なり）。当たらなければ、推測で手順を作らないための案内 `notInGuide` を返します。`get_app_guide`（`id`）は節の本文と関係する節を、`id` を省くと画面ごとの目次を返します。答えの `appVersion` は手引きを同梱した接続口の版（アプリと同じ版）です。
- 本文の「」の中は、画面のボタン・見出し・タブの名前そのままです。`app/test/app-guide.test.ts` が、「」の中が今の画面の文（`app/src` の文・差し替えられる文の一覧・提案書の文など）にあることを確かめるので、画面の言葉を変えて手引きを直し忘れると CI で落ちます。
- 書くのは今の画面にある物だけです。説明（INSTRUCTIONS）で、手引きに無い操作は「手引きに見当たらない」と答えるよう伝えています。

- 家を買う・子が生まれるなどの場面は、近い見本に `get_input_recipe` の手本を重ねて作ります（見本の一覧に場面ごとの見本は持ちません）。

### 計算の入力を組み立てる（0196）

- `get_input_guide` を `section` なしで呼ぶと、形の決まり（ID は UUID 第4版・金額は値の箱・率は文字・時点の形）、区分の一覧、計算できる最小の入力の例（`skeleton`）、新しい UUID が返ります。`section` に区分の鍵（`residences` など）か入力の中の場所（`/household/residences/purchase` など）を渡すと、その物の欄・条件・例を返します。どれもエンジンと同じスキーマから作ります。
- `get_input_recipe` は、場面の手本を、その世帯の ID と配列の位置に合わせた `changes` で返します（関係する欄も一緒に。家なら頭金・諸費用・入居・住宅ローン・住宅ローン控除の住宅の情報、子なら親子の関係・教育の目標・子の生活費）。`params` で時期や額を変えられます。手本を重ねるときは `apply: true` で返る `input` を次の手本に渡します。
- 手元の預金を何回かに分けて投資に移す形（例: 5,000万円を今1,000万円・2年後2,000万円・7年後2,000万円）は、口座の `fromDeposit` に1回ずつ `{"at": 時点, "amount": 円}` を書きます（0258。`get_input_guide` の `accounts` にも出ます）。その月に預金（収支が入る口座）から移し、年間収支には入れません。書ける口座は課税口座・NISA・財形・持株会・外貨預金・暗号資産です（iDeCo・企業型DC・預金には書きません。書いても計算に使いません）。NISA は成長投資枠に入れ、年の枠（成長投資枠 年240万円）・生涯の枠（1,800万円、うち成長投資枠1,200万円）を超えた分は預金に残る（課税口座へは回らない）ので、超えるときは年を分けて書きます。計算基準月より前・表の最後の年より後の行は計算に使いません。答えでは、移した額が移動の行（`cf.transfer.investment`・`cf.transfer.nisa.growth` など。計算式 `plan.cashflow.fromDeposit`）に出ます。プランの差分（`plan_changes`）でも、入力項目ID `account.fromDeposit` で行を足す・額や時期を変えることができます。
- `calculate`・`explain_value` が入力の形の誤りで止まったときは、エラーの文に「直し方」（足りない欄・知らない欄・選べる値・正しい形）が付きます。同じスキーマで確かめ直した手がかりで、判定はエンジンが正です。入力の値はエラーの文に写しません。

### 新しい世帯の候補をアプリに入れる（0208）

「架空の世帯を作って、アプリに入れて」のように、AI が組み立てた世帯をアプリの世帯にするときは、`propose_household` で「新しい世帯の候補」を出します。AI は世帯を直接作れません。

1. AI が `get_input_guide`・`get_input_recipe` で入力を組み立て、`calculate` で確かめます。
2. `propose_household` に `kind`（`fictional`＝架空・`client`＝お客さま）・`title`（60文字まで）・`note`（推定したこと。1000文字まで）・`input` を渡します。接続口は `calculate` と同じ道で確かめ、計算できなければアプリに出さずに「直し方」を返します。通れば、答えに主な数字（`keyFigures`。年金の見込みは省く）が付きます。
3. アプリ本体は、知っている欄だけを読み、入力を画面と同じ計算エンジンでもう一度確かめて（スキーマに無い欄・範囲の外の値は断る）、メモリの中に承認待ちで置きます（5件まで）。世帯の一覧は変わりません。アプリを閉じる・AI接続口をオフにすると消えます。
4. 画面の上に「AIから新しい世帯の候補が届いています」の帯が出ます。AIからの新しい世帯の候補の確認画面に、家族・収入・資産・住まい・ローン・生活費と、AI が推定したこと（「推定」の値には印）が出ます。題・推定したこと・入力の名前とメモの欄・推定の根拠（`estimate.basis`。120文字まで）の番号らしい所は、書類の候補と同じ決まりで消します（消した数を出します）。FP は「架空」か「お客さま」かを選び直せます。
5. 「世帯として作る」を押したときだけ、世帯ができます。値の出どころは AI（候補の ID）、承認は FP として残り、AI が推定したことは FP のメモの1行に入ります。AI が値の出どころを「手で直した」（`override`）・「自動」（`auto`）と書いても、作った世帯では全部 AI の値になります。AI が書いた確かさ（`certainty`）と推定の元（`estimate.source`）は持ち込みません（推定の印と根拠は残ります）。世帯ファイルの meta に出どころの記録（`origin`）が残ります。

**「架空」の世帯**: 架空として作った世帯には、世帯の一覧・上の帯・開いている世帯に「架空」の印が付きます。お客さまの情報を含まないので、同意の記録が無くても AI に渡せます（期限・取り消し・AIに渡した記録・縮約版は同じ）。世帯の一覧の「お客さまの世帯にする」で、お客さまの世帯にできます（同意を記録するまで渡せなくなり、共有中ならその場で止まります）。お客さまの世帯を架空にする操作はありません。お客さまとして作った世帯は、今までどおり同意を記録するまで渡せません。

### 計算の答えの主な数字・年齢・大きさ（0194）

`calculate` の答えには、年ごとの数字のほかに次が付きます。

- `keyFigures`（主な数字）: アプリの「プランを比較」と同じ関数で数えた、`at_ages`（既定は95歳）の時点の金融資産・資産が尽きる年・金融資産がいちばん少ない年と額・生涯の手取りの合計・生涯の支出の合計・住宅ローンの返済の合計と、65歳からの年金の月額 `pension`（世帯の合計 `monthly`・受け取り開始からの月額 `claimedMonthly`・人ごと `people`。今の水準＝賃金・物価の伸びとマクロ経済スライドを外した額で、アプリの比較の表の年金の行と同じ。0200）。
- 年ごとの数字・表の行・合計 `totals` は、アプリの画面の表に出す年からです（計算基準月が年の途中なら、数か月分しかない計算の最初の年は入れません。主な数字・数字の根拠と同じ。`totals.income − totals.taxSi` が生涯の手取りと同じになります。0200）。
- `members` と年ごとの `ages`: 家族の年齢（アプリのキャッシュフロー表の年齢の行と同じ呼び方・同じ「世帯にいる年」）。
- `protection`・`inheritanceTax`: 入力に必要保障額（`/protection`）・相続税の目安（`/inheritanceTax`。`points` に `now`・`bothAfter`・`contingency` を入れる）があれば、その答え（人に `self`・`spouse` などの鍵を添える）。

答えは次で小さくできます（何も選ばなければ今までどおり）。比較する・振るときは主な数字だけを取ると、1通り 0.7KB ほどです（年金の見込みは写しをもう1〜2回計算するので、要らなければ `omit` に `pension` を入れると速くなります）。

| 選ぶ物 | 意味 |
|---|---|
| `every_years` | 何年おきの年だけ（1〜10。最初と最後の年はいつも入る） |
| `fields` | summary の年ごとの数字を選ぶ（`income`・`taxSi`・`expense`・`net`・`financialAssets`・`debt`・`shortfall`） |
| `omit` | 省く物（`notices`・`noticeText`〔計算のお知らせの文と内訳だけ。0210〕・`packs`・`totals`・`insurance`・`ages`・`years`・`keyFigures`・`protection`・`protectionDetail`・`inheritanceTax`・`pension`） |
| `at_ages` | 主な数字の「○歳時点」の本人の年齢（5つまで）。表の範囲の外の年齢（今より若い・表の最後の年より先）は、端の年の残高で代えず、`{"age": 110, "year": null, "amount": null, "reason": "表の範囲（ご本人46〜100歳・2027〜2081年）の外の年齢のため、数えていません"}` のように返す。選ばないときの既定の95歳は、画面と同じく今までどおり（表が95歳より前に終わる世帯では最後の年） |
| `from_year`・`to_year` | 年ごとの数字・表の行の年の範囲（含む）。`from_year` が `to_year` より後なら、空の年ごとの数字を返さずに断る。範囲に表の年が1つも無ければ、表の年を添えて断る（重なる年があれば、その年だけ） |

`explain_value` も `omit`（`sources`＝出典の文・`params`＝使った制度の値・`message`＝読み方の案内）で小さくできます。出典は制度の値ID から `get_regulation_value` で引けます。

頼み方の例: 「salariedCoupleTwoKids と dualNoKids の、資産が尽きる年と65歳・90歳の時点の資産を比較して」「salariedCoupleTwoKids の金融資産の推移を5年ごとに、家族の年齢つきの表にして」

### 計算のお知らせ（画面と同じ文。0210）

`calculate` の答えの `notices` は、アプリの結果のタブの「計算のお知らせ」と同じ関数（`app/src/workspace/engineNotices.ts` の `noticeRows`）で作った、画面と同じ文の行です（エンジンは知らせをコードと ID だけで出し、画面がそれを文にします。接続口も同じ関数を同梱して動かすので、文の表は画面の1つだけです）。

- 1行は `kind`（画面の種類の言葉: 入力が足りない・計算に入れていない・前提の外・仮の値・推定・データの確認待ち）・`text`（画面の文）・`subjects`（対象の人・物の呼び名）・`years`（年の範囲）・`parts`（内訳。制度の値の名前と年など）・`item`（入力で直すときの入力項目。画面の「入力で開く」の先）です。同じ知らせは1行にまとめ、並びは画面と同じ種類の順です。子・世帯の外の家族の年金の加入記録の推計のように、画面が出さない知らせは出しません。
- 事務所の文（カスタム層の説明の文の差し替え）は当てず、公式の文を返します。事務所の設定で隠している知らせも隠しません。物の ID は返しません（保険・口座の名前の欄が文字ならその名前。渡された世帯の縮約版では名前は渡っていません）。
- 大きさ: 見本の世帯で 1.4〜3.5KB（前のコードと ID の形とほぼ同じ）。同じ世帯を何度も計算するときは、`omit` に `noticeText`（文と内訳を省き、種類と鍵 `key` だけ。半分より小さい）か `notices` を入れます。`compare`・`sweep`・`find_threshold`・`chart`・`table` の答えには入りません。

### 入力の確かめ（お客さまに聞くこと。0210）

「面談の前に、お客さまに聞くことをまとめて」と頼まれたときは、`check_inputs` を使います（読むだけ。世帯のデータは変えません）。

- 中身は、アプリの入力のタブの「確かめの一覧」（`app/src/workspace/input/checkRows.ts` の `checkList`）と同じ行・同じ並びです: 未入力（0円で計算中）→ まだ入れていない項目 → 書類待ち → 確かめの注意（範囲の外の値・ほかの入力と合わない値・購入の払い方が無いなど）→ 計算のお知らせ（入力で直せる所）→ 推定（結果に効く順）。接続口は行を足さず、画面の一覧の行をそのまま使います（これから買う家の頭金が0円の購入も、画面の一覧の確かめの注意に出ます）。
- 1行は `item`（入力項目）・`field`（欄か物の見出し。計算のお知らせの行は画面のお知らせの文）・`value`（今の値）・`subjects`（計算のお知らせの対象）・`reason`（短い理由）・`question`（お客さまに聞く文の案。丁寧な言葉）・`rule`（当てた決まりの名前）・`premise`（前提条件の行だけ。`client`＝お客さまと確かめる前提・`fp`＝FP が決める前提）です。種類ごとに `groups` にまとめ、`counts`（種類ごとの数）・`total`・`truncated`（`max_items` で切ったか）が付きます。
- `question` は、決まりの表（`app/src/connector/check.ts` の `RULES`）で行ごとに決めます。今の決まり: 子の教育の進路が無い・退職金が無い・ねんきん定期便の額や加入月数が無い・失業給付・生活費が無い・住まいが無い・本人と配偶者の介護の費用が無い・保険が無い・まだ入れていない入力項目（入力項目ごとの文）・購入の残りの払い方が無い・頭金が0円か空欄・退職金の確かめ・保険の重なり・範囲の外の値・年金の加入記録が無い・退職金の受け取る時期・持ち家の時価の元・土地と建物の割合・介護の費用の目安・年収が推定か空欄。表に無い行は、種類ごとの決まりの文（「〜は、〇〇で合っていますか。」「〜を教えていただけますか。」など）です。決まりは表に1件足せば増やせます。
- 種類は `kinds` で選べます（既定は画面の一覧の既定と同じ。`certainty`〔本人の申告・概算の値〕・`premise`〔前提条件のうち事務所の既定値どおりの値。0214〕は選んだときだけ）。`max_items`（既定30・100まで）で行の数を絞ります。
- 世帯の書き方は `calculate` と同じで、プランを確かめるときは `plan_changes`・`changes` を当てます（答えに `planChanges`）。計算のお知らせを作るため、`calculate` と同じ道で1回計算します。計算できない入力（必須の欄が無い・スキーマの範囲の外の値）なら、`calculate` と同じ直し方を返します。
- 時間の目安: 見本の世帯で 4〜7 秒（画面の入力の欄の定義を読み込むため）。答えは 3〜8KB です。

### 前提条件の事務所の既定値（0214）

前提条件の値（物価・賃金・運用利回り・不動産の評価・資産の種類ごとの利回りなど）は、ほとんどの事務所で世帯ごとでなく事務所で決めます。アプリでは、世帯の前提条件の値が事務所の既定値（事務所で決めていなければ提供元の既定の値）と同じなら印を出さず（事務所の既定値）、違えば「この世帯だけ」と出します（0260）。どちらも**推定ではありません**（お客さまに確かめる値ではなく、FP が決める前提です）。運用の利回り（`investmentReturn`。配分も利回りも入れていない運用の口座の率）は、世帯の前提条件の画面に出しません（事務所の既定値の画面で決め、世帯で変えるときは口座ごとの利回りに入れます。前の世帯で「この世帯だけ」の値がある世帯だけ、詳細に1行出ます。計算は変わりません。0260）。

- `check_inputs` の推定（`estimated`）の行に前提条件は出ません。事務所の既定値どおりの前提条件は種類 `premise` の行（選んだときだけ）です。行の `premise` で2つに分けます: `client` はお客さまと一緒に確かめる前提（前提条件の入力項目の標準に出す欄。表を何歳まで見るか・物価の上昇率・給与の上昇率。行の `field` は「経済の前提: 物価の上昇率」のように区画の名前から）で、問いの文は「〜は、1%で見ています。この見込みでよろしいですか（お客さまと確かめる前提です。事務所の既定値）。」、`fp` は FP が決める細かい前提（詳細だけの欄。預金の利回り・年金の調整率・不動産の評価・資産の種類ごとの利回りなど）で、問いの文は「〜は、事務所の既定値のままでよろしいですか（FP が決める前提です）。」です。どちらも事務所の既定値に従っている欄で、見分けは画面の欄の定義の入れ方（標準か詳細か。`app/src/workspace/input/checkRows.ts` の `premiseWithClient`）で決めます（0260。前は「お客さまと確かめる前提」の区画で分けていました）。表を何歳まで見るかは、画面の確かめの一覧と同じく前提条件の行には出ません。事務所の既定値をそのまま使っていた値で、その後に事務所が既定値を変えた物は、確かめの注意（`notice`）に「事務所の既定値が変わりました（1%→1.5%）。この世帯は前の値で計算しています」と出ます（世帯の値は黙って変わりません）。
- 前提条件の欄の名前（id）は次のとおりです（AI の道具で事務所の既定値を読む・直すときの名前。使い回しません）。表の正は `app/src/workspace/input/premiseDefaults.ts` の `PREMISE_DEFS`、事務所データの置き場所は設計記録 0214 の3。
  - 経済の前提: `inflation`・`wageGrowth`・`investmentReturn`・`depositReturn`・`educationInflation`・`pensionMacroSlide`・`pensionMacroSlideEmployee`（世帯では `assumptions.<id>.default`）
  - 不動産の評価: `realEstateValuation.landGrowth`・`realEstateValuation.landShare`・`realEstateValuation.usefulLife.wood`（`lightSteel`・`steel`・`rc`）・`realEstateValuation.residualFloor`・`realEstateValuation.saleCostRate`（世帯では `assumptions.realEstateValuation.…`。`landShare`・`residualFloor`・`saleCostRate` の事務所データの置き場所は事務所の推定の値 `preset.realEstate.*` ですが、ほかの前提条件と同じく世帯に写します。アプリは新しい世帯を作るときと、値の無い世帯を開いたときに事務所の値を写すので、事務所が後で値を変えても作った世帯の結果は変わらず、確かめの注意に「事務所の既定値が変わりました」と出ます。0218。物件ごとの値があれば、その物件はそちらを使います）
  - 資産の種類ごとの利回り: `assetReturns.<種類>`（`cash.deposit`・`cash.foreign`・`bond.domestic`・`bond.global`〔先進国債券〕・`bond.emerging`〔新興国債券。0252〕・`equity.domestic`・`equity.global`〔先進国株式〕・`equity.emerging`〔新興国株式。0252〕・`reit.domestic`・`reit.global`・`balanced`・`commodity`・`realEstate`・`other`。世帯では `assumptions.assetReturns.<種類>.default`）
- 世帯ファイルの仮の印 `assumed["<欄のキー>"]` が「事務所の既定値（年月）」の欄は、事務所の既定値を写した欄です（推定の印ではありません。前の版のアプリでは推定と読まれます）。

### 計算の前の処理（画面と同じ。0184）

`calculate`・`explain_value` は、アプリの画面と同じく、計算の前に次を当ててから計算します（画面の関数 `app/src/engine/moneyRows.ts` の `forEngine` を接続口に同梱して動かすので、画面と同じ数字になります）。

- 計算に入れない物を外す: 見込みが「不確実」の物（入るお金・出るお金・子への援助・受け取る相続・遺贈・贈与・相続で受け継ぐ借金。前の版の「この行を計算に入れる」にした入るお金・借金は残す）。「最初から計算に入れない」を選んだ夢。見本の世帯・渡された世帯・AIが組み立てた入力のどれにも当てます。
- 事務所の推定の値を足す: FPの事務所が既定値の画面で変えた推定の値と、推定で埋めない目安。渡された世帯（`share_id`）のときだけ、アプリ本体が計算に使う読み取りに事務所データの値を添えます（`get_shared_household` の答えには入りません。FPが書いた根拠の文はAIに渡りません）。

何かを当てたときは、答えに `preparation`（外した物と、足した事務所の値の値ID）が付きます。当てないのは、画面の結果の見方（区画「夢と予定」の物ごとの入れ外し）と、保存していない変更です（渡されるのは保存した世帯）。そのときは、画面の数字と違うことがあります。

### 比較（0198）

「対策を3つ並べて」「この世帯とこの世帯を比較して」「物価 0%・1%・2% で並べて」のように何通りも並べるときは、`calculate` を何度も呼ばず `compare` を使います。

- 基本の世帯（`sample_household_id`・`share_id`・`input` のどれか1つ）と、基本に当てる `changes`・`plan_changes`・`stress_test`（か `market_stress`）を書き、`variants` に8通りまで並べます。
- 世帯を書かない通りは基本に重ねます（基本の変更の後に、その通りの `plan_changes`・`changes` を当てる。`stress_test`・`market_stress` はどちらかを書けばその通りの物、書かなければ基本の物）。`sample_household_id`・`share_id`・`input` を書いた通りは、その世帯で計算します（見本の世帯どうし・渡された世帯どうしも並べられます）。
- 答えの `results` の1つ目が基本で、通りごとに主な数字 `keyFigures`（`calculate` と同じ。アプリの「プランを比較」と同じ数え方）・基本との差 `diff`（この通り − 基本の円。資産が尽きる年は画面の比較の表と同じ文）・選んだ数字の年ごとの系列 `series`（`series` で選ぶ。既定は金融資産を5年ごと・家族の年齢つき。画面の表に出す年から）・当てたプランの変更 `planChanges` が出ます。
- `market_stress` は、アプリの資産運用のタブの「相場が下がった場合」の型です: `drop`（退職の直後に株などが下がる）・`low`（取り崩しを始めてから、予定が無ければ退職から、しばらく利回りが低いまま）・`minus1`（利回りがずっと想定より1%低い）。画面と同じ関数で、プランの変更を当てた後に重ねます（`stress_test` とは1つの通りにどちらか1つ）。答えの `marketStress` に画面の文が出ます。頼み方の例: 「investmentCouple で、相場が下がった場合の3つを並べて」
- 主な数字には65歳からの年金の月額が入り、`diff` に `pensionMonthly`・`pensionClaimedMonthly`（基本との月額の差）が出ます。
- `at_ages` に表の範囲の外の年齢を書くと、その年齢の `keyFigures.assetsAtAge` は金額が `null` で理由 `reason` が付き、`diff.assetsAtAge` のその年齢の差も `null` です。`from_year` が `to_year` より後なら断ります。
- 主な数字には住宅ローンの利息の合計 `loanInterest`（0205）も入り、`diff.loanInterest` が基本との差です（「利息の合計は今のままで X 万円、+2% で Y 万円」）。数え方は下の「住宅ローンの利息と金利」。
- 形の違う通り・当てはまらない変更・読めない共有・計算できない入力・9通り目から後は、その通りだけ `status: "error"` と理由 `reason` を返し、ほかの通りは計算します。
- 1通りの計算は `calculate` と同じ道（プランの変更 → 計算の前の処理 → 計算 → 主な数字）です。渡された世帯は `calculate` と同じくアプリ本体に頼み、読むたびに道具の名前 `compare` で「AIに渡した記録」に残ります（1回の呼び出しで同じ世帯は1回だけ読みます）。
- 大きさと時間の目安（見本の世帯）: 基本＋3通りで約 9KB・0.7 秒、基本＋8通りで約 19KB・約 1.8 秒（年金の見込みを含む。0200）。`ages: false` で年齢を省くと1通り約 0.7KB 小さくなります。

### 感度と境目探し（0202）

「何歳まで働けば足りる？」「生活費は月いくらまでなら使える？」「退職を60〜70歳で1歳ずつ変えたら？」のように、1つの項目を動かして答えを探すときは、`calculate` を何度も呼ばず、次の2つを使います。どちらも、振る項目を `list_plan_items` の `target`・`item`（`plan_changes` の1件から `value` を外した物）で `vary` に書き（一覧が場所 `at` か `lever` を添えた項目は、それもそのまま。下の「場所だけ違う項目を振る」）、値ごとの計算は `calculate` に `plan_changes` でその値を渡したときと同じです（画面のプランと同じ関数で当てるので、働く最後の年齢なら生活費の退職の段階・積立の終わりも一緒に動きます）。基本の世帯の書き方・`changes`・`plan_changes`・`stress_test`・`market_stress` は `compare` の基本と同じで、振る値は基本の変更の後に当てます。渡された世帯は1回の呼び出しで1回だけ読み、道具の名前（`sweep`・`find_threshold`）で「AIに渡した記録」に残ります。

- **`sweep`（感度）**: `from`・`to`・`step` か `values` で値を並べます（21個まで。超えれば計算せず、収まる刻みの目安を返します）。値の形は項目の `kind` に合わせます: 年齢・整数・金額は整数、率は10進の文字列（`"0.01"`）。`step` を省くと、年齢は1歳、金額・率は画面のスライダーの刻みです。配偶者の働き方と年収（`kind` が `work`）は、今の働き方（か `work_type`）のまま1年の収入を振ります。答えは `columns`（列の名前）と `rows`（値ごとの主な数字）の表です。列は `value`・`assetsAt95`（`at_ages` の年齢の時点の金融資産）・`depletionYear`・`depletionAge`・`minimumYear`・`minimumAmount`・`lifetimeTakeHome`・`lifetimeExpense`・`loanRepayment`・`pensionMonthly`・`pensionClaimedMonthly` で、`figures` で選べます（`pension` を省くと年金の見込みの計算をしないので速くなります）。項目の範囲の外の値（例: 働く最後の年齢の45歳）は計算せず、`notComputed` に値と理由を返します。年齢・整数・金額（と働き方の年収）は JSON の数で書きます。`"310000"` のような文字は数に直さず断ります（答えの表の `value` の列に文字を混ぜないため。率は今までどおり10進の文字 `"0.01"`）。`at_ages` に表の範囲の外の年齢を書くと、その列は `null` で、`outOfRange` に列の名前・年齢・理由を返します。
- **`find_threshold`（境目探し）**: `from`・`to`・`step`（答えの細かさ）で探す範囲、`condition` で条件、`want` で `max`（満たす、いちばん大きい値。例: 生活費の上限）か `min`（いちばん小さい値。例: いちばん早い退職の年齢・足りる最低の利回り）を書きます。条件は `noDepletion`（資産が最後まで尽きない）・`assetsAtAge`（本人が `age` 歳の時点の金融資産が `at_least` 円以上）・`minimumAtLeast`（金融資産がいちばん少ない年でも `at_least` 円以上）です。`assetsAtAge` の `age` が表の範囲の外（今より若い・表の最後の年より先）なら、端の年の残高で判定せず、表の範囲を添えて断ります。
  - 探し方: 動かすと主な数字が一方向にだけ動くと分かっている項目（毎月の生活費・働く最後の年齢・運用の利回り）は二分探索（範囲の両端を計算し、間を半分ずつ狭める。2,001個の刻みまで）、ほかの項目（年金の受け取り開始・NISA の積立・繰上返済・配偶者の年収など）は刻みで振って、欲しい端から4つずつ確かめます（21個まで）。どちらにしたかと理由が `method`・`methodNote` に出ます。`method` で `bisect`・`scan` を選ぶこともできます。
  - 答え: `status`（`found`＝範囲の中に境目がある・`edge`＝範囲の端の値でも満たす〔境目は範囲の外かもしれないので、範囲を広げて探し直す〕・`notFound`＝範囲の中に満たす値が無い）・`threshold`（境目の値）・`message`（境目の文）・`rows`（境目の値とその1つ外側の値、`notFound` なら範囲の両端の主な数字。`sweep` と同じ列に、条件を満たすかの `meets`）・`computed`（計算した回数）。探す間は年金の見込みを数えず、答えの行だけ数え直します。範囲の端が項目の範囲の外なら、計算せずに理由を返します。
- 大きさと時間の目安（見本の世帯 `salariedCoupleTwoKids`。リリースのビルド・ほかの作業と同時に動いている10コアの手元の機械）: 働く最後の年齢を60〜70歳で振ると、`calculate` を11回（答え約152KB・約9〜11秒。主な数字だけでも約16KB）の代わりに `sweep` 1回（約1.5KB・約4秒。列を3つに絞ると約1KB）。生活費の上限を1,000円刻みで探す（15万〜40万円の251個）と、`find_threshold` 1回（10回計算・約1.4KB・約7秒）。

- **場所だけ違う項目を振る（0204）**: 資産運用の「毎月の積立額」と「積立をやめる年齢」、退職後の生活費の割合、教育の段階ごとの欄のように、同じ対象・同じ入力項目ID で場所だけが違う項目は、`plan_changes` と同じく `vary` に一覧の `at` か `lever` を添えます（例 `{"target": "assumptions", "item": "account.contributions", "lever": "investStopAge"}`）。項目は `plan_changes` と同じ画面の当てはめで選び、当てはまらなければ同じ理由を返します。場所を書かなければ、今までどおり場所の要らない項目だけを選びます。場所の要る項目に場所を書かなかったときは、計算せずに、選べる場所を `list_plan_items` と同じ形（`at` か `lever`・`place`・`label`）で `places` に返します。単調と分かる項目の二分探索は、場所の要らない項目だけです（場所を添えた項目は刻みで振ります）。

頼み方の例: 「salariedCoupleTwoKids で、生活費は月いくらまでなら最後まで足りる？ 1,000円単位で」「何歳まで働けば、90歳の時点で1,000万円残る？」「配偶者の年収を100万〜160万円で10万円ずつ振って、生涯の手取りを表にして」「積立をやめる年齢を何歳まで早めても、90歳の時点で1,000万円残る？」

### 比較をグラフにする（0203）

「変動金利の上がり方を3通りにして比較し、グラフにして」のように、比較した答えをセミナーの資料やブログに使うグラフにするときは、AI のアプリに数字を描かせず `chart` を使います。

1. `list_plan_items` で、住宅ローンの「金利の見込み（変動金利）」の項目（`kind: "rateOutlook"`。変動金利の住宅ローンごとに1つ）を探します。入力の「住まい・ローン」の「金利の見込み（変動金利）」の欄と同じ型（`presets`: `flat`＝今の金利のまま・`up1`＝10年で1%上がる〔5年後に＋0.5%・10年後に＋1%〕・`up2`＝10年で2%上がる〔5年後に＋1%・10年後に＋2%〕）と、今の金利 `currentRate`・起点の月 `from` が出ます。
2. `chart` の基本と通りの `plan_changes` に、その項目（`target`・`item` と、一覧が添えた場所 `lever`）と値を入れます。値は型の名前か、5年ごとの上乗せ `{"adds": ["0.005", "0.01"]}`（5年後に＋0.5%・10年後に＋1%。6段まで。各段 −3%〜+5%）。入力の欄で型を選んだときと同じ関数で当たるので、画面で同じ型を選んだときと同じ数字になります。
3. 返るのは、説明と通りごとの主な数字（キャプション用）の文章、続けてグラフの PNG（MCP の image。AI のアプリでそのまま見える）と、`format` が `svg`・`both` なら SVG（`image/svg+xml`）です。

例:

```json
{ "sample_household_id": "salariedCoupleTwoKids", "label": "今のまま",
  "plan_changes": [{ "target": "<ローンの ID>", "item": "debt.rateSchedule", "lever": "loanRateOutlook", "value": "flat" }],
  "variants": [
    { "label": "10年で+1%", "plan_changes": [{ "target": "<ローンの ID>", "item": "debt.rateSchedule", "lever": "loanRateOutlook", "value": "up1" }] },
    { "label": "10年で+2%", "plan_changes": [{ "target": "<ローンの ID>", "item": "debt.rateSchedule", "lever": "loanRateOutlook", "value": "up2" }] } ],
  "charts": ["assets", "repayment", "rate", "keyFigures"], "figures": ["assetsAtAge", "minimum", "loanRepayment", "loanInterest"], "format": "both" }
```

- グラフの種類（`charts`。既定は `assets`・`repayment`・`keyFigures`）: `assets`（通りごとの金融資産の推移）・`repayment`（通りごとの住宅ローンの返済額の推移。年額）・`keyFigures`（主な数字の棒。`figures` で `assetsAtAge`・`minimum`・`loanRepayment`・`loanInterest`・`lifetimeTakeHome`・`lifetimeExpense` から選ぶ）・`interest`（通りごとの住宅ローンの利息の推移。年額。0205）・`rate`（通りごとの住宅ローンの金利の推移。その年の最後の返済に当てた金利で、縦の目盛りは %。金利の違う住宅ローンを2本以上返している年は描かない。0205）。`title` は1種類だけのときに渡せます。`theme` は `light`（既定。白地・印刷向け）か `dark`。
- どのグラフにも、題・凡例（通りの文字 A・B… と名前）・単位（万円。`rate` は %）・前提の短い注（通りの違い・物価上昇率・運用利回り・相場の想定〔重ねていなければ、その旨〕。運用利回りは、利回りも配分も入れていない運用の口座など、その率を計算に使う物がある通りだけ〔提案書の前提の一覧と同じ判定。0260 の追記〕）・試算の時点と「将来の結果を約束するものではない」旨が入ります。線の右端と棒の下にも通りの文字が入り、色だけに頼りません。
- 「ファイナンシアで試算」の出典は、`credit: true` のときだけ入ります（既定は入れない。0207）。FP がブログ・セミナーの資料に自分の名前で使うときに、ソフトの名前を入れなくてよいようにしています。前提の注・試算の時点・将来を約束しない旨は、`credit` に関わらずいつも入ります。
- 年ごとの推移は、下の「系列の名前」のどれでも `series` に入れると折れ線にできます（1つにつき1枚。`charts` と合わせて8枚まで）。支出の内訳の表の期間の合計は `charts` の `expenseBreakdown`（通りごとの横の棒）です。`series` を書いたときは、`charts` を省くと `series` の折れ線だけを作ります。
- 数字は `compare` と同じ道で計算した物だけを描きます（AI から数字を受け取りません）。どれかの通りを計算できないときは、グラフを作らずに理由を返します。
- `at_ages`（棒の「○歳時点の金融資産」の年齢。最初の1つを使う）が、どれかの通りの表の範囲の外なら、端の年の残高を描かず、グラフを作らずに理由を返します（`compare` の `keyFigures.assetsAtAge` の `reason` と同じ）。
- 見た目は画面と同じです（座標・目盛りの関数、線の色〔色の見分けにくい人にも見分けやすい組み合わせ〕、文字と線の色）。PNG は接続口に同梱した字体（BIZ UDゴシック）で描き、外へは何も送りません。
- お客さまの名前・ID は描きません。通りの名前（`label`）と題（`title`）に書いた文字はそのまま入るので、お客さまの名前を書かないでください。公開に使うときは、実在のお客さまの世帯なら、金額を丸める・珍しい組み合わせを変える・お客さまに一言ことわる、のどれかをしてから使ってください（見本の世帯はすべて架空です）。
- 系列の住宅ローンの数字は `compare` の `series`・`calculate` の `fields` でも選べます: `loanRepayment`（住宅ローンの返済。年額。繰上返済・手数料を含み、表に出す年の合計が `keyFigures.loanRepayment`）・`loanBalance`（住宅ローン残高。画面の表の行と同じ）・`loanInterest`（住宅ローンの利息。年額）・`loanRate`（その年の住宅ローンの金利）。利息と金利は下の「住宅ローンの利息と金利」。
- 変動金利の上がり方は、この項目のほかに、結果のタブの「変動金利の上昇」（前提の `loanRateShifts`。ある年から一律の上乗せ）と、ストレステスト `rateRise`（決まった型。上げ幅を選べない）があります。どちらも今ある後の段に重なるので、入力の欄の型とは当て方が違います。
- 大きさと時間の目安（見本の世帯で3通り）: 3つのグラフの PNG と SVG で約 420KB・約 1 秒、PNG だけ（既定）で約 400KB、1つだけなら約 130〜150KB（PNG は1枚約 100KB、SVG は約 8KB）。

### 年ごとの表にする（0209）

「キャッシュフロー表を5年ごと・家族の年齢つきで CSV にして」「退職60・65・70歳の金融資産と年間収支を表にして」のように表が欲しいときは、`table` を使います。AI が `calculate`・`compare` の JSON から表を組み立て直す必要がなく、数字を写し間違えません。

- 世帯と通りの書き方は `compare` と同じです（基本の世帯は `sample_household_id`・`share_id`・`input` のどれか1つ。`changes`・`plan_changes`・`stress_test`・`market_stress` も当てられ、`variants` は8通りまで。省くと基本だけの表）。計算も `compare` と同じ道で、数字は AI から受け取りません。どれかの通りを計算できないときは、表を作らずに `compare` と同じ理由を返します。
- 年・年齢・数字は画面のキャッシュフロー表と同じです（表に出す年は計算基準月が年の途中なら翌年から。年齢はその年に迎える年齢。万円は画面と同じ四捨五入）。
- 行（`rows`。既定は `income`・`taxSi`・`expense`・`net`・`financialAssets`）: 上の「系列の名前」のどれでも選べます（同じ名前・同じ数字。支出の内訳 `expenseLiving`〜`expenseOther` も）。`expenseBreakdown` は、支出の内訳のうち、どれかの通りに値のある物をまとめて選びます（全部足すと `expense`）。`incomeBreakdown` は、収入の内訳（`incomeSalary`〜`incomeOther`）のうち値のある物をまとめて選びます（全部足すと `income`。0211）。NISA の積立 `nisaContribution`・残高 `nisaBalance` も行にできます（0211）。`loanRate` は %（10進の文字を百倍した数。丸めない）、ほかは単位（`unit`）の金額です。
- 年（`from_year`・`to_year`・`every_years`。既定5年ごと。最初の年と最後の年はいつも入る）か、本人の年齢で選ぶ年（`from_age`・`to_age`。例「60〜90歳」は `from_age: 60`・`to_age: 90`。年齢は画面の表の年齢の行と同じく、その年に迎える年齢。通りに別の世帯があれば、通りごとにその世帯の本人の年齢で選ぶ。0211）。年と年齢を両方書くと、どちらに合わせるか決まらないので理由を返します。選んだ範囲に表の年が無いときも、表の年を添えて理由を返します。年齢の列にする家族（`members`: `self`・`spouse`・`child1`…。既定は全員、`[]` で無し）、単位（`unit`: `man`＝万円〔既定〕・`yen`＝円）、形（`format`: `csv`〔既定。負の数は `-`、桁の区切りなし〕・`markdown`〔画面と同じく3桁の区切りと ▲〕）を選べます。
- 通りが2つ以上のときの並べ方（`layout`）: `byRow`（数字ごとに通りを列に並べる。CSV は「金融資産残高・65歳で退職（万円）」のような列の1つの表、Markdown は数字ごとの表。既定）・`byVariant`（通りごとに分ける。CSV は先頭の「通り」の列で縦に積んだ1つの表、Markdown は通りごとの表）。別の世帯の通りがあるときの既定は `byVariant` です（`byRow` の年齢の列は基本の世帯の年齢）。
- 向き（`orientation`。0211）: `yearsDown`（年を行に、数字を列に。グラフを描く・プログラムで読むのに向く。既定）か `yearsAcross`（年を列に、数字と年齢を行に。画面のキャッシュフロー表と同じ向き）。`yearsAcross` は同じ表の縦と横を入れ替えた物で、マスの数字・並べ方（`layout`）・注は変わりません。
- 表の下に、必ず「※」の注が入ります: 通りの違い（反映したプランの変更。例「中学から私立: 第1子の進路の型 中学から私立」。グラフの注と同じ書き方で、どの通りにもプランの変更が無ければ書かない。0211）・前提（物価上昇率・運用利回り。運用利回りは、その率を計算に使う物がある通りだけ〔グラフと同じ〕。通りで違えば通りごと）・相場などの想定（重ねた「相場が下がった場合」・ストレステスト。無ければ「なし」）・単位・選んだ行の意味・計算基準月と「将来の結果を約束するものではありません」の旨。注は表の一部で、外せません。「ファイナンシアで試算」の出典は `credit: true` のときだけ入ります（既定は入れない。`chart` の `credit` と同じ）。CSV では、表の後の空の行から下が注です（プログラムで読むときは、最初の空の行までを表として読む）。
- 日本語の Windows の Excel は、BOM の無い UTF-8 の CSV ファイルを文字化けして開くことがあります。Excel で開くファイルにするときは `bom: true`（表の文の頭に BOM〔U+FEFF〕を付ける）にするか、UTF-8（BOM付き）で保存します。既定で付けないのは、AI のアプリやプログラムが表の文を読むときに、見えない文字が頭に付いて列の名前が崩れることがあるためです。
- 答えは2つの文です: 短い説明の JSON（`note`・`format`・`unit`・`layout`・`orientation`・`rows`・`years`・`variants`・`bytes`）と、表の文（そのままファイルにできる）。
- 大きさの目安（見本の世帯 salariedCoupleTwoKids）: CSV の表の文は、同じ数字を返す `compare`・`calculate` の答え（JSON）より小さくなります。退職60・65・70歳の3通りで金融資産残高と年間収支を5年ごと: CSV 約 1.3KB・`compare` 約 8.2KB（約6.5分の1）。同じ3通りで6つの数字を毎年: CSV 約 6.1KB・`compare` 約 31KB（約5分の1）。1通りで6つの数字を毎年: CSV 約 2.8KB・`calculate` 約 9.1KB（約3分の1）。1通りを5年ごとのような小さな表では、表の下の注（約 0.5KB）の分だけ差が縮みます（約 1.2KB・約 2.3KB で約2分の1）。

例:

```json
{ "sample_household_id": "salariedCoupleTwoKids", "label": "60歳で退職",
  "plan_changes": [{ "target": "<ご本人の ID>", "item": "employment.to", "value": 60 }],
  "variants": [
    { "label": "65歳で退職", "plan_changes": [{ "target": "<ご本人の ID>", "item": "employment.to", "value": 65 }] },
    { "label": "70歳で退職", "plan_changes": [{ "target": "<ご本人の ID>", "item": "employment.to", "value": 70 }] } ],
```

### AI が受け取った数字で自分でグラフを描くとき（0209）

チャットの画面の部品やコードの実行で、AI が数字を受け取って自分でグラフや図を描くことがあります。接続口の説明（INSTRUCTIONS）で、AI に次を守るよう伝えています。

1. 数字は `table`（か `compare` の `series`）から取り、足し引き・丸め直し・なめらかにする・間を埋める・先へ延ばすなどで変えない（表に無い年は描かない）。
2. 単位（万円）と、年・年齢の軸を書く。
3. `table` の表の下の注（前提・相場などの想定・試算の時点と、将来の結果を約束するものではない旨）を必ず図に添える。
4. 「ファイナンシアで試算」の出典は、FP が望んだときだけ入れる（既定は入れない。`chart`・`table` の `credit` と同じ）。
5. 画面と同じ見た目のグラフが要るとき・資料にそのまま使うグラフは、自分で描かず `chart` を使う。

### 住宅ローンの利息と金利（0205）

エンジンの計算（毎月の返済・ボーナス返済・変動金利の5年ルールと125%ルール・未払利息・繰上返済・借り換え・団信・売ったときの返済・返し終えた年）のまま、ローンごとに年ごとの利息と金利を数えています（エンジンの要約 `summary.loans`）。

- **利息**は、返済のうち利息に充てた額です（未払利息を後から払った分を含みます）。返済額が利息に足りない月（125%ルールで返済額を上げきれないとき）は返済額の全部が利息で、残りは未払利息として持ち越します。借り換えで新しいローンに含めた未払利息は、新しいローンの元金として数えます。そのため、その年の返済の合計（`loanRepayment`）＝元金に充てた額＋利息＋手数料・諸費用です。
- **金利**は、その年の最後の返済に当てた金利（10進の文字。例 `"0.0065"`＝0.65%）です。年の途中で金利が変わった年は変わった後の金利、前提の「変動金利の上昇」（`loanRateShifts`）・ストレステスト `rateRise` の上乗せも含みます。
- 主な数字の `keyFigures.loanInterest`（住宅ローンの利息の合計）は、住宅ローン（`kind` が `mortgage`）の利息を、`loanRepayment` と同じ年（画面の表に出す年）で足した額です。計算基準月が年の途中なら、その年の数か月分は入りません（エンジンの要約の `interestTotal` は計算基準月からの合計）。住宅ローンが無ければ 0。`omit` に `loanInterest` を入れると、主な数字の利息の合計と、`output: "table"` の `summary.loans` を省きます。
- 年ごとの `loanInterest`・`loanRate` は、`calculate` の `fields`・`compare` の `series` に入れたときだけ返します（既定の答えの大きさは変わりません）。`loanRate` は、返済の無い年と、金利の違う住宅ローンを2本以上返している年（ペアローンで金利が違うときなど）は `null` です。ローンごとの数字は `calculate` の `output: "table"` の `summary.loans`（ローンの ID・種類・年ごとの `interest` と `rate`・`interestTotal`。自動車ローンなど住宅ローン以外の世帯の負債も入ります）にあります。
- `sweep`・`find_threshold` の `figures` にも `loanInterest` を選べます（選んだときだけ列に入ります）。
- 画面の表には、利息と金利の行はありません（画面と同じ数字の見本は、エンジンの要約の数字と、返済の合計との関係で確かめます）。

### 事務所の言い方に文言を直す（0212・0016 の追記）

画面の文（入力の欄の「?」の説明・入力のまとまりの注〔見込みが「不確実」の行の注記〕・計算の知らせ・推定の根拠の文・結果の画面の文）と名前（入力の欄・キャッシュフロー表の行・結果の画面の「夢と予定」のまとまり・列の名前・見込み・「ほか○件を見る」）は、カスタム層の `settings/texts.json`・`settings/terms.json` で事務所の言い方に直せます。`list_custom_texts` は、アプリに同梱した一覧（アプリ本体が埋め込む物と同じ中身）を返すだけの道具です。

- 1件ごとに `id`・`where`（画面のどこに出るか）・`audience`（`customer` はお客さまと一緒に見る画面の文）・`text`（公式の文。差し込みの印つき）・`vars`（使える印。`meaning` と、計算の値の入る印には `number: true`）・`ops`（できる操作）・`hash`（下書きの `basedOn` に写す指紋）。
- 絞り方: `file`（`texts`＝文〔既定〕・`terms`＝名前）・`kind`（文は `field`・`section`・`notice`・`estimate`・`result`、名前は `field`・`row`・`result`）・`prefix`（id の頭。例 `result:invest/`）・`query`（言葉。全角・半角と大文字・小文字の違いは問いません〔言葉と文の両方を NFKC にそろえて照らし合わせる。「ＮＩＳＡ」でも「NISA」と同じ結果〕。`search_coverage`・`get_regulation_value` の `query`、`list_sample_households` の `tags` も同じ）・`limit`（既定50、200まで）・`offset`。答えには分野ごとの数（`areas`）と書き方（`howTo`）が付きます。
- 結果の画面の文（`result:<タブ>/<名前>`）は、数字と名前がいつも差し込みの印です（例 `result:invest/verdict` の公式の文は `{plan}では、金融資産は {age} まで持ちます`）。差し込む値は単位まで入ります（`{age}` は「84歳」）。書き換えるだけで、消せるのはグラフの注だけです。知らない印は承認できず、数字の入る印を落とすと注意が出ます。名前の一覧の `result:dreamsAndPlans/…`（「夢と予定」のまとまり・列の名前・見込み・「ほか{count}を見る」）も同じで、`{count}` には「4件」のように「件」まで入ります（行の名前は、入力の画面とそろえるので載せていません）。
- 入力の欄の見込みの「?」は、見本の世帯に出ない欄も含めて5通りが載っています（入るお金の行のうち相続・贈与でない物は `field:incomeFlow.likelihood#receive`、子への援助は `field:goal.education/gifts/*/priority`）。見込みが「不確実」の行の注記は `section:money.uncertainNote` で、書き換えるだけです（まとまりの注の中のその部分だけが変わります）。
- この接続口はカスタム層のファイルを書きません。FP のフォルダに書ける AI が下書きを書くか、FP に渡して置いてもらいます。効くのは、FP がアプリの事務所の既定値の「カスタム層」の画面（「説明の文（カスタム層）」「名前（カスタム層）」）で承認した後だけで、計算の結果はどの文でも変わりません。プロンプト `office_wording` が、この進め方の頼み方の型です。
- 入力の欄の隠す・並べ替え（`settings/fields.json`）の id は、`file: fields` で引けます（0213）。中身はアプリ本体が埋め込む欄の一覧（`fields-reference@1.0`）と同じで、1件の `text` は公式の欄の名前、`ops` は `hide`・`order` です。答えの `howTo` に書き方（行は `id` と `hide`〔true〕・`order`〔1〜99。まとまりの中で何番目に出すか〕。値の入った欄は隠しても出る・既定の値は書けない・計算は変わらない）が付きます。承認は事務所の既定値の「カスタム層」の画面の「入力の欄の見せ方（カスタム層）」です。

```json
{ "schema": "texts@1.0",
  "entries": [
    { "id": "result:invest/verdict", "do": "replace", "text": "{plan}の場合、金融資産が続くのは {age} までです", "basedOn": "sha256:…（list_custom_texts の hash）" } ] }
```

### 画面の見せ方の設定（表示の設定。0213）

「対策に最初から NISA も出して」「家計の体力の目安は出さないで」のように、FP の AI に画面の見せ方を変えてもらう形を、3つの段で作ります（設計記録 0213）。段A（読むだけ）・段B（事務所の既定値の案。0215。渡された世帯ごとの案。0220）・段C（結果のタブ・資産と負債のタブの事務所の既定値。0216）の3つとも、できています。

| 段 | 中身 |
|---|---|
| 段A（できた） | `get_display_settings`: 見せ方だけの設定の一覧（id・画面と同じ名前・どこで決めるか・効く画面・アプリのどこで変えるか・提案書と持ち帰り用のレポートに出るか・値の形・選べる値・既定）と、事務所の既定値・渡された世帯の今の値を返す。変えるのは FP がアプリの画面で |
| 段B の前半（できた。0215） | `propose_display_settings`: 事務所の既定値の見せ方だけの設定の案を、承認待ちの候補としてアプリに出す（`propose_scenario`・`propose_feature_code` と同じ形）。アプリの事務所の既定値の画面が設定ごとに「今 → 案」を出し、FP が「反映する」か「捨てる」を選ぶ。反映するごとに前の値を事務所データに残し（設定ごとに直近3件）、「前の値に戻す」で戻せる |

- 載せるのは、値も計算の結果も変えない見せ方の設定だけです。計算の結果を変える設定（前提条件の標準値・必要保障額の数え方・介護・受け取る予定の相続の見込み・不動産の評価の割合・表の最後の年齢・FP顧問料の料金表・事務所の推定の値）、名前・ロゴ・色・見た目、Web のヒアリングのひな形は載せません（答えの `outOfScope`）。計算のお知らせの「入力が足りない」「計算に入れていない」と確かめの注意は、どの設定でも隠せません（`neverHidden`）。
- 今の21件: 事務所の既定値（`scope: office`）の `input.order`（入力のホームの入力項目の並び）・`input.living`（基本生活費の内訳の並べ方）・`result.levers`（対策に最初から出す項目）・`contingency.premises`（想定の前提に最初から出す項目）・`contingency.scenes`（場面の帯に並べる場面）・`contingency.openScene`（開いたときに選んでおく場面）・`features.combinedBs`（合算BS を使う。読むだけ。機能を有効にするコードが要る）、事務所の既定と世帯ごとの両方（`both`）の `input.items`（新しい世帯で出す入力項目と、開いたときの入れ方。事務所の既定は新しい世帯に写すだけ）と、`result.metrics`（出す数字）・`result.atAge`・`result.layout`（比較の仕方）・`result.invBreakdown`・`result.invPeriods`・`balance.health`（家計の体力の目安を表示する）・`balance.guide`（家計の体力の目安の幅）・`balance.points`（「時点を並べる」の既定）・`balance.moneyThree.wording`・`.months`・`.years`（お金の3つの分け方）の11件（事務所の既定値は `officeEffect: followers`＝事務所の既定値に従う世帯にすぐ効く。0216）、世帯だけ（`household`）の `result.addedItems`（対策に足した項目）・`balance.columns`（この世帯で並べる時点）。作っている途中の設定があれば `pending` に出ます。
- 一覧はアプリの画面の定数から作ります（`app/src/connector/displayCatalog.ts`。`npm run build:explain` が `crates/lifeplan/dist/display-catalog.json` に書き、接続口が埋め込む）。選べる種類や既定を変えると、接続口の一覧も一緒に変わります。
- 今の値は、設定の `current.office`・`current.household` に `{ value, isDefault, text }`（`text` は画面の言葉の要約）で入ります。渡された世帯の11件には `followsOffice` も添えます（`true` は事務所の既定値に従っていて `value` は事務所の今の値、`false` はこの世帯だけの値。0216）。事務所の既定値はアプリ本体が事務所データから見せ方だけの欄を名前で選んで写し（計算の設定・推定の値・名前やロゴ・ヒアリングのひな形は写さない）、渡された世帯は世帯ファイルの本文の見せ方の区画（`display`・`household.itemChoice`・`workspace.shownItems`。数・真偽・短い英数字の値だけ）を、物の ID を共有ごとの仮の ID にして渡します。読み方は画面と同じ関数です（`app/src/connector/display.ts`）。
- アプリが起動していない（か AI接続口がオフの）ときは、一覧と既定だけを返し、`app.status` が `notRunning` になります。
- `ids` で設定を選べます（省くと全部で約 30KB）。例 `{ "ids": ["result.levers"] }`。
- この道具では設定を変えられません。答えの `change` に、アプリのどの画面のどの区画で変えるかが書いてあり、AI はそれを FP に伝えます。答えの `proposable`（と各設定の `proposable: true`）の18件は、下の `propose_display_settings` で事務所の既定値を変える案を出せます。答えの `householdProposable`（と各設定の `householdProposable: true`）の13件は、`share_id` を書いて渡された世帯ごとの案を出せます。プロンプト `office_display` が、この進め方の頼み方の型です。

#### 表示の設定の案（`propose_display_settings`。0215）

- 入力は `changes`（1〜18件。1件は `id`・`value`・任意の `note`〔理由。500文字まで〕。同じ設定は1回だけ）。`value` は `get_display_settings` の `current.office.value` と同じ形です（整数・真偽は数・`true`/`false` で書き、文字にしません）。例:

```json
{ "changes": [
  { "id": "result.levers", "value": ["lever:retireAge", "lever:pensionAge", "lever:nisaMonthly", "lever:livingMonthly", "spouse:work"], "note": "NISA の相談が多いので最初から出す" },
  { "id": "contingency.openScene", "value": "income" },
  { "id": "result.atAge", "value": 85 },
  { "id": "balance.guide", "value": { "months": [3, 9], "risk": [10, 40], "debt": 50 } } ] }
```

- 案をアプリに出す前に、表示の設定の一覧の選べる値・値の形で確かめます（画面と同じ関数。`app/src/connector/displayProposal.ts`）。知らない id・18件以外の設定（世帯だけ・読むだけ）・選べない値・範囲の外の値（「○歳時点」の年齢は選択肢の年齢、お金の3つの分け方の何か月分・何年先までは範囲の中の整数、家計の体力の目安の幅は下限より大きい上限）・重複・形の違う値は、近い候補を添えて断り、その呼び出しでは何もしません（ほかの正しい案もアプリに出しません）。入力項目の並びは全部の入力項目を並べます。基本生活費の内訳の並べ方の行の名前は20文字までで、改行などの制御文字・見えない書式の文字は使えません。
- 案はアプリのメモリの中に承認待ちで入るだけです（4件まで。アプリを閉じる・AI接続口をオフにすると消える）。アプリの上の帯と、事務所の既定値の「結果と万一の画面」のいちばん上の「AIからの表示の設定の案」に、設定ごとの「今 → 案」と AI の理由が出ます。FP が「反映する」を押した設定だけが事務所の既定値に入り（すぐ保存。どの世帯にもすぐ効く。`input.items` は新しく作る世帯にだけ効き、作った世帯にはそろえない。結果のタブ・資産と負債のタブの11件は、事務所の既定値に従う世帯にだけ効き、従わない世帯にはそろえない）、「捨てる」を押した設定は何も変えずに外れます。
- 反映するごとに前の値を事務所データ（`defaults.displayHistory`。事務所データの形の版 3 から）に残し（設定ごとに直近3件）、事務所の既定値の画面の「前の値に戻す」で戻せます。事務所の既定値は世帯の中身ではないので、AIに渡した記録には残りません。

#### 渡された世帯ごとの表示の設定の案（`propose_display_settings` の `share_id`。0220）

- `share_id`（`list_shared_households` の共有 ID）を書くと、その世帯の世帯ごとの表示の設定の案になります。出せるのは `householdProposable` の13件: `input.items`（入力項目の選び方）・`result.metrics`・`result.atAge`・`result.layout`・`result.invBreakdown`・`result.invPeriods`・`balance.health`・`balance.guide`・`balance.points`・`balance.columns`（この世帯で並べる時点）・`balance.moneyThree.wording`・`.months`・`.years`。`value` は `current.household.value` と同じ形です。`balance.columns` は `null`（「時点を並べる」の既定のまま）か、`{ "point": 候補の鍵 }`・`{ "year": 西暦の年 }` を2〜4つ（重ならずに）。

```json
{ "share_id": "s-…", "changes": [
  { "id": "result.atAge", "value": 85, "note": "このご夫婦とは85歳時点で話す" },
  { "id": "balance.columns", "value": [{ "point": "now" }, { "point": "childIndep" }, { "point": "retire" }] },
  { "id": "balance.health", "value": false } ] }
```

- 値は事務所の既定値の案と同じ関数で確かめます。事務所の既定値だけの設定（`input.order`・`input.living`・`result.levers`・`contingency.*`）・対策に足した項目（`result.addedItems`。鍵に物の ID が入るので出せない）・読むだけの設定・選べない値・範囲の外の値は、近い候補を添えて断り、何もしません。
- 共有の決まりは世帯を扱うほかの道具と同じです（期限内・取り消されていない・同意がある。架空の世帯は同意が無くても渡せる。期限切れは `EXPIRED`、取り消し・同意の撤回は `REVOKED`）。案を出したことは、その世帯の「AIに渡した記録」の `proposals` に残ります（同じ世帯に同じ中身の案がもう一度届いたときは、同じ案を返し、記録にも足しません）。
- 案はアプリのメモリの中に、世帯ごとに承認待ちで入るだけです（1つの世帯で4件まで。アプリを閉じる・AI接続口をオフにすると消える）。その世帯を開いていなくても届き、上の帯にどの世帯に届いているかが出ます（入力の画面では顧客番号と仮名、お客さまと一緒に見る画面では件数だけ）。その世帯を開くと、結果のタブのプランの帯の下の「AIからの表示の設定の案」に、事務所の既定値の案と同じ見た目で設定ごとの「今 → 案」と AI の理由が出ます。「今」には、事務所の既定値に従っている設定かこの世帯だけの値かが添えてあります。
- FP が「反映する」を押した設定は、この世帯だけの値になります（事務所の既定値に従う印を外す。押す前が事務所の既定値でも外す）。反映は元に戻すの履歴に入り、「元に戻す」で戻せます。押す前が事務所の既定値だった設定のうち、表示の設定に印を出す設定（「○歳時点」の年齢・「時点を並べる」の既定・目安の幅・「何か月分」・「何年先まで」）は、表示の設定の「事務所の既定値に戻す」でも戻せます（ほかの設定は選び直します。0213 の段C）。世帯ファイルの形式は変えていません（前の値は世帯ファイルに残しません）。閲覧だけで開いている世帯では反映できません（捨てることはできます）。

### Web のヒアリングの URL を発行する（0222）

「新しいお客さまに URL で事前のヒアリングを送りたい」「この世帯の足りない所だけ URL で聞きたい」のように頼まれたときは、`get_hearing_options` で聞ける項目を引き、`issue_hearing_url` で URL を発行します（FP の承認は挟みません。利用者の判断。アプリもこの接続口もメールは送らず、URL と案内文を送るのは FP です）。

- 票は2つ（`simple`＝シンプル〔簡易の票〕・`detail`＝詳細〔詳細の票〕）で、1つの依頼に混ぜられません。項目キー・ひな形・数え方は FP の画面と同じです（0192）。金額の「だいたいの範囲」は金額の項目の `range`（既定は付ける）で付け外しします。
- 書き方: `template`（`simple`・`detail`・`review`〔見直し〕・`missing`〔足りない所だけ〕か事務所のひな形の名前）から始め、要るときだけ `items`（`[{ key, mode?, range? }]`。書くとひな形の項目を置き換える。分野はその項目の分野）・`custom`（独自の質問。10問まで。`answer` は `text`・`yesNo`・`choice`）・`documents`（頼む書類。15通まで。`[{ kind, owner? }]`。人の書類は省くとご本人）・`name`（依頼の一覧に出す名前）・`purpose`（何のための問いか）を書きます。`preview: true` は発行せずに数と要約だけを返します。

```json
{ "template": "simple",
  "items": [{ "key": "hs.family.adult.birthYearMonth" }, { "key": "hs.work.type" }, { "key": "hs.income.annual" }, { "key": "hs.housing.type" }, { "key": "hs.assets.depositTotal" }],
  "custom": [{ "label": "面談の場所のご希望", "answer": "choice", "choices": ["事務所", "オンライン"] }],
  "documents": [{ "kind": "withholding" }],
  "name": "初回の面談の前",
  "preview": true }
```

- 選び方は、アプリに頼む前に FP の画面と同じ関数（`app/src/workspace/hearing/aiSelection.ts`。`plan.js` に同梱）で確かめます。知らない項目（近い候補を添える）・もう一方の票の項目・範囲の項目を直接書いた・重なり・上限の超え・形の違い・制御文字と見えない書式の文字は、断ってその呼び出しでは何もしません。
- `share_id` を書くと渡された世帯の依頼です（共有の決まりは世帯を扱うほかの道具と同じ）。`get_hearing_options` の `filled`（今の値があるか。値は返さない。FP の画面と同じ決め方で、まだ何も入れていない新しい世帯は値なし）と `check_inputs` の「お客さまに聞くこと」に合わせて、`missing`（詳細の票のうち今の値の無い項目）に `items` で足す、`review`（今の値のある項目を確かめてもらう）にする、`mode: confirm`（今の値のある詳細の票の項目だけ）を書く、が使えます。発行したことは、その世帯の「AIに渡した記録」の `proposals` に `hearing:<依頼番号>` で残ります。`share_id` を書かなければ世帯の決まっていない依頼（新しいお客さま向け）です。
- 答え: 聞く項目の数（`selectedCount`）・お客さまの画面の数（`screens`）・所要時間の目安（`minutes`）・期限（`expiresAt`。30日）・依頼番号（`requestId`）・`summary`。**見直しを含まない依頼だけ** URL（`url`）と案内文（`invitation`）が付きます。見直しを含む依頼は、URL の # の後ろの鍵で今の値が読めるので返さず、FP がアプリの「発行した URL」で案内文をコピーします。顧客番号・世帯の内部 ID・呼び名は返りません。
- 発行はアプリ本体が画面に頼み、画面が FP の画面と同じ部品で鍵を作って受け付けのサーバーに問いを置きます（接続口は鍵も世帯ファイルも事務所データも扱いません）。AI が書いた文の番号らしい所は、書類の候補と同じ決まりで消します（`masked` に数）。置き場所は、渡された世帯をアプリで開いていれば世帯ファイル、開いていなければ事務所データ（その世帯を開いたときに世帯ファイルへ移る）、世帯の決まっていない依頼は事務所データ（答えが届いたら FP が新しい世帯か開いている世帯へ移す）です。
- アプリの上の帯に「AI が URL を発行しました」が出て、FP は一覧で確かめ・取り消せます。世帯の「発行した URL」の行には「AI が発行」が出ます（「URL生成」で作った URL と同じ表。まだ世帯の決まっていない URL は、表の下の「まだ世帯の決まっていない、AI が発行した URL（N件）」から開く）。
- 上限: 1時間に10件（アプリを開いている間）・世帯の決まっていない受け付け中の依頼は20件まで（利用者の判断〔2026-11-17〕で、β で使われ方を見るまでこの値）。本番の受け付けのサーバーが無い（配布元の設定の `[hearing_web]` が空）・つながらないときは、その理由を返して何も発行しません。
- `propose_hearing_template` は、名前（40文字まで）と同じ書き方の選び方を、事務所の既定値の「入力の画面」のいちばん上の「AIからのヒアリングのひな形の案」に承認待ちで出すだけです（4件まで。`review`・`missing`・`mode: confirm` は世帯に依るので断る）。FP が「ひな形として保存する」を押したときだけ事務所のひな形（URL で聞くときの「カスタム」）に入ります（同じ名前は置き換え。20件まで）。
- お客さまの答えを読む道具はありません（受け取り・取り込みは FP がアプリで行います）。使い方の例（プロンプト）`hearing_url` が、この進め方の頼み方の型です。

### プランの動かす項目（画面と同じ。0195・0201・0206）

画面の結果のタブのプランで動かす項目（働く最後の年齢・年金の受け取り開始・NISA の積立・毎月の生活費・配偶者の働き方と年収・FP顧問料・資産運用の利回りと配分・住宅ローンの借入額・繰上返済・金利・変動金利の上昇、入力の数の欄など）は、1つ動かすと関係する欄も一緒に動きます（働く最後の年齢なら、働き方の期間の終わり・生活費の「退職後」の段階・積立の終わり・定年後の働き方。毎月の生活費なら、計算基準月にかかる生活費の行の月額と、月額で入れた段階。内訳で入れた行は、費目の値はそのままで、内訳の合計をそろえる月額 `categoryTotal` を書く。0262）。`changes`（JSON Pointer）で欄を1つだけ動かすと、画面と違う数字になることがあります。

1. `list_plan_items` で、その世帯で動かせる項目を見ます（子の進路の型は下の「子の進路の型」）。項目ごとに `target`（対象）・`item`（入力項目ID）・`label`・今の値 `value`・値の形 `kind`・`unit`・範囲 `min`・`max`・`slider`・`options`・補足 `note`・プランの候補に出せるか `proposable` が返ります。同じ対象・同じ入力項目ID で場所だけが違う項目（資産運用の「毎月の積立額」「積立をやめる年齢」、取り崩しの3項目、黒字の貯まり方、生活費の段階ごとの割合、教育の段階ごとの欄、住宅ローンの金利の段階、定年後の予定の定年など）には、選ぶための場所（入力の欄の場所 `at` か、合成の対策の名前 `lever` のどちらか1つ）と、人が読める区別 `place`（例「子ども・教育 › 第2子 › 大学（18歳から）」）も添えます。既定は対策・資産運用・貯まり方・よく使う項目だけで、`fields: true` か `group` で入力の欄から作った項目も返します。
2. `calculate`・`explain_value`・`compare` の `plan_changes` に、同じ `[{ "target": …, "item": …, "value": … }]`（場所を添えた項目は `[{ "target": …, "item": …, "at": […], "value": … }]` か `[{ "target": …, "item": …, "lever": "…", "value": … }]`。場所は一覧のまま渡す）を渡します。画面のプランと同じ関数（`app/src/workspace/plans/` の動かす項目の一覧と当て方）を接続口に同梱して当てるので、画面で同じ値にしたときと同じ数字になります。答えの `planChanges` に、変更ごとの前と後の文と `status`（`applied`＝当てた・`same`＝今と同じ値なので変わらない・`restored`＝今と同じ値で、前の同じ項目の変更を取り消した・`replaced`＝後の変更が同じ項目を動かすので使わなかった）、場所を添えた変更には `place` が出ます。同じ項目を2回以上書くと、後の値が勝ちます（後の値が今の値と同じなら、その項目は今の値のまま。0198 の追記）。当てはまらない変更（対象・入力項目ID の違い・値の形・範囲の外）があれば、計算せずに理由を返します。金額の項目には上の端があり、超える値は「入れてよい範囲（月1億円まで）の外の値のため、取り込みません」のように断ります（円と万円の取り違え・桁の誤りを止めるため。月額1億円・年額10億円・一時の額〔借入額・繰上返済など〕100億円で、入力の欄の「桁を確かめてください」の目安〔月額1,000万円・年額1億円〕の10倍。今の値がもっと大きければ今の値まで。`propose_scenario` の候補も、画面の「AIからの候補」で同じく取り込みません）。
3. 同じ書き方を、渡された世帯なら `propose_scenario` の `changes` にそのまま渡せます（AI が計算で確かめた物と、プランの候補が同じになります）。アプリ本体は、対象と `at` の中の共有の仮の ID を元の ID に戻して承認待ちに入れ、画面の「AIからの候補」が同じ当てはめでその項目に当てます（表に `place` の区別も出ます）。資産の配分の行・旧NISA の買付の年ごとの内訳・借り換えとその新しい金利の段も、世帯ファイルの形式 0.76 から要素の ID を持つので（設計記録 0206）、これらの欄も `at` のまま候補に出せます（見本の世帯では、どの項目も `proposable` が true）。場所の `at` に、世帯のデータに書かれていない要素の ID（ID を持たない並びの要素に場所から振る ID。今は保険の数表の最初の行の解約返戻金だけ）がある項目は、元の ID に戻せないので `proposable` が false です（計算はできます）。

`plan_changes` は `changes`・`stress_test` の後、計算の前の処理の前に当てます（`changes` と一緒に使えます）。場所を添えた項目を、場所を外して渡すと、今までどおり1つに決まらないので当てません（場所の無い前の書き方の変更・候補は、今までと同じ項目・同じ答えになります）。場所の無いプランの候補は、世帯ファイルにも前と同じ形で残ります（場所を添えた候補を残すため、世帯ファイルの形式は 0.75 から。並びの要素の ID は 0.76 から）。渡された世帯では、縮約版の定年後の働き方の条件（`get_shared_household` の `postRetirement`）を、画面で保存した世帯を開いたときと同じくそのまま使います。渡されるのは保存した世帯の現状なので、保存したプラン（プランA・プランB …）の上に重ねて試すことはできません。

画面の部品は `crates/lifeplan/dist/plan.js`（約 2MB）にまとめ、計算と同じ固めた実行環境で、プランを当てるときと一覧を返すときだけ読み込みます。固めた実行環境に無い組み込み（`structuredClone`・数の `toLocaleString` など）と呼べない Math の関数（`round`・整数の指数の `pow`）は、その JS の中だけで、画面と同じ答えになる実装に置き換えます（設計記録 0195 の4）。

#### 子の進路の型（0211）

進路の型（すべて公立・大学だけ私立・高校から私立・中学から私立・すべて私立）を、子ごとの動かす項目「第1子の進路の型」として出します（入力の子ども・教育の入力項目には、2026-11-14 から「進路の型」の欄はありません。入力では学校ごとに公立・私立を選びます）（よく使う項目。画面の結果のタブの「＋ 動かす項目を追加」にも出ます）。

- 出る子: 教育の目標（進路）を入れた子のうち、型が決める学校（幼稚園〜大学）でまだ終わっていない段がある子。教育の段が全部過ぎた子・子のいない世帯には出ません。
- 書き方: `{"target": "<教育の目標の ID>", "item": "goal.education", "lever": "educationCourse", "value": "juniorPrivate"}`（一覧のまま）。`kind` は `choice` で、`options` に型の名前と言葉（`allPublic`＝すべて公立（国公立大）・`univPrivate`＝大学だけ私立・`highPrivate`＝高校から私立・`juniorPrivate`＝中学から私立・`allPrivate`＝すべて私立）が並びます。値は型の名前か、言葉そのもの（「中学から私立」）。知らない型は当てません。
- 当て方: 前に入力の欄で型を選んだときと同じ関数（`setCoursePreset`）で、型が決める段の公立・私立をまとめて変えます（前の学校の推定の額をそのまま入れた年額・入学金は外して入れ直す。短大・専門学校・高専・大学院は変えない）。画面の結果のタブで同じ型を選んだときと、教育の段・計算の数字が同じです。
- 今の値: 学校ごとの公立・私立の並びが型に当たればその型、当たらなければ `null`（学校ごとに選んだ進路）。もう過ぎた段がある子では、同じ並びになる前の型に読めることがあります（高校生の子に「中学から私立」を当てると「高校から私立」と読める。計算は同じ）。
- `compare`・`chart`・`table` の通りの `plan_changes`、`sweep` の `vary`（`values` に型の名前を並べる。範囲〔`from`・`to`〕では振れません）で使えます。境目探し（`find_threshold`）は、並びに大小の無い項目なので使いません。グラフと表の注の「通りの違い」に「第1子の進路の型 中学から私立」のように出ます（`changes` で教育の段を直に書き換えると、数字は同じでも注に進路の違いが出ません）。

## 6. 世帯を渡すと何が起きるか

- 世帯の復号・許可の判定・縮約・文章の包み方・記録は、**アプリ本体だけ**が行います（`crates/ai-share`）。接続口は鍵も世帯ファイルも扱いません。
- 渡せるのは、お客さまの外部AIへの提供の同意がある世帯、事務所の設定で FP が「事務所のプライバシーポリシーに AI の利用を書いている」ことを確かめていてお客さまが「同意しない」と答えていない世帯（同意の答えが無い世帯を含む。撤回した世帯は除く）、架空の世帯だけです。判定は `crates/ai-share/src/basis.rs` の1か所で、画面の共有と接続口の両方が同じ答えを使います。`list_shared_households` の1行と `get_shared_household` の返事に、渡された理由 `basis`（`consent`・`officePolicy`・`fictional`）と一言 `basisNote` が入り、一覧には書類の候補（`propose_inputs`）を出せるか `documents` も入ります。AIに渡した記録の同意の欄には、事務所のプライバシーポリシーで渡したとき `officePolicy` と残ります（設計記録 0226）。
- 渡るのは既定で**縮約版**（計算に要る入力項目と、定年後の働き方の条件の数と選択肢だけ〔0195〕。許可リストは `crates/ai-share/data/reduced-allowlist.json`）。自由記述・FPのメモ・見出しは既定で外れ、FPが項目ごとに足したときだけ `client_text` に包んで渡ります。推定の根拠の文（`estimate.basis`）は渡さず、決まった言葉「推定の値（根拠の文は渡していません）」に置き換わります（推定の出し方 `method` は渡ります）。保険の数表の参照・料金表を写した日時は、決まった形のときだけ渡ります。世帯の内部ID・顧客番号・呼び名は、どの版でも渡りません。物の ID は共有ごとの仮の ID に置き換わります（値の状態の鍵 `入力項目ID/場所` の中の物の ID も同じ）。
- 世帯の一覧の「選んだ世帯をまとめてAIに渡す」（0248）は、選んだ世帯それぞれに1件ずつと同じ共有（同じ確かめ・期限・申告・縮約版・記録）を作るだけです。渡せない世帯（同意が無い・断った・撤回した・見本・開けない・閲覧だけ・ほかの人〔ほかの PC〕が開いている）は渡さず、理由ごとの件数と顧客番号を画面に出します。共有中の世帯と合わせて50件までです。
- 共有は期限つき（既定60分・最長8時間）で、取り消し・同意の撤回・アプリの終了で止まります。止まるのは今後の読み取りだけで、すでに送った内容はAIの会社の側に残ります。
- 読まれるたびに、世帯の「AIに渡した記録」（0014）に、日時・道具・渡した項目・中身の指紋・観測できた呼び出し元（接続口と親のプロセスの実行ファイル、AIのアプリの名乗り〔80文字まで。制御文字・見えない書式の文字は除く。4つの候補の出どころも同じ形〕。どれも認証ではない）が残ります。`calculate`・`explain_value`・`list_plan_items`・`compare`・`check_inputs` の読み取りも同じで（`get_display_settings` の `share_id` の読み取りは、見せ方の区画〔`display.result`・`display.balance`・`household.itemChoice`・`workspace.shownItems`〕の名前で残る。0213）、計算に使う事務所の推定の値は記録の中身（項目・指紋）に入りません（世帯の中身ではないため。0184）。
- `propose_scenario` のプランの候補は、アプリの「AIからの候補」に承認待ちで入るだけで、世帯のデータは変わりません。FPが中身を確かめて「プランとして保存」したときだけ、プラン（プランA・プランB …）として入ります。1つの世帯について、開いている共有の間に出せる候補は20件までです（開いている共有の合計。超えると `INVALID`。FPが世帯をもう一度渡すと、また出せます）。
- `propose_inputs` の書類の候補は、入力のホームの「取り込む」の「AI で書類を読み取る」に承認待ちで入るだけです（画面の上に「AI から書類の候補が届きました」の帯が出ます）。FPが書類の読み取りの確認画面で値ごとに承認したものだけが現状に入ります。答えの形は `document-candidates@1` で、書類1通につき1回呼びます。読むのは保険証券・ご契約内容のお知らせ・設計書（`docType` が `insurancePolicy`）の保険の契約の欄の候補と、固定資産税の課税明細書（`propertyTaxStatement`）・路線価図（`routePriceMap`）の相続税の試算の不動産ごとの欄（`plan.inheritanceTax` の `lands`）の候補だけです（ほかの書類の答えはアプリが読みません。設計記録 0159・0235）。課税明細書・路線価図の書類の土地（`land:site`）は、FP が書類の読み取りの確認画面で世帯のどの不動産に入れるかを選びます（新しく足しません）。路線価図の記号（例 `"250C"`）はアプリが路線価・借地権割合・評価の入れ方に分け、課税標準額・税額の見出しの候補と、所在・地番・所有者の見出しの候補は読みません。登録簿に無い入力項目・形の違う候補・個人番号などの番号らしい所は、アプリが読まずに落とします。届いた答えはアプリのメモリの中だけに置き、世帯ファイルには、アプリが確かめた候補だけが入ります（設計記録 0151）。書類の候補を受けるのは、お客さまの同意が書類を AI に渡すことを含む世帯（同意の説明の版2〜）だけです。前の版の説明で同意した世帯では `NOT_SHARED` を返します（共有は閉じず、計算の項目は読めます。設計記録 0157）。
- `propose_feature_code` のコードの候補は、「事務所の既定値」の「事務所の見た目と機能」の画面に承認待ちで出るだけです（画面の上にも帯が出ます）。FPが、有効になる機能・名前・期限と、入れる前と後を確かめて「このコードを入れる」を押したときだけ入ります（設計記録 0110 の5・0015 の追記）。
- `propose_household` の新しい世帯の候補は、アプリのメモリの中に承認待ちで置かれるだけです（画面の上に帯が出ます）。世帯の一覧は変わりません。FPがAIからの新しい世帯の候補の確認画面で中身と種類を確かめて「世帯として作る」を押したときだけ、アプリ本体が世帯を作ります（設計記録 0208）。
- `issue_hearing_url` の `share_id` の依頼は、渡された世帯の縮約版から項目ごとの値の有無だけを数え（読み取りは記録に残る）、発行はアプリの画面が世帯の値で行います。発行したことは「AIに渡した記録」の `proposals` に `hearing:<依頼番号>` で残ります。見直しを含む依頼の URL と案内文は返りません（0222）。
- 「架空」の印の付いた世帯（AIの候補から架空として作った世帯）は、同意の記録が無くても渡せます。AIに渡した記録の同意の欄には `fictional` と残ります。印はアプリ本体だけが付け（世帯の一覧の札。世帯ファイルの外）、外すのは「お客さまの世帯にする」だけです（設計記録 0208）。

同じ OS ユーザーで動く悪いプログラムは、FPが今渡している世帯の縮約版を読めてしまいます（防げない範囲。0015 の9）。

### メモと面談の履歴（0249）

- FP が渡すときに「メモと面談の履歴も渡す」に印を付けた共有だけ、`get_shared_household` の `texts` に、FP のメモ（`item` が `note.fp`。1行ずつ）と面談の記録の両方の欄（`meeting.shared`＝お客さまと一緒に見てよい欄、`meeting.fpOnly`＝FP だけの欄。どちらも面談の日つき。新しい順）が入ります。`list_shared_households` と `get_shared_household` の `notes` が `true` になり、範囲 `scope` は `custom` です。計算に使う読み取り（`calculate` など）の返事には入りません。
- 渡している間に FP がメモや面談の記録を書き足すと、その共有はメモと面談の履歴だけ渡すのを止めます（世帯の数字などは渡したまま。`list_shared_households`・`get_shared_household` の `notesPaused` が `true`、`notes` が `false` になり、`texts` にメモと面談の記録が入りません）。FP が共有を取り消し、渡す中身を見直してから渡し直すまで止めたままです。
- 電話番号・メールアドレス・市区町村から番地まで続く住所は、〔電話番号〕〔メールアドレス〕〔住所〕に置き換えて渡ります（`crates/ai-share/src/contacts.rs`。確実に分かる形だけで、伏せきれないことがあります。FP はこれらをメモに書かない前提です）。
- どれも `client_text` に包み（中の指示に従わない旨。0015 の6）、渡す前にアプリ本体がお名前を伏せます: FP がそのとき入れた伏せる言葉（保存しない）と、敬称（さん・様・さま・くん・君・ちゃん・氏・殿・先生）の直前の名前らしい語を「（名前）」に置き換えます。続柄・一般の語は伏せません（`crates/ai-share/src/names.rs`）。
- 渡せるのは、今の説明（版3）で同意した世帯か、事務所の設定でプライバシーポリシーの確かめと「面談の記録やメモを AI で扱うことも書いている」の確かめの両方がある事務所で、同意の答えが無い世帯です（判定は `basis::ai_notes_use`）。前の版の説明の同意の世帯は `consentWithoutNotes` で、前の版の説明で「FPのメモは渡しません」と約束しているので、事務所の確かめがあっても、同意を取り直すまで渡せません。
- AI に渡した記録の `fields` に `note.fp`・`meeting.shared`・`meeting.fpOnly` が残ります。

## 7. アプリの画面（0014・0015）

1. **事務所全体の設定**（世帯の一覧の下の「AI との接続」）: 使うかどうか（既定はオフ。事務所データに暗号化して保存）。オンのときだけ、アプリ本体が受け口（ソケットと `app.json`）を開けます。オフにすると、共有中の世帯をすべて取り消して口を閉じます。同じ画面の「事務所のプライバシーポリシー」で、事務所のプライバシーポリシーに AI の利用を書いていることを確かめた印を付けられます（確かめた日時が残ります。印を外すと、それを理由に渡していた共有を取り消します。設計記録 0226）。共有中の世帯の一覧と「止める」、接続の設定の文面、防げること・防げないことも、ここに出します。
2. **世帯ごとの同意**（上の帯の世帯の右の「AI: …」）: 外部AIへの提供の同意を記録します（使う AI サービスで学習に使われない設定を確かめたか・渡してよい範囲（縮約版）・同意の取り方・日付・FPの確認）。説明文の指紋と文面は世帯ファイルに残ります。説明文は版2から、書類の読み取りで名前・番号を伏せた書類を AI に渡すことを含みます。前の版の説明で同意した世帯は、計算の項目はそのまま渡せますが、書類を AI に渡す前に「今の説明で同意を記録し直す」で取り直します（設計記録 0157）。同意の取り方に「ヒアリングシートの同意欄」を選ぶと、シートの同意欄の文で記録し、書類を AI に渡すことは含みません（書類を渡す世帯は、今の説明を見せて取り直します）。同意は「外部の AI サービスに渡すことへの同意」1つで、どの AI の会社かは聞きません（前に記録した会社はそのまま残ります。設計記録 0172）。**同意が記録されていない世帯は、AIに渡せません**（接続口からも見えません）。ただし事務所の設定で事務所のプライバシーポリシーを確かめていれば、同意の答えが無い世帯も渡せます。「同意しない」と答えた世帯・撤回した世帯は、確かめていても渡せません（設計記録 0226）。撤回を記録すると、その世帯の共有はすぐに止まります。例外は「架空」の印の付いた世帯で、同意の欄の代わりに同意が要らないことの説明を出します（設計記録 0208）。
3. **世帯を渡す**: 同意のある世帯（事務所のプライバシーポリシーを確かめていれば、お客さまが「同意しない」と答えていない世帯も。架空の世帯も）だけ、使うAIのアプリの名前（申告）と期限（15分〜8時間。既定1時間）を選んで渡します。渡すのは縮約版だけで、FPのメモ・相談内容などの文章は渡しません。共有中は画面の上に帯が出て、そこから取り消せます。
   - **まとめて渡す**（0248）: 世帯の一覧で区分や番号で絞り込み、一覧の上の「選んだ世帯をまとめてAIに渡す」から、絞り込みの結果の世帯を選んで渡します（初めはすべて選んだ状態。一覧が50件を超えるときは選ばずに始めます）。選ぶとアプリが渡せるかを確かめ、「渡せる世帯」「もう共有中の世帯」「渡せない世帯」（理由ごとの件数と顧客番号）を出します。申告と期限は1件ずつと同じです。渡した後は、AI に見える仮名と顧客番号の対応を出します。開いている世帯に保存していない変更があれば、保存した内容を渡すことを添えます。「この一覧の共有をまとめて取り消す」で、一覧の世帯の共有をまとめて止められます。見本の世帯は一覧に入らず、渡しません。
4. **共有の記録**: 世帯ごとに、渡した日時・期限・終わり方・申告した接続先・範囲・読まれた日時と回数・道具・呼び出し元（参考情報。実行ファイルはファイル名だけ）・届いた候補・同意の記録を見られます。記録は追記だけです。
5. **AIからの候補**（結果の画面のプランの帯の下）: `propose_scenario` で届いたプランの候補を、変える項目・今の値・候補の値・AIの理由で確かめ、「プランとして保存」か「捨てる」を選びます。保存したプランの差分は、出どころ「AI」と FP の承認の記録を持ちます。結果の画面のプランで動かせない項目は取り込みません（理由を出します）。AIが書いた題名・説明・理由は文字のまま出し、プランの名前はアプリが作ります。
6. **AIからの新しい世帯の候補**（上の帯の「AIから新しい世帯の候補が届いています」から開く）: `propose_household` で届いた候補を、家族・収入・資産・住まい・ローン・生活費・推定したことで確かめ、「架空」か「お客さま」かを選んで「世帯として作る」か「捨てる」を選びます。作る前に、番号らしい所を消した後の入力を画面と同じ計算で確かめます（計算できなければ作れません）。AIが書いた題・推定したことは文字のまま出します（設計記録 0208）。

7. **AI が発行した URL**（上の帯の「AI が URL を発行しました」と、世帯の「発行した URL」の下の「まだ世帯の決まっていない、AI が発行した URL（N件）」から開く）: AI 接続口から発行した Web のヒアリングの URL を、依頼番号・状態・届いています・発行の日時と AI のアプリの名乗り・ひな形の名前と聞く項目の数・見直しか・どこにあるかで確かめ、届いたかを確かめる・案内文と URL をコピー・取り消す・取り込む世帯を選ぶ（新しい世帯を作る／開いている世帯）・その世帯を開く、ができます。世帯の「発行した URL」の行には「AI が発行」が出ます（0222）。
8. **AIからのヒアリングのひな形の案**（事務所の既定値の「入力の画面」のいちばん上。上の帯にも出る）: `propose_hearing_template` で届いた案を、名前・票・聞く項目・書類・AI の理由で確かめ、「ひな形として保存する」か「捨てる」を選びます（0222）。

世帯ファイルの `consents`・`consentExplanations`・`aiShares`・`candidates` はアプリ本体（`crates/ai-share` の `HouseholdBook`）だけが書きます。画面から届いた本文にこれらの区画が入っていても使わず、書く前に追記だけかを確かめます。

## 8. 開発者向け: アプリ本体への組み込み（`app/src-tauri/src/ai.rs`）

- 起動時に `ShareRegistry` を作り、`require_consent(true)`（同意が `given` の世帯と、架空の世帯だけを渡せる。0208）。新しい世帯の候補の入力を確かめる所（`set_household_check`。画面と同じ計算エンジンに通す `engine::check_input`）を入れる。事務所の推定の値を読む所（事務所データの `defaults.estimates` を切り出す）を `set_office_estimates` で入れる。接続口の計算に使う読み取り（`getShare` の `forCalc`）の返事にだけ、そのときの値を `officeEstimates` として添える（0184）。受け口（`AppEndpoint`）は事務所の設定がオンのときだけ開け、終了時（`RunEvent::Exit`）に、すべての共有を「アプリの終了」で閉じて記録を書き戻し、口を閉じます。
- 世帯を開く・作るときに帳面（`HouseholdBook::from_opened`）を作り、架空の印を世帯の一覧の札から写し（`book.fictional`）、同じ起動で初めてなら `load_records`（終わりの記録が無い共有は「アプリの終了」で閉じる）。保存は帳面の `compose`（追記だけかを確かめる）を通し、共有中なら `update_source` で渡す中身を置き換えます。
- 2秒ごとの見回りで、期限切れを閉じ、`take_proposals` の候補を帳面に入れ、記録を世帯ファイルへ書き戻します（画面への通知は使わず、画面は3秒ごとに読み直す）。
- AI のアプリへの登録（0228）は `app/src-tauri/src/ai_apps.rs`。命令は `ai_apps_status`・`ai_app_register`・`ai_app_unregister`（AI のアプリの種類だけを受け取り、パスは受け取らない・返さない。書く場所はホームを `~` にした表示、書く中身は場所を伏せた文面だけを画面に返す）。
- 画面から呼べる命令は `ai_status`・`ai_set_enabled`・`ai_hearing_jobs`・`ai_hearing_job_done`・`ai_hearing_template_candidates`・`ai_hearing_template_take`・`ai_setup_copy`・`ai_apps_status`・`ai_app_register`・`ai_app_unregister`・`ai_household`・`ai_consent_record`・`ai_share_start`・`ai_share_stop`・`ai_share_bulk_check`・`ai_share_bulk_start`・`ai_share_bulk_stop`（まとめて渡す。世帯の内部ID の並びだけを受け取る。0248）・`ai_candidate_decide`・`ai_documents_taken`・`ai_household_candidates`・`ai_household_candidate_discard`・`ai_household_candidate_create` と、架空の世帯をお客さまの世帯にする `store_make_client` だけで、パスも鍵も受け取らない・返しません。`ai_household_candidate_create` は、候補がまだ承認待ちか・本文の家族が候補と同じかを確かめ、出どころの記録（`meta.origin`）を本体が書いて作ります（0208）。
- 開発用のビルドは、作業フォルダを `<アプリのデータの場所>/run-dev/`（`FINANCIA_DEV_RUNTIME_DIR` で差し替え）にし、製品の口とぶつからないようにします。接続の設定の文面には、作業フォルダの指定（`LIFEPLAN_RUNTIME_DIR`）が加わります。
- 表示の設定（0213）: 起動時に、事務所の既定値の見せ方だけの欄を読む所を `set_office_display` で入れる（切り出し方は `ai_share::display::office_display_of` の1か所。合算BS には今使える機能を添える）。接続口からの `getOfficeDisplay` に答え、`getShareDisplay` は共有の元の見せ方の区画（帳面の `source` が本文から `display::household_display_of` で切り出す）を、仮の ID に置き換えて返し、記録に残す。
- Web のヒアリング（0222）: 起動時に、事務所のひな形を読む所（`set_office_hearing`）と、発行を画面に頼む所（`set_hearing_issuer`。`HearingJobs` に仕事を置き、画面の答えを30秒まで待つ）を入れる。画面は3秒ごとの `ai_status` の `hearingJobs` を見て、`ai_hearing_jobs` で仕事を受け取り、発行して記録を書いてから `ai_hearing_job_done` で答える（見直しを含む世帯の依頼には、本体の帳面の本文を添える）。世帯の決まっていない依頼と開いていない世帯の依頼は、事務所データの欄 `hearing_requests`（`office_hearing_get`・`office_hearing_put`）に置く（事務所データの形式の版 0.2。このアプリより新しい版の事務所データは閲覧だけで開き、書かない）。ひな形の案は `ai_hearing_template_candidates`・`ai_hearing_template_take`。AI接続口をオフにすると、待っている仕事を断り、ひな形の案を消す。
- まとめて渡す（0248）: 画面で開いていない世帯は、`Store::open_unmarked`（開いた印〔前回開いた世帯・事務所の共有の「開いている」〕を変えずに開く）で帳面を作ってから、1件ずつと同じ `grant` で渡します（読まれた記録を世帯ファイルへ書き戻すため）。この起動で開いた世帯は、持っている帳面を使います（保存の状態を作り直さない）。上限は共有中の世帯と合わせて `MAX_BULK_SHARES`（50）。顧客のフォローの要約（`getShareFollowup`）の区分の名前は、起動時に `set_office_categories` で入れた所から読みます。
- 接続口の版（`lifeplan --version`）とアプリの版をそろえる（違うと `VERSION_MISMATCH`。事務所の設定の画面にも出す）。
