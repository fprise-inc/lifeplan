# 0122. 暗号資産を金融資産の器の種類にする（取り崩さない・売ったときの雑所得の税は計算しない）と世帯ファイルの形式 0.60

- 状態: 採用（一部未確定）（2026-11-05）
- 固定の強さ: 骨格は、器の種類 `cryptoAsset`（暗号資産）の名前と意味（金融資産の合計に入れる・取り崩さない〔0124 で、2028年からの申告分離課税で取り崩す形に改めた〕・器の利回りも資産の配分も無ければ利回り0・既定の時価の下落の対象）、残高の行 `cf.balance.account.cryptoAsset` と積立の行 `cf.transfer.savings.cryptoAsset`、その他の資産の細目 `cryptoAsset` をなくしたこと、形式 0.60 の変換の段。画面の欄の並び・説明の文・ボタンの置き場所・箱の色・相場の下落の選択肢の言葉は後から変えてよい（変えたら追記に書く）
- 前提にする記録: 0004（科目の木）、0008 の9（資産の器）、0011（形式の版と変換の段）、0025・0027（全資産・全負債のバランスシート）、0026（資産運用・取り崩し・時価の下落）、0044（入るお金の行と課税の扱い）、0071（万一の前提の相場の下落）、0120（その他の資産の中身の細目）

## 背景

- 0120 で、その他の資産（器の種類 `otherAsset`）の中身の細目に暗号資産 `cryptoAsset` を足した。その他の資産は金融資産に入れず、取り崩さず、時価の下落の対象から外し、評価額は増減率だけで動く。
- 利用者の判断: 暗号資産は「その他の資産」の細目ではなく、金融資産の口座の種類にする。貯蓄・運用の金融資産の「＋ 預貯金 ＋ NISA ＋ iDeCo ＋ 課税口座」の右の「そのほか」（財形・企業型DC・外貨預金・持株会・小規模企業共済・旧NISA など）の中に「暗号資産」を足す。
- 利用者の判断: 売ったときの税は雑所得（総合課税）。エンジンの課税口座は上場株式等の分離課税なので、そのままでは合わない。取得価額を持ち、取り崩したときの利益を雑所得として所得に入れるのが正しい形。エンジンでそれができるなら作り、大きすぎるなら取り崩しの対象から外して評価額だけを持つ形にする。
- あわせて、入るお金の行「動産の売却（車以外）」の説明が、貴金属・美術品を非課税の既定のまま例に挙げていた。生活に通常必要でない動産（貴金属・宝石・書画・骨董・美術工芸品など）で1個または1組の価額が30万円を超える物の売却は、譲渡所得として課税される（所得税法9条1項9号・所得税法施行令25条）。

## 決定

### 1. 器の種類 `cryptoAsset`（暗号資産）

- 器の種類に `cryptoAsset` を足した（エンジンの `AccountKind`・入力のスキーマ・画面の種類の一覧 `labels.ts` の `ACCOUNT_KINDS`「暗号資産」）。
- その他の資産の細目から `cryptoAsset` を外した（エンジンの型・入力のスキーマ・画面の中身の選択肢・バランスシートの細目の名前）。0120 の骨格の細目の値のうち、この1つだけを外す（0120 の追記）。

### 2. 金融資産としての扱い（計算エンジン `plan.cashflow` 改訂20）

- **金融資産の合計に入れる**（`cf.balance.financial`）。残高は器ごとの行 `cf.balance.account.cryptoAsset`（物の ID・名義つき）。相続税の目安でも金融資産として数える（`inheritance.estimate` は変えていない。金融資産の器の扱いのまま）。
- **取り崩さない**（0124 で、2028年から取り崩す形に改めた。以下はこの記録の時点の決定。`NEVER_WITHDRAWN`。iDeCo・企業型DC・不動産・その他の資産と同じ）。取り崩しの順番（`assumptions.withdrawal.order`）に書いても取り崩さない。画面の取り崩す順番にも並べない（`savings/model.ts` の `NOT_ORDERED`）。預金が尽きても売らないので、資金の不足（`cf.balance.shortfall`）が出る。
- **利回り**: 器の利回り（`expectedReturn`）か資産の配分（`assetMix`）があればそれ。どちらも無ければ **0**（今の評価額のまま。`sdk/helpers.ts` の `specRate`、画面の目安 `plans/allocation.ts` も同じ）。利回りの段階・例外の年（0040）は使える。運用する器（`INVEST_KINDS`）には入れないので、資産配分の入れ方（0026 の allocation）の共通の配分・信託報酬と、利回りの書き換え（`returnShifts`）は当てない。
- **資産クラス**: 資産クラスの一覧（`assetClass`）に暗号資産は足さない。画面は暗号資産の器に「＋ 資産の配分」を出さない（入っていれば今までどおり見せる）。
- **時価の下落**: 器の種類を書かない下落（`marketShocks` の `kinds` も `assetClasses` も無い下落）の対象にする（`SHOCK_EXEMPT` に入れない）。資産クラスを書いた下落は、配分の無い暗号資産を下げない（`shockShare` が運用でない器として null）。`kinds` に `cryptoAsset` を書けば器ごと下げる。万一の前提の「相場の下落」の下げる資産に「暗号資産」（`kind:cryptoAsset`。器ごと）を足した。既定の並び（株・REIT・持株会）には入れない（外貨預金と同じ）。
- **積立**: 積立（`contributions`）は決済口座から出て、行 `cf.transfer.savings.cryptoAsset`（暗号資産の積立）に出る。0004 の科目の木の上2段は変えない（器の間の移動 `cf.transfer` の中分類 `savings` の下の明細に足した）。
- 取得価額（`costBasis`）は持てるが、計算に使わない（画面にも出さない）。引き出せない期間（`withdrawalLockedUntil`）は意味が無いので画面に出さない。（0124 で、取得価額を取り崩しの税に使い、どちらの欄も画面に出すようにした）
- 合計の入れ方（0026 の total）では、ほかの金融資産の器と同じく、まとめた金融資産の器の中に入る（暗号資産の器は外れ、まとめた器の取り崩しに含まれる）。
- 取り崩しの計画の率（`investment.drawdown.rate`）の元の「年の初めの金融資産」には入る（iDeCo と同じ）。

### 3. 売ったときの税: 取り崩しの対象から外し、評価額だけを持つ形にした（0124 で改めた）

- **0124 で改めた**: 令和8年度税制改正の特定暗号資産の申告分離課税（2028年1月から）の前提で、2028年からは課税口座と同じに取り崩し、利益に分離課税の税をかける。2027年までと、税の扱いを雑所得にした暗号資産（欄 `cryptoTaxation`）は、下のとおり取り崩さない。下の「作らなかったもの」は、2027年までと雑所得の物について今も同じ。

- **作らなかったもの（利用者の判断の「正しい形」）**: 取り崩した暗号資産の利益（売った額−取得価額）を雑所得としてその年の所得に入れ、所得税・住民税（と、それに連なる国民健康保険料・後期高齢者医療の保険料・高額療養費の区分・住民税の非課税の判定など）を計算し直す形。
- **理由**: 取り崩しは `plan.cashflow` が年ごとに、税・社会保険料を計算し終えた後の年間収支の不足から決めている。課税口座の譲渡益の税は分離課税で税率が一定なので、取り崩しの中で税を引いて売る額を決められる（二分探索）。雑所得は総合課税で、ほかの所得と合わせた累進の税率と、所得で決まる保険料・給付に効くので、取り崩す額を決めるには、その年の税・社会保険料の部品をもう一度呼び直す（年ごとに計算の順番を入れ替える）必要がある。今のエンジンは部品を依存の順に1回ずつ呼ぶ作り（0005・0006）で、これを変えるのは計算エンジン全体の作りの変更になり、この作業には大きすぎる。
- 一律の税率で近似して取り崩す形も採らなかった（総合課税の税率は人と年で 15%〜55% と大きく違い、黙って結果が変わる）。
- FP が売る予定を入れたいときは、売る額を入るお金の行（課税の扱い「雑所得（その他）」、取得費の欄に買った額。雑所得として、ほかの所得と合わせて税を計算する）で入れ、売る分を暗号資産の残高から外す（二重に数えないため。画面のまとまりの説明に書いた）。

### 4. 画面

- 貯蓄・運用の区画「金融資産」の足すボタンに「＋ 暗号資産」（詳細。持株会の後）。簡易では「そのほか ▾（財形・企業型DC・外貨預金・持株会・暗号資産・小規模企業共済・旧NISA など）」から出す。
- 欄は種類・名義・今の残高（時価）・残高の時点（詳細）・毎月の積立・利回り（年。空欄は0、「?」に「入れなければ0」）。積立があれば積立の終わり（詳細）。まとまりの説明に、金融資産の合計に入るが取り崩しには使わないこと・その理由・売る予定の入れ方を書いた。「続きを見る」の文は「残高の時点を入れる」（積立があれば「残高の時点・積立の終わりを入れる」）。
- その他の資産から種類を「暗号資産」に変えたら、中身の細目を外し、評価額の増減率（`valueGrowth`）を器の利回り（`expectedReturn`）へ移す。
- 区画「その他の資産」の説明から暗号資産を外し、「暗号資産は上の金融資産の『そのほか』の『暗号資産』で入れます」を足した。
- 探して開く（`searchWords.ts`）: 暗号資産・仮想通貨・ビットコイン・イーサリアム・BTC・ETH を、その他の資産から貯蓄・運用の「暗号資産」へ移した。
- 口座の表の並び（`KIND_ORDER`）は外貨預金の次。資産の推移の口座の内訳のまとまりは「課税口座など」、資産の内訳のドーナツ（口座ごと）は「暗号資産」、資産の種類ごとは「暗号資産」（配分が無いとき）。

### 5. バランスシート・提案書

- 分け方の部品（`report/src/bsGroups.ts`）: 暗号資産は「値動きのある運用」（金融資産）の項目「暗号資産」（持株会の後、まとめた金融資産の前）。資産と負債のタブ・提案書のバランスシートの図・お金の3つの分け方はこの部品をそのまま使う。箱の色は値動きのある運用の青の仲間（`--bs-cryptoAsset: #1f6386`。白い文字との差 6.6:1）。
- 提案書の年の抜粋の表（`build.ts` の `sheetOf`）は金融資産の行に入る。資産運用の計画のまとまりは「課税口座など」、器の名前は「暗号資産」。

### 6. 世帯ファイルの形式 0.60

- 器の種類を足し、細目を外したので、形式の版を `0.60` に上げた（0011 の5。MINOR）。前の版のアプリは種類 `cryptoAsset` を入力の検査で通さないので、閲覧だけにする。
- 変換の段（0.59 → 0.60）:
  - 現状の世帯の器のうち、細目 `cryptoAsset` のその他の資産を種類 `cryptoAsset` へ移す（細目を外し、評価額の増減率 `valueGrowth` は器の利回り `expectedReturn` へ。器の利回りがあればそちらを残す。値の状態の行の鍵 `account.valueGrowth` は `account.expectedReturn` に、`account.subtype` の行は外す）。
  - プランの差分: 足す器（`op: add`・`collection: account`）は同じに直す。移した器の増減率の差分は器の利回りの差分にする。移した器の細目の差分と、ほかの器の細目を `cryptoAsset` にする差分は捨てる（細目は計算に使っていなかったので、そのプランの計算の結果は変わらない）。
  - 表示した項目（`workspace.shownItems`）・確かめた記録（`household.agreed`）・次回確かめる印（`household.recheck`）の鍵を合わせる（`field:sav/<器>/growth` → `rate`、`subtype` は外す）。
  - 控え・ヒアリングの記録の中身は変えない。画面が控えを計算するときは、なくした細目を外して、控えのまま「その他の資産」で計算する（`surplus.ts` の `withoutRemovedAssumptions`。控えの結果は変わらない）。
  - 移した物があれば、開いたときの知らせ `cryptoAccounts`（移した数・プランの差分を変えた数）を足す。画面は「暗号資産を金融資産の口座にしました」と、結果が前と変わることがあることを出す。
- 見本 `crates/household-store/tests/fixtures/household-format/0.60/` は、0.59 の見本の暗号資産の細目の器を暗号資産の器（器の利回り 2%・2030年12月までの毎月1万円の積立）にした物。

### 7. 「動産の売却（車以外）」の説明（`app/src/workspace/input/moneyRows.ts`）

- 家具・衣服など生活に使う物を売ったお金は非課税、貴金属・宝石（貴金属を使った時計・装身具を含む）・書画・骨董・美術工芸品で1個（1組）30万円を超える物と、金地金など生活に使うためでない物を売った利益は譲渡所得（総合課税。特別控除年50万円、5年を超えて持った物は2分の1）と書いた。貴金属・美術品を非課税の例として並べるのをやめた。
- この計算には総合課税の譲渡所得の区分が無いので、利益が出るときは課税の扱いを「一時所得」にして取得費を入れると、5年を超えて持った物と同じ形の目安になる（5年以内は少なめに出る）と書いた。その他の資産に入れた物は評価額と二重に数えないこと、暗号資産は動産でなく「暗号資産」で入れることも書いた。課税の扱いの既定（非課税）は変えない（多くは生活に使う物の売却で、既定を変えると今の世帯の結果が黙って変わる）。

### 8. 合わせた所・合わせなかった所

- AI に渡す縮約版の許可の一覧（0015。`crates/ai-share/data/reduced-allowlist.json`）: 入力項目ID で選ぶ形で、`account.kind`・`account.contributions`・`account.expectedReturn` は入っている。値は決まった一覧の記号なので、一覧も版も変えない。
- ヒアリングシート: 口座の欄は預金・課税口座・NISA・iDeCo・企業型DC だけで、外貨預金・持株会などと同じく暗号資産の欄は無い。シートの版が上がるので足さない（未確定）。
- 入力項目ID の登録簿（`registry/items.yaml`）の `account.subtype` の名前から暗号資産を外した。行の登録簿（`registry/rows.yaml`）に2行を足した。

## 理由

- **金融資産に数え、取り崩さない**: 利用者の判断（金融資産の口座の種類）に合わせ、家計の金融資産・バランスシートで暗号資産が見えるようにした。取り崩しに使うと、税を計算しないまま（または近似のまま）手取りを家計に入れることになり、税の分だけ資金が尽きる年が遅れて見える。取り崩さなければ、資金の不足が出る年は暗号資産が無い場合と同じで、金融資産の合計（＝資産が尽きる年の判定）には評価額が残る。売れば足りる、という読み方は iDeCo（受け取りの前）と同じ。
- **利回りの既定を0にする**: 根拠を示せる見込みの利回りが無い。運用利回り（前提）を当てると、株式などと同じ伸びを黙って見込むことになる。FP が見込みを入れれば、その利回りで動く。
- **既定の時価の下落の対象にする**: 値動きの大きい資産で、預金・外貨預金のように下げない器に入れる理由が無い。万一の前提の相場の下落では、株・REIT と同時に下がるとは限らないので、既定に入れず選べるようにした。
- **形式の版を上げて移す**: 細目と種類で同じ物を書けると、計算の扱いが2つになる。前の版の細目の器は、細目が表示だけだったので、移しても FP の入れた値は失われない（増減率は利回りへ）。

## 代案（採らなかったもの）

- 取り崩しに使い、雑所得の税を計算する（利用者の判断の「正しい形」）: 上の 3 の理由。作るなら、年ごとに税・社会保険料の部品を呼び直す作り（下の未確定）。
- 取り崩しに使い、税をかけない（まとめた金融資産の器と同じ）: 税の分だけ結果が甘くなる。
- 課税口座と同じ分離課税の税率で近似する: 総合課税と税率が大きく違う。
- その他の資産のまま、細目ごとに金融資産に数えるかを変える: 細目を計算に使わない 0120 の骨格に反し、画面の置き場所も利用者の判断と違う。
- 資産クラスに暗号資産を足す（前提の利回り・値動きを資産クラスで持つ）: 公的な統計・目安が無く、資産配分の入れ方の配分にも入ってしまう。
