# 0018. ヒアリングシートの形式

- 状態: 採用（一部未確定）（2026-10-08）
- 固定の強さ: β公開から変えない（骨格）。ヒアリングシートの形式とシート定義は、β公開の時点で「安定」とする（一度配ったシートは、後のどの版のアプリでも取り込める）

## 背景

面談の前に顧客から家族・収入・年金・住まい・保険などの情報を集めるために、ファイナンシアは世帯ごとにヒアリングシートを書き出す。最初の版は Web フォームではなく、Excel（.xlsx）と印刷用 PDF にする。

- FPのアプリがシートを書き出し、FPが顧客に送る（メール・紙など。送り方はFPが決める）。
- 顧客が記入して返し、FPがアプリで取り込む。取り込んだ値は候補として並び、FPが承認する。
- FPライズはシートのやりとりに関与しない。

配ったシートは顧客の手元に残り、何か月も後に返ってくることがある。その間にアプリが更新されても取り込めなければならない。また、Excel は顧客が自由に編集・保存し直せるので、行の挿入や別のソフトでの保存（Numbers・Google スプレッドシートなど）で形が崩れても、誤った項目に値を入れてはならない。

関連: ID体系（ヒアリング項目のキー `hs.*`）は 0004、金額と単位は 0002、時間の規約は 0003、世帯のデータモデルと候補は 0008、拡張領域は 0011、持たない情報は 0012、同意の記録は 0014、カスタム層の設定は 0016、PDF（Typst）は 0009。

## 決定

### 1. 1つのシート定義からすべてを作る

- **シート定義**（JSON）を唯一の正とし、Excel・印刷用 PDF・取り込みの規則をそこから作る。シート定義の形式は JSON Schema で定め、公開する。
- 置き場所はリポジトリの `hearing/sheets/<シートID>/<版>.json`。公式のシートは次の3つから始める。
  - `basic` … 初回用の簡易版（1〜2ページ）
  - `full` … 詳細版
  - `review` … 見直しの面談用の確認シート（前回の値を記入して書き出す。FPが選んだときだけ）
- シート定義が持つもの: シートID、版、項目の一覧（項目キー、表示名、入力の型、単位、選択肢、記入例、転記の手引き、繰り返しの数）、ページとセルの配置、**項目キー→入力項目ID（0004）の変換表**、追加された版・廃止された版。
- 公開した版のシート定義は変えない。変えるときは新しい版を作る。アプリには、公開したすべての版のシート定義を同梱し続ける。

### 2. 版番号と管理の値を3か所に埋め込む

書き出す .xlsx に、次の管理の値を埋め込む。

| 値 | 例 | 用途 |
|---|---|---|
| 形式名 | `fprise-lifeplan-hearing` | このソフトのシートかの判定 |
| 形式の版 | `1.0` | 埋め込みの形そのものの版（`MAJOR.MINOR`。0001） |
| シートIDと版 | `full` / `3` | どのシート定義で読むか |
| 依頼番号 | `R-7K3P9Q`（乱数） | アプリの中の「依頼の記録」と結びつける |
| 表示用の顧客番号 | `A0042` | FPと顧客が紙・画面で見分けるため |
| 配置の指紋 | SHA-256 | FPが項目を選んで作ったシートの配置の照合 |
| 書き出したアプリの版・日時 | `1.2.0` / `2027-02-10` | 調査用 |

- 埋め込む場所は3か所にする（どれかが別のソフトでの保存で失われても読めるように）。
  1. 隠したシート `_lifeplan`（Excel の「非常に隠す」状態）に、上の値をキーと値の2列で書く。
  2. 文書のユーザー設定のプロパティに、同じ値を書く。
  3. 1枚目の見える位置に「管理欄」として、シートIDと版・依頼番号・顧客番号を印字する（紙で返ってきたときにFPが読めるように。印刷用 PDF にも同じ欄を入れる）。
- 取り込むときは、見つかった値どうしが食い違えば取り込みを止め、FPに見せる。
- **世帯の内部ID は埋め込まない**。シートは暗号化されないままメールなどで行き来するので、内部ID は暗号化したファイルの中だけに置く（0012）。シートと世帯は依頼番号で結びつける。依頼の記録（依頼番号・シートIDと版・配置の指紋・書き出した日時）は世帯ファイルの取り込みの記録に暗号化して残す。
- 名前の欄は作らない。シートに「お名前は書かないでください」と明記する。

### 3. 項目キー

- 項目キーは `hs.<分野>.<項目>` の点区切りの英字（例: `hs.income.salary`、`hs.pension.notice.type`）。命名は 0004 に従う。
- **キーは変えない・使い回さない**。意味が変わるときは新しいキーを作り、古いキーは「廃止」として定義に残す（過去の版のシートを読むため）。
- 家族の人数や保険の件数のように繰り返す項目は、キーは1つにし、何番目かを別に持つ（例: `hs.family.birthYearMonth` の3番目）。繰り返しの上限はシート定義に書く。
- FPの独自の質問は、最初の版では自由記述のメモ欄だけにする（計算には使わない）。キーは拡張の名前空間 `ext.<作成者>.<項目キー>` に予約しておく（0011）。

### 4. セルの配置

- 回答のセルの位置は、シートIDと版ごとに固定し、シート定義に書く。
- 回答のセルには、Excel の「名前の定義」も付ける。名前は項目キーをそのまま使い、繰り返しは `_n` を付ける（例: `hs.income.salary`、`hs.family.birthYearMonth_3`）。
  - 取り込みは、まず名前の定義でセルを探し、シート定義の固定の位置と一致するかを確かめる。顧客が行を挿入して位置がずれていても、名前の定義が付いていけば読める。名前と位置が食い違う項目は「要確認」として候補に出し、黙って読まない。
- 回答の状態（値／未回答／わからない／該当なし）は、値のセルの隣に「状態のセル」を置き、選択肢（「わからない」「該当なし」）で選ばせる。値も状態も空なら「未回答」。数値のセルに文字を混ぜないための形。
- 金額は単位（円・万円、月額・年額）を項目ごとにシートに表示し、取り込みで円の整数（0002）にそろえる。生年月は西暦の年と月の選択肢（和暦を併記）で受ける。
- 入力規則（選択肢・数値・整数の範囲）、記入例、書類のどの欄を写すかの見本（転記の手引き）を入れる。
- シートは回答のセル以外を保護する（パスワードは付けない）。形を崩しにくくするためで、守りのためではない。
- **マクロは使わない**（.xlsx で書き出す）。インターネットから来たファイルのマクロは既定でブロックされるため。
- 1枚目に、事務所名・利用目的・FPの個人情報保護方針の連絡先、用意してほしい書類の一覧、同意の欄（利用目的の確認、家族の情報の扱い、外部AIへの提供〔任意〕）を置く。同意の欄は取り込むと世帯の同意の記録（0014）に入る。
- 聞かないこと（健康の実在の状態、マイナンバー・基礎年金番号などの番号類、口座番号、書類の画像）は、シートに「聞きません」と明記し、欄を作らない（0012）。
- 学校名・保険の商品名は自由記述で受け、取り込むときにアプリで照合する。

### 5. FPが項目を選んで作るシート

- FPは、カスタム層の設定（0016）で、項目の選択と並びを変えられる。項目キーは公式のものをそのまま使い、配置だけが変わる。
- 選び方から作った配置は、シート定義と同じ形で書き出し、指紋（配置の指紋）を付ける。
- 取り込むときは、**アプリの側に残した依頼の記録と配置**を正として読む。シートに埋め込まれた値は依頼を見つけるためだけに使い、配置の情報としては信用しない（顧客の手元で書き換えられうるため）。
- 依頼の記録が見つからないとき（別のPCで取り込むなど）は、公式のシートなら同梱のシート定義で読む。FPが作ったシートなら、カスタム層に残った同じ指紋の配置を探し、見つからなければ取り込まずにFPに知らせる。

### 6. 取り込み

- 取り込みは、他のソフトからの移行で使う汎用 Excel と同じ取り込みの画面で行う。ただしシートの形が決まっているので、AIを使わず、決まった手順で読む。
- 返ってきたファイルは信用しない。
  - 受け付けるのは .xlsx だけ（.xls・.ods・.numbers などは「.xlsx で保存し直してください」と案内する）。
  - マクロ・外部リンク・埋め込みのオブジェクトは読まず、実行もしない。
  - 数式は評価しない。回答のセルに数式があれば、保存されている計算結果の値を「要確認」として候補に出す。結果の値が無ければ読まない。
  - ファイルの大きさ、zip を展開した後の大きさ、中のファイル数に上限を置く（巨大なファイル・壊れたファイル・展開すると膨らむファイルへの対策）。
  - 読むのは、管理の値と、シート定義（または依頼の記録の配置）が指すセルだけ。他のセル・他のシートは読まない。
- 読んだ値は、シートの版ごとの変換表で入力項目ID に写し、さらに今のデータモデルへの変換を順につないで、候補（出どころは「ヒアリング」）にする。知らないキーは「取り込み保留」として残し、FPに見せる。
- 「わからない」は値の状態「わからない」として取り込み、面談のチェックリストに載せる。
- 取り込んだ元の回答（伏せ字の処理をした後）は、世帯ファイルの取り込みの記録に暗号化して残す。元の .xlsx ファイルそのものは保存しない。

### 7. 過去の版の取り込み

- アプリは、公開したすべての版のシート定義と変換表を同梱し続ける。新しいアプリが古い版を読めなくなる変更はしない。
- 各版について、架空の値を記入した .xlsx の見本をテスト用に作り、リポジトリに永久に残す。

### 8. 印刷用 PDF

- 同じシート定義から Typst で作る（0009）。項目・選択肢・管理欄はシート定義と同じ。
- 紙で返ってきたものは、FPがアプリで入力する（読み取りの機能は最初の版では作らない）。

### 9. 前回の値を記入した確認シート

- 見直しの面談用に、前回の値を記入した `review` シートを、FPが選んだときだけ書き出せる。
- 書き出す前に「暗号化されない Excel に金額が載ります」と警告し、書き出したことを記録する。既定の保存先は、カスタム層・AIの作業フォルダの外にする（0020）。

## 理由

- **シート定義を唯一の正に**: Excel・PDF・取り込みの規則を別々に作ると、項目や配置がずれ、ずれた分だけ誤った項目に値が入る。
- **キーを使い回さない**: 古い版のシートは何か月も後に返ってくる。同じキーが別の意味に変わると、古いシートの値が黙って別の項目に入る。
- **3か所に埋め込む**: 隠したシートやユーザー設定のプロパティは、別のソフトで保存し直すと失われることがある。見える管理欄は、紙で返ってきたときにも使える。
- **名前の定義と固定の位置の照合**: 固定の位置だけだと、顧客が行を1つ挿入しただけで全部ずれる。名前の定義だけだと、名前を消されたときに気づけない。両方を照らし合わせ、食い違いは要確認にする。
- **内部IDを埋め込まない**: シートは暗号化されずに行き来する。内部ID はアプリのあらゆる記録を結ぶ鍵になる値なので、暗号化した中だけに留める。依頼番号は依頼ごとの乱数で、漏れても他の記録と結びつかない。
- **配置はアプリの側の記録を正に**: シートの中の値は顧客の手元で書き換えられうる。配置を信用すると、書き換えで別の項目に値を入れさせられる。

## 影響

- **後から変えると何が起きるか**: 埋め込みの形・項目キー・名前の定義の付け方・状態のセルの形を変えると、配布済みのシートを取り込めなくなる。顧客の手元にあるシートは回収できない。
- **守るべき決まり**
  - 公開したシート定義を書き換えない（新しい版を作る）。
  - 項目キーを変えない・使い回さない・消さない（廃止として残す）。
  - 取り込みで、シート定義（または依頼の記録の配置）が指すセル以外を読まない。
  - 埋め込みの形の版（形式の版）を上げるときも、前の形式の版を読み続ける。
- **テストで確かめること**
  - 公開したすべての版の見本 .xlsx が取り込め、期待どおりの候補になる。
  - 行を挿入した・名前の定義を消した・隠したシートを消した・ユーザー設定のプロパティを消した見本で、要確認になるか、残った管理の値で正しく読める。
  - Numbers・Google スプレッドシート・LibreOffice で開いて保存し直した見本が取り込める（取り込めないときは、分かる言葉で止まる）。
  - 管理の値が食い違う見本で、取り込みが止まる。
  - マクロ入り・外部リンク入り・数式入り・巨大・壊れた・展開すると膨らむ見本で、実行も読み込みもせず、アプリが落ちない。
  - 書き出したシートに、名前の欄・世帯の内部ID・聞かない項目の欄が無い。
  - FPが項目を選んで作ったシートが、依頼の記録の配置で読める。依頼の記録が無いときに、黙って読まない。
