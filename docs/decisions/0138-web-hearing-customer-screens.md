- 固定の強さ: 内部（お客さまの画面の作り・まとめ方の表・言葉。0125 の5 の「内部」の範囲）。暗号の形・受け付けの API・届いた答えの中身の形（`fprise-lifeplan-hearing-web-answers` 0.1）・答えの受け皿（Excel と同じ回答の一覧）は変えない。世帯ファイルの形式の版は変えない。シート定義は同意の欄の文だけを直した（`basic` 版2・`full` 版2〜4。配置の指紋に入らないので版は上げない。0018 の追記）
- 前提にする記録: 0014（同意の記録）、0018（ヒアリングシートの形式）、0125（Web のヒアリング）、0135 の6（詳細のヒアリングシート版3 のご両親）、0155（版4 の確定申告の仕方）

## 背景

- 0125 の Web のヒアリングを、発行から取り込みまで通して確かめたところ、お客さまの画面に次の不具合と迷う所が見つかった。
  - 見直しの票で、前回の値が Excel の書き出しと同じ言葉（「持ち家」「パート・アルバイト」「1985年（昭和60年）」「4月」）で届くのに、問いを飛ばす決まりと選択肢のボタンは内部の値（`own`・`partTime`）で比べるため、飛ばしが働かない（持ち家の世帯で住宅ローンの問いが出ない など）。前回の選択肢が光らず、月の欄が空になる。
  - 「働いていない」が選択肢と小さなボタンの2つ並び、選択肢の方では年収を聞き続ける。
  - 確かめの画面で、全角・桁区切りの金額が単位なし（「８５０」「98,000」）。「直す」から戻ると「確かめに戻る」が2つ並ぶ。進み具合の分母が答えるたびに変わる。
  - 問いの言葉がシートの欄の名前のまま（「ご健在か」「年齢（生年月を書かないとき）」）。生年の選択が未来の年から始まる。生年月の月を知らないと先へ進めない。金額と範囲の画面が長い。
  - 最初の画面に問いの数・所要時間・誰に届くかが無い。送った後の画面で分かることが少なく、送った内容を見られない。端末に残る途中の答えを消せない。
- 利用者の判断（2026-11-06）: 事前のヒアリングは**項目を少なく、まずお客さまに答えて送ってもらうこと**を主軸にする。**通常の票（`basic`。0192 でシンプルに改名）が主**で、詳細の票（`full`）はオプションとして残す。1画面1問の決まりを通常の票では緩め、人ごと・お住まい・お金を1画面にまとめる。金額は「だいたいの範囲」を押すのを先に、きっちりした額は開いて入れる。「ご相談したいこと」は同意の直後に置く。途中まででも送れることを確かめの画面で分かるようにする。
- 利用者の判断（以前の設計の決定）: お客さまの控えは「送った内容をその場で見る・印刷するだけ」（ファイルの保存はしない）。画面は事務所名だけで、一番下に小さく「このページの仕組み」のリンク。同意の AI の文は「担当の FP が、AI を使ってお答えを整理することがあります（お名前は渡しません）」。

## 決定

### 1. 画面のまとめ方（`hearing/src/web/flow.ts`）

- 画面の問いは「画面の中の問いの並び」（`ScreenField`: 項目キー・番号・別の答え方）にした。別の答え方（`alt`）は、金額の「だいたいの範囲」と、簡易の票の生年月の代わりの年齢。
- 同じ画面に出す問いは表（`GROUPS`。主の項目 → 続けて出す項目。同じ区画・同じ繰り返しのときだけ。続けて出す項目にも出す条件 `SHOW` が効く）:

  | 主の項目 | 同じ画面に出す項目 |
  |---|---|
  | 生年月（大人） | 性別（年齢は別の答え方） |
  | 生年月（お子さま） | 性別（詳細の票） |
  | いまの働き方 | 年収 |
  | 事業の所得（自営業の方。詳細の票） | 確定申告の仕方（版4） |
  | いまのお住まい | 家賃・住宅ローンの毎月の返済額・残高 |
  | 預貯金 | 投資 |
  | 毎月の生活費 | 保険料の合計 |
  | ご健在か（ご両親） | お年・同居（詳細の票は介護が始まっているかも） |
  | 仕送り（ご両親。詳細の票） | 援助・介護の費用 |
  | 受け取る予定の相続・贈与（詳細の票） | 受け取る時期・額 |

- 簡易の票のお子さまの生年月は、番号ごとに分けず全員を1画面に（`ACROSS`。続けて出す項目が無いときだけ）。
- 分岐の問いは、同じ区画で要るものを最初に要る所で1画面にまとめる（ご家族の区画: 配偶者の方がいるか＋お子さまの人数）。
- ご両親の前に分岐の問い「ご両親のことも、うかがってよいですか（はい／いいえ）」を足した（`parent`）。「いいえ」ならご両親の問いを出さず、送らない（未回答）。詳細の票（版3 から）の受け取る予定の相続・贈与もご両親の区画の問いなので、「いいえ」なら出さない（分岐の問いを聞いていない選び方なら出す）。
- 詳細の票（版3 から。今の版4 も同じ）のご両親は1人に2画面: 「ご健在か・お年・同居・介護が始まっているか」と「仕送り・援助・介護の費用」。亡くなった方には2つ目の画面とお年などを出さない。介護の費用は介護が「始まっていない」なら出さない。受け取る時期・額は「ある」のとき（答える前は出す）。
- 「ご相談したいこと・気になっていること」は、どの区画にあっても同意の直後に出す（区画は「はじめに」）。
- 目安: 通常の票（今の名前はシンプル）で夫婦と子2人・ご両親を聞かないとき、問いの画面は12（同意・ご相談・ご家族の分岐・ご本人・配偶者の方・お子さま・働き方2・お住まい・お金・毎月のお金・これからの予定。ご両親の分岐の1画面は別）。
- 詳細の票にも同じ表が効く（生年月と性別・お住まいと家賃）。詳細の票のための別のまとめ方は、版3 で足したご両親・相続の問いと、版4 で足した確定申告の仕方（上の表の詳細の票の行）だけ。確定申告の仕方は自営業の方にだけ出す（0155）ので、「当てはまらない」のボタンは出さない（「わからない」は出す）。

### 2. 見直しの前回の値

- 問いに載せる前回の値（`buildPacket` の `prefill`）を、お客さまの画面の答えの形にする（`webPrefill`）: 選択肢はラベル → 値、年月は「1985年（昭和60年）」「4月」→ 1985・4、範囲はラベルのまま。取り込みは言葉でも値でも読むので（`parseValue`）、届く答えの形は変わらない。
- これで飛ばしの決まりが前回の値で働き、前回の選択肢が光り、月の欄が埋まる。

### 3. 問いと答えの言葉

- 問いの言葉は画面用の補い（`packet.ts` の `WEB_LABELS`）で持つ。シート定義・配置の指紋は変えない。直した所は「影響」の表。
- 「当てはまらない」のボタン（`NA_LABEL`）: 答えに合わせて飛ばした後にしか出ない問い（働いている方の年収・賃貸の方の家賃・預貯金・住宅ローンのある方の残高・給与の年収）には出さない。住宅ローンの返済額は「住宅ローンはない」（選ぶと残高を聞かない）、投資は「持っていない」、保険料は「保険に入っていない」。ボタンを出さない項目は、手引きの「該当なし」の文も外す。
- 働き方の小さなボタン「働いていない」は出さない（選択肢の方だけ）。選択肢の「働いていない」は年収・仕事の問いを出さない。**休業中は年収を聞く**（休業の前の年収で、戻った後を考えるため）。
- 分岐の問いの選択肢: 「いない／1人／2人／3人／4人以上」「ない／1本／2本」「入っていない／1件…／5件以上」。最後の段より多いときの言い方を説明に足す。
- 確かめの画面・送った内容の金額は、全角・桁区切り・単位つきで打っても単位つきで出す（「年 850万円」「月 98,000円」。範囲も「月 9〜11万円」）。
- 最初の画面の注意（`WEB_NOTES`）: 「番号でお客さまを見分けます」を「お名前がなくても、担当の FP にはどなたのお答えか分かります」に、「当てはまらない問いは…」を外し、「途中まででも送れます。答えていない所は、面談のときにうかがいます」を足した。

### 4. 入れやすさ

- 金額に範囲があるときは、**範囲のボタンが先**（2列）で、きっちりした額は「くわしい額を入れる」で開く（前の答えに額があれば開いて出す）。範囲を選ぶと額を、額を入れると範囲を消す（どちらか一方）。範囲を押したら自動で次へは進まない（1画面に問いが複数あるため）。
- 選択肢は、短いもの（男性・女性 など）と5つ以上のもの（働き方 など）を2列にして画面を短くする。
- 年の選択は新しい年から: 大人の生年月は今年の15年前から（年齢の欄の下限 15 歳に合わせる）、お子さまの生年月は出産の予定のため3年後から、ほかの年月は今年から。前回の値などで範囲の外の年が入っていれば、その年も選べる。
- 生年月の月に「わからない」（大人の生年月だけ。年齢の欄があるため）。選ぶと「1981年生まれなら、いま44歳か45歳です」を出し、年齢を入れれば先へ進める。年だけの生年月は取り込めないので送らない（年齢だけを送る）。
- **空のまま「次へ」は「あとで」と同じ**（答えの無い問いに「あとで」を付ける）。「あとで」のボタンは残す（押しやすいまま）。続きからは、どの問いにも答えていない最初の画面へ。

### 5. 進み具合

- 分母のある「n / m」をやめ、段（はじめに・区画の順・書類・確かめ）の印と今の段の名前を出す。段は問いの中身で決まり、答えで変わらない（`progress`）。

### 6. 最初の画面・確かめの画面・送った後の画面

- 最初の画面: 「（事務所名）からのご質問です」を大きく。問いの画面の数と所要時間の目安（夫婦と子2人・ご両親も聞く前提で数え、1画面15秒・書類1通1分。`estimate`）、「この端末の中で暗号化してから送ります。（事務所名）の担当の FP だけが開けます」、回答の期限を囲みで出す。
- 確かめの画面: 「まだの問いが N、まだの書類が M あります。途中まででも送れます。答えていない所は、面談のときにうかがいます」と「まだの問いに答える」（まだの最初の画面へ。戻ると確かめの画面）。問いごとに1行（画面にまとめた問いも1つずつ）。
- 「直す」から来た画面は、下の左のボタンを出さず、右の「確かめに戻る」だけ。
- 送った後の画面: 「（事務所名）に届きました」・送った日時・「あとで送る」にした書類があれば「担当の FP から送り方をお知らせします」・「送った内容を見る」（確かめの画面と同じ一覧を見るだけ）・「印刷する」（ブラウザの印刷。ボタンなどは印刷しない）。ファイルには保存しない。「このページを閉じると、送った内容はこの端末には残りません。控えが要るときは、閉じる前に印刷してください」。担当の FP に知らせてほしい文は、アプリが届いたことを知らせるようになるまで残す。

### 7. この端末の入力を消す・このページの仕組み

- 「この端末の入力を消す」（最初の画面〔続きのとき〕と確かめの画面。2回目の「消す」で消す）: 端末の中の下書きを消し、付けた書類をサーバーから外し、最初の画面に戻る。
- 一番下に小さく「このページの仕組み」（開くと短い説明）: 端末の中で鍵をかけて（暗号化して）から送り、開けるのは担当の FP のアプリだけ・途中で預かる置き場もページを動かす提供元も中身は読めない仕組み・担当の FP が受け取るか期限が過ぎると置き場から消える・途中の答えは端末の中に鍵をかけて残し、送ると消える。「絶対に見えない」とは書かない。提供元の名前と窓口は、配る所の説明のページ（本番の手作業）に置く。

### 8. 同意の文

- 外部の AI への提供の同意（`hs.consent.externalAi`）の文を「（任意）担当の FP が、AI を使ってお答えを整理することがあります（お名前は渡しません）。このことに同意します」にした。Web の画面とシート（`basic` 版2・`full` 版2〜4。Excel・印刷用 PDF）で同じ文。同意の種類 `externalAi`・選択肢・取り込みは変えない。廃止した版1 のシート定義は配ったときの文のまま。

## 理由

- **前回の値を値に直して載せる**: 取り込みは言葉でも値でも読むので、問いに載せる形だけを画面の形にそろえれば、届く答えの形・取り込みを変えずに飛ばしと選んだ所の光りが直る。
- **表でまとめる**: まとめ方を画面の部品の中に書くと、詳細の票・FP の見本と食い違う。項目キーの表なら同じ流れの関数で両方の票に効き、テストで確かめられる。
- **範囲が先**: 手軽さが主軸（利用者の判断）。範囲は押すだけで答えられ、取り込みは今の範囲の真ん中の推定のまま使える。きっちりした額を知っている人は開いて入れられる。
- **空のまま「次へ」を「あとで」と同じに**: 2つの違いがお客さまに分からず、確かめの画面ではどちらも「まだ」だった。同じにすれば「続きから」の動きも1つになる。
- **休業中は年収を聞く**: 産休・育休は戻る前提で、休業の前の年収が戻った後の収入の手がかりになる。取り込みも休業中に年収を読む。
- **月が「わからない」なら年だけを送らない**: 取り込みは年月の両方が要り、年だけでは読めない（要確認の知らせになる）。年齢の欄があるので、年齢で答えてもらう。
- **段の進み具合**: 分岐の問いの答えで画面の数が変わるので、分母のある数はどうしても動く。段は答えで変わらない。
- **控えは見る・印刷だけ**: 端末に平文のファイルを残さない（以前の設計の決定）。

## 代案（採らなかったもの）

- **範囲を押したら自動で次へ**: 1画面に問いが複数あるので、1つ押しただけで進むと残りを飛ばす。
- **月が「わからない」のとき、6月などの仮の月で送る**: 生年月を作ってしまうので、年齢で答えてもらう。
- **「あとで」のボタンを外す**: 空のまま「次へ」と同じ動きになったが、「答えなくてよい」ことが見えるように残す（利用者の判断:「わからない」「あとで」は押しやすいまま）。
