# 0156. 離婚・未婚のひとり親のひとり親控除と、婚姻の状態の欄（寡婦控除の判定・世帯ファイルの形式 0.69）

- 状態: 採用（一部未確定）（2026-11-07）
- 固定の強さ: 骨格（構成員の欄 `members[].maritalStatus` の名前と値 `unmarried`・`divorced`・`bereaved`・`married`、省略は婚姻していないとみなすこと、世帯の法律婚の関係の終わり方が欄より先に効くこと、形式 0.69）。判定の部品 `tax.survivorStatus` の中身（改訂4）は差し替えられる公式部品のまま（0119。出力の形は変えていない）。画面の欄の置き場所・言葉・読むだけの1行は内部（後から変えてよい）
- 前提にする記録: 0141（家族の入力項目の見せ方。ひとり親の1行と「離婚・未婚のひとり親の控除は計算していない」の未確定）、0046（家族のカード・関係の形と終わり）、0035 の4・5（世帯の外の家族・関係の期間）、0008（世帯のデータモデル・万一の重ね）、0007（制度データの形式）、0011（形式の版と変換の段）、0015（AI に渡す縮約版）、0119（差し替えられる部品）、0130・0131（言葉と欄の部品）

## 背景

- ひとり親控除・寡婦控除の判定（`tax.survivorStatus`）は、配偶者が**万一の想定で亡くなった後**だけを扱っていた。離婚・未婚のひとり親は入力に形が無いとして判定せず、見本 4-3-01（ひとり親と子2人・30代）のような世帯でもひとり親控除が計算に入っていなかった。0141 で画面の1行を「計算に入れていません」にし、計算に足すかを利用者の判断に回した。
- 利用者の判断（2026-11-07）: β公開の前に、離婚・未婚のひとり親のひとり親控除をふだんの税の計算に足す。児童扶養手当は β の後（今回は入れない）。

## 決定

### 1. 制度の要件と値を公式の資料で確かめた（制度データは今のまま）

- **ひとり親**（所得税法2条1項31号・81条、地方税法292条1項12号・314条の2、国税庁 No.1171）: その年の12月31日の現況で、(1) 現に婚姻をしていない（か、配偶者の生死が明らかでない一定の人）、(2) 事実上婚姻関係と同様の事情にある人がいない、(3) 生計を一にする子（総所得金額等が上限以下で、他の人の同一生計配偶者・扶養親族になっていない）がいる、(4) 本人の合計所得金額が500万円以下。男女・未婚・離婚・死別を問わない。控除は所得税35万円（令和9年分から38万円）・住民税30万円（令和10年度分から33万円）。
- **子の所得の上限**: 所得税は令和2〜6年分 48万円・令和7年分 58万円・令和8年分から 62万円（所得税法施行令11条の2第2項、国税庁 No.1171）。住民税は地方税法施行令46条の2の2第2項で「当該年度の初日の属する年の前年」の所得で 令和7年度まで 48万円・令和8年度 58万円・令和9年度から 62万円（e-Gov の令和7年4月・令和8年1月・令和8年11月・令和9年1月の版で確かめた）。**同じ所得の年で所得税と住民税の上限は同じ**なので、判定は所得税の値ID `incomeTax.singleParentDeduction.childIncomeLimit` を所得の年で引いて、住民税にも使う（今までどおり。住民税の値を別に持たない）。令和7年分以降の基礎控除等の改正で変わったのは子の所得の上限の額だけで、要件の形は変わっていない。
- **本人の合計所得金額の上限**: 500万円（所得税・住民税とも）。公布済みの最新の版（令和10年1月1日）まで変わらない（制度データの記録のとおり）。
- **配偶者の生死が明らかでない一定の人**は、政令（所得税法施行令11条・11条の2第1項、地方税法施行令46条の2・46条の2の2第1項）で太平洋戦争の終結の当時の未帰還者の配偶者に限るので、扱わない。
- **事実婚**（所得税法施行規則1条の3・1条の4）は、住民票の世帯主との続柄が「未届の夫・妻」と記載された人。同じ世帯に住民票がある人なので、世帯の関係の「事実婚」（`relation.marriage` `deFacto`）で表せる。
- **寡婦**（所得税法2条1項30号・80条、国税庁 No.1170）: ひとり親に当たらない女性で、合計所得金額500万円以下、かつ 夫と死別した後婚姻をしていない（扶養親族の要件なし）か、夫と離婚した後婚姻をしていなくて扶養親族がいる。事実婚の人がいれば当たらない。「夫」は民法上の婚姻（法律婚）の相手。控除は所得税27万円・住民税26万円。
- 制度データの値（ひとり親の控除額・本人と子の所得の上限・寡婦の控除額と所得の上限・調整控除の人的控除額の差〔母5万円・父1万円・寡婦1万円〕）は、2026-10-09 に原本（e-Gov の条文・国税庁・自治体の案内）と照合済みで、今回は足し・直しをしていない。

### 2. 判定の決まり（`tax.survivorStatus` 改訂4）

- その年の12月の婚姻の状態を次の順で決める。
  1. 配偶者の関係（法律婚・事実婚）が12月にあれば「配偶者がいる」（ひとり親・寡婦のどちらでもない）。12月に終わる関係は、12月31日にはまだ配偶者。
  2. その月までに終わった**法律婚**の関係のうち、いちばん後に終わったものの終わり方。相手の万一の想定の死亡の月で終わった（重ねは死亡の月で関係を終える）なら死別、ほかは離婚。事実婚の関係が終わっても婚姻の状態は変えない（法律婚ではないので、寡婦の「夫」に当たらない）。
  3. 終わった法律婚の関係が無ければ、構成員の欄 `maritalStatus`（3）。省略は未婚とみなす（婚姻していない）。
- **ひとり親**: 婚姻の状態が「配偶者がいる」「婚姻している（別居など）」でなく、生計を一にする子（世帯にいる子で、その年の総所得金額等が上限以下。世帯の外の子は数えない〔0035 の4。今までどおり〕）がいて、本人の合計所得金額（分離課税の退職所得・譲渡所得を含む。今までどおり）が上限以下。
- **寡婦**: ひとり親でない女性で、本人の合計所得金額が上限以下、かつ 死別か、離婚で扶養親族がいる。扶養親族は、世帯にいる子と扶養している親・祖父母（世帯の外の家族は扶養していると入れたときだけ。世帯の外の子は養育費・仕送りの行がその月を含むときだけ。`tax.dependentDeduction` と同じ見方）で、合計所得金額が扶養親族の上限（`incomeTax.dependentIncomeLimit`。値の無い年は子の所得の上限）以下の人。未婚・省略は寡婦にしない。
- 上限の値がその年の制度データに無ければ判定しない（`has` で確かめる。制度データを持たない試験用のパック・値の無い昔の年）。制度の値は、子がいるときと寡婦を判定するときだけ引く。
- 出力の形（`widow`・`singleParent`）・約束の版（1.0）は変えていない。所得控除（`tax.deductions`）は今までどおりこの判定から控除額と調整控除の人的控除額の差を出す（計算の式は変えていない。説明の文だけ直した）。

### 3. 入力: 構成員の欄 `members[].maritalStatus`（世帯ファイルの形式 0.69）

- 構成員に任意の欄 `maritalStatus`（配偶者の関係が無い期間の婚姻の状態）を足した。値は 未婚 `unmarried`・離婚 `divorced`・死別 `bereaved`・婚姻している `married`（別居などで配偶者を世帯に入れていない）。省略は婚姻していないとみなす（ひとり親控除は判定し、寡婦控除は判定しない）。
- 世帯に法律婚の関係があれば、その期間と終わりの後は関係から決め、この欄は使わない（2 の順）。この欄は「世帯に関係の無い期間」だけに効く。
- 世帯ファイルの形式の版を `0.69` に上げた（足すだけの MINOR。前の版のアプリは入力の検査で知らない欄を通さないので閲覧だけにする）。変換の段は形式の版だけを書き換える（前の版の世帯は欄が無い＝婚姻していないとみなす）。見本 `crates/household-store/tests/fixtures/household-format/0.69`（0.68 の見本のご本人に「離婚」）。
- 入力項目ID `member.maritalStatus` を登録簿に足した（`npm run gen`）。AI に渡す縮約版の許可リストに入れた（税の計算に要る。`reduced@31`。0015）。
- **画面**: 家族の入力項目の**詳細**で、配偶者が世帯にいない（計算の基準の月）ご本人のまとまりに選ぶ欄「婚姻の状態」（入れない〔婚姻していない〕・未婚・離婚・死別・婚姻している〔別居など〕。空欄＝婚姻していない）。標準の欄は増やさない（空欄のままで、ひとり親控除はふつうの世帯で正しく入るため）。単身の世帯にも出す（寡婦控除の判定）。夫婦の世帯・配偶者・子には出さない。

### 4. 画面の1行

- ひとり親の世帯の読むだけの1行「ひとり親控除・児童扶養手当」の値を「控除は計算に入れています（手当は入れていません）」にした。ご本人の婚姻の状態が「婚姻している（別居など）」なら「どちらも計算に入れていません（婚姻している）」。「?」に要件（未婚・離婚・死別のどれでも、子の所得が上限以下、合計所得金額500万円以下、所得税35万円・住民税30万円）と、別居していて離婚していないときの直し方、児童扶養手当は入れていないことを書いた。

### 5. 計算の結果が変わる所

- 配偶者が世帯にいなくて生計を一にする子がいる世帯で、本人の合計所得金額が500万円以下の年に、ひとり親控除が入る（所得税・住民税が下がる）。前は万一の想定の死別の後だけだった。
- 見本 4-3-01（ひとり親と子2人・30代。モデル世帯 `sampleSingleParent`）: 2026〜2041年にひとり親控除が入り、下の子が世帯を離れる2042年4月の後の年から入らない（ご本人の婚姻の状態は空欄なので、その後の寡婦控除は判定しない）。年ごとの税は 2026年 −5,193円（所得税）、2027年 −38,400円（所得税 −19,400円・住民税 −19,000円）、2028〜2031年 −62,400〜−67,200円、2032〜2041年 −53,400〜−65,600円、2042年 −43,400円・2043年 −18,500円（住民税の年度のずれ）。表の期間の税・社会保険料の合計で −934,593円。
- ほかのモデル世帯で変わるのは無い。`unionConstruction`（本人と17歳の子）は本人の合計所得金額が 502万円・508万円で上限を超えるので入らない。単身の世帯は子がいなく、婚姻の状態が空欄なので寡婦控除も入らない。万一の想定の死別の世帯（`survivorEmployeeLoan`・`survivorSelfEmployed`）は今までどおり。
- 夫婦の世帯は変わらない（配偶者の関係がある）。

## 理由

- **空欄を「婚姻していない」とみなす**: 配偶者を世帯に入れずに子がいる世帯は、ほとんどが離婚・未婚・死別のひとり親で、ひとり親控除の要件はこの3つで同じ。空欄で控除を入れないと、0141 で見つかった計算の漏れがそのまま残る。別居していて離婚していない人だけが「婚姻している」を選べばよい。
- **寡婦は空欄では判定しない**: 寡婦は死別と離婚（扶養親族あり）で要件が違い、未婚の人は当たらない。分からないまま入れると控除を多く見積もる側に外れるので、FP が入れたときだけ入れる。
- **欄を標準にしない**: 空欄のままでひとり親控除は正しく入り、詳細の欄が要るのは別居中・寡婦の判定だけ（0078 の標準の欄は「必要十分」）。
- **事実婚は世帯の関係で表す**: 税の事実婚は住民票の「未届の夫・妻」で同じ世帯の人なので、世帯に「＋ パートナー（事実婚）」で入れる今の形がそのまま当たる。新しい欄を作ると、世帯の関係と食い違う入れ方ができてしまう。
- **世帯の関係を欄より先にする**: 関係の終わり（離婚・万一の想定の死亡）は時点を持ち、プランで「離婚する案」を作るとその年から判定が変わる。欄は時点を持たないので、関係の無い期間だけに使う。
- **子の所得の上限を所得税の値で住民税にも使う**: 原本で同じ所得の年の上限が同じことを確かめた。値を2つ持つと、片方だけ直す誤りが起きる。将来ずれたら住民税の値ID を足す（未確定）。

## 代案（採らなかったもの）

- **欄を足さずに、配偶者のいない世帯は全部ひとり親とする**: 別居中で離婚していない人を外せず、寡婦の死別・離婚の区別もできない。
- **欄を標準にする**: ひとり親の世帯の FP が毎回選ぶことになり、空欄の既定で正しい世帯がほとんどなのに手数が増える。
- **「生死不明」を選択肢にする**: 政令で戦後の未帰還者の配偶者に限るので、今の世帯では当たらない。
- **住民税の子の所得の上限の値ID を足す**: 今は所得税と同じ値なので、二重に持たない（上の理由）。

## 未確定

- **児童扶養手当**の計算（β の後。利用者の判断）。入れるまでは「＋ 児童扶養手当など」で受け取っている額を入れる。
- **他の人の扶養親族になっている子**（元の配偶者が扶養控除を受けている子）は、生計を一にする子から外すべきだが、世帯の外の人の扶養を表す形が無いので外していない。世帯の外の子（離れて暮らす子）は今までどおり数えない。
- 婚姻の状態の欄を、ご本人のほかの大人（世帯の中の親など）にも出すか。今は、親・祖父母は世帯の外の家族が既定で、世帯の中で税を計算する親の寡婦控除は、エンジンは判定できるが画面に欄が無い。
- 住民税の合計所得金額は分離課税の退職所得を含まないが、判定は所得税の合計所得金額（退職所得を含む）で1回だけしている（今までどおり）。退職金を受け取る年のひとり親・寡婦の住民税の判定がずれうる。
- 所得税と住民税の子の所得の上限がずれる改正が出たら、住民税の値ID（`residentTax.singleParentDeduction.childIncomeLimit`）を足し、判定を税目ごとにする。
- ヒアリングシートに婚姻の状態の問いを足すか（今は足していない。画面の詳細の欄だけ）。
