# 0135. 介護・親と相続・贈与のつながり（介護の費用は亡くなる見込みで止める・推定の相続の時期は相手についてくる・親を援助の贈与する人に・介護の物の欄・仕送りの行で扶養を判定・詳細のヒアリングシートのご両親）

- 状態: 採用（一部未確定）（2026-11-07）
- 固定の強さ: 内部（世帯ファイルの形式の版は変えない。エンジンの部品は改訂だけを上げる: `care.expense` 改訂5・`socialInsurance.healthStatus` 改訂7。ヒアリングシートは `full` 版3 を足し版2 を廃止〔0018 の決まりどおり〕。画面の言葉・選択肢の見せ方は後から変えてよい）
- 前提にする記録: 0018（ヒアリングシート）、0035 の4（世帯の外の家族・贈与者）、0041（値の状態の操作・推定）、0042（世帯の外の家族のお金）、0043（入力画面でプランを直す・欄の印）、0044（お金の行）、0059（介護・親）、0060（相続・贈与）、0077（説明は「?」の中）、0130（言葉の決まり）

## 背景

入力項目を通しで入れ直した見直しと、ありえない結果の見張り（0129）で、介護・親と相続・贈与のあいだに次の問題が見つかった。

1. 介護を受ける人（母など）の亡くなる見込みを介護の期間の途中に入れても、介護の費用が期間の終わりまで出ていた（亡くなった後も約3年）。0035 の4 の追記（2026-10-27）は「介護の費用はもともと亡くなる見込みで止まっていた」と書いていたが、`care.expense` は介護を受ける人の亡くなる見込みを見ていなかった。
2. 受け取る相続の時期は、足したときに相手の亡くなる見込みの10か月後を推定で入れるが、相手を父から母に変えても、相手の亡くなる見込みを直しても、前の時期のまま（推定の印も残る）だった。
3. 住宅資金・教育資金の援助の「贈与する人」に、介護・親で足した父母が出なかった。援助に選ぶには相続・贈与で生年月の無い贈与する人をもう1人足すことになり、同じ人が2人並んだ。利用者の判断（2026-11-06）で選べるようにすると決まった。
4. 介護の物の欄: 誰が払うかが標準の画面に出ない・払う人の選択肢に世帯の外の家族が並ぶ・プランの編集中に「現状: ○○ ↺ 現状に戻す」が出ない・空欄の月々の費用の推定が欄に出ず「この値にする」が無い・介護保険のサービスの額（10割）を入れたときに月々の費用が合計なのか対象外の分なのか分からない。
5. 健康保険の扶養の判定（別居の親）は人の欄の「仕送りの額」だけを読み、仕送りの出るお金の行を見ていなかった（同じ仕送りを2か所に入れる）。
6. 詳細のヒアリングシートにご両親の問いが無く、見直し（詳細の票に前回の値を記入）でも親が抜けた。どの票にも、仕送り・援助・介護が始まっているか・受け取る予定の相続の問いが無かった。利用者の判断（2026-11-06）で詳細の票に足すと決まった（ただし事前の回答では使われにくい見込みなので、目立たせない）。

## 決定

### 1. 介護の費用は、介護を受ける人が亡くなった（離れた）月から出さない（`care.expense` 改訂5）

- 介護を受ける人の `leaves`（世帯の外の家族では亡くなる見込み、世帯の人では世帯を離れる月）の月から、期間・一時費用が残っていても介護の費用を出さない。万一の想定で介護を受ける人が亡くなるときは、亡くなる月の翌月から（その月までは世帯にいる扱い。同じ部品の世帯の数え方と同じ）。
- 期間（か月）の欄はそのまま（詳細）。「介護の終わりの既定は亡くなる見込みまで」は、終わりの欄を足さずに計算で止める形にした（値の形を変えない）。介護の物の見出しは、止まるときに「2036年9月〜2039年3月（亡くなる見込みまで）」と出す。期間の欄の「?」にも書く。

### 2. 推定のままの相続の受け取る時期は、相手の亡くなる見込みについてくる（画面の側）

- 受け取る時期に推定の印（`in/<行>/from` の仮の印）があるときだけ、(a) 行の相手を変えたとき、(b) 相手の亡くなる見込みの欄を直したとき・「平均余命で入れる」を押したときに、新しい亡くなる見込みの10か月後で入れ直す（`inheritance.ts` の `followInheritTiming`）。FP が時期を入れたら（欄を書いたら）推定の印を外し、その後は動かさない。
- 時点の持ち方は今のまま（亡くなる見込みが年齢の形なら年齢＋10か月、年月なら年月）。「母が亡くなってから10か月後」の名前つきイベントの形にはしなかった（亡くなる見込みを出来事にすると、介護・親の欄と出来事の一覧の両方に同じ時点が出て、出来事の正本の決まり〔0038〕で直し方が2通りになるため）。

### 3. 介護・親の親・祖父母を、援助の贈与する人に選べる（世帯ファイルの形式の版は変えない）

- 援助（住宅資金の援助 `residences[].purchase.gifts[].donor`・子への援助 `goals[].education.gifts[].donor`）の贈与する人の候補（`labels.ts` の `donorOptions`）に、介護・親の世帯の外の家族のうち親・祖父母（生年月のある人）を出す。選ぶと、その構成員の ID を `donor` に書く。生年月を入れない贈与する人（画面の中の `donors`）は「生年月を入れない贈与する人（ご本人の親）」として残す。前に援助で選んだ人が親・祖父母でなくなっても候補に残す。
- **形式の版を上げない理由**: 世帯ファイルでは形式 0.17 から、贈与者は生年月の無い世帯の外の家族の構成員として持ち、援助の `donor` はもともと構成員の ID を指している（0035 の4）。エンジンの `gift.received` も、`donor` が世帯の外の家族の構成員なら続柄と「誰の家族か」から贈与者の区分を出す（同じ人からの贈与を合わせて数える `gift.tax` もその ID で数える）。指せる人が「生年月の無い構成員」から「世帯の外の家族の親・祖父母」に広がるだけで、本文の形・欄・値の種類は変わらない。前の版のアプリで開いても計算は同じ（選択肢に出ないだけ）。
- 介護・親で親を外すと、その人を指す援助の贈与する人も外す（`removeMember`）。介護・親の親のまとまりに「援助 ○ 件で、贈与する人に選ばれています」、相続・贈与の贈与する人の区画に「贈与する人（父）」の1行を出す。
- 相続・贈与の「＋ 親を足す」（生年月を入れない贈与する人）は残す。区画の説明を「介護・親の項目で足した親・祖父母は、そのまま援助の贈与する人に選べます。生年月を入れずに贈与する人だけを置くときは、ここで足します」にした。

### 4. 介護の物の欄（`events.ts` の `careGroup`・`care.ts` の `careCostGroup`）

- **払う人**（値の形は今のまま: 空は介護を受ける人、ほかは構成員の ID）: 世帯の外の家族の介護は「介護を受ける人のお金から（足りない分は世帯）／世帯（ご本人）／配偶者」、世帯の人の介護は「介護を受ける人（ご本人）／介護を受ける人でない方」。父・義父などは選べない（前に選んだ人は添え書きを付けて残す）。
- **誰が払うかの1行**: 「この費用は世帯が払います。母のお金を入れると、まず母のお金から払います」（親のお金を入れた人は「まず母のお金から払い、尽きた月から世帯が払います」）。まとまりの説明として「?」に入れた（0077。画面に常に出すのは名前・値・印・操作まで）。
- **介護保険のサービスの額（10割）**: 入っていれば、月々の費用の名前を「介護保険の対象外の費用（食費・居住費など・月額）」にする。10割の欄は「介護保険のサービスの額（1割負担の前・月額）」。計算は前から、サービスの額に自己負担の割合（1〜3割）と高額介護サービス費の上限を当てた額に、月々の費用（保険の対象外の分）を足していた（`care.expense`。エンジンのテストに例を足して確かめた）。名前を計算に合わせた。
- **空欄の推定**: 月々の費用（サービスの額が空のときだけ）・期間・一時費用が空欄なら、エンジンが使う統計の平均（事務所の推定の値があればその値）を欄に「推定」として見せ、「この値にする」でその値を書く（0041 の `blankEstimate`。事務所の既定値で「推定で埋めない」にしたときは出さない）。確かめの一覧の推定にも数える。
- **当て先**: どの欄にも当て先（介護の物・入力項目ID）を付け、プランの編集中に「現状: 施設 ↺ 現状に戻す」を出す（0043）。

### 5. 健康保険の扶養の判定の仕送りは、仕送りの行があれば行の額（`socialInsurance.healthStatus` 改訂7）

- 別居の親・祖父母の「仕送りの額の未満」の判定は、その人を相手にした仕送りの出るお金の行（種類 `allowance`・1回だけの行を除く）があれば、その月を含む行の額（今の値段。月額の行は12か月分・毎年の行はその額・何年かごとの行は1年あたり）の合計と比べる。行が無ければ今までどおり人の欄 `support.allowance`（sdk の `allowanceRowsAnnual`）。
- 画面: 行があれば「仕送りの額（月額）」の欄は出さず「仕送りの額（扶養の判定）: 親への仕送りの行の額を使います」の1行（前に入れた欄の値は残す）。行が無ければ欄を残し、「＋ 仕送り（毎月）」で行を足せる。

### 6. 詳細のヒアリングシートを `full` 版3 に（`full` 版2 は廃止。0018 の1・7）

- 版2 の項目はキーを変えずにそのまま残し、区画「10. ご両親」を生活費の後・そのほかの前に足した（目立たせない。説明は「分かる範囲でかまいません。空欄のままでもかまいません」）。繰り返しの軸 `parent`（ご本人のお父さま・お母さま、配偶者の方のお父さま・お母さま）を足した。
- 問い: ご健在か・年齢・いっしょに暮らしているか（簡易版と同じキー `hs.family.parent.*`）、仕送り（ご両親へ・毎月）`hs.family.parent.allowance`、援助（ご両親から・毎月）`hs.family.parent.support`、介護が始まっているか（始まっていない・在宅・施設）`hs.family.parent.care`、介護の費用（毎月）`hs.family.parent.careMonthly`。世帯で1つ: 受け取る予定の相続・贈与（ある・ない）`hs.inherit.expected`、受け取る時期の見込み（年）`hs.inherit.year`、受け取る額の目安（万円）`hs.inherit.amount`。
- 取り込み: 仕送りは相手をその親にした仕送りの行（今の月から毎月）、援助は援助・仕送りを受ける行（今の月から毎月）、介護が始まっていればその親の介護の費用（始まりは前の月で仮の印・期間は空欄で統計の平均・月々の費用は記入の額）。受け取る予定の相続は相続・遺贈の行1件（時期は記入の年の1月、無ければ1年後で仮の印。額は記入の額、無ければ未入力。見込みは「当てにしない」。相手はシートで聞かないので空）。介護が始まっていないのに費用の記入がある・「ない」なのに時期や額がある、は取り込まずに知らせる。親を承認しなかったときは、その親を指す行・介護も入れない（候補の物の中の構成員を指す欄に `counterparty` を足した）。
- 前回の値の書き出し（見直し）は、ご両親（4人まで）とその人の仕送り・援助・始まっている介護、相続・遺贈の行の最初の1件を記入する。
- 取り込んだ親の亡くなる見込みは、承認したときに画面と同じ平均余命の推定（仮の印）を入れる（前から `applyImport` が入れていた。取り込みの規則 `import.ts` の親は `leaves: null` のままで、画面の側で入れる）。
- Web で答えるヒアリングも同じ定義を使う（詳細の元のシートは書き出せる最新の版）。ひな形の名前・並びは変えていない。

## 理由

- 亡くなった人の介護の費用を世帯が払い続けることは無い。終わりの欄を足すと値の形が変わり、期間と終わりの2つの入れ方ができる。計算で止めれば今の期間の欄のまま正しくなる。
- 推定の時期は「相手の亡くなる見込みの10か月後」という決まりから出した値なので、元が動けば動くのが自然。FP が入れた時期は FP の判断なので動かさない（0041 の「確定は明示の操作だけ」）。
- 贈与する人を世帯の外の家族として介護・親に置く形（2026-10-25 の決定）に、援助の選択肢を合わせただけで、データの形は前から同じ人を指せた。
- 介護の物の欄は、計算がしていることを名前と選択肢に出し、ほかの推定の欄と同じ操作にそろえた。
- 仕送りを欄と行の2か所に入れると食い違う。行は支出にも効くので、行を正にした。

## 代案（採らなかったもの）

- 介護の物に終わりの時点の欄を足す（「期間 か月」を「終わり」にする）: 値の形が変わり、前の世帯の変換が要る。計算で止める形で足りる。
- 受け取る相続の時期を「母が亡くなる」名前つきイベントからの10か月後にする: 上の2のとおり、亡くなる見込みの直し方が2通りになる。
- 援助の贈与する人のために世帯ファイルの形式の版を上げる: 上の3のとおり、本文の形が変わらないので上げない（形式の版を上げる変更は回数を少なくする。0011 の5）。
- 仕送りの額の欄を無くし、いつも「＋ 仕送り（毎月）」だけにする: 扶養の判定だけに使う（支出に入れない）入れ方を残したい世帯があり、標準と詳細の切り替えの「?」の一覧（`levelHelp.ts`）もこの欄を挙げている。行があるときだけ欄を隠した。

## 影響

- 計算の結果が変わる所: (1) 介護を受ける人の亡くなる見込みが介護の期間の途中にある世帯は、その月から介護の費用が無くなる（見本の棚の世帯とモデル世帯には当たる物が無く、結果は変わらない）。万一の想定で介護を受ける人が亡くなるときも同じ。(2) 別居の親を相手にした仕送りの行がある世帯は、健康保険の扶養の判定に行の額を使う（行の額が欄と違う世帯だけ変わる）。(3) 推定のままの相続の時期は、相手や亡くなる見込みを変えた後に動く。
- ヒアリングシート: 書き出せる詳細の票は `full` 版3。前に配った `full` 版2・版1 は今までどおり取り込める。見本 `hearing/samples/full-3-sample.{json,xlsx}` を足した。
- 見張りの直す待ちの一覧から、介護の費用が亡くなった後も続く件と、受け取る相続の時期が相手の変更についてこない件を外した。通しの入力のテスト（0132）の世帯③の同じ2件の直す待ちを、確かめるテストにした（読む欄の名前を今の「時期」に、払う人の選択肢を「世帯（ご本人）」に合わせた）。

## 未確定・後の段階に回したこと

- 計算のお知らせの「介護の費用のうち入っていない所は、目安で計算しています」は残っている（欄に推定を出したので重なる）。お知らせの一覧の側で、推定を欄に出した物を外すかは、お知らせの一覧の見直しで決める。
- 住まいの援助・子への援助の「援助する人」の「?」の説明（「家族の項目で足した親・祖父母…」）と、援助を足したときの既定の贈与する人（生年月を入れない贈与する人の最初の1人）は、それぞれの入力項目の見直しで今の形に合わせる。相続・贈与の区画の「＋ 父を足す」「＋ 母を足す」（世帯の外の家族として足して相手に選ぶ）も同じ。
- 贈与する人に選んだ親のお金（0042）を見ているとき、援助の額をその人のお金から引くか。
- 生年月を入れない贈与する人と、介護・親の同じ親を1人にまとめる操作。
- 受け取る予定の相続の行の相手（誰から）をヒアリングシートで聞くか（βで答えられ方を見て）。
