# 0257. まとまりの中の「＋」で足した行を、押したまとまりのすぐ下に並べる（あげる贈与の孫・介護の次の段階・ペアローンの2本目・車の続きと車の出るお金の行）

- 状態: 採用（2026-11-23。5・6 と「利用者の判断」は同じ日の追記）
- 固定の強さ: 内部（入力項目の画面の並びだけ。世帯ファイルの形・計算・欄のキー・ボタンのキー・行の名前の数え方は変えない。「＋ この車の続き」だけは、足した車を世帯の中の並びで押した車のすぐ後ろに入れる）。決まりとして残すのは「人や物のまとまりの中のボタンで足した行は、そのまとまりのすぐ下に並べる（同じ区画の中に置ける物は）」の1つ。別の区画に置く物は、下の「利用者の判断」のとおり
- 前提にする記録: 0044（お金の行）、0045（1つの物は1つの入力項目）、0143（介護の段階）、0175（住宅の購入の中の住宅ローン）、0237（物の枠の中の中枠・車の枠の中のローン）、0060（あげる贈与の相手の孫）

## 背景

- 相続・贈与の「あげる贈与」の区画で、孫のまとまり（例「孫（0歳・生年月は仮の値）」）の「＋ この孫へのあげる贈与」を押すと、足した行が孫のまとまりの上（区画の頭）に出ていた。区画のまとまりを「あげる贈与の行 → 今ある援助の読むだけの行 → 孫のまとまり」の順に並べていたため。孫を後ろに置いた理由は、コードにも記録にも無かった。
- 同じ形（人や物のまとまりの中のボタンで足した物が、そのまとまりと離れて出る）が、ほかの入力項目にもあるかを調べた。

## 決定

### 1. あげる贈与: 孫のまとまりのすぐ下に、その孫を相手にした行（利用者の判断）

- 区画のまとまりの並びを「相手が孫でない行 → 今ある援助の読むだけの行 → 孫ごとに『孫のまとまり → その孫を相手にした行』」にする（`inheritance.ts` の `giveGroups`）。
- 行の相手（`counterparty`）が、あげる贈与の相手の孫（世帯の外の孫）なら、その孫の下。相手が子・相手なし（その他の人）などの行は、今までどおり区画の上。
- 行どうしの順（時期の順。0044）は変えない。1つの行の中の小さなまとまり（`ev/<行の id>/…`。贈与の形・払う人など）は、行の見出しのすぐ後ろに続けたまま。
- 行の「相手（誰へ）」を選び直すと、行はその相手の所へ移る。区画の「＋ あげる贈与」で足した行も、既定の相手（候補が2人以上なら離れて暮らす子・孫の1人目。推定の印つき。0150）が孫なら、その孫の下に出る。孫を外すと、行は相手なしになって区画の上に戻る。

### 2. 介護の費用: 介護を受ける人ごとに続けて並べる

- 区画「介護の費用」の介護の物を、介護を受ける人ごとにまとめて並べる（`care.ts` の `careByMember`。人の順は、その人の介護が世帯の中で最初に出てくる順。同じ人の段階どうしは世帯の中の並びのまま）。
- 前は世帯の中の並び（足した順）のままで、たとえば「ご本人の介護 → 配偶者の介護」のとき、ご本人の「＋ 次の段階」で足した2段階目が配偶者の介護の下に出ていた。
- 見出しの「（1段階目）」「（2段階目）」の数え方（`labels.ts` の `careStageMark`。同じ人の中の世帯の並びの順）は変えない。人ごとにまとめても同じ人の中の順は同じなので、見出しの段階の番号と上からの順は合ったまま。

### 3. 住宅の購入の中の住宅ローン: ペアローンの2本目を1本目のすぐ後ろに

- 住宅の購入の中に出す住宅ローン（0175）に、つながるローン（`purchaseLoans`）のペアローンの相手（`pairWith`）を、相手のすぐ後ろに足して見せる（`housing.ts` の `shownPurchaseLoans`）。
- 「＋ ペアローン（配偶者の2本目）」で足した2本目は、借入の年月を1本目に合わせるだけで控除の条件の住まい（`housing.residence`）を持たない。1本目の借入の年月が購入の月と違う購入の予定では、2本目だけが「住宅ローン」の区画に離れて出ていた。
- 見せる所の並びだけを変え、購入の形（現金で買う・住宅ローンを使う）・借入額の推定・控除の決まりは `purchaseLoans` のまま。ほかの購入の予定につながるローンは足さない（同じローンを2か所に出さない）。

### 4. 足した行へ画面が移る動き

- 「＋」で足した物は、どの区画に出ても、見える所へ動かして光らせ、最初の欄に移る（`revealAdded`。押す前に無かった画面の要素を足した物として探す仕組みなので、並びに関わらず動く）。1〜3 のどれも、足した直後に行が見え、行の最初の欄（名前・介護を受ける人）に移ることを、開発中のアプリで確かめた。別の区画に出る物（下の「利用者の判断」で今のままにした物）も、画面はその行へ移る。5・6 の行も、足した直後に見えて最初の欄に移ることを確かめた。

### 5. 車「＋ この車の続き」: 押した車のすぐ後ろに入れる（利用者の判断）

- 前は足した車を世帯の中の並びのいちばん後ろに入れていて、ご本人の車 1 の続きが、配偶者の車 2 の後ろに「車 3」として出ていた。押した車のすぐ後ろに入れる（`cars.ts` の `addNextCar`）。
- 見出しの「車 N」と、出来事の名前の番号（「車 2の購入」など。`namedEvents.ts`）は世帯の中の並びで数えるので、後ろの車の番号が1つずつ繰り下がる（例: 配偶者の車が車 2 → 車 3）。番号が動くのは、続きを足したその時だけ。続きの車の購入の時期は、今までどおり押した車を手放す出来事から決まる（並びが変わっても指す車は同じ）。
- 押した車が名義の最後の車のときだけボタンが出る決まり（`lastCar`）は今まで。いちばん後ろの車の続きは、いちばん後ろに入る。

### 6. 車の「＋ 手放した後の移動の費用」「＋ 古くなってからの修理費」の行: その車の枠の中に出す（利用者の判断）

- 前は車の枠の中のボタンで足すのに、行は車の入力項目の下の区画「出るお金」に出ていた。始まりがその車の出来事から決まる車の出るお金の行を、その車の枠の中に出す（`cars.ts` の `carRowsByCar`・`carRowBands`）。今返している自動車ローンを車の枠に入れた 0237 と同じく、見せ方だけで、行の持ち方（`periodicExpenses`）・計算・欄のキーは変えない。
- どの車の行か: 始まりが、その車を手放す出来事の翌月の行は「手放した後」の行（`afterCarAdded` と同じ見分け方）で、枠のいちばん下（前に「手放した後（この後、世帯に車がありません）」のボタンがあった所）に出す。それ以外で、始まりがその車の購入の出来事からの行（続きの車は、元の車を手放す出来事から始まる。同じ出来事から始まる車が何台かあれば、行の始まりより前に始まる車のうち、いちばん後に始まる車）は、「維持費」の後（「伸び方・万一のとき」の前）に出す。
- 行の頭のまとまりは車の枠の中の中枠にし、行の続くまとまり（払う人・額の変化など）も同じ枠の中に入れる。「▸」は車に1つ。
- どの車にも合わない行（年月で始まりを入れた行・区画の「＋」で足した行・始まりを車の出来事から外した行）は、今までどおり区画「出るお金」に出す。
- 「手放した後」の見出しの言葉と、維持費の中枠の中身は変えていない（同じ所を別の変更で直しているため、並べる所だけを直した）。

## 調べた範囲

- 見本の世帯（`data/modelHouseholds/` の全件）と空の世帯に、区画の「＋」を1回ずつ押した世帯を足して、16 の入力項目のすべてのまとまりの中の「＋」のボタン（選択肢のボタンは選択肢ごと）を押し、足したまとまりが押したまとまりの近く（同じ物のまとまりの続き）に出るかを見た（その場の点検の道具。リポジトリには入れていない）。
- 「＋ 年額の変化」などの段階・例外・内訳の行・金利の段階・繰上返済・塾・習い事・保障・更新・働き方などは、押した物の枠の中（足すボタンのすぐ上か下）に出ていた。ひな形のボタン（「よくあるライフイベント」「入れ忘れがないか」など）は区画の一覧に足す物で、人や物のまとまりではないので対象にしない。
- 直した 1〜3 のほかに、押したまとまりと離れて出る所が6つあった。そのうち2つ（車）は 5・6 で直し、残る4つは下の「利用者の判断」のとおり今のまま。

## 利用者の判断（2026-11-23。表のおすすめのとおり）

| 場所 | 前の並び | 決めたこと | 理由 |
