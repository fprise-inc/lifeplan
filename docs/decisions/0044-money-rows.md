# 0044. お金の行（入るお金・出るお金を同じ形の行に、課税の扱い、基本の計算に入れない物、確実な分だけで見る）

- 状態: 採用（一部未確定）（2026-10-26）
- 固定の強さ: β公開から変えない（骨格）。エンジンの入力の形（入るお金の行 `incomeFlows` の欄 `id`・`label`・`kind`・`taxTreatment`・`row`・`from`・`to`・`everyYears`・`monthly`・`amount`・`cost`・`growth`・`stages`・`exceptions`・`onContingency`・`recipient`・`counterparty`・`likelihood`・`includeInBase`・`giftMethod`、出るお金の行 `periodicExpenses` に足した欄 `monthly`・`kind`・`counterparty`・`payer`・`priority`・`gift`、表の行の選択肢の `cf.expense.education`・`cf.expense.living.car`、口座の間の移し替え `transfers` の形、負債の `inheritedFrom`・`likelihood`・`includeInBase`）、入力項目ID（`incomeFlow.*`・`transfer.*`・`periodicExpense.monthly`・`.kind`・`.counterparty`・`.payer`・`.priority`・`.gift`・`debt.inheritedFrom`・`.likelihood`・`.includeInBase`）、課税の扱いの9通りの意味、受け取る相続・遺贈・贈与の不確かな行を要求から外す決まり（エンジンは変えない）、確実な分だけで見る範囲は骨格。種類の一覧（足してよい。意味は変えない）・種類ごとの既定・カードの置き場所・画面の見せ方は後から変えてよい（変えたら追記に書く）

## 背景

- 出るお金は周期的な支出（`periodicExpenses`。n年ごとの1回の額）しか無く、入るお金（相続・贈与・援助・養育費・手当・副業・売却代金など）は表せなかった（預金に今から足す近似は時期がずれる）。入るお金が無いと、相続・家族・介護・親の画面の設計が成り立たない。
- 0035 の2・7 は、入るお金の行を「足すだけの形」とし、出るお金の行と同じ形の土台にする、課税の扱いを種類から既定で決める、見込みが不確かな受け取る相続・贈与と受け継ぐ借金は基本の計算に入れない（アプリが要求から外す）、口座の間の移し替えは入れ物だけ、と決めた。0036 の6 は、確実な分だけで見る見方を保存しない自動の差分で作ると決めた。
- 前提にする記録: 0002（金額・率・丸め）、0003（時点の型）、0006（部品の改訂）、0008（世帯のデータモデル・値の箱）、0035・0036（世帯ファイルの形・差分）、0038（時点の部品）、0040（段階と例外の年）、0041（値の状態）、0043（入力画面でプランを直す）。

## 決定

### 1. 入るお金の行（エンジンの入力 `household.incomeFlows`）

- 形は出るお金の行と同じ土台: 名前 `label`（表示だけ）・種類 `kind`・額 `amount`（値の箱。計算基準年の価格の1回の額。月額の行は月額）・時期（最初に受け取る月 `from`・終わり `to`〔空は最後まで〕・何年ごと `everyYears`・月額の行 `monthly`〔最初の月から終わりの月まで毎月。何年ごとは1だけ〕）・伸び方 `growth`（省略は前提の物価上昇率）・段階 `stages` と例外の年 `exceptions`（0040 と同じ形）・万一のときの扱い `onContingency`。向きは物の集まりで決める（マイナスの額は作らない）。
- 受け取る人 `recipient`（世帯の中の構成員。省略は世帯）・相手 `counterparty`（誰から。構成員。多くは世帯の外の家族）・見込み `likelihood`（`certain`・`likely`・`uncertain`。省略は「たぶん」）・基本の計算に入れる `includeInBase`・課税の扱い `taxTreatment`（省略は種類の既定）・表の行 `row`（省略は種類の既定）・必要経費・取得費 `cost`（値の箱。1回の額と同じ基準）・贈与税の課税の方法 `giftMethod`。
- 計算（部品 `income.flows`）:
  - 受け取りの月と額は出るお金の行と同じ解き方（共通の部分 `sdk/moneyRows.ts` の `moneyRowPayments`）。表の行に、受け取る月のお金の動きを入れる（受け取る人を入れた行は、その人のお金の動きとして）。
  - 受け取る人が世帯の外の家族の行は、世帯のお金に入れない（その人のお金の見通しの側で読む）。
  - 万一のときの扱いは、受け取る人を入れた行はその人の万一、入れていない行は世帯の万一（だれかの万一）の月の翌月から当てる。
- 種類（`kind`）と既定:

| 種類 | 課税の扱いの既定 | 表の行の既定（1回／くり返す） |
|---|---|---|
| `inheritance` 相続・遺贈 | 相続税で見る | 相続 |
| `giftReceived` 贈与を受ける | 贈与税で見る | 贈与（受けた資金援助） |
| `support` 援助・仕送りを受ける | 非課税 | その他の一時金／その他の収入 |
| `educationSupport` 教育資金の援助を受ける | 非課税 | その他の一時金／その他の収入 |
| `childSupport` 養育費 | 非課税 | その他の収入 |
| `propertyDivision` 財産分与 | 非課税 | その他の一時金／その他の収入 |
| `householdContribution` 同居の家族が家計に入れるお金 | 非課税 | その他の収入 |
| `benefit` 手当・給付金（額で） | 非課税 | 給付 |
| `unemployment` 失業給付などの額 | 非課税 | 失業の給付 |
| `survivorPension` 受給中の遺族年金・障害年金（額で） | 非課税 | 公的年金 |
| `foreignPension` 外国の年金（額で） | 雑所得（その他） | 公的年金 |
| `scholarshipGrant` 給付型の奨学金・学費の助成 | 非課税 | 教育の給付 |
| `childPays` 子が払う分 | 非課税 | その他の収入 |
| `sideJob` 副業・雑所得 | 雑所得（業務） | 副業 |
| `otherWork` その他の働く収入（給与） | 給与 | 給与 |
| `saleBusiness` 売却代金（事業・出資持分） | 譲渡所得（分離） | その他の一時金 |
| `saleGoods` 動産の売却（車以外） | 非課税 | その他の一時金 |

### 2. 課税の扱い（9通り）と、税・社会保険料へのつなぎ

税を受ける人は受け取る人（省略は本人）。今ある税の部品の入口を使う（部品 `income.flows` が人×年の所得 `byMember` を出し、各部品が読む）:

| 課税の扱い | つなぎ方 |
|---|---|
| `nonTaxable` 非課税 | 所得に入れない |
| `temporary` 一時所得 | 収入−必要経費を、保険の一時所得と合わせ、特別控除（50万円まで）を引いた2分の1を総所得金額に入れる（`tax.totalIncome` の `temporary`。保険の部品 `insurance.income` は特別控除の前の額 `temporaryGross` を添える） |
| `miscBusiness`・`miscOther` 雑所得（業務・その他） | 収入−必要経費を、公的年金等以外の雑所得として総所得金額に入れる（`miscellaneous`） |
| `salary` 給与（社会保険なし） | 本業の給与収入と合わせて給与所得にする（`tax.employmentIncome`）。社会保険料はかけない |
| `business` 事業 | 収入−必要経費を事業所得に足す（`tax.totalIncome` の `other`） |
| `capitalGains` 譲渡所得（分離） | 年の収入−取得費（0円より下げない）に、一般株式等の譲渡所得等の税率で所得税（1,000円未満を切り捨てた額×率に復興特別所得税・防衛特別所得税を足し、100円未満を切り捨て。翌年3月）と住民税（翌年6月）をかける（`income.flows` が出す。表の行 `cf.taxSi.incomeTax.capitalGains`・`cf.taxSi.residentTax.capitalGains`）。総所得金額には入れず `separate` で添え、合計所得金額の判定（所得控除・配偶者控除・扶養・寡婦とひとり親の判定）と、国民健康保険・後期高齢者医療の所得割と軽減の判定に足す |
| `inheritance` 相続税で見る | 所得税・住民税をかけない。相続税は計算しない（知らせ `N_NOT_SUPPORTED`〔`incomeFlow.inheritanceTax`〕。受け取る側の相続税の額は出るお金の行で入れる） |
| `gift` 贈与税で見る | 相手を贈与者として、受け取る人の贈与を `gift.received` に集め、`gift.tax` が暦年課税・相続時精算課税で計算する（世帯の外から受け取る贈与なので翌年3月に表に載せる。直系尊属から18歳以上は特例税率。相手が無ければ一般税率） |

- 一時所得・雑所得・事業所得の損失（必要経費が収入を超える）は、その区分の中で人×年に合わせて0円で止める（ほかの所得と通算しない）。
- 必要経費・取得費は、受け取る額と同じ割合で伸ばす（段階・例外の年・万一の割合も同じ割合）。
- 制度データに `incomeTax.generalShares.rate`（一般株式等の譲渡所得等の所得税の税率）・`residentTax.generalShares.rate`（同じく住民税）を足した（原本での確認待ち）。値の無い年は知らせ `N_PARAM_MISSING` を出し、税をかけない。

### 3. 出るお金の行（今の周期的な支出を広げる）

- 足した欄（どれも任意。無ければ今と同じ）: 月額の行 `monthly`、種類 `kind`（`general`・`allowance` 仕送り・`childSupport` 養育費を払う・`gift` あげる贈与・`education` 塾・習い事・留学・`repair` 修繕・リフォーム・`realEstateCost` 不動産の一時の経費・`livingAnnual` 年払いの暮らしの支出・`car` 車の修理・用品・`other`。表示と表の行の既定）、相手 `counterparty`、払う人 `payer`、優先度 `priority`（`need`・`want`・`wish`。省略は「必要」と読む）、あげる贈与 `gift`（`method` 暦年課税・相続時精算課税、`purpose` 使い道）。
- 払う人は世帯の中の構成員だけ（夫婦で別の財布は持たない）。入れた行の万一のときの扱いは、その人の万一だけに当てる。払う人が世帯の外の家族の行は世帯から出さない。
- **あげる贈与**: 相手（世帯の外の家族。孫など）への贈与。額は世帯から出す。受け取る人の贈与税は受け取る人が払うので世帯から出さず、要約（`summary.gifts`。`inCashflow: false`）に出す。相手が世帯の外の子・孫なら直系尊属からの贈与（特例税率）。使い道が「生活費・教育費をその都度払う」（`asNeeded`）の贈与は非課税なので集めない。住宅資金（`housing`）は住宅取得等資金の非課税を使う。相手の生年月が無いとき（画面の中では贈与者の形）は、贈与税の要約は出さない（画面が生年月を求める）。
- 表の行の選択肢に教育費 `cf.expense.education`・車の維持費 `cf.expense.living.car` を足した（行は今の登録簿にある）。
- 部品 `expense.periodic` の改訂4。段階と例外の年の解き方は 0040 のまま（入るお金と同じ共通の部分を使う）。

### 4. 1本の行を両側で読む（世帯の外の家族のお金との関係）

- 相手が世帯の外の家族で、その人のお金の見通しも見ているとき、1本の行を両側が反対の向きで読む（行を2本にしない）: 世帯の出るお金の行（仕送りなど。相手＝その人）はその人のお金に入る、世帯の入るお金の行（援助など。相手＝その人）はその人のお金から出る。
- 世帯の外の家族のお金（0042 の `outside.wallet`。お金を入れた人だけ）は、相手がその人の出るお金の行の支払い（`expense.periodic` のお金の動き）をその人のお金に入れ、相手がその人の入るお金の行の受け取り（`income.flows` のお金の動き。税の行を除く）をその人のお金から引く（部品の改訂2）。世帯の側は行のまま。
- 収入を世帯に入れる月（家計が1つの月）は世帯の中の移し替えなので読まない。その人のお金が尽きても、世帯が受け取る援助は行のとおり入る（尽きた後の援助の止め方は後の回）。

### 5. 基本の計算に入れない物と、確実な分だけで見る（アプリの側。エンジンは変えない）

- **基本の計算に入れない**: 見込みが「不確か」で `includeInBase` が `true` でない、受け取る相続・遺贈・贈与の入るお金の行（種類 `inheritance`・`giftReceived`）と、相続で受け継ぐ借金（`inheritedFrom` のある負債）。アプリがエンジンへ要求を渡すところ（`app/src/engine/moneyRows.ts` の `forEngine`。画面側のエンジン・本体の正の計算・根拠の記録・万一の画面・提案書・持ち帰り用のレポートの計算のすべての入口）で外す。世帯のデータからは消さない。ほかの種類の入るお金には広げない。外す物が無ければ要求は同じ物（計算し直さない）。
- 画面は行に「計算に入れていません」と出し、詳細の「基本の計算に入れる」（`includeInBase` の `set`）で入れられる。プランを直しているときは、そのプランの差分になる（見込みは事実の見立てなので変えない）。
- **確実な分だけで見る**（0036 の6 の保存しない自動の差分）: 見込みが「不確か」の入るお金の行のすべてと、優先度が「希望」「夢」の出るお金の行を外した要求で、結果のタブの全部のプランを計算し直して見る切り替え（`certainOnly`）。外した行の数を見出しに出す。保存しない。外す行の無い世帯では切り替えを出さない。

### 6. 口座の間の移し替え（入れ物だけ）

- `household.transfers`: `{id, label?, at, from, to, how, linked?}`。`how` は `{kind: "amount", amount}`・`{kind: "ratio", ratio}`・`{kind: "all"}`・`{kind: "over", threshold}`（残高が決めた額を超えた分）。`linked` は結び付けたお金の行。
- 画面には出さない。計算に入れるまで、あればエンジンは知らせ `N_NOT_SUPPORTED`（`transfers`）を出して計算に入れない。

### 7. 相続で受け継ぐ借金

- 負債（ほかのローン）に、元の借り手 `inheritedFrom`・見込み `likelihood`・基本の計算に入れる `includeInBase` を足した。計算には使わない（5 の決まりでアプリが外す）。返済の欄は今のローンの欄で入れる。

### 8. 入力の部品とカードへの置き方（画面）

- 1行のまとまり（簡易）: 見出しに「名前　額・1回／毎月／毎年／n年ごと　時期」（2026-10-31 に「入／出｜」を外した。末尾の追記）。欄は名前・種類（そのカードで選べる種類が2つ以上のとき）・時期（1回／毎月〔月額〕／毎年・n年ごと）・額・始まり（時点の部品。0038）・何年ごと・終わり・札（入るお金は見込み、出るお金は優先度。既定は薄い字）。相続・贈与の区画だけ相手も簡易。詳細に既定と違う値があれば「詳細あり: …」。不確かで基本の計算に入れていない行は「計算に入れていません」。
- 詳細は3つのまとまり: 課税の扱い（課税の扱い・必要経費・贈与税の課税の方法。欄の下に結果への効き方の一文）／受け取る人・相手・伸び方・万一のときの扱い・表の行（受け取る相続・贈与は「基本の計算に入れる」も。出るお金は払う人・相手・伸び方・万一のときの扱い。あげる贈与は使い道と課税の方法）／段階と例外の年（0040 の部品）。
- 足すときの値: 入るお金の額は「未入力（0円で計算中）」（目安を作らない。相続・援助の額は外れると大きく誤るため）、出るお金は種類のひな形の推定（目安のボタンの値。0041）。確定は明示の操作だけ（0041）。
- カードの置き場所（行の種類で決める。同じ種類はいつも同じカード）:

| カード | 入るお金 | 出るお金 |
|---|---|---|
| 家族 | 養育費を受け取る・財産分与・同居の家族が家計に入れるお金・手当・給付金 | 養育費を払う・仕送り（相手が親・祖父母でないとき） |
| 働き方と収入 | 副業・雑所得・失業給付などの額・その他の働く収入・売却代金（事業・出資持分） | — |
| 年金 | 受給中の遺族年金・障害年金・外国の年金 | — |
| 子ども・教育 | 教育資金の援助・給付型の奨学金・子が払う分 | 塾・習い事・留学など |
| 住まい・ローン | 住まいの補助金・移住の支援金・売電の収入 | 修繕・リフォーム |
| 保険 | 計算の型に無い保険の給付の見込み | — |
| 貯蓄・運用 | — | 不動産の一時の経費 |
| 基本生活費 | — | 年払い・数年おきの暮らしの支出（表の行の既定は「基本生活費に含める」） |
| 車 | — | 車の修理・用品など（表の行の既定は「車の維持費」） |
| ライフイベント | 祝い金・お見舞い・一時の給付金・一時所得・動産の売却・その他の入金 | 一時的支出・n年ごとの支出（今の行。種類の無い古い行もここ）・その他の支出 |
| ライフイベントの中の「介護・親」の区画 | 援助・仕送りを受ける | 親への仕送り |
| ライフイベントの中の「相続・贈与」の区画 | 相続・遺贈・贈与を受ける（＋相続で受け継ぐ借金） | あげる贈与（＋世帯の外の孫を足す） |

  介護・親と相続・贈与のカードはカードの組み直しの回に作る。それまではライフイベントのカードの区画に置く。ライフイベント以外のカードのお金の行の区画は詳細に出す。
- 家族のカードの仕送り（月額）の欄に値があって、その人を相手にした仕送りの行が無ければ、「＋ 仕送りを出るお金の行にする」を出す（押したときだけ作る。黙って支出にしない。0035 の11）。
- 欄はどれも当て先（向き先は行そのもの・入力項目ID・場所。0036 の2）を持ち、プランの編集（0043）と値の状態の操作（0041）にそのまま乗る。行を足す・外すは `add`・`remove`、欄を直すと `set`。

### 9. 古い世帯

- 何もしなくても読める: 種類・優先度・相手・払う人の無い周期的な支出は、ライフイベントのカードの出るお金の行（優先度は「必要」、時期の入れ方は今の値から読む）。開いても書き換えない。
- 世帯ファイルの形式を `0.20` に上げた（足すだけの MINOR。0035 の1）。`0.19` → `0.20` の変換の段は版だけを書き換える。見本 `crates/household-store/tests/fixtures/household-format/0.20/`（不確かな相続・必要経費と段階と例外の年のある副業・月額の援助・贈与税で見る贈与・あげる贈与・仕送り・口座の間の移し替え・受け継ぐ借金・「基本の計算に入れる」の差分と入るお金の行を足す差分）。並びの要素の ID の一覧（0035 の5）に、入るお金の行の段階と例外の年を足した（新しい並び。画面は足すときに乱数の ID を付ける）。

## 理由

- **出るお金と同じ土台にする**: 時期・額・伸び方・段階・例外の年・万一の解き方を1つにでき、画面の部品とプランの差分の当て方も同じになる。行を作ったカードの区画で向きが決まるので、マイナスの額を作らない。
- **課税の扱いを種類の既定＋詳細で直す**: FP は種類を選ぶだけで正しい税の部品につながり、例外（1個30万円を超える貴金属の売却など）は詳細で直せる。種類ごとに別の計算を作らない（項目を増やさない）。
- **今ある税の部品の入口に足す**: 給与所得の控除・一時所得の特別控除・合計所得金額の判定・贈与税の暦年課税と精算課税は、すでに部品がある。入るお金の行の所得をそこに足せば、控除の段・扶養・社会保険料の判定まで同じ決まりで動く。一時所得の特別控除は人×年に1つなので、保険の一時所得と合わせて引く。
- **譲渡所得（分離）の税をこの部品で計算する**: 一般株式等の税率は一定で、計算が小さい。総所得金額に入れると累進の税になって大きくずれる。
- **不確かな相続を要求から外す**: 当てにならない遺産で楽な結果を見る誤りを防ぐ。エンジンに見込みの決まりを入れず、作業中の世帯から要求を作るときに外せば、プランの見込み・`includeInBase` の差分がそのまま効き、エンジンの計算と3つの実行環境の一致の確かめは変わらない。
- **確実な分だけで見るを保存しない**: 見方であってプランではないので、差分として残すと現状を直すたびに古くなる。

## 代案（採らなかったもの）

- **入るお金を周期的な支出の0円の行や、預金への足し込みで表す**: 時期がずれ、課税・表の行・見込みを持てない。
- **課税の扱いごとに別の物の集まりにする**: 画面の部品と差分の当て方が増える。
- **見込みが不確かな行の外し方をエンジンに入れる**: エンジンの入力の意味が見込みで変わり、一致の確かめと部品の改訂が増える。
- **譲渡所得（分離）を一時所得や雑所得で近似する**: 事業・出資持分の売却では税が大きくずれる。
