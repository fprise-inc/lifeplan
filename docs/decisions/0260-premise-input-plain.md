## 決定（利用者の判断。下調べの案のおすすめのとおり。「確かめた」の記録だけは消す）

### 1. 前提条件はふつうの欄の形

- 区画は、計算の期間（表を何歳まで見るか）・経済の前提・結果のタブで動かした利回り・金利（ある世帯だけ）・資産の種類ごとの利回り・不動産の評価（持ち家・収益不動産など。不動産のある世帯だけ）・計算の基準の月と計算の決まり・FP顧問料、その下に前提と推定の一覧。
- 標準: 計算の期間・経済の前提の物価の上昇率と給与の上昇率・FP顧問料・一覧。詳細: たたまずに全部（経済の前提に預金の利回り・教育費の上昇率・年金の調整率〔基礎年金・厚生年金〕を足した6つ、資産の種類ごとの利回り、不動産の評価、計算の基準の月と計算の決まり）。前の「お客さまと確かめる前提」の見出しと、細かい前提をたたむ1行（`PREMISE_FOLD_SECTIONS`・`inPremiseFold`・`premiseSummary`）はやめた。経済の前提は1つの枠で、標準では「▸ 続きを見る」も出さない（詳細に切り替えて見る。まとまりの `noMore`）。
- パネルの名前の下にいつも1文: 「値は事務所の既定値です。この世帯だけ変えるときは欄を直します（「この世帯だけ」と出て、いつでも戻せます）。」（入力項目の定義の `headNote`。前の「?」の中の入力項目の説明 `lead` とは別）。
- 欄ごとの「事務所の既定値」の印は出さない。事務所の既定値と違う欄だけ、名前の横に「この世帯だけ」と、欄の下に「事務所の既定値（1%）に戻す」（4列の資産の種類ごとの利回りは「戻す」）。事務所の既定値が後で変わった欄は「既定値が変わりました」と「今の既定値（0.2%）にする」。値の状態（確定と読む）・確かめの一覧の知らせは今までどおり（1押しの名前は「この世帯に反映する」に言い換えた）。
- 例外の年は、区画「例外の年（経済の前提）」のボタンの並びをやめ、率の欄の下の小さなリンク「＋ 例外の年」（詳細だけ。欄の `links`。探して開く・書類の読み取りは `groupActions` で欄のリンクも探す）。足した例外の年は、その区画の欄の並びの下のまとまり。資産の種類ごとの利回りは、今までどおり値を入れた種類だけ。
- 空欄の欄は、計算に使う値を欄の中に薄く見せる（`FieldState.blankShown`。推定の見た目にしない）。教育費の上昇率・土地の上昇率は「空欄: 物価の上昇率と同じ」、厚生年金の調整率は「空欄: 基礎年金と同じ」、預金・外貨預金は「空欄: 預金の利回りと同じ」。ほかの資産の種類は値だけ（区画の頭の1文と「?」で、空欄は事務所の既定値で計算すると言う）。
- お客さまへの一言は「例」の1行に短くした（物価の上昇率「例 30年後の100万円は、今の約74万円の値打ち」、給与の上昇率「例 年収500万円は、20年後に約610万円（物価と同じ）」）。前の長い言い方は欄の「?」の中に「お客さまへの話し方の例: …」で置く（`FieldState.talkHelp`）。表を何歳まで見るかは、欄の下に「2027年〜2083年の57年分（ご本人102歳・配偶者100歳の年まで）」。
- 欄の名前は2行に折れないように短くした（「（年）」を外す: 預金の利回り・教育費の上昇率・年金の調整率（基礎年金）・年金の調整率（厚生年金）・土地の上昇率・売却の費用）。耐用年数は不動産の評価の枠の中の小さな見出し「耐用年数」と、構造の名前の4つの欄。前提条件の id・欄のキー・値の置き場所（address）は変えない。事務所の既定値の画面の名前は前のまま（`PremiseDef.officeLabel`）。計算の決まりの欄は「お金の数え方」「運用益の数え方」。
- 確かめの一覧・AI接続口の行の名前は「区画の名前: 欄の名前」なので、「経済の前提: 物価の上昇率」「計算の期間: 表を何歳まで見るか」のようになる。

### 2. 運用の利回りは世帯の入力の画面から外す（計算は変えない）

- 世帯の前提条件の画面には、標準・詳細とも出さない。値は今までどおり事務所の既定値の「前提条件の既定値」で決め、新しい世帯に写し、世帯の値で計算する（作った世帯は黙って変えない。0073 の3）。事務所の既定値の画面の名前は「配分も利回りも入れていない運用の口座」（`INVESTMENT_RETURN_LABEL`。前の「運用利回り（年）」）。
- 黙って隠れる所を残さないため: 前の世帯で「この世帯だけ」の値がある・事務所の既定値が後で変わった（確かめの一覧の知らせから移れるように）・例外の年がある・推定の印のままの世帯だけ、詳細の資産の種類ごとの利回りの区画の最後に1行で出す（`investmentReturnShown`。「戻す」で事務所の既定値にすると出なくなる）。欄の表 `PREMISE_DEFS` には残す（知らせ・AI接続口の id・事務所データは今までどおり）。
- 世帯で変えたいときは、貯蓄・運用の口座ごとの「利回り（年）」に入れる。口座の利回りの空欄は「空欄: 年1.0%（事務所の既定値）」のように出どころを出す（口座の表の欄の下にも「空欄: 事務所の既定値」。資産の配分の口座は「資産の配分から」、預金・外貨預金は「預金の利回り」〔資産の種類ごとの利回りにあれば「資産の種類ごとの利回りの外貨預金」など〕、暗号資産は「今の評価額のまま」、前の世帯のこの世帯だけの値なら「前提条件のこの世帯の値」、事務所の既定値が後で変わった値なら「前の事務所の既定値」）。合計の入れ方の平均の利回りの説明も同じ出どころ。
- お客さまと確かめる前提（AI接続口の入力の確かめの `premise: client`）は、前提条件の標準に出す欄（表を何歳まで見るか・物価の上昇率・給与の上昇率）。見分けは区画のキーでなく欄の入れ方（標準か詳細か。`premiseWithClient`）で決める（前の `TALK_PREMISE_SECTION` はなくした）。
- 入力のホームの要約は「物価 1.0%・給与 1.0%・100歳まで」。運用の利回りのこの世帯だけの値は、下の小さな1行「細かい前提: この世帯だけ変えた所 N件」に数える。
- 提案書の前提の一覧の「運用利回り（資産の器ごとの指定が無いもの）」の行は、その率を計算に使う物があるときだけ出す: 提案・比較のプラン・必要保障額のどれかの計算の要求で、利回りも配分も入れていない運用の口座・資産の種類ごとの利回りが空欄の配分の種類（預金の種類・不動産を除く）・預金の利回りの無い前の要求の預金・資産の種類の利回りの無い保険の貯蓄型（変額・外貨建て）・必要保障額の逆算方式（`engine/src/sdk/returnUse.ts` の `investmentReturnUsed`。入力の形だけで決め、迷うときは「使う」）。見本・モデル世帯では、使わないと判定した世帯は、この率を変えても結果が1円も変わらないことをテストで確かめる。
- 万一のときのタブ: 必要保障額を逆算方式で出す世帯（見ているプランの前提）は、想定の前提の下に「遺族の資金の運用の利回り: 年1%（事務所の既定値）。必要保障額の逆算方式で、遺族の金融資産をこの率で伸ばして数えます…」を出す。
- AI接続口の表・グラフの前提の注（「運用利回り 1%（資産ごとの指定が無いもの）」）は、この回では変えない。

### 3. 前提と推定の一覧（読むだけ）

- 「確かめた」の列と、確かめる操作（`setAgreed`・`agreedKey`）をなくした。一覧は読むだけで、行の名前から前提条件の欄へ移れる。
- 区分は見出しの行（列にしない）。列は項目・値・状態・出典・根拠の4つ。状態は欄と同じ印（事務所の既定値どおりは印なし・「この世帯だけ」は藍・「既定値が変わりました」「推定」は橙・「決まり」は灰。`AssumptionRow.tone`）。
- 出典は短く: 事務所の既定値どおりは「事務所の既定値」（事務所で決めた値は「事務所の既定値（年月）」。提供元の既定の値であることは一覧の「?」の中で言う）、この世帯だけは「この世帯で入れた値（事務所は 1%）」、変わった物は「前の事務所の既定値（今は 1.5%）」。
- 事務所の既定値どおりの資産の種類ごとの利回りは1行「そのほかの種類（10）」（全部どおりなら「どの種類も（14）」）に、事務所の既定値どおりの耐用年数は1行「耐用年数（木造・軽量鉄骨造・重量鉄骨造・鉄筋コンクリート造）22・19・34・47年」にまとめ、違う物だけ1行ずつ。運用の利回りは、画面に出す世帯だけ資産の種類ごとの利回りの区分に出る。
- お客さまと確かめたことを残したいときは、面談の記録・メモに書く（今ある仕組み）。

- 前提条件のパネルと前提と推定の一覧は、文字を5段＋印にそろえる（段1 パネルの名前 20px・段2 区画の見出し 16px 太・左の線・段3 まとまり・表の見出し 14.7px 太・段4 欄の名前〔太〕・値・本文 14.4px・段5 説明・空欄のときの値・例・出典・リンク 12.8px 灰・印 11.8px 太。文字の大きさ「中」のとき）。余白は区画の間 24px・見出しと中身 8px・欄の間 縦14px 横24px・枠の内側 12〜16px。率の欄は経済の前提と計算の決まりが3列、資産の種類ごとの利回り・不動産の評価・耐用年数が4列（幅が狭いときは2列）。`app.css` の `.ipanel[data-item="assumptions"]` の中だけで決め、ほかの入力項目は変えない。5段の値は、事務所の既定値の画面の5段と同じ値にそろえる（共通の変数にまとめるのは後の回）。

## 理由

- 前提条件だけ形が違うと、FP は入力項目ごとに読み方を変えることになる。ほかの入力項目と同じ区画・欄・印の決まりにするのが、ちぐはぐと長さの両方にいちばん効く。事務所の既定値の値は、違う欄でだけ要る情報なので「戻す（1%）」で足りる。
- 運用の利回りは、口座ごとの利回りか資産の配分で決まる世帯がほとんどで、世帯の前提として最初に見せると、効いていない率をお客さまと確かめることになる。値そのものをなくすと、利回りを入れていない口座の計算が変わる（作った世帯の結果が黙って変わる）ので、画面から外すだけにした。外した後も、前の世帯の値・知らせ・空欄の出どころは見えるようにした。
- 「確かめた」は計算にも書類にも使っていない記録で、残しておいて困る物は無いので、世帯ファイルからも消した（利用者の判断）。

## 代案（採らなかったもの）

- 事務所の既定値と並べる表の形（項目・この世帯の値・事務所の既定値の列）: 事務所の既定値がいつも見えるが、ほかの入力項目と違う形になり、詳細は今の案より長い。お客さまへの一言の置き場所も狭い。
- 運用の利回りを詳細の資産の種類ごとの利回りの区画に、名前を変えていつも出す: 世帯の画面に効いていない率が残る。前の世帯の値がある世帯だけ出す形で足りる。
- 運用の利回りの値そのものをなくす: 上の理由（作った世帯の結果が変わる）。
- 「確かめた」の記録を世帯ファイルに残す（形式の版を上げない）: 読み書きの道を残す理由が無い（利用者の判断）。
