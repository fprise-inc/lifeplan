## 決定

### 1. 控除証明書の電子データの残りの読み手（`documents/certificatesXml.ts`。0153 の読み手に足す）

- 読み手は同じ（ID `xml.deductionCertificate`、**版を 2 に上げた**。読める証明書が増え、日付の読み方が増えたため）。1つのファイルに何通入っていてもよく、証明書1通を読み取りの記録1件にする（0153 のまま）。値の読み方（金額・和暦と西暦の日付・区分・文字の番号を消す）は `documents/xmlValues.ts` にまとめた（0153 の読み手も同じ部品を使う）。
- **読まない要素**（木に入れない。`CERTIFICATE_SKIPPED` を 0153 の `SKIPPED` に足した）: 国民年金保険料等の基礎年金番号等・被保険者の氏名と住所・その他の特記事項・発行団体・ユニークコード、**小規模企業共済等の氏名・住所・共済契約者番号／基礎年金番号**・備考（全体と月ごと）・ユニークコード、年末残高等の借入れ等をしている者（住所・氏名）・連帯債務者名・債権者の所在地と事業免許番号等・参考事項（法人番号・支店名・連絡先・番号・発行回数・その他）、住宅借入金等特別控除のあて名（郵便番号・住所・氏名）・税務署長名・整理番号／お問い合わせ番号・備考。
- **国民年金保険料等控除証明書**（書類の種類 `pensionPremiumDeduction` を足した）:
  - 国民年金保険料は、アプリが加入の状態から計算するので**照合だけの値**（「国民年金保険料（○年の納付額）」。合計額か納付済額＋見込額。行 `cf.taxSi.pension` と証明の年で比べる）。前納の証明書は1年分と限らないので、行と比べない。
  - 国民年金基金の掛金は、今の国民年金基金の掛金（月額 `retirementBenefit.contributions` の `["monthly"]`、名義の人の物）の候補（合計を12で割り切れれば月額、割り切れなければ年額のまま〔直して入れる〕。確からしさ中）と、照合だけの値（行 `cf.taxSi.pension.fund`）。国民年金基金を書類から新しく足す形は作っていない（足すボタンのキーが人ごとに違う。下の未確定）。
  - その他の種別は照合だけの値。
- **小規模企業共済等掛金控除証明書**: 掛金の種別で新しい物 `account:ideco` か `account:smallBusinessMutualAid` の候補1件と、名義 `account.owner`（書類の名義の人。氏名は読まないので確からしさ中）・毎月の積立 `account.contributions`（小規模企業共済は掛金月額、iDeCo は月ごとの金額のいちばん後の月。月ごとに違えば確からしさ中と添え書き。どちらも無ければ控除の合計額を12で割り切れるときだけ）・小規模企業共済の加入した年月 `account.enrolledSince`（契約年月日）。控除の合計額は照合だけの値。掛金の種別が読めなければ読まない。
- **年末残高等証明書**（金融機関）: 借入の明細ごとに新しい物 `debt:mortgage` の候補（名前の代わりに、元の場所の文字に「債権者 住宅ローン（内訳）」）と、残高 `debt.balance`・残高の時点 `debt.balanceAsOf`（残高基準日。無ければ証明の前の年の12月で確からしさ中）・借入額 `debt.principal`（当初金額）・**借りた年月 `debt.start`**（当初借入年月日。時点の欄。4）・**完済の年月**（返済期間の欄 `debt.repayment` の `["termMonths"]` に、償還期間の至の年月。至が無ければ当初借入年月日＋年数・月数で確からしさ中）・ローンの名義 `debt.debtors`（連帯債務の記載があれば「夫婦で連帯債務」、無ければ書類の名義の人。どちらも確からしさ中。種類を決める欄なので1つずつ承認）。家屋の取得の対価等の額は照合だけの値（控除の取得対価の欄は、控除を受ける形にしてから出る欄で、家屋の分だけの額のことがあるため）。
- **年末調整のための住宅借入金等特別控除証明書**（税務署。書類の種類 `housingLoanCredit` を足した。8つの版の札の対応は `LOAN_CREDIT_FORMS`）: 明細ごとに `debt:mortgage` の候補（ふつうは今あるローンに当てる。確からしさ中）と、入居の年月（控除）`debt.housing`（居住開始年月日。新築等が無ければ増改築等）・住宅の種類 `debt.housing` の `["propertyType"]`（住宅の区分等の言葉: 認定住宅・ZEH・省エネ基準適合。区分の記載が無ければ適用種別の言葉から、認定住宅用 → 認定住宅、ただの居住者用 → その他の住宅、で確からしさ中）・新築か中古か `["newBuild"]`（新築・買取再販 → 新築、中古住宅 → 中古）。令和5年以降の居住の版は、年末残高（住宅のみ・土地等のみ・住宅及び土地等の合計）と、その時点（年末調整の年の12月）。どちらも確からしさ中（金融機関の見込みの額）。控除率・限度額・控除額はアプリが計算するので読まない。
- 額の書かれていない証明書は「読める値がありません」と理由を出して記録にしない。証明書の要素が1つも無いファイルは、読める証明書の種類を並べた理由を出す。

### 2. 書類から足す新しい物の種類（`documents/objects.ts`）

- `debt:mortgage`（住まいの「＋ 住宅ローン」と同じボタンで作る。今の残高から入れるローンになる）・`account:ideco`（「＋ iDeCo」）・`account:smallBusinessMutualAid`（「＋ 小規模企業共済」。足せる人〔事業所得・役員〕のいない世帯ではボタンが無いので足せず、理由を出す）を足した。0152 の申し送りのとおり、欄の一覧（`fields.md`）を作り直し、住宅ローンの手引きの「今は足せない」を直した（新しいローンの答えの見本を足し、見本の世帯で承認まで通すテストに入れた）。
- 物の種類ごとに、今ある物のうち同じ種類の物（`sameKind`）と持ち主（`ownerOf`）を持つ。保険は今までの見分け方（細目かひな形）、ローンは住まいの住宅ローン、口座は同じ口座の種類。

### 3. 今ある物に当てる（`documents/review.ts` の `linkObject`・`linkTargets`）と、「この書類を読む」の入口（`documents/start.ts`・`DocumentStart.tsx`）

- **今ある物に当てる**: 新しい物の候補ごとに「足す」「足さない」に加えて、同じ種類の今ある物ごとに「今の○○「名前」に当てる」を出す（名義の人の物を先に。4件まで）。当てると、物の候補は「足した」と同じ状態（`accepted`）で、`created` に当てた物の ID と印 `linked` を持つ。物は作らず、その中の値の候補は当てた物の欄に当たる（値は今までどおり1つずつ承認。今の値と違えば「違う」で、まとめての承認に入らない）。同じ種類でない物には当てられない。知らせの文は「同じなら『今の○○に当てる』で、今の○○の欄に入れられます」に変えた（0148 の「同じなら足さないにして今の契約を直す」は、この操作で代わる）。保険の入れ漏れの一覧では「今の契約に当てました」。
- **「この書類を読む」の入口**（0148 の段取りの5）:
  - 書類のお願いの1通ごと（`DocRequests`）に「この書類を読む」。その1通の持ち主（`DocRequest` に足した `holder`〔人〕と `object`〔保険の契約・ローン〕）を初めの値にする。
  - 入力の欄の書類待ちの印の中（`StateMark`。入力のパネルが置く文脈 `DocReadContext`）に「この書類を読む」。その欄の書類（書類のお願いの1通）の入口と同じ。
  - 保険・年金の入力項目の見出しの下に「書類から読む: ○○は AI の答えを貼り付けて、○○は電子データ（XML）をこのパソコンの中で読めます。」の1行と「書類から読む」（`STAGE_STARTS`）。
  - どれも「この書類を読む」の画面を開き、電子データで読める書類なら「XML のファイルを選ぶ」、AI の答えを貼り付ける（貼り付けの画面は、その書類の種類の読み方の手引きを選んだ形で開く）、AI接続口（保存した世帯だけ）、欄に打つ、を並べる。
  - 入力のパネルから進むときは、保存していない変更を保存してからパネルを閉じて進む（確かめの画面は現状を直すので、パネルの下書きと食い違わせない）。プランの編集中は入口を出さない（取り込みは現状に入るので。0072 の4）。
  - 読んだ記録には、名義の人が決まっていなければ入口の名義の人を、人も物も書かない候補で書類の物と同じ集まり（保険 `insurance.`・ローン `debt.`）の候補には書類の物を入れる（`withStart`）。新しい物の候補は黙って当てない（確かめの画面で FP が「今の○○に当てる」を選ぶ）。
- 書類のお願いの書類の名前 → 書類の種類: ねんきん定期便 → 定期便、住民税の決定通知書 → 住民税の決定通知書、保険証券 → 保険証券、返済予定表 → 返済予定表（住宅ローンなら電子データの年末残高等証明書・住宅借入金等特別控除証明書も読める）、会社の退職金規程 → そのほかの書類。

### 4. 当て先と承認の決まりの足し（`documents/apply.ts`・`review.ts`。足すだけ）

- **時点の欄に書類の年月を入れる**: 時点の欄（`when`）は、候補の値が年月（`YYYY-MM`）のときだけ、決まった年月の時点として入れる（年齢・出来事で決める入れ方は欄で直す）。直すときも年月で入れる。0148 の未確定「時点の欄を書類から入れる形」の一部を決めた。欄の一覧にも時点の欄を「年月（YYYY-MM。時点の欄）」として載せた。手引きは住宅ローンの借りた年月だけを書く形に直し、保険の保険期間・払込期間（年齢で決まることが多い）は今までどおり書かない。
- **続柄の選択肢の欄に書類の名義の人を当てる**: 選択肢の値が続柄の鍵（ローンの名義の `self`・`spouse` など）の欄で、候補の値が `holder` なら、名義の人の続柄に当てる（名義を選ぶまで承認できない）。
- **値の形で当てる欄を絞る**: 当てる欄が何本もあり、人か物の書かれた候補なら、候補の値をその欄の形にできる欄に絞る（口座の「毎月の積立」〔円〕と「積立の終わり」〔時点〕のように、同じ入力項目の場所の無い欄が2つあるとき）。人も物も書かない候補は今までどおり1本でも FP が選ぶ（0152 の3）。
- 年数・月数の欄に年月の候補が来たとき（借入額から入れたローンの「返済期間（年）」に、書類の完済の年月）は、「年月の値です。この欄は年数で入れるので、書類を見て直して入れてください」と理由を出す（黙って換算しない）。

### 6. AI 向けの説明書・手引き（0152 の足し）

- AI接続口の道具の入力の形（`propose_inputs`）の書類の種類に2つを足し、物の種類の説明を直した（見本 `input-schema.json` も）。

## 理由

- **国民年金保険料を照合だけにする**: アプリは第1号の期間から保険料を計算する。証明書の額を入力にすると、免除・前納・追納の月の扱いが入力と計算で二重になる。差を見せれば、加入の状態の入れ誤りに気づける。
- **ローン・口座を新しい物の候補にし、今ある物に当てる操作を足す**: 読み手は世帯を見ないので、今の物に当てるか新しく足すかは書類からは決められない。黙ってまとめると、同じ銀行の2本目のローン・夫婦それぞれの iDeCo を取り違える。足す・当てるを FP が選ぶ形なら、入れ漏れと二重の入力の両方を防げる。保険の「同じ契約かも」も、この操作で今の契約に入れられるようになった。
- **完済の年月で返済期間を入れる**: 書類から足すローンは今の残高から入れる形になり、その形の返済期間の欄は完済の年月。証明書の償還期間の至の年月がそのまま当たる。借入額から入れた今のローンでは年数の欄なので、理由を出して直してもらう（ローンの入れ方は書類からは決めない）。
- **時点の欄は年月だけ**: 書類に印字されているのは年月で、年齢・出来事で決める形は FP の判断。年月の時点として入れれば、欄の「年月」の入れ方と同じになり、後から年齢の入れ方に直せる。
- **入口の初めの値**: 書類のお願いは持ち主ごとの1通なので、どなたの書類か・どのローンの書類かが決まっている。FP に同じことを2回選ばせない。新しい物の候補だけは黙って当てない（当てる操作は1つずつ見える方がよい）。
- **入力のパネルから進むときは保存する**: 確かめの画面で承認すると現状が変わる。パネルの下書きを残したまま進むと、パネルを保存したときに承認した値を上書きする。

## 代案（採らなかったもの）

- 読み手に世帯を渡して、今ある物に当てる候補を読み手が作る: 読み手は書類だけを見る部品のまま（テストと AI の答えと同じ口にする）。当てるのは確かめの画面の操作にした。
- 小規模企業共済等の証明書の氏名で名義の人を当てる: 名前を読まない決まり（0148 の3）のとおり、名義は FP が続柄で選ぶ。
- 住宅借入金等特別控除証明書の控除率・控除額を照合だけの値にする: アプリの控除の計算は年ごとの残高と入居の年で決まり、行の年と証明書の年分を合わせる形がまだ無い。値が多くなり確かめの画面を重くする。
- 公的年金等の源泉徴収票の電子データを、仕様を見ずに推測で読む: 要素の名前が分からず、取り違えるおそれがある。
