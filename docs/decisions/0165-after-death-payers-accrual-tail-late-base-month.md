# 0165. 亡くなった後のお金の名義（国保・後期高齢者医療・介護保険の第1号の世帯主と払う人、小規模企業共済の死亡の共済金、給付を受け取る親）・発生の年の表の最後の年・制度データより先の計算基準月

- 状態: 採用（一部未確定）（2026-11-08）
- 固定の強さ: 骨格（発生の年で集める表〔`aggregation: "accrual"`〕に、表の最後の年に帰属して表の後に払うお金も載せること。0003 の追記）。sdk に足した関数（`presentAt`・`householdHeadAt`・`firstPresent`・`reassignAfterLeave`）は試験版（0006 の部品の約束と同じ）。部品の中身（各部品の改訂）と、後ろの計算で延ばす年数（2年）は内部
- 前提にする記録: 0003（時間の規約・2本の時間軸・`aggregation`）、0008（世帯のデータモデル・万一の重ね）、0035 の4（世帯の外の家族の判定の世帯）、0039（相続税の目安）、0099（延長の仮定・さかのぼりの仮定）、0119（差し替えられる部品）

## 背景

性質テスト（全モデル世帯で、本人の亡くなる時期・計算基準月・表の長さをずらして計算し、どの世帯にも成り立つはずの性質を確かめる）で、次の5つが見つかった。

1. **計算基準月が2030年4月以後だと、JS の例外（TypeError）で止まる。** 年金の改定率（`pension.revision`）は、計算基準月の年度の3年前から表の最後の年度までの窓の中で制度データの値を探し、窓の中に値が無いと最初の値を読めずに止まった。再評価率（`pension.record`）は10年度前までしかさかのぼらず、国民年金の保険料（`socialInsurance.nationalPension`）は基準月の2年前より後に値が無いと賃金で延ばさずに最後の値のままだった。54のモデル世帯を計算基準月 2030-04・2033-04・2038-04・2050-04 で計算すると、216回すべてが止まった。
2. **本人（世帯主）が亡くなった後も、国民健康保険・後期高齢者医療の世帯主が亡くなった本人のまま。** 世帯主を「本人の構成員」の決め打ちにしていたので、亡くなった後の年度も、亡くなった本人の前の年の所得が遺族の軽減の判定に入り、亡くなった後に払う保険料が亡くなった本人の名で出た（社会保険料控除も遺族に付かなかった）。介護保険の第1号の保険料も、亡くなった月より後に払う分割の残りが亡くなった人の名で出た。
3. **小規模企業共済の共済契約者が亡くなっても、生前の受け取りの予定どおりに受け取り、亡くなった人の所得として退職所得・雑所得の税がかかった。**
4. **発生の年で集める表は、表の最後の1〜2年のお金を落とした。** 表の最後の年に帰属して表の後に払うお金（11・12月分の年金を翌年2月に払う、最後の年の所得の住民税を翌年に払うなど）は、計算が表の終わりで切れるので無かった。表の長さを変えると、同じ年の行の額が変わった。
5. **亡くなった親の名で、児童手当・高等学校等就学支援金などを受け取り続けた**（受け取る親を「子の最初の親」の決め打ちにしていた。額は同じで名義だけ）。

## 決定

### 1. 制度データの最後の年度より先の計算基準月（止めずに延ばす）

- `pension.revision` 改訂3: 窓の中に値が無ければ、値のある最後の年度まで最大100年前へさかのぼって探し、そこから前提（物価・賃金・マクロ経済スライド）で延ばす。表もその年度から出す。値が1つも無いデータの組（架空の見本など）では `E_PARAM_NO_VALUE` で止める（JS の例外にしない）。
- `pension.record` 改訂6: 再評価率を探す範囲を10年度前から100年度前に広げた。
- `socialInsurance.nationalPension` 改訂4: 基準月の2年前より後に値が無ければ、値のある最後の年度までさかのぼり、賃金で延ばす。
- 推定の知らせは今までどおり `N_PARAM_PROJECTED`。ほかの制度データの表のうち、最後の行に終わりの日がある値（31件。年金の改定率・再評価率・支援給付金・雇用保険の日額・後期高齢者医療と介護の第1号の料率・国民年金の保険料）を読む部品を全部見た。止まる作りは上の3つだけで、ほかは延長の仮定（0099）で計算が続く。
- 直した後は、上の216回のどれも止まらない。

### 2. 世帯主と払う人（国民健康保険・後期高齢者医療・介護保険の第1号）

- sdk に関数を足した。
  - `presentAt(ctx, member, at)`: 月 `at` に世帯にいるか（生まれた後・加わった後・離れる前。万一の重ねで亡くなった人は、亡くなった月の翌月から離れる）。
  - `householdHeadAt(ctx, members, at)`: 月 `at` の世帯主。その月に世帯にいる人のうち、本人、いなければ配偶者、いなければ年長の人（生年月の早い人。同じなら並びの順）。
  - `reassignAfterLeave(ctx, members, flows)`: 払う人が離れた（亡くなった）月より後に払うお金の動きを、払う月の世帯主の名にする。その月の世帯主がいなければそのまま。
  - `firstPresent(ctx, members, ids, at)`: 候補のうち、月 `at` に世帯にいる最初の人（5）。
- `socialInsurance.nationalHealth` 改訂11・`socialInsurance.lateElderly` 改訂8: 軽減の判定の世帯主は、その年度の始まり（計算基準月より前の年度は計算基準月）に判定の世帯にいる人から決める（`householdHeadAt`）。国民健康保険の納付義務者も同じ。亡くなった月より後に払う分（亡くなった人の分の残り）は、払う月の世帯主（遺族）の名にする（`reassignAfterLeave`）。社会保険料控除は払った人に付く（所得税法74条）ので、遺族の控除になる。
- `socialInsurance.careFirst` 改訂6: 亡くなった月より後に払う分割の残りを、同じく払う月の世帯主の名にする（額は変えない）。
- 任意継続（`socialInsurance.continuation`）は加入者ごとの保険料で世帯主を使わないので変えていない。住民税の非課税・扶養控除は、もう「その時に世帯にいる人」で絞っている。

### 3. 小規模企業共済の死亡の共済金（`account.mutualAid` 改訂3）

- 共済契約者が亡くなったら、亡くなった月の翌月に、その時の残高（その月までの掛金と運用益を足した額）を、死亡を事由とする共済金として遺族（亡くなった当時の配偶者。いなければ子）が一時金で受け取る（行 `cf.income.lumpSum.inheritance`、式 `account.mutualAid.deathLumpSum`。iDeCo の死亡一時金と同じ形）。
- みなし相続財産（相続税法3条1項2号の退職手当金等）なので、退職所得・雑所得の税をかけない（退職所得の受け取り・年金の受け取りに入れない）。知らせ `N_INHERITANCE_TAX`。相続税の目安（0039）は、もう共済を死亡退職金の側で数えている。
- 分割で受け取っている途中で亡くなったら、亡くなった月の翌月から後の分割の分を、その月に遺族へ一時金で渡す。
- 企業型DC・確定給付・退職金・個人年金保険も、亡くなる時期を11通りずらして全モデル世帯で試した。亡くなった後に、亡くなった人の名で入るお金は残っていない。

### 4. 発生の年で集める表の最後の年（`runEngine`。0003 の追記）

- `aggregation: "accrual"` の世帯は、表の最後の年を2年延ばした計算（後ろの計算）を、ふだんの計算とは別にもう1回する。後ろの計算から、帰属の年が表の最後の年までのお金の動き・年ごとの行・表を取り、ふだんの計算の結果と入れ替える（表の最初の年より前に帰属する分を最初の年に載せる決まり〔0003 の 2026-10-08 の追記〕と対）。
- 見出し・必要保障額・相続税の目安・要約の明細（保険・不動産など）は、ふだんの計算のまま（表の終わりそのものを使う部品があるため）。後ろの計算では必要保障額・相続税の目安を求めない。
- 後ろの計算がエンジンの誤り（`EngineError`）で止まる世帯（延ばした年に年齢の上限を超えるなど）は、ふだんの計算のまま返す。
- 部品の出力だけを求める呼び出し（`entry`）と表示の先出し（`preview`）は、今までどおり1回だけ計算する。
- 現金主義（`cash`。既定）の世帯は何も変わらない。
- 全モデル世帯で、表を半分の長さにしても、短い表の年の行が長い表と同じになった。

### 5. 給付を受け取る親・援助を払う親

- `benefit.childAllowance` 改訂4・`education.support` 改訂7・`education.cost` 改訂10（払う人を書いていない子への援助）: 受け取る（払う）親を、その月に世帯にいる最初の親にした（`firstPresent`）。額は変わらず、名義だけが変わる。

## 理由

- **止めずに延ばす**: 計算基準月が先の年でも、制度データの最後の値から前提で延ばせば計算できる（延長の仮定。0099）。止まるのは JS の例外で、利用者には直し方が分からない。
- **世帯主を年度の始まりで決める**: 国民健康保険の軽減の判定は、その年度の世帯主と被保険者の前の年の所得で行う。亡くなった人はその年度の世帯にいない。年度の途中で亡くなったら、その年度の判定は年度の始まりの世帯主のまま（軽減の判定は賦課期日〔4月1日。年度の途中で入った世帯は入った日〕の世帯で行い、年度の途中で世帯主が亡くなっても判定し直さない）。
- **払う人を払う月の世帯主にする**: 亡くなった人は払えない。亡くなった後の分割の残りは、世帯主（遺族）が払うとみなす。控除を遺族に付けないと、遺族の税を多く見積もる。
- **共済を iDeCo と同じ形にする**: 死亡を事由とする共済金は遺族の受け取りで、相続税の対象。受け取りの予定どおりに亡くなった人の所得で受け取る形は、受け取りの時期も税も違う。
- **発生の年の表を後ろの計算で埋める**: 表の最後の年に帰属する分は、表の後に払うので計算が表の終わりで切れると無くなる。部品ごとに表の後の分を出す形は、部品が多く漏れやすい。表を延ばして計算し、帰属の年で切る形なら、どの部品の分も落ちない。計算は2回になるが、発生の年の表は移行元のソフトとの照合のための設定で、既定の `cash` の速さは変わらない。

## 代案（採らなかったもの）

- **計算基準月が制度データより先なら入力の検査で止める**: 先の年の計画を作れなくなる。延長の仮定で計算できる。
- **国保の世帯主を月ごとに決める**: 軽減の判定は年度に1回で、年度の途中で判定し直さない。払う人だけを払う月で決める。
- **発生の年の表で、表の最後の年を「途中まで」と知らせるだけにする**: 表の長さを変えると同じ年の額が変わる性質が残る。

## 影響

- 計算基準月が2030年4月以後の世帯は、止まらずに計算できるようになる。
- 本人の死亡の想定を入れた世帯で、遺族が国保・後期高齢者医療・介護保険の第1号に入る場合。モデル世帯（現金主義）で変わるのは2つ。
  - `survivorEmployeeLoan`（本人の死亡 2031-04）: 2031〜2060年の国保・介護保険料・児童手当の名義が遺族に移り、国保の軽減の判定から亡くなった本人の所得が外れて、表の期間の国保・介護保険料が 78,670円 下がる（年間収支の合計が +78,670円）。
  - `survivorSelfEmployed`（本人の死亡 2034-06）: 同じく 2034〜2060年の名義が遺族に移り、国保・介護保険料・子ども・子育て支援金が 101,640円 下がる。亡くなった年の国保の控除が遺族に移るので、亡くなった本人の 2034年分の所得税（準確定申告。2035年に払う）が 10,100円 上がる（差し引きで年間収支の合計が +91,540円）。遺族に所得がある世帯では、遺族の所得税・住民税が国保の控除の分だけ下がる（遺族に事業所得300万円を足した試しで、年5万〜8万円ほど）。
- 小規模企業共済がある世帯で、共済契約者の死亡の想定を入れたとき。受け取りの時期が亡くなった月の翌月になり、退職所得・雑所得の税がかからなくなる。
- 発生の年で集める世帯は、表の最後の1〜2年の行が変わる（全モデル世帯を発生の年にすると、どれも最後の1〜2年の年金・住民税・保険料などが増える）。モデル世帯はどれも現金主義なので、既定の結果は変わらない。
- テスト: `engine/test/after-death.test.ts`（計算基準月 2030-04・2040-04、亡くなった後の国保の軽減と名義、介護保険の第1号・後期高齢者医療の名義、共済の死亡の共済金、発生の年の表の長さ、児童手当の名義）。`engine/test/engine.test.ts` の「aggregation を切り替える」の決まりを、発生の年の表の合計は帰属の年が表の最後の年までの分、に直した。

## 未確定

- **亡くなった月の社会保険料**: 資格を失う日は亡くなった日の翌日で、保険料は資格を失った月の前月まで（月末に亡くなったときだけその月も数える）。今は亡くなった月の分を、勤め先の健康保険・厚生年金・介護・子ども・子育て支援金・国民年金・介護の第1号・後期高齢者医療で1か月多く数え、遺族の国保・第1号は翌月から入る。直すときは、健康保険・年金の種別・勤め先の加入の状態を決める部品で、亡くなった人をその月から加入なしにする。遺族年金の加入月数にも響くので、別の変更で直す。
- **亡くなった人の名義の資産・負債**（収益不動産の家賃、住宅ローン、車、固定資産税、課税口座の取り崩しと譲渡益の税、介護費の支払い）が、亡くなった後も亡くなった人の名のまま。相続する人の決め方（配偶者・子が全部を相続したとみなす、法定相続分で共有にする、名義は変えず税だけを亡くなった年までにする）を決めてから直す。
- **子の死亡の想定**: 入れても、その子の教育費・保育料などが続く。画面からは入れられない。入力の検査で死亡の想定を世帯の大人だけに限るかを決める。
- 後ろの計算で延ばす年数（2年）で足りるか。表の最後の年に帰属して2年より後に払うお金は、今の部品には無い。

## 追記

- 2026-11-08: 未確定の「亡くなった人の名義の資産・負債」は、利用者の判断で、配偶者（いなければ子を等分）が全部を相続したとみなし、亡くなった月の翌月から名義を移す形に決めた（0173）。相続する人を画面で選ぶ欄は後で決める。
