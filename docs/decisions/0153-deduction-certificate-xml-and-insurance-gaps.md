- 状態: 採用（一部未確定）（2026-11-07）

- 前提にする記録: 0148（書類の読み取りの土台。読み口 `readProposal`・答えの形 `document-candidates@1`・区画 `documents`・確かめの画面・番号を読まない決まり）、0055（保険の契約のひな形・未入力の警告）、0034（明細の取り込み。このパソコンの中だけで読む）、0012（持たない情報）、0041（確定は明示の操作だけ）

## 背景

- 利用者の判断（2026-11-07）: 書類の読み取りの小さい案は必ず作る。この記録はその中の「決まった形の電子データ（保険）」の1本。同意の無い世帯でも使えるよう、アプリの中で読み、外へ送らない。
- 公的な保険料控除証明書の電子データ（年末調整のソフトが取り込む形）の仕様を、利用者の判断で読んだ。資料はリポジトリに入れず、文も写さない。わかったことを自分の言葉で書く:
  - 証明書は種類ごとの決まった名前の要素で、生命保険料控除証明書と地震保険料控除証明書は別の要素。ほかに国民年金保険料等・小規模企業共済等掛金・住宅ローンの年末残高等・住宅借入金等特別控除の証明書がある。
  - 生命保険の証明書は、証明書の頭に保険会社名・法人番号・証明日・契約者があり、契約の明細が繰り返しで入る。明細には証明年・適用制度・証券番号・保険の種類・契約日・団体のコード・被保険者と被保険者番号・払込方法・受取人・保険期間・個人年金の欄（受取人の生年月日・払込期間・年金の種類・支払期間・支払開始日）・その他の文がある。
  - 額は2組ある。「証明額」（証明の対象の月分の始まりと終わり、旧制度〔一般・個人年金〕と新制度〔一般・介護医療・個人年金〕ごとの保険料・配当金・差し引いた額）と、「12月までの見込み」（同じ区分ごとの年間の払込保険料・配当金・申告額）。年末調整のソフトは見込みの申告額があればそれを、無ければ証明額の差し引いた額を区分の額として取り込む。
  - 地震保険の証明書は、明細に区分（地震保険料・旧長期損害保険料・両方）・証券番号と枝番号・被保険者名・保険の対象（建物・家財など）・保険期間の始まりと年数・払込方法・地震保険料と控除の対象額・旧長期損害保険料と控除の対象額がある。区分と額の組み合わせで取り込めない形が決まっている。
  - 日付は年・月・日の子の要素で書く形がある。区分は区分の番号と名前の子の要素で書く。
  - 要素の外側の包み・名前空間の名前・電子署名の形は、読んだ資料からは確かめられなかった。
- 書類の読み取りの1本目（0148）は、控除証明書の契約を新しい保険の契約の候補にする口と、同じ種類・同じ人の契約があるときの知らせまでを作った。保険会社・契約年月で同じ契約かもしれないと知らせることと、入れ漏れの一覧は、この回に残していた。

## 決定

### 1. 安全な XML の読み手（`app/src/workspace/documents/xml.ts`）

- 依存を足さず、ブラウザの XML の部品も使わない小さな読み手にした（どこで動いても同じ決まりで読み、テストと本体で同じに動く）。
- **読まない XML**: 文書型の宣言・実体の宣言のあるもの（外の参照・実体の膨らみを起こさない）、決まった5つと数字の参照のほかの実体の参照があるもの、閉じていない・開きと閉じが違う・一番外の要素が2つ以上・要素の外に文字があるもの。
- 上限（内部）: 2,000,000 バイト、入れ子 40 段、要素 50,000、1つの要素の文字 10,000 字。
- ファイルの文字コード: 先頭の印（UTF-8・UTF-16）か XML の宣言（UTF-8・Shift_JIS・EUC-JP）で読み、合わなければ読まない。ZIP・PDF のファイルは「展開して XML を選んでください」「XML を選んでください」と理由を出す。
- 名前空間の接頭辞は外して要素の名前だけで持ち、名前空間の名前は見ない（包みと名前空間の名前が確かめられなかったため。どの深さの証明書の要素でも探す）。属性は形を確かめるが持たない。
- **読まない要素**（`skip`）は、中身ごと木に入れない（中の形は確かめる）。氏名・番号を、読んだ時点で持たないため。
- 電子署名は確かめない。読み手が出すのは候補だけで、FP が書類と見比べて承認する（0148 の2）。

### 2. 控除証明書の読み手（`documents/deductionXml.ts`。読み手の ID `xml.deductionCertificate`・版 1）

- 1つのファイルに証明書が何通・明細が何件あってもよい。**証明書1通を読み取りの記録1件**（0148 の1）にし、**明細1件を新しい保険の契約の候補1件**にする（1通の明細は30件まで。証明書は50通まで）。記録には読み手の ID と版、ファイルの指紋と大きさを持ち、元のファイル・ファイル名は持たない（0148 のまま）。
- 生命保険料控除証明書・地震保険料控除証明書だけを読む。ほかの証明書は「○○の電子データは、まだ読めません」と理由を出し、同じファイルの読める証明書は読む。証明書の要素が無いファイルは「控除証明書の電子データではありません」。
- **読まない**（木に入れない）: 契約者・被保険者・受取人の氏名、証券番号と枝番号、被保険者番号、法人番号、団体のコード、受取人の生年月日、適用条文、その他の文。読む文字（会社名・保険の種類・年金の種類・払込方法・区分の名前・保険の対象）も番号らしい所を消し（0148 の3）、消した数を記録の `dropped` に足す。出した答えは読み口 `readProposal` を通す（番号の決まり・上限・当て先の確かめは同じ）。
- 書類の時点は証明日の年月。名義の人は決めない（名前を読まないので、FP が続柄で選ぶ）。
- **生命保険の契約ごとの候補**:

### 3. 保険の入れ漏れの一覧（`documents/insuranceGaps.ts`）

- 新しい保険の契約の候補がある読み取りの記録なら、どの読み方（この読み手・AI の答え・貼り付け）でも作る。画面を開くたびに今の世帯から作り、保存しない。
- 書類の契約ごとに、今ある保険の契約と4つの手がかりを比べる: **保険会社**（書類の名前の先頭の語〔会社名〕が、今ある契約の名前に入っている。会社の種類の言葉と空白は外して比べる）・**種類**（種類の細目が同じ）・**契約年月**・**年間の保険料**（月払いは12倍して、3%の差まで）。
  - **2つ以上が合えば「同じ契約かもしれません」**と、合った手がかりを添えて知らせる。黙ってまとめない（同じなら FP が「足さない」にして、今の契約の欄を直す）。確かめの画面の知らせ（0148 の「同じ契約が、もうあるかもしれません」）にも足す。
  - 1つも合わない（種類だけが合うのを含む）なら「今の保険の入力に無さそうです」。種類だけが合う契約は手がかりとして名前だけを添える。
  - この記録で足した契約は「足しました」（その契約とは比べない）、足さないにした契約は「足さないことにしました」。
- 一覧の列は、書類の契約（名前と種類）・契約年月・年間の保険料・控除の区分・今の保険の入力。上に「この書類の契約 ○件のうち、無さそうな契約 ○件・同じ契約かもしれない契約 ○件」と、保障の額は証明書に無いので証券を見て入れてもらう案内を出す。
- 今の入力にあって証明書に無い契約（解約した契約・控除の対象でない契約かもしれない）は、この回は一覧にしない。

- 入力のホームの「取り込む」の「書類の読み取り」の1行に「**控除証明書の電子データ（XML）を読む**」（ファイルを選ぶ。一度に10ファイルまで）と、「このパソコンの中だけで読みます（外へ送りません）。元のファイル・氏名・証券番号は保存しません」の説明。読んだら記録を足して、読んだばかりの証明書の確かめの画面を開く。読めなかったファイルの理由を出す（2つ以上のファイルを選んだときは、画面の中だけファイル名を添える。記録には残さない）。

## 理由

- **自前の小さな XML の読み手**: ブラウザの XML の部品は、実体の扱い・大きさの上限・壊れた XML の扱いが動く所で違い、テスト（Node）と本体（WebView）で同じに確かめられない。控除証明書は小さく、要る形（要素・文字・決まった参照）も少ない。文書型の宣言を丸ごと断れば、外の参照と実体の膨らみの両方を防げる。
- **名前空間を見ない**: 包みと名前空間の名前を資料から確かめられず、利用者の実物のファイルで確かめるまで決め打ちしない方が読める。要素の名前は仕様で決まっていて、証明書の要素の中だけで探すので取り違えない。
- **読まない欄を木に入れない**: 読み口で番号を落とす決まり（0148）があっても、氏名は番号の形ではないので落ちない。読む欄を選ぶだけでなく、読まない欄の中身を最初から持たない方が、記録・画面・不具合の報告のどこにも出ないと言える。
- **保険料は見込みの年間の払込保険料**: 計算に要るのは払う保険料で、申告額（配当金を引いた額）ではない。証明額は証明日までの月分なので1年分でないことが多い。月額に直すのは12で割り切れるときだけにし、割り切れなければ年額のまま入れる（端数を作らない）。
- **地震保険の保険料を確からしさ低にする**: 証明書の額は地震保険の分だけで、火災保険を合わせた契約の保険料より小さい。候補には出す（入れ漏れの手がかりと、地震の分だけの契約のため）が、まとめての承認で黙って入らないようにした。
- **契約者を名義の人に・被保険者は出さない**: 電子データは控除を受ける契約者が取り出すもので、契約者は名義の人と言える。被保険者は名前しか無く（読まない）、配偶者や子のこともあるので、足したときの既定（ご本人の推定）のまま証券で確かめてもらう。
- **入れ漏れの比べは2つの手がかりから**: 種類だけ・会社だけで同じとみなすと、同じ会社の2本目の医療保険を見落とす。2つ以上が合ったときだけ「同じかも」とし、それでも黙ってまとめない（0148 の決まり）。

## 代案（採らなかったもの）

- ブラウザの `DOMParser` で読む: 上の理由で採らない。
- 証明書の明細をまとめて1件の記録にする（ファイル1つで1件）: 生命保険と地震保険で書類の種類が違い、読み取りの成績も書類の種類ごとに数えるので、証明書ごとに分けた。
- 申告額を保険料の候補にする: 配当金を引いた額で、払う保険料ではないので照合だけの値にした。
- 同じ契約かもしれないとき、今の契約に当てる候補を作る: 0148 の未確定のまま（今は知らせるだけ）。
