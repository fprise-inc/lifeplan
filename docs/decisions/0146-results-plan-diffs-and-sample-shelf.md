## 背景

入力項目を通しで入れて結果・提案書・プランの差分を見たところ、次のことが分かった。

- 自営業の事業所得と、年金で受け取る企業年金（確定給付企業年金・企業型DC・iDeCo・小規模企業共済の分割・個人年金保険など）が、キャッシュフロー表の「その他の収入」（養育費・奨学金の受け取り・相続と同じ行）に入っていた。会社員には「ご本人の給与」の行があるのに、自営業の世帯の表に主な収入の行が無かった。
- プランの違いの一覧・結果のタブの「変えたこと」・面談の準備の世帯の中身の一覧に、内部の名前（「incomeFlow「相続・遺贈」」「外す: member」）や生の値（「home → facility」「なし → {"cohabiting":true,…}」）が出ていた。「変えたこと」では入力で直した差分が「— → —」だった。入力で直した差分（介護を施設に・同居など）は提案書の変更点に入らなかった。
- 世帯の中身の一覧で、ご本人・配偶者が「年金」の見出しの下に並び、介護・FP顧問料の行に額が無かった。
- 違いの一覧は「プランの操作 ▾」を開いた中にあり、全部を見るには2回押す。開いた一覧に見出しも閉じるも無く、チェックが何か書いていなかった。
- 結果のタブの目標で、1回だけの贈与が「1年ごとに 110万円」、優先度は「できれば」の決め打ちだった。結果のタブ・提案書の家族の行に世帯の外の親が「ご家族 92歳」と並んでいた。
- 資産と負債のタブの今の年の箱が「事実（今・入力した値）」なのに、入れた値（預金500万円）と違う年末の見込み（588万円）を見せていた。家計の体力の目安の「生活費 月33万円で計算」は、入れた基本生活費（月30万円）に車の費用を足した額だった。
- 万一のときの残された配偶者の年収が「年収（賞与を除く）」で、働き方と収入の「年収（税込み・賞与込み）」と基準が違った。

## 決定

### 1. キャッシュフロー表の「○○の事業所得」と「企業年金・個人年金」の行（0128 の足し方にそろえる）

- 収入の側に、人ごとの「○○の事業所得」（鍵 `business:<人の鍵>`。`cf.income.business` のその人のマス）を給与の行のすぐ後に、「企業年金・個人年金」（鍵 `corporatePension`。`cf.income.corporatePension` の全部）を年金の行のすぐ後に足す。「その他の収入」から外す（二重に数えない）。収入合計・年間収支は変わらない。値のある年が無い行は今までどおり出さない（会社員だけの世帯に行は増えない）。
- 行の名前は `report/src/rowNames.ts` の公式の名前（`{person}の事業所得`・「企業年金・個人年金」。企業年金・個人年金は登録簿の `cf.income.corporatePension` の名前と同じ）。事業所得は人ごとの行なので、給与・年金と同じく `{person}` を差し込む（`ROW_NAME_VARS`）。
- 同じ行の並びを使う所すべてに入れた: 結果のタブの表・お客さまに見せる画面・持ち帰り用のレポート（`app/src/workspace/present.ts` の `rowDefs`）、提案書（`report/src/build.ts` の `rowDefs`。帳票は行の鍵で並べるだけなので Typst は変えない）。
- 収支の推移のグラフは今までどおり事業所得を「給与」の系列に入れる（事業所得のある世帯だけ、系列の名前を提案書の「家計の今」と同じ「給与・事業の収入」にする）。企業年金・個人年金は「その他の収入」の系列のまま。表とグラフの対応の表（見張りの `TABLE_TO_CHART`）に `business → salary`・`corporatePension → incomeOther` を書いた。
- 直す待ちの `business-and-pension-rows` を消し、通しの入力のテストの「事業所得・企業年金の行」の `it.fails` を `it` にした。

### 2. 違いの一覧・変えたこと・世帯の中身の一覧の言葉

- 物の集まりの呼び名（`plans/planEdit.ts` の `COLLECTION_LABELS`）を全部の物の集まりに書く: 入るお金（`incomeFlow`）・出るお金（`periodicExpense`。前は「支出」）・口座の間の移し替え（`transfer`）。呼び名の無い物の集まりは英字を出さず「物」。テストで、物の集まりの全部に呼び名があることを確かめる。
- 家族の関係は「家族の関係（ご本人と母）」、介護は「介護（母・施設）」のように中身を添える（場所を変えた置き換えで前と後が分かる）。呼び名が同じ物の置き換え（相手・中身を変えた）は、後ろに「（中身を変えた）」を付ける。
- まとまった値（扶養と同居など、欄が中の値ごとにある物）を丸ごと変えた差分は、中の欄ごとの「同居している: いいえ → 同居している: はい」にする（違う欄だけ。`subFieldTexts`）。JSON を出さない。
- 結果のタブの「変えたこと」で、動かす項目の一覧に無い差分（入力で直した差分）は、違いの一覧と同じ行の文（何を・前・後）にする（`plans.ts` の `changesOf`。違いの一覧の作り方 `diffRows` をそのまま使う）。
- 提案書・持ち帰り用のレポートの変更点（動かした値の一覧 `changesOfValues`）に、入力で直した差分を違いの一覧と同じ文で足す（そのプランの差分のうち、動かす項目に読み替えられない物。オフの差分は入れない）。結果のタブで保存していない変更がある間の「変えたこと」も同じ。打ち手ごとの効果（1件ずつ足す計算）には入れない（今までどおり動かす項目だけ）。0043 の未確定「違いの一覧を提案書・持ち帰り用のレポートの変えたことに書き出す形」はこれで決めた。
- 物の形を変えて戻した（回数を1回から毎月にして1回に戻すなど）ときに、置き換えの組が「同じ物を外して同じ物を足す」で残っていたので、記録するたびに中身の変わらない組を外す（`pruneIdleReplacements`）。
- 直す待ちの `internal-names-in-lists` を消し、通しの入力のテストの「世帯の中身の一覧に incomeFlow」の直す待ちを外した。

### 3. 面談の準備の世帯の中身の一覧

- 人は、世帯の中の人と離れて暮らす子を「家族」、世帯の外の親・祖父母・兄弟姉妹・孫を「介護・親」の下に置く（`objectCards` が人のカードを決める。前は人を最初に指す欄の入力項目〔ご本人なら年金〕だった）。
- 介護の行に「施設・月13.8万円・55か月」（在宅か施設か・月々の費用の合計・期間）、FP顧問料の行に「単発30万円＋月1万円」（止めている契約は「（止めている）」）。ほかの額の行も欄の外の額の書き方（0131 の7。「月5万円」「8.3万円」「4,500円」）にそろえた。

### 4. 編集の対象の箱の「違いの一覧（n）」（利用者の判断）と、違いの一覧の見出し

- プランを選んでいる間、編集の対象の箱の右端に文字のリンク「違いの一覧（n）」（n は計算に入れている違いの数。オフ・要確認の数はカーソルを合わせたときの補足、要確認があれば文字の色）。押すと箱の下に違いの一覧を開く・閉じる。「プランの操作 ▾」の中の入口はやめた（同じ物を2か所に出さない）。
- 0077 の「選んでも配置が1ピクセルも動かない」を守るため、現状のときも同じ部品を見えない・押せない形（`off`・`disabled`・`aria-hidden`・Tab で止まらない）で置き、幅を同じにする（`min-width`）。開発中のアプリで、現状とプランBで箱の幅・高さが同じことを確かめた。
- 違いの一覧の頭に見出し「プランBで現状から変えた所（n）」と「閉じる」、各行のチェックの横に「計算に入れる」。

### 5. 結果の目標・家族の行・資産と負債・万一の言葉

- 目標の「その他」のカード（出るお金の行）: 1回の行は「2027年11月 110万円」、毎月は「毎月 5万円」、毎年は「毎年 110万円」、n年ごとは「3年ごとに 30万円」（額は欄の外の書き方）。1回の行の名前は「一時的な支出」（何年かごとの支出と分ける）。優先度は行の値（省略は欄の既定の「必ず」。前は「できれば」の決め打ち）。1回の行の「足りるか」はその年で見る。
- 結果のタブの上の行（世帯の人の並び）と、提案書の家族の行（`members`）に、世帯の外の家族（介護・親で足した親など）を出さない。表の年齢の行には今までどおり「お母さま」などで出る。
- 資産と負債のタブの今の年の札は「2026年末の見込み（入力した値から）」（図の今の年は、入れた残高に計算の基準の月の後のお金の動きを足した年末の額のため）。年のつまみの下の見本は「今の年 入力した値から出した年末の見込み」。
- 家計の体力の目安の文は「基本生活費 月30万円＋車 月3万円で計算」（生活費の行に入る車の費用を分ける。分母は今までどおり両方の合計）。ローン返済を分母に入れるときは「＋ローン返済 月9万円」。月額は欄の外の書き方（1万円未満は円）。

## 理由

- 表の行は「不動産の売却」（0128）と同じ足し方にし、表・提案書・事務所の名前の差し替えを同じ鍵でそろえた。自営業の世帯の主な収入が「その他の収入」に埋もれると、FP が表を見せて説明しにくい。
- 違いの一覧と「変えたこと」・提案書の変更点は、同じ差分を見ているので同じ文にした（文を作る所を1つにして、どこかだけ内部の名前が出ることを無くす）。
- 「違いの一覧（n）」は利用者の判断（編集中の箱の中に文字のリンクで出す。箱の大きさ・配置は動かさない）。0077 の配置の決まりを守るため、見えない同じ部品で場所を取っておく形にした。
- 見本は面談でお客さまに見せる物なので、赤い未入力を出さない。未入力の仕組みのテストは、見本の中身ではなく仕組みを見るので、未入力の形を作って見る。新しい見本は、手で書いた JSON ではなく入力の画面と同じ欄・ボタンで作り、形が画面の書く形と同じになるようにした。

## 代案（採らなかったもの）

- 事業所得をグラフでも別の系列にする: 系列が増えると色が足りず、働いて得る収入としては給与と同じ側で見るほうが分かりやすい。名前だけを「給与・事業の収入」にした。
- 企業年金を公的年金の系列・行に入れる: 公的年金の行は年金の推計・書類の額と比べて見る行なので、分けた。
- 「プランの操作 ▾」の中の違いの一覧の入口を残す: 同じ物が2か所になる。
- 見本の推定の値を推定のまま持つ: ほかの見本は確定の値で持っていて、モデル世帯の往復のテスト（値を変えて戻すと元に戻る）も確定の値を前提にしている。見本の作り手が決めた値として確定にした。

## 未確定・後の段階に回したこと

- Tab で「?」へ移ると説明が開く（0077 の追記 2026-10-29 で「Tab で『?』へ移れば今までどおり開く」と決めてある）。欄から欄へ Tab で進むと、間の「?」で1回止まって説明が開く。0077 の決まりなので変えていない。Tab の並びから「?」を外すか（キーボードでは別のキーで開く）は利用者が決める。
