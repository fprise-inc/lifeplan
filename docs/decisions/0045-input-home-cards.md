# 0045. 入力のホームのカードの組み直し（14枚・物の置き場所・ピン・カードの状態4つ・進み具合）

- 状態: 採用（一部未確定）（2026-10-26）
- 固定の強さ: 内部（画面の作り）。世帯ファイルの形は変えない（足したカードの記録 `addedItems` と保存した項目の印 `confirmed` は今の形のまま、意味だけを変えた）。カードの名前・並び・1行の案内の文言・状態の色・最初の5枚の選び方は後から変えてよい

## 背景

- 入力のホームは11枚のカード（家族・働き方と収入・年金・基本生活費・子ども・教育・住まい・ローン・保険・貯蓄・運用・ライフイベント・車・前提条件）だった。退職金は働き方と収入の中、親（世帯の外の家族）は家族の中、介護はライフイベントと「＋ 項目を追加」の2か所、贈与する人は家族の中、と、世代をまたぐお金と親の世代の物が散らばっていた。
- 「＋ 項目を追加」で足した物は別のカードになり、元のカードには出なかった。そのため、ライフイベントのカードにも、プランの違いの数にも出なかった。
- カードの状態は「入力済み・推定あり・未入力」の3つで、物が無いまま保存したカードも「入力済み」になった。0円で計算している欄（未入力の印の0円）があっても、物があれば「入力済み」に見えた。
- 値の状態の仕組み（0041）で、欄ごとに「推定・わからない・該当なし・確定・未入力（0円で計算中）」を読めるようになり、入っていない物（退職金・教育費・住居費・保険など）を確かめの一覧のいちばん上に出すようにした。カードの状態はまだそれを使っていなかった。
- 0035 の世帯ファイルの形式の表で、足したカード `addedItems` は「変わらない（意味をピンに。物は属するカードにも出る）」と決めてある。

- プランの違いの一覧の、欄から引けない物の集まりのカードを付け替えた（`retirementBenefit` → 退職金・企業年金、`care` → 介護・親、`donor` → 相続・贈与）。

### 3. ピン（足したカードの記録の意味を変えた）

- `addedItems` の1件（`id`・`kind`・`ref`・`art`）を「ピン」と読む。物（`ref`）は種類が属するカードに出し、ホームのカードの格子の下に「ピン」として並べる。ピンを押すと、属するカードの段階の定義から、その物のまとまり（と、その物の段階の表）だけを開く。
- 属するカード: 周期的な支出は種類のカード（0044。種類の無い行はライフイベント、子の年齢で始まる物は子ども・教育）、介護の費用は介護・親、車は車、FP顧問料は前提条件。
- 「＋ 項目を追加」（ペット・留学・名前を付けた支出・介護の費用）は、物を属するカードに作り、ピンを足す（2026-11-04 にやめ、「探して開く」にした。追記。前に足した物とピンは今までどおり読む）。留学は子がいれば子ごとにも選べ、子を選ぶと時期をその子の年齢（20歳か、もう過ぎていれば来年の年齢）で持ち、子ども・教育のその子の区画に入る。行は子を選ばない留学と同じ一時的支出。
- どのカードの物も、まとまりの見出しの「📌 ホームに出す」でピンにでき、「📌 ホームから外す」で外せる（物は残る）。出せるのは `addedItems` の種類にある物（周期的な支出・介護の費用・車・FP顧問料）だけ。ほかの物（構成員・口座・保険など）を出すには `kind` の種類を足すことになるので、世帯ファイルの形を直す回に決める。
- ピンは進み具合に数えない（物が属するカードで数える）。カードの保存の印（`confirmed`）にも足さない。
- プランで足した物のピンは、そのプランの編集中だけ出る（現状のホームでは、物が現状に無いので出さない）。プランの色の札「プランBで足した」を付ける。プランの違いの数は、物が属するカードに数える。
- 前の版で足したカードの記録（周期的な支出・介護の費用、前の前の版の車・FP顧問料）は、開いても書き換えず、そのままピンとして見せる。物は属するカードにも出るようになる（前は足したカードにだけ出していた）。物を外したピンは、保存したときに記録から外す（プランで足した物のピンは残す。今までと同じ）。

### 4. カードの状態（4つ。色だけでなく印と文字でも）

| 状態 | 決まり（上から順に当てる） | 印 |
|---|---|---|
| 未入力（0円の所あり） | 0円で計算している欄（値の状態 `missing`）か、入っていない物（確かめの一覧のいちばん上の物）がある。物が無く、「当てはまらない」も決めていないときも | 0（赤の点線の枠） |
| 推定で計算中 | 推定・わからない（代わりの値）の欄がある。記録の無い人の年金（働き方の期間から推計）も物の単位で数える。前提条件の標準の値は数えない | ! |
| 当てはまらない | 無いと決めてある（子がいない・どの子も教育費なし、どの人も勤め先に退職金の制度が無い）か、物が無くて FP が保存した・「当てはまらない」を押した | − |
| 入力済み | 物があり、上のどれでもない | ✓ |

- 欄の状態は値の状態の仕組み（`valueState.ts` の `fieldStatus`）で読み、同じ当て先を見せる欄は1つに数える。入っていない物は `fill.ts` の `gapsOf`（退職金の物は退職金・企業年金のカードに付け替えた）。
- 前の「入力済み（なし）」（物が無く保存した項目）は「当てはまらない」になる。保存した項目の印 `confirmed` の形と意味（そのカードを FP が保存した）は変えない。

### 5. 進み具合

- 「未入力（0円の所あり）○」をいちばん左に強く出し（0のときは控えめに）、続けて「14項目中 入力済み○・推定で計算中○・当てはまらない○」。4つの合計はいつも14。
- 項目ごとのマスの帯は4つの状態で塗り分ける（色に加えて枠の形も変える）。

### 6. 最初の5枚と、残りの9枚の1押し

- 最初の5枚は家族・働き方と収入・基本生活費・貯蓄・運用・住まい・ローン（`DEFAULT_LAYOUT.first`）。最初の5枚に未入力が残る間は、ホームに「まず最初の5枚を入れてください」の案内（閉じられる）と、5枚のカードに「最初の5枚」の印を出す。
- 残りのカードは、未入力・推定で計算中のときに、何で計算しているかの1行をカードの上に出す（例: 「入れなくても計算できます（保障は無しで計算中）」「働き方の期間から推計して計算中です」）。
- 未入力のカードには1押しを出す:
  - 「当てはまらない」: そのカードの入っていない物を「該当なし」にし（教育費なし・勤め先に制度が無い・住居費なし・保険に入っていない）、保存した項目の印を付ける。物があって0円の欄が残るカードには出さない（欄を直すのはパネルで）。
  - 「目安で入れる」: そのカードの入っていない物を推定で埋める（0041 の「推定で埋める」と同じ）。推定を作れる物があるときだけ。
- 1押しは現状を直す。プランの編集中は出さない。

## 理由

- 物の形を変えずに見せるカードだけを変えた: 世帯ファイルの形の変更は1回にまとめる決まり（0035）で、カードの組み直しは画面の側で済む。欄のキーも変えないので、保存した差分・動かす項目・読み替え表に影響しない。
- 読むだけの1行を見せるだけの欄にした: 今の欄の部品でそのまま描け、確かめの一覧・状態の数・差分の対応から外す決まり（`readOnly`）がすでにある。
- ピンを `addedItems` のままにした: 0035 の決め。前の版の記録をそのまま読め、物が属するカードに出るので、プランの違いの数・確かめの一覧・動かす項目にも出る。
- 状態を値の状態から決めた: 0円で黙って計算している所を、欄・確かめの一覧・カード・進み具合で同じ決まりで見せるため。
- 未入力の数を左に強く出した: ここが0なら、気づかずに0円で誤ることは無い。

## 代案（採らなかったもの）

- カードを足さずに区画を足す（11枚のまま）: ライフイベントと働き方と収入が重くなり、世代をまたぐお金がカードにならない。
- お金の向きでカードを組み直す（7枚）: 今の並びの決まりを崩し、全部の段階の定義と欄のキーの付け直しが要る。
- ピンを別の記録に持つ: 世帯ファイルの形が変わる。
- 物の無いカードを全部「当てはまらない」と読む: 入れ忘れと「無い」を分けられず、0円で誤るのを見落とす。

## 追記
- 2026-10-27（退職金・企業年金のカード。0057・0058）: 未確定の「退職金・企業年金の受け取り方と目安」を入れた（人ごとに何件でも・入れ方・種類ごとの欄・目安の自動と確かめの注意・受け取りの並び）。カードの状態の「当てはまらない」は、退職給付を外してその人の勤め先が該当なしになったときにもなる。
- 2026-10-26（介護・親のカードの中身。0059）: 贈与する人（`donors`。生年月を持たない世帯の外の家族）の欄のまとまりを、介護・親のカードの世帯の外の家族の区画に並べた（足す操作は相続・贈与のカードに残す）。本人・配偶者の介護を決めていないときの未入力の警告と「目安で入れる」を入れた（入っていない物に1人ずつ出す）。
- 2026-10-27（年金のカードの中身。0066・0067）: 年金のカードの要約を、計算の結果から読む65歳からの額の合計の月額（「夫婦で月…万円（65歳から・推定）」）にした（入力のホームが計算の道を持つとき。無ければ前からの入力の値の要約）。年金のカードはお金の行の区画を自分の中に置く。
- 2026-10-27（入力のホームの仕上げ。0072）: 未確定の「進み具合を押してそのカードだけに絞る」を入れた。確かめの一覧の「カード › 物 › 欄」の絞り込みは、カード・状態・出どころ・確かさの絞り込みにした。ホームに全部のカードの入れ方（簡易／詳細）と小さな結果（金融資産の線と足りなくなる年）を置いた。
- 2026-10-27（事務所の既定値。0073）: 未確定の「事務所の設定（並び・最初の5枚）の保存の場所と画面」を入れた（事務所データの `defaults.layout`。世帯の一覧の「事務所の既定値」）。
- 2026-10-27（抜けの知らせは入れ始めた項目だけ）: 新しい世帯で入力項目を開くと、何も入れていないのに赤い札「未入力（0円の所あり）」と、入っていない物の赤い帯（「住居費: 住まいが入っていないので…」）が最初から出ていた。入れた後に抜けがあれば出すのが自然なので、状態に「まだ入れていない」（`empty`）を足した。計算と世帯ファイルの形は変えない。
  - 入れ始めたか（`items.ts` の `startedOf`）は世帯ファイルの今の情報だけで決める: 項目に属する物がある・保存した項目の印（`confirmed`。保存と「当てはまらない」）がある・無いと決めてある（子がいない・勤め先に制度が無いなど）・その項目の欄に FP が入れた印（出どころが自動でない値の箱か値の状態の行。確定・わからない・該当なし・承認など）がある・0円で計算している欄がある（欄は物の上にある）。どれでもなく、4つの状態の「未入力（0円の所あり）」に当たる項目を「まだ入れていない」にする。推定・当てはまらない・入力済みの決まりは変えない。
  - ホームのカード: 点線の枠と灰色の絵（今の「まだ入っていません」の見せ方）のまま、枠は赤でなく灰色にし、札を出さない（文字の「まだ入っていません」で状態が分かる）。1行の案内と「当てはまらない」「目安で入れる」の1押しは今のとおり出す。
