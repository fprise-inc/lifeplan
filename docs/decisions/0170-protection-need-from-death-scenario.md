# 0170. 必要保障額を死亡の想定の表から組み立てる（近似の範囲を狭める）と、死亡の場面・相続税の目安の直し

- 状態: 採用（一部未確定）（2026-11-08）
- 固定の強さ: 内部（必要保障額の組み立て方・区画の分け方・死亡の場面の決まり）。必要保障額の出力の形（`protection.need` の約束の版 1.1）・世帯ファイルの形式の版は変えない。部品の書き方の約束（`COMPONENT_API_VERSION`）は 1.4 → 1.5（`ctx.deathScenario` を足しただけ。公式部品の書き方は変わらない）。`insurance.policy` は約束の版 1.1 → 1.2（任意の欄 `start` を足した）
- 前提にする記録: 0005（実行環境と二本立て。追記 2026-10-09 の必要保障額の近道）、0006（部品の書き方の約束）、0008（万一の重ね）、0039（相続税の目安）、0054（必要保障額の内訳）

## 背景

- 必要保障額の推移（`protection.need`）は、「この年に亡くなったら」を1年ずつずらして何十回も全体を計算し直すと遅いので、万一なしの計算の部品の結果から遺族の収支を組み立てる近道だった（0005 の追記 2026-10-09。「団信で消える住宅ローン・遺族の税と社会保険料の変化は近似」）。
- 同じ月の死亡の想定で全体を計算し直した表（万一のタブの「死亡」の場面の表）と、内訳の区画ごとに突き合わせると、近似の範囲を超えて食い違っていた（見本の世帯 43件のうち 41件で税と社会保険料が10万円以上ずれた）。
  - 税と社会保険料: 亡くなった人の所得で計算した世帯の国保を数え、遺族が新しく払う国民年金（第3号から第1号）・国保を数えない（自営業の世帯で約1,700万〜2,900万円多く、会社員と専業の配偶者の世帯で約270〜520万円少なく出た）
  - 公的な支援: 亡くなった後に受けられるようになる修学支援（給付の奨学金・授業料の減免）を数えない（約1,000万円多く出た）
  - 介護: 亡くなった本人の将来の介護の費用と、世帯の外の親が自分の預金から払う介護の費用を数える
  - 収益不動産: 物件のローンの返済だけを住居費に数え、家賃・売却の代金・物件の経費を数えない
  - 教育費に奨学金の受け取りを、住居費に住宅購入の援助の受け取りを足す（入るお金を出るお金として数える）
  - 住宅購入の予定より前に亡くなるとき、まだ借りていないローンを団信で消えたとみなす（全体の計算は、亡くなった人の名でローンを始めて遺族が全額返していた）
- ほかに、死亡の場面と相続税の目安に次の誤りがあった。
  - 死亡の場面の死亡退職金を勤続の月数で按分しない（万一の重ねが働き方の期間を死亡の月で終えるので、按分の条件が成り立たない）。勤続の始まりより前に亡くなると、まだ勤めていない勤め先の見込み額を全額受け取る
  - 加入中の死亡保険金を、亡くなる月（1月）ではなく年末の死亡保障額で数える（年の途中で終わる定期保険が0円・収入保障が11か月分少ない）
  - 生活費に「万一のときの扱い」を入れると、予備の生活資金が0円になる
  - 逆算方式で「資産が尽きないようにする遺族の年齢」を期間の終わりより後にしても、期間の終わりで打ち切る
  - 相続税の目安の「死亡の想定」の時点が、収入保障保険の年金（相続税の対象）を数えない。「二人とも亡くなった後」が、先に亡くなった人の団信つきの住宅ローンの残高を債務として引く
  - 死亡の当時55歳未満の夫（遺族厚生年金の遺族でない）に遺族厚生年金を出し、子に出さない
  - 万一のタブの「○歳時点の金融資産」が、表示の設定の年齢ではなくいつも95歳

## 決定

### 1. 必要保障額は、死亡の想定の表から組み立てる（近似の範囲を狭める）

- 計算エンジンは、必要保障額を求めるとき、部品に `ctx.deathScenario(member, month)` を渡す。構成員がその月に亡くなる想定（万一の重ね。0008 の7）を同じ入力に当て、お金の動きを集める部品（`plan.flows`）までを別に計算したお金の動きを返す（万一のタブの「死亡」の場面の表と同じ計算。根拠の記録なし・知らせは捨てる・同じ人と月は1回の計算で1回だけ）。残高・運用益・取り崩し・譲渡益の税（`plan.cashflow`）は、必要保障額が数えない物なので計算しない。ほかの部品では `null`。
- `protection.need`（改訂6）は、亡くなる人ごと・遺族（配偶者）ごとに1回だけ、最初の年に亡くなる想定の表を求め、ほかの年は、その表のうち「亡くなる月の翌月から」の分を使う（下の 2 の近似）。区画は場面の表の行で分ける。
  - 必要な資金: 生活費（基本生活費の行。遺族の割合・生活費の万一のときの扱いは場面の計算が当てる）・住居費（住居関連費と負債の返済）・教育費（教育費の行だけ）・保険料・介護・税と社会保険料・そのほか（周期的な支出・FP顧問料・不動産の経費・車・結婚の援助など）
  - 準備できる資金: 遺族年金・遺族の収入（遺族〔配偶者〕の名の収入、世帯の名の収入〔相続・贈与の受け取りなど〕、亡くなった人の名で続く収入〔相続した物件の賃料・売却の代金など〕）・公的な支援（児童手当・就学支援金と修学支援・奨学金の受け取り）
  - 税と社会保険料: 遺族の名の物と、世帯の国保（国民健康保険・任意継続。世帯主の名で出る）と、亡くなった人の名で死亡の年の後に帰属する物（相続した物件の賃料の所得税・売却の譲渡所得の税など）。亡くなった人の死亡の年までの所得の税（準確定申告・翌年の住民税）は、前と同じく数えない
  - 数えない行: 子・世帯の外の家族の収入と税（子は独立していく人として、前と同じ）、取り崩して使うお金・ゆとりの支出・上場株式等と暗号資産の譲渡益の税・相続税（資産の残り方で変わる）、死亡で受け取る一時金と保険（死亡退職金・確定拠出年金と小規模企業共済の死亡一時金・保証期間の残り・弔慰金・死亡保険金・収入保障）、整理資金（要求の値）
  - 現状の検算の差（使途不明金）は、万一なしの計算の額（今の世帯の検算。亡くなる年で変わらない。場面の計算では、検算の年より前に亡くなると差が変わってしまう）
  - 亡くなった人の車は、前の決まり（改訂2）のまま: 「万一のときの扱い」（死亡に当てるもの）を入れていない車は数えない。入れた車と遺族の車は場面の計算が割合を当てる
- 亡くなる年ごとに求める物（前と同じ）: 遺族年金（`pension.survivor` に死亡の月を渡す。配偶者が受給権の無い夫なら子の分も。下の 4）・死亡退職金（見込み額を勤続の月数で按分。**勤続の始まりより前なら0**）・確定拠出年金の死亡一時金・弔慰金・金融資産（亡くなる年の前の年末）。
- 加入中の死亡保険金は、**亡くなる月の死亡保障額**（`insurance.policy` の約束の版 1.2 で足した年ごとの `start`: その年の最初の月〔計算基準年は計算基準月〕に亡くなったときの額。家族特約などの others も）。
- 団信で消える返済（内訳の `creditLife`。表示だけ）は、万一なしの返済のうち、**亡くなる月より前に借りた**、団信の対象に亡くなる人がいる負債の分。
- 予備の生活資金は、場面の表の死亡の月の翌月の基本生活費（遺族の割合・万一のときの扱いを当てた後）の n か月分。
- 逆算方式は、目標の年齢が期間の終わりより後なら、その年齢まで年ごとの収支を作る（積み上げの額・内訳は期間の終わりまでのまま）。
- 要求のあいだの使い回し: `ctx.deathScenario` を呼んだ部品は、入力の全体に依存する（入力がまったく同じ要求のときだけ使い回す）。

### 2. 近似として残すもの（0005 の追記の「近似」を、この範囲に狭める）

- **最初の年の表を、後の年にも使う**: 亡くなった後のお金の動きは、どの年に亡くなっても同じとみなす。前の年の所得で決まる物（修学支援の区分の判定・住民税・国保の軽減・扶養の数え方）だけが、亡くなる年によって1〜2年ずれる（死亡の想定で計算し直すと、亡くなった人の前の年の所得で判定する年が残る）。見本の世帯で、計算基準年の翌年（万一のタブの既定の年）は税と社会保険料が10万円以内、5年後・10年後に亡くなる年は、修学支援で最大約280万円、税と社会保険料で約20万円、必要保障額が少なく出る（修学支援は、生計維持者が亡くなったときの家計急変の判定に近い）。遺族（配偶者）が変わる年（結婚・離婚）からは、その年の表を求め直す。
- 亡くなった人の車（入れていない車を数えない）・亡くなった人の死亡の年までの所得の税・子の収入と税・小規模企業共済の死亡一時金（準備できる資金に数えない）は、場面の表と違う決まりのまま。
- 速さ: 必要保障額の要求は、亡くなる人ごとに全体の計算（お金の動きまで）が1回増える。作業の Mac の Node（V8）で、計測の世帯（夫婦2人の推移）が 約75 → 約120 ミリ秒、見本の世帯で 27〜45 → 45〜67 ミリ秒（1.5〜1.7倍）。製品の quickjs-ng では CI の速さの計測（項目 `protection`。目安3秒）で確かめる。亡くなる年ごとに全体を計算し直す形（正確）は、同じ Mac で 0.7秒前後（20〜40年分×2人）になり、quickjs-ng では目安を大きく超えるので採らない。

### 3. 死亡の場面（全体の計算）の直し

- **死亡退職金の按分**: 万一の重ね（`overlay.ts`）は、働き方の期間を死亡の月で終える前に、その期間にひもづく退職給付（見込み額を入れた物）に予定の勤続期間（`service`）を書いておく。`retirement.benefit`（改訂4）は、見込み額を「死亡の月まで÷予定の終わりまで」で按分する。勤続の始まりより前に亡くなるなら死亡退職金は無い。見込みの計算（公務員の退職手当・役員退職慰労金）は、前と同じく死亡の月までの期間で計算する。
- **借入の前の死亡**（`debt.schedule` 改訂7）: 債務者（主たる債務者・連帯債務者）が全員、借入の月より前に亡くなる世帯の負債（住宅購入の予定のローンなど）は、組めないので返済を計算せず、借入の額を借入の月に現金で払う（住宅ローンは住宅の取得の行、ほかはその負債の行。計算式ID `debt.schedule.cashInstead`。知らせ `N_ESTIMATED debt.startsAfterDeath`）。団信も効かない。購入の予定そのもの（取りやめ・時期を変える）は FP が決める。前は亡くなった人の名でローンを始めて、遺族が返していた。

### 4. 遺族厚生年金の受給者（`pension.survivor` 改訂6・`pension.survivorRight` 改訂2）

- 死亡の当時55歳未満の夫は遺族厚生年金の遺族でない（厚生年金保険法59条1項1号）。遺族基礎年金を受ける間も遺族厚生年金を出さない（前は「遺族基礎年金を受ける間は60歳前でも」を受給権の無い夫にも当てていた）。
- このとき遺族厚生年金は子が受け取る（配偶者に受給権が無いので子の分は止まらない。66条1項）。遺族基礎年金は夫が受け、子の分は止まる（国民年金法41条2項）。世帯の合計は同じで、人ごとの内訳が変わる。

### 5. 相続税の目安（`inheritance.estimate` 改訂2）

- 「死亡の想定」の時点は、年金で受け取る死亡保険金（収入保障。契約者が亡くなる人で相続税の対象。相続税法3条1項1号）も数える。評価は「いま」の時点と同じく受け取る総額（相続税法24条の評価にはしない。0039 の3 の目安の近似のまま）。
- 「二人とも亡くなった後」は、夫婦のどちらかが団信の対象の負債の残高を、その人の分だけ債務から除く（先に亡くなった人の死亡で消えている）。

### 6. 万一のタブの「○歳時点の金融資産」

- 表示の設定の「○歳時点」（主画面の結果・提案書と同じ）を使う。前は見本の世帯の値か95歳だった。

## 理由

- 万一のタブは、同じ死亡の場面について「必要保障額」と「場面の表」を並べる。数え方が違うと、FP が説明できない。部品の結果から組み立て直す近道は、万一で変わる部品（国保・国民年金・修学支援・介護・団信など）を1つずつ近道の側に作り直す必要があり、漏れが続く。場面の計算をそのまま使えば、万一の重ねと部品の決まりが1か所で済む。
- 亡くなる年ごとに全体を計算し直すと正確だが、quickjs-ng では目安の3秒を大きく超える。亡くなった後のお金の動きは、前の年の所得で決まる物のほかは亡くなる年によらないので、遺族ごとに1回の計算で、近似の範囲を「前の年の所得で決まる1〜2年」に狭められる。
- 借入の前の死亡は、「亡くなった人の名でローンを組む」も「まだ借りていないローンが団信で消える」も起きない。購入の予定を消すかは FP の判断なので、予定のままにして、ローンを組めない分を現金で払う（必要保障額にも、その分が入る）。

## 代案（採らなかったもの）

- 亡くなる年ごとに全体を計算し直す（正確。速さで採らない。上の 2）。
- 近道のまま、国保・国民年金・修学支援・介護などの部品に死亡の月の入力を足して、1つずつ遺族の分を計算する（漏れが続く。場面の計算と二重になる）。
- 借入の前の死亡で、遺族の名で借りたとみなす（前の全体の計算と同じ額。団信の無い遺族のローンを勝手に組むことになる）、購入の予定を取りやめる（FP の判断を先取りする）。

## 影響

- 必要保障額の結果が変わる（PR の説明に見本の世帯ごとの数字）。自営業の世帯・修学支援を受けられる子のいる世帯・収益不動産のある世帯で少なく、会社員と専業の配偶者の世帯で少し多く出る。内訳の区画の中身も変わる（教育費から結婚の援助を「そのほか」へ、奨学金の受け取りを公的な支援へ、住宅購入の援助を遺族の収入へ）。
- 死亡の場面の表: 死亡退職金が按分で少なくなる（若いうちに亡くなる想定ほど）。住宅購入の予定の前に亡くなる場面は、ローンの返済の代わりに借入の額を現金で払う。
- 部品の書き方の約束 1.5（`ctx.deathScenario`）。差し替えの `protection.need` も使える（0119）。
- 世帯ファイルの形式の版・必要保障額の出力の形は変えない。

## 未確定

- 修学支援の家計急変（生計維持者が亡くなった後の判定）を全体の計算に入れるか。入れると、上の 2 の近似のずれの大きい所が消える。
- 小規模企業共済の死亡一時金を、必要保障額の準備できる資金（一時の分）に数えるか（内訳の欄を足すなら約束の版を上げる）。
- 亡くなった人の車の扱いを場面の表とそろえるか（今は部品の頭の決まり〔改訂2〕のまま）。
- 借入の前に亡くなる住宅購入の予定を、画面で FP に確かめる形（今は知らせだけ）。

## 追記

- 2026-11-08: 未確定のうち3つを、利用者の判断で入れた・そろえた（0173）。修学支援の家計急変（生計維持者が亡くなった月の翌月から、亡くなった人を除いて判定し直す）を入れ、2 の近似の修学支援のずれ（最大 約280万円）が無くなった（見本の世帯で、後の年に最初の年の表を使う額と、その年に亡くなる想定の額の差は、税と社会保険料の約24万円まで）。小規模企業共済の死亡を事由とする共済金を準備できる資金（一時の分。内訳の `mutualAidLump`。約束の版 1.2）に数える。亡くなった人の車は場面の表のとおりに数える（入れていない車も、相続する人が持ち続ける）。あわせて、計算基準年に亡くなる年の確定拠出年金の死亡一時金を、計算基準月の前の残高にした（前は0円）。
