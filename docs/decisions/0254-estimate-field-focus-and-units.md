# 0254. 推定の欄に入ると推定の数字を全部選ぶ・欄の中は数字だけで単位と「この値にする」は欄の外・推定の選択肢を選ばれた見た目に

- 状態: 採用（一部未確定）（2026-11-23）
- 固定の強さ: 内部（画面の見せ方と操作）。値の状態の決め方・推定の値・世帯ファイルの形・計算は変えない。決まりとして残すのは「推定の欄に入ると推定の文字を全部選ぶ。何も打たずに離れたら推定のまま」「欄 → 単位 →『この値にする』の並び。『この値にする』を欄の中に入れない」「推定している選択肢は点線・薄い色で選ばれた見た目。押すと FP が選んだ確定」「空のまま離れたときの知らせは理由だけ」の4つ。欄の幅・色・文言は後から変えてよい（変えたら追記に書く）
- 前提にする記録: 0041（値の状態と「この値にする」。2026-10-27・2026-11-07・2026-11-10・2026-11-11 の追記）、0038（時点の部品）、0101（「今から」だけで入れる欄）、0236（区切りボタン）

## 背景

利用者が見た画面（車の入力項目）で次のことがあった。

- 推定の値が入った欄（点線の枠・「推定」の印）を押すと、押した所に文字の位置が来るだけで、推定の値を打ち直すには自分で消す必要があった。
- 「次の買い替えの時期」は欄の中に「3年後」と単位まで入り、「この値にする」は欄の外の右。「買い替えの周期」は欄の中が「8」だけで「年ごと」は外、「この値にする」は欄の中の左に入り込んでいた（0041 の 2026-10-27 の追記で、値が短い数の欄だけ「この値にする」を欄の中に置いていた）。同じ入力項目の中で並びがばらばら。
- 欄を空にして離れると「「」は入れられないため、前の値のままです。空にはできません。値を入れてください」と、空の文字を「」で出していた。
- iDeCo の「受け取り方」（貯蓄・運用の入力項目の区切りボタン）は、空欄のまま一時金で計算しているのに、どのボタンも選ばれていない見た目で「推定」の印だけが出ていた。

## 決定

### 1. 推定の欄に入ると、推定の数字を全部選ぶ（`app/src/workspace/input/estimateFocus.ts`）

- 対象は推定の値の欄（値の状態が推定。仮の値も同じ）で、欄に見えている推定の値か、空欄のまま推定で計算している欄が灰色で見せている推定の値（0041 の 2026-11-10 の追記）があるもの。数の欄・円の欄・％の欄・年月の欄（入力の欄の部品 `Field`）、時点の欄（`WhenField`）、貯蓄・運用の入力項目の数の欄（`NumBox`。受け取りを始める年齢・積立をやめる年齢・利回りなど）のすべてで同じ。
- 押して入る・Tab（Shift+Tab）で入ると、推定の文字を欄に入れて全部選ぶ。そのまま打てば置き換わり、← → で選択を外して一部を直せる。
- 押して入るときは、押した所に文字の位置を置く既定の動きを止めてから欄に入る（止めないと、Chrome・WebKit とも、マウスを離したときに選択が外れる）。もう入っている欄を押したときは今までどおり。
- 何も打たずに離れたら、値も「推定」の印も変えない（0041 の「入ったときと同じ文字のまま離れたら書かない」のまま）。空欄の推定の欄で、選ばれた灰色の値を消して空のまま離れたときも、空欄の推定のまま（使えない文字の知らせも出さない）。
- 打った値は推定と同じ値でも FP が入れた値の確定（0041 の 2026-11-07 の追記のまま）。
- FP が入れた値の欄（確定）・書類待ち・該当なし・未入力の欄は今までどおり（全部は選ばない）。

### 2. 欄 → 単位 →「この値にする」の並び

- 欄の中は数字だけで右寄せ。単位（年後・歳・年ごと・万円・月額・％など）は欄のすぐ右。「この値にする」はいつも単位のさらに右で、欄の中には入れない（0041 の 2026-10-27 の追記の「数の欄は欄の中」をやめた。`fillInside`・`FILL_VALUE_ROOM` を外した）。
- 文字を打つ欄（数・円・％・年月）は、欄・単位・「この値にする」を1つの並び（`.fld-in`）にまとめ、幅の狭い列（3列の並び）では欄を縮めて「この値にする」を次の行へ落とさない。
- 時点の欄は、欄に見せる文字が「3年後」「65歳」のように数字と単位だけのときに、欄の中を「3」「65」、単位を欄のすぐ右に出す（`whenNumber`）。欄の中の数字だけを打ち直しても同じ時点に読める（○年後の欄の「5」は5年後、年齢の欄の「60」は60歳。0038 の読み方のまま）。打っている文字が数字だけの間は単位を出し、年月・出来事からの形を打ち始めたら単位を消す。「3年2か月後」「65歳の誕生月」「配偶者65歳」・年月・出来事からは今までどおり欄の中にそのまま。
- 貯蓄・運用の入力項目の専用の欄（残高・取得価額・利回り・運用しない分など）の「この値にする」も、欄の下の操作の行から、単位のすぐ右（「推定」の印があればその右）へ移した（`FieldFill`）。
- アプリ全体で「この値にする」が出る欄を、見本の世帯の全部の入力項目（詳細・「▸」を全部開く）で調べた。欄の中に入っていたのは、子ども・教育（学校の費用・入学金・在学年数など）、介護（月々の費用・一時費用）、住まい（火災保険料・地震保険料）、収益不動産（土地の割合）、車（買い替えの周期）。時点の欄で単位が欄の中に入っていたのは、車の次の買い替えの時期・手放す時期など。どれも上の並びになる。

### 3. 空のまま離れたときの知らせ

- 「「○○」は入れられないため、前の値のままです。理由」の組み立てを1つの関数（`keptText`）にまとめ、打った文字が空のときは理由だけ（「空にはできません。値を入れてください」。時点の欄は「空にはできません。時点を入れてください」）を出す。入力の欄の部品・時点の欄・貯蓄・運用の数の欄・結果のタブの動かす項目の額の欄（空のときの理由を「空にはできません。値を入れてください」にした）の4か所で同じ。

### 4. 推定している選択肢は、点線・薄い色で選ばれた見た目（利用者の判断）

- 区切りボタン（入力の欄の部品の `SegChoice` と、貯蓄・運用の入力項目の iDeCo・企業型DC の「受け取り方」）: 空欄のまま推定で計算している選択肢（`blankEstimate` の値。受け取り方は一時金）と、推定の値として入っている選択肢（申告の仕方など）を、ほかの推定の欄と同じ点線・薄い色で選ばれた見た目にする（`.seg-g button.is-est-opt`）。カーソルを合わせると推定の根拠（例「推定: 退職の年（60歳）に一時金で受け取る計算（押すと、この選択で確定します）」）。
- どれかを押すと FP が選んだ値の確定になり、ふつうの選ばれた見た目（藍の塗り）になって「推定」の印が消える。推定の選択肢そのものを押したときも確定（区切りボタンは押した選択肢を `typeValue` で書く。推定と同じ値でも打った値と同じ確定になる）。
- 選ぶ欄（プルダウン）: 空欄のまま推定で計算している欄は、空の選択肢を「（推定: 一時金）」でなく推定の選択肢の名前（「一時金」）で選ばれた形にし、欄を点線・薄い色にする。この空の選択肢は一覧には出さない（`hidden`・`disabled`）ので、一覧で同じ「一時金」を選ぶと FP が選んだ確定になる。推定の値が入っている選ぶ欄も、点線・薄い色の枠にする。時点の欄の「入れ方」などの横の選ぶ欄は対象にしない。
- 「推定」の印・「この値にする」は今までどおり。

## 理由

- 推定の値は「打ち直す前提の目安」なので、入ったときに全部選ばれていれば、そのまま打つだけで直せる。何もしなければ変わらないので、Tab で通るだけの操作で推定が確定に変わることもない。
- 欄の中に数字以外（単位・ボタン）が入ると、欄ごとに並びが変わり、値の文字とボタンが近くて押し間違えやすい。並びを1つに決めれば、どの欄でも同じ所を見ればよい。
- 推定の選択肢が選ばれていない見た目だと、空欄で何を計算しているかが分からない。ほかの推定の欄と同じ点線の見た目にそろえた。

## 未確定の要点

- 3列の並びでは、推定の欄（「この値にする」がある欄）だけ欄が狭くなり、隣の確定の欄と幅がそろわない。「この値にする」を小さくするか、列の数を変えるか。

- 文字の大きさ「大」で、とても狭い列のときは欄を縮めきれずにはみ出すことがある（最小の幅は数の欄 4.5em）。
