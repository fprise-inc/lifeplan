# 0133. 働き方の入口と働く最後の年齢の推定（種類を変えたときの入れ直し・目安の定年を過ぎた人・過去の退職金）、定年後の年収、パートの初めの値、年金の書類の欄

- 状態: 採用（一部未確定）（2026-11-07）
- 固定の強さ: 内部（推定の作り方・初めの値・欄の出し方。世帯ファイルの形式の版・エンジンの部品は変えない）。事務所の既定値に「自営業の働く最後の年齢」（`preset.work.selfEmployedRetireAge`）を1つ足した（値は後から変えてよい。変えたら `rev` を上げて追記に書く）
- 前提にする記録: 0047（働き方と収入）、0057（退職金・企業年金）、0066（年金）、0041（値の状態・確かめの一覧）、0111（事務所の推定の値）、0129（ありえない結果の見張り）、0130（言葉の決まり）、0131（欄の部品）

## 背景

通しで入力を試すと、働き方の推定が入れた働き方についてこず、結果を黙って誤らせていた。

1. 自営業として入れると働く最後の年齢が空欄で、表の最後（100歳）まで事業所得が入る。知らせも無い。
2. 自営業から公務員・正社員に変えても定年が入らず、公務員として100歳まで働く。
3. 会社員として入れてからパート・役員に変えると、「定年60歳→65歳まで再雇用」の推定と再雇用の期間が残る。
4. 60歳以上の人を会社員として入れると、22歳〜60歳の正社員（過去）が作られ、受け取りが過去になる退職一時金（約1,800万円）が推定で足される（入力のホームに「見込み」として出る）。今の働き方が再雇用の人に「定年」「定年後の働き方」「定年後の年収」が出て、今の年収と同じ値を2か所で直せる。
5. 働き方の入口が「会社員として入れる」「自営業として入れる」の2つだけで、パート・公務員・役員は会社員で入れてから種類を変える（3 の副作用）。専業主婦などは「働いていない」を選べない。
6. 推定の年収・賞与・住民税に端数（「118.404万円」「711.3036万円」）。定年後の年収だけ「賞与を除く」。パートの週の時間の初めの値（20時間）が年収の推定（週15時間）と食い違い、印も無い。「＋ 働き方」で1か月だけの期間ができる。
7. 年金: 50歳未満のねんきん定期便の老齢基礎年金の額を入れても計算に効かない（エンジンは加入月数から計算する）。国民年金の加入月数の説明が定期便の「国民年金 計」（第1号・第3号だけ）を写すよう言い、計算の読み方（20〜59歳の厚生年金の月も含む）とずれていた。書類からに変えると加入月数のボタンが2つ出る。受給中（年金額改定通知書）でも受け取り開始の欄が出る（計算は読まない）。
8. 確定給付企業年金を年金で受け取るのに、一時金の見込み額が「未入力」のまま残る。

## 決定

### 1. 働く最後の年齢の推定（`stages/work.ts` の `lastAgeEstimate`・`mainEndEstimate`・`estimateWorkEnd`）

- 働き方の種類ごとの目安: 正社員・公務員は定年（今までどおり。正社員は事務所の既定値の定年・公務員は生まれた年度の定年。65歳より前なら65歳まで再雇用の推定）、自営業は事務所の既定値 `preset.work.selfEmployedRetireAge`（70歳。利用者の判断。見本の自営業の世帯も70歳）、パート・契約は65歳（65歳までの雇用確保の決まり）、会社役員は70歳（退任の年齢。役員の見本と同じ）。休業中・働いていないは終わりを置かない。
- どれも推定の印（働く最後の年齢の欄、正社員・公務員は定年の欄）。根拠の頭は「既定の値（…）」（0130）。
- **目安の年齢をもう過ぎている人**（目安の年齢になる前の月が計算の基準の月より前）は、過去の定年を推定しない: 65歳前なら65歳まで（65歳までの雇用確保の決まり）、65歳からは今から5年（90歳まで）。正社員を選んだ63歳の人は「今も正社員」として65歳までにする（過去の正社員と今の再雇用を作らない）。
- 終わりを置くときは、働く最後の年齢の欄と同じ決まり（`applyRetireMonth`）で期間を終え、退職の段の生活費・NISA の積立の終わりも合わせる。終わりを置いた期間の失業給付・高年齢雇用継続給付は、新しく作った期間と同じく「おまかせ（推定）」にする（「未入力」にしない）。

### 2. 働き方の入口（`nowGroup`）

- 「働き方を入れる」の1つのボタンの中の選択肢（0040 の追記の `choice`）: 正社員・パート・アルバイト・契約社員・嘱託・公務員・会社役員・自営業・休業中・働いていない（専業主婦・主夫など）。選んだ種類で期間を作り、年収・住民税・働く最後（1）・定年と定年後の予定・退職金の目安を推定で入れる。60歳からは「契約社員・嘱託（再雇用など）」を先頭に出す。
- 期間の始まりは、正社員・契約・公務員・役員・自営業が22歳の4月（厚生年金・国民年金の推計に使う。前の「会社員として入れる」と同じ）、パート・休業中・働いていないは計算の基準の月（ヒアリングシートの取り込みと同じ）。
- 「働いていない」は種類 `unemployed` の期間（収入なし・終わり無し・推定の印無し）を作る。入力のホームの働き方は推定のない入れた値になる。
- **定年（会社員の目安）をもう過ぎた人の「契約社員・嘱託（再雇用など）」**: 22歳の4月から定年の前の月までの正社員（辞め方は定年の推定）と、定年の月からの今の再雇用（働く最後は 1 の推定。65歳前なら65歳まで）の2つの期間を作る。前の勤め先の正社員の期間は、厚生年金の推計と、前の勤め先の企業年金の当て先に使う。受け取りが過去になるので退職金の目安は足さず、定年の欄も出さない（4）。
- 正社員・自営業の選択肢のボタンの鍵は前の2つのボタンと同じ（`work/<人>/start`・`work/<人>/startSelf`）。ほかは `work/<人>/start/<種類>`。

### 3. 種類を変えたときの入れ直し（`refitWorkEnd`）

- 今の働き方の期間の種類を変えたとき、期間の終わりが無いか、終わりが推定のまま（定年・働く最後の年齢の印がある）なら、推定のままの定年後の予定（再雇用の期間）を外し、新しい種類の 1 の推定を入れ直す（正社員・公務員は定年と定年後の予定、パート・契約は65歳、役員は70歳、自営業は事務所の既定値）。パート・契約・役員・自営業では定年後の予定を外す（定年の欄を出さない）。FP が入れた終わり（印の無い終わり）・定年は変えない。
- 年収・賞与の推定の入れ直し（推定のままなら新しい種類の統計に）と、パート・働いていないで退職金の目安を足さないこと（目安のままの退職金を外す）は、今までどおり（0057）。
- 働く最後の月が「＋ 働き方」や詳細の終わりで変わったのに、働く最後の年齢の推定の印が前のままなら外す（`dropStaleEndMarks`）。

### 4. 定年をもう過ぎた人と過去の退職金

- 定年（今の勤め先の期間の終わり）が計算の基準の月より前の人は、定年後の予定のまとまりで定年・定年後の働き方・定年後の年収を出さず、働く最後の年齢だけにする（今の年収は今の働き方の欄で直す）。
- 退職金の目安（`fill.ts` の `retirementEstimate`）は、受け取り（勤め先を辞めた翌月）が計算の基準の月より前になるなら作らない（自動で足さない・確かめの一覧の「推定で入れる」にも「入っていない」にも出さない。入力のホームの見込みにも入らない）。

### 5. 終わりの無い働き方の注意

- 今の働き方に終わりが無く（休業中・働いていないを除く）、収入が表の最後まで入る人は、働く最後の年齢の欄の注意「働く最後の年齢が決まっていません（100歳まで事業所得を入れています）」と「70歳までにする（推定）」のボタンを出す（確かめの一覧の「確かめの注意」にも出る）。年齢は表の最後の年の12月の年齢。

### 6. 定年後の年収（`postSalaryField`）と推定の額の丸め

- 欄の名前を「定年後の年収（税込み・賞与込み）」にした（今の年収と同じ基準。0130 の年収の決まり）。見せる値は定年後の期間の年収と賞与の合計。合計を入れると、確定の賞与（打ち手で作った定年後の期間の0円も）はそのまま、推定のまま・無い賞与は賃金の統計（定年後の働き方・定年の年齢）の年収と賞与の割合で分ける（今の年収の欄と同じ決まり。世帯ファイルは年収と賞与の2つの箱のまま）。定年後の期間がまだ無いときは分けずに定年後の予定の年収にする。
- 推定の根拠の文を「今の年収（賞与を除く）×86%（同じ働き方の60〜64歳の平均÷55〜59歳の平均…）」にした（掛けているのは定年の時点でなく今の年収のため。推定の作り方の見直しは後の段階）。
- 年収・賞与・事業所得・住民税の推定は千円単位に四捨五入する（`hearing/src/estimates.ts`。生活費の推定と同じ）。定年後の再雇用の比（`reemploymentRatio`）は丸める前の額で取る。

### 7. パートの初めの値と「＋ 働き方」

- パートの週の所定労働時間の初めの値を15時間にした（年収の推定 `preset.wage.partTime.weeklyHours` と同じ値を読む）。ヒアリングシートの空欄の初めの値 `preset.work.weeklyHours.partTime` も20→15時間（`rev` 2）。勤め先の従業員数・週の時間が初めの値のままなら推定の印（根拠「既定の値（パートの週の所定労働時間・15時間。社会保険の判定に使います）」）を付ける（直すとその欄の印は外れる）。
- パートの健康保険の初めの値は、配偶者が勤め先の健康保険（協会けんぽ・健保組合・共済）のときだけ「家族の扶養」、ほかは国民健康保険。
- 「＋ 働き方」で足す期間の終わりは、始まりから5年（90歳になる前の月まで）。

### 8. 年金の書類の欄（`stages/pension.ts`）

- **50歳未満の定期便の老齢基礎年金の額**: エンジンの年金の記録の部品（`pension.record`）は50歳未満の定期便の基礎年金の額を読まず、加入月数から計算する（`amounts.basic = null`）。同じ物を二重に持たないよう、欄を出さない（新しく作る記録には未入力の印の箱も置かない。前に入れた額は消さない）。未入力の判定も老齢厚生年金の額だけで見る。
- **国民年金の加入月数の読み方**: エンジンは `months.basic` を「老齢基礎年金の額に数える20〜59歳の月」（第1号の納付・第3号・厚生年金の月）として読み、加入歴からも20〜59歳の全部の月を数える。日本年金機構のねんきん定期便の様式では「国民年金（a）」の内訳が第1号・第3号・「国民年金 計」で、厚生年金の月は「厚生年金保険（b）」、両方を足した「年金加入期間 合計（未納月数を除く）（a＋b＋c）」がある。計算は変えず、欄の説明を「年金加入期間 合計（国民年金 計と厚生年金保険 計の合計）を写す。20歳前・60歳からの厚生年金の月と免除・猶予の月は含めない」にした（代わりの値「20歳の月から作成年月まで」と同じ読み方）。
- **書類からに変えたとき**: 新しく定期便の記録を作ったら、加入月数に代わりの値を推定の印で入れる（0か月のまま年金を少なく・0円にしない）。「加入月数を書類で確かめる」のボタンは、前の版で保存した0か月のままの定期便にだけ出る。残した記録に戻したとき・書類の種類を変えたときは、前の加入月数をそのまま引き継ぐ。
- **経過的加算の額**: エンジン（`pension.oldAgeBase`）は、加入月数から計算する記録（定期便・厚生年金の月数のある受給中）では経過的加算の額を読まず、加入月数から計算する。写しても効かないので、その記録では欄を出さない。見込額だけの記録と、厚生年金の月数の無い受給中の記録だけに出す（入れなければ0円）。
- **受給中（年金額改定通知書）**: エンジン（`pension.oldAgeBase`）は受給中の記録の受け取り開始を読まず、今受け取っている年金として計算する。受け取り開始の欄を出さず、読むだけの1行「受け取り開始: 受給中（今の年金額で計算）」にする。繰下げを待っている人は、定期便（50歳以上）で受け取り開始を入れる（「?」に書いた）。

### 9. 確定給付企業年金を年金で受け取るとき（`stages/retirement.ts`）

- 受け取り方が「年金」で、一時金の見込み額が未入力（額の無い・未入力の印の箱）なら、一時金の欄を出さず（未入力にも数えない）、年金の年額を入れる欄にする（入れるまでは未入力）。一時金の額（入れた額・推定）があれば残して見せる（年金の年額が空欄なら、その額から年金に直すため）。併用のときは今までどおり両方。

## 理由

- 自営業の70歳は利用者の判断（入れ忘れると甘く出る向きで、ざっくり入れる FP ほど気づけない）。事務所の既定値にしたのは、事務所ごとの顧客の層で変えたいため。
- 目安の定年を過ぎた人を「今の働き方のまま65歳（か今から5年）まで」にしたのは、過去の正社員の期間と過去の退職金を推定で作ると、もう受け取った退職金を将来の収入にしてしまうため。今の働き方は FP が選んだ種類のままにした（63歳で正社員と選んだ人を再雇用に書き換えない）。
- 種類を変えたときに推定だけを入れ直すのは、値の状態の決まり（確定は明示の操作だけ。0041）のため。印の無い終わり・定年は人が入れた値として残す。
- 50歳未満の定期便の基礎年金の額は、計算に使うより欄を出さないほうにした。加入月数から計算すれば、これからの加入の分も同じ式で足せ、二重に持つとどちらが正か迷うため。
- 加入月数は計算を変えずに説明を直した。定期便に「年金加入期間 合計」の欄があり、写す欄を1つにできる。計算を「国民年金 計＋厚生年金の月」に変えると、20歳前・60歳からの厚生年金の月を分けられない。

## 代案（採らなかったもの）

- 自営業の働く最後の年齢を会社員の再雇用と同じ65歳: 自営業は定年が無く、65歳では多くの世帯で早すぎる（利用者の判断）。
- 60歳以上の入口で、過去の正社員と今の再雇用を作り直す（前の形）: 過去の退職金と定年の欄が残る。厚生年金の推計に効く22歳からの期間は、今の働き方の期間の始まり（22歳の4月）で持つ。
- 年金の推計が外れやすい人に「定期便の数字を入れてください」の知らせ: 利用者の判断で出さない（推計が外れるのはしかたない）。

## 影響

- 計算: 新しく入れる・種類を変える働き方の推定だけが変わる（今ある世帯・見本の世帯は、開いただけでは変わらない）。自営業として入れた人は70歳で事業所得が終わる（前は表の最後まで）。会社員からパートに変えた人は65歳まで（前は60歳の定年と65歳までの再雇用の推定）。60歳以上の人を正社員で入れると65歳まで（過去の退職一時金は足さない）。推定のままの年収・賞与・事業所得・住民税は千円単位に（差は500円まで。推定の入れ直しで、推定のままの値は丸めた額になる）。パートの週の時間の初めの値15時間（勤め先の規模の初めの値が50人なので、社会保険の判定は変わらない）。定期便を新しく選んだ人は、加入月数の代わりの値で計算する（前は0か月のまま）。
- 世帯ファイル: 形式の版は変えない。事務所の既定値に `preset.work.selfEmployedRetireAge` を足した。
- エンジン: 変えない（50歳未満の定期便の基礎年金の額・受給中の受け取り開始の読み方を確かめただけ）。
- テスト: `app/test/work-estimates.test.ts`（入口の選択肢・働いていない・自営業の70歳と事務所の既定値・終わりを空にしたときの注意・種類の入れ直し〔自営業→公務員・自営業→パート・会社員→パート・会社員→役員・人が入れた終わりを残す〕・60歳以上・過去の退職金・定年後の期間が今の人の欄・定年後の年収・パートの初めの値と健康保険・「＋ 働き方」の5年・推定の丸め・取り込んだ世帯の働く最後・年金の書類の欄・企業年金の年金受け取り）。見張りの直す待ちの一覧（0129）から `past-retirement-estimate`・`retirement-estimate-after-type-change`・`self-employed-no-end`・`civil-servant-from-self-no-end` を外した。通しの入力のテスト（0132。`app/test/walkthrough/`）: 働き方の入口の操作を新しいボタンに直し、60代の世帯のご本人は「契約社員・嘱託（再雇用など）」から入れる。直す待ちだった「パートに変えると配偶者の年収の推定が変わる」「定年が過去の人に目安の退職一時金を足さない」「企業年金を年金で受け取るとき一時金を未入力に数えない」を通常のテストに、見張りの直す待ちから「再雇用・パートなのに定年の推定が残る」を、欄ごとの効き目の直す待ちから経過的加算を外し、50歳未満の定期便の老齢基礎年金の額は「欄を出さない」ことを確かめる形にした。丸めた額・パートの初めの値・定期便の加入月数に合わせて直したテスト: `card-pension`・`screen-fixes`・`estimates`（画面とヒアリングシート）・`import`（ヒアリングシート）。
