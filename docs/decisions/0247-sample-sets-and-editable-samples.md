# 0247. 見本の作り直し（見本番号をなくす・セットと見出し・どの見本も直せる・最初の状態に戻す・法人経営者の見本はコードで）

- 状態: 採用（一部未確定）（2026-11-23。2026-11-22 に提案、利用者の判断を受けて採用）
- 固定の強さ: 骨格は、(a) 見本は番号を持たないこと、(b) 見本かどうか・どのセットの見本か・最初の状態を世帯ファイルと一覧の欄に持つ形（`sample` の欄の名前と意味、世帯ファイルの `meta.sample`、本文の区画 `sampleInitial`）、(c) セットの ID の付け方、(d) コードで出すセットは 0110 のコードの確かめをそのまま使うこと。世帯ファイルの形式は「安定」の公開の約束（0.87。変換の段と見本ファイルを添える）。見本の顔ぶれ・名前・絞り込みの項目の語・見出しの言葉・画面の並び・AI接続口の答えの形（試験版）は後から変えてよい（変えたら追記に書く）
- 前提にする記録: 0009（控え）、0011（世帯ファイルの封筒・形式の移行）、0012（識別）、0013（暗号化・完全削除）、0023・0024（事務所の共有・同期フォルダ）、0033（顧客番号と見本の棚）、0096（保存していない変更を黙って捨てない）、0097（開き直した後の元に戻す）、0110（機能を有効にするコード）、0114（拡張の束・公式の拡張）、0166（前の世代で開く）、0182（面談の履歴）、0197（合算BS の見本）、0199（AI接続口の見本の一覧）、0208（AI の世帯の候補）
- この記録が変える記録: 0033 の3・4 と 2 の最後の文（見本番号・一覧を作り直すときの見分け方・見本を開いても保存しない決まり・見本の顔ぶれ）、0197 の2〜4（見本の世帯でだけコードなしで見せる扱い）、0199 の1（一覧の `no`）、0244 の見本番号を前提にした所（見本番号の列・番号で開く・番号で確かめる）。どれも β公開の前なので、0001 の4 の「β公開前は、新しい記録で理由を残せば変えてよい」による。それぞれの記録に「0247 で変えた」の追記を足した（0110・0114 にも、見本のセットを出す条件の追記を足した）。形式 0.87 の 0011 の追記は、保存の形を入れるときに書く
- 作る順: この記録の決定は、下の「作る順」の段ごとに入る。入るまでは前の記録の作りのまま（たとえば見本番号は、1段目が入るまで残る）

## 背景

- 見本番号（0033 の3。「家族の形-本人の年代-順番」。順番 01〜09 はアプリに入っている見本、10〜 は自分で作った見本）は、番号で出どころを表していた。見本の数や種類（配られるセット）が増えると 01〜09 に収まらず、02 の次が 10 になる並びも分かりにくい。
- 番号は保存の形にも入っている。一覧の欄の `sample.no`、表示の番号 `customerNo`（見本は見本番号を入れている）、世帯ファイルの `meta.customerNo`。事務所データが古い世代に戻って一覧を世帯ファイルから作り直すときは「表示の番号が見本番号の形なら見本」と推し量っている（`numbering::label_from_no`）。自由な顧客番号（英数字とハイフンの16字まで）に `3-4-10` と入れた顧客の世帯は、作り直しで見本に化ける。見本の名前と項目は作り直しで失われる（「見本 3-4-10」という仮の名前になる）。
- 今は、アプリの見本は保存しない世帯として開き、自分で作った見本も「この見本を直す」を押すまで保存しない（`sampleNotSaving`）。「見るだけの開き方」があるために、帯の文・入力のパネルの「保存」の知らせ・合算BS の見本の扱い（0197）・書類の読み取りの「見本で試す」・AI への共有の条件が、それぞれ「保存していない見本か」を見分けている。
- 合算BS の見本（0197）は、コードを持たない人にも「アプリの見本を保存しないで開いているときだけ」見せている。見本をふつうに保存できるようにすると、この条件が成り立たなくなる。
- β公開で世帯ファイルの形式を 1.0 にする（0011 の追記）。見本の持ち方は、その前に固める。

## 決定

### 1. 見本は番号を持たない

- **見本番号をなくす。** 一覧の欄・世帯ファイル・画面・AI接続口のどこにも、見本の番号を持たない・出さない。見本は名前と「家族の形・本人の年代」「項目」で探す。
- **一覧の欄の `sample`（`SampleInfo`）の新しい形**（PC の中の事務所データの一覧 `CatalogEntry` と、共有フォルダの一覧の欄のファイル `Card` で同じ。`Label` に平らに入る）:

  ```json
  "sample": {
    "name": "退職前後の夫婦・60代",
    "traits": ["会社員", "持ち家"],
    "family": 3,
    "age": 6,
    "origin": { "set": "official.basic", "id": "sampleSeniorRental", "rev": 1 },
    "changed": true
  }
  ```

  | 欄 | 中身 |
  |---|---|
  | `name` | 見本の名前（1〜40字。前後の空白なし・制御文字なし。今と同じ決まり） |
  | `traits` | 絞り込みの項目（12個まで・1つ12字まで。今と同じ） |
  | `family` | 家族の形（1 単身・2 夫婦のみ・3 夫婦と子・4 ひとり親・5 シニア）。今までは番号の1つ目から読んでいた |
  | `age` | 本人の年代（2〜7）。今までは番号の2つ目から読んでいた |
  | `origin` | 任意。**セットの見本を直した版**のときだけ持つ（5）。`set` はセットの ID（3）、`id` はそのセットの中の見本の ID、`rev` はセットの定義が持つ見本の中身の版（整数。無ければ 0） |
  | `changed` | 任意（無ければ false）。最初の状態から変わっているか（6）。「最初の状態に戻す」を出すかを、一覧を見ただけで決めるため |

  - `origin` が無い見本が「自分で作った見本」（登録・複製した物）。
  - 欄 `no` は書かない。読むときだけ受け付ける（移行。8）。
- **表示の番号 `customerNo`**: 見本は空の文字列（一覧の欄・開いた世帯の答え）。世帯ファイルの `meta.customerNo` は、見本では書かない（欄ごと無い）。
- **世帯ファイルの `meta.sample`**（形式 0.87 で足す任意の欄）: 一覧の欄の `sample` と同じ形（`changed` を除く）。本体が保存のたびに一覧の欄から書く（`META_WRITTEN` に足す。画面は書かない）。見本でない世帯には無い。
  - 一覧を世帯ファイルから作り直すとき（`Store::catalog_from_file` と、共有フォルダから PC の中へ戻すときの `shared.rs` の同じ所）は、**`meta.sample` があれば見本**（名前・項目・家族の形・年代・出どころがそのまま戻る）。無ければ顧客の世帯（自由な番号）。
  - 0.86 までのファイル（`meta.formatVersion` が 0.87 より前）で `meta.sample` が無く、`meta.customerNo` が前の見本番号の形のときだけ、前と同じく見本として戻す（名前は「見本（夫婦と子・40代）」の形で、重なれば 8 の決まりで番号を足す）。0.87 からのファイルには、番号の形での推し量りを使わない。
- **同じ名前の見本は作れない。** 比較は前後の空白を除いた文字列の一致（Unicode の正規化は NFC）。見えない文字（幅の無い空白・つなぎ・向きの制御・BOM など）の入った名前は作れない（同じに見えて違う名前ができるため）。比較する相手は、(a) 同じ棚（PC の中、または事務所の共有フォルダ）のすべての見本の `name`、(b) アプリに入っているすべてのセット（コードで出していないセットも含む）の見本の名前。重なれば `E_STORE_SAMPLE_NAME`（「同じ名前の見本があります。別の名前にしてください」）。セットの見本を直した版（`origin` あり）は、元の見本と同じ名前を持つ（同じ見本なので重なりに数えない）。
  - 事務所の共有・同期フォルダでは、2台がほぼ同時に同じ名前で作ると防げない（一覧の欄が届く前）。そのまま両方を出す（内部ID で指すので、操作は取り違えない）。名前を直すときに重なりを知らせる。
- **完全削除の確かめ**: 見本は、見本番号の代わりに**見本の名前**を打つ（`Store::delete` の `confirm` を、見本では `sample.name` と比較する。顧客の世帯は今までどおり顧客番号）。
- **見本の名前と項目を直す**（`update_sample`）: 家族の形・年代も直せるようにする（番号に入っていたので直せなかった）。引数は `id`・`name`・`traits`・`family`・`age`。セットの見本を直した版（`origin` あり）は名前・項目・家族の形・年代を直せない（セットの定義が正）。
- **本体から消す物**: `numbering::sample_no`・`next_sample_order`・`FIRST_OWN_SAMPLE`・`MAX_SAMPLE_ORDER`、`SampleRequest` から番号を作る所、`E_STORE_SAMPLE` の「番号の空きが無い」。`parse_sample_no` は移行のためだけに残す（公開しない）。

### 2. 見本の一覧は「セット」で分け、見出しは種類が2つ以上のときだけ出す

- 見本の種類は3つ: **「ファイナンシアの見本」**（全員に入っている）、**配られたセット**（今は「法人経営者の見本」の1つ）、**「自分で作った見本」**（事務所の共有を使っているときは「事務所で作った見本」。1人で複数の PC の同期フォルダのときは「自分で作った見本」）。
- 並びは ファイナンシアの見本 → 配られたセット（セットの定義の順）→ 自分で作った見本。セットの中はセットの定義の順、自分で作った見本は名前の順。
- **見出しは、今出ている種類が2つ以上のときだけ出す。** はじめて使う人（ファイナンシアの見本だけ）には見出しを出さない。コードで出していないセットは、見出しも行も数も出さない（「ほかにもある」と感じさせる物を出さない）。絞り込みで行が0件になった種類の見出しは出さない。
- 行ごとの出どころの印（今の「アプリ」）は付けない。見本番号の列を無くし、「家族・年代」の列は `family`・`age` から書く。名前で探す欄を足す（名前の一部で探す）。絞り込み（家族の形・年代・項目）は今までどおりで、番号ではなく `family`・`age` を見る。
- 行の操作: 「開く」「この見本をもとに顧客を作る」「複製する」は、どの見本にも出す。「名前と項目を直す」「完全削除」は自分で作った見本だけ。「最初の状態に戻す」は `changed` の見本だけ（6）。
- 上の帯・世帯の箱の表示は「見本「（名前）」」。見本を開いているときの帯は「見本「（名前）」（夫婦と子・40代・架空）を開いています。手直しは自動で保存します。」。

### 3. セットの定義（アプリに入っているセットと、後から読み込むセットを同じ形で）

- セットの定義（アプリの中。`app/src/workspace/samples/sets.ts` に新しく置く。今の `catalog.ts` の `DEMO_HOUSEHOLDS` を分けて移す）:

  ```ts
  interface SampleSet {
    id: string;            // 例 "official.basic"・"official.corporateOwner"
    name: string;          // 見出し（「ファイナンシアの見本」「法人経営者の見本」）
    feature?: FeatureId;   // 機能を有効にするコードの機能の名前（0110）。無ければ全員に出す
    samples: readonly DemoHousehold[];   // 並び順どおり
  }
  ```

  - `DemoHousehold` は `sampleNo` を外し、`family`・`age`・`rev`（中身の版。整数）を足す。ほかの欄（`id`＝モデル世帯の名前・`title`・`traits`・`steps`・`firstProposal`・`plans`・`snapshots`・`extValues` など）は今のまま。
  - セットの ID は「作成者.名前」（0004 の点区切り・英小文字で始まる英数字）。作成者 `official` は提供元だけ（0011 の4・0114 の3 と同じ予約）。
  - 見本の ID（`origin.id`）はセットの中で重ならない。アプリに入っているセットではモデル世帯の名前（`data/modelHouseholds/<id>.json`）。
- **アプリに入っているセット**: `official.basic`（ファイナンシアの見本。12件。9）と `official.corporateOwner`（法人経営者の見本。`feature: "combinedBs"`。当面1件。7）。
- 棚に出さないモデル世帯（計算の確かめ用）で、目盛り・最初の提案をテストや開発用の入口（`#household=`）が使う物は、セットに入れずに別の並び（`OFF_SHELF_DEMOS`）に残す。`demoHousehold(id)` は両方から探す。
- **後の段（入口だけ）**: セットをファイルで配って読み込む形は、0114 の段2（別に配る束の読み込み）と同じ入口にする。束のマニフェストに種類「見本のセット」を足し、セットの定義（上の形の JSON）とモデル世帯のファイルを束に入れる。提供元の署名（0114 の8 の `signature.json`）のある束だけが作成者 `official` と `feature` を名乗れる。読み込んだセットも一覧の欄の `origin.set`・`origin.id`・`rev` で同じに扱える（この記録の保存の形は、セットがどこから来たかに頼らない）。読み込みの画面・承認・置き場所は段2 で決める。

### 4. 「見るだけの開き方」をやめる

- どの見本も、開いたらふつうの世帯と同じに直せて、自動で保存する。
- 無くす物: 「この見本を直す」のボタン、見本を開いたときに自動保存を止める扱い（`sampleMode` の `view`／`edit`、`sampleNotSaving`）、入力のパネルの「見本のため保存しません」の知らせ（`panelSavedToast` の見本の分け）、帯の「動かしても見本は変わりません（閉じれば元どおり…）」。
- 自分で作った見本（保存した世帯）は、顧客の世帯と同じ道で開く（ほかのメンバーが開いているときの扱い・閲覧だけの役割も同じ）。
- 見本は今までどおり顧客の一覧に出さない・顧客番号を持たない・AI への共有（世帯を渡す）の対象にしない。
- **知らせ**（利用者の判断）: この変更の前の版を使っていた人に、更新の後に1回だけ、世帯の一覧の見本の所に「見本は直せるようになりました。元に戻すときは『最初の状態に戻す』」と出す（閉じたら次からは出さない）。はじめて使う人には出さない（前の「動かしても見本は変わりません」を知らないため）。前の版を使っていたかの見分け方は、作るときに決める。帯の「手直しは自動で保存します」（2）は、知らせを閉じた後も出す。

### 5. ファイナンシアの見本・配られたセットの見本を直せるようにする（最初に変えたときに、保存の場所へ写しを作る）

- **開く**: 一覧の行を開くとき、その見本を直した版（同じ棚に `origin.set`・`origin.id` が同じ見本）があればそれを開く。無ければ、今までどおりアプリの中の見本（モデル世帯＋目盛り・プラン・控え・拡張の値）を保存しない世帯として開く。
- **最初に変えたとき**（自動保存が保存する中身〔世帯・プラン・帯の並び・表示の設定〕が、開いた直後と変わったとき）に、本体へ「セットの見本を直した版を作る」を頼む（`store_create` に `sample: { name, traits, family, age, origin }`）。作れたら、その場で保存した世帯に切り替わり、以後は自動保存。画面は離れない・元に戻す（↶）の履歴は続ける。
  - 作れないとき（保存の準備ができていない・復元が要る・共有フォルダが見つからない・閲覧だけの役割・事務所データが新しい版）は、理由の知らせを出し、保存していない世帯のまま続ける。離れるときは、保存していない新しい世帯と同じ確かめ（0096）を出す。
  - 作る前に、本体は同じ `origin` の見本が棚に無いかを確かめる（共有では一覧を読み直してから）。あれば `E_STORE_SAMPLE_EXISTS` を返し、画面は「ほかの人が先に直した版があります」と知らせて、その版を開くか、今の中身を「複製する」で自分の見本にするかを選ばせる（今の変更は黙って捨てない）。
- **開発用の入口**（`#household=<id>`・自己点検・`#seed`）で開いた見本は、今までどおり保存しない（写しを作らない）。画面の確かめとテストの結果が、前に動かした中身に左右されないようにする。
- **直した版の中身**: 見本を開いたときの中身（メモの例の文・プラン・控え・拡張の値を含む）に、FP の変更を足した物。ふつうの世帯ファイルとして、暗号化・直前の世代・毎日のバックアップ・復元キー・事務所の共有にそのまま載る。直していない見本はファイルを作らない（鍵も作らない・バックアップにも入らない）。
- **事務所の共有・同期フォルダ**: 直した版は棚に1つ（事務所の全員に同じ直した版が出る。今の「見本の棚は事務所で1つ」と同じ。だれでも「最初の状態に戻す」ができる。利用者の判断。人ごとに持ちたいときは「複製する」で自分の見本を作る）。同期が遅れて同じ `origin` の版が2つできたときは、どちらも消さない: 作った日時が早い方（同じなら内部ID の小さい方）をその見本の直した版として出し、もう一方は「自分で作った見本」の所に「（名前）（別の版）」と出す（表示だけの決まり。一覧の欄は書き換えない。開く・複製する・完全削除はできる）。
- **アプリの更新で見本の中身が新しくなったとき**: 直していない見本は、アプリの中の新しい中身がそのまま開く。直した版は変わらない。直した版の `origin.rev` がセットの定義の `rev` より古いときは、行に「元の見本が新しくなっています（最初の状態に戻すと新しい中身になります）」と出す。
- **セットの定義から見本が無くなったとき**（後の版で顔ぶれを入れ替えた・セットごと無くなった）: 直した版は消さず、「自分で作った見本」として出す（名前はそのまま。重なれば「（前の版）」を付ける。表示だけの決まり）。最初の状態はもう無いので、「今の状態を最初の状態にする」を選ぶまで「最初の状態に戻す」は出さない。
- **コードで出すセットを出さなくなったとき**（7）: 直した版は出さない。消さない（7 で決める）。
- **顧客を作る・複製する**: 直した版から「この見本をもとに顧客を作る」「複製する」は、今の中身（直した後）で作る。直していない見本からは、今までどおりアプリの中の見本から作る。セットの見本から顧客を作るときにメモ（例の文）と面談の履歴を写さない決まり（0182 の追記）は、直した版でも同じ。

### 6. 「最初の状態に戻す」

- **セットの見本を直した版**（`origin` あり）: 最初の状態は、アプリの中の今の見本。戻すときは**直した版を消す**（完全削除と同じ消し方: 世帯ファイル・直前の世代・バックアップの写し・鍵。削除の記録を残す。利用者の判断。戻す前の中身を自動で別の見本に残す案は採らない）。次に開くと、アプリの中の見本（更新で新しくなっていれば新しい中身）が開く。
  - 確かめの画面を1回出す: 「この見本を最初の状態に戻します。直した中身（プラン・控え・面談の履歴・メモ・読み取った書類）は消えます。取り消せません。残したいときは、先に「複製する」で自分の見本にしてください。」。名前を打つ確かめは付けない（完全削除ではなく、見本は残るため）。
  - `changed` は、直した版があるあいだ true（直した版がある＝最初の状態から変わっている）。
- **自分で作った見本**: 最初の状態は、登録（「見本に登録」）・複製・見本として新しく作ったときの中身。世帯ファイルの本文の新しい任意の区画 `sampleInitial` に持つ（形式 0.87）。

  ```json
  "sampleInitial": {
    "at": "2026-12-01T10:00:00+09:00",
    "appVersion": "0.9.0",
    "formatVersion": "0.87",
    "sections": { "household": {}, "proposals": [], "workspace": {}, "display": {}, "ext": {}, "extDefinitions": {}, "snapshots": [] }
  }
  ```

## 理由

- **番号を持たない**: 番号は「並べる」「出どころを表す」「取り違えを防ぐ（完全削除の確かめ）」の3つを兼ねていた。並びはセットの定義の順、出どころは `origin`、取り違えを防ぐのは名前（重ならない）で、それぞれ別に持てる。番号の形から見本かどうかを推し量る作り直しは、顧客の世帯を見本に化けさせうるので、世帯ファイルに `meta.sample` を持って推し量りをやめる。
- **家族の形・年代を欄で持つ**: 番号から読んでいた絞り込みを、番号なしで続けるため。直せるようにもなる。
- **最初に変えたときに写しを作る**: 直していない見本はファイルも鍵も作らないので、はじめて使う人の保存の場所・バックアップ・事務所の共有フォルダに、使っていない見本が並ばない。アプリの更新で見本が新しくなったとき、直していない見本が自動で新しくなる（利用者の判断で求められた動き）。直した版はふつうの世帯ファイルなので、暗号化・バックアップ・復元キー・共有の仕組みを新しく作らずに済む。
- **セットの見本の「戻す」は直した版を消す**: 「直した版がある＝変わっている」「無い＝アプリの中の今の見本」の2つの状態だけになり、「直した版はあるが最初と同じ」という3つ目の状態（更新で新しくするかを別に見分ける必要がある）を作らない。
- **自分で作った見本の最初の状態は、世帯ファイルの中の区画に持つ**: 世帯ファイル1つで自己完結する（0011 の3）。別のファイルにすると、差し替えの保存・バックアップ・完全削除・事務所の共有・鍵の付け替えのそれぞれに、もう1つのファイルの扱いを足すことになり、完全削除で消し残す危なさが出る。大きさは自分で作った見本だけ2倍ほど（0.86 の見本ファイルの本文は約 280KB、うち世帯が約 58KB・控えが約 50KB。暗号化・復号は 1MB で約8ミリ秒〔0011 の試作〕）。
- **本体が `sampleInitial` を持ち越す**: 画面は本文を組み立て直して保存する。画面が知らない区画は落ちるので、本体の側で持ち越す。
- **コードは合算BS と同じ**: 見本のセットと合算BS は同じ相手（会社を顧問先に持つ FP）に一緒に出す物で、別のコードにすると発行・期限・止める手順が2つになる。
- **0197 の扱いを外す**: 「保存しないで開いている」ことを条件にしていたので、見本を保存できるようにすると守れない。合算BS の見せどころの見本をコードで出すセットへ移せば、条件は 0110 だけになる。

## 代案（採らなかったもの）

- **番号を残し、アプリの見本の範囲を広げる（01〜49 など）**: セットが増えるたびに範囲を決め直すことになり、02 の次が 50 になるだけ。採らない。
- **はじめから保存の場所に全部の見本を置く**: 使わない見本の世帯ファイルと鍵が、はじめて使う人の保存の場所・毎日のバックアップ・共有フォルダに並ぶ。アプリの更新のたびに「直していないか」を比較して入れ替える仕組みが要る。事務所の共有では、どの PC が置くか・2台が同時に置いたときの重なりの扱いが要る。採らない。
- **差分だけ持つ**: アプリの更新で元の見本が変わると、差分の意味が変わる（消えた物への差分・ID の変わった物）。ふつうの世帯と別の保存の道になる。採らない。
- **セットの見本の「戻す」を、直した版の本文をアプリの見本で上書きする形にする**: 直前の世代が残る利点はあるが、「直した版はあるが最初と同じ」の状態ができ、更新で新しくするかの見分けが別に要る。採らない（残したいときは先に複製する、を確かめの画面に書く）。
- **最初の状態に控え（0009）を使う**: 控えは計算の要求・プラン・万一の前提の写しで、メモ・面談の履歴・拡張の値（会社の数字）・表示の設定・帯の並び・ほかの控えを持たない。控えの一覧と「前回と比較」にも出てしまう。控えは作った後に変えない決まりなので「今の状態を最初の状態にする」とも合わない。採らない。
- **最初の状態を別のファイルに持つ**: 上の理由（消し残し・共有・鍵の付け替え）。採らない。
- **直前の世代（`.prev`）・毎日のバックアップを最初の状態に使う**: 直前の世代は保存のたびに入れ替わり、バックアップは30世代で消える。採らない。
- **法人経営者の見本に新しいコードを作る**: 上の理由。採らない。
- **コードを持たない人にも、見本でだけ合算BS を見せ続ける（保存しない開き方を見本にだけ残す）**: どの見本も直せる・コードで守る機能は見本でもコードの条件で出す、という利用者の判断に反する。採らない。
- 利用者の判断で選ばなかった案は、下の「利用者の判断」の節に書く。

## 影響

- 世帯ファイルの形式 0.87（任意の欄と区画を足すだけ）。事務所データ 0.3、共有フォルダの形式 0.2。画面・本体の命令・開発用のサーバーの代わり・AI接続口の答え・手引き・多くのテストが変わる。
- 見本を動かすと保存されるようになる。面談やセミナーで見本を動かした後は、次に開くと動かした後のまま（戻すのは「最初の状態に戻す」）。保存していないプランの変更（つまみを動かしただけ）は、今までどおり保存しない。
- コードを持たない人は、見本で合算BS を見られなくなる。提案書の章の「（見本）」の印は無くなる。
- 計算エンジン・制度データ・顧客の世帯の番号の決まり（0033 の1・2 の前半）は変わらない。
- 後から変えると: `sample` の欄と `meta.sample`・`sampleInitial` は β公開の後は形式の移行（一方向の変換）が要る。セットの ID と見本の ID を変えると、直した版が元の見本とつながらなくなる（「自分で作った見本」として出る）。
