- 固定の強さ: 世帯のデータの欄（`accounts[].property` の任意の欄 `acquisition.parts`・`acquisition.equipmentLife`・`acquisition.costs`・`acquisition.equity`・`rental.commonFee`・`rental.parking`・`rental.otherMonthly`・`rental.keyMoney`・`expenses.items`（費目の名前の一覧）・`repairs`・`lodging` の名前と値の一覧）と、それぞれの計算での読み方（3〜8）は骨格。欄の並び・標準と詳細の分け方・文言・知らせの文は後から変えてよい（変えたら追記に書く）
- 前提にする記録: 0002（金額・率・丸め）、0006（約束の版と改訂）、0008（負債の型）、0011（世帯ファイルの形式と一方向の移行）、0015（AIに渡す縮約版）、0028（住まい以外の不動産の中身）、0035（足すだけの形の版上げ・並びの要素の ID）、0040（段階と例外の年）、0064（計算の知らせ）、0077・0078（標準／詳細・説明は「?」の中）、0079（入力項目「収益不動産」）

## 背景

- 0079 で収益不動産を独立した入力項目にし、物件を見分ける欄と一覧表を足した。不動産を専門とする FP が物件を整理・分析できるようにする段階の2つ目として、お金の欄（取得の内訳・家賃以外の収入・経費の費目・大きな修繕・ローン・民泊・宿）を足す。
- 後の段階で、売ったときの税（取得費）・利回り（実質利回り・自己資金に対する手残り）を出す。そのための値（取得時の諸費用・自己資金）も、ここで持つ。

## 決定

### 1. 入れ方（標準と詳細）

| まとまり | 欄 | 標準／詳細 |

| 土地と建物 | 取得価額の内訳（土地・建物・建物附属設備）、建物附属設備の耐用年数（建物附属設備を入れたとき）、取得時の諸費用・自己資金（取得価額を入れたとき） | 詳細 |
| 家賃収入 | 共益費（月額）・駐車場の収入（月額）・その他の月の収入、礼金・更新料（年あたりの見込み） | 詳細 |
| 経費 | 年額（合計）・家賃に対する割合 | 標準（今のまま） |
| 経費 | 費目（建物管理費・修繕積立金／固定資産税・都市計画税／損害保険（火災・地震）／地代（権利が借地権のとき）／共用部の光熱費・清掃・設備点検／入居者募集の費用・原状回復／税理士の報酬・その他） | 詳細 |

| 民泊・宿（種類が民泊・宿のとき） | 営業の形・売上の入れ方・1泊の単価・稼働率・営業日数（か月の売上の見込み）、運営代行の手数料・仲介サイトの手数料 | 標準 |

- 説明は欄の「?」の中に入れる。画面に出すのは欄の名前・値・印・操作の名前と、計算の知らせ（0064）だけ。

### 2. 世帯のデータ（`accounts[].property` の任意の欄）

- `acquisition.parts`（`land`・`building`・`equipment`。円）・`acquisition.equipmentLife`（2〜50年）・`acquisition.costs`（円）・`acquisition.equity`（円）
- `rental.commonFee`・`rental.parking`・`rental.otherMonthly`（月額。円）・`rental.keyMoney`（年あたり。円）
- `expenses.items`（年額。円）: `management`・`propertyTax`・`insurance`・`groundRent`・`facility`・`leasing`・`cleaning`・`supplies`・`utilities`・`other`
- `repairs`: `{ id, at（時点）, amount（円）, label?（40字まで） }` の並び（要素は ID を持つ。0035 の5）
- `lodging`: `business`（`privateLodging` 住宅宿泊事業・`inn` 旅館業〔簡易宿所など〕・`specialZone` 特区民泊）・`salesBy`（`night`・`month`。省略は `month`）・`nightly`（円）・`occupancy`（率）・`days`（1〜366）・`platformRate`（率）
- 金額は値の箱にしない（推定の値を持たない、FP が入れるだけの欄。`acquisition.price` と同じ）。

### 3. 取得（減価償却）

- **取得価額の内訳を入れたら、土地の割合より優先して取得価額を分ける**（減価償却の基と、土地の取得のための借入の利息の分け方）。画面では取得価額（合計）を内訳の合計にし、内訳がある間は取得価額の欄を書き換えさせない（内訳を全部消すと、最後の合計のまま書き換えられる欄に戻る）。
- 評価額の土地の割合は、入れた土地の割合 → 内訳の土地の割合 → 前提 → 目安の順（内訳を入れたら、目安を使った知らせは出ない）。入れた土地の割合は評価額（時価）を分けるだけに使う。
- **建物附属設備**は建物とは別に、定額法で減価償却する。耐用年数は省略で法定の15年（給排水・電気・ガスの設備など）。中古は建物と同じ経過年数で簡便法（0028 の4）に直す。耐用年数を入れたら、その年数をそのまま使う（FP が使う年数を入れたとみなし、簡便法を重ねない）。貸し始めから月割り・帳簿の残りが1円になるまでは建物と同じ。
- **取得時の諸費用**は、建物と建物附属設備の分を償却の基に足す。分け方は取得価額の比（内訳があれば内訳の額、無ければ取得価額×(1−土地の割合)。円未満切り捨て）。土地の分は償却しない（売ったときの取得費に入るので、段階3で使う）。土地の取得のための借入の利息の分け方（0028 の4）は、諸費用を足した後の建物と建物附属設備の額で見る。
- **自己資金**は計算に使わない（段階4の自己資金に対する手残りの割合のために持つ）。

### 4. 収入

- **家賃以外の月の収入**（共益費・駐車場・その他）: 家賃と同じ空室を見込む割合を掛け（円未満切り捨て）、家賃と同じ変化率で、家賃と同じ年から動かす。家賃の段階・例外の年は当てない（家賃の額を置き換える入力なので）。家賃に対する割合の経費（管理委託料）は、家賃とこれらの合計に掛ける。
- **礼金・更新料の年あたりの見込み**: 12か月に分けて（端数は最後の月）、貸している月に受け取る。空室の割合は掛けない（入替わり・更新の周期からならした見込みの額なので）。変化率は家賃と同じ。家賃に対する割合の経費は掛けない。
- どれも家賃収入の行 `cf.income.other.rental` に、家賃と合わせて月ごとに出す。

### 5. 経費の費目

- 費目を1つでも入れたら、経費の年額は**費目の合計**にし、年額の欄（`expenses.annual`）は使わない（消さずに残す。費目を全部空にすると年額の欄の値に戻る）。画面では、費目がある間は年額の欄を「費目の合計」の印で見せ、書き換えさせない。
- 年額の段階・例外の年・変化率は、その合計に当てる（割合の段は合計×割合）。
- 地代は権利が借地権のとき、共用部の光熱費など・入居者募集の費用などは民泊・宿でないとき、清掃・リネン・消耗品・光熱費・通信は民泊・宿のときに欄を出す（値が入っていれば、いつでも出す）。計算は、入っている費目を全部足す。

### 6. 大きな修繕の予定

- その月に一時の支出として、不動産の経費の行 `cf.expense.other.realEstate`（計算式ID `asset.realEstate.repair`）に出す。持っている間の分だけ（売った後・持ち始める前は出さない）。
- 不動産所得の上は、**貸している月なら全額をその年の経費**にする。資本的支出として償却する扱いは作らず、知らせ `N_ASSUMED`（`realEstate.repairExpensed`）で「全額をその年の経費として計算しています」と出す。
- 中身（`label`）は表示用で、計算には使わない。

### 7. 物件のローン

- 型は負債（`debts[]`・`debts[].property`。0028）のまま。今まで出していなかった欄（借入先＝負債の名前 `label`、金利の段階、繰上返済、借り換え、団信 `creditLife`）を出した。借り換えは1件ごとに、借り換えの年月・新しい金利（1つの段）・金利の種類・返済期間（月数）・返済の方法・費用・費用を新しいローンに含めるか。金利の段階・繰上返済のまとまりは住まい・ローンのカードと同じ部品（`loanStepGroups`）。
- 団信に入っていれば、万一の想定で名義の人が亡くなった月の返済の後に残高が消え、その後の返済と利息は無くなる（`debt.creditLifeEvents`・`debt.schedule` は負債の種類を見ないので、住宅ローンと同じに働く。テストで確かめた）。消えた後の利息は不動産所得に入らない。

### 8. 民泊・宿

- 種類で民泊・宿を選ぶと、中身に `lodging` を作り（ほかの種類にすると外す）、家賃収入のまとまりを「宿泊の売上」の入れ方にする。計算部品は種類（`kind`）を読まず、`lodging` があるかで決める（0079 の3）。
- 売上: 「月の売上の見込み」（`rental.monthly` に入れる）か、「1泊の単価×稼働率×営業日数（年）÷12」（`salesBy` が `night`。1泊の単価×稼働率を円未満切り捨て、×日数÷12 を円未満切り捨て）。営業日数の省略は、住宅宿泊事業なら180日、ほかは365日。**住宅宿泊事業は営業日数を年180日までに抑え**、超えた値を入れたら欄と知らせ `N_LIMIT_APPLIED`（`realEstate.lodging.days`）で「180日で計算しています」と出す。
- `lodging` があるときは、空室を見込む割合・家賃以外の月の収入・礼金・更新料を使わない（入っていても読まない）。変化率・段階・例外の年・貸し始めと貸し終わりは家賃と同じ。
- 経費: 運営代行の手数料は家賃に対する割合の欄（`expenses.rate`）を「売上に対する割合」として使い、仲介サイトの手数料（`lodging.platformRate`）を足した割合を売上に掛ける。清掃・リネン・消耗品・光熱費・通信は経費の費目（5）。
- 所得の区分（雑所得・事業所得）は段階3で計算する。今は**今までどおり不動産所得として計算**し、知らせ `N_ASSUMED`（`realEstate.lodgingIncome`）を出す。種類の欄の知らせ（0079 の3）も「所得は不動産所得として計算しています…売上が年1,000万円を超えるときの消費税は計算しません」に直した。
- 消費税は扱わない。売上（その物件のその年の受け取り）が1,000万円を超える年があれば、知らせ `N_NOT_SUPPORTED`（`realEstate.consumptionTax`）を出す。

### 9. 物件の一覧表

- 「月の家賃」を「月の収入（空室を見込んだ後）」にした: 家賃×(1−空室の割合) と、家賃以外の月の収入×(1−空室の割合)（それぞれ円未満切り捨て）の合計。民泊・宿は月の売上。礼金・更新料は入れない（年に一度の受け取りをならした額なので、月の収入の比べ方からは外す）。

### 10. 計算部品・世帯ファイル・縮約版

- 計算部品 `asset.realEstate` の改訂を 4 にした（3〜8 の読み方）。約束の版（1.0）と出力の形は変えていない（入力は世帯のデータの任意の欄を足しただけで、部品の入力・出力の欄は同じ。0006 の4）。出力の不動産所得の内訳の `rent`・`expenses`・`depreciation` に、家賃以外の収入・費目・修繕・建物附属設備の償却が入る。
- **新しい欄を入れていない世帯の計算の結果は変わらない**（エンジンのテストで表とお金の動きが同じことを確かめた。見本の世帯の結果も同じ）。自己資金だけを入れても結果は同じ。
- 世帯ファイルの形式の版を `0.32` に上げた（足すだけの MINOR。0011 の5・0035 の1）。`0.31` → `0.32` の変換の段は形式の版だけを書き換える。見本 `crates/household-store/tests/fixtures/household-format/0.32/` は、`0.31` の見本の物件に3〜6 の欄を入れ、民泊・宿の物件を1件足した物。
- AI に渡す縮約版: 入力項目ID は足していない（新しい欄は `account.property` の中で、決まった値か数）。縮約版の許可リストの版は変えない。修繕の中身（`label`）は形の決まっていない文字列なので、縮約版では許可リストにかかわらず外れる（車の維持費の内訳の名前と同じ。入力項目ID を分けていないので、足して渡すこともできない）。持ち帰り用のレポートでも外す（`app/src/workspace/takeaway/sanitize.ts`）。

## 理由

- **内訳を土地の割合より優先する**: 売買契約書に土地・建物（消費税の額から逆算した建物の額）が書いてあれば、それが税の上の取得価額の分け方になる。割合で分けると、内訳を知っている FP の値と食い違う。評価額（時価）の分け方は別の話なので、入れた土地の割合があればそちらを使う。
- **諸費用の建物の分を償却の基に足す**: 不動産所得の計算で、仲介手数料などの取得のための費用は取得価額に含めるのが基本（登録免許税・不動産取得税は必要経費にもできるが、取得価額に含めることも認められる）。1つの合計で持つので、全部を取得価額に含める扱いにそろえた。その年の経費にすると、取得の年だけ大きな損失が出て、損益通算で税が大きく動く（入れ方の違いで結果が振れる）。
- **費目の合計で年額を置き換える（足さない）**: 年額と費目を足すと、同じ経費を二重に数えやすい。費目を入れ始めたら合計を正にし、年額の欄は残しておく（戻せる）。
- **修繕は全額をその年の経費**: 修繕費と資本的支出の区分（金額・周期・中身で決まる）は FP が税理士と決めることが多く、今の入力では分けられない。まず一時の支出として手元のお金の動きを正しく出し、税の上の扱いは知らせで明示する。
- **民泊・宿を種類でなく `lodging` で計算する**: 0079 で種類は計算に使わないと決めた（骨格）。入れ方の欄を種類に合わせて作り外すことで、種類と計算の食い違いを画面の側で防ぐ。
- **ローンは負債の型のまま**: 返済の計算（金利の段階・繰上返済・借り換え・団信）はもう全部あり、画面に出すだけで済む。

## 代案（採らなかったもの）

- 取得時の諸費用をその年の経費にする: 上の理由。段階3で分けて持つ必要が出たら、`costs` の内訳を足す。
- 共益費などに空室の割合とは別の割合を持つ: 駐車場だけ空きが多い物件もあるが、物件ごとに1つの割合で十分という判断（分けたくなったら任意の欄で足せる）。
- 大きな修繕を「出るお金の行」（`realEstateCost`。0079 の1）にまとめる: 出るお金の行は物件を指さず、不動産所得の経費にならない。物件の中に持つ。
- 大きな修繕に新しい行（`cf.expense.lumpSum.*`）を作る: 物件ごとの経費の数字（提案書の収益不動産のまとめ・不動産の経費の行）が修繕を数えなくなる。同じ不動産の経費の行に、別の計算式ID で出す。
- 民泊・宿の売上の新しい行: 家賃収入の行（不動産の賃料）にまとめる。所得の区分を分ける段階3で見直す。
