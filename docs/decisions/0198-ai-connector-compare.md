# 0198. AI接続口に、1回で何通りも計算して並べる「比べる道具」（compare）を足す

- 状態: 採用（一部未確定）（2026-11-11）
- 固定の強さ: 道具の名前と入出力（`compare` の引数と答えの `results`・`keyFigures`・`diff`・`series`・`members`・`planChanges`・`reason`）は試験版（0015 と同じ。予告して変えることがある）。作り（calculate と同じ道を通す・同時に計算する数・同じ世帯は1回だけ読む）は内部
- 前提にする記録: 0005（計算の実行環境）、0014（AIに渡した記録）、0015（AI接続口）、0184（計算の前の処理）、0194（主な数字）、0195（プランの動かす項目）

## 背景

- FP が AI に頼みたいことのうち、「共働き子なしと会社員の夫婦子2人を比べて」「物価 0%・1%・2% を並べて」「対策を3つ並べて」「2人のお客さまの世帯を比べて」は、`calculate` を通りの数だけ呼ぶとできた。ただ、呼ぶ回数が多く、答えが通りごとに積み上がり、基本との差や「資産が尽きる年」の違いを AI が自分で数えていた（数え方が画面の「プランを比べる」とずれるおそれ）。
- 0194 で主な数字（`keyFigures`）を、0195 で画面と同じ「動かす項目」（`plan_changes`）を入れたので、その上に、1回で何通りも計算して並べる道具を置ける。

## 決定

### 1. 道具 `compare`（単体の群。`share_id` のときは世帯を扱う群）

- 基本: 世帯は `calculate` と同じく見本の世帯（`sample_household_id`）・FPが渡した世帯（`share_id`）・AIが組み立てた入力（`input`）のどれか1つ。基本に当てる `changes`・`plan_changes`・`stress_test` も書ける。名前は `label`（既定「基本」）。
- 通り（`variants`）: 基本のほかに8通りまで。通りごとに `label`・世帯（書かなくてよい）・`changes`・`plan_changes`・`stress_test`。
  - 世帯を書かない通りは**基本に重ねる**: 基本の世帯に、基本の `changes` の後に通りの `changes`、基本の `plan_changes` の後に通りの `plan_changes` をつないで当てる（同じ項目は後の値が勝つ。画面で2つのつまみを動かしたプランと同じ）。`stress_test` は通りに書けば通りの物、書かなければ基本の物。`calculate` に、つないだ変更を渡したときと同じ答えになる。
  - 世帯（`sample_household_id`・`share_id`・`input`）を書いた通りは、その世帯に通りの変更だけを当てる（別の見本の世帯・別の渡された世帯どうしも並べられる）。
- 系列の選び方: `series`（年ごとに返す数字。既定 `["financialAssets"]`。`calculate` の `fields` と同じ7つ）・`every_years`（既定5）・`from_year`・`to_year`・`at_ages`（主な数字の年齢。既定95歳）・`ages`（false なら系列に家族の年齢を付けない）。
- 答え: `results` の1つ目が基本、2つ目からが通り。通りごとに `key`（base・v1…）・`label`・`from`（`sampleHouseholdId`・`shareId`・`input`、基本に重ねた通りは `onBase`）・`status`・`keyFigures`（`calculate` と同じ）・`diff`（基本との差。この通り − 基本の円。資産が尽きる年は画面の比較の表と同じ文「尽きなくなる」「+22年」など）・`series`（年・家族の年齢・選んだ数字）・`members`（年齢の鍵と呼び方）・`planChanges`（当てた変更の名前・前・後・当てたか）・`preparation`（計算の前の処理の印。世帯の物は数だけ）。ほかに `note`（読み方）・`computed`（計算した通りの数）。
- 系列の年は、主な数字と同じく画面の表に出す年から（計算基準月が年の途中なら、計算の最初の年は表に出ないので系列にも入れない）。最初の年と最後の年はいつも入る。

### 2. 通りごとの理由（ほかの通りは計算する）

- 形の違う通り（知らない欄・型の違い）・世帯を2つ以上書いた通り・当てはまらないプランの変更（範囲の外・知らない対象。変更ごとの当てはめも返す）・無い見本の世帯・読めない共有（取り消し・期限切れ・同意なし）・計算できない入力（0196 の直し方つき）・9通り目から後は、その通りの `status` を `error` にし、`reason` に理由と直し方を書いて、ほかの通りは計算する。
- 基本の世帯を読めないときは、基本に重ねる通りも計算しない（別の世帯の通りは計算する）。1通りも計算できなければ道具の答えを失敗にする（中身は同じ形）。
- 通りが1つも無い・選べない `series`・範囲の外の `every_years`・`at_ages` は、呼び出し全体の誤りとして返す。

### 3. 作り

- 1通りの計算は `calculate` と同じ関数（`server.rs` の `compute`: プランの変更 → 計算の前の処理 → 計算 → 主な数字と年齢）を通す。`calculate` もこの関数を使うように直した（答えは変えない）。差の数え方以外の数え方は接続口に書かない。
- 渡された世帯は `calculate` と同じく `base_input`（アプリ本体の `GetShare`。同意・期限・縮約・包み方・記録はアプリ本体だけ）で読み、読んだ道具の名前 `compare` で「AIに渡した記録」に残る。1回の呼び出しで同じ世帯（同じ共有 ID・同じ見本）は1回だけ読む（記録も1回）。
- 通りごとに新しい固めた実行環境で、同時に4つまで計算する（1つ 128MB まで）。

### 4. 測った数字（見本の世帯 `salariedCoupleTwoKids`、リリースのビルド、10コアの手元の機械。2回目以降）

| 呼び方 | 時間 | 答えの大きさ |
|---|---|---|
| `calculate`（主な数字だけ） | 0.24 秒 | 0.4KB |
| 基本＋1通り（プランの変更） | 0.34 秒 | 4.1KB |
| 基本＋3通り（プランの変更） | 0.39 秒 | 7.6KB |
| 基本＋8通り（働く最後の年齢を60〜67歳） | 1.0 秒 | 16.2KB |
| 基本＋8通り（別の見本の世帯） | 0.39 秒 | 10.4KB |

- プランの変更を当てる通りは、画面の部品の JS（0195 の `plan.js`）を通りごとに読み込むので、1通り約 0.1 秒増える。上限の8通りでも約1秒（見込みの約2秒の内）。
- 答えは1通り約 1.5KB（5年ごとの金融資産と家族の年齢）。`ages: false` で約 0.7KB 小さくなる。同じことを `calculate` で年ごとの合計を取って並べると、1通り約 13KB。

### 5. テスト

- 画面の側（`app/test/connector-compare.test.ts`）: 画面で見本の世帯を開き、結果のタブのつまみを動かしたプラン（`applyValues`）を比較の表（`compareTable`・`metricsOf`）に現状と並べたときの主な数字・資産が尽きる年の差の文・画面の表の年の金融資産を、3つの見本の問い（対策を3つ並べる・基本に重ねる・物価上昇率を振る）と見本の世帯4つで見本（`crates/lifeplan/tests/fixtures/compare/expected.json`）に書く（`LIFEPLAN_UPDATE_FIXTURES=1` で作り直す）。
- 接続口の側（`crates/lifeplan/tests/mcp_connector.rs`）:
  - `compare_matches_the_screen`: 本物の接続口に MCP で `compare` を呼び、通りごとの主な数字・系列（毎年）・資産が尽きる年の差の文が見本と同じこと、基本に重ねる通りが `calculate` につないだ変更を渡したときと同じこと、見本の世帯どうしの系列が5年ごと・最初と最後の年つき・年齢つきであること、通りごとの理由（形の違い・範囲の外・無い見本・世帯を2つ）とほかの通りが計算されること、9通り目の理由、答えの大きさ、引数の誤り。道具の入力の形の見本（`fixtures/tools/compare.input-schema.json`）。
  - `compare_shared_households`: 渡された世帯2つと見本の世帯を並べ、縮約版でも見本の世帯と同じ数字、共有の仮の ID の `plan_changes` が当たること、人が書いた文・メモ・元の ID・顧客番号が答えに出ないこと、読んだことが世帯ごとに `compare` で1回ずつ記録に残ること、取り消した共有の通りだけ `REVOKED` の理由になること、基本の共有を取り消すと基本に重ねる通りも計算しないこと。
  - `compare.rs` の単体のテスト（差の文・差の数え方・通りの形）。

## 理由

- 1通りの計算を `calculate` と同じ関数にすれば、比べる道具の数字は `calculate`・画面の「プランを比べる」とずれない（計算の前の処理・プランの当て方・主な数字の数え方を二重に持たない）。
- 基本に重ねる書き方なら、「この世帯で対策を3つ」を、基本の世帯を1回書くだけで頼める。別の世帯の通りも同じ形で書けるので、見本どうし・渡された世帯どうしも1つの道具で並べられる。
- 通りごとに理由を返せば、AI は直す通りだけを呼び直せる（1つの誤りで全部をやり直さない）。

## 代案（採らなかったもの）

- **比べる道具の答えを `calculate` の答えの並びにする**: 1通り約 13KB 積み上がり、比べるのに要らない物（知らせ・制度データの版・毎年の数字）が多い。
- **差を画面の比較の表の文（「+123万円」）で返す**: AI が数として扱いにくい。差は円の数で返し、資産が尽きる年だけ画面と同じ文にした（年の差・尽きなくなる・尽きるようになるを1つで表せるため）。
- **エンジンのまとめて計算（`runBatch`）で通りを1度に計算する**: 計算の前の処理・プランの当て方・主な数字は通りごとに要り、実行環境を分けた方が1つの通りの誤りが他に響かない。
- **上限を超えた呼び出し全体を断る**: 頼まれた通りのうち8通りは計算できるので、超えた分だけ理由を返す。
