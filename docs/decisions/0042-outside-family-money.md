# 0042. 世帯の外の家族のお金（簡易の家計。介護の費用はまず本人のお金から）

- 状態: 採用（一部未確定）（2026-10-26）
- 固定の強さ: β公開から変えない（骨格）。エンジンの入力の形（構成員の `wallet` と欄 `balance`・`living`・`pension`・`lumpSums[].id`・`at`・`amount`、入力項目ID `member.wallet`）、預金を入れたときだけ計算すること（欄が空なら今と同じ）、介護の費用はまず本人のお金から払い尽きた月から世帯が払うこと、家計を1つにする期間との関係（4）、尽きる見込みの月を要約 `outsideWallets` に出すことは骨格。尽きる月の文言・できごとの印・画面の欄の置き場所は後から変えてよい（変えたら追記に書く）

## 背景

- 親・祖父母は世帯の外の家族になり（0035 の4 と追記）、親の年金は世帯の収入に入らなくなった。ところが親の介護の費用は今も世帯が全部払う形なので、親の介護がある世帯の結果が厳しく出る（見本の世帯 `parentCare` は2040年末の金融資産が 1,439万円 → 175万円）。実際には、親の介護の費用の多くは親の年金と預金で払い、足りなくなってから子の世帯が払う。
- 正式公開では、親のお金を詳しく見る形（世帯からの仕送り・立て替え、親が世帯に払う援助、家を担保に借りる、保険料の目安、年ごとの残高の表、万一の想定ごとの計算し直し）を作る。β には、その芯になる**簡単な形**を前倒しで入れる。
- 前提にする記録: 0003（時点の型）、0008（世帯のデータモデル・値の箱）、0035（世帯ファイルの形式。足すだけの形は MINOR）、0036（プランの差分の当て先）、0041（値の状態・未入力）。

## 決定

### 1. 入力の形（エンジンの入力。任意の欄）

- 構成員（`members[]`）に `wallet`（入力項目ID `member.wallet`）を足す。世帯の外の家族（`outside` を持つ人）で、生年月のある人だけ持てる（スキーマで止める）。

```json
"wallet": {
  "balance": {"value": 5000000, "state": "confirmed", "origin": {"kind": "manual"}},
  "living": {"value": 100000, "state": "confirmed", "origin": {"kind": "manual"}},
  "pension": {"value": 900000, "state": "confirmed", "origin": {"kind": "manual"}},
  "lumpSums": [{"id": "<入金>", "at": {"at": "2029-04"}, "amount": {"value": 3000000, "state": "confirmed", "origin": {"kind": "manual"}}}]
}
```

| 欄 | 意味 | 空のとき |
|---|---|---|
| `balance` | 預金など（計算基準月の初めの残高。値の箱） | **この人のお金を計算しない**（介護の費用は今までどおり世帯が払う） |
| `living` | この人の生活費（月額。計算基準年の価格。値の箱）。物価上昇率で伸ばす | 0円（画面は未入力の警告） |
| `pension` | この人の公的年金（年額・額面。値の箱）。入れると、エンジンの推計の公的年金（`cf.income.pension` の下の行）の代わりに、計算基準月から毎月12分の1を入れる（計算基準年の額のまま） | エンジンの推計（年金の記録・働き方の期間から。0035 の4 の「その人のお金の見通し」） |
| `lumpSums` | 一時の入金（家を売る・保険金など）。要素は ID・時点の型・額（値の箱） | 無い |

- 新しく足す円の値なので、どの額も値の箱で持つ（0035 の3）。値の状態は箱の中にあり、`valueStates` には書かない。
- 並びの要素（一時の入金）は ID を持つ（0035 の5）。プランの差分は向き先 `{"member": <人>}`・`member.wallet`・場所（`["balance"]`、`["lumpSums", <入金>, "amount"]` など）で当てる（0036 の2）。

### 2. 計算（部品 `outside.wallet`）

- お金を入れた人（預金の欄がある人。sdk の `hasWallet`）ごとに、計算基準月から月ごとに残高を積む:

  残高 ＝ 前の月の残高 ＋ その人のお金の動き（年金・給付などの収入 − その人の税・社会保険料。`plan.memberFlows`。年金を入れたときは推計の公的年金の代わりに入れた額）＋ 一時の入金 − 生活費 − その人が介護を受ける費用

- **その人が介護を受ける費用**（`careExpenses` で `member` がその人の物の、`care.expense` のお金の動き）は、まずこの残高から払う。払いきれない分は世帯が払う（`plan.flows` が、払えた分を介護の費用から引き、残りだけを世帯の支出にする）。払う人の欄 `care.payer` は、世帯が払う分をどの人の行に載せるか（と万一のときの扱い）として今のまま読む。
- **尽きる月**: その月の入るお金を足した残高で、その月の生活費・税・社会保険料・介護の費用を払いきれない最初の月。その月の払いきれない介護の費用は世帯が払い、残高は0円にする。その後も入るお金が出るお金より多い月はまた積み、介護の費用の一部を払う。
- 生活費の足りない分（尽きた後も、介護の費用と別に生活費が払えない分）は数えない（世帯からの仕送りの行を作る回に入れる）。
- 税・社会保険料は、エンジンが構成員ごとに出した額（推計の年金から計算した額）をそのまま引く。年金を入れたときも計算し直さない（目安。正しく見るには、その人の年金の記録を入れ、年金の欄は空にする）。
- 計算する期間は、計算基準月から、表の最後の月・亡くなる見込み（`leaves`）の前の月・万一の想定で亡くなる月の、いちばん早い月まで。その後の残高は使わない（受け取る相続とのつなぎは後の回）。
- 万一の想定・ストレステストは、それぞれの計算の中で同じ部品が計算する（想定ごとの差を知らせる形は後の回）。

### 3. 欄が空の世帯

- お金の欄が無い世帯、または預金の欄が空の世帯は、今と同じ（世帯が全部払う）。古い世帯の結果を黙って変えない。生活費だけ入れても計算しない。
- 入力画面で新しく親・祖父母を足したときは、空のお金の欄（`wallet: {}`）を作り、預金・生活費を「未入力」の警告にする（推定は入れない。0041）。預金を入れるまで結果は変わらない。前からある世帯の世帯の外の家族は、「＋ この人のお金を入れる」で欄を出す。

### 4. 家計を1つにする期間との関係（0035 の4）

同じお金を世帯の家計とこの人の家計の両方に入れない、を決まりにする。期間の中の月は、印ごとに次のとおり:

| 月 | その人の年金・給与などと税・社会保険料 | その人の生活費 | その人が介護を受ける費用 | 一時の入金 |
|---|---|---|---|---|
| 期間の外 | この人のお金に入れる | この人のお金から引く | まずこの人のお金から | この人のお金 |
| 生活費の人数に入れる月（`living`） | （収入の印のとおり） | 引かない（世帯の生活費の人数に入る） | （収入の印のとおり） | この人のお金 |
| 収入を世帯に入れる月（`income`） | 世帯に入る（今の決まり）。この人のお金には入れない | （生活費の印のとおり） | 世帯が払う（家計が1つなので今の決まりどおり） | この人のお金 |

- 期間の間も、預金の残高はそのまま持ち越す（世帯の金融資産には入れない）。期間が終われば、残った残高から続ける。

### 5. 結果に出すもの

- エンジンの要約 `summary.outsideWallets`: お金を入れた人ごとの `{member, depleted}`（尽きる見込みの月。尽きなければ `null`）。根の部品 `plan.cashflow` の details から写す（約束の版 1.4）。
- 画面: 結果のできごとに「お母さまのお金が尽きる見込み（2030年12月・90歳。この後の介護の費用は世帯が払います）」を出す（印「親」。キャッシュフロー表のできごとの行・グラフの丸）。家族のカードの説明に、尽きる見込みは結果のできごとに出ることを書く。
- 年ごとの残高の表は出さない（正式公開の詳しい形）。

### 6. 世帯ファイルと登録簿

- 世帯ファイルの形式を **0.19** に上げる（足すだけの MINOR。0035 の1・7）。0.18 → 0.19 の変換の段は版だけを書き換える。0.18 までのアプリは知らない欄を読み落として書き戻すので、版を上げて閲覧だけにする。0.19 の見本（親のお金と、預金を変えるプランの差分を持つ）を足す。
- 入力項目ID `member.wallet` を登録簿に足す（エンジンの入力のスキーマの `x-item`）。AI接続口の縮約版の許可リストに入れ、版を `reduced@11` にした（0015。計算に要る数の項目）。
- 見本の世帯 `parentMoney`（`parentCare` の親にお金を入れたもの）を足した。

### 7. 入力画面（小さな形）

- 家族のカードの、世帯の外の家族のまとまり（詳細）に、「この人の預金など（今の残高）」「この人の生活費（月額）」「この人の年金（年額。空欄は推計）」「一時の入金（時期・額。＋ で足す・外す）」と「この人のお金を外す」を出す。どの欄も当て先（向き先は構成員・`member.wallet`・場所）を持つ。
- 介護・親のカードを組み直す回に作り直す前提の形（区画の置き場所・夫婦で1つのお金にするか・誰が払うかの選択はその回）。

## 理由

- **構成員の欄にする**: 世帯の外の家族の生年月・年金の推計・亡くなる見込み・家計を1つにする期間を、そのまま使える。別の物の集まりにすると指す ID が増える。
- **預金を入れたときだけ計算する**: 古い世帯と、親を足しただけの世帯の結果を黙って変えない。預金が空で年金だけで介護の費用を払うと、生活費が未入力のまま親の年金が全部介護に回り、楽な結果になる誤りが起きやすい。
- **介護の費用だけを世帯に回す**: β で親の介護の結果が厳しすぎる点を直すのが目的。生活費の不足を世帯が払う形は、仕送りの行（相手・向き・万一のときの扱い）と同時に作らないと二重に数える。
- **家計を1つにする期間で印ごとに分ける**: 0035 の4 の「収入は `income` の期間だけ世帯に入れる・生活費の人数は `living` の期間だけ」をそのまま裏返すと、どのお金もどちらか一方の家計にだけ入る。
- **税・社会保険料は計算し直さない**: 入れた年金の額から所得を出し直すには、年金の記録の形（基礎・厚生の別）が要る。簡単な形では目安とし、正しく見る道（年金の記録）を残す。

## 代案（採らなかったもの）

- **介護の費用の払う人を世帯の外の家族にしたときだけ、その人のお金から払う**: 前からの世帯は払う人を世帯の人にしているものが多く、お金を入れても効かない。払う人の選択は介護・親のカードの回に作る。
- **お金の欄を `outside` の中に置く**: 入力項目ID の中に入力項目ID が入る形になり、当て先の決まり（いちばん内側の入力項目ID）を読む所すべてで確かめが要る。構成員の欄 `wallet` にして、`outside` の無い人には持たせないことをスキーマで止める。
- **預金が空でも生活費・年金で計算する**: 未入力の0円で親の年金が全部介護に回り、結果が楽になる。

## 影響

- **エンジン**: スキーマ（`member.wallet`・要約 `outsideWallets`）、部品 `outside.wallet`（新）、`plan.flows`（改訂11。介護の費用から本人のお金で払った分を引く）、`plan.cashflow`（約束の版 1.4・改訂14。details に尽きる見込み）、sdk の `hasWallet`。お金を入れていない世帯の結果は変わらない（見本の世帯の結果は、新しく足した `parentMoney` のほかは同じ）。
- **画面**: 家族のカードの欄、新しく足す親・祖父母に空のお金の欄、結果のできごと。
- **本体**: 形式 0.19 の段と見本。
- **AI接続口**: 縮約版の許可リスト `reduced@11`。
