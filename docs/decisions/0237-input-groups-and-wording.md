# 0237. 入力項目のまとまり（中枠）と言葉をそろえる（車・収益不動産・保険・働き方の中枠、今返しているローンを車の枠の中へ、見出しの名前の繰り返しを外す、足す・外すのボタンの言葉）

- 状態: 採用（一部未確定）（2026-11-21）
- 固定の強さ: 内部（画面の見せ方と言葉）。世帯ファイルの形・保存される値・計算は変えない。欄のキー・欄の名前・事務所の見せ方の id（`textIds.ts` の `fieldTextId`）も変えない。まとまりに足した `where`（入力項目の画面の外で言う名前）と、入力項目の定義の形の選択肢 `StageOptions.bands` は見せ方だけの印。中枠の分け方・見出しの言葉・ローンをどの車の枠に出すかの決まりは後から変えてよい（変えたら追記に書く）。決まりとして残すのは「中枠に分けても、欄のキーと画面の外で言う名前は変えない」「足すボタンは『＋ 名詞』、外すボタンは『外す』」
- 前提にする記録: 0077（説明は「?」の中。2026-10-31 の追記の中枠）、0078（標準の欄と「▸ 続きを見る」・開いたときの知らせ）、0083（入力項目を標準・詳細のどちらで開くか）、0130 の1（入力項目をまたぐ言葉の決まり）と 2026-11-07 の追記（「外す」）、0079（収益不動産の入力項目）、0134（車の入力項目）、0055（保険の入力項目）、0016（事務所のカスタマイズ層）

## 背景

- 欄の多い物（車1台・収益不動産1件・保険の契約1件・働き方の期間1つ）は、1つの枠の中に欄が平らに並び、どこからどこまでが同じ話か分かりにくかった。住宅ローンだけは中枠（左の線＋小見出し）に分けてあった（0077 の追記）。
- 今返している自動車ローンは車の区画の下の別の区画に、収益不動産のローンは物件の欄の後ろに並び、どの車・どの物件のローンかが離れていた。
- 人の区画の中のまとまりの見出しが「ご本人の公的年金」「ご本人の働き方 1」のように、区画の見出しと同じ名前を繰り返していた。
- 足すボタンの言葉が「＋ ○○を足す」「○○を入れる」「＋ ○○」と入力項目ごとに違い、自動の選択肢（「自動: ○○」）や「段」「段階」も混ざっていた。
- 形を先に画面で確かめ、どれを入れるかは利用者の判断（2026-11-20）で決めた。

## 決定

### 1. 物1件を中枠に分ける（道具は `app/src/workspace/input/stages/bands.ts` の `splitBands`）

中枠の形と見た目は 0077 の追記のまま（まとまりに `band: true`、キーは物の頭のまとまりのキー＋`/band/<id>`）。欄とボタンのキー・中身（読み方・書き方）は変えず、まとまりの分け方だけを変える。物の頭のまとまりは、見出しと「外す」（とホームに出すピン）だけにする。

| 物 | 中枠（上から） | いつ |
|---|---|---|
| 車1台（買う車） | 車と買い替え → 価格・買い方 →（今返しているローン。下の2）→ 維持費 → 伸び方・万一のとき → 手放した後 | 標準・詳細とも |
| 車1台（リース） | 契約の内容 → 維持費 → 伸び方・万一のとき | 標準・詳細とも |
| 収益不動産1件 | 物件と評価額 → 土地と建物 → 家賃収入（宿泊なら宿泊の売上）→ 経費 → この物件のローン → 売却・大きな修繕の予定 | 標準・詳細とも |
| 保険の契約1件 | 契約と保障 → 保障の明細 → 保険料 → 解約・解約返戻金（積立金を持つ契約は「積立金・解約」） | **詳細だけ**（下の3） |
| 働き方の期間1つ | 期間と種類 → 収入 → 税・社会保険 → 辞めるとき | 詳細だけ（標準は「今の働き方」の1つのまとまりのまま） |

- **「▸」の単位**: 車は車1台に1つ（頭のまとまり）。中枠の中で欄が入れ替わる所（買い替えの「○歳まで買い替える」など）の知らせ（0078 の追記）は、頭の「▸」を開いたときに今までどおり出す（`FieldViews.tsx` の `swapNotesOf` が、頭の「▸」で開く中枠の欄も見る）。
- **収益不動産は、まとまりごとの「▸」を今のまま残す**（「所在地・持分・メモなどを入れる」「土地の取得価額・取得の年月を入れる」「経費の内訳を入れる」など。1つにまとめる案は採らなかった）。開く文（`moreLabel`）を持つ中枠だけは、自分の「▸」を持つ頭として扱う（`FieldViews.tsx` の `isHead`）。
- 欄もボタンも無い中枠は作らない。中枠の欄が詳細だけなら、中枠も詳細。

### 2. 今返しているローンは、車・物件の枠の中に出す

見せ方だけで、ローンのデータの持ち方（`debts[]`。車との結び付きは持たない）と計算は変えない。ローンの欄のキー（`housing/debt/<id>/…`）も今までのまま。

- **車**（`cars.ts` の `loansByCar`）: 今返している自動車ローンは、ローンの名義（主な借り手）と同じ名義の今の車の枠の中（「価格・買い方」の後・「維持費」の前）に、中枠「今返しているローン（名義）」で出す（同じ車に2本あれば「今返しているローン 1」「2」）。同じ名義の今の車が何台かあれば、出ているローンの少ない車に。同じ名義の車が無くても、今の車が1台だけならその車に出す。
- どの車にも出せないローンだけ、車の区画のすぐ下の区画に残す。見出しは、今の車があるとき「ほかの自動車ローン（名義の合う今の車がありません）」、今の車が無い世帯（ローンだけ先に入っている世帯）は今までの「今返している自動車ローン」。
- 足すボタンは、今の車の枠の中の「＋ 今返しているローン」（標準）。押すと、その車の名義でローンを足す（額・金利・期間の推定は今までの足すボタンと同じ）。今の車が無い世帯は、下の区画の「＋ 自動車ローン」（今までどおりご本人の名義）。
- **収益不動産**: 「この物件のローン」は物件の枠の中の中枠にする（今までも物件ごとに並んでいた。置き場所を「経費」の後・「売却・大きな修繕の予定」の前にそろえた）。

### 3. 保険の中枠は、詳細の画面で開く形だけ

- 標準の画面の契約は欄が少なく、中枠に分けると見出しばかりになるので、今までの形のままにする（利用者の判断）。
- 入力項目の定義を作る `buildStage(id, wh, o)`・`itemStage(wh, id, o)` に形の選択肢 `StageOptions`（`bands?: boolean`）を足した。入力項目の画面（`InputPanel.tsx`）が詳細で開くときだけ `bands: true` を渡す。`bands` で形が変わるのは保険だけ。
- 確かめの一覧・入力の検索・プランの違いの一覧・書類の読み取りは、既定の形（`bands` なし）を読む。まとまりのキーと名前が今までと変わらない。

### 4. 見出しから名前の繰り返しを外し、画面の外では名前を補う（`GroupDef.where`）

- 人の区画の中のまとまりは、見出しに人の名前を付けない（区画の見出しがその人）: 「公的年金」「国民年金の免除・猶予（これまで）」「加入歴 N」「働き方」「今の働き方」「働き方 N」「定年後の予定」「会社とのお金（役員）」「確定申告」。
- まとまりに `where`（入力項目の画面の外で、どこの欄かを言う名前）を足した。見出しを短くしたまとまりと、物の中の中枠は、`where` に今までの名前（「ご本人の公的年金」「車 1（ご本人・今の車）」など）を持つ。
- 画面の外で名前を作る4か所は、どれも `where ?? title` を読む: 確かめの一覧（`checkRows.ts`）、入力の検索（`inputSearch.ts`）、プランの違いの一覧（`plans/planEdit.ts`・`plans/items.ts`）、書類の読み取りの入れ先（`documents/resolve.ts`）。この4か所に出る名前は、今までと同じ。

### 5. 足す・外すのボタンと、選択肢の言葉（0130 の1 の表に足す決まり）

| 種類 | 決まり | 使わない言い方 |
|---|---|---|
| 足すボタン | 「＋ 名詞」（「＋ 物件」「＋ 次の段階」「＋ 塾・習い事」）。名詞だけでは何を足すか分からないときは言葉を足す（「＋ 贈与の相手の孫」「＋ 期間（ご本人の年齢で区切る）」）。夢プランの「＋ 夢」は、見出しのすぐ下にあるので短いままにする（利用者の判断）。向きや中身を動詞で言い分けているボタン（「＋ 養育費を受け取る」「＋ 養育費を払う」「＋ ○○のお金が持つかを見る」など）はそのまま | 「＋ ○○を足す」「○○を入れる」「＋」の無い足すボタン |
| 足すボタンの場所 | 足して増える物の並びの最後（足した物の後ろ） | 並びの前 |
| 外すボタン | 「外す」（0130 の追記のまま）。値を空にする直しも「この額を外す」 | 消す・削除 |
| まだ無いとき | 見出しはそのまま、見出しの下に1行「まだありません」 | 見出しの中の「（まだありません）」 |
| 自動の選択肢 | 「おまかせ（推定: ○○）」「おまかせ（家族から判定）」 | 「自動: ○○」「自動（…）」 |
| 段階 | 金利・生活費・介護・料金などの区切りは「段階」（数えるときも「2段階」） | 段 |

- 人の区画の中の足すボタンにも名前を付けない（「＋ 働き方 2」）。
- 説明・注意の文の中でボタンを指す所も、新しいボタンの言葉に合わせた。入力の検索の言葉（`searchWords.ts`）と標準・詳細の説明（`levelHelp.ts`）も同じ。

## 入れなかったもの

- 収益不動産の「▸」を1つにまとめる案、ライフイベントで「入るお金」を先にする案。
- 介護で段階を足したとき、枠の名前が同じ人の名前で並ぶ所の直し（未確定）。
