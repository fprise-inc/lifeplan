# 0139. ヒアリングの取り込みで今の値を壊さない（お答えの無い欄は今の値のまま・今の方が詳しければ既定で残す・「今 → 届いた値」を並べる）

- 状態: 採用（一部未確定）（2026-11-06。2026-11-09 に決定の9を追記）
- 固定の強さ: 内部（取り込みの候補の作り方・承認したときの入れ方・候補の画面・Web の依頼の一覧の出し方。言葉・欄の名前の表・決まりの細部は後から変えてよい。変えたら追記に書く）。世帯ファイルの形式の版は変えない。0125 の骨格（暗号の形・受け付けの API・届いた答えの中身の形・Excel と同じ受け皿）は変えない。取り込みの部品の候補の欄の記録（`FieldRecord`）に印を2つ足した（`hearing/` の中の型。書き出す形ではない）
- 前提にする記録: 0008（値の箱・推定と仮の印・承認）、0018（ヒアリングシートの取り込み）、0041（値の状態の行）、0052（簡易のシートの残高と返済額から置く住宅ローン）、0059（親の亡くなる見込みの推定）、0125（Web のヒアリング）、0133（働く最後の年齢の推定）、0135（詳細版のヒアリングシート版3 のご両親）、0155（確定申告の仕方）、0035（並びの要素の ID）、0193（Web のヒアリングの通しの点検）

## 背景

- Web のヒアリング（0125）を、値の入った世帯で発行から取り込みまで通して確かめたところ、取り込みで今の世帯の値が壊れた。
  - お客さまが「あとで」にした預貯金（今は 800万円）が、「記入がありません（0円として計算します）」の候補になって初めからチェック済みで、承認すると0円になった。空欄の生活費・答えの無い配偶者の方の生年月（仮の値）・聞いていない住み始めた年月（仮の値）も同じく今の値を上書きする候補になった。
  - 毎月の返済額だけ答え、残高を「わからない」にすると、毎月の返済額から置いた仮の住宅ローン（0052）が、詳しく入れてあった住宅ローン（残高 2,240万円・借入額 3,200万円・2016年4月から）を置きかえた。候補の画面には今の値が出ず、「今の値と違う欄 5」の数だけだった。
  - 取り込みの画面は Excel と同じ（0125 の4）なので、Excel のシートの空欄・範囲の答えでも同じことが起きる。
- あわせて、取り込みの画面と依頼の一覧の小さな迷いが見つかった（Web の答えで毎回出る「記入の年月が計算基準月より後」・候補の画面で項目の名前が縦に1字ずつ崩れる・送った日時が出ない・回答の無いときも「受け取る」が主のボタン・元に戻しても「取り込み済み」のまま）。
- 取り込んだ親に亡くなる見込みが入らない、という指摘もあった（取り込みの部品は `leaves: null` で親を作る）。

## 決定

### 1. お答えの無い欄の印

1. 取り込みの部品（`hearing/src/import.ts`）は、候補の欄の記録に **`noAnswer`** を付ける: その欄の項目に答えが無い（空欄・Web の「あとで」・形の違う値・このシートで聞いていない）のに、目安・仮の値・初めの値で補った欄。「わからない」「該当なし」は答え（付けない）。範囲の答えから読んだ値も答え。
2. ほかの答えから分けた値は答えとして扱う（`noAnswer` を付けない）。今は、年収（賞与を含む）の答えから賞与の目安を分けた賞与の欄だけ（今の賞与を残すと、年収の答えと合計が合わなくなる）。
3. 仮の値の欄（値の箱を持たない欄。0008）には、入力の画面の欄のキー **`uiKey`**（取り込みの結果の `assumed` のキー）を付ける。今の世帯の同じ欄の仮の印と照らすのに使う。

### 2. 今の世帯と照らす（候補の画面。Excel と Web で同じ。`app/src/workspace/hearing/sheet.ts` の `viewOfResult`）

1. 今の世帯にある物（変更の候補）は、欄ごとに「今の値」と「届いた値」を比べる。違う欄が、どれも**お答えの無い欄で今の値を残せる欄**だけなら、候補の種類を **「お答えなし」**（`noAnswer`）にする。候補にせず（チェックの欄を出さない）、候補の画面の下に「お答えがありません（今の値のまま）」として、物と欄と今の値を並べる。承認で選ばれていても入れない。
2. 今の値を残せる欄: 値の箱は確定・推定・該当なし（FP が決めた値）。値の箱が未入力・わからないなら、補った値（目安など）を入れる。値の箱を持たない欄は、入れ物があれば、欄が無い・なし（null）も今の値として残す。
3. 答えた欄とお答えの無い欄が混ざる変更の候補は、そのまま候補にし、承認したときにお答えの無い欄だけ今の値と今の仮の印に戻す（答えた欄だけが変わる）。本人・配偶者・子の性別は、記入が無いと取り込みの初めの値（男性など）が入るだけなので、記入が無ければ今の性別を残す（比べにも使わない）。
4. **今の値の方が詳しい**: 今の値が確定（値の箱は確定の状態、値の箱の無い欄は仮の印が無い）で、届いた値が範囲・推定・仮の値（欄の記録が `estimated`・`unknown`・`assumed`）の欄を「粗い」とする。変更の候補の変わる欄が粗い欄だけなら、**既定でチェックを外し**、「今の値の方が詳しいので残します（届いた〇〇は範囲・推定・仮の値です）。届いた値にするなら、チェックを入れてください」と出す。記入どおりの値でも変わる欄があれば既定で入れ、粗い欄の名前を「今の確定の値が範囲・推定・仮の値に置きかわります」と知らせる。
5. 変更の候補は、項目（お客さまの答え）の下に、変わる欄ごとに **「今 〇〇 → 届いた値 〇〇」** を並べる。お答えの無い欄は「今 〇〇（お答えが無いので今の値のまま）」。欄の名前は入力項目IDと場所の表（無ければ入力項目の名前）、値の言葉は場所から単位を決める（円・か月・時間・人・%・年月。構成員は呼び名、選ぶ答えはシートの選択肢の言葉）。
6. 今の値を残した項目の「記入がありません（0円として計算します）」「空欄のため目安で補いました」「仮の値（…）」の知らせ・面談で確かめることは、残した値と合わないので出さない（同じ項目を、今の値の無い物で補った値のまま使うときは出す）。

### 3. 記入の年月（Web の答え）

- Web の答えの記入の年月は、送った月をページが入れる（0125 の5。お客さまが選んだ年月ではない）。取り込みの部品に `filledOnIsSubmission` を足し、Web の取り込みでは、計算基準月より後でも**差が1年までは知らせない**（計算基準月の時点の額として扱うのは同じ）。1年を超えて離れたときだけ「お答えを送った年月（…）が計算基準月（…）より1年を超えて後です（…計算基準月を確かめてください）」と出す。Excel は今までどおり。

### 4. 候補の画面・依頼の一覧

1. 候補の欄は「項目の名前・答え」の2列と、その下の段（範囲の根拠の長い文・「今 → 届いた値」）にする（長い根拠が横に並ぶと、項目の名前が縦に1字ずつ崩れていた）。
2. お客さまが送った日時（`submittedAt`）を、依頼の一覧の行（受け取った後）と、取り込みの画面の見出しの下に出す（「心当たりのない日時なら、別の方が送ったおそれがあります」。URL を見た別の人が送った場合に気づくため。0125 の影響の「漏れたときの範囲」）。
3. 依頼の一覧のボタン: 回答があると分かるまでは「回答を確かめる」だけを主のボタンにし、「受け取る」は出さない。「回答を確かめる」で回答があると分かったら「受け取る」を主にする。
4. **元に戻したとき**: 依頼の記録は元に戻す・やり直すで戻さない（0125 の4。サーバーの状態と食い違うため）はそのまま。画面の状況は、依頼の記録が「取り込み済み」でも、世帯の取り込みの記録（元に戻すで戻る）にその依頼番号が無ければ **「受け取り済み（取り込みを元に戻しました）」** と出し、「もう一度取り込む」を主のボタンにして「取り込みを元に戻したので、世帯には入っていません（受け取った答えはこの世帯に残っています）」と添える。やり直すと「取り込み済み」に戻る。依頼の記録の状態そのものは書き換えない。

### 5. 取り込んだ親の亡くなる見込み

- 取り込みの部品が作る親は `leaves: null` のままだが、アプリは承認したときに、新しく入る親に、画面で親を足したときと同じ平均余命の推定（仮の印。0059。`care.ts` の `withDeathEstimate`）を入れている（2026-10-27 から）。指摘は取り込みの部品だけを読んだもので、承認の後の世帯には入る。今回は、それを候補の画面で分かるようにした（新しい親の候補に「亡くなる見込みは、平均余命の推定（仮の値）で入れます」、今いる親の候補に「…今の値のままです」）。Web の取り込みでも入ることをテストで確かめる。

### 6. 取り込みの後の推定とご両親の行（0133・0135 と合わせる）

承認の後始末で入れる推定（働く最後の年齢の推定〔0133。`withWorkEndEstimates`〕・新しい親の亡くなる見込みの推定〔0059・0135〕）と、詳細版の版3 のご両親の行も、1〜2 の決まりに従う。

1. **働き方の期間の終わり**: 取り込みの部品は、定年の答えが無い期間にも終わりの欄の記録（場所 `/to`）を付ける。答えが無ければ `noAnswer`（承認しても今の終わりを残す）、「わからない」は答え（状態 `unknown`。今の終わりが確定なら粗い欄）、記入があれば今までどおり年月の欄（`/to/at`）。
2. **働く最後の年齢の推定を入れる人**: 期間の終わりを取り込んだ側の値にした人（新しく足した期間・定年を答えた期間・「わからない」の期間）だけ。今の終わりを残した期間には、終わりが無くても推定を入れない（答えの無い所は今のまま。FP が入力の画面の「働く最後の年齢を推定で入れる」で入れられる）。空の世帯への取り込みは前と同じく推定が入る。
3. **推定の印**: 今の世帯の働く最後の年齢の推定の印（`work/<人>/mainEnd`・`postType`・`retireAge`）は、その人の期間の終わりを取り込んだ側の値にしたときだけ外す（構成員の候補を承認しただけでは外さない。外すと推定の値が確定に見える）。世帯を離れる時期を今のまま残した構成員の印（`family/<人>/leaves`。親の亡くなる見込み・子の独立）も残す。
4. **世帯を離れる時期**: 本人・配偶者・子の候補を承認しても、世帯を離れる時期（子の独立・亡くなる見込み）は今の値を残す（どのシートでも聞かない。前は取り込んだ「なし」で上書きしていた）。親は前から残していた（`keepParent`）。
5. **ご両親の仕送り・援助・介護の費用と、受け取る予定の相続・贈与の行**: 今の世帯に同じ行があれば、記録のある欄（額・介護の場所・答えた時期など）だけを入れ、シートで聞かない欄（始まり・終わり・相手・見込み・介護の期間など）は今の値を残す。比べるのも記録のある欄だけ。介護が始まった年月（シートで聞かない仮の値）はお答えの無い欄にし、受け取る予定の相続の額の空欄も記録してお答えの無い欄にする。受け取る予定の相続・贈与は、相手をシートで聞かないので、今の行に相手があっても同じ行として対応づける（前は相手の違いで新規になり、同じ相続が2行になった）。
6. **元に戻す**: 取り込みと後始末の推定は1回の保存なので、元に戻すと推定の分も取り込みの前に戻る（テストで確かめる）。
8. **確定申告の仕方**（詳細版の版4 から。0155）: 答えが無い（空欄・「わからない」・「該当なし」・版3 までのシート）か、自営業でない人の答え（取り込まずに知らせる）なら、本人・配偶者の候補を承認しても今の申告の仕方を残し、比べにも使わない（前は取り込んだ「入れていない」で上書きし、違う所の無い変更の候補になっていた）。答え直した申告の仕方は記入どおりの変更として入る。
7. 候補の画面の退職金の分野の名前を「退職金」にした（前は内部の一覧の名前が出ていた。詳細版の通しの確かめで見つかった）。

### 7. 働き方の種類が変わったとき（2026-11-07 の追記）

値の入った世帯に、今の期間と働き方の種類が違う答え（正社員 → 会社役員・自営業・パートなど）を取り込むと、今の期間を残したまま新しい期間が足され、同じ人の働き方が同じ月に2つ続いて給与が二重になった。続いて働く最後の年齢の推定が重なった期間に当たり、答えた定年が推定で上書きされた（同じシートを取り込み直すと答えの定年に戻った）。

1. **対応づけ**: 働き方の期間は、種類でなく **その人の今（計算基準月）にかかっている期間** と対応づける（取り込みは答えを計算基準月の時点の値として扱う）。同じ種類の期間があればそれを先に。今にかかっている期間が無ければ新規（今までどおり）。過去の同じ種類の期間と対応づけることも無くなる。
2. **候補の画面**: 種類が違えば1つの変更の候補にし、欄ごとの「今 → 届いた値」に「働き方 今 会社員（正社員）→ 届いた値 会社役員」を出す。その下に承認の入れ方を2つ並べて FP が選ぶ（`CandidateView.work`・`applyImport` の第5引数）。
   - **終えて足す**（既定）: 今の期間を、届いた働き方を始めた年月の前の月で終え、届いた働き方の期間を足す（転職・独立・役員になったとき）。この入れ方では「今 → 届いた値」と置きかわりの知らせは出さない（今の期間を置きかえないため）。退職金などの参照は新しい期間を指す。
   - **置きかえる**: 今の期間（同じ ID）を届いた働き方にする（今の入力が古かったとき）。お答えの無い欄は今の値のまま（決定の2）。
   - 始めた年月の答えが無い・今の期間の始まり以前・計算基準月より後のときは、終えて足すは選べず、置きかえるだけにする（理由を出す）。
3. **今の終わりが推定のとき**（働く最後の年齢・定年の印がある）: 終わりは残さない。推定の定年後の期間（今の期間の終わりの次の月からの期間）と定年後の予定・推定の印を外し、定年の答えがあればそれ、無ければ届いた働き方で働く最後の年齢を推定し直す（入力の画面で働き方の種類を変えたときと同じ考え方）。FP が入れた終わりは、置きかえるでお答えが無ければ残す（決定の2）。
4. **FP が入れたこの後の期間**（定年後の予定など）は残す。届いた働き方に終わりが無ければ、その前の月で終える（推定しない。重ねない）。届いた定年と重なるときは候補の画面で知らせる（未確定）。
5. **定年の「わからない」「該当なし」**（終わり無し）と、今の終わりが働く最後の年齢の推定のときは「同じ」とみる（同じシートの取り込み直しで「変わった」に出さない。承認しても推定が入り直して中身は同じ）。推定と一緒に入る辞めた後の給付を受け取るかの推定（失業給付・高年齢雇用継続給付の自動の推定）も比べない。今の終わりが確定のときは今までどおり粗い答え（既定で残す）。
6. **元に戻す**: 取り込みは今の世帯を書き換えず、1回の保存なので、元に戻すと期間の終わり・外した定年後の期間・推定の印も取り込む前に戻る。

### 8. 分岐の答え（Web のヒアリングだけ。2026-11-08 の追記）

Web の答えの中身 0.2 の分岐の答え（配偶者の方がいるか・お子さまの人数・住宅ローンの本数・保険の件数・ご両親のことを答えるか。0158 の3）を取り込みにつないだ。

1. **取り込みの部品**: `importAnswers` の選び方に `gates` を足した（Web の取り込み `importWeb` が依頼の記録の `received.gates` を渡す）。取り込みの部品は世帯を知らないので、形を確かめて（知っている問い・このシートに関わる繰り返しがある・数が 0〜繰り返しの数〔配偶者の方・ご両親のことは 0 か 1〕）結果の `gates` に写すだけ。候補・世帯は分岐の答えの無いときと同じ（「0人」の答えでも、子を消す候補は作らない）。
2. **候補の画面**（`viewOfResult` の `gates`。`gateNotices`）: 分岐の答えを今の世帯と照らし、違えば候補の画面の上に「要確認: 分岐の答えが今の世帯と違います」として並べる。
   - お子さま・住宅ローン・保険: 「お子さまは0人とのお答え（今の世帯は2人）」「住宅ローンは0本とのお答え（今の世帯は1本）」「保険は0件とのお答え（今の世帯は1件）」。多いときも同じ形で出す（足りない人・物は新規の候補として並ぶ）。最後の段（「4人以上」など）は、今の世帯がそれ以上なら同じとみる。住宅ローンは住まいのもの（収益不動産のローンは数えない）、保険は世帯の保険の全部（シートの保険の種類に損害保険も入るため）。面談の準備の分岐の答え（0158 の3）と同じ数え方。
   - 配偶者の方: 「配偶者はいないとのお答え（今の世帯にはいます）」「配偶者がいるとのお答え（今の世帯にはいません）」。
   - ご両親のこと「答えない」: 今の世帯にご両親か、ご両親の区画の行（仕送り・援助・介護の費用・受け取る予定の相続）があるときだけ「ご両親のことは答えないとのお答え（今の世帯のご両親 2人と、仕送り・援助・介護・受け取る予定の相続の値は今のまま）」。
   - 分岐の答えが今の世帯と同じなら何も出さない。届かなかった問い（聞かなかった・答えなかった）も出さない。
3. **世帯の人や行は黙って消さない**: 知らせだけにし、消す候補は作らない。承認しても今の世帯の子・配偶者の方・ご両親・ローン・保険・教育の行は今のまま。お答えのとおりなら、FP が入力の画面で直す（候補の画面に「取り込みでは、今の世帯の人や行を消しません（承認しても今のまま）。お答えのとおりなら、承認の後に入力の画面で直してください」と添える）。
4. **「答えない」を選んだ分岐の下の問い**（ご両親の問いなど）は、答えが届かないので、ほかの空欄と同じお答えの無い所（今の値のまま）。ご両親の候補・仕送りなどの行の候補は作らない（今までどおり）。
5. **Excel のシートには分岐の答えが無い**（`gates` を渡さない）。Excel の取り込みは変えない（知らせも出さない）。
6. 分岐の答えは依頼の記録（`received.gates`。0158）にあるので、取り込みの記録（`imports`）には足さない（世帯ファイルの形式は変えない）。

### 9. 記録のある欄だけを今の行に重ねる・お答えの無い新しい行・お子さまの当て方（2026-11-09 の追記）

Web のヒアリングの通しの点検（0193）で、承認すると今の世帯の欄が消えることが見つかった。取り込みの候補と承認は Excel と Web で同じ処理（`viewOfResult`・`applyImport`）なので、Excel のシートでも同じことが起きていた。

- **何が消えていたか**: 変更の候補を承認すると、ご両親の仕送り・援助・介護の費用と受け取る予定の相続・贈与の行（決定の6の5）のほかは、行ごと取り込んだ行に置きかえていた（お答えの無い欄だけを今の値に戻していた）。取り込みの部品はシートで聞く欄しか作らないので、聞かない欄が消えた。
  - シンプルの票で年収を答えただけで、働き方の標準報酬月額・企業年金・失業給付を受け取るか、が消えた。
  - 見直しの票では、ほかに、預貯金・投資の取得価額と資産の配分、住まいの評価（構造・築年・土地の割合）と持ち分、固定資産税・管理費の上がり方、住まいの入居のイベントへのつながり（住み始めた年月をイベントで入れていた）、教育の塾と受験の費用、生活費の段階、保険の解約返戻率、行の中の並びの要素の ID（0035）が消えた。本人・配偶者・子も、聞かない欄（年金の繰下げ・婚姻の状態など）を今の値に戻すのは決めた欄（連帯保証の額・性別・世帯を離れる時期・確定申告の仕方）だけだった。
  - 消えた欄が「違う所」になるので、見直しで前回の値のまま送っても、違う欄の無い変更の候補が10件ほど出て、既定でチェックが付いた。

1. **記録のある欄だけを重ねる**（`patchRow`）: 変更の候補を承認すると、今の行を元に、取り込みの部品が記録した欄（どの欄をどの項目から入れたか）だけを届いた値にする。全部の一覧で同じ（決定の6の5 の考え方を全部に広げた）。本人・配偶者・子もこの形にした（前の `keepMember` の決めた欄は、この形で今の値のまま残る）。
   - 途中の入れ物が今の行に無ければ（積立の無い口座に毎月の積立額の答えなど）、届いた行の入れ物ごと入れる。
   - 年月の時点がイベント・年齢で決まる欄（入居のイベントにつながる住み始めた年月など）は、解いた年月が届いた年月と同じなら今の時点のまま。違えば時点ごと届いた値にする。
   - 入れ物ごと記録のある欄（住宅ローン控除の条件）は、届いた値に無い欄（取得価額・持ち分など、シートで聞かない欄）を今の値のまま残す。時点の形の値は重ねない（`{ event }` と `{ at }` が混ざらないように）。
   - 並びの要素ごと記録のある欄（進路の学校）は、並びの形（数と順）を届いた値にし、同じ種類（学校の段・種類）の今の要素があれば、その要素の ID と届いた値に無い欄（受験の費用など）を残す。違う学校になった要素は届いた値のまま（前の学校の受験の費用を持ち越さない）。
   - 一緒に入れる欄（構成員の中だけ）: 確定申告の仕方は申告の方法と青色申告特別控除で1つ（白色の答えで今の控除を残さない）。子の生年月は、生まれる予定か・世帯に入る年月と組。
   - 範囲・推定・仮の値の答えが今の値と同じ（金額などが同じ）なら、今の値（確定の状態・承認の記録・印）のまま。記入どおり（確定）の答えは、同じ値でも届いた値（承認の記録が付く）。
   - 行ごと置きかえるのは、親（`keepParent`。シートで聞いた欄だけを入れる。前から）と、働き方の種類が変わった期間（決定の7。今の種類に付いた標準報酬月額などは、届いた働き方に当てはまらない）だけ。
2. **候補の差の判定**（`viewOfResult`）: 変わるかどうかは、承認すると入る行（今の行に重ねた形）と今の行で比べる。前は取り込んだ行と比べていたので、聞かない欄の違いで「変更」になった。比べる値は、時点がイベントなどで決まる欄は解いた年月。本人・配偶者・子の比べ方の特例（連帯保証の額・性別・世帯を離れる時期・確定申告の仕方を比べない）は、重ねた形で同じになるので外した。
3. **仮の印**（入力の画面の `assumed`）: 記録のある欄だけを重ねた行では、値を入れた欄の今の印だけを外す（取り込みの部品の印のキーと、欄の場所ごとの印の最後の段の表 `MARK_SUFFIXES`）。聞かない欄の印は、値と一緒に残す（前は、置きかえた行の印を全部外していた）。行ごと置きかえた行は前と同じ。
4. **年収が変わったときの知らせ**: 働き方の候補で給与が変わり、今の行に標準報酬月額があれば、候補に「標準報酬月額・企業年金など、シートでお聞きしていない欄は今の値のままです。年収が大きく変わったときは、承認の後に入力の画面で確かめてください」と添える。
5. **お答えの無い新しい行**: 今の世帯の人を指す新しい行で、どの欄にもお答えが無い（目安・推定で補っただけ）ものは、ほかに同じ人を指す新しい行が無ければ作らない（お答えなし。候補の画面の下に「今 入れていない」と並べる。全部を選んで承認しても入れない）。答えていない配偶者の方の住民税の推定（取り込みの部品が、前の年に働いていた人に足す推定の行）がこれに当たった。同じ人の働き方が新しく入るとき（今の世帯に無かった働き方を答えた）は、新しい働き方の計算に要るので、前と同じく一緒に入る。空の世帯への取り込みも前と同じ（人が新しいので当たらない）。
6. **お子さまの当て方**（`memberMatch`）: 取り込んだ子を、問いの順（何人目のお子さまの問いか。生年月の欄の記録の番号）で、今の世帯の生まれの順の子に当てる（シートと Web の前回の値も生まれの順に並べている）。今の世帯にいない番目のお子さまは新規の家族。前は、答えのある子だけを生まれの順に当てたので、3人目（出産の予定）の生年月だけを答えると、その答えが今の第1子に当たり、第1子の生年月が 2027年3月に書き換わる変更の候補に既定でチェックが付いた。候補の見出しも問いの順で「第3子」と呼ぶ（前は取り込んだ側の生まれの順で「第1子」）。
7. **Excel も同じ**: 1〜6 は候補と承認の処理（`sheet.ts`）だけを変えたので、Excel のシートの取り込みにも同じく効く（`app/test/hearing-import-keep.test.ts`: 見直しで書き出したシートをそのまま取り込むと既定でチェックの付く候補が無く、全部を選んで承認しても欄が消えない・簡易版の見本で標準報酬月額などが残る）。

## 理由

- **候補にしない（チェックを外すだけにしない）**: お答えの無い項目は、お客さまが何も言っていない所。チェックを外しただけの候補は、FP が「全部入れる」つもりで押すと今の値が消える。今の値を残すのが「何も言っていない」の正しい読み方で、FP が別の値にしたければ入力の画面で直せる。
- **混ざった候補は欄ごとに戻す**: 候補ごとにしか選べないと、答えた生年月を入れるために、答えていない性別・仕事を始めた年月の仮の値まで入れることになる。戻すのは記録のある欄（取り込みの部品が「どの欄をどの項目から入れたか」を記録している欄）だけなので、物の形は取り込んだ物のまま崩れない。
- **粗い欄だけの候補を既定で外す（混ざった候補は既定で入れる）**: 範囲・推定・仮の値だけの変更は、今の確定の値より情報が少ないので、既定で残す方が壊れない。記入どおりの値が入っている候補（返済予定表を見て書いた住宅ローンなど）を既定で外すと、詳細の票の取り込みのたびに多くの候補を入れ直すことになるので、既定で入れて置きかわる欄を知らせる。
- **今 → 届いた値を欄ごとに**: お客さまの答え（毎月の返済額）と、置きかわる欄（残高・借入額・借りた年月・金利）は1対1でないので、答えの横に今の値を1つ出すだけでは何が変わるか分からない。世帯の値どうしで比べると、Excel・Web・簡易・詳細のどの票でも同じ言葉で並ぶ。
- **元に戻したときに依頼の記録を書き換えない**: 0125 の4 の理由（受け取ったらサーバーから消すので、依頼の記録を前に戻すと「まだ受け取っていない」になり、サーバーの状態と食い違う）は変わらない。世帯の取り込みの記録と照らして出し分ければ、記録を書き換えずに世帯と画面がそろう。
- **推定より「答えの無い所は今のまま」を優先する（6）**: 働く最後の年齢の推定（0133）は「取り込んだ終わりの無い働き方が100歳まで続かない」ためのもので、空の世帯や新しい期間ではそのまま効く。今の世帯に終わりがある期間でそれを「無し」にして推定で置きかえると、FP が入れた定年や定年後の予定が、お客さまが何も言っていないのに変わる（定年後の再雇用の期間まで足された）。今の終わりが無い期間は、入力の画面と見張り（0129）が「終わりの無い働き方」を知らせるので、そこで直す。
- **働き方は今にかかっている期間と対応づける（決定の7）**: シートが聞くのは「いまの働き方」なので、答えが指すのは今の期間。種類で分けると、答えた人が1人なのに働き方が2つ続き、給与・社会保険・税が二重になる。黙って2本並べるより、1つの変更として見せて FP に入れ方を選んでもらう方が誤りに気づける。
- **既定を「終えて足す」にする**: 答えの「いまの仕事を始めた年月」が今の期間の始まりより後なら、FP の入力（前の勤め先）と答え（今の勤め先）は両方とも正しい見込みが高い（転職・独立・役員になった）。終えて足すは、FP が入れた前の期間を消さずに、今から先を答えのとおりにする（将来の計算はどちらの入れ方でも同じ）。FP の入力が誤りだったときは置きかえるを選ぶか、前の期間を入力の画面で消せる。置きかえるを既定にすると、誤りでなかったときに FP の入れた前の期間が黙って消える（決定の「今の値を壊さない」と反対）。
- **推定の終わりは届いた働き方で入れ直す**: 前の働き方の定年と再雇用の推定は、働き方が変われば当てはまらない（会社役員に正社員の定年60歳と再雇用が残る）。入力の画面で種類を変えたときも推定を入れ直している。
- **分岐の答えは知らせだけにする（決定の8）**: 「お子さま 0人」は、今の世帯の子2人が誤りだったのか、お客さまが答えを飛ばしたくて「いない」を選んだのか、取り込みでは分からない。消す候補を作ると、FP が「全部入れる」つもりで押したときに、子と教育の行・子を指す保険の受取人などが消え、元に戻すまで気づきにくい。今の値を壊さない（決定の1・2）と同じく、何も言っていない所と同じに扱って今のまま残し、違いを目立つ所に出して FP が入力の画面で直す方が誤りが小さい。
- **知らせは候補の画面で今の世帯と照らす**: 取り込みの部品は世帯を知らない受け皿のまま（代案の「取り込みの部品の中で今の世帯と照らす」と同じ理由）。
- **記入の年月の差は1年**: 計算基準月は月末や面談の前に1〜2か月ずれるのが普通で、そのたびに注意が出ると読まれなくなる。1年を超えるずれは、計算基準月を直し忘れた世帯の見分けに使える。

- **記録のある欄だけを重ねる（決定の9）**: 取り込みの部品は、シートで聞いた欄の値を作り、どの欄をどの項目から入れたかを記録している。記録の無い欄は、お客さまが何も言っていない所で、取り込んだ行には初めの値か欄そのものが無い。行ごと置きかえると、それが「答え」として今の値を消す。決定の1・2 の「お答えの無い所は今のまま」を、欄の記録が無い所にも当てるのが自然。
- **働き方の種類が変わった期間は行ごと**: 今の種類（正社員）に付いた標準報酬月額・企業年金を、届いた働き方（会社役員・パート）に残すと、計算が当てはまらない値で動く。今の入力が古かったときの入れ方なので、届いた行を正にする。
- **お答えの無い新しい行は作らない（同じ人の新しい行があれば作る）**: 今の世帯が推定の行なしで計算できているなら、お客さまが何も言っていない推定の行を足す理由が無い。働き方が新しく入るときは、取り込みの部品と入力の画面が住民税の推定を足すのと同じ理由（前の年の所得から計算し直すと、古い年の制度データが無くて止まる）で要る。
- **お子さまは問いの順**: Web の画面とシートは「1人目・2人目・3人目」と問いを並べ、前回の値も今の世帯の生まれの順に入れている。答えのある子だけを詰めて当てると、答えの無い番目があるだけで当て先がずれる。

## 代案（採らなかったもの）

- **聞かない欄の表を作って残す（行ごと置きかえたうえで、決めた欄だけ戻す）**: 前の本人・配偶者・子のやり方。欄が増えるたびに表を足すことになり、足し忘れると消える（今回の不具合はそれ）。記録のある欄だけを重ねれば、新しい欄も今の値のまま残る。
- **お子さまを生年月の近さで当てる**: 記入した生年月が今の値と大きく違う（誤りを直した）ときに別の子に当たる。問いの番目の方が、お客さまが答えた形に合う。

- **お答えの無い欄を含む候補を全部、既定でチェックを外す**: 外した候補を FP が入れると、答えた欄と一緒に答えの無い欄も上書きされる。外す候補が多く、FP の手数も増える。
- **取り込みの部品の中で今の世帯と照らす**: 取り込みの部品は世帯を知らない受け皿（0018・0125）のまま、照らすのはアプリの側（候補の画面と同じ所）に置く。
- **依頼の記録に「元に戻した」の状態を足す**: 元に戻す・やり直すで依頼の記録を書き換えることになり、0125 の4 の決まりと反対になる。
- **分岐の答えが0のとき、今の人・行を消す候補を作る（既定でチェックを外す）**: 外した候補でも、FP が全部を選んで承認すると消える（お答えの無い欄を候補にしない理由と同じ）。子を消すと、子を指す行（教育・保険の受取人・扶養）の後始末も要り、元に戻すまで計算が大きく変わる。
- **親の亡くなる見込みを取り込みの部品で入れる**: 平均余命の表と推定の決まりは入力の画面の側（`care.ts`）にあり、二か所に置くと食い違う。承認のときに入れる今の形を残す（0129 の未確定に同じ問いがある）。
