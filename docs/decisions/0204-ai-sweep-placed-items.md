# 0204. AI接続口の感度・境目探しで、場所だけ違う「動かす項目」も振れるようにする（vary の at・lever）

- 状態: 採用（2026-11-11）
- 固定の強さ: 書き方（`sweep`・`find_threshold` の `vary` の `at`・`lever`、選べなかったときの答えの `places`）と使い方の例 `find_boundary` は試験版（0015 と同じ。予告して変えることがある）。作り（振る項目を選ぶ画面の関数 `pickPlanItem`）は内部
- 前提にする記録: 0015（AI接続口）、0195（プランの動かす項目）、0199（使い方の例）、0201（場所つきの動かす項目）、0202（感度・境目探し）

## 背景

- 0201 で `plan_changes` に場所（入力の欄の場所 `at`・合成の対策の名前 `lever`）が入り、資産運用の「毎月の積立額」と「積立をやめる年齢」、退職後の生活費の割合、教育の段階ごとの欄なども選べるようになった。
- 一方、0202 の `sweep`・`find_threshold` の振る項目 `vary` は `target`・`item` だけで、一覧の項目のうち場所の要らない物だけを選んでいた（0201 と同時に入ったため、場所の要る項目を黙って別の項目に取り違えないよう、わざと外していた。0202 の未確定）。そのため「積立をやめる年齢を何歳まで早めても足りる？」「退職後の生活費を今の何割までにできる？」は、`calculate` を何度も呼ぶしかなかった。

## 決定

### 1. `vary` に場所を足す

- `vary` は `plan_changes` の1件から `value` を外した物そのまま: `{target, item}` に、一覧が添えた項目だけ `at` か `lever` のどちらか1つを足す。値ごとの計算は、場所も添えたまま `plan_changes` の後につなぐ（0202 と同じ）。
- 振る項目は、`plan_changes` と同じ画面の当てはめ（`app/src/workspace/plans/candidates.ts` の `matchItems`）で選ぶ。画面の関数 `pickPlanItem`（`app/src/connector/plan.ts`）が当てはめ、選んだ項目を `list_plan_items` の1件と同じ形（今の値・値の形・範囲・`place`）で返す。接続口に別の選び方を書かない。
  - 当てはまらない（0件・2件以上）・`at` と `lever` の両方を書いた、のときの理由は `plan_changes` と同じ文。
  - 場所を書かなければ、今までどおり場所の要らない項目だけを選ぶ（場所の要る項目に場所なしで当たっても選ばない。0202 と同じ答え）。
- 場所の要る項目に場所を書かなかったときは、計算せずに、同じ対象・同じ入力項目ID で選べる場所を `list_plan_items` と同じ形（`at` か `lever`・`place`・`label`）で `places` に並べ、文（`message`）にも `lever "investStopAge"（資産運用 › 積立をやめる年齢）` の形で書く。当てはまらない場所を書いたときも、選べる場所があれば添える。
- 答えの `vary` に、添えた `at`・`lever` と `place` を足す。
- `find_threshold` の探し方: 単調と分かる項目（毎月の生活費・働く最後の年齢・運用の利回り）の二分探索は、場所の要らない項目だけにする。場所を添えた項目は、同じ入力項目ID でも別の欄なので、刻みで振る（`method: "bisect"` で頼めば二分探索）。

### 2. 使い方の例に「境目を探す」を足す

- MCP のプロンプト `find_boundary`（境目を探す）: 引数は世帯と探したい境目（省くと「最後まで資産が尽きない、いちばん早い退職の年齢」）。`list_plan_items` で項目を確かめ（場所もそのまま）、`calculate` を何度も呼ばずに `find_threshold` で探し、`edge` なら範囲を広げ、境目とその1つ外側の数字を小さな表にする、の順で書く。
- INSTRUCTIONS・道具の説明・`docs/ai-connector.md` に、`vary` の場所と使い方の例を足した。

### 3. テスト

- 画面の側（`app/test/connector-plan.test.ts`）: 見本の世帯3件の一覧（`fields: true`）のすべての項目を、一覧の書き方で `pickPlanItem` に渡すと一覧と同じ1件が返ること。場所の要る項目から場所を外すと、その項目を選ばず（場所の要らない別の項目に当たるか、選べる場所を一覧と同じ形で返す）、当てはまらない場所・両方の場所・違う対象の理由が `applyPlan` と同じ文なこと。
- 接続口の側（`crates/lifeplan/tests/mcp_connector.rs` の `sweep_and_threshold_over_a_placed_item`）: 積立額（`lever`）の `sweep` の値ごとの数字が、同じ場所の `plan_changes` で `calculate` した数字と同じ。退職後の生活費の割合（`at`）の `find_threshold` の答えが、同じ範囲の `sweep` の表から欲しい端で初めて条件を満たす値と同じで、刻みで振ったこと。積立をやめる年齢（`lever`）も探せること。場所を書かなかったとき（`sweep`・`find_threshold` とも）に、計算せずに選べる場所を返すこと。使い方の例の一覧と中身（`prompts_list_and_expand`）。道具の入力の形の見本（`tests/fixtures/tools/`）は作り直した。

## 理由

- **画面の関数で選ぶ**: `plan_changes` と振る項目で選び方が違うと、同じ書き方で別の項目に当たる（`sweep` の表と `calculate` の数字がずれる）。0201 で当てはめを1か所（`matchItems`）にした考えのまま、振る項目もそこで選ぶ。
- **場所なしの答えを変えない**: 場所を書かない `vary` は、0202 と同じ項目・同じ答え。場所の要る項目に場所なしで当たる場合（前提を対象にする前提条件でない入力項目）は、`plan_changes` では当たるが、振る項目では取り違えに気づきにくいので選ばず、選べる場所を返す。
- **二分探索を場所の要らない項目に限る**: 単調と分かる項目の一覧は入力項目ID で書いている。同じ入力項目ID で場所だけ違う欄（生活費の段階の割合など）が同じく単調とは確かめていない。

## 代案

- **接続口の中で一覧から探す（今までの作り）に場所の一致を足す**: 一覧の選び方は `matchItems` で確かめてから作るので、多くは同じ答えになる。ただ、選び方の決まり（対象の合わせ方など）を接続口にもう1つ書くことになるので、画面の関数を呼ぶ方にした。
- **場所なしでも、1つに決まれば場所の要る項目を選ぶ**: `plan_changes` とそろうが、0202 の答えが変わる。場所を書けば選べるので、今の形にした。

## 未確定

- 2つの項目を一緒に振るか（0202 の未確定のまま）。
