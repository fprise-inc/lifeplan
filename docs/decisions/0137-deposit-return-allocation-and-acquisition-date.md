# 0137. 預金の利回りを運用利回りと分ける・資産配分を計算に渡す・取得価額を0円で書かない・収益不動産の取得の年月だけの取得と、世帯ファイルの形式 0.67

- 状態: 採用（一部未確定）（2026-11-07）
- 固定の強さ: 骨格（計算の要求の前提 `assumptions.depositReturn` と、資産クラスの利回りの代わりの順〔資産クラスごとの利回り → 預金の種類は預金の利回り → 運用利回り。不動産は0〕、収益不動産の取得 `accounts[].property.acquisition` の `price` の省略の意味、形式 0.67）。既定の値（0.1%）・画面の欄の並び・知らせの文・資産配分の目安の値は後から変えてよい（変えたら追記に書き、推定の見直しの一覧も直す）
- 前提にする記録: 0008 の8（前提条件は年ごとの列）、0026（資産運用の入れ方・資産配分）、0028・0080（収益不動産の取得）、0031（合計の入れ方の運用しない分）、0035 の3（仮の印）、0041（値の状態の操作・確かめの一覧）、0070（前提条件の入力項目）、0073（事務所の既定値の前提条件の標準値）、0111（事務所の推定の値）、0129（直す待ちの一覧）

## 背景

入力項目を通しで入れて見直したところ、貯蓄・運用・前提条件・収益不動産に、結果を黙って誤らせる所が見つかった。

1. **預金が運用利回りで増える**。預金・外貨預金の利回りの代わりの値が前提条件の運用利回りだった（`engine/src/sdk/helpers.ts` の資産クラスの利回り、画面の `plans/allocation.ts`）。運用利回りを3%にすると預金も年3%で増え、利回りを上げた世帯ほど預金まで甘くなる。合計の入れ方の「運用しない分」も同じ。
2. **資産配分に切り替えただけでは、画面の割合・期待リターン・信託報酬が計算に入らない**。画面は目安の割合（国内株25%・外国株40%…）・期待リターン（5%・6%…）・信託報酬0.25%を灰色で出し「組み合わせた期待リターン 4.1%」と見せていたが、計算の入れ物（`assumptions.investment.allocation`・`assumptions.assetReturns`）は空のままで、計算は口座の入れ方のままだった。
3. **NISA・課税口座・こどもNISA を足すと取得価額が「0円」の確定の値で入る**（欄の説明は「入れなければ時価と同じ」）。課税口座300万円なら取り崩すときに全額を利益として約20%の税、NISA は生涯の枠を使っていないとみなす。
4. **収益不動産の取得の年月を空にすると取得価額ごと消える**。取得価額の無いときに取得の年月を打っても残らない（計算の要求の形が取得価額と年月の両方を求めていたため、画面が取得ごと消していた）。
5. 前提条件の説明と足すボタン: 運用利回りの説明が「費用・税を引く前」で、利回りは費用を引いた後として入れる決まり（10月27日の利用者の判断）と逆。「＋ 例外の年（年金の調整率）」が2つ並び基礎年金と厚生年金の区別が付かない。「資産の種類ごとの利回り」の足すボタンが先頭の6つだけで、国内REIT・不動産などは押せない。

利用者の判断（2026-11-06）: 預金・外貨預金の利回りの初めの値は普通預金の目安 0.1%（前提条件の詳細に「預金の利回り」を出して直せるように）。**今ある世帯も含めて直す**（テストの段階なので見本の世帯の結果が変わってよい）。貸していない土地の値動きは今のまま（0%）。預金の利回りと貸していない土地の値動きを事務所の既定値に足すかは、まだ決めていない。

## 決定

### 1. 預金の利回り（計算の要求 `assumptions.depositReturn`）

- 前提条件に年ごとの列 `depositReturn` を足す（任意）。資産クラスの利回りの代わりの順は「資産クラスごとの利回り（`assetReturns`）→ 預金・外貨預金の資産クラス（`cash.deposit`・`cash.foreign`）は預金の利回り → 運用利回り」。不動産は今までどおり0。
  - 預金・外貨預金の口座、合計の入れ方の運用しない分、資産配分の現金、口座の資産の配分の現金のどれも同じ決まり（計算は `helpers.ts` の1か所、画面の見込みは `plans/allocation.ts` の `classRate` で同じ決まり）。
  - **省略は運用利回り**（前の版の計算の要求・控えの中身は今までどおりの結果）。読む部品（iDeCo・小規模企業共済・貸していない資産の売却・キャッシュフロー表・保険）の reads に足し、改訂を1つ上げた（結果は預金の利回りを入れた世帯だけ変わる）。
- 新しい世帯は既定の値 0.1%（`DEFAULT_ASSUMPTIONS`。普通預金の金利の目安。仮の値で、推定の見直しの一覧に載せる）。前提条件の詳細に「預金の利回り（年）」の欄を出す（推定の印・空欄で既定の値に戻す・例外の年あり）。資産の種類ごとの利回りに預金・外貨預金があれば、その種類はそちらで計算する（欄の下に「預金は『資産の種類ごとの利回り』の預金（0.1%）で計算しています」）。預金の利回りの無い前の要求（変換の段を通らない計算の要求の写し）は空欄で「空欄（運用利回りと同じ 1%で計算しています）」と添える。
- 今ある世帯は、形式 0.67 の変換の段で、預金の利回りが無ければ既定の値 0.1% を書く（6 の形式）。
- **事務所の既定値にはまだ足さない**。足すときは、前提条件の標準値の系列 `OFFICE_ASSUMPTIONS`（`office/settings.ts`）に `depositReturn` を1つ足し、範囲と名前の表に1行ずつ添えるだけで済む形にした（系列の名前と前提条件の欄のキー `assume/<名前>`・仮の印のキーが同じ。事務所の既定値の画面の既定の値は `DEFAULT_ASSUMPTIONS` から引く）。

### 2. 資産配分を計算に渡す（`savings/model.ts`）

- 入れ方を資産配分に切り替えたら（`switchMethod`）、配分が無ければ画面の既定の割合（`DEFAULT_MIX`）と目安の信託報酬を `allocation` に書き、割合のある資産の種類（今と段階）で期待リターンの無い物は、目安（事務所の推定の値があればその値）を前提条件の資産の種類ごとの利回りに**推定の印**（「既定の値（外国株の期待リターンの目安 6%。…）」）で書く（`fillAllocation`）。打つと確定、表で空にすると目安の推定に戻す（灰色の値と計算の値を食い違わせない）。預金の種類（現金・外貨預金）は書かず、預金の利回りに任せる。
- 資産配分から別の入れ方に戻したら、推定のまま書いた期待リターンを外す（`dropEstimatedClassReturns`）。口座の入れ方で資産の配分を持つ口座（NISA の外国株100%など）の利回りが、切り替える前と同じに戻る。FP が打った値は残す。
- 表の「期待リターン」の灰色の値・組み合わせた期待リターン・信託報酬は、計算と同じ値を見せる（期待リターンの無い種類は運用利回り・預金の利回り、配分を書いた世帯の信託報酬は書いた値で、無ければ引かない）。前の版で資産配分にした世帯で、配分や期待リターンが計算に無ければ、表の上に「…が、まだ計算に入っていません」と「表の値で計算する」を出す（押したときだけ書く）。
- 推定の印は前提条件の「資産の種類ごとの利回り」の欄の仮の印（`assume/assetReturns/<種類>/default`）。確かめの一覧では、前提条件の標準の値の折りたたみに出る。

### 3. 取得価額を0円で書かない（`stages/savings.ts`）

- NISA・課税口座・こどもNISA を足すとき、取得価額を書かない（空欄＝時価と同じ）。
- 前の版で足した口座で、残高があるのに取得価額が0円（暗号資産を除く）なら、取得価額の欄と確かめの一覧に「取得価額が0円です（…）。分からなければ時価と同じにします」と「時価と同じにする」（取得価額を外す）を出す。押したときだけ直す（値は黙って変えない。0041）。

### 4. 収益不動産の取得の年月だけの取得（計算の要求 `accounts[].property.acquisition`）

- 取得は取得の年月（`at`）だけでもよい（`price` を省略できる）。取得価額（内訳があれば内訳の合計）の無い取得は、減価償却・帳簿価額・売ったときの取得費に使わない（取得の入力が無いときと同じ。知らせ N_INPUT_REQUIRED・概算取得費）。取得の年月は、建った年の省略・貸し始めの省略・売ったときの長期と短期の分けに使う。取得価額のある取得は今までと同じ結果（`asset.realEstate` 改訂9・約束の版 1.5）。
- 画面（`stages/rental.ts`）: 取得の年月を空にしたら年月だけ外し、取得価額（か内訳）があれば評価額の時点で補って推定の印（「既定の値（評価額の時点 2026年10月。…）」）を付ける。取得価額を先に入れたときも同じ。取得の年月を打つと確定。取得価額を空にしても取得の年月・内訳・諸費用は残す（補った年月のままなら年月も外す。年月だけの取得を黙って作らない）。取得の年月を先に入れても残る。

### 5. 前提条件の説明と足すボタン（`stages/assumptions.ts`）

- 運用利回りの説明: 「預金以外で、資産の配分を入れていない口座の利回りです（運用の費用を引いた後。税は計算で引きます）」。資産の種類ごとの利回りの区画の説明に、こちらは信託報酬などの費用を引く前の率（費用は資産配分の信託報酬で引く）と、運用利回り・預金の利回りは費用を引いた後と区別を書く。
- 例外の年の見出しと足すボタンは欄の名前から「（年）」だけ外し、括弧の中の区別は残す（「＋ 例外の年（年金の調整率・基礎年金）」「＋ 例外の年（年金の調整率・厚生年金）」。`exceptionWhat`）。
- 資産の種類ごとの利回りの足すボタンは、まだ足していない種類を全部出す（先頭の6つに絞らない）。預金・外貨預金を足したら今の預金の利回りから始める。

### 6. 世帯ファイルの形式 0.67

- 足した欄: `assumptions.depositReturn`、`accounts[].property.acquisition` の `price` の省略。前の版のアプリは入力の検査で通さないので、版を上げて閲覧だけにする。
- 変換の段（0.66 → 0.67）: 今の世帯の前提条件に預金の利回りが無ければ既定の値（0.1%）を書く。もう持っている世帯・前提条件の無い本文はそのまま。控えの中身・プランの差分には触れない（控えは前の結果のまま）。0.66 の段の後に積む（住まいの売却の返済・持ち家の評価の入れ方の 0.66 の後）。
- モデル世帯（`data/modelHouseholds` の52件のうち51件。アプリの見本の棚の12件を含む）にも預金の利回り 0.1% を書いた（今の世帯の形にそろえる）。FP顧問料の提案の試験用のモデル世帯（`advisoryFeeProposal`）だけは書かない（提案の「運用利回り 2%→3%」の効果が、預金も運用利回りで増えていた分を含んで顧問料を上回る組み立てのため。預金の利回りの無い前の要求の確かめも兼ねる。作り直すときに預金の利回りを足す）。見本の棚の12件は、どれも資産の種類ごとの利回りに預金 0.1%（外貨預金のある見本は外貨預金 1.5%）を持っていたので、預金の分を外して前提条件の預金の利回り（同じ 0.1%）に任せた（前提条件で預金の利回りを直すと見本の預金にも効くように。外貨預金 1.5% は残す）。**見本の棚の結果は変わらない**。見本の棚に無い試験用のモデル世帯は、預金が運用利回り（1〜2%）から 0.1% になり、金融資産が少し下がる。預金の利回りの無い前の要求の結果が変わらないことは、エンジンの単体のテストで確かめる。

## 理由

- 預金の利回りを資産の種類ごとの利回りの「預金」に書く形にしなかったのは、前提条件の標準値（事務所の既定値）に足すとき、ほかの前提と同じ「年ごとの列を1つ」の形にしたかったため（`OFFICE_ASSUMPTIONS` に1つ足せば済む）。資産の種類ごとの利回りに預金を書いた世帯は、今までどおりそちらを優先する。
- 省略を運用利回りにしたのは、前の版の要求・控えを開き直しても結果が変わらないようにするため。今ある世帯は変換の段で書くので、利用者の判断どおり 0.1% で計算する。
- 資産配分で期待リターンを推定の印で書いたのは、確定は明示の操作だけ（0041）と、印の無い決まった値をなくす決まりのため。戻したときに推定の値を外すのは、資産配分に切り替えた世帯だけが変わるようにするため（口座の入れ方で資産の配分を持つ口座の利回りまで動かさない）。
- 取得価額を省略できる形にしたのは、取得の年月を先に入れる順を許し、年月を消したときに取得価額まで消す不具合を元から無くすため。取得価額の無い取得を償却に使わないのは、今までの「取得の入力が無い」の扱いと同じにするため。

## 代案（採らなかったもの）

- **預金の利回りを資産の種類ごとの利回りの預金に書く**: 事務所の既定値に足しにくい。資産の種類ごとの利回りの区画にいつも預金・外貨預金の行が出る。
- **計算で預金の利回りを決まった0.1%にする（世帯に書かない）**: 前の版の要求・控えの結果が変わる。根拠の値がコードの中に入る。
- **資産配分の表の値を計算に入れず、表を運用利回りの1%に合わせる**: 資産配分は割合と期待リターンで入れる形なので、入れ方の意味が無くなる。
- **取得の年月を空にしたら取得の年月だけを世帯の外（画面の側）に残す**: 保存すると消える。計算に使えない。

## 追記

- 2026-11-07（事務所の既定値。0073 の追記）: 未確定の1つ目を決めた（利用者の判断）。預金の利回りと貸していない不動産（空き家・土地・別荘）の値動きを、事務所の既定値の前提条件の標準値に足した。預金の利回りは 1 の形（`OFFICE_ASSUMPTIONS` に `depositReturn`）。貸していない不動産の値動きは、前提条件に年ごとの列を足さず、入れ子の場所 `assetReturns.realEstate` に写す（計算はもともと資産の種類ごとの利回りの不動産で動かしているため。置き場所の表は `office/current.ts` の `NESTED_OFFICE_ASSUMPTIONS`）。既定は今のまま（0.1%・0%）。2 の「資産配分から戻したら推定の値を外す」は、資産配分で目安を書く種類だけにした（事務所の既定値で写した不動産を外さない）。
