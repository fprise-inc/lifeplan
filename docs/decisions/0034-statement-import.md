# 0034. 明細の取り込みと仕分けのヒアリング（段階1: CSV・文字の入った PDF）

- 状態: 採用（一部未確定）（2026-10-23）
- 固定の強さ: β公開から変えない（骨格）。すべて PC の中で読み外に送らないこと、番号らしき数字を読んだ時点で消すこと、元のファイルを保存しないこと、読み手を差し替えられる形（欄の表＋列の対応付け）、2層の辞書（同梱・事務所で覚える）、区分を働き方で変えること、候補として受けて FP が承認すること、世帯ファイルの区画 `statements` の形（形式 0.14。確認シートの依頼の記録 `requests` は 0.15、同じ番号に複数の行を結ぶのは 0.16）・確認シートの管理の値の置き場所（3か所）と番号で行を結ぶことは骨格。どの迷う行を店ごとにまとめるか（追記「店ごとにまとめる」の決まり）は後から変えてよい。同梱の辞書の中身・見出しの言葉の一覧・金額の閾値（高額・年1回）・注意の文言・画面の見せ方は後から変えてよい（変えたら追記に書き、辞書は `BUILTIN_VERSION` を上げる）

## 背景

- 基本生活費の内訳・一時的支出は、ライフプランの数字を大きく動かすのに、面談では「だいたい月○万円」としか聞けないことが多い。お客さまのクレジットカード・銀行・家計簿アプリの明細を読み、項目ごとの月平均と年1回の支払いを出せれば、聞き取りの手間と思い込みのずれが減る。
- 明細には、カード番号・口座番号・店の名前（通院先など）・振込の相手の名前が入る。顧客の情報を外に送らない方針（0012・0015）と、持たない情報（0012）に合わせる必要がある。
- CSV の列の並び・文字コード・金額や日付の書き方はカード会社・銀行・アプリごとに違い、PDF しか出せない会社もある。写真・スクショの文字認識（段階3）と会計ソフトの試算表（段階2）も後で足したい。
- 区分（家計か、会社に請求する立替か、事業の経費か）は、世帯の働き方で変わる。夫婦で働き方が違う世帯もある。
- 外から来た案は候補として受け、FP が承認して取り込む（0008 の5。ヒアリングの取り込み 0018・AIの提案 0015 と同じ）。
- 前提: 0002（金額）、0008（値の箱・候補）、0011（世帯ファイル・事務所データ）、0012（持たない情報）、0014・0015（AIに渡した記録・AI接続口）、0018（ヒアリングシート）、0020（書き出し）、0023・0024（事務所での共有）。

## 決定

### 1. 段階と置き場所

- 段階1（今回）: クレジットカード・銀行・家計簿アプリの明細の **CSV**（TSV も）と、**文字の入った PDF**。段階2: 会計ソフトの試算表。段階3: スクショ・写真の文字認識。段階4: AIに聞く仕分け（下の10。今回は設計だけ）。
- 部品はリポジトリ直下の `statement/`（npm の依存なしの TypeScript。画面からも読む。hearing/ と同じ作り）。ファイルを開くダイアログ・大きさの確かめ・事務所データ（覚えた辞書と形）の保存はアプリ本体（Rust）が受け持つ。
- `statement/src/` は Node の組み込みも、外への通信（`fetch` など）も使わない（lint で止める）。

### 2. 外に送らない・番号を消す・元のファイルを持たない

- 読む・仕分ける・数えるは、すべて PC の中で行う。AIに聞く仕分け（段階4）も、既定はオフで、FP が選んだ店の名前だけを送る（下の10）。
- **カード番号・口座番号らしき数字は、読んだ時点で消す**（`●●●●` に置き換え、何桁あったかも残さない）。読み手はすべての欄を `maskCell` に通してから返し、読み手の外の共通の処理（`readStatement`）でもう一度すべての欄を通す（差し替えた読み手が消し忘れても、`readStatement` より外へ番号を出さない）。消すもの:
  - A. 数字と伏せ字（`*`・`X`・`●` など）が区切り（空白・ハイフン）をはさんで10字以上続くもの（カード番号・伏せ字つきのカード番号・電話番号）
  - B. 「口座番号」「カード番号」「お客様番号」「契約番号」などの見出しのすぐ後の数字（4字以上）
  - C. 区切りの無い7桁以上の数字（口座番号は7桁）
  - D. 見出しが口座・番号の列、または全部の行が同じ7桁以上の数字の列は、列ごと消す
  - 消さないもの: 日付・金額として読める欄（金額は9桁まで。10桁以上の数は金額として読まない）。残る危険: 見出しの無い表で、行ごとに違う7桁の数字だけが1つの欄に入っている場合は金額と区別できない（その列を金額に選ばなければ行には入らない）。
- **振込・送金の相手の名前は残さない**（銀行・家計簿アプリの「振込 ミドリ タロウ」は「振込（相手の名前は残しません）」にする）。利用者の欄は「本人・家族」だけを読み、名前は読まない（0012）。
- **元のファイルは保存しない**。残すのは元のファイルの指紋（SHA-256）と大きさ、取り込んだ結果（番号を消した後の行）だけ（0011 の取り込みの記録・0018 の6 と同じ考え方）。元のファイルのバイト列は `readStatement` の外へ出さない。同じ指紋のファイルは2回取り込まない。
- 明細の見出しの部分（名義人の名前・住所などの行）は、明細の行として読めないので残らない（表の見本として画面に出すときも番号は消した後）。

### 3. 読み手と列の対応付け

- **読み手**（`StatementReader`）は、ファイルを「欄の表」（番号を消した後の行と欄）にする部品で、差し替えられる: `{id, version, label, accepts(bytes, fileName) → 0〜1, table(bytes, kind) → {table, encoding?, issues, fixedMapping?, statementDate?}}`。一番大きい `accepts` の読み手を使う。段階1は `csv`（版1）と `pdfText`（版1）。段階2・3の読み手は `DEFAULT_READERS` に足す（取り込みの記録に読み手の id と版を残す）。
- **CSV**: 区切り（カンマ・タブ）を最初の数行から決め、RFC 4180 の二重引用符・欄の中の改行を読む。上限は2万行・100列・1欄500字。
- **文字コード**: BOM（UTF-8・UTF-16LE/BE）を先に見て、無ければ UTF-8 として厳密に読み、読めなければ Shift_JIS（Windows-31J）。全角・半角は NFKC でそろえる（半角カナ→全角カナ・全角英数字→半角）。
- **PDF（文字の入ったもの）**: 外の部品を使わずに読む（`statement/src/pdf/`。新しい依存を足さない。ライセンス・大きさの検査を増やさないため）。読むのは間接オブジェクト・オブジェクトストリーム・ページの木・フォント（ToUnicode の CMap・幅の表 W/DW/Widths）・内容のストリーム（FlateDecode・ASCIIHexDecode・PNG の予測子）だけで、JavaScript・埋め込みファイル・フォーム・注釈は読まない。暗号化された PDF は読まず「パスワードを外して保存し直して」と案内する。文字の無い PDF（画像だけ）は段階3と案内する。上限は 10MB・オブジェクト20万・展開後 60MB・200ページ。文字は位置から行（同じ高さ）と欄（横の隙間）にまとめる。
  - PDF に見出しの行（使った日・店・金額の言葉）があれば CSV と同じ列の対応付けで読む。無ければ「最初の欄が日付・最後の欄が金額」の行を読み、間の欄を店の名前・支払い方法にする（読み手が決めた対応付け）。
  - 明細の見出しの部分の日付（「2026年1月10日お支払い分」）を、年の無い日付（「12/03」）の年の手がかりにし、その日より後になる日付は前の年にする。
- **列の対応付け**（`ColumnMapping`）: `{headerRow: 見出しの行（0始まり）| null, columns: {役割 → 列の番号}, sign: "expensePositive" | "expenseNegative"}`。役割は 使った日 `date`・店の名前 `merchant`・金額 `amount`・出金 `withdrawal`・入金 `deposit`・その月に払う額 `payAmount`・払う月 `payMonth`・支払い方法 `plan`・分割の回数 `installmentCount`・何回目 `installmentIndex`・利用者 `user`・分類 `category`・メモ `memo`・振替の印 `transfer`。使った日・店の名前・金額（どれか）の列が要る。同じ列を2つの役割に使わない。
- **推し量り**: 最初の30行から見出しの言葉が一番多く当たる行を見出しとし、見出しの言葉（一般の言葉の一覧。`HEADER_WORDS`）から対応付けを推し量る。見出しが無ければ欄の形（日付・金額・文字）から推し量る。家計簿アプリ・銀行で金額の6割以上が負なら「支出が負」と読む。
- **覚える**: 見出しの並びの指紋（種類＋見出しの言葉をそろえた形の並びの SHA-256。見出しが無い表は欄の形の並び）で、FP が選んだ対応付けを覚え、次から同じ指紋・同じ種類の明細に使う（事務所データ。下の5）。推し量った対応付けは毎回 FP に確かめてもらい（`needsMapping`）、FP が確かめた・選び直したものを覚える。
- **値の読み方**: 金額はカンマ・円・`¥`・符号（`-`・`−`・`△`・`▲`・末尾の `-`）・括弧を読み、円の整数（0002）にする（小数のある金額・10桁以上は読まない）。日付は区切り・8桁・和暦（令和・平成・昭和・R/H/S）・2桁の年・年の無い月日（手がかりの年で補い、補ったことを行に残す。手がかりは表の中の年つきの日付・明細の見出しの日付。どちらにも年が無い明細は、取り込みの画面で FP が年を選ぶ。初めは推定の年（いちばん新しい月日が今日より後にならない年）で読む。選ぶ年はいちばん新しい月日の年で、月日を1年の輪に並べていちばん長い間の前をいちばん新しい月日とし、それより後の月日は前の年として読む（11月〜2月の明細の11月・12月は前の年））を読む。支払い方法は「1回・一括・分割3回・3回中2回目・2/3・リボ・ボーナス一括」を読む。合計・小計・残高の行は飛ばす。
- **プリセット**（カード会社ごとの決まった形）は、公開された説明で列の名前と並びを確かめられたものだけを足す。今回は確かめられる公開の説明が見つからなかったので、見出しの言葉の推し量りと FP が選んで覚える形だけにした（未確定の1）。他社のソフトの書き出しの形や明細の実物は写さない。テストの明細はすべて架空（`statement/test/fixtures/`。`scripts/fixtures.ts` で作る）。

### 4. 店の名前をそろえる・辞書・項目

- **店の鍵**（`merchantKey`）: NFKC・英字を大文字・ひらがな→カタカナ・小さいカナ→大きいカナ（半角カナの明細は小さいカナを書けないため）、決済サービスの前置き（`PAYPAY*` などの一般に見かける形。後ろに区切りがあるときだけ）を取り、空白の後ろの支店名（「〇〇店」「〇〇テン」「〇〇SS」など）と末尾の店の番号を取り、空白と区切りの記号を取る。64字まで。空白の無い名前の支店名は取らない（店の名前を削りすぎないため。辞書は前方一致で引く）。
- **辞書は2層**:
  - (a) アプリ同梱の最初の辞書（`statement/src/classify/builtin.ts`。版 `BUILTIN_VERSION`）。よくある全国チェーン・公共料金・通信会社・一般の言葉（「病院」「駐車場」「年会費」など）。一致の仕方は完全一致・前方一致（既定）・含む。強さは 完全一致＞前方一致＞含む、同じなら長い言葉。印: `annual`（年1回の候補: 自動車税・固定資産税・車検・年会費・年払いの保険など）・`engineTax`（所得税・住民税・社会保険料。計算で出すので除外）。カード会社への引き落とし（カード会社の名前の一覧 `CARD_ISSUERS` と、どの会社か分からない「カード」「クレジット」）は銀行の明細だけで見る。
  - (b) FP が直した結果を覚える辞書（事務所データに暗号化。下の5）。行は `{key: 店の鍵, category, annual?, at, by?, removed?}`。同梱の辞書と同じ答えは覚えない（太らせない）。覚えた違う答えを同梱の答えに直したときは、消した印の行（`removed`）で消す。上限は事務所全体で2万行（古い行から外す）。
- **引き当ての順番**: FP がその行で決めた項目 → 家計簿アプリの振替の印 → 覚えた辞書（完全一致）→ 同梱の辞書のカード会社への引き落とし → 家計簿アプリの分類の言葉 → 同梱の辞書 → 分からない（迷う行）。
- **自動の仕分けの結果は保存しない**。毎回、行と FP の決めたことと辞書から作り直す（辞書が良くなれば、まだ決めていない行も良くなる）。
- **項目**（`StatementCategory`）は、日本FP協会の家計の分け方（基本生活費・住居関連費・車両費・教育費・保険料・その他の支出・一時的支出）とアプリの既存の言葉に合わせる:

### 5. 事務所データ（覚えた辞書と覚えた形）

- 覚えた辞書と覚えた形（`{fingerprint, kind, mapping, label?, at, by?}`。上限500）は、事務所全体のデータとして事務所データ（暗号化）に持つ（0011 の6。欄 `statement`。欄の無い古い事務所データは空）。世帯ファイルには入れない。店の鍵と項目・列の対応付けだけで、金額・日付・お客さまの情報は持たない。
- **事務所で共有しているとき**（0023。1人で複数の PC の同期フォルダ 0024 も同じ）は、共有フォルダの `lifeplan-office/statement-dict/<メンバーID>.lpsd` に、そのメンバーが覚えた行だけを書く（識別の印 `LPSD`・形式名 `lifeplan.statementDictionary`。0011 の1 と同じ容器で、事務所の親鍵から用途 `lifeplan/statement-dictionary/v1` で導いた鍵で暗号化。見出し全体を改ざん検出の対象にする）。メンバーごとのファイルにするのは、同期サービスの上で2人が同じファイルを書き合わないため。
- 読むときは、名簿にいる全員のファイルと PC の中の写しを合わせる。同じ鍵の行は**日時の新しいほう**、同じ日時なら消した行、次にメンバーID の大きいほう（どの PC でも同じ結果。画面の側の `mergeEntries` と本体の `statement_dict::merge` は同じ決まり）。読めないファイル（30日を過ぎた前の親鍵など）は飛ばし、PC の中の写しで使い続ける。外したメンバーのファイルも事務所の辞書として読む（0023 の追記 2026-11-04。外した人が知らない親鍵で書かれたものだけ）。
- 直した人（`by`）は、本体が自分のメンバーID を入れる（呼んだ側の値は使わない）。1人で使うときは持たない。1回に覚える行に形の合わないものが1つでもあれば、何も覚えない。
- 本体の呼び口: `Store::statement_office()`（合わせた辞書と形）・`Store::statement_learn(entries, formats)`。

- 行は、読み手が返した値（番号を消した後）と店の鍵、FP が決めたこと（持ち主 `owner`・項目 `category`・区分 `bucket`・割合 `share`・決めた日時 `decidedAt`）。自動の仕分けの結果は持たない。
- `period` は使った日の最初と最後（FP が直せる。12か月分の明細の初日・末日に直すと月平均が正しくなる）。
- 1つの世帯の行は合わせて5万行まで。
- `requests` の `rows` はシートの番号 → 取り込みの ID と行の ID。店ごとにまとめたシートの1行は同じ番号が並ぶ（上の例の 2。形式 0.16 から。追記「店ごとにまとめる」）。同じ取り込みの同じ行は1回だけ。
- **持たないもの**: 元のファイル、ファイル名（名前が入りうるため）、番号を消す前の文字、振込の相手の名前、利用者の名前。
- **渡さないもの**: AI接続口の縮約版（0015 の6。縮約版は計算の要求からだけ作るので、この区画は入らない。テストで確かめる）、持ち帰り用のレポート（0030）。不具合報告の匿名化した書き出し（0020 の4）では、取り込みの記録としてこの区画を外す（書き出しを作る回で実装する）。全データの書き出し（0020）には入る（世帯ファイルの公開形式そのもの）。

### 7. 区分（どこに入るか）は働き方で変える

| 働き方 | 選べる区分 |
|---|---|
| 会社員（正社員・契約・パート・公務員・休業中） | 家計／立替（会社に請求する分）／一時的／除外 |
| 個人事業主 | 家計／事業の経費（**割合で分けられる**）／一時的／除外 |
| 法人役員 | 家計／会社の経費／一時的／除外 |
| 働いていない・持ち主の無い口座（共用） | 家計／一時的／除外 |

- 働き方は、行の持ち主（行で選んだ構成員 → 明細の持ち主）の、計算基準日の月の働き方の期間から決める（`at` と「○歳になった月」の時点を読む）。副業のように1人が2つの働き方を持つときは、FP が `styles` で足す（選べる区分は足し合わせ）。
- **複数の働き方の世帯**（夫は会社員・妻は個人事業主）は、明細ごとの持ち主と、行ごとの持ち主（家族カードの行を配偶者にする、など）で分かれる。
- 決まり方の順番: FP がその行で決めた区分（持ち主の働き方で選べなければ使わず、迷う印「選べない区分」を付ける）→ 世帯の決まり（店の鍵の決まりが項目の決まりより強い。持ち主を決めた決まりはその人の行だけ）→ 自動（カードの引き落とし・計算で出す税・振替・収入は除外、年会費・一時的な支出・年1回の候補は一時的、ほかは家計）。
- **割合の按分**: 割合は 0 より大きく 1 以下の10進の文字列（小数4桁まで）。事業の分＝金額×割合を切り捨て、残りを家計に入れる（返品の負の金額も同じ割合で戻す）。立替・事業・会社の分は家計から外し、持ち主ごとの月平均として別に出す（参考）。
- 個人事業主・法人役員の行のうち、通信・交通・車・交際・家具家電・教養娯楽・その他・分からない店で区分を決めていないものは「区分が決まらない」の迷う行にする（会社員の立替は FP が選ぶときだけ）。

### 8. カードならではの扱いと、計算に使う数

- **二重に数えない**:
  - 銀行の明細の「カード会社への引き落とし」は、そのカードの明細がその頃（引き落としの日の62日前から当日まで）を覆っていれば自動で除外する。どのカード会社か分かる引き落としは、同じ `issuer` のカードの明細だけで覆う（カード会社を決めていないカードの明細は、どの引き落としも覆う）。覆う明細が無ければ**除外せず家計に入れ、知らせる**（迷う行）。
  - 同じ口座の別の取り込みに出た同じ行（使った日・店の鍵・金額・分割の回数が同じ）は数えない（分割の2回目以降の行・期間の重なった明細）。同じ取り込みの中の同じ行は別の買い物として数える（数の多いほうだけ数える）。別の口座の同じ行は重ねない。
  - 返品・取り消し（負の行）は、同じ口座・同じ店・同じ額の正の行を前の120日から探して組にし、両方とも数えない。元の行が無ければ、その月の項目から差し引いて知らせる。
- **分割・リボ**: 回数を読み、月平均は使った日の全額で数える。払う月ごとの金額（`paymentSchedule`）は、分割を回数で分け（端数は1回目）、払う月の欄が無ければカードは使った月の翌月から。リボは払う月が分からないので外して件数を知らせる。
- **年会費**は一時的の候補。**家族カード**の行は印を付け、行ごとに持ち主を選べる。
- **使った日と払う月のずれ**: 生活費の月平均は**使った日**で数える（払う月では数えない）。
- **年1回の支払い**: 店の鍵ごとに、(1) 約1年おき（330〜400日）・似た額（2割以内）で2回以上なら確かさ高・毎年、約2年おき（700〜760日）なら確かさ高・2年に1回、(2) 辞書の年1回の印があり1回だけなら、その口座の期間が1年分（335日以上）あれば確かさ中、無ければ低、(3) 印が無くても、ふだんの買い物（食費・日用品・水道光熱・通信・交通・現金）でない3万円以上の1回だけの支払いは、1年分の期間があれば確かさ中、期間が足りなければ10万円以上を確かさ低。確かさ中・高は区分を一時的にする。低は「年1回かは分からない」の迷う行にする。分割の買い物は年1回にしない（高額の印で見せる）。
- **高額**: 1行10万円以上で家計に入っている行（年1回の候補でないもの）は「高額（一時的か迷う）」の迷う行にする。
- **月平均の出し方**: 口座・カードごとに、取り込んだ期間（明細の期間を合わせた日数。重なりは1回）で割って月平均にし、足し合わせる（期間の違う明細を混ぜても少なく出ない）。月平均＝合計×365.25÷12÷日数（整数の計算で四捨五入。`1461/48`）。年1回の支払い（一時的）は月平均に入れず、一時的支出として別に出す。
- **12か月に満たないとき**: 同じ出し方（季節の補正はしない）。期間が1年分（335日。使った日から出す期間は12か月分でも365日より短く出るため）に満たなければ注意を出し、水道・光熱などの季節で変わる項目は偏ると知らせる。3か月（85日）に満たなければ強い注意を出し、候補を要確認にする。年1回の支払いは見つけきれないことがあると知らせる。
- 出す数（`StatementSummary`）: 口座ごとの期間、全体の期間と月の数、基本生活費の内訳ごとの月平均と内訳の項目、合計、分からない店の月平均、参考の値（住居・教育・保険・車・税の月平均）、家計から外した分（持ち主ごと）、一時的支出（店ごとの回・1回の額・年の額・年1回の確かさ）、迷う行の数、注意。

### 9. 候補に落とす・迷う行

- **候補**は 0008 の5 の差分と同じ形 `{id, target, item, op, value, before, enabled, origin: {kind: "import", ref}, source: "import", sourceRef, status: "pending" | "needsReview", confidence?}` に、画面の見出し `title`・説明 `note`・一覧 `collection` を足したもの。出どころ `import` は承認の記録が要る（計算エンジンのスキーマ）。`ref` は候補を取り込んだ記録（`applied` の ID）。
- 値の箱は推定（`state: "estimated"`・`estimate.method`: `statementAverage`（月平均）・`statementAnnual`（年1回）・`basis`: 期間と月の数）。
- 取り込む先は入力の既存の欄:
  - **基本生活費**: 今の欄が内訳（`byCategory`）なら内訳を置き換え（明細に出てこない内訳＝仕送りなどは今の値を残す）、合計（`total`）なら合計を置き換え、無ければ内訳の欄を足す（伸び方は物価に合わせる）。
  - **年1回の支払い**（確かさ中・高）: 名前を付けた支出（`periodicExpenses`）を足す（行は項目から選ぶ。次の回は最後の回の月を計算基準日の後まで進めた月、`everyYears` は1か2、終わりは無し）。保険・教育・税は、それぞれの欄で入れるので候補にしない（参考の値と一時的支出の一覧に出す）。同じ名前の支出があれば要確認。
- 期間が3か月に満たない・迷う行が残る・年1回の確かさが中のときは要確認（`needsReview`）。FP がチェックした候補だけを、承認の記録 `{by: "fp", at, candidate}` を付けて入れる（`applyCandidates`）。取り込んだことは `applied` に残す。
- **迷う行の一覧**（`reviewList`）: 辞書で分からない・区分が決まらない・選べない区分・高額・年1回かは分からない・カードの引き落としを除外できない・リボ・元の見つからない返品。重い印から、同じなら金額の大きい順。分からない店は店の鍵ごとにまとめ（`unknownMerchants`）、1回で決められるようにする。FP が決めた行（`decidedAt`）は迷う行から外す（選べない区分の印は残す）。
- FP が決めたこと（`RowDecision`: 項目・区分・割合・持ち主。`null` で取り消し）は行に書き（`applyDecisions`）、項目を直したら覚える辞書の行を作る（`learnFromDecisions`。本体の `statement_learn` へ）。区分・割合は世帯ごとに違うので、事務所の辞書には入れず、世帯の決まり（`addRule`）にする。
- `requests`（形式 0.15 から。任意）は確認シート（下の9 の最後）の依頼の記録。店ごとにまとめたシートの1行は、同じ番号に複数の行を結ぶ（形式 0.16 から）。
- **前もってお客さまに印を付けてもらう Excel**（2026-10-23 の追記「確認シート」で実装した。ここは最初の設計）: ヒアリングシートの Excel の仕組み（0018 の .xlsx の書き出し・取り込み・管理の値を3か所に埋め込む・返ってきたファイルを信用しない）に乗せる。
  - 書き出すのは迷う行だけ（使った日・店の名前（番号を消した後）・金額・今の項目の案）と、選択肢の欄（項目・「家計／仕事で使った（会社に請求・事業・会社）／一時的／分からない」）とメモの欄。
  - 行は世帯の内部ID・取り込みの ID を書かず、依頼ごとの通し番号（`1`〜）で結び、依頼の記録（依頼番号・行の番号→取り込みの ID と行の ID の対応・書き出した日時）を世帯ファイルの `statements` に暗号化して残す（0018 の2 と同じ考え方。依頼の記録を足す欄は次の回で決める）。
  - 暗号化されない Excel に店の名前と金額が載るので、書き出す前に警告する（0018 の9 と同じ）。
  - 取り込んだ答えは決めたことの候補として見せ、FP が承認したものだけを `applyDecisions` に渡す。

### 10. AIに聞く仕分け（段階4。設計だけ。今回は実装しない）

- **最初はオフ**。事務所の設定で AI接続口（0015）がオンで、かつ FP がこの機能をオンにしたときだけ使える。
- 送るのは **FP が選んだ行の店の名前だけ**（番号を消した後・そろえる前の表示の名前）。金額・日付・持ち主・口座・お客さまの情報・世帯の内部ID は送らない。**送る前に画面で一覧を見せ**、FP が確かめてから送る。
- 道は2つ:
  - **AI接続口（MCP）**: 0015 の2 の道具の群に「明細の店の名前」を足す（移行の見出しの群と同じ扱い。FP が画面で「AIに店の名前を渡す」を押したときだけ使える）。道具の初期案は `get_statement_merchants`（渡すことにした店の名前の一覧と、選べる項目の id と言葉）と `propose_merchant_categories`（「店の名前 → 項目」の案を返す。大きさの上限つき）。案は候補として受け、FP が承認したものだけを覚える辞書に入れる（`learnFromDecisions` と同じ道）。店の名前は人が書いた文章ではないが、`client_text` と同じ包み方（0015 の6）で渡す。渡したこと（いつ・何件・指紋）は AIに渡した記録（0014）に残す。
  - **ウェブのチャットAI**: 店の名前の一覧と聞き方の文面をコピーし、FP が貼り付ける。返ってきた答え（決まった形の表）を貼り戻すと、候補として読む（返ってきた文面を信用しない形で読む）。
- 世帯の外部AIへの提供の同意（0014）が無い世帯でも、店の名前だけなら送ってよい（2026-10-23 に決定。送る前に画面で一覧を見せる・既定はオフ・FP が選んだ行だけ、は同じ。追記）。

## 理由

- **読む・仕分けるを PC の中で**: 明細は顧客の暮らしがそのまま出る情報で、提供元が顧客データを受け取る経路を作らない方針（0012）に合わせる。
- **番号を読んだ時点で消す・2回通す**: どこかの処理で消し忘れても、保存・画面・AI のどこにも番号が出ないようにする。読み手を差し替えられる作りなので、共通の処理でもう一度通す。
- **元のファイルを持たない**: 元のファイルには名義人の名前・住所・カード番号の全桁が入りうる。指紋があれば、同じファイルの2回の取り込みと、どのファイルから来たかは確かめられる。
- **欄の表＋列の対応付け**: CSV・PDF・写真（段階3）のどれも「欄の表」にしてしまえば、対応付け・覚え方・値の読み方を1つにできる。
- **自動の仕分けの結果を保存しない**: 辞書は事務所で育つので、保存した結果は古くなる。FP の決めたことだけを保存すれば、作り直しても FP の判断は消えない。
- **事務所の辞書は店の名前と項目だけ・区分は世帯の決まり**: 「この店は食費」は事務所で共有できるが、「通信の6割は事業」は世帯ごとに違う。
- **口座ごとの期間で割る**: 夫のカードは12か月分・妻のカードは3か月分のように期間が違う明細を1つの期間で割ると、短い明細の分が少なく出る。
- **使った日で数える**: 払う月で数えると、分割・締め日・ボーナス払いで月がずれ、生活費の実感と合わない。
- **候補にして承認**: 明細から出す数は推定で、迷う行が残ることもある。ヒアリング・AIの案と同じ承認の道に乗せれば、承認の記録・出どころが同じ形で残る。
