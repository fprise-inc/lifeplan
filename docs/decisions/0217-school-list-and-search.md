# 0217. 学校の一覧（学校コード）と学校名の欄の探し方（学費を学校から出す第1段）

- 状態: 採用（一部未確定）（2026-11-16）
- 固定の強さ: 学校の主キー（学校コード）・段に持つ形（`goals[].education.stages[].school` の `{school, unit, rows, source}`。0010 の9）・パックの ID `master.education.schools` は 0010 の骨格のまま。正本の CSV の列・別名の辞書の形・画面に配る形・探し方の並び・候補の見せ方は内部（後から変えてよい）
- 前提にする記録: 0010（学費データ。学校コードを主キーに・別名の辞書・平均で補う段）、0062（子ども・教育の入力項目。学校名は「同梱まで見せるだけ」だった）、0018（ヒアリングシートの学校名は自由記述で受け、取り込むときに照合する）、0021（ライセンス）、0035・0011（世帯ファイルの形式の版）

## 背景

- 0010 の2・追記（2026-10-09）で、学校名は打つたびに候補が絞られる部分一致の検索にし、学校を選んだら学部・学科を選び、候補の一番上に「学校未定（平均で計算）」を置くと決めていた。学校の一覧を同梱していなかったので、0062 の学校名の欄は「学校未定」を見せるだけだった。
- 学費の学校別の実データ（国立大学の全校・私立大学の医・歯・薬・獣医・東京都の私立中学・高校）は次の段で入れる。その前に、学校を一意に指せる一覧と探し方、選んだ学校を世帯に持つ所を作る。
- 文部科学省は「学校コード」（13桁。学校種2桁・都道府県番号2桁・設置区分1桁・学校番号7桁・検査数字1桁）を全学校種に付け、一覧（学校名・所在地・廃止の日・移行後の学校コード）を年1回公開している（文部科学省ウェブサイト利用規約。CC BY 4.0 と互換。商用の利用もできる）。一覧に学校名の読みは無い。

## 決定

### 1. 学校の一覧のデータ（`data/schools/`）

- 出典: 文部科学省「学校コード一覧」令和8年5月1日時点（暫定版。一覧の更新日 2026年5月20日）の CSV の4つ（幼稚園〜各種学校の東日本の2つ・西日本の1つ、大学・短期大学・高等専門学校の1つ）。文部科学省の「学校コード」のページ（https://www.mext.go.jp/b_menu/toukei/mext_01087.html ）から 2026-11-15 に取った。ファイル名・URL・取得日・指紋（sha256）は `pack.yaml` の `sources`。進学情報サイト・学校の一覧を集めたサイトからは取らない。
- 正本は `schools.csv`（列: 学校コード・学校種・都道府県番号・設置区分・学校名・市区町村・廃止の日・移行後の学校コード。0010 の未確定「正本を CSV にするか YAML にするか」は CSV に決めた）。`app/scripts/school-list-import.ts <取った CSV のフォルダ>` で作り直せる（取った CSV の指紋が `pack.yaml` と合わなければ止まる）。
  - 所在地と郵便番号は持たない。候補の見分けに使う市区町村だけを所在地から切り出す（公立の学校の名前「○○市立」から集めた市区町村の名前を先に当て、政令指定都市は区まで、郡は外す）。名前の中に市・町の字がある市（四日市市・大町市など）を字の位置だけで切ると誤るため。
  - 移行後の学校コードが自分自身の行（一覧に2つ）は、移行先なしと読む。
  - 検査数字が合わない学校コードが一覧に 212 ある（60,285 校のうち）。一覧のコードが文部科学省の正なので、誤りにはせず数だけを確かめる（急に増えたら取り込みの誤りを疑う）。
- **入れた学校種は全部**（13種・60,285校。うち廃止していない 55,593校）:

### 2. 画面に配る形と大きさ

- 画面の準備（`app/scripts/prepare-assets.ts`）が、正本の CSV と辞書から `app/src/generated/schools.data.js`（JSON の文字を1回で読む形。学校1つは `[学校コード, 学校名, 市区町村の番号, 読み, 廃止の日, 移行先]`、学校種・都道府県・設置区分は学校コードから読む）を作る。リポジトリには入れない（作った物）。
- **画面の初めの読み込みに入れない**。学校名の欄が描かれたときに遅れて読む（別のファイルになる）。読み方の登録は画面だけ（`input/schoolLoader.ts`）で、AI接続口の1つの JS には入れない。
- 大きさ: 3.73MB（gzip で約0.73MB）。読み込み 約35ms・索引を作る 約145ms・1回の検索 約3ms（手元の Mac、Node）。デスクトップのアプリに同梱するので、通信の量ではなく初めの描画の速さが問題になるが、遅れて読むので入力の画面を開く速さは変わらない。
- 別の案（採らなかったもの）:
  - 公立の小学校・中学校を外す（約2.6万校減って約半分）: 公立の小学校・中学校は学区で決まり学費の差も無いが、学校名を入れておきたい（面談の記録・ヒアリングシートの照合）FP もいる。全校分と決めていたので外さない。大きさが問題になれば、学校種ごとに分けて段の欄を開いたときにその学校種だけ読む形にする（形を変えずにできる）。
  - 計算エンジンのパックとして配る（署名つきの更新。0017）: 一覧は計算に使わない（学費の実データの行を世帯に写して計算する。0010 の9）ので、今は画面に同梱する。学費の実データ（第2段）を配る形と合わせて決める（未確定）。

### 3. 探し方（`app/src/workspace/input/schools.ts`）

- 部分一致。比べる前に、全角半角（NFKC）・大文字小文字・カタカナをひらがな・旧字体を新字体（藝→芸・應→応・髙→高・﨑→崎など、学校名で使われる字だけ）・「ヶ」を「け」にそろえ、空白・中黒・記号のハイフンを外す。一覧の名前は変えない。
- 引ける物: 学校名・読み（辞書にある学校）・略称と別の表記（辞書）・旧校名（廃止した学校のうち、移行先〔一覧の移行後の学校コードと辞書の補い〕をたどった先が今ある学校。名前が同じなら移行先の名前で引ける）。
- 並び: 全部一致 → 前方一致 → 途中の一致。同じなら学校名 → 読み → 略称・別の表記 → 旧校名、名前の短い順、学校コードの順。同じ学校は1回だけ（いちばん合う引き方で）。候補は30件まで出し、残りは「ほか n 件（続けて打つと絞り込めます）」。
- 段に合う学校種だけを候補に出す（1 の表）。インターナショナルスクールを選んだ幼稚園〜高校の段は各種学校も出す。
- 同じ名前の学校（例: 「さくら幼稚園」は14校）は、候補の2行目「都道府県＋市区町村・国立／公立／私立・学校種」で見分ける。

### 4. 学校名の欄（`app/src/workspace/input/schoolField.ts`）

- 欄は詳細（今までどおり）。打つ欄と候補の一覧（`FieldViews.tsx` の `SearchPicker`。上下で選ぶ・Enter で決める・Esc で閉じる）。欄の定義は選ぶ欄（`kind: "select"`）のまま、打って選ぶ欄の定義 `search` を足した（確かめの一覧・往復のテストは選ぶ欄と同じに扱う）。
- 候補の一番上はいつも「学校未定（平均で計算）」。選ぶと段の `school` を外し、今までどおり公立・私立と系統・通い方の平均で計算する。
- 学校を選ぶと、段に `school: {school: 学校コード, unit: 学校コード, rows: [], source: {pack: "master.education.schools", version}}` を持つ。**学費の実データの行はまだ無いので `rows` は空**で、計算エンジンは行の無い学校を前から平均で計算する（`education.cost` は `rows` が1行以上のときだけ学校の行を使う）。部局（学部・学科）が無いときの `unit` は学校コードと同じ（0010 の3）。
- 選んだ学校の設置区分に、段の公立・私立の欄を合わせる（国立の学校は国立。その段に国立が無い幼稚園・短大・専門学校は公立。インターナショナルスクールは変えない）。前の推定の年額・入学金は、公立・私立を変えたときと同じく外す（0062 の追記 2026-10-30）。学校が私立なのに平均が公立のまま、のような食い違いを作らないため。後で公立・私立の欄だけを変えて合わなくなったら、欄の下で知らせる。
- 欄の横に、選んだ学校の所在地・国立公立私立・学校種と、「学費の実データはまだ無いので、〔使っている平均。統計名と年度〕で計算しています」を出す（0010 の7）。
- 選べない学校: 段に合わない学校種（大学の段で附属高校など）と、廃止した学校。理由を欄の下に出し、世帯は変えない。
- 前に入った廃止した学校のコードは黙って書き換えず（0035 の11）、「この学校は〜の時点で廃止され、〇〇に移っています」と「〇〇にする」のボタンを出す。移行先が無ければ選び直すよう知らせる。一覧に無い学校コードも知らせる。
- 学部・学科の欄は、学校の学部・学科の一覧（配る形の `departments`）がある学校だけに出す。今は一覧の中身が無いので出ない（第2段）。選ぶと `unit` を `<学校コード>/<部局ID>` にする。

### 5. ヒアリングシートの学校名の照合の土台（0010 の9・0018）

- ヒアリングシートの「考えている学校名」の自由記述は、取り込みの記録（`hearing.imports[].answers`）に元の文字のまま残っている。照合して確定した学校コードは、段の `school.school`（FP が候補から選んだとき）。新しい欄は足さない。
- 学校名の欄が学校未定のとき、その子の自由記述を欄の横に「ヒアリングシートの学校名: 〜」と出し、欄に入ると、その文字で探した候補を「ヒアリングシートの学校名『〜』の候補」として出す（何も打たなくても候補が出る）。黙って学校を決めない。
- 照合の関数 `matchSchoolText`: そのまま探し、見つからなければ括弧の中（「（第一志望）」）を外し、次に読点・スラッシュの前だけで探す。
- 何番目の子かは、取り込みと同じ数え方（生年月の入った子を順に、世帯の子の並びに当てる）で読む。取り込んだ後に子を足して並びが変わると、別の子の学校名が出ることがある（候補を出すだけで書き換えないので、ずれても計算は変わらない）。

### 6. 世帯ファイルの形式の版

- **上げない**（今の 0.78 のまま）。段の `school`（学校コード・`unit`・`rows`・`source`）は 0010 の9 で前からあり、`rows` を空にした形も今のスキーマ（`engine.input.json` の `schoolTuition`）で通る。ヒアリングシートの元の文字も取り込みの記録の中に前からある。
- 古い世帯（学校名が空）はそのまま読み、学校未定で見せる。

## 理由

- **全学校種を入れる**: 学校コードは全学校種で同じ形なので、段ごとに選べる学校種を決めるだけで済む。学費の実データを入れる範囲（第2段）が広がっても一覧を作り直さなくてよい。大きさは遅れて読むことで初めの描画に効かない。
- **読みを推測で作らない**: 公式の一覧に読みが無く、学校名の読みは固有名詞で推測が外れやすい（誤った読みは検索の誤りになり、気づきにくい）。辞書の欄 `readings` だけ用意し、学校の公式の表記で確かめた学校から足す。カタカナの名前はひらがなで打っても引け、漢字の名前は漢字・略称・旧校名で引ける。
- **公立・私立を学校に合わせる**: 実データの無い学校は平均で計算するので、選んだ学校と平均の区分が違うと、学校を選んだのに違う区分の平均で計算することになる。
- **`rows` を空にして学校コードを持つ**: 0010 の9 の形のまま、実データが入ったら同じ所に行を写せる。エンジンは行が無ければ前から平均で計算するので、計算は変わらない。
