# 0084. 対策に最初から出す項目（事務所の既定値）と既定の4項目・配偶者の働き方と年収・対策の欄の列

- 状態: 採用（一部未確定）（2026-10-29）
- 固定の強さ: 内部（画面の見せ方と事務所データの任意の欄）。事務所データの `defaults.levers` は足すだけの形。「見せ方だけで値も計算も変えない」「選んだプランで値が入っている項目は隠さない」「世帯には写さず、世帯ごとには持たない」の3つは、変えるときは追記に書く。合成の対策 `spouseWork` の名前は使い回さない（0036 の3）。既定の組み合わせ・選べる種類・文言・列の数は後から変えてよい
- 前提にする記録: 0008（2026-10-17 の追記の6: 動かす項目の一覧）、0016（主画面の ③ 対策）、0035 の9（読み替え表）、0036（差分の型・合成の対策）、0073（事務所の既定値）、0083（入力項目の選び方）

## 背景

- 主画面の対策に最初から出る項目は、どの世帯でも同じ5つ（働く最後の年齢・年金の受け取り開始・NISA の積立額・毎月の生活費・FP顧問料）だった（動かす項目の `builtin`）。ほかの項目は、世帯を開くたびに「＋ 動かす項目を追加」で足していた。
- 事務所によって、いつも動かす項目が違う（住宅ローンの金利を毎回見る、運用の利回りを毎回見るなど）。顧問料を取らない事務所では、FP顧問料の切り替えは要らない。
- 既定の組み合わせは、使う人の判断で4つにした（決定の2）。後で決め直せるよう、差し替えは1か所にする。

## 決定

### 1. 選べる種類

- 対策の固定の項目5つと配偶者の働き方と年収（6 で足した項目）、「＋ 動かす項目を追加」の資産運用（6つ）・貯まり方（1つ）・よく使う項目（住宅ローンの借入額・繰上返済・金利、変動金利の上昇、資産運用の配分）。種類の一覧は `app/src/workspace/plans/leverChoice.ts` の `LEVER_KINDS`。
- **入力の欄そのものを動かす項目（キーが `field:` の物）は対象にしない**。入力の欄の数だけあり（世帯の物の数で増える）、欄のキーは物の ID を含むので、事務所で種類として選ぶ単位にならない。今までどおり「＋ 動かす項目を追加」で足す。
- 世帯ごとに1つずつある項目は**種類で選ぶ**: `loan:principal`・`loan:prepay`・`loan:rate`（ローンごと）、`mix`（口座ごと）。選ぶと、その世帯の当てはまる物すべての項目が出る（例: 「住宅ローンの金利」で、ペアローンなら2本とも）。当てはまる物が無い世帯には出ない。借入額と繰上返済は、借入が始まっているかでローンごとにどちらかになる（0008 の追記の6）ので、別の種類にした。
- どの動かす項目も、`field:` でなければ種類を持つ（テストで確かめる。項目を足したら種類も足す）。

### 2. 置き場所と形

- 事務所データの `defaults` の中の足すだけの欄 `levers`（0073 の1）: `{ shown?: 種類[], hidden?: 種類[] }`。**既定の組み合わせとの違いだけ**を持つ（入力項目の選び方 `itemChoice` が「全部出す」との違いを `hidden` で持つのと同じ考え方）。`shown` は既定に無いが出す種類、`hidden` は既定にあるが出さない種類。
- 読むとき（`readOfficeSettings` → `readLeverChoice`）は、知らない種類・文字でない値・重なりを捨て、一覧の並びにそろえる。両方にある種類は「出さない」。欄の無い古い事務所データ・読めない値は空（既定のまま）で、今と同じ動きになる。事務所データの形式の版は上げない。
- 既定の組み合わせは `DEFAULT_LEVER_KINDS` の1か所。**働く最後の年齢・年金の受け取り開始・毎月の生活費・配偶者の働き方と年収の4つと、FP顧問料**（顧問料の契約がある世帯だけ出る。4つには数えず、4つの後ろに出る）。NISA の積立は既定から外した（「＋ 動かす項目を追加」の見出し「対策」で足せる。事務所の設定で戻せる）。世帯に出せない項目（配偶者がいない・顧問料の契約が無いなど）は、その分を詰める。**差し替えると、事務所が足した・外した種類はそのままで、触っていない種類は新しい既定に従う**（全部を写して持つ形にすると、既定を良くしても、一度でも保存した事務所には届かない）。

### 3. 世帯には写さない・世帯ごとには持たない

- 見せ方だけで計算の数に効かないので、新しい世帯に写す決まり（0073 の3）は当てない。入力項目の並びと同じく、画面がその場で読む。変えると、作った世帯も含めてどの世帯の対策にもすぐ効く。
- 世帯ごとの選び方は作らない。その場で「＋ 動かす項目を追加」で足せる（足した項目は今までどおり作業の状態の `shownItems`）。

### 4. 対策に出す項目

- 出すのは (1) 最初から出す項目、(2) 「＋ 動かす項目を追加」で足した項目、(3) **選んだプランで値が入っている項目**（最初から出さない種類でも出す。0083 の4と同じく、黙って値を隠さない）。
- 最初から出す項目は外せない（「外す」を出さない）。(2)(3) は外せる（動かした値は現状に戻す）。最初から出さない項目を動かすと、足した項目にする（値を現状と同じに戻しても、動かしている途中で消えない）。
- 並びは一覧の並びのまま: 対策の固定の項目（専用の形）→ 最初から出すほかの項目（配偶者の働き方と年収など。一覧の並び）→ FP顧問料 → 足した項目（足した順）→ 値が入っている項目（一覧の並び）。**並びを選ぶ設定は作らない**。
- 見本の世帯のプランで NISA を動かしている物（見本のプラン・最初のプラン）は、値が入っているので今までどおり NISA が出る（見本のプランは崩れない）。
- 最初から出さない対策の固定の項目は、「＋ 動かす項目を追加」の一覧に見出し「対策」で出る。足すと、対策の上に今までと同じ専用の形で出る。最初から出す項目は一覧に載せない。

### 5. FP顧問料を外す

- 顧問料を取らない事務所のため、FP顧問料も外せる。外すのは切り替えを出さないことだけで、計算は変わらない: プランに値が無ければ、契約の「現状にも入れる」のとおり（足したばかりの契約は現状に入れないので、顧問料は0のまま）。プランで「入れる」にしてあれば、切り替えも出し、計算にも入る。

### 6. 配偶者の働き方と年収（新しい動かす項目）

- 1つの項目で、配偶者の今の働き方の種類（入力の「働き方」と同じ選択肢。休業中は今が休業のときだけ出す）と1年の収入（給与は賞与込みの年収、自営業は事業所得）を動かす。キーは `spouse:<構成員の ID>:work`、値は `{type, annual}`。**働き方と年収を2つの項目に分けなかった**: 働き方を変えると年収の意味（給与か事業所得か、0円か）と目安が変わり、別々に動かすと「パートにしたのに年収は正社員のまま」のような組み合わせが途中にでき、計算と見出しの文がちぐはぐになる。1つの項目なら、種類を選び直したときに年収をその種類の目安にそろえられる（入れていた年収は残す。働いていなかったときだけ目安にする）。
- 当て方: 計算基準月にしている（無ければこれから始まる）働き方の期間の種類を変え（入力で働き方を選び直したのと同じ `convertPeriod`。要る欄を足し、要らない欄を外す）、年収を入れる（給与は今の賞与の割合で年収と賞与に分ける。推定のままの標準報酬月額は新しい年収に合わせる）。働いていない配偶者で期間が無ければ、計算基準月から65歳になる前の月までの期間を足す。働く期間（始まり・終わり）は変えない（入力で直す）。
- 出さない世帯: 配偶者がいない。今もこれからも働き方の期間が無く、もう65歳を過ぎている（足す期間が作れない）。
- 保存: 1つの値をそのまま書かない（種類を変えると複数の欄が変わる）ので、合成の対策 `spouseWork`（構成員を持つ）として差分に書く（0036 の3）。0.16 の読み替え表は凍結しているので行を足さず、画面の鍵と合成の対策を行き来する表を後ろに足した（`store/readings.ts` の `LATER_ENTRIES`。世帯ファイルには鍵を書かないので、本体の 0.16 → 0.17 の変換の段は読まない）。差分の当て方・入力画面でプランを直したときの置き場所（働き方と収入の入力項目）も、ほかの合成の対策と同じ。
- 入力の欄の項目（`field:work/period/…/annual` など）はそのまま残る（別の項目として足せる）。

### 7. 対策の欄の列

- 対策の欄の1行の数を 4 → 2 → 1 にした（前は 4 → 3 → 2）。区切りは 1260px で2列、760px で1列。大きな文字は 2 → 1（980px で1列。前は 3 → 2）。3列の途中をなくしたのは、既定の4項目が「3つと1つ」に割れて、2行目に1つだけ残らないようにするため。1列の区切りは、2列で1項目の幅が目盛りの数字と基準の札を1行に並べられる（約330px）うちは2列にする幅にした。
- 万一のときのタブの想定の前提（`.cg-premises .lv-grid`。前は 3 → 2 → 1）も同じ 4 → 2 → 1（大きな文字は 2 → 1）にそろえた。

### 8. 画面

- 事務所の既定値のパネルに区画「対策に最初から出す項目」を足した（入力項目の選び方の区画の次）。見出し（対策・資産運用・貯まり方・よく使う項目）ごとに種類のチェックと、ローン・口座ごとの種類の短い注記。「標準に戻す」で既定に戻す。保存の知らせに「対策に最初から出す項目は、どの世帯にもすぐ効きます」を足した。

## 理由

- 配偶者の働き方と年収を既定に入れた: 共働きにする・パートの時間を増やすは、退職の年齢・年金・生活費と並んで面談でいつも試す打ち手で、毎回「＋ 動かす項目を追加」で足していた。NISA の積立は、積立額より運用の期間・取り崩しで見ることが多く、資産運用の項目から足せる。
- 種類で選ぶ: ローン・口座の ID は世帯ごとに違うので、事務所の既定値には種類しか書けない。
- 違いだけを持つ: 2 のとおり、後で既定を決め直したときに、事務所が触っていない所へ届く。
- 値が入った項目は出す: 外した項目でプランの値が動いているのに見えないと、結果の差の理由が画面から消える。
- 写さない: 見せ方だけで、お客さまに見せた数字は変わらない。写すと、事務所の選び方を変えるたびに世帯ごとに直すことになる。

## 代案（採らなかったもの）

- 出す種類を全部の一覧で持つ: 2 の理由。
- 入力の欄（`field:`）も選べるようにする: 1 の理由。よく使う欄が分かれば、種類（よく使う項目）として足す。
- 世帯ごとにも選ぶ: 3 のとおり、その場で足せる。
- 並びも選べるようにする: 並べ替えの部品が要り、対策の固定の項目の専用の形と混ざる。要るとわかってから。
- 配偶者の働き方と年収を2項目に分ける: 6 の理由。
- 配偶者の働き方を 0.16 の読み替え表に足す: 表は 0.16 の鍵だけの凍結した表で、どの行も凍結した見本で確かめる決まり（0035 の12）。0.16 の世帯ファイルに無い鍵なので、別の表にした。
