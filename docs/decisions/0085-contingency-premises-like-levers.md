# 0085. 万一のタブの想定の前提を対策と同じ表示に・場面の札の条件・万一の既定を事務所の既定値に・就業不能と収入が減るの配偶者の働き方（働き方の置き換え）と世帯ファイルの形式 0.36

- 状態: 採用（一部未確定）（2026-10-29）
- 固定の強さ: 次は骨格（変えるときは追記に書く）: 計算エンジンの入力の `workChanges`（働き方の置き換え。万一の重ねの後に、期間の始まりからその人の働き方の期間を置き換える）、画面の側の万一の前提の `partnerWork`（場面の種類 → 構成員の ID → 働き方）と入力項目ID `contingencyPremise.partnerWork`、形式 0.36。次は内部（後から変えてよい）: 想定の前提の項目の種類と既定の組み合わせ（`DEFAULT_PREMISE_KINDS`）、事務所データの `defaults.premises`・`scenes`・`protection` の形（足すだけの欄）、場面の札の文言、枠の描き方
- 前提にする記録: 0008（万一の層）、0035（形式の版の上げ方・入力項目ID）、0036（差分の型）、0071（万一の前提・プランごとの上書き）、0073（事務所の既定値）、0084（対策に最初から出す項目）

## 背景

- 万一のタブの想定の前提は、全部の場面の欄を区画ごとに一度に並べ、「標準／詳細」で数を切り替えていた。結果のタブの対策（0084）は、最初から出す項目・「＋ 動かす項目を追加」で足す項目・値が入っている項目の形になった。見る場面の前提だけを、対策と同じ操作で動かしたい。
- 配偶者の働き方と年収（0084 の6）は面談でいつも試す打ち手だが、万一のタブでは死亡の場面の「残された配偶者の働き方」（`work`）しか無く、就業不能・収入が減るの場面で配偶者が働きに出る・時間を増やすを試せなかった。エンジンの `survivor.spouseWork` は万一の想定（`contingencies`）の中にあり、収入が減るの場面には万一の想定が無い（収入の減少 `incomeShocks` だけ）。
- 「いつまでの資金を数えるか」「必要保障額の出し方」は、世帯ごとにほとんど変えない事務所の決まりで、想定の前提の欄に並べる物ではなかった。
- 場面の帯の札は「収入が減ったとき」「相場が下がったとき」で、条件（何割・何年）が見えなかった。

## 決定

### 1. 想定の前提の項目（対策と同じ表示）

- 想定の前提は、**選んでいる場面の項目だけ**を出す。出すのは (1) 最初から出す項目（事務所の既定値。外せない）、(2) 「＋ 動かす項目を追加」で足した項目（足した順）、(3) 値を変えた項目（共通の前提か見ているプランで既定と違う値・プランで上書きした値。最初から出さない項目でも出す）。(2)(3) は「外す」で外せ、外すと値は既定に戻す（0084 の4 と同じ決まり）。「標準／詳細」の切り替えはなくした。
- 項目の種類と並びは `app/src/workspace/contingency/premiseChoice.ts` の `PREMISE_KINDS`、世帯と場面ごとの項目（欄）は `inputs.ts` の `premiseItems`。場面ごとの既定の4つ（`DEFAULT_PREMISE_KINDS`。差し替えはここだけ）:

| 場面 | 既定の4つ | 追加で出せる項目 |
|---|---|---|
| 死亡 | 遺族の生活費の割合・残された配偶者の働き方・残された配偶者の年収・整理資金 | 遺族の生活費の割合（末子の独立の後）・子の独立とみなす年齢・死亡退職金・弔慰金・業務上の死亡・予備の生活資金・働き方を変える時期と何歳まで・団信 |
| 就業不能・障害 | 仮定の等級・医療費（1か月）・医療費の月数・配偶者の働き方と年収 | 65歳からの年金の組み合わせ・働き方を変える時期と何歳まで・団信 |
| 大きな病気 | 働けない期間・病気の種類・入院の日数・医療費（1か月） | 手術の回数・医療費の月数・復帰の後の収入（期間と割合） |
| 収入が減る | 誰の収入・減る割合・何年・配偶者の働き方と年収 | 働き方を変える時期と何歳まで |
| 相場の下落 | 下がる幅・下げる資産・利回りを抑える年数・その間の利回り | 同じ年に相場の下落を重ねる |

- 「同じ年に相場の下落を重ねる」は、相場の下落のほかの場面に効く全プラン共通の見方なので、どの場面でも追加で出せる（値が入っていればどの場面にも出る）。
- 世帯に当てはまらない項目は出さない（詰める）: 配偶者がいない世帯の配偶者の働き方、子がいない世帯の末子の独立の後・子の独立の年齢、住宅ローンが無い世帯の団信、障害年金に当たらない等級の65歳からの組み合わせ、働き方が「今の働き方を続ける」ときの変える時期。遺族の生活費の割合は今の決まりのまま（子がいる世帯は子がいる間、いない世帯は子がいない世帯の割合）。
- 残された配偶者の年収は、働き方が「今の働き方を続ける」「働かない」のときは枠を出して動かせない（説明だけ。既定の4つの並びを崩さない）。
- 団信（住まい・ローンと同じ欄）は死亡の場面の追加で出せる項目にした。団信には高度障害・就業不能の特約の欄があるので、就業不能の場面の追加にも置いた。団信の欄は入力の値（世帯の要求）なので「値を変えた項目」には数えない。
- 配偶者の働き方と年収（就業不能・収入が減る）は、対策の「配偶者の働き方と年収」と同じく1つの枠（働き方を選び、働くなら年収を1万円の刻みで動かす）。死亡は、指示どおり働き方と年収を別の2項目にした。
- プランごとの上書き（「前提を直す先: 全プラン共通／このプランだけ」。0071 の2）・共通と違う値の印・「↺ 共通に戻す」は今の動きのまま。
- 足した項目（`ContingencyUi.premiseAdded`）は作業の状態で、世帯を開き直すと消える（値を変えた項目は値で出るので、黙って消える値は無い）。世帯ファイルには書かない。
- 枠の並びは対策と同じ 4 → 2 → 1 列（大きな文字は 2 → 1。0084 の7）。

### 2. 場面の札に条件を書く

- 収入が減る: 見出しを「収入が2割減る（3年）」にした（ご本人のほかの収入なら「配偶者の収入が…」「2人の収入が…」。呼び方は世帯の呼び方から）。下の行は誰の給与・事業の所得か。
- 相場の下落: 見出しを「相場が3割下がる」。下の行は下げる資産（株・REIT か選んだ資産）と、戻り方があれば「その後3年は利回り0%まで」。
- 死亡・就業不能・大きな病気の見出しは人の言い方のまま（条件を足すと長くなるため）。下の行に条件を書く: 大きな病気は「がん・12か月働けない」、就業不能は等級。就業不能・収入が減るで配偶者の働き方を置き換えていれば「・配偶者はパート」、相場の下落を重ねていれば「・相場も下落」を足す。
- 条件（前提）を動かすと、札の文字も変わる（見ているプランの前提で作る）。

### 3. 必要保障額の数え方を事務所の既定値へ

- 「いつまでの資金を数えるか」（配偶者が決めた年齢を含む）と「必要保障額の出し方」（逆算で資産が尽きないようにする遺族の年齢を含む）を、想定の前提から外し、事務所の既定値 `defaults.protection`（`{ horizon?, protection? }`。標準と同じ所は持たない）に移した。
- **新しい世帯を作るときに、世帯の万一の前提（`horizon`・`protection`）に写す**（0073 の3 の写し方。前提条件と同じく、作った世帯は後で事務所の値を変えても黙って変わらない）。既に世帯に値が入っている世帯・値の無い前の世帯は、その世帯の値（無ければ標準）のまま計算する。
- 世帯の値が事務所と違うときに分かり直せる所を、万一のタブの想定の前提の下の小さな1行にした: 「必要保障額の数え方: この世帯は『配偶者の平均余命まで・積み上げ方式』です（事務所の既定値は『…』）。事務所の値にする」。押すと全プラン共通の前提を事務所の値にする。確かめの一覧ではなくここにしたのは、必要保障額の推移を見ているタブで気づけ、ほかの確かめ（事実の確かめ）と混ざらないため。
- 万一の前提の入力項目ID（`contingencyPremise.horizon`・`.protection`）とプランごとの上書きの差分は残す（前に作った上書きはそのまま当たる。画面から新しく作る所はなくなった）。

### 4. 事務所の既定値の万一のときの既定

- 事務所の既定値のパネルに区画「万一のときのタブ」を足した: 場面の帯に並べる場面（種類ごと。既定は全部。1つは並べる）、開いたときに選んでおく場面（既定はご本人の死亡）、想定の前提に最初から出す項目（場面ごとのチェック。「場面と項目を標準に戻す」）、必要保障額の数え方。
- 事務所データの `defaults` の足すだけの欄: `premises`（`{ shown?, hidden? }`。既定の組み合わせとの違いだけ。0084 の2 と同じ考え方）、`scenes`（`{ hidden?: 種類[], open?: 場面 }`）、`protection`。欄の無い古い事務所データ・読めない値は既定のまま。事務所データの形式の版は上げない。
- 場面の帯・開いたときの場面・最初から出す項目は見せ方だけなので、世帯に写さず、世帯ごとには選ばない（変えるとどの世帯にもすぐ効く）。
- 開いたときの場面: その世帯で最後に見た場面（作業の状態）や URL の場面があればそちら（今の動きのまま）。無ければ事務所の開いたときの場面。世帯に無い場面（単身でご本人の死亡が無いなど）・並べない種類の場面なら、並べる場面の最初。

### 5. 就業不能・収入が減るの配偶者の働き方と年収（計算）

- **計算の意味**: その場面が起きた後、配偶者の働き方と年収をその値に置き換える。就業不能・障害は想定の人の配偶者、収入が減るはご本人の配偶者。**いつから・いつまでは死亡のときの残された配偶者の働き方と同じ決まり**: 起きた月の○か月後（既定6か月）か、時点（下の子の年齢・出来事から。起きた月より前なら起きた月）から、○歳（既定65歳）になる月の前月まで。「働かない」は起きた月の○か月後から働かない期間。年収は賞与を除く年収（自営業は事業の所得）で、空欄は働き方ごとの目安。
- 死亡と違うところ: 配偶者は亡くなっていないので、パートは国民健康保険・国民年金にせず、働き方の目安のまま（扶養に入るかは入力の決まりのまま）。
- 場面の大きな病気は対象にしない（働けない期間が短く、元の働き方に戻る想定のため。要るとわかってから）。
- **エンジン**: 入力に `workChanges`（働き方の期間の並び。スキーマ `engine/schemas/engine.input.json`）を足した。期間ごとに、その始まりから、その人のそれまでの働き方の期間を置き換える（`survivor.spouseWork` と同じ当て方: 始まりより後の期間は外し、またぐ期間は前の月で終える）。**万一の想定の有無によらず、万一の重ねの後に当てる**（`engine/src/engine/overlay.ts` の `applyWorkChanges`。0008 の7 の決まり方の順番の最後のさらに後）。万一の想定の中に置かなかったのは、収入が減るの場面に万一の想定が無いため（`contingencies` は要求に1件まで・種類は死亡・障害・就業不能）。死亡の場面は今までどおり `survivor.spouseWork`。
- **画面の側の前提**: `ContingencyPlan.partnerWork`（場面の種類 `disability`・`income` → 働き方を変える構成員の ID → 働き方。形は死亡の `work` と同じ）。入力項目ID `contingencyPremise.partnerWork`（正本は `app/schemas/household.contingency.json` の `x-item`。登録簿に載る）。プランごとの上書きは 0071 の2 のとおり、その入力項目ID と場所（`["income", <構成員>, "annualSalary"]` など）の差分。違いの一覧の言い方は「就業不能のときの配偶者の働き方」など。
- AI接続口の縮約版の許可リストに入れ、版を `reduced@23` にした（計算の前提の決まった値と数。文章の項目ではない）。

### 6. 世帯ファイルの形式 0.36

- 形式の版を `0.36` にした（画面の側の万一の前提に `partnerWork` を足すだけの MINOR。任意で計算に使う）。`0.35` のアプリは知らない欄を読み落として書き戻すので、版を上げて閲覧だけにする。`0.35` → `0.36` の変換の段は形式の版だけを書き換える。
- 見本 `crates/household-store/tests/fixtures/household-format/0.36/`（0.35 の見本の本文に、配偶者の就業不能・収入が減るの働き方と、最初のプランで収入が減るの配偶者の年収を上書きする差分を足した物）。封筒の見出しは変えていない。

## 理由

- 選んでいる場面だけ・既定の4つ: 前提の欄が場面の数だけ並び、見ている場面に効く欄を探す手間があった。対策と同じ操作にそろえると、覚えることが1つで済む。
- 値を変えた項目は出す: 外した項目の値で結果が動いているのに見えないと、結果の差の理由が画面から消える（0084 の4・0083 の4 と同じ）。
- 働き方の置き換えを万一の想定の外に: 収入が減るの場面は万一の想定を持たない。万一の想定の形（1件・3種類）を広げるより、層を1つ足す方が、死亡の決まり（`survivor.spouseWork`）を変えずに済む。
- 必要保障額の数え方を写す（参照しない）: 0073 の3 のとおり、世帯ファイルは事務所データに頼らず、後で事務所の値を変えても、お客さまに見せた必要保障額は黙って変わらない。

## 代案（採らなかったもの）

- 就業不能の場面だけ `survivor.spouseWork` を使う: 名前が遺族の側で、収入が減るの場面には使えない。
- 画面の側で要求の働き方の期間を直接書き換える: 万一・ストレスの重ねはエンジンの1か所で行う決まり（0008 の7）から外れる。
- 足した項目を世帯ファイルに書く: 見せ方だけで、値を変えた項目は値で出るので要らない。要るとわかってから（対策の `shownItems` と同じ置き場所にできる）。
- 必要保障額の数え方の違いを確かめの一覧に出す: 3 の理由。
