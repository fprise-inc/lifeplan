# 0197. 合算BS の見本の世帯と、アプリの見本の世帯では機能を有効にするコードが無くても合算BS を見られる形

- 状態: 採用（一部未確定）（2026-11-11）
- 固定の強さ: 骨格は、見本の世帯でだけ見せる条件（アプリに入っている見本の世帯を、保存しないで開いているときだけ。保存した世帯・FP が作った見本では、0110 の条件のまま）と、コードの確かめ（0110）を変えないこと、見本で見せた見るもの・提案書の章に「見本」の印を付けること（提案書の印は公式の帳票が付け、束の帳票からは消せない）。見本の世帯の数字・印の文言・置き場所は変えてよい
- 前提にする記録: 0033（見本の世帯と見本の棚）、0105（役員の家計の側）、0107（合算BS）、0110（機能を有効にするコード）、0114（拡張の束・公式の拡張）

## 背景

- 合算BS（経営者個人と会社のバランスシート）は同梱の公式の拡張 `ext.official.combinedBs` で、機能を有効にするコード（0110）を入れ、事務所の設定の印を付けた FP の、役員として働く人のいる世帯でだけ出る（0114 の7）。
- 紹介・説明会・画面の撮影などで、まだコードを持っていない人にも合算BS を見せたい（利用者の判断。見本の画面でよい）。
- アプリの見本の世帯（0033）に、会社の数字（宣言型の入力欄 `fields/company.json` の欄）の入った世帯が無かった。役員の見本（`sampleExecutive`）も家計の側だけで、合算BS を開いても「会社の数字を入れる」の空の画面になる。

## 決定

### 1. 合算BS の見本の世帯を1つ足す（`sampleOwnerCompany`、見本番号 3-5-03）

- 「会社を経営する夫婦と子1人・50代（合算BS の見本）」。すべて架空（会社の名前は持たない）。家計の側はほかの見本と同じ程度に入れる: ご本人57歳は会社員から自分で作った会社の代表（役員報酬 年1,800万円・70歳で退任・役員退職慰労金・小規模企業共済・在職老齢年金）、配偶者は家事専業、子17歳（私立大学・自宅）、持ち家（住宅ローンなし）、預金と NISA。
- 合算BS の見せどころが分かる数字にする（丸い架空の数字）:
  - 家計の側（0105）: 自社株（出資額）1,000万円、会社への貸付金 500万円、会社の借入の連帯保証 5,000万円。
  - 会社の試算表（2026年9月末）: 現預金 4,000万円・売上債権 2,500万円・在庫 600万円・その他の流動資産 400万円・土地 2,500万円・建物など 1,800万円・投資など（保険積立金など。退職金の準備）3,000万円・その他の固定資産 700万円、短期借入金 1,500万円・長期借入金 6,000万円・経営者からの借入金 600万円・その他の負債 2,400万円、資本金 1,000万円・剰余金 4,000万円（資産 1億5,500万円＝負債 1億500万円＋資本金＋剰余金）。毎月の固定費 800万円・借入の返済 120万円。段階は「成熟期」。実力に直す点検に在庫・建物など・土地（時価）の額（直した額で並べるの印は付けない）。
  - 見えること: 自社株と資本金の組は合っている。会社への貸付金（家計 500万円）と会社の経営者からの借入金（会社 600万円）は合わないので、会社の側に合わせたお知らせが出る（書き漏れの見本）。連帯保証は二重に数えないお知らせ。現預金は家計が厚く（何か月分も多い）、会社は目安の6か月分に届かない（4.3か月分）。合算の純資産は「会社の財産（剰余金）」と「個人の財産」に分かれる。
- 会社の数字は計算の入力ではないので、モデル世帯のファイル（`data/modelHouseholds/sampleOwnerCompany.json`。エンジンへの要求）には入れず、アプリの見本の一覧（`app/src/workspace/catalog.ts`）の新しい任意の欄 `extValues`（入力欄の値の置き場所 → 値。世帯ファイルの拡張領域と同じ形）に置く。開くときに束の宣言で確かめて読む（世帯ファイルを読むときと同じ。宣言に合わない値は捨てる）。
- 見本の一覧・説明の表（`data/modelHouseholds/README.md`）・絞り込みの項目は、ほかの見本と同じ扱い。AI接続口の見本の一覧（0015）にも、ほかのモデル世帯と同じく出る（計算の入力だけ。会社の数字は出ない）。

### 2. アプリの見本の世帯では、コードが無くても合算BS を見られる（見るだけ・試せる）

- **条件**: アプリに入っている見本の世帯（すべて架空。0033 のアプリの見本）を、**保存しないで開いているときだけ**。コードの機能（マニフェストの `activation.feature`）を持つ公式の拡張を、コードと事務所の設定の印が無くても見せる。世帯の条件（`activation.households`。合算BS は役員として働く人のいる世帯）は守る。
  - 保存した世帯（お客さまの世帯）と、FP が作った見本（見本の棚の「自分で作った見本」）は対象にしない。どちらも FP が中身を入れられ、お客さまの情報が入りうるため。0110 の条件のまま。
  - コードで有効で印も付いているときは、見本の世帯でもふつうに使える（見本の印は付けない）。コードはあるが印を外しているときは、見本の世帯では見本の印を付けて見せる。
- **見え方**: 資産と負債のタブの見るものの切り替えに「合算BS（会社と合わせる）」と小さな「見本」の印。見るものの中に「見本の世帯なので、有効にするコードが無くても見られます。お客さまの世帯で使うには、コードが要ります。」の1文。会社の数字の入力欄も出し、変えて試せる（見本の世帯は保存しないので、開き直せば元どおり。0033）。
- **作り**: 作業の層に、見本の世帯でだけ見せる束を返す関数 `sampleExtensions`（`app/src/workspace/extensions/run.ts`）を足した。今使える束（`activeExtensions`）は変えない。画面は2つを合わせて使い、見本で見せた束にだけ印を付ける。
- **コードの確かめは変えない**: 本体のコードの確かめ・`app/src/workspace/office/featureCodes.ts`・事務所の既定値の区画「法人経営者向けの機能」（コードが無ければ出さない）・期限切れや止めたときの知らせ（`hiddenNote`）は変えない。見本でない世帯の扱いは前と同じ（テストで両方を確かめる）。

### 3. 見本から世帯・見本を作ったとき

- 「この見本をもとに顧客を作る」「写して手直しする」で作った世帯にも、会社の数字（拡張領域の値）を写す（ほかの数字と同じく見本の架空の値。コードを入れた FP が写して手直しする使い方に要る）。
- 作った世帯は保存した世帯なので、0110 の条件のまま: コードが無ければ、見るもの・提案書の章は出さない（コードを入れていない FP には今までどおり何も出さない）。データは消さない。コードを入れて印を付けると見られる。
- 作ったときの知らせに「合算BS の会社の数字も写しましたが、有効にするコードが無いので、この世帯では見られません（コードを入れると見られます）」を足す（見本で合算BS を見せていて、会社の数字が入っているときだけ）。

### 4. 提案書の章も、見本の世帯なら出せる（「見本」の印を付ける）

- 見本の世帯では、提案書の章の一覧に「会社と合わせたバランスシート（合算BS）（見本）」が出て、ふつうと同じく最初から選んである。
- PDF では、その章の見出しの下に「見本」の印と「見本の世帯（架空）なので、機能を有効にするコードが無くても載せています。お客さまの世帯の提案書に載せるには、コードが要ります。」の1文を付ける。印は公式の帳票（`report/typst/report-core`）が付ける（束の帳票 `reports/chapter.typ` は変えず、束の側からは消せない。0009 の「刻印・必須の記載はアプリが外側で付ける」と同じ考え方）。
- 帳票の入力（試験版 0.1.0 の中で足すだけ）: 任意の欄 `extensionSamples`（見本として載せた拡張の章の id の並び。`extensions` に材料のある章だけ。章を外すと印も外す）。

## 理由

- **アプリの見本だけに限る**: アプリの見本は提供元が作ってアプリと一緒に配る架空の世帯で、お客さまの情報が入らない。保存した世帯・FP の見本まで開くと、コードで守る意味が無くなる。開いた見本の数字を書き換えても保存はできず、提案書には見本の印が付く。
- **別の関数にして今の条件を変えない**: 見本でない世帯の扱いを変えないことを、コードの形でも確かめられる（`activeExtensions` は1文字も変えていない）。
- **作った世帯に数字を写す**: 写さないと、コードを入れた FP が見本を写して直すときに入れ直しになる。見本の値は架空なので写しても困らない。見えない値が残ることは、期限が切れたとき（0110 の3）と同じ扱い。
- **提案書も出す**: 説明会や紹介では、提案書の章まで見せたい。印を付ければ、見本の章をお客さま向けの提案書と取り違えない。

## 代案（採らなかったもの）

- **見本の世帯でも、見るものだけで提案書の章は出さない**: 見せたい物が欠ける。印で足りる。
- **保存した見本（FP が作った見本）でも見せる**: FP が中身を入れられるので採らない。
- **作った世帯から会社の数字を消す**: 上の理由。コードを入れたときに戻らなくなる。
- **作った世帯で、コードが無いことの1文を資産と負債のタブに出す**: コードを入れていない FP の世帯の画面に、今は合算BS のことを何も出さない（0110）。見本でない世帯の画面を変えないために採らない（作ったときの知らせの1文で伝える）。

## できること・できないこと

- できる: コードを持たない FP・まだ使っていない人に、見本の世帯で合算BS の画面・入力欄・提案書の章を見せる。
- できない（防がない）: 見本の世帯を開いて数字をお客さまのものに入れ替えれば、保存しないまま見て、見本の印付きの提案書を作れる。保存はできず、印は消せない。アプリを書き換えた人が確かめを外せるのは 0110 と同じ。

## 影響

- 画面: 資産と負債のタブの見るものに「見本」の印と案内（見本の世帯でだけ）。提案書の章の名前に「（見本）」。見本から世帯を作ったときの知らせ。
- 帳票: 入力に任意の `extensionSamples`、公式の帳票に見本の印（`parts/layout.typ` の `sample-mark`）。
- 見本の一覧: アプリの見本が15件（モデル世帯は57件）。見本の一覧の任意の欄 `extValues`。
- 計算エンジン・世帯ファイルの形式・ほかのモデル世帯の計算の結果は変わらない。コードの確かめ・見本でない世帯の画面は変わらない。

## 未確定

- 見本の印の言い方（画面と提案書）は、説明会で使ってもらってから直す。
- 合算BS のほかに、コードで守る公式の拡張が増えたとき、どれも見本の世帯で見せるか（今はコードの機能を持つ公式の拡張を、同じ条件で見せる。拡張ごとに選ぶ欄は作っていない）。
