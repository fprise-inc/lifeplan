# 0214. 前提条件は事務所の既定値で決め、世帯では「事務所の既定値」か「この世帯だけ」と見せる

- 状態: 採用（2026-11-14）
- 固定の強さ: 事務所データの形（`defaults.version: 2` で足した欄 `realEstateValuation`・`assetReturns`、`assumptions` に足した2つの系列）と、前提条件の欄の id（下の表の「id」の列）は、AI接続口の道具からも使う名前なので、足すことはあっても別の意味に使い回さない。「作った世帯は黙って変えない」決まり（0073 の3）は変えない。画面の言葉・並び・折りたたみの形は後から変えてよい
- 前提にする記録: 0073（事務所の既定値）、0070（前提条件のカード）、0041（値の状態と確かめの一覧）、0111（事務所の推定の値）、0145（既定の値で埋まる欄の推定の印）、0137（預金の利回り・資産配分）

## 背景

- 前提条件の値（物価・賃金・運用利回り・不動産の評価・資産の種類ごとの利回りなど）は、ほとんどの事務所で世帯ごとでなく事務所で決める。ところが事務所の既定値の画面で決められるのは、物価・賃金・運用利回り・預金の利回り・年金の調整率・貸していない不動産の値動き・表の最後の年の年齢・相続税の目安の評価の割合だけだった。不動産の評価・資産の種類ごとの利回り・教育費の上昇率・厚生年金の調整率は、世帯ごとに直すしかなかった。
- 世帯の前提条件は、事務所の既定値や提供元の既定の値をそのまま使っている値も、灰色の点線の「推定」と「この値にする」で出していた。お客さまの事実を補う推定（収入・生活費など）と同じ見た目なので、FP には「値が決まっていないのでは」「押さないといけないのでは」と見えていた。
- 前提条件のカードを開くと、経済の前提・例外の年・不動産の評価・資産の種類ごとの利回りが全部並び、事務所の既定値のままの世帯でも長い画面になっていた。

## 決定

### 1. 前提条件の置き場所は事務所の既定値の1か所にする

- 前提条件の欄のうち「既定の値」があるものは、全部、事務所の既定値の画面の「前提条件の既定値」で決められる（下の表）。計算の決まり（お金の数え方・運用益の数え方）と計算の基準の月は既定の値でなく決まりなので入れない。表の最後の年（何歳まで見るか）は今までどおり事務所の既定値の年齢（0073 の追記 2026-11-05）。相続税の目安の評価の割合も今までどおり。
- 画面の区画は3つ: 経済の前提（7つ）・不動産の評価（持ち家・収益不動産など）・資産の種類ごとの利回り。不動産の評価と資産の種類ごとの利回りは、世帯の前提条件と同じ3列の小さな欄の並びにする（下の4）。
- 土地の割合・建物の残りの価値の下限・売却の費用の3つは、前から事務所の推定の値（0111。値ID `preset.realEstate.landShare`・`residualFloor`・`saleCostRate`）で変えられた。置き場所を2つにしないため、前提条件の既定値の画面の欄は同じ事務所の推定の値を読み書きする（下の「事務所の推定の値」の区画にも同じ値が出る）。この3つは推定の元の値なので世帯に写さず、世帯で空欄の物件はその場の事務所の値で計算する（0111 のまま）。

### 2. 事務所データの形（`defaults.version: 2`）

- 前の版の形（`version: 1`）に、足すだけの欄を加えた。前の版の事務所データはそのまま読める（無い欄は「決めていない」＝提供元の既定の値）。前の版のアプリは知らない欄を読まずに通すので、新しい版で保存した事務所データも読める（足した欄の値は使われない）。
  - `assumptions`（前からの欄。系列の名前 → 率の文字）に `educationInflation`（教育費の上昇率）・`pensionMacroSlideEmployee`（厚生年金の調整率）を足した。貸していない不動産の値動き `heldEstateGrowth` は、資産の種類ごとの利回りの不動産（id `assetReturns.realEstate`）の置き場所としてそのまま使う。
  - `realEstateValuation`（新）: `landGrowth`（土地の上昇率。率の文字）・`usefulLife`（構造 → 耐用年数の年。`wood`・`lightSteel`・`steel`・`rc`）。
  - `assetReturns`（新）: 資産の種類 → 率の文字（不動産を除く11種類。不動産は上の `heldEstateGrowth`）。
- 読むときは欄ごとに世帯の前提条件の欄と同じ範囲で確かめ、範囲の外・読めない値は「決めていない」にする（`office/settings.ts` の `readOfficeSettings`）。空欄（決めていない）は持たない。
- 画面の側で読む今の値（`office/current.ts` の `officeNow().premises`）は、id → 値の文字の1つの表にした（耐用年数も年の数の文字）。土地の割合など3つは事務所の推定の値なので、この表に入れない（推定の目安の側で読む）。

### 4. 世帯の前提条件の見せ方

- 世帯の値が事務所の既定値（事務所で決めていなければ提供元の既定の値）と同じなら、決まった値として普通に見せ（灰色の点線にしない。「この値にする」を出さない）、欄の名前の横に小さく「事務所の既定値」と出す。
- この世帯だけ違う値にしたら「この世帯だけ」と出し、その横に「事務所の既定値に戻す」のリンクを置く（押すと事務所の今の値にする。空欄にしても同じ）。
- 事務所の既定値をそのまま使っていた値で、その後に事務所の既定値が変わった物は「事務所の既定値が変わりました（1.0%→1.5%）」と出し、「今の既定値にする」のリンクを置く（下の5）。
- 値の状態（0041）は、この3つのどれでも「確定」と読む（推定の数・「推定の値をまとめて使う」・提案書の「一部は統計の平均で補っています」に入れない）。灰色の「推定」は、お客さまに確かめる統計の推定（収入・生活費など）だけに残す。
  - 例外: 資産配分の入れ方で書いた資産の種類の期待リターンの目安（事務所の推定の値 `preset.invest.*.return`。0137）は、推定の印のまま（灰色の「推定」と「この値にする」）。事務所の既定値でなく、推定の目安から書いた値のため。
- 入力のホームの前提条件の項目の札は、全部が事務所の既定値どおりなら「事務所の既定値どおり」（前の「既定の値で計算中」）、この世帯だけの値が1つでもあれば「入力済み」。
- 前提条件のカードを開くと、経済の前提・例外の年・不動産の評価・資産の種類ごとの利回りは、ふだんは1行にたたむ:「前提条件: 事務所の既定値どおり（この世帯だけ変えた所 0件）」（この世帯だけの値があれば「前提条件: 事務所の既定値と、この世帯だけ変えた所 2件」、事務所の既定値が変わった所があればその数も添える）。押すと全部の欄を出す。確かめの一覧・前提と推定の一覧・検索から欄へ移るときは開いて出す。結果のタブで動かした利回り・金利と FP顧問料は、たたまずに出す。
- 資産の種類ごとの利回りは、不動産の評価と同じ3列の小さな欄の並びにして、12種類を全部出す（前の「＋ 国内株式」のように1つずつ足す形をやめた）。空欄は計算と同じ値（預金・外貨預金は預金の利回り、ほかは運用利回り、不動産は0%）を見せる。この世帯だけ値を入れた種類には「＋ 例外の年（国内株式）」を出す。

### 5. 後で事務所の既定値を変えたとき（作った世帯は黙って変えない）

- 作った世帯の値は変えない（0073 の3 のまま）。事務所の既定値を使っていた欄の値が、事務所の今の既定値と違うときは、確かめの一覧の「確かめの注意」に「事務所の既定値が変わりました（1.0%→1.5%）」と出し、「この世帯に当てる」の1押しを置く（押すと今の既定値にし、「事務所の既定値」の印に戻す）。前の「事務所の新しい値があります」を言い直し、今回足した欄（不動産の評価・資産の種類ごとの利回り・教育費・厚生年金の調整率）にも広げた。
- 「事務所の既定値を使っていた」と読むのは: 事務所の既定値を写したときの印（世帯の仮の印 `assumed[<欄のキー>]` が「事務所の既定値（年月）」）がある欄か、提供元の既定の値のまま FP が触っていない欄（年ごとの列は既定の値と同じで値の状態の行が無い、ほかは値が無い）。FP が打った値・「この値にする」を押した値は「この世帯だけ」（知らせは出さない）。
- 土地の割合など3つ（事務所の推定の値）は世帯に写さないので、空欄の物件は事務所の値を変えるとその場で変わる（0111 のまま。この知らせは出さない）。

### 6. 古い世帯の読み方（移し替え）

- 世帯ファイルは書き換えない（形式の版も上げない）。計算の要求は何も変わらないので、どの世帯も計算の結果は変わらない（この回の変更は見せ方と置き場所だけ）。
- 読み方:
  1. 「事務所の既定値（年月）」の印がある・提供元の既定の値のまま触っていない欄で、値が今の事務所の既定値と同じ → 「事務所の既定値」。
  2. 同じ印がある・触っていない欄で、値が今の事務所の既定値と違う → 「事務所の既定値が変わりました」と確かめの注意（値は変えない）。
  3. FP が打った値・「この値にする」で確定にした値 → 今の事務所の既定値と同じなら「事務所の既定値」、違えば「この世帯だけ」。
- 2 を「この世帯だけ」にしなかったのは、FP がその世帯のために決めた値でないものを「この世帯だけ」と見せると、事務所の既定値を直したのに世帯に届いていないことに気づけないため。黙って今の既定値に書き換えなかったのは、お客さまに見せた結果が変わるため（0073 の理由）。どちらも一番驚かない形として、値はそのまま・知らせは出す、にした。
- 新しい世帯を作るとき（空の世帯だけ。0073 の3）は、事務所で決めた欄を世帯に書き、「事務所の既定値（年月）」の印を付ける（前と同じ印。前の版のアプリでは「推定」と読まれる）。この世帯だけの値を打つと印を外し、事務所の既定値と同じ値を打つか「事務所の既定値に戻す」を押すと印を付け直す。

### 7. 確かめの一覧・前提と推定の一覧・AI接続口

- 確かめの一覧の「前提条件の標準の値」（いちばん下の折りたたみ。0041 の追記 2026-11-06）は「前提条件（事務所の既定値どおり）」と言い直し、事務所の既定値どおりの前提条件を、操作を付けずに並べる（数にも、まとめての「この値にする」にも入れない。前と同じ）。
- 前提と推定の一覧の「状態」は、前提条件の欄では「事務所の既定値」「この世帯だけ」「事務所の既定値が変わりました」。「出典・根拠」は「事務所の既定値（年月）」「提供元の既定の値」「この世帯で入れた値」など。事務所の既定値どおりの行は「お客さまと確かめた」の印を出さない（世帯ごとに確かめる値でないため。この世帯だけの値には出す）。推定の根拠（各入力項目）の行と万一の前提の行は今までどおり。
- AI接続口の `check_inputs` の種類 `premise` は「前提条件（事務所の既定値どおり）」の行で、問いの文は「〜は、事務所の既定値のままでよろしいですか（FP が決める前提です）。」にした。前提条件の id と事務所データの置き場所は上の表（AI の道具で事務所の既定値を読む・直すときの名前）。

## 理由

- 前提条件は事務所の方針で、お客さまの事実ではない。統計の推定と同じ灰色で見せると、確かめるべき値（収入・生活費）と、事務所で決めてある値の見分けがつかない。
- 置き場所を1か所にしないと、FP は世帯ごとに同じ値を打ち直すことになり、打ち忘れの世帯だけ違う前提で計算される。
- 「この世帯だけ」と「事務所の既定値に戻す」を並べると、どこを直したかと戻し方が、その欄の上で分かる。
- 3つ（土地の割合など）を事務所の推定の値のままにしたのは、同じ値を2つの置き場所に持つと、どちらが効いているか分からなくなるため。

## 代案（採らなかったもの）

- 事務所の既定値を世帯から参照し、事務所で変えるとすぐどの世帯にも効く: お客さまに見せた結果が黙って変わる（0073 の理由）。利用者の判断で今の写す形のまま（ア）。
- 事務所の既定値と違う値を全部「この世帯だけ」と見せる: 上の6の 2 の理由。
- 土地の割合など3つも写す形にする: 事務所の推定の値（0111）と二重になる。
- 前提条件の欄を新しい世帯ファイルの欄（「事務所の既定値に従う」の印）で持つ: 世帯ファイルの形式の版を上げることになり、前の版のアプリで読めなくなる。前からある仮の印で足りる。
