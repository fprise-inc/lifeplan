# 0041. 値の状態の操作と確かめの一覧（確定は明示の操作だけ・4つの操作・推定で埋める）

- 状態: 採用（一部未確定）（2026-10-26）
- 固定の強さ: β公開から変えない（骨格）。確定は明示の操作だけで状態を変えること（欄に入って離れる・Tab で通る・同じ値を書き戻す・パネルを開いて最初の欄に入る、では値も状態も変えない）、4つの操作の意味、「✓ この値で確定」は推定の根拠（`estimate`）を残した確定にすること、FP が値を変えたら値が変わった所の前からの値の状態の行を外すこと、古い世帯を開いても推定を自動で入れないこと（「推定で埋める」を押したときだけ）は骨格。確かめの一覧の並び・文言・印の色、目安のボタンの値の一覧、推定で埋める物の範囲（目安を作れる物を足していく）は後から変えてよい（変えたら追記に書く）

## 背景

- 世帯ファイルの形式 0.17（0035）で、値の状態（推定・わからない・該当なし・確定）の置き場所が、値の箱（0008 の2）か、その値を持つ物の値の状態の欄 `valueStates` の1か所に決まった。画面の側はまだ、推定の値の欄に入って離れるだけで確定になり（欄の書き戻しで同じ値を入れ直すと確定にしていた）、わからない・該当なしを欄から選べず、値を打っても `valueStates` の行（わからない・承認の記録など）を直していなかった。
- 入れていない所の扱いを「推定・わからない・該当なし・未入力（0円で計算中）」にそろえ、FP が推定の所と入れていない所を一覧で確かめ、そこから欄へ移れるようにする。古い世帯では、今まで0円だった所（教育・退職金・住居費など）に黙って推定を入れない（0035 の11）。
- 前提にする記録: 0008（値の箱・推定の入れ直し）、0035（3 値の状態、11 古い世帯を開いたとき）、0036（8 入力画面でプランを直すときの決まり）。

## 決定

### 1. 欄の値の状態を読む・変える関数を1つにする

- 画面の欄の状態は、どの欄も同じ関数で読む（`app/src/workspace/input/valueState.ts` の `fieldStatus`）。呼ぶ側は、状態が値の箱にあるか、`valueStates` の行にあるか、画面の中の仮の印（推定・出どころ `auto` の行を画面の中で持つ形。0035 の追記）にあるかを分けない。
- 読める状態は5つ: 推定・わからない・該当なし・確定と、**未入力（0円で計算中）**。未入力は状態を持たない。値が無く、推定も該当なしも無い円の欄（任意でない欄）と、「未入力（0円で計算）」の印の0円の推定（年金の見込額・統計の無い年収など、前からある印）を、画面が決まりで未入力と読む。
- 欄の当て先（0036 の2）は欄の定義が持つ（`address`）。持たない欄は、0.16 の欄のキーから読み替え表（0035 の9）で引く（欄の定義が当て先を持つまでの橋渡し）。当て先の無い欄は、値の箱か仮の印だけで状態を持つ。

### 2. 確定は明示の操作だけ

- 欄の書き方（`form.ts` の `field`）は、今の値と同じ値なら世帯を変えない（推定の値と同じ値を書き戻しても確定にしない）。前の「推定を同じ値で入れ直したら確定にする」はやめた。
- 欄の部品（`FieldViews.tsx`）は、欄に入ったときと同じ文字のまま離れたら書かない。打っている間は今までどおり値を書く（文字を打った・選び直したなら、同じ値に戻っても確定でよい。入力の操作があったため）。
- パネルを開いて最初の欄に移る・確かめの一覧から欄に移るのは、移るだけ（書かない）。保存していない変更の知らせは、値か状態が変わったときだけ出る。

### 3. 4つの操作（どの欄も同じ部品）

| 操作 | 何をするか | 値の箱の欄 | 箱でない値 |
|---|---|---|---|
| ✓ この値で確定 | 推定（わからないなら代わりの値）を、その値のまま確定にする | `{value, state: confirmed, origin: manual, estimate}`（推定の根拠を残す） | 行 `{state: confirmed, origin: manual, estimate}`（仮の印は外す） |
| 推定に戻す | 空欄にしたときの推定に戻す（空欄が推定になる欄だけ） | 推定の箱を入れ直す | 行を外し、推定（仮の印）に戻す |
| わからない | 聞いたが分からない。今の値（無ければ推定）を代わりの値にする | `{state: unknown, origin: manual, substitute}` | 値はそのまま、行 `{state: unknown, origin: manual, estimate}` |
| 該当なし | FP が「無い」と決める（任意の円の欄だけ） | `{state: notApplicable, origin: manual}` | 値を省き（省けない欄は0）、行 `{state: notApplicable, origin: manual}` |

- 「✓ この値で確定」は、確定の値に推定の根拠 `estimate` を残す（スキーマは確定の箱・行に `estimate` を持てる）。打って入れた確定（根拠なし）・古い世帯の記録の無い確定と見分けるため（目安のボタンと同じ値の候補を出すかに使う。5）。0035 の3 の「`{"state": "confirmed", "origin": {"kind": "manual"}}` の行を書く」を、根拠つきの行にした（形は同じ。`estimate` は任意の欄）。
- 箱でない値の状態の操作は、値を書き換えずに行だけを書く（該当なしだけ値を省く。値の書き方は差分の当て方と同じ `writeAt`）。欄が見せる値と当て先の値の形が違う欄（進路の型の選択が進路の段の並びの状態を持つなど）でも、値を壊さない。
- 使える操作は欄の種類と状態で決める（`availableOps`）。わからない・該当なしは数の欄だけ（選択・オンオフ・年月・名前は持たない）。該当なしは任意の円の欄だけ（エンジンが値の無いことを許す欄）。
- まとまり・カードの「推定をまとめて確定」（入力のパネルの見えている欄）と、確かめの一覧の「推定をまとめて確定（全部）」は、推定の欄だけを1つずつ「✓ この値で確定」にする。
- 推定の入れ直し（0008 の追記 2026-10-11 の2）は、出どころ `auto` の推定と、わからないの代わりの値のうち統計の推定のもの（`substitute` の出し方が `statistic`）だけ。確定（根拠つきも記録の無いものも）と、FP が前に入れていた値を代わりにしたわからないは変えない。

### 4. 値を変えたら、値が変わった所の行を外す

- FP が値を打った・選んだ・ボタンで変えたとき、その変更の前からあった行のうち、当て先の値が前と違うものを外す（`rows.ts` の `dropStaleRows`。欄の書き方と、入力のパネルの変更のすべてに当てる）。わからない・該当なし・承認の記録（ヒアリング・取り込み）・確かさの行が、FP の打った値に残らない。推定（出どころ `auto`）でない行も同じ。
- この変更で新しく書いた行・書き換えた行は外さない（値の状態の操作・推定で埋めるで書いた行は残る）。値の変わらない所の行も残る。
- **ヒアリングの取り込みで同じ ID の物を置き換えたとき**: 取り込んだ物の行が正。前の物の行のうち、取り込んだ物に同じ鍵の行が無く、取り込みで値が変わらない所の行（FP が決めた該当なし・わからない・確定の記録）は、取り込んだ物に写す（`carryRows`）。値が変わった所の行は写さない（取り込んだ値と承認の記録が正）。0036 の追記 2026-10-26（土台の点検の直し）の9 の「値の状態の行を取り込みのときに残すか」は、これで決める。

### 5. 確かめの一覧

- 入力のホームの道具に置く（`CheckList.tsx`・`checkRows.ts`）。行は世帯の物と欄の定義から毎回作り、保存しない。
- 並び（上から）: ① 未入力（0円で計算中。入っていない物と未入力の欄）② わからない ③ 確かめの注意（目安のボタンと同じ確定の値・ほかの入力と合わない値の知らせ）④ 推定（影響の大きい順。年額×残りの年数のおおよそ）。同じ種類の中はカードの順。カードで絞り込める。
- 行ごとに「開く」（そのカードのパネルを開き、その欄に移る。詳細の欄なら詳細にする。移るだけで書かない）と、行の操作（推定は「✓ 確定」、入っていない物は「推定で埋める」「該当なし」、目安のボタンと同じ値は「✓ この値で確定」「推定にする」）。
- 同じ値を2つの欄が見せる（今の働き方の欄と、働き方の期間の欄など）ときは、当て先で1行にまとめる。
- **目安のボタンと同じ確定の値**（0035 の11）: 前の版のボタンは、家賃・固定資産税・修繕費・一時的支出・n年ごとの支出・借入額・保険料を、印の無い確定の値で入れていた。その値のまま記録の無い確定（根拠の無い確定・承認の記録なし）の欄を、確かめの注意に出す。値も状態も変えない。FP が確かめて「✓ この値で確定」（根拠に「目安のボタンと同じ値を確かめた」を残す）か「推定にする」を押すと、一覧から消える。一覧の値は `PRESET_VALUES`（一時的支出・n年ごとの支出はボタンの名前のままのときだけ）。
- 新しく押すボタンは、印の無い確定の値でなく、推定（出し方 `standard`、根拠「目安のボタンの値（…）」）で入れる（賃貸の家賃、持ち家の固定資産税・修繕費、一時的支出・n年ごとの支出、足した項目のひな形）。値は同じなので、計算の結果は変わらない。

### 6. 入っていない物と「推定で埋める」

- 入っていない物（`fill.ts` の `gapsOf`）と、その推定・該当なし:

| 物 | 入っていないとき | 推定で埋める | 該当なし |
|---|---|---|---|
| 子の教育（進路が無い子。これからの段がある子だけ） | 教育費0円 | 標準の進路の型（幼稚園〜高校は公立、大学は私立・文系・自宅）。進路の段の並びに推定の行（`goal.education/stages`、出し方 `standard`） | 段の無い進路と、該当なしの行（教育費なし） |
| 退職金（今の働き方が正社員・公務員で、その人の退職金が無い） | 0円 | 正社員: 統計の退職一時金の目安（`retirementLumpSumEstimate`。定年は期間の終わり、無ければ60歳）。公務員: 退職手当の見込みの計算（最終の月給は統計の年収の目安÷12）と、その推定の行 | 今の働き方の期間の `employment.retirementBenefit` に該当なしの行（勤め先に制度が無い） |
| 基本生活費（無い） | 0円 | 世帯の人数の統計の目安 | — |
| 住居費（住まいも住宅ローンも無く、カードを保存していない） | 0円 | 賃貸・家賃 月8万円（目安のボタンの値。統計の家賃の目安はまだ無い。出し方 `standard`） | カードを「当てはまらない」にする（保存した項目の印） |
| 保険（契約が無く、カードを保存していない） | 保険料・保障0円 | 入れない（保障の額は商品ごとで、外れると大きく誤るため。未入力の警告だけ） | カードを「当てはまらない」にする |

- **古い世帯を開いたとき**: 自動で入れない。確かめの一覧のいちばん上と、そのカードのパネルの上に出し、FP が「推定で埋める」（1件ごと・カードごと・まとめて）か「該当なし」を押したときだけ書く。開いただけでは世帯を1文字も変えない。
- **新しく入れるとき**（新しく作る世帯も、古い世帯で FP が新しく足すときも）: 最初から推定で入れる。子を足すと進路を推定で入れ、「会社員として入れる」・働き方を正社員や公務員にすると退職金の目安を入れる（該当なしにしてあれば入れない）。新しく作る空の世帯は、前からの基本生活費の推定と本人の仮の値から始まる（子・働き方は FP が足したときに推定が入る）。
- 推定で入れた進路は、推定のまま（行が出どころ `auto` の推定）なら、子の生年月・計算基準月に合わせて入れ直す（推定の入れ直し）。FP が進路の型・段を変えると、行が外れて入れ直さない。
- 推定で入れる物は、今ある推定の関数で作れる範囲だけ。作れない物（定年後の再雇用、生活費の段階、本人・配偶者の介護の費用、年金の見込額の推計、家賃の統計の目安）は「推定で埋める」を出さない（未入力の警告と「開く」だけ）。足していく。

### 7. プランを選んでいるとき

- 値の状態の操作も、そのプランの差分にする（0036 の8）。プランの中身（作業中の世帯）に同じ操作を当て、できた値の箱を、そのプランのその当て先の自分の差分（値を変える `set`）にする（`planStateOp`・`plans.ts` の `setPlanValue`）。
  - 土台の中身（土台が無ければ現状）と同じ値の箱に戻ったら、自分の差分を消す。
  - このプランで足した物の中の値なら、その足す差分の物を直す（`set` を重ねない）。
  - 差分の `before` は、作った時点の現状の値の箱（画面の中の仮の印は推定の箱として読む）。
- 欄の部品は、操作を親から受け取る（`FieldStateOps`）。入力のパネルは今は現状を直す操作を渡す。入力画面でプランを直す画面を作る回に、プランを選んでいるときは `planStateOp` を渡す（部品は変えない）。

## 理由

- **同じ値の書き戻しで状態を変えない**: 欄を通るだけで推定が確定になると、FP が確かめていない推定が「確定」として残り、確かめの一覧からも消える。明示の操作だけにすれば、推定の印が確かめた所と確かめていない所を正しく分ける。
- **確定に推定の根拠を残す**: 値の箱には行が無いので、記録の無い確定と FP が確かめた確定を見分ける欄が要る。`estimate` はスキーマ上どの状態でも持て、計算に使わず、どの値の種類にも同じ形で付く。
- **値が変わった所の行を外す**: 行はその値の状態の記録なので、値が変われば記録ではなくなる。前からの行で値の変わった所だけを外せば、操作で書いた行・値の変わらない所の行を誤って消さない。
- **取り込みで値が変わらない所の行を残す**: ヒアリングで同じ物を取り込み直すたびに、FP が決めた「該当なし」「わからない」が消えると、確かめの一覧に同じ所が何度も戻る。値が変わった所は取り込んだ値と承認が正。
- **古い世帯に自動で入れない**: 開いただけで教育費・退職金が入ると、前に出した提案と結果が黙って変わる。押したときだけ入れれば、FP が変わる所を知った上で選べる。
- **新しく入れるときは推定から**: 入れ忘れた教育費・退職金が0円のまま結果に出る誤りを、新しい世帯から無くす。外れたときは確かめの一覧の上に出て、該当なしにできる。

## 代案（採らなかったもの）

- **欄を離れたら同じ値でも確定にする（前のまま）**: 上の理由のとおり、確かめていない推定が確定になる。
- **「✓ この値で確定」を根拠の無い確定にする**: 打った値・古い世帯の値と見分けられず、目安のボタンと同じ値の候補が消せない。
- **古い世帯を開いたときに、0円の所へ推定を入れて知らせる**: 黙って書き換えないの決まり（0035 の11）に反する。知らせを閉じただけで結果が変わる。
- **入っていない物の該当なしを、画面の側の新しい欄に持つ**: 世帯ファイルの形が変わる。値の状態の行（物の `valueStates`）と保存した項目の印で持てる。
- **取り込みで置き換えた物の行を全部捨てる**: FP の決めた状態が取り込みのたびに消える。

## 影響

- **画面**: 欄の定義に `write`（同じ値の確かめをしない書き方）・`boxed`（箱の読み書き）・`address`（当て先）を足した。欄の部品に状態の印（推定・わからない・該当なし・未入力）と4つの操作、入力のパネルに「推定をまとめて確定」と入っていない物の知らせ、入力のホームに確かめの一覧。目安のボタンを推定（`standard`）で入れる。
- **世帯ファイルの形**: 変えない（形式 0.17 のまま）。値の状態の行と確定の箱の `estimate` は 0.17 の形の中。
- **エンジン**: 変えない。わからない・該当なしの値の箱は前から読める（代わりの値・値なし）。
- **計算の結果**: 見本の世帯・モデル世帯は変わらない（開いただけでは書かず、ボタンの値は同じ値の推定）。FP が「推定で埋める」を押した世帯と、新しく子・会社員の働き方を足した世帯は、教育費・退職金の分だけ結果が変わる。
- **守ること**:
  - 欄の書き方は、同じ値なら世帯を返す（同じもの）。状態は明示の操作だけで変える。
  - 値の状態を読む・変えるのは `valueState.ts` を通す（値の箱か行かを呼ぶ側で分けない）。
  - 古い世帯を開く道で、推定の物を足さない（`gapsOf` に出すだけ）。
- **テスト**: `app/test/value-state.test.ts`（欄を通る・同じ値を書き戻すで変わらない、4つの操作と計算できること、まとめて確定、打ったときの行の直し、取り込みの行、保存と読み直し、プランの中の操作、古い世帯に自動で入れない・推定で埋める・該当なし、新しく入れるときの推定と入れ直し、確かめの一覧）。
