# 0236. 入力画面の部品の見た目をそろえる（チェックは1行・チェックで出てきた欄のまとまり・区切りボタンは欄ごとの指定・小さなボタンの形・まとまりの見出し）

- 状態: 採用（一部未確定）（2026-11-21）
- 固定の強さ: 内部（画面の見せ方）。世帯ファイルの形・保存される値・計算は変えない。欄の定義に足した指定（`FieldBase.opens`、選ぶ欄の `segmented`・`onOff`、ボタンの `check`）は見せ方だけの印で、欄の読み書き（`get`・`set`）は今までのまま。どの欄に付けるかは後から変えてよい。決まりとして残すのは「区切りボタンは選択肢の数で自動に切り替えず、欄ごとに指定する」「同じ名前・同じ選択肢の欄は、入力項目をまたいで同じ形にする」「人を選ぶ欄は区切りボタンにしない」の3つ
- 前提にする記録: 0016（カスタマイズ層の「欄を隠す・並べ替える」）、0041（値の状態と推定の欄の見た目）、0077（説明は「?」の中・まとまりの中枠）、0078（標準の欄と「▸ 続きを見る」）

## 背景

- 入力画面の部品（チェック・選ぶ欄・小さなボタン・まとまりの見出し）が、入力項目ごとに少しずつ違う形で増えていた。
  - チェックの欄は「名前の行」と「四角の行」の2段で、数字の欄と並ぶと何のチェックか読み取りにくかった。
  - チェックを入れると下に欄が出てくる所（収益不動産の「貸している」「売る予定がある」など）は、出てきた欄がほかの欄と同じ並びに混ざり、どのチェックの中身かが分からなかった。
  - 同じ「オン・オフ」なのに、チェック・2択の選ぶ欄（「使う／使わない」）・押すと名前が変わるボタン（「住宅ローン控除を受けない」⇄「受ける」）の3通りがあった。
  - 2〜3択の選ぶ欄は、開かないと選択肢が見えない。「性別」「返済方法」のように決まった短い2択は、並べて見せた方が早い。
  - 小さなボタン（「＋ 〜」・「この値にする」・単位のボタンなど）の角・文字の色・選んでいる状態の見せ方がばらばらだった。
  - 欄が少ないまとまりは「左に見出し・右に欄」の詰めた形で描くが、見出しに要約やボタン（「ホームに出す」「外す」）が載ると、左の狭い列に押し込まれて要約が3行に折れ、ボタンが散らばった（介護・親の標準）。
- 試しの版でこれらをまとめて形にして比較し、利用者の判断（2026-11-20）で次を採用した。試しの版では、2〜3択を選択肢の数で自動に区切りボタンへ切り替えたが、同じ入力項目の中で区切りボタンと選ぶ欄が混ざって見えた（選択肢の言葉が長い欄・人を選ぶ欄は幅が足りず選ぶ欄のままになるため）。このため、**欄ごとに指定する**形に改める。単位のボタンに付けていた「⇄」の印は採用しない。

## 決定

### 1. チェックの欄は1行（四角が左・名前が右）

- 値が真偽の欄（読むだけ・検索つきを除く）は、四角を左、名前を右の1行で描く。名前を押しても切り替わる。「?」と状態の印は名前のすぐ後ろ。
- 数字の欄・選ぶ欄と並んだときは、名前の行のぶんだけ下げて、四角の行を隣の入力の行と同じ高さにする。選ぶ欄と区切りボタンの行は、数字の欄と同じ高さにそろえる。
- 行にチェックしか無いのに上に空きが残らないように、次のチェックは行に1つで置く（幅いっぱい・下げない）: 並びにチェックが1つだけ／並びの最後に続くチェック（後ろにチェックでない欄が無い）／出てくる欄を持つチェック（3）のすぐ前のチェック。
- 名前が長くて折れても、四角は1行目の高さのまま。「?」は名前の最後の字と離れない（「?」だけが次の行に落ちない）。

### 2. オン・オフは、どこでもチェックで

- オン・オフだけの2択の選ぶ欄は、欄に `onOff: { on, off }`（選択肢の値）を書くと、チェックの欄と同じ見た目で描く。**書かれる値は選択肢の値のまま**（真偽に変えない）。選択肢がこの2つだけで、今の値がどちらかのときだけチェックにする（ほかの値が残っている間は選ぶ欄のまま）。
- オン・オフを切り替えるボタンは、ボタンに `check: { label, on }` を書くと、チェックの見た目で描く。押したときの処理はボタンのときのまま。
- 付けた所: 働き方と収入の「統計の年齢カーブで増やす」（`use`／`none`）、住宅ローンの「住宅ローン控除を受ける」（今の残高から入れたローンの「受けない」⇄「受ける」のボタン）。

### 3. チェックで出てきた欄は、チェックのすぐ下に「左の線＋字下げ」でまとめる

- チェックの欄に `opens` を書く: `"rest"` は同じ並びの後ろの欄すべて（と、間に入るボタン・まとまり）、キーの並びはその欄だけ（チェックのすぐ後ろに続く欄）。
- チェックは行に1つで置き、出てきた欄はそのすぐ下に、左の線（まとまりの中枠と同じ線）と字下げでひとまとまりにする。まとまりには「〜で出てきた欄」の名前を付ける（読み上げ用）。
- キーの並びで書いたチェックは、外しているときも行に1つのまま（入れたときに置き場が動かない）。
- 出てくる欄を持つまとまりは、詰めた形（5）にしない。
- 付けた所: 収益不動産の「貸している」「売る予定がある」、貯蓄・運用の「売る予定がある」（どれも `"rest"`）、働き方と収入の「勤め先に確定給付企業年金・共済などがある」（掛金の欄）、住宅ローンの団体信用生命保険の「就業不能の特約」（残高が消えるまでの月数の欄。チェックのすぐ後ろに並べ替えた）。
- **事務所のカスタマイズとの関係**: 欄の並べ替え・隠すは今までどおり先に効き、その後の並びでまとまりを作る。出てきた欄を事務所が別の所へ並べ替えると、その欄は左の線のまとまりの外に、ふつうの欄として出る（欄は増えも減りもしない）。

### 4. 区切りボタン（欄ごとの指定）

- 選ぶ欄に `segmented: true` を書くと、全部の選択肢をボタンで並べ、選んでいる方を塗りで見せる（`role="radiogroup"`・矢印キーで移る）。書かれる値は選択肢の値のまま。空欄のまま推定で計算している選択肢は点線（推定の欄の枠と同じ意味）。
- **選択肢の数では決めない**。指定してよいのは、選択肢が決まった2〜3個で、言葉が短い欄だけ（詰めた形の列の幅に1行で収まる）。
- **人・口座など、世帯で中身が変わる選択肢の欄には付けない**（ご本人／配偶者の2択でも選ぶ欄のまま。家族が増えると選択肢が増え、形が入れ替わるため）。
- **同じ名前・同じ選択肢の欄は、入力項目をまたいで同じ形にする**。テスト（`app/test/input-parts.test.ts`）が、見本の世帯すべてで混ざりが無いことを確かめる。
- 読むだけの欄・見出しつきの選択肢・検索つき・選択肢が1つの欄は、指定があっても選ぶ欄のまま。
- 指定した欄（2026-11-21）:

| 欄の名前 | 選択肢 | 入力項目 |
|---|---|---|
| 性別 | 男性｜女性 | 家族、介護・親（世帯の外の家族） |
| 入れ方 | 総額で｜内訳で／今の額に対する割合で｜月額で／額で｜今の額に対する割合で／利回りで｜資産の配分で | 基本生活費、時期で変わる欄（段階） |

- 選ぶ欄のままにした2〜3択: 人を選ぶ欄（名義・契約者・受取人・払う人・相手・介護を受ける人など）、口座を選ぶ欄、「公立・私立」（子ども・教育の学校ごとの欄。選択肢が3つの欄と2つの欄があり、1つの表の中で形が割れるため全部を選ぶ欄に）、「種類」、「おまかせ」を含む3択、括弧の注が長い2択（高校の就学支援金・維持費の入れ方・ローンの「入れ方」）。

### 5. まとまりの見出しと、詰めた形

- （下の「7. 追記」で、詰めた形そのものを無くした。この項は最初の決まりとして残す）詰めた形（左に見出し・右に欄）は、**見出しだけの小さなまとまり**に限る。見出しに要約・ボタン（「ホームに出す」「外す」）・推定のままの1行・「▸ 続きを見る」のどれかがあるまとまりと、出てくる欄を持つまとまり（3）は、見出しを上に1行で置くふつうの形にする。
- 見出しの並びは **名前 →「?」→ 要約**。右のボタンは、要約が長くても折れない・縮まない（要約の方が折り返す）。
- これで、子ども・教育の「第1子の進路」のように「▸」を開くと見出しが動く所も動かなくなる。

### 6. 小さなボタンの形

- 欄のまわりのボタンは4段にそろえる: ふつう＝藍の枠（「＋ 〜」。小さい物は「この値にする」）／控えめ＝下線のリンク／危ない＝赤い文字／主＝藍の塗り。
- **主のボタン（「保存」など）の大きさは変えない**。
- 角の丸み・文字の色・押せないときの見た目を主のボタンとそろえる。選んでいる状態のボタン（目安の選択など）は塗りだけで見せる（頭の「●」は外す）。

### 7. 追記（2026-11-21）: 枠の見出しの残り3点（利用者の判断）

最初の変更の後に、見出しの形がそろっていない所が3つ残っていた。利用者の判断で3つとも直す。どれも見せ方（名前と並び）だけで、世帯のデータ・保存の形・計算は変えない。

**(1) 詰めた形を無くす**

- 5 で「見出しだけの小さなまとまり」に残した詰めた形（左の幅170pxの列に見出し・右に欄）は、名前が長いと左の列で何行にも折れた（ライフイベント・相続の詳細の「払う人・伸び方・万一のときの扱い」）。
- 名前の長さで形を分ける決まりは、文字の大きさ（標準・大）や名前の付け方で崩れる。**どのまとまりも、見出しは幅いっぱいの1行・欄は次の行から**にそろえ、詰めた形そのものを無くす（`FieldViews.tsx` の `Group` の判定と、`app.css` の `.in-group.compact` の決まりを消す）。
- 調べた範囲: 見本の世帯すべて × 全部の入力項目 × 標準・詳細（「▸」は全部開く）。詰めた形が残っていたのは4種類で、どれも同じ直しで見出しが上の1行になる。

| まとまり | 入力項目 | 前の形 |
|---|---|---|
| 払う人・伸び方・万一のときの扱い（払う人・相手・…も） | ライフイベント、相続・贈与 | 左の列で名前が3〜4行に折れる |
| あげる贈与（課税の方法など） | 相続・贈与 | 左の列に名前と「?」 |
| 児童手当・就学支援金 | 子ども・教育（詳細） | 左の列で名前が2行に折れる |
| ご本人の確定申告・配偶者の確定申告 | 働き方と収入 | 左の列に名前（1行に収まっていた） |

- `GroupDef.wideHead`（詰めた形にしない指定）は、指定が残っていても何も変わらない（今はどのまとまりも同じ形）。

**(2) お金の行・夢の見出しは、名前と要約を分ける**

- 入る・出るお金の行（ライフイベント・相続と贈与・仕送りなど）と夢の枠は、太字の名前の中に額と時期が入っていた（「家族旅行 30万円・毎年 2030年4月〜最後まで」が全部太字）。
- 見出しを **名前 →「?」→ 要約** にそろえる: 太字は名前（「家族旅行」「夢1｜家族で海外旅行」）だけ、額と時期（夢は「（最初から計算に入れない）」も）は後ろの小さな字の要約に分ける。
- 仕組み: まとまりに、見出しに出す名前（`GroupDef.headName`）を足す。**一覧の名前（`title`）は前のまま「名前 額 時期」**で、確かめの一覧・検索・プランの違い・書類の読み取りに出る名前は変えない（名前を付けていない同じ種類の行〔「毎年の支出」が2つなど〕を、額と時期で見分けられるように）。`title` は `headName` と要約を空白でつないだ物と同じ（テストで確かめる）。
- 直した所: `moneyRows.ts` の行の見出し（入るお金の行・出るお金の行の2か所）と、`events.ts` の夢の枠。

**(3) 介護の段階が2つ以上のときは、名前に段階を付ける**

- 「＋ 次の段階を足す」で段階を足すと、枠の名前が両方「母の介護」になり、見出しでも一覧でも見分けられなかった。
- 同じ人の介護が2つ以上あるときは「母の介護（1段階目）」「母の介護（2段階目）」と出す。**1つだけのときは今のまま「母の介護」**。父・配偶者の親・ご本人など、どの人でも同じで、人ごとに数える。
- 数え方は、世帯の中の並びの順（入力の画面で上から並ぶ順。足した段階は末尾に入る）。始まりの月では数えない（始まりを直している途中で、名前が入れ替わらないように）。
- 名前を作る関数は1つ（`labels.ts` の `careLabel`・`careStageMark`）にして、名前を出す所はどこもそれを使う。

| 名前が出る所 | 段階が2つ以上のとき | 仕組み |
|---|---|---|
| 入力の画面の見出し | 母の介護（2段階目） | まとまりの名前 |
| 確かめの一覧 | 母の介護（2段階目）: 在宅か施設か など | まとまりの名前から |
| 入力の検索 | 母の介護（2段階目） | まとまりの名前から |
| プランの違い | 母の介護（2段階目）: … | まとまりの名前から |
| 書類の読み取りの入れ先 | 母の介護（2段階目）: … | まとまりの名前から |
| ホームに出した項目 | 母の介護（2段階目） | 同じ関数 |
| 計算のお知らせの物の名前 | 母の介護（2段階目） | 同じ関数 |
| 近い予定の一覧 | 母の介護（2段階目）が始まる見込み | 同じ関数 |

- 変えない所: 人ごとにまとめる名前（費用の合計の見出しなど「母の介護」）、ヒアリングの質問の名前、ご本人・配偶者の未入力の知らせ（「…の介護の費用」）。どれも段階ごとの名前ではない。
- プランの違いは、現状とプランの両方から名前を引き、先に見つけた方（現状）を使う決まりのまま。現状は1段階・プランの中だけで段階を足したときは、現状からある段階は「母の介護」、足した段階は「母の介護（2段階目）」と出る（プランの編集の画面の見出しは「母の介護（1段階目）」）。
- 介護の区画の説明の「段を並べます」は「段階を並べます」に直す（画面の言葉は「段階」）。

### 8. 追記（2026-11-21）: 切り替えのボタンの色と文字をそろえる（利用者の判断）

未確定に残していた3点を、利用者の判断で決めた。

- **「公立・私立」「種類」、人や口座を選ぶ欄、「おまかせ」付きの3択、注の長い2択は、選ぶ欄のまま**（選択肢が増えうる所と、横に並べると幅が足りない所のため）。
- **同じ「入れ方」という名前でも、短い2択は区切りボタン・選択肢の多い所は選ぶ欄のまま**（名前の方は変えない）。
- **切り替えのボタンは、色と文字の大きさをそろえる**。欄の区切りボタンは藍・小さめの文字、パネルの頭の「標準／詳細」と、画面や区画の切り替え（グラフの切り替え・貯蓄の「入れ方」・前提と推定の一覧の絞り込み・提案書の出し方など）は墨・大きめの文字で、同じ「並んだ中から1つ選ぶ」ボタンが2つの見た目になっていた。次の形に1つにする。

| | 前 | 後 |
|---|---|---|
| 選んでいる方 | 欄の中＝藍の塗り／そのほか＝墨の塗り（切り替えは頭に「●」） | どれも藍の塗り・白い文字（「●」は付けない。6 の「塗りだけで見せる」と同じ） |
| 選んでいない方 | 欄の中＝白地に藍の文字／そのほか＝白地に墨の文字 | どれも白地に藍の文字（重ねると薄い藍） |
| 枠と仕切りの線 | 欄の中＝藍／そのほか＝墨 | どれも藍 |
| 文字の大きさ | 0.86rem（欄の中）・1rem（「標準／詳細」・貯蓄の「入れ方」）・0.9rem（切り替え）・0.85rem（貯蓄の小さい切り替え） | どれも 0.9rem |

- 決まりは `app/src/styles/app.css` の `.level-switch`・`.seg-g`・`.fld-c > .seg-g.fld-seg` の3つに置く。3つとも同じ色の変数（`--prop`・`--prop-ink`・`--prop-bg`・`--on-fill`）を使うので、暗い画面でも同じ見た目になる。
- そろえないもの: 線の太さは隣の部品に合わせたまま（欄の中は入力の枠と同じ 1.5px、画面とパネルの頭は 2px）。「入力項目を選ぶ」と事務所の設定の一覧に並ぶ小さい「標準／詳細」は、行に収めるため小さい文字（0.78rem）のまま（色はそろう）。
- 欄の区切りボタンは文字が少し大きくなる（0.86rem → 0.9rem）。見本の世帯で全部の入力項目を標準・詳細、文字の大きさ 中・大で開き、折り返しと横のはみ出しが前と変わらないことを確かめた。
- キーボードで移ったときの黄色い枠は、ボタンの内側に出す（枠の角で切れないように）。
- 持ち帰り用のレポートの切り替えも同じ決まりを使うので、同じ色になる。
