# 0236. 入力画面の部品の見た目をそろえる（チェックは1行・チェックで出てきた欄のまとまり・区切りボタンは欄ごとの指定・小さなボタンの形・まとまりの見出し）

- 状態: 採用（一部未確定）（2026-11-21）
- 固定の強さ: 内部（画面の見せ方）。世帯ファイルの形・保存される値・計算は変えない。欄の定義に足した指定（`FieldBase.opens`、選ぶ欄の `segmented`・`onOff`、ボタンの `check`）は見せ方だけの印で、欄の読み書き（`get`・`set`）は今までのまま。どの欄に付けるかは後から変えてよい。決まりとして残すのは「区切りボタンは選択肢の数で自動に切り替えず、欄ごとに指定する」「同じ名前・同じ選択肢の欄は、入力項目をまたいで同じ形にする」「人を選ぶ欄は区切りボタンにしない」の3つ
- 前提にする記録: 0016（カスタマイズ層の「欄を隠す・並べ替える」）、0041（値の状態と推定の欄の見た目）、0077（説明は「?」の中・まとまりの中枠）、0078（標準の欄と「▸ 続きを見る」）

## 背景

- 入力画面の部品（チェック・選ぶ欄・小さなボタン・まとまりの見出し）が、入力項目ごとに少しずつ違う形で増えていた。
  - チェックの欄は「名前の行」と「四角の行」の2段で、数字の欄と並ぶと何のチェックか読み取りにくかった。
  - チェックを入れると下に欄が出てくる所（収益不動産の「貸している」「売る予定がある」など）は、出てきた欄がほかの欄と同じ並びに混ざり、どのチェックの中身かが分からなかった。
  - 同じ「オン・オフ」なのに、チェック・2択の選ぶ欄（「使う／使わない」）・押すと名前が変わるボタン（「住宅ローン控除を受けない」⇄「受ける」）の3通りがあった。
  - 2〜3択の選ぶ欄は、開かないと選択肢が見えない。「性別」「返済方法」のように決まった短い2択は、並べて見せた方が早い。
  - 小さなボタン（「＋ 〜」・「この値にする」・単位のボタンなど）の角・文字の色・選んでいる状態の見せ方がばらばらだった。
  - 欄が少ないまとまりは「左に見出し・右に欄」の詰めた形で描くが、見出しに要約やボタン（「ホームに出す」「外す」）が載ると、左の狭い列に押し込まれて要約が3行に折れ、ボタンが散らばった（介護・親の標準）。
- 試しの版でこれらをまとめて形にして比較し、利用者の判断（2026-11-20）で次を採用した。試しの版では、2〜3択を選択肢の数で自動に区切りボタンへ切り替えたが、同じ入力項目の中で区切りボタンと選ぶ欄が混ざって見えた（選択肢の言葉が長い欄・人を選ぶ欄は幅が足りず選ぶ欄のままになるため）。このため、**欄ごとに指定する**形に改める。単位のボタンに付けていた「⇄」の印は採用しない。

## 決定

### 1. チェックの欄は1行（四角が左・名前が右）

- 値が真偽の欄（読むだけ・検索つきを除く）は、四角を左、名前を右の1行で描く。名前を押しても切り替わる。「?」と状態の印は名前のすぐ後ろ。
- 数字の欄・選ぶ欄と並んだときは、名前の行のぶんだけ下げて、四角の行を隣の入力の行と同じ高さにする。選ぶ欄と区切りボタンの行は、数字の欄と同じ高さにそろえる。
- 行にチェックしか無いのに上に空きが残らないように、次のチェックは行に1つで置く（幅いっぱい・下げない）: 並びにチェックが1つだけ／並びの最後に続くチェック（後ろにチェックでない欄が無い）／出てくる欄を持つチェック（3）のすぐ前のチェック。
- 名前が長くて折れても、四角は1行目の高さのまま。「?」は名前の最後の字と離れない（「?」だけが次の行に落ちない）。

### 2. オン・オフは、どこでもチェックで

- オン・オフだけの2択の選ぶ欄は、欄に `onOff: { on, off }`（選択肢の値）を書くと、チェックの欄と同じ見た目で描く。**書かれる値は選択肢の値のまま**（真偽に変えない）。選択肢がこの2つだけで、今の値がどちらかのときだけチェックにする（ほかの値が残っている間は選ぶ欄のまま）。
- オン・オフを切り替えるボタンは、ボタンに `check: { label, on }` を書くと、チェックの見た目で描く。押したときの処理はボタンのときのまま。
- 付けた所: 働き方と収入の「統計の年齢カーブで増やす」（`use`／`none`）、住宅ローンの「住宅ローン控除を受ける」（今の残高から入れたローンの「受けない」⇄「受ける」のボタン）。

### 3. チェックで出てきた欄は、チェックのすぐ下に「左の線＋字下げ」でまとめる

- チェックの欄に `opens` を書く: `"rest"` は同じ並びの後ろの欄すべて（と、間に入るボタン・まとまり）、キーの並びはその欄だけ（チェックのすぐ後ろに続く欄）。
- チェックは行に1つで置き、出てきた欄はそのすぐ下に、左の線（まとまりの中枠と同じ線）と字下げでひとまとまりにする。まとまりには「〜で出てきた欄」の名前を付ける（読み上げ用）。
- キーの並びで書いたチェックは、外しているときも行に1つのまま（入れたときに置き場が動かない）。
- 出てくる欄を持つまとまりは、詰めた形（5）にしない。
- 付けた所: 収益不動産の「貸している」「売る予定がある」、貯蓄・運用の「売る予定がある」（どれも `"rest"`）、働き方と収入の「勤め先に確定給付企業年金・共済などがある」（掛金の欄）、住宅ローンの団体信用生命保険の「就業不能の特約」（残高が消えるまでの月数の欄。チェックのすぐ後ろに並べ替えた）。
- **事務所のカスタマイズとの関係**: 欄の並べ替え・隠すは今までどおり先に効き、その後の並びでまとまりを作る。出てきた欄を事務所が別の所へ並べ替えると、その欄は左の線のまとまりの外に、ふつうの欄として出る（欄は増えも減りもしない）。

### 4. 区切りボタン（欄ごとの指定）

- 選ぶ欄に `segmented: true` を書くと、全部の選択肢をボタンで並べ、選んでいる方を塗りで見せる（`role="radiogroup"`・矢印キーで移る）。書かれる値は選択肢の値のまま。空欄のまま推定で計算している選択肢は点線（推定の欄の枠と同じ意味）。
- **選択肢の数では決めない**。指定してよいのは、選択肢が決まった2〜3個で、言葉が短い欄だけ（詰めた形の列の幅に1行で収まる）。
- **人・口座など、世帯で中身が変わる選択肢の欄には付けない**（ご本人／配偶者の2択でも選ぶ欄のまま。家族が増えると選択肢が増え、形が入れ替わるため）。
- **同じ名前・同じ選択肢の欄は、入力項目をまたいで同じ形にする**。テスト（`app/test/input-parts.test.ts`）が、見本の世帯すべてで混ざりが無いことを確かめる。
- 読むだけの欄・見出しつきの選択肢・検索つき・選択肢が1つの欄は、指定があっても選ぶ欄のまま。
- 指定した欄（2026-11-21）:

### 5. まとまりの見出しと、詰めた形

- 詰めた形（左に見出し・右に欄）は、**見出しだけの小さなまとまり**に限る。見出しに要約・ボタン（「ホームに出す」「外す」）・推定のままの1行・「▸ 続きを見る」のどれかがあるまとまりと、出てくる欄を持つまとまり（3）は、見出しを上に1行で置くふつうの形にする。
- 見出しの並びは **名前 →「?」→ 要約**。右のボタンは、要約が長くても折れない・縮まない（要約の方が折り返す）。
- これで、子ども・教育の「第1子の進路」のように「▸」を開くと見出しが動く所も動かなくなる。

### 6. 小さなボタンの形

- 欄のまわりのボタンは4段にそろえる: ふつう＝藍の枠（「＋ 〜」。小さい物は「この値にする」）／控えめ＝下線のリンク／危ない＝赤い文字／主＝藍の塗り。
- **主のボタン（「保存」など）の大きさは変えない**。
- 角の丸み・文字の色・押せないときの見た目を主のボタンとそろえる。選んでいる状態のボタン（目安の選択など）は塗りだけで見せる（頭の「●」は外す）。
