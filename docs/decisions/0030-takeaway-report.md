# 0030. 持ち帰り用の動くレポート（顧客に渡す HTML ファイル1つ）

- 状態: 採用（一部未確定）（2026-10-21）
- 固定の強さ: 骨格（ファイルの中のデータの入れ物の形 `financia.takeaway` の版1・暗号の方式・CSP の考え方・中身に入れてよい値の型と、計算の要求から外す欄の決め方）。画面の見た目・載せる画面の選択肢・注意書きの文言・ファイル名は後から変えてよい（変えたら追記に書く）

## 背景

- 提案書の PDF（0009）は紙と同じで、顧客が「働く年齢を2年延ばしたら」「生活費を月2万円減らしたら」を自分で試せない。面談の後に家で家族と見直すための、動くレポートが欲しい。
- 顧客にアプリを入れてもらう形や、サーバーで見せる形は取らない。顧客のデータが提供元のサーバーを通らないこと（0012）と、オフラインで開けることが前提。
- 書き出しの決まり（0020）: 平文で出るのは FP が画面で明示的に操作したときだけ、警告と記録つき、既定の保存先はカスタム層・AI の作業フォルダの外、パスを画面に渡さない。提示層の約束（0016 の2）: 顧客に見せるものは、内部情報を受け取らない部品と型で作る。
- 関連: 計算エンジンの二本立ては 0005、制度データの形式は 0007、世帯のデータは 0008、控えは 0009、世帯ファイルの形式移行は 0011、持たない情報は 0012、画面の安全は 0016、書き出しは 0020、バランスシートの図は 0027。

## 決定

### 1. 形: ブラウザで開く HTML ファイル1つ

- FP が世帯ごとに書き出し、顧客に渡す。顧客はブラウザで開き（ネットワークは要らない）、グラフを見て、FP が許したつまみを動かして試せる。外のファイル・サーバーは一切読まない。
- 1つのファイルに次を入れる:
  1. 画面の部品（`app/src/takeaway/viewer/` を1つの JS と1つの CSS にまとめたもの。`scripts/build-takeaway.ts`）。
  2. 計算エンジン: `engine/dist/engine.js` と**バイト単位で同じもの**（アプリの画面側のエンジン、本体が埋め込むものと同じファイル）を gzip で縮めて Base64 にした塊と、元の JS の SHA-256。開いたときにほどき、指紋を確かめてから読み込む。
  3. データの塊: 中身（下の2）と、その世帯の計算に必要な制度データ（下の3）を JSON にして gzip で縮め、パスワードを付けたときは暗号化して Base64 にしたもの。
  4. 入れた部品のライセンスの文（提供元の MIT と、画面の部品にまとめた npm の依存の LICENSE をそのまま）。HTML の末尾にコメントで入れ、画面の注意書きに「ファイルの末尾に書いてある」と出す（MIT は写しにライセンスの文を含めることを求めるため）。
- 置き場所: 提案書のタブの中に「提案書（PDF）／持ち帰り用のレポート（ブラウザで開くファイル）」の切り替えを置く（上のタブは増やさない）。どちらも「顧客に渡すもの」で、載せるプランの選び方・宛名・平文の書き出しの出口が同じため。
- 既定のファイル名は `ライフプランの試算_YYYY-MM-DD.html`（パスワードを付けたときは `_パスワードつき` を足す）。顧客に渡すファイルなので、宛名も事務所の中の顧客番号も入れない。

### 2. 中身に入れてよい値（構造で守る）

- 中身の型は `app/src/takeaway/model.ts` の `TakeawayPayload`（許可した項目だけの別の型。提示層の `PresentationModel` と同じ考え方）。作業の層の `app/src/workspace/takeaway/build.ts` が、許可した項目だけを写して作る:
  - 作成日・制度データの版（提案書の刻印と同じ書式）・必須の記載（提案書と同じ文。本体の `report.rs` の文と同じことを cargo test で確かめる）・「○歳時点」の年齢・載せる画面
  - プラン（帯の文字・名前・計算の要求）。先頭は現状（A）。FP の提案のプランと基準のプラン（グラフの点線）は帯の文字で指す
  - 顧客が動かせるつまみ（下の4）
  - 宛名と事務所名（任意。書き出すときに FP が入れたものだけ。保存しない）
- 計算の要求（`EngineRequest`）は `sanitize.ts` で次のとおり加工する:
  - 計算の要求の形はスキーマで決まっていて、決まっていない欄は持てない（`additionalProperties: false`）。その中で文字を自由に入れられる欄を1つずつ扱いを決める（`FREE_TEXT`）: 値の出どころの参照と AI のアプリの名前は外す、推定の根拠の文と周期的な支出の見出しは決まった言葉にする、保険の商品の参照・料金表から写したメニュー・学校のコース・習い事の見出しは外す、学校コードは決まった値に置き換える（学費の行は自己完結で、コードは計算に使わない）。スキーマに自由記述の欄が増えたら、テストが止まり、扱いを決めるまで通らない。
  - 値の出どころ（AI からの候補・ヒアリング・取り込み）は「手で入れた値」にし、承認の記録は外す（AI の記録を持ち出さない）。
  - 物・構成員の ID は、書き出すたびに新しい乱数の ID に付け替える（世帯ファイルの ID と結び付けられないように。対応は保つ）。
- 入れないもの: FP 用のメモ、呼び名、控え、ヒアリングの記録、AI の記録、案の差分（作った日時・出どころ・承認・注記）、世帯の内部 ID、顧客番号、事務所の設定（料金表の写し）、カスタム計算の印、鍵、ファイルのパス。
- 顧客が開く画面の部品（`app/src/takeaway/`）は、lint で読み込みを限る: 作業の層のうち計算結果から提示用の値を作る純粋な部品（`levers`・`present`・`roles`・`balanceTab`）と提示層の部品だけ。本体の命令（`@tauri-apps/*`）・二本立ての部品・画面の大枠は読めない。

### 3. 制度データはその世帯の計算に使うものだけ

- 載せるプランと、提案のプランでつまみをそれぞれ端（いちばん小さい値・大きい値）まで動かした要求・FP顧問料を入れ替えた要求を、根拠の記録の要約（`trace: summary`）で計算し、出てきた制度の値の ID だけを残す（パックの見出しは全部残す）。
- 絞った制度データで同じ要求を計算し直し、全部の制度データの結果と同じになることを確かめる。1つでも違えば全部の制度データを入れる（記録には「絞れなかった」とだけ出す）。
- 制度データのパックの指紋（`digest`）は元のパックのもののまま（絞ったことは中身の値の数で分かる）。エンジンは指紋を確かめない（本体が署名を確かめたパックから作るため）。

### 4. 顧客が動かせるつまみ

- 最初は結果の画面の対策の固定の項目と同じもの: 働く最後の年齢・年金の受け取り開始・NISA の積立額・毎月の生活費、と FP顧問料の入れる・入れない（契約がある世帯だけ）。FP は書き出すときに外したいものを外せる。
- 当て方はアプリの対策と同じ部品（`workspace/levers.ts` の `applyLevers`・`applyAdvisoryFee`）を使い、同じ値なら同じ要求になる。範囲は対策のスライダーと同じ（載せるプランの値が入るように広げる）。範囲の外の値と、許していないつまみは当てない。
- つまみが効くのは見ているプランだけ（現状は動かせない。アプリの対策と同じ）。「↶ 1つ前に戻す」（最後に動かした1つだけを戻す）と「最初に戻す」（顧客が動かした値を全部外し、FP の提案の値にする）を置く（どちらも何が起きるかを言葉だけで分かるようにする。前は「元に戻す」「FP の提案に戻す」で、最初に戻るのか1つ戻るのか分かりにくかった）。
- FP が「動かす項目を追加」で足した項目（住宅ローン・運用の利回りなど）は、最初の版では載せない（未確定）。

### 5. 外と話さないファイル（CSP）

- `<meta http-equiv="Content-Security-Policy">` を文字コードの次（どの読み込みよりも先）に置く:

  ```
  default-src 'none'; script-src 'sha256-<画面の部品>' blob:; style-src 'sha256-<CSS>'; img-src 'none'; font-src 'none';
  connect-src 'none'; media-src 'none'; object-src 'none'; frame-src 'none'; child-src 'none'; worker-src 'none';
  manifest-src 'none'; base-uri 'none'; form-action 'none'
  ```

  - 実行できるのは、ハッシュで決めた画面の部品のスクリプト1つと、その部品が作る `blob:` の URL（縮めた計算エンジンをほどいて読み込むため）だけ。`unsafe-inline`・`unsafe-eval` は使わない。データの塊は実行されない `<script type="application/octet-stream">`・`application/json` に入れる。
  - 画像・フォントは入れない（フォントは端末の日本語のフォント。大きさを抑えるため）。リンク・フォーム・iframe も置かない。
- 画面の部品は、通信（fetch・XHR・WebSocket など）・ブラウザの保存機能・動的な import を使わない（テストで確かめる）。

### 6. 開くときのパスワード

- FP は開くときのパスワードを付けられる（付けることをすすめる）。付けたときは、データの塊（宛名・作成日・事務所名・計算の要求・制度データ）を丸ごと暗号化する。平文で残るのは見出し（形式・版・暗号の値・塩・IV）と、公開のコード（画面の部品・計算エンジン）と、決まった題名だけ。
- 暗号: パスワード（NFC に正規化）から **PBKDF2-SHA256（60万回）** で鍵を作り、**AES-256-GCM** で暗号化する。塩は16バイト、IV は12バイトの乱数で、書き出すたびに変わる。見出しの文字列を追加の認証データにして、回数などの書き換えも見つける。開く側はブラウザの標準の暗号の機能（WebCrypto）で、違うパスワード・書き換えのときは開かない。
- 暗号化はアプリの画面の側で、同じ部品（`app/src/takeaway/container.ts`）を書き出す側と開く側で使う。0016 の1 の「暗号は本体」は世帯の鍵（0013）を画面に渡さないための決まりで、この暗号は FP が画面に入れたパスワードだけを使い、アプリの鍵は関わらない。開く側の実装が同じであることを、往復のテストで確かめられる。本体は保存の前に、「パスワードを付けた」と画面が言うときは見出しに暗号の値（決めた方式・回数60万回以上）があることを確かめる（記録の「パスワードの有無」が正しいように）。
- パスワードはファイルにもアプリにも保存しない。最低8文字。アプリが乱数のパスワード（見間違えやすい文字を除いた4文字×3）を作れる。画面に「ファイルとは別の方法で伝える」と出す。
- 引き継ぎファイル（0020 の3）の Argon2id ではなく PBKDF2 にしたのは、開く側が顧客のブラウザで、標準の機能だけで動かす（外の部品を入れない）ため。回数は今の推奨（60万回）にし、見出しに書くので後から上げられる。

### 7. 書き出しの出口と記録

- 保存は本体の平文の書き出しの出口（`export.rs`。0020 の5・6）を通す。画面は用途ごとの命令 `takeaway_save` に HTML のバイト列と作成日・パスワードの有無だけを渡し、保存先は本体が OS のダイアログで FP に選ばせる。パスは受け取らない・返さない。既定の保存先・止める場所・同期フォルダの知らせは提案書と同じ。
- 本体は保存の前に形を確かめる: 先頭が `<!doctype html>`、CSP の meta で外への通信を止めている、データの見出しがある、パスワードの有無が見出しと合う、大きさが上限（20MB）以下。
- パスワードなしのときは、保存のたびに平文の注意を出す（提案書の PDF より中身が多い。計算に使う入力の値がすべて入るため）。
- 記録: 本体の書き出しの記録（種類・日時・指紋・同期フォルダか）に「パスワードを付けたか」を足した。世帯ファイルには控え（0009 の2）を残す: きっかけ `takeaway` と、`snapshots[].takeaway`（載せたプランの文字と名前・FP の提案のプラン・パスワードの有無・顧客が動かせるつまみ・載せた画面・作成日・ファイルの指紋）。パスワード・宛名・事務所名は持たない。世帯ファイルの形式の版を **0.10** にした（足すだけの MINOR。0.9 までのアプリは知らないきっかけの控えを読み落とすので、版を上げて閲覧だけにする。0011 の5）。

### 8. 画面

- アプリの結果の画面を顧客向けに簡単にしたもの。上から: 見出し（宛名・作成日・事務所名）→ プランの帯（FP の提案・基準・表示中・試し中の札）→ 大きなグラフ（資産の推移・収支の推移。アプリと同じ部品 `MainChart`。ホバーで○・クリックで固定・行き過ぎのない動き）→ 試してみる（つまみ）→ 資産と負債の図（アプリと同じ部品 `BsFigure`。年のつまみと主な年。グラフで固定した年に合わせる）→ キャッシュフロー表の要約（年齢・収入合計・支出合計・年間収支・金融資産残高。既定は5年ごと、すべての年も見られる）→ 注意書き（試算であること・FP に相談すること・どこにも送らないこと、提案書と同じ必須の記載、作成日・制度データの版・事務所名）。
- 載せる画面は FP が選ぶ（グラフはいつも。資産と負債の図・キャッシュフロー表の要約は外せる）。
- スマホの縦の画面（幅375px）でも見られる: 帯は横に送る、グラフは低め、つまみは1列、表は横に送る。狭い幅ではグラフの年の目盛りを10年ごとにする（提示層の `MainChart` に足した。アプリの幅では今までどおり5年ごと）。
  - 画面の幅が 640px 未満（提示層の `narrow.ts`。アプリの画面・提案書の見本にも同じ決まりで効く）: 資産の推移のグラフの中の「○歳で不足」の文字は出さない（線に重なって読みにくい。見出しの文が同じことを言い、0の線の△と縦の点線は残す）。バランスシートの図は図の外の左右の札を描かず、柱を幅いっぱいにして、名前と金額を箱の中と図の下の一覧（折り返すので画面の端で切れない）に出す。
  - グラフの使い方の文は、狭い幅・タッチの端末（ホバーできない）では「グラフを押すとその年の数字が出ます」だけにする（「クリック」「Esc」を言わない）。
- アプリの提案書のタブの右に、顧客が開いたときと同じ画面の見本を出す（同じ部品 `TakeawayView`。計算は画面側のエンジン）。
- 事務所名は、事務所の設定ができるまで、書き出すときに入れる欄（アプリを開いている間だけ覚える）。個人の氏名は入れない形をすすめる。

## 理由

- **HTML ファイル1つにする**: 顧客は特別なものを入れずに開け、メールや共有のフォルダで1つのファイルとして渡せる。データがファイルの中だけにあるので、提供元のサーバーを通らない（0012）。
- **計算エンジンを同じバイト列で入れる**: 顧客がつまみを動かした結果と、アプリの画面で FP が見せた結果が同じ計算になる。別に作り直したエンジンだと、数字が食い違う原因になる。指紋で同じことを確かめられる。
- **中身を許可した型で作り、自由記述の欄をスキーマから機械的に洗い出す**: 「見せないように気をつける」方式は、欄が増えるたびに漏れる。型とテストで、内部情報が入りようがない形にする（0016 の2 と同じ考え方）。
- **CSP をファイルの中に持つ**: 顧客の端末のブラウザの設定に頼らず、ファイル自身が外への通信を止める。画面の部品にコードの誤りがあっても、外への送信に至らない。
- **制度データを絞り、絞った結果を確かめる**: ファイルを小さくし、その世帯に関係のない制度の値を配らない。確かめで違いが出たら全部入れるので、数字の正しさを犠牲にしない。

## 影響

- **後から変えると**: データの入れ物の形・暗号の方式を変えると、渡したファイルを新しい部品で開けなくなる（渡したファイルは自分の中に開く部品を持っているので開けなくなることはないが、形を変えるときは版を上げる）。CSP を緩めると、顧客の端末から外へ送れる形になりうる。
- **守るべき決まり**
  - 中身は `TakeawayPayload` だけ。項目を足すときは、内部情報でないことを確かめ、テストの許可した項目の一覧も直す。
  - 計算の要求のスキーマに自由記述の欄を足したら、`FREE_TEXT` で扱いを決める（決めるまでテストが止まる）。
  - 顧客が開く画面の部品から、本体の命令・世帯ファイル・AI の部品を読み込まない（lint）。
  - CSP を緩めない。画面の部品で通信・保存の機能・動的な import を使わない。
  - 暗号の回数を下げない。パスワードをファイルにもアプリにも保存しない。
- **テストで確かめること**（`app/test/takeaway.test.ts`・`app/scripts/check-takeaway.ts`・`app/src-tauri/src/takeaway.rs`）
  - 目印の文字を入れた世帯（メモ・呼び名・案の注記・AI の出どころ・料金表のメニュー・周期的な支出の見出し・推定の根拠・学校コード・保険の商品の参照）で、中身に目印も元の ID も出ない。ID を付け替えても計算の数字は同じ。
  - パスワードありのとき、ファイルのどこにも平文の数字・宛名・事務所名・プランの名前が残らない。データの塊は gzip としてほどけない。正しいパスワードだけで開き、違うパスワード・1ビットの書き換え・見出しの書き換えでは開かない。塩と IV は毎回違う。
  - CSP の meta が先頭にあり、外への通信を止めている。実行するスクリプトは1つでそのハッシュが CSP にある。外を指す属性・要素が無い。画面の部品が通信・保存の機能を使わない。計算エンジンが `engine/dist/engine.js` とバイト単位で同じ。
  - つまみの当て方がアプリの対策と同じ。制度データを絞っても、つまみの端まで同じ結果。
  - ネットワークを切ったヘッドレスのブラウザで開き（CI でも）: グラフが出る・つまみで計算し直す・1つ前に戻す・最初に戻す・スマホの幅で横にはみ出さない・CSP の違反が0件・外へのリクエストが0件。パスワードありは違うパスワードで開かず、正しいパスワードで開く。
  - 本体: 形の確かめ（CSP が無い・緩い・パスワードの有無が合わない・大きすぎるものは保存しない）、既定のファイル名に日付だけ、必須の記載が提案書と同じ。

## 試作での確認

- 架空のモデル世帯（会社員の夫婦と子2人）でプランを6つ載せたファイルが約 1.0MB（1,021,236 バイト）。内訳は計算エンジン（gzip・Base64）約 0.69MB、画面の部品（JS と CSS）約 0.20MB、データの塊（中身と絞った制度データ。gzip・Base64）約 0.11MB、ライセンスの文 約 2KB。制度データは 479 の値のうち 210 に絞れた（元の JSON で約 2.0MB → 約 1.2MB、縮めた後は約 0.1MB）。パスワードの有無で大きさはほぼ変わらない。
