# 0212. 結果の画面の文を事務所の言い方に直せるようにし、AI接続口に差し替えられる文の一覧を返す道具を足す（list_custom_texts）

- 状態: 採用（一部未確定）（2026-11-13）
- 固定の強さ: 説明の一覧の `result:` の `id`・`vars`・`numberVars`、道具の名前と入出力（`list_custom_texts`）、使い方の例 `office_wording` は試験版（0016 の 2026-11-01 の追記の9・0015 と同じ。予告して変えることがある）。結論の1文は消せないこと、文を字のまま出すこと、承認するまで効かないこと、どの文でも計算の結果は変わらないことは固定。
- 前提にする記録: 0016（画面の安全とカスタマイズ層。3・4 と 2026-11-01・2026-11-02 の追記）、0015（AI接続口）、0026（資産運用と取り崩し）、0074（結果のタブのポイント）、0085（万一のとき）、0199（使い方の例）

## 背景

- カスタム層の説明の文の差し替え（`settings/texts.json`。0016 の 2026-11-01・2026-11-02 の追記）で直せるのは、入力の欄の「?」の説明・計算の知らせ・推定の根拠の文の3種類だけだった。結果の画面の文は画面の部品の中に書いてあり、事務所の言い方に直せなかった。
- FP がいちばん直したいのは、お客さまと一緒に読む結果の画面の文。例: 資産運用の結論の1文「プランCでは、金融資産は 84歳 まで持ちます」と、その2行目「足りない年だけ取り崩す場合（取り崩しの予定なし）／プランA（基準）は54歳まで」。
- この2行目の「足りない年だけ取り崩す場合（取り崩しの予定なし）」は、「取り崩す」のに「予定なし」と読めて分かりにくかった。
- FP の AI は、直せる文の id・公式の文・使える差し込みの印を知らないと `settings/texts.json` を書けない。今は一覧が AI 用パック（0019 の7）に入っておらず、AI接続口にも道具が無かった。

## 決定

### 1. 結果の画面の文を説明の一覧に載せる（`result:<タブ>/<名前>`）

- 文の表は `app/src/workspace/resultTexts.ts` の1か所に書く（`RESULT_TEXTS`）。説明の一覧を作るビルドの段（`app/scripts/textsCatalog.ts`）がこの表から一覧に載せ、画面はこの表から文を作る。文を足すときは表に1行足せば一覧にも載る。
- id は `result:<タブ>/<名前>`（タブは `main`＝結果のタブ・`invest`＝結果のタブの資産の推移・`contingency`＝万一のときのタブ）。一度出した id は別の意味に使い回さない（0016 の 2026-11-01 の追記の2）。
- 一覧の1件は今までと同じ形（`kind: "result"`・`audience: "customer"`）。結果の画面はお客さまと一緒に見るので、お客さまに見える文としてまとめて承認の画面の先頭に出る（0016 の 2026-11-01 の追記の5）。
- できる操作: 書き換える（`replace`）だけ。消せる（`hide`）のはグラフの注（資産の内訳の注2つ・相場が下がった場合の注）だけ。結論の1文・取り崩しの条件・ポイントは画面の柱の文なので消せない（0016 の 2026-11-01 の追記の4）。足す（`append`）は1行の文に段落を足すことになるので入れない。

### 2. 数字と名前はいつも差し込みの印にする

- 公式の文に入る数字・名前（年齢・年・額・率・プランの名前・人の呼び方・万一の場面）は、すべて差し込みの印（`{age}`・`{plan}`・`{basePlan}`・`{baseAge}` など）で書く。事務所の文にも同じ値が入るので、直した文でも計算した値が出る。
- 差し込む値は単位まで入れた文字（年齢「84歳」・年「2045年」・額「17万円」・率「4.0%」）。単位の付け方を事務所の文に任せない（「84」に何を付けるかで文が崩れない）。印の意味は一覧の `varsHelp` に例つきで書く（AI と承認の画面のため）。
- 1つの文の中で言い方が分かれる所（基準のプランかどうか・取り崩し方・預金が残るかなくなるか・前後の年と比較した多さを出すか・完済が退職の翌年か）は、別の id にする。結論の1文の後半（「100歳まで足ります」など）・大きな支出が重なるほかの年・退職から年金までの間の相手の働く収入は、別の id の文を `{status}`・`{others}`・`{note}` に入れる（無ければ空）。どの部分の文も事務所の文にできる。
- ポイントの見直し（0074 の追記 2026-11-12）で無くなった種類（教育と介護が重なる・NISA の枠を使い切る年）の id は一覧に載せない（一覧に出す前に無くなったので、`formerIds` も要らない）。
- 一覧の1件に `numberVars`（計算の値が入る印）を足した。本体は書き換えた文がこの印を落としていると注意 `W_TEXTS_VAR_MISSING` を出す（承認はできる。わざと外すこともあるため）。名前の印（`{plan}` など）は落としても注意しない。知らない印は今までどおり誤り `E_TEXTS_PLACEHOLDER` で承認できない（0016 の 2026-11-01 の追記の3）。
- 太字: 公式の文の太字の所（結論の1文の年齢など）は表の段（`{ b: … }`）で決め、公式の文の見た目は今までと同じ。事務所の文では、公式の文で太字の段に入っていた印の値だけを太字にする（事務所の文の中の字は太字にしない。文の中に書式の決まりを持ち込まない）。

### 3. 当て方

- 当てるのは、承認したときに一覧にあった公式の文が今の公式の文と同じ行だけ（今までの `applyOfficeText` と同じ）。アプリの更新で公式の文が変わった行は、本体が今までどおり使い続けて知らせるか、意味が変わった・印が無くなったときは止める（0016 の 2026-11-01 の追記の7。ここは変えていない）。
- 文はただの文字。差し込む値も字のまま入れ、印として読み直さない。画面の部品は文字として描き、HTML として差し込まない。
- 文は、作業の層が提示用の値を作るとき（`present.ts`・`invest/present.ts`・`contingency/present.ts`・`tools/fpTools.ts`）に当てる。提示層の部品は当てた後の部品の並びを受け取るだけで、設定を読まない（0016 の2）。万一のときの必要保障額の結論の1文も、作業の層で部品の並び（`ProtectionChartModel.verdict`）にした。
- 事務所の文であることは、結果の画面に出さない（お客さまと一緒に見る画面の文。0016 の 2026-11-01 の追記の5）。公式の文は、事務所の既定値の画面の承認の区画で見られる。
- 提案書（PDF）の資産運用の条件・運用の期間と、持ち帰り用のレポートは、公式の文のまま（関数に事務所の文を渡さない）。提案書の文言は帳票の設定で変える（0016 の 2026-11-01 の追記の5）。

### 4. 取り崩しの条件の言い方を直す（公式の文）

- 前: 「足りない年だけ取り崩す場合（取り崩しの予定なし）」
- 後: 「取り崩しの予定を入れず、足りない年だけ取り崩す場合」（ほかの2つ「65歳から毎月17万円ずつ取り崩す場合」と同じ「〜する場合」の形）
- 関係する文もそろえた: 入力の「貯蓄・運用」のパネルの取り崩しの欄「予定なし（足りないときだけ取り崩す）」→「予定を入れず、足りない年だけ取り崩す」、取り崩し方の「?」の「予定なしは、収支が足りない年だけ取り崩します」→「「予定なし」は、取り崩しの予定を入れず、収支が足りない年だけ取り崩します」。運用の期間の帯の「{age}〜（足りない年だけ取り崩す）」と、対策の欄の取り崩しの計算（`DrawdownCalc.tsx`）の文は、取り崩す・取り崩さないが食い違って読める所が無いので変えていない。
- この文は今回はじめて一覧に載せたので、前の公式の文で書いた事務所の文は無い（更新の確かめは起きない）。提案書の資産運用の条件も同じ関数なので、新しい言い方になる。

### 5. AI接続口: 差し替えられる文の一覧 `list_custom_texts`（読むだけ）

- アプリに同梱した説明の一覧（`texts-reference@1.0`）と名前の一覧（`terms-reference@1.0`）を返す。中身はアプリ本体が埋め込む一覧と同じ（`npm run build:explain` が同じ関数で `crates/lifeplan/dist/texts-catalog.json`・`terms-catalog.json` に書き、接続口が埋め込む）。
- 1件ごとに `id`・`kind`・`where`（画面のどこに出るか）・`audience`・`text`（公式の文。差し込みの印つき）・`vars`（印ごとに `name`・`meaning`、計算の値の入る印には `number: true`）・`ops`・`noticeKind`（知らせだけ）・`hash`（下書きの `basedOn` に写す）。
- 絞り方: `file`（`texts`＝文〔既定〕・`terms`＝名前）・`kind`（分野）・`prefix`（id の頭）・`query`（id・どこ・公式の文の言葉）・`limit`（既定50・200まで）・`offset`。答えにはいつも、分野ごとの数（`areas`）・書き方（`howTo`。行の形と決まり）・承認の案内（`approval`）を添える。
- 道具はカスタム層のファイルを書かない。AI（FP のフォルダに書ける AI）が下書きを書くか、FP に渡して置いてもらい、FP がアプリの事務所の既定値の画面で承認したときだけ効く。書く道具を足さないのは、承認の台帳と保存庫（0016 の3・6）の外から画面の文を変える道を作らないため（0016 の 2026-11-02 の追記の2「AI 接続口の道具は足していない」と同じ考え）。
- 接続口の説明（INSTRUCTIONS）に、頼まれたら `list_custom_texts` で引いて下書きを書くこと・数字と名前は印のまま残すこと・承認するまで効かないこと・接続口はファイルを書かないことを足した。
- 使い方の例 `office_wording`（「事務所の言い方に文言を直す」。引数は直したい文や名前 `target`・事務所の言い方 `style`。どちらも任意）を足した。

## 見本の世帯での数字

見本の棚の salariedCoupleTwoKids（取り崩しの予定なし）で、見本のプランB（65歳まで働くほか2件）を選び、結果のタブの資産の推移を開いた（開発用のサーバーで確かめた）:

- 公式の文: 「プランBでは、金融資産は **102歳** まで持ちます」、2行目「取り崩しの予定を入れず、足りない年だけ取り崩す場合／プランA（基準）は76歳まで」
- `result:invest/verdict` を「{plan}の場合、金融資産が続くのは {age} までです」、`result:invest/conditionNone` を「取り崩しの予定は入れず、収支が足りない年だけ金融資産から使う場合」、`result:invest/verdictBase` を「基準の{basePlan}は {baseAge} まで」に書き換えて承認: 「プランBの場合、金融資産が続くのは **102歳** までです」、2行目「取り崩しの予定は入れず、収支が足りない年だけ金融資産から使う場合／基準のプランAは 76歳 まで」
- 年齢は同じ計算の値で、太字は公式の文と同じ所（年齢）だけ。見本の世帯すべてで、事務所の文を当てないときの文が変更の前と同じこと（取り崩しの条件の直しを除く）も確かめた。

## 理由

- 結果の画面の文は、FP がお客さまと一緒に読み、言い方を事務所ごとに変えたい所。計算に効かないので、説明の文と同じ宣言型の設定で足りる（0016 の 2026-11-01 の追記の理由 (1)）。
- 数字を事務所の文に書き込むと、世帯ごと・計算ごとに文が違って一覧に載せられない。数字と名前をいつも印にすれば、どの世帯にも同じ文が効き、直した文でも計算の値が出る。
- 文の表を1か所にしたのは、画面の文と一覧の公式の文がずれないようにするため（一覧は表から作り、画面も表から作る）。前後で公式の文が変わっていないことは、見本の世帯すべてで変更の前と後の文を並べて確かめた（違ったのは取り崩しの条件の言い方の直しだけ）。
- 道具を読むだけにしたのは、承認の台帳の外から画面の文が変わる道を作らないため。AI が一覧を引ければ、下書きの id・印・指紋を写し間違えにくい。

## 代案（採らなかったもの）

- **結果の画面の文を `present:` の id にする**（0016 の 2026-11-01 の追記の2 の表の例 `present:main.conclusion`）: 結果のタブ・万一のときのタブは FP の作業の画面で、説明モードやお客さまに見せる画面（提示層の画面）とは別に直したいことがある。`present:` はお客さまに見せる画面の文に残し、結果の画面は `result:` にした。
- **印の値を数字だけにして単位を事務所の文に任せる**: 「{age}歳」と書き忘れる・二重に書くと文が崩れる。値に単位まで入れ、意味の例に書いた。
- **太字を文の中の印（`**` など）で書けるようにする**: 文に書式の決まりを持ち込む（0016 の4）。値の太字だけ公式の文に合わせれば、結論の1文の読みやすさは保てる。
- **結論の1文を消せるようにする**: 画面の柱の文で、無いと結果の読み違いに気づけない（0016 の 2026-11-01 の追記の4）。
- **接続口に `settings/texts.json` を書く道具を足す**: 上の理由のとおり。
