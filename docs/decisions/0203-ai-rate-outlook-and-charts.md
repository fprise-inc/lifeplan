# 0203. 変動金利の見込みを「動かす項目」にし、比べた答えを画面と同じ見た目のグラフにする（AI接続口の chart・住宅ローンの系列）

- 状態: 採用（一部未確定）（2026-11-11）
- 固定の強さ: 道具の名前と入出力（`chart`、`compare`・`calculate` の系列 `loanRepayment`・`loanBalance`、`list_plan_items` の `kind: "rateOutlook"`）は試験版（0015 と同じ。予告して変えることがある）。合成の対策の名前 `loanRateOutlook`（プランの差分の向き先。0036 の3）は骨格（名前は使い回さない）。作り（グラフを画面の関数で SVG にし接続口の中で PNG にする・字体を同梱する）は内部
- 前提にする記録: 0005（計算の実行環境）、0015（AI接続口）、0016（提示層）、0036（プランの差分）、0078（標準の欄。変動金利の見込みの1欄）、0183（画面の関数を同梱する）、0195（動かす項目）、0198（比べる道具）、0199（公開に使うときの案内）、0201（場所つきの動かす項目）

## 背景

- FP が AI に「この世帯で、変動金利の上がり方を3通り（今のまま・10年で+1%・10年で+2%）にして比べ、グラフにして」と頼み、そのグラフをセミナーの資料やブログにそのまま使いたい。多くの FP がする使い方なので、確実にできるようにする（利用者の判断）。
- 今の状態:
  - 入力の「住まい・ローン」には「金利の見込み（変動金利）」の欄がある（0078）。型（今の金利のまま・10年で○%上がる）を選ぶと、今（これから借りるなら借入の月）から5年ごとに金利の段を置く。エンジンは段ごとの金利・5年ルール・125%ルール・未払利息に対応している。
  - しかし動かす項目（0195）にこの欄は無く、AI は金利の段を JSON Pointer で直に書き換えるしかなかった（画面と同じ動き方になる保証がない）。結果のタブの「変動金利の上昇」（前提の `loanRateShifts`）は、ある年から一律に上乗せする型で、入力の欄の型とは当て方が違う（今ある後の段に重なる）。ストレステスト `rateRise` は決まった型（目安＋1%）だけ。
  - 比べる道具の系列に住宅ローンの返済額・残高が無かった。
  - グラフは、数字を受け取った AI のアプリが描いていた。描くたびに見た目が変わり、描き間違えるおそれがある。

## 決定

### 1. 動かす項目「金利の見込み（変動金利）」（住宅ローン1本ごと）

- 入力の「金利の見込み（変動金利）」の欄が出る住宅ローン（今か借入の月の金利の段が変動金利の住宅ローン）ごとに、結果のタブの動かす項目 `loan:<ID>:outlook` を足す（`plans/items.ts` の `outlookItem`。まとまりは「よく使う」）。入力項目ID は欄と同じ `debt.rateSchedule`、対象はそのローン。ローンが複数ある世帯では、ローンごとの項目（対象のローンの ID）を選ぶ。
- 値は、今の金利（借入の月の金利）からの上乗せを5年ごとに並べた物 `{adds: ["0.005", "0.01"]}`（`adds[0]` が5年後、`adds[1]` が10年後…。10進の文字。6段＝30年先まで。各段は −3%〜+5% で、今の金利を下回らない）。`[]` は今の金利のまま。上げ幅（10年で +0.5%・+1%・+2% など）と、5年ごとの段の数を選べる。
- 当てるのは入力の欄と同じ関数: 欄の型を選んだときの処理を `setRateOutlook`（`input/stages/housingLoans.ts`）に切り出し、欄も動かす項目もこれを呼ぶ。今の金利の段より後の段を、今から5年ごとの変動金利の段（今の金利＋上乗せ）に置き換える。欄で同じ型を選んだときと、金利の段（年月・種類・金利）・計算の数字が同じ（テストで確かめる）。
- 今の値: 欄の型に当たればその型の上乗せ、5年ごとちょうどの変動金利の段ならその上乗せ、どちらでもなければ null（「金利の段階で入れた見込み」。そのまま）。
- AI の値の形: 型の名前（`"flat"`・`"up1"`・`"up2"`。入力の欄の型と同じ目安）か、上乗せの並び（`{adds: [...]}` か並びそのもの。数も受ける）。段の数・幅の外は取り込まない（画面の「AIからの候補」も同じ当てはめ。`plans/candidates.ts` の `outlookValue`）。
- `list_plan_items` は `kind: "rateOutlook"`・`presets`（型の名前・文・上乗せ）・`currentRate`・`from`（見込みの起点の月）・`stepYears: 5`・`maxSteps`・`addRange` を返す。同じ対象・同じ入力項目ID の項目（当初の金利・金利の段階の欄）があるので、0201 の場所 `lever: "loanRateOutlook"` を添えて選ぶ。
- 画面: 結果のタブの「＋ 動かす項目を追加」の「よく使う」に出し、入力の欄と同じ型を選ぶ（`ItemControls.tsx` の `OutlookRow`）。型でない見込み（AI の候補で入った上乗せ・金利の段階で入れた見込み）は、その値の行として残す。
- プランの持ち方: 合成の対策 `loanRateOutlook`（向き先 `{lever, object}`）の `set` で持つ（`store/readings.ts` の後から足した合成の対策）。当て先の `set` にしないのは、1つの値で金利の段の並び（段の数・年月・金利）をまとめて置き換えるため（0036 の3。0036 に追記した）。前の版のアプリは、この名前を知らないので当てない（要確認の差分として残す）。
- 当てる順: 同じローンの「金利」（当初の金利を動かすと段も同じ幅で動く）より前。両方を動かすと、見込みの段の上に同じ幅が乗る（どちらの順でも同じ金利になる）。
- 「変動金利の上昇」（`loanRateShifts`）とストレステスト `rateRise` は変えない（どちらも今ある段に一律に上乗せする型）。

### 2. 比べる道具・計算の系列に住宅ローンの数字

- `compare` の `series`・`calculate` の `fields` に `loanRepayment`（住宅ローンの返済。年額。繰上返済・手数料を含む）・`loanBalance`（住宅ローン残高。年末）を足す。選んだときだけ返す（既定の答えの大きさは変えない）。
- 数え方は画面と同じ関数（`connector/summary.ts` の `loanYearsOf`）: 返済は主な数字の住宅ローンの返済の合計（`plans/compare.ts` の `metricsOf`）と同じ行で、表に出す年の合計が `keyFigures.loanRepayment` になる。残高は画面のキャッシュフロー表の「住宅ローン残高」の行と同じ。
- 適用金利・利息は返さない（未確定）。エンジンは年ごとの利息を内部で数えているが、表示の形の出力に無い。表の数字から逆算すると、団信・借り換え・売ったときの返済で合わなくなる。

### 3. グラフの道具 `chart`

- 入力は `compare` と同じ世帯と通りの書き方に、`charts`（作るグラフ）・`figures`（棒の数字）・`title`・`theme`（`light`・`dark`）・`format`（`png`・`svg`・`both`）。数字は AI から受け取らない（`compare` と同じ道で計算した数字だけを描く。`server.rs` の `run_compare` を `compare` と共有）。どれかの通りを計算できなければ、グラフを作らずに `compare` と同じ理由を返す（足りない通りのあるグラフを出さない）。
- グラフは3種類: `assets`（通りごとの金融資産の推移。折れ線）・`repayment`（通りごとの住宅ローンの返済額の推移。年額の折れ線。いちばん遅く返し終える年まで）・`keyFigures`（主な数字の比べ。棒。既定は○歳時点の金融資産・金融資産がいちばん少ない額・住宅ローンの返済の合計）。
- 必ず入れる物: 題・凡例（通りの文字 A・B… と名前）・単位（万円）・前提の短い注（通りの違い〔当てたプランの変更の文。金利の見込みなら「10年で1%上がる（5年後に＋0.5%・10年後に＋1%）」〕・物価上昇率・運用利回り・相場の想定）・「ファイナンシアで試算」の旨と試算の時点（計算基準月）と「将来の結果を約束するものではありません」。年の目盛りの下に本人の年齢。
- お客さまの名前・ID は入れない: グラフの関数に渡すのは通りの名前と数字と本人の年齢だけ（家族の呼び方・物の ID は渡さない）。通りの名前・題は AI が書いた文字がそのまま入るので、道具の説明に「お客さまの名前を書かない」と書く。
- 見た目は画面と同じ部品で作る（別の見た目を作らない）:
  - 座標・目盛り・線は画面のグラフと同じ関数（`presentation/chart.ts` の `FRAME`・`domainOf`・`scaleOf`・`linePath`・`spreadX`）。目盛りの間隔の関数 `niceStep` は、結果が OS で変わる `Math.log10` を使わず、10 のべきと比べて指数を求める形に直した（画面の目盛りは変わらない）。
  - 線の色は画面の全部のプランを重ねる表示の色（`presentation/planColors.ts` に移した `PLAN_COLOR_STYLES`。白地で 3:1 以上・色の見分け方の違いを模しても見分けられる組み合わせ）、暗い画面の色も同じ。文字・線・地・不足の範囲の色は画面の色の決め事（`app.css`）と同じ（`app/test/chart-colors.test.ts` で確かめる）。
  - 色だけに頼らない: 線の右端に丸と通りの文字、棒の下に通りの文字（画面のプランの文字と同じ）。0未満の範囲は薄い地と「0未満は不足」の言葉（画面と同じ）。
  - 提案書（Typst）のグラフの部品は画面の関数を使えない（Typst の中で描く）ので使わない。
- 作り: グラフの SVG は画面の関数をまとめた JS（`crates/lifeplan/dist/explain.js` の `chart`。`app/src/connector/chart.ts`）を、計算と同じ固めた実行環境で動かして作る。PNG は接続口の中で `resvg`（ほかの crate が使っている版と同じ 0.47.0。OS の字体・外の画像は読まない）で描き、字体は提案書と同じ BIZ UDゴシック（SIL OFL 1.1。`report/fonts/`）を接続口に同梱する（約 9MB 大きくなる）。PNG は SVG の2倍の大きさ（幅 1520px）。
- 答え: 1つ目の文章に説明・公開に使うときの案内（0199 と同じ考え。金額を丸める・珍しい組み合わせを変える・お客さまに一言ことわる。止める仕組みにはしない）・グラフごとの題と画像の説明（代わりの文）・通りごとの主な数字と差（キャプションを書くときに使う。描いた数字と同じ）、続けて PNG（MCP の `image`）と SVG（`image/svg+xml` の埋め込み。`financia://chart/<種類>.svg`）。外へは何も送らない。
- 大きさと時間（見本の世帯 salariedCoupleTwoKids で3通り。開発用のビルド）: 3つのグラフの PNG と SVG で約 420KB・約 1 秒。PNG だけ（既定）で約 400KB、1つだけなら約 130〜150KB（PNG は1枚約 95〜105KB、SVG は約 7〜9KB）。

- 頼み方の例と手順を `docs/ai-connector.md` と INSTRUCTIONS に書いた（`list_plan_items` で「金利の見込み（変動金利）」を探す → `chart` の通りの `plan_changes` に型の名前か上乗せを入れる）。
- 使い方の例のプロンプト（0199）に `chart_rate_paths`（金利の上がり方を3通り比べてグラフにする。引数 `household`*・`paths`・`purpose`）を足した。

### 5. 見本の世帯

- 変動金利の住宅ローンのある見本の世帯は14件ある。叶えたい使い方の例には、会社員の夫婦と子2人・変動金利の住宅ローン（残高 2,240万円・今 0.65%）の `salariedCoupleTwoKids` を使う（新しい見本は作らない。見本の一覧の手直しとぶつからない）。

## 理由

- 入力の欄と同じ関数で当てれば、AI が試した見込みと、FP が入力の欄で選んだ見込みが同じ金利の段になる（直すのは1か所。0183・0195 と同じ考え）。
- 型の名前だけでなく上乗せの並びも受ければ、「10年で+0.5%」「15年で+3%」のような FP ごとの見込みも、同じ関数で試せる。
- グラフを接続口の中で画面の関数で描けば、毎回同じ見た目になり、数字を描き間違えない（AI のアプリが数字を描き直さない）。PNG を返せば AI のアプリでそのまま見え、SVG を返せば資料に貼っても粗くならない。

## 代案（採らなかったもの）

- **前提の `loanRateShifts`（変動金利の上昇）を段を重ねられる形に広げる**: 今ある後の段に重なるので、入力の欄で型を選んだときと同じ金利の段にならない。ローンごとに選べない。
- **ストレステスト `rateRise` に上げ幅を足す**: 同じく一律の上乗せで、欄と同じにならない（エンジンの型の引数は今のまま）。
- **当て先の `set`（金利の段の並びそのもの）でプランに持つ**: 値が段の並び（ID・年月つき）になり、つまみの値（上乗せ）と違う物を持つことになる。今の値の読み直し・候補の当てはめが欄と別の書き方になる。
- **グラフを AI のアプリに描かせる（数字だけ返す）**: 今のまま。見た目が毎回変わり、描き間違えるおそれがある。
- **グラフを Rust で描く**: 画面の目盛り・色の決め事を二重に持つことになる。
- **画面の部品（preact の MainChart.tsx）をそのまま描く**: 固めた実行環境に preact を入れることになる（外の部品を入れない決まり。0183）。座標の関数・色の表を共有する形にした。
- **PNG を作らず SVG だけ返す**: 多くの AI のアプリが SVG の画像を表示しない。
- **OS の字体で PNG を描く**: OS で見た目が変わり、字体が無い OS では字が出ない。
- **利息・適用金利を表の数字から逆算する**: 団信・借り換え・売ったときの返済で合わなくなる（未確定に置く）。
