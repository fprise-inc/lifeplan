# 0210. AI接続口の計算のお知らせを画面と同じ文で返し、「お客さまに聞くこと」を作る入力の確かめの道具を足す（check_inputs）

- 状態: 採用（一部未確定）（2026-11-13）
- 固定の強さ: 道具の名前と入出力（`check_inputs` の引数・答えの形、`calculate` の `notices` の行の形と `omit` の `noticeText`）と使い方の例 `prepare_questions` は試験版（0015 と同じ。予告して変えることがある）。お知らせの文を画面の文の表の1つだけから作ること・確かめの一覧を画面と同じ関数で作ることは骨格。聞く文の決まりの表の中身は内部（随時足す）
- 前提にする記録: 0015（AI接続口）、0041（確かめの一覧）、0064（計算の知らせの画面）、0074（ポイント）、0183（画面の関数を同梱する）、0194（主な数字）、0195（プランの動かす項目）、0199（使い方の例）、0209（表）

## 背景

- `calculate` の答えの `notices` は、エンジンの知らせをコードと ID のまま（`{"code": "N_ESTIMATED", "ids": ["pension.record", "pensionRecord", "<物の ID>"]}`）返していた。AI はコードの意味を推し量って FP に伝えるので、画面の結果のタブの「計算のお知らせ」と違う言葉になり、物の ID も答えに混じっていた。画面は知らせを `app/src/workspace/engineNotices.ts` の文の表で、FP 向けの文・種類・対象・年・内訳にし、同じ知らせを1行にまとめている（0064。結果のタブの見せ方は 2026-11-12 に控えめな1行にした。0064・0074 の追記）。
- FP は面談の前に、AI に「お客さまに聞くこと」をまとめてほしい。推定や既定の値で計算している所、入っていなさそうな所（子がいるのに教育の進路が無い・家を買うのに頭金が無いなど）、範囲の外の値は、画面の入力のタブの「確かめの一覧」（0041。`app/src/workspace/input/checkRows.ts` の `checkList`）がすでに見つけている。接続口にはそれを読む道具が無く、AI は世帯の入力を自分で読んで推し量るしかなかった。

## 決定

### 1. 計算のお知らせを画面と同じ文で返す

- `calculate` の `notices` を、画面の結果のタブと同じ関数（`noticeRows`）で作った行にする。接続口には `app/src/connector/notices.ts` を同梱し（数字の根拠の JS。0183）、主な数字と同じ同梱の関数（`summarize`）の中で、計算の前の処理を当てる前の要求（物の呼び名を引く）と計算の結果から作る。文の表は画面の1つだけで、接続口に文を写さない。
- 1行の形: `kind`（画面の閉じた1行の内訳と同じ種類の言葉。入力が足りない・計算に入れていない・前提の外・仮の値・推定・データの確認待ち）・`text`（画面の文）・`subjects`（対象の人・物の呼び名）・`years`（年の範囲）・`parts`（内訳）・`item`（入力で直すときの入力項目の名前。画面の「入力で開く」の先。入力のホームの入力項目の名前）。空の添え書きは省く。並び・まとめ方・画面が出さない知らせ（子・世帯の外の家族の年金の加入記録の推計）は画面と同じ。
- 事務所の文（カスタム層の説明の文の差し替え）は当てず、公式の文を返す。事務所の設定で隠している知らせも隠さない（AI には隠す理由が無く、FP が隠した理由は FP の事務所の中のこと）。
- 小さくする: `omit` に `noticeText` を足す（文と内訳を省き、種類・鍵 `key`・対象・年・入力項目だけ。UTF-8 で半分より小さい）。`notices` を省けば今までどおり無い。`compare`・`sweep`・`find_threshold`・`chart`・`table`・`propose_household` は今までどおり知らせを数えない。
- 画面の部品を読まない同梱の JS に入れるため、画面の側を次のように分けた（中身は変えない）: 入力の15項目の順番と名前を `input/stageOrder.ts` に（`stages/index.ts` は写しを出す）、事務所の文の preact の入れ物を `office/customTextsContext.ts` に、保険の計算の入れ物（`useInsuranceView`）を `input/useInsuranceView.ts` に。数字の根拠の JS の頭に、プランの動かす項目の JS と同じ `structuredClone`・`crypto.randomUUID`・`TextEncoder` の代わりを置く（作業中の世帯を作るときに要る）。

### 2. 入力の確かめの道具 `check_inputs`

- 世帯（見本の世帯・FPが渡した世帯・AIが組み立てた入力のどれか1つ）か、プラン（`plan_changes`・`changes` を当てた世帯）を、画面の確かめの一覧と同じ関数（`checkList`）で見て、行ごとに「お客さまに聞くこと」の案を添えて返す。読むだけで、世帯のデータは変えない。
- 計算のお知らせ（入力で直せる物）を一覧に入れるため、`calculate` と同じ道（プランの変更 → 計算の前の処理 → 計算）で1回計算し、1 と同じ関数で行にして渡す。主な数字・年齢・年金の見込みは数えない。計算できない入力（必須の欄が無い・スキーマの範囲の外の値）は、`calculate` と同じ直し方を返す（エンジンの確かめが正）。
- 同梱の JS は `app/src/connector/check.ts`（入力の欄の定義を読むので、プランの動かす項目の JS に入れる。作業中の世帯の作り方は `connector/working.ts` に分けて共有する）。行の選び方・並び・欄の見出し・今の値・根拠は画面の一覧のまま（既定の種類も画面と同じ。`kinds` で `certainty`・`premise` も選べる。`max_items` で行の数を絞り、`counts`・`truncated` で切った数が分かる）。
- 接続口は行を足さない（画面の一覧の行だけ）。これから買う家の頭金が0円の購入（計算の入力では頭金を省けないので、入れていない頭金は0円になり、画面の欄は0円を確定の値として見せる）は、画面の確かめの一覧の確かめの注意に足した（下の追記）。
- 1行の形: `item`（入力項目）・`field`（欄か物の見出し。計算のお知らせの行は画面の文）・`value`・`subjects`・`reason`（短い理由。決まりが無ければ画面の根拠の最初の文。かっこの中の「。」では切らない）・`question`（お客さまに聞く文の案。丁寧な言葉）・`rule`（当てた決まりの名前）。種類ごとに `groups` にまとめる。物の ID・お客さまの名前は返さない。
- 聞く文は、決まりの表（`RULES`）で行ごとに決める。行の id（入っていない物は `fill.ts` の `gapsOf` の id、確かめの注意は `checkRows.ts` の id、計算のお知らせは文の表の鍵）か、欄の入力項目ID で選ぶ。最初の決まり（明らかに正しい物だけ）:
  - 入っていない物: 子の教育の進路・退職金・ねんきん定期便の額と加入月数・失業給付・基本生活費・住まい・本人と配偶者の介護の費用・保険
  - まだ入れていない入力項目（入力項目ごとの文）
  - 確かめの注意: 購入の残りの払い方が無い・頭金が0円か空欄・退職金の確かめ・保険の重なり・範囲の外の値
  - 計算のお知らせ: 年金の加入記録が無い・退職金の受け取る時期・持ち家の時価の元・土地と建物の割合・介護の費用の目安
  - 欄: 年収が推定か空欄
  表に無い行は、種類ごとの決まりの文（値のある行は「〜は、〇〇で合っていますか。」、無い行は「〜を教えていただけますか。」など）。決まりは表に1件足し、テストに当たる世帯を1つ足せば増やせる。
- 道具の名前は `check_inputs`（画面の「確かめの一覧」の言葉。書き出し・承認・設定の道具と取り違えない名前）。

### 3. 使い方の例 `prepare_questions`

「面談の前に、お客さまに聞くことをまとめる」。引数は世帯（省くと渡されている世帯）・面談のテーマ・確かめたいプラン。`check_inputs` を呼び、テーマに関係の深い順に10問ほどに絞り、1問ごとに聞く文・なぜ聞くか・持ってきてもらうとよい書類をまとめ、前提条件の行は「FP が確かめること」として分ける。`question` は案なので FP が面談の前に確かめる旨を添える。使い方の例は13個になる。面談の準備（`prepare_meeting`）も、お客さまに確かめることを `check_inputs` で取るようにした。

## 見本の世帯での答え

- `calculate` の `notices`（`omit` に years・pension）: salariedCoupleTwoKids は前のコードの形の23件・約 2.7KB が、画面と同じ9行・約 2.4KB。sampleParentsCare は38件・約 4.3KB が11行・約 3.5KB。`noticeText` を省くと半分より小さい。時間はほぼ変わらない（0.6〜0.8 秒）。
- `check_inputs`: salariedCoupleTwoKids で7行（まだ入れていない項目5・確かめの注意2）・約 3.3KB、sampleParentsCare で15行・約 6.6KB。時間は 4〜7 秒（入力の欄の定義を読み込むため）。例（年金の加入記録を外した salariedCoupleTwoKids）:

```json
{ "item": "年金", "field": "年金の加入記録（ねんきん定期便）が入っていないので、働き方の入力から推計して計算しています",
  "subjects": ["ご本人", "配偶者"], "reason": "計算のお知らせ（仮の値・推定）",
  "question": "ご本人・配偶者のねんきん定期便（かねんきんネットの画面）はお手元にありますか。あれば、見せていただけますか。", "rule": "pensionRecord" }
```

## 理由

- 画面と同じ関数で文にすれば、FP が画面で見る言葉と AI の言葉がそろい、文の表を直せば両方が変わる（写した文はずれる）。
- 確かめの一覧は、推定・未入力・確かめの注意を画面の欄の定義から毎回作っている。接続口が別に決まりを書くと、画面と違う所を指したり、見落としたりする。画面の行に聞く文を添えるだけにすれば、一覧が増えれば道具の行も増える。
- 聞く文は FP がお客さまに使う言葉で、画面には無い。最初は明らかに正しい場面だけに決まりを書き、ほかは種類ごとの決まりの文で、行を落とさずに返す。

## 代案（採らなかったもの）

- **知らせの文を Rust に写す**: 画面の文の表とずれる。
- **知らせを既定で鍵だけにし、文は別の道具で引く**: 呼び出しが増え、AI が鍵の意味を推し量る。文の行は前のコードの形とほぼ同じ大きさなので、既定で文を返し、`noticeText` で小さくできるようにした。
- **確かめの決まりを接続口で別に書く**（「子がいて教育が無い」などを入力から直接見る）: 画面の一覧と二重になり、画面で直した所（「該当なし」にした項目など）を拾ってしまう。
- **整数の欄の範囲の外の値を接続口で確かめる**: エンジンのスキーマが範囲の外の値で計算を止めるので（直し方を返す）、足しても当たる場面が無かった。割合の欄の範囲の外の値は、画面の一覧が確かめの注意に出す。
- **聞く文を AI に任せる**（行だけ返す）: 道具ごと・会話ごとに言葉が変わる。決まりの表の文を案として返し、AI はテーマに合わせて絞って整える。

## 追記（2026-11-13）: 頭金0円の確かめを画面の確かめの一覧に出す・決めたこと

最初の版では、これから買う家の頭金が0円の購入を接続口だけが確かめの注意に足していた（画面と AI で一覧が違っていた）。次のように決めた。

1. **画面の確かめの一覧に出す**: `input/checkRows.ts` の `checkList` が、これから買う家（買う月が計算基準月より後か同じ）で物件の価格があり、頭金が0円（空欄を含む）の購入ごとに、確かめの注意の1行を出す（「住宅の購入: 頭金」・今の値「0円」・「これから買う家の頭金が0円です（頭金なしで、物件の価格を住宅ローンか手元のお金で払う計算です）。頭金なしで買う予定か確かめてください」。「開く」は頭金の欄へ）。もう買った家・現金で買う形（頭金＝物件の価格）は当たらない。同じ欄の行（未入力・推定など）が既にあれば出さない。接続口の `check_inputs` は行を足さず、画面の一覧をそのまま使う（聞く文の決まり `downPayment` はこの行に当たる）。
2. **事務所の文**: 今は AI に渡さない（公式の文のまま）。要望が出たら見直す。
3. **前のコードと ID の形の知らせ**: 返さない（道具は試験版）。鍵が要るときは `omit` の `noticeText` で `key` を取る。
4. **聞く文の決まりを増やす**: FP が使ってから、推定の多い欄ごと・書類待ちの書類ごとの文から足す。
5. **聞く順番**: 画面の一覧の並びのまま（AI のプロンプトでテーマに合わせて絞る）。
