# 0099. 制度データが持っている時期より前の値（さかのぼりの仮定）

- 状態: 採用（一部未確定）（2026-10-31）
- 固定の強さ: 骨格（引く日が最初の行より前のときに止めずに最初の行を使うこと、値の有無を見るときは今までどおり値が無いこと、見出しの `notices` に `N_PARAM_BACKFILLED` を出すこと）。画面の文は内部
- 前提にする記録: 0003（時間の規約と値を選ぶ基準。2026-10-25・2026-10-27 の追記）、0007（制度データの形式。延長の仮定の追記）、0064（計算の知らせを画面に出す）

## 背景

- 制度データは、多くの値を2025年・2025年度（令和7年度）から持つ。延長の仮定（0007 の追記（2026-10-08））は「期限の後」だけで、引く日が最初の行より前のときは `E_PARAM_NO_VALUE` で計算を止めていた。
- 計算は、表に載る月のほかに、計算基準月より前の時期の値も引く。次の2つで止まっていた（見本の世帯を、計算基準月や受給者の生年を変えて全部の組で確かめた）。
  1. **計算基準月が1〜5月**: 今年度の住民税（6月から翌年5月。計算基準月が2026年1〜5月なら2025年度）を、決定額が無い人は前の年（2024年）の所得から計算し直す。2024年分の所得税の値（給与所得控除・基礎控除・扶養の所得の要件・給与所得の表の刻み・生命保険料控除の特例の年齢）、住民税の2025年度の扶養の所得の要件、2024年の給与から引く協会けんぽの令和6年度より前の月の分の料率（健康保険・介護保険）が無く、見本の世帯のほとんどが止まった。国民健康保険の世帯は、令和7年度の保険料（1〜3月の納期）で子ども・子育て支援金の区分の年齢の値（令和8年度から）が無く止まった。
  2. **100歳を超える受給者**: 年金を受け取り始めた月（1916〜1926年生まれは1981〜1991年）の年金額の端数（`pension.amount.rounding`。2015年4月から）が無く止まった。
- 0003 の追記（2026-10-27）は、値の無い月を最も古い値で埋めると適用されない期間の値を黙って使うことになるとして、止めたまま本当の過去の値を足していく方針だった。足していく値は計算の道筋ごとに増え（協会けんぽは都道府県の数だけ行が要る）、足し終わるまでは、計算基準月を動かすだけで計算ができない。
- そこで、制度データの範囲の外でも計算を止めず、古い値で代用したことを知らせる形に改めると判断した（数字が変わる扱いはこの記録の4に書く）。

## 決定

### 1. さかのぼりの仮定（エンジンの制度データの読み取り）

- 引く日が、同じ条件・管轄の**どの行よりも前**（制度データが持っている時期より前）なら、計算を止めずに**その組の最初の行**の値を使う（`engine/src/regulation/reader.ts` の `backfill`）。選んだ行には `backfilledYear`（引いた日の年）を付ける。
- 次は今までどおり止める（値が無い）:
  - 管轄・条件に合う行が1つも無い（知らない協会けんぽの支部など）。
  - 行と行の間が空いている日（パックの組み立てで空きを拒むので、データの誤り）。
- **値の有無を見るとき**（部品の `has`。延長の仮定を使わない `noExtension`）は、最初の行より前は今までどおり「値が無い」。部品はこれで「制度が始まる前」を判定できる（住宅ローン控除の入居の年の `N_PARAM_MISSING` など、今までの判定は変わらない）。
- 見出しの `notices` に `{code: "N_PARAM_BACKFILLED", ids: [<値ID>@<rev>, <最初の年>, <最後の年>]}` を出す（年は値を引いた日の年。延長の仮定の `N_PARAM_EXTENDED` と同じ形）。根拠の記録の値の使用には `backfilled: true` を付ける（出力のスキーマに足した）。
- 区間の使い回し（0005 の追記）は、最初の行の適用開始が行の変わりうる日の鍵に入っているので、さかのぼりの区間と最初の行の区間を分けて扱う（CI の一致の確かめ `checkSame`・`segments` は、さかのぼりの印の有無も比べる）。

### 2. 制度が始まる前の年度にかけない（部品）

- さかのぼりの仮定は「その時期にも同じ制度があった」とみなす仮定なので、**その時期に無かった制度**を計算に入れてしまうところは部品で避ける。今回の範囲では、国民健康保険の子ども・子育て支援金の区分（令和8年度から）を、令和8年度より前の年度にかけない（`socialInsurance.nationalHealth` 改訂10。料率の入力に支援金の欄があっても、令和7年度の保険料には当てない）。判定は、18歳未満の均等割をかけない年齢の値（`socialInsurance.nationalHealth.childSupport.perCapitaFromAge`。区分が始まった日から）の有無で行う。

### 3. 画面の知らせ

- 計算の知らせ（0064）の「制度データの確認待ち・先の年の値」の種類に1行で出す: 「制度データが持っている時期より前の値は、制度データのいちばん古い値で計算しています（その時期の実際の制度の値とは違うことがあります）」。内訳に値の名前と年の範囲（例: 給与所得控除〔2024年〕）。部品の ID は付かない（全体の段が出す知らせ）。

### 4. 数字が変わる場合の扱い

- **今まで計算できていた世帯の結果は1円も変わらない**。さかのぼりの仮定を使うのは、前は `E_PARAM_NO_VALUE` で止まっていた引き方だけ（見本の世帯の計算基準月 2026年10月では使わないことを試験で確かめる）。
- 新しく計算できるようになる世帯では、その時期の実際の値と違う値で計算した所がある。今わかっているのは次のとおりで、どれも見出しの知らせで分かる。
  - **計算基準月が1〜5月で、今年度の住民税の決定額が無い人**: 表に載る1〜5月の住民税（2025年度）を、2024年の所得に2025年分の給与所得控除・基礎控除・扶養の所得の要件（2025年の改正の後の値）を当てて計算し直すので、実際の2025年度の住民税より少なめに出ることがある（例: 給与所得控除の最低額 65万円（実際の2024年分は55万円）、扶養の所得の要件 58万円（48万円））。2024年の給与から引く健康保険・介護保険の料率のうち、制度データより前の月の分は、制度データのいちばん古い年度の料率で数える（社会保険料控除の額だけに効く）。今年度の住民税の決定額（通知書の年税額）を入れると計算し直さないので、この仮定を使わない。
  - **100歳を超える受給者**: 受け取り始めた月の年金額の端数を、今の決まり（1円未満の四捨五入。2015年4月から）で丸める（実際は当時の決まりで100円単位）。表に載る年の額の違いは、受け取り始めの額の丸めの差（50円まで）に改定率をかけた分だけ。
- 本当の過去の値を制度データに足したら、その値はその時期の行で引かれ、知らせは出なくなる（足す方針は 0007 のとおり。足したときに数字が変わるのは、知らせの出ていた世帯だけ）。

## 理由

- 止めると、計算基準月を動かす・古い世帯を開くといった普通の操作で、何も見られなくなる。差が出るのは計算基準月より前の時期の値で、表に効くのは今年度の住民税の一部と、年金の受け取り始めの端数に限られる。
- 黙って使うのではなく、見出しの知らせで値の名前と年を出す。延長の仮定（期限の後に最後の行が続くとみなす）と同じ考え方を、前の向きにも当てる。
- 値の有無の判定（`has`）を変えないので、「制度が始まる前は無い」ことを使う部品の判定と結果は変わらない。

## 代案（採らなかったもの）

- **本当の過去の値を全部足す**（0003 の追記（2026-10-27）の方針）: 正しいが、計算の道筋ごとに要る値が増え続け（協会けんぽの都道府県ごとの料率など）、足し終わるまで止まる。足す方針は残し、足すまでの間を止めない形にした。
- **計算基準月の年度の値で計算する**（国民健康保険の扱いを広げる）: 0003 の追記（2026-10-27）のとおり、値のある時期の保険料まで変わるので採らない。
- **画面で計算基準月を6月以後に限る**: 1〜5月の相談で使えなくなる。年金の受け取り始めの端数のような計算基準月と関係の無い時期の値には効かない。

## 影響

- エンジン: `engine/src/regulation/reader.ts`（さかのぼりの仮定）、`engine/src/registry/ctx.ts`・`segments.ts`・`trace.ts`（記録・確かめ・根拠の記録）、`engine/src/engine/run.ts`（見出しの `N_PARAM_BACKFILLED`）、`engine/schemas/engine.output.json`（根拠の記録の `backfilled`）、部品 `socialInsurance.nationalHealth` 改訂10。
- 画面: `app/src/workspace/engineNotices.ts`（知らせの文）。
- 世帯の形式・制度データは変えない。
