# 0199. AI接続口の見本の世帯の一覧を短くし、使い方の例をプロンプトで出し、説明に答えの小さな取り方・ほかのソフトとの違い・公開に使うときの案内を足す

- 状態: 採用（一部未確定）（2026-11-11）
- 固定の強さ: 道具の入出力（`list_sample_households` の `tags`・`include_test` と答えの形）とプロンプトの名前・引数・文は試験版（0015 と同じ。予告して変えることがある）。見本の名前と目印を見本の棚から作ること（別の一覧を持たない）は内部の取り決め。説明（INSTRUCTIONS）の文言は変えてよい
- 前提にする記録: 0015（AI接続口）、0033（見本の世帯と見本の棚）、0183（数字の根拠・対応範囲の一覧）、0184（計算の前の処理）、0194（主な数字と答えの大きさ）、0195（プランの動かす項目）、0196（入力の形の案内と場面の手本）、0197（合算BS の見本の世帯）、0198（比べる道具）、0200（表の最初の年・年金の月額・相場が下がった場合の型）

## 背景

- 見本の世帯の一覧（`list_sample_households`）は、モデル世帯の57件すべてを、`data/modelHouseholds/README.md` の説明（作った日・ファイルの名前・制度の細部の入った開発者向けの文）と構成員の配列で返していて、約30KB あった。AI が見本を選ぶたびに大きな答えを読み、FP に見せる名前にもならなかった。セミナーの場面（単身・子育て・シニア など）で選ぶ目印も無かった。
- 57件のうち、アプリの見本の棚（0033）に出しているのは15件だけで、残りは制度の計算を確かめるための世帯（表が2027年までの物が多い）。どちらも同じ並びに出ていた。
- 「この接続口で何ができる？」に答える材料が、説明（INSTRUCTIONS）の文だけだった。よくある頼み方（2つの世帯を比べる・対策を並べる・セミナー用の架空の世帯・面談の準備・数字の根拠の説明・計算に入っているかの確認）を、AI のアプリの一覧から選べる形が無かった。
- 説明に、ほかのソフトとの違いを聞かれたときの答え方と、お客さまの数字を公開に使うときの案内が無かった（何通りも比べるときは比べる道具を使うことは 0198 で足した）。

## 決定

### 1. 見本の世帯の一覧は、見本の棚と同じ名前と目印で、短く返す

- 既定は、アプリの見本の棚にある見本（`app/src/workspace/catalog.ts` の `DEMO_HOUSEHOLDS`）だけを、見本番号の順に返す。1件は `id`・`no`（見本番号）・`title`（棚の名前）・`tags`（目印）・`members`（家族の続柄・性別・年齢を1行の文で）・`period`（計算の期間）。全体で約5.5KB（前は約30KB）。
- 目印は、画面の見本の棚と同じ物をそのまま使う: 見本番号から読む家族の形（単身・夫婦のみ・夫婦と子・ひとり親・シニア）と年代（`store/numbering.ts`）、棚の絞り込みの項目（`traits`。会社員・自営業・役員・年金生活・共働き・片働き・持ち家・賃貸・住宅ローン・教育費・資産運用・収益不動産・親の介護・相続など）。画面の項目に無い場面の目印は、棚の項目から決まる物だけを足す: 子育て（教育費の項目がある）・シニア（家族の形がシニアか、本人が60代以上）・合算BS（会社の数字の入った見本。0197）。別の一覧は作らない。
- 名前と目印は `app/src/connector/samples.ts` が棚から作り、`npm run build:explain` が `crates/lifeplan/dist/samples.json` にして、接続口がビルドの時に埋め込む（数字の根拠の読み方・プランの動かす項目と同じ置き場所。0183・0195）。見本を足す・名前を変えると、接続口の一覧も一緒に変わる。
- `tags` で絞れる: 渡した目印のどれにも当てはまる見本だけ。目印か名前の一部でもよい（「介護」は「親の介護・相続」に当たる）。答えの `tags` に、使える目印を出す。当てはまらなければ、目印を減らすか入力の形の案内（0196）で組み立てるよう返す。
- 家を買う・子が生まれるなどの場面ごとの見本は持たない。近い見本に場面の手本（`get_input_recipe`。0196）を重ねて作るよう、一覧の案内に書く。
- 棚に無いモデル世帯は「開発の試験用」の目印で分け、既定では出さない（数だけ案内に書く）。`include_test: true` か、`tags` に「開発の試験用」を入れると出る。名前は README の説明から括弧の中・記号を除いた最初の文（40文字まで）。
- 合算BS の見本には「会社の数字（合算BS）は、アプリの画面でこの見本を開くと見られます。この接続口で計算するのは家計の側だけです。」と添える。機能を有効にするコード（0110）の話は出さない（0197 の追記と同じ）。
- `get_sample_household` の答えに、棚の名前・目印（試験用は「開発の試験用」）を足す。計算の入力と README の説明はそのまま。

### 2. 使い方の例を MCP のプロンプトとして出す

- rmcp の prompts（版は今のまま 3.5.1）で7つ出す。中身は FP から AI への頼み方の文（利用者の役の1通）で、引数をその場で埋める。プロンプトを選んでも道具は呼ばれず、AI が文を読んで道具を使う。

| 名前 | 見出し | 引数（* は必須） |
|---|---|---|
| `what_can_you_do` | この接続口でできること | なし |
| `compare_households` | 2つの世帯を比べる | `household_a`*・`household_b`*・`focus` |
| `compare_measures` | 対策をいくつか並べて比べる | `household`*・`measures`・`at_ages`・`market_stress` |
| `make_seminar_household` | セミナー用の架空の世帯を作る | `profile`*・`events`・`output` |
| `prepare_meeting` | 面談の準備 | `household`・`topic` |
| `explain_to_client` | 数字の根拠をお客さまに分かる言葉で説明する | `household`*・`number`* |
| `check_coverage` | 制度や計算に入っているかを調べる | `topic`* |

- 文の中の道具は、今ある道具だけを名前で書く（calculate・compare・list_plan_items・explain_value・get_regulation_value・search_coverage・get_coverage・get_input_guide・get_input_recipe・list_sample_households・get_sample_household・list_shared_households・propose_scenario）。テストで、文の中の道具の名前がどれも道具の一覧にあることを確かめる。
- 何通りも比べる所（2つの世帯・対策を並べる・面談の準備）は、`calculate` を何度も呼ばずに比べる道具（`compare`。0198）で1回で計算する、と書く。2つ目の世帯は `variants` の1通り、対策は `variants` の通りの `plan_changes`。対策を並べる・面談の準備（老後資金・資産運用）では、相場が下がった場合の型（`market_stress` の drop・low・minus1。0200）を重ねた通りも選べるよう書く。主な数字には65歳からの年金の月額（`keyFigures.pension`。0200）を入れて並べる。
- 引数は MCP の決まりで文字だけ。空の文字は書かなかったものとして扱う（アプリによっては空で送る）。世帯の引数は、見本の id なら `sample_household_id`、渡した世帯の share_id なら `share_id` として使うよう書く。
- 世帯の中身・顧客の情報はプロンプトに入れない（引数は FP がその場で書く文だけ）。

### 3. 説明（INSTRUCTIONS）に書き足す

- 答えを小さく取る: 今の `calculate` の行に、見本の世帯の一覧は `tags` で絞り、`explain_value` は `omit`・`depth` で小さくできること、主な数字に年金の月額が入り `omit` の `pension` で省けること、年ごとの数字は画面の表と同じ年から始まること（0200）を足す（比べる・振るときに主な数字だけを取ることは 0194、何通りも並べるときに `compare` を使うことは 0198 のとおり）。
- ほかのソフトとの違い: ファイナンシアの側は対応範囲の一覧と道具の答えで確かめた事実だけを答え、ほかのソフトの機能・計算の仕方・数字は推測で断定しない。確かめられないことは確かめられないと伝え、そのソフトの資料で確かめるよう勧める。
- 「何ができる？」と聞かれたら、場面ごとに頼み方の例を添えて紹介し、AI のアプリのプロンプトの一覧からも選べると伝える。
- 公開に使うときの案内（軽い形。止める仕組みにはしない）: FP がお客さまの世帯の数字をブログ・セミナー・SNS などに使いたいと言ったら、①年齢・年収・資産の数字を丸める（例: 年齢は「30代」、年収は50万円単位）②家族構成と珍しい条件（職業・地域・珍しい制度）の組み合わせで人が分かりそうなら変える ③お客さまに一言ことわる、を一言添える。見本の世帯・架空の世帯の数字には要らない。`docs/ai-connector.md` の「頼み方の例」にも同じことを書く。

## 理由

- **棚と同じ名前と目印**: FP がアプリの見本の棚で見ている名前で AI も話せる。別の一覧を持つと、見本を足したときに片方だけ直ってずれる。JSON にするのは、画面の一覧（TypeScript）を接続口（Rust）が直接読めないためで、作るのは数字の根拠の読み方と同じまとめる道具に任せる。
- **場面の目印は棚の項目から決まる物だけ**: 「子育て」「シニア」は画面の項目（教育費・家族の形と年代）の言い換えで、決め方が1行で書ける。「住宅購入」のように棚の見本に当てはまる物が無い場面は、目印を作らず手本を重ねる案内にする（見本を足すのはセミナーの場面を聞いてから。0196 の未確定と同じ）。
- **試験用を既定で出さない**: 表が2027年までの世帯を FP の場面で選ぶと、老後の数字が出ない。開発の確かめには今までどおり使えるよう、目印で出せるようにする。
- **プロンプトは頼み方の文だけ**: 道具を呼ぶのは AI で、FP は選んで引数を書くだけでよい。道具の答えをプロンプトに入れないので、顧客の情報がプロンプトの一覧や文に入らない。
- **公開の案内を止める仕組みにしない**: 公開するのは FP で、接続口からは何も外に出ない。人が分かりそうかどうかは場面ごとの判断で、決まりで止めると見本・架空の世帯まで止まる。AI がその場で一言添えるのがいちばん軽い。

## 代案（採らなかったもの）

- **README の説明を短く書き直して、全部を出す**: README は開発者向けの記録として要る。FP の名前は棚が正なので、そちらを使う。
- **目印の一覧を接続口の側に持つ**: 棚とずれる。
- **プロンプトの中で道具を呼んで、答えまで入れて返す**: プロンプトは AI のアプリが一覧を出すたびに読まれうる。世帯の中身を入れない。
- **公開に使うときは、接続口が数字を丸めた答えを返す**: どこまで丸めるかは場面で違い、計算の数字が画面とずれる。

## できること・できないこと

- できる: 「子育て中の見本を見せて」「シニアで収益不動産のある見本は？」に、5KB ほどの答えで答える。Claude Desktop などで、よくある頼み方を一覧から選ぶ。
- できない（作らない）: 見本の棚に無い場面の見本を目印で出すこと（手本を重ねる）。公開に使う文の点検・止めること。

## 影響

- 接続口: `list_sample_households` の入力（`tags`・`include_test`）と答えの形（前の `description`・`baseMonth`・`endYear`・構成員の配列は、`title`・`no`・`tags`・`members` の文・`period` に）。プロンプトの7つ（サーバーの能力に `prompts` を足した）。INSTRUCTIONS の4か所。
- まとめる道具: `npm run build:explain` が `crates/lifeplan/dist/samples.json` も作る（CI の受け渡しにも足した）。`src/connector/` が `store/numbering` を読めるよう lint の決まりを足した。
- アプリの画面・見本の棚・計算エンジン・世帯ファイルは変わらない。

## 未確定

- 場面の目印を足すか（住宅購入・相続 など、棚の見本を足すときに一緒に決める）。プロンプトを足すか（保険の見直し・教育費 など、使ってもらってから）。
- 公開に使うときの案内の言い方（βで使ってもらってから直す）。
