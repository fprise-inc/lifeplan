# 0035. 世帯ファイルの形式 0.17（作りの変わる形を1回の版上げにまとめる）

- 状態: 採用（一部未確定）（2026-10-26）
- 固定の強さ: β公開から変えない（骨格）。世帯ファイルの形式は「安定」の公開の約束（0011）。中身のある変換の段を 0.16 → 0.17 の1段にまとめること、値の状態の置き場所（値の箱か物の値の状態の欄 `valueStates` のどちらか一方）、確定は明示の操作だけで状態を変えること、世帯の外の家族を構成員の印 `outside` で持つことと贈与者をそれにそろえること、並びの要素の ID、当て先（向き先＋入力項目ID＋場所。0036）で値を指し欄のキーを保存しないこと、読み替え表の置き場所と形、古い世帯を黙って書き換えないことは骨格。足すだけの形の欄の名前と値の一覧はそれぞれを足す回に決める（この記録の追記に書く）。変換の段で振る ID の作り方（内部）、開いたときの知らせの文言、画面の見せ方は後から変えてよい（変えたら追記に書く）

## 背景

- 入力画面を作り直す。カードを組み直し、入るお金と出るお金を同じ形の行にし、親などを世帯の外の家族として持ち、入れていない所を「推定・わからない・該当なし・未入力」の4つにそろえ、プランで物を足す・外す・選択や時点を変えられるようにする。どれも世帯ファイルの形に効く。
- βで作った世帯ファイルは、正式版とその後のすべての版で読める（0011 の5）。βの後に作りを変えると、その変換の段をずっと持ち続け、βで作った世帯がすべてその段を通る。形式の版を上げる変更は、まとめて回数を少なくする（0011 の5）。
- 今の形（0.16）の問題:
  - 値の箱（0008 の2）で持つ欄は一部だけで、借入額・購入の価格・保険料・保障の額など円の欄の多くと、選択・時点・回数・率の多くは、値だけを裸で持つ。これらの推定の印は画面の側の `household.assumed` に**欄のキー**で持つので、欄のキーを変えると外れ、プランで足した物にも付かない。
  - 親・祖父母を家族に足すと世帯の構成員になり、その人の年金の推計が世帯の収入に入る。世帯の外の人として持つ形が無い。贈与者は別の物 `donors` で、介護を受ける親と同じ人を表せない。
  - 関係（`relations`）・生活費の段階と費目・積立の期間・金利の段階・繰上返済などの並びの要素に ID が無く、プランの差分や印が並びの番号でしか指せない。同じ2人の関係を期間で分けて持てるか（事実婚から入籍など）も決めていない。
  - プランの差分は値を変える `set` だけで、画面の「動かす項目のキー」（`field:<欄のキー>` など）で当てている（0008 の追記 2026-10-17）。欄のキーを変えると、保存したプランが当たらなくなる。差分の型は 0036 で決める。
- 前提にする記録: 0001（書き方・変え方）、0004（ID・登録簿）、0008（世帯のデータモデル・値の箱）、0009（作業中のプランと控え）、0011（封筒・一方向の形式移行）。

## 決定

### 1. 版上げの方針

- **作りが変わる形**（古いファイルのままでは新しい読み方で読めず、変換の段で中身を書き換える形）は、すべて **0.16 → 0.17 の1段**に入れる。下の2の表の「作りが変わる」の行が全部これに当たる。
- **足すだけの形**（任意の欄・物の集まり・選択肢を足すだけで、古いファイルがそのまま読める形）は、その計算と画面を作る回に入れ、回ごとに MINOR を1つ上げる。変換の段は版だけを書き換える段にする（0.4〜0.16 の前例と同じ。0011 の5）。小さく、0.17 の形と組になるものは 0.17 の回にいっしょに入れる（2の表の「入れる回」）。
  - 計算を入れない欄を形だけ先に入れない（入れたのに結果に出ない欄を作らない）。例外は、2の表で「入れ物だけ」と書いた口座の間の移し替えで、計算を入れるまでエンジンは知らせを出して計算に入れない。
  - 足すだけの形は β の後に入れても古いファイルはそのまま読める（MINOR）。β の前に間に合わなかったものは、β の後に入れてよい。
- β公開のときの形を、安定の最初の版 `1.0` にする（0011 の追記）。0.17 より後の `0.x` → `1.0` の段は、版だけを書き換える段にする。
- 0.17 の段を取り込んだ後に、その段の誤りが見つかったとき: β の前は、その段を直してよい（0.17 で保存した世帯は試験のものだけのため。直したら見本を作り直し、追記に書く）。β の後は新しい段で直す。

### 3. 値の状態（推定の入れ物）

- 入れていない所と外から来た値は、どの欄も次の状態で持つ。意味は値の箱（0008 の2）の `state` と同じ。

| 状態 | `state` | 計算に使う値 | いつ |
|---|---|---|---|
| 推定 | `estimated`（`estimate` を必ず持つ） | 欄の値（目安） | 統計・事務所のひな形・ほかの値からの逆算・標準の値で埋めた |
| わからない | `unknown` | 代わりの値 | 聞いたが分からなかった |
| 該当なし | `notApplicable` | 無い | FP が「無い」と決めた |
| 確定 | `confirmed` | 欄の値 | FP が入れた・選んだ、外から来た値を承認した |

  「未入力（0円で計算中）」は状態を持たない（値も推定も該当なしも無いことを、画面が決まりで判定する）。

- **置き場所は1つの値に1か所**:
  - 値の箱を持つ値（今ある値の箱の欄と、これから箱で足す欄）は、今のまま箱の中。
  - 値の箱を持たない値は、**その値を持つ物の `valueStates`（値の状態の欄）** に、当て先の入力項目ID と場所で作った鍵で持つ。物の外の値（表の最後の年・前提条件）は、要求の入力の `valueStates`（`household.request.input.valueStates`）に持つ。画面の側の物（万一の前提など）も同じ形の `valueStates` を持てる。
  - 同じ値を値の箱と `valueStates` の両方に書かない（テストで確かめる）。
- 形:

```json
"debts": [{
  "id": "<ローン>",
  "kind": "mortgage",
  "principal": 30000000,
  "rateSchedule": [{"id": "<金利の段>", "from": {"at": "2027-04"}, "type": "fixed", "rate": "0.008"}],
  "valueStates": {
    "debt.principal": {"state": "estimated", "origin": {"kind": "auto"}, "estimate": {"method": "derived", "basis": "物件の価格−頭金"}},
    "debt.rateSchedule/<金利の段>/rate": {"state": "estimated", "origin": {"kind": "auto"}, "estimate": {"method": "standard", "basis": "標準の値（全期間固定0.8%）"}}
  }
}]
```

  - 鍵は「入力項目ID」か「入力項目ID/場所」。場所は 0036 の2 の `at`（入力項目の値の中の道。並びの要素は ID、欄は名前）を `/` でつないだもの。値の当て先が1通りに決まるので、鍵も1通りに決まる。
  - 行の形（スキーマ `common.json` の `valueState`）は、値の箱から `value`・`substitute` を除いたもの: `state`（必須）・`origin`（必須）・`estimate`・`approval`・`certainty`。
  - 推定の行は `estimate` を必ず持つ。わからないの行は、欄に入れた代わりの値の根拠として `estimate` を必ず持つ（値の箱の `substitute` に当たる。値そのものは欄にある）。該当なしの行の値は欄を省く（省けない欄は0）。確定の行は、出どころ・承認・確かさを残すときだけ書く。
  - **行の無い値は「記録の無い確定」**。古いファイルの箱を持たない値はすべてこれになる（黙って推定にしない）。FP が「✓ この値で確定」を押したときは `{"state": "confirmed", "origin": {"kind": "manual"}}` の行を書き、記録の無い確定と見分けられるようにする。
  - 外から来た値（ヒアリング・取り込み・AI）は、行にも承認の記録を必ず持つ（値の箱と同じ決まり。0008 の2）。
- 確かさ `certainty`（値の箱と行の任意の欄。計算には使わない）: `document`（書類で確認）・`declared`（本人の申告）・`rough`（概算）。無ければ未指定。画面が出どころから既定を入れる（書類の取り込み → `document`、ヒアリング・お客さまが自分でする見直しの聞き取り → `declared`、手入力 → 入れない）。
- 推定の出し方 `estimate.method` に `standard`（標準の値・目安のボタン・仮の値）を足す。
- **確定は明示の操作だけ**（欄に入っただけで確定になることを、形の上でも起こさない）:
  - 値と状態を変えるのは、値を打った・選んだ・ボタンで変えたとき、「✓ この値で確定」「推定をまとめて確定」「推定に戻す」「わからない」「該当なし」を押したときだけ。欄に入って離れる・Tab で通る・同じ文字を書き戻す・パネルを開いて最初の欄に入る、では値の箱も `valueStates` も1文字も変えない（同じ文字を書き戻しても状態を確定にしない）。
  - 推定の入れ直しは、出どころ `auto` の推定と、わからないの代わりの値だけを入れ直す（0008 の追記 2026-10-11 の2 のまま）。確定（記録の無い確定を含む）は変えない。
- エンジンは `valueStates` を計算に使わない。エンジンの入力のスキーマの物の定義すべてと要求の入力に、知っている任意の欄として足す（知らない欄を拒む決まり〔0004 の7〕は保つ）。計算の結果は変わらない。
- 0008 の2「入力項目ID を持つすべての入力値は値の箱で持つ」は、この記録で次のように改める: 今ある値の箱はそのまま。値の箱を持たない値は箱へ移さず、状態を物の `valueStates` で持つ。**新しく足す円の値は値の箱で持つ**（0008 の2 のとおり）。新しく足す選択・時点・回数・率・名前は、値だけで持ち、状態は `valueStates` で持つ。

### 4. 世帯の外の家族

- 親・祖父母・兄弟姉妹・離れて住む子・前の結婚の子・孫など、**家計を世帯と別にする家族**は、構成員（`members`）に印 `outside` を付けて持つ。構成員の ID・生年月・関係・年金の記録・介護を受ける人の仕組みをそのまま使う。

```json
{
  "id": "<父>",
  "kind": "parent",
  "birth": {"birthYearMonth": "1952-05", "bornOnFirst": false},
  "sex": "male",
  "joins": null,
  "leaves": null,
  "expected": false,
  "support": {"dependent": false, "cohabiting": false, "allowance": 30000},
  "outside": {
    "of": "<本人>",
    "periods": [{"id": "<期間>", "from": {"at": "2031-04"}, "to": null, "living": true, "income": false}],
    "employeeInsurance": false
  }
}
```

- 欄:
  - `outside` がある構成員が世帯の外の家族。無い構成員は今と同じ世帯の中の構成員。
  - `of`: 誰の家族か（構成員の ID）。続柄の文字は持たず、`kind`・`of`・性別・関係から画面が作る（0008 の3）。贈与者から作った人で、元の贈与者に `of` が無かったものだけ省いてよく、そのときは今の贈与者と同じく「贈与を受ける人の家族」と読む。
  - `kind` に `sibling`（兄弟姉妹）・`grandchild`（孫）を足す。世帯の外の家族の `kind` は `parent`・`grandparent`・`sibling`・`child`・`grandchild`・`other`。
  - `periods`: 家計を1つにする期間（無い・空なら家計はいつも別）。期間ごとに `living`（生活費の人数に入れる。既定 true）と `income`（年金・給与などの収入を世帯に入れる。既定 false）を別々に持つ。期間は重ならない。要素は ID を持つ。
  - `employeeInsurance`: 勤め先の健康保険に入っている（世帯の人をその人の扶養に入れられる）。既定 false。
  - 生年月 `birth`・性別 `sex` は、世帯の外の家族だけ省ける（贈与者から作った人など）。年齢を使う計算（介護・年金の推計・亡くなる見込み・扶養の判定）にその人を使うときは、画面が生年月を求める。
  - `joins`・`leaves` は、その人を計算に出す期間として読む（`leaves` は亡くなる見込み。世帯に加わる・離れる、の意味ではない）。
  - 扶養と同居の印 `support`（`dependent`・`cohabiting`・`allowance`）は今のまま（健康保険・税の扶養の判定に使う）。仕送りを支出にする形は、相手をその人にした出るお金の行で、`allowance` は支出にしない（0008 の追記 2026-10-26 の2 のまま）。
- 計算の決まり（エンジン。世帯の外の家族の計算を入れる回に作る）:
  - 世帯の外の家族の年金・給与・給付は、世帯の収入・表の行に入れない。`income` の期間だけ入れる。
  - 生活費の人数・遺族の生活費・表の最後の年の標準・世帯の税と社会保険料の対象に入れない（`living` の期間は生活費の人数にだけ入れる）。
  - その人自身の所得・年金の推計は、介護の自己負担の割合・住民税の非課税・扶養の判定と、その人のお金の見通しにだけ使う。
  - 介護を受ける人（`careExpenses[].member`）・お金の行の相手・相続人・贈与の相手、世帯の人を健康保険の扶養に入れる人になれる。世帯の外の家族どうしの配偶者の関係（両親）も、今の関係の形で持つ。
- **贈与者 `donors` はなくし、世帯の外の家族にそろえる**。贈与の物の `donor`（住宅資金の援助・子への援助）は世帯の外の家族の構成員の ID を指す。贈与者から作る構成員は贈与者と同じ ID にするので、指す先は変わらない。直系尊属かどうかは、今の贈与者と同じ考え方（`kind` と `of` と受け取る人）で導く。
- 入力項目ID: `member.outside` を足す。`donor.kind`・`donor.of` は廃止（読み替え先 `member.kind`・`member.outside`）にする（0004 の3）。

### 5. 並びの要素の ID と、関係を期間で持つ

- 次の並びの要素は `id`（UUID 第4版。0004 の4）を持つ。プランの差分・値の状態の欄・取り込みの候補が1件ずつ指すため。
  - 関係 `relations[]`
  - 生活費 `livingExpenses[].stages[]`・`categories[]`
  - 口座の積立 `accounts[].contributions[]`
  - 負債の金利の段階 `debts[].rateSchedule[]`・繰上返済 `prepayments[]`
  - 住宅資金の援助 `residences[].purchase.gifts[]`
  - 保険の更新 `insuranceContracts[].renewals[]`（保障 `coverages[]` は前から持つ）
  - 教育の目標の段・習い事・奨学金・教育ローン・援助 `goals[].education.stages[]`・`lessons[]`・`scholarships[]`・`loans[]`・`gifts[]`
  - FP顧問料の単発の料金と改定の段 `advisoryFees[].terms.oneTime[]`・`terms.recurring.revision.steps[]`

### 7. 足すだけの形の要点

欄の名前と値の一覧は、それぞれの形を足す回に決め、この記録の追記に書く（足すだけなので、この記録の決定は変わらない）。ここには β の前に入れる形の骨組みだけを書く。

- **入るお金の行** `incomeFlows`（物の集まり。出るお金の行 `periodicExpenses` と同じ形の土台）: 名前・種類・額（値の箱）・時期（1回か、くり返し。時点の型）・受け取る人・相手（構成員。多くは世帯の外の家族）・見込み・課税の扱い・伸び方・段階・例外の年・万一のときの扱い・表の行。向きは物の集まりで決める（マイナスの額は作らない）。課税の扱いは8通り（非課税・一時所得・雑所得〔業務〕・雑所得〔その他〕・給与〔社会保険なし〕・譲渡所得〔分離〕・贈与税で見る・相続税で見る）で、種類から既定を決める。
- **出るお金の行に足す欄**: 相手・優先度・払う人（構成員）・種類・あげる贈与（相手・くり返し・使い道・課税の方法。贈与税は受け取る人が払うので世帯からは出さず、要約に出す）・段階・例外の年。表の行の選択肢に教育費・車の維持費を足す（行は `registry/rows.yaml` に足す）。
- 相手が世帯の外の家族で、その人のお金も見ているときは、1本の行を両方の側が反対の向きで読む（行を2本にしない）。
- **見込み・優先度**: 入るお金と、相続で受け継ぐ借金（ほかのローン。誰から受け継ぐかの欄を持つ負債。欄の名前は相続・贈与のカードの回に決める）に `likelihood`（`certain` 確実・`likely` たぶん・`uncertain` 不確か）、出るお金と目標に `priority`（`need`・`want`・`wish`。目標の `priority` と同じ値）。計算での扱い:
  - **見込みが「不確か」の、受け取る相続・遺贈・贈与の行（入るお金の行のうち種類が「相続・遺贈」「贈与を受ける」のもの）と、相続で受け継ぐ借金は、基本の計算に入れない**。「確実」「たぶん」は入れる。行は消さずに残し、画面に「計算に入れていない」と見せる。不動産を受け取る行（行き先の物へのつなぎ）が不確かなときは、つないだ物（持ち始める時点のある不動産・置き換える住まい）も同じく入れない。
  - 当てるのは上の行と借金だけで、ほかの種類の入るお金（家族・働き方・介護・親などのカードの行、住宅資金の援助・子への援助）には広げない（当てにならない遺産で楽な結果を見る誤りは、相続に特有なため）。
  - 入れるかは、その行・負債の任意の欄 `includeInBase` で変える（`true` で、不確かでも基本の計算に入れる。省略は見込みで決める）。プランで入れるときは、この欄の `set` にする（見込みは事実の見立てなので、計算に入れるために変えない）。現状でも FP が選べば入れられる。
  - エンジンは変えない。アプリが作業中の世帯から要求を作るときに外す（0036 の6）。世帯のデータからは消さない。
  - 優先度と、上のほかの見込みは計算に使わない。「確実な分だけで見る」（見込みが不確かな入るお金のすべてと、優先度が「希望」「夢」の出るお金を外す）は、別の見方として、保存しない自動の差分で作る（0036 の6）。
- **段階と例外の年**: 段階は生活費の `stages` と同じ形（`id`・`at`・額か今の額に対する割合・次の段まで何年かけて変えるか）。例外の年は `exceptions`（`id`・`year`・額）。
- **働き方の期間ごとの伸び**: 給与の `growth` を、昇給カーブの値ID か年率を持てる形に広げる（今の形はそのまま読める）。事業所得にも伸びの率。空欄は前提の賃金上昇率。
- **表示だけの欄**: `label`（負債・口座・保険・住まい・お金の行）、住まいの建て方、保険の種類のひな形、口座の満期の年月。計算に使わない。
- **不動産を持ち始める時点**: 不動産の器の中身 `property` に、持ち始める時点（相続・贈与で受け取る・後で買う）と前の持ち主の取得費を引き継ぐ欄。その時点から資産・負債・家賃収入・経費・相続税の目安に入れる。
- **口座の間の移し替え** `transfers`: いつ・どの口座から・どの口座へ・いくら（額・割合・全部・残高が決めた額を超えた分）と、結び付けたお金の行。β では入れ物だけ（画面に出さない）。計算を入れるまで、あればエンジンは知らせを出して計算に入れない。
- **譲渡所得の税の額の口**: 住まいの売却 `residences[].sale` と住まい以外の不動産の売却 `accounts[].property.sale` に、税の額（値の箱）。入れた額は売った年の手取りから引く。自動の計算は後の回で、入れた額が優先する。
- **相続税の額の口**: 受け取る側は、出るお金の行の種類「相続税」（表の行 `cf.taxSi.inheritanceTax`）。遺す側は、目安の額を直す口（年と額。相続税の目安を作る回に形を決める）。
- **保険**: 保障の行の給付の種類の追加（三大疾病などの一時金）、保障の行ごとの被保険者（省略は契約の被保険者）、外貨建て・変額の契約を円の目安で計算する印、万一の想定の病気の想定（病気の種類・入院の日数・手術の回数）。
- **雇用保険の基本手当など**: 辞め方（今の `endsWith`）と受け取るか（既定は受け取らない。古い世帯の結果を変えない）。
- **任意継続**: 健保組合・共済の任意継続の月額（値の箱）。株の売却益などを保険料の所得に入れるか。
- **学校外の費用の入れ方**（統計の平均で／行で入れる。行で入れるときは統計を足さない）、**車の維持費の入れ方**（合計／内訳。両方の値を残す）。
- **画面の側**: カードごとの段 `workspace.levels`（カードの ID → `simple`・`detail`）、入れ方の区分、万一の前提の任意の欄。

### 9. 読み替え表

- 古い欄のキー・動かす項目のキーを、当て先（0036 の2）か合成の対策（0036 の3）に読み替える表を、**1か所** `registry/readings.yaml`（YAML が正本、ビルドで JSON。0004 の追記）に置く。本体の変換の段・画面（控えの中の古い差分・古い要求を読むとき）・AI の候補の読み込み・テストが、同じ表を読む。形は次のとおり（鍵の型は例。実際の鍵は 0.16 の欄の定義から作る）。

```yaml
kind: reading
entries:
  - from: "field:housing/debt/{object}/principal"
    until: "0.16"
    to: {target: object, item: debt.principal, at: []}
  - from: "field:living/{object}/stage/{index}/ratio"
    until: "0.16"
    to: {target: object, item: livingExpense.stages, at: ["{element}", "ratio"]}
  - from: "assumed:housing/debt/{object}/principal"
    until: "0.16"
    to: {target: object, item: debt.principal, at: [], method: derived}
  - from: "lever:retireAge"
    until: "0.16"
    to: {lever: retireAge}
```

  - `from` は古い鍵の型。前置きは `field:`（差分の鍵と対策に足した項目のうち入力の欄のもの）・`assumed:`（仮の印の欄のキー）、そのほかは動かす項目のキーのまま（`lever:`・`loan:`・`mix:`・`inv:`・`surplus:`・`rates:`）。`{object}`・`{member}` は物・構成員の ID、`{index}` は並びの番号の入る所。
  - `to.target` は `object`・`member`・`assumptions`・`input`・`contingency`（0036 の2）、または `to.lever`（合成の対策の名前。物を持つ対策は `{object}` も）。`{element}` は、`{index}` の番号の要素に変換の段が振った ID（10 の1 の作り方で同じ ID になる）。
  - `until` は、その鍵を世帯ファイルに書いた最後の形式の版。
  - 値の形が変わる鍵は `convert`（例: 月額 → 年額）、仮の印は `method`（推定の出し方。書かなければ `standard`）を書く。
- **0.17 から、世帯ファイルに欄のキー・動かす項目のキーを保存しない**（差分・状態の欄・対策に足した項目は当て先で持つ）。そのため欄のキーは画面の作り直しで変えてよく、読み替え表に足すのは、0.16 までに保存された鍵と、合成の対策を当て先に寄せたとき（0036 の3）だけになる。
- 表に載せる鍵は、0.16 の画面が世帯ファイルに書きえた鍵の全部（差分になる数の欄の欄のキー・仮の印の欄のキー・動かす項目のキー）。0.17 の回に 0.16 の欄の定義から機械で作り、12 の凍結した見本で確かめる。
- 入力項目ID の付け直し・廃止は、この表ではなく登録簿 `registry/items.yaml` の `aliases`・`replacedBy` に書く（6）。表の `to.item` は登録簿にある ID だけにする（CI で確かめる）。

### 10. 0.16 → 0.17 の変換の段

入力と出力が決まった純粋な関数（0011 の5）。読み替え表は、ビルドで作った JSON を本体に組み込んで使う。次の順に行う。

1. **並びの要素の ID**（5）: ID の無い要素に ID を振る。作り方: 文字列 `lifeplan.migrate.0.17:<場所>` の SHA-256 の先頭16バイトに、UUID 第4版の版と変種のビットを立て、小文字・ハイフンつきの36文字にする。場所は `<親の物の ID>/<親の物から並びまでの欄の名前を / でつないだもの>/<並びの番号>`（例 `<ローン>/rateSchedule/0`・`<目標>/education/stages/2`・`<住まい>/purchase/gifts/1`。前提の列は親を `assumptions` に、関係は `relations/<番号>/<一方の構成員の ID>/<他方の構成員の ID>`〔配偶者は `a`・`b`、親子は `parent`・`child` の順〕）。同じ本文からはいつも同じ ID になり、世帯ファイルの中で重ならない。
2. **世帯の外の家族**（4）:
   - `kind` が `parent`・`grandparent` で `outside` の無い構成員に `outside: {"periods": []}` を付ける。その構成員を親とする関係（`parentOf`）の子が世帯の中の構成員なら、`of` をその子にする（複数なら構成員の並びで最初）。同居と扶養の印・`joins`・`leaves`・年金の記録・介護の物は変えない。家計を1つにする期間は作らない（FP が決める）。知らせ `outsideFamily` を1件書く。
   - これが、不具合の直しとして変換の段で中身を書き換える**唯一の例外**（親の年金が世帯の収入に入るのは誤りで、古い世帯だけ誤りのまま残すと、同じ親で結果が違うため）。
   - 贈与者 `donors[]` の1件ごとに、同じ ID の構成員 `{"id", "kind", "joins": null, "leaves": null, "expected": false, "outside": {"of"?, "periods": []}}`（生年月・性別なし）を足し、`donors` を消す。贈与の物の `donor` はそのまま（同じ ID）。結果は変わらないので知らせは書かない。
3. **仮の印** `household.assumed`: 鍵ごとに読み替え表（`assumed:`）で当て先に直し、当て先の物の `valueStates` に `{"state": "estimated", "origin": {"kind": "auto"}, "estimate": {"method": <表の method>, "basis": <仮の印の文>}}` を書く。当て先の値が値の箱なら書かない（箱の状態が正）。読み替えられない鍵・当て先の物が無い鍵は `assumed` に残す（画面は読むだけ）。全部移せたら `assumed` を消す。
4. **プランの差分**: 0036 の5。読み替えられなかった差分があれば知らせ `unresolvedDiffs` を書く。
5. **対策に足した項目** `workspace.shownItems`: 鍵ごとに読み替え表で当て先（0036 の2 の `target`・`item`・`at`）か合成の対策に直す。直せない鍵は捨てる。
6. **形式の版** `meta.formatVersion` を `0.17` にする。

変えないもの: 控え `snapshots`（中の古い要求・差分・保存していないプランの値を含めて）・ヒアリングの記録・明細の取り込みの記録・拡張領域・`meta` のほかの欄・値と値の箱。

### 11. 古い世帯を開いたとき（黙って書き換えない）

開いた世帯は黙って書き換えない（0008 の追記 2026-10-11 の2）。扱いが変わる所は知らせて FP が選ぶ。

### 13. β の後に変えない部分

| 部分 | 固定の強さ |
|---|---|
| 値の状態の4つと置き場所（値の箱か `valueStates` の一方）、`valueStates` の鍵の作り方と行の形、確定は明示の操作だけ | 骨格 |
| 世帯の外の家族の印 `outside` の形と意味、贈与者をそろえたこと、家計を1つにする期間と2つの印 | 骨格 |
| 並びの要素の ID（どの並びが持つか）、関係を期間で複数持つこと | 骨格（ID を持つ並びは足してよい。外さない） |
| 読み替え表の置き場所と形、欄のキーを保存しないこと | 骨格（表の中身は足してよい。消さない） |
| 世帯ファイルの形式 | 安定の公開の約束（0011）。β の後に足す欄は MINOR |
| 変換の段で振る ID の作り方 | 内部（変えるなら凍結した見本で、前と同じ ID になることを確かめる） |
| 知らせの文言・画面の見せ方・状態の印の色 | 後から変えてよい |

## 理由

- **値の状態を物の中に持つ**: 状態がその値を持つ物といっしょに動く。プランで足した物・複製した物・控えの写しに状態が付いたまま入り、物を外せば状態も消える。欄のキーにも、世帯の中の別の表との付け合わせにも頼らない。
- **箱を持たない値を値の箱へ移さない**: 移すとエンジンの入力の形・すべての計算部品・画面・ヒアリング・AI接続口の読み方が変わり、3つの実行環境で同じ結果になることを確かめ直すことになる。円の値だけ移しても、選択・時点・回数の状態には別の置き場所が要り、置き場所が2つになるのは同じ。物の `valueStates` ならエンジンの計算は変わらず、どの種類の値にも同じ形で付けられる。新しく足す円の値だけは値の箱にして、0008 の2 の考え方を保つ。
- **行の無い値を「記録の無い確定」にする**: 古い世帯の値を黙って推定に変えない。FP が明示に確定した値には行を書くので、目安のボタンと同じ値の確かめにも使える。
- **世帯の外の家族を構成員の印にする**: 年齢・関係・年金の記録・介護を受ける人の仕組みを使い回せる。別の物の集まりにすると、どれも別に作ることになる。
- **贈与者をそろえる**: 同じ親が贈与者と介護を受ける人で別の物になると、相続人の数え方・お金の行の相手・贈与の要約を1人の人として扱えない。同じ ID にすれば、贈与の物が指す先を書き換えずに済む。
- **親の構成員だけを変換で書き換える**: 親の年金が世帯の収入に入るのは誤り。古い世帯だけ誤りのまま残すと、同じ親で結果が違う。開いたときに1回知らせ、家計を1つにする期間は FP が決める。
- **要素の ID を決まった作り方で振る**: 段が純粋な関数のまま、見本の期待の値を固定できる。閲覧だけで開いた世帯を開き直しても同じ ID になり、古い差分の並びの番号から同じ ID を引ける。
- **読み替え表を登録簿の場所に1つ置く**: 本体の段（Rust）と画面（TypeScript）とテストが同じデータを読めば、読み替えの食い違いが起きない。欄のキーを保存しなくすれば、表は古い鍵の分で止まる。
- **作りの変わる形だけを1段にまとめ、足すだけの形は回ごとに入れる**: 中身のある段をずっと持つ負担は作りの変わる形にだけある。足すだけの形は版だけを書き換える段で、β の後でも入れられる。計算の入らない欄を先に入れると、入れたのに結果に出ない欄になる。

## 代案（採らなかったもの）

- **箱を持たない値をすべて値の箱へ移す**（0008 の2 の文のとおりにする）: 上の理由のとおり、エンジンと全部の部品の読み方が変わり、確かめが重い。選択・時点まで箱にすると、エンジンの分岐の全部に及ぶ。
- **状態を世帯の1か所の表（物の ID＋入力項目ID）に持つ**: プランで足した物・複製・外した物と食い違い、付け替えと片付けが要る。
- **世帯の外の家族を新しい物の集まりにする**: 生年月・関係・年金の推計・介護の判定を別に作ることになる。
- **贈与者を残し、世帯の外の家族を指す欄を足す**: 同じ人を2つの物で持つことになり、どちらが正か決められない（0008 の6 の「正本は1つ」）。
- **変換の段で乱数の ID を振る**: 段が純粋な関数でなくなり、見本の期待の値を固定できない。開き直すたびに ID が変わる。
- **足すだけの形も全部 0.17 に入れる**: 計算の入らない欄をエンジンが受け付けることになり、欄の細部を計算を作る前に決めきれない。
- **差分などに欄のキーを手がかりとして残す**: 欄のキーは作り直しで変わるので、残すと古くなる。欄の定義が当て先を持てば、当て先から欄を引ける。

## 影響

- **エンジン**: 入力のスキーマに `valueStates`（物の定義すべてと要求の入力）・`outside`・並びの要素の `id`・`kind` の値・`plan.endYear`・`plan.baseMonth` の注釈・`certainty`・`standard` を足し、`donors` をなくす。贈与の部品は贈与者を世帯の外の家族の構成員から読む。生年月の無い構成員を年齢の計算に使わない。同じ2人の2本の関係を期間どおりに読むことを確かめる。0.17 の回には、これ以外の計算は変えない（世帯の外の家族の計算を入れる回から、親の構成員を持つ世帯の結果が変わる）。

- **本体**: 0.17 の段、読み替え表の組み込み、見本と凍結した見本。
- **ヒアリングの取り込み**（0018）: 書く先を当て先で決め、出どころと承認の記録を値の箱か `valueStates` に書く。

- **書き出し**（0020）: 全データの書き出しは本文そのものなので、足した欄もそのまま出る。
- **守ること**:
  - 世帯ファイルに欄のキー・動かす項目のキーを保存しない。
  - 値の状態は1か所（値の箱か `valueStates`）。同じ値に両方を書かない。
  - 欄に入っただけ・同じ文字の書き戻しで、値も状態も変えない。

  - 0.17 の段は、取り込んだ後は1の決まりでしか直さない。
