# 0167. 公式の資料との突き合わせで見つかった税と年金の計算の直し（所得金額調整控除の子ども等の分・66歳前の受け取り・中高齢寡婦加算の40歳・見込額の記録の特別支給・給与所得の端数）

- 状態: 採用（一部未確定）（2026-11-08）
- 固定の強さ: 内部（計算の直し。部品の約束の版・世帯ファイルの形式の版は変えない）。部品 `tax.totalIncomeBase` を足した（`tax.totalIncome` の中身を分けた。差し替えられる公式部品の「法律・制度」の区分。0119）
- 前提にする記録: 0002（端数処理。仮の規約 `conv.tax.fractionalDeduction`）、0006（部品表・小さな部品に分ける）、0007（制度データの形式）、0012（持たない情報。障害の状態）、0038・0066・0078（受け取り開始の入力）、0086（所得の区分と所得金額調整控除の給与と年金の分）、0119（差し替えられる公式部品）

## 背景

- 制度の計算を、エンジンのコードを読む前に公式の資料（条文・国税庁・日本年金機構）から作り直し、エンジンの答えと突き合わせた点検（201件）で、5つの誤りが見つかった。どれも新しい物（これまでの点検の記録・設計記録の未確定に無い）。給与所得の端数の一部は 0002 の「原本で確かめるまでの仮の規約」で、確かめたら逆向きだった。
- 直す前に、期待値どおりに落ちるテストを書いた（`engine/test/officialRecheck.test.ts`。28件のうち直す前は22件が落ちた）。テストは見張りとして残す。

## 決定

### 1. 所得金額調整控除の子ども・特別障害者等の分（租税特別措置法41条の3の11第1項・3項、国税庁 No.1411）

- その年の給与等の収入金額が850万円を超え、**年齢23歳未満の扶養親族**がいる人は、（給与等の収入金額〔1,000万円が上限〕−850万円）×10%（1円未満は切り上げ。国税庁 No.1411・年末調整のしかた）を給与所得から引く。給与と公的年金等の両方がある分（同条2項。今までどおり）は、この分を引いた後の給与所得から引く。出力の `adjustment` は両方の合計。
- **扶養親族**は、扶養控除（`tax.dependentDeduction`）と同じ範囲: 配偶者以外の子と、扶養していると入れた親・祖父母（世帯の外の家族は扶養していると入れた人、世帯の外の子は養育費・仕送りの行がある間）で、合計所得金額（所得税。退職所得・分離課税の譲渡所得を含む）が扶養親族の上限以下（令和8年分から62万円）の人。年齢と所得の判定はその年の12月31日（本人がその年に亡くなれば死亡の時、その前に亡くなった親族は死亡の時）の現況（同条3項）。
- **夫婦の両方が受けられる**: 扶養控除と違い、同じ子について、給与850万円超の夫婦それぞれが受ける（国税庁 No.1411 の注）。
- 判定するのは本人と配偶者（kind `self`・`spouse`）だけ。子や親の構成員が給与850万円超でも、その人の扶養親族は関係から決められないので判定しない。
- **特別障害者**（本人・同一生計配偶者・扶養親族が特別障害者）の分は判定しない。構成員に障害の状態の欄が無く、実在の障害の状態は持たない情報（0012）。0012 の未確定（障害に関わる税の扱いを実在の状態なしで表す方法）が決まるまで、この分は計算に入らない。
- **部品を分けた**: 扶養親族かどうかは子の合計所得金額で決まるので、合計所得金額の部品が子の合計所得金額を求める必要がある。部品が自分自身を呼ぶと循環になる（0006）ので、今までの中身を `tax.totalIncomeBase`（子ども等の分を引く前。出力の形は同じ）に移し、`tax.totalIncome`（改訂10）は `tax.totalIncomeBase` を呼んで子ども等の分を引く部品にした。子の構成員は子ども等の分を受けないので、子の合計所得金額は分ける前の部品の値と同じ。ほかの部品は今までどおり `tax.totalIncome` を呼ぶ。
- 制度データ（`regulation.tax` 2026.18.0）: `incomeTax.incomeAdjustment.children.revenueThreshold`（850万円）・`.revenueCap`（1,000万円）・`.rate`（0.1）・`.youngDependentUntilAge`（23歳。`reachMonth`）は条文とタックスアンサーの2つの読み方で照らし合わせて確認済み。`.rounding`（1円未満の切り上げ）は国税庁の2つの資料で一致するが条文に定めが無いので確認待ち（生命保険料控除の切り上げと同じ扱い）。給与と年金の分の値の出典の位置は、令和8年10月1日の版の条番号（41条の3の11第2項）に直した（値は同じ）。

### 2. 66歳になる前の受け取りは繰下げにならない（国民年金法28条1項・18条1項、厚生年金保険法44条の3第1項）

- 繰下げの申出は、65歳に達した日から1年を経過した日（66歳）より後にしかできない。受け取りの始まりを65歳に達した月の翌月（N）から12か月未満にしたときは**普通の請求**で、増額は無く、N の分からさかのぼって受ける。
- エンジンは、老齢基礎年金・老齢厚生年金のそれぞれで、受け取りの始まりが N より後で N から12か月未満なら N にする（SDK の `oldAgeClaimMonths`。`pension.oldAgeBase` 改訂6）。知らせ `N_ASSUMED`（`pension.deferral.beforeSixtySix`）を出す。66歳0か月からは今までどおり 0.7%×月数の増額。
- **さかのぼって受ける分は、N から毎月受けるとみなす**（決めたこと）。実際は請求した後にまとめて振り込まれるが、公的年金の収入の年は本来の支払期月で決まる（さかのぼって受けた年金は、もとの年の収入になる）ので、税と所得の年は N から毎月の方が合う。お金が手元に入る時期のずれは1年に満たない。
- 画面の「〇歳から」の欄は1歳ずつだが、時点の欄（年月）・ヒアリングの取り込み・SDK では月で入るので、エンジンで扱う。画面の欄は変えていない。

### 3. 中高齢寡婦加算の40歳の判定（厚生年金保険法62条1項）

- 中高齢寡婦加算は、夫の死亡の当時40歳以上65歳未満の妻、または40歳に達した当時に遺族基礎年金の対象の子と生計を同じくしていた妻に付く。エンジンは、支払いの始まりの月（死亡の翌月、子があれば遺族基礎年金が終わった翌月）と40歳に達した月を比べていたので、その翌月に40歳になる妻にも付いていた。
- 40歳の判定の月を、子が無ければ**死亡の月**、子があれば**最後の子が対象でなくなる月**（18歳に達した後の最初の3月）にした（`pension.survivor` 改訂6）。支払いの始まりの月は今のまま。40歳に達した月が判定の月と同じときは、日の前後が分からないので達していたとみなす（付ける）。
- 遺族年金のほかの年齢の判定も同じ形か見た: 遺族厚生年金の30歳未満の5年の有期（死亡の月 < 30歳に達した月）、夫の55歳（死亡の月 < 55歳に達した月）、経過的寡婦加算の「受給権を得たとき65歳以上」（死亡の翌月 ≥ 65歳に達した月の翌月）、遺族基礎年金の亡くなった人の65歳、寡婦年金の60歳から65歳まで（支払いの始まりと終わり）は、どれも死亡の月か支払いの月と正しく比べていて、ずれは無かった。同じ月は達していたとみなす扱いもそろっている。

### 4. 見込額の記録でも特別支給の老齢厚生年金を計算する（厚生年金保険法附則8条の2）

- 年金の記録が「見込額だけ」（`projection`）だと、特別支給の老齢厚生年金の欄（報酬比例部分）を空けたときに計算していなかった。画面の欄の説明は「入れなければ生年月と加入の記録から計算します（対象の生年月の人だけ）」で、食い違っていた。
- **計算する方に合わせた**（決めたこと）。理由: 見込額は65歳から受け取る額で、50歳以上のねんきん定期便の見込額と同じ意味（60歳まで今の加入を続けたときの65歳からの額）。特別支給の対象の生年月（男性は昭和36年4月1日以前、女性は昭和41年4月1日以前）の人は2026年に60歳以上で、定期便なら50歳以上の版の世代なので、50歳以上の定期便と同じ扱いが自然。受給の要件は生年月日・性別と厚生年金の1年以上だけで、見込額の記録からも決められる。50歳未満の定期便の世代（今後の加入を足して計算する世代）には特別支給の対象がいない。
- 額は、欄に入れた額があればそれ、無ければ記録の老齢厚生年金の見込額（報酬比例）。50歳以上の定期便と同じ。見込額の記録で厚生年金の加入月数を入れていないときは、老齢厚生年金の見込額があれば1年以上とみなす（受給資格期間を満たすとみなすのと同じ扱い）。
- `pension.employeeMonths`（加給年金の判定に使う、配偶者が240月以上の老齢厚生年金の受給権を持つ月）も同じ判定を使うので、見込額の記録の対象の生年月の人は、特別支給の開始の月から受給権を持つ（改訂3）。

### 5. 給与所得の端数（所得税法別表第五・措置法29条の4第2項。0002 の追記）

- 給与収入が最低保障額＋1,000円未満（令和7年分 65.1万円未満、令和8・9年分 74.1万円未満、令和10年分から 69.1万円未満）は給与所得0円。表の最初の区分（「691,000円未満 0」など）を、制度データの区分の幅の最初の段（0円からその額未満までを1つの区分にし、区分の下限0円の給与所得0円）で表した（`incomeTax.employmentIncome.tableSteps` rev 4〜6）。これまでは1円ごとの区分で、1〜999円の給与所得が出ていた。
- 給与収入660万円以上の給与所得（算式で求める額）は1円未満を切り捨てる（別表第五の備考・年末調整のしかた）。制度の端数処理 `incomeTax.employmentIncome.rounding`（確認済み）を足し、`tax.employmentIncome`（改訂6）は 収入×(1−率)−加算額 をこの端数処理で丸める。これまでの仮の規約（控除額を切り捨て）では給与所得が1円多かった。

## 理由

- 1 で部品を分けたのは、子の合計所得金額を求める方法がほかに無いため（子の給与・事業・年金などを別に足すと、合計所得金額の計算が2か所になって食い違う）。分けた部品は今までの中身そのままなので、ほかの所の結果は変わらない。
- 2 で「N から毎月」にしたのは、税と所得の年が合い、作りも小さい（受け取りの始まりを N にするだけ）ため。
- 4 は、画面の説明に合わせる（エンジンを直す）方が、FP がふだん使う入れ方（見込額だけ）で結果が正しくなる。説明の文を「入れなければ0円」に直す案は、対象の生年月の人の1〜2年分の年金が黙って抜けたままになる。

## 代案（採らなかったもの）

- 所得金額調整控除の子ども等の分を、扶養控除の部品（`tax.dependentDeduction`）の「23歳未満の扶養親族がいるか」から読む: その部品は合計所得金額を使うので循環になり、また扶養控除を受ける人（夫婦のうち所得の多い方）にしか答えを出さない。
- 66歳前の受け取りで、さかのぼりを請求の月にまとめて払う: お金の時期は実際に近いが、税の年がずれ、支払いの作り（偶数月の支払い）を変える必要がある。
- 見込額の記録では特別支給の欄の説明を「入れなければ0円」にし、未入力の知らせを出す: 上の理由で採らない。

## 影響

- 計算の結果が変わる世帯: (1) 給与収入850万円超で23歳未満の子などがいる本人・配偶者（給与1,000万円以上で給与所得が年15万円少なくなり、所得税・住民税が年4.5〜5万円ほど少なくなる。配偶者控除の段など合計所得金額で決まる判定にも効く）、(2) 受け取りの始まりを65歳1〜11か月にした人（増額が無くなり、65歳の翌月から受け取る）、(3) 妻の40歳の誕生月が夫の死亡の月の翌月か、末の子の18歳の年度末の翌月の万一の想定（中高齢寡婦加算が無くなる）、(4) 見込額の記録で特別支給の欄を空けた、対象の生年月の人（63・64歳の報酬比例部分が足される）、(5) 給与収入が最低保障額＋1〜999円の人と660万円以上の人（給与所得が最大999円・1円変わる）。
- 部品 `tax.totalIncomeBase` を足した（部品表・差し替えの一覧・SDK の説明書の一覧）。世帯ファイルの形式の版・部品の約束の版・`IPC_VERSION` は変えない。

## 未確定

- 所得金額調整控除の特別障害者の分（本人・同一生計配偶者・扶養親族）。0012 の未確定（障害に関わる税の扱いを実在の状態なしで表す方法）と一緒に決める。
- 所得金額調整控除の端数（1円未満の切り上げ）の法令の根拠（条文に見つけていない。国税庁の資料の2つで一致）。
- 公的年金等の雑所得の1円未満の向き（今は控除額を切り捨てる仮の規約 `conv.tax.fractionalDeduction` で、雑所得が1円多い場合がある）。国税庁 No.1600 の速算表は画像で、端数の向きを公式の資料の文で確かめられなかったので直していない。確定申告の手引きなどの原本で確かめてから決める。
- 70歳以後に請求したときの5年前のみなし繰下げ（令和5年4月から）は、受け取りの始まり＝選んだ月の作りでは出てこない（今回は扱わない）。

## 追記
