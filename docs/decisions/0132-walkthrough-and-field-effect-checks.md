# 0132. 通しの入力のテスト（画面のキー入力で3世帯を入れて結果まで出す）と、欄ごとの効き目のテスト

- 状態: 採用（一部未確定）（2026-11-07）
- 固定の強さ: 内部（テストと CI だけ。画面・計算・世帯ファイルは変えない。世帯ファイルの形式の版は変えない。世帯の入れ方・確かめの中身・一覧の行・言葉は後から変えてよい。変えたら追記に書く）
- 前提にする記録: 0129（ありえない結果の見張りと直す待ちの一覧）、0030（持ち帰り用のレポートを見えないブラウザで開く確かめ）、0005 の追記 2026-10-28（変更に関わるジョブだけ流す CI）、0008（値の箱）、0011（世帯ファイル）

## 背景

- 入力項目を通しで入れて確かめたところ、単体のテストでは見ていない「画面の操作と結果の組み合わせ」で起きる誤りが見つかった（円の欄の「15万」が15円、打ちかけの空で物が消える、働き方を変えても推定が残る、亡くなる見込みを直しても相続・介護がついてこない、など）。0129 は操作を関数で再現して結果を見張るが、画面の部品の上での操作（押す・打つ・Tab・保存）そのものは通していない。
- 入力項目の欄には「入れても計算に効かない欄」もあった（ねんきん定期便〔50歳未満〕の老齢基礎年金の額、資産配分の割合）。画面に出ている欄が計算に効くか、記録だけの欄かを、欄ごとに毎回確かめる仕組みが無かった。
- 利用者の判断で、同じ種類の誤りを二度と出さないための自動の点検として、0129 と並べて置く。

## 決定

### 1. 通しの入力のテスト（`app/test/walkthrough/walkthrough.test.ts`・`households.ts`・`browser.ts`・`pageHelpers.ts`）

- 開発用のサーバー（Vite。設定は `vite.config.ts` のまま、ポートは OS に空いている物を選ばせる。開発中のアプリのポート 1420 は使わない）と見えないブラウザ（DevTools の口〔CDP〕を Node の WebSocket で使う。npm の依存なし。0030 と同じやり方）を起こす。
- 3つの架空の世帯を、世帯を選ぶ → 空から作る → 入力項目を順に、画面のキー入力で入れる: ① 会社員の夫婦と子2人・持ち家（住宅ローンあり）を標準の欄だけで、② 自営業のひとり親と子1人・賃貸を詳細も使って、③ 60代の夫婦（再雇用・企業年金・完済の持ち家・区分マンション1室・母の介護と相続）を詳細も使って。
- 操作は人と同じ形にする: 押すのは本物のマウスの出来事（欄の中の「この値にする」などに隠れていない点を探して押す）。打つのは、欄を押して中を全部選び、そのまま打って（選んだ文字が打った文字に置き換わる。途中で空にしない）Tab。消すのは全部選んで Backspace。選ぶ欄（select）は、選択肢の一覧がブラウザの外に出るので、値を選んで変更の出来事を送る。ほかの物（パネルの下の固定の帯など）に隠れて押せない欄は、押さずに欄に入る（Tab で来たのと同じ）。隠れていた欄は記録に残す（`WALKTHROUGH_TIMING=1`）。
- 入れ終えたら、開発用のサーバーの世帯の置き場（メモリの中）から自動の保存の後の本文を読み、本文（`fromBody`）と計算の結果（エンジン）で、入れた値が世帯の中身と結果に届いたかを確かめる。結果のタブ（表の行）・資産と負債のタブ・万一のときのタブも開く。
- 見本の棚の主な世帯（3-4-01・4-3-01・5-6-01・3-5-01）は、全部の入力項目のパネルを開いて閉じ、結果のタブまで出す（見本は保存しないので、世帯の中身の確かめはしない）。
- 開いたパネルの文字に、内部の名前（英字のキー・JSON・選択肢の生の値）と「○つ」の数え方が無いかを見る。入れた3世帯には 0129 の見張りの決まり（`subjectOf`・`watch`）も当てる。
- 画面で JavaScript の例外が出ていないことも見る。

### 2. 欄ごとの効き目のテスト（`app/test/walkthrough/fieldEffect.ts`・`fieldEffectWatch.ts`・`field-effect-a〜d.test.ts`）

- 入力項目の欄の定義（`buildStage` の全部の欄。FP顧問料を含む16）を、見本の棚の世帯と `data/modelHouseholds/` の全部の世帯でたどる。欄は「形」（入力項目と欄のキー。物の ID・並びの番号を `*` にした物）でまとめる。
- 欄を1つずつ動かす（額は増やす・0にする・大きく増やす、整数は前後、率は上げ下げ、年月・時点は前後にずらす〔同じ形のまま〕、選ぶ欄は別の選択肢、はい・いいえは反対）。書いて計算の要求が変わったら、結果（キャッシュフロー表〔資産と負債の行を含む〕・相続税の目安・ご本人の死亡の万一〔翌年に起きた場合〕）のどれかが変わるかを見る。どれかの世帯で変われば、その形は「効く」。
- 時間を延ばさないため、効かなかった形は4件の世帯まで、1つの欄の動かし方は3通りまで試す。記録だけの欄・この点検で見られない欄は1件の世帯だけ。
- 一覧（`fieldEffectWatch.ts`）: 記録だけの欄（`RECORD_ONLY`。エンジンの入力の形で「計算には使わない」と書いてある欄など。動かしても変わらないことを確かめる）、直す待ちの欄（`NOT_EFFECTIVE_YET`。計算に使うはずなのに今は効かない）、この点検で効き目を見られない欄（`NOT_OBSERVED`。効く条件〔金利が上がる見込みのときだけ、など〕か見え方〔就業不能・病気の想定だけ、など〕を書く）。どの一覧にも無い形が効かなければ落ちる。一覧の行が今の欄に当たらなくなっても落ちる。
- 同じ形でも世帯（書類の種類）で効き方が違う欄の直す待ちは、世帯を決めて見る（`effectIn`。`field-effect-a.test.ts` の `it.fails`）。

### 3. 直す待ちの決まり

- 今ある不具合で通らない確かめは、vitest の `it.fails`（まだ落ちることを確かめる）にする。直したまとまりは `it.fails` を `it` にする（直ったのに `it.fails` のままだと「通ってしまった」で落ちる）。効き目の直す待ちは `NOT_EFFECTIVE_YET` の行を消す（消し忘れると「直す待ちの一覧の欄は、まだ効かない」が落ちる）。
- 行は中身の言葉で書く（直す作業の番号は書かない）。

### 4. 流し方と CI

- 流すのは `FINANCIA_WALKTHROUGH=1` のときだけ（ふだんの `npm test` では飛ばす。アプリの単体テストの時間を延ばさない）。手元では `npm run check:walkthrough`（ブラウザは `HEADLESS_BROWSER`、無ければ `CHROME_BIN`、Mac なら Chrome。見つからなければ飛ばす）。`WALKTHROUGH_SHOTS=<フォルダ>` で各世帯の結果のタブなどの写真を残す。`FIELD_EFFECT_DUMP=<フォルダ>` で効き目のたどった結果を書き出す。
- CI はジョブ `walkthrough` を足す。流す条件は `app` のジョブと同じ（`needs.changes.outputs.app`。変更に関わるジョブだけ流す仕組み〔`.github/scripts/ci-changes.sh`〕は変えない）。`engine` のジョブのまとめた JS を受け取り、`app` のジョブと並べて流す（`app` のジョブは単体テストだけで約8分かかるので、同じジョブの1段にすると全体が延びる）。落ちたら写真を成果物に残す。
- 効き目のテストは計算の回数が多い（手元で数百〜千数百回）ので、入力項目で4つのファイルに分け、vitest のワーカーで並べて流す。

### 5. 決めたこと

- 見本の世帯は「キー入力で全部入れ直す」でなく「全部のパネルを開いて閉じ、結果まで出す」にした。全部をキー入力で入れ直すと CI の時間が延びすぎる（1世帯で数分）ため。入れた値が届くかは3世帯で見る。
- 選ぶ欄（select）は、本物のキー操作で選ぶと OS ごとに動きが違うので、値を選んで変更の出来事を送る（人が一覧から選んだときと同じ出来事）。
- 子の生年月は、入れると生年月の順に並び直るので、下の子から入れる（上の子から入れると、1人目に入れた後に並びが変わり、次の欄が同じ子になる）。並び直りそのものは画面の決まりのまま。
- 「計算しています」の札が出ている間は、次の操作を待つ（5秒まで）。出たままの所は記録に残す。
- 効き目の「結果」は、キャッシュフロー表・相続税の目安・ご本人の死亡の万一の3つにした。就業不能・病気・収入が減る・相場が下がるの想定と、見せ方の切り替え（確実な分だけ）、収益不動産のタブの分析の数字は見ない（そこだけに効く欄は `NOT_OBSERVED` に理由つきで書く）。

## 理由

- 不具合は画面の部品の上の操作（打ちかけの空・欄を離れたときの決まり方・並び直り・推定の入れ直し）で起きていたので、関数の再現（0129）だけでは見落とす。画面のキー入力で通す点検を1本持ち、決まりは 0129 の物を当てる。
- 欄の効き目は、欄の定義（`buildStage`）とエンジンをそのまま使って全部の欄を機械的に動かすのがいちばん漏れが少ない。記録だけの欄は、エンジンの入力の形の説明（「計算には使わない」）を正にして一覧に書く。

## 影響

- 画面・計算・世帯ファイルは変わらない。CI に `walkthrough` のジョブが1つ増える（`app` の変更のときだけ。`app` のジョブと並べて流すので、全体の時間はほぼ延びない）。
- 不具合を直すまとまりは、直した物の `it.fails` を `it` にし、効き目の直す待ちの行を消す。欄を足したまとまりは、その欄が効くか、記録だけなら `RECORD_ONLY` に書く。

## 未確定

- 見本の世帯を全部キー入力で入れ直す点検を、夜の定時の実行に回すか。
- 就業不能・病気の想定、確実な分だけの見方、収益不動産のタブの分析の数字も効き目の「結果」に足すか（足すと `NOT_OBSERVED` の行が減るが、計算の回数が増える）。
- 2つの欄を組で動かさないと効かない欄（これから加わると加わる時期、引き下げの期間と幅、減価償却の引き継ぎの年と数字）を、組で動かす確かめにするか。

## 追記

### 2026-11-07: ブラウザの起動と画面の描き終わりの待ち方

- 背景: 通しの入力のテスト（1回目に「押す物が見つかりません」「空から作る」が見つからない）と、持ち帰り用のレポートの確かめ（`app/scripts/check-takeaway.ts`。「ブラウザの DevTools の口が開きませんでした」で20秒の待ちが切れる）が、手元でも CI でもたまに1回目に落ち、流し直すと通っていた。どちらも決まった時間で待っていた所（ブラウザの起動の20秒・30秒、押す物は1回だけ探す、画面は最初の部品が出たら次へ）。
- **決定**: 決まった時間を延ばすのでなく、物が出たことを待つ形にした。
  - ブラウザの起動（`app/scripts/headless.ts`。2つの確かめで共通）: 口が開いた印（標準エラーの「DevTools listening on」か、作業用のフォルダの `DevToolsActivePort`）を待ち、その口が答える（`/json/version`）ことまで確かめてから返す。ブラウザが途中で終わったら待たずに失敗にする。起動に失敗したら（1回の上限 60秒・すぐ終わる）、新しい作業用のフォルダで1回だけ起こし直す。WebSocket は開いたことを待つ（開けなければ失敗）。
  - 開発用のサーバー（`test/walkthrough/browser.ts`）: 画面を開く前に入口（`/src/main.tsx`）を読ませ、静的な読み込みが落ち着くまで待つ（`warmupRequest`・`waitForRequestsIdle`。初めの依存のまとめを先に済ませる）。
  - 画面: 上の帯の世帯の名前のボタン（か初めての起動の問い）が出たことを待つ。出ない・読み込みが壊れた印（依存のまとめ直しで古い部品を読んだ・部品を読めなかった例外）があれば、1回だけ読み直す。
  - 押す物・欄・選ぶ欄: 見つからなければ 0.2 秒ずつ、8 秒まで探し直す（出たらすぐ押す。本当に無いときは今までと同じ理由の文で落ちる）。
  - 持ち帰り用のレポートの確かめの、ページの中の物を待つ上限を 20 秒から 60 秒にした（物が出たらすぐ次へ進むので、通るときの時間は変わらない）。
- 確かめ: 手元（Mac・Chrome）で、Vite の依存のまとめの控えを消した冷えた状態から `npm run check:walkthrough` を5回続けて流し、5回とも通った（結果は PR に書いた）。起動の待ち方は `app/test/headless-launch.test.ts`（口の真似をする小さなプログラムで、標準エラー・`DevToolsActivePort`・1回目に終わったときの起こし直し・2回とも失敗したときにすぐ理由つきで落ちること）。
