# 0175. 入力の残りの直し（割合の欄の範囲・住宅の購入の「どう買うか」・終わりの無い働き方の退職金・休業を挟んだ働き方の年収）

- 状態: 採用（2026-11-08）
- 固定の強さ: 内部（入力の画面の欄と操作の決まりだけ。世帯ファイルの形式の版・計算エンジンの部品は変えない）
- 前提にする記録: 0008（購入とつながる住宅ローン）、0049（働く最後の年齢・定年の推定）、0098（率の欄の範囲）、0161（購入にローンが無いときの知らせ）、0162（割合の欄の範囲）、0163（受け取る時期が決まらない退職金）

## 背景

バグの調査で残っていた4つを、利用者の判断（2026-11-08）にもとづいて直す。

1. 0162 の未確定: 範囲の無い割合の欄（ご本人の持分・連帯債務の負担割合・団体信用生命保険の保障割合・一時金で受け取る割合・お金の分け方の割合・車の頭金の割合）に、150% や −10% を入れられた。
2. 0161 の 6（購入にローンが無いとき）: 知らせは出るが、住宅を現金で買う選び方が画面に無かった（頭金を物件の価格と同じにすれば現金の形になる、と知らせの文で案内するだけ）。利用者の判断: 頭金は住宅ローンありきの話なので、その前にどう買うかを選び、住宅ローンを選んだら頭金と住宅ローンの欄が出るようにする。
3. 0163 の判断が要る点: 働き方の期間に終わりが無い人の退職金は、受け取る時期が決まらず未入力の印になる。見本の世帯 dualNoKids で退職金の「目安で入れる」を押しても、カードは未入力のままだった。
4. 介護休業・育児休業を期間で挟んだ働き方で、標準の「年収（税込み・賞与込み）」を直しても、休業の後の同じ勤め先の期間の年収は変わらなかった（見本 parentCare で、460万→470万にしても休業の後の5年は 420万のまま）。

## 決定

### 1. 割合の欄は 0〜100%

- 次の欄に 0〜100% の範囲を付けた（0098・0162 と同じ形。欄の定義の `min: 0`・`max: 100`）:
  - 住宅の名義と持分の「ご本人の持分」
  - 住宅ローンの「ご本人の負担割合（連帯債務）」
  - 団体信用生命保険の「保障割合」
  - 退職金・企業年金の「一時金で受け取る割合」と、iDeCo・企業型DC・小規模企業共済の「一時金で受け取る割合」
  - 口座の資産の配分の「割合」
  - 車のローンの「頭金（下取りを引いた額に対する割合）」
- 範囲の外は、打った時点で理由（「100%より大きい値は設定できません。」）を出して書かない。すでに入っている範囲の外の値は、値を変えずに計算し、欄の下と確かめの一覧に知らせて「○%にする」で直せる（0098 の決まりのまま）。
- 決めたこと: 「お金の分け方の割合」は、口座の資産の配分（資産の種類ごとにお金をどう分けるか）の割合と読んだ。黒字の使い道の割合は、前から 0〜100% が付いている。

### 2. 住宅の購入の「どう買うか」

- 住宅の購入（購入の予定の持ち家）の欄に、物件の価格の次に「どう買うか」を置く。選択肢は「現金で買う（住宅ローンなし）」と「住宅ローンを使う」。
- **世帯ファイルには持たず、今の形から読む**（形式の版を変えない。エンジンは今の「購入の予定＋つながる住宅ローン」の形のまま計算できる）:
  - つながる住宅ローン（`purchaseLoans`。控除の条件の住まいがその家か、借入の年月が購入の月。注文住宅は土地の決済の月も）があれば「住宅ローンを使う」。
  - つながるローンが無く、頭金が物件の価格（注文住宅は土地と建物の合計）以上なら「現金で買う」。エンジンは購入の月に頭金（＝物件の価格）と諸費用を払うので、手元のお金から払う計算になる。
  - どちらでもなければ、まだ選んでいない。欄は空で未入力の印（「物件の価格−頭金（○万円）の払い方が入っていません。借入にも預金からの払いにも入らず、計算に入っていません。『どう買うか』で…選んでください」）。確かめの一覧にもこの欄の行で出す。黙って現金とはみなさない。
- 現金で買うを選ぶと: この家につながる住宅ローンを外し（ペアローンの相手の欄・控除の仮の出来事・ローンの入れ方も片付ける）、頭金を物件の価格と同じ額にする（頭金の推定の行は外す）。頭金の欄（注文住宅は土地の決済で払う頭金の欄も）とローンの欄は出さない。現金で買う形のまま、どの欄・ボタンから合計が変わっても（物件の価格・注文住宅の建物の代金・購入の種類の選び直しなど）、頭金が合計についていく（現金で買うなら合計の全額を払う。合計が変わって「まだ選んでいない」に戻らない。利用者の判断 2026-11-08）。住宅の購入の欄とボタンの書き込みをすべて包み、書く前が現金で買う形で、書いた後にローンがつながらず頭金が合計と違えば、頭金を合計にする（`keepCash`）。
- 住宅ローンを使うを選ぶと: 頭金が物件の価格と同じ（現金の形）なら頭金を目安（物件の価格×頭金の割合＋住宅資金の援助）に戻し、物件の価格−頭金を借りる住宅ローンを、この購入とつないで足す（「＋ 住宅ローン」と同じ初めの値。最後に足した購入でなくても、その購入とつなぐ）。
- この家につながる住宅ローンの欄は、住まいの区画の「住宅の購入」の中（住宅資金の援助の後、持ち家の評価の前）に「この家の住宅ローン（ご本人）」として続けて出し、「住宅ローン」の区画には出さない（区画には「住宅購入の予定の住宅ローンは、住まいの『住宅の購入』の中に出しています」と添える）。欄のキーは前と同じ。
- 0161 の物件の価格の欄の知らせと「＋ 住宅ローンを足す（物件の価格−頭金を借りる）」のボタンは、この欄の未入力の印に替えた。見張りの決まり `purchaseUnfunded` はそのまま通る（知らせの文に「払い方が入っていません」を残した）。

### 3. 終わりの無い働き方の退職金は、働く最後の年齢の推定で期間の終わりを補う

- 退職金の目安を入れるとき（入力項目の「目安で入れる」と「＋ 退職金・企業年金を足す」の最初の目安。`fillRetirement`）、勤め先（今の働き方の期間）に終わりが無ければ、働き方を入れたときと同じ推定（`estimateWorkEnd`。正社員・公務員は定年と定年後の予定、ほかは働く最後の年齢の目安。0049）で期間の終わりを置き、推定の印を付ける。
- 受け取る時期は勤め先を辞めた翌月に決まり、退職金は計算に入る。dualNoKids で「目安で入れる」の後の退職金のカードは「推定で計算中」（前は「未入力」）。
- FP が終わりを入れた期間・終わりのある期間は変えない。補った終わりを外して終わりの無い期間に戻すと、前のとおり受け取る時期の欄が未入力の印になる（0163）。

### 4. 休業を挟んだ同じ勤め先の期間の年収（H3-006 の案 (a)）

- 標準の今の働き方の「年収（税込み・賞与込み）」を直したら（打つ・空にする・値の状態の操作）、休業を挟んで続く同じ勤め先の期間（今の期間の終わりの翌月から休業の期間が続き、その翌月から始まる同じ種類の期間。休業と戻りが何度続いても順にたどる）の年収と賞与も、今の期間と同じ値にする。
- 休業の後の期間を FP が別に直していた（直す前の年収か賞与が今の期間と違う）ときは、一緒に直さない。
- 欄には「休業の後の同じ勤め先の期間（○年○月から）も、年収が今と同じなら同じ額にします」と添える。詳細の「働き方 1・2…」の年収・賞与の欄は、その期間だけを直す（前のとおり）。
- 決めたこと: 「同じ勤め先」は、休業を挟んで続く同じ種類（正社員・契約など）の期間とみる（世帯ファイルに勤め先の名前の欄が無いため）。

## 理由

- 範囲の外の割合は入れ間違いで、計算が止まるか意味の無い結果になる。ほかの割合の欄（0162）とそろえた。
- どう買うかを先に選ぶと、ローンの足し忘れ（0161 で知らせにした物）と現金で買う形を、FP が見分けて選べる。選び方を今の形から読むので、古い世帯もそのまま開け、形式の版を上げずに済む。前からローンの付いた世帯は住宅ローンを使う、頭金＝物件の価格の世帯は現金で買う（前から現金で払う計算だった）と読み、どちらでもない世帯だけを未入力にする。
- 期間の終わりが無いと退職金が計算に入らないのは、実際の入力でよくある形（終わりを決めていない）なので、目安を入れるときは働き方を入れたときと同じ推定で終わりを補うのが自然。推定の印で FP に見せる。
- 標準に出ているのは「今の働き方」の年収1つだけなので、FP は勤め先の年収を直したつもりになる。休業の後の期間を別に直していれば、FP の値を優先する（0041）。

## 代案（採らなかったもの）

- どう買うかを世帯ファイルの新しい欄に持つ: 形式の版を上げ、今の形（ローンと頭金）と二重に持つことになる。今の形から一通りに読めるので持たない。
- 現金で買う形を、ローンが無ければ黙って選ぶ: ローンの足し忘れが見えなくなる（0161 の理由のまま）。
- 退職金の受け取る時期だけを定年の推定の月にして、働き方の期間は終わりの無いままにする: 退職金を受け取った後も給与が最後まで続き、働き方と食い違う。

## 影響

- 画面: 欄の定義（`stages/housing.ts`・`housingLoans.ts`・`retirement.ts`・`savings.ts`・`cars.ts`・`work.ts`）、確かめの一覧（`checkRows.ts`）、退職金の目安（`fill.ts`）。
- 計算の結果（見本の棚・モデル世帯をそのまま開いた結果は変わらない。次の操作をした世帯だけ）:
  - 「どう買うか」で現金で買うを選んだ世帯: 物件の価格（と諸費用）を購入の月に預金から払う（前は物件の価格−頭金が計算に入っていなかった）。ローンから現金に選び直した世帯は、その住宅ローンが無くなる。
  - 住宅ローンを使うを選んだ世帯: 前の「＋ 住宅ローンを足す」と同じ。
  - 終わりの無い働き方で退職金の「目安で入れる」を押した世帯: 働き方の期間に定年などの推定の終わりが入り、定年後の予定・辞めた後の給付の推定も入る（働き方を入れたときと同じ）。dualNoKids では、退職一時金 約1,806万円×2人が辞めた翌月に入るようになる（前は0円）。給与は推定の定年で終わり、定年後の予定の期間が足される。
  - 休業を挟んだ働き方で標準の年収を直した世帯: 休業の後の期間も同じ額になる（parentCare で 460万→470万にすると、休業の後の5年も +10万円／年。前は休業の前の5か月分だけ）。
- テスト: `app/test/input-leftovers.test.ts`（直す前に落ちることを確かめた見張り）、`app/test/walkthrough`（世帯5: まだ選んでいない → 現金で買う → 住宅ローンを使う）。`housing-follow-fixes.test.ts`・`housing-review.test.ts`・`items.test.ts` の期待を直した。

## 未確定

- なし（下の2つは 2026-11-08 に決めた）。
  - 現金で買う形で、注文住宅の土地・建物の代金の欄から合計が変わったときも頭金がついていく（利用者の判断。決定の2）。
  - プランの中で「どう買うか」を選び直したときの差分の形: 新しい差分の種類は作らない。入力の画面で選んだときと同じ操作（つながる住宅ローンを外す・足す、頭金を直す）を、プランの差分の決まり（0036・0043）のまま、物の足し外しと欄の差分として記録する。プランの中では「どう買うか」は差分を当てた後の世帯から読むので、プランごとに現金・ローンが分かれ、現状は変わらない（`input-leftovers.test.ts` で確かめた）。
