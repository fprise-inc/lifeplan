# 0126. 収益不動産の家賃の入れ方（今の実際の家賃収入）と、減価償却を確定申告の数字から引き継ぐことと、世帯ファイルの形式 0.65

- 状態: 採用（一部未確定）（2026-11-06）
- 固定の強さ: 骨格は、世帯ファイルの欄 `accounts[].property.rental.rentBy`（`fullOccupancy` 満室時の家賃と空室率・`actual` 今の実際の家賃収入。省略は `fullOccupancy`）と `accounts[].property.depreciationCarryover`（`year`・`building`／`equipment` の `book`・`annual`）の名前と意味、`asset.realEstate` の約束の版 1.4 の任意の出力（`cash[].current`・`facts.rentBy`）、`asset.realEstateAnalysis` の約束の版 1.2 の任意の出力（`rentBy`・`years[].currentYield`）、形式 0.65 の変換の段。画面の欄の並び・言葉・知らせの文、引き継いだ年より前の年の償却費の近似、分析の数字の見せ方（「—」と理由の文）は後から変えてよい（変えたら追記に書く）
- 前提にする記録: 0002（金額・率・丸め）、0006（約束の版と改訂）、0011（形式の版と変換の段）、0028（住まい以外の不動産）、0079（入力項目「収益不動産」）、0080（お金の欄）、0081（税と出口）、0082（分析の数字と提案書）

## 背景

- 収益不動産（0079〜0082）を、不動産に詳しい FP の声で見直した。足りないと言われたのは次の2つ。
  1. **家賃の入れ方**: 今は「満室時の家賃（合計）」と「空室率」だけで入れる。FP は確定申告（不動産所得の収支内訳書・青色申告決算書）やレントロールから、今の実際の家賃収入を知っていることが多い。それを満室時の家賃の欄に入れると、空室率で二重に引く心配がある。
  2. **減価償却**: 今は取得価額・取得の年・建物の構造（中古は簡便法）から計算し直す。確定申告の減価償却の明細と合わないことがある（資本的支出を足している・取得価額の土地と建物の分け方が違う・相続で受け継いだ物件で被相続人の未償却残高を引き継いでいる、など）。FP は申告書の数字を持っている。
- 利用者（ソフトの提供元）は「おすすめどおりに」と了承した。

## 決定

### 1. 家賃の入れ方（`rental.rentBy`。標準の段）

- 「家賃の入れ方」を選べるようにした: 「満室時の家賃と空室率で」（`fullOccupancy`。今までどおり・既定）／「今の実際の家賃収入で」（`actual`）。種類ごとの言葉にする:
  - 駐車場: 「満車時の駐車料と空き区画の割合で」／「今の実際の駐車料の収入で」。家賃の欄は「今の駐車料の収入（合計・月額）」
  - 貸している土地: 「地代と貸していない割合で」／「今の実際の地代収入で」。家賃の欄は「今の地代収入（月額）」
  - ほかの種類: 家賃の欄は「今の家賃収入（合計・月額）」
  - 民泊・宿は今の「売上の入れ方」（`lodging.salesBy`）があるので、この欄を出さない（入っていても計算は読まない）。
- **今の実際の家賃収入で入れたとき**:
  - `rental.monthly` は空室を見込んだ後の今の家賃収入（月額。画面で年額に切り替えて入れられる）とみなし、空室率を掛けない。
  - 家賃以外の月の収入（共益費・駐車場・その他）も、空室を見込んだ後の今の額とみなし、空室率を掛けない（同じ選択に従う）。礼金・更新料は、今までどおり空室率を掛けない。
  - 家賃の変化率・段階・例外の年・家賃に対する割合の経費（管理委託料など）は今までどおり当てる。
  - 空室率の欄は出さない。値が残っていれば、計算に使っていないことを知らせる1行（「空室率が残っています（計算には使っていません）」）を出し、確かめの一覧に「外す」を添える（住宅ローンの全期間固定に残った5年ルール・125%ルールの知らせ〔0052 の追記〕と同じ作り）。満室時の家賃で入れる形に戻すと、また使う。
- 物件の一覧表の月の収入（0079 の9）・計算式の説明の文も、今の実際の家賃収入ならその額のままにした。

### 2. 分析の数字（満室の額が無いとき）

- 今の実際の家賃収入で入れた物件は、満室のときの収入が分からないので:
  - **表面利回り**（満室のときの収入÷取得価額）は出さない（`grossYield` は null）。代わりに**今の収入での表面利回り**（`currentYield`＝受け取った家賃と家賃以外の月の収入〔礼金・更新料を除く〕の年換算÷取得価額）を出し、画面と提案書では「表面利回り（今の収入で）」の名前で見せる（物件ごとの一覧の表では「4.1%（今の収入）」のように添える）。
  - **損益分岐の入居率**（（経費＋約定の返済）÷満室のときの収入）は出さない（null）。画面は「—（満室時の家賃を入れていません）」、提案書は「—」と「満室時の収入を入れていないので、損益分岐の入居率は出していません」の1行。
  - 実質利回り・返済比率・返済余裕率・借入の割合・自己資金に対する手残りの割合・手残りは、今までどおり実際に入る収入から出す（式は同じ）。
- 合計（全物件）の表面利回り・損益分岐は、今までどおり満室のときの収入のある物件だけで出す（今の実際の家賃収入の物件を混ぜない）。
- エンジン: `asset.realEstate`（改訂8・約束の版 1.4）の分析の材料 `cash[].gross` を null にし、`cash[].current`（受け取った家賃と家賃以外の月の収入。礼金・更新料を除く）と `facts.rentBy`（`actual`）を出す。`asset.realEstateAnalysis`（改訂3・約束の版 1.2）が `rentBy` と `years[].currentYield` を出す。
- 物件の見出しの1行（画面と提案書）に「家賃収入は今の実際の額で入力」（駐車場・土地は種類の言葉）を書く。

### 3. 減価償却の引き継ぎ（`depreciationCarryover`。詳細の段）

- 物件の中に「減価償却を確定申告の数字から引き継ぐ」のまとまりを足した（貸している物件だけ。詳細の段）。欄は、引き継ぐ年（その年の年末の数字。既定は計算の基準の年の前の年）・建物の未償却残高（年末）・建物の年間の償却費・建物附属設備（駐車場・土地は「設備」）の未償却残高（年末）・年間の償却費。設備は任意。
- **入れたら**（未償却残高と年間の償却費の両方がそろった部分があれば）、取得価額・建物の構造・建った年（中古の簡便法）からの計算の代わりに、引き継いだ年の翌年から、入れた年額で、未償却残高が1円（備忘価額）になるまで償却する。
  - 貸している月数で月割り（12か月に満たない年は年額×月数÷12。円未満切り捨て）。最後の年は残高−1円まで。
  - **入れていない部分は償却しない**（建物だけを入れたら、取得価額の内訳の建物附属設備も償却しない）。申告の明細は物件の償却資産の全部の一覧で、計算した設備と申告の建物を混ぜると、申告で建物にまとめた設備を二重に償却するおそれがあるため。取得価額の内訳に設備があるのに引き継ぎに設備が無ければ、設備の欄で知らせる（申告で建物にまとめているなら、そのままでよい）。
  - 片方（未償却残高か年間の償却費）だけのときは、その部分を計算に使わず、欄で「両方そろうまで、この部分は計算に使いません」と知らせる。どの部分もそろっていなければ、取得価額からの計算のまま。
  - **引き継いだ年とその前の年**（計算基準年の2年前からの計算の窓の中。前の年の所得で決まる住民税・国民健康保険料のため）の償却費は、入れた年額（貸している月数で月割り）とする。引き継いだ年の分は申告の数字そのもので、その前の年は近似（未確定）。
  - **取得価額が無くても償却する**（相続で受け継いだ物件など、取得価額が手元に無くても申告の数字はある）。そのとき、取得の入力を求める知らせ（`N_INPUT_REQUIRED` の `account.property.acquisition`）は出さない。
- **帳簿価額・売ったときの取得費・含み益**（矛盾しないように）:
  - 取得価額があれば、帳簿価額（`years[].book`）＝土地の分（取得価額〔内訳があれば内訳の合計〕＋取得時の諸費用−取得価額から出した建物と建物附属設備の償却の基）＋その年の年末の未償却残高。含み益＝評価額−帳簿価額（0082）。
  - 譲渡所得の取得費（0081）＝土地の分＋売るときの未償却残高（引き継いだ残高から、その後の売る前の月までの償却を引いた額）。概算取得費（売却価格の5%）のほうが大きければそれ（今までどおり）。資本的支出を足した残高なら、取得費は取得価額＋諸費用より大きくなりうる（そのままにする）。
  - 取得価額が無ければ、帳簿価額・含み益は出さず（土地の分が分からない）、売ったときは今までどおり概算取得費で、所有期間は長期とみなす（知らせも今までどおり）。
  - 土地の分は取得価額を土地の割合・取得価額の内訳で分けて出すので、申告の建物の取得価額と分け方が違うときは、申告の内訳を「取得価額の内訳」に入れると土地の分も申告とそろう（「?」に書いた）。
- **減価償却が終わる年**（`facts.depreciationEnd`）・**貸し続けたら終わる年**・**元金の返済が減価償却費を上回る年**（デッドクロス）も、引き継いだ残高と年額から出す（償却費の行が変わるので、0082 の式のまま追いかける）。引き継いだ残高が1円以下なら、償却は終わっていて、終わった年は引き継いだ年とする。
- 引き継ぐ年は、計算の基準の年が後で動いても変わらないように、額を入れたときに値として書く（額を全部空にしたら引き継ぎごと外す。既定でない年だけが入っていれば残す）。
- 物件の見出しの1行（画面と提案書）に「減価償却は2025年の確定申告から引き継ぎ」を書く。

### 4. 税の扱いの根拠（国税庁の資料）

- 平成19年4月1日以後に取得した減価償却資産は、償却可能限度額と残存価額が廃止され、耐用年数を経過した時点で帳簿価額1円（備忘価額）まで償却する。定額法の償却費は毎年同額で、最後の年は「期首帳簿価額−1円」とのいずれか少ない額（国税庁 タックスアンサー No.2106「定額法と定率法による減価償却（平成19年4月1日以後に取得する場合）」）。→ 引き継いだ年額で残高が1円になるまで、とした。
- 資本的支出は、原則として、その資本的支出の金額を取得価額として、本体と種類・耐用年数を同じくする資産を新たに取得したものとみなして償却する（No.2107「資本的支出を行った場合の減価償却」）。→ 申告の未償却残高・償却費に資本的支出の分が含まれるので、計算し直すより申告の数字を引き継ぐほうが合う。
- 相続により取得した賃貸用の建物は、中古資産の見積もりによる耐用年数（簡便法）を使えず、被相続人の取得価額・耐用年数・経過年数・未償却残高を引き継いで計算する（国税庁 質疑応答事例「相続により取得した減価償却資産の耐用年数」・「平成19年4月1日以降に相続により減価償却資産を取得した場合」。所得税法60条1項）。→ 今の計算（取得の年より建った年が前なら簡便法）では合わないので、引き継ぎの欄で申告の数字を使えるようにした。
- 建物の取得費は、購入代金などから所有期間中の減価償却費相当額を差し引いて計算する（No.3252「取得費となるもの」）。→ 売ったときの取得費は、土地の分＋その時点の未償却残高とした。
- 平成19年3月31日以前に取得した資産（旧定額法）は、取得価額の95%まで償却した後、翌年から5年間で1円まで均等に償却する（No.2106 の関連の取扱い・上の質疑応答事例の例。所得税法施行令134条2項）。→ 引き継いだ年額で1円まで続けるのは、95%に達する前の物件では最後の5年の均等償却の時期がずれる近似（未確定）。

### 5. 世帯ファイルの形式 0.65

- 足すだけの MINOR。`accounts[].property.rental.rentBy` と `accounts[].property.depreciationCarryover` を足した。前の版のアプリは入力の検査で知らない欄を通さないので、版を上げて閲覧だけにする。本体の変換の段（0.64 → 0.65）は形式の版だけを書き換える（家賃の入れ方の省略は満室時の家賃と空室率で、前の版と同じ計算）。見本 `crates/household-store/tests/fixtures/household-format/0.65/`（0.64 の見本の収益不動産に、今の実際の家賃収入と、建物と設備の引き継ぎを足した。空室率は前の値のまま残る）。
- 欄はどちらも入力項目 `account.property` の中なので、入力項目ID（0004）・縮約版の許可リスト（0015）は変えない。
- 引き継ぎの欄は、額を書くと引き継ぐ年も書く（2か所）ので、対策で動かす項目にしない（欄の定義で `structural`。申告の事実で、プランで動かすものではない）。家賃の入れ方は選択の欄で、物の形が変わる（空室率の欄の出し方）ので同じく `structural`。

## 理由

- **家賃の入れ方を選ぶ形にした**（満室時の家賃の欄の意味を黙って変えない）: 今までの世帯（満室時の家賃と空室率）の計算を変えず、申告の数字で入れたい FP は1つ選ぶだけで二重に引かない。空室率の欄を消さずに残りを知らせるのは、入れ方を戻したときに前の値が残るほうが自然で、消すのは FP の判断（「外す」）にした。
- **満室の額が無い物件の表面利回りを「今の収入で」にした**（「—」だけにしない）: 不動産の実務では、満室想定の利回り（想定利回り）と今の家賃での利回り（現況利回り）の両方を見る。今の家賃収入を入れた物件で表面利回りを空にすると、物件を見比べる数字が1つ減る。名前に「今の収入で」を添え、合計には混ぜないので、満室の数字と取り違えない。損益分岐の入居率は、今の入居率が分からないと入居率に直せない（今の収入に対する割合は入居率ではない）ので出さず、理由を添えた。
- **減価償却は申告の数字をそのまま先へ延ばす形にした**（申告の数字から取得価額や耐用年数を逆算しない）: 未償却残高と年間の償却費は申告書にそのまま書いてあり、写すだけで翌年からの償却が申告と一致する。資本的支出・按分・相続の違いを、ソフトが推し量らなくてよい。
- **入れていない部分は償却しない**: 申告の明細と計算を混ぜると、どちらかに無い資産・二重の資産が出る。申告を正とするなら、申告の一覧に無い物は無いとみなすほうが筋が通る（知らせで気付けるようにした）。
- **取得価額が無くても償却する**: 相続で受け継いだ物件などは、申告の数字はあっても取得価額が手元に無いことがある。帳簿価額・取得費の土地の分だけは分からないので、そこは今までどおり出さない・概算取得費にした。

## 代案（採らなかったもの）

- 満室時の家賃の欄に「今の実際の家賃収入」も入れられるよう説明だけを直す: 空室率を0にし忘れると二重に引く心配が残る。
- 今の実際の家賃収入と空室率から満室時の家賃を逆算する（実際÷(1−空室率)）: 今の空室率が分からないから実際の額で入れるので、逆算の前提が無い。
- 今の実際の家賃収入の物件の表面利回り・損益分岐を、実際の額で満室の数字と同じ欄に出す: 合計の表面利回りに満室の数字と今の数字が混ざり、損益分岐の「入居率」の意味が変わる。
- 引き継ぎを資産ごとの行（資本的支出ごと）にする: 申告の明細の行をすべて写すのは手間が大きい。建物と設備の2つにまとめ、合わせたときのずれは未確定に残した。
- 申告の数字から耐用年数・償却率を逆算し、取得価額からの計算に戻す: 資本的支出・相続の扱いで逆算の前提が崩れる。
