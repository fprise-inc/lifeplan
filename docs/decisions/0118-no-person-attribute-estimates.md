# 0118. 人の属性（学歴・性別）で推定の数字を分けない（給与・賞与・パートの時給・昇給カーブ・再雇用・退職一時金の目安）と世帯ファイルの形式 0.58

- 状態: 採用（一部未確定）（2026-11-03）
- 固定の強さ: 骨格（下の決定の1の決まり「人の属性で推定の数字を分けない。法律で扱いが違うもの・平均余命は除く」。新しい推定・目安・マスタデータの値を足すときもこの決まりに従う）。世帯ファイルの形式 0.58 の変換の段（統計の年齢カーブの値ID を男女計・学歴計に直す・退職給付の学歴を外す）は変えない。学歴を分けない値の作り方（単純な平均・記入企業数で重み付けした平均）と仮の値の額は内部（変えるときは値の `rev` を足し、`docs/estimates-review.md` の行を直す）。知らせの文は後から変えてよい
- 前提にする記録: 0007（マスタデータの形）、0008（値の箱と推定）、0011（形式の版と変換の段）、0041（確かめの一覧）、0047（働き方と収入・再雇用の年収の推定）、0057（退職金・企業年金のカード）、0078（性別の欄）、0111（事務所の推定の値）、0116（統計の年齢カーブ）

## 背景

- 利用者の判断（2026-11-03）: 「学歴で分ける選択肢は全部外す」「性別で分ける推定は男女計だけにする」。理由は、FP が顧客の前で画面を見せたとき、学歴・性別によって数字が高い・低いと出てしまうと、顧客の気分を害したり差別と受け取られたりするおそれがあるため。
- それまでの推定は、次の所で人の属性で数字を分けていた。
  - 給与・賞与の推定（正社員・契約）: 賃金構造基本統計調査の男・女の表を、その人の性別で選んでいた（性別が空なら男の表）。パートの時給・統計の無い働き方の仮の値（`preset.wage.provisional.<働き方>.<性別>.*`）も男女別。
  - 定年後の再雇用の年収の推定: 同じ働き方・性別の60〜64歳÷55〜59歳。
  - 統計の年齢カーブ（0116）: 男女計・男性・女性の表と、正社員の学歴（中学〜大学院）を選べた。
  - 退職一時金の目安（0057）: 学歴の欄（大学・大学院卒／高校卒〔管理・事務・技術職〕／高校卒〔現業職〕）で表を選び、選んでいなければ「大学・大学院卒とみなす」と根拠の文に書いていた。ヒアリングシートの取り込みも「大学・大学院卒とみなす」。
- 一方、法律で男女の扱いが違う計算（特別支給の老齢厚生年金の開始年齢・中高齢寡婦加算・遺族年金・寡婦控除・ひとり親・健康保険の出産の給付など）は、性別が無いと正しく計算できない。平均余命（簡易生命表の男女別。親の葬儀の時期・必要保障額の期間）は、統計の推定だが寿命の差は計算の前提そのもので、男女計にすると女性の遺族の必要保障額を短く見積もる。

## 決定

### 1. 決まり: 人の属性で推定の数字を分けない

- 推定・目安（推定の値の箱・目安のボタン・計算のときにエンジンが引く統計の目安・定年後の予定の推定・事務所の推定の値の一覧）の数字を、**人の属性（性別・学歴）で分けない**。統計を使うときは男女計・学歴計の表（無ければ下の2の作り方で学歴を分けない値）を使う。
- 分けてよいのは、人の属性でない物: 働き方の種類（正社員・正社員以外・公務員・パート・役員）、年齢、勤め先の企業規模、勤続年数、辞め方、世帯の人数、子の進路（教育費の学校の段。子の属性ではなく選んだ進路の費用）。
- **除く物（性別で分けたままにする）**: 法律で男女の扱いが違う計算（上の背景の物）と、平均余命（簡易生命表の男女別）。構成員の性別の欄そのもの（0078）は、法律の計算に要るので残す。
- 画面・提案書・根拠の文に、人の学歴の言葉（大学卒・高校卒など）や「男性の表」「女性の表」を出さない。根拠の文に「男女計」「学歴を分けない値」と書くのはよい（どの表を使ったかを正直に書く）。
- 今後、新しい推定・目安・マスタデータの値を足すときもこの決まりに従う（人の属性で分けた統計しか無いときは、2の作り方で分けない値を作り、作り方を値の `approval.note` に書く）。

### 3. 推定の関数と画面

- `hearing/src/estimates.ts`: `salaryEstimate(type, options)`・`bonusShareEstimate(type, total, options)` は性別を受け取らない（引数から外した。呼ぶ側で性別を渡せない形にして、誤って分けないようにする）。年齢階級の表・年齢計・パートの時給は男女計。`reemploymentRatio(type)`（再雇用の比。男女計の60〜64歳÷55〜59歳）を足した。`retirementLumpSumEstimate` は学歴を受け取らず、学歴を分けない値だけを引く。統計の年齢カーブの選び方 `WageCurveChoice` は雇用形態と企業規模だけ。`neutralWageCurveId`（前の値ID → 男女計・学歴計の値ID）を足した。
- 働き方と収入（`app/src/workspace/input/stages/work.ts`）: 給与・賞与の推定・定年後の再雇用の年収の推定（「同じ働き方の60〜64歳の平均÷55〜59歳の平均。賃金の統計の年齢階級の表〔男女計〕」）から性別を外した。詳細の「統計の年齢カーブで増やす」は「使わない／統計の年齢カーブで増やす」の2つにし、「年齢カーブの学歴」の欄と「この人の性別と違う表です」の知らせをなくした。企業規模の欄は残す（勤め先の属性）。
- 退職金・企業年金（`app/src/workspace/input/stages/retirement.ts`・`retirementBenefits.ts`）: 退職一時金の詳細の「学歴」の欄をなくし、目安の根拠の文の「（定年・大学・大学院卒とみなす）」を「（定年）」にした。種類を変えたときに学歴を引き継がない。ヒアリングシートの取り込み（`hearing/src/import.ts`）の退職一時金の代わりの値も同じ。ヒアリングシートに人の学歴を聞く問いは無かった（性別の問いは法律の計算に要るので残す）。
- 事務所の推定の値の一覧（`app/src/workspace/office/estimateCatalog.ts`）: 名前から性別・学歴を外した（一覧はマスタデータの値を全部載せる決まりなので、外した値は一覧から消える）。平均余命の名前の男女はそのまま。
- 計算エンジン: `income.salary` の改訂を 8 にし、読める統計の年齢カーブを男女計・学歴計の8値にした（計算の仕方は同じ）。前の値ID は読めない（`E_PARAM_UNDECLARED`）。入力のスキーマの `retirementBenefit.education` は消さずに「使わない」とし、登録簿で `deprecated` にした（控えの中など、前に保存した値を読めるように。画面は書かない）。

### 4. 前の世帯ファイル（形式 0.58）

- 形式の版を `0.58` に上げた（MINOR）。変換の段（`crates/household-store/src/migrate.rs` の 0.57 → 0.58）:
  - 現状（`household`）とプランの差分（`proposals`）の中の、性別・学歴で分けた統計の年齢カーブの値ID を、同じ雇用形態・企業規模の男女計・学歴計の値ID に直す。
  - 現状の退職給付の学歴 `education` と、その値の状態の行を外す。プランの差分の、足す退職給付の中の学歴も外し、学歴を書く差分は捨てる。
  - 控え（`snapshots`）・ヒアリングの記録の中身は変えない（控えを今のエンジンで計算するときは、画面が同じ決まりで値ID を直す。`withoutRemovedAssumptions`）。
  - 推定のままの給与・賞与・退職一時金の目安の値は変換の段では変えない（統計の写しは画面にあるので）。画面が推定を入れ直すとき（入力を直したとき）に新しい目安で入る。人が入れた値・確定の値は変えない。
  - 直した物・推定のままの物があれば、開いたときの知らせ `{"kind": "neutralEstimates", "count", "plans", "estimates"}` を足す。画面は「推定を性別・学歴で分けないようにしました」と、直した数・入れ直す推定の数・「結果が前と変わることがあります。入れた額はそのままです」を出す（0035 の8・0087 の世帯の知らせ）。
- 前の版のアプリは学歴の欄を書き戻し、前の値ID で計算するので、版を上げて閲覧だけにする。

### 5. 事務所の推定の値

- 事務所の設定に、外した値ID（男女別の給与・学歴別の退職金・性別の仮の値など）の事務所の値が残っていても、推定は引かない（使わない値になる）。事務所の値は消さない。

## 理由

- **男女計の表にする（男女の平均や、性別の表の中の一方ではなく）**: 賃金構造基本統計調査は男女計の表を公表しているので、作らずに一次の数字を使える。男女の単純な平均は、男女の労働者数の違いを無視する。
- **学歴を分けない値の作り方**: 公表に学歴計が無いので作るしかない。人数の重みがあれば重み付きの平均が筋だが、就労条件総合調査は区分ごとの退職者の数を公表していないので、単純な平均にした（ほかの調査の人数で重みを付けると、退職給付の制度・企業の範囲が違う数を混ぜることになる）。東京都の表は記入企業数があり、モデル退職金は企業ごとの規定の額なので、記入企業数で重み付けすると「記入したすべての企業の答えの平均」になる。どちらも作り方を値の注記に書き、根拠の文では「学歴を分けない値」とだけ書く。
- **仮の値は前の男女別の平均**: 出典の無い仮の値で、どちらかの性別の値に寄せる理由が無い。
- **性別・学歴で分けた値をマスタデータから外す（残して読まないのではなく）**: 残すと事務所の推定の値の一覧に出て、統計の写し（画面の束）にも入り、後の作業で誤って使いやすい。登録簿には `removed` と `replacedBy` で残るので、値ID は使い回さない。統計の年齢カーブは 0116 で入れたばかりで、前の値ID を書いた世帯はほとんど無い。
- **退職給付の学歴の欄はスキーマに残す（`deprecated`）**: 控えの中の前の値を、スキーマの検査で落とさないため。画面は書かず、変換の段が現状とプランから外す。
- **推定の値を変換の段で入れ直さない**: 統計の写しは画面（`hearing/src/statistics.generated.ts`）にあり、本体の変換の段は統計を持たない。開いたときの知らせで、入れ直すことと結果が変わることを知らせる。
- **平均余命を除く**: 寿命の男女差は必要保障額の期間・親の葬儀の時期の前提そのもので、男女計にすると女性の遺族の生活費を短く見積もり、保障の不足を小さく出す（顧客に不利な方へずれる）。法律で男女の扱いが違う計算は、制度そのもの。

## 影響

- 計算の結果が変わる所（推定のままの値を入れ直した後。人が入れた値は変わらない）:
  - 正社員の給与・賞与の推定（年額の合計）: 男性は下がり、女性は上がる。30歳 男 567.7万円・女 459.4万円 → 528.2万円、45歳 男 715.9万円・女 518.1万円 → 650.0万円、57歳 男 763.8万円・女 542.8万円 → 697.5万円。
  - 契約・嘱託: 45歳 男 365.4万円・女 295.0万円 → 317.0万円（30歳 → 320.5万円、57歳 → 313.6万円）。
  - パートの推定の年収（時給×週15時間×52週）: 男 138.0万円・女 110.6万円 → 118.4万円。
  - 役員の報酬の仮の値: 男 600万円・女 480万円 → 540万円。公務員の賞与の仮の値: 男 160万円・女 140万円 → 150万円（公務員の給与はもともと男女の区別なし）。
  - 定年後の再雇用の年収の比: 正社員 男 84%・女 90% → 86%、契約・嘱託 男 116%・女 105% → 120%（60〜64歳÷55〜59歳）。
  - 退職一時金の目安（前は学歴を選んでいなければ大学・大学院卒の値）: 定年・勤続38年 2,037万円 → 1,806万円、定年・勤続22年 1,021万円 → 661万円、会社都合（勤続20年以上かつ45歳以上）1,738万円 → 1,287万円、自己都合 1,441万円 → 1,214万円、早期優遇 2,266万円 → 2,281万円。勤続20年未満・45歳未満（東京都の表）は、例えば自己都合・勤続10年 112.5万円 → 104.8万円、会社都合・勤続4年 30.4万円 → 28.5万円。前に高校卒を選んでいた世帯は上がる（例: 定年・勤続22年・高校卒〔現業職〕406万円 → 661万円）。
  - 給与が変わると、社会保険料（標準報酬月額を空欄にしている期間）・税・厚生年金・退職後の資産も変わる。
  - 統計の年齢カーブを性別・学歴の表で選んでいた期間は、同じ企業規模の男女計・学歴計の係数で伸ばす。
