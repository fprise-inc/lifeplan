# 0061. 世帯に保存する相続税の目安の設定と遺したい額（要求の入力の欄）と、世帯ファイルの形式 0.24

- 状態: 採用（一部未確定）（2026-10-27）
- 固定の強さ: β公開から変えない（骨格）。入力項目ID `plan.inheritanceTax`・`plan.legacy`、置き場所（計算の要求の入力 `input.inheritanceTax`〔時点 `points` を入れない〕・`input.legacy.amount`〔値の箱〕）、時点の無い `inheritanceTax` と `legacy` をアプリがエンジンへ渡す要求から外す決まり、形式 0.24 は骨格。文言は後から変えてよい

## 背景

- 相続税の目安（0039）は、要求に `input.inheritanceTax` を入れたときだけ計算する部品で、不動産の評価の割合・名義の無い財産の分け方・葬式の費用・養子・法定相続人の数を直す口・FP が入れた額を要求の欄として持つ。0039 の10 で、これらを世帯ファイルと入力画面に足すことにしていた。
- 遺したい額（0060）は、計算には使わない表示だけの値だが、プランごとに比べたい（プランの差分で直せる形にしたい）。
- プランの差分は計算の要求の入力に当てる（0036）。画面の側の値（`loanEntry` など）はプランの差分にならない。
- 前提にする記録: 0011（世帯ファイル・変換の段）、0015（AI接続口の縮約版）、0035（形式の版の上げ方）、0036（差分の当て先）、0039（相続税の目安）、0044 の5（エンジンへ渡す要求からアプリが外す物）。

## 決定

### 1. 置き場所

- 相続税の目安の設定は、計算の要求の入力の `inheritanceTax`（エンジンの今の欄）に、**時点 `points` を入れずに**持つ（`realEstateRatio`・`unassignedShare`・`funeral`・`adopted`・`heirCounts`・`overrides`。0039 の10 の欄のうち、いま亡くなったときの死亡退職金の額と二人とも亡くなった後の後に亡くなる人は、まだ画面に出さない）。スキーマのこの欄に入力項目ID `plan.inheritanceTax` を付けた。
- 遺したい額は、計算の要求の入力に足した欄 `legacy`（入力項目ID `plan.legacy`。`amount` は値の箱。計算には使わない。表示だけ。`debt.label` と同じく、エンジンは受けるが読まない欄）。
- どちらも物の集まりに属さない要求の入力の項目なので、プランの差分は向き先 `{plan: "input"}` で当てる（表の最後の年 `plan.endYear` と同じ）。

### 2. エンジンへ渡す要求から外す（アプリの側）

- アプリがエンジンへ要求を渡すところ（`app/src/engine/moneyRows.ts` の `forEngine`。画面側のエンジン・本体の正の計算・根拠の記録・万一の画面・提案書・持ち帰り用のレポートの計算のすべての入口）で、**時点の無い `inheritanceTax`** と `legacy` を外す（`withoutStoredSettings`）。どちらもお金の流れに効かないので結果は同じで、設定を直しても計算し直さない。
- 相続税の目安を求める要求（入力のホームの目安 `inheritanceRequest`・万一のタブの死亡の想定）は、世帯の設定に時点を足して作る（時点のある `inheritanceTax` は外さない）。

### 3. 世帯ファイルの形式 0.24

- 形式の版を `0.24` に上げた（足すだけの MINOR。0035 の1・7）。`0.23` → `0.24` の変換の段は形式の版だけを書き換える。`0.23` のアプリは知らない欄を読み落として書き戻すので、版を上げて閲覧だけにする。
- 見本 `crates/household-store/tests/fixtures/household-format/0.24/`（0.23 の見本に、相続税の目安の設定〔不動産の評価の割合・葬式の費用・法定相続人の数を直す口・FP が入れた額〕・遺したい額・遺したい額を変えるプランの差分を足した）。

### 4. AI接続口

- 縮約版の許可リストに `plan.inheritanceTax`・`plan.legacy` を入れ、版を `reduced@15` にした（どれも計算と見せ方に使う数。0015）。

## 理由

- **要求の入力の欄にした**: プランの差分・値の状態の行・読み替えの仕組みがそのまま使える。相続税の目安の設定はもともとエンジンの要求の欄なので、別の置き場所を作ると写し替えが要る。
- **時点の無い設定を外した**: 置いたまま渡すと、毎回の計算で相続税の目安も計算され（要求したときだけ計算する決まり。0039 の1）、出力と根拠の記録が大きくなる。

## 代案（採らなかったもの）

- 画面の側の値（`loanEntry` と同じ区画）に置く: プランの差分にならない。遺したい額・FP が入れた額をプランごとに比べられない。
- 遺したい額を相続税の目安の設定の中に置く: 相続税と関係の無い目標の値で、エンジンの要求の欄の意味が混ざる。

## 影響

- **エンジン**: 入力のスキーマ（`inheritanceTax` に入力項目ID、`legacy` を足した）。部品・見本の世帯の結果は変わらない。
- **画面**: `engine/moneyRows.ts`（`withoutStoredSettings`）、`engine/types.ts`、`contingency/requests.ts`、`store/body.ts`（形式の版）。
- **本体**: 形式 0.24 の段と見本、AI接続口の縮約版の許可リスト。
- **登録簿**: 入力項目ID 2つ（`registry/items.yaml`・本体の値の場所の写し）。
