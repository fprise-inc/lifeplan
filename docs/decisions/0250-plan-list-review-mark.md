# 0250. プランの一覧の「! 要確認 n」を押せる印にし、確かめることを吹き出しに1行ずつ出す（対策の「変えたこと」へ移れる）

- 状態: 採用（一部未確定）（2026-11-23）
- 固定の強さ: 内部（画面の見せ方と操作）。要確認の決め方・件数の数え方・文・世帯ファイルの形・保存される値・計算は変えない。決まりとして残すのは「プランの一覧の要確認の印は押せるボタンで、押すと（Enter・Space でも）中身を出す」「中身の文は対策の『変えたこと』と同じ（`changesOf` の `reviewNote`）を使い回し、別の文を作らない」「印をボタンにしても表の行の高さを変えない」の3つ。吹き出しの幅・文言・移り先のボタンの言葉は後から変えてよい（変えたら追記に書く）
- 前提にする記録: 0036（プランの差分と要確認。7 と 8）、0077（説明の「?」）、0239（重ねて出す画面の閉じ方・Esc は上の1つだけ）、0240（ボタンの4段）

## 背景

- 結果のタブの「プランの一覧（N件）」の表で、プランの名前の右に「! 要確認 2」の印が出る。印はただの文字で、何を確かめればよいかは、そのプランを帯で選んで対策の「変えたこと」を開くまで分からなかった（利用者の要望）。
- 件数は `PlanList.tsx` で `changesOf(…)` の行のうち `state` が `ok` でない物を数えていた。同じ行の説明の文（`reviewNote`。例「現状のプランが 月30万円→月32万円 に変わりました」）は、対策の「変えたこと」の一覧（`LeverPanel.tsx`）で既に出している。

## 決定

### 1. 印は押せるボタン（`app/src/workspace/plans/ReviewMark.tsx` の `ReviewMark`）

- 見た目は今までの印（`.pb-review.sm`）のまま。押せることは、カーソルを合わせたときと開いている間の下線で示す。
- カーソルを合わせたときは短い説明だけ（`title`「確かめること 2件。押すと一覧」）。
- 押す（Enter・Space でも）と、印のすぐ下に小さな吹き出しを出す。中身は「確かめること（n件）」と、行ごとに項目の名前と説明の文。文は `changesOf` の `reviewNote` をそのまま使う（対策の「変えたこと」と同じ文）。
- 吹き出しは画面に固定して置く（`position: fixed`。表の枠の横送り `overflow-x: auto` に切られない・表の行の高さを変えない）。置き場所は説明の「?」と同じ決め方（`helpPlace`。画面の端からはみ出さない）。見た目は説明の「?」の箱（`.help-pop`）を土台に、行を要確認の色（黄土の左の線）にした。
- ボタンにすると枠の分だけ行が 1.5px 高くなったので、印のボタンだけ行の高さを詰めた（`line-height: 1.2`）。文字の大きさ 中・大 のどちらでも、表の行の高さが前と同じになることを画面で確かめた。

### 2. 閉じ方（0239 にそろえる）

- もう一度押す・Esc・外を押す・吹き出しの右上の「閉じる」。
- Esc は `useEscClose` で重ねた順に入れる。プランの一覧の上に出している間は、1回の Esc で吹き出しだけが閉じ、一覧は残る（もう一度の Esc で一覧が閉じる）。Esc と「閉じる」で閉じたときは、フォーカスを印に戻す。
- 吹き出しは押した物のすぐ下に開く小さな物なので、0239 の 5 の「その場に開く小さな物」と同じく、丸い × ではなく文字のリンクの「閉じる」にした。

### 3. 直す場所へ移る（「対策で確かめる」）

- 吹き出しの下に「対策で確かめる」を置く。押すと、そのプランを帯で選び（帯に無ければ足す。5つを超えるときは今までと同じ知らせで1つ外す）、プランの一覧を閉じ、対策の「変えたこと」を開いて、その区画へ移る。フォーカスは「! 要確認」のボタンへ移す（キーボードでも続けて操作できる）。
- 「変えたこと」では要確認の行が上に並び、行ごとに「確認した（このまま）」「この差分を外す」で直せる（今までどおり）。
- 入力の画面の違いの一覧へ移す形も試したが、違いの一覧は、結果のタブで動かした値の「現状のプランが変わりました」を要確認に出さない（`planEdit.ts` の `diffRows` は差分を反映した結果の要確認だけを見る）。移った先に要確認が見えないので、移り先は対策にした。
- 行ごとに、その項目の場所へ移すことはしない（移り先の「変えたこと」が行ごとの直し方を持っているため、プランごとに1つのボタンで足りる）。

### 4. 形を選んだ理由

- カーソルを合わせたときだけ出す `title` の吹き出しは、タッチやキーボードでは見えず、文も長くできない。
- 説明の「?」の部品（`Help`。印を引き金にする `mark`）を使う形も考えたが、その部品の印は Tab の順に入らず（キーボードは F1 で開く。0077）、中に押せるボタンを置く作りではない。要確認は「何をすればよいか」まで知りたい物なので、Tab で止まるボタンにし、中に移り先のボタンを置ける吹き出しにした。

## 理由

- 中身の文を使い回すので、対策と一覧で同じ要確認の説明が別の言葉になることがない。
- 押せる・キーボードで開ける・閉じ方が他の重ねて出す物と同じなので、使い方を新しく覚えなくてよい。

## 未確定の要点

- 帯に並ぶプランの箱にも要確認の印を出すか（今は一覧と対策だけ）。
- 入力の画面の違いの一覧でも、結果のタブで動かした値の「現状のプランが変わりました」を要確認に出すか（出せば、移り先を入力にも選べる）。
