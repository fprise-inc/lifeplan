# 0221. 口座に名前（金融機関名・用途など）を付けられるようにする

- 状態: 採用（2026-11-17）
- 固定の強さ: 世帯ファイルの欄 `accounts[].label`（形式の版 0.81）の名前と意味（表示だけで計算に使わない・40文字まで・空と空白だけは名前なしと同じ）は骨格。入力項目ID `account.label` と、AI に渡す縮約版で文章の項目として既定で外すことは試験版（AI接続口の約束。0015）。画面の見せ方（「名前を付ける」のリンク・欄の置き場所・呼び名の形「名前（種類・名義）」）と、番号らしき数字の見分け方は内部
- 前提にする記録: 0008 の9（資産の器）、0026（資産運用・入れ方）、0011 の5（世帯ファイルの形式と移行）、0015 の6（縮約版と文章の項目）、0030（持ち帰り用のレポート）、0012（顧客の情報を最小にする）

## 背景

- 口座（資産の器 `accounts[]`）は種類（預金・課税口座・NISA・iDeCo など）と名義だけで呼んでいた（「NISA（ご本人）」）。同じ種類の口座を金融機関ごとに分けて入れると、画面ではどれがどれか見分けられなかった。
- 現場の FP から、金融機関の名前を付けて口座ごとに残高を入れたいという声があった。口座が多い人に「まとめる」「ネット銀行へ移す」といった提案をするとき、どこに何があるかが分からない年配の方と一緒に見るとき、NISA がどの金融機関にあるかを示すときに要る。
- 口座ごとに入れる方法と合計で入れる方法（0026・0031）はすでにあるが、世帯ファイルの口座に名前の欄が無かった。NISA などは種類だけで、金融機関を持たない。

## 決定

### 1. 世帯ファイルの欄（形式の版 0.81）

- 口座に任意の欄 `label` を足す（`engine/schemas/engine.input.json` の `$defs/account`。入力項目ID `account.label`）。文字、40文字まで（`maxLength: 40`。数え方は JSON Schema のとおりコードポイント。絵文字1つも1文字）。
- 表示だけで、計算エンジンは読まない。どの種類の口座（預金・課税口座・NISA・こどもNISA・旧NISA・ジュニアNISA・iDeCo・企業型DC・財形・持株会・外貨預金・暗号資産・小規模企業共済など）にも付けられる。スキーマの上では、貸していない不動産・その他の資産・合計の器（`pooled`）にも持てるが、画面で名前の欄を出すのは金融資産の口座だけ（合計の器は「まだ分けていない」の1行で、名前は要らない。不動産は物件名 `property.name`、その他の資産は中身の細目で見分ける）。
- 空のときは欄を持たない（欄が無い＝名前なし）。画面は空・空白だけの名前を書かずに欄を外す。前の版・AI・取り込みで空や空白だけの名前が入っていても、読む側（`accountLabelOf`）は名前なしと同じに扱う（今までの呼び名のまま）。空白だけを止める正規表現をスキーマに書かないのは、AI に渡す縮約版が正規表現のある文字を「形の決まった文字」として扱うため（0015 の6）。
- 世帯ファイルの形式の版を `0.81` にした（足すだけの MINOR。前の版のアプリは計算の入力の検査で知らない欄を通さないので、版を上げて閲覧だけにする）。`0.80` → `0.81` の変換の段は形式の版だけを書き換える（欄を書き足さない＝前の版の世帯はどの口座も名前なし）。見本 `crates/household-store/tests/fixtures/household-format/0.81/`（0.80 の見本の預金・NISA・課税口座の3つに名前。NISA と課税口座は同じ架空の金融機関）。

### 2. 画面での入れ方（名前を入れないときは目立たせない）

- 入れなくても今までどおり使える。名前の無い口座には欄を出さず、口座の表（貯蓄・運用の「口座ごとの残高・積立額・利回り」）の名義の横に、小さな薄い「名前を付ける」のリンクだけを置く。押すとその口座の種類の名前の下に細い欄が開く（灰色の入力例「名前（任意）例: ○○銀行」）。名前のある口座は欄をいつも出す（入れた名前を隠さない）。
- 欄は打っている間は下書きだけで、離れたとき（Enter）に決める（ほかの数の欄と同じ）。Esc は打ちかけを捨てる。空にして離れると名前を外して欄を閉じる。
- 打った文字は整えて書く（改行・タブなどの制御文字を空白に、続く空白を1つに、前後の空白を除く）。書かずに理由を欄の下に出すもの: 40文字を超える名前、口座番号などの番号らしき数字（明細の取り込みと同じ見分け方 `maskText`: 7桁以上の数字・「口座番号」などの見出しの後の数字・10字以上の番号の並び）。
- 欄の定義（`stages/savings.ts` の `accountLabelField`。名前「名前」・詳細の欄・`optional`）も持つ。確かめの一覧・前回との違い・探して開く・値の当て先（`account.label`）は、この定義から作る。「口座ごとの詳細」の区画には重ねて出さない（表で入れる）。

### 3. 名前に入れるもの（個人を特定する情報を入れない）

- 欄の説明（「?」と欄の title）で、金融機関名や用途（例: ○○銀行・△△証券・教育資金用）を入れること、氏名・口座番号は入れないことを書く。この作りは顧客の氏名の欄を持たない（構成員は続柄と呼び名。0012）ので、口座の名前にも氏名を入れない前提にそろえる。
- 番号らしき数字は上の2のとおり書かない。氏名らしい文字は機械で見分けられないので、説明の一言で促すだけにする。

### 4. 名前を出す所（口座を1行ずつ見せている所）

名前のある口座は「名前（種類・名義）」と呼ぶ（例「○○証券（NISA・ご本人）」。同じ金融機関に NISA と課税口座があっても見分けられるよう、種類と名義を残す）。名前が無ければ今までの呼び名のまま。

- 入力: 口座の表の欄、口座のまとまりの見出し（確かめの一覧の行・前回との違いの「どこ」にも出る）、取り崩す順番の並べ替え、収支が入る口座（決済口座）の選択肢（同じ呼び名の預金が2つ以上のときだけ番号を添える。名前を付ければ名前で見分ける）、黒字の貯まり方の「収支が入る口座」、iDeCo・企業型DC・小規模企業共済の受け取りの小見出し、利回りの段階の口座の名前、退職の段の「DC の受け取り」の行、受け取りの並び（「iDeCo（○○証券）の一時金」）。
- 結果: 年間収支の行を開くと出る取り崩しの子の行（「うち ○○証券（ご本人のNISA）から払った分（取り崩し）」）、対策の「資産運用の配分（○○証券・NISA・ご本人）」、計算のお知らせの呼び名（今までも名前があれば名前を使う形だった）。
- 前回との違い・プランの違い: 足した・外した口座の行（「口座（NISA）「○○証券」」）。
- AI が作った世帯の確かめの画面の資産の行。
- 出さない所: 資産と負債のタブのバランスシート・資産の推移の積み上げ・資産の内訳のドーナツ・提案書のバランスシートと運用の推移は、口座を種類ごとにまとめた行なので名前を出さない（今のまま）。

### 5. 計算の結果は変えない

- 計算エンジンは名前を読まない（部品も約束の版も変えない）。見本の世帯（`data/modelHouseholds` の全部）のすべての口座に名前を付けても、表・要約・お知らせが同じことを確かめる。一致テスト（parity）の答えも変わらない。

### 6. 前回との違い（控え）で名前の違いをどう出すか

- 名前だけを変えた・付けた・外したときも、前回との入力の違いに「○○証券（NISA・ご本人）: 名前　なし → ○○証券」の1行を出す（ローンの名前・保険の契約の表示名と同じく、欄ごとの入力の違いとして出す）。計算の結果の違いは出ない（結果は変わらない）。
- 理由: 前回との違いは「何を入れ直したか」を確かめる一覧で、名前を付けた・直したことも入力の変更として残っているほうが、前回の控えと比較するときに迷わない。

### 7. 持ち帰り用のレポート・AI接続口

- 持ち帰り用のレポート（0030）: 名前は残す（`FREE_TEXT` の扱いを `keep`）。お客さまが自分の口座を見分けるための名前で、年間収支の取り崩しの子の行に出る。ローンの名前・保険の契約の表示名・物件名は FP の書いた文として外しているが、口座の名前は金融機関名や用途を入れる欄で、番号らしき数字は書けないので、顧客に渡すファイルに入れてよいと決めた。
- AI接続口（0015 の6）: 縮約版では文章の項目として既定で外す（`crates/ai-share/src/reduce.rs` の `TEXT_ITEMS` に `account.label`・書いた人「FP（口座の名前）」）。FP が項目ごとに足したときだけ、入力から抜いて包んだ文章（`client_text`）として渡す。縮約版の許可リストの版は変えない（`reduced@33` のまま）。
- AI が書く側: 世帯の候補（`propose_household`。0208）の入力に名前を書ける（スキーマの欄なので）。読み口はほかの名前の欄と同じく `cleanText` で番号らしい所を消す。プランの候補（`propose_scenario`）では、文章の項目なので今までどおり書けない（`proposal.rs`）。入力の形の案内（`get_input_guide`）はスキーマから作るので、名前の欄が載る。

## 理由

- 名前を種類に置き換えず「名前（種類・名義）」にするのは、同じ金融機関の NISA と課税口座のように、名前だけでは見分けられない口座があるため。種類で税と取り崩しの扱いが違うので、種類は消さない。
- 欄を任意にして、入れないときは小さなリンクだけにするのは、多くの世帯は種類と名義で足り、空の欄が口座ごとに並ぶと表が見にくくなるため。
- 長さを40文字にするのは、口座の表の「口座」の列（幅15文字ほど）と取り崩す順番の行に収まり、金融機関名と支店・用途（例「○○信託銀行 △△支店（教育資金）」）が入る長さのため。
- 空白だけの名前を読む側でも名前なしと扱うのは、スキーマで止めない（上の1）ので、AI・取り込み・手で直した世帯ファイルから入ってきても、見出しが空にならないようにするため。
