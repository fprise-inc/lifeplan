# 0109. 基本生活費の内訳の並べ方を事務所ごとに決める（名前を変える・まとめる・隠す・分ける）

- 状態: 採用（一部未確定）（2026-11-01）
- 固定の強さ: 内部（事務所データの任意の欄 `defaults.living` と画面の作り。世帯ファイルの形式の版・計算エンジンの入力・10の内訳と推定は変えない）。分けた行の額は世帯ファイルの拡張領域の公式の項目 `ext.official.livingParts`（0011 の4）に置き、形は「内訳の要素の ID → 名前と月額の並び」。公式の項目にするときは形式の移行の中で引き継ぐ（0011 の4）。「まとめた行の額を今の額の割合で分ける」「隠した内訳はその他の行に入れる」「分けた行の合計が内訳の額」の決まりは、入れた値の内訳ごとの額に効くので、変えるときは追記に書く。名前・説明の文・見え方・編集の画面は後から変えてよい

## 背景

- 基本生活費の内訳（月額）は10の内訳（0100・0106）を標準の名前で並べる。事務所ごとに、お客さまに聞くときの分け方が違う（「固定費」の1行で聞く、医療費は分けて聞かない、食費を自炊と外食に分けて聞く、など）。
- 内訳の値（`LivingCategory`）と推定（同じ人数の世帯の平均。`master.living.statistics`）は計算・明細の取り込み・ヒアリング・推定の入れ直しが使う骨格で、事務所ごとに変えられない。見せ方だけを変え、入れた額を10の内訳に戻す決まりを1つにする必要があった。
- 前提にする記録: 0011（拡張領域・事務所データ）、0041（値の状態の操作）、0043（入力画面でプランを直す）、0048（基本生活費の入力項目）、0073・0084（事務所の既定値。見せ方だけの設定は世帯に写さない）、0100（10の内訳）、0106（内訳の「?」・合計の行）。

## 決定

### 1. 置き場所と形（事務所の既定値 `defaults.living`）

- 事務所データの既定値に足すだけの欄 `living`（`{ rows: 行の並び }`）。欄の無い古い事務所データ・読めない値・標準と同じ並べ方は「標準」で、欄を持たない（`office/livingLayout.ts` の `readLivingLayout`）。
- 行は3種類:

| 行 | 形 | 中身の内訳 |
|---|---|---|
| 1つの内訳 | `{kind: "one", category, label?}` | その内訳（名前を変えられる。名前が無ければ標準の名前） |
| まとめた行 | `{kind: "group", label, categories}` | 2つ以上の内訳（例: 水道・光熱費＋通信費＝「固定費」） |
| 分けた行 | `{kind: "split", category, label?, parts: [{label, share?}]}` | 1つの内訳を2〜6の行に（例: 食費 → 自炊・外食）。`share` は整数の%で、どの行にもあって合計100のときだけ使う（無ければ等分） |

- どの行にも無い内訳は**隠す**。**その他は隠せず、分けられない**（隠した内訳を入れる行のため。無ければ最後に1行足し、分けた行にあれば1行に戻す）。同じ内訳の2つ目・知らない内訳・名前の無い分けた行は捨てる。名前は20文字まで。
- 見せ方だけなので**世帯には写さない**（0084 の対策に最初から出す項目と同じ）。変えるとどの世帯の内訳の行にもすぐ効く。画面の側の操作が読む今の並べ方は `office/livingLayout.ts` の `livingLayoutNow`（読み込んだとき・保存したときに入れる）。

### 2. 入れた額を10の内訳に戻す決まり

- **並べ方を変えただけでは、世帯の値も結果も変わらない**。値が変わるのは、FP が行に入れたときだけ。計算は今までどおり10の内訳（とその合計）で、推定（同じ人数の世帯の平均）も同じ。
- **名前を変えた行**: 今までの内訳の欄そのもの（同じ鍵・同じ当て先。プランの差分・確かめの一覧・対策の動かす項目も今までどおり）。名前と「?」だけが変わる。
- **まとめた行**: 値は中身の内訳の合計。入れた額は**中身の内訳の今の額の割合**で分ける（千円単位。端は割合の一番大きい内訳）。どれも0円・空なら同じ人数の世帯の平均の割合で分け、平均の表も無ければその他（無ければ最初の内訳）に置く。分けた額はどれも確定（FP が決めたのは合計で、分け方は決まりどおり）。空にすると中身の内訳を外す。推定のままの内訳は「この値にする」で、どれもその額のまま確定にする。中身の一部が推定なら、欄の名前の横の「推定」の印（`partEstimated`）に「うち通信費は推定」と出す。
  - 今の額の割合にした理由: 統計の割合で配り直すと、ほかの事務所で内訳ごとに入れた額の比が消える。推定のままなら今の額＝統計の割合なので、新しい世帯は統計の割合で分かれる。
- **隠した内訳**: その他の行に入れる。その他の行は、その他と隠した内訳の**まとめた行**として扱う（値は合計、入れた額は今の額の割合で分ける）。隠した内訳に値が無い（要素が無い）ときは、今までのその他の欄。どちらでも、隠した内訳の額は見えない所に残らない（その他の行の値に入っている）。「?」に「隠している内訳（医療費）の分も、ここに入れます」。
  - 0円にしない理由: 隠した内訳に値がある世帯（推定の按分・ほかの事務所で入れた世帯）で、合計と推定が黙って変わる。
- **分けた行**: 内訳の額＝分けた行の合計。内訳の行は読むだけの小計（「食費」）にし、その下に分けた行（「自炊（食費）」「外食（食費）」）を出す。
  - 分けていない（分けた額が無い・内訳の額がほかで変わった）ときは、内訳の額を事務所の割合（決めていなければ等分）で分けた目安を**推定**として見せる（千円単位。端は割合の一番大きい行。合計は内訳の額のまま。内訳の按分の推定と同じ単位）。値は書かない。
  - 1つの行を入れると、ほかの行は見せていた目安のまま推定で残り、内訳の額は行の合計になる。内訳の箱は、どの行も確定なら確定、目安の行が残っていれば推定（根拠「自炊・外食の合計（外食は事務所の割合の目安）」）。目安の行は「この値にする」で確定にできる。空にした行は0円。
  - 推定の見せ方: 分けた行の横の目安は、事務所が割合を決めたときだけ「同じ人数の世帯の平均 月○万円（食費の平均の60%）」。割合を決めていなければ、平均は小計（内訳）の横にだけ出す（統計に無い分け方の平均は作らない）。
- 内訳の最後の合計の行（0106 の4）は今までどおり10の内訳の合計。前の分け方の内訳（交通・通信、その他の消費）と仕送り（前の内訳）は今までどおり、中身の内訳の行の後ろ・最後に前の名前で出す。

### 3. 分けた行の額を世帯に残す（拡張領域 `ext.official.livingParts`）

- 分けた行の名前と額は、作業中の世帯の画面の側の値 `livingParts`（内訳の要素の ID → `[{label, monthly, estimated?}]`）に持ち、世帯ファイルでは本文の拡張領域の公式の項目 `ext.official.livingParts`（定義は `extDefinitions` に写す。`attachTo: household`）に置く（`store/body.ts`）。household の区画には入れない。
  - 形式の版を上げない理由: 計算に使わない見せ方の補いで、拡張領域は知らないアプリも捨てずに書き戻す（0011 の4）。版を上げると、ほかの変更と同じ時期に変換の段が重なる。
- **使ってよいのは、分けた行の合計が今の内訳の額と同じときだけ**。明細の取り込み・推定の入れ直し・ほかの事務所や標準の並べ方で内訳の額を直したときは、古い分け方として使わず（目安で見せる）、保存するときに外す。
- **ほかの並べ方の事務所で開いたとき**: 計算は10の内訳なので結果は同じ。分けた額は失わない:
  - その内訳を1行で出す事務所（標準を含む）では、内訳の欄の横に「分けた行: 自炊 5万円・外食 2万円」と添える。
  - 名前の違う分け方の事務所では、小計の横に「前の分けた行: …」と添え、分けた行は目安で見せる。その事務所で分けた行を入れると、その事務所の分け方で置き換える。
- **プラン**: プランの中身（`planView`）で分けた行を入れると、内訳の額はプランの差分（`livingExpense.categories` の値）になり、分けた額は「プランの ID:要素の ID」に置く（現状は変えない）。プランの中身はそのプランと土台のプランの物を先に読む。プランが無くなった物は保存しない。
- 古い世帯・分けていない世帯は何も変わらない（拡張領域を作らない）。

### 4. 欄の説明（「?」）

- 名前を変えた行: 「中身は内訳の「食費」です。」の後に、その内訳の説明（0106）。
- まとめた行: 「「水道・光熱費」「通信費」をまとめた行です。」「入れた額は、今の内訳の額の割合（どれも0円なら同じ人数の世帯の平均の割合）で分けて計算します。」と、中身の内訳ごとの説明の1行目の箇条書き。
- 分けた行の小計: 「「自炊」「外食」の合計です（この額で計算します）」と、その内訳の説明。分けた行: 何を分けた行か・分けていないときの目安の作り方と、内訳の説明の1行目。
- 内訳のまとまりの「?」（推定の作り方と入れ先の一覧。0106 の1）の後に、「内訳は事務所の並べ方で出しています（…）。計算は10の内訳のままで、推定も同じです」を足す。入れ先の一覧は内訳の標準の名前のまま（行の「?」で中身の内訳が分かる）。

### 5. 事務所の既定値の画面

- 事務所の既定値のパネルに区画「基本生活費の内訳の並べ方」（`office/LivingLayoutEditor.tsx`）: 行ごとに名前の欄・↑↓・「下の行とまとめる」・「まとめるのをやめる」・「分ける」（分けた行の名前と割合の欄・「＋ 分けた行を足す」・「外す」）・「分けるのをやめる」・「隠す」。隠している内訳は下に並べ「戻す」。「既定の並べ方に戻す」。
- 右（狭い画面では下）に**見え方**: 4人の世帯の平均の額で、行の名前・中身の内訳（まとめた行は「水道・光熱費＋通信費」、隠した内訳は「隠した医療費を含む」）・分けた行と、合計（10の内訳の平均の合計のまま）。
- 分けた行の割合がそろっていない（入れた欄があるのに全部でない・合計が100でない）ときは、欄の下に「割合はどの行にも入れ、合計を100%にしてください（今は○%。そろうまでは等分で見せます）」。保存は止めない（読むときに割合を外し、等分にする）。
- 編集中は読む前の形のまま持ち、保存・読み込みのときに整える（名前の前後の空白・空の名前は標準の名前など）。

### 6. ほかの所での扱い

- **確かめの一覧・前提と推定の一覧**: 入力項目の欄から作るので、事務所の並べ方の行で出る（まとめた行・分けた行が推定なら、その行が1行）。
- **プランの違いの一覧・結果の表の行・対策の動かす項目**: 10の内訳のまま（違いは内訳ごと、結果の表の基本生活費の子の行は計算の行）。まとめた行・分けた行は対策の動かす項目にしない（画面の鍵を当て先に読み替えられないため。名前を変えた行は今までどおり）。
- **提案書**: 基本生活費は1行（内訳の表を載せていない）なので変えない。
- **ヒアリングシート**: 基本生活費の内訳を持たない（総額だけ。0106 の3）ので変えない。
- **明細の取り込み**: 10の内訳に入れる（候補の説明も標準の名前）。取り込むと内訳の要素が新しくなるので、前に分けた額は使わず（目安で見せる）、保存のときに外れる。

## 理由

- 10の内訳と推定を変えない: 計算・統計の目安・明細の取り込み・ヒアリング・推定の入れ直しが内訳の値に頼っている。事務所ごとに内訳そのものを持つと、推定の元（家計調査の区分）との対応と、ほかの事務所で開いたときの読み方が崩れる。
- 戻す決まりを「今の額の割合」1つにした: まとめた行と隠した内訳（その他の行）を同じ決まりで扱え、新しい世帯では統計の割合、FP が内訳ごとに入れた世帯ではその比が残る。
- 分けた行の目安を事務所の割合（無ければ等分）で見せる: 「内訳の推定だけを見せ、分けた行は空」にすると、1つ目の行を入れた途端に内訳の額がその行だけになり、推定の合計が黙って下がる。目安を見せておけば、入れた行の分だけが変わる。
- 世帯に写さない: 見せ方だけで、計算の数に効かない（0084 と同じ）。事務所で並べ方を直したら、どの世帯もすぐその並べ方で見られる。

## 代案（採らなかったもの）

- まとめた行の額を統計の割合で分ける（いつも）: ほかの事務所で内訳ごとに入れた額の比が消える。
- 隠した内訳を0円にする・その他に全部移す: 隠した内訳に値がある世帯で、内訳ごとの額（結果の表の子の行）が黙って変わる。今の額の割合なら、入れた額の分だけが変わる。
- 分けた行を計算の内訳の要素として持つ（同じ内訳の要素を2つ）: 内訳の値ごとに1つの要素を前提にしている所（推定の按分・明細の取り込み・前の分け方の分け直し）が多く、名前も持てない。
- 分けた行の額を世帯ファイルの household の区画に置き、形式の版を上げる: 3 の理由。公式の項目にするときは形式の移行の中で引き継ぐ。
- 分けた行の目安を統計の品目で作る（外食など）: 分け方は事務所が決めるので、統計の区分と合わない物が多い。事務所の割合で見せ、平均は事務所が割合を決めたときだけ割合で添える。
