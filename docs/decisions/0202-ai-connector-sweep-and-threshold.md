# 0202. AI接続口に、1つの項目を範囲で振る「感度」（sweep）と、条件を満たす境目を探す「境目探し」（find_threshold）を足す

- 状態: 採用（一部未確定）（2026-11-11）
- 固定の強さ: 道具の名前と入出力（`sweep`・`find_threshold` の引数と、答えの `columns`・`rows`・`notComputed`・`status`・`threshold`・`method`・`computed`）は試験版（0015 と同じ。予告して変えることがある）。作り（compare と同じ道を通す・単調と分かる項目の一覧・同時に計算する数）は内部
- 前提にする記録: 0005（計算の実行環境）、0014（AIに渡した記録）、0015（AI接続口）、0184（計算の前の処理）、0194（主な数字）、0195（プランの動かす項目）、0198（比べる道具）、0200（年金の見込み・相場が下がった場合）

## 背景

- FP が AI に頼みたいことのうち、「退職を60〜70歳で1歳ずつ変えたら？」「生活費は月いくらまでなら最後まで足りる？」「何歳まで働けば足りる？」「配偶者の年収を振ったら（106万円・130万円の壁）？」は、`calculate` を値の数だけ呼ぶとできた。ただ、働く最後の年齢を11通り振ると11回・約150KB（主な数字だけに絞っても約16KB）になり、境目を探すときは AI が二分探索を自分で回していた（呼ぶ回数・答えが積み上がり、探し方も AI まかせ）。
- 0195 で画面と同じ「動かす項目」（`plan_changes`）を、0198 で1回で何通りも計算する道（`compute`・`compute_all`）を入れたので、その上に、1つの項目を振る道具と、境目を接続口の中で探す道具を置ける。

## 決定

### 1. 振る項目と値の書き方（2つの道具で同じ）

- 振る項目は `vary` に、`list_plan_items` の `target`・`item`（`plan_changes` の1件から `value` を外した物）で書く。接続口は、その世帯の動かす項目の一覧（`list_plan_items` と同じ画面の関数。入力の欄から作った項目も含む）から項目を探し、今の値・値の形（`kind`）・刻みの既定を読む。一覧に無ければ計算せずに、`list_plan_items` で確かめるよう返す。
- 値は `from`・`to`・`step` で並べる（`sweep` は `values` でそのまま並べてもよい）。値の形は項目の `kind` に合わせる: 年齢・整数・金額は整数、率・10進は10進の文字列（数で書いてもよく、`"0.0150"` は `"0.015"` にそろえる。小数の足し算は10進のまま行い、2進の誤差を入れない）。配偶者の働き方と年収（`kind` が `work`）は、今の働き方（か `work_type`）のまま1年の収入を振る。ほかの形（入れる・入れない、配分、金利の上昇）は `sweep` の `values` でだけ並べられる。
- `step` を省くと、年齢・整数は1、金額・率は画面のスライダーの刻み。`to` が刻みで割り切れなければ、`to` を超えない所まで。
- 値ごとの計算は、基本の `plan_changes` の後に振る項目の1件をつないで（同じ項目なら振る値が勝つ）、`compare` と同じ `compute`（プランの変更 → 相場が下がった場合 → 計算の前の処理 → 計算 → 主な数字）を通す。`calculate` に `plan_changes` でその値を渡したときと同じ数字になる。
- 値が項目の範囲の外か（働く最後の年齢の45歳など）は、接続口に決まりを書かず、画面の関数（プランの候補と同じ当てはめ。0195）に任せる。範囲の外の値はエンジンを動かさずに、その理由を返す。
- 基本の世帯（`sample_household_id`・`share_id`・`input`）・`changes`・`plan_changes`・`stress_test`・`market_stress` は `compare` の基本と同じ書き方で、同じ確かめを通す。渡された世帯は `base_input`（アプリ本体の `GetShare`。同意・期限・縮約・包み方・記録はアプリ本体だけ）で、1回の呼び出しで1回だけ読み、道具の名前（`sweep`・`find_threshold`）で「AIに渡した記録」に残る。

### 2. 感度 `sweep`

- 21個まで振る。超えれば計算せず、範囲に収まる刻みの目安（例: 0〜7% を 0.05% 刻みなら「0.0035 以上」）を返す。21個は、働く最後の年齢の画面の範囲（50〜75歳）の多くの部分、利回りの 0〜10% を 0.5% 刻み、生活費の 20万〜40万円を1万円刻みが1回に入り、計算が同時に4つで数秒に収まる数として選んだ。
- 答えは表の形: `columns`（列の名前）と `rows`（値ごとの並び）。列は `value`（振った値。`work` は1年の収入）・`assetsAt○○`（`at_ages` の年齢の時点の金融資産。既定95歳）・`depletionYear`・`depletionAge`（資産が尽きる年と本人の年齢）・`minimumYear`・`minimumAmount`・`lifetimeTakeHome`・`lifetimeExpense`・`loanRepayment`・`pensionMonthly`・`pensionClaimedMonthly`（`calculate` の `keyFigures` と同じ数え方）。`figures` で列を選べ、`pension` を省くと年金の見込みの計算をしない。
- 計算しなかった値は `notComputed` に、同じ理由ごとにまとめて `{values, reason}` で返す（ほかの値は計算する）。1つも計算できなければ道具の答えを失敗にする（中身は同じ形）。
- 答えに添える説明は短い1文にし、列の意味は道具の説明に書く（説明は接続のときに1回だけ渡るので、呼ぶたびの答えを小さくする）。

### 3. 境目探し `find_threshold`

- `condition`（`noDepletion`＝資産が最後まで尽きない・`assetsAtAge`＝本人が `age` 歳の時点の金融資産が `at_least` 円以上・`minimumAtLeast`＝金融資産がいちばん少ない年でも `at_least` 円以上）を満たす値のうち、`want` が `max` ならいちばん大きい値（生活費の上限）、`min` ならいちばん小さい値（いちばん早い退職の年齢・足りる最低の利回り）を、刻み `step` の細かさで探す。
- 探し方:
  - 動かすと主な数字が一方向にだけ動くと分かっている項目（`sweep.rs` の `MONOTONE`: 毎月の生活費〔多いほど支出が増える〕・働く最後の年齢〔遅いほど働く年の収入が増える〕・運用の利回り〔高いほど運用している資産が増える〕）は**二分探索**。範囲の両端を一緒に計算し、欲しい端が満たせば `edge`、反対の端も満たさなければ `notFound`、そうでなければ「満たさない側」と「満たす側」を保って半分ずつ狭める。刻みの数は 2,001 個まで（探す計算は最大13回）。条件はどれも「金融資産が多いほど満たしやすい」ので、項目が単調なら条件も単調になる。
  - ほかの項目（年金の受け取り開始・NISA の積立・繰上返済・配偶者の年収など。手取りや資産が一方向に動くとは限らない）は**刻みで振る**。欲しい端（`max` なら大きい方）から4つずつ計算し、最初に条件を満たした所で止める。21個まで（`sweep` と同じ）。範囲の中に満たす所がほかにもあるかもしれないことを `methodNote` に書く。
  - `method` で `bisect`・`scan` を選ぶこともできる（`bisect` を単調と分かっていない項目に使うと、そのことを `methodNote` に書く）。どちらにしたかは `method`、理由は `methodNote` に返す。
- 答え: `status`（`found`・`edge`・`notFound`）・`threshold`（境目の値）・`message`（「「資産が最後まで尽きない」を満たすいちばん大きい値は 275,000円 です（1つ外側の 276,000円 では満たしません）」のような文。年齢は「64歳」、金額は「275,000円」、率は「6.8%」）・`rows`（境目の値とその1つ外側の値。`edge` は端の値だけ、`notFound` は範囲の両端。`sweep` と同じ列に、条件を満たすかの `meets` を足し、小さい値の順）・`range`（使った範囲と刻みと値の数）・`computed`（計算した回数）。
- 探す間は年金の見込み（写しをもう1〜2回計算する。0200）を数えない（条件に使わないため）。`figures` に `pension` があれば、答えの行だけ年金の見込みを含めて数え直し、その回数も `computed` に入れる。
- 計算できない値（範囲の端が項目の範囲の外など）に当たったら、そこで探すのをやめ、値と理由と計算した回数を返す（失敗の答え）。

### 4. 測った数字（見本の世帯 `salariedCoupleTwoKids`、リリースのビルド、10コアの手元の機械。ほかの作業と同時に動いていて、`calculate` 1回が約 0.85 秒かかる状態。2回測った）

| 呼び方 | 計算の回数 | 時間 | 答えの大きさ |
|---|---|---|---|
| 働く最後の年齢 60〜70歳: `calculate` を11回（既定の答え） | 11 | 9.4〜10.8 秒 | 152KB |
| 同じ: `calculate` を11回（主な数字だけ） | 11 | 8.3〜9.7 秒 | 16.3KB |
| 同じ: `sweep` 1回（列は全部） | 11 | 3.8〜4.5 秒 | 1.5KB |
| 同じ: `sweep` 1回（列を3つ。年金の見込みなし） | 11 | 2.1〜2.7 秒 | 1.0KB |
| 毎月の生活費 25万〜35万円を1万円ずつ: `sweep` 1回 | 11 | 3.9〜4.0 秒 | 1.6KB |
| 生活費の上限（15万〜40万円を1,000円刻み・251個。尽きない）: `find_threshold`（二分探索） | 10 | 6.9〜7.7 秒 | 1.4KB |
| いちばん早い退職の年齢（55〜75歳。尽きない）: `find_threshold`（二分探索） | 7 | 4.6〜4.8 秒 | 1.4KB |
| 同じ: `find_threshold`（`method: "scan"`） | 12 | 3.5〜3.7 秒 | 1.3KB |

- 答えは、11回・約150KB だった使い道が1回・約1〜1.5KB になった。生活費の上限は「月27.5万円まで（27.6万円で尽きる）」と出た（AI が二分探索を5回回したときと同じ答えで、細かさは1,000円）。
- 二分探索は1回ずつ順に計算するので、同時に4つ計算する刻みの探し方より、計算の回数は少ないが時間は長いことがある（上の退職の年齢で 4.7 秒と 3.6 秒）。
- 働く最後の年齢を振ると、画面と同じく生活費の退職の段階・積立の終わりも一緒に動く（AI が雇用の終わりの月だけを動かしたときの「画面と違う数字」は出ない）。

## 理由

- 1つの値の計算を `compare` と同じ `compute` にすれば、感度・境目探しの数字は `calculate`・`compare`・画面の「プランを比べる」とずれない（プランの当て方・計算の前の処理・主な数字の数え方を二重に持たない）。
- 振る項目を `plan_changes` と同じ書き方にすれば、画面と同じく関係する欄が一緒に動き、見つけた値をそのまま `propose_scenario` の `changes` に渡せる。
- 範囲の外かどうかを画面の関数に任せれば、画面のスライダー・欄・プランの候補と同じ範囲になる（接続口に範囲の決まりを写すと、画面の範囲が変わったときにずれる）。
- 表の形（列の名前を1回、行は値の並び）にすれば、同じ鍵を行ごとに繰り返さず、11行で約1KB に収まる。
- 二分探索は、単調と分かっている項目でだけ正しい。手取りや資産が一方向に動くとは限らない項目（年金の受け取り開始・配偶者の年収の壁・繰上返済）で二分探索をすると、境目を取り違えるおそれがある。そのため既定は、単調と分かる項目の一覧に載っている物だけ二分探索にし、どちらにしたかを答えに書く。

## 代案（採らなかったもの）

- **振る項目を JSON Pointer（`changes`）で書く**: 欄を1つしか動かさないので、働く最後の年齢では画面と違う数字になる（0195 の背景）。
- **答えを `compare` の `results` の並びにする**: 1値あたり約1.5KB（年ごとの系列・差・名前）になり、11値で約16KB。感度は主な数字の表で足りる。
- **境目探しをいつも刻みで振る**: 生活費を1,000円刻みで探すと251回の計算になる。単調と分かる項目は二分探索で10回ほど。
- **二分探索を4つずつ並べて計算する（4分探索）**: 時間は半分ほどになるが、計算の回数は増える。頼まれた「二分探索」と答えの `computed` の読みやすさを先にした（未確定に置く）。
- **範囲の外の値を接続口が先に断る**: 画面の範囲の決まり（今の年齢の次から・今の値が外にあれば広げる など）を写すことになる。画面の関数に当ててみて、断られた値だけ理由を返す。
