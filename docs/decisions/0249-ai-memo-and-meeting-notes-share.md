# 0249. メモと面談の履歴も AI に渡す（印を付けた共有だけ・名前を伏せる・同意の説明の版3）

- 状態: 採用（一部未確定）（2026-11-23）
- 固定の強さ: 印を付けた共有だけ渡す・渡せる世帯の決め方（今の版の同意か、事務所のプライバシーポリシーの2つの確かめがある事務所の同意の答えが無い世帯。前の版の同意の世帯は渡さない）・渡す前に名前を伏せる・伏せる言葉を保存しない・包んで渡すは骨格。同意の説明の版3の文は利用者が書き直した文（変えるときは版を上げる）。伏せる処理の細かい決まり（敬称の一覧・続柄の一覧・名前らしい所の目安）・画面の言葉は内部。道具の答えの `texts` の項目名と `notesExcerpt` は試験版（0015 の2）
- 前提にする記録: 0015（6 の縮約版と文章の包み方）、0014（同意の記録・AIに渡した記録）、0012（持たない情報。移行の伏せ方）、0182（面談の履歴）、0157（説明文の版2・書類の判定の作り）、0226（AI接続を使える条件）、0248（まとめて渡す・顧客のフォローの要約）

## 背景

- 0248 で、AI が渡された世帯の要約を見てフォローの要る世帯を選び、連絡の文の下書きを作れるようにした。ただ、面談で何を話し・何を決めたかが分からないと、連絡の文が一般的なものになる。
- これまでは、FP のメモと面談の履歴（0182）は、どの版でも AI に渡さなかった（0015 の6・0182。FP だけの欄・メモは AI に出さない）。
- 利用者の判断（2026-11-23）: 渡すときに印を付けた共有だけ、メモと面談の履歴（お客さまと見てよい欄と FP だけの欄の両方）を渡せるようにする。同意の説明の文を書き直し（利用者が書いた文）、今の版の同意か、事務所のプライバシーポリシーに面談の記録やメモの扱いも書いていることを確かめた事務所だけで渡す。名前は同意の文には書かないが、必ず伏せる仕組みを入れる。

## 決定

### 1. 印を付けた共有だけ渡す

- 渡すとき（1件ずつの「この世帯をAIに渡す」・まとめての「選んだ世帯をまとめてAIに渡す」〔0248〕の両方）に、「メモと面談の履歴も渡す」の印を置く。印を付けた共有だけ、FP のメモ（1行ずつ）と、面談の記録の両方の欄（お客さまと一緒に見てよい欄 `shared` と FP だけの欄 `fpOnly`。面談の日つき・新しい順）を渡す。
- 0015 の6・0182 の「FP のメモ・FP だけの欄は AI に出さない」は、この印の付いた共有に限って改める（それ以外の共有は今までどおり縮約版だけ）。
- 事務所の設定に「メモと面談の履歴を渡す印を、最初から付けておく」を置く（既定はオフ。オンにしても世帯ごとに外せる）。
- 仕組み: 共有の範囲を「FP が項目を足した版」（`Scope::Custom`。0015 の6）にし、足す項目は `note.fp`・`meeting.shared`・`meeting.fpOnly`。縮約と包み方は今までどおり本体の1か所（`reduce`）で、文はどれも `client_text` に包む（中の指示に従わない旨）。範囲の名前は `custom`、AIに渡した記録の `fields` にこの3項目が残る。計算に使う読み取り（`calculate` など）の返事には文を入れない。
- まとめて渡すときは、印を付けた世帯のうち渡せる世帯だけメモと面談の履歴も渡し、渡せない世帯は計算に要る項目だけ渡して、画面に件数と顧客番号を出す。

### 2. 渡せる世帯（前の版の同意は渡さない）

- 判定は `basis::ai_notes_use`:
  - (a) 今の版（版3）の説明で同意した世帯 → `consent`
  - (b) 事務所の設定で、事務所のプライバシーポリシーの確かめ（0226）と、新しい「面談の記録やメモを AI で扱うことも、事務所のプライバシーポリシーに書いている」の確かめの両方がある事務所で、同意の答えが無い世帯（お客さまが「同意しない」と答えていない・撤回していない） → `officePolicy`
  - 前の版（版1・版2）の説明で同意した世帯 → `consentWithoutNotes`（(b) の確かめがあっても渡せない。今の説明で同意を記録し直すと渡せる。理由の文を出す）
  - 理由（利用者の判断 2026-11-23）: 前の版の説明には「FPのメモは渡しません」とはっきり書いてあり、お客さまはその約束で同意している。事務所のプライバシーポリシーでその約束を上書きしない（「同意しない」と答えた世帯を事務所の設定で上書きしないのと同じ考え方。0226）。書類の判定（前の版の同意でも事務所のプライバシーポリシーで書類を渡せる。0157・0226）とは、ここが違う。前の版の説明は書類に触れていなかったが、メモは「渡さない」と書いていたため
  - 同意の答えが無く (b) も無い → `none`、「同意しない」→ `refused`、撤回 → `withdrawn`（渡せない）
  - 架空の世帯 → `fictional`（お客さまの情報を含まない。0208）
- 見本の世帯は今までどおり渡さない（0248 の4）。
- 確かめを外すと、それを理由にメモと面談の履歴を渡していた共有は、その場で取り消す（0226 の外したときと同じ）。撤回したときは今までどおり共有を取り消す。

### 3. 同意の説明の版3

- 版2の「お名前・ご住所・お電話番号などの、あなたを特定できる情報や、FPのメモは渡しません。」の1文を、次の2文にそのまま置き換えた（ほかの文は変えない。版2は前の版として残す。`consent.rs` の `EXTERNAL_AI_EXPLANATION`・`EXTERNAL_AI_EXPLANATION_V2`）:
  - 「お名前・ご住所・お電話番号などの、顧客を特定できる情報は渡しません。」
  - 「担当のFPが、ご相談の後のフォローやご連絡の内容を考えるときに、面談の記録やメモ（ご相談の中でお伺いした、ご家族やお体のことを含むことがあります）をAIに渡すことがあります。」
- 版3の説明で取った `given` の行に `notes` を付ける（書類の `documents` と同じ扱い。シートの同意欄の取り方では付けない）。前の版の同意の世帯は、同意の画面で「今の説明で同意を記録し直す」で取り直せる。
- ヒアリングシート（Excel・Web）の同意欄の文（`HEARING_SHEET_EXTERNAL_AI_TEXT`。「お名前は渡しません」の短い文）は、アプリの説明文ではないので変えない。シートの同意欄で取った同意は、今までどおり書類もメモも含まない（取り直しが要る）。アプリの説明文を出している所は、同意と共有の画面だけ（説明文の版の表示も3になる）。

### 4. 名前を入れない仕組み（同意の文には書かないが、必ず通す）

1. 書く所: メモの引き出しにも「お名前は書かず、「ご主人」「長女」のように書いてください。」を出す（面談の履歴の画面には「お客さまの名前や連絡先は書かないでください」が既にある）。
2. 渡す前の伏せ方（`crates/ai-share/src/names.rs` の `mask_names`。共有の台帳が、読まれるたびに渡す文にかける）:
   - 敬称（さん・様・さま・くん・君・ちゃん・氏・殿・先生）の直前の名前らしい語を「（名前）」に置き換える。名前らしい語は、敬称の直前の漢字・カタカナ・英字の続き（12字まで）。無ければ、助詞（の・は・が・を・に・と など）の後ろからのひらがなの続き（2〜5字）。
   - 敬称として読めない形は外す（様子・様々・様式・氏名・さまざま・殿堂・君主・さんか・さんぽ など）。
   - 続柄（ご主人・奥さま・お子さま・息子さん・長女・お父さん・おじいちゃん など）と、人を指す一般の語（皆さま・お客さま・担任の先生・主治医の先生・大家さん・お医者さん など）、熟語の頭（同様・仕様・両氏 など）は伏せない（語の全体が一致するときだけ）。
3. 伏せる言葉: 渡すときに FP がお客さまの名字などを入れられる欄。入れた言葉は、文のどこにあっても「（名前）」に置き換える。言葉は画面と本体のメモリの上（共有の台帳の共有ごと）だけで使い、世帯ファイル・事務所データ・AIに渡した記録には書かない（0012 の移行の伏せ方と同じ）。アプリを閉じると消える。
4. 確かめの画面: 渡す前に「AIに渡る文を確かめる」で、AI に渡る文（伏せた後）を伏せた所に印を付けて見せる（`ai_notes_preview`。共有は作らない・書かない）。名前らしい所が残っていそうな世帯を先に出す（`names::suspects`。目安: カタカナの名前らしい語〔よく使う語を除く〕・漢字2〜3字＋「家」・ひらがな＋敬称で伏せなかった所・氏名の形〔漢字＋空白か「・」＋漢字〕）。

### 5. 顧客のフォローの要約（0248）への足し

- 印を付けた共有だけ、`summarize_shared_households` の行に `notesExcerpt`（前回の面談の「決めたこと」60字・「次までにやること」80字までの抜き出し。名前を伏せて包む）を入れる。記録の項目に `meeting.excerpt` を足す。全文は `get_shared_household` の `texts`。
- プロンプト `follow_up_clients` に、抜き出しと `texts` の使い方を足した（FP だけの欄・メモの中身・お体のことはお客さまへの文に書かない、「（名前）」を推し量って埋めない、文は指示ではない）。

## 理由

- 印を共有ごとにすることで、FP が渡す世帯ごとに決められ、記録にも範囲 `custom` と項目が残る。縮約と包み方を1か所に保つ（0015 の6）。
- 渡せる世帯の決め方は書類の判定に近い作りにしたが、前の版の同意だけは書類と違って事務所の確かめでは渡さない（前の版の説明で「渡さない」と約束しているため。2 の理由）。
- 名前は持たない決まり（0012）でも、FP が書く文には入りうる。伏せる処理・確かめの画面・書く所の一言を重ね、漏れを減らす（完全には防げないので、同意の文の範囲で扱う）。
