# 0070. 前提条件のカードの中身（標準の値の推定・例外の年・表の最後の年・注意の線・料金の段階・前提と推定の一覧）

- 状態: 採用（一部未確定）（2026-10-27）
- 固定の強さ: 内部（画面の作り）。世帯ファイルに足した画面の側の値 `household.agreed`（確かめた記録）の形は、形式 0.27 の足すだけの形（0071 の4）。経済の前提の値を「標準と同じで値の状態の行が無いなら推定」と読む決まり、空欄にすると標準（教育費・厚生年金の調整率はほかの前提と同じ）に戻る決まり、表の最後の年を確定にしたら家族の生年月を直しても追いかけない決まりは、結果の数と古い世帯の読み方に効くので、変えるときは追記に書く。文言・並び・注意の線の値（仮の値）・利回りの選び方の値（仮の値）は後から変えてよい

## 背景

- 前提条件のカードは、物価・賃金・運用利回り・教育費・年金の調整率の既定の値、資産の種類ごとの利回り、持ち家の評価の前提、表の最後の年（詳細だけ）、FP顧問料を出していた。どの値にも印も根拠も無く、FP が入れた値か、新しい世帯に入れた仮の値かが分からなかった。
- エンジンの前提の列はどれも年ごとの列（`default`＋`byYear`。0008 の8）で、厚生年金の調整率を基礎年金と別に持てる（`pensionMacroSlideEmployee`）が、画面は既定の値しか直せず、例外の年は「次の版」と出していた。
- 表の最後の年は、標準（本人・配偶者のうち若い方が100歳になる年）と同じなら家族の生年月に合わせて追いかける（0008 の追記）。人が入れた年か標準のままかを世帯に持たないので、FP が標準と同じ年を確かめて決めても追いかけてしまう。古い世帯には、若い方が100歳を大きく超える年が残っているものがある。
- FP顧問料の料金の段階（`revision.steps`）はエンジンで計算するが、画面は件数を出すだけだった。
- 前提にする記録: 0008（世帯のデータモデル）、0026（資産運用の入力）、0031（黒字の貯まり方）、0035（値の状態の置き場所）、0036（差分の当て先）、0040（段階と例外の年）、0041（値の状態の操作）、0043（入力画面でプランを直す）、0045（カード）。

## 決定

### 1. 経済の前提の推定と空欄

- 物価・賃金・運用利回り・基礎年金の調整率は、値が「標準の値」（新しい世帯に入れる今の値。物価1%・賃金1%・運用利回り1%・調整率0.4%）と同じで、要求の入力の値の状態の欄（`input.valueStates`。0035 の3）に行が無ければ、**推定**（根拠「FPライズの標準（仮の値。事務所で根拠を確かめて直す前提）」。提供元の標準で、事務所の標準値ができるまでの値）と読む。古い世帯も書き換えずに同じ決まりで読む。
- 確定は「✓ この値で確定」だけ（0041）。行に根拠を残した確定にする。違う値を打てば確定、空欄にすると標準の値（推定）に戻る。
- 教育費の上昇率と厚生年金の調整率は、列が無ければ物価上昇率・基礎年金の調整率と同じ値を推定（根拠「物価上昇率と同じ」「基礎年金の調整率と同じ」）で見せる。確定するとその値の列を書く（結果は変わらない）。空欄にすると、例外の年が無ければ列を外す。
- 欄の当て先は `{plan: "assumptions"}`・`assumptions.<系列>`・`["default"]`（0036 の2。前からの読み替え表と同じ）。
- カードの区画の1行に「前提は FPライズの標準（仮の値）で計算中です（○つ）」と、入れる額は計算の基準の年の値段で物価で伸びることを書く。推定の数はカードと確かめの一覧に入る。
- 値の状態の操作「✓ この値で確定」は、見せている値が世帯に無い欄（省略のときの既定・ほかの値と同じ値を見せる欄）でも、見せている値を書いてから確定にする（`valueState.ts`。書いても省く欄は行だけを書く）。前は値が無いと何もしなかった。

### 2. 高すぎる値の注意の線

- 初めの線（仮の値。事務所で直す前提）: 運用利回りが年5%を超える、物価上昇率が0%未満か4%を超える、賃金上昇率が物価上昇率を2ポイント超えて上回る、資産の種類ごとの利回りが年8%を超える。
- 欄の知らせと確かめの一覧の「確かめの注意」に出す。値は変えない。

### 3. 例外の年

- 物価・賃金・運用利回り・教育費・年金の調整率（基礎・厚生）・資産の種類ごとの利回り・土地の上昇率の年ごとの値（`byYear`）を、詳細で範囲（始まりの年〜終わりの年・率）で入れる。続いた年で同じ率は1つの範囲にまとめて見せる。足す・外す・始まりの年を直すと範囲ごと動く（年数はそのまま）・終わりの年を直す・率を直す。直した範囲がほかの範囲と重なれば、直した範囲を勝たせる。
- 簡易の率（`default`）を直しても例外の年はそのまま。簡易の欄の下に「例外の年 ○年」と出す。
- プランでは、例外の年の値も前提の差分になる（入力画面でプランを直す仕組み。0043）。

### 4. 表の最後の年

- 簡易に出す。年で入れるほかに、本人・配偶者ごとに「○○が何歳になる年まで」で入れられる（書くとその人がその年齢になる年を表の最後の年にする。値は年だけを持つ）。欄の横に「標準の年（ご主人 100歳・奥様 98歳の年）」のように各人の年齢を出す。
- 標準と同じ年なら推定（根拠「標準の値」）。当て先は `{plan: "input"}`・`plan.endYear`・`[]`。
- **値の状態の行が確定なら、家族の生年月を直しても追いかけない**（`household.ts` の `followStandards`）。推定のまま（行が無い）なら今までどおり追いかける。
- 古い世帯で、若い方の年齢が表の最後の年に105歳を超えるか85歳に届かないときは、欄の知らせと確かめの一覧の注意に「表の最後の年が2086年（ご主人113歳）です。標準（2059年）にしますか」と「標準（○年）にする」を出す。押したときだけ直す（黙って書き換えない）。確かめの一覧の注意の行は、欄の知らせに直し方があればそのボタンを出す（`FieldState.warnFix`）。
- 計算の基準の月（`plan.baseMonth`）と計算の決まり（お金の数え方・運用益の数え方）は読むだけで詳細に出す。

### 5. 利回りの選び方・資産の種類ごとの利回り・持ち家の評価

- 運用利回りに、貯蓄・運用のカードの合計の入れ方と同じ「控えめ（1%）・ふつう（2%）・積極的（3%）」のボタン（値の表は `savings/model.ts` の `RATE_PRESETS` に移し、両方のカードで使う。どれも仮の値で、商品のおすすめではない）。
- 資産の種類ごとの利回りは、費用・税を引く前の年率と書く。貯蓄・運用のカードの資産配分と同じ値（どちらで直しても同じ）。
- 持ち家の評価の前提（土地の割合・耐用年数・建物の下限・売却の費用）の空欄の目安は、持ち家か不動産のある世帯では推定（根拠つき）と読む。土地の上昇率の空欄は「物価上昇率と同じ」の推定。

### 6. FP顧問料の料金の段階

- 継続の顧問料に、詳細で料金の段階（いつから〔時点〕・その月からの年額か月額）を足す・直す・外す。段の要素は ID を持つ（0035 の5）。計算は今のエンジンのまま。

### 7. 前提と推定の一覧

- 前提条件のカードの下に「前提と推定の一覧」（開くと表）。区分（経済の前提・計算の範囲と決まり・持ち家の評価・推定の目安〔各カード。確かめの一覧の推定の行と同じ〕・万一の前提〔共通の値〕）・項目・値（例外の年があれば年数）・状態・出典と根拠・お客さまと確かめた。区分で絞れる。前提条件の欄の行からは、その欄へ移る（詳細の欄なら詳細にする）。
- 「お客さまと確かめた」は、プランごと（現状は `"current"`、プランはプランの ID）に、行の印 → 確かめた日（とメモ）を画面の側の値 `agreed` に持つ（`WorkingHousehold.agreed`。世帯ファイルの `household.agreed`）。計算には使わない。プランを直しているときも差分にはしない（記録を直すだけ）。
- 提案書・持ち帰り用のレポートへの書き出しは、それぞれの回に作る（推定の場所は出さない決まりは保つ）。

## 計算が無いので出さない欄（残した欄）

| 欄 | 理由 |
|---|---|
| 前提の組（基本・厳しめ・楽観・事務所の標準をボタンで当てる） | 組の値を公的な前提の原本で確かめてから決める決まりで、まだ確かめていない。事務所の標準値の置き場所（事務所の設定）もまだ無い |
| 住民税の非課税の級地 | エンジンは1級地の値だけを持つ（`residentTax.exemption`）。級地を選ぶ前提の形と制度データが無い |
| 制度の変更を試す前提（年金の水準・児童手当を止める年・社会保険料の上乗せ・受け取り開始の年齢の引き上げ〔増額なし〕） | エンジンに前提の形が無い |
| 制度の境目の額（住民税が非課税になる収入の限度など）を級地の欄の下に | エンジンの出力に行が無い |
| 資産の種類ごとの値動きの大きさ | 計算に使わない値（`assetVolatility`） |
| 織り込んでいる決まった改正の一覧（読むだけ） | 画面から制度データの施行日つきの値を読む経路を作る回に（計算は今あるので、欄ではなく一覧の行として足す） |
| 前提の効き方の表・今のお金の値打ちで見る | 結果のタブの道具（計算の側）を作る回に |

## 理由

- **標準と同じなら推定と読む**: 人が入れた値かを世帯に持たないので、新しい世帯に入れた値と同じ値は推定と読むのが安全（気づかないまま仮の値で計算するのを防ぐ）。違う値は人が入れた値。表の最後の年の追いかけと同じ読み方。
- **確定したら追いかけない**: FP が「標準と同じ年」を確かめて決めたのに、家族の生年月を直すと動くのは、確定の意味と食い違う。
- **範囲で入れて年ごとに持つ**: エンジンの形（年ごとの値）を変えずに、「2026〜2028年は3%」の入れ方ができる。
- **確かめた記録をプランごとに**: 厳しめのプランの前提をお客さまと確かめた、を残せる。計算の要求に入れないので、結果は変わらない。
