# 0206. ID を持たなかった並びの要素に ID を振り、AI接続口の場所 at でプランの候補に出せるようにする（資産の配分の行・買付の年ごとの内訳・借り換え。形式 0.76）

- 状態: 採用（2026-11-11）
- 固定の強さ: 並びの要素の ID（世帯ファイルの `accounts[].assetMix[].id`・`accounts[].returnStages[].assetMix[].id`・`accounts[].lots[].id`・`debts[].refinance[].id`・`debts[].refinance[].rateSchedule[].id`。形式 0.76）と、変換の段が振る ID が前に画面の指していた決まった ID と同じであることは骨格（0035 の5 と同じ）。振る順（中の並びを先に）・同じ ID が並びにあるときの作り直し方は内部
- 前提にする記録: 0004（ID）、0011（封筒・形式の版）、0035（並びの要素の ID・決まった ID の作り方）、0036（プランの差分の当て先）、0201（場所 at・lever）

## 背景

- 0201 で、場所だけ違う動かす項目を場所 `at`（入力の欄の道。並びの要素は ID）で選べるようにした。ただ、ID を持たない並びの要素（資産の配分の行・旧NISA の買付の年ごとの内訳・借り換えの欄）は、画面が親の物の ID と場所から決まった ID（0035 の10 の1）を作って指していた。渡された世帯では親の ID が共有の仮の ID なので、決まった ID も別の値になり、アプリ本体が元の ID に戻せない。そのため `list_plan_items` はこれらの項目を `proposable: false` にしていた（0201 の未確定。0201 の時点で見本の世帯の場所に ID を含む 504 件中 71 件、今の版では 502 件中 69 件）。
- 内訳: 器の資産の配分の行の割合 51 件、旧NISA の買付の年ごとの内訳（買った年・取得価額・時価）12 件、借り換え（新しい金利・新しい返済期間・費用）6 件。見本の世帯には無いが、器の利回りの段階の資産の配分の行と、保険の数表の最初の行の解約返戻金も同じ形。
- 0035 の5 は、資産の配分 `assetMix` と旧NISA の年ごとの残高 `lots` を「ID を持たないままにする並び（入力項目の値の全体を差分の1件で変える）」にしていた。ところが入力の画面は行ごとの欄（割合・時価など）を持ち、動かす項目も行ごとにできている。

## 決定

### 1. ID を持つ並びを足す

- 次の並びの要素も `id`（UUID 第4版の形）を持つ: 器の資産の配分の行 `accounts[].assetMix[]`、器の利回りの段階の資産の配分の行 `accounts[].returnStages[].assetMix[]`（計算の入力のスキーマの共通の形 `assetMix`。資産配分の段階 `assumptions.investment.allocation.stages[].mix[]` も同じ形なので ID を持てるが、行ごとの動かす項目が無いので振らない）、旧NISA の買付の年ごとの内訳 `accounts[].lots[]`、借り換え `debts[].refinance[]` とその新しい金利の段 `debts[].refinance[].rateSchedule[]`（金利の段は前から ID を持てたが、借り換えの中は振っていなかった）。
- 計算の入力のスキーマ（`engine/schemas/engine.input.json`）に任意の欄 `id` を足した。エンジンは使わない（計算の結果は変わらない）。縮約版は ID の形の文字をそのまま渡し、共有の仮の ID に置き換える（ほかの要素の ID と同じ）。

### 2. ID の作り方: 前に画面が指していた決まった ID と同じ

- ID の無い要素には、画面がその要素を指していた決まった ID（`<ID を持ついちばん近い物>/<欄の名前>/<番号>` から作る。0035 の10 の1・`readings.ts` の `migrationId`）と同じ ID を振る。例: 器の資産の配分の2行目は `<器の ID>/assetMix/1`、ID の無かった借り換えの中の金利の段は `<負債の ID>/refinance/0/rateSchedule/0`、ID のある利回りの段階の中の行は `<段の ID>/assetMix/0`。
- そのため、前の版で保存したプランの差分（当て先の `at`）・値の状態の欄の鍵・外から来た候補の `at` は、書き換えずに同じ要素を指したまま。中の並びは外の並びより先に振る（外の要素に ID が無かったときの場所を、決まった ID の作り方とそろえる）。同じ並びにもう同じ ID があれば、場所に数を足して作り直す（画面の `placeId` と同じ）。
- 振る所は2つで、同じ決まり: 本体の変換の段（`crates/household-store` の 0.75 → 0.76）と、画面が世帯を開くとき（`app/src/workspace/store/elementIds.ts` の `giveElementIds`。見本の世帯・AI が組み立てた入力・ヒアリングから作った世帯など、ID の無い要求を開くとき）。画面で新しく足した行は、今までの並びと同じく乱数の ID（開き直すとき）。

### 3. 画面で ID を保つ

- 行を外す（資産の配分・買付の年・借り換え）・足す・欄を直す・割合の合計を100%に直す、では、ほかの行の ID を変えない（今の画面の作りのまま。テストで確かめる）。
- プランの「資産運用の配分」（器の配分の全体を1つの値で変える動かす項目）を当てるときは、同じ資産の種類の今の行の ID を引き継ぐ（無い種類の行は ID を持たない）。値の形（`[{assetClass, share}]`）は変えない。

### 4. 世帯ファイルの形式 0.76

- 形式の版を **0.75 → 0.76** に上げた（足すだけの MINOR）。0201 の5 と 0011 の決まり（前の版のアプリが新しい欄を読み落として別の物に当てる・書き戻して落とす・読めない、なら版を上げて閲覧だけにする）に当てはめた: 前の版のアプリは計算の入力の検査（知らない欄を拒む。0004 の7）で行の `id` を通さず、その世帯を計算できない。版を上げないと、前の版のアプリで開いて保存できてしまう。
- 変換の段は版だけでなく、2の ID を書く（控えの中身は変えない。0011 の5）。見本 `crates/household-store/tests/fixtures/household-format/0.76/` は、0.75 の見本に住宅ローンの借り換えを1件足して本体が変換した形。

### 5. AI接続口

- 見本の世帯 55 件で、`list_plan_items` の `proposable: false` は 69 件 → **0 件**。場所 `at` の中の行の ID も、ほかの要素の ID と同じく共有の仮の ID のまま `calculate`・`propose_scenario` に渡せ、アプリ本体が元の ID に戻す。書き方・答えの形は変えない（`at` の中の ID の値が、決まった ID から世帯に書かれた ID になるだけで、見本の世帯では同じ値）。
- `proposable` の決まり（場所に世帯のデータに書かれていない要素の ID があれば false）は残す。残る形は6。

### 6. 残したもの（わざと ID を振らない）

- **保険の数表の行 `insuranceContracts[].schedule.rows[]`**（動かす項目は簡易の入れ方の「解約返戻金」1つで、最初の行を指す）: 数表は年ごとの数の組で、保険の商品のパックから写す・取り込み直すと全体が置き換わる（0035 の5 の ID を持たない並びのまま）。行は数十〜百あり、1件ずつ足す・外すことも無い。この項目は渡された世帯では `proposable: false` のまま（計算はできる）。見本の世帯には無い（0 件）。
- 0035 の5 のほかの ID を持たない並び（債務者・持分・受取人・加入歴・資産配分の段階の配分の行など）は、行ごとの動かす項目が無いので変えない。

## 理由

- **ID を書く（アプリ本体が仮の ID から振り直した ID を戻す案にしなかった）**: 戻す案は、アプリ本体が画面の決まった ID の作り方（親の探し方・場所の書き方）を持ち、AI の `at` を作り直すことになる。親の物を足す・並べ替えると番号の場所が変わり、別の行に当たる（0035 の5 で並びの要素に ID を持たせた理由と同じ）。ID を書けば、ほかの並びと同じ1つの仕組み（共有の仮の ID の置き換え）で済む。
- **決まった ID を前と同じにした**: 前の版の世帯のプランの差分・値の状態の欄・候補を書き換えずに済み、読み替えの表も要らない。画面と本体が同じ作り方で振るので、どちらで開いても同じ ID になる。
- **版を上げた**: 4 のとおり。

## 代案（採らなかったもの）

- **アプリ本体が決まった ID を振り直して戻す**: 上の理由。
- **行の `at` を番号で書く**: 足す・外すで別の行に当たる（0035 の5）。
- **形式 0.75 のまま、画面が開くときだけ ID を振る**: 保存すると ID が書かれ、0.75 のアプリが計算できない世帯ファイルが 0.75 の版で残る。
- **保険の数表の行にも ID を振る**: 6 のとおり。

## テスト

- 画面の側（`app/test/array-element-ids.test.ts`）: 見本の世帯を開くと新しく ID を持つ要素がすべて決まった ID を持ち、行ごとの動かす項目の当て先が ID を振る前と同じこと。借り換えの中の段・利回りの段階の中の行の場所の決まり。0.75 の見本の世帯ファイルを読むと ID が付き、書き戻して読み直しても1文字も変わらないこと。0.76 の見本（本体が変換した形）と画面の振る ID が同じこと。画面で行を外す・足す・配分を当てても、ほかの行の ID が変わらないこと。
- 接続口の側（`app/test/connector-plan.test.ts`・`crates/lifeplan/tests/mcp_connector.rs`）: 見本の世帯のどの項目も `proposable` が true。資産の配分の行・買付の年・借り換えの金利と費用の変更が画面でつまみを動かしたときと同じ数字。渡された世帯の一覧の資産の配分の行の場所をそのまま `calculate` と `propose_scenario` に渡すと当たり、アプリ本体が `at` の中の行の ID も元に戻すこと。
- 本体の側: `migrate.rs` の変換の段のテスト（決まった ID・ID のある要素はそのまま・中の並びの場所・同じ ID の作り直し・控えを変えない・2回通しても同じ）と、形式の見本（すべての版を変換すると行が ID を持ち、0.76 より前の見本は決まった ID）。
