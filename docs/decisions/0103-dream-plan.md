# 0103. 夢プラン・子への援助の優先度と、世帯ファイルの形式 0.46

- 状態: 採用（一部未確定）（2026-11-01）
- 固定の強さ: 骨格は、夢を出るお金の行の種類 `dream` で持つこと、行の `dream`（`rank`・`include`〔省略は入れる〕・`note`）の形と意味、子への援助 `goals[].education.gifts[].priority`（`need`・`want`。省略は必ず）、入力項目ID `periodicExpense.dream`・`periodicExpense.dreamNote`、計算に入れない夢は要求を作るときに外す（エンジンは変えない）こと。ひな形の名前と仮の時期・欄の並び・文言・要約の言い方・提案書の章の見せ方は後から変えてよい

## 背景

- ヒアリングでは「この先、やりたいことは何ですか」から聞くことが多いが、ライフイベントの入力項目には、ご家族の夢を夢として並べる所が無かった。夢はふつうの出るお金の行に優先度「できれば」で入れるしかなく、順位・なぜかなえたいか・計算に入れるかを持てなかった。
- 出るお金の行の優先度には古い値の「夢」（`wish`）があるが、画面では「できれば」と同じ扱いで見せている（0044 の追記）。優先度の札に3つ目の値を足すと、ふつうの行の「必ず」「できれば」の意味が揺れる。
- 結果の画面の目標の区画（`GoalCards`）は作ってあったが画面に出しておらず、「やりたいこと」は仮のカード1枚（「まだ入れていません」）だった。
- 子への援助（`goals[].education.gifts`。ライフイベントの子の結婚の援助のひな形もここに足す）には優先度の欄が無く、「確実な分だけ」の見方で外せなかった（0068 の追記 2026-10-31 の2）。
- 前提にする記録: 0044（お金の行・結果の見方）、0068（ライフイベントの入力項目）、0077（足した物1件を1つの枠に）、0100（基本生活費の内訳）、0101（形式 0.45）。

## 決定

### 1. データの形（夢はふつうの行と別の種類）

- 夢は出るお金の行（`periodicExpenses`）の**種類 `dream`** で持つ。ふつうの行の優先度（必ず・できれば）とは別の物で、夢の行は優先度の欄を持たない（3つ目の優先度は作らない）。
  - 別の並び（世帯の `dreams`）にしなかった理由: 夢の計算はふつうの一時的支出の行と同じで、プランの差分・値の状態・仮の印・この世帯の予定・提案書のライフイベント表・お金の3つの分け方が、出るお金の行のままで使える。別の並びにすると、それぞれに夢の読み方を足すことになる。
- 行の `dream` に、夢だけの値を書く:
  - `rank`: 順位（1が最初）。並びは順位の順、順位の無い物・同じ順位は世帯の並びの順。「↑ 上へ」「↓ 下へ」で動かすと1から振り直す（プランを直しているときは、順位の値を変える差分になる。並びの順を動かす差分は無いので、順位を値で持つ）。
  - `include`: 計算に入れるか（省略は入れる。「計算に入れない」を選ぶと `false`）。
  - `note`: ひとことメモ（なぜかなえたいか。200字まで）。入力項目ID は `periodicExpense.dreamNote`（AIに渡す縮約版では文章の項目として既定で外す。持ち帰り用のレポートでは外す）。
- 時期は1回か年ごと（始まり・何年ごと・終わり）で、時点の入れ方（今から・年齢など）はほかのライフイベントの行と同じ。表の行は**一時的支出**（`cf.expense.lumpSum.other`。ほかのライフイベントの行と同じ）。
- 計算エンジンは変えない: エンジンには夢もふつうの一時的支出の行として渡す。**計算に入れない夢は、アプリが要求を作るとき（`forEngine`。受け取る相続の `includeInBase` と同じ所）に外す**。エンジンの入力のスキーマには種類 `dream` と行の `dream`（計算には使わない）、子への援助の `priority` を足しただけで、計算の式・部品の改訂・一致テストは同じ。
- 古い値の優先度「夢」（`wish`）の行は、今までどおり「できれば」で見せ、行に「**夢にする**」のボタンを出す（どの入力項目の行でも）。押すと、種類を夢にし、優先度を外し、いちばん下の順位にし、表の行を一時的支出にする（名前・額・時期はそのまま）。自動では移さない。

### 2. 画面（ライフイベントの入力項目のいちばん上）

- 区画「**夢プラン**」を、出るお金の区画より上に置く（ヒアリングで最初に聞くため）。説明: 「ご家族がかなえたいことを、上から順に並べます。車・住まいそのものを夢にするときも、ここでは額と時期で入れます。維持費・ローンは車・住まいの入力項目で」。絵・絵文字は使わない。
- 夢の1件は1つの枠（まとまり1つ。0077 の追記）。見出しは「夢1｜夫婦で海外旅行 120万円・1回 2041年4月」（額が0円なら「額は未入力」、計算に入れない夢は「（計算に入れない）」を添える）。欄は名前・時期（1回／年ごと）・額・時期（年ごとなら初め・何年ごと・終わり）・ひとことメモ（なぜかなえたいか）・計算に入れる。種類・表の行・優先度の欄は出さない。前に毎月で入れた行は毎月も残して見せ、毎月の支出は基本生活費で入れると添える（ライフイベントの行と同じ）。
- ボタン: 「↑ 上へ」（いちばん上には出さない）・「↓ 下へ」（いちばん下には出さない）・「外す」。区画に「＋ 夢を足す」（名前は空・1回・1年後・額は未入力）。
- **夢のひな形**（小さなボタン。行を足した後も出し、足した数を「入れた（2件）」）。名前と時期だけを入れ、額は未入力の警告（0円で計算中）。時期は仮の印（「ひな形の仮の時期（…）。この世帯に合わせて直してください」。直すと外れる）:

| ひな形 | 時期 |
|---|---|
| 特別な旅行 | ご本人が65歳になる月（退職のころ） |
| 趣味を始める（道具など） | 今から1年後 |
| 学び直し・資格 | 今から1年後 |
| 憧れの車 | 今から3年後 |
| 二拠点や別荘 | ご本人が60歳になる月 |
| 移住 | ご本人が60歳になる月 |
| 起業 | 今から3年後 |
| 家族の記念 | 今から5年後 |

  ご本人がその年齢を過ぎていれば今から1年後。どれも1回（年ごとにかかるなら FP が「年ごと」にする。ひな形の「?」に書く）。上の3つ（旅行・趣味・学び直し）は、ライフイベントの出るお金のひな形「楽しみ・学び」をまとめた物（下の追記 2026-11-01）。
- 夢はふつうの出るお金の区画に出さない（ライフイベントの行・ひな形の「入れた」に数えない）。入力項目の要約の件数には数える。この世帯の予定には名前に★を付けて載せる（計算に入れない夢は「（計算に入れない）」を添える）。

### 3. 計算と結果

- 計算に入れる夢は、基本の計算に入る（キャッシュフロー表の一時的支出の行）。
- 結果の見方（0044 の追記）: 「外している物」の一覧に、夢を理由の札「**夢**」で並べ、1件ずつ入れ外しできる。「確実な分だけ」は夢を外す。「計算に入れない」夢は、ふだんも外れていて、ここで入れて見られる（要求の写しで `include` を true にする。世帯もプランも変えない）。
- 結果の画面の対策の下に、目標の区画（`GoalCards`）を出す。前の「やりたいこと」の仮のカードの代わりに、夢のカード（「夢1」・計算に入れる／入れない・名前・時期〔「2041年（ご本人65歳）」「2031年（ご本人50歳）から2040年まで・毎年」〕・額〔未入力は「額は未入力」〕）を順位の順に並べる。夢が無ければ、入れる所を案内する1枚（「夢」「まだ入れていません」「ライフイベントの入力項目の『夢プラン』で入れます」）。目標の区画のほかのカード（教育・住宅ローンの完済・老後の生活資金・周期的な支出）は前のままで、周期的な支出のカードに夢は入れない。
- **要約の1文**: 選んでいるプランを、夢を全部外して1回だけ足して計算し（計算に入る夢があるときだけ。枠 `nodream`。指を離してから計算する）、夢を入れた計算と資産が尽きる年を比べる（`report/src/dreams.ts` の `dreamSummary`。提案書と同じ）:
  - 夢を入れても尽きない: 「夢をすべて入れても100歳まで足ります」
  - 夢を入れると尽き、外すと尽きない: 「夢をすべて入れると82歳で不足します（入れなければ足ります）」
  - 外しても尽きるが、外すと遅くなる: 「夢をすべて入れると82歳で不足します（入れなくても88歳で不足します）」
  - 外しても同じ年に尽きる: 「夢を入れなくても82歳で不足します（夢で不足の時期は変わりません）」
  - 一部の夢を計算に入れていない（入力か見方で）: 「計算に入れた夢（5件中3件）を入れても…」、どれも入れていない: 「夢はどれも計算に入れていません」
  - 年齢はご本人の年齢、最後の年はご本人の表の最後の年の年齢（「100歳まで」）。夢を外した計算がまだ無いときは出さない。

### 4. 提案書

- 章「**ご家族の夢**」（章の一覧では「ご家族の夢（夢プラン）」。基本項目の次、ライフイベント表の前）: 要約の1文と、順位・夢・時期・金額（未入力は「未定」）・計算（入れる／入れない）の表。夢の無い世帯では載せない。ひとことメモは載せない（FP の画面の物）。提案書を作るとき、夢を全部外した提案を1回足して計算する（材料 `proposalWithoutDreams`）。帳票の入力の形の版は変えない（任意の欄 `dreams` を足しただけ）。
- 「ライフイベント表」: 計算に入れる夢を★を付けて載せ（「★憧れの車（600万円）」）、表の下に「★はご家族の夢（夢プラン）です。」。計算に入れない夢は前提の出来事でないので載せない（ご家族の夢の章には載る）。

### 5. 子への援助の優先度

- 子への援助（`goals[].education.gifts[]`）に優先度 `priority`（`need` 必ず・`want` できれば）を足した。子ども・教育の入力項目の援助の欄に「優先度」（必ず・できれば）を標準で出す。省略は必ず（前の援助は必ずのまま。結果は変わらない）。
- ライフイベントの「子の結婚の援助」のひな形は「できれば」で足す（0068 の追記 2026-10-31 の2 の「援助は必ずとして計算する」をやめた）。ライフイベントの読むだけの行に優先度を添える（「2052年・100万円・できれば」）。
- 「できれば」の援助は、ふつうの「できれば」の行と同じく、「確実な分だけ」で外し、「外している物」の一覧に「第1子への援助（結婚資金）」として理由「できれば」で並ぶ（1件ずつ入れ外しできる）。

### 6. 世帯ファイルの形式 0.46

- 足すだけの MINOR（種類 `dream`・行の `dream`・援助の `priority`）。0.45 → 0.46 の変換の段は形式の版だけを書き換える。前の版のアプリは種類 dream の行を読めず、援助の優先度を読み落として書き戻すので、版を上げて閲覧だけにする。
- 見本 `crates/household-store/tests/fixtures/household-format/0.46/`（夢3件〔1件は計算に入れない・順位は並びと違う・ひとことメモつき〕と、優先度「できれば」の子への援助）。
- 入力項目ID `periodicExpense.dream`（順位・計算に入れるか。縮約版の許可リストに入れ、版を `reduced@25` にした）・`periodicExpense.dreamNote`（文章の項目。既定で外す）。

## 追記

- 2026-11-01（ライフイベントと夢プランを意味で分ける）: ライフイベントの出るお金のひな形は「ご家族に起きること・備え」だけにし、「ご家族のやりたいこと」は夢プランのひな形にまとめた（0068 の同じ日の追記）。

  - ライフイベントの「楽しみ・学び」（特別な旅行・大きな買い物〔趣味の道具など〕・資格・学び直し）を夢のひな形へ移し、重ならないようにまとめた: 「夫婦で海外旅行」と「特別な旅行」→「特別な旅行」（「?」に海外の旅行・記念の旅行などと書く）、「趣味を始める」と「大きな買い物」→「趣味を始める（道具など）」、「学び直し」と「資格・学び直し」→「学び直し・資格」。並びは旅行・趣味・学び直し・憧れの車・二拠点や別荘・移住・起業・家族の記念。
