# 0166. 開けない世帯ファイルを直前の世代で開き直す（勧める場合・壊れたファイルの残し方・開くときの文言）

- 状態: 採用（一部未確定）（2026-11-08）
- 固定の強さ: 骨格（直前の世代を勧めるのは本体の開く操作が「壊れている・知らない版・本文が読めない」で失敗したときだけ・壊れたファイルは捨てずに `conflicts/` に暗号化のまま残す・`.prev` は残す・応答にパスを入れない）。画面と文言は内部。世帯ファイルの形式の版・`IPC_VERSION` は変えない
- 前提にする記録: 0011（7 の保存の手順と直前の世代 `.prev`）、0013（暗号化・完全削除の範囲）、0016（許可した命令だけ）、0023・0024（事務所の共有・同期フォルダ。分岐の写しを `conflicts/` に残す）

## 背景

- 0011 の7 で、保存のたびに直前の世代（`<ファイル名>.prev`）を1つ残すと決めた。起動時の片付けは「今のファイルが無い」ときだけ `.prev` から戻す。
- 今のファイルが**ある**のに開けない（途中で切れた・空・頭だけ残った・ゼロで埋まった）とき、アプリは「壊れています」と出すだけで、FP が `.prev` を使う道が無かった。`.prev` は PC の中にあっても、FP には見えず、手で戻すことも求めない（本体の応答にデータフォルダのパスを入れない。0016 の1）。
- 開く操作の失敗の文言が、ふだんの文言（「保存の処理に失敗しました」）と混ざっていて、開こうとして失敗したのに「保存」と出ることがあった。

## 決定

### 1. 本体の2つの操作（`household-store`）

- `previous_generation(id)`: 今のファイルが開けず、`.prev` が開ける（封筒の認証・世帯の鍵・本文の変換まで通る）ときだけ、その時点 `{generation, savedAt, savedBy}` を返す。今のファイルが開けるとき・`.prev` が無いか開けないときは「無い」を返す。応答にファイルのパスを入れない（0016 の1）。
- `open_previous(id)`: 上と同じ条件のときだけ、今のファイルを `.prev` の写しに置き換えて開く。条件に合わないときは誤りの符号 `E_STORE_NO_PREVIOUS` を返す。
  - 壊れた今のファイルは捨てずに、この PC の中の `conflicts/` に `<世帯ID>.<拡張子>.broken-<日付>-<乱数>` の名前で、暗号化されたまま残す（分岐の写しと同じ置き場所。0011 の7）。
  - 今のファイルが無い状態で書くので、`.prev` は置き換わらずに残る。開き直した後に保存すると、0011 の7 の手順どおり `.prev` が新しくなる。
- 画面に許す命令は `store_previous_generation`・`store_open_previous` の2つ（0016 の許可した命令だけ）。開発用のサーバー（ブラウザでの確かめ）はメモリの中で壊れないので、いつも「無い」を返す。

### 2. 直前の世代を勧める場合

- 勧めるのは、本体の開く操作が次の符号で失敗したときだけ: `E_STORE_CORRUPT`（壊れている）・`E_STORE_FORMAT_UNKNOWN`（知らない形式の版）・`E_STORE_BODY`（本文が読めない）。
- 鍵・復元キー・新しい版のアプリが要る・事務所の共有の失敗では勧めない。今のファイルは壊れておらず、古い内容に戻すと、直した後の変更を失うだけになるため。
- 本体が開けた本文の形が画面に合わない（`E_BODY_SHAPE`）ときも勧めない（ファイルは壊れていない）。
- 勧める画面では、戻す前に「何日の保存か・何回目の保存か・保存した人（事務所で共有しているとき）」を見せ、直前の保存の後に入れた変更は戻らないこと、開けなかったファイルは PC の中に別名で残すことを書く。押すまで何も変えない。

### 3. 開くときの文言

- 世帯を開く操作（一覧から開く・見本を開く・起動時に前の世帯を開く）の失敗は、開く操作の言葉（「〜のため、開けませんでした」）で出す。開く操作に限らない符号（復元キー・新しい版・事務所の共有など）は、ふだんの文言のまま。
- ふだんの文言の既定（知らない符号）は「世帯の処理に失敗しました（符号）」にする（保存に限らないため）。

### 4. 完全削除

- `conflicts/` の `<世帯ID>.` で始まるファイルは、世帯の完全削除で一緒に消える（0013 の範囲のまま。新しい置き場所を作らない）。

## 理由

- `.prev` は保存の手順で必ず残る完全な世代なので、壊れたときに使える一番新しい物。毎日のバックアップ（最大1日前）より失う変更が少ない。
- 壊れたファイルを捨てないのは、壊れ方を後で調べられるようにするためと、FP が「開き直したが前のほうがよかった」ときの手掛かりを残すため。分岐の写しと同じ置き場所にすれば、完全削除の範囲を変えずに済む。
- 勧める場合を絞るのは、壊れていないファイルを古い内容で上書きする道を作らないため。

## 代案（採らなかったもの）

- 開けないときに黙って `.prev` で開く: どの時点に戻ったかを FP が知らないまま古い内容で計算が進むので採らない。
- 壊れたファイルをその場で消す: 調べる手掛かりが無くなる。誤って勧めたときに取り返せないので採らない。
- 毎日のバックアップから戻す操作も今回まとめて作る: 日付を選ぶ画面と、戻す前の今のファイルの残し方を別に決める必要があるので、今回は作らない（未確定）。

## 影響

- `crates/household-store`: `PreviousGeneration`・`previous_generation`・`open_previous`・誤りの符号 `E_STORE_NO_PREVIOUS`。開く操作の復号と変換を `decode_household` にまとめた（動きは変えない）。テストは、空・半分・1バイト欠け・頭の9バイト・ゼロ埋めの5通りで開き直せること、`.prev` が無い・壊れているとき、今のファイルが開けるとき、応答にパスが無いことを確かめる。
- `app/src-tauri`: 命令2つと許可。
- `app/src/workspace`: `store/PreviousPanel.tsx`（勧める画面）、`App.tsx` の開く操作、`store/HouseholdPanel.tsx` の `openMessage`。テスト `app/test/store-open-failure.test.ts`。
- 世帯ファイルの形式の版・本文・`IPC_VERSION` は変えない。
