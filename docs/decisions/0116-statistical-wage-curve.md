# 0116. 統計の年齢カーブ（賃金構造基本統計調査の性別・学歴・企業規模の昇給カーブを、詳細で選べるようにする）

- 状態: 採用（一部未確定）（2026-11-03）
- 固定の強さ: 値ID の形 `wageStats.curve.<雇用形態>.<性別>.<学歴>.<企業規模>` は骨格（世帯ファイルの `salary.growth.curve` に書く値で、登録簿に載せた ID は消さない。0004）。既定の昇給の入れ方を前提の賃金上昇率だけのままにすること（統計の年齢カーブは詳細で選んだ期間だけ）は、β公開の後に比べて決めるまでの決まり（下の未確定）。係数の作り方（労働者数の下限・60歳以後の扱い・どの段を1にするか）は内部（変えるときは値の `rev` を足し、`docs/estimates-review.md` の行を直す）。欄の名前・並び・初めの選び方・効き方の文は後から変えてよい
- 前提にする記録: 0007（制度データ・マスタデータの形）、0008（世帯のデータモデル。2026-10-26 の追記の2: 年齢の賃金カーブは既定にせず詳細で選んだときだけ）、0040（期間ごとの伸び）、0047（働き方と収入）、0078（標準の欄。性別の欄）、0111（事務所の推定の値）

## 背景

- 利用者の判断: 働き方と収入の昇給の既定値として、賃金構造基本統計調査（厚生労働省。年齢×性別×企業規模×学歴）の統計値をマスタデータに持つことを、β公開までの作業にする。年齢の賃金カーブを既定にするかは、β公開で使ってもらって比べてから決めるので、それまでは詳細で選べるだけにする。
- 計算エンジンの給与の部品（`income.salary`）は、働き方の期間に昇給カーブ（`salary.growth.curve`。年齢ごとの係数の段階表の値ID）を書くと、その年の12月31日の年齢の係数と前の年の係数の比を、前提の賃金上昇率の伸びに掛ける（0008 の追記）。読めるカーブは `wageStats.default`（正社員・正職員・男女計・学歴計・企業規模計。60歳以後も下がる）の1つだけで、画面に選ぶ欄は無かった（入っている期間を見せるだけ）。
- マスタデータの年齢階級の表（`wageStats.byAge.*`）は、雇用形態・性別・企業規模ごとの学歴計だけだった。原本の統計表（雇用形態別 第1表）には学歴（中学・高校・専門学校・高専・短大・大学・大学院）の内訳もある。

## 決定

### 1. マスタデータ: 統計の年齢カーブの係数（96値。`master.wageStats` 2026.3.0）

- 値ID: `wageStats.curve.<regular|nonRegular>.<all|male|female>.<学歴>.<all|large|medium|small>`。学歴は `all`（学歴計）・`juniorHigh`（中学）・`highSchool`（高校）・`vocational`（専門学校）・`juniorCollege`（高専・短大）・`university`（大学）・`graduate`（大学院）。企業規模は企業規模計（10人以上）・1,000人以上・100〜999人・10〜99人。
  - 正社員・正職員（`regular`）は性別3×学歴7×企業規模4の84値。正社員・正職員以外（`nonRegular`）は学歴計だけの性別3×企業規模4の12値。
  - 値の形は `wageStats.default` と同じ（`unit: rate`・`kind: bracketTable`・`basis: incomeYear`・`upTo` が年齢階級の上限の年齢、`rate` が係数。小数4桁の10進の文字列）。
- 出典: 厚生労働省「令和7年賃金構造基本統計調査」一般労働者 雇用形態別 第1表「雇用形態、年齢階級別きまって支給する現金給与額、所定内給与額及び年間賞与その他特別給与額」（民営事業所・産業計）の統計表の Excel（e-Stat。正社員・正職員計 `statInfId=000040421141`、正社員・正職員以外計 `statInfId=000040421142`）。原本は 2026-10-26 に取得して非公開のリポジトリに置いたもの（0021）。2026-11-03 に e-Stat から取得し直し、指紋（sha256）が同じことを確かめた（同じ写しなので、写しは足していない）。令和8年調査はまだ公表されていない（e-Stat の一覧の最新は令和7年。公表は例年3月）。各値の `sources` に URL・取得日・指紋・位置（シートの行）を書いた。
- 加工の方法（各値の `approval.note` にも書いた）:
  1. 年齢階級（〜19歳・20〜24歳…55〜59歳）ごとの年収 ＝ きまって支給する現金給与額（月額。残業代などを含む）×12 ＋ 年間賞与その他特別給与額（千円）。
  2. 労働者数が1,000人（表の100十人）に満たないか値の無い階級は使わない。最初に使える階級を1とし、それより若い階級も1、途中の使わない階級は1つ若い階級の係数のまま（今の表では途中の階級に当たる組は無く、当たるのは若い階級だけ）。
  3. 係数 ＝ 各階級の年収 ÷ 最初に使える階級の年収（小数4桁に四捨五入）。
  4. 60〜64歳・65〜69歳・70歳〜の3つの階級は55〜59歳の係数のまま（伸ばさない・下げない）。
- 照合（`approval.method: reviewed`・`paths: 2`）: ① 統計表の Excel のセル（表頭の企業規模と表側の性別・学歴・年齢階級で引く）。② 年齢階級の値を労働者数で重み付けした平均が年齢計と表示の桁の丸めの範囲で一致（使った96の組の、きまって支給する現金給与額と年間賞与のずれは最大0.06%）。あわせて、同じ読み方で学歴計の年齢階級の表（前からある `wageStats.byAge.*` の384段）と `wageStats.default` の係数がすべて同じになることを確かめた。
- `wageStats.default` は変えない（59歳までは `wageStats.curve.regular.all.all.all` と同じ係数、60歳以後は下がる）。画面からは選ばないが、入っている期間は今までどおり計算し、欄に「前の版の表で増やす（正社員・男女計・60歳以後も下がる）」として見せる。

### 2. 計算エンジン

- `income.salary` の改訂を 7 にし、読める値ID（`params`）に上の96値を足した。計算の仕方は変えていない: 入力の年収（期間の最初の年。計算基準年より前なら計算基準年の額）から、毎年「1＋前提の賃金上昇率」と「その年の12月31日の年齢の係数 ÷ 前の年の係数」を掛ける。つまり将来の年収 ＝ 今の年収 × 将来の年齢の係数 ÷ 今の年齢の係数 × 賃金上昇率の累積。
- 統計の年齢カーブは同じ年の年齢ごとの差（横断面）なので、物価・賃金の全体の伸び（賃金上昇率）とは別に掛ける。「この期間の伸び（年率）」とは両方は書けない（0040 のスキーマのまま）。

### 3. 画面: 詳細の働き方の期間の「統計の年齢カーブで増やす」

- 給与の期間のうち、正社員（正社員・正職員の表）と契約・嘱託（正社員・正職員以外の表）にだけ出す。詳細の欄（標準の「今の働き方」の「▸ 詳しく」にも、その期間の詳しい欄として出る）。パート・公務員・役員には出さない（期間に既にカーブが入っていれば、見せて「使わない」に戻せる）。
- 欄（当て先はどれも期間の `employment.salary.growth` の `curve`）:
  - **統計の年齢カーブで増やす**: 使わない（前提条件の賃金上昇率か「この期間の伸び（年率）」で伸ばす）／男女計の表で増やす（性別を使わない）／男性の表で増やす／女性の表で増やす。その人の性別の選択肢に「（この人の性別）」と添える。選ぶと値ID を書く。使っているときは効き方の文（「係数 45歳 2.39 → 55〜59歳 2.55（今の年収の1.07倍まで。前提条件の賃金上昇率の分は別に伸ばします。60歳以後は伸ばしません）」）と、性別の表がその人の性別と違えば「この人の性別（男性）と違う表です」を添える。
  - **年齢カーブの学歴**（正社員だけ。使っているとき）: 学歴計（分けない）・中学・高校・専門学校・高専・短大・大学・大学院。
  - **年齢カーブの企業規模**（使っているとき）: 企業規模計（分けない）・1,000人以上・100〜999人・10〜99人。勤め先の従業員数が入っていれば「勤め先の従業員数（300人）なら「100〜999人」」と添える（従業員数から自動では選ばない）。
- 初めの選び方は男女計・学歴計・企業規模計（選んだ性別の表だけ。学歴・企業規模は後で選ぶ）。性別・学歴・企業規模のどれを選び直しても、ほかの2つは残す。
- 「この期間の伸び（年率）」を入れると年齢カーブの代わりになる（今までどおり）。率の欄の説明に「入れると統計の年齢カーブは使いません」、カーブを使っているときの空欄の文を「空欄: 統計の年齢カーブ（年齢の係数の比）と前提条件の賃金上昇率」にした。
- **性別の扱い**（0078 の性別の欄）: 性別は標準では本人だけで、配偶者は本人の逆を推定の印で入れて詳細で直す。年齢カーブを性別の表で選ぶと、配偶者の性別が推定のままのこともあるので、性別を使わない男女計の表を選べるようにし、初めの選び方にした。性別の表は FP が明示して選ぶ（構成員の性別が変わっても値ID は変えない。違えば欄に知らせる）。
- **働き方の種類を変えたとき**（`convertPeriod`）: 正社員⇄契約・嘱託は同じ性別・企業規模の表に移す（正社員・正職員以外の表は学歴計なので、学歴は学歴計になる。戻しても学歴計のまま）。カーブを選べない種類にしたら外す（前提条件の賃金上昇率に戻る）。`wageStats.default` も正社員・男女計・学歴計・企業規模計として移す。

### 4. 事務所の推定の値（0111）

- 96値も事務所の既定値の画面の一覧に載る（マスタデータの値は全部載せる決まり）。数が多いので、まとまり「昇給カーブ」を足して `wageStats.default` と一緒にそこへ置いた（名前は「統計の年齢カーブの係数（正社員・男性・大学・1,000人以上。詳細で選んだときだけ使う）」の形）。事務所の値にすると、そのカーブを選んだ期間の計算に効く（計算のときに引く目安と同じ。0111 の2）。

### 5. 既定は変えない

- 新しい世帯・見本の世帯・前に保存した世帯のどれにも、統計の年齢カーブを書き足さない（世帯を開いて欄を作っても書かない）。見本の世帯（51件）の計算の結果（`flows`・`annual`）は、前のエンジンと同じであることを確かめた。

## 理由

- **係数をマスタデータに持つ（年収の額でなく）**: エンジンの昇給カーブは係数の段階表を値ID で読む形（0008 の追記）で、世帯ファイルにはその値ID を書く。係数にすれば、エンジン・画面・事務所の値の仕組みを変えずに使える。年収の額の表は、推定（今の年収の目安）に使う学歴計の表（`wageStats.byAge.*`）が既にある。
- **値ID を組ごとに分ける（条件のキーにしない）**: 学歴・企業規模の条件のキー（0007 の `conditions`）は無く、足すと形式の版が変わり、世帯の入力にも学歴・企業規模の欄が要る。値ID に入れれば、世帯は1つの値ID を書くだけで済む（0007 の追記の「別の値 ID にして、部品のみなしで選ぶ」と同じ考え）。
- **正社員・正職員以外は学歴計だけ**: 学歴と企業規模を重ねると労働者数の少ない階級が多く（大学院・中学・高専・短大で、働く年齢の階級に推計の労働者数が数十人〜数百人の組がある）、隣の階級との比が0.5〜2.4倍に跳ぶ。契約・嘱託の年収は年齢でほとんど伸びないので、学歴で分ける意味も小さい。
- **労働者数の下限**: 推計の労働者数が少ない階級は、標本が少なく年ごとに大きく動く。下限は、正社員・正職員の働く年齢（20〜59歳）の階級の多くを残しつつ、跳びの大きい階級を外せる1,000人にした。当たるのは若い階級だけで、その年齢では伸ばさない（係数1）ことになる。
- **60歳以後は伸ばさない**: 統計の60歳以後の階級には、定年後の再雇用で下がった賃金が入る。定年後の下がり方は、働き方の期間の定年後の予定（再雇用の年収の割合。0047 の3）で入れるので、カーブでも下げると二重になる。60歳以後も同じ勤め先で同じ働き方を続ける期間（定年が65歳など）に、平均の下がり方を当てないためでもある。
- **最初に使える階級を1にする**: 係数は比でしか使わないので、どの段を1にしても計算は同じ。`wageStats.default` と同じ「最初の段を1」にそろえ、大学・大学院などの値の無い若い階級は1にした。
- **男女計を初めの選び方に**: 性別の表は男女の差（女性の表は年齢で伸びが小さい）をそのまま将来の年収に入れる。配偶者の性別が推定のままのこともあり、FP が選んでから使うほうがよい。
- **既定にしない**: 利用者の判断（β公開で比べてから決める）。年齢カーブは、年齢ごとの横断面の差で、同じ人が年を取ったときの伸び（縦断）とは違う（昇進しなかった人・転職した人も入る）。既定にすると、前提の賃金上昇率だけで見てきた結果と大きく違う世帯が出る（正社員・男性・学歴計・企業規模計の表で、55〜59歳までに今の年収の、45歳なら1.07倍、30歳なら1.35倍。賃金上昇率の分は別）。

## 影響

- 世帯ファイルの形は変えない（`salary.growth.curve` は前からある欄。形式の版は上げない）。
- 計算の結果は、統計の年齢カーブを選んだ期間だけ変わる（見本の世帯は変わらない）。選ぶと、その期間の給与・賞与が年齢で伸び、社会保険料（標準報酬月額を空欄にしている期間）・税・厚生年金・退職後の資産も変わる。
- 推定の目安の写し（`hearing/src/statistics.generated.ts`）が約100KB 増える（96値の段階表。画面の束に入る）。
- テスト: `engine/test/lifeplan.test.ts`（性別・学歴・企業規模の表の係数の比・60歳以後は伸ばさない・96値を部品が読める）、`hearing/test/estimates.test.ts`（値ID の作り方と読み方・96値がそろう・`wageStats.default` と59歳まで同じ）、`app/test/wage-curve.test.ts`（既定は使わない・見本の世帯に書き足さない・選ぶと値ID と当て先・学歴と企業規模・性別の知らせ・率の欄との入れ替え・働き方の種類を変えたとき・前の版の表）。

## 未確定（β公開の後に決めること）

- **年齢の賃金カーブを既定にするか**（β公開で前提の賃金上昇率だけの場合と比べてから。既定にするなら、新しい世帯だけか、推定のままの年収の期間にも入れるか、性別の表を使うか）。
- 学歴を構成員の欄として持つか（退職金の目安の学歴 `retirementBenefits[].education` と合わせるか）。勤め先の従業員数から企業規模を選ぶか（今は知らせを添えるだけ。従業員数の初めの値は推定の印の無い仮の値のため）。
- 年齢階級の段差（5歳ごとに一度に伸びる）を、階級の真ん中の年齢でつないで毎年なめらかに伸ばすか（エンジンの読み方を変えるので、部品の改訂と結果の差を見てから）。
- 公務員（国家公務員の行政職俸給表（一）の年齢階層別の平均給与月額 `wageStats.civilServant.monthlyByAge` から作れる）・パート（短時間労働者の表）のカーブ。
- ヒアリングシート・事務所の既定値（新しい世帯の初めの昇給の入れ方）から選べるようにするか。
- 令和8年調査（2027年3月ごろの公表）を取り込むとき、新しい行（`rev`）を足すか、値ID を年で分けるか（世帯に書いた値ID の係数が黙って変わるため）。

## 追記

- 2026-11-03（人の属性で推定の数字を分けない。詳しくは 0118）: 利用者の判断で、統計の年齢カーブを**男女計・学歴計の表だけ**にした（決定の1・3・4を改める）。
  - マスタデータ（`master.wageStats` 2026.4.0）: 係数は男女計・学歴計の8値（`wageStats.curve.<regular|nonRegular>.all.all.<all|large|medium|small>`。値は前と同じ）だけにし、性別・学歴で分けた88値を外した（登録簿は `removed`・`replacedBy` に男女計・学歴計の同じ企業規模の値ID）。値ID の形は変えない（性別・学歴の位置は `all`）。
  - エンジン: `income.salary` の改訂を 8 にし、読める値ID を8値にした（前の値ID は読めない）。
  - 画面: 「統計の年齢カーブで増やす」は「使わない／統計の年齢カーブで増やす」の2つ。「年齢カーブの学歴」の欄・性別の表の選択肢・「この人の性別と違う表です」の知らせをなくした。企業規模の欄は残す（人の属性でなく勤め先の属性）。種類を変えたときは同じ企業規模の表に移す。
  - 事務所の推定の値のまとまり「昇給カーブ」は8値と `wageStats.default`（名前から性別・学歴を外した）。
  - 前の世帯: 形式 0.58 の変換の段が、性別・学歴の表の値ID を同じ雇用形態・企業規模の男女計・学歴計に直す（控えは画面が計算するときに直す）。
  - 未確定のうち「性別の表を使うか」「学歴を構成員の欄に持つか」は、使わない・持たないに決めた（0118 の決まり）。
