# 0252. 資産配分の割合の表を作り直す: 選べる資産の種類・GPIF の基本ポートフォリオの既定・事務所の既定の割合・資産の種類ごとの信託報酬と、世帯ファイルの形式 0.89

- 状態: 採用（2026-11-23。2026-11-24 に未確定を決めた）
- 固定の強さ: 骨格は、資産の種類のキー（前の `equity.global`・`bond.global` を先進国と読む・新しい `equity.emerging`・`bond.emerging`）、要求の欄 `assumptions.investment.allocation.fees`（資産の種類 → 年率）の名前と意味（無い種類は前の版の `fee`、それも無ければ0）、事務所データの欄 `assetMix` の名前と意味、形式 0.89 の変換の段。既定の割合（GPIF の基本ポートフォリオ）・目安の値・相関・表の並び・画面の言葉は後から変えてよい（変えたら追記に書く）
- 前提にする記録: 0026（資産運用の入れ方）、0040（資産配分の段階）、0111（事務所の推定の値）、0137（資産配分を計算に渡す・預金の利回り）、0177（割合の合計で割って按分する）、0214（前提条件の事務所の既定値）、0011・0035（世帯ファイルの形式の版の上げ方）、0036（プランの差分）

## 背景

- 入力の「貯蓄・運用」の資産配分の表は、国内株式・外国株式・外国債券・外国REIT・預金の5種類に固定で、既定の割合（25%・40%・20%・5%・10%）はコードに直書きだった。国内債券・新興国・国内REIT・コモディティ・外貨預金は、前提条件の利回りにはあっても割合の表で選べなかった。
- 信託報酬は配分全体で1つ（平均の欄）だった。投資信託の信託報酬は資産の種類で大きく違う（先進国株式の指数の物と新興国債券の物など）ので、FP は頭の中で平均を出して入れていた。
- 事務所の既定値で決められるのは資産の種類ごとの利回りまでで、割合と信託報酬は世帯ごとにしか決められなかった。

## 決定（利用者の判断）

### 1. 割合の表で選べる資産の種類

- 株式（国内株式・先進国株式・新興国株式）、債券（国内債券・先進国債券・新興国債券）、REIT（国内REIT・外国REIT）、コモディティ（金など）・預金・外貨預金の11種類（`app/src/workspace/input/savings/model.ts` の `CLASSES`）。バランス型・不動産・その他は割合の表に出さない（前提条件の「資産の種類ごとの利回り」には残す。資産配分の段階の資産の種類の選択肢からも外すが、前の版で入れた段の値はそのまま見せる）。
- 前の「外国株式」「外国債券」は「先進国株式」「先進国債券」と読み替える。**キーは変えない**（`equity.global`・`bond.global` を先進国として残し、新興国を新しいキー `equity.emerging`・`bond.emerging` で足した）。理由:
  - キーは、世帯の前提条件の利回り（`assumptions.assetReturns`）・値動きの大きさ・相場の下落の種類（`marketShocks[].assetClasses`・ストレステスト）・口座ごとの配分（`accounts[].assetMix`）・利回りの段階・プランの差分の場所・事務所データの `assetReturns`・事務所の推定の値の値ID（`preset.invest.equity.global.*`）・前提条件の欄の id（AI接続口の名前。0214 で「使い回さない」と決めた物）・欄の読み替え表（0.16 の凍結の表を含む）の全部で使っている。付け替えると、これら全部の移行が要り、凍結した読み替え表と前の版の控えは書き換えられない。
  - 前の「外国株式」の目安（期待リターン 6%・値動き 20%）は、もともと先進国の指数を思って入れた値で、読み替えても意味が変わらない。名前（`labels.ts` の `ASSET_CLASSES`）だけを直したので、計算の結果はどの世帯も変わらない。
- 前提条件の「資産の種類ごとの利回り」も同じ名前（先進国株式・先進国債券・新興国株式・新興国債券・コモディティ〔金など〕）で、14種類を並べる。計算エンジンの資産クラスの一覧（`engine.input.json` の `assetClass`）に新興国の2つを足した。

### 2. 割合の既定（GPIF の基本ポートフォリオ）と事務所の既定値

- 提供元の既定は GPIF の基本ポートフォリオ（国内債券・外国債券・国内株式・外国株式を25%ずつ）。外国は先進国に読み替える（`GPIF_MIX`）。
- 事務所の既定値の画面の「前提条件の既定値」に「資産配分の資産の種類ごとの割合」の区画を足した。11種類を並べ、割合と信託報酬（年）を入れる。割合が全部空欄なら提供元の既定（GPIF）。入れるときは合計を100%にする（合わなければ欄の下に「合計を100%にしてください（今は○%）」と出し、保存できない）。
- 事務所データに足すだけの欄 `assetMix`（種類と割合〔小数の文字〕の並び。表の11種類だけ・同じ種類は1つ・合計が100%）を足し、形の版を 5 にした（`office/settings.ts`。前の版の事務所データはそのまま読む）。割合は世帯に写さない。**割合をまだ持たない世帯**（資産配分の入れ方にしていない世帯・前の版で資産配分にしたが割合の無い世帯）が資産配分にするときに、その時点の事務所の割合（無ければ GPIF）で始める（`defaultMix`）。割合を持っている世帯は変えない（作った世帯は黙って変えない。0073 の3）。
- 前の直書きの既定（25%・40%・20%・5%・10%）はなくした。割合を持たないまま資産配分の入れ方にした世帯は、新しい既定で計算する（結果が変わってよい。利用者の判断）。

### 3. 資産の種類ごとの信託報酬

- 信託報酬は資産の種類ごとに持つ（要求の `assumptions.investment.allocation.fees`。資産の種類 → 年率）。表に「信託報酬（年）」の列を足し、全体の信託報酬は入れる欄をやめて、アプリが割合でならした値を読むだけにした（表の合計の行に「割合でならすと 0.14%」、表の下に「信託報酬（割合でならすと） 0.14%」）。
- 計算エンジン（`engine/src/engine/investment.ts`）: 資産配分の入れ方で、配分（段階の配分も）の行ごとに信託報酬を写し、器の利回り（`sdk/helpers.ts` の `accountReturnRate`）で行の利回りから引いてから割合でならす（＝割合でならした信託報酬を引く。段階はその段の割合で、リバランスしないときはずれた割合で）。`fees` に無い種類は前の版の配分全体の値 `fee`、それも無ければ0。
- **どの行も同じ信託報酬なら、行に書かずに器の信託報酬（前の版の `fee` と同じ計算の道）にする。** 前の版の世帯の移し方（下の5）で全部の種類に同じ値を入れた世帯は、計算の道が前の版と同じになり、結果は1円も変わらない（率の計算は小数12桁で丸めるので、割合でならした値と元の値が丸めで食い違わないようにした）。エンジンのテスト（`engine/test/investment.test.ts`）で、リバランスしない・段階のある配分も含めて前の版と同じ額になることを確かめる。
- 種類ごとの信託報酬の目安は事務所の推定の値（0111）の `preset.invest.<種類>.fee`（ひな形）。事務所の既定値の画面の新しい区画の「信託報酬」の列は、この値を読み書きする（「推定の値（統計・目安）」の区画と同じ値。置き場所を2つにしない。0214 の土地の割合と同じ考え方）。新しく割合の表に足した種類・割合をまだ持たない世帯が資産配分にするときに、その種類の目安を世帯に書く。世帯で空欄にすると目安に戻す。
- 前の配分全体の目安 `preset.invest.fee`（0.25%）はなくした。上書きしていた事務所の値は、読むときに知らない値ID として捨てる（新しく資産配分にする世帯から、種類ごとの目安を使う）。

### 4. 表の操作

- 表には今の配分の種類だけを並べる（表の種類の並び）。表の下の「＋ 資産の種類を足す」で、見出し（株式・債券・REIT・コモディティ・預金）ごとの一覧から選ぶと、割合0%の行を足す（信託報酬は目安、期待リターンは目安を推定の印で計算に渡す。0137 と同じ）。行の右の「外す」で外す（1行だけのときは出さない。段階の配分に無い種類は信託報酬も外す）。
- 割合の入力の動きは今の決まりのまま: 1行の割合を直すと、ほかの行と合わせて合計で割った割合にする（0177）。今回、割り直した割合の端数（小数第4位）は最も大きい行で合わせ、合計がちょうど100%になるようにした（前は端数で合計が99.9%と出て、合計の行が赤くなることがあった）。表の合計の行は丸める前の割合の合計で出す。
- 0%の行は残す（前は0%にすると外れた。外すときは「外す」）。全部0%にしたら既定の割合に戻す（前と同じ）。
- 内訳のドーナツ（資産の種類ごと）は、割合の表に預金の行が無くても預金の口座を「預金」に出す。

### 5. 世帯ファイルの形式 0.89（形を変える MINOR。0251 の 0.88 の後）

- 足した欄: `assumptions.investment.allocation.fees`（任意）と、資産の種類の新興国の2つ。前の版のアプリは計算の入力の検査で知らない欄・知らない種類を通さないので、版を上げて閲覧だけにする。
- 変換の段（`crates/household-store/src/migrate.rs` の `v0_88_to_0_89`）: 配分全体の信託報酬 `allocation.fee` を持つ世帯は、その値を**割合の表の11種類と、配分（段階の配分も）に出てくる種類の全部**に入れた `fees` に移し、`fee` を外す（「今まで平均の欄に値を入れていた世帯は、その値を全種類に入れて結果が変わらないように移す」。利用者の判断）。全部の種類に入れるのは、あとで足した種類・プランの差分の配分に出てくる種類も同じ値で計算するため。
- プランの差分（入力項目 `assumptions.investment`）: 場所 `["allocation", "fee"]` は `["allocation", "fees"]` にし、値と前の値の箱の中の率を同じく `fees` にする（種類は今の世帯の配分の種類も入れ、前の値は今の世帯と同じ形にする。プランの見直しで「変わった」にしない）。場所 `["allocation"]`・`[]` は、値と前の値の中の配分を同じく移す。割合だけの差分・ほかの入力項目の差分は変えない。
- 控え（`snapshots`）と自分で作った見本の最初の状態（`sampleInitial`）の中身は変えない（0011 の5・0247）。計算エンジンは前の版の `fee` も読むので、控えはそのまま計算できる。
- 信託報酬の無い配分（`fee` も `fees` も無い）は書き足さない（前の版と同じく引かずに計算する。資産配分の表は「信託報酬が、まだ計算に入っていません」と出し、「表の値で計算する」で目安を入れられる）。
- 見本 `0.89/`（先進国株式・新興国株式・国内債券の配分と種類ごとの信託報酬）。

### 6. 目安の値（推定）

- 11種類の期待リターン（信託報酬を引く前）・値動きの大きさ・信託報酬の目安を `hearing/src/presets.ts` に置いた（`preset.invest.<種類>.return`・`volatility`・`fee`。外貨預金は期待リターンの目安を持たない〔預金の利回りで計算する〕）。**どれも原本の統計・商品の公表の値で確かめていない仮の値（相場の目安）**で、根拠の文にもそう書いた。前の「外国株」「債券」「REIT」「現金」の値は変えず、名前だけ直した。一覧は `docs/estimates-review.md` の10章。
- 資産の種類の間の相関の目安（55組）は `presets.ts` の `investCorrelation`（表の「値動きの大きさ」を組み合わせるときだけに使う。計算には使わない）。数が多く事務所の推定の値の画面が埋まるので、事務所では変えられない値にした（`docs/estimates-review.md` の「一覧に入れていない値」）。組み合わせた値動きの大きさは、相関の目安が食い違って負になっても0で止める。

## 決めたこと（2026-11-24。利用者の判断）

- 先進国債券の目安（期待リターン 1%・値動きの大きさ 5%）は、次の目安の見直しで根拠を確かめて直す（それまでは今の値のまま。直すと推定のままの世帯の期待リターンの推定が変わることを、見直しのときに知らせる）。
- 新しく足した種類（新興国・国内REIT・コモディティ・外貨預金）の目安と相関の目安は、指数の提供元が公表する値で根拠を書く（次の目安の見直しで。それまでは「確かめていない仮の値」のまま）。
- 事務所の既定の割合を変えても、割合を持っている世帯には知らせない（割合は前提条件と違い世帯ごとに決める物。作った世帯は黙って変えない〔0073 の3〕のまま）。
- 万一の「相場が下がったとき」の既定で下げるのは株・REIT だけ（新興国株式は入れる。新興国債券は下げない）。
- 事務所が前の配分全体の目安 `preset.invest.fee` を上書きしていた値は、知らせずに捨てる（3 の決定のまま。β公開の前で、使っている事務所が無いため）。

## 追記（2026-11-24。点検の直し）

- 口座の運用の費用との関係: 口座ごとの入れ方で口座に入れた「運用の費用（年）」（`accounts[].fee`）は、資産配分にしても消さずに残る（前からの決まり）。前の版は配分全体の信託報酬がいつも口座の費用を上書きしていた。この記録の最初の形は、種類ごとの信託報酬が1つでも違うと行ごとに引いたうえで口座の費用も引いていた（二重）。前の版どおり、種類ごとの信託報酬がある配分は口座の費用をいつも上書きする形に直した（行に書いたときは器の費用を0にする。`engine/src/engine/investment.ts` の `allocationFees`）。エンジンと画面のテストで、口座に費用1%が残った世帯が二重に引かないことを確かめる。
- 移行（形式 0.89）で、AI からの候補の差分（`candidates[].diffs`。値を箱に入れずに持つ）の `["allocation", "fee"]`・`["allocation"]`・`[]` も、プランの差分と同じく移す。`fees` に入れる種類には、プランと候補の資産運用の差分に出てくる種類（プランで足した段階の配分のバランス型・不動産・その他など）も数える（その種類だけ信託報酬が0になって結果が変わるのを防ぐ）。
- 万一の「相場が下がったとき」の既定の下げる種類にも新興国株式を入れ、貯蓄・運用の側（株などの割合・ストレステスト）と1か所（`input/labels.ts` の `RISKY_ASSET_CLASSES`）にそろえた。新興国債券は下げる種類に入れない（利用者の判断。上の「決めたこと」）。
- 入力のホームの「探して開く」に、新興国・先進国・REIT・コモディティ・信託報酬などの言葉を足した。AI接続口の説明（`docs/ai-connector.md`）の資産の種類の一覧に新興国の2つを足した。
