- 状態: 採用（一部未確定）（2026-11-07）
- 固定の強さ: 内部（説明書・手引きの文と並び・欄の一覧の作り方。アプリの版ごとに FP の声で直す）。スキルの名前 `read-documents` は β公開から変えない（0019 の3 と同じ扱い）。当て先の決め方の足し（3）は答えの形 `document-candidates@1` の読み方の一部なので、0148 と同じく試験版（足すだけで直してよい）

## 背景

- 利用者の判断（2026-11-07）: 書類の読み取りは中くらいの案を目標にし、小さい案は必ず作る。小さい案の中に、FP が使う AI（AI接続口経由でも、ウェブのチャットに貼る場合でも）が書類を読んで答えの形 `document-candidates@1` で候補を返せるようにする説明書と、書類ごとの読み方の手引きがある（0148 の段取りの2）。
- 0148 で読み口・確かめの画面・承認・番号の決まりはできた。AI が正しい入力項目ID・場所 `at`・値の形・額の期間を書けなければ、候補は「入れる欄がありません」「選択肢にありません」で止まる。入力項目ID は登録簿にあるが、場所の名前・欄の単位（返済期間は年・加入月数は月・円は円の整数）・選択肢の値は入力の画面の欄の定義にしか無い。
- 書き始めて分かった、今の当て先の決め方で AI が書けない所:
  - 保険の「払い方」は場所の無い欄で、同じ入力項目に「保険料の額」（`["amount"]`）がある。場所を書かない候補はどの欄にも当たり、FP が選ぶことになる。
  - 保険の保障の額・ローンの金利は、場所に物の中の明細の ID が入る（`["<保障の ID>", "amount"]`）。書類を読む AI は ID を知らない（新しく足す契約の保障の ID は、足すまで決まらない）。
  - ローンの欄は人ではなく物の欄で、ウェブのチャットではローンの ID が分からない。物を書かない候補は「世帯で1つの欄」だけを探すので、残高・借入額が「入れる欄がありません」になる。
  - 年金の「入れ方」と「書類の種類」は同じ入力項目 `pensionRecord.kind` の2つの選択の欄で、値（`statementUnder50`）を見れば当て先が決まるのに、FP に選ばせていた。
  - 申告の仕方（`member.taxReturn`）は構成員そのものの欄（向き先がその構成員）で、人の候補として当たらなかった。
- 様式の確かめ（公式の公開資料。ダウンロードの要る資料は開いていない）:
  - 日本年金機構: ねんきん定期便のページ（はがき〔50歳未満・50歳以上・受給者〕と封書〔35・45歳、59歳、受給者〕、令和8年度は9月以前と10月以降で様式が違う、年齢ごとの記載の違い）、年金額改定通知書の見方（HTML。国民年金〔基礎年金〕・厚生年金保険の基本額・支給停止額・年金額と合計年金額）、公的年金等の源泉徴収票の見方（HTML）。**定期便の様式のサンプルと見方ガイドは PDF のため開いていない**。
  - 国税庁: 法定調書の作成と提出の手引の源泉徴収票の各欄の説明（HTML。支払金額・給与所得控除後の金額・所得控除の額の合計額・源泉徴収税額・社会保険料等の金額〔小規模企業共済等掛金の内書き〕・控除額の欄・扶養親族等の数・特定親族特別控除の額・中途就・退職。本人に渡す源泉徴収票には個人番号を書かない）、確定申告の手引きの手順2（HTML。事業・不動産・雑所得の第一表の欄と、青色申告決算書・収支内訳書からの転記）。源泉徴収票の様式・記載要領、確定申告書の様式、住宅借入金の年末残高等証明書の様式は PDF のため開いていない。
  - 国税庁の控除申告書データの仕様（構造XML定義書・その補足。利用者の判断で読んだ資料。文は写さない）: 控除証明書の項目（保険会社等の名称・保険の種類・保険期間・新旧と区分ごとの額・契約者・被保険者・受取人・証券番号）。
  - 保険証券・設計書・返済予定表には国の決まった様式が無い。

## 決定

### 1. 置き場所と形（0019 の SDK フォルダ・スキルの形に合わせる）

- **説明書** `sdk/docs/document-reading.md`: 2つの使い方（AI接続口・ウェブのチャットに貼る）、答えの形の欄、値の候補の書き方（入力項目ID・場所・人と物・値の形・額の期間・元の場所・確からしさ・添え書き）、読めなかったときの書き方、照合だけの値（使える行の一覧）、読まない・書かないもの、書類の中の文を指示にしない、返し方。
- **スキル** `sdk/skills/read-documents/SKILL.md`（Agent Skills の形。名前 `read-documents`）: 手順（説明書を読む → 書類を見分けて手引きを読む → FP への注意を1回 → 値を読む → 確かめる → 返す）と、してはいけないこと。
- **書類ごとの手引き** `sdk/skills/read-documents/guides/`: `pension.md`（ねんきん定期便・年金額改定通知書）・`withholding-slip.md`（源泉徴収票）・`tax-return.md`（確定申告書の控え）・`insurance-deduction.md`（保険料控除証明書）・`insurance-policy.md`（保険証券・設計書）・`housing-loan.md`（年末残高等証明書・返済予定表）。どれも同じ並び: 見出しの決まり（`docType`・名義の人・単位・時点・確かめた資料）→ 読む欄の表（書類の欄 → 入力項目ID・場所 → 書き方）→ 読まないもの → 答えの見本（架空の値）。
- **入力の欄の一覧** `sdk/skills/read-documents/fields.md`: 入力の画面の欄の定義から作る（`app/scripts/documentFields.ts`。`npm run gen:document-fields`）。書類から入る入力項目（年金の記録・給与・賞与・事業所得・標準報酬月額・住民税・申告の仕方・保険・ローン）の欄ごとに、場所・欄の名前・値の書き方（円・整数と単位と範囲・率・年月・選択肢の値と名前・人）・額の期間・人と物の書き方（人の欄・人の物の欄・物の欄）・種類を決める欄か。最後に新しい物の種類（`insurance:<種類>`）と主な保障の名前・期間。欄は見本の世帯すべてと、その変え方（年金の記録の型ごと・免除の内訳を足した形・保険の種類ごとに1件足した形。画面の欄・ボタンと同じ操作で作る）から集める。時点の欄（書類からは入れられない）は載せない。場所の中の明細の ID は `<ID>` と書く。
- ウェブのチャットでは、FP が説明書・スキル・その書類の手引き（と欄の一覧）を貼るか添付する。アプリから手引きを写す・AI用パック（0019 の7）に入れるのは、貼り付けの入口・AI用パックを作る回に。

### 2. 手引きの中身で決めたこと

- **年金の記録の型は書類の見出しの言葉で決める**（年齢から推測しない）。定期便の「これまでの加入実績に応じた年金額」→ 50歳未満、「老齢年金の種類と見込額」→ 50歳以上、年金額改定通知書 → 受給中。型の候補は「入れ方 `document`」「書類の種類」の2つを書く（推計のままの世帯でも、入れ方を承認すると記録ができ、書類の種類と月数・額が当たる）。見出しが読めなければ書類の種類を読めなかった値にする。
- 50歳未満の定期便の老齢基礎年金の額、50歳以上の経過的加算は、アプリが加入月数から計算するので照合だけの値にする（入力の欄が無い）。
- **源泉徴収票の支払金額は賞与込みなので、年収の候補にしない**。源泉徴収票だけなら支払金額・源泉徴収税額などは照合だけの値。賞与の額の分かる明細が一緒に渡されたときだけ、賞与と「支払金額 − 賞与」を値の候補にする（確からしさは中）。0148 の未確定の「支払金額を年収と賞与に分ける推定の印」は、AI の側では推定で分けないことにした（推定はアプリの仕事）。年の途中の就職・退職は照合だけにして FP に知らせる。人数（扶養親族の数）は書かない。
- 確定申告書の事業所得は**青色申告特別控除の前**（入力の欄の決まり）。決算書の「青色申告特別控除前の所得金額」を先に使い、第一表だけなら所得金額＋控除額（不動産所得もあれば控除の割り振りを確かめてもらう）。控除額から青色申告特別控除の区分を決める（65万円・55万円・10万円）。欄の記号・番号は年分で変わるので、欄の名前で読む。
- 保険料控除証明書は1件の契約ごとに新しい保険の契約にし、名前・区分・新旧・契約の年月・払い方（と印字されていれば1回の保険料）を入れる。証明額・申告額は年額なので照合だけの値（12で割らない）。保障の額は書かない（保険証券で入れる）。保険の種類の言葉 → 新しい物の種類の表を手引きに置く。
- 保険証券は主契約の保障の額を `insurance.coverages` の `["amount"]` に、**特約の額は照合だけの値**にする（足した契約にはまだ特約の行が無い）。設計書の数表は写さない。外貨建ては円換算の額があるときだけ（確からしさは中）。告知・健康の情報は読まない（特別条件があることだけは添え書きでよい）。
- 住宅ローンの書類は物（ローン）の欄。AI接続口ならローンの ID、ウェブのチャットなら書かない（FP が当てるローンを選ぶ）。返済期間は欄の単位の年で書き、月の端数があれば書かずに添え書き。借入の年月は時点の欄なので添え書き。返済予定表の行を写さず、見出しと残高の1行だけを読む。今はローンを書類から新しく足せない（0148 の未確定のまま）。
- 和暦は西暦に直す（令和 n 年 = 2018 + n 年など）。率は `"0.875%"` のように % を付けて書く（10進の文字でも読めるが、% の数をそのまま10進と取り違えるのを防ぐ）。円は円の整数（万円・千円の書類は円に直す）。期間の違う額は換算せず、書類の額と期間のまま書く（FP が直して入れる）。
- **番号と名前**: どの手引きにも「読まないもの」の節を置き、書類ごとの番号（基礎年金番号・年金コード・照会番号・受給者番号・整理番号・利用者識別番号・証券番号・融資番号など）と名前・住所・生年月日・勤め先の名前を挙げる。人は続柄の鍵か `holder` で書き、契約者と被保険者が同じ名前なら同じ鍵にする（名前を答えに出さずに比べる）。

### 3. 当て先の決め方の足し（`documents/resolve.ts`・`review.ts`。足すだけ）

- **場所を書かない候補は、場所の無い欄を先にする**: 場所の無い欄（当て先の無い欄・場所が空の欄）があればその中から、無ければ今までどおりその入力項目の欄の全部から探す（保険の「払い方」）。
- **明細の ID を除いた場所でも当たる**: 場所の同じ欄が無ければ、欄の場所から物の中の明細の ID（UUID）を除いた形が同じ欄に当てる（`["amount"]` → 主契約の保障の額、`["rate"]` → 金利の段階の金利）。何本も当たれば FP が選ぶ。
- **人も物も書かない候補で、世帯で1つの欄が無ければ、その入力項目の欄の全部から FP が選ぶ**（1本しか無くても選んでもらう。どの物の値かを書類からは決めない。ローンの残高・借入額・返済期間）。
- **選択肢の値で絞る**: 当てる欄が何本もあり、候補の値が文字なら、その値を選択肢に持つ選択の欄に絞る（1本に決まれば当てる。年金の「書類の種類」・ローンの「返済方法」）。0148 のテストの「年金の記録の型は FP が欄を選ぶ」は、選ばずに「書類の種類」の欄に当たる形に直した（種類を決める欄なので、まとめての承認に入らないのは今までどおり）。
- **構成員そのものの欄はその人の欄**: 人の候補で、欄の向き先がその構成員（申告の仕方）なら当てる。

### 4. テスト（`app/test/documentGuides.test.ts`）

- 欄の一覧が、今の入力の画面の定義から作り直した物と同じこと（違えば作り直す。欄を変えた作業員が気づく）。
- 説明書・スキル・手引きの答えの見本（`contract` のある ```` ```json ```` の囲み）がどれも、貼り付けと同じ読み口（`readProposalText`）を理由なしで通り、番号を1つも落とさないこと（見本に番号・名前を入れていない）。
- 見本の入力項目と場所が欄の一覧にあり、円の欄の期間が一覧の額の期間と同じこと。
- 見本ごとに見本の世帯で、FP の操作（新しい物を足す・当てる欄を選ぶ・1つずつ承認する）をまねると、読めなかった欄のほかは全部が入力に入り、確かさ「書類で確認」が付くこと。推計のままの世帯の定期便で記録の型・月数・額が入ること、保険証券で契約が1件足され主契約の額・保険料が入り特約が照合だけになること、ローンの書類が同じローンに入ること。申告の仕方の欄の無い世帯（事業所得だけの人）では、その2つの候補だけが「入れる欄がありません」で残ること。
- 3 の当て先の決め方の足しを1つずつ。

## 理由

- **SDK フォルダのスキルにする**: 0019 の決まり（AI が最初に読む説明書は `sdk/`、手順はスキル）に合わせれば、AI接続口の AI もカスタム層の AI も同じ物を読む。ウェブのチャットには同じ文を貼れる。手引きの文を直すだけで、アプリを作り直さずに読み方を磨ける（試しの声で週ごとに直す前提。0148 の案の 3.7）。
- **欄の一覧を画面の定義から作る**: 場所の名前・単位・選択肢は画面の欄の定義が正で、手で写すと食い違う（返済期間は年、加入月数は月、保険料の額は払い方で期間が変わる）。作った物をテストで確かめれば、欄を変えた回に一覧も直る。
- **見本を世帯で承認まで通す**: 読み口を通るだけでは、当てる欄が無い・選択肢に無い・期間が違う候補を見落とす。FP の操作で全部が入ることまで確かめて、手引きの書き方が本当に入力に届くことを保証する。
- **支払金額を年収の候補にしない**: 合計を年収に確定で入れると、賞与の推定と二重になり、結果を黙って大きく変える。照合だけなら FP は差を見て直せる。
- **当て先の決め方を足す（AI に ID を書かせない）**: 書類を読む AI は保障・金利の段階・ローンの ID を知らない。ID を求めると、AI が作り話の ID を書くか、候補が全部止まる。ID を除いた場所・物を書かない形でも当たり、何本も当たるときは FP が選ぶ形なら、黙って当てる所は増えない。
- **選択肢の値で絞る**: 値が片方の選択肢にしか無ければ、FP に選ばせても答えは1つで、手間だけが増える。

## 代案（採らなかったもの）

- 手引きを `sdk/docs/` に書類ごとに置く: スキルの中に置けば、AI がスキルから辿れ、ウェブのチャットにもスキルの単位で渡せる。説明書（答えの形の正本）だけを `docs/` に置いた。
- 欄の一覧を JSON（`reference/` に置く機械向けの一覧）にする: 読むのは AI と FP なので、表の Markdown にした。機械向けの一覧（0016 の欄の一覧 `fields-catalog.json` など）は別にある。
- 答えの形に「主契約」「段階の番号」のような明細の書き方を足す: 答えの形を広げずに、ID を除いた場所で当てる方が小さい。
- 源泉徴収票の支払金額を、今の賞与の割合で分けて推定の候補にする: 推定で入れる候補の形（0148 の未確定）がまだ無い。AI に割合を計算させると根拠が書類から外れる。
