# 0193. Web のヒアリングの通しの点検: 発行から取り込み・保存までの一周を決まった場合で流し、毎回同じことを確かめる

- 状態: 採用（一部未確定）（2026-11-09）
- 固定の強さ: 内部（テストの決まり。流す場合・確かめることは、ヒアリングを直すまとまりが足してよい。暗号の形・API・届いた答えの中身の形・世帯ファイルの形式は変えない）
- 前提にする記録: 0125（Web のヒアリング）、0138（お客さまの画面）、0139（取り込みで今の値を壊さない）、0158（書類の別送り・分岐の答え）、0190（書類の頼み方）、0191（受け取った書類）、0011（世帯ファイル）、0035（並びの要素の ID）

## 背景

- Web のヒアリングは、発行・お客さまの画面・書類の送り・受け取り・取り込みの部分ごとにテストがあった（`hearing/test/web.test.ts`・`app/test/hearing-web.test.ts` など）。お客さまの答えは、どれも下書きの形をテストの中で直に作っていた（画面に出ない問いの答えも作れる）。
- 開発中のアプリで発行から取り込みまで通した確かめで、部分のテストに見えない不具合が見つかった（取り込みで今の値が消える・見直しの飛ばしが働かない・数が場所ごとに違う）。
- 利用者の判断（2026-11-06）で、計画に「発行から取り込みまでの一周を流すテスト」を入れ、「今の値が消えない」「見直しで答えた所が飛ぶ」「数が合う」を毎回確かめることにした。

## 決定

### 1. 置き場所と形

- `app/test/hearing-roundtrip.test.ts`（FP の側の作業の層と、お客さまの側の部品の両方を読むので app のテスト）。
- 暗号と中継は本物の関数を通す（`issueWeb`・`openRequest`・`uploadFile`・`sendDocuments`・`submitAnswers`・`receiveWeb`・`cleanupOnServer`）。サーバーは受け付けの処理（`hearing/relay/handler.ts`）をメモリの置き場（`memoryStore`）で動かす（今のテストと同じ）。
- **お客さまは画面を1つずつ進む**（`walk`）。今の下書きで並ぶ画面の順に、その画面に出ている問い・分岐の問い・書類だけに答える。空のまま「次へ」は「あとで」（`Form.tsx` の `next` と同じ）。書類の「手元にない」は、書類の画面の中身（かわりに聞く問い）を並べ直してから答える。書類は答えの前に送る（`Form.tsx` と同じ）。前回の値（見直し）は、答え方に無ければそのまま送る。
- FP は受け取り、受け取った分をサーバーから消し、**既定のチェックのまま承認**して取り込む（FP が全部にチェックを入れる場合は、その場合の中で）。

### 2. 流す場合

| 場合 | 中身 |
|---|---|
| 1. 値の入った世帯にシンプルの票 | 夫婦と子2人・持ち家と住宅ローンの世帯（見本の棚の世帯）。年収・預貯金などを答え、粗い答え（毎月の返済額だけ）が混ざる |
| 2. 見直しの票 | 前回の値のまま確かめて送る・答えを変える（持ち家→賃貸）・ご両親のことを答える |
| 3. 「あとで」・空のまま | 一部を「あとで」、一部を空のまま「次へ」。全部をそうして FP が全部にチェックを入れる |
| 4. 書類つき | ご本人と配偶者の方の源泉徴収票・ねんきん定期便。写真を付ける・「手元にない」・「あとで送る」（答えの後に同じ URL から送る） |
| 5. 分岐の答えが今の世帯と違う | お子さま3人・1人（今は2人）、配偶者の方「いらっしゃらない」（今はいる） |

### 3. 毎回確かめること

1. **今の値が消えない**: 今の世帯の行（人・働き方・ローン・口座・保険・目標・生活費…）が1つも消えない。お答えの無い候補（「あとで」・空のまま・出なかった問いだけの物）に既定でチェックが付かない。場合ごとに、答えていない所の値が今のまま。**行が残っている所の、値のある欄が無くならない**（`lostFields`。答えた欄は値が変わってよいが、無くならない）。
2. **見直しで、答えた所（前回の値）に合わせて問いが飛ぶ**（持ち家なら家賃を聞かずローンを聞く・会社員に勤務時間を聞かない など）。答えを変えると出る問いが変わり、出なくなった問いの前回の値は送らない。
3. **数が合う**:
   - お客さまが通った画面 ＝ 送る直前の下書きで並ぶ画面（最初の画面・確かめの画面を除く）。
   - 受け取った答え ＝ お客さまが答えた問い（画面に出た問いの「あとで」でない答え。月の無い生年月は送らない）＋ 記入の年月・同意・ページが入れる「該当なし」。捨てた答えは0。画面に出ていない問いの答えは無い。
   - お客さまの最初の画面の「N画面ほど」＝ 数える前提の家族（夫婦と子2人・ご両親あり）で答えた画面の数。
   - FP の画面の「問い N画面」＝ 同じ家族でお客さまが答える画面の数（単位はお客さまの最初の画面と同じ「同意・分岐の問い・問いの画面」。書類・確かめは入れない。0192 の4）。ご両親を聞く票は、ご両親のことを「答えない」を選んだときの数も同じ。
   - 依頼の一覧の受け取った答えの数（「問いの画面 N のうち M 画面に答えあり」）＝ お客さまが通った画面の数と、そのうち答えた画面の数（0192 の4）。
4. **取り込みの後の世帯ファイルを保存して読み戻しても同じ**: アプリが開く形（推定の入れ直し・新しく足した並びの要素の ID。`App.tsx` の `openedFrom` と同じ）で本文に書き、読み戻した世帯の要求・ヒアリングの記録・推定の印・依頼の記録が同じ。もう一度書いても同じ中身。

### 4. 直す待ち

- 今ある不具合は、直すまで「直す待ち」の `it.fails` にする（まだ落ちることを確かめる。直ったのに `it.fails` のままだと落ちる）。名前に「直す待ち（直すまとまり・記録）」と理由を書く（`app/test/walkthrough` と同じ書き方）。直したまとまりが `it` にする。
- 2026-11-09 の時点の直す待ち:
  - ~~FP の画面の数え方（FP の画面の問いの数・依頼の一覧の「答え N」がお客さまの数と違う。FP の画面のまとまりで直す）。~~（2026-11-09 に 0192 で直し、`it` に戻した）
  - 取り込み（0139 の続き）: 変更の候補を承認すると、シートで聞かない欄（標準報酬月額・企業年金・失業給付・取得価額・資産の配分・住まいの評価と持ち分・教育の塾と受験・生活費の段階 など）が消える。見直しで前回の値のまま送っても変更の候補が出て、既定でチェックが付く。答えていない配偶者の方の住民税が、推定 0円の新しい行として既定で入る（要確認）。お子さま3人と答えて3人目だけ生年月を答えると、その答えが今の第1子に当たる。

### 5. 足すとき

- ヒアリングの問い・飛ばす決まり・書類・取り込みを変えるまとまりは、この一周に場合か確かめを足す（部分のテストに加えて）。ひな形の名前が変わったら、テストの頭の `SIMPLE`・`REVIEW` を合わせる。FP の画面の数え方が関数になったら、テストの `fpQuestionCount` をその関数にする。

### 決めたこと（迷った所）

- FP の画面の「問い N」は、画面の部品（`WebBuilder.tsx`）が問いを非同期に作るため、文字に描いて読めない。部品の式（`screens(packet, initialDraft(packet))` の問いの画面の数）をテストの中に写した。0192 で数え方が関数（`estimateOf`）になったので、`fpQuestionCount` はその関数にした。
- 「数が合う」は単位をそろえて比べる（問いの画面の数どうし・答えた問いの数どうし）。今の画面は場所ごとに単位が違う（FP の画面の「問い N」は問いの画面だけ、お客さまの最初の画面の「N画面ほど」は同意と分岐の問いを含む、依頼の一覧の「項目 N」は選んだ項目、「答え N」は記入の年月と同意を含む）。どの単位で見せるかは FP の画面のまとまりで決める。
- 「欄が消えない」は、行が残っている所の値のある末端の欄の道で比べる（世帯の行は ID、行の中の並びは番号で）。行の中の並びの要素の ID が変わるのも「消えた」に数える（案の差分が要素の ID を指すため）。

## 理由

- **画面の順に答える**: 下書きを直に作ると、画面に出ない問いの答えも作れてしまい、「見ていない問いの答えが届く」「見た問いの答えが落ちる」を見つけられない。お客さまの画面と同じ並べ方（`screens`）で進めば、飛ばす決まりと送る答えの食い違いが見える。
- **既定のチェックのまま承認**: FP がふつうに押す形。今の値を壊すかどうかは、既定の選び方で決まる。
- **保存して読み戻す**: 取り込みは新しい行・欄を作る。読み戻しで形が整う（ID が付く・欄が落ちる）と、保存の前と後で計算や案の差分が変わる。

## 代案（採らなかったもの）

- **画面を動かして通す（手元のサーバーとブラウザ）**: CI で流せない（`wrangler` を依存に入れていない。0125）。手元の試し（`hearing/scripts/relay-smoke.ts`）と、開発中のアプリでの通しの確かめに任せる。
- **見つけた不具合をこのまとまりで直す**: 取り込みと FP の画面は別のまとまりが直している。テストだけを足し、直す待ちにする。
