## 背景

- Web のヒアリングを発行から取り込みまで通して確かめたところ、FP の画面にいくつもの迷い・不具合があった。
  - 入口が「取り込む」の中にあり、聞くことと取り込むことが分かれていない。ひな形の名前が Excel と違う（「初回の前」と「通常（初回の前）」）。
  - 「年収」と「年収のだいたいの範囲」が別の項目として並び、数にも入る。何を聞いて何を聞かないかが開かないと分からない。
  - 問いの数・項目の数が場所ごとに違う（FP の画面は配偶者の方・お子さまのいない下書きで数え、お客さまの最初の画面は同意と分岐の問いを含む夫婦と子2人で数え、依頼の一覧は記入の年月と同意を含む答えの数）。
  - ひな形を切り替えると書類と独自の質問が黙って消える。独自の質問は自由記述だけで、足した後に直せない。分野を外すと並びの最後に回る。
  - 回答が届いても、「確かめる」を押すまで分からず、押した結果も画面を閉じると消える。依頼の行に何を頼んだかが出ない。発行した後もボタンが同じまま押せる。押せないボタンが押せるように見える。
  - 事務所のひな形に、作った世帯の書類待ちの結びつきと持ち主が入る。顧客番号はアプリを開いている間1つだけ覚え、別の世帯に持ち越す。事務所名が空でも黙って発行できる。案内文の所要時間が決め打ちで、偽の URL への注意が無い。値の入った世帯でも何も知らせない。
- 利用者の判断（2026-11-06）:
  - ひな形の名前は「シンプル」「詳細」「見直し」「カスタム」（カスタムは自分で選んだ・保存した組み合わせ）。Excel のヒアリングシートの「通常」も「シンプル」にそろえる。
  - 「ご相談したいこと」を、選べる話題にする（既定の話題＋自由記述）。FP が事務所の既定値と依頼ごとに、足す・外す・言い換えるができる。
  - シンプルではご両親の問いを既定で外す（FP が足せば聞ける）。
  - 届いたらアプリで知らせる（10月の設計案の決定 No.6）。送った内容をその場で見る・印刷する（No.14）の FP の側。

## 決定

### 1. 入口（H-101）

- FP のメニューの「取り込む」を「ヒアリング・取り込む」にし、項目を「ヒアリング（Excel・URL で聞く・取り込む）」とした。開いた中身は2段: 「ヒアリングで聞く: Excel を書き出す／URL で聞く」と「ヒアリングを取り込む: 記入済みの Excel を取り込む／URL の答えは下の『URL の依頼』から」。

### 2. ひな形（H-102・H-107・H-119・利用者の判断）

- URL: シンプル（`basic`）・詳細（`full`）・見直し（`full` で今の値を確かめてもらう）。保存した組み合わせは「カスタム」の下に並べる。ひな形から項目を直したら「カスタム」と出す。ひな形の説明に、聞く項目の数と所要時間（4 の数え方）を添える。
- シンプルは区画「ご両親」を既定で外す。外した分野は灰色のまま元の位置に残るので、チェックすれば聞ける。
- ひな形を切り替えても、書類・独自の質問・話題は残す。項目を直した後なら「直した項目は、選んだひな形の項目に戻ります」と確かめる。カスタムを選ぶと書類・独自の質問も置き換わるので、そのことも確かめる。
- 選び方に任意の欄 `name`（ひな形の名前）を持たせ、依頼の一覧の行に出す。直した組み合わせは「カスタム（シンプルから）」、保存した組み合わせは「カスタム: 名前」。名前の無い前の依頼は、元のシートと聞き方から決める。
- Excel のシートの種類も「シンプル」「詳細」「見直し（前回の値つき）」。取り込みの住宅ローンの知らせは「シンプルのシートの残高と毎月の返済額から…」。
- 世帯に値があるのにシンプル・詳細を選んでいると、「前回の値を見せて確かめてもらうなら見直し」と注意する（取り込みでは今の値を残せる。0139）。

### 3. 項目の選び方（H-103・H-104・H-123・H-122）

- 金額の「だいたいの範囲」の項目は並べない。金額の項目の行の「範囲でも答えられる」で付け外しし、金額の項目と一緒に選ぶ・外す・並べ替える。数にも入れない。
- 上に「聞く: ご家族・お仕事と収入… ／ 聞かない: ご両親」の1行。分野の見出しの右に、聞く項目の名前を3つまで（ほか N）。
- 分野・項目は外しても元の位置に残す（並びは、選んだ物の並びに、選んでいない物を元のシートの位置の近くに差し込む）。
- 見本（右のスマホの画面）は、開いている世帯の人数（配偶者の方・お子さま・住宅ローン・保険）を分岐の答えに入れて出す。お子さまごとの問いも「見る」で開ける。

### 4. 数え方を1つに（H-106）

- **聞く項目の数**: 選んだ項目の数（範囲の項目は数えない。独自の質問は数える。`selectedCount`）。FP の画面の見出し・ひな形の説明・発行のボタン・依頼の一覧で同じ数。
- **お客さまの画面の数と所要時間**: お客さまの最初の画面と同じ数え方（`estimate`。同意・分岐の問い・問いの画面を、夫婦と子2人・住宅ローン1本・保険2件で数える）。FP の画面・案内文の所要時間はこの数。FP の画面には、開いている世帯の人数で数えた数も添える（`estimate` に世帯の人数を渡す）。
- **受け取った答えの数**: 届いた答えで出る問いの画面の数と、そのうち答えのあった画面の数（同じ数え方。依頼の一覧と受け取った知らせ）。前の「答え 34」（記入の年月と同意を含む答えの数）はやめた。
- 分岐の問いの答えと今の世帯の人数を比べる数え方（面談の準備の `gateNotes` と取り込みの知らせの `gateNotices`）は、`gateCounts` の1つにまとめた。

### 5. ご相談したいことの話題（利用者の判断）

- 既定の話題は9つ: 毎月のやりくり／教育費／住まい・住宅ローン／老後のお金・年金／保険の見直し／資産運用・NISA・iDeCo／税金・確定申告／親のこと／働き方の変化。これに自由記述（今までの「ご相談したいこと」の欄）が付く。
- FP の画面の「ご相談したいことの話題」で、依頼ごとに言い換える・外す・足す・並べ替える（20まで・1つ30字まで）。「事務所の既定にする」で事務所の既定値（0073 の事務所データ。事務所のひな形 `hearingTemplates` と同じ置き場の `hearingTopics`）に置き、次の依頼から最初に入る。「標準の話題に戻す」で欄を外す。空の一覧を既定にすると、話題を出さない（自由記述だけ）。
- 選び方の任意の欄 `topics`（話題の言葉の並び）。問いの中のご相談したいことの項目に `topics` を載せ、問いの言葉を「ご相談したいことは何ですか（いくつでも選べます）」にする。お客さまの画面は話題のボタン（いくつでも）と「ほかにあれば、自由にお書きください（任意）」の欄を同じ画面に出す。確かめの画面・送った内容に「教育費、老後のお金・年金（書いた文）」。
- 届いた答えの中身に任意の欄 `topics`（選んだ話題の言葉。問いの並び）。FP の側は、選び方の話題に載る言葉だけを受け、ほかは捨てて数える（信用しない。0125 の6）。
- 取り込みでは、話題を自由記述と一緒に FP 用のメモに入れる（「【ご相談したいこと・気になっていること】選んだ話題: 教育費、老後のお金・年金。上の子の大学の費用が心配です」）。面談の準備（前回から変わったこと）に「選んだ話題」「書いたこと」を出す。
- 版の文字は 0.2 のまま: 足したのは省ける欄だけで、省けば前と同じ問い・答えになる。指紋（`selectionDigest`）には話題を入れない（言い回し。0125 の7）。

### 6. 独自の質問（H-109）

- 足した後に、文・補足・答えの形を直せる（「直す」）。答えの形は、自由に書く（今まで）・はい・いいえ・選択肢から選ぶ（2〜8つ。1つ40字まで）。
- 選び方の独自の質問 `CustomQuestion` に任意の欄 `answer`（`text`・`yesNo`・`choice`）と `choices`。問いでは選ぶ問い（`choice`）になり、値も言葉にする（取り込みの FP 用のメモに「【面談の場所のご希望】オンライン」とそのまま入る）。計算には使わない（今まで通り）。
- 指紋には、自由記述でない質問だけ答えの形を入れる（自由記述の質問だけの依頼の指紋は前と同じ）。

### 7. 発行（H-113・H-114・H-116・H-117・H-118）

- 顧客番号は開いている世帯の顧客番号を初めから入れる（直せる）。世帯をまたいで覚えない（Excel の書き出しも同じ）。見本の世帯は空。
- 事務所名が空なら「お客さまの最初の画面には『担当の FP』と出ます」と注意する（発行は止めない）。
- 押せないボタンは薄い色にし、指の形にしない（FP の画面・依頼の一覧・取り込みの画面）。
- 発行した後は、発行した URL と案内文をその箱の上に出し、ボタンを「同じ内容でもう1通作る」にする（主のボタンにしない）。選び方を直すと「URL を発行する」に戻る。
- 案内文: 所要時間は 4 の数（「4分ほどです」）。「リンクは『https://…/h/』で始まります。違うときは開かずに、ご連絡ください」「お名前・口座番号・暗証番号・カード番号・マイナンバーはお聞きしません。ログインもありません」「お答えを送れるのは1回だけです。送る前に、確かめの画面で見直せます」を足した。

### 8. 事務所のひな形（カスタム）（H-115）

- 保存するときに、頼む書類から書類待ちの結びつき（`docRequest`）と持ち主を外し、書類の種類だけを残す（書類待ちから足した書類は、見出し・説明を書類の一覧の言葉に戻す）。名前は「カスタム: 名前」。

### 9. 届いた知らせ（H-110・No.6）

- 保存した世帯を開いている間、受け付けている依頼を、開いたときと5分ごとに確かめる（本体の命令 `hearing_web_call` の状況の口。依頼ごとの回数の制限〔1分60回〕より十分に少ない）。結果は**アプリを開いている間だけ覚え、世帯ファイルには置かない**（画面を閉じても消えない。アプリを開き直せば開いたときに確かめ直す）。
- 届いていれば: 依頼の行に「届いています」、入力のホームの上に「URL で聞いた回答が届いています（N件）［開く］」、FP のメニューの「ヒアリング」の右に「回答が届いています N件」、世帯の一覧の開いている行に「回答が届いています」。受け取って取り込んでいない答えがあれば「取り込み待ち」。
- 世帯の一覧の開いていない世帯は、保存したときの印（要約の後ろに「｜回答が届いています」「｜取り込み待ち」を付けて保存し、一覧が分けて出す）。開いていない世帯のサーバーは確かめない（鍵が世帯ファイルの中にあるため）。

### 10. 依頼の一覧（H-111・H-124・No.14）

- 行に「シンプル（聞く項目 16）・書類: 源泉徴収票（ご本人）・顧客番号 0001」。
- 取り消し・受け付けを終えるの確かめの言葉を「お客さまはこの URL を開けなくなります（途中のお答えも送れません）。取り消しますか」に。
- 「送られた内容を見る」: お客さまの送った後の画面と同じ部品（`SentAnswers`）・同じ並び・同じ言葉で出す（問いは依頼の記録から作り直す。通信しない）。「印刷」はその一覧だけを刷る（印刷したものは暗号化されないと添える）。

### 11. 取り込みの画面（0190 の未確定・前の作業の残り）

- 頼んだ書類で分かる問いの欄でお答えが無いものは、「お答えが無いので今の値のまま」ではなく「源泉徴収票（ご本人）を待っています」（届いていれば「源泉徴収票（ご本人）が届いています（見て入れてください）」）と出す。お客さまが「手元にない」を選んだ書類は言い分けない（かわりに聞いた答えがある）。お答えなしの物が書類待ちの欄だけなら「書類を待っています」の別の段にまとめる。見出しに「書類待ちの欄 N」。
- 入れる値が無い（全部お答えなし・同じ）ときも、「取り込み済みにする（入れる値はありません）」で0件の承認ができる（メモ・同意の記録・取り込みの記録だけが入る）。

### 12. 世帯ファイルの形式 0.73

- `hearing.web` の1件の選び方 `record.selection` に任意の欄 `topics`・`name`、独自の質問 `custom[]` に任意の欄 `answer`・`choices`、受け取った答え `received` に任意の欄 `topics` を足すだけの MINOR。前の版のアプリは答えの形を知らずに選ぶ質問を自由記述として扱うので、版を上げて閲覧だけにする。変換の段は形式の版だけを書き換える（前の版の記録は欄が無い＝話題なし・自由記述の質問）。0.72 の段の後に積む。見本 `0.73/`（0.72 の見本に欄を足したもの）。

### 決めたこと（迷った所）

- **既定の話題の数**: 計画の記録には「既定の話題（10）」とあったが、依頼の文の9つにした（「親のこと」は介護・相続をまとめた1つ）。
- **話題を答えのどこに入れるか**: ご相談したいことの答え（自由記述）に混ぜず、答えの中身の別の欄 `topics` にした。届いた答えを信用しない確かめ（選び方の話題に載る言葉だけ）ができ、面談の準備で話題と書いた文を分けて出せる。取り込みでは今のメモの手順に乗せるため、メモの文に合わせて1つの文にする。
- **版の文字を 0.2 のままにした**: 足したのは省ける欄だけで、前の版の問い・答えはそのまま読める。版を上げると、発行済みの依頼の答えを受け取れなくなる（受け取る側は版を厳しく見る）。本番の公開前で、前の形の受け入れも作らない（0158 と同じ考え方）。
- **届いた知らせを世帯ファイルに置かない**: 確かめるたびに世帯を保存すると、事務所の共有で同時に開いている人とぶつかる。受け取った答えは世帯ファイルにあるので、「取り込み待ち」は保存した世帯からも分かる。世帯の一覧の印は、要約の文の後ろに足す（本体の世帯の一覧の形を変えないため。要約は60字まで・氏名を入れない決まりのまま）。
- **確かめる間隔は5分**: 回答は面談の前の数日〜数週間の間に届くので、分の単位の速さは要らない。
- **数の単位**: 「問い」の数は画面の数（お客さまが答える手間に近い）、「項目」の数は選んだ項目の数。お客さまの最初の画面に合わせ、FP の画面も夫婦と子2人で数え、世帯の人数の数を添えた（お客さまの問いに世帯の人数を載せない: URL が漏れたときに読める物を増やさない）。
- **受け取った答えの数**: 答えのあった画面の数にした。答えの数（記入の年月・同意・範囲を含む）は、FP の画面・お客さまの画面のどの数とも単位が違うため。
- **ひな形の切り替えで残すもの**: 書類・独自の質問・話題は元のシートに関わらないので残す。保存したカスタムを選んだときは、その中身（書類・独自の質問を含む）に置き換える。
- **Excel の版1 のシートの題**: `basic` 版1（廃止・配ったシートを読むため同梱）の題の「（通常版）」は変えない（配ったシートの言葉のまま。版2 の題は「ライフプランのための事前のご質問」で名前を書かない）。
- **お客さまの送った後の画面の「担当の FP に、送ったことをお知らせください」**: 残した（アプリは世帯を開いている間しか確かめないため）。

## 理由

- **手軽さが主軸**（0138）: シンプルにご両親を入れないと、ご両親の分だけ画面が増える。話題をボタンにすると、書く手間なしにまず答えてもらえる。
- **数をそろえる**: 場所ごとに数が違うと、FP がお客さまに伝える目安（何分ほど）が当たらない。お客さまの最初の画面の数を正にすれば、案内文・FP の画面・お客さまの画面が同じ数になる。
- **届いたことが分かる**: お客さまに「送ったことを知らせて」と頼まなくても、FP が開いている間に分かる。知らせを世帯の外に置けば、同時に開いた人とぶつからない。
- **カスタムに世帯を持ち込まない**: ひな形は世帯をまたいで使うので、その世帯の書類待ち・持ち主が入ると、別の世帯で誤った結びつきになる。

## 代案（採らなかったもの）

- **話題を答えの自由記述の文に混ぜて送る**: 中身の形は変わらないが、届いた話題を確かめられず、面談の準備で分けて出せない。
- **届いた知らせを依頼の記録に置く**: 確かめるたびに保存が要り、共有の世帯で保存がぶつかる。
- **世帯の一覧の形（本体）に印の欄を足す**: 本体の世帯の一覧・事務所の共有の名簿の形を変えることになる。要約の文の後ろで足りる。
- **FP の画面の数を世帯の人数だけで数える**: お客さまの最初の画面の数と違ってしまう（お客さまの問いには世帯の人数を載せない）。
