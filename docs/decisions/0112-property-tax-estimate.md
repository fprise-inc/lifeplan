# 0112. 固定資産税・都市計画税の推定（購入の予定の持ち家の最初の年の額と、新築の軽減・評価替えの段）

- 状態: 採用（一部未確定）（2026-11-03）
- 固定の強さ: 推定は画面の側で世帯に入れる（最初の年の額は固定資産税の欄の推定、変化は「今の額に対する割合」の段の推定）こと、計算エンジンは固定資産税を計算しないこと（今の `residence.propertyTax` の読み方のまま）、法令で決まる値を事務所で変えられないことは骨格。式・目安の値・根拠の文・段の置き方は後から変えてよい（変えたら追記に書く）
- 前提にする記録: 0008 の2（推定）、0040（段階と例外の年）、0041（値の状態）、0049（推定の段階の決まり）、0052（住まい・ローン。2026-11-03 の追記の購入の種類）、0111（事務所の推定の値）

## 背景

- 購入の予定の持ち家の固定資産税は、目安のボタンの値（年12万円）の1つの額で、物件の価格にも新築か中古かにもよらなかった。新築の軽減（建物の分が半分）が終わる年に上がり、3年ごとの評価替えで建物の分が下がっていく動きは、FP が「＋ 固定資産税の変化」で手で入れるしかなかった。

## 決定

### 1. いつ入れるか

- 購入の予定の持ち家で、固定資産税の欄が推定のまま（目安のボタンの値か、この推定）のとき。「＋ 住宅購入の予定」で足したときと、購入の種類（0052 の 2026-11-03 の追記）を選んだときに入れ、その後は推定のままの欄と推定の段だけを、入力を直すたびに入れ直す（`refreshEstimates`。0008 の追記 2026-10-26 の3）。
- 今住んでいる持ち家は推定しない（今の目安のボタンの値のまま）。納税通知書があるはずで、建物の価格・建った年が分からないことが多く、推定のほうが外れやすい。
- FP が固定資産税の欄に額（納税通知書・販売会社の試算の額など）を入れたら、その額が優先（入れ直さない）。推定の段は「今の額に対する割合」なので、その額を元に同じ形で動き、割合は入れ直し続ける。FP が直した段・足した段は変えない。FP が外した推定の段は覚えて足し直さない（0049 の推定の段階と同じ決まり。「該当なし」の行）。

### 2. 式

- 土地の評価額 L＝物件の価格×土地の割合（持ち家の評価の土地の割合。空なら前提条件の値か目安の30%）×土地の評価額の割合。建物の評価額 B＝物件の価格×（1−土地の割合）×建物の評価額の割合。
- その年の税＝L×1/6×1.4%＋L×1/3×都市計画税率＋B(年)×1.4%×（新築の軽減の間は1/2）＋B(年)×都市計画税率（100円に丸める）。
- B(年)＝B×g(その年に効いている評価替えの年−建った年)÷g(最初の年の同じ年数)。g(a)＝max(下限, 1−(1−下限)×a÷下限まで下がる年数)。評価替えの年は2024年から3年ごと。
- 最初の年は購入の翌年（1月1日の持ち主にかかる）。計算エンジンは住み始めの年から欄の額を払うので、購入の年もこの額（引き渡しの精算の目安）。
- 新築の軽減は、建った年の翌年から、戸建て3年・マンション5年（長期優良住宅は戸建て5年・マンション7年）。新築は建った年を入れていなければ購入の年に建ったとみなす。中古は建った年を入れていれば、その年からの残りの軽減を当て、入れていなければ購入の年に建ったとみなして軽減を当てない（根拠の文に書く）。
- 段: 最初の年の次の年から、住み終わりの年と計算の最後の年の早いほうまで、税の額が前の年と変わる年に「この年から先」の割合の段（最初の年の額に対する割合）を置く。軽減が終わる年は上がり、評価替えの年は下がり、下限に届いたら止まる。土地の分は横ばい。
  - 割合は小数1桁の％（0.001 刻み。例 97.7%）にそろえて入れ、計算もその値で行う（根拠の文の％と同じ値）。そろえた割合が前の段と同じ年は段にしない。FP が打つ割合の桁は今のまま。
  - 固定資産税の変動率は空のまま（0）にする。計算は段の額に、計算の基準の年からの年数分の変動率を掛ける（`housing.residence`）ので、変動率を入れると段に加えて毎年動く。推定の段があるときは、変動率の欄の説明と欄の下の一言でこの関係を知らせる（評価替えの下がり方は段に入っているので、ふつうは入れない）。
- 長期優良住宅か: つながる住宅ローンに控除の条件があれば、その住宅の種類が認定住宅（長期優良住宅・低炭素住宅）か。ローンを組まない人（控除の条件が無い）は、住宅の購入の詳細の「長期優良住宅（認定）」（`residence.purchase.longLife`。表示と推定の元だけで計算に使わない。形式 0.53）。

### 3. 目安と法令の値

- 目安（事務所の推定の値。`hearing/src/presets.ts`。0111）: 土地の評価額の割合 70%（公示価格の7割程度）・建物の評価額の割合 60%（建築の価格の5〜7割）・都市計画税の税率 0.3%（上限で止める）・建物の評価額の下限 20%・下限まで下がる年数（木造・軽量鉄骨造 30年、重量鉄骨造・鉄筋コンクリート造 60年）。
- 法令の値（`app/src/workspace/input/propertyTax.ts` の `PROPERTY_TAX_LAW`。事務所で変えられない。`docs/estimates-review.md` の「一覧に入れていない値」）: 固定資産税の標準税率 1.4%、都市計画税の上限 0.3%、小規模住宅用地の特例（固定資産税 1/6・都市計画税 1/3）、新築住宅の減額（建物の固定資産税の1/2、戸建て3年・中高層の耐火のマンション5年、認定長期優良住宅は5年・7年）、評価替えの3年ごと。
- 根拠の文は「固定資産税の推定（…）」で始め、最初の年の額には価格・土地の割合・種類・評価額の割合・特例と軽減を、段には理由（軽減が終わる・評価替えで築何年の分だけ下がる・下限で止まる）と、固定資産税の欄の額に対する割合を書く。

## 理由

- 画面の側で世帯に入れる: 推定の値は FP が見て直す物（0008 の2）で、根拠の文を欄に出せる。計算エンジンに式を持たせると、FP が直す口が無くなり、一致テスト・制度データの手続きも要る。今の段の部品（0040）だけで表せる。
- 割合の段: FP が実際の額を入れたときに、軽減の終わり・評価替えの形をそのまま残せる（額の段だと、FP の額と食い違う）。
- 法令の値を制度データ（`data/regulation/`）に置かなかった: 計算エンジンが固定資産税を計算しないので、パックに置いても読む部品が無い。画面の側の法令の値（耐用年数・自動車税など）と同じく、コードの1か所に条文の番号を添えて置き、見直しの一覧に載せる。

## 代案（採らなかったもの）

- 計算エンジンで固定資産税を推定する: 上の理由。
- 段を毎年の少しずつの下げ（「何年かけて移すか」）で表す: 評価替えは3年ごとに変わるので、実際の動き（3年ごとの段）に合わせた。
- 今住んでいる持ち家も推定する: 上の1。
