# 0052. 住まい・ローンのカードの中身（住まいの種類・目安の値の推定・ローンの入れ方の区分と逆算・借りる人・控除の条件・ほかのローン）

- 状態: 採用（一部未確定）（2026-10-26）
- 固定の強さ: β公開から変えない（骨格）。世帯ファイルに足した欄（住まいの建て方 `residence.style`、負債の名前 `debt.label` と種類の細目 `debt.subtype`、画面の側のローンの入れ方の区分 `loanEntry`）の名前と値の一覧、建て方と名前と種類の細目は計算に使わないこと、「家賃なし」は賃貸で家賃が該当なしの箱であること、入れ方の区分は見せ方と逆算の決まりだけで計算の要求に入れないこと、逆算した値・目安のボタンの値・仮の値を推定（値の状態の行）で持つことは骨格。欄の並び・簡易と詳細の分け方・文言・標準の値（金利の目安・頭金と諸費用の割合）は後から変えてよい（変えたら追記に書く）

## 背景

- 入力のホームを14枚のカードに組み直した（0045）。住まい・ローンのカードは最初の5枚に入り、ざっくり入れる人が簡易の欄だけで住居費とローンを入れられることが要る。今の画面は、住宅ローンを借入額・借入の年月・金利・期間からしか入れられず、手元に通帳の引き落としの額や残高証明書しか無い人が入れにくい。ほかのローン（カードローン・リボなど）は詳細の区画にしか無く、借入額から入れる形だった。
- 目安のボタンの値（物件の価格・頭金・諸費用・借入額・金利・期間）が、印の無い決まった値で入っていた（0041 の5 で、新しく押すボタンは推定で入れると決めた）。
- 住宅ローン控除の条件は見せるだけの欄で、住宅の種類・入居の年月などを直せなかった。
- 実家・親の家に家賃なしで住む形と、その家を相続する形が無かった（相続する家を貯蓄・運用の不動産で作ると、住まいと二重になる）。
- 前提にする記録: 0008（世帯のデータモデル・値の箱）、0025（持ち家の評価と売却）、0035（世帯ファイルの形式。足すだけの形）、0038（時点の部品）、0040（段階と例外の年）、0041（値の状態の操作）、0043（入力画面でプランを直す）、0044（お金の行）、0045（カード）。

## 決定

### 1. 住まい

- **種類は3つ**: 賃貸（社宅・寮を含む）／持ち家／家賃なし（実家・親の家など）。家賃なしは、形の上では賃貸（`kind: "rent"`）で、家賃の値の箱が該当なし（`{state: "notApplicable"}`）。家賃は0円で計算する。ボタン「＋ 家賃なし」を足した。
- **種類を変えても形の違う値は消さない**: 賃貸の家賃と、持ち家の税・修繕・購入・評価は、種類を変えても世帯に残し（隠すだけ）、計算は種類に合う値だけを読む（計算エンジンは前から種類で読み分けている）。戻すと前の値が見える。足りない値は目安のボタンの値（推定）で入れる。
- 住み始め・住み終わりは時点の部品（0038）。住まいが2つ以上（住み替え）なら簡易に出す。
- 賃貸: 家賃（簡易）、家賃の変動率・更新料・更新の間隔（詳細。間隔は前からエンジンにある `rent.renewalEveryMonths`。空欄は24か月）。
- 持ち家: 建て方（簡易。戸建て・マンション。`residence.style`。計算には使わず、建物の構造の推定の元にする: 構造が空か推定なら、マンションは鉄筋コンクリート造、戸建ては木造を推定で入れる）、固定資産税・都市計画税と修繕費・管理費（簡易）、固定資産税の変動率（詳細。前からエンジンにある `propertyTax.growth`）、修繕費の変動率（詳細）、名義と持分（詳細。本人・配偶者の100%か夫婦の共有と本人の持分）。
- 家賃・修繕費・固定資産税の段階と例外の年は 0040 の部品のまま（詳細。簡易のときは札で知らせる）。大きな修繕・リフォーム・補助金・売電は、このカードのお金の行の区画（0044）で入れる。
- **住み終わりの後**: そのまま持つ／住み終わりの月に売る（選択。売ると前からの売却 `sale` を置く）。売るときは売却価格（簡易）・売却の費用（詳細）と、**譲渡所得の税の額の口**（簡易。0053）。人に貸す形はまだ無い（計算が無いので欄を出さない）。
- **持ち家の評価**: 今住んでいる持ち家の評価額は、入れるまで**未入力の警告**（0円で数えている。資産と負債の推移と相続税の目安に入らない）。購入の予定の持ち家は物件の価格を使うので空欄でよい。
- **この家を相続する**（家賃なしの住まいの詳細のボタン）: 家賃なしの住まいを相続の時点の前の月で終え、同じ家の持ち家をその月から足す。時点は相続・贈与のカードの受け取る相続の行があればその月、無ければ10年後（直す）。足した持ち家の評価額は未入力（相続の見込みの額を入れる）、税・修繕は目安のボタンの値。貯蓄・運用に別の不動産を作らないので二重にならない。

### 2. 目安のボタンの値は推定、外れやすい所は未入力の警告

| 値 | 入れ方 | 状態と根拠 |
|---|---|---|
| 家賃 月8万円・固定資産税 年12万円・修繕費 月1.5万円 | 値の箱（前から） | 推定（目安のボタンの値） |
| 物件の価格 4,000万円・購入の時期 2年後 | 値だけ（物の値の状態の行） | 推定（目安のボタンの値・標準の値） |
| 頭金（物件の価格の1割）・諸費用（物件の価格の5%） | 値だけ（行） | 推定。推定のままなら物件の価格を直したときに入れ直す（根拠の文に額を入れ、値を変えて書き直した行が古い行として外れないようにする） |
| 住宅ローンの金利 年0.8%（変動）・返済期間35年（完済が80歳を超えるなら80歳まで） | 値だけ（行） | 推定（目安のボタンの値・標準の値） |
| 今の住宅ローンの今の残高 3,000万円 | 値の箱 | 推定（目安のボタンの値）。借りた年と借入額は「仮（残高の時点から借りたとみなす）」の推定 |
| 自動車ローン（今返している分）200万円・年2%・5年 | 値だけ（行） | 推定（目安のボタンの値） |
| ほかのローンの金利 | 値だけ（行） | 推定（種類ごとの標準の値: カードローン・リボ 年15%、奨学金 年0.5%、リフォームローン 年2.5%、契約者貸付 年3%、親・知人 0%、その他 年3%）。種類を変えると、推定のままなら新しい種類の値に |
| 住宅資金の援助の額 | 値だけ | **未入力（0円で計算中）**。目安を作らない（外れると結果を大きく誤らせる） |
| ほかのローンの今の残高・毎月の返済額 | 残高は値の箱 | **未入力**（入れるまで残高0円・5年で返すとみなす） |
| 今の持ち家の評価額 | 値の箱 | **未入力**（購入の価格が無いとき） |

- 値の箱を持たない値の「未入力」は、値の状態の行の推定で根拠の文が「未入力」で始まるもの（値の箱の「未入力（0円で計算）」の印と同じ読み方。`valueState.ts` の `fieldStatus` を、行の推定にも同じ決まりで読むように直した）。FP が値を打つと行は外れる（0041 の4）。
- 古い世帯を開いても、どの値も書き換えない（ボタンの値と同じ確定の値は、0041 の5 の確かめの一覧に出るだけ）。

### 3. 購入の予定と住宅資金の援助

- 購入の予定: 購入の時期・物件の価格・頭金（簡易）、諸費用（詳細）。建物が建った年は持ち家の評価の欄（中古を買うなら入れる。住宅ローン控除の新築か中古かにも使う）。
- 住宅資金の援助（入るお金の見た目。物は前からの `purchase.gifts`）: 援助する人・援助の額（簡易）、受け取る人・贈与税の課税の方法・住宅取得等資金の非課税（詳細）。受け取るのは購入の月（前のまま）。

### 4. 住宅ローンの入れ方の区分と逆算

- 区分は3つ（簡易の「入れ方」の選択。画面の側 `WorkingHousehold.loanEntry`＝負債の ID → 区分。無いローンは「借入額から」。世帯ファイルの本文の `household` の区画に入る）:

| 区分 | 簡易の欄 | 逆算して推定にする値 |
|---|---|---|
| 借入額から（契約書） | 借入額・借入の年月・金利・返済期間、毎月の返済額（目安。見せるだけ） | — |
| 毎月の返済額から（通帳の引き落とし） | 毎月の返済額・金利・借入の年月・返済期間 | 借入額（金利・期間・返済方法を直すと、同じ返済額のまま解き直す） |
| 今の残高から（残高証明書・返済予定表） | 今の残高・毎月の返済額・完済の年月 | 金利（残高・完済の年月・借入の年月を直すと、同じ返済額のまま解き直す）。借りた年と借入額は仮 |

- データは同じ物で、区分を変えても値は消えない。「今の残高から」に変えたとき残高が無ければ、借入額・金利・期間から計算した今の残高を推定で置く（時点は計算の基準の月）。
- 逆算は画面の補助（`input/loanMath.ts`）。最初の金利の段だけで解き、毎月の返済額はボーナス返済の分を除いた月の分（元金均等は最初の月）。逆算した金利は小数7桁にし、計算し直した返済額が入れた額と同じになる近くの値を選ぶ。返済額×残りの月数が残高に届かない・利息に届かないときは解かない（値は前のまま）。
- 逆算した値の推定の行は根拠の文に「逆算」と値を入れる。FP がその値を打つと確定になり、解き直さない。
- 今の残高から入れたローンは借りた年が仮なので、**住宅ローン控除の仮の条件を置かない**（置いてあった仮の条件は外す）。その代わり、控除の条件が無い間は「入居の年月（控除）」を簡易に出して**未入力の警告**（「入居の年月を入れると住宅ローン控除を計算します」。確かめの一覧の未入力にも出る）にし、黙って控除を0円にしない。入居の年月を入れると控除の条件（控えめの既定: その他の住宅・中古）を置く。入居から13年を過ぎた・要件を満たさないなどで当てはまらなければ、ボタン「住宅ローン控除は当てはまらない（該当なし）」で警告を消す（負債の値の状態の欄に、控除の条件の全体 `debt.housing` の該当なしの行を書く。入居の年月を入れると外す）。
- 新しい住宅ローン: 購入の予定とつながるなら「借入額から」（借入額は物件の価格−頭金の推定。前のまま）、今住んでいる家のローンは「今の残高から」。

### 5. 借りる人とペアローン

- 借りる人（簡易）: 本人／配偶者／夫婦で連帯債務（1本を2人で。負担割合は半分ずつの既定で、本人の負担割合を詳細で直す）／収入合算（配偶者が連帯保証人）。前からある `debt.debtors` の形のまま。団信の対象が前の主債務者だけなら、新しい主債務者に付け替える。
- ペアローン: 「＋ ペアローン（配偶者の2本目）」で配偶者の2本目を足し、両方に `pairWith` を付ける。2本目の借入額は1本目の半分（推定）。1本目が物件の価格−頭金の推定なら、1本目は残り（合計は購入の予定と合う）。団信・控除の条件は1本ずつ。

### 6. 住宅ローン控除の条件の欄

- 簡易: 要約の1行（受ける・入居の年月・新築か中古か・住宅の種類・持分）と、住宅の種類（認定住宅／ZEH水準省エネ住宅／省エネ基準適合住宅／その他の住宅）。詳細: 控除を受ける、入居の年月、新築か中古か、取得対価、子育て世帯・若者夫婦世帯の上乗せ（自動・対象・対象外）。どれも前からある `debt.housing` の欄。
- 仮の条件の印は住宅の種類の欄が持つ（欄のキーは前の見せるだけの欄と同じ）。どれかの欄を直すと印を外し、条件の全部を確定にする（印のある間だけ借入の年月・住まいに合わせて入れ直す。前のまま）。「✓ この値で確定」でも同じ。
- 2028年以後に入居する新築で、省エネ基準適合住宅・その他の住宅を選んでいるときは、控除の対象にならないことを欄の下で知らせる（制度データの借入限度額が0のため）。
- 借入限度額・控除の期間・控除率は入れる欄にしない（制度データで決まる）。

### 7. ほかのローン

- 区画を簡易にした（「ほかのローン（カードローン・奨学金など）」）。ボタン: カードローン・リボ、奨学金（本人・配偶者が返している）（簡易）、リフォームローン、その他のローン、自動車ローン（今返している。詳細）。
- 種類（簡易。`debt.subtype`。カードローン・リボ／奨学金／リフォームローン／契約者貸付（保険）／親・知人からの借入／その他。計算の種類 `debt.kind` は奨学金だけ `scholarship`、ほかは `other`）と名前（詳細。`debt.label`）。どちらも計算には使わない。
- 簡易は「今の残高から」: 今の残高・毎月の返済額。完済の年月は残高・返済額・金利から逆算（推定）。金利を直すと同じ返済額のまま完済の年月を解き直し、完済の年月を入れると金利を解き直す。入れ方を「借入額から」にすると借入額・借入の年月・返済期間で入れられる。
- 相続で受け継ぐ借金（0044 の7）の返済の欄もここに出す（元の借り手と見込みは相続・贈与のカード）。
- 自動車ローン（今返している分）は、車のカードに出すまでここで入れる。

### 8. プランと値の状態

- 欄はどれも当て先（0036 の2）を持つか、前の欄のキーから読み替え表で引ける。プランを直しているときの書き方は 0043 のまま（作業中の世帯の違いを差分にする）。入れ方の区分は見せ方なので、プランを直しているときに変えても世帯に1つ（`recordPlanEdit` が世帯の側に写す）。
- 逆算する欄（毎月の返済額・完済の年月・逆算の推定のあるローンの金利・期間・借入の年月・残高）と、ほかの値も変える欄（建て方・入居の年月）は、欄の定義に `sideEffects` の説明を持つ。

### 9. 持ち帰り用のレポートと縮約版

- ローンの名前（`debt.label`）は FP が書いた文なので、持ち帰り用のレポートでは外し（種類の細目から見せる）、AI接続口の縮約版でも文章の項目として既定で外す。建て方・種類の細目は縮約版の許可リストに入れた（版 `reduced@13`。0015）。

## 理由

- **入れ方の区分を3つにする**: 手元の書類で形が違い（契約書・通帳・残高証明書）、どの区分でも残りの値から足りない1つ（借入額か金利）を逆算して計算できる。区分の間で値を引き継げるので、書類がそろってから入れ直しても消えない。
- **区分を画面の側に持つ**: 計算の要求の意味は変わらない（エンジンは借入額・借入の年月・金利・期間・残高を読むだけ）。逆算の結果は値と推定の行で残るので、区分が無くても計算は同じ。
- **今の残高から入れたローンに控除の仮の条件を置かない**: 借りた年が仮のまま控除を計算すると、昔借りたローンに今年から13年の控除が付き、税が大きく少なく出る。
- **建て方・名前・種類の細目を計算に使わない欄にする**: 推定の元と見せ方に要るが、計算の型（`kind`）を増やすと部品と一致の確かめが増える。
- **援助の額・ほかのローンの残高と返済額・評価額を未入力の警告にする**: 外れると結果を大きく誤らせる値に目安を入れると、気づかないまま誤る。
- **種類を変えても値を消さない**: 賃貸⇄持ち家・購入の予定を試し比べるとき、前の値が消えると入れ直しになる。エンジンは種類で読み分けるので、残しても計算は変わらない。

## 代案（採らなかったもの）

- **毎月の返済額・完済の年を世帯ファイルに持つ**: 借入額・金利・期間・残高から決まるので持たない（持つと値が2か所になる）。逆算の元にした額は推定の行の根拠の文に残る。
- **ほかのローンの種類ごとに計算の種類を足す**: 返済の計算は同じなので、表示と推定の元の欄で足りる。
- **「家賃なし」を種類の選択肢としてエンジンに足す**: 家賃の箱の該当なしで表せ、エンジンを変えずに済む。
- **今の残高から入れたローンの控除を、借入の年月を入れるまで計算しない（入居の年月の欄も出さない）**: 控除を受けている人が入れられない。入居の年月だけを入れれば計算できる。

  - **住宅購入の予定は「住宅の購入」の1件**: 前は「住まい N（持ち家）」の枠の中に「住宅の購入」のまとまりがあり、別の住まいを足したように見えた。購入の予定の持ち家は、物の名前を「住宅の購入」にし、購入の欄（購入の時期・物件の価格・頭金・諸費用）を頭に、住まいの欄をその後に並べる（見せ方だけ。欄のキーは `…/purchase/…` のまま）。諸費用は購入の月の大きな出費なので標準に出す。持ち家の評価の「建物が建った年」は、購入の予定では「建物が完成する年」。
