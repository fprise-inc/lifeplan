# 0071. 万一のタブの前提（プランごとの上書き・入力項目ID・足した場面と前提）と、世帯ファイルの形式 0.27

- 状態: 採用（一部未確定）（2026-10-27）
- 固定の強さ: β公開から変えない（骨格）。万一の前提の入力項目ID `contingencyPremise.*`（前提の直下の欄ごとに1つ。正本は画面の側の区画のスキーマ `app/schemas/household.contingency.json` の `x-item`）、プランごとの上書きを向き先 `{plan: "contingency"}`・その入力項目ID・前提の中の場所の値を変える差分で持つこと、場面・起きる年・重ねる印を差分にしないこと、そのプランの前提を「共通の前提に土台から順に差分を当てたもの」にすること、形式 0.27 は骨格。前提の欄の並び・簡易と詳細の分け方・文言・帯の計算の順番・既定の値（仮の値）は後から変えてよい

## 背景

- 万一の前提（遺族の生活費の割合・一時の資金・必要保障額の期間・残された配偶者の働き方・等級・医療費・病気・相場の下落）は、画面の側に世帯で1つ持つ（`WorkingHousehold.contingency`）。プランの差分の形には向き先 `{plan: "contingency"}` があるが（0036 の2）、入力項目ID の名前が決まっておらず（0035 の6 の未確定）、差分は「まだ当てられない差分」として見せるだけだった（0036 の追記）。万一のタブでプランを見ても、前提はどのプランでも同じだった。
- エンジンには、必要保障額の逆算方式（`protection.method: reverse`・`reverseUntilAge`）、子の独立とみなす年齢（`survivor.independenceAge`）、業務上の死亡（`deathBenefits.workRelated`）、構成員のだれにでも置ける就業不能の想定、収入の減少（`assumptions.incomeShocks`）、器の種類でも書ける時価の下落（`marketShocks` の `kinds`）、利回りの書き換え（`returnShifts`）があり、ストレスの層と万一の層を同じ要求に重ねられる。画面には無かった。
- 起きる年は、対象の人が75歳になる年までで切っていた。
- 前提にする記録: 0008（世帯のデータモデル・万一の層）、0026（大きな病気・相場の下落）、0035（形式の版の上げ方・入力項目ID）、0036（差分の型）、0043（入力画面でプランを直す）、0054・0055（病気の想定）、0070（前提条件のカード）。

## 決定

### 1. 万一の前提の入力項目ID

- 前提の直下の欄ごとに1つの入力項目ID を付ける: `contingencyPremise.survivor`（遺族の側の前提）・`.horizon`（必要保障額を数える期間）・`.protection`（出し方）・`.work`（残された配偶者の働き方。構成員の ID → 働き方）・`.grade`・`.medical`・`.oldAgeChoice`・`.illness`・`.incomeDrop`・`.market`。中の値は差分の場所 `at` で指す（例: 遺族の生活費の子がいる間は `contingencyPremise.survivor`・`["livingRatio", "beforeIndependence"]`、残された配偶者の年収は `contingencyPremise.work`・`[<構成員>, "annualSalary"]`）。
- 正本は世帯ファイルの本文の画面の側の区画のスキーマ `app/schemas/household.contingency.json` の `x-item`（0035 の6）。登録簿 `registry/items.yaml` に、区画の名前 `contingencyPremise`・場所（欄の名前）で載る（`engine/scripts/registry.ts` がこのスキーマも読む。エンジンの入力のスキーマと同じ ID を持てない）。
- 起きる年（`year`）と、相場の下落を重ねる印（`stackMarket`）は ID を持たない（場面の選び方で、プランの差分にしない。0036 の2 の場面・起きる年・人を差分にしない決まり）。
- AI接続口の縮約版の許可リストに入れ、版を `reduced@18` にした（どれも計算の前提の数。縮約版が渡す要求の入力には画面の側の値は入らない。0015）。

### 2. プランごとの上書き

- そのプランの万一の前提 = 全プラン共通の前提の写しに、土台のいちばん下のプランから順に、オンの `{plan: "contingency"}` の値を変える差分を当てたもの（同じ場所は後のプランが勝つ。0036 の6 の3）。差分の値は値の箱で、値が `null` なら省く（既定に戻す）。当てた結果は `applyDiffs` の `contingency` に返し、計算の要求（エンジンの入力）は変えない。
- 要確認: 入力項目ID が万一の前提のものでなければ「意味の変わった欄」で当てない。共通の前提の値が、差分を作った時点の値（`before`）から変わっていれば「入力が変わりました」（当てる）。「まだ当てられない差分」の状態はなくした。
- 「このプランを現状に反映する」は、そのプランの前提を共通の前提にする。
- 違いの一覧では、行を「万一の前提（万一のタブ）」のまとまりに、「万一の前提: 遺族の生活費（子がいる間） 共通: 70% → 60%」の形で出す。
- 万一のタブの前提のパネルの見出しに「前提を直す先: 全プラン共通 ／ プランBだけ」（プランを見ているときだけ。保存したプランだけ選べる）。既定は共通。
  - 「プランBだけ」で直すと、変わった値ごとに、そのプランの差分を作る・直す。土台（土台が無ければ共通）と同じ値に戻すと差分を消す。
  - 共通のまま直すと、共通の前提を直す（そのプランで上書きした値はそのまま）。
  - どちらでも、起きる年・重ねる印は共通を直す。
  - 共通と違う値の欄に、縦線と「プランBだけ・共通: 70%」（土台から来た上書きは「土台のプランで変更」）と「↺ 共通に戻す」。戻すと、そのプランの差分を消す（土台が上書きしていれば共通の値に戻す差分を作る）。見出しに「プランBだけの前提 ○か所」。

### 3. 足した場面と前提（どれもエンジンの今の形で計算する）

| 区画 | 足した物 | 要求での形 |
|---|---|---|
| 場面 | 大きな病気（配偶者も） | 配偶者の就業不能の想定 |
| 場面 | 収入が減る（誰の収入〔本人・配偶者・両方〕・減る割合・年数。既定は本人・2割・3年） | 起きる月から、その人の `incomeShocks` |
| 場面 | 重ねる「死亡・就業不能・病気・収入が減るの場面にも、同じ年の相場の下落を重ねる」 | 万一の層と時価の下落を同じ要求に |
| 起きる年 | 表の最後の年まで（上限60年。75歳で切らない） | — |
| 遺族の生活費 | 子の独立とみなす年齢（既定22歳。独立の時点を入れていない子に使う） | `survivor.independenceAge` |
| 一時の資金 | 業務上の死亡として見る | `deathBenefits.workRelated` |
| 必要保障額の出し方 | 積み上げ・逆算、逆算で遺族が何歳になるまで資産が尽きないようにするか（既定は平均余命） | `protection.method`・`reverseUntilAge` |
| 残された配偶者の働き方 | 変える時期を時点で（下の子の年齢・出来事から。亡くなった月より前なら亡くなった月。空欄は「亡くなった月から○か月後」） | 働き方の期間の始まり |
| 大きな病気 | 復帰の後の働き方（○か月は収入を元の○割に） | 戻った月から `incomeShocks` |
| 相場の下落 | 下げる資産（国内・外国の株と REIT・債券・バランス型・コモディティ・配分を入れていない持株会・外貨預金。既定は株・REIT と持株会で、今までと同じ結果）、下がった後の戻り方（○年は運用の利回りを○%までに） | `marketShocks`（資産の種類は配分の割合で、持株会・外貨預金は器ごと）・`returnShifts` の上限 |

- 相場の下落は、型のストレステストではなく、要求の前提に時価の下落を直接書く（既定の選び方では型と同じ下落で、結果は同じ）。持株会を選ばないときは、配分の無い運用の器から持株会を外す。
- 前提の欄に簡易と詳細を付けた（簡易は場面ごとに1〜3欄: 今の世帯に当たる遺族の生活費の割合・整理資金・働き方と年収・病気の働けない期間・収入が減るの3欄・下がる幅と重ねる印）。
- 死亡の場面の結果に、残された人の年金の月額の一言（「奥様の年金: 月○万円（2031年。遺族年金を含む。2045年〔66歳〕からは月○万円）」。エンジンの結果の年金の行を読むだけ）。
- 年ごとの結果の帯は、選んだ年の前後（2年まで）→ 最初の年から5年ごと → 残りの年の順に計算する（それぞれ選んだ年に近い順）。

### 4. 世帯ファイルの形式 0.27

- 形式の版を `0.27` にした（足すだけの MINOR。0035 の1・7）。画面の側の万一の前提に上の任意の欄（`survivor.independenceAge`・`deathBenefits.workRelated`・`protection`・`work.<人>.from`・`illness.afterMonths`・`afterRatio`・`incomeDrop`・`market.classes`・`recoveryYears`・`recoveryCap`・`stackMarket`）を、画面の側の値に前提と推定の一覧の確かめた記録 `agreed`（0070 の7）を足した。万一の前提を上書きする差分は 0.17 からある差分の形で書く。
- 変換の段は形式の版だけを書き換える（0.26 → 0.27）。前の版のアプリは知らない欄を読み落として書き戻すので、版を上げて閲覧だけにする。
- 見本 `crates/household-store/tests/fixtures/household-format/0.27/`（0.26 の見本に、上の欄・前提の例外の年と厚生年金の調整率・表の最後の年の確定の行・確かめた記録・遺族の生活費を上書きするプランの差分を足した）。

## 計算が無いので出さない欄（残した欄）

| 欄 | 理由 |
|---|---|
| 遺族年金を受け取らない（事実婚で生計維持が認められない場合） | 遺族年金を計算から外す前提がエンジンに無い |
| 亡くなった人の口座が使えない月数 | 死亡の想定で口座を止める形がエンジンに無い（予備の生活資金で当座のお金を見込む） |
| 相続税の目安を支払いとして入れる | 相続税の目安をお金の流れに入れる選択がエンジンに無い（表示だけ） |
| 単身・世帯の外の家族を養う人の死亡の場面 | 遺るお金と養っている人の必要額を出す計算が無い |
| 2人とも亡くなる・死亡と就業不能を重ねる | 万一の想定は要求に1件だけ |
| 万一のあとに増える支出・就業不能の給付の額の口（起きた後に始まる） | お金の行の「起きた後に始まる」扱いがエンジンに無い |
| 「遺族の生活費はいくらまでなら足りるか」のボタン | 逆算の道具（画面の側で繰り返し計算する）を作る回に |
| 万一のタブの一覧からお金の行の万一のときの扱いを直す | 物の欄を共有する一覧を作る回に（欄は各カードにある） |

## 理由

- **欄ごとに1つの ID と場所**: 前提はほとんどが入れ子の小さな値で、欄ごとに ID を付けると数が多く、残された配偶者の働き方は構成員ごとの入れ物。0036 の2 の「いちばん内側の入力項目ID と、その中の場所」に当てはめると、直下の欄ごとの ID で足りる。
- **画面の側の区画のスキーマを正本に**: エンジンの入力ではない値の ID を、エンジンの入力のスキーマに混ぜない（0035 の6）。
- **要求を変えず前提に当てる**: 万一の前提は計算の層で、プランの要求（エンジンの入力）と別。万一のタブがそのプランの前提で層を重ねる。
- **時価の下落を直接書く**: 持株会・外貨預金を器ごと下げる下落と、資産の種類の割合で下げる下落を、1つの型では同時に書けないため。既定の選び方は型と同じ下落なので結果は変わらない。
