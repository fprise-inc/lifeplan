# 0026. 資産運用（入れ方・期間を分けた積立・NISA の枠・iDeCo の受け取り・資産配分・取り崩し・相場の下落）

- 状態: 採用（一部未確定）（2026-10-19）
- 固定の強さ: β公開から変えない（骨格）。世帯のデータの欄（器の種類 `pooled`・`accounts[].expectedReturn`・`accounts[].fee`・`accounts[].payout.destination`・`payout.start` の省略）・前提の欄（`assumptions.investment`・`assumptions.assetVolatility`・`assumptions.returnShifts`・`marketShocks[].assetClasses`）・ストレステストの型（`lowReturnPeriod`・`returnShortfall`）・行ID（`cf.expense.living.drawdown`・`cf.balance.account.pooled`）・2つの読み方の変更（積立の終わりと受け取りの始まりの省略）は骨格。事務所の標準値（期待リターン・値動きの大きさ・相関・大きな病気の目安）と画面・帳票の見せ方は後から変えてよい（変えたら追記に書く）

## 背景

- 資産運用の入力は「器（口座）ごとの残高と、1本の積立」だけで、合計しか分からない顧客・資産の割合で話したい FP のどちらにも合わなかった。積立は年齢で額を変えられず（エンジンの `contributions` はもともと複数の期間を持てる）、積立の終わりが空なら「表の最後まで」積み立てていた。
- NISA の枠を超えた積立は黙って預金に残り、知らせも選択肢も無かった。iDeCo・企業型DC の受け取りが空なら「75歳で一時金」だった。
- 結果の画面は「資産が尽きる年」だけで、運用の期間（積み立てる・据え置く・取り崩す）・口座ごとの内訳・相場が下がった場合が見えなかった。
- 0002（金額・率・丸め）、0003 の3（運用益は年に1回、期首残高×年利＋出入り×年利×1/2）、0008 の9（器の型）、0011（形式の版）、0025（金融資産に入れない器）が前提。

## 決定

### 1. 入れ方（`assumptions.investment.method`）

- 3つ: `total`（合計）・`accounts`（口座。省略の既定で、今までの計算）・`allocation`（資産配分）。上下を感じさせない言葉にし、画面で「器」は使わず「口座」と書く。
- 合計は、器の種類 `pooled`（まとめた金融資産）1つで表す（残高・期間を分けた積立・FP が入れた平均の利回り `expectedReturn`）。合計の入れ方では、エンジンが計算の前に金融資産の器を外し、`pooled` だけで計算する（不動産・その他の資産・保険の器は残す）。iDeCo の掛金の所得控除・NISA の非課税も入らない、簡易な入れ方として扱う。会社が出す企業型DC の掛金は合計の積立に含めない（家計から出る額だけ）。
- 口座・資産配分の入れ方では、`pooled` は「まだ口座に分けていない分」になる: 残高は `pooled` の残高−ほかの金融資産の器の残高の合計（0未満は0）、毎月の積立は月ごとに `pooled` の積立−ほかの器の本人の積立の合計（0未満は0）。どちらも0なら器ごと外す。合計から口座に切り替えても自動で按分しない（FP が口座に入れた分だけ減り、0で消える）。画面は口座に切り替えたときに0なら `pooled` を外し、合計に切り替えたときは口座の値を足して `pooled` を作り直す（入力は消さない）。まだ分けていない分は、決済口座の次に取り崩す（税なし）。
- 重ね方はエンジンの1か所（`engine/src/engine/investment.ts`。万一・ストレスの重ね（overlay.ts）より先）。3つの実行環境で同じ結果になる。

### 2. 期間を分けた積立と、積立をやめる年

- 積立は器ごとに「○歳から月○万円」の期間を並べる（`contributions` の複数の期間。NISA は `tranche` ごと）。画面は「＋期間を追加」で足し、終わりは次の期間の始まりの前の月か、積立をやめる年。
- **読み方の変更**: 積立の終わり（`to`）が空の積立は、名義の人の退職の月まで（退職のイベントか、最後の働き方の期間の終わり。働き方の期間の無い人は本人の退職の月。終わりの無い働き方の人と、どちらも分からないときは今までどおり表の最後まで）。iDeCo・企業型DC の掛金は加入の決まり（ideco.contribution）で止まるので書き換えない。画面は空欄を「退職の年まで」と仮に見せ、「推定あり」の印を付ける。既存の世帯ファイルは書き換えず、空のまま新しい読み方で読む（形式の版 0.5。0011 の追記）。

### 3. NISA の枠と、超えた分

- つみたて投資枠の年間の枠を超えた積立は、成長投資枠の残り（年間・生涯の成長の枠・生涯の枠）に入れる。それも超えた分は `investment.nisaOverflow` で決める: `deposit`（預金に残す。既定）・`taxable`（名義人の課税口座で続ける。無ければ作る。利回りは元の NISA の器にそろえる）。
- 画面は「○年に NISA の枠を使い切ります」と知らせ、超えた分の扱いを選ばせる（入力の見込みは画面で出す。売った簿価の分の枠の復活は数えない目安。計算はエンジン）。

### 4. iDeCo・企業型DC の受け取り

- **読み方の変更**: 受け取りの始まり（`payout.start`）が空なら、名義の人の退職の月の翌月を、60歳に達する月〜65歳に達する月に収めた月（退職の月が分からなければ65歳）。受け取り方も空なら一時金。今までの「75歳で一時金」をやめる。受け取りを始められる月より前なら、今までどおりその月から（account.idecoPayout）。
- 受け取り方（一時金・年金・併用）は iDeCo・企業型DC のどちらにも欄を持つ。
- 受け取ったお金の行き先 `payout.destination`: `deposit`（預金に入れる。既定）・`invest`（運用を続ける。受け取った年に、受け取った額（税を引く前）を名義人の NISA のその年の枠の残りへ、残りを課税口座へ移す。税は年間収支から預金で払う近似）。

### 5. 資産配分

- `investment.allocation`: 資産の種類ごとの割合（`mix`）・信託報酬（`fee`）・リバランス（`rebalance`。省略は年1回、元の割合に戻す）。資産配分の入れ方では、運用する器（課税口座・NISA・iDeCo・企業型DC・持株会）に共通で当て、FP が器に入れた利回りは使わない。預金は変えない。
- 器の利回り＝割合で平均した期待リターン（前提 `assetReturns`）−信託報酬（器の `fee`）。FP が入れた器の利回り（`expectedReturn`）があればそれを使う。
- **値動きの大きさによる目減りは差し引かない**: 期待リターンは、長い期間の平均の年率（幾何平均）として FP が入れる値とし、値動きの大きさ（`assetVolatility`。標準偏差）は計算に使わない（結果の幅の計算の材料として持つ。画面で組み合わせた値動きの大きさを見せるときだけ、事務所の標準の相関で組み合わせる）。算術平均で入れた値なら、FP が目減り（おおよそ値動きの大きさの2乗の半分）を引いて入れる。
- リバランスしないときは、資産の種類ごとの増え方で割合がずれる: その年の重み＝割合×計算基準年からの増え方（Π(1＋その年の利回り)）。積立・取り崩しも今の割合で入る近似。
- 課税口座の税 `investment.taxableTax`: `onSale`（売るときに利益に。既定。今までどおり）・`annual`（毎年の運用益に上場株式等の税をかけ、取得価額を時価にそろえる。控えめな近似で、税の行には出さない）。
- 取り崩す口座の順番は今までどおり `assumptions.withdrawal.order`（画面は預金・課税口座・NISA の3つのまとまりで並べ替える）。
- 事務所の標準値（期待リターン・値動きの大きさ・相関）は仮の値（国内株5%・18%、外国株6%・20%、債券1%・5%、REIT 4%・18%、現金0.1%・0.5%、信託報酬0.25%）。根拠を確かめて事務所で直す前提で、画面に「空欄は事務所の標準値（いまは仮の値）」と書く。商品のおすすめは出さない。

### 6. 取り崩しの計画（`investment.drawdown`）

- 「取り崩し」は、金融資産から生活に使う額とする。計画が無ければ今までどおり、収支が足りない年だけ取り崩す。
- 定額（`fixed`・毎月の額）か定率（`rate`・年の初めの金融資産×率）。始まりの月から、その年の額と、その年の収支の不足（年間収支−本人の掛金がマイナスの分）を比べ、多い分を「取り崩して使うお金」（`cf.expense.living.drawdown`）として年間収支から引く（不足のほうが大きい年は、不足の分を今までどおり取り崩す）。
- 結果の画面の「取り崩しの計算」は、この計画を本物のエンジンで計算する（何歳まで持つか、○歳まで持たせるなら毎月いくらまで（定額は1万円・定率は0.1%の刻みで半分ずつ絞り込む））。

### 7. 相場が下がった場合

- 時価の下落 `marketShocks[]` に `assetClasses` を書くと、器の資産の配分のうちその資産クラスの割合だけ下げる（配分の無い運用の器は全体、運用でない器は下げない）。
- 利回りの書き換え `returnShifts[]`（運用する器だけ。from〜to の年に add を足し、cap より高ければ cap）。対策の「運用の利回り」もこれで動かす。
- ストレステストの型を2つ足す: `lowReturnPeriod`（ある年から years 年のあいだ利回りを cap までに抑える）・`returnShortfall`（ずっと add だけ低い）。結果の画面の3つの型は、退職の年の年末に株・REIT が3割下がる（`marketDropAtRetirement`＋`assetClasses`）・取り崩しを始めてから（予定が無ければ退職から）10年間 年0.5%まで・ずっと1%低い。万一のときの「相場が下がったとき」は、起きる年を1年ずつ変えて、株・REIT が2〜5割下がる型を重ねる。
- 「成功率」「失敗」という言葉は使わない。確率の計算（結果の幅）は次の版。

### 8. 行と表示

- 足す行: `cf.balance.account.pooled`（まとめた金融資産。金融資産に入る）、`cf.expense.living.drawdown`（取り崩して使うお金）。
- 足した入力項目（器の利回り・運用の費用・前提の investment・assetVolatility・returnShifts）は計算に要る値なので、AI に渡す縮約版の許可リストに入れた（`reduced@3`。0015 の6）。
- 資産の推移の見出しは「金融資産は○歳まで持ちます」（尽きる年の前の年の年齢。尽きなければ表の最後の年の年齢）。口座の内訳・運用の期間の帯は表示の設定（`display.invBreakdown`・`display.invPeriods`。運用の期間は省略で「取り崩しの計画があるときだけ」）として覚える。
