# 0107. 会社と合わせたバランスシート（合算BS）を、事務所の設定で使うと決めたときだけ出す公式の画面の機能として先に置く（暫定）と、世帯ファイルの形式 0.50

- 状態: 採用（暫定。カスタム層の仕組みができたら移す）（2026-11-01）
- 固定の強さ: 骨格は、既定は使わない（事務所の設定 `features.combinedBs` が true で、役員として働く人のいる世帯のときだけ画面と提案書に出る）こと、会社の入力を計算の要求の外の区画（世帯ファイルの `household.companyBs`）に持ち計算の結果を変えないこと、組の両側の額が合わないときは会社の側の額に合わせること、形式 0.50 の変換の段（版だけを書き換える）。画面の並び・文言・段階の目安の文・点検の項目・図の色は変えてよい

## 背景

- 0105 の6 で、経営者個人（家計）と会社のバランスシートを並べて合わせる見本（合算BS）は、カスタム層（0016）の見本として、カスタム層の仕組みができてから作ると決めていた。カスタム層の仕組み（読み込み・承認と指紋・隔離実行・差し込み口・宣言型の入力欄・提案書の任意の章）は、まだ1つも動いていない。
- 会社を顧問先に持つ FP のグループに、12月の試しの版で合算BS を使ってもらいたい（利用者の判断。2026-11-01 の案 B）。カスタム層を待つと間に合わない。
- ふつうの FP・世帯には要らない機能で、標準の画面に出すと入力と画面が重くなる（0027 の8 の考え方）。会社の数字の計算は家計のソフトの範囲を超える（0105 の背景）。

## 決定

### 1. 置き場所（暫定）: 公式の画面の中の、既定では使わない機能

- 事務所の既定値（0073）に、ほかの設定と分けた区画「法人経営者向けの機能」を足し、印「合算BS（経営者個人と会社のバランスシート）を使う」を置く（事務所データの `defaults.features.combinedBs`。既定は false。欄の無い古い事務所データ・読めない値は使わない）。見せ方だけなので世帯には写さず、変えるとどの世帯にもすぐ効く。
- 印を付け、かつ役員として働く人（`employmentPeriods[].type` が `executive`）のいる世帯のときだけ、次が出る。どちらでもなければ画面・提案書は前と同じ（見るものの切り替えも出ない）。
  - 資産と負債のタブの「見るもの」（0027 の8 の差し込み口 `customViews`）に「合算BS（会社と合わせる）」。
  - 提案書の章の一覧に「会社と合わせたバランスシート（合算BS）」（章を選び、会社の数字を入れたときだけ載る）。
- 事務所の既定値は起動のときにも読む（0109 で入った読み込み）ので、開いた世帯にすぐ効く。

### 2. 中身（0105 の6 の見本の中身のとおり）

- **会社の今のバランスシートの入力**（見るものの中の「会社の数字を入れる」。万円で入れる）: 基準日（試算表の月末）、現預金・売上債権・在庫・その他の流動資産・土地・建物など・投資など・その他の固定資産・経営者への貸付金・経営者への立替金、短期借入金・長期借入金・経営者からの借入金・その他の負債、資本金・資本金のうちほかの株主の分・剰余金（マイナスも入る）、毎月の固定費（仕入は含めない）・毎月の借入の返済。経営者（家計）の毎月の固定の支出（空欄は家計の生活費＋ローン返済の月額。0105 の3 と同じ数え方）。会社の先の年の見込みは作らない。
- **3つの段**（段の切り替え。最初は③）: ①2枚を並べる（家計は今の年の年末のバランスシート、会社は試算表の数字）、②貸し借りを相殺する（4つの組を両側から消した2枚）、③足して1枚にする（家計・会社・合算の3枚）。図は家計のバランスシートと同じ部品で、段をまたいで共通の縮尺。会社の科目は「現預金」が「すぐ使えるお金」の箱、ほかは「そのほかの資産（換金しにくいもの）」の箱、負債は「借入金など」の箱に入れる（見るものの中だけ、分け方の名前を置き換える）。
- **相殺する4つの組**: 自社株（出資額。0105）↔ 資本金（ほかの株主の分を除く）、会社への貸付金（0105）↔ 経営者からの借入金、会社からの借入金（0105）↔ 経営者への貸付金、会社への未払金 ↔ 経営者への立替金。家計の側の会社への未払金の欄は無い（0 として扱う）。
  - 両側が合わないときは、**会社の側の額に合わせて見る**（両側をそれぞれ全部消し、差は個人の財産に入る。経営者の側の書き漏れとして直す考え方）。お知らせ「（組の名前）: 片方にしか載っていません。経営者の側は○万円、会社の側は○万円です。合算では会社の側の額に合わせて見ています。…」を出す（赤で煽らない。0027 の6）。
  - 会社の資産の合計と、負債＋資本金＋剰余金が合わないときもお知らせ（剰余金は資産−負債−資本金で見る）。
  - 経営者の連帯保証（0105）は、会社の借入金として合算の負債に入っているので二重に数えない（お知らせで1文）。
- **純資産の内訳**: 合算の純資産を「会社の財産（剰余金）」「ほかの株主の出資」（あれば）「個人の財産」に分ける。資本金は財産に数えない。図の純資産の箱の中も分けて積む（どれも0以上のときだけ。`BsYearModel.netParts`）。
- **指標**: 総合（合算）・個人（家計）・会社のそれぞれで、現預金 ÷ 毎月の固定の支出（何か月分。小数第1位）。目安は6か月分、できれば12か月分。届かないときは段で目指す文（「まず3か月分、次に6か月分」「まず6か月分」。0105 の3 と同じ言い方）。
- **会社の段階**（創業期・急成長期・不安定成長期・安定成長期・成熟期・異常時）を選ぶと、どちらの口座にお金を厚くするかの目安の1文（落ち着いた言い方の「ひとつの考え方」）。選ばなくてよい。
- **実力に直す点検**（任意）: 売上債権・在庫・建物など・土地（時価）・投資など・会社が保証している債務を、FP が直した額で入れる。「直した額で並べる」に印を付けたときだけ、その額で並べる（保証している債務は負債に足す）。計算では直さない。経営者への貸付金は、合算では相殺するので額を入れない（点検の説明だけ）。
- **提案書の章**: 3枚の図（共通の縮尺）・お知らせ・相殺した4つの組・純資産の内訳・何か月分・段階の1文・直した額。帳票の入力に `combinedBs`（任意。試験版 0.1.0 の中で足すだけ）。

### 3. 部品の形（後でカスタム層へ移すため）

- 値を作るのは副作用の無い関数だけ: `report/src/combinedBs.ts` の `combinedBs(会社の入力, 家計の今の年のバランスシート)`（アプリの見るものと提案書の章で同じ部品）と、`app/src/workspace/combined/combinedView.ts` の `combinedBsView(会社の入力, 今の年の BsYearModel) → BsCustomViewModel`（宣言型の入力欄・表・お知らせ・段を含む）。画面（`BalanceTab.tsx` の `CustomView`）は受け取った値を出すだけで、合算BS のことを知らない。
- 差し込み口の値 `BsCustomViewModel` に、任意の `steps`・`scale`・`groups`・`notices`・`sections`（表と文）・`form`（宣言型の欄: 万円・年月・選ぶ・印）・`empty`・`lead` を足した（0027 の8 の形を広げた。カスタム層の部品が同じ形で値を作れる）。欄の値は文字で作業の層へ返す（`onCustomField`）。
- 計算エンジンは変えない。会社の入力は計算の要求に入れない（計算の結果・キャッシュフロー表・家計のバランスシートは、印の有無・会社の数字の有無で変わらない。テストで確かめる）。

### 4. 世帯ファイルの形式 0.50

- 足すだけの MINOR: `household.companyBs`（`version: 1`・`asOf`・`amounts`・`stage`・`ownerMonthly`・`restated`・`useRestated`。入れていなければ欄を持たない。読むときに形を確かめ、読めない所は捨てる）。前の版のアプリは会社の数字を扱えないので、版を上げて閲覧だけにする。
- 変換の段は形式の版だけを書き換える（`0.49` → `0.50`。同じ日に入った 0.49〔子の貸与の奨学金の種類。0104 の追記〕の段の後に積む）。見本 `0.50/`（0.49 の見本に会社の入力を足したもの）。
- 拡張領域（0011 の4 の `ext`）ではなく世帯の区画にしたのは、元に戻す・やり直す・自動保存・読み込みの確かめを、ほかの画面の側の値（`itemChoice` など）と同じ道で通すため。区画の名前で計算の要求と分けている。

### 5. 合わせて決めたこと（0105 の未確定。利用者の「おすすめで」）

- **連帯保証を提案書に出す**: バランスシートの図の下に1行の注「会社の借入の連帯保証（○万円）は負債に入れていません（…）。保証を含めると、今の純資産は○万円です。」（帳票の入力の `balanceSheet.guarantee`。保証の無い世帯は欄を持たない）。合算BS の印に関係なく出す。
- **時点を並べる・プランを比較**でも、保証の点線の箱を出す。保証の額は今の額なので、今の年の図の下にだけ出る（時点を並べるなら「今」の列だけ）。
- **会社への貸付金の返ってくる見込み**は欄にしない（FP のメモで補う）。

## 理由

- **公式の画面に、既定では使わない機能として置く**: 試しの版に間に合わせつつ、ふつうの FP・世帯の画面を変えない。印を事務所の設定にしたのは、使うのが事務所（顧問先に会社を持つ FP）単位の判断だから。
- **会社の側に合わせる**: 会社の帳簿（試算表）は外の確かめを経た数字で、経営者の側の書き漏れのほうが起きやすい。両側を全部消すと、差がそのまま個人の財産の直しになり、図と表の数字の説明が1つで済む。
- **見通しは作らない・計算に混ぜない**: 会社の数字の計算は家計のソフトの範囲を超える（0105）。今の1枚を並べるだけなら、計算エンジンの約束を変えずに足せる。

## 後でカスタム層へ移す道筋

1. カスタム層の最小の仕組み（0105 の6 の1〜4・6）と、資産と負債のタブの差し込み口（0105 の6 の5。`BalanceTabModel.customViews` を作る部品の約束）を決めて作る。
2. `report/src/combinedBs.ts` と `combinedView.ts` を `sdk/examples/` の見本に写す（入出力はそのまま。会社の入力の欄は宣言型の入力欄 `fields/` に、値は拡張領域 `ext.<作成者>.combinedBs` に）。提案書の章は独自帳票の章にする。
3. 形式の変換の段で、`household.companyBs` を FP が選んだ拡張項目へ引き継ぐ（0011 の4 の「公式が同じ意味の項目を後から足したとき」の逆向き。引き継いだことを `meta` に記録）。
4. 公式の画面の印「合算BS」と区画を外し、事務所の既定値の印を読んだら、カスタム層の見本を入れる案内を出す。

## 影響

- 世帯ファイルの形式が 0.50 になる（0.49 のアプリは閲覧だけ）。
- 提案書: 章の一覧に「会社と合わせたバランスシート（合算BS）」（印を付けたときだけ選べる）、帳票の入力に任意の `combinedBs` と `balanceSheet.guarantee`、Typst の `pages/combined.typ`（`bs-column` に箱の名前をそのまま書く `labels` を足した）。
- 画面: 事務所の既定値の区画「法人経営者向けの機能」、資産と負債のタブの見るもの、時点を並べる・プランを比較の今の年の点線の箱、元に戻すの知らせ「会社の数字（合算BS）」。
- 計算エンジン・モデル世帯の計算の結果は変わらない。
