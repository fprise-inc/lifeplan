# 0262. 対策「毎月の生活費」を内訳で入れた生活費・2つ以上の生活費・月額の段階でも効かせる（内訳の合計をそろえる月額と、形式 0.94）

- 状態: 採用（一部未確定）（2026-11-26）
- 固定の強さ: 骨格は、生活費の行の欄 `livingExpenses[].categoryTotal`（値の箱。入力項目ID `livingExpense.categoryTotal`）の名前と意味（入れ方が内訳の行だけ。各費目の値はそのままにして、計算のときだけ内訳の割合で分け直し、合計をこの額にする。総額の行では読まない）と、形式 0.94 の変換の段（版だけ）。つまみが動かす行の選び方・月額の段階の動かし方・押せない形の理由の文・下の文の書き方は後から変えてよい（変えたら追記に書く）
- 前提にする記録: 0048（基本生活費の入力項目）、0100（内訳の10費目）、0084（対策に最初から出す項目）、0036（プランの差分・合成の対策）、0162（入力で直した欄と対策）、0011・0035（形式の版の上げ方）、0015（AI接続口の縮約版）

## 背景

- 結果のタブの対策の「毎月の生活費」のつまみを動かしても、グラフ（選んだプランの金融資産）が動かない世帯があった（利用者の報告。2026-11-26）。
- 原因: つまみは世帯の生活費のうち「入れ方が総額の最初の行」の月額だけを書き換えていた。一方で、つまみを出すか・下の文・基準は現状の世帯から決めていた。そのため次の形で、つまみが出ているのに効かない・ほとんど効かなかった。
  1. 選んだプランの中で、生活費の入れ方を「内訳で」にした（現状は総額）。プランを反映した世帯に総額の行が無く、何も書き換えずに終わる（全く動かない）。
  2. 毎月の生活費が2つ以上あり、最初の総額の行の期間が短い（その期間だけ動く）。
  3. 段階を「月額」で入れている（その段階より後は動かない。下の文は割合の段階しか書かないので分からない）。
- 現状で内訳の入れ方をしている世帯には、つまみ自体が出なかった。

## 決定（利用者の判断「B＋C＋A、案1」）

### 1. 内訳の入れ方でも効かせる（案1: 合計をそろえる月額）

- 入れ方が内訳の行では、つまみの値を内訳の合計として読む。動かすと、生活費の行に「内訳の合計をそろえる月額」`categoryTotal`（値の箱）を書く。各費目の値と推定の印はそのままで、計算のときだけ内訳の割合で分け直し、合計をこの額にする（推定の費目は推定のまま。推定し直しても食い違わない）。
- つまみの値を内訳の合計と同じ額にしたときは、そろえる月額を書かない（外す）。
- 計算（`expense.living` の改訂5）: `categoryTotal` があれば、各費目の最初の月額を内訳の割合で分け直す（`conv.expense.share`。端数は最初の費目。内訳の合計が0なら全部を最初の費目）。割合の段階・月額の段階は、分け直した後の額から今までどおり。総額の行では読まない。書いていない世帯の結果は1円も変わらない。
- 今の値（つまみの値）: 総額の行は月額、内訳の行は `categoryTotal` か内訳の合計（`livingTotalOf`）。現状が内訳の入れ方の世帯にもつまみを出す。
- 入力の画面: 内訳の「合計」の行は今までどおり内訳の合計で、そろえているときは「計算は月○万円にそろえています」と添える。その下に「計算でそろえる合計（月額）」の欄を、そろえているときだけ出す（結果に効く値を隠さない。空にすると、そろえるのをやめて内訳の合計で計算する）。
- 段階の「今の額」（段階の欄の下の額の目安）・預金に残しておく額の目安・予備費の元の額も、そろえた額で数える。

### 2. 動かす行と月額の段階（C）

- つまみは、計算基準月に当てはまる行を動かす（始まりが計算基準月以前で、終わりが計算基準月以後。2つ以上なら総額の行を先に、同じなら並びの順）。当てはまる行が無ければ、これから始まる最初の行。入れ方は総額・内訳のどちらでもよい（`leverLivingOf`）。
- 月額で入れた段階も、つまみの値と今の値の比で同じ割合で動かす（円未満は四捨五入）。割合の段階はそのまま（割合なので一緒に動く）。
- つまみの下の文: 割合の段階に加えて、月額の段階（「子の独立後は月25.5万円」）と、節目が「その他」の段（その年月で「2030年4月から90%」）も書く。毎月の生活費が2つ以上なら「毎月の生活費 2（2026年10月から）だけを動かします」、内訳の行なら「内訳（合計月28万円）を割合のまま月26万円にそろえます」を先に書く。

### 3. 値・基準・下の文は選んだプランを反映した世帯から

- つまみの下の文は、選んだプランを反映した世帯（プランの差分と動かした値を反映した要求）から作る。
- つまみの値と「基準（A）」は、動かした値があればその値、無ければ、キーに戻せない差分（入力の画面でプランを直した差分。`@plan`）があるプランはそのプランを反映した世帯から読み、無ければ今までどおり現状から読む（`naturalValue`）。`@plan` のあるプランで、つまみを現状と同じ額に動かしても、プランの中身と違う額なら値として残す（`normalizeValues`）。

### 4. 効かない形（A）

- 選んだプランを反映した世帯で、つまみが効かない形（生活費が無い・計算の期間に当てはまる行が無い・内訳が1つも無い・総額の月額が空）なら、つまみと数の欄を押せない形にし、下の文の代わりに理由を出す（例「内訳が1つも入っていないので動かせません（入力の画面の基本生活費で内訳を入れます）」）。値は記録しない（`livingLeverBlock`）。

### 5. 世帯ファイルの形式 0.94（足すだけの MINOR。0.93 の後）

- 足した欄: 生活費の行の `categoryTotal`（任意。値の箱）。前の版のアプリは計算の入力の検査で知らない欄を通さないので、版を上げて閲覧だけにする。
- 変換の段（`crates/household-store/src/migrate.rs` の `add_living_category_total`）は版だけを書き換える（前の版の世帯は欄が無い＝内訳の合計で計算）。控え・自分で作った見本の最初の状態の中身は変えない。版の番号は定数 `LIVING_CATEGORY_TOTAL` の1か所。
- 見本 `0.94/`（内訳の行〔内訳の合計 月33万円〕を月30万円にそろえている）。
- プランに持つ値は今までどおり合成の対策 `livingMonthly` の差分（値はつまみの値）で、差分の形は変えない。欄 `categoryTotal` が世帯に入るのは、プランを現状に反映したとき・入力の画面の欄・AI からの入力のとき。

### 6. あわせて直したもの

- 対策の「変えたこと」・入力のホームの違いの一覧で、まとまった値の差分（生活費の内訳の月額など）の変えた後の値を、並びの要素の ID で読むようにした（前は値の中を道でたどって見つからず「食費: なし」と出ていた）。
- AI接続口: 入力の形の案内（生活費の区分）に `categoryTotal` の書き方を足し、縮約版の許可リストに `livingExpense.categoryTotal` を入れた（計算に要る。`reduced@35`）。画面の操作の手引き（`docs/app-guide/04-results.md` の `results.levers`）に生活費のつまみの効き方を書いた。
