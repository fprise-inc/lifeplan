# 0169. 見つかった不具合の直し（別居の婚姻の保育料と出生後休業支援給付・表の最後の年の年齢の数え方と今年より前に終わる表・計算できないときの札・金額の丸め・前の言葉）

- 状態: 採用（一部未確定）（2026-11-08）
- 固定の強さ: 内部（計算エンジンの部品 `education.nurseryFee` の改訂5・`benefit.employment` の改訂5、画面の表の最後の年の決め方と文。世帯ファイルの形式の版は変えない）
- 前提にする記録: 0008（表の最後の年の標準）、0029（保育料）、0070・0073（表を何歳まで見るかの選び方・事務所の既定値）、0130（言葉の決まり）、0150（打った値は推定と同じでも確定）、0156（婚姻の状態の欄・ひとり親控除）

## 背景

まとめて調べた不具合のうち、別々の所にある小さめの物をまとめて直した。

1. **別居の婚姻で、保育料がひとり親世帯等の軽減のまま**: 保育料（`education.nurseryFee`）のひとり親世帯等は「その月に世帯にいる子の親が1人」だけで決めていた。0156 で婚姻の状態の欄（`maritalStatus`）を足し、ひとり親控除は「婚姻している（別居など）」ならひとり親にしないが、保育料はその欄を見ていなかった。子の親ではない再婚の相手が世帯にいる（配偶者の関係がある）ときも、ひとり親世帯等になっていた。
   同じ所を見ると、育児休業の出生後休業支援給付（`benefit.employment`）も「世帯に配偶者の関係が無い＝配偶者がいない」とみなし、別居して婚姻している人にも配偶者の育児休業の要件を外していた。
2. **101歳以上の人がいると計算できないのに「準備できています」**: 表の最後の年の標準は「若い方が100歳になる年」で、すでに100歳を過ぎた人では今年より前の年になり、計算エンジンが `E_ARGUMENT endYear` で止まった。そのとき画面は前の計算の残りの結果で、プランの札に「100歳まで足りる」、目標に「準備できています」を出していた。100歳ちょうどでは表が0年になった。
3. **1月1日生まれで「100歳まで」が99歳の年になる**: 表を何歳まで見るかの選び方は「年齢に達する月」（法律の数え方。1日生まれは前の月）で年を決め、年齢の欄と表の年齢の行は「その年の12月末の年齢＝生まれ年との差」で見せていた。1月1日生まれだけ、選び方の「100歳」が前の年（99歳の年）になった。
4. **同じ値の丸めが違う**: 結果のタブの対策の基準は「月20.9万円」、入力の欄の「現状:」は「月21万円」だった。
5. **事業所得の欄の「?」の最初の一言**が「確定申告書の所得金額（青色申告特別控除の前）」で、確定申告書の所得金額（控除の後）を写すと控除を2回引く読み方ができた。
6. **前の言葉・前の決まりの文が残っていた所**（4か所）: 年齢カーブの「?」の「この期間の伸び（年率）」（欄の今の名前は「伸び率（年）」）、事務所の既定値の推定の一覧の「家賃の変動率（年）」（欄は「家賃の伸び率（年）」）、索引の 0141 の行の「ひとり親控除は計算していない」、`defaultMark.ts` の冒頭の「値の無い欄に既定と同じ値を打っても確定にしない」（0150 で確定にした）。

## 決定

### 1. 婚姻の状態の見方を、ひとり親控除・保育料・出生後休業支援給付でそろえる

- sdk に `marriedAt(ctx, relations, member, m)` を足す。月 m に婚姻しているか（配偶者のない者でないか）を、ひとり親控除（`tax.survivorStatus`）と同じ順で決める:
  1. 配偶者の関係（法律婚・事実婚）がその月にあれば婚姻している
  2. その月までに終わった法律婚の関係があれば婚姻していない（離婚・死別。欄は使わない）
  3. 無ければ欄 `maritalStatus` が「婚姻している（別居など）」のときだけ婚姻している（省略は婚姻していない）
- **保育料**（`education.nurseryFee` の改訂5）: ひとり親世帯等は「その月に世帯にいる子の親が1人で、その親が `marriedAt` で婚姻していない」とき。配偶者のない者（母子及び父子並びに寡婦福祉法6条1項）の判定を、ひとり親控除と同じ見方にした。子の親ではない再婚の相手が世帯にいる月も、ひとり親世帯等にしない。
- **出生後休業支援給付**（`benefit.employment` の改訂5）: 世帯に配偶者の関係が無くても、欄が「婚姻している（別居など）」なら配偶者がいるとみなす。世帯の外の配偶者の育児休業は分からないので、配偶者の要件を満たさないとして出さない（決めたこと。控えめの側に倒した。配偶者が育児休業をとるなら、配偶者を世帯に入れて休業の期間を入れる）。
- 婚姻の状態の欄の「?」に、保育料と出生後休業支援給付でも使うことを足した。

### 2. 表の最後の年は、少なくとも5年分にする。計算できないプランに「足りる」を出さない

- 年齢で決める表の最後の年（標準・選び方・事務所の既定値・家族を直したときの追いかけ・空の世帯）は、計算基準月を渡して、表の最初の年（計算基準月が年の途中なら翌年）から**少なくとも5年分**になるように後ろへずらす（`MIN_TABLE_YEARS`）。若い方が96歳以上で100歳まで（など）を選んだ世帯だけが変わる（決めたこと。「今の年齢＋数年」の案のうち、選び方の年齢ごとに年がばらつかない形にした）。
- ずらした結果、いくつもの選び方の年齢が同じ年になるときは、選び方の欄には既定の年齢（無ければ一番上の年齢）を見せる。
- 年で入れる欄・年齢で入れる欄の下限は、計算基準月の年ではなく表の最初の年にする（年の途中の計算基準月の年にすると表が0年になる）。
- 計算エンジンがエラーを返したプラン（前の計算の残りの結果を持っている）は、プランの札を「計算できません」、結論の1文を「今の入力では計算できませんでした」、目標の札を「計算できていません」（「必ず」の目標の準備OK は0件）にする。選んだプランか基準のプランのどちらかが計算できないとき。

### 3. 「○歳になる年」は、その年の12月末に○歳の年（生まれ年＋年齢）

- 表の最後の年を年齢で決めるとき（`endYearForAge`）は、表の年齢の行・年齢の欄・ヒントと同じく「生まれ年＋年齢」にする。1日生まれの「達する日」（前の月）を使わない（決めたこと。表は年ごとで、年齢の行と同じ年齢・年になることを優先した。法律の「達する日」は働き方・年金など月で効く所だけで使う）。
- 1月1日生まれの世帯だけ、標準の表の最後の年が1年延びる。保存した世帯の表の最後の年は、黙って書き換えない（家族を直したときの追いかけ・選び方を選び直したときに新しい数え方の年になる）。

### 4. 金額の欄の文の丸め

- 入力の欄の値の文（プランの差分の文・「現状:」）は、10万円以上の端数を、対策の値の文と同じく万円の小数1桁（千円の位で四捨五入。`amountText`）にする。1万円ちょうどの倍数は今までどおり「21万円」、10万円未満の端数は円。

### 5. 文の直し

- 事業所得の「?」の最初を「青色申告特別控除を引く前の事業所得の額」にし、申告書の所得金額は控除の後なので、そのまま写すと控除を2回引くことを書き足した。
- 年齢カーブの「?」は「伸び率（年）」、推定の一覧は「家賃の伸び率（年）」、索引の 0141 の行は「ひとり親控除は計算に入れ、児童扶養手当は計算していない」、`defaultMark.ts` の冒頭は 0150 の決まりに直した。

## 理由

- 婚姻の状態の欄はひとり親控除のために足したが、FP が「婚姻している（別居など）」を選ぶのは、同じ人が制度の上で配偶者のある者だから。制度ごとに違う見方をすると、同じ世帯で控除と保育料の答えが食い違う。
- 表の最後の年が今年より前になると、計算そのものが止まる。止めるより、短くても表を出す方が FP の手が止まらない。5年は、短い表でも年ごとの収支の流れが見える長さとして決めた。
- 計算できないときに前の結果で「準備できています」と出すのは、誤った安心を与える。

## 影響

- 計算の結果が変わる世帯:
  - 世帯にいる親が1人で、婚姻の状態の欄が「婚姻している（別居など）」か、子の親でない配偶者が世帯にいる世帯の0〜2歳の保育料（自動の計算）。ひとり親世帯等の軽減（所得の上限の77,101円未満の段・多子の軽減の数え方）が外れる。例: 住民税の所得割の合算額が77,100円の世帯で、月9,000円 → 30,000円。
  - 世帯に配偶者の関係が無く、婚姻の状態の欄が「婚姻している（別居など）」の人の出生後休業支援給付（出なくなる）。
  - 本人・配偶者のうち若い方が1月1日生まれの世帯の標準の表の最後の年（1年延びる。新しく作る・家族を直す・選び直すとき）。
  - 若い方が96歳以上の世帯の表の最後の年（少なくとも5年分）。
- 画面: 入力の欄の金額の文（「月21万円」→「月20.9万円」のように、10万円以上の端数が小数1桁になる）、計算できないときの札と結論の1文、婚姻の状態・事業所得・年齢カーブの「?」の文、事務所の既定値の推定の一覧の名前。
- 世帯ファイルの形式の版・値の形は変えない。
