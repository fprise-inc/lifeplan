# 0180. 持ち帰り・明細・計算の時間切れの直し（つまみの補足の呼び名・時間切れの頼み直しと文・口座ごとの短い期間・返品で負になった内訳・割合だけの行・同じ明細を別の口座に入れる前の知らせ）

- 状態: 採用（一部未確定）（2026-11-08）
- 固定の強さ: 内部（画面の文・知らせの符号と文・頼み直しの回数と待ち・同じ明細とみなすしきい値は変えてよい。世帯ファイルの形式の版・明細の記録の形・持ち帰りの中身の型・計算エンジンは変えない）
- 前提にする記録: 0005（計算エンジンの実行環境と二本立て・時間の上限）、0009（提案書）、0030（持ち帰り用のレポート）、0034（明細の取り込み）

## 背景

明細・帳票・持ち帰りの出口を調べて見つかった不具合を、まとめて直した。

1. **持ち帰り用のレポートに子の呼び名が入る**: 生活費の節目に「子の独立」が2つ以上あると、つまみ「毎月の生活費」の補足が「第2子（呼び名）の独立後は85%」になり、顧客に渡すファイルにそのまま入った（0030 の2 で「入れないもの」にした呼び名）。補足の文は結果の画面と持ち帰りで同じ部品（`plans/items.ts` の `leverNote`）を使い、構成員の呼び方（呼び名つき）で子を書いていた。持ち帰りの目印のテストは、ご本人の呼び名とメモだけに目印を入れていた。
2. **パソコンの負荷が高いと計算が時間切れになり、止まったまま**: 本体の計算の時間の上限（10秒）は経った時間で測る（`crates/engine-host` の deadline。CPU を取れない時間も数える）。アプリは最大8本を同時に計算するので、ほかの重い作業と並ぶと重い世帯が `E_HOST_TIMEOUT` になった（調べた PC で、負荷 100 を超えると8本のうち1本）。そのとき画面は「今の入力では計算できませんでした（E_HOST_TIMEOUT）」と入力が悪いように書き、見出しの「確定前」のまま計算し直さなかった（何か入力を変えるまで）。提案書は要求のどれか1つが時間切れになると全部止まった。
3. **12か月の口座と25日の口座を混ぜると、短い期間の注意が出ない**: 短い期間の判定（3か月＝85日未満で強い注意・候補を要確認）は一番長い口座の日数だけで見ていた。月平均は口座ごとの日数で割るので、25日しかない口座の数週間の買い物が、そのまま月の額になって生活費の候補に入った。
4. **返品で内訳の月平均が負になると、画面と候補の説明が食い違う**: 明細の期間の前に買った物の返品が大きいと、内訳（被服・美容など）の月平均が負になる。行の額は 0円にしていたが、画面は「0円」の下に負の内訳を並べ、候補の説明は明細に出てきたその内訳を「明細に出てこない内訳」と書いていた。
5. **確認シートで割合だけ書いた行が黙って捨てられる**: 「どこに入るか」が空で「事業の割合」だけを書いた行は、印の無い行として読まず、「印の付いた行はありませんでした」とだけ出た。
6. **同じ明細を別の口座として取り込むと、全部の行が二重になる**: 0034 の8 は「別の口座の同じ行は重ねない」（家族それぞれのカードで同じ日に同じ店で同じ額を払うことはある）。同じファイルそのものは指紋で止まるが、保存し直したファイル（改行だけ違うなど）を、登録し直したカードや家計簿アプリの書き出し（同じカードの行を含む）として入れると、生活費がそのまま2倍近くになり、知らせも出なかった。利用者の判断で、重ねない決めは変えずに、取り込む前に知らせることにした。

## 決定

### 1. 顧客に渡す文は、呼び名を使わず続柄で書く

- 構成員の呼び方（`input/labels.ts` の `memberLabels`・`memberLabel`）に「呼び名を付けない」指定（`nicknames: false`）を足した。続柄（ご本人・配偶者・第1子・父・義母など）だけになる。
- 動かせる項目の補足（`MovableItem.note`）に `forCustomer` を足し、持ち帰り（`takeaway/build.ts` の `leverItems`）はこれで補足を作る。生活費の補足は「第2子の独立後は85%」になる。結果の画面・プランの編集の補足は、FP が見分けやすいよう今までどおり呼び名つき。
- 目印のテストを広げた（`app/test/takeaway.test.ts`）:
  - 呼び名の目印を、ご本人だけでなく世帯の全員に付ける（`takeawayFixture.ts`）。
  - 子の独立の節目が2つある生活費の世帯で、中身に目印が出ないこと。
  - FP だけが見る文字（呼び名・メモ・確かめた印のメモ・確かめの一覧の印の見出し・仮の値の理由・内訳を分けた行の名前・案の注記）に目印を入れて、中身に出ないこと。
  - 中身の文字の欄（計算の要求の外）を並べ、決まった欄の一覧と同じであること（欄が増えたら止まり、呼び名やメモが入らないかを確かめてから一覧に足す）。計算の要求の中は、今までどおりスキーマの自由記述の欄（`FREE_TEXT`）で見る。
- 提案書（0009）の材料のテストも、メモの他の FP だけが見る文字（上と同じ）に目印を入れて、入らないことを確かめる。提案書に呼び名を入れない決めは無い（0030 の「入れないもの」は持ち帰りだけ）ので、提案書の変更点の文の呼び名は今までどおり（未確定に書く）。

### 2. 時間切れは、その枠だけを頼み直し、入力のせいと書かない

- **頼み直し**: 本体の正の計算（`host.compute`）を包み（`engine/retry.ts` の `retryTimedOut`）、`E_HOST_TIMEOUT` になった枠だけを、1秒・3秒待って2回まで頼み直す。頼み直すのは時間切れの枠だけなので、同時に計算する本数が減り、通りやすくなる。主画面・提案書・万一・取り崩しの計算など、本体の計算を頼む所すべてに効く（本体の道具の作り方の1か所で包む）。ほかのエラー（制度データに値が無い・メモリーの上限など）は入力で決まるので頼み直さない。
- **文**: 時間切れは「計算に時間がかかりすぎて、途中で止まりました。入力のせいではなく、パソコンの負荷が高いときに起きます。ほかのアプリを閉じるか、少し待ってから、もう一度計算してください（E_HOST_TIMEOUT）」。入力のタブでも「今の入力では計算できませんでした」を付けない（`engineErrors.ts` の `HOST_BUSY_TEXT`・`isHostBusy`）。`E_HOST_MEMORY` にも文を足した（入力で決まるので「今の入力では」のまま）。
- **もう一度計算する**: 頼み直しても時間切れなら、文の横に「もう一度計算する」のボタンを出す。押すと、正の計算になっていない枠（時間切れの枠）だけを計算し直す（二本立ての `release`）。自動で何度も頼み直さないのは、本当に重いときに PC をさらに重くし続けないため。
- **提案書**: 時間切れの要求だけが頼み直される（上の包み）。それでも終わらなければ「作れませんでした。計算に時間がかかりすぎて…「作り直す」を押してください（E_HOST_TIMEOUT）」。
- **時間の上限の決め方（0005）は変えない**: 経った時間で測るのは、quickjs-ng の割り込みの仕組みで確実に打ち切れる測り方がこれだけで、CPU の時間を OS をまたいで同じに測る手段を本体に入れるほどの理由が無いため。負荷の山は一時的で、時間切れの枠だけの頼み直しで同時の本数が自然に減る。上限の数値（10秒）と同時の本数（8）を負荷で変えるかは、0005 の未確定（計算プロセスを分ける回）と合わせて決める。

### 3. 期間の短さは口座ごとに見る

- 明細のまとめ（`statement/src/summary.ts`）に `shortAccounts` を足す: 期間が3か月（85日）に満たない口座のうち、家計に入る行がある口座（名前と日数）。一番長い口座も短いときは入れない（今までの全体の強い注意 `S_VERY_SHORT_PERIOD` で知らせる）。
- 短い口座があれば、知らせ `S_VERY_SHORT_ACCOUNT`（注意）に口座の名前と月の数を出す（「期間が3か月に満たない口座があります（「配偶者のカード」0.8か月）…」）。候補（`candidates.ts`）は要確認にし、説明に「期間が3か月に満たない口座（…）があるため、参考の値です」。
- 1年に満たない注意（`S_SHORT_PERIOD`）と季節の注意は、今までどおり一番長い口座で見る（決めたこと: 短い口座の年1回の支払いの見落としは月平均を大きく誤らせない。強い注意を出す 85日未満の口座だけを口座ごとにした）。

### 4. 返品で負になった内訳は、印を付けて0円にし、候補は今の値を残すと書く

- 生活費の行（`LivingLine`）に `negative`（内訳の和。負の数）を足す。行の額は今までどおり 0円。知らせ `S_NEGATIVE_LIVING`（お知らせ）に内訳と負の額を出す。
- 画面（明細の数の区画）は、その行の内訳の後に「（返品・取り消しが多く月平均が負のため、0円で数えています）」。
- 候補（内訳の形の生活費）は、月平均が0円以下になった内訳を「明細に出てこない内訳」と分けて、「返品・取り消しが多く月平均が0円以下になった内訳（被服・美容）は今の値を残します」と書く。値は今までどおり今の値を残す（決めたこと: 0円で置き換えるより、期間の前の買い物の返品で偶然負になった月の値より今の値のほうが近い）。

### 5. 割合だけの行は、事業の経費として要確認で読む

- 確認シートの読み戻し（`statement/src/sheet/read.ts`）で、「どこに入るか」が空で「事業の割合」が書かれた行は、事業の経費（割合つき）として読み、候補を要確認にする（「「どこに入るか」が空でした。事業の割合が書かれているので、事業の経費として読みました」）。割合は事業の経費のときにしか意味が無いので、書いた方の答えはこれと読むのが自然。
- お使いになった方の働き方で事業の経費を選べない行と、読めない割合（「半分」など）は、候補にせず知らせ（`S_SHEET_VALUE`）に出す。

### 6. 同じ明細を別の口座に取り込む前に聞く

- 取り込む前に、取り込もうとしている明細の行と、すでにある別の口座の行を比べる（`statement/src/log.ts` の `sameAsOtherAccount`）。使った日・金額・店の鍵（摘要を整えたもの。空白・全角半角の揺れをそろえる）が同じ行を1行ずつ対にして数え（同じ行を2回数えない）、一番多く一致した口座を返す。比べるのは FP が外していない取り込みだけ。
- **しきい値**: 一致した行が、取り込もうとしている行の **8割以上**で、かつ **3行以上**（`SAME_STATEMENT_RATIO`・`SAME_STATEMENT_MIN_ROWS`）。8割は「大半が同じ」の目安で、1行だけ直して保存し直した明細・長い明細の一部（同じカードの1か月分）も拾う。家族それぞれのカードで同じ店の同じ額が数行重なる程度では出ない。3行は、2行ほどの短い明細の偶然の一致で聞かないため。
- **画面**: 当てはまると、取り込む前に「同じ明細ではありませんか？（「ご本人のカード」の口座と 8件が同じです。…）」と、「別の明細として取り込む」「やめる」を出す。「別の明細として取り込む」は今までどおり取り込み、0034 の8 のとおり別の口座の同じ行は重ねない（両方を数える）。同じ口座に取り込み直すときは聞かない（同じ口座の中の重なりは今までどおり二重にしない）。
- 0034 の8 の決めは変えない。知らせを出すのは取り込む前の1回だけ（取り込んだ後の数の区画には出さない）。

## 理由

- 呼び名は、構成員の呼び方の部品を通るどの文からも入りうる。顧客に渡す文を作る側で「呼び名を使わない」と指定する形にすると、補足を作る部品を2つに分けずに済み、画面の文は変わらない。中身の文字の欄を一覧で見張ると、新しい欄を足したときに確かめ漏れが無い。
- 時間切れは入力のせいではないので、入力を直させる文は FP を迷わせる。時間切れの枠だけを少し待って頼み直すと、負荷の山を避けつつ同時の本数が減る。自動の頼み直しは回数を限り、その後は FP が押す形にした。
- 0034 の8 が口座ごとに日数で割ると決めたのと同じ考えで、期間の短さも口座ごとに見るのが自然。
- 画面の数字と説明の文が合わないと、FP がどちらを信じてよいか分からない。

## 影響

- 計算エンジン・世帯ファイルの形式の版・明細の記録の形・持ち帰りの中身の型は変えない。計算の結果の数字は変わらない。
- 持ち帰り用のレポート: 子の独立の節目が2つ以上ある合計の生活費で、子に呼び名を付けた世帯の、つまみの補足（呼び名が消える）。
- 画面: 時間切れの文と「もう一度計算する」のボタン、提案書の時間切れの文。時間切れのとき、本体の計算が最大2回まで頼み直され、結果が出るまでの時間が延びることがある（最も長くて 30秒あまり）。
- 明細: 25日分のような短い口座を混ぜた世帯の生活費の候補が要確認になる（今までは最初からチェックが付いていた）。返品で負になった内訳の知らせと説明。割合だけの行が要確認の候補になる。同じ明細を別の口座に入れる前の問い。
