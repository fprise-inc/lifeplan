# 0079. 入力項目「収益不動産」（貸している不動産を物件ごとに）と、物件を見分ける欄・世帯ファイルの形式 0.31

- 状態: 採用（一部未確定）（2026-10-28）
- 固定の強さ: 世帯のデータの欄（`accounts[].property` の任意の欄 `name`・`kind`・`location`・`share`・`tenure`・`units`・`area`・`memo` の名前と値の一覧、どれも計算に使わないこと）、入力項目ID（`account.property.name`・`account.property.location`・`account.property.memo`）、段階の ID `rental`、「中身（property）を持つ不動産の器が収益不動産の物件」という読み方は骨格。欄の並び・標準と詳細の分け方・文言・一覧表の列・ローン残高の目安の出し方は後から変えてよい（変えたら追記に書く）
- 前提にする記録: 0004（入力項目ID）、0011（世帯ファイルの形式と一方向の移行）、0015（AIに渡す縮約版）、0028（住まい以外の不動産の中身）、0030（持ち帰り用のレポート）、0035（足すだけの形の版上げ）、0039（持ち始める時点）、0040（段階と例外の年）、0045（入力のホームのカード）、0077・0078（標準／詳細）

## 背景

- 住まい以外の不動産は、入力項目「貯蓄・運用」の口座の1種類（器の種類 `realEstate`）で、「土地と建物に分ける」をオンにすると中身（0028）の欄が出る作りだった。不動産を何件も持つ世帯では、口座の並びの中に物件が埋もれ、物件ごとの評価額・ローン・家賃を見比べる場所が無い。
- 不動産を専門とする FP が、そうした世帯の物件を整理・分析できるようにする。全体は段階に分け、この記録は最初の段階（入力項目を独立させ、物件を見分ける欄と一覧表を足す）。利回り・手残り・民泊の売上と経費・帳票などは後の段階で足す。

## 決定

### 1. 入力項目「収益不動産」

- 段階（入力のホームの項目）`rental` を足し、標準の並びで「貯蓄・運用」の後に置く（15項目。0045 の並びの相対の順番は変えない）。まとまりは「資産と備え」。絵は `app/src/assets/illustrations/rental.webp`（集合住宅と鍵。ほかの絵と同じ CC0）。
- 物件は、不動産の器（`accounts[]` の `kind: "realEstate"`）のうち**中身 `property` を持つもの**。中身の無い不動産（評価額だけ）は「貯蓄・運用」の「その他の資産」に残る。どちらも同じ器の型で、集まりは分けない。
- 「＋ 物件を足す」で1件ずつ足す。足した物件は中身を持つ（家賃は「未入力（0円で計算中）」の印で始める）ので、最初から中身の欄が出る。「土地と建物に分ける」のスイッチはやめた。
- 物件ごとに1つのまとまり。見出しは「物件名（種類・評価額）」。0028 の欄（構造・建った年・土地の割合・取得・家賃・空室・変化率・期間・経費・段階と例外の年・売却・その物件のローン・持ち始める時点）はこちらへ移した。欄のキーは貯蓄・運用の中にあったときのまま（`sav/<器の ID>/…`）にして、次回確かめるの印・読み替え表の当て先をそのまま当てる。
- 「?」の説明: 「人に貸して、家賃や地代を受け取っている不動産です（アパート・区分マンション・戸建て・店舗・駐車場・貸している土地など）。貸していない土地・別荘は『貯蓄・運用』のその他の資産に入れます」。
- 持っていない世帯では、ほかの項目と同じ「まだ入れていない」の控えめな出し方で、「当てはまらない」の1押しで抜けられる。カードの要約は「1件・評価額 1,800万円」。
- 不動産の一時の経費（出るお金の行の種類 `realEstateCost`。大規模修繕・原状回復など）の区画も、貯蓄・運用からこちらへ移した（行の属するカードは種類で決まるので、保存済みの行もそのまま移る）。
- 計算の知らせのうち物件のもの（取得の入力が無い・土地の割合の目安）は、この項目を開く。

### 2. 貯蓄・運用に残す不動産

- 区画の名前を「その他の資産」にし、「＋ 貸していない不動産」（中身の無い不動産の器）と「＋ その他の資産」を残す。まとまりの「?」で「人に貸している物件は『収益不動産』で入れます」と案内し、「収益不動産へ移す」（中身を持たせる。評価額と名義はそのまま）を置く。
- 貯蓄・運用の要約に、収益不動産の物件の評価額は数えない（二重に数えない）。

### 3. 物件を見分ける欄（`accounts[].property` の任意の欄。計算には使わない）

| 欄 | 形 | 標準／詳細 |
|---|---|---|
| `name` 物件名 | 文字（80字まで）。無いときの呼び方は「物件1」「物件2」（収益不動産の中の並びの番号） | 標準 |
| `kind` 種類 | `condo` 区分マンション・`apartment` 一棟アパート・`mansion` 一棟マンション・`house` 戸建て・`commercial` 店舗/事務所・`parking` 駐車場・`land` 貸している土地・`lodging` 民泊・宿 | 標準 |
| `location` 所在地 | 文字（40字まで）。都道府県・市区町村まで。番地は持たない | 詳細 |
| `share` 持分 | 率（0〜1）。共有のとき | 詳細 |
| `tenure` 権利 | `ownership` 所有権・`leasehold` 借地権 | 詳細 |
| `units` 戸数 | 整数（1〜9999） | 一棟（一棟アパート・一棟マンション）のとき標準、ほかは詳細 |
| `area` 面積 | `land` 土地・`floor` 建物の延べ床（㎡。10進の文字列） | 詳細 |
| `memo` メモ | 文字（400字まで） | 詳細 |

- 計算部品（`asset.realEstate` など）はこれらを読まない。入れても計算の結果は変わらない（テストで確かめる）。
- 持分を1未満で入れたら、欄に「計算はまだ全部を名義の人の分として扱います」の知らせを出す（持分の計算は後の段階）。
- 民泊・宿を選んだら、欄とまとまりに「売上と経費の入れ方、所得の区分（雑所得・事業所得）は今後の版で対応します。今は家賃の欄に月の売上の見込みを入れてください」と出す。今は選択肢を足すだけで、計算は不動産所得のまま。
- 空室は家賃収入の「空室を見込む割合」だけで入れる。いま埋まっている戸数・部屋ごとの家賃の表は持たない。

### 4. 物件の一覧表

- 収益不動産の項目の上に、物件名・種類・評価額・ローン残高・月の家賃（空室を見込んだ後）と合計の行を出す。計算の結果を待たず、入力から出せる数字だけ。
- ローン残高は、その物件を指す負債（`debts[].property`）の今の残高（入れていればその値）。入れていなければ借入額・最初の金利・返済の方法・期間から、計算の基準の月の残高を出す目安（金利の段階・繰上返済・ボーナス返済は見ない）。
- 月の家賃は、家賃（月額）×（1−空室を見込む割合）の円未満を切り捨てた額（エンジンと同じ）。
- 利回り・手残りは後の段階で足す。

### 5. 世帯ファイルの形式 0.31

- 3 の欄を足したので、形式の版を `0.31` に上げた（足すだけの MINOR。0011 の5・0035 の1）。`0.30` のアプリは知らない欄を読み落として書き戻すので、版を上げて閲覧だけにする。`0.30` → `0.31` の変換の段は形式の版だけを書き換える。
- 保存済みの世帯の中身のある不動産は、何もしないで収益不動産に出る（器も集まりも同じ。移し替えの段は要らない）。
- 見本 `crates/household-store/tests/fixtures/household-format/0.31/` は、`0.30` の見本の中身のある不動産に3の欄を全部入れた物。

### 6. AI に渡す縮約版・持ち帰り用のレポート

- 物件名・所在地・メモは、FP が書いた文で個人に近い（所在地は家族の他の情報と合わせると世帯を絞り込みやすい）ので、入力項目ID を分け（`account.property.name`・`account.property.location`・`account.property.memo`）、縮約版では**文章の項目として既定で外す**（FP が項目ごとに足せる。0015 の6）。種類・持分・権利・戸数・面積は決まった値か数なので、`account.property` のまま縮約版に入る。許可リストの版を `reduced@21` にした。
- 持ち帰り用のレポート（0030）では、物件名・所在地・メモを外す。

## 理由

- **器と集まりを変えない**: 0028 で決めたとおり、不動産の器は評価額・名義・時点・中身を持ち、計算もバランスシートもこの器で動いている。集まりを分けると、移行の段で中身を書き換え、評価・税・BS の読み方を2つ持つことになる。「中身を持つ器＝物件」と読めば、保存済みの世帯はそのまま新しい項目に出る。
- **貯蓄・運用に「＋ 貸していない不動産」を残す**: 貸していない土地・別荘も相続税の目安では不動産の評価の割合で見る（器の種類 `realEstate` が要る）。「その他の資産」に入れると種類が変わり、相続税の目安とバランスシートの分け方が変わる。物件を足す口は収益不動産だけにし、貯蓄・運用は「評価額だけの不動産」に名前と案内を絞って、同じ物を2か所で足す重なりを小さくした。貸すことになったら「収益不動産へ移す」で同じ器のまま移す。
- **欄のキーを変えない**: 欄のキーは次回確かめるの印と、0.16 までの読み替え表が当て先を引くのに使う。変えると保存済みの印が当たらなくなる。
- **物件名・所在地・メモを縮約版から既定で外す**: 計算に要らず、人が書いた文で、所在地は個人の特定に近い。分析の補助に要るときは FP が文章の項目として足せる。

## 代案（採らなかったもの）

- 新しい集まり `rentalProperties` を作って器を移す: 0028 の代案と同じ理由で採らない（評価・BS・税の読み方が2つになり、移行の段で中身を書き換える）。
- 貯蓄・運用から不動産を足す口をなくし、貸していない土地も収益不動産に入れる: 「?」の案内と食い違い、貸していない物件に家賃の欄が出る。
- 所在地を都道府県の選択と市区町村の文字の2つの欄にする: 段階1では見分けるための欄で、分けても計算に使わない。1つの文字の欄にして、縮約版・持ち帰り用のレポートで1つの項目として外せるようにした。

## 未確定・後の段階に回したこと

- 利回り（表面・実質）・手残り（税引き後のお金）・物件ごとの不動産所得を一覧表に足す（計算の結果を読む）。
- 民泊・宿の売上（稼働・単価）と経費（手数料・清掃など）の入れ方と、所得の区分（雑所得・事業所得）の計算。
- 持分を計算に入れる（評価額・家賃・経費・ローンの持分の分だけを名義の人の所得にする。共有者が世帯の中にいるときの分け方）。
- 「収益不動産のまとめ」の帳票に物件名・種類を載せる（持ち帰り用のレポートと同じく物件名を外すか、提案書では載せるか）。
- 収益不動産から「貸していない不動産」へ戻す操作（中身を捨てることになるので、確かめの出し方と合わせて決める）。今は物件を外して貯蓄・運用で足し直す。
- 事務所の設定で項目の並びを保存している事務所では、新しい項目が並びの最後に足される（0073 の決まり）。

## 追記

- 2026-10-28（お金の欄。0080）: 3 の民泊・宿の知らせを「所得は不動産所得として計算しています（雑所得・事業所得の区分は今後の版で対応します）。売上が年1,000万円を超えるときの消費税は計算しません」に直し、まとまりの注記をやめて種類の欄の知らせだけにした。民泊・宿を選ぶと中身に民泊・宿の入れ方 `lodging` を作り、家賃収入を宿泊の売上の入れ方にする（計算部品は種類を読まず `lodging` を読む。3 の「計算には使わない」は変えていない）。4 の一覧表の「月の家賃」を「月の収入（空室を見込んだ後）」にした（家賃以外の月の収入を含み、民泊・宿は月の売上）。未確定の「民泊・宿の売上と経費の入れ方」は 0080 で決めた（所得の区分は残る）。
- 2026-10-28（税と出口。0081）: 3 の「計算部品はこれらを読まない」を、種類（`kind`）と戸数（`units`）だけ改めた: 事業的規模の目安（5棟10室。青色申告特別控除の55万円・65万円の要件）を数えるときに `asset.realEstate`・`tax.totalIncome` が読む（区分マンションは1室、一棟・店舗/事務所・民泊・宿は戸数の室、戸建ては1棟）。ほかの見分ける欄（物件名・所在地・持分・権利・面積・メモ）は今までどおり計算に使わない。種類と戸数を入れても、表の数字は青色申告で55万円・65万円を選んだ人のほかは変わらない（10室以上なら個人事業税の知らせ）。民泊・宿の種類の欄の知らせ（不動産所得として計算）は外し、消費税・個人事業税を計算しないことは種類の欄の「?」に書いた。持分は今も計算に入れない。
- 2026-10-29（分析の数字と提案書。0082）: 未確定の「利回り・手残りを一覧表に足す」は、一覧表に表面利回り・実質利回り・月の手残り（税引前）と合計の行を足した（世帯の今の入力の写しの要求を1回求めた結果の、表の最初の年の分析の数字）。4 の「計算の結果を待たず、入力から出せる数字だけ」は、評価額・ローン残高・月の収入の列のまま。未確定の「収益不動産のまとめの帳票に物件名・種類を載せるか」は、提案書の PDF には物件名と種類を載せる（所在地・メモは載せない。持ち帰り用のレポートと縮約版の決まりは変えない）と決めた（0082 の8）。
- 2026-11-05（不動産に詳しい FP に見てもらう前の見直し）: 画面を撮って見つけた所を、利用者の判断で直した。
  - **建物の無い種類（貸している土地・駐車場）**: 3 の「計算部品は種類を読まない」を、事業的規模の目安（0081）に加えて、もう1つ改めた: `asset.realEstate` が種類を読み、貸している土地・駐車場の土地の割合の省略を 1 にする（取得価額も評価額も全部土地。減価償却なし。0028 の追記）。画面は、建物の構造・建った年・土地の割合の欄を出さず、まとまりの名前を「土地」（駐車場は「土地と設備」）、取得価額を「取得価額」（「?」は、売ったときの取得費と土地の取得のための借入の利息の分け方に使うこと）にした。駐車場は、詳細の取得価額の内訳に「土地」と「設備（舗装・機械式駐車設備など）」を出し、設備を入れたら「設備の耐用年数」（「?」に舗装の法定耐用年数の例。入れなければ15年）。建物の内訳の欄は出さない。
    - 決めたこと: 駐車場の設備は新しい欄を足さず、取得価額の内訳の建物附属設備の欄を使い回す（計算は建物附属設備と同じく、別の耐用年数の定額法）。理由: 舗装・機械式駐車設備は建物附属設備ではなく構築物・機械装置だが、計算で要るのは「土地とは別の、償却する額と耐用年数」だけで、それは今の欄で足りる。欄を足すと世帯ファイルの形式を上げることになり、建物のある種類と同じ物を2つの名前で持つことになる。入れなければ設備は無いもの（全部土地）とした（貸している土地・青空駐車場では償却する物が無いのがふつう）。
