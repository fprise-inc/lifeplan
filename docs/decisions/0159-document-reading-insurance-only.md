## 背景

- 0148・0151〜0154 で、AI の答えの貼り付け・AI接続口の道具・マイナポータルの電子データ（XML）から、ねんきん定期便・年金額改定通知書・源泉徴収票（給与・公的年金等）・確定申告書・住宅ローンの書類・各種の控除証明書・保険証券を読めるようにした。
- 利用者の判断（2026-11-07）: 書類をもらえば FP が自分で見て簡単に数字を入れられる書類は、「書類の取り込み → 確かめの画面 → 数字を取り込む」の段を踏む必要がない。現実の使い方で、本当に取り込むべき書類だけに絞る。
- **ものさし**（利用者が OK した整理）: 取り込みが割に合うのは、次のどれかに当たる書類だけ。
  1. 打つ数が多い（1通で十数欄以上、または同じ形の物が何件もある）
  2. 読み方が難しい（どの数字をどの欄に入れるか、FP でも迷う・取り違えやすい）
  3. 行が多いデータ（CSV など、何十〜何百行ある）
- 逆に、数字が数個で書類のどこを見ればよいかが決まっている書類は、取り込むより打つほうが早い。取り込みには手数がかかる: AI で読むなら書類の名前・番号を伏せる → AI に渡す → 答えを貼り付ける → 確かめの画面で1つずつ承認する、しかも外部AIへの同意（書類を含む説明の版2。0157）のある世帯だけ。電子データ（XML）なら、お客さまがマイナポータルから保存して FP に渡す必要があり、実際に渡される見込みが低い。

## 決定

### 1. 取り込む範囲（読み口 `documents/proposal.ts`・道具 `propose_inputs`）

- 読み口 `readProposal` が受けるのは、書類の種類 `docType` が `insurancePolicy`（保険証券・ご契約内容のお知らせ・設計書）の答えだけ。ほかの種類・種類の無い答えは、読み取りの記録にせず「読めるのは保険証券・ご契約内容のお知らせ・設計書（docType は insurancePolicy）だけです。ほかの書類は、書類を見て入力の欄に打ってください（欄の「?」に書類のどこを見るかがあります）」の理由を出す（貼り付けの画面・AI接続口の帯に出る）。
- 値の候補は保険の契約の欄（入力項目ID が `insurance.` で始まる物）だけ。ほかの入力項目の候補は、その候補だけ読まずに「保険の契約の欄でない候補（読めるのは保険の書類だけです）」の理由を残す。照合だけの値（特約の額・積立金の額など）はそのまま受ける。
- 新しい物の種類は保険の契約 `insurance:<種類>` だけ（`documents/objects.ts` の `NEW_OBJECT_KINDS`。住宅ローン `debt:mortgage`・iDeCo `account:ideco`・小規模企業共済 `account:smallBusinessMutualAid` を外した）。
- AI接続口の道具の入力の形（`crates/lifeplan/src/server.rs`）の書類の種類の一覧を `insurancePolicy` の1つにし、道具の説明・全体の説明（`INSTRUCTIONS`）に「保険の書類だけ・ほかの書類の答えは送らない」を書いた。本体（`crates/ai-share/src/documents.rs`）は今までどおり形の外側だけを見る（書類の種類・入力項目の確かめは読み口の1か所。0151 の1）。

### 5. 前に読んだ書類の記録（区画 `documents` の行）の扱い

- **世帯ファイルの形式の版は上げない**（区画の形は変えていない）。
- 取り込みを外した書類の前の記録は、**捨てずに読む**（`documents/log.ts`）: 書類の種類（`RETIRED_DOC_TYPES`）と新しい物の種類（`RETIRED_OBJECT_KINDS`。住宅ローン・iDeCo・小規模企業共済）を、読める物の一覧とは別に持ち、記録の種類・物の候補・その中の値の候補を今までどおり残す（番号を消し直す決まりは同じ）。読んで書き戻しても1文字も変わらない（0.68〜0.70 の見本の世帯ファイルの源泉徴収票の記録で確かめた）。
- 確かめの画面では**見るだけ**（`documents/review.ts`）: 知らせ「この書類の取り込みは外しました。前に読んだ記録を残していますが、ここでは見るだけです（承認・直すはできません）。値は書類を見て入力の欄に打ってください…」を出し、未決の行は「この書類の取り込みは外しました。書類を見て入力の欄に打ってください」の理由で承認・直すができない（操作の部品でも断る）。物の候補は足せず（「取り込みを外した書類の住宅ローンです（足せません）」）、今ある物にも当てない。「入れない」と、現状に入れた候補の無い記録の「この書類の候補を捨てる」はできる。
- 未決の数に数えない（`pendingCount` が0。入力のホームの「未決 ○件」・AI接続口の帯に出さない）。読んだ書類の切り替えには「見るだけ」と出す。
- 前に承認して現状に入れた値（承認の記録・確かさ「書類で確認」）はそのまま（記録が指す先も残る）。

### 6. 入口

- 入力のホームの「取り込む」の「書類の読み取り」は、「読んだ書類を確かめる」「AI の答えを貼り付ける」と、見本の世帯の「架空の保険証券の見本で試す」だけにした（説明は「保険証券・ご契約内容のお知らせ・設計書を AI に読ませた答えを、候補として取り込みます…ほかの書類は、書類を見て欄に打ってください（欄の「?」に書類のどこを見るかがあります）」）。
- 「この書類を読む」（0154 の3）は、書類のお願いのうち保険証券（手術の1回の額の書類待ち）の1通と、その書類待ちの欄の印、保険の入力項目の見出しにだけ出す（`documents/start.ts` の `readableDoc`。`docStartOf` は読めない書類に null を返す）。画面は「AI の答えを貼り付ける」「AI接続口で読む」「欄に打つ」の3つ。
- 貼り付けの画面の「読み方の手引きを写す」は、選べる書類が1つなので書類の種類を選ぶ欄を出さず、「読めるのは保険証券・ご契約内容のお知らせ・設計書だけです」と出す（写す文は説明書＋保険の手引き＋欄の一覧）。

### 8. 決めたこと（作りながら決めた）

- **「そのほかの書類」（`other`）も受けない**: 保険の書類だけに絞る判断なので、種類の分からない答えも読まない（種類の無い答え・`other` の答えは理由を出す）。前の記録の `other` は見るだけ。
- **値の候補も保険の契約の欄だけにする**: 書類の種類だけを絞ると、保険の書類の答えに年収などの候補を混ぜて入れられる。欄で絞れば、手引き・欄の一覧・読み口の範囲が同じになる。
- **前の記録は見るだけ（承認させない）**: 外した書類の読み方の手引き・見本・当て方の細部（年金の記録の型の当て方・ローンを書類から足す形）はもう面倒を見ないので、承認できる形のままにすると、確かめていない道が残る。β公開の前で、前の記録は開発中の試しの世帯だけの見込み。記録は捨てない（承認の記録が指す先と、どの書類から入れた値かを残すため）。
- **当て先と値の形の一般の決まりは残す**: 欄の種類ごとの決まり（年月・率・選択肢・人・時点の欄・年数の欄に年月が来たときの理由など）は保険の欄にも当たり、外すと保険の答えの読み方が変わる。ローンの名義の続柄の選択肢に名義の人を当てる決まり（0154 の4）も、欄の種類で決まる一般の決まりなので残した。
- **読み取りの記録の型の `via: "reader"` と `file`**: アプリの中の読み手（電子データ）はもう無いが、前の記録に残るので型と読み方は残した（読み口の文脈からは `file` を外した）。
- **同意の説明文（0157 の版2）の3段落目の「保険証券やねんきん定期便などの書類」は変えない**: 説明文を変えると版を上げて同意を取り直す必要がある（0157）。例示が今より広いだけで、書類を AI に渡すことの説明としては正しい。次に説明文を直すときに合わせる（未確定）。
- **見比べだけの値（照合だけの値）の仕組みは残す**: 保険の手引きで特約の額・積立金の額に使う。計算の表の行と比べる口（`row`・`year`）も残す（保険の書類ではふつう書かない）。

## 理由

- **ものさしで絞る**: 確かめの画面を通す取り込みは、同意・伏せ字・貼り付け・1つずつの承認の手数がかかる。数字が数個の書類は打つほうが早く、取り込みの道を残すと、FP は「取り込むべきか打つべきか」を毎回考えることになる。保険証券は1件で十数欄、世帯で何件もあり、主契約と特約・払い方と保険料の期間・保険の種類の取り違えが起きやすいので、取り込みが割に合う。
- **電子データの読み手を外す**: 控除証明書の XML は、お客さまがマイナポータルから保存して渡す必要があり、実際に渡される見込みが低い。住宅借入金等特別控除証明書だけで8つの版があり、年ごとに様式が変わる物を追いかけ続ける手間に見合わない。
- **かわりの一言を「?」に置く**: 取り込みをやめても、FP が迷わず打てることが目的。AI 向けの手引きに書いた「どの欄を見るか」は、そのまま FP にも役に立つ。欄の下は1行まで（0130・0077）なので、今ある「?」の説明に足した。
- **前の記録を残す**: 世帯ファイルの記録は FP が承認した値の出どころを指している。捨てると「書類で確認」の値の根拠が消える。形式の版を上げずに読めるので、前の版のアプリとも食い違わない。
- **答えの形の範囲を狭める（0148 の固定の強さの例外）**: 0148 は答えの形を「β公開までは足すだけで直してよい」とした。今回は利用者の判断で、使う書類そのものを絞ったので、足すだけにしない。形（欄の名前と意味）は変えておらず、受ける範囲だけを狭めた。β公開の前で、外の作り手が使っている答えは無い。

## 代案（採らなかったもの）

- 入口だけ隠して、読み手と手引きは残す: 使わない道の不具合を直し続けることになる。利用者の判断で、使わなくなった物は消す。
- 前の記録を読むときに捨てる（知らない種類として落とす）: 承認の記録が指す先が消える。0148 の決まり（現状に入れた候補のある記録は外さない）にも合わない。
- 前の記録を今までどおり承認できる形で残す: 上の「決めたこと」の理由。
- 控除証明書の取り込みだけ残す（入れ漏れの一覧のため）: 保障の額が無いので結局は証券を見て入れる。紙の証明書なら枚数を見比べれば気づける（利用者が OK した整理の 3.1）。
