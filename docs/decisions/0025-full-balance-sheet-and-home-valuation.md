# 0025. 全資産・全負債のバランスシート（持ち家の評価・売却・車・その他の資産）

- 状態: 採用（一部未確定）（2026-10-19）
- 固定の強さ: β公開から変えない（骨格）。行ID（`cf.balance.account.car`・`cf.balance.account.otherAsset`）、世帯のデータの欄（`residences[].valuation`・`residences[].sale`・器の種類 `otherAsset` と `accounts[].valueGrowth`・前提 `assumptions.realEstateValuation`）、計算部品ID（`housing.valuation`・`asset.car`）は骨格。目安の値（耐用年数・土地の割合・下限・売却の費用）と画面・帳票の見せ方は後から変えてよい（変えたら追記に書く）

## 背景

- 結果の画面の「資産と負債の推移」は、資産＝金融資産（預金・NISA・iDeCo/企業型DC・その他）、負債＝住宅ローン・その他の負債だけで、純資産も金融資産−負債だった。キャッシュフロー表には不動産の行（`cf.balance.account.realEstate`）があるのに、グラフにも純資産にも入っていなかった。
- 不動産の行は、購入した持ち家の「購入の価格」を不動産の資産クラスの利回り（省略は0）で動かしただけで、建物が古くなって価値が下がることを表していなかった。今住んでいる持ち家（購入の入力が無い）は評価されなかった。住み終わり（売却）は「対応していない」の知らせだけだった。
- 顧客に家計の全体（家・車・保険の解約返戻金も含めた資産と、住宅ローンなどの負債）を説明するには、全資産・全負債のバランスシート（BS）が要る。一方、老後の資金が足りるかは、取り崩せる金融資産で見る（家は住んでいる間は取り崩せない）。
- 0004 の6 は `cf.balance` の中分類（`financial`・`account`・`return`・`debt`・`nisaFrame`・`shortfall`）を固定している。0008 の9 は資産の器の型、0002 は金額・率・丸め、0003 は年末の値の扱いを決めている。

## 決定

### 1. 行と、金融資産の範囲

- 資産の評価額は、これまでどおり器ごとの残高の行 `cf.balance.account.<種類>` に、物の ID（`object`）と名義（`member`）を付けて出す（0004 の追記 2026-10-09 の形）。中分類は増やさない。
- 足す明細の行: `cf.balance.account.car`（車の評価額。物の ID は車）、`cf.balance.account.otherAsset`（その他の資産。物の ID は器）。
- **金融資産の合計（`cf.balance.financial`）に入れない行**: 不動産（`realEstate`）・保険の解約返戻金（`insurance`）・車（`car`）・その他の資産（`otherAsset`）。どれも取り崩しに使わない（決済口座の不足を補わない）。資産が尽きる年・老後の資金の判定は、今までどおり金融資産で見る。
- 純資産の行はエンジンに作らない（表の行の足し算で出る値なので、画面と帳票が同じ決まりで足す）。**純資産＝金融資産＋不動産＋その他の資産（車・保険の解約返戻金・その他の資産）−負債（住宅ローン・その他の負債）**。

### 2. 持ち家の評価（計算部品 `housing.valuation`）

- 対象は住まいの持ち家（`kind: own`）。評価の基にする額は、`valuation.value`（`asOf` の時点の土地と建物の合計。値の箱で、推定も入れられる）か、無ければ購入の価格（購入の月）。どちらも無い持ち家は評価せず、知らせ `N_INPUT_REQUIRED`（`residence.valuation`）を出す。
- 土地と建物に分ける: 土地＝基にする額×土地の割合、建物＝残り。土地の割合は、物件の `valuation.landShare` → 前提 `realEstateValuation.landShare` → 目安の順（目安を使ったら知らせ `N_DEFAULT_USED`）。
- 土地: 基にする年の翌年から、毎年の土地の上昇率（前提 `realEstateValuation.landGrowth`。年ごとの列。省略は物価上昇率）を当てる（1年ごとに円未満切り捨て。規則ID `conv.asset.valuation`）。
- 建物: 構造（`wood`・`lightSteel`・`steel`・`rc`。省略は木造）の耐用年数で定額で減らし、残りの価値の下限より下げない。築年数 a の年末の残りの割合 f(a)＝max(下限, 1−a÷耐用年数)（率の割り算は小数12桁・銀行丸め。0002）、a＝その年−建った年（`valuation.builtYear`。省略は基にする年＝新築）。中古で買ったときや、昔の購入の価格から評価するときも、基にする年の割合に対する比で減らす: 建物＝基にする建物の額×f(その年)÷f(基にする年)。
- 年末の評価額＝土地＋建物。持っている年（購入の年、または計算基準年から、住み終わりの年まで）の年末に出す。

### 3. 目安の値と根拠（前提条件。世帯ごとに変えられ、事務所の標準を写せる形）

| 前提 | 目安 | 根拠 |
|---|---|---|
| 建物の耐用年数 | 木造22年・軽量鉄骨造19年（骨格材の肉厚3mm以下）・重量鉄骨造34年（4mm超）・鉄筋コンクリート造47年 | 減価償却資産の耐用年数等に関する省令の別表第一（住宅用の建物）。市場の価格の減り方とは違うので、FP が地域・物件で直す前提 |
| 建物の残りの価値の下限 | 建てた時の価値の2割 | 固定資産評価基準（総務省）の家屋の経年減点補正率の下限（0.20）。古い家屋にも一定の価値を残す考え方に合わせる |
| 土地の割合 | 3割 | 住宅金融支援機構「フラット35利用者調査」の土地付注文住宅の、所要資金に占める土地取得費の全国の割合（おおむね3割。首都圏は4割程度）。地域で大きく違うので、物件ごとの入力を優先する |
| 土地の上昇率 | 物価上昇率と同じ | 前提を増やしすぎないため。地価の見通しを持つ FP は年ごとの列で入れる |
| 売却の費用 | 売却価格の4% | 仲介手数料の上限（宅地建物取引業法の報酬額の告示: 売買価格の3%＋6万円と消費税）と、印紙税・抵当権の抹消などの目安 |

- 前提は `assumptions.realEstateValuation`（`landGrowth`・`landShare`・`usefulLife`（構造ごと）・`residualFloor`・`saleCostRate`）に持つ。0008 の8 のとおり、事務所の標準値はプランを作るときに写す（事務所の標準の画面はまだ無い）。

### 4. 売却（`residences[].sale`）

- 住み終わり（`to`）がある持ち家だけで使う。住み終わりの月に、売却価格（`sale.price`。省略はその年の評価額）から売却の費用（売却価格×費用の割合。`sale.costRate` → 前提 → 目安）を引いた**手取り**を、名義の人の一時金の収入（`cf.income.lumpSum.realEstateSale`。計算式ID `housing.valuation.sale`）にする。手取りはその年の収支に入り、決済口座（金融資産）に入る。
- 売った年の年末には不動産を持っていない（評価額の行を出さない）。つまり、評価額（資産）が手取り（金融資産）に変わり、差（費用と、評価額と売却価格の差）だけ純資産が動く。
- 譲渡所得の税は計算しない（居住用の財産の3,000万円の特別控除の範囲の売却を前提にする。知らせ `N_NOT_SUPPORTED`（`residence.saleTax`））。住宅ローンの残りは返済の予定のまま（売る月に返すなら、住宅ローンの繰上返済で入れる）。
- 売却の無い住み終わりは、これまでどおり住み終わりの年まで評価に載せ、その後は消える（知らせ `N_NOT_SUPPORTED`（`residence.sale`））。

### 5. 車の評価額（計算部品 `asset.car`）

- お金の動きの部品（`expense.car`）とは別の部品にし、車の入力（`cars[]`。複数台）から読める範囲だけで出す（車の入力の形と車の計算は変えない）。読むのは名義・購入（最初の購入の月・周期・価格・下取り・今の車）・手放す時期・伸び方。
- 買い替えのたびに、その車は買った月の価格（`expense.car` と同じ伸び方の額）から、次の買い替えの月の下取りの額（無ければ0）まで、月ごとに定額で下がるとみなす。年末の評価額＝価格−（価格−下取り）×買ってからの月数÷周期の月数（円未満切り捨て）。今の車は、最初の買い替えの月の周期の前に計算基準年の価格で買ったとみなす。手放した後の年末には持っていない。万一のときの扱い（`onContingency`）は評価額に当てない。

### 6. その他の資産（器の種類 `otherAsset`）

- 資産の器（0008 の9）に種類 `otherAsset` を足す（貴金属・美術品・貸付金など、FP が入れる資産）。評価額（`marketValue`）と時点、評価額の増減率 `valueGrowth`（年率。マイナスも書ける）を持つ。増減率を入れなければ評価額のまま（資産の配分 `assetMix` を入れたときはその利回り）。
- `valueGrowth` は不動産の器（住まい以外の不動産。`realEstate`）でも使える（入れなければ今までどおり不動産の資産クラスの利回り）。
- 時価の下落（ストレステスト）の既定の対象から外す。

### 7. 画面と提案書

- 結果の画面の「資産と負債の推移」: 資産＝金融資産の内訳（預金・NISA・iDeCo・企業型DC・その他の金融資産）・不動産・その他の資産（車・保険の解約返戻金など）、負債＝住宅ローン・その他の負債。金融資産の器のマイナス（預金の不足）は負債の側に斜線で積む。純資産の線は不動産・その他の資産を含む。全部のプランを重ねる表示は純資産の線で、見出しに「不動産・その他の資産を含む」と書く。「資産の推移」（金融資産だけ）は変えない。
- グラフの下に、固定した年（固定していなければ既定の年）のバランスシート（左に資産、右に負債と純資産。資産の合計＝負債と純資産の合計）。左右に並べる表示では基準と選んだプランの2つ。説明モードでは出さない。
- 提案書: 「基本項目」の資産と負債を、計算基準年の年末のバランスシート（現状）にする。「キャッシュフロー表」の章の続きに、純資産の推移（現状と提案）と、年の抜粋（今・10年後・退職の年・75歳・目標の年）のバランスシート（提案。最後の行に現状の純資産）を載せる。帳票の入力の `basics.balance` と `balanceSheet`。

### 8. 世帯ファイルの形式

- 世帯のデータに任意の欄を足した（器の種類の値の追加を含む）ので、世帯ファイルの形式の版を `0.4` に上げる（0011 の5。足すだけの MINOR。`0.3` → `0.4` の変換は版だけを書き換える）。古い版のアプリは `0.4` のファイルを読むだけで開く。

## 理由

- **中分類を増やさず器ごとの残高の行に置く**: 0004 の6 の固定を守り、不動産・保険の解約返戻金と同じ並びに置ける。物の ID で1件ずつ引ける。
- **純資産の行をエンジンに作らない**: 行の足し算で決まる値で、資産の区分（何を金融資産に入れるか）は表示の決まり。画面と帳票は同じ決まりで足し、テストで合計の一致を確かめる。
- **土地と建物に分ける**: 建物は古くなるほど価値が下がり、土地は下がらない（物価などで動く）という、顧客に説明しやすい形。法定耐用年数は根拠を示しやすく、構造で差が付く。下限を置かないと、築年数の古い家の価値が0になり実感と合わない。
- **評価額と売却の手取りを分ける**: 売却の前の年までは評価額（資産）、売った年からは手取り（現金）にすると、資産の二重計上も抜けも起きない。費用と売却価格の差が純資産の動きとして見える。
- **車を別の部品にする**: 車の入力と計算は並行して直されるので、評価額だけを読む別の部品にすると、合わせ直しが小さくて済む。
- **金融資産の範囲を変えない**: 老後の資金が足りるか（資産が尽きる年）は、取り崩せる金融資産で判定するのが FP の実務と同じ。

## 代案（採らなかったもの）

- 不動産を資産クラスの利回り（省略は0）で動かす（前の形）: 建物の減価を表せず、30年後も購入の価格のままになる。
- 中分類 `cf.balance.asset` を新しく作る: 0004 の6 の固定を変えることになり、既存の器ごとの行と二重になる。
- 定率法・市場の取引の統計（築年数ごとの成約価格）で建物を減らす: 根拠のデータの持ち方（制度データ・マスタデータ）が決まっていないため、最初の版は定額法と前提の値にする。

## 影響

- `plan.cashflow` は改訂8（不動産の行を `housing.valuation` の評価額に、車の行、その他の資産）、`plan.flows` は改訂6（売却の手取りを集める）。購入した持ち家の不動産の行の値は変わる（建物の減価）。金融資産・年間収支は、売却を入れない限り変わらない。
- テストで確かめること: 建物の減り方（耐用年数・下限・中古の比）と土地の上昇を、別に書いた10進の計算と突き合わせる。売却の年の手取りと評価額の関係、売った年に評価額が消えること。金融資産の合計＝金融資産の器の行の合計、資産の合計＝負債の合計＋純資産（エンジン・画面・帳票）。

## 未確定

- 目安の値を制度データ・マスタデータ（0007）に移すか（地域ごとの土地の割合・地価の見通しを持つ場合）。β公開までに決める。
- 譲渡所得の税（3,000万円の特別控除を超える売却・買い換えの特例）と、売るときの住宅ローンの一括返済を自動で入れるか。
- 事務所の標準値の画面（前提の写し方）。賃貸に出す・相続するなど、売却以外の住み終わりの扱い。
- 万一のときの扱い（車を手放すなど）を評価額に当てるか。
