# 0191. Web のヒアリングで受け取った書類を FP が見て使う: 入力項目の横で見る・受け取った書類の一覧・自分のフォルダに保存

- 状態: 採用（一部未確定）（2026-11-08）
- 固定の強さ: 内部（画面の作り・言葉・ファイル名の決まり・入力項目と書類のつながりの表は後から変えてよい）。世帯ファイルの形式は 0.72（`hearing.web` の1件の受け取った書類のファイルに、見た・保存したの日時の任意の欄を足すだけの MINOR。変換の段は版だけを書き換える。6）
- 前提にする記録: 0011（世帯ファイルと形式の版）、0012（持たない情報）、0016（画面の安全・CSP）、0020（平文の書き出しの出口）、0021（ライセンス）、0102（書類のお願い・書類待ちの印）、0125（Web のヒアリング）、0158（書類は何回でも送れる・送りごとの記録）、0159（書類の読み取りは保険証券だけ）

## 背景

- Web のヒアリング（0125・0158）で受け取った書類は、世帯ファイルの中に置き、取り込むの中の「Web の依頼」の書類の欄で開けた。写真は 900 画素の幅で欄の中に描くだけで、拡大・回転は無く、入力項目のパネルを開くと見えなくなった。PDF・HEIC はアプリの中で開けず、保存して外で開くしかなかった（平文のファイルになる）。いつ受け取った書類がいくつ残っているかの一覧も無かった。
- 書類の読み取り（取り込み）は保険証券・設計書だけに絞った（0159）。源泉徴収票・ねんきん定期便などは、**FP が届いた書類を見て、入力項目に打つ**。だから「書類を見ながら打つ」が楽であることが大事になった。
- 利用者の判断（2026-11-06・2026-11-07）:
  - 受け取った書類は FP が自分で管理する。サーバーの分は受け取ったら消す（0158 のまま）。
  - アプリは書類を自動で消したり、「消してよいですか」と促したりしない。
  - かわりに、手軽に「自分のフォルダに保存」できるようにし、受け取った書類の一覧を出す。

## 決定

### 1. 入力項目の横で書類を見る（見る枠）

- 画面の右に「届いた書類」の枠（`app/src/workspace/hearing/DocViewer.tsx`）を出す。入力のパネルを開いたまま、パネルは左に寄って並ぶ（狭い画面では枠が下半分）。枠は入力のパネルの外にあり、パネルの下書き・保存・閉じ方は変えない。Esc は枠だけを閉じる。
- 拡大・縮小（幅に合わせる・ボタン・Ctrl＋ホイール・キーの ＋ − 0）・右に90度ずつ回す（R）・拡大したときはつかんで動かす。枠の上で書類を切り替える（選ぶ・前と次のファイル）。
- 写真は今までどおりバイトを `createImageBitmap` で絵にしてキャンバスに描く（`img` の URL にしない。0016）。**PDF はページごとに絵にしてキャンバスに描く**（ページ送り）。HEIC はブラウザが絵にできないとき、保存して外で開くように出す。
- 入口:
  - **入力のパネルの見出しの下に「届いた書類」**: その入力項目で見ながら打つ書類だけを「源泉徴収票（ご本人）を見る（2枚）」のように並べる（`DocLinks`）。どの書類がどの入力項目かは、書類の種類（ひな形の kind）から引く表（`DOC_CARDS`。源泉徴収票・給与明細・確定申告書・住民税の決定通知書 → 働き方と収入、ねんきん定期便 → 年金 など）と、書類のお願いの1通（0102）と結びついた書類なら、その1通の欄の入力項目から引く。ピン（ホームに出した物）は物が属する入力項目で引く。
  - 書類のお願い（0102）の1通に「届いた書類を見る」（Web で届いたとき）。「開く」で欄に移って、見ながら打てる。
  - 受け取った書類の一覧の「見る」、取り込むの中の Web の依頼の書類の「開く」（写真も PDF も枠に出す）。
- 書類待ちの印（0102）は今までどおり、FP が値を入れたら消える（見る枠はこの決まりに触らない）。

### 2. 受け取った書類の一覧

- 入力のホームの見出しに「受け取った書類（N件・2.1MB）」（受け取った書類があるときだけ）。押すと一覧（`app/src/workspace/hearing/ReceivedDocs.tsx`）。
- 世帯の全部の Web の依頼の受け取った書類を、新しく受け取った順に1ファイル1行: 書類の名前・持ち主（ご本人・配偶者など）・受け取った日時（送りの記録 `batches`。お客さまが送った日時は申告として添える）・大きさ・見たか・自分のフォルダに保存したか（日付）・「見る」「保存」「消す」。
- 見出しに合計の件数・大きさ・1世帯の上限（40MB）・まだ見ていない件数・まだ保存していない件数。「まだ保存していない書類を保存（N件）」「全部を保存（N件）」。
- 書類の名前は、書類のひな形の定義（`hearing/src/web/documents.ts` の `DOCUMENT_TEMPLATES`）から引く。見出しの残りの括弧を持ち主とみる（「ねんきん定期便（ご本人）」→ ねんきん定期便・ご本人）。頼む書類に持ち主の欄（`whose`）ができたら、それを使う。ひな形が増えても、ここは直さずに名前が出る。
- **消すのは FP が「消す」を押したときだけ**。押すと「この世帯から消します（元に戻せません）。まだ自分のフォルダに保存していません」（保存していなければ）を出し、もう一度押して消す。アプリは期限で消さず、消すように促す文も出さない。取り込むの中の Web の依頼の説明の「写し終えたら消してください」を外した。

### 3. 自分のフォルダに保存

- 1つずつ（一覧の行・見る枠の「保存」）: 今までどおり保存のダイアログで場所と名前を選ぶ（既定の名前は4のとおり）。
- まとめて（一覧の「まだ保存していない書類を保存」「全部を保存」）: **フォルダを1回選び**、そのフォルダに全部を書く。同じ名前のファイルがあれば、中身が同じならそのまま（書き直さない）、違えば `_2`・`_3` を足す（上書きしない）。
- デスクトップのアプリ（本体）: 平文の書き出しの出口（0020）を通す。命令 `hearing_documents_folder`（OS のフォルダのダイアログ。保存してはいけない場所〔データフォルダ・カスタム層〕は断る。選んだフォルダはアプリを開いている間だけ本体が覚え、パスは画面に返さない）と `hearing_document_save_into`（1ファイルを選んだフォルダに書く。形の確かめとファイル名の直しは `hearing_document_save` と同じ）。書き出しの記録（種類・日時・指紋・同期フォルダか）は今までどおり残す。同期フォルダの中なら、保存はして画面に知らせる。
- ブラウザ（開発用のサーバーで画面だけを開いたとき）: フォルダを選べるブラウザ（File System Access）は選んだフォルダに書く（同じ名前の決まりは本体と同じ）。選べないブラウザはダウンロード（ブラウザのダウンロードのフォルダ）。1つずつはファイルの保存のダイアログ（あれば）かダウンロード。前の開発用のサーバーの保存の口（`/__dev/hearing/docsave`）は外した。
- 保存できたら、そのファイルに「保存した」の印（日時）を付ける。保存先・ファイル名は持たない（0020 の5）。

### 4. 保存のファイル名の決まり

- **`顧客番号_書類の名前_持ち主_受け取った日.拡張子`**（例: `A0042_源泉徴収票_ご本人_20261108.jpg`。持ち主が分からなければ省く）。
  - 顧客番号を先に置く: 何世帯分も同じフォルダに保存しても、世帯ごとに並ぶ。顧客番号とお名前の対応は FP がアプリの外で持つ（0012 の1）。
  - **お客さまのお名前は入れない**: アプリは氏名を持たない（0012 の2。氏名の欄を作らない）。名前を入れる口を作ると、名前を打たせることになる。FP が自分のフォルダで名前を付け直すのは自由。
  - 持ち主は書類のお願いと同じ呼び方（ご本人・配偶者・医療保険・ご本人 など。FP が付けた呼び名は使わない。0102 の1）。
  - 日付は **FP が受け取った日**（`YYYYMMDD`。並べたときに日付の順になる）。お客さまが送った日時は申告で、端末の時計に左右されるため。
  - 同じ日に同じ書類を何枚か受け取ったときは、古く受け取った順に2枚目から `_2`・`_3`。後から届いた書類で、前に保存した書類の名前は変わらない（同じ日に別の依頼で届いた同じ書類も、後のものに番号）。
  - 使えない字・空白・括弧は `_` にする（フォルダを指せない。本体でも直す）。

### 5. 見た・保存したの印

- 見る枠で初めて描けたファイルに「見た」（最初の日時）、保存できたファイルに「保存した」（最後の日時）を付ける。
- 印は Web の依頼の記録（`hearing.web` の1件の `files[]`）に置く。依頼の記録と同じく、元に戻す・やり直すの履歴には積まない（本体の画面の `putWeb`）。入力のパネルを開いている間に付けた印を、パネルの下書き（開いたときの世帯から作る）を保存したときに戻さない（入力のホームが今の依頼の記録を保つ）。

### 6. 世帯ファイルの形式 0.72

- 受け取った書類のファイル（`hearing.web[].files[]`）に任意の欄 `viewedAt`（初めて見た日時）・`savedAt`（自分のフォルダに最後に保存した日時）を足した。`hearing.web` の1件の形が変わるので、形式の版を `0.72` に上げた（足すだけの MINOR）。
- 前の版のアプリは印を知らずに書き戻すので、版を上げて閲覧だけにする。変換の段は形式の版だけを書き換える（0.70 の段の後に積む）。前の版の記録は欄が無い＝まだ見ていない・まだ保存していない、として読む（欄を書き足さない）。
- 見本 `crates/household-store/tests/fixtures/household-format/0.72/`（0.71 の見本の受け取った書類に見た・保存したの印を足したもの）。

### 7. 世帯ファイルの中に書類を持ったままにするか

- **今のまま（世帯ファイルの中に、世帯の鍵で暗号化して置く。0125 の8）**。一覧に件数と大きさと1世帯の上限を出して、FP が判断できるようにした。
- 理由: 外に出すと、鍵置き場と完全削除（0013 の5）・同期（0024）の決まりを別の置き場で作り直すことになる（0125 の代案のとおり）。利用者の判断で書類は FP が自分で管理し、アプリが自動で消さないので、大きくなったら FP が一覧の大きさを見て、保存してから消せばよい。大きな世帯ファイルの保存の速さは、0125 の未確定（別の置き場にするか）のまま β で見る。

### 決めたこと（迷った所）

- **PDF を絵にする部品に pdf.js（npm の `pdfjs-dist` 6.4.299。Apache-2.0）を使う**。理由: お客さまの PDF（スキャン・文字の入った PDF）をページごとに絵にする部品が、画面にも本体にも無かった（提案書の見本は本体の Typst が作る PDF だけ）。本体で描く（PDFium など）と、OS ごとの共有ライブラリを配ることになる。pdf.js は画面の中で動き、0021 の許すライセンス。
  - 画面の CSP は変えない（`worker-src 'none'`・`script-src 'self'`）。worker を作らず、計算の側を同じ所で動かす（`globalThis.pdfjsWorker`）。pdf.js 6 は eval を使わない。WebAssembly の読み手（JPEG 2000 などの画像）は読み込まない（その形の画像は描けないことがある。未確定）。
  - 描くのはキャンバスだけ。注釈・リンク・フォーム・スクリプトの層は作らない（お客さまの PDF の中の押せる物を出さない）。
  - 開くときにだけ読み込む（画面の最初の読み込みを重くしない）。
  - 文字の形（CMap。Adobe の BSD-3-Clause）と標準のフォントのうち Foxit の物（BSD-3-Clause）を `public/pdfjs/` に同梱する（`prepare-assets` が写す。外へ通信しない）。日本語の PDF はフォントを埋め込まずに CMap で文字を引くものが多く、CMap が無いと文字が出ない。**Liberation のフォント（GPL-2.0 と例外）は同梱しない**（0021 で GPL を止めている。無ければ pdf.js は OS のフォントで代わりに描く）。
- まとめて保存の本体の命令は「フォルダを選ぶ」と「選んだフォルダに1つ書く」の2つに分けた。理由: 1つの命令に何十 MB の書類をまとめて渡すと、画面から本体への受け渡しが base64 の JSON になり重い。1ファイルずつ生のバイトで渡せば、今の `hearing_document_save` と同じ確かめを使え、1つ失敗しても残りは書ける。パスは本体だけが持つ。
- 1件だけでも、一覧の「まだ保存していない書類を保存」「全部を保存」はフォルダを選ぶ（ボタンの説明どおり。行の「保存」は保存のダイアログ）。
- 入力のパネルの入口は、見出しの下の1行にした（欄ごとの「源泉徴収票を見る」にはしていない）。理由: 欄の部品は入力項目のブラッシュアップで並行して直している。欄ごとの入口は、どの欄がどの書類のどこかの表（0159 の「書類のどこを見るか」の一言と一緒に）ができたら足す（未確定）。
- 見る枠は1つの窓の中の枠にした（別の窓にはしていない）。理由: 本体で別の窓を作ると、窓ごとの権限（capabilities）と CSP・世帯の鍵の受け渡しを足すことになる。画面の右に固定し、入力のパネルを左に寄せれば、ふつうの PC の画面の幅で並べて見られる。
- 一覧は世帯の全部の Web の依頼をまたいで、新しく受け取った順の1ファイル1行にした（依頼ごとの書類の欄は今までどおり取り込むの中に残す）。

## 理由

- **見ながら打つ**: 書類の読み取りを保険証券だけにしたので、ほかの書類は FP の手で打つ。パネルを閉じずに書類を横に出せれば、行き来の手数が無くなる。
- **一覧と大きさ**: FP が自分で管理するには、何がいつ届いて、見たか・保存したか・どれだけの大きさかが一目で分かる必要がある。
- **ファイル名に顧客番号と受け取った日**: FP のフォルダで世帯と時期が分かり、アプリの外の顧客の台帳と顧客番号でつながる。お名前を持たない決まり（0012）を崩さない。

## 代案（採らなかったもの）

- **写し終えたら「消してよいですか」を出す**（計画の初めのおすすめ）: 利用者の判断で、アプリは促さない。
- **期限を決めて自動で消す**: 利用者の判断で、FP が自分で管理する。
- **書類を世帯ファイルの外（別の暗号化した添付）に置く**: 7 のとおり、削除と同期の決まりを作り直すことになる。β の大きさの声を見てから（0125 の未確定）。
- **PDF をブラウザの内蔵の表示で開く（iframe・embed）**: CSP の `frame-src 'none'`・`object-src 'none'` を緩めることになり、PDF の中のリンクやスクリプトの扱いがブラウザ任せになる。Mac の WKWebView と Windows の WebView2 で見え方も揃わない。
- **ファイル名にお客さまのお名前を入れる（FP がその場で入れる）**: 名前を打たせる口になり、保存しない決まりでも打った名前が平文のファイル名として残る。顧客番号で足りる。

## 追記
