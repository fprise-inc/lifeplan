# 0100. 基本生活費の内訳を10費目に分け直す（束をやめる・統計の目安から仕送り金と家庭用耐久財を除く・「わからない」をなくす）と、世帯ファイルの形式 0.43

- 状態: 採用（2026-10-31）
- 固定の強さ: β公開から変えない（骨格）。内訳の値 `communication`・`transit`・`pocketAndSocial`・`other`（`LivingCategory`）、計算の行 `cf.expense.living.{communication,transit,pocketAndSocial,other}`、マスタデータの値ID `living.statistics.categoryMonthly.{communication,transit,pocketAndSocial,other}` は骨格。内訳の名前・並び・欄の説明は後から変えてよい

## 背景

- 内訳で入れるときの欄は、家計調査の10大費目に寄せた9費目を、簡易は6つの束（日用品・衣服、医療・こづかい・その他など）にまとめ、詳細で「うち …」を開く形だった（0048 の2）。お客さまが家計簿で付けている分け方（家計簿アプリでよくある分け方）と合わず、通信費と交通費、美容とその他が1つの欄に入っていた。
- 統計の目安（`living.statistics.basicMonthly`）は、消費支出から住居・教育・自動車等関係費を除いた額で、**仕送り金**（子ども・教育、介護・親の入力項目で入れる）と**家庭用耐久財**（家電・家具。年払い・数年おきの暮らしの支出のひな形「家電・家具の買い替え」で入れる）を含んでいた。どちらもほかの所で入れるので、目安のままだと二重に数える。
- 基本生活費の欄には「わからない」があったが、代わりの値は統計の目安で、推定の印とほとんど同じ意味だった。
- 前提にする記録: 0007（制度の値・統計の形）、0008（世帯のデータモデル・推定）、0011（世帯ファイルの形式と変換の段）、0041（値の状態の操作）、0048（基本生活費の入力項目）、0049（生活費の人数と推定の段階）。

## 決定

### 1. 内訳（10費目と仕送り）

「内訳で」を選ぶと、次の11の欄を束にせず全部、標準で並べる（「詳しく」に畳まない。束の合計の欄と「うち …」の欄はなくした）。

| 値 | 名前 | 統計の目安（家計調査 第3-1表の区分） |
|---|---|---|
| `food` | 食費 | 食料 |
| `utilities` | 水道・光熱費 | 光熱・水道 |
| `communication` | 通信費（足した） | 通信（7.3） |
| `transit` | 交通費（足した） | 交通（7.1。自動車等関係費と通信を含まない） |
| `furniture` | 日用品 | 家具・家事用品−家庭用耐久財 |
| `clothing` | 被服・美容 | 被服及び履物＋理美容サービス＋理美容用品 |
| `health` | 医療費 | 保健医療 |
| `recreation` | 趣味・娯楽 | 教養娯楽 |
| `pocketAndSocial` | こづかい・交際費（足した） | こづかい（使途不明）＋交際費 |
| `other` | その他（足した） | その他の消費支出−理美容サービス−理美容用品−こづかい−交際費−仕送り金 |
| `allowance` | 仕送り | 推定は0円（今までどおり） |

- インターネット接続料（品目 88Y）は、この表に世帯人員別の値が無い（表は小分類まで）ので通信へ移さない。統計では教養娯楽（他の教養娯楽サービス）の中にあることを、通信費と趣味・娯楽の欄の説明に書く。
- 欄の説明に書くこと:
  - 交通費: ガソリン・駐車場・高速代・車の保険などは「車」の入力項目で入れる。ときどき使うカーシェア・レンタカーはここ（ガソリン・レンタカーとカーシェアの料金は統計では自動車等関係費の中で、目安に入っていないので、使う世帯だけ足す）。
  - 日用品: 家電・家具の買い替えは「年払い・数年おきの暮らしの支出」の「家電・家具の買い替え」で入れる（目安からも除いた）。
  - 統計の目安に一部が入っている物は引かずに説明だけ書く: 習い事の月謝（趣味・娯楽。統計の月謝類）、掛け捨ての保険料（火災保険など）と保育の費用（その他。統計の他の諸雑費）。
- 総額を内訳に分ける按分（0048 の2）は、この10費目の割合で分け、端は「その他」に置く（前は「その他の消費」）。仕送りは0円。内訳で入れた後に総額を直したときの差も「その他（まだ分けていない）」に置く。

### 3. 計算エンジン

- `LivingCategory` に4つの値を足した（スキーマ `engine.input.json` の `livingCategory`、部品 `expense.living` の行の対応〔改訂4〕、登録簿 `registry/rows.yaml`）。計算は今までどおり内訳の合計（内訳ごとの行）。

### 4. 前の世帯（形式 0.43 の変換の段と画面）

- 前の分け方の確定の値（交通・通信、その他の消費）は書き換えず、前の名前（「交通・通信費」「その他の消費（こづかい・交際費など）」）で、交通費・その他の後ろに出す。まとまりの添え書きに「前の分け方の内訳です」。
- 確定の交通・通信には「交通と通信に分ける」のボタン: 同じ人数の世帯の交通・通信の割合で分け（交通費を千円単位、残りを通信費）、両方を推定（出し方 `derived`）にする。合計は変えない。交通費は前の要素の ID を引き継ぐ。交通費・通信費に値があるときは出さない（足し合わせると FP の値が推定になるため）。
- 按分の推定のまま（どの内訳も推定で、根拠が「総額を内訳に分けた目安」）の前の分け方の内訳は、推定の入れ直しで今の分け方に分け直す（総額が統計の推定なら新しい目安で、FP が入れた総額なら同じ合計で）。交通費は交通・通信の、その他はその他の消費の要素の ID を引き継ぐ。
- 統計の推定のままの総額は、新しい目安で入れ直す（0008 の推定の入れ直しの決まりのとおり）。

### 5. 「わからない」をなくす（基本生活費の入力項目だけ）

- 値の状態の操作（0041）の「わからない」を、基本生活費の入力項目（`livingExpense.*`。総額・内訳・段階の割合と月額など）と、お金の行の種類 `livingAnnual`（年払い・数年おきの暮らしの支出。入力項目ID ではなく行の種類で見る）には出さない（`valueState.ts` の `availableOps`）。分からなければ統計やよくある額の目安の推定のままにすればよく、推定がそのまま代わりの値なので、印を別に持つ意味が無い。確定（この値にする）と推定に戻すは今までどおり。
- 形式 0.42 → 0.43 の変換の段（`crates/household-store/src/migrate.rs`）:
  - 代わりの値が自動の推定（統計・按分・ひな形の目安）の「わからない」の箱 → その推定の箱（値は同じ。推定の入れ直しの対象）。
  - 代わりの値が FP の入れた値（根拠「前に入っていた値を代わりに使う」、または自動でない値）の箱 → **その値のまま推定の印**（出どころ `manual`、根拠「「わからない」の代わりに使っていた値（…）」）。入れ直さないので結果は黙って変わらない。
  - 箱でない値の「わからない」の行（段の割合など。`valueStates`）→ 推定の行（根拠はそのまま）。
  - 現状の基本生活費の物と livingAnnual の行、プランの差分（基本生活費の入力項目・livingAnnual の行を向き先にする差分の値と前の値、足す物の中）が対象。控え・ヒアリングの記録は変えない。
  - 変えた物があれば、開いたときの知らせ `livingUnknown`（数・プランの差分の数。押すと基本生活費の入力項目を開く）を足す。
  - 内訳の束の合計を動かしたプランの差分（合成の対策 `livingGroupDaily`・`livingGroupMisc`）は、代表の内訳（家具・家事用品／その他の消費）の月額の差分に置き直す（代表＝束の合計−束のほかの内訳の現状の値。束の直し方と同じ）。代表の内訳が現状に無いときは変えない（プランの一覧の要確認に出る）。
- ヒアリングシートは「わからない」の選び方を残す。取り込むと、基本生活費は統計の目安の推定（根拠「ヒアリングで「わからない」。…」）にし、面談のチェックリストには今までどおり載せる。画面の推定の入れ直しでも根拠の頭を残す。

### 6. 世帯ファイルの形式 0.43

- 内訳の値を足し、基本生活費の「わからない」を推定にする MINOR。0.42 のエンジンは新しい内訳の値を知らずに計算できないので、版を上げて閲覧だけにする。見本 `crates/household-store/tests/fixtures/household-format/0.43/`（0.42 の見本の基本生活費を内訳で入れ、新しい4つの内訳と前の分け方の交通・通信を持たせた物）。

## 理由

- 内訳を全部出す: 11の欄は1画面に収まり、束の合計を直したときの「差を代表の費目に置く」決まりを覚えなくてよい。お客さまの家計簿の分け方と1対1に近くなり、明細の取り込みの区分とも対応させやすい。
- 仕送り金と家庭用耐久財を目安から除く: どちらもほかの入力項目・ひな形で入れる物で、目安に含めたままだと、ひな形を足した世帯で二重に数える。
- 「わからない」をなくす: 基本生活費は世帯があれば必ずある額で、分からないときの答えは統計の目安そのもの。印が2つ（推定とわからない）あると、確かめの一覧での扱いが分かれるだけだった。

## 代案（採らなかったもの）

- インターネット接続料を通信へ移す: 第3-1表に世帯人員別の値が無く、品目別の表（世帯人員別でない）から割合で移すと、表に無い数を作ることになる。
- 前の世帯の交通・通信・その他の消費を開いたときに自動で分ける: FP が入れた値を黙って推定にすることになる。ボタンで選べるようにした。
- 習い事・掛け捨ての保険料・保育の費用を目安から引く: 表に世帯人員別の品目の値が無い物があり、引き方が揃わない。説明に書くだけにした。

## 追記

### 2026-10-31: 年払い・数年おきの暮らしの支出の区画のボタンをまとめる・ほかの入力項目の読むだけの行と旅行のひな形を外す

- 確かめの一覧（「年1回・数年に1回の支出（入れ忘れがないか）」）にあった、ほかの入力項目で入れる物の読むだけの行（固定資産税・修繕、自動車税・車検、保険の年払い）を外した。生活費ではなく、入れる所は FP が分かる。車の費用は交通費の欄の説明で「車」の入力項目へ案内する（1 のとおり）。
- ひな形のボタンは、行が無いときの区画の下の簡易のボタンをやめ、どれもこの確かめの一覧のまとまりの中に、標準と詳細で同じ形で並べる（まとまりも標準）。並びは「通院・歯の治療」「ペットの医療」「帰省」「家電・家具の買い替え」「年会費・サブスクの年払い」「スマホの買い替え」「パソコンの買い替え」、最後にひな形に無い行を足す「＋ その他の年払い・数年おきの支出」（前の「＋ 年払い・数年おきの支出」）。足したひな形はボタンの代わりに「入れた（行の名前）」の行になる（0048 の追記 2026-10-29 の確かめの一覧を改めた）。
- **旅行のひな形を外した**。旅行はライフイベントの入力項目のひな形「家族旅行」（毎年30万円の目安）で入れる。前に足した「旅行」の行は、ふつうの行のまま残る（確かめの一覧には出さない）。
