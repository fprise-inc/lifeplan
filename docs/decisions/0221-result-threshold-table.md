# 0221. 結果のタブの「足りる境目」（運用の利回りごとの、最後まで足りるいちばん早い働く最後の年齢）

- 状態: 採用（一部未確定）（2026-11-17）
- 固定の強さ: 内部（画面の見た目・言葉・列の数と刻み・計算の頼み方は後から変えてよい。判定と動かす項目の意味は 0202 の `find_threshold` とそろえ続ける）
- 前提にする記録: 0064・0074（結果のタブの計算のお知らせ・ポイントの閉じた1行）、0084（対策の項目）、0195（プランの動かす項目）、0202（AI接続口の感度・境目探し）、0026（取り崩しの計算）、0098（率の範囲）

## 背景

- 結果のタブの見出し（「プランBでは、金融資産は 93歳 まで持ちます」）を見た FP が次に知りたいのは「何歳まで働けば足りるか」「利回りがいくらなら足りるか」だが、画面では対策のスライダーを1つずつ動かして探すしかなかった。AI接続口には境目探し（`find_threshold`。0202）があるが、画面には無かった。
- 結果のタブはもう情報が多い。新しいボタンや区画を足すと画面がごちゃごちゃする。

## 決定

### 1. 置き場所と見た目

- 結果のタブの見出しの下の、「計算のお知らせ ○件 ▸」「ポイント ○件 ▸」と同じ並び（`.result-quiet`）に、同じ形の小さな文字「足りる境目 ▸」を1つ足す。ふだんは閉じていて、画面は今とほぼ同じ。
- 開くと、すぐ下（ほかの2つを開いたときと同じ場所）に小さな表を出す。
  - 見出し: 最後まで足りる、いちばん早い「働く最後の年齢」
  - 1行目: 運用の利回り（5列）。2行目: その利回りのとき、金融資産が最後まで尽きない、いちばん早い働く最後の年齢（ご本人）。
  - 今のプランの列は太字と薄い地。表の下に「今のプラン（プランB）は 利回り4%・65歳まで働く」、配偶者がいれば「配偶者の働く年齢は今のままです（動かすのはご本人だけ）」。
  - どの年齢でも足りない列は「75歳まで働いても足りません」（○はスライダーの上の端。文字は不足の色）、いちばん若い年齢でも足りる列は「55歳でも足ります」（○はスライダーの下の端）、計算できなかった列は「計算できませんでした」。
- 狭い幅では、行の名前を折り返し、ますの余白を詰めて5列を幅に収める（収まらないときだけ表の枠の中で横に送る。画面は横にはみ出さない）。文字の大きさ「大」でも同じ並び。

### 2. 列（運用の利回り）

- 今のプラン（選んでいるプラン）の利回りを中心に、1%刻みで5列（今が4%なら 2〜6%）。利回りは対策の項目「運用の利回り（預金を除く）」（`inv:rate`）の値と同じ当て先・同じ読み方（運用する口座の残高で平均し、前提の書き換えを足した値）。
- 0%より下の列は出さず、その分を上に足して5列にする（今が0.1%なら 0.1〜4.1%）。運用の利回りの範囲（0098。上の端 15%）より上も出さず、その分を下に足す。今のプランの列は、マイナスの利回りでも出す。
- 見せ方は小数1桁で、.0 は付けない（「4%」「3.3%」）。

### 3. 判定と探し方（AI接続口の find_threshold とそろえる）

- 判定は `find_threshold` の `noDepletion`（資産が最後まで尽きない）と同じ: 主な数字の「資産が尽きる年」（`plans/compare.ts` の `metricsOf`。接続口の `keyFigures.depletion` と同じ関数）が無いこと。結果の見出しの「最後まで足ります」とも同じ。
- 動かすのは対策の「働く最後の年齢」（`lever:retireAge`。接続口の `employment.to`）と「運用の利回り（預金を除く）」（`inv:rate`。接続口の `assumptions.returnShifts`）。1つのますは、選んでいるプランの値に2つを重ね、画面のプランと同じ関数（`plans.ts` の `applyValues`）で要求にする（働く最後の年齢なら、生活費の退職の段階・積立の終わり・定年後の働き方も一緒に動く）。接続口の `plan_changes` で同じ2つを渡したときと同じ要求になる（テストで確かめる）。表に出している結果と同じく、結果の見方（夢と予定の入れ外し）も当てる。
- 探す範囲は、対策の「働く最後の年齢」のスライダーの範囲（今の年齢の次か50歳の遅い方〜75歳。今の値が上の端より上なら広げる。`list_plan_items` の範囲と同じ）。
- 探し方は `find_threshold` の二分探索（`want: min`）と同じ: 範囲の両端を計算し、若い端で足りれば「○歳でも足ります」、上の端でも足りなければ「○歳まで働いても足りません」、そうでなければ「足りない年齢」と「足りる年齢」を保って半分ずつ狭める。働く最後の年齢は単調と分かる項目（0202 の `MONOTONE`）なので二分探索でよい。同じ年齢は2度計算せず、1列あたり 2＋log2(範囲の年齢の数) 回以内（50〜75歳なら7回）。
- 5列は一緒に進める: 1回ごとに、まだ決まっていない列の年齢をまとめて本体に頼む（`host.ts` の `batchCompute`。本体は枠を同時に計算する。表示の計算とは別の待ち行列）。見本の世帯で全部で約20〜35回の計算。

### 4. いつ計算するか

- 開いたときだけ計算する。閉じている間は計算しない。開いている間に選んでいるプラン・その値・結果の見方が変わったら、少し待って（0.3秒。スライダーを動かしている間に何度も計算し直さない）計算し直し、前の計算は途中でやめる。前のプランの答えは出さない（計算している間は「計算しています…」）。

### 5. 列を押したとき

- 答えのある列（境目の年齢・「○歳でも足ります」）を押すと、その利回りと年齢を対策に入れる。対策のスライダーを動かしたのと同じ扱い（選んでいるプランの保存していない変更）で、「運用の利回り」の項目が対策に出ていなければ出す。2つの変更は元に戻すの1回で一緒に戻る。押した後は表の下に「対策に入れました: 働く最後の年齢 67歳・運用の利回り 年4%」。
- 「足りません」「計算できませんでした」の列は押せない。

### 6. 出さない世帯・場面

- 働く最後の年齢の対策が出せない世帯では、「足りる境目」自体を出さない: 対策に「働く最後の年齢」が無い（勤めの終わりが入っていない）・ご本人に今かこれから収入のある働き方（勤め・自営業）が無い（年金暮らし・働いていない）・働き方がもう終わっている（退職した）・スライダーが動かない。運用の利回りの項目が無い（金融資産の口座が無い）世帯も出さない。
- 選んでいるプランの計算ができなかったとき（結果の見出しを出さないとき）も出さない。
- 「計算のお知らせ」「ポイント」とそろえた扱い:
  - 基準の案・ほかの案のどれを選んでいても、選んでいるプランで計算して出す。現状・基準のプランを選んでいるとき（対策のスライダーが動かせないとき）は、表は出すが列は押せず、「列を押して対策に入れるのは、動かせるプランを選んだときです」と出す（取り崩しの計算の「対策に入れる」と同じ）。
  - 見本の世帯（読み取り専用の棚）・読み取り専用で開いた世帯でも出し、列も押せる（対策のスライダーと同じく、動かした値は保存しない）。
  - 説明モードの間も出す（2つと同じく、グラフの枠の上の並びは説明モードでも残る）。
  - お客さまと一緒に見る結果のタブに出る。グラフの小窓・提案書・持ち帰り用のレポートには出さない（2つと同じ）。

## 理由

- 2つの小さな文字と同じ並び・同じ開き方にすれば、閉じているときの画面はほとんど変わらず、開き方も覚え直さなくてよい。
- 判定・動かす項目・探し方を `find_threshold` とそろえれば、画面の表と AI の答えが食い違わない（同じ世帯・同じプランなら同じ年齢）。
- 列を押すと対策に入る形にすれば、表で見つけた組み合わせをそのままグラフ・比較の表・保存に使える。

## 代案（採らなかったもの）

- **結果のタブに新しい区画やボタンを置く**: 画面がごちゃごちゃする（本人が心配した点）。
- **閉じている間も先に計算しておく**: 1回開くごとに約20〜35回の計算になる。開かない FP のほうが多いので、開いたときだけにした。
- **0%より下の列を除いたまま、列を減らす**: 預金が中心の世帯（0.1%など）で3列しか出ず、比較にならない。上に足して5列にした。
- **画面で1列ずつ1回ずつ計算する（取り崩しの計算と同じ）**: 本体は枠を同時に計算できるのに使わず、時間が数倍かかる。
