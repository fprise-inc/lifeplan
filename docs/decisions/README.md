# 設計記録（ADR）の索引

ファイナンシア（Financia）の、あとから変えにくい骨組みの決定の記録。β公開（2027年2月予定）から骨格は変えない。

- 書き方・状態・固定の強さの意味・変え方は [0001](0001-decision-records-and-freeze-policy.md) を先に読む。
- 状態と固定の強さの正は各記録の冒頭の行。この索引はそれを写した案内で、食い違ったら各記録が正（CIで一致を確かめる。0001）。
- 提供元は FPライズ（FPRISE, INC.）。記録に書くのは技術の決定だけ（0001 の9）。

## 未確定の要点（11月以降に決めること）

各記録の「未確定」の要約。詳しい条件と「いつ・何を見て決めるか」は各記録を見る。決めたら各記録の「追記」に書き、この節も直す。

- **0001**: 記録の英語版を用意するか。（公開の約束の版の初期値は 2026-10-08 に決定: β公開までは `0.x`、β公開で安定のものを `1.0`）
- **0002**: 率の途中の桁（小数12桁）で足りるか（12月）。負の値に固有の丸めが要る制度があるか。年金・給付などの端数処理の規則ID（所得税・住民税・社会保険料の分は 2026-10-08 に追記）。Rust 側で金額を受ける型（`i64` 案）。
- **0003**: 日単位の給付の近似（暦の日数か30日換算か、12月）。年の途中で変わる「年分」の値の書き方（11月）。運用益の丸めと互換モードで変えられる項目（移行を扱う記録はまだ無く、β公開までに作る）。（税・社会保険料の支払月の既定は 2026-10-08 に追記）
- **0004**: 明細（第3段）の科目の一覧（11〜12月）。可処分所得方式の行の並び（1月）。器ごとの残高の行の分け方（11月）。（登録簿の置き場所・形式は 2026-10-08 に決定: `registry/` の YAML）
- **0005**: 遅いPC・Windows 実機での速さ（β公開まで）。計算プロセスの起動時間と待機の数（プロセスかスレッド＋割り込みか）。上限の最終値、本物の部品での再計測。（凍結の順番は 2026-10-08 に確認済み）
- **0006**: 差し替えを許す公式部品の一覧（12〜1月）と、開く3つの差し込み口の約束の中身（12月）。`full` の記録の圧縮と大きさの目安（細かさは 2026-10-08 に「部品の呼び出しごと」と決定）、`summary` が要るか（1〜3月）。エンジン全体のスキーマの版の扱い（0011 と、11月）。
- **0007**: 式の型・連動の規則の一覧、条件のキーと `features` の名前の最初の一覧。データの組と「データの組の版」の形。（版の初期値・値IDの命名・等級表の形は 2026-10-08 に追記）
- **0008**: 収入・支出・退職給付の物の細部。口座の `kind`・保険の `template`・資産クラスの正式な一覧。現状の版を積むときの引き継ぎ。（「わからない」の代わりの値の扱いは 2026-10-11 に追記: 推定は入力のときに入れ、元の入力が変わったら入れ直す）
- **0009**: 刻印の帯を守る実装（11月に試作）と刻印の書式。宛名の重ね方、PDF をバイト単位で同じにするか。帳票の入力の JSON Schema の最初の版。
- **0010**: 学部系統の対応表と `track` の一覧。統計の内訳の粒度、自宅外の生活費の置き場所。専門学校・大学院・短大の扱いと、学校の一覧の正本の形式。
- **0011**: 電源断への備え（`F_FULLFSYNC`、Windows の差し替えの API）と同期フォルダの上での扱い。拡張子、圧縮、見出しを JSON か CBOR か。`embedded.regulation` の範囲、拡張の作成者名の付け方。
- **0012**: 障害に関わる税の扱いを実在の状態なしで表す方法。氏名らしい語・禁止語の検出規則。顧客番号の既定の書式。
- **0013**: 署名した版でのキーチェーンの確認ダイアログ、Windows 実機（資格情報マネージャーか DPAPI のファイルか）。親鍵の入れ替えの画面をいつ入れるか。Windows Hello・Touch ID の扱い、復元キーの別の見せ方。
- **0014**: `reads` に残す呼び出し元の情報を Mac・Windows でどこまで取れるか。顧客本人への開示用の読める一覧、説明文のひな形、同意の有効期限。
- **0015**: Windows 実機（名前付きパイプ）とストア版の設定の場所。相手の実行ファイルの署名の確認、縮約版の許可リスト、期限の選択肢。道具の最終の一覧、`rmcp` の成熟度、拡張（MCPB）の署名。

- **0018**: 項目の一覧とキー、繰り返しの上限。使う部品（`rust_xlsxwriter`・`calamine`）とファイルの上限の値。QR コード、Web フォームを作る場合の形。
- **0019**: スキルをAIごとの決まった場所にも置くか、英語版の説明書。AI用パックの形、PATH への登録、`AGENTS.md` の上限の大きさ、説明書の質の確認の基準。
- **0020**: 顧客本人への開示用の読める一覧。不具合報告で生年月をずらす幅と金額の係数の幅。引き継ぎのパスワードの形、クリップボードへの写しの扱い、同期フォルダの見分け方。（キャッシュフロー表の Excel・CSV の書き出しは 2026-10-08 に追記）
- **0021**: 公的な検定の問題から作ったテストを公開できるか。ライセンスの一覧の道具の選定（開発だけの依存の扱いは 2026-10-08 に追記）、REUSE の形式を採るか。プルリクエストの自動クローズ、ブランチ保護（0022 と）。
- **0022**: 値の種類ごとの変化率の上限の初期値と卒業の基準。段階配信の段階と割合、自動配信用の鍵の保管と使い方。確認期間中の通知と止める手順、巻き戻したときの知らせ方、自動のAIの処理の上限。

## 記録をまたいで残っている整合の課題（11月に決める）

- 他のソフトからの移行（読み取り規則・用語辞書）の記録がまだ無い。0001 の公開の約束の表と 0003 が前提にしているので、β公開までに新しい番号で作る。
- 2026-10-08 に解決したもの（各記録の追記）: 約束の版の宣言の書き方（`requires` を範囲にそろえ、`"1"` は `">=1 <2"` の省略形。0006・0007）、取り下げの指し方（`<ID>@<改訂の整数>`。0007・0009）、配信の目録の欄名（`catalogVersion`。0022）、上書きの記録の `proposedBy`・`approvedBy`（0008）。
