# 0016. 画面の安全とカスタマイズ層

- 状態: 採用（一部未確定）（2026-10-08）
- 固定の強さ: 画面の箱の考え方（CSP・許可した命令だけ・画面に保存しない）、カスタム層の置き場所と4種類の中身、承認と指紋での固定、隔離実行、画面系は宣言型だけ、提示層の作り方は β公開から変えない（骨格）。拡張モジュールの書き方（マニフェストの項目・SDK の関数）は試験版（予告して変えることがある。0001）。カスタム層の設定の書き方（説明の文の差し替え `texts` と説明の一覧の `id` を含む。2026-11-01 の追記。名前の差し替え `terms`・入力の欄の見せ方 `fields` と名前の一覧・欄の一覧の `id` も。2026-11-02 の追記）も試験版

## 背景

ファイナンシアは、顧客の世帯データを扱う画面（Tauri 2 の WebView）と、FPやFPのAIが作り変える部分（カスタム層）を同じアプリの中に持つ。AIが書いたコードを顧客データのそばで動かす以上、次の3つを仕組みで守る必要がある。

1. 画面から外へデータが出ない。画面に顧客データが残らない。
2. FPやAIが作った計算部品・帳票が、顧客データを持ち出せない。FPが承認していないものは動かない。
3. 顧客に見せる画面と提案書に、FP向けの情報（メモ、他の顧客、カスタム計算の印など）が出ない。

画面は3つの層に分ける: **入力**（世帯の事実を入れる）、**作業**（FPが分析・提案を作る）、**提示**（顧客に見せる。対面・画面共有）。

関連: 計算エンジンの実行環境と二本立ては 0005、部品表・差し込み口・版は 0006、控えと刻印は 0009、事務所データと拡張領域は 0011、暗号化とデータフォルダは 0013、AI接続口は 0015、SDKフォルダと AGENTS.md は 0019。

## 決定

### 1. 画面（WebView）は「外と話せない箱」にする

- **CSP**（本番の設定。開発用の `devCsp` は本番のビルドに入れない）:

  ```
  default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self'; font-src 'self';
  connect-src 'self' ipc: http://ipc.localhost; media-src 'none'; object-src 'none'; frame-src 'none';
  worker-src 'none'; base-uri 'none'; form-action 'none'
  ```

  - `unsafe-eval`・`unsafe-inline` は使わない（文字列からのコード実行を止める）。`form-action` と `base-uri` は `default-src` では止まらないので明示する。
  - 画面の部品・フォント・画像はすべてアプリに埋め込み、外のサーバーから読み込まない。
- **本体の命令（Tauri の capabilities）**: 画面から呼べるのは、アプリが自分で定義して `build.rs` で登録した命令のうち、capabilities のファイル（1つ）に載せたものだけにする。
  - ファイル・シェル・ブラウザを開く・ウィンドウ操作・HTTP などのプラグインの権限は、画面に与えない。
  - 「パスやURLを引数に取る汎用の命令」（任意のファイルを読む、任意のURLを開く など）は作らない。命令は「この世帯を保存する」「この計算をする」のように用途ごとに作る。
  - 命令を足すときは、capabilities のファイルの差分をレビューの対象にする。
- **画面に保存しない**:
  - 起動時のスクリプト（画面のどのスクリプトよりも先に動き、上書きできない形）で、`localStorage`・`sessionStorage`・`indexedDB`・`caches`・`document.cookie` を使えなくする（使うと例外になる）。
  - WebView は「ディスクに保存しない置き場」（incognito）で開く。二重にする。
  - 画面では WebAssembly を使わないので、起動時のスクリプトで `WebAssembly` を消す（CSP の下でも動くことを確認したため）。
  - 本番のビルドでは、画面のコンソールに顧客データを出さない。
- **外部リンク**: アプリの中では外のページを開かない。
  - 画面の移動（`on_navigation`）と新しいウィンドウ（`on_new_window`）は本体で止める。`target="_blank"` のリンクは、クリックを横取りする小さなスクリプトで止める。
  - 外のページは、アプリの命令を通して既定のブラウザで開く。開けるのは `https://` だけ。アプリが持つ一覧（同梱の説明ページなど）に載っていない先は、開く前にURLを見せて確認する。
- **役割の分け方**: 復号・署名の確認・ファイルの読み書き・通信はすべて Rust 側で行い、画面側では行わない。画面側の計算は、操作中の速い表示のための公式のエンジンだけ（二本立て。0005）。**カスタムの計算部品は画面の中では動かさない**。

### 2. 提示層は「内部情報を受け取らない部品」だけで作る

- 提示層の部品が受け取れるのは、アプリ本体が作る「提示用の値」（`PresentationModel`）だけにする。提示用の値は、許可リストで項目を選んで作る別の型で、次を含まない: FPのメモ、他の顧客の情報、カスタム計算の印と内部記録、取り下げなどFP向けの注記、AIへの共有の状態、根拠の記録のうちFP向けの部分。
- 提示層の部品は、入力・作業の層の状態（ストア）を読み込めない。自動チェック（読み込みの規則）でこれを禁止する。
- 提示層には、カスタム層からコードを入れられない（画面系のカスタマイズは宣言型だけ。下の4）。
- 「FP用のメモを隠す」の切り替え（入力の層）とは別の仕組みとする。切り替えは見た目の都合、提示層は構造で守る。

### 3. カスタム層の置き場所と中身

- カスタム層は、アプリ本体・データフォルダ（0013）とは別のフォルダに置く。FPのAIがこのフォルダを作業フォルダとして開く前提で作る。
  - 既定の場所は、Mac が `~/Documents/lifeplan-custom/`、Windows が `%USERPROFILE%\Documents\lifeplan-custom\`（製品名に依存させない）。FPが変えられる。
  - カスタム層とデータフォルダ・鍵置き場は、互いに相手を含んではいけない。含む場所を選ぼうとしたらアプリが止める（データフォルダの側の決まりは 0011・0013）。
- フォルダの構成:

  ```
  lifeplan-custom/
    AGENTS.md  CLAUDE.md  GEMINI.md   … アプリが管理（0019）
    NOTES.md                          … FPのメモ（アプリは触らない。0019）
    sdk/                              … SDKフォルダ（アプリが丸ごと入れ替える。0019）
    settings/                         … 1. 設定（前提条件の標準値、帳票の文言・構成・ロゴ、
                                           ヒアリングの項目の選択と並び、移行の用語辞書と対応付け、画面の用語セット）
    modules/<モジュール名>/            … 2. 計算部品（エンジン一式を含む）
    reports/<帳票名>/                  … 3. 帳票（Typst）
    fields/                           … 4. 入力欄（宣言型の独自の入力欄。値は世帯ファイルの拡張領域へ。0011）
  ```

- 承認の台帳と、承認した中身の保存庫は、カスタム層の中に置かず、アプリが管理する事務所データの側（0011）に置く。カスタム層はAIが自由に書き換えられる場所なので、承認の記録まで書き換えられないようにするため。台帳には事務所の親鍵から作った改ざん検出を付け、書き換えられたら承認を無効にする。

### 4. 画面系のカスタマイズは宣言型だけ

- 設定・帳票の構成・入力欄・ヒアリングの項目は、JSON（または YAML）の設定ファイルだけで行い、それぞれに JSON Schema を用意してアプリが検査する。
- HTML・CSS・JavaScript を画面に差し込む手段は作らない。設定の中の文字列は、文字として表示し、HTML として解釈しない。
- ロゴなどの画像は PNG と JPEG だけを受け付け、大きさに上限を置く（SVG は中にスクリプトを持てるので受け付けない）。
- コードを書けるのは計算部品（とエンジン一式）と、帳票（Typst）だけにする。

### 5. 拡張モジュール（計算部品）の書き方

- TypeScript で書く。ビルドは不要で、アプリが読み込むときに型を取り除く。
- 読み込めるのは、モジュールのフォルダの中の相対パスと、公式SDK（`@lifeplan/sdk`）だけ。外部のパッケージ、`node:` で始まるもの、動的な `import()` は使えない。
- 時計（`Date` など）と乱数（`Math.random` など）は呼ぶと例外になる。基準日は入力で渡す（0003）。`Math.pow`・`exp`・`log` などOSで最後の桁がずれる関数も使えない（0005）。端数処理は条文を指定する公式の関数だけを使う（0002）。
- 正しさの判定は、実行時の JSON Schema の検査と、根拠の記録の形式の検査で行う（0006）。
- **マニフェスト**（`manifest.json`）を必須にする:

  ```json
  {
    "manifestVersion": "1.0",
    "id": "ext.exampleOffice.retirementRule",
    "name": "勤務先の退職金規程（〇〇社型）",
    "version": "1.2.0",
    "author": "（作成者の表示名）",
    "license": "MIT",
    "kind": "component",
    "entry": "index.ts",
    "provides": [
      { "type": "replace", "target": "retirement.benefit.rules", "contract": "1" },
      { "type": "extend", "extensionPoint": "slot.expense.flow", "contract": "1" }
    ],
    "reads": ["employment.retirementRule", "income.salary.annual"],
    "dependsOn": [{ "id": "ext.exampleOffice.common", "version": "^1.0.0" }],
    "description": "モジュールが何をするかの説明"
  }
  ```

  - `manifestVersion` はマニフェストの書き方の版（`MAJOR.MINOR`。0001）。`id` は拡張の名前空間（`ext.<作成者>.<名前>`。各段は0004の書式。0011）に従う。
  - `kind` は `component`（計算部品）か `engine`（エンジン一式）。
  - `provides` の `replace` は公式部品の差し替え（差し替えてよい公式部品の一覧に載ったものだけ）、`extend` は差し込み口への追加。どちらも約束の版（0006）を書く。
  - `reads` に書いた入力項目だけを渡す。書いていない項目は渡さない。
  - 同じ部品に有効な差し替えは1つだけ。ぶつかる場合は承認できない。
- 上の例の項目名・部品IDは説明用で、実際の一覧は 0004・0006 と SDK に従う。

### 6. 承認と指紋での固定

- **アプリの画面の外で変わったものは、4種類（設定・計算部品・帳票・入力欄）とも承認の対象にする**。アプリの設定画面で FP が自分で変えたものは、その操作を承認とみなす。
- 新しいもの・変わったものは「保留」に置き、承認の画面に次を見せる: 前に承認した版との差分、差し替える公式部品と差し込み口、読む入力項目、モデル世帯での公式との計算の差（計算部品・エンジン一式・帳票の場合）、ライセンス。
- 画面に「隔離で防げるのは情報の持ち出しで、数字の正しさは保証しない」と書き、有効にする前に公式との差を必ず見せる。
- FPが承認したら、中身の指紋（モジュールのフォルダの全ファイルを、パスの順に並べて計算した SHA-256）で固定する。動かすのは、承認した指紋と一致する中身だけ。ファイルが1つでも変わったら承認を外し、保留に戻す。
- 承認待ちのモジュールを使うプランは「モジュールが承認待ちのため計算できません」と明示し、黙って公式に戻さない。
- 承認した中身は、指紋を名前にして版ごとに保存庫へ保存し、古い版を消さない（控えの再現のため。0009）。
- **共有用の形式（モジュール束）**: 1つの zip に、マニフェスト・ファイル・指紋の一覧・任意の作者の署名を入れる。取り込んだものは必ず保留に置き、署名があっても承認を省かない（署名は「誰が作ったか」の表示にだけ使う）。
- FPライズは、共有モジュールの置き場（カタログ）を運営しない。

### 7. 隔離実行

- 計算部品とエンジン一式は、Rust に組み込んだ quickjs-ng（`rquickjs`）の中でだけ動かす（0005）。
  - ネットワーク・ファイル・タイマー・時計・乱数・ホストの機能を持たない環境にする。
  - 渡すのは、入力のコピー（中で書き換えても元は変わらない）、制度データの読み取り関数、端数処理などの公式の関数だけ。
  - 実行環境は計算の要求ごとに新しく作って捨てる。同じ環境を使い回すと、組み込みの差し替え（例: `Math.min`）で次の計算の結果だけが黙って変わりうるため。
  - 時間・メモリ・スタックの上限を付け、時間の上限が効かない重い処理でも、別の計算プロセスごと外から打ち切る。上限の値と計算プロセスの作りは 0005 に従う（カスタム部品にだけ別の値を設けない）。
- **独自帳票（Typst）**: 帳票のフォルダと、アプリが渡した値だけを読める。Typst のパッケージをネットワークから取りに行く機能は切り、アプリに同梱した公式の帳票部品だけを使える。時間とメモリの上限を付ける。
- **脱出テスト**をリリースのたびに流す: ネットワーク・保存領域・本体の命令・時計・乱数・ファイル・モジュールの読み込みが、計算部品の中からすべて失敗すること、上限で止まりホストが落ちないこと。

### 8. カスタム計算の扱い

- カスタムの計算部品・エンジン一式を使ったプランは、FP向けの画面に「カスタム計算あり」と出す。顧客が見る提案書PDFと提示層には出さない。使ったモジュールの指紋は、世帯ファイルと控え、PDFの印刷されない内部情報に残す（0009）。
- 画面に「公式の計算」「カスタムの計算」の切り替えを置き、差を並べて見られるようにする。
- テストは3種類（①約束＝必ず通る、②性質＝警告、③公式との差＝合否にしない）。コマンド `lifeplan module test` で流せる（0019）。

## 理由

- **画面を箱にする**: 画面は表示のための部品（WebView）で、ブラウザと同じく外と通信する能力を持っている。CSP と capabilities で能力を最初から取り上げておけば、画面のコードに誤りがあっても、外への送信や任意のファイル操作に至らない。
- **画面に保存しない**: WebView の保存機能は、アプリの暗号化（0013）の外にある。ここに顧客データが残ると、常に暗号化するという約束が破れる。
- **承認の台帳をカスタム層の外に置く**: AI はカスタム層のファイルを自由に書き換える。承認の記録まで同じ場所にあると、AI（や乗っ取られた AI）が承認を偽造できる。
- **設定も承認の対象にする**: AI がファイルを直接書き換える使い方が前提なので、前提条件の標準値や帳票の文言が、FPの知らないうちに変わらないようにする。
- **提示層を型で分ける**: 「表示しないように気をつける」方式は、部品が増えるたびに漏れの機会が増える。受け取る値の型に内部情報が無ければ、誤っても表示しようがない。
- **画面系を宣言型だけにする**: 画面にコードを入れられると、CSP と capabilities の箱の内側で、顧客データを扱う画面そのものが改造できてしまう。計算部品は隔離実行で囲えるが、画面のコードは囲えない。
- **カスタム層を書類フォルダに置く**: FPとFPのAIが日常的に開く場所なので、見つけやすい場所にする。データフォルダと分けるのは、AIの作業範囲に顧客データを入れないため。

## 影響

- **後から変えると何が起きるか**: カスタム層の場所・4種類の構成・マニフェストの形を変えると、全FPのカスタムとAIの手順（0019）が壊れる。承認の方式を緩めると、配布済みの環境で未承認のコードが動く状態を作りうる。CSP や capabilities を緩めると、画面の安全の前提が崩れる。
- **守るべき決まり**
  - CSP・capabilities・起動時のスクリプトの変更は、安全のレビューを必ず通す。
  - 画面のコードで、ブラウザの保存機能・外部の読み込み・`eval` 系を使わない。
  - 提示層の部品は `PresentationModel` 以外を受け取らない。
  - カスタムの計算部品を、画面の中や隔離の外で動かす経路を作らない。
  - 拡張モジュールの書き方は試験版。変えるときは3か月前に予告し、AI向けの移行手順と自動変換を添える（0001）。
- **テストで確かめること**
  - 画面から外への通信（fetch・XHR・画像・スクリプト・スタイル・WebSocket・EventSource・sendBeacon・iframe）が0件。`eval`・`new Function`・文字列の `setTimeout`・後から足した `script` が止まる。
  - 登録していない命令・プラグインの命令が「許可されていない」で拒否される。
  - 画面の保存機能5種類が例外になる。画面がディスクに残すファイルが0個（ディスクの置き場を探すスクリプトで確かめる）。
  - 外部リンク4種類（ふつうのリンク・`location.href`・`window.open`・`target="_blank"`）がアプリ内で開かない。
  - 提示層の画面を、メモ欄などに目印の文字列を入れた世帯で表示し、目印が画面のどこにも出ない。
  - 未承認・変更後のモジュールが動かない。台帳を書き換えると承認が無効になる。
  - 脱出テスト（上の7）。
  - Windows（WebView2）と Mac（WKWebView）の両方で、上のすべて。

## 試作での確認

Mac（Apple M5、WKWebView、Tauri 2.12.1）で確かめた。

- CSP ありで、画面から外への通信の試み9種類のうち見張りサーバーに届いたのは **0件**（CSP なしでは8件届いた）。文字列からのコード実行4種類はすべて止まった。
- 許可していない本体の機能11種類（自作の禁止命令・存在しない命令・ファイル・シェル・ブラウザを開く2種・ウィンドウ・イベント・アプリ・パス・WebView）はすべて拒否され、許可した3つだけが呼べた。
- 画面の保存機能5種類を起動時のスクリプトで使えなくできた。incognito では、画面がディスクに書いたファイルが **0個**だった。
- 画面側の計算（5案×4想定）は中央値約16ミリ秒（目標の0.1秒を大きく下回る）。CSP の下でも対処なしで動き、本体の QuickJS と結果のハッシュがビット単位で一致した。
- 外部リンクはアプリ内で開かず、既定のブラウザへ回す作りにできた（`target="_blank"` は小さなスクリプトが必要）。
- WebAssembly は CSP（`unsafe-eval` なし）の下でも動いたため、起動時に消す決定にした。
- 隔離実行（Rust 組込みの QuickJS）: ネットワーク・ファイル・モジュール・ホストの内部・タイマー・時計・乱数への脱出はすべて失敗した。無限ループは0.1秒の上限で、メモリを使い尽くす計算は32MBの上限で（31〜93ミリ秒で）止まり、ホストは落ちなかった。参考に試した Node の `vm` はホストに届き、隔離に使えないことを確認した。組み込みのオブジェクトを凍らせないと、同じ環境の中の差し替えで結果だけが黙って変わることも確認した。

## 未確定（11月以降に決めること）

- **Windows（WebView2）での確認**: CSP・capabilities は共通の仕組みなので同じく効く見込みだが、incognito（InPrivate）でディスクに何も残らないかを実機で確かめる。
- **型を取り除く部品**: Rust 製のもの（oxc・swc など）のどれを使うか。ライセンスと大きさで決める。

  1. **置き場所と形**: カスタム層の `settings/texts.json`（1つのファイル）。JSON Schema（`sdk/schemas/settings/texts.schema.json`）でアプリが検査する。

     ```json
     {
       "schema": "texts@1.0",
       "entries": [
         { "id": "field:debt.rateSchedule/*/rate", "do": "replace", "text": "…", "basedOn": "sha256:…" },
         { "id": "notice:N_NOT_SUPPORTED|transfers", "do": "append", "text": "…", "basedOn": "sha256:…" },
         { "id": "action:insurance.addCoverage", "do": "hide", "basedOn": "sha256:…" }
       ]
     }
     ```

     - `do` は3つ: `replace`（書き換える。公式の文が無い所に書けば、説明を足すことになる）、`append`（公式の文の後ろに段落を足す。公式の文が直れば、足した段落の前も新しくなる）、`hide`（消す。説明なら「?」ごと出さない）。
     - `basedOn`（必須）は、書いたときの公式の文の指紋（下の2 の説明の一覧の `hash`）。更新で公式の文が変わったことを見つけるために使う（7）。
     - 同じ `id` の行は1つだけ（2つあれば承認できない）。説明の一覧に無い `id` の行は誤りにせず、承認の画面に「使われていない行」として出して読み飛ばす（更新で欄が無くなっても、設定のファイル全体を止めないため）。
  2. **どの文かの識別（説明の一覧）**: アプリは、書き換えられる文をすべて載せた**説明の一覧**を SDK に同梱する（`sdk/reference/texts.json`。リリースのビルドが画面の定義から作る。0019 の2 の `reference/` に足す）。1件の中身は `id`・`kind`・`where`（画面のどこの文か。日本語）・`audience`（`fp`／`customer`。5）・`text`（公式の文。差し込みの印つき）・`vars`（使える差し込みの印と意味。3）・`hash`（`text` の SHA-256）・`ops`（できる操作。4）・任意の `formerIds`・任意の `meaningChanged`（7）。

       | 文 | `id` | 例 |
       |---|---|---|
       | 欄の説明 | `field:<入力項目ID>[/<道>]`（入力項目ID は 0004。道は 0036 の当て先の `at` で、並びの要素の ID は `*`） | `field:debt.rateSchedule/*/rate` |

       | 確かめの注意 | `check:<名前>` | — |
       | 推定の根拠の文 | `estimate:<入力項目ID>[/<道>][#<型>]`（1つの欄に根拠の文が何通りかあるときは `#` で分ける） | `estimate:ui.savings.stopAge#retired` |

  3. **文の決まり**（4 の「HTML として解釈しない」をこの設定に当てる）:
     - 文はただの文字。HTML・Markdown として解釈しない（`<b>` も `**` も字のまま出る）。画面の部品は文を文字として入れ、HTML として差し込む道（`dangerouslySetInnerHTML` など）に渡さない（今の `Help` と同じ）。
     - 改行（`\n`）は段落の区切りとして出す（今の説明の文と同じ）。行頭の「・」は字のまま出す（箇条書きの形にはしない）。
     - 受け付けない字: 改行のほかの制御文字と、文字の向きを変える字（U+202A〜U+202E・U+2066〜U+2069）。見た目と中身が違う文を作れるため。
