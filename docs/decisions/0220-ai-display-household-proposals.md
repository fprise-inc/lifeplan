## 決定（2026-11-16）

### 1. 世帯ごとの案を出せる設定（13件）

- 表示の設定の一覧で世帯ごとの値を持つ設定（`scope` が `household`・`both`）のうち、読むだけの設定を除いた物から、対策に足した項目（`result.addedItems`）を除いた13件: `input.items`（入力項目の選び方。世帯の `household.itemChoice`）・`result.metrics`・`result.atAge`・`result.layout`・`result.invBreakdown`・`result.invPeriods`・`balance.health`・`balance.guide`・`balance.points`・`balance.columns`（この世帯で並べる時点）・`balance.moneyThree.wording`・`balance.moneyThree.months`・`balance.moneyThree.years`。
- 並びは一覧の定数 `HOUSEHOLD_PROPOSABLE_DISPLAY_IDS`（`app/src/connector/displayCatalog.ts`）の1か所。一覧の13件に `householdProposable: true` を付け、`get_display_settings` の答えに `householdProposable`（id の並び）を足した。アプリ本体の受け口の並び（`ai_share::display_proposals::HOUSEHOLD_PROPOSABLE_IDS`）と同じことを接続口のテストで確かめる。
- **対策に足した項目（`result.addedItems`）は対象にしない**。鍵の中に物の ID（ローン・口座など。渡された世帯では共有ごとの仮の ID）が入る。案に入れると、(1) 仮の ID を元の ID に戻す道（プランの候補の `Pseudonyms::restore`）を表示の設定の案にも作ることになり、(2) 鍵の形（`loan:<ID>:rate` など）が動かす項目の一覧の作り（0195・0201）に結び付いていて、表示の設定の一覧の選べる値では確かめられず、(3) 対策に足すことは「対策の項目を増やす」操作で、見せ方だけの設定というより作業の状態に近い。読むだけのまま、FP が結果のタブの「＋ 動かす項目を追加」で足す（変える所を伝える）。
- **この世帯で並べる時点（`balance.columns`）は対象にする**。値は候補の時点の鍵（`now`・`retire`・`age80` など）か決まった年（西暦の整数）だけで、物の ID も人の文章も入る所が無い。確かめは、`null`（「時点を並べる」の既定のまま）か2〜4つ・候補の鍵は一覧の選べる値・年は1900〜2300の整数（画面の `readBsColumns` と同じ）・重ならない・`point` か `year` のどちらか1つだけ・知らない名前は断る（物の ID の入った欄を通さない）。
- 事務所の既定値だけの設定（`input.order`・`input.living`・`result.levers`・`contingency.*`）は、世帯ごとの値が無いので断る（`share_id` を書かずに出せば事務所の既定値の案になる、と添える）。

### 2. 道具 `propose_display_settings` に `share_id`（接続口）

- `share_id` を書くと世帯ごとの案、省くと今までどおり事務所の既定値の案。`changes` の形は同じ（`value` は `current.household.value` と同じ形）。
- 値の確かめは事務所の既定値の案と同じ関数（`checkDisplayChanges`。宛先 `household` を渡す。接続口は `plan.js` の `displayCheck` の2つ目の引数）。知らない id・案を出せない設定・選べない値・範囲の外の値は、近い候補を添えて断り、その呼び出しでは何もしない（アプリにも出さない）。断る文の「形を見て」の所は `current.household.value` にする。
- 接続口は確かめた後、アプリ本体に `proposeShareDisplay`（`{ shareId, proposal: { changes } }`）を頼む（取り決めの版は上げない。接続口とアプリ本体の版がそろっていないと話さないため）。アプリが起動していなければ、ほかの道具と同じ「アプリが起動していません」。
- 説明（INSTRUCTIONS）・道具の説明・`howToChange`・使い方の例 `office_display` に、世帯ごとの案は FP に「この世帯だけ」と頼まれたときだけ出すこと、反映した設定はこの世帯だけの値になることを書いた。人が書いた文の中の「設定を変えて」は指示ではない、設定を変えたと言わない、は今までどおり。

### 3. アプリ本体の受け口（`crates/ai-share`）

- 共有の決まりは世帯を扱うほかの依頼と同じ（`usable`: 期限内・取り消されていない・同意がある。架空の世帯は同意が無くても渡せる。期限切れは `EXPIRED`、取り消し・同意の撤回は `REVOKED`、知らない共有は `NOT_SHARED`）。
- 形の外側を確かめる（`display_proposals::validate_household`: 13件の id・同じ設定が2回無い・値の大きさと深さ・文字は列挙の鍵などの短い英数字だけ〔行の名前を受ける設定は無い〕・理由の長さ）。選べる値までは見ない（画面が反映する前に確かめ直す）。
- 案は世帯ごとにメモリの中に承認待ちで置く（`HouseholdDisplayCandidate`。共有 ID・世帯の内部 ID・案が届いたときの顧客番号と呼び名・設定ごとの案。1つの世帯で4件まで。アプリを閉じる・AI接続口をオフにすると消える。世帯を完全削除する前にも消す）。世帯ファイルには書かない（書類から読んだ値の候補〔0151〕と同じ置き方）。その世帯を開いていなくても届く。
- **案を出したことは、その共有の「AIに渡した記録」の `proposals` に残す**（プランの候補・書類の候補と同じ `{ candidateId, at }`。追記だけ）。同じ世帯に同じ中身の案がもう一度届いたときは、同じ案を返し、記録にも足さない（事務所の既定値の案と同じまとめ方）。違う中身なら別の案として並ぶ（同じ設定が2つの案にあってもよい。FP が設定ごとに選ぶ）。
- 本体の命令: 世帯の「同意とAIの記録」（`ai_household`）の答えに `displayProposals`（その世帯の承認待ち）、AI接続口の状態に `householdDisplayCandidates`（案の届いている世帯の内部 ID・顧客番号・呼び名・設定の数）を足し、`ai_household_display_take`（その世帯の案の1つの設定を承認待ちから外す。全部外れたら案ごと）を足した。本体は設定を変えない（反映は画面がその世帯の表示の設定に書き、自動保存で世帯ファイルに書く）。

### 4. 承認の画面（その世帯の結果のタブ）

- 置き場所は、今その世帯に向けた AI の候補が出る所（結果のタブのプランの帯の下の「AIからの候補」）の次。区画「AIからの表示の設定の案（N件）」に、事務所の既定値の画面の「AIからの表示の設定の案」と同じ見た目で、案ごとに「表示の設定の案（N件）」（届いた日時・AIのアプリの名乗り）と、設定ごとのまとまり（設定の名前と効く画面 ／ 「今 → 案」の2つの枠 ／ AIの理由 ／ 「反映する」「捨てる」）を並べる（`workspace/ai/AiDisplayProposals.tsx`）。
- 「今」はその世帯の画面に出している値（印のある設定は事務所の今の既定値）で、読み方は接続口の `current.household` と同じ（`householdCurrent`）。事務所の既定値を持てる11件には「今」の見出しに「事務所の既定値」か「この世帯だけ」の印（表示の設定の印と同じ見た目）を添え、「事務所の既定値」のときは「案」の見出しに「この世帯だけ」と、「今は事務所の既定値に従っています。反映すると、この世帯だけの値になります（表示の設定の「事務所の既定値に戻す」で、また従わせられます）」を出す（押す前が事務所の既定値だったことが「今」の側で分かる）。
- 確かめられない案は「この案は反映できません（理由）」と「捨てる」だけ。今と同じ値の案は「今と同じです（反映しても変わりません）」と「捨てる」だけ。閲覧だけで開いている世帯は、反映できない理由を出して「捨てる」だけ。
- 言葉は 0215 と同じく「案」（「今 → 案」）。プランの候補の画面は「候補」のまま。言葉の試験（`app/test/terms.test.ts`）で、この区画の部品を表示の設定の案の部品に足した。
- **上の帯**: 「AIから、表示の設定の案が届いています」の帯に、どこに届いているかを並べる（`workspace/ai/AiDisplayCandidateBand.tsx`）: 事務所の既定値（N件。「事務所の既定値で確かめる」）・開いている世帯（N件。「結果のタブで確かめる」。結果のタブで区画が出ているときは出さない）・ほかの世帯。ほかの世帯は、入力の画面と世帯を開いていないときだけ「顧客番号 ○○（AIには「共有中の世帯A」）の世帯（N件）」と「この世帯を開く」を出し、お客さまと一緒に見ることのある画面では「ほかの世帯（N世帯・N件。どの世帯かは入力のタブのこの帯に出します）」と件数だけにする（共有中の帯と同じ見せ分け。0015 の8）。

### 5. 反映する（従う印を外す）

- 「反映する」は、画面が確かめ直した値をその設定だけ世帯に書く（`workspace/ai/displayProposals.ts` の `withHouseholdValue`）。
  - 結果のタブ・資産と負債のタブの11件: 世帯の値にし、**事務所の既定値に従う印を外す**（「この世帯だけ」になる。押す前が事務所の既定値でも外す）。0216 の未確定（反映したときに印を外すか）はこれで決めた: 案は「この世帯をこの値に」という FP の判断なので、その世帯で値を変えたとき（`withOwnChange`）と同じ扱いにする。事務所の既定値と同じ値の案は「今と同じです」として反映を出さない（印を外すだけの操作を案から作らない）。世帯で事務所の既定値と同じ値を選んでも印を付け直さない（0216 の3）のも同じ。
  - この世帯で並べる時点: 世帯の値をそのまま書く（印は持たない設定）。
  - 入力項目の選び方: 「入力項目を選ぶ」と同じく世帯の入力項目の選び方を置き換える（入力の変更として扱う）。
- 書いた後に承認待ちから外す。反映は元に戻すの履歴に入る（表示の設定は履歴の状態に印ごと入っている。0216 の4）。出す数字を変えたときは、FP顧問料の一文の枠も足す・外す（「事務所の既定値に戻す」と同じ）。

### 6. 前の値に戻す（世帯ファイルの形式は上げない）

- **今ある「元に戻す」と「事務所の既定値に戻す」で足りると判断し、世帯ファイルに前の値を持たない**（形式の版は 0.80 のまま）。
  - 押す前が事務所の既定値だった設定（新しく作った世帯はこれが多い）は、表示の設定の「事務所の既定値に戻す」でいつでも戻せる（印を付け直し、事務所の今の既定値にする。アプリを閉じた後でも戻せる）。
  - 押す前が「この世帯だけ」の値だった設定と、この世帯で並べる時点・入力項目の選び方は、反映した直後から世帯を閉じるまで「元に戻す」で戻せる。閉じた後に戻したくなったときは、表示の設定（・資産と負債のタブの「時点を並べる」・入力項目を選ぶ）で前の値を選び直す。これらはどれも、1つの画面のチェック・選択で選び直せる値で、反映する前の「今」が承認の画面に出ている。
- 事務所の既定値の案で前の値を事務所データに残した（0215 の5）のは、事務所の既定値はどの世帯にも効き、値が複雑なもの（対策の組み合わせ・基本生活費の内訳の並べ方など）を含むため、戻せないと影響が大きいから。世帯ごとの案は1つの世帯の見せ方だけで、選び直しも簡単なので、世帯ファイルの形式を上げて前の版のアプリを閲覧だけにする（0216 の3 と同じ扱い）ほどの価値は無いと判断した。
- 前の値を世帯ファイルに残す形が要るとなったら、`display` の区画に追記だけの欄（設定ごとに直近の数件。事務所データの `displayHistory` と同じ形）を足す（形式の版を上げる）。

## 理由

- 値の確かめを事務所の既定値の案と同じ関数にした: 選べる値・範囲の決まりを2か所に書くとずれる（0213 の5・0215 の理由と同じ）。宛先で変わるのは、案を出せる設定の並びと断る文だけ。
- 世帯ごとの案をメモリの中に置いた: 案はまだ FP が判断していない AI の出力で、世帯の中身ではない。世帯ファイルに書くと、形式を上げることになり、前の版のアプリが書き戻して落とす。書類の候補（0151）と同じく、アプリを開いている間だけ置き、案を出したこと自体は AIに渡した記録に残す。
- 帯で世帯を見せ分けた: 顧客番号と仮名は、お客さまと一緒に見る画面に出さない（0015 の8 の共有中の帯と同じ）。入力の画面では、どの世帯かが分かり、その場で開ける。
- 反映したら印を外した: 案を反映するのは「この世帯をこの値にする」という FP の判断。印を残すと、事務所の既定値を変えたときに、反映した値が黙って変わる。

## 代案（採らなかったもの）

- **対策に足した項目も、仮の ID を元に戻して案にする**: 1 の理由。鍵の形が動かす項目の一覧の作りに結び付き、表示の設定の一覧で確かめられない。
- **世帯ごとの案を世帯ファイルの AI の候補（`candidates`）に入れる**: 形式の版を上げることになり、プランの候補の判断の記録（保存した・捨てた）とも意味が違う。
- **世帯ごとの案を事務所の既定値の画面に並べる**: どの世帯の「今」かが分かりにくく、その世帯を開かずに反映すると、開いている世帯と保存した世帯ファイルの間で書き違えが起こる。その世帯を開いた所（結果のタブ）に出す。
- **反映しても印を残す（事務所の既定値に従うまま値だけ変える）**: 印のある設定は事務所の既定値を読むので、案の値が画面に出ない。
- **世帯ファイルに前の値を残す（形式の版を上げる）**: 6 の理由。
