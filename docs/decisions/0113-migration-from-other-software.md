- 状態: 採用（一部未確定）（2026-11-03）

- 前提にする記録: 0001 の5（公開の約束の表）、0003 の7（計算方式の設定 `compatibility`）、0004 の6・7（科目の木・参照値）、0008 の2・5・8（値の箱・候補・移行したプランの前提）、0011 の2・4（取り込みの記録・拡張領域）、0012 の2〜4（持たない情報・伏せ字）、0015 の2・7（移行の見出しの道具・承認制）、0016 の3・4・6（カスタム層・宣言型・承認）、0018 の6（取り込みの画面）、0019（SDK・スキル `build-term-dictionary`）、0020（書き出し）、0021 の1・3（ライセンス・リポジトリ）、0034（明細の取り込みの読み手と伏せ字）、0041（値の状態・書類で確かめる）

## 背景

- FP の多くは、今までライフプランの別のソフトで作ったプランを持っている。お客さまごとに入れ直すのは手間が大きく、前のプランの数字との違いを説明できないと、乗り換えたお客さまとの話が止まる。
- 前提の記録が、この記録を前提にしていた。0001 の公開の約束の表に「移行の読み取り規則・用語辞書の書き方（試験版）」があり、0003 の7 の `compatibility`（互換モード）は「変えられる項目の一覧は移行の記録で決める」として `null` に固定したままになっている。0004 は移行元の科目との対応を「読み取り規則・用語辞書の側に持つ」とし、0011 は取り込みの記録の中身、0012 は伏せ字、0015 は AI に見出しだけを渡す道具、0019 は用語辞書を作るスキル、0021 は公式の読み取り規則の置き場所を決めていた。ばらばらに書かれていた約束を、この記録で1つの形にする。
- リポジトリの中の今の実装（2026-11-03）:
  - 移行の読み取りの部品は無い。エンジンの入力の `calcConventions.compatibility` は `null` だけを受け付け（`engine/schemas/engine.input.json`）、画面の側はいつも `null` を書く（`app/src/workspace/input/household.ts`）。
  - 使い回せる部品はある: 文字の入った PDF・CSV の読み手と番号を消す処理（`statement/src/pdf/`・`statement/src/csv/`・`maskCell`。0034 の2・3）、.xlsx を信用せずに読む土台（`xlsx/src/read.ts`）、記入済みのシートを候補にして承認する流れ（`hearing/src/import.ts`・`approveAll`。0018 の6）、カスタム層の検査・承認の台帳（`crates/custom-layer`。0016 の追記）。
  - 入力のホームの「取り込む」には、ヒアリングシートと「AI に資料を渡す」（前の帳票・面談のメモなどを FP の AI に渡し、AI が読んだ値を候補として受ける。0072）がある。外部AIへの同意がある世帯だけで使え、値が FP の AI の会社へ渡る。
- 他のソフトの帳票は、ソフトごと・版ごとに見出しも並びも違い、年齢の数え方・最初の年の扱い・上昇率を掛け始める年などの「数え方」も違う。数え方の違いは、同じ入力でも表の数字を変えるので、照合（差を説明すること）の邪魔になる。
- このリポジトリは公開されている。他社の製品名・帳票の実物・帳票から写した並びを公開側に置くと、他社の帳票の写しや、他社と関係があるかのような見え方になる（0001 の9・0021 の4）。

## 決定

### 1. 読むファイルと、読まないファイル

- 読むのは、移行元のソフトが**人に渡す・書き出すために作ったファイル**だけ: 文字の入った PDF の帳票（提案書・キャッシュフロー表・入力の一覧）、Excel（.xlsx）・CSV の書き出し。
- 読まないもの:
  - 移行元のソフトの保存ファイル・データベースなどの独自の形式（中の形を解き明かして読むことはしない）。
  - 暗号化・パスワード・利用の制限がかかったファイル。保護は外さない（0019 の「やってはいけないこと」の5）。PDF の暗号化は 0034 の3 と同じく読まずに「保護のないファイルで書き出し直してください」と案内する。
  - 文字の無い PDF（画像だけ）・写真・スキャン。この部品では文字を読み取らない。「AI に資料を渡す」（外部AIへの同意がある世帯だけ）か、手で入れるように案内する（明細の段階3 の文字認識を作る回に、同じ部品を使うかを決める。未確定）。
- .xls・.ods などは「.xlsx で保存し直してください」と案内する（0018 の6 と同じ）。

### 2. 外に送らない・最初に伏せ字にする・元のファイルを持たない

- 読む・対応付ける・数えるは、すべて FP の PC の中で行う（0012 の4）。提供元の中継は作らない。AI を使うのは FP が画面で「AI に見出しを渡す」を押したときだけで、渡すのは伏せ字の後の見出しと並びだけ（値は渡さない。0015 の2。下の6）。
- **伏せ字は、読み手が欄の表を返した直後**（規則を当てる前、画面に出す前、何かを保存する前）に、すべての欄に1回かける。消すもの:
  - 番号: 0034 の2 の A〜D（カード番号・口座番号・番号の見出しの後の数字・7桁以上の数字）をそのまま使う（`maskCell` を通す）。証券番号・顧客番号・基礎年金番号などの見出しも B の見出しの一覧に足す。
  - 連絡先: 電話番号・メールアドレス・郵便番号（`〒` と7桁）・住所らしい文字（都道府県名か市区町村名で始まり番地の数字が続く欄）は「（住所）」「（連絡先）」に置き換える。
  - 氏名: 取り込みの最初に FP が入れた家族の名前（メモリの上だけで使い、保存しない。0012 の2）は「本人」「配偶者」「第1子」などの続柄に、それ以外の敬称（様・さん・殿・氏）の前の語は「（氏名）」に置き換える。規則が氏名・住所の欄と宣言した所（下の4 の `drop`）は欄ごと消す。勤め先の名前も持たない（0012 の3）。
  - 生年月日は、読んだ時点で生年月と1日生まれかに直し、日を捨てる（0012 の3）。
- 伏せ字の規則は1か所に置き（部品の中の関数1つ）、どの読み手・どの規則にも同じものを当てる。規則や辞書から伏せ字を弱めることはできない（強めること＝`drop` を足すことだけできる）。
- **元のファイルは保存しない**。残すのは指紋（SHA-256）と大きさ、読み手の id と版、伏せ字の後の抽出結果だけ（0011 の2・0034 の2 と同じ）。ファイル名も持たない（名前が入りうるため）。同じ指紋のファイルを同じ世帯に2回取り込もうとしたら知らせる（止めはしない。移行元で直して出し直した帳票と見分けられないため）。

### 3. 3段の作り

```
ファイル ──読み手──▶ 欄の表（ページ・行・欄。伏せ字の後）
         ──読み取り規則──▶ 区画ごとの「見出し＋値」（どこに何があるか）
         ──用語辞書──▶ 対応先（入力項目・表の行・移行メモ・読まない）と単位
         ──▶ 候補（出どころ「移行」）＋参照値＋移行メモ ──FP の確かめと承認──▶ 世帯
```

- **読み手**は 0034 の3 の `StatementReader` と同じ形（`{id, version, accepts, table}`）で、`pdfText`・`xlsx`・`csv` の3つから始める。中身は明細の読み手と `xlsx/` の土台を使い回す（新しい依存を足さない）。
- **読み取り規則**は「どこに何があるか」（区画の見つけ方と区画の形）だけを書き、**用語辞書**は「その見出しが何か」（対応先と単位）だけを書く。分けるのは、同じソフトの版違いで並びが変わっても辞書をそのまま使えるようにするため、また AI に頼むのは辞書だけ（見出しの意味の対応付け）にするため（0015 の2）。
- 規則と辞書は**宣言型の JSON だけ**で、プログラム・正規表現・式を持たない（0016 の4）。言葉の一致は 完全一致・前方一致・含む の3つ（0034 の4 の辞書と同じ強さの順）。見出しの言葉はそろえてから比べる（NFKC・空白と区切りの記号を取る・全角半角をそろえる。0034 の3 と同じ関数）。
- 部品はリポジトリ直下の `migration/`（npm の依存なしの TypeScript。画面からも読む。`statement/`・`hearing/` と同じ作り）。`migration/src/` は外への通信も Node の組み込みも使わない（lint で止める）。ファイルを開くダイアログ・大きさの確かめ・事務所データの保存は本体（Rust）が受け持つ。

### 4. 読み取り規則の形（`migration-rule@1.0`。試験版）

```json
{
  "format": "lifeplan.migrationRule",
  "contract": "migration-rule@1.0",
  "id": "official.genericReport",
  "revision": 1,
  "label": "汎用の読み取り（よくある見出しから）",
  "reads": { "product": null, "document": "ライフプランの帳票", "editions": [], "readers": ["pdfText", "xlsx", "csv"] },
  "detect": { "allWords": [], "anyWords": ["キャッシュフロー表", "年間収支", "貯蓄残高"], "minHits": 2 },
  "units": { "money": "万円" },
  "conventions": { "tableAge": "yearEnd", "tableBalance": "yearEnd", "valueBasis": "nominal" },
  "dictionaries": ["official.fpTerms"],
  "blocks": [
    { "id": "family", "kind": "pairs", "anchor": { "words": ["家族構成", "家族"] }, "repeat": "member" },
    { "id": "assumptions", "kind": "pairs", "anchor": { "words": ["前提条件"] } },
    { "id": "loans", "kind": "table", "anchor": { "words": ["ローン"] }, "object": "debt" },
    { "id": "cf", "kind": "yearTable", "anchor": { "words": ["キャッシュフロー表"] }, "yearHeader": { "words": ["西暦", "年"] } },
    { "id": "owner", "kind": "drop", "anchor": { "words": ["お客様名", "ご住所"] } }
  ]
}
```

- `id`: `<作成者>.<名前>`（0004 の命名の決まり。各段は英小文字で始まる英数字）。作成者 `official` は公式だけが使う（予約。0011 の4 と同じ）。**ID・ファイル名には他社の名前・製品名・商標を入れない**（下の11）。製品ごとの公式の規則は製品の名前を入れない通し番号（`official.source001` の形）にする。公開した ID は使い回さない。
- `revision`: 規則の改訂の整数。中身を変えたら上げる。取り込みの記録に `id@revision` で残す（0007・0009 の指し方と同じ）。
- `reads`: 何を読む規則か。`product` は移行元の製品名（文字のまま。画面の「読み取り対応」の表記と商標の注記にだけ使う。下の11）。汎用の規則は `null`。`document` は帳票の種類の言葉、`editions` は確かめた版の言葉、`readers` は使える読み手。
- `detect`: その規則で読めるかの判定。`allWords` はすべて、`anyWords` は `minHits` 個以上が、見出しの言葉として表のどこかにあれば当てはまる。当てはまった言葉の数で点を付け、いちばん点の高い規則を初めに選ぶ（FP が選び直せる）。どれも当てはまらなければ汎用の規則。
- `units`: 区画で単位が書いていないときの単位（`money`: `円`・`千円`・`万円`）。欄の中に単位があれば（「123万円」「1.5%」）そちらが先。
- `conventions`: 移行元の数え方（下の8 の項目の名前と値、と `aggregation`・`investmentTiming`〔0003 の7〕・`valueBasis`〔表が名目か現在価値か〕）。照合の見せ方と、照合用のプランの互換モードの初めの値にだけ使う。書いていない項目は「分からない」で、照合の画面で FP が選べる。
- `blocks`: 区画の一覧。区画の種類は閉じた一覧で、足すだけにする（足すのは MINOR）:

| 種類 | 形 | 使い道 |
|---|---|---|
| `pairs` | 「見出し：値」の組が並ぶ所 | 家族・収入・前提条件・住まい。`repeat: "member"` は人ごとに繰り返す（続柄の見出しで人を分ける） |
| `table` | 1行が1つの物で、列に見出しがある表 | ローン・保険・口座の一覧。`object` は物の種類（`debt`・`insurance`・`account` など。0008） |
| `yearTable` | 年が列（または行）に並ぶ表 | キャッシュフロー表・残高の推移。値は**参照値**にだけなる（0004 の7）。年は西暦・和暦を読む。年齢の行は人の生年の確かめに使い、値にしない |
| `drop` | 読まない所 | 氏名・住所・担当者の欄。伏せ字をかけた上で、欄ごと捨てる |

- 区画の見つけ方 `anchor` は見出しの言葉だけ（ページ番号 `page` で絞ることはできる）。位置の座標では書かない（版が変わって行がずれても読めるように。0018 の理由と同じ考え方）。区画の終わりは、次の区画の見出しか、空の行が2つ続く所か、ページの終わり。
- 規則は1つの帳票に1つ当てる。1つのファイルに複数の帳票（現状と提案など）があるときは、最初の版では FP が選んだ1つのプランの分だけを読む（未確定）。

### 5. 用語辞書の形（`term-dictionary@1.0`。試験版）

```json
{
  "format": "lifeplan.termDictionary",
  "contract": "term-dictionary@1.0",
  "id": "official.fpTerms",
  "revision": 1,
  "label": "よく使われる見出しの言葉",
  "roles": [
    { "words": ["本人", "ご本人", "世帯主"], "role": "self" },
    { "words": ["配偶者"], "role": "spouse" },
    { "words": ["第1子", "長男", "長女"], "role": "child", "order": 1 }
  ],
  "entries": [
    { "words": ["給与（賞与を除く）"], "match": "prefix", "to": { "item": "employment.salary.annual" }, "value": { "unit": "money", "period": "annual" } },
    { "words": ["基本生活費"], "to": { "item": "livingExpense.monthly" }, "value": { "unit": "money", "period": "annual" } },
    { "words": ["物価上昇率"], "to": { "item": "assumptions.inflation" }, "value": { "unit": "percent" } },
    { "words": ["年間収支"], "to": { "row": "cf.net" } },
    { "words": ["貯蓄残高", "金融資産残高"], "to": { "row": "cf.balance.financial" } },
    { "words": ["備考", "メモ"], "to": { "memo": true } },
    { "words": ["勤務先"], "to": { "drop": true } }
  ]
}
```

- 対応先の ID は登録簿（`registry/items.yaml`・`registry/rows.yaml`。0004）の ID だけを使う（登録簿に無い ID・`deprecated` の ID を書いた辞書は検査で断る）。上の例の言葉は形を示すためのもの。移行元の1つの値がファイナンシアの2つの欄にまたがるもの（賞与を含む年収など）は、1つの欄に寄せて書かず、移行メモにして FP に分けてもらう（分け方を辞書に書けるようにするかは未確定）。
- `id`・`revision` の付け方は規則と同じ。
- **対応先 `to` は5種類のどれか1つ**:

| 対応先 | 意味 | 世帯での行き先 |
|---|---|---|
| `{item, member?, object?}` | 入力項目（入力項目ID。0004）。`member` は続柄（`roles` の `role`）、`object` は `table` の区画の物 | 候補（下の7） |
| `{row}` | キャッシュフロー表の行（行ID。0004 の6） | 参照値（取り込みの記録だけ。計算に入らない） |
| `{item: "assumptions.<名前>"}` | 前提条件（入力項目の一種） | 移行したプランの前提条件の候補（0008 の8） |
| `{memo: true}` | 対応先の無い項目として残す | 移行メモ（伏せ字の後の見出しと値の文字） |
| `{drop: true}` | 読まない | 何も残さない |

- `value`: 値の読み方。`unit` は `money`（区画の `units.money` か欄の中の単位で円にする）・`yen`・`percent`（`"0.015"` の10進の文字にする。0002）・`years`・`months`・`age`・`yearMonth`（和暦・西暦・`年月`）・`count`・`choice`（`choices: {"言葉": "値"}` で選択肢に写す）・`text`（移行メモにだけ使える）。`period` は `annual`・`monthly` で、入力項目の持ち方（登録簿の単位）と違えば、決まった1つの関数で直す（月額 ×12、年額 ÷12 は 0002 の丸め `conv.migration.period`）。符号（`△`・`▲`・`-`）・カンマ・括弧の読み方は明細の金額の読み方（0034 の3）と同じ。
- 1つの見出しに当てはまる行が辞書に2つ以上あるときの強さは、完全一致＞前方一致＞含む、同じなら長い言葉、同じなら辞書の並びで先の行（0034 の4 と同じ）。
- 移行元の科目と科目の木の対応は辞書にだけ持ち、科目の木（0004 の6）には入れない。

### 6. 公式の規則と FP が足す規則（置き場所と引く順）

| 層 | 置き場所 | 中身 | 効き方 |
|---|---|---|---|
| (a) 公式・汎用 | 公開側 `migration/rules/official.*.json`・`migration/dictionaries/official.*.json`（CC0。0021 の1） | 汎用の規則 `official.genericReport` と、製品によらない見出しの言葉の辞書 `official.fpTerms` | アプリに同梱。いつでも使える |
| (b) 公式・製品ごと | 非公開のリポジトリ（0021 の3）。公式版のビルドのときだけ同梱する | 特定の製品の帳票の規則と辞書（`reads.product` を持つ） | 署名のある公式版だけで使える。公開側だけでビルドしたアプリには無い（公開側だけでビルドとテストが通る。0021 の3 の依存の向き） |
| (c) 事務所の規則 | カスタム層の `settings/migration/rules/<id>.json`・`settings/migration/dictionaries/<id>.json`（0016 の3） | FP（と FP の AI）が書いた規則と辞書。作成者は `official` 以外 | カスタム層の検査・指紋・承認の台帳（0016 の6・2026-11-02 の追記の種類 `migrationRule`・`termDictionary`）を通し、承認するまで効かない |
| (d) 覚えた対応 | 事務所データ（暗号化。0011 の6。欄 `migration`） | 確かめの画面で FP が直した「見出しの言葉 → 対応先」（規則の `id` ごと。金額・日付・お客さまの情報は持たない） | 次の取り込みから効く。上限は事務所全体で1万行（古い行から外す） |

- **対応先を引く順**: この取り込みで FP が決めた対応 → (d) 覚えた対応（同じ規則の id、完全一致）→ 規則が `dictionaries` に挙げた辞書（挙げた順。事務所の辞書を公式の辞書より前に挙げられる）→ (a) の `official.fpTerms` → 分からない（確かめの画面で「要確認」にする。黙って移行メモにしない）。
- 公式の規則・辞書（(a)・(b)）はアプリの更新で届く（配信の更新 0017 で規則だけを配るかは未確定）。新しい改訂が来ても、取り込み済みの世帯は変わらない（取り込みの記録に `id@revision` が残る）。
- (d) は同じ答えを公式の辞書が返すときは覚えない（太らせない。0034 の4 と同じ）。事務所で共有しているときに (d) を共有するかは未確定（0034 の5 の明細の辞書と同じ形にするかを、事務所の共有の使われ方を見て決める）。
- FP の AI が見出しの対応付けを手伝うとき（0015 の2 の `get_import_headings`・`propose_term_dictionary`）は、AI が返す辞書も `term-dictionary@1.0` の形で、確かめの画面に**候補の対応**として出るだけ。FP が確かめた分だけがこの取り込みに効き、「覚える」を押した分が (d) に入る。AI に見出しを渡したことは取り込みの記録に残す（0015 の7）。

### 7. 読み取った値の値の状態と出どころ

- **出どころ**はいつも `import`（移行。0008 の2）で、`ref` は取り込みの記録（下の10）の ID。候補（0008 の5）は `source: "import"`・`sourceRef` を持ち、FP が承認するまで現状にもプランにも効かない。承認した値は `approval: {by: "fp", at, candidate}` を持つ（承認できるのは FP だけ）。
- **値の状態**は、次の順で決める（確かめの画面で FP が変えられる）:

| 読んだもの | 値の状態 |
|---|---|
| 辞書の対応先が入力項目で、値を読めた | `confirmed`（確定） |
| 時点で変わる値（預金・ローンの残高、年金の加入月数、住民税の年税額など。登録簿で「時点のある値」と印を付けた入力項目）で、移行元のプランの基準の年月が新しい計算基準月と違う | 書類で確かめる欄（0041 の 2026-10-31 の追記の2 の `docCheck`）なら `unknown`（書類待ち）で、代わりの値 `substitute` に読んだ値（`estimated`・推定の出し方 `migrated`・根拠「移行元のプラン（2024年4月時点）の値」）。書類で確かめる欄でなければ `estimated`（推定の出し方 `migrated`、根拠は同じ） |
| 移行元の年齢だけがあり生年月が無い | 生年月を `estimated`（推定の出し方 `migrated`、根拠「移行元の帳票の年齢（○歳・○年○月時点）から」）。帳票の年齢がどの時点の年齢か（規則の `conventions.tableAge`。分からなければその年の12月31日）から生まれ年を決め、月はその年の7月（1日生まれでない）とする（ずれを半年までにし、子の学年は4月2日〜12月生まれの多いほうに入る） |
| 値が読めない・単位が分からない・同じ見出しが2か所で違う値 | 値にしない。確かめの画面で「要確認」 |
| 移行元の表の数字（`yearTable` の区画） | 値にしない。参照値（下の9 の照合・10 の `referenceValues`） |

- 推定の出し方 `migrated` は、推定の入れ直し（0008 の追記）の対象にしない（出どころが `auto` ではないため）。FP が書類で確かめて入れ直すと、出どころ `manual` の確定になる（今の値の箱の決まりのまま）。
- 移行で値が入らなかった欄は、入力の画面と同じ推定（出どころ `auto`）で補う（移行は推定を止めない）。書類待ちになった欄は、確かめの一覧（0041）と書類のお願い（0102）にそのまま載る。
- 値の確かさ `certainty`（0035 の3）は付けない（移行元で FP が何から入れたか分からないため）。FP が確かめの画面で付けられる。
- **参照値を入力にしない**（0004 の7）。移行元の表の数字を入力として使いたいときは、FP の操作で候補に変え、出どころ「移行」として承認する（0004 の7 のまま）。

### 8. 互換モード（`calcConventions.compatibility`。0003 の7）

- **互換モードは照合のための寄せ**で、移行元の計算を再現するものではない。変えられるのは、同じ入力を「いつ・どう数えるか」の数え方だけで、制度の計算・税・社会保険・制度の値の引き方（`basis`・`ageSwitch`。0003 の4・9）は変えない。
- 形（`null` か、次の物）:

```json
{
  "source": { "import": "<取り込みの記録のID>", "rule": "official.source001@3" },
  "items": { "tableAge": "yearStart", "firstYear": "wholeYear", "growthStart": "baseYear" }
}
```

- `items` には今の既定と違う項目だけを書く（1つ以上）。書いていない項目は既定。**項目は閉じた一覧**で、足すだけにする（項目や値を足すのは MINOR。意味は変えない・消さない）:

| 項目 | 値（先頭が既定＝ファイナンシアの数え方） | 何が変わるか | 計算か表示か |
|---|---|---|---|
| `tableAge` 表の年齢 | `yearEnd`（その年の12月31日の満年齢。0003 の1）・`yearStart`（その年の1月1日の満年齢） | 表・グラフ・帳票に出す年齢 | 表示だけ |
| `tableBalance` 表の残高の時点 | `yearEnd`（年末の残高。0003 の1）・`yearStart`（年の初めの残高＝前の年の年末） | 表の残高の行を1年ずらして見せる | 表示だけ |
| `ageTiming` 年齢で決めた時点の解き方 | `month`（年齢に達する月。0003 の4・6）・`yearOfReach`（その年齢に達する年の1月）・`yearAfterReach`（達した年の翌年の1月） | FP が年齢で入れた時点（退職・年金の受け取り開始・働き方の期間の年齢の端など。0038）と、そこから決まる出来事。**制度の年齢の切り替え（`ageSwitch`）は変えない** | 計算 |
| `firstYear` 最初の年 | `fromBaseMonth`（計算基準月から。0003 の5）・`wholeYear`（計算基準年の1月から1年分。残高はその年の1月の初めの値とみなす） | 最初の年の収支と運用益の月数 | 計算 |
| `growthStart` 上昇率を掛け始める年 | `nextYear`（計算基準年は入れた額のまま、翌年から掛ける。今の上昇率の道具 `grownByYear`）・`baseYear`（計算基準年から1年分掛ける） | 物価上昇率・教育費の上昇率・行ごとの上昇率で増やす額 | 計算 |

- 計算の項目は、エンジンの中の決まった1か所（時点を年月に解く所・計算基準月を決める所・上昇率の道具）でだけ読む。計算部品が互換モードを見て自分で分かれることはしない（0003 の「部品は年齢から月を自分で計算しない」と同じ考え方。部品が `compatibility` を読まないことを lint とテストで確かめる）。`source` は計算に使わず、根拠の記録（0006）に写す。
- **使えるプラン**: 互換モードを持てるのは、その世帯の移行の取り込みの記録（`source.import`）から作った照合用のプランだけ（新しく作ったプランは `null` のまま。0003 の7）。取り込みで作るプランは互換モードを使わない（既定はファイナンシアの数え方）。照合の画面（下の9）で FP が「移行元の数え方に寄せて比べる」を押すと、そのプランの複製を互換モードつきで作る（名前の初めは「照合用（移行元の数え方）」）。`source.import` の指す記録が世帯に無い `compatibility` は、本体が読むときに `null` に直し、知らせを出す。
- 互換モードを外す（`null` にする）のは前提条件の変更で、提案の差分の一種として記録する（0003 の7）。外した後にもう一度つけるのは、照合の画面からだけ。
- 互換モードのプランは、プランの名前の帯と結果の画面に「移行元の数え方（照合用）」の印を出し、提案書などの PDF にはアプリが帳票の外側で「移行元の数え方に寄せた照合用の計算です」と刻印する（0009 の刻印と同じ所。帳票の作り変えで消せない）。
- **β公開までに計算の中身を作る項目は、照合で差の大きいものから選ぶ**（下の「実装の段取り」）。形と項目の名前・値はこの記録で固定し、作っていない項目の値は画面に出さず、エンジンは断る（`E_ARGUMENT`）。運用益の丸めを寄せる項目（0003 の未確定）は、照合で要ると分かったときに足す。

### 9. 確かめの画面の流れ

入口は入力のホームの「取り込む ▾」の「他のソフトから移す」と、世帯の一覧の「新しい世帯」の横の「他のソフトのファイルから作る」（新しい世帯を作ってから同じ画面を開く）。ヒアリングシートの取り込み（0018 の6。決まった手順で読む）とは同じ入口に並べ、中身の画面は分ける。プランの編集中は、ほかの取り込みと同じく「現状に切り替える」を出す（0043 の追記）。

1. **ファイルを選ぶ**: 本体のダイアログで選ぶ。大きさ・ページ数の上限は明細と同じ値から始める（0034 の3。10MB・200ページ）。読めない理由（暗号化・画像だけ・形式）はここで分かる言葉で止める。
2. **家族の名前（任意）**: 伏せ字のために家族の名前を入れる欄を出す（「保存しません。この画面を閉じると消えます」）。入れなくても、敬称と規則の `drop` で伏せ字にする。
3. **読み取りの対応**: 選ばれた規則を「読み取り対応: ○○の△△（確かめた版: …）」の形で出し（下の11）、選び直せる。当てはまる規則が無ければ汎用の規則で読み、「AI に見出しを渡す」（外部AIへの同意がある世帯だけ・アプリの AI接続口がオンのときだけ）を出す。
4. **対応の確かめ**: 区画ごとの表で、見出し（伏せ字の後）・読んだ値・対応先（入力の欄の名前／表の行／移行メモ／読まない）・値の状態（確定・推定・書類待ち）・どこから決まったか（規則・覚えた対応・AI の候補・FP）を並べる。「要確認」の行は FP が対応先を選ぶか「読まない」を選ぶまで承認できない。直した行に「この対応を覚える」（6 の (d)）。伏せ字にした所の数と、伏せ字の後の元の表も見られる。
5. **家族と人の割り当て**: 読んだ人を続柄で並べ、誰を本人にするかを FP が選ぶ（続柄の言葉はソフトによって本人の取り方が違うため）。
6. **前提条件**: 移行元の前提（物価上昇率・利回り・賃金上昇率など）を、取り込みで作るプラン（名前「移行元の前提」）の前提条件の候補として並べる。世帯がもうプランを持っていれば、新しいプランとして足す（今のプランの前提は変えない）。
7. **承認**: 「承認して取り込む」で、候補をまとめて承認し（承認の記録は1件ずつ付く）、取り込みの記録を残す。承認しない候補は記録に残さない。
8. **照合**（承認の後、いつでも取り込みの記録から開ける）: 参照値のある行ごとに、年ごとの「移行元」「ファイナンシア」「差」を移行元の単位（万円なら万円に丸めて）・名目か現在価値か（規則の `valueBasis`。0003 の8 の見せ方）で並べ、差の大きい行・年に印を付ける。差の説明の手がかりとして、数え方の違い（規則の `conventions` と今のプランの違い）、移行元の基準の年月と制度データの版の違い、対応先の無かった項目（移行メモの数）を出す。ここに「移行元の数え方に寄せて比べる」（8）を置く。

- 画面の文言・並び・閾値は内部（理由を残せば変えてよい）。

### 10. 世帯ファイルに持つ形（本文の区画 `migrations`）

0011 の2 の「取り込みの記録（移行）」の中身を、明細の区画 `statements`（0034 の6）と同じく、移行の区画に置く（任意。移行したことの無い世帯は区画ごと無い）。

```json
{
  "version": 1,
  "imports": [{
    "id": "<取り込みの記録>",
    "kind": "migration",
    "at": "2027-03-02T10:15:00+09:00",
    "approvedBy": "fp",
    "file": { "sha256": "sha256:…", "bytes": 123456 },
    "reader": { "id": "pdfText", "version": 1 },
    "rule": { "id": "official.source001", "revision": 3, "contract": "migration-rule@1.0" },
    "dictionaries": [{ "id": "official.fpTerms", "revision": 1 }],
    "source": { "product": "（規則の reads.product の写し）", "document": "（帳票の種類）", "edition": "（読んだ版の言葉）", "planBaseMonth": "2024-04" },
    "extracted": [{ "block": "family", "label": "（伏せ字の後の見出し）", "text": "（伏せ字の後の値の文字）", "to": { "item": "…", "member": "self" }, "decidedBy": "rule" }],
    "referenceValues": [{ "row": "cf.net", "year": 2035, "amount": 1830000, "label": "年間収支", "basisMonth": "2024-04", "precision": 10000 }],
    "memo": [{ "label": "（伏せ字の後の見出し）", "text": "（伏せ字の後の値の文字）" }],
    "conventions": { "tableAge": "yearStart", "firstYear": "wholeYear" },
    "candidates": ["<候補>"],
    "ai": { "headings": false }
  }]
}
```

- `extracted` は伏せ字の後の抽出結果（`decidedBy` は `rule`・`learned`・`ai`・`fp`）、`referenceValues` は参照値（0004 の7 の形に、移行元の数字の単位を表す `precision`〔円で 1・1000・10000〕を足した）、`memo` は移行メモ（対応先の無い項目）、`conventions` は移行元の数え方（規則が言ったものに、照合の画面で FP が直したものを重ねた）、`ai.headings` は AI に見出しを渡したか。
- **持たないもの**: 元のファイル、ファイル名、伏せ字の前の文字、家族の名前、移行元のソフトの計算の式。
- **渡さないもの**: AI接続口の縮約版（0015 の6。縮約版は計算の要求からだけ作るので入らない）、持ち帰り用のレポート（0030）。不具合報告の匿名化した書き出し（0020 の4）では区画ごと外す（0020 の「外すもの」の取り込みの記録・移行メモ）。全データの書き出し（0020）には入る。
- 世帯ファイルの形式は、この区画・互換モードの形（8）・推定の出し方 `migrated`（7）を足す回に MINOR で上げる（どれも足すだけ。0011 の5）。

### 11. 他社名の表記

- **機能の名前・ファイナンシアの製品の名前・画面のボタン・ID・ファイル名に他社の名前・製品名を入れない**。機能の名前は「他のソフトから移す」、互換モードは「移行元の数え方」と呼び、「○○互換」「○○モード」とは呼ばない。
- 他社の製品名が画面に出るのは、規則の `reads.product` から作る**「読み取り対応: ○○の△△」**（例の形: 「読み取り対応: ○○の PDF レポート（確かめた版: …）」）の表記と、取り込みの記録の `source` を見せる所だけ。文字だけで出し、ロゴ・似せた色や書体は使わない。
- **商標の注記**: 読み取り対応を出す画面（取り込みの画面と、ライセンスの画面の「読み取り対応の表記について」）に次の文を出す: 「記載の製品名は、各社の商標または登録商標です。ファイナンシアは、それらの製品の提供元と関係がなく、提供元の承認を受けたものではありません。読み取りは、FP がお持ちの帳票のファイルを、この PC の中で読むだけです。読み取りの結果は、移行元のソフトの計算を再現するものではありません。」（文言は内部）
- 公開側のリポジトリ（コード・設計記録・SDK の説明書と見本・テストの見本）には他社の名前・製品名を書かない。製品名を持つ規則（6 の (b)）は非公開のリポジトリにだけ置く。CI で、公開側の `migration/rules/` の規則の `reads.product` が `null` であることを確かめる。
- 提案書・持ち帰り用のレポートなど、お客さまに渡す物には移行元の製品名を出さない（照合の画面は FP 向けだけ）。

### 12. サンプルとテスト

- **他のソフトの帳票の実物・そこから作った見本・期待値は公開側に置かない**（0021 の3・4）。非公開のリポジトリに置き、それを使うテスト（製品ごとの規則で読めること・照合の差）は非公開のリポジトリの CI でだけ流す。結果の数値も公開側に写さない。
- 公開側のテストの見本は、すべて架空の帳票を道具（`migration/scripts/fixtures.ts`）で作る。見本の並び・見出しは汎用の言葉で組み、特定の製品の帳票に似せない。
- テストで確かめること: 伏せ字（番号・連絡先・住所・敬称の前の語・FP が入れた家族の名前・`drop` の区画）が規則を当てる前に消え、取り込みの記録・画面の値・AI に渡す見出しのどこにも残らないこと／規則と辞書の JSON Schema の検査（知らない欄・登録簿に無い ID・プログラムらしき値を断る）／過去の版の書き方（`migration-rule@1.0` から）の見本がいつまでも読めること／参照値がエンジンの入力に入らないこと（0004）／候補が承認まで現状に効かないこと／7 の値の状態の決まり（時点のある値・書類で確かめる欄・年齢から生年月）／互換モードの各項目で変わるのが決めた所だけで、`ageSwitch` で決まる制度の切り替えの月が変わらないこと／`compatibility` の `source.import` が無い世帯で `null` に直ること／公開側の規則の `reads.product` が `null` であること。

## 理由

- **人に渡す帳票と書き出しだけを読む**: FP が持っていてよいのは、お客さまに渡した帳票と書き出した表で、保存ファイルの独自の形式を解き明かすのは他社の作りに踏み込む。保護を外さないのも同じ理由（0019）。読める範囲は狭くなるが、移行に要る入力の一覧とキャッシュフロー表は帳票に載っている。
- **伏せ字を最初の1か所に**: 規則・辞書は FP や AI が書き足すので、規則の側に伏せ字を任せると、誰かが必ず消し忘れる。読み手の直後に共通の関数で1回かければ、規則の出来によらず名前と番号が残らない（0034 の2 と同じ考え方）。
- **規則と辞書を分け、宣言型にする**: 版違いで並びが変わるのは規則、言葉の意味は辞書と、変わる理由が違う。AI に頼むのは意味の対応付け（辞書）だけにすれば、渡すのは見出しだけで済む（0015）。プログラムを持たせないのは、カスタム層の画面系と同じく、検査と承認で中身を確かめられるようにするため（0016 の4）。
- **対応先を5種類に閉じる**: 入力にするか、参照値にするか、メモに残すか、捨てるかが、どの規則でも同じ形になり、参照値が入力に紛れ込む経路を作らない（0004 の7）。
- **値の状態を決まった順で**: 移行元の値は、FP が前に入れた値なので確定として扱えるが、残高や加入月数は時間が経つと違う値になる。書類で確かめる欄は書類待ちにしておけば、今ある確かめの一覧と書類のお願いの流れにそのまま乗る（0041・0102）。新しい印を作らず、推定の出し方を1つ足すだけで済む。
- **互換モードを照合用の複製だけに**: 数え方を寄せたプランを提案に使うと、ファイナンシアの数字として説明できない計算がお客さまに渡る。照合用のプランに分け、印と刻印を付けておけば、差の説明に使いながら、提案はファイナンシアの数え方で作れる。
- **項目を数え方だけに絞り、計算の1か所でだけ読む**: 制度の計算まで寄せ始めると、移行元のソフトごとの計算の写しになり、終わりがない。数え方の項目なら、エンジンの中の決まった所だけを変えればよく、部品の作り変え（0016）に影響しない。
- **製品ごとの規則を非公開に**: 公開側に他社の製品名と帳票から写した並びを置くと、他社の帳票の写しや、関係があるかのような見え方になる。公式版に同梱する配り方は、許諾のある学費の数値と同じ（0010 の追記）。汎用の規則と辞書は公開側に置き、フォークや FP が自分の規則を作る見本にする。
- **ID に製品名を入れない**: ID は使い回さず消さない（0004）ので、一度入れると取り消せない。表示の言葉（`reads.product`）は後から直せる。

## 影響

- **後から変えると何が起きるか**: 伏せ字の位置・持たない物を緩めると、取り込みの記録にお客さまの名前や番号が残りうる。対応先の種類や値の状態の決まりを変えると、取り込み済みの世帯と新しく取り込む世帯で同じ帳票の扱いが分かれる。互換モードの項目の意味を変えると、照合用のプランの数字が黙って変わる。規則・辞書の書き方を変えると、FP の事務所の規則が読めなくなる（試験版なので、0001 の5 のとおり予告と移行の手順を添え、過去の版の書き方を読み続ける）。
- **守るべき決まり**:
  - 伏せ字は読み手の直後の1か所だけで行い、規則・辞書から弱められないようにする。
  - 参照値をエンジンの入力に入れる経路を作らない（0004）。
  - 計算部品は `compatibility` を読まない。互換モードの項目はエンジンの決まった1か所でだけ読む。
  - 公開側に他社の名前・製品名・帳票の実物を置かない。
  - 規則・辞書の公開した ID と改訂を使い回さない。
- **0021 の3 の表との関係**: 0021 の3 の公開用のリポジトリの中身の「公式の読み取り規則」は、汎用の規則と辞書（6 の (a)）のこと。製品ごとの公式の規則（6 の (b)）は「他のソフトの帳票との対応に関する資料」と同じく非公開のリポジトリに置く（0021 の追記）。
- 0001 の5 の表の「移行の読み取り規則・用語辞書の書き方（試験版）」は、`migration-rule@1.0` と `term-dictionary@1.0` のこと。安定に上げるときは、ほかの試験版の約束と同じく記録を書く（0001 の5）。

## 未確定

- **製品ごとの公式の規則をどれから作るか・版をどう追うか**: 非公開のサンプルがそろった順に、12月〜1月に作る（どの製品かは公開側に書かない）。移行元の新しい版が出たときに規則の改訂をどの頻度で出すかは、最初の規則で読めなくなった例を見て決める。
- **互換モードの各項目の計算をβ公開までに作るか**: 非公開のサンプルで照合を作る12月〜1月に、項目ごとの差の大きさを見て決める。運用益の丸めを寄せる項目を足すか（0003 の未確定）も同じ照合で決める。
- **照合の差の印の閾値と、差の説明の文**: 照合の画面を作る回に、非公開のサンプルの差の出方を見て決める（内部）。
- **1つのファイルに複数のプラン（現状と提案など）があるとき**: 最初の版は FP が選んだ1つだけ。βで複数のプランを移したい声があれば、提案の差分（0008 の5）として移す形を考える。
- **1つの値が2つの欄にまたがるとき**（賞与を含む年収、住居費に含まれる管理費など）: 最初の版は移行メモにして FP に分けてもらう。辞書に分け方（割合・既定の月数）を書けるようにするかは、製品ごとの規則を作る12月〜1月に、どれだけ出てくるかを見て決める。
- **住所・氏名らしい語の検出の細かい規則**: 0012 の未確定（氏名らしい語・禁止語の検出規則）と同じ回に、架空の帳票で誤検出の度合いを見て決める。
- **覚えた対応を事務所で共有するか**: 事務所の共有（0023）の使われ方を見て、β公開の後に決める。共有するなら明細の辞書（0034 の5）と同じ形にする。
- **規則だけを配信の更新（0017）で配るか**: β の間はアプリの更新で届ける。規則の直しの頻度を見て、正式公開までに決める。
- **AI 接続口の移行の見出しの道具の入出力**（`get_import_headings`・`propose_term_dictionary`）: 0015 の道具の最終の一覧と一緒に、正式公開までに決める（それまでは「AI に資料を渡す」を使う）。
- **文字の無い PDF・写真の読み取り**: 明細の段階3（0034 の1）の文字認識を作る回に、同じ部品を使うかを決める。
- **上限の値**（ファイルの大きさ・ページ・抽出の行数・覚えた対応の行数）: 明細と同じ値から始め、非公開のサンプルの大きさを見て見直す。
