# 0036. プランの差分の型（値を変える・物を足す・物を外す、当て先、読み替え）

- 状態: 採用（一部未確定）（2026-10-26）
- 固定の強さ: β公開から変えない（骨格）。差分の3つの種類と形、当て先（向き先＋入力項目ID＋場所）で当て1つの値に当て先を1通りにすること、欄のキーを保存しないこと、置き換えの組と連鎖、合成の対策を向き先 `lever` で持ち当て先へ寄せる決まり、当てる順番、要確認の決まり（保存するのは読み替えられなかった差分だけ）、古い差分を読み替え表で直し直せないものを捨てずに残すこと、プランの中身をアプリが作ってからエンジンに渡すことは骨格。合成の対策の一覧は足してよい（名前は使い回さない）。画面の見せ方（印の色・文言・一覧の並び）は後から変えてよい

## 背景

- 0008 の5 は、差分と候補の共通の形（`target`・`item`・`op: set | add | remove`）を決めた。作ったのは値を変える `set` だけで、当て方は画面の「動かす項目のキー」（`key`。`field:<欄のキー>`・`lever:retireAge` など）だった（0008 の追記 2026-10-17）。`target`・`item` は記録として持つだけで、当てるときには使っていない。数の欄でない欄（選択・オンオフ・年月・時点・名前）は差分にできない。
- 入力画面でもプランを直せるようにする。全部のカードが現状とプランで同じ画面で、物を足す・外す、選択や年月を変える、形が変わる選択（賃貸⇄持ち家など）を差分にする。万一の前提も、変えたい項目だけプランごとに上書きできるようにする。
- 入力画面の作り直しで欄のキーは変わる。キーで当てたままだと、保存したプランが当たらなくなる。
- 世帯ファイルの形の変更は 0035 の 0.16 → 0.17 の段にまとめる。値の状態の置き場所（値の箱か物の `valueStates`）・並びの要素の ID・読み替え表は 0035。

## 決定

### 1. 差分の3つの種類

| 種類 | `op` | 何をするか |
|---|---|---|
| 値を変える | `set` | 1つの値を変える（数・選択・オンオフ・年月・時点・名前、または入力項目の値の全体） |
| 物を足す | `add` | 物を1件足す（物の集まりの1件か、物の中の並びの要素1件） |
| 物を外す | `remove` | 物を1件外す（同上） |

### 2. 当て先（向き先＋入力項目ID＋場所）

- 差分は `target`（向き先）・`item`（入力項目ID。0004）・`at`（場所）で当てる。

| `target` | 意味 |
|---|---|
| `{"object": ID}` | 世帯の物の集まりの1件（構成員のほか） |
| `{"member": ID}` | 構成員（世帯の外の家族を含む。0035 の4） |
| `{"plan": "assumptions"}` | 前提条件 |
| `{"plan": "input"}` | 要求の入力の値（表の最後の年 `plan.endYear`。計算の基準の月はプランで変えない） |
| `{"plan": "contingency"}` | 万一の前提（画面の側。全プラン共通の前提を、このプランだけ上書きする） |
| `{"collection": 名前}` | 足す先の物の集まり（`add` だけ。名前はエンジンの入力のスキーマの `x-collection`。例 `debt`・`insurance`・`member`・`relation`） |
| `{"lever": 名前}`・`{"lever": 名前, "object": ID}` | 合成の対策（3。`set` だけ） |

- **1つの値の当て先は1通りだけ**（同じ値を2つの当て先で書かない）:
  - 向き先は、その値を含む**いちばん外の物**（物の集まりの1件・構成員）か、前提・要求の入力・万一の前提。物の中の並びの要素（保障・段階など）は向き先にしない。
  - `item` は、その値を含む**いちばん内側の、入力項目ID を持つ欄**の ID。
  - `at` は、その欄の値の中の道（文字の並び）。並びの要素は ID、欄は名前で書く。欄の値そのものなら `[]`。
  - 例:

| 値 | `target` | `item` | `at` |
|---|---|---|---|
| 住宅ローンの借入額 | `{"object": "<ローン>"}` | `debt.principal` | `[]` |
| 金利の段の率 | `{"object": "<ローン>"}` | `debt.rateSchedule` | `["<金利の段>", "rate"]` |
| 生活費の段の割合 | `{"object": "<生活費>"}` | `livingExpense.stages` | `["<段>", "ratio"]` |
| 保障の額 | `{"object": "<保険契約>"}` | `insurance.coverages` | `["<保障>", "amount"]` |
| 購入の価格 | `{"object": "<住まい>"}` | `residence.purchase` | `["price"]` |
| 世帯の外の家族の家計を1つにする期間の印 | `{"member": "<父>"}` | `member.outside` | `["periods", "<期間>", "living"]` |
| 物価上昇率の2030年の例外 | `{"plan": "assumptions"}` | `assumptions.inflation` | `["byYear", "2030"]` |
| 表の最後の年 | `{"plan": "input"}` | `plan.endYear` | `[]` |
| 万一の前提の1つの値 | `{"plan": "contingency"}` | 万一の前提の入力項目ID（0035 の6） | 前提の中の道 |

- ID を持たない並び（0035 の5）の中の値は、入力項目の値の全体を `set` で変える（`at: []`、値は並びの全体）。
- 同じプランの中で、同じ当て先の差分は1件だけ。入力項目の値の全体を変える差分と、その中の値を変える差分を、同じプランに重ねない（全体を変えたら、中の差分はそのプランから外す）。
- 画面の鍵（欄のキー・動かす項目のキー）は差分に保存しない（0035 の9）。画面は、欄の定義が持つ当て先から欄を引く。

### 3. 合成の対策（向き先 `lever`）

- 1つのつまみで、決まった関数で複数の値を動かす対策（働く最後の年齢・年金の受け取り開始・NISA の積立・生活費・資産運用の積立と取り崩し・ローンの金利の段をそろえて動かす・繰上返済で借入を減らす・変動金利の上昇・FP顧問料を入れるか、など）は、向き先 `{"lever": 名前}`（物を持つ対策は `object` も）の `set` で持つ。値はつまみの値（値の箱）。当てるのはアプリの決まった関数で、名前ごとに1つ。名前は使い回さない。
- 合成の対策は、出来事（時点の正本）や当て先の `set`・`add`・`remove` に置き換えられるものから寄せる（例: 働く最後の年齢は、退職の出来事の時点の `set` にする）。寄せたら、読み替え表（0035 の9）に `lever` → 当て先を足し、その回の変換の段で古い差分を直す。β の前に寄せきれなかった対策は、β の後も `lever` のまま読み続ける。
- 新しい対策は、まず当て先の `set`・`add`・`remove` で作れないかを考え、作れないときだけ `lever` を足す（名前と当て方を、この記録の追記に書く）。

### 4. 差分の形

```json
{
  "id": "<差分>",
  "op": "set",
  "target": {"object": "<ローン>"},
  "item": "debt.principal",
  "at": [],
  "value": {"value": 25000000, "state": "confirmed", "origin": {"kind": "manual"}},
  "before": {"value": 30000000, "state": "estimated", "origin": {"kind": "auto"}, "estimate": {"method": "derived", "basis": "物件の価格−頭金"}},
  "pair": null,
  "cause": null,
  "enabled": true,
  "origin": {"kind": "manual"},
  "note": null
}
```

| 欄 | `set` | `add` | `remove` |
|---|---|---|---|
| `target` | 向き先（2） | 物の集まりへは `{"collection": 名前}`、物の中の並びへはいちばん外の物（`{"object"}`・`{"member"}`） | 物の集まりの1件はその物、並びの要素はいちばん外の物 |
| `item` | 入力項目ID | 並びへは、その並びを含むいちばん内側の入力項目ID（2の決まり）、物の集まりへは `null` | 並びの要素は足すときと同じ、物の集まりの1件は `null` |
| `at` | 場所 | 並びへは、入力項目の値から並びまでの道（並びが値そのものなら `[]`。例 住宅資金の援助は `residence.purchase` の `["gifts"]`）、物の集まりへは `[]` | 並びの要素は、足すときの道の後ろに要素の ID（例 `["gifts", "<援助>"]`）、物の集まりの1件は `[]` |
| `value` | 新しい値の値の箱 | 足す物の全体（新しい ID。中の `valueStates` も） | `null` |
| `before` | 作った時点の現状の値の値の箱（現状に無ければ `null`） | `null` | 外した時点の現状の物の全体 |

- `value` はいつも値の箱（0008 の5）。値の箱を持つ欄へは箱をそのまま書く。値の箱を持たない欄へは、箱の値（わからないなら代わりの値、該当なしなら欄を省く）を欄に書き、箱のほかの欄（状態・出どころ・推定・承認・確かさ）を、向き先の物の `valueStates` の行に書く（0035 の3）。
- `pair`（置き換えの組）: 形が変わる選択（住まいの賃貸⇄持ち家・働き方の種類・年金の入れ方・退職給付の一時金⇄年金・保険の入れ方など）は、同じ `pair`（組の ID）を持つ `remove` と `add` の2件で持つ。一覧では1件（「住まい: 賃貸 → 持ち家（購入）」）に見せ、オン／オフ・戻すは組ごとにする（組の `enabled` はそろえる）。
- `cause`（連鎖）: 外したときの連鎖（8）で一緒に外した差分と、関係の終わりで選んだ差分に、きっかけの差分の ID を書く。
- `origin`（差分の出どころ）: `{"kind": "manual"}`（入力画面で直した）・`{"kind": "result"}`（結果のタブの対策・動かす項目で動かした）・`{"kind": "ai", "ref": 候補の ID, "connector": AI のアプリが名乗った名前}`。AI の候補を承認した差分は `approval`（承認した記録）を持つ（今のまま）。動かし直した差分の出どころは、動かした所のものになる（今のまま）。
- `enabled`・`note` は今のまま。
- 0.16 から読み替えた差分は `legacy`（0.16 の `key`・`target`・`item`）を持つ。読み替えられなかった差分は `unresolved: true` を持ち、当てない（5）。

### 5. 古い差分の読み替え（0.16 → 0.17 の変換の段）

- 0.16 の差分 `{id, key, target, item, op: "set", value, before, enabled, origin, approval?, note}` を、`key` から読み替え表（0035 の9）で直す:
  - `field:<欄のキー>` は、当て先の `set` にする。
  - そのほかの動かす項目のキーは、当て先の `set`（借入額・資産の配分など、1つの値を動かすもの）か、`lever` の `set`（合成の対策）にする。
  - `id`・`value`・`before`・`enabled`・`origin`・`approval`・`note` はそのまま。`legacy: {key, target, item}` を足す。値の形が変わる鍵は表の `convert` で直す。
- 直せない差分（表に無い鍵・当て先の物が無い）は**捨てずに**、`op: "set"`・0.16 の `target`・`item`・`at: null`・`unresolved: true`・`legacy` で残す。当てずに、違いの一覧の要確認に「読み替えられなかった差分」として出す（FP が外すか、入力で直す）。開いたときの知らせ `unresolvedDiffs` も書く（0035 の8）。
- プランの ID・名前・土台 `base`・印・作った日時・反映した日時・出どころは変えない。
- 控えの中の差分と、保存していないプランの値（動かす項目のキーで持つ）は変えない。読むときに同じ表で読み替える（0009）。

### 6. 当てる順番と、エンジンへ渡す前の当て方

- プランの中身は、現状に、土台のプランから順に差分を当てた世帯（作業中の世帯）。作業中の世帯はアプリが作り、エンジンには作業中の世帯から作った要求を渡す（エンジンは差分を知らない）。
- 順番:
  1. 土台のいちばん下のプランから順に、プランごとに `remove` → `add` → `set`（`lever` を除く）を当てる。同じ当て先は後のプランが勝つ。
  2. 次に `lever` の `set` を当てる。土台から順に重ね、同じ名前（と物）は後のプランが勝つ。当てる順は今の「欄 → 対策 → FP顧問料」を保つ。
  3. 万一の前提は、全プラン共通の前提の写しに `{"plan": "contingency"}` の差分を当て、そのプランの万一の想定を作る。
  4. 作業中の世帯から要求を作るとき、見込みが「不確か」で `includeInBase` が `true` でない、受け取る相続・遺贈・贈与の行と相続で受け継ぐ借金（と、不動産を受け取る行につないだ物）を要求に入れない（0035 の7）。作業中の世帯からは消さない。差分を当てた後に決めるので、プランでの見込みや `includeInBase` の `set` が効く。現状の計算にも同じ決まりを当てる。
- 当てた作業中の世帯を、エンジンの入力のスキーマで確かめてから要求にする。
- 保存しない自動の差分も、同じ当て方で作る: 「確実な分だけで見る」（4 の決まりとは別の見方。見込みが「不確か」の入るお金のすべてと、優先度が「希望」「夢」の出るお金を外す `remove`）、時期の幅で並べる比べ（時点の `set` を幅の中の年ごとに）。

### 7. 当て先が無くなったとき・要確認

| 場面 | 当てるか | 要確認の言い方（例） |
|---|---|---|
| `set` の向き先の物か場所が、作業中の世帯に無い（現状から消えた・土台のプランで外した） | 当てない | この差分が指していた物が無くなりました |
| `set` の `before` と今の現状の値が違う | 当てる | 入力（現状）が ○ → ○ に変わりました |
| `remove` の物が作業中の世帯に無い | 何もしない | 外す物がもうありません |
| `remove` の `before` と今の現状の物が違う | 外す | 外す物が変わっていました |
| `add` の物の ID が作業中の世帯にもうある（このプランの中身を現状に反映した後など） | 足さない | もう入っています |
| `add` の物が指す物（お金の行の相手・ローンの住まいなど）が無い | 足さない | 足す物の相手がありません |
| 入力項目ID が廃止（意味が変わった欄。0035 の6） | 当てない | 意味の変わった欄です |
| 読み替えられなかった差分（`unresolved`） | 当てない | 読み替えられなかった差分です |

- 要確認は保存しない（開くたび・現状を直すたびに、現状に照らして決める）。保存するのは `unresolved` だけ。
- FP の選び方: 「確認した（このまま）」（`set` は `before` を今の値に、`remove` は `before` を今の物にする）・「この差分を外す」。足す差分は「足す物を直す」も選べる。

### 8. 入力画面でプランを直すときの決まり

- 画面の部品は、現状の編集とプランの編集で同じ（プランの編集でだけ出す欄・隠す欄を作らない）。違いは書く先だけ: 現状を直すときは世帯を直し、プランを直すときはそのプランの差分を直す。プランを直すときの画面は、作業中の世帯を見せる。
- 欄の定義が当て先（向き先の見つけ方・入力項目ID・場所）を持つ。欄を直すと:
  - その当て先の自分の `set` を作る・直す。現状と同じ値に戻し、土台にその当て先の差分が無ければ、自分の差分を消す。土台と同じ値に戻したら、自分の差分を消す。
  - このプランで足した物の中の欄なら、その `add` の `value` を直す（`set` を重ねない）。
- 物を足すと `add`。現状の物を外すと `remove`（`before` に物の全体）。このプランで足した物を外すと、その `add` を消す。現状の物を外したら、その物への自分の `set` は消す。
- 形が変わる選択は、置き換えの組（4 の `pair`）。
- **外したときの連鎖**: 外す物を指す物（持ち家 → その住宅ローンと控除の条件、子 → 進路・援助、世帯の外の家族 → その人を相手にしたお金の行・介護）を並べて確かめ、FP が選んだものを、同じ `cause` の `remove` にする。関係の終わり（離婚など）を `set` したときも、配偶者の名義の物を並べ、「外す（配偶者と一緒に世帯を出る）／残す／分ける（財産分与のお金の行を足す）」を選ばせ、選んでできた差分に `cause` を付ける。指す欄の一覧は、エンジンの入力のスキーマで ID を指す欄から作る（注釈の名前は実装で決める）。
- 推定の入れ直しは、作業中の世帯でも同じ決まり（0035 の3）。入れ直した推定は、出どころ `auto` の値の箱の `set` になる。
- 取り込み・ヒアリング・お客さまが自分でする見直しの聞き取り・明細の承認は、現状への候補にだけ入れる（プランの差分にしない）。
- **現状と違う所の印と戻す**:
  - 欄: 現状と違う欄に印と「現状: ○○」。「↺ 現状に戻す」で自分の差分を消す。
  - 足した物: 「このプランで足した」。外した物: 消さずに薄く見せ、「このプランで外した ↺」。
  - 土台のプランから来た差分: 「土台（プランB）で変更」。戻すと、このプランに現状へ戻す差分を作る（`set` は現状の値の `set`、土台の `add` は同じ物の `remove`、土台の `remove` は同じ物を足し戻す `add`）。
  - 入力のホームのカード: そのカードの違う所の数。
  - 見込みが不確かで基本の計算に入れていない行（6 の4）: 「計算に入れていない」。プランを直しているときは「このプランで計算に入れる」（`includeInBase` の `set`）を選べる。
- **違いの一覧**: 差分1件ずつ（置き換えの組は1件）に「何を・現状 → プラン」・オン／オフ・戻す・要確認・出どころ。要確認を上に、カードごとに並べる。提案書・持ち帰り用のレポートの「変えたこと」に書き出せる。
- カードに読むだけで出す計算の値（推計の年金・退職金の見込みなど）は、プランを直しているときは、そのプランの結果から読む。
- 結果のタブの対策・動かす項目は、入力画面と同じプランの同じ差分を書く（同じ当て先なら1件。どちらで直しても同じ差分が変わる）。動かす項目の一覧は、プランで直せる欄と同じ一覧（選択・年月も）から作る。
- 「このプランを現状に反映する」は今のまま: 作業中の世帯を現状にし、そのプランの差分を消して土台を外す。足した物は ID のまま（中の `valueStates` も）現状に入る。ほかのプランの差分は残り、当て先が無くなった・現状が変わったものは要確認になる。

### 9. AI の候補との関係

- 候補（0008 の5）は差分と同じ形（`op`・`target`・`item`・`at`・`value`）で受ける。行き先は「現状への候補」（資料から読んだ事実）と「プランの案」（AI が考えた打ち手）の2つで、どちらも FP が承認する（AI は承認できない。今のまま）。
- AI接続口の道具の入出力（試験版。0015）に `at` と `add`・`remove` を足すのは、AI の候補を広げる回にする（予告と移行の決まりは 0001 の5）。それまでは今の `set`（`target`・`item`）で受け、当て先が1つに決まらない候補は、今と同じく取り込まない。
- 候補の `item` が別名なら新しい ID へ置き換え、廃止なら要確認にする（0035 の6）。

### 10. 0008・0009 との関係

## 理由

- **当て先で当てる**: 入力項目ID と物の ID は画面の作り直しで変わらない（0004）。欄のキーで当てると、作り直しのたびに保存したプランが外れる。0008 の5 がもともと決めていた形に戻すことにもなる。
- **当て先を1通りにする**: 同じ値を指す差分が2つの形で書けると、「同じ当て先は1件」も「後のプランが勝つ」も成り立たず、違いの一覧に同じ変更が2行出る。
- **欄のキーを保存しない**: 手がかりとして残しても、作り直しで古くなり、読み替え表を増やし続けることになる。
- **足す物の全体を `add` の値に持つ**: 足した物の中の欄を直したときに `set` を重ねずに済み、物の中の値の状態も物といっしょに動く。現状に反映するときは、その物をそのまま入れればよい。
- **外す物の全体を `before` に持つ**: 現状が変わったときに要確認を出せ、戻すときや一覧の「何を外したか」に使える。
- **置き換えの組**: 賃貸⇄持ち家のような選択は、1つの値ではなく物の形が変わる。外す・足すの2件にすれば、物ごとの当て方のまま扱え、一覧では1件に見せられる。
- **合成の対策を別の向き先で残す**: 今の対策のつまみ（働く最後の年齢など）は、複数の値を決まった関数で動かす。β の前にすべてを当て先へ寄せきれなくても、保存したプランを失わずに読み続けられる。
- **プランごとに 外す → 足す → 値を変える**: 外した物に値を当てる、足す前の物に値を当てる、という食い違いを順番で避けられる。土台のプランから順に当てれば、同じ当て先は後のプランが勝つ。
- **要確認を保存しない**: 現状は直されるたびに変わるので、保存すると古くなる。読み替えの失敗だけは、もう一度読み替えても直らないので保存する。
- **プランの中身をアプリが作る**: エンジンは1つの世帯の入力だけを受ける（0006・0008）。差分の当て方を画面の側に置けば、エンジンの入力の形は変わらない。

## 影響

- **画面**: `plans/plans.ts` の差分の型と当て方を、当て先・3つの種類・順番・要確認に作り直す（大きく作り直すのはここ）。動かす項目の一覧（`plans/items.ts`）は当て先で項目を作り、選択・年月の欄も出す。入力画面は、プランを選んでいるとき作業中の世帯を部品に渡し、欄の定義の当て先で差分を書く。違いの一覧・印・戻すを作る。控えの中の古い差分は、読み替え表で読む。
- **本体**: 0.17 の段で古い差分を読み替える（0035 の10）。
- **AI接続口**: 9 のとおり。今の候補の取り込み（当て先と入力項目ID で動かす項目に当てはめる）は、当て先を正にした形に直す。
- **提案書・持ち帰り用のレポート**: 「変えたこと」を差分の一覧から作る。
- **守ること**:
  - 差分に欄のキー・動かす項目のキーを保存しない。
  - 1つの値の当て先は1通り。新しい欄を作るときは、欄の定義に当て先を持たせる。
  - 足した物の中を直すときは `add` を直す。外した物への `set` を残さない。
  - 合成の対策を足すときは、名前を使い回さず、追記に書く。
- **テストで確かめること**:
  - 3つの種類のそれぞれと置き換えの組・連鎖が、当てて現状と同じ形の世帯になり、エンジンの入力のスキーマを通ること。
  - 土台のプランから順に当て、同じ当て先は後のプランが勝つこと。外した物への `set`・足す前の物への `set` が要確認になること。
  - 7 の表の場面ごとに、当てるか・要確認が期待どおりであること。
  - 欄のキーを変えても（欄の定義の当て先が同じなら）、保存したプランが同じ結果になること。
  - 0.16 の見本のプランを 0.17 に読み替えて当てた結果が、0.16 の当て方で当てた結果と同じであること（0035 の12 の凍結した見本と、見本の世帯の計算の固定値）。
  - 入力画面で直す → 差分 → 戻す、の往復で元の世帯とプランに戻ること（今の入力の画面の往復のテストを、プランの編集にも広げる）。
  - 値の箱を持たない欄への `set` で、値が欄に、状態が `valueStates` に入ること。
  - 見込みが不確かな受け取る相続・遺贈・贈与と受け継ぐ借金が要求に入らず、`includeInBase` の `set` で入ること。ほかの種類の入るお金は、不確かでも要求に入ること。
