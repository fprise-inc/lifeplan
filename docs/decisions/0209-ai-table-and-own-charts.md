# 0209. AI接続口の計算の答えを年ごとの表（CSV・Markdown）にし、AI が自分でグラフを描くときの決まりを説明に足す（table）

- 状態: 採用（一部未確定）（2026-11-12）
- 固定の強さ: 道具の名前と入出力（`table` の引数・行の名前・答えの2つの文の形）と使い方の例 `make_table` は試験版（0015 と同じ。予告して変えることがある）。表の下の注を必ず入れること・数字を AI から受け取らないことは骨格。作り（同梱した画面の関数で表を作る）は内部
- 前提にする記録: 0015（AI接続口）、0016（提示層）、0183（画面の関数を同梱する）、0194（主な数字と年齢）、0198（比較の道具）、0199（公開に使うときの案内）、0203（グラフ）、0205（住宅ローンの利息と金利）

## 背景

- FP は AI に「キャッシュフロー表を5年ごと・家族の年齢つきで CSV にして」「退職60・65・70歳の金融資産を表にして」と頼み、表計算ソフト・資料・ブログに使いたい。今は AI が `calculate`・`compare` の JSON を読み、自分で表に組み立て直していた。組み立てるたびに、列の選び方・年・単位・丸めが変わり、数字を写し間違えるおそれがある。JSON は表より大きく、会話の枠を食う。
- AI のアプリには、受け取った数字で自分でグラフを描く物がある（チャットの画面の部品・コードの実行）。描くときに数字をなめらかにしたり、先の年へ延ばしたり、前提と試算の旨を落としたりするおそれがある。
- 書き出しの道具（`export` の名の道具）は持たない決まり（0015 の2。世帯のデータを外へ書き出す道具は無い）。この道具は、計算の答えを文の表にして AI に返すだけで、世帯のデータを書き出さない。

## 決定

### 1. 表の道具 `table`

- 世帯と通りの書き方は `compare` と同じ（基本の世帯は見本の世帯・FPが渡した世帯・AIが組み立てた入力のどれか1つ。`changes`・`plan_changes`・`stress_test`・`market_stress`。`variants` は8通りまでで、省くと基本だけ）。計算は `compare` と同じ道（`run_compare`）で、数字は AI から受け取らない。主な数字・年金の見込み・年齢は数えない（表は同梱した画面の関数が数える）。どれかの通りを計算できないときは、表を作らずに `compare` と同じ理由を返す（グラフと同じ）。
- 表は同梱した画面の関数（`app/src/connector/table.ts`。数字の根拠と同じ1つの JS）で作る:
  - 年は画面のキャッシュフロー表に出す年（`displayYears`・`yearsWithin`。計算基準月が年の途中なら翌年から）。何年おき（`every_years`。既定5）は `calculate`・`compare` と同じ選び方（最初の年と最後の年はいつも入る）。
  - 年齢は画面の表の年齢の行（`summaryOf`）。年齢の列にする家族は年齢の鍵（`members`。既定は全員）。
  - 行の名前は `compare` の系列と同じ（`income`・`taxSi`・`expense`・`net`・`financialAssets`・`debt`・`shortfall`・`loanRepayment`・`loanBalance`・`loanInterest`・`loanRate`）に、`takeHome`（手取り＝収入合計−税・社会保険料。年ごとの合計が `keyFigures.lifetimeTakeHome`）・`expenseBreakdown`（支出の内訳。画面の表の支出の行〔`rowDefs` の支出のまとまりの、税・社会保険料の外の行〕ごと。値のある行だけ。足すと支出）・`pension`（公的年金。画面の表の人ごとの年金の行の合計）を足す。既定は `income`・`taxSi`・`expense`・`net`・`financialAssets`。系列と同じ名前の行は、系列と同じ行の足し方・同じ関数（住宅ローンは `loanYearsOf`）で数え、同じ数字になることを接続口のテストで確かめる。
  - 単位は万円（既定。画面と同じ丸め `toMan`＝四捨五入・符号は対称）か円。住宅ローンの金利は %（10進の文字を百倍した文。丸めない）。
  - 形は CSV（既定。数は数のまま、負の数は `-`、桁の区切りなし）か Markdown（画面と同じ書き方。3桁の区切りと ▲）。
- 通りが2つ以上のときの並べ方（`layout`）: `byRow`（数字ごとに通りを列に並べる。CSV は「金融資産残高・65歳で退職（万円）」の列の1つの表、Markdown は数字ごとの表。既定）と `byVariant`（通りごと。CSV は先頭の「通り」の列で縦に積んだ1つの表、Markdown は通りごとの表）。別の世帯の通りがあるときの既定は `byVariant`（`byRow` の年齢の列は基本の世帯の年齢になるため）。
- 表の下に必ず「※」の注を入れる（外す引数は無い）: 前提（物価上昇率・運用利回り。グラフの注と同じ書き方。通りで違えば通りごと）・相場などの想定（重ねた「相場が下がった場合」・ストレステスト。無ければ「なし」）・単位・選んだ行の意味（手取り・支出・負債残高・公的年金・資金の不足・支出の内訳・金利）・計算基準月と「将来の結果を約束するものではありません」の旨。CSV では表の後の空の行から下が注（1行1つの欄）。
- 「ファイナンシアで試算」の旨は `credit: true` のときだけ入れる（既定は入れない）。
- BOM: 日本語の Windows の Excel は BOM の無い UTF-8 の CSV を文字化けして開くことがある。`bom: true` で表の文の頭に BOM（U+FEFF）を付ける。既定は付けない（AI のアプリ・プログラムが文を読むときに、見えない文字で1つ目の列の名前が崩れることがあるため。ファイルにする AI のアプリが BOM 付きで保存できることもある）。
- 答えは2つの文: 短い説明の JSON（注は表の一部であることと、数字を変えずに使うこと・形・単位・並べ方・列の名前・年・通り・表の文の大きさ）と、表の文（そのままファイルにできる）。
- お客さまの名前・物の ID は入れない（列の名前は行の名前・家族の呼び方〔ご本人・配偶者・第1子…〕・通りの名前だけ。通りの名前に書いた文字はそのまま入るので、説明で名前を書かないよう伝える）。

### 2. AI が自分でグラフを描くときの決まり（説明）

接続口の説明（INSTRUCTIONS）と `docs/ai-connector.md` に書く:

1. 数字は `table`（か `compare` の `series`）から取り、足し引き・丸め直し・なめらかにする・間を埋める・先へ延ばすなどで変えない（表に無い年は描かない）。
2. 単位（万円）と、年・年齢の軸を書く。
3. `table` の表の下の注（前提・相場などの想定・試算の時点と、将来の結果を約束するものではない旨）を必ず図に添える。
4. 「ファイナンシアで試算」の旨は、FP が望んだときだけ入れる（既定は入れない）。
5. 画面と同じ見た目のグラフが要るとき・資料にそのまま使うグラフは、自分で描かず `chart` を使う。

### 3. 使い方の例 `make_table`

「表にする（CSV・Markdown。自分でグラフにするときも）」。引数は世帯（必ず）・表にしたい数字と年・並べたい通り・使い方（Excel で開く・資料に貼る・自分でグラフにする）。`table` の選び方と、2 の決まりを頼み方の文に入れる。

## 見本の世帯での数字

salariedCoupleTwoKids（計算基準月 2026年10月。表は 2027年から 2081年）で、働く最後の年齢を 60・65・70歳にした3通り:

- 金融資産残高（万円）: 2047年（ご本人66歳）は 1,520・3,276・3,844、2081年（100歳）は ▲2,616・1,508・4,233。`compare` の系列（円）を画面と同じく万円に丸めた数と同じ。
- 大きさ: 金融資産残高と年間収支を5年ごとにした CSV の表の文は約 1.3KB、同じ数字の `compare` の答え（JSON）は約 8.2KB（約6.5分の1）。6つの数字を毎年にすると約 6.1KB と約 31KB（約5分の1）。1通りの6つの数字を毎年にすると約 2.8KB と `calculate` の約 9.1KB（約3分の1）。1通りを5年ごとのような小さな表では、注（約 0.5KB）の分だけ差が縮む（約 1.2KB と約 2.3KB）。

## 理由

- 表は FP が頼むことの多い形で、AI が JSON から組み立て直すと、写し間違い・丸め方の違い・年の選び方の違いが起きうる。接続口が画面と同じ関数で表にすれば、画面の表と同じ数字になる。
- 注を外せなくするのは、表がファイルや資料になって会話の外へ出ても、前提と試算の旨が一緒に付いて行くようにするため（0199 の公開に使うときの案内と同じ考え）。
- 「ファイナンシアで試算」を既定で入れないのは、FP が自分の名前で出す資料・お客さまへの説明に使うことが多く、出典の書き方は FP が決める物だから。前提と試算の旨（約束しないこと）は誤解を防ぐ物なので、いつも入れる。
- CSV を既定にするのは、表計算ソフト・プログラムで読めて、いちばん小さいから。Markdown はチャットと資料にそのまま貼れる。
- 行の名前を `compare` の系列と同じにするのは、AI が道具ごとに名前を覚え直さなくてよいようにするため。

## 代案（採らなかったもの）

- **道具の名前を `export_table` にする**: 書き出しの道具を持たない決まり（0015 の2）と取り違えやすく、接続口のテストも名前に `export` を含む道具を止めている。計算の答えを文で返すだけなので `table`（`chart` と同じ動詞の無い名前）にした。
- **Rust で表を組む**: 支出の内訳・公的年金・年齢は画面の表の行の決め方（`rowDefs`・`ageRows`）に頼るので、同梱した画面の関数で作る方が画面とずれない。
- **`calculate`・`compare` に `format: "csv"` を足す**: 答えの形が引数で大きく変わり、主な数字・差・プランの当てはめと混ざる。表だけを返す道具に分けた。
- **注を別の文にする（表の文に入れない）**: 表だけがファイルになったときに注が落ちる。
- **BOM を既定で付ける**: AI のアプリ・プログラムが読むときに崩れることがある。Excel で開くときだけ付ける。
- **xlsx を返す**: 接続口に表計算の部品を入れることになり、AI のアプリでそのまま見えない。CSV を Excel で開けば足りる。
