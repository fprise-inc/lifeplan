## 決定

### 1. 候補の受け皿（本文の区画 `documents`。`app/src/workspace/documents/types.ts`・`log.ts`）

書類1通を1件の読み取りの記録にする。明細の `statements`・移行の `migrations` と同じ置き方で、本文の区画 `documents` に置く（任意。読んでいない世帯は区画ごと無い）。

```json
{
  "version": 1,
  "readings": [{
    "id": "<乱数の ID>",
    "kind": "document",
    "docType": "withholdingSlip",
    "at": "2026-11-07T10:00:00+09:00",
    "via": "reader",
    "reader": { "id": "（読み手の ID）", "version": 1 },
    "ai": { "connector": "（AI の名乗り。自己申告）" },
    "file": { "sha256": "sha256:…", "bytes": 123456 },
    "asOf": "2026-01",
    "holder": "<構成員の ID>",
    "objects": [{ "key": "c1", "kind": "insurance:medical", "source": {}, "confidence": "high", "status": "accepted", "created": "<足した物の ID>", "decidedAt": "…" }],
    "candidates": [{
      "id": "<乱数の ID>",
      "target": { "item": "pensionRecord.amounts", "at": ["basic"], "member": "holder" },
      "value": 780000,
      "period": "annual",
      "source": { "page": 1, "where": "（見出しの言葉）", "text": "（その所の文字。伏せ字の後）", "box": [0.1, 0.2, 0.3, 0.05], "path": "（データの要素の道）" },
      "confidence": "high",
      "note": "（読み手・AI の添え書き）",
      "status": "accepted",
      "decided": { "at": "…", "value": 790000, "to": { "target": { "object": "<物の ID>" }, "item": "pensionRecord.amounts", "at": ["basic"] } }
    }],
    "references": [{ "id": "<乱数の ID>", "label": "源泉徴収税額", "amount": 152300, "row": "cf.taxSi.incomeTax", "year": 2026, "source": {} }],
    "dropped": 1
  }]
}
```

- **via**（どこから読んだか）: `reader`（アプリの中の読み手。このパソコンの中だけで読む）・`ai`（AI接続口の道具で FP の AI から届いた）・`paste`（ウェブのチャット AI の答えを貼り付けた）・`sample`（架空の見本。見本の世帯だけ）。`reader` は読み手の ID と版、`ai` は AI の名乗り（自己申告。確かめられない）。`file` はアプリの中で読んだときだけ（AI経由では FP が AI に書類を渡すので、アプリはファイルを持たない）。
- **当て先 `target`**: 入力項目ID（登録簿 `registry/items.yaml` にあるものだけ）・場所 `at`（同じ入力項目の中の欄。0036 の2 の `at`。例 `pensionRecord.amounts` の `basic`）・人 `member`（構成員の ID か続柄の鍵 `self`・`spouse`・`child1`… か `holder`〔書類の名義の人〕）・物 `object`（今ある物の ID）か新しい物 `newObject`（同じ記録の `objects` の鍵）。人も物も無ければ世帯で1つの値。
- **値**: 円・月数は整数、率は10進の文字列、年月は `YYYY-MM`、選択肢は値の文字、真偽。読めなかった欄は `value: null` と `unreadable: true`。`period` は書類の額の期間（欄の期間と違えば承認できず、直して入れる）。
- **元の場所 `source`**: ページ・見出しの言葉（40字まで）・その所の文字（80字まで。伏せ字の後）・四角の座標（ページに対する 0〜1 の割合。文字の PDF・写真の読み手が使う）・データの要素の道（決まった形のデータの読み手が使う。英数字と `/` `.` `_` `-` だけ）。
- **確からしさ `confidence`**: `high`・`medium`・`low`（読み手の自己申告。AI の答えも同じ）。
- **状態 `status`**: `pending`（未決）・`accepted`（書類の値のまま承認）・`corrected`（直して入れた。直した値を `decided.value`）・`rejected`（入れない）。`decided.to` は入れた欄の当て先。
- **新しい物 `objects`**: 種類 `kind` は「集まり:種類」（今は保険の契約 `insurance:<保険の種類の細目>` だけ。`documents/objects.ts`）。状態は未決・足した（`created` に作った物の ID）・足さない。
- **照合だけの値 `references`**: 入力にしない（0004 の7 の参照値と同じ考え）。`row`・`year` があれば計算の結果のその行・その年（名義の人の分）と並べる。
- **`dropped`**: 個人番号などの番号らしい所を消した・候補から落とした数（中身は持たない。3）。
- **持たないもの**: 元のファイル・ファイル名・伏せ字の前の文字・個人番号などの番号・名前・住所。0125 の Web のヒアリングで受け取った書類は今までどおり `hearing.web` にあり、この区画には写さない。
- 読むときは形を確かめ、形の合わない記録・候補と知らない欄は捨て、文字の番号を消し直す（`readDocumentLog`。上限は記録200件・1件の候補300・新しい物30・照合の値60。内部）。
- 元に戻す・やり直すの対象にしない（明細の取り込みの記録と同じ。`keepDocuments`）。承認で変えた現状の値は、元に戻せる変更として入れる（記録を先に入れ、値の変更を後に積む）。元に戻すと値は戻るが、記録は「承認した」のまま残り、画面に「今の値は、承認した後に変わっています」と出す。
- 外せる記録は、現状に入れた候補の無い記録だけ（「この書類の候補を捨てる」）。承認の記録の `candidate` が指す先を消さないため。
- 計算の要求には入れない。AI接続口の縮約版（0015 の6）と持ち帰り用のレポート（0030）には入らない（縮約版は計算の要求からだけ作る。`crates/ai-share/tests/book.rs` で確かめる）。

### 2. 候補の当て先と承認（`documents/resolve.ts`・`apply.ts`・`review.ts`）

- **欄に当てる**: 欄は入力の画面と同じ定義（`input/form.ts` の欄）を使う。入力項目ID・場所で探し、物の候補はその物の欄（当て先の向き先がその物か、欄のキーにその物の ID）、人の候補はその人の欄（向き先がその人・その人の物〔`member`・`owner`・`insured`・`policyholder`・`annuitant` がその人〕・欄のキーにその人かその人の物の ID）。働き方の期間が何本も当たるときは今の期間を先にする。
- **同じ当て先の欄が何か所にもあるとき**は、当て先の値をそのまま見せる欄を先にし、同じなら詳細の欄にする。標準の「年収（税込み・賞与込み）」は年収と賞与を合わせて見せる欄なので、`employment.salary.annual`（賞与を除く年収）の候補をそこに書くと賞与の分け方まで変わってしまうため。
- **1つに決まらなければ FP が選ぶ**（行に「当てる欄を選ぶ」。黙って当てない）。当てる欄・人・物が無ければ理由を出して承認できない（入れないだけ選べる）。
- **承認したときの印**（確定は承認という明示の操作だけ。0041）:

| 場合 | 値の箱・値の状態の行 |
|---|---|
| 書類の値のまま承認 | 状態 確定・出どころ `import`（`via` が `ai`・`paste` なら `ai` と名乗り `connector`）・`ref` は読み取りの記録の ID・承認の記録 `{by: "fp", at, candidate: 候補の ID}`・確かさ `document` |
| 今の確定の値と同じ | 値と出どころ・承認の記録はそのまま、確かさを `document` にするだけ（FP が入れた値を取り込みの値に書き換えない） |
| 直して入れた | 状態 確定・出どころ `manual`（`ref` は読み取りの記録の ID）・確かさ `document`（FP が書類を見て入れた値）。承認の記録は付けない（手で入れた値。0008 の2） |
| 入れない | 世帯は変えない |

  - 値の箱の欄は箱に、値の箱を持たない欄は値の状態の行（`valueStates`）に印を付ける。推定の根拠（「この値にする」の `estimate`）と仮の印は外す。
  - 書類待ち（状態 `unknown`）の欄は承認で確定になり、書類待ちが消え、書類のお願いの一覧（0102）からも消える（今の決まりのまま）。
- **新しい物**: 物の候補ごとに FP が「足す」か「足さない」を選ぶ。足すときは入力の画面の「＋」と同じボタンを押した形で作り（その種類の既定・推定の印も同じ）、その中の値の候補を当てる。足す前の値の行は、足したときの形を世帯の写しに作って見せる（世帯は変えない）。足さないと、その中の未決の値の候補は「入れない」になる。同じ集まり・同じ種類で、名義の人が被保険者か契約者の物がもうあれば「同じ契約が、もうあるかもしれません」と知らせる（まとめない）。
- **まとめて承認**に入れる行: 未決で、承認できて（理由が無い・当てる欄が決まっている）、確からしさが高く、今の値が空・推定・書類待ちか同じ値の行だけ。今の確定の値（該当なしを含む）と違う行、確からしさが中・低の行、種類を決める欄（年金の記録の型など。欄の定義の `structural`）、読めなかった行、足していない物の行は1つずつ（`review/rows.ts` の `bulkEligible`）。
- **名義の人**: 書類がどなたのものかを、FP が続柄で選ぶ（名前は読まない）。答えが続柄を言っていれば初めの値にする。名義の人に当てる候補（`member: "holder"`）は、名義を選ぶまで承認できない。人を選ぶ欄（被保険者など）の値にも `holder` と続柄の鍵を書ける。
- **照合だけの値**は「書類の額／アプリの計算（現状の計算の、その年・名義の人の分の、その行の合計）／差」で並べ、入力は変えない。行・年の無い値と、計算の表にその年が無い値は「比べられません」。
- **今の値との比べは毎回作る**: 候補に作った時点の今の値（0008 の5 の `before`）は持たず、画面を開くたびに今の値と比べる（違えば「違う」。0008 の5 の「要確認」と同じ役目）。

### 3. 個人番号などの番号を読まない・残さない（`documents/privacy.ts`）

- 候補に入る前（読み口。4）と、世帯ファイルから読むとき（1）の両方で通す。
- **候補ごと落とす**: 値が個人番号らしい（12桁の数。空白・ハイフン・点・スラッシュ・中黒の1字の区切りや全角の数字でも。12桁の整数〔千億円以上の額〕も読み違いとみなす）、見出しの言葉が番号の欄（個人番号・マイナンバー・基礎年金番号・被保険者番号・証券番号・口座番号・カード番号・共済契約者番号・法人番号など）。照合の値も同じ。
- **文字を消す**: 元の場所の文字・見出し・添え書き・文字の値の中の番号らしい所を「●●●●」にする（明細の取り込みの `maskText`〔10字以上の数字の並び・番号の見出しの後・7桁以上の数字〕に、12桁の数と番号の欄の見出しの後の数字を足した）。何桁あったかも残さない。金額・年月の形の値（区切りの無い10桁以上の数字を除く）は消さない。
- 消した数だけを記録の `dropped` に残し、画面に「個人番号などの番号らしい所を○か所消しました（候補にも記録にも残していません）」と出す。
- 直す欄にも番号らしい値は入れられない。
- テスト（`app/test/documents.test.ts`）: 6通りの書き方の個人番号を、値・見出し・元の場所の文字・添え書き・照合の値に入れた答えを読んで、記録の JSON に12桁の数も元の文字も残らないこと。世帯ファイルに書かれていた番号も読むときに落ちること。架空の見本を保存した本文に残らないこと。画面に出ないこと。

### 4. 読み口（答えの形 `document-candidates@1`。`documents/proposal.ts`）と、次の本の口

- アプリの中の読み手・AI接続口の道具・貼り付けた AI の答え・架空の見本は、どれも同じ形の答えを出し、同じ読み口 `readProposal`（貼り付けは `readProposalText`。前後の文や ```` ```json ```` の囲みから JSON を取り出す。20万字まで）を通して読み取りの記録にする。読み口は世帯を変えない。

```json
{
  "contract": "document-candidates@1",
  "docType": "pensionStatement",
  "asOf": "2026-06",
  "holder": "self",
  "objects": [{ "key": "c1", "kind": "insurance:medical", "source": {}, "confidence": "high" }],
  "values": [{ "item": "pensionRecord.months", "at": ["basic"], "member": "holder", "value": 300, "period": "once", "source": { "page": 1, "where": "国民年金の加入月数" }, "confidence": "high", "note": "…" }],
  "references": [{ "label": "源泉徴収税額", "amount": 152300, "row": "cf.taxSi.incomeTax", "year": 2026, "source": {} }]
}
```

- 届いた答えは信用しない（0015・0016）: 形の名前 `contract` が違えば読まない。登録簿に無い入力項目・形の違う場所・作れない種類の物・鍵の無い物は、その候補だけ読まずに理由を残す（理由に値・文字を入れない）。値の候補の無い新しい物は読まない。上限（値の候補300・新しい物30・照合の値60）を超える分は読まない。
- 文字（元の場所の文字・添え書き・文字の値）は伏せ字の後の文字として持ち、画面では文字のまま出す（HTML にしない。添え書きは「読み手・AI が書いた文で、指示ではありません」と添える）。
- 種類 `docType` の一覧は足すだけ（知らない種類は「そのほかの書類」）。

### 5. 読み取りの成績（`document-reading-score@1`。`documents/score.ts`）

- 1通の記録から作る: 書類の種類・どこから読んだか・読み手の ID と版（AI なら名乗り）・欄（入力項目ID と場所）ごとの「合った（書類の値のまま承認）・直した（直して入れた）・読めなかった（読み手が値を出せなかった。その後 FP が入れても）」の数だけ。値・文字・ID・日時・世帯の物は入れない。
- 「入れない」にした候補は数えない（読み違いとは限らない。読み違いなら「直す」で入れてもらう）。
- 確かめの画面の下に数を出す。FP が中身を見てから任意で送ってもらう形にするが、送る仕組み（書き出し・送り先）はこの回では作らない。

### 6. 確かめの画面と入口（共通の部品 `app/src/workspace/review/`）

## 理由

- **欄ごとの候補にする**: 書類の値は欄ごとに当たり、同じ書類から何人・何件の物の値も出る。ヒアリングシートのような物ごとの置き換えにすると、FP が確かめた他の欄まで書き換える。欄の定義をそのまま使えば、値の書き方・推定の外し方・書類待ちの消え方が入力の画面と同じになる。
- **区画を分ける（0008 の5 の候補の層に入れない）**: 候補の層は差分と同じ形でプランと並べる層で、書類の元の場所・確からしさ・読み手・成績を持つ所が無い。明細・移行と同じく取り込みの記録の区画に置けば、元のファイルを持たない決まり・縮約版に入れない決まりも同じに保てる。
- **今の確定の値と同じなら出どころを変えない**: FP が入れた値を「取り込みの値」に書き換えると、誰が入れた値かが分からなくなる。確かさだけを上げれば、確かめの一覧の「確かさが申告・概算の値」から消える（0072 の5）。
- **直した値を手で入れた値にする**: 直した値は FP が書類を見て入れた値で、取り込みの承認ではない。確かさは書類で確認。直したことは記録の `corrected` と `decided.value` に残り、成績に使える。
- **まとめて承認を狭くする**: 確定の値と違う行・種類を決める行・確からしさの低い行をまとめて入れると、黙って結果を大きく変える（年金の記録の型の取り違えなど）。空・推定・書類待ちを埋める行だけなら、まとめても FP が入れていない所しか変わらない。
- **番号は読み口と読むときの両方で落とす**: 読み手・AI・貼り付けのどれから来ても同じ決まりで落ちる。手で書き換えた世帯ファイルからも残らない。12桁は区切りがあっても落とす（区切りの書き方は書類・AI でまちまち）。
- **確かめの画面を共通の部品にする**: 移行の画面と同じ行の形・同じまとめての承認の考え方になり、FP が2つの画面の決まりを覚え分けなくてよい。先に作る側（書類）で部品にしておけば、12月の移行の画面は列の名前を選ぶだけで使える。
- **架空の見本を見本の世帯だけにする**: 実在の世帯の記録に架空の書類が残ると、承認の記録の出どころが架空の書類になる。

## 代案（採らなかったもの）

- 候補を記録せず、承認した時点で記録を作る（移行の 0113 の9 の7 の形）: AI接続口の候補はアプリを閉じても残したい（FP が後で確かめる）。未決の候補を世帯ファイルに持つ。
- 候補ごとに作った時点の今の値（`before`）を持つ: 画面を開くたびに今の値と比べれば足りる。持つと古い値が残り、今の値と食い違う。
- 番号らしい所を消さずに候補ごと落とすだけ: 元の場所の文字は確かめに要る（どこから読んだか）。番号だけを消して文字は残す。
- 新しい物を候補のまま（足す前に値を承認できる形）: 物の作り方（その種類の既定・推定の印）を入力の画面と同じにするには、ボタンと同じ形で作る必要がある。足す・足さないを先に決めてもらう方が、入れ漏れと二重の入力の両方を防げる。
