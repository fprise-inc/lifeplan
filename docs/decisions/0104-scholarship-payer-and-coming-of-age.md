# 0104. 子の奨学金を誰が返すか・第一種の奨学金の返済・成人式の時期を子の生年月に合わせる・今返している住宅ローンの仮の金利と、世帯ファイルの形式 0.47

- 状態: 採用（一部未確定）（2026-11-01）
- 固定の強さ: 骨格は、子の貸与の奨学金の `repaidBy`（`child` 子が返す・`household` 世帯で返す。省略は子）の意味（子が返す返済は世帯のお金の動き・負債に入れず、要約 `childScholarships` に出す）、ほかのローンの種類 `scholarshipFree`（第一種・無利子）、時点の年齢の規則 `schoolYearJanuary`（その年齢になる年度の1月）、形式 0.47 の変換の段（前の奨学金は世帯で返す・子が1人に決まる成人式の行だけ子の年齢の時点に置き直す）。画面の文言・書き添えの文の言い方・欄の並び・今返している住宅ローンの固定金利の目安の値は後から変えてよい

## 背景

- 日本では、貸与の奨学金（日本学生支援機構など）は、卒業した後に子が自分で返すことが多い。計算エンジンの教育費（`education.cost`）は、子の貸与の奨学金の返済を、返す人（`debtor`）が子でも親でも世帯のお金の動きと負債に入れていた。画面の奨学金の枠には「返す人が子なら、子の返済は世帯の支出に入れません」と書いてあったが、計算はそうなっていなかった（返す人「子」は負債の名義だけだった）。
- 本人・配偶者が今返している奨学金（住まい・ローンの入力項目のほかのローン「奨学金の返済」）は、利率の目安が第二種（有利子）の今返している人の平均 年0.75%（`loanRates.scholarship.repaying`）の1つだけで、無利子の第一種を選べなかった。
- ライフイベントの「子の成人式」のひな形は、足したときの年月（20歳になる年度の1月）で行を持っていたので、後から子の生年月を直しても成人式の時期が動かなかった。
- 今返している住宅ローン（借りたのが計算の基準の月まで）の金利の目安は、金利の種類を問わず住宅ローン利用者の借入金利の中央値 年0.85%（`housing.statistics.mortgageRate.current`）だった（0052 の追記 2026-11-01）。利用者の75%が変動型の調査の中央値で、全期間固定・固定期間選択型には低すぎる。
- 前提にする記録: 0003（年齢の切り替えの規則）、0008（世帯のデータの形）、0011（形式の版と変換）、0052（住まい・ローン）、0062（子ども・教育）、0068（ライフイベント）、0103（形式 0.46）。

## 決定

### 1. 子の奨学金を誰が返すか（`repaidBy`）

- 子の貸与の奨学金（`goals[].education.scholarships[]`）に、返すのは誰か `repaidBy` を足す: `child`（子が返す）・`household`（世帯で返す）。**省略は子が返す**（よくある形）。画面の欄「返す人」は「子が返す」「世帯で返す」の2つ（詳細）。新しく足す奨学金は「子が返す」。
- **子が返す**: 返済は世帯のお金の動き（表の「奨学金の返済」の行）にも、負債の残高（貸借対照表の「奨学金」）にも入れない。在学中に受け取る奨学金は、今までどおり学費に使う入るお金（`cf.income.other.scholarship`）のまま。名義（`debtor`）は使わない。
- **世帯で返す**: 今までどおり返済を世帯のお金の動きと負債に入れる。負債の名義は `debtor`（`parent` なら親、省略・`child` なら子）。前の画面の「返す人 親」は名義の欄で、今は画面に出さない（前のファイルの値は残して名義に使う）。
- 子が返す返済は黙って消さない: 計算エンジンが**何をいくら返すか**を出し、FP が説明できるようにする。
  - 部品 `education.cost` の約束の版 1.1（改訂9）: 出力に `childRepaid`（教育の目標の物・子・借りた総額・最初の月の返済額・返す期間〔表の期間の中の最初と最後の月〕・表の期間の中の返済の合計）。返済の計算は世帯で返すときと同じ `debt.schedule`（元利均等）。
  - 部品 `plan.cashflow` の約束の版 1.8（改訂19）: `details.childScholarships` に写し、エンジンが出力の `summary.childScholarships` に写す（出力のスキーマ `engine.output#/$defs/childScholarships`）。
  - 書き添えの文（提案書とアプリで同じ部品 `report/src/childScholarships.ts`）: 「第2子の奨学金の返済（2037年10月〜2045年12月・月々約1.5万円・合計約147万円）は、第2子が返すので世帯の収支に入れていません」。子ごとに1文。
    - アプリの結果の画面: 目標の区画（夢のひとことの下）に出す。
    - 提案書: 前提条件の注（`assumptions.notes`）に出す。
  - 子ども・教育の奨学金の枠の説明も、返す人で書き分ける（子が返す: 「卒業の後に子が返します。子の返済は世帯の支出に入れません（結果の画面と提案書に返済の額を書き添えます）」）。
- 住まい・ローンの入力項目の読むだけの1行は「子の貸与の奨学金（世帯で返す）n件」（前は「親が返す」）。
- 万一の必要保障額（`protection.need`）が数える教育費も、子が返す返済を含まない（教育費の部品のお金の動きを使うため）。

### 2. 第一種（無利子）の奨学金の返済

- ほかのローンの種類（`debts[].subtype`）に `scholarshipFree`「奨学金の返済（第一種・無利子）」を足す。計算の種類は `scholarship`、金利の目安は **0%**（根拠の文「第一種奨学金（無利子）は利率0%」）。
- 前の種類 `scholarship` の名前を「奨学金の返済（第二種・有利子）」にし、目安は今までどおり今返している人の第二種の利率の平均 **年0.75%**（`loanRates.scholarship.repaying`）。根拠の文の「無利子の第一種なら0%」は「無利子の第一種なら種類で選んでください」にした。
- 種類を変えると、金利が目安のままなら新しい種類の目安に入れ直す（0052 の決まりのまま）。足すボタンは今までどおり「＋ 奨学金の返済」の1つ（第二種で足す。第一種は種類で選ぶ）。

### 3. 成人式の時期を子の生年月に合わせる（`schoolYearJanuary`）

- 時点の年齢の切り替えの規則に `schoolYearJanuary`（その年齢になる年度の1月。年度の区切りは `schoolYear` と同じ4月2日〜翌年4月1日生まれ。`schoolYear` の月の3か月前）を足した（0003 の表）。計算エンジン（`time/ageSwitch.ts`）・画面（`workspace/timepoint.ts`）・提案書（`build.ts`）が同じ決まりで解く。
- ライフイベントの「子の成人式」のひな形は、行の時期を `{ memberAge: { member: <子>, years: 20, ageSwitch: "schoolYearJanuary" } }`（20歳になる年度の1月）で持つ。子の生年月を直すと、成人式の時期も一緒に動く。
- 時点の欄の言い方: 欄は「第1子20歳の年度の1月」、読みは「第1子が20歳になる年度の1月（令和15年1月）」。打つときは「20歳の年度の1月」「20歳になる年度の1月」と読む。

### 4. 今返している住宅ローンの仮の金利（金利の種類ごと）

- 変動金利（と、ヒアリングシートの簡易版の住宅ローン〔変動金利で置く〕）: 今までどおり住宅ローン利用者の借入金利の中央値 **年0.85%**（`housing.statistics.mortgageRate.current`）。
- 全期間固定・固定期間選択型: 前の種類ごとの目安（新しく借りるときの金利）に戻した。全期間固定 **年3.83%**（`housing.statistics.mortgageRate.fixed`。住宅金融支援機構【フラット３５】の最も多い借入金利、2026年10月）、固定期間選択型（当初10年）**年3.80%**（`housing.statistics.mortgageRate.fixedPeriod10`。主要な銀行の当初10年の最も低い適用金利の平均）。
  - 過去の年に借りた人（今返している人）の固定金利の数を探したが、使える公表の数（表の形）が無かった: 【フラット３５】の借入金利の推移は図だけで数の表が無く（平成15年10月からの各期間の PDF）、住宅ローン利用者の実態調査は金利の種類ごとの借入金利を出していない。利用者の中央値（約0.85%）は変動型の金利に寄っているので、固定には使わない。
  - そのため、新しく借りるときの目安で代え、根拠の文に「借りた年ごとの金利の公表の数が無いので、新しく借りるときの目安で代えています」と書く（例:「今返している住宅ローン（全期間固定） 年3.83%（…）」）。過去に借りた固定金利は今の目安より低いことが多い（【フラット３５】の推移の図でも、令和5年より前は今より低い）ので、返済予定表で直す。
- 金利の種類の欄の知らせ: 「金利が推定のままなら、今返している住宅ローンの推定の金利（選んだ種類の分）に入れ直します」（前は「種類で変わりません」）。

### 5. 世帯ファイルの形式 0.47

- 1〜3を1つの版にまとめた（MINOR）。前の版のアプリは、返す人を読み落として書き戻し、新しい規則の時点・新しい種類のローンを読めないので、版を上げて閲覧だけにする。
- `0.46` → `0.47` の変換の段（本体 `household-store`）:
  - **前の奨学金は「世帯で返す」**（`repaidBy: household`。もう `repaidBy` がある物は変えない。`debtor` は残す）。前の計算は返済を世帯の収支に入れていたので、開いた世帯の結果を変えない。新しい既定（子が返す）に自動で変えると、FP が知らないうちに結果が良くなるため。子が返すなら、FP が「返す人」を直す。
  - **子の成人式の行**: 名前に「成人式」があり、時期が年月だけの1回の行（終わりが空か始まりと同じ）のうち、その月が**ちょうど1人**の一緒に暮らす子の成人式の月（20歳になる年度の1月）で、名前の頭の「第N子」（生まれた順の一緒に暮らす子の番号）がほかの子を指していない行だけを、その子の年齢の時点に置き直す（月は変わらないので、結果も変わらない）。どの子の月でもない行（時期を式の月に直した行・子の生年月を直した後の行など）と、2人以上の子の月に当たる行は、年月のまま。
  - プランの差分で足した物（教育の目標・奨学金・出るお金の行）も同じに直す。控え（`snapshots`）・ヒアリングの記録の中身は変えない。
- 見本 `crates/household-store/tests/fixtures/household-format/0.47/`（0.46 の見本に、子が返す奨学金・世帯で返す奨学金・子の年齢の成人式・第一種の奨学金の返済を足した物）。

- モデル世帯 `educationTwoKids`（第2子が貸与の奨学金を「卒業後に子が返す」。`debtor: child` で、`repaidBy` は無い〔子が返す〕）: 第2子の返済（月14,838円・2037年10月から）を世帯の収支に入れなくなり、年間収支が2037年 +44,514円、2038〜2045年 毎年 +178,056円。2045年末の金融資産は +1,596,206円（78,591,928円 → 80,188,134円）。要約の `childScholarships` に、借りた総額 2,592,000円・表の期間の中の返済の合計 1,468,962円（2037年10月〜2045年12月）。
- ほかのモデル世帯は子の貸与の奨学金を持たないので、結果は変わらない。
- 世帯ファイル（0.46 以前）は、変換の段で世帯で返すにするので、結果は変わらない。

## 追記

- 2026-11-01（子ども・教育の貸与の奨学金の種類と、世帯ファイルの形式 0.49）:
  - 子の貸与の奨学金（`goals[].education.scholarships[]`）に種類 `type` を足した: `first`「第一種（無利子）」・`second`「第二種（有利子）」。**省略は第二種**。画面の欄「種類」（詳細。奨学金の枠のいちばん上）、枠の見出しは「貸与の奨学金（第一種） 月50,000円」のように種類を添える。種類は表示と利率の目安の元だけで、計算は今までどおり利率（`rate`）で行う（エンジンの部品は変えない。入力のスキーマに欄を足しただけ）。
  - 利率の目安: 第一種は **0%**（根拠の文「第一種奨学金（無利子）は利率0%」）、第二種は今までどおり、これから借りる第二種の目安 **年3%**（`loanRates.scholarship`）。今返している奨学金の返済（ほかのローン）と同じく、種類を変えたとき、利率が推定のまま（目安のボタンの値）なら新しい種類の目安に入れ直し、FP が入れた利率は変えない（0052 の決まり。欄の「?」: 「種類で利率の目安が決まります（第一種は無利子で0%、第二種は年3%〔…〕）。利率を入れていれば、種類を変えても利率は変えません」）。
  - 足すボタンは今までどおり「＋ 貸与の奨学金」の1つ（第二種で足す。種類は書かずに省略のまま。第一種は種類で選ぶ）。月額の目安（月5万円）と返す年数（返還年数算出表。第一種・第二種で同じ表）は、種類で変えない。
  - 前の世帯: 種類の無い奨学金は、入っている利率のまま第二種として読む（利率を書き換えない）ので、結果は変わらない。前に利率を0%にして第一種のつもりで入れていた奨学金も、見出しは「第二種」になるが、計算は0%のまま（FP が種類を第一種に直せばよい）。
  - 形式 0.49（足すだけの MINOR）: 前の版のアプリは種類を読み落として書き戻すので、版を上げて閲覧だけにする。0.48 → 0.49 の変換の段（本体 `household-store`）は形式の版だけを書き換える。見本 `crates/household-store/tests/fixtures/household-format/0.49/`（0.48 の見本の本文の、子が返す奨学金を第一種・0% にした物）。
  - ヒアリングシートには子の奨学金の欄が無いので、変えない。
  - 見本の世帯の結果: 変わらない（モデル世帯の奨学金に種類は無く、利率のまま計算する）。
  - テスト: `app/test/education-card.test.ts`（種類の欄・第一種で0%・第二種に戻すと年3%・入れた利率は変えない・見出し）、`app/test/store.test.ts`（0.49 の形の保存と読み戻し・種類は計算に使わない）、`crates/household-store`（0.48 → 0.49 の変換の段・0.49 の見本）。
