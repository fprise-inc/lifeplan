# 0125. Web のヒアリング: FP が選んだ問いを URL で渡し、お客さまがブラウザで1画面ずつ答え、答えと書類を端から端まで暗号化して届ける

- 状態: 採用（一部未確定）（2026-11-05）
- 固定の強さ: 骨格は、暗号の形（URL のフラグメントの形 `1.<問いの鍵の元>.<FP の公開鍵>`・鍵の導き方・封筒の形・追加の認証データ）、受け付けのサーバーの API の道と体の形（`/api/hearing/v1`）、届いた答えの中身の形（`fprise-lifeplan-hearing-web-answers` 0.1）と、答えの受け皿が Excel と同じ（0018 の filled-sheet の回答の一覧）であること。お客さまの画面の作り・問いを飛ばす決まりの細部・言葉・書類の一覧と説明・上限の値・FP の画面は内部（後から変えてよい。変えたら追記に書く）。世帯ファイルの形式は 0.63（取り込みの記録 `hearing.web` を足すだけの MINOR）
- 前提にする記録: 0011（世帯ファイルと形式の版）、0012（持たない情報・提供元に届く経路）、0013（暗号化と鍵）、0014（同意の記録）、0016（画面の安全・CSP）、0018（ヒアリングシートの形式・シート定義・項目キー・依頼番号・取り込み）、0030（持ち帰り用のレポート。外と話さないページ）、0073（事務所の既定値）、0087（financia.jp の受け付けのページ）、0102（書類のお願い）、0121（事務所の見た目）

## 背景

- 事前のヒアリングは Excel と印刷用 PDF だけで、Web フォームは「次の版以降に判断」（0018 の未確定）、書類の受け取りは「β公開の後に判断。作るなら Cloudflare＋E2E」としていた（0102）。
- 利用者の判断（2026-11-05）: **FP が聞きたい項目を選んで URL を発行し、お客さまがブラウザで1画面ずつ答える形を、すぐ作る**。書類も同じ道で、ブラウザの中で暗号化して送ってもらう。サーバーの仕組みまで作り、手元で試せる所まで進める。本番への公開（契約・DNS・届出の相談・規約）は利用者の手作業。
- 守ること: 提供元のサーバーを通っても、提供元は答え・書類・問いの中身を読めない（0012 の4 の考え方を、「経路が無い」から「経路はあるが鍵が届かない」に置き換える）。返ってきた物は信用しない（0018 の6）。名前は聞かない（0018 の2）。

## 決定

### 1. 全体の形

1. FP のアプリが依頼ごとに鍵を作り、問いを暗号化して受け付けのサーバーに置き、URL を発行する。FP はその URL をメールなどで送る（アプリはメールを送らない）。
2. お客さまは URL をブラウザで開き、1画面ずつ答える。書類は撮るかファイルを選ぶ。答えと書類は**お客さまのブラウザの中で FP の公開鍵あてに暗号化**して置く。
3. FP のアプリが受け取り、FP の秘密鍵で開き、世帯ファイルに入れてから、サーバーから消す。取り込みは Excel と同じ候補の画面で FP が承認する。

### 2. 暗号（WebCrypto の標準の部品だけ。自前の暗号は作らない）

- **依頼ごとに FP のアプリが作るもの**（`hearing/src/web/e2e.ts`）: 問いの鍵の元（32バイトの乱数）・FP の鍵の組（ECDH P-256）・受け取りの合言葉（32バイトの乱数）。
- **URL**: `https://<受け付けのホスト>/h/#1.<問いの鍵の元>.<FP の公開鍵（圧縮しない65バイト）>`（どちらも base64url）。フラグメント（# の後）はブラウザがサーバーに送らない。お客さまのページの `Referrer-Policy: no-referrer` で外にも漏らさない。
- **問いの鍵の元から HKDF-SHA256 で導くもの**（塩は決まった文字 `financia-hearing-web-v1`、用途の文字で分ける）: サーバーの上の名前（16バイト）・送るときの合言葉（32バイト）・問いを解く鍵（AES-256-GCM）・端末の中の下書きの鍵（AES-256-GCM）。
- **問い**: 問いを解く鍵で AES-GCM。追加の認証データ（AAD）に「何の暗号文か・依頼の名前・FP の公開鍵」を入れる（フラグメントの公開鍵を差し替えると開けない）。
- **答えと書類**: お客さまのブラウザが使い捨ての鍵の組（ECDH P-256）を作り、FP の公開鍵との共有の値を HKDF-SHA256（塩は16バイトの乱数、用途は依頼の名前と「答え」か「書類のファイルの番号」）で AES-256-GCM の鍵にする。封筒は `1.<使い捨ての公開鍵>.<塩>.<iv>.<暗号文>`。AAD に依頼の名前・用途・使い捨ての公開鍵を入れる（別の依頼・別の書類の暗号文への付け替えを開かない）。
- **開けるのは FP の秘密鍵だけ**。URL が漏れても、もう送った答え・書類は読めない（問いと、確かめてもらう項目の前回の値は読める。4 の注意）。
- FP の秘密鍵・受け取りの合言葉・問いの鍵の元は、依頼の記録として**世帯ファイルの中だけ**に置く（0013 の世帯の鍵で暗号化される。画面の保存機能・ログに置かない）。

### 3. 受け付けのサーバー（`hearing/relay/`。Cloudflare Workers＋R2。手元は `wrangler dev`）

- **置くもの**: 問いの暗号文・答えの暗号文・書類の暗号文・2つの合言葉の SHA-256・日時だけ。鍵は届かない。
- **API**（頭は `/api/hearing/v1`。体は JSON、暗号文は base64url の文字）:

  | 動き | 道 | 誰が | 合言葉 |
  |---|---|---|---|
  | 依頼を作る | `POST /requests` | FP（本体） | 無し（名前・合言葉のハッシュ・期限・問いの暗号文を送る） |
  | 問いを受け取る | `GET /requests/<名前>` | お客さま | 無し（暗号文だけ。開くにはフラグメントの鍵が要る） |
  | 書類を置く・外す | `PUT・DELETE /requests/<名前>/files/<番号>` | お客さま | 送るときの合言葉（送る前だけ） |
  | 答えを送る | `PUT /requests/<名前>/answers` | お客さま | 送るときの合言葉（1回だけ。2回目は 409） |
  | 状況・答え・書類 | `GET /requests/<名前>/status`・`/answers`・`/files/<番号>` | FP（本体） | 受け取りの合言葉 |
  | 消す | `DELETE /requests/<名前>` | FP（本体） | 受け取りの合言葉 |

- **期限**: 最長30日・最短1日（FP が7・14・30日から選ぶ）。期限を過ぎたものは断り（410）、見つけたときに消す。R2 の期限の決まり（31日）でも消す（本番の手作業）。FP が受け取ったら消す。
- **大きさの上限**: 問いの暗号文 400KB・答えの暗号文 800KB・書類1ファイル 10MB（暗号文はその base64url に余裕を足した値）・依頼ごとの書類の合計 40MB・ファイル30まで（中身の上限は5の表）。
- **回数の制限**: Cloudflare の回数の制限の部品（依頼を作る: 接続元ごとに 1分20回、依頼ごと: 1分60回）。接続元は数えるのに使うだけで残さない。
- **1回だけの送信**: R2 の条件つきの書き込み（`If-None-Match: *`）で、答えはもうあれば書かない。R2 は書いた直後から同じものが読める（強い整合）。
- **ログ**: 中身・IP・合言葉をログに書かない。Worker のコードは console を使わない（lint で止める）。Workers の観測のログは切る（`wrangler.toml` の `[observability] enabled = false`）。Cloudflare 自身の通信の記録（接続元の IP を含みうる）は提供元が消せないので、規約・案内に書く（本番の手作業）。
- **合言葉の比べ方**: SHA-256 の16進を、時間で中身が分からない比べ方で比べる。送るときの合言葉と受け取りの合言葉は別のもの（同じなら作るのを断る）。呼び出しの Origin は同じ所（お客さまのページ）か無し（FP のアプリの本体）だけを受ける。
- **お客さまのページを配る**: 同じ Worker が `/h/` の下の静的なファイル（5）を配る。どの答えにも守りの見出し（CSP・`no-referrer`・`nosniff`・`frame-ancestors 'none'`・権限の止め）を付ける。

### 4. FP の側（アプリ）

- **入口**: 取り込みの「ヒアリングシート」に「Web で聞く（URL）」。保存した世帯でだけ発行できる（鍵を世帯ファイルに置くため）。
- **項目を選ぶ**（`app/src/workspace/hearing/WebBuilder.tsx`・`web.ts`）:
  - ひな形から始める: 初回の前（簡易の票 `basic`）・詳細（`full`）・見直し（`full` で、今の世帯に値のある項目を「確かめてもらう」に）・事務所のひな形。
  - 分野ごと・項目ごとに選ぶ（まとめて選ぶ・外す）。分野の並びと、分野の中の項目の並びを ↑↓ で変える。
  - 見直しでは、項目ごとに「聞く（空欄から）」か「確かめてもらう（今の値を見せる）」を選ぶ。聞かないなら選ばない。
  - FP の独自の質問（自由記述。10問まで）を足せる。項目キーは 0018 の3 の予約 `ext.office.q<乱数>`。答えは FP 用のメモに入り、計算には使わない。
  - 元のシートは1つの依頼で1つ（`basic` か `full`）。簡易の票と詳細の票の項目は、同じ取り込みの手順で読み替えるので（0018 の追記 2026-10-27）、混ぜると答えを取り違える。
  - 顧客にどう見えるかを、右にお客さまの画面の見本（同じ部品。通信しない・何も残さない）で見られる。項目の「見る」でその問いを開く。
  - よく使う組み合わせを、事務所のひな形として事務所の既定値（0073）の `hearingTemplates` に保存できる（20件まで。世帯には写さない）。
- **頼む書類**（同じ画面）: 一覧から足す（源泉徴収票・ねんきん定期便・保険証券・住宅ローンの返済予定表・固定資産税の通知書・給与明細・確定申告書の控え・iDeCo や NISA の残高の分かる物・住民税の決定通知書・会社の退職金規程）。書類ごとに「何のため」「写す所」の短い説明が付き、FP が直せる。入力の画面の「書類待ち」（0102）の1通から「この書類を頼む」を選ぶと、その1通と結びつく（15通まで）。
- **URL を発行する**: 顧客番号（英数字）・事務所名（事務所の見た目の名前。0121）・何のための問いか・個人情報の窓口・有効期限。発行すると URL と案内文のひな形が出て、コピーできる。案内文に顧客番号・金額は入れない。「確かめてもらう」項目があるときは「URL を知っている人は今の値を読める」と注意する。
- **依頼の一覧**（`WebRequests.tsx`）: 発行済み・回答あり・受け取り済み・取り込み済み・期限切れ・取り消し。「回答を確かめる」「受け取る」「取り込む」「書類」「案内文をコピー」「取り消す」。
- **受け取る**: 答えを開き、届いた答えを確かめ（下の「信用しない」）、書類は指紋（SHA-256）・形（見出しのバイト）・大きさが答えの一覧の申告と合うものだけを受け取る。世帯に入れて**世帯ファイルに書けてから**サーバーから消す（書けなければ消さない。もう一度受け取れる）。
- **取り込む**: Excel と同じ受け皿（`filledOf`。管理の値はアプリの側の依頼の記録から作る）にそろえ、選んだ項目だけを残したシート定義（`importDefinition`）で `importAnswers` に通し、今の取り込みの画面（候補・新規と変更・要確認・矛盾・推定の印）で FP が承認する。承認すると「取り込み済み」。
- **受け取った書類**: その世帯の書類として開く（画像は `createImageBitmap` でキャンバスに描く。`img` の URL にしない。0016）・保存する（平文の書き出しの出口。種類 `HearingDocument`）・消す（写し終えたら）。書類のお願い（0102）の一覧に「Web で頼んでいます」「Web で届いた（N）」「手元にない」「あとで送る」が出る。
- **通信**: 画面は通信しない。本体の命令 `hearing_web_call` だけが、配布元の設定の `[hearing_web]` の `relay` の https のホストに、決まった道（FP の動きだけ）で話す。お客さまのページの URL は `hearing_web_config`。**開発用のビルド（debug）だけ**、環境変数 `FINANCIA_DEV_HEARING_RELAY`・`FINANCIA_DEV_HEARING_PAGE` でこの PC の中の受け付け（`wrangler dev`）を向ける。開発用のサーバー（vite）は同じ所の `/api/hearing/v1` で受け付けの処理をメモリの置き場で動かし（`FINANCIA_DEV_HEARING_RELAY` があればそこへ回す）、`/h/` にお客さまのページを出す。
- **元に戻す**: 依頼の記録は元に戻す・やり直すで前の状態に戻さない（サーバーの状態と食い違うため。控え・明細の記録と同じ扱い）。

### 5. お客さまの側（`app/src/hearingForm/`。アプリと同じリポジトリで作る静的なページ）

- **作り**: Preact の1ページ。`npm run build:hearing-form` で `app/dist-hearing-form/h/` に作る。外のスクリプト・フォント・画像を読まない（端末の文字を使う）。CSP は `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' blob:; connect-src 'self'; …; frame-ancestors 'none'`（meta とサーバーの見出しの両方。`blob:` は選んだ写真の縮小の表示だけ）。HTML の script・link に完全性の印（integrity）を付け、配るファイルの指紋を `fingerprints.json` に書く。FP のアプリの見本も同じ部品（`Form.tsx`）を使う（lint で、作業の層・本体の命令・エンジンを読めなくしてある）。
- **流れ**（`hearing/src/web/flow.ts`）: 最初の画面（事務所の名前と色・何のための問いか・名前を書かない・聞かないこと・期限・個人情報の窓口）→ 同意（0014。シートの同意の3つ）→ 問い（1画面に1つ。生年月と年齢、金額とその「だいたいの範囲」は同じ画面）→ 送っていただきたい書類 → 確かめの画面（全部の答えを見直し、「直す」でその問いに移り、確かめに戻る）→ 送った後の画面（送れたこと・FP に知らせてほしいこと）。
- **進み具合・戻る／次へ・「わからない」「当てはまらない」（項目ごとの言葉。例: 働いていない・卒業した・進学しない）・「あとで」**。
- **答えに合わせて問いを飛ばす**: 分岐の問い（配偶者の方がいるか・お子さまの人数・住宅ローンの本数・保険の件数）は答えの一覧に入れず、決まった答えに写す（配偶者の方がいない → 配偶者の方の生年月・年齢・ご結婚の形を「該当なし」。人数を超える分は出さない＝未回答）。項目ごとの条件は表（働いていない人の仕事の問い・自営業の給与・会社役員だけの会社とのお金・持ち家だけのローンと固定資産税・賃貸と社宅だけの家賃・協会けんぽだけの都道府県・亡くなったご両親の年齢・収入保障保険だけの年金月額など）。前の答えがまだ無いときは出す（飛ばしすぎない）。見えなくなった問いの答えは送らない（下書きには残す）。記入の年月は送った月をページが入れる（問いにしない）。
- **入れやすさ**: 金額は単位（万円・円、月あたり・1年あたり）を横に出し、万円は「＝ 5,200,000円」と円で見せる。年月は年（和暦つき）と月の選択。数字は全角・桁区切りも受ける。記入例・転記の手引きを出す（シートの手引きの「該当なし」は画面の言葉に直し、分岐の問いで聞くことの文は外す）。
- **途中で閉じても続きから**: 下書き（答え・分岐の答え・付けた書類の番号）は、この端末のこのブラウザの保存機能に、依頼の鍵から導いた鍵で暗号化して置く（31日より古いものは読まない。送ったら消す）。開き直すと「続きから」で、まだの最初の問いへ。書類のファイルそのものは付けたときに暗号化してサーバーに置くので、下書きには番号だけ。
- **書類**: 書類ごとに「撮る」（カメラ）・「ファイルを選ぶ」・「手元にない」・「あとで送る」。状態（まだ・付けました（N）・手元にない・あとで送る）を一目で出す。撮る前の注意を出す（全体が写るように・マイナンバーや基礎年金番号・証券番号・口座番号は写さないか隠す・何枚かに分けてよい・ほかのものを写さない）。
- **書類の形と大きさ**（`hearing/src/web/documents.ts`）:

  | 決め | 値 |
  |---|---|
  | 受け付ける形 | JPEG・PNG・HEIC（HEIF）・PDF。見出しのバイトで決める（名前・ブラウザの申告は信用しない）。SVG・HTML などは断る |
  | 写真 | 送る前にブラウザで長い辺 2000 画素に縮め、JPEG に描き直す（撮った場所などの付いた情報も落ちる）。描けない HEIC は上限の中ならそのまま |
  | 1ファイル | 10MB まで（縮めた後） |
  | 1つの依頼の合計 | 40MB まで・20ファイルまで・1通の書類に6ファイルまで |
  | 有効期限 | 依頼と同じ（最長30日）。FP が受け取ったら消す |

- **見た目**: スマホを先に。文字は 18px から、押す所は 52px の高さ。事務所の基調の色（0121。白地で読める濃さに直したもの）を上の帯・ボタンに使う。

### 6. 届いた答えを信用しない

- 答えの中身の形（形式名・版・依頼番号）を確かめ、依頼番号がアプリの側の記録と違えば受け取らない。
- 選んでいない項目・繰り返しの範囲の外・その項目で選べない状態・重なり・形の違う値は捨てて数え、FP に知らせる（「形の違う答え N は捨てました」）。文の長さに上限。
- 取り込みの管理の値（シートID・版・依頼番号・顧客番号・指紋）はアプリの側の記録から作る（0018 の5。届いたものを使わない）。
- 書類は、答えの一覧に載せたファイルだけを受け取り、指紋・形・大きさが合わないものは受け取らない。
- 改ざんされた暗号文・別の依頼や書類の暗号文は開けない（E_WEB_DECRYPT。受け取らない）。

### 7. 答えの受け皿と記録

- 答えは Excel と同じ回答の一覧（`Answer[]`）。取り込みの記録（0011 の imports）・同意の記録の下書き（0014。方法は今までどおり `hearingSheet`＝ヒアリングの同意欄。依頼番号で Web の依頼と分かる）も Excel と同じ。
- 依頼の記録は `hearing.web`（世帯ファイルの取り込みの記録の区画）。1件に、依頼の記録（依頼番号・サーバーの上の名前・鍵の組と合言葉・選び方・指紋・顧客番号・発行と期限の日時・URL）・状態・受け取った答え・受け取った書類（base64url。1世帯 40MB まで）・取り込んだ日時。
- **選び方の指紋**（0018 の5 の配置の指紋に当たるもの）: 元のシート・区画と項目の並び・聞き方・独自の質問のキー・書類の ID と種類の SHA-256（言い回しは入れない）。管理の値の `layoutDigest` に入れる。

### 8. 世帯ファイルの形式 0.63

## 理由

- **鍵をフラグメントに**: サーバーに鍵が届かない形を、アカウントも鍵の配りも無しに作れる。お客さまの手間は URL を開くだけ。
- **FP の公開鍵あてに暗号化**: 問いの鍵だけで答えも暗号化すると、URL が漏れたときに送った答えまで読まれる。公開鍵あてなら、URL を持つ人が読めるのは問いだけ。
- **合言葉を2つに分ける**: 送るとき（お客さま）と受け取り・消すとき（FP）の権限を分ける。送るときの合言葉は鍵の元から導くので、URL のほかに渡すものが無い。サーバーの上の名前だけを知る人（サーバーの記録を見た人）は、送ることも受け取ることもできない。
- **R2**: 書いた直後から同じものが読め、条件つきの書き込みで「1回だけ」を守れる。大きな書類を置ける。KV は整合が遅れて届く（1回だけを守りにくい）。
- **答えの受け皿を Excel と同じに**: 取り込みの手順・候補の画面・同意の記録・取り込みの記録を作り直さずに済み、Excel と Web で同じ答えなら同じ候補になる。
- **元のシートを1つに**: 簡易の票の項目は詳細の票の項目に読み替えて取り込むので、両方の項目を1つの依頼に混ぜると、片方の答えでもう片方が上書きされる。
- **書類を世帯ファイルに**: 利用者の判断（受け取った書類をその世帯の書類として開ける・保存できるように）。保存の場所と暗号化を世帯ファイルと世帯の鍵（0013）にそろえれば、鍵置き場と完全削除（0013 の5）がそのまま効く。別の置き場を作ると、削除と同期の決まりを作り直すことになる。

## 代案（採らなかったもの）

- **問いの鍵だけで答えも暗号化する**: URL が漏れると送った答えも読まれる。
- **FP のアカウントを作り、サーバーで FP を見分ける**: アカウントと鍵の配りが要り、提供元が FP と顧客の結びつきを持つことになる。
- **KV に置く**: 期限で消える仕組みはあるが、整合が遅れて届くので「答えは1回だけ」を守れない。大きな書類を置きにくい。
- **書類を別のファイルにする**: 世帯の鍵と完全削除の決まりを、別の置き場で作り直すことになる。1世帯の上限（40MB）と「写し終えたら消す」で世帯ファイルの大きさを抑える。
