# 0077. 説明は「?」の中・推定の根拠は押したとき（入力のホームの上部とプランの選択の手直し）

- 状態: 採用（2026-10-27）
- 固定の強さ: 内部（画面の見せ方）。計算・保存・世帯ファイルの形は変えない。「画面に常に出す文字は欄の名前・値・状態の印・操作の名前まで」「説明は共通の『?』の部品の中」「推定の根拠は印を押したとき」の3つは、ほかの画面にも当てる決まり（変えるときは追記に書く）。文の中身・並び・色は後から変えてよい
- 前提にする記録: 0041（値の状態の操作）、0043（入力画面でプランを直す）、0045（14枚のカード）、0072（入力のホームの仕上げ）。

## 背景

- 入力の画面に説明の文が多すぎて、どこを見ればよいか分かりにくい、という使う人の感想があった。入力のホームの上部には、説明の段落（2か所に同じ文）・進み具合・全部のカードの入れ方・小さな結果・編集の対象・控え・FP の道具・取り込む・確かめの一覧・最初の5枚の案内が、ばらばらの行に9行ほど並んでいた。
- 編集の対象でプランを選ぶと、画面全体の左に色の帯が出て中身が右へずれ、上部の行の数も変わっていた（画面が動く）。
- カードは一覧性のために7列に小さくしていた（0045）が、前の大きさ（4列）の方が見やすいという感想があった。
- 退職金・企業年金・介護・相続・贈与のカードは、専用の絵ができるまでほかのカードの絵を借りていた。
- 入れ方の「簡易」という言葉は、お客さまの前の画面で手抜きの印象を与えるおそれがある。

## 決定

### 1. 説明の「?」の共通の部品（`app/src/presentation/Help.tsx`）

- 丸に「?」のボタン。カーソルを合わせる・キーボードでフォーカスする・押す（タッチ）のどれでも説明が開く。押すと開いたままになり、もう一度押す・Esc・外を押す・フォーカスが外へ出ると閉じる。Esc は入力のパネルを閉じるより先に受ける（説明だけを閉じる）。
- 開いた説明は画面に重ねて出す（`position: fixed`。周りの配置を動かさない。画面の端ではみ出さない位置に置く。transform のかかった枠の中でも同じ位置）。
- 説明の文は閉じている間も隠して置き、ボタンの `aria-describedby` で読み上げに渡す。ボタンの名前は「○○の説明」、開閉は `aria-expanded`。
- 「?」の代わりに印（例: 欄の「推定」の札）を押して開く形も同じ部品で作る（`mark`）。
- 開き方の決まりは純粋な関数 `helpNext` にし、テストで確かめる。

### 2. 画面に常に出す文字

- 画面に常に出すのは「欄の名前・値・状態の印・操作の名前」まで。使い方の説明・注意・制度の説明は「?」の中へ移す。同じ文を2回出さない。
- ただし、入れ間違いを防ぐのに要る短い一言（単位・読み替えた時点など）と、状態の知らせ（未入力の所・使えない理由）は残してよい。

### 3. 入力のホームの上部（2行）

- 1行目: 見出し「入力」と「?」・確かめの一覧・進み具合。2行目: 編集の対象と道具（控え・FP の道具・取り込む）。開いた中身（控え・FP の道具・取り込むの中身・違いの一覧・確かめの一覧）は2行目の下に幅いっぱいで出す。最初の5枚の案内は今のまま（閉じたら出さない）。
- 外した物: 説明の段落（「カードを押すと…暗号化して自動で保存します…」）、入力のホームの上の「入力（現状）を直すと、保存したプラン（○件）にも反映されます…」、編集の対象の横の同じ文。中身は見出しの「?」と編集の対象の「?」へ（1回だけ）。
- **小さな結果（金融資産の見込みの線と足りなくなる年）を外した**（0072 の2。`input/MiniResult.tsx` を消した）。結果はタブで見る。
- **全部のカードの入れ方の一括の切り替え（「入れ方（全部のカード）」）を外した**（0072 の2）。入れ方はカードごとに、パネルの見出しの切り替えで変える（入力のホームの中で、カードごとに覚える。世帯ファイル・設定には書かない。URL の `#level=detail` は、まだ切り替えていないカードの初めの入れ方として読む）。一括の値を保存した設定は前から無いので、古い値を読む心配は無い。
- **入れ方の言葉を「標準／詳細」にした**（画面の言葉だけ。コードの識別子 `simple`・世帯ファイル・計算は変えない）。万一のタブの前提の欄の形式（0071）も同じ言葉にする。ヒアリングシートの「簡易版」は入れ方の意味ではないので変えない。

### 4. 編集の対象（プランの選択）

- プランの色は、編集の対象の箱の枠と左の小さな点だけに使う。画面全体の色・左の帯は出さない。今どのプランを直しているかは、箱（枠の色・点・選んだプランの名前）で分かる。
- **プランを選んでも、上部とカードの配置は1ピクセルも動かさない**:
  - 箱の中の並びは現状とプランで同じ（点・編集の対象・「?」・「プランの操作 ▾」）。枠の太さは同じで色だけ変える。違いの一覧・結果を見る・新しいプラン（現状から・複製・土台に）は「プランの操作」の中に重ねて出す。
  - 取り込むはボタンのまま（開くと「○○の編集中は取り込めません」と「現状に切り替える」）。確かめの一覧のボタンの文は現状とプランで同じ（いつも現状を直すことは「?」の中）。
  - カードの「プランB: 1か所」は絵の右上に重ねる札にする（カードの高さを変えない。プランの色にしない）。カードの「当てはまらない」「目安で入れる」は、プランの編集中も出したまま押せない形にする。
  - 入力で直せない理由（結果のタブに保存していない変更がある）は「入力では直せません」の印にし、押すと理由が開く。
- テスト: 差分の無いプランを選んだ前後で、上部とカードの骨組み（要素と class の並び）が同じこと。色だけを変える class は CSS で色だけであることを確かめる。

### 5. カードの大きさと絵

- カードの並びを前の形に戻す: 4列（1180px 以下で3列）・間 18px、文字を大きくしたときは3列（1180px 以下で2列）。カードの中の余白・名前・要約の数字の大きさも前の大きさに戻す（進み具合で絞る・状態の印の位置は今のまま）。
- 退職金・企業年金・介護・親・相続・贈与に専用の絵を足した（ほかのカードと同じ作り方。CC0）。どのカードも別の絵であることをテストで確かめる。

### 6. カードのパネルの説明・推定の根拠・入力例

- **欄の説明**（`help`・読むだけの理由 `readOnly`・ほかへの影響 `sideEffects`・時点の欄の月の決まり `monthOnly`）は、欄の名前の横の「?」の中へ（`FieldViews.tsx`）。欄の下に常に出すのは、入れた文字の問題・注意（`warn`・`derived`）・時点の読み・出来事の状態だけ。
- **区画・まとまりの説明**（`SectionDef.note`・`GroupDef.note`・操作だけのまとまりの説明）は、見出しの横の「?」の中へ。ただし頭の状態の言葉「まだありません」は画面に残す（`splitNote`）。
- **パネルの見出しの下の説明**（カードの説明と「空欄は推定で補う・✓ この値で確定」の決まり）は、見出しの「?」の中へ。保存の横の1行は状態（推定のままの欄の数）だけにし、保存すると何が起きるかは「?」の中へ。
- 専用の部品の説明（貯蓄・運用の区画の説明と入れ方の説明・保険の保障の見え方の線の説明と病気の前提・年金の見込み・受け取りの並び・前提と推定の一覧・相続税の目安）も、見出しの横の「?」の中へ。
- **推定の根拠**: 欄の「推定」「仮」「わからない」「未入力」の印は、根拠があれば押せる印にし（`StateMark`。同じ「?」の部品の `mark`）、押すと根拠が開く。欄の下の「推定: …」の1行は出さない（専用の部品の欄の `FieldStateLine` も同じ）。欄の横の読みのうち長い推定の根拠（「推定あり: …」）も印にする。
- **確かめの一覧**: 推定・わからない・確かさの行の根拠は、行の「根拠 ▾」で開く（閉じた形では出さない）。未入力・確かめの注意・計算の知らせの行の文は状態の知らせなので、今までどおり出す。一覧の説明は見出しの「?」の中へ。
- **灰色の入力例**: 欄の種類ごとに入る幅（em）を決め（`input/placeholder.ts`。数の欄 8.3・時点の欄 9.3・年月 6.8・文字 15・貯蓄の表 5／3.4／2）、収まる例だけを使う。未入力の欄は「未入力」（前は「未入力（0円で計算中）」で途切れていた）、時点の欄の空欄の例は「空欄＝○○」が収まるときだけ、収まらなければ入れ方の例（「例: 60歳」など。空欄のときの読みは欄の下に出る）。年月の欄は 8em に広げた。どのカードのパネルの入力例も幅に収まることを、見本の世帯と空の世帯でテストする（`app/test/placeholder.test.ts`）。文字の幅の目安は全角 1em・半角 0.65em（見えない Chrome で測って合わせた）。
- 結果のタブの対策・万一の前提で同じ欄の部品を使う所は、名前を隠したまま「?」だけを出す。

## 理由

- 説明を「?」に入れると、画面は名前と値だけになり、見る所が減る。説明は消さずに、知りたいときに1か所で読める。部品を1つにすると、開き方・読み上げ・見た目がどこでもそろう。
- プランを選ぶたびに画面が動くと、どこを見ていたかを見失う。色を箱だけにすると、今のプランは箱を見れば分かり、ほかは現状と同じ見え方のまま比べられる。
- 小さな結果は、入力の画面では細かすぎて読み取れず、結果のタブと二重になる。全部のカードの入れ方は、カードごとの切り替えで足り、入れていない欄が一度に出たり消えたりする方が分かりにくい。

## 選ばなかった案

- 説明を小さな字で欄の下に残す: 字を小さくしても行の数は減らず、ごちゃごちゃは変わらない。
- 「?」をブラウザの title（ツールチップ）にする: タッチで開けず、キーボードでも読めない。
- プランの操作をボタンのまま並べ、現状のときは隠す: 選ぶと箱の幅が変わり、右にある道具が動く。

## 追記（2026-10-27）: 「?」の形と、開いた説明の文を選べるようにする

使う人から「?の字が大きく、丸の中央に収まっていない」「開いた説明の文をマウスで選んでコピーしたい」という声があった。

- **「?」は字ではなく SVG の線で描く**（`HELP_GLYPH`）。字の上下の余白（アセント・ディセント）はフォントで違い、`line-height: 1` でも丸の中央から下へずれ、上が丸の線にかかっていた。SVG は丸の内側いっぱいの正方形に描き、字の外形（線の太さを含む）の中心を正方形の中心に置く。字の高さは内側の6割以下（前より少し小さく）。寸法は em で決まるので、文字の大きさ（中・大）・置き場所（見出しの横・欄の名前の横・保存の横）のどれでも同じ形で中央になる。ボタンは `box-sizing: border-box`（枠の線の太さで内側がずれない）。「推定」の札などの印（`mark`）は今のまま字で出す。
- **カーソルを「?」から箱へ動かす途中で閉じない**: 外れてから閉じるまで 300ms 待ち（`HELP_LEAVE_MS`。その間に「?」か箱へ戻れば閉じない）、「?」と箱のすき間（6px）は箱の見えない帯（`::before`、箱が上に出るときは下側）で埋める。箱は「?」と同じ包みの中なので、箱の上にカーソルがある間は開いたまま。開閉の待ちの決まりは `helpHoverGate`（タイマーを渡して画面の外で確かめる）。
- **箱の文は選んでコピーできる**: 箱の中を押したときにフォーカスを止めていた処理（`mousedown` の既定の動きを止める）をやめ、箱を `tabindex="-1"` にしてフォーカスが箱へ移るようにした（「?」の外へ出たと見なさない。フォーカスが「?」と箱の両方の外へ出たときに閉じる）。箱は `user-select: text`（親が選べない設定でも選べる）。
- **箱の中で押す・ドラッグするのは周りへ伝えない**: 箱の `pointerdown`・`mousedown`・`click` は親へ伝えない（下の欄・パネル・つかむ帯が動かない）。欄の名前（`label`）の中に置いたときは、押しても欄へフォーカスが移らないようにする。箱の中で押したままカーソルが外へ出ても閉じず、離したあと外にいれば待ってから閉じる。
- 押して開いたまま（固定）のときも同じように選べる。Esc・外を押す・もう一度押すで閉じるのは今のまま。
- テスト: `app/test/help-mark.test.ts`（字の外形の中心・大きさ・SVG で描くこと、箱へ移る間に閉じないこと、箱の中の選択で閉じないこと、選べる設定）。

## 追記（2026-10-27）: ホームは5列・画面では「入力項目」と呼ぶ・「＋」で足した物を見せる

- **ホームは5列**（5章を改める）: 14項目と最後の「＋ 項目を追加」の15個が 5列×3段に収まる（間 18px）。1339px 以下は3列（3列×5段）、820px 以下は2列、520px 以下は1列。文字を大きくしたとき（`html.big`）は今のまま3列（1180px 以下で2列）。5列のときは絵を少し縦長（10:7）にし、4列のときと同じくらいの高さを保つ。絵の高さはどの列でも 200px まで（文字の大きさは変えない）。数が増えても並びは次の段に続き、「＋ 項目を追加」はいつも最後。
- **画面では「カード」と言わず「入力項目」と呼ぶ**（文の中で短くするときは「項目」。例:「最初の5項目」「働き方と収入の項目で入れます」）。進み具合の「14項目中」とそろえる。入力項目の中の1つずつは今のまま「欄」。画面・確かめの一覧・「?」の中・知らせ・ヒアリングの取り込みの文を直した。コード・識別子・設計記録の用語（カード・`ih-card` など）は変えない。結果の側の「カード」（結論のカード・3つの箱の「内訳を見る」）と、お金のカード（クレジットカード・カードローン・明細）は別の物なので変えない。

## 追記（2026-10-27）: FP の操作は上の帯の FP のメニューにまとめる

使う人の判断で、入力のホームの上部にあった「控え」「FP の道具」「取り込む」の行を、顧客と一緒に見る画面に常に出すのをやめる（3 を改める）。
