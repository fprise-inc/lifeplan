# 0077. 説明は「?」の中・推定の根拠は押したとき（入力のホームの上部とプランの選択の手直し）

- 状態: 採用（2026-10-27）
- 固定の強さ: 内部（画面の見せ方）。計算・保存・世帯ファイルの形は変えない。「画面に常に出す文字は欄の名前・値・状態の印・操作の名前まで」「説明は共通の『?』の部品の中」「推定の根拠は印を押したとき」の3つは、ほかの画面にも当てる決まり（変えるときは追記に書く）。文の中身・並び・色は後から変えてよい
- 前提にする記録: 0041（値の状態の操作）、0043（入力画面でプランを直す）、0045（14枚のカード）、0072（入力のホームの仕上げ）。

## 背景

- 入力の画面に説明の文が多すぎて、どこを見ればよいか分かりにくい、という使う人の感想があった。入力のホームの上部には、説明の段落（2か所に同じ文）・進み具合・全部のカードの入れ方・小さな結果・編集の対象・控え・FP の道具・取り込む・確かめの一覧・最初の5枚の案内が、ばらばらの行に9行ほど並んでいた。
- 編集の対象でプランを選ぶと、画面全体の左に色の帯が出て中身が右へずれ、上部の行の数も変わっていた（画面が動く）。
- カードは一覧性のために7列に小さくしていた（0045）が、前の大きさ（4列）の方が見やすいという感想があった。
- 退職金・企業年金・介護・相続・贈与のカードは、専用の絵ができるまでほかのカードの絵を借りていた。
- 入れ方の「簡易」という言葉は、お客さまの前の画面で手抜きの印象を与えるおそれがある。

## 決定

### 1. 説明の「?」の共通の部品（`app/src/presentation/Help.tsx`）

- 丸に「?」のボタン。カーソルを合わせる・キーボードでフォーカスする・押す（タッチ）のどれでも説明が開く。押すと開いたままになり、もう一度押す・Esc・外を押す・フォーカスが外へ出ると閉じる。Esc は入力のパネルを閉じるより先に受ける（説明だけを閉じる）。
- 開いた説明は画面に重ねて出す（`position: fixed`。周りの配置を動かさない。画面の端ではみ出さない位置に置く。transform のかかった枠の中でも同じ位置）。
- 説明の文は閉じている間も隠して置き、ボタンの `aria-describedby` で読み上げに渡す。ボタンの名前は「○○の説明」、開閉は `aria-expanded`。
- 「?」の代わりに印（例: 欄の「推定」の札）を押して開く形も同じ部品で作る（`mark`）。
- 開き方の決まりは純粋な関数 `helpNext` にし、テストで確かめる。

### 2. 画面に常に出す文字

- 画面に常に出すのは「欄の名前・値・状態の印・操作の名前」まで。使い方の説明・注意・制度の説明は「?」の中へ移す。同じ文を2回出さない。
- ただし、入れ間違いを防ぐのに要る短い一言（単位・読み替えた時点など）と、状態の知らせ（未入力の所・使えない理由）は残してよい。

### 3. 入力のホームの上部（2行）

- 1行目: 見出し「入力」と「?」・確かめの一覧・進み具合。2行目: 編集の対象と道具（控え・FP の道具・取り込む）。開いた中身（控え・FP の道具・取り込むの中身・違いの一覧・確かめの一覧）は2行目の下に幅いっぱいで出す。最初の5枚の案内は今のまま（閉じたら出さない）。
- 外した物: 説明の段落（「カードを押すと…暗号化して自動で保存します…」）、入力のホームの上の「入力（現状）を直すと、保存したプラン（○件）にも反映されます…」、編集の対象の横の同じ文。中身は見出しの「?」と編集の対象の「?」へ（1回だけ）。
- **小さな結果（金融資産の見込みの線と足りなくなる年）を外した**（0072 の2。`input/MiniResult.tsx` を消した）。結果はタブで見る。
- **全部のカードの入れ方の一括の切り替え（「入れ方（全部のカード）」）を外した**（0072 の2）。入れ方はカードごとに、パネルの見出しの切り替えで変える（入力のホームの中で、カードごとに覚える。世帯ファイル・設定には書かない。URL の `#level=detail` は、まだ切り替えていないカードの初めの入れ方として読む）。一括の値を保存した設定は前から無いので、古い値を読む心配は無い。
- **入れ方の言葉を「標準／詳細」にした**（画面の言葉だけ。コードの識別子 `simple`・世帯ファイル・計算は変えない）。万一のタブの前提の欄の形式（0071）も同じ言葉にする。ヒアリングシートの「簡易版」は入れ方の意味ではないので変えない。

### 4. 編集の対象（プランの選択）

- プランの色は、編集の対象の箱の枠と左の小さな点だけに使う。画面全体の色・左の帯は出さない。今どのプランを直しているかは、箱（枠の色・点・選んだプランの名前）で分かる。
- **プランを選んでも、上部とカードの配置は1ピクセルも動かさない**:
  - 箱の中の並びは現状とプランで同じ（点・編集の対象・「?」・「プランの操作 ▾」）。枠の太さは同じで色だけ変える。違いの一覧・結果を見る・新しいプラン（現状から・複製・土台に）は「プランの操作」の中に重ねて出す。
  - 取り込むはボタンのまま（開くと「○○の編集中は取り込めません」と「現状に切り替える」）。確かめの一覧のボタンの文は現状とプランで同じ（いつも現状を直すことは「?」の中）。
  - カードの「プランB: 1か所」は絵の右上に重ねる札にする（カードの高さを変えない。プランの色にしない）。カードの「当てはまらない」「目安で入れる」は、プランの編集中も出したまま押せない形にする。
  - 入力で直せない理由（結果のタブに保存していない変更がある）は「入力では直せません」の印にし、押すと理由が開く。
- テスト: 差分の無いプランを選んだ前後で、上部とカードの骨組み（要素と class の並び）が同じこと。色だけを変える class は CSS で色だけであることを確かめる。

### 5. カードの大きさと絵

- カードの並びを前の形に戻す: 4列（1180px 以下で3列）・間 18px、文字を大きくしたときは3列（1180px 以下で2列）。カードの中の余白・名前・要約の数字の大きさも前の大きさに戻す（進み具合で絞る・状態の印の位置は今のまま）。
- 退職金・企業年金・介護・親・相続・贈与に専用の絵を足した（ほかのカードと同じ作り方。CC0）。どのカードも別の絵であることをテストで確かめる。

## 理由

- 説明を「?」に入れると、画面は名前と値だけになり、見る所が減る。説明は消さずに、知りたいときに1か所で読める。部品を1つにすると、開き方・読み上げ・見た目がどこでもそろう。
- プランを選ぶたびに画面が動くと、どこを見ていたかを見失う。色を箱だけにすると、今のプランは箱を見れば分かり、ほかは現状と同じ見え方のまま比べられる。
- 小さな結果は、入力の画面では細かすぎて読み取れず、結果のタブと二重になる。全部のカードの入れ方は、カードごとの切り替えで足り、入れていない欄が一度に出たり消えたりする方が分かりにくい。

## 選ばなかった案

- 説明を小さな字で欄の下に残す: 字を小さくしても行の数は減らず、ごちゃごちゃは変わらない。
- 「?」をブラウザの title（ツールチップ）にする: タッチで開けず、キーボードでも読めない。
- プランの操作をボタンのまま並べ、現状のときは隠す: 選ぶと箱の幅が変わり、右にある道具が動く。
