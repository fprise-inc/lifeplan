# 0182. 面談の履歴（面談ごとの記録・お客さまと見てよい欄と FP だけの欄・保険の意向・その日の控え）と、メモを FP のメニューの中へ

- 状態: 採用（一部未確定）（2026-11-09）
- 固定の強さ: 区画の形（本文の区画 `meetings` の `version`・`records[]` の `id`・`on`・`shared`〔`talked`・`decided`・`todo`・`insurance`〕・`fpOnly`〔`note`・`insurance`〕・`snapshot`・`by`・`editedBy`）は世帯ファイルの形式（0011）として骨格。FP だけの欄を提示層・持ち帰り・提案書・AI に出さない決まりは 0016 の2 と同じ強さ。画面の作り・言葉・並び・欄の長さの上限は内部（後から変えてよい）。世帯ファイルの形式 0.74
- 前提にする記録: 0009（控え）、0011（世帯ファイルと移行）、0012（顧客の名前を持たない）、0016（画面の安全。提示層は内部情報を受け取らない）、0023（事務所での共有・書いた人・分岐）、0030（持ち帰り用のレポートの自由記述の洗い出し）、0074（面談の準備・前回から変わったこと）、0077（FP のメニュー）

## 背景

- 世帯ごとの記録は、FP 用のメモ（1行に1つの自由記述。0016 の2）と控え（その時点の写し。0009）しか無かった。面談を重ねると、「いつ・何を話して・何を決めて・次までに何をするか」がメモの行に混ざり、前回の面談を見返しにくい。
- 保険をおすすめするときは、保険業法の意向把握・意向確認の流れ（最初にうかがった意向・申し込む前に確かめた意向・その違い）を記録しておく必要がある。
- 上の帯に「メモ」のボタンが常に出ていた。お客さまと一緒に画面を見るときにも目に入り、帯の幅も取る。
- 利用者の判断（2026-11-09）:
  - メモは上の帯のボタンをやめ、FP のメニュー（カバンのアイコン）の中の「メモ」の行にする。件数は行の横に。開くと今と同じ引き出し。メモは「いつも気をつけておくこと」の置き場として残す。
  - 世帯ファイルの中に、面談ごとの記録を残す。中身は面談の日・話したこと・決めたこと・次までにやること。欄を「お客さまと一緒に見てよい欄」と「FP だけが見る欄」に分ける。
  - FP だけの欄は今のメモと同じ扱い（提示層・持ち帰り・提案書・AI に出さない）。お客さまと見てよい欄も、まずは画面で一緒に見るだけにする。
  - その日の控えとつなげる。1件を開くと、そのときの控えの数字と並べて見返せる。
  - 保険の意向の欄を最初から入れる（当初の意向・最終的な意向・違いがあればその理由。どれも任意）。意向はお客さまと確かめる物なので、既定は「お客さまと見てよい」側。
  - 事務所で共有しているときは、メモと同じく書いた人を残す。名前・連絡先の欄は作らない（顧客の名前を持たない。顧客管理の機能は持たない）。

## 決定

### 1. メモは FP のメニューの中へ（0016・0077 の追記）

- 上の帯の「メモ」のボタン（`memo-btn`）をなくし、FP のメニュー（`app/src/workspace/header/FpMenu.tsx` の `fpMenuGroups`）の最初の見出し「メモ・面談の履歴」に「メモ」の行を置く。行の横（note）に件数（「3件」。無ければ「まだありません」）。
- 押すと今と同じ右の端の引き出し（`MemoDrawer`）が開く。根拠の引き出しとは同時に出さない（今と同じ）。中身・書いた人の残し方（0023 の6）は変えない。
- 画面の確かめ用の `#memo` はそのまま使える。

### 2. 面談の履歴の形（本文の区画 `meetings`。形式 0.74）

- 世帯ファイルの本文に区画 `meetings` を足す（`{ "version": 1, "records": [...] }`。記録が無ければ区画を作らない。`household` の区画には置かない）。1件の形:

  ```json
  {
    "id": "（UUID）",
    "on": "2026-11-09",
    "shared": { "talked": "話したこと", "decided": "決めたこと", "todo": "次までにやること",
                "insurance": { "initial": "当初の意向", "final": "最終的な意向", "reason": "違いがあればその理由" } },
    "fpOnly": { "note": "FP のメモ" },
    "snapshot": "（つないだ控えの ID）",
    "by": "（書いた人のメンバーの内部ID）",
    "editedBy": "（最後に直した人のメンバーの内部ID）"
  }
  ```

- **2つの欄は入れ物で分ける**: お客さまと一緒に見てよい欄は `shared`、FP だけが見る欄は `fpOnly`。「見せない」を表示の印で持たず、入れ物で分ける（0016 の2 と同じ考え方。将来お客さまと見てよい欄を持ち帰り・提案書に出すときも、`shared` だけを許可リストで写せばよい）。
- **保険の意向**（`insurance`）は、どちらか一方の入れ物だけに入る。既定は `shared`。FP が「この意向を FP だけの欄にする」を選ぶと `fpOnly` へ移す。読むときに両方にあれば `fpOnly` を残す（見せる側に広げない）。
- **控え**は ID だけを持つ（控えの中身は写さない。控えを消すと「つないだ控えは外されています」と出し、記録は残す）。
- **書いた人**: 事務所で共有しているとき（自分のメンバーの内部ID があるとき）だけ。新しい記録は `by` を自分に、ほかの人が直したら `editedBy` をその人にする（書いた人が直したときは付けない）。画面から届いた `by` は使わない（前の記録のまま）。表示名は世帯ファイルの記録（`meta.editors`）と事務所の名簿から（メモと同じ）。
- **名前・連絡先の欄は作らない**（0012）。入力の画面に「お客さまの名前や連絡先は書かないでください」と添える。
- 読むときは `readMeetings`（`app/src/workspace/meetings/meetings.ts`）で形を確かめ、形の合わない記録・同じ ID の2つ目を捨てる。知らない欄（名前など）は持たない。欄は1つ 4000 字、記録は 500 件まで。
- 面談の履歴は元に戻す・やり直すの対象にする（メモと同じ。控えは対象にしない〔0009〕ので、記録を足すときに作った控えは、元に戻しても残る）。知らせの名前は「面談の履歴」。
- 計算の要求の外なので、変えても計算し直さない。

### 3. 画面（作業の層）

- 入口: FP のメニューの「メモ・面談の履歴」の見出しに「面談の履歴（N件）」の行（横に「前回 2026年11月9日」）。押すと入力のホームの上部の置き場（0077 の追記 2026-11-05）に開く（`app/src/workspace/meetings/MeetingTools.tsx`）。
- 一覧（新しい順）: 日・要点（決めたこと、無ければ話したことの1行目）・控えのあるなし・書いた人・「開く」。「＋ 面談の記録を足す」。
- 足す／直す: 面談の日（既定は今日）・お客さまと一緒に見てよい欄（話したこと・決めたこと・次までにやること）・保険の意向（当初の意向・最終的な意向・違いがあればその理由。「この意向を FP だけの欄にする」）・FP だけ（FP のメモ）・その日の控え（「この時点を残して、つなぐ」〔足すときの既定〕・「つながない」・今ある控え）。書いた欄も控えも無い記録は足さない（控えを作る前に確かめる）。
- 1件を開く: 左に記録（お客さまと見てよい欄・FP だけの欄を色で分ける。FP だけの欄はメモと同じ色）、右に「そのときの控えと今」（控えの時点の見込み・今の見込み・入力の違い。前回から変わったことの「前回との違い」と同じ部品 `SnapshotCompare`。0074）。狭い画面では上下。
- 「FP だけの欄を隠す（お客さまと一緒に見るとき）」: 入れると、一覧・開いた記録・入力の画面から FP のメモと FP だけにした意向を外す。
- 前回から変わったこと（0074）の「前回との違い」に「前回の面談の記録を開く（日）」を置く。比べる控えをつないだ記録があれば「この控えの面談の記録を開く」にして、その記録を開く。

### 4. 出さない所（0016 の2・0030）

- 提示層（`app/src/presentation/`）の部品は `PresentationModel` しか受け取らないので、面談の履歴は構造で入らない。
- 持ち帰り用のレポート（`app/src/takeaway/`）・提案書（report）は計算の要求と決まった欄からだけ作るので入らない。お客さまと見てよい欄も、今は入れない（未確定）。→ 2026-11-09 の追記で、持ち帰り用のレポートにだけ、最後の面談の「決めたこと」「次までにやること」を入れると決めた（提案書には入れない）。
- AI への提供（`crates/ai-share`）は計算の要求の入力からだけ縮約版を作るので入らない。
- 控え（0009）の写しにも入れない（控えは計算の写し。面談の記録は控えの ID を持つ側）。
- テストで、目印の文字を入れた面談の記録（両方の欄・両方の置き方の保険の意向）が、持ち帰り・提案書・提示層の部品・AI の縮約版・控えに出ないことを確かめる。

### 5. 世帯ファイルの形式 0.74 と、消えないこと

- 形式の版を `0.74` に上げた（本文の区画 `meetings` を足すだけの MINOR。前の版のアプリは区画を知らずに書き戻すと記録を落とすので、版を上げて閲覧だけにする）。本体の変換の段（0.73 → 0.74）は版だけを書き換える（前の版の世帯は記録が無い＝区画を作らない）。見本 `0.74/`（0.73 の見本に面談の記録2件を足した物）。
- 事務所の共有の分岐の「両方を残す」（0023 の7）: 控えと同じく両方の分岐の記録を残す。同じ記録を両方で直していたら、こちらの分を別の ID の写しにして足す（どちらも消さない）。
- ヒアリングの取り込み（承認）・控えを作ること・控えの持ち越し（元に戻す・やり直すのとき）・暗号化した見本の変換で消えないことをテストで確かめる。明細と書類の取り込みは記録の区画だけを入れ替え、世帯の残りはそのまま持つ（`putStatements`・`putDocuments`）。

## 理由

- **メモを FP のメニューへ**: お客さまと一緒に見る画面の帯に FP の物を出さない（0077 の考え方）。よく使う物なので、メニューの最初の見出しに置く。
- **入れ物で分ける**: 1つの記録の中に「見せてよい」「見せない」が混ざると、表示の印で分ける形は欄が増えるたびに漏れる。入れ物を分けておけば、出す側は `shared` だけを見ればよい。
- **区画を household の外に**: 面談の記録は計算の要求とも、いつも気をつけておくメモとも違う、積み上がる記録（控え・明細・書類の読み取りと同じ）。分岐で両方を残すときも区画ごとに扱える。
- **控えは ID だけ**: 控えは作った後に変えない写し（0009）。記録の側から指せば、控えを重ねて持たずに済む。
- **保険の意向を最初から**: 後から欄を足すと、前の記録に意向の欄が無いことになる。意向把握の記録の書き出しは、比較推奨の記録と一緒に作る（未確定）。

## 代案（採らなかったもの）

- 面談の記録をメモの行に日付つきで書く: 1件を開いて控えと並べられず、欄を分けられない。
- 欄ごとに「お客さまに見せる」の印を付ける: 印の付け忘れ・読み落としで漏れる（上の理由）。
- 1件ごとに控えの中身を写す: 控えと二重になり、世帯ファイルが太る。
- 面談の履歴を右の端の引き出しにする: 控えの数字と並べる幅が無い。

## 影響

- **後から変えると何が起きるか**: 区画の形を変えると、配った世帯ファイルの変換の段が要る。`shared`・`fpOnly` の分け方を崩すと、出さない決まりがテストだけで守られる形になる。
- **守るべき決まり**
  - 提示層・持ち帰り・提案書・AI に面談の履歴を渡さない（お客さまと見てよい欄を出すときは、`shared` だけを許可リストで写し、この記録を改める）。
  - 面談の履歴に名前・連絡先の欄を作らない。
- **テストで確かめること**: `app/test/meetings.test.ts`（形・読むときの確かめ・書いた人・区画の保存と読み戻し・分岐の両方を残す・控え・ヒアリングの取り込み・元に戻すの名前・FP のメニュー・画面の一覧と1件・FP だけの欄を隠す・前回から変わったことからの入口）、`app/test/store.test.ts`（0.74 の形）、`app/test/takeaway.test.ts`・`app/test/report.test.ts`・`app/test/layout.test.ts`（目印が出ない）、`crates/ai-share/tests/book.rs`（AI の縮約版に出ない）、`crates/household-store`（変換の段・見本 0.74）。
