# 0060. 相続・贈与のカードの中身（受け取る予定の見込みと時期の推定・不確かな行を入れる1押し・贈与する人は読むだけ・遺したい額・相続税の目安の見せ方と設定）

- 状態: 採用（一部未確定）（2026-10-27）
- 固定の強さ: 内部（画面の作り）。世帯ファイルに足した欄（相続税の目安の設定・遺したい額）は 0061。区画の並び・文言・推定の決め方・内訳の見せ方は後から変えてよい（変えたら追記に書く）

## 背景

- 0045 で相続・贈与のカードの枠を作り、受け取る予定の相続・贈与（入るお金の行）・相続で受け継ぐ借金・あげる贈与（出るお金の行）・贈与する人・今ある援助の読むだけの1行と、相続税の目安の1行（0039 の結果を読むだけ）を集めた。
- 相続の受け取る時期は、行を足すと「1年後」の年月が入るだけで、相手（親）の亡くなる見込みとつながっていなかった。見込み「不確か」の行は基本の計算に入らない（0044 の5）が、入れるには詳細を開いて印を付けるしかなかった。
- 相続税の目安は時点ごとの1行だけで、財産の内訳・相続人・含めていない決まりが見えず、目安の設定（不動産の評価の割合・葬式の費用・養子・相続人の数・FP が入れた額）を入れる所が無かった（0039 の10 で「世帯ファイルと入力画面に足す欄」とした物）。
- 「子にいくら遺したいか」を入れる所が無かった。
- 前提にする記録: 0039（相続税の目安）、0044（お金の行）、0045（14枚のカード）、0059（介護・親のカード）、0061（世帯ファイルに足した欄と形式 0.24）。

### 3. 遺したい額は表示だけ

- 取り崩しの逆算の条件にはしない（逆算の計算がまだ無い）。表の最後の年の金融資産と比べた1行だけを出す。計算の要求からは外す（0061）ので、入れても結果は同じ。

## 理由

- **受け取る時期を亡くなる見込みに付けた**: 親の年齢・亡くなる見込みを直すたびに相続の時期を直す手間と、ずれたまま忘れる誤りを無くす。介護の目安の始まり（0059）と同じ時点から決まる。
- **不確かな行を入れる1押しを簡易に出した**: 「入っていない」ことが見えても、入れる操作が詳細の奥だと、プランで比べる操作に届かない。
- **贈与する人を読むだけにした**: 1つの物は1つのカードにだけ出す決まり（0045）。贈与する人は世帯の外の家族（世帯ファイルでも世帯の外の家族の構成員で書く。0035）なので、介護・親のカードの区画に置く。
- **相続税の目安の内訳を出した**: 「かからない見込み」の根拠（財産と基礎控除）と、含めていない特例が見えないと、FP が額で直すかを決められない。

## 代案（採らなかったもの）

- 遺したい額を取り崩しの逆算の条件にする: 逆算の計算が入る回に、この欄をそのまま条件として読む。
- 受け取る相続の額を「親の遺産の総額から」出す（受け取る側の目安）: エンジンの相続税の目安に受け取る側の時点が無い（0039 の未確定）。計算が入る回に詳細の欄として足す。
- 相続税の目安を資産と負債のタブ・結果のグラフにも出す: 見せ方の回に決める（ここではカードと万一のタブ）。

  3. **一人の世帯の目安の題名**: 時点 `bothAfter`（表の最後の年の12月）の呼び方を、配偶者のいる世帯（結婚の予定も。計算エンジンは世帯の中のご本人・配偶者の財産を合わせる）は「二人とも亡くなった後」、一人の世帯は「表の最後の年」にした（`labels.ts` の `bothAfterLabel`）。パネルの目安の見出し（「表の最後の年（2077年）」）・ホームの要約の下の1行（「相続税（表の最後の年）: …」）・税理士などが出した額の欄と説明・区画「遺したい額」「相続税の目安の設定」の説明で同じ言葉にする。前は欄の名前だけが一人の世帯に合わせてあり、見出しと要約の1行は「二人とも亡くなった後」のままだった。
  4. **保存したときの札**: 物の無い入力項目を保存すると「該当なし」にする決まり（0045 の「当てはまらない」）はそのまま。見本を保存しないで開いているとき（0033 の 2026-11-10 の追記）も、パネルの「保存」は開いている間の世帯に同じ印を付ける（見本のファイルは変わらず、開き直すと「まだ入れていない」に戻る）ので、相続・贈与で何も入れずに保存すると「該当なし」になるのは決まりどおり。ただ、この項目の「物」の数え方が、あげる贈与の相手の孫・遺したい額・相続税の目安の設定（不動産の評価の割合・葬式の費用・相続人の数・税理士などが出した額など）を数えていなかったので、それだけを入れて保存しても「該当なし」になり、保存の前は遺したい額だけで「未入力（0円の所あり）」になっていた。これらも物に数える（事務所の既定値から写した不動産の評価の割合〔推定の印のあるもの〕は数えない）。要約は、行が無ければ「1人（あげる贈与の相手の孫）」「遺したい額 1,000万円」。あげる贈与の相手の孫は、介護・親の物には数えない（介護・親には読むだけの1行）。
- 2026-11-11（孫の番号の後続）: 呼び名の無い孫に番号を付けるのと同じ決まりを、兄弟姉妹・祖父母・親・ほかの家族にも当てる。同じ呼び方の人が2人以上なら、足した順に続柄の呼び方へ番号を付ける（「兄弟姉妹1」「兄弟姉妹2」、性別を入れた祖父母は「祖父1」「祖父2」、性別の値の無い祖父母・親は「祖父母1」「親1」。`labels.ts` の `memberLabels`）。呼び名のある人はそのまま、1人だけなら付けない、顧客に渡すファイルでは同じ続柄の呼び方の人が2人以上なら全員に番号が付くのも孫と同じ。ご本人・配偶者・子は今までどおり（子は「第1子」「離れて暮らす子1」で見分けられる）。入力の画面・面談の準備・ヒアリングシート・プランの動かす項目（AI接続口の一覧も）は同じ関数なので、どこでも同じ呼び方になる。
