# 0141. 家族・働き方と収入・退職金・企業年金・年金の入力項目の見せ方（子の仮の生年月と並び・続柄・加わる時期・離れて暮らす子・ひとり親の1行、詳細の欄の並び・役員報酬の月額・辞め方の自動・今の期間の終わり、退職一時金の前提の1行・種類の並びと選んで足す・制度が無い1押し、年金の書類の額は円・推定の付け方・書類の額の内訳）

- 状態: 採用（一部未確定）（2026-11-07）
- 固定の強さ: 内部（画面の欄・言葉・並び・足したときの仮の値・推定の印。世帯ファイルの形式の版・エンジンは変えない。世帯ファイルの値の形も変えない〔役員報酬は年額のまま・年金の額は円の整数のまま〕）
- 前提にする記録: 0046（家族）、0047（働き方と収入）、0057（退職金・企業年金）、0066（年金）、0067（年金の見込み）、0041（値の状態）、0077（説明は「?」の中）、0078（標準と詳細）、0130（言葉の決まり）、0131（欄の部品）、0133（働く最後の年齢の推定と年金の書類の欄）

## 背景

通しで入力を試した FP の声と、入力項目ごとの見直しで、次の見え方の問題が見つかった。

1. 「＋ 子」を2回押すと、2人とも同じ仮の生年月（双子として教育費の推定が同じ年に重なる）。
2. 子の生年月を入れると、子が生年月の順に並び直り、Tab で次に進むと同じ子の欄に戻る（打っている間に並びが変わる）。
3. 配偶者・子の続柄に「配偶者・親・祖父母」が並ぶ。子を「配偶者」にすると夫婦の関係の無い2人目の配偶者ができ、家族の入力項目から見えなくなる。親・祖父母を選ぶと黙って介護・親の入力項目へ移る。
4. 呼び名の例がご本人・配偶者にも「例: 上のお子さん」。詳細の欄の並びが標準と違う（呼び名が先頭）。配偶者の関係の読むだけの1行が「詳しく入れるの…」（無い言葉）で、詳細ではすぐ下の「夫婦の関係」と同じ中身を2回出す。
5. 「これから加わる（結婚の予定）」のチェックと「結婚の予定（加わる時期）」の2欄で、どちらを入れればよいか分からない（夫婦の関係の始まりとも別）。
6. 「＋ 離れて暮らす子への仕送り」が、一緒に暮らす子しかいない世帯にも出る（相手は独立の早い一緒に暮らす子）。離れて暮らす子を家族の入力項目から足せない。
7. ひとり親の世帯で、ひとり親と分かる表示が無い。児童扶養手当は計算しないのに「?」にも書いていない。**確かめると、ひとり親控除は配偶者と死別した後（万一の想定）だけ計算していて、離婚・未婚のひとり親の控除は計算していなかった**（エンジンの `tax.survivorStatus`）。
8. 詳細の年収と賞与の間に伸び方の2欄が入る。役員の「月の報酬（年額・賞与を除く）」は「月の」なのに年額で入れる。今の勤め先を推定で定年にしているのに、辞め方の先頭の「自動」が「自己都合（60歳前に辞めるので）」。今の働き方の期間の詳細の「終わり（最後の月）」が、定年後の予定の「定年」か「働く最後の年齢」と同じ物を2か所に出す。働いていない人にも定年後の予定が出る。協会けんぽの支部の初めの値（東京）に印が無く、人が選んだ値と見分けられない。定年・働く最後の欄の「誰の年齢で」に子が並ぶ。
9. 退職一時金の目安（例 1,806万円）の前提（勤続・辞め方・制度のある会社の平均）が「?」の長い文の中だけで、制度の無い勤め先を1回で入れられない。役員退職慰労金の見込みの計算の額が欄に出ない。種類の選択肢6つが働き方によらず並び、「＋ 足す」は種類を選ぶ前に足す（自営業はいきなり国民年金基金）。勤続期間の空欄の意味が「勤め先の期間」だけで年月が分からない。「万一亡くなったときの扱い」の説明が開いたままの欄で「▾ たたむ」（言葉の決まりで使わない言葉）。
10. 年金: 書類（ねんきん定期便・年金額改定通知書）は円で書いてあるのに、欄は万円（478,200円 → 47.82）。推計のしかたの5行の文が欄の横に常に出る。書類から入れても見込みに「推定」が付く。繰り下げた人も見込みの行は65歳からの額。書類からの見込みと書類の額の差の説明が無い。受け取り開始の灰色の文字が「例: 60歳」（繰上げを勧めるように見える）。自営業だけの人にも老齢厚生年金の受け取り開始の欄が出る。

## 決定

### 1. 家族（`stages/family.ts`）

- **2人目からの子の仮の生年月**: 世帯の中のいちばん下の子（これから生まれる子を除く）の3年後（`CHILD_SPACING_MONTHS`）。計算の基準の月より後になるなら基準の月。1人目は今までどおり（ご本人の32歳の年の4月か今年の4月）。仮の印は今までどおり。
- **打っている間に子を並び替えない**: 家族の入力項目の人の並び（`panelOrder`）は、ご本人・配偶者の後は世帯ファイルの並び（足した順）。生年月の順への並べ直しは、家族の入力項目を保存したとき（`sortChildrenByBirth`。`InputView.tsx` の保存。プランの編集中は並べ直さない）。呼び名（第1子・第2子）と計算は今までどおり生年月の順で読むので、並べ直しても結果は変わらない。
- **続柄**: 子・同居の家族の続柄は「子／その他の家族（同居の兄弟姉妹など）」だけ（`familyKindOptions`）。親・祖父母は介護・親の入力項目で足す旨を「?」に。前の版で別の続柄が入っている人は「（前に選んだ続柄）」で残す。**配偶者は続柄を選ばない**（「＋ 配偶者」で足した人。外すのは「この家族を外す」）。標準の欄の数は1つ減る（家族 8→7）。`labels.ts` の `KIND_OPTIONS` は変えない（ほかの所が使う）。
- **呼び名の例**: ご本人「例: 世帯主」、配偶者「例: パートナー」、子「例: 上のお子さん」、その他の家族「例: 弟」。
- **欄の並び**: 標準と同じ「続柄 → 生年月 → 性別」の後に、詳細で増える「1日生まれ → 呼び名 → 関係 → 加わる時期」。
- **生年月**: 年齢でも入れられる（0131 の3 の `ageInput` を当てはめた）。入力例は「例: 1985-04」、生まれる予定は今から2年後の年月（「例: 2028-10」）。
- **関係の1行**: 「「詳細」の「夫婦の関係」で直せます」（段階があれば「段階があります。…」）。標準だけの欄（`simpleOnly`。詳細ではすぐ下に夫婦の関係のまとまりがある）。夫婦の関係の欄は「関係の終わり」「この段階の始まり／終わり」（0130 の期間・段階の言葉）。
- **加わる時期の1欄**: チェックと時期の2欄をやめ、「加わる時期」（配偶者は「加わる時期（結婚の予定）」。空欄＝最初から）の1欄。配偶者は、時期を入れたら「これから加わる」（`expected`）にし、空にすると戻す。最初の夫婦の関係の始まりが空か前の加わる時期と同じなら、関係の始まりも同じ時点にする（違う月を FP が入れていれば変えない）。子の `expected` は「これから生まれる子」の意味なので、子の加わる時期では印を変えない。前の版で印だけ付けて時期が空の配偶者には、印を外せるチェック「これから加わる（前の版の印）」を残す。世帯ファイルは `expected` と `joins` のまま。
- **離れて暮らす子**: 家族の構成に「＋ 離れて暮らす子」（世帯の外の家族として足す。物は介護・親の入力項目に並び、生年月などはそこで直す）。「＋ 離れて暮らす子への仕送り」は世帯の外の子がいるときだけ（相手はその子）。世帯の外の家族の読むだけの1行に年齢を添える（「母（89歳）」）。
- **ひとり親の世帯**（計算の基準の月に配偶者が世帯にいなくて、一緒に暮らす子がいる。`singleParent`）: 読むだけの1行「ひとり親控除・児童扶養手当: 計算に入れていません」（「?」に「ひとり親控除は配偶者と死別した後〔万一の想定〕だけ計算に入れる。離婚・未婚のひとり親の控除は今は計算に入れていない。児童扶養手当・自治体の手当も計算しないので受け取っている額を入れる」）。入るお金の「＋ 手当・給付金」の名前を「＋ 児童扶養手当など」にする（足す行は同じ）。手当・給付金のボタンの「?」はどの世帯でも「児童扶養手当・自治体の手当（ひとり親の手当など）は計算に入れていません。受け取っている額を入れてください（児童手当は子ども・教育の入力項目で計算します）」。

### 2. 働き方と収入（`stages/work.ts`）

- **詳細の並び**: 年収（賞与を除く）→ 賞与 → 伸び率（年）→ 統計の年齢カーブ。伸びの欄の名前を「伸び率（年）」に（0130 の伸び方の言葉。既定は変えない）。
- **役員報酬を月額で**: 役員の標準の欄を「月の報酬（役員報酬の月額）」にし、月額で入れる（見せる値は年額÷12〔円未満は四捨五入〕、書くときは×12。世帯ファイルは年額のまま）。退職金の最終報酬月額と単位がそろう。名前に「月の報酬」を残したのは、入力の探す言葉の辞書（`searchWords.ts`）が「役員報酬」「給料」を「月の報酬」の欄に当てていて、この作業では辞書を直さないため（下の未確定）。
- **辞め方の自動**: 定年後の予定の定年で辞める期間（今の勤め先）で、辞め方が入っている（推定の定年か FP が選んだ値）なら、先頭の「自動」を「自動: 定年（定年後の予定の定年で辞めるので）」にし、選ぶと推定の定年（推定の印）に戻す。辞め方が空の前の世帯は、エンジンの自動の決まり（60歳前なら自己都合）のまま見せる（今までの「辞め方を定年にする」の注意も残る）。ほかの期間の「自動」は今までどおり空に戻す。
- **今の期間の終わり**: 今の働き方の期間の終わりが、定年後の予定の「定年」（定年を過ぎていないとき）か「働く最後の年齢」（その人の最後の期間）と同じ物なら、詳細の「終わり」を出さない（`endShownElsewhere`）。終わりの欄の名前は「終わり」（0130）。代わりに、**定年後の予定の無い人は働く最後の年齢を空にできる**（空は最後の期間の終わりを外す。0133 の5 の注意と推定に戻すボタンが出る。`clearLastEnd`）。定年後の予定のある人は空にできない（定年後の働き方を「働かない」にすると定年が働く最後になる旨を出す）。
- **働いていない人**: 今の働き方が「働いていない」（終わり無し）で、この後の働き方も無い人には、定年後の予定のまとまりを出さない（これから働くなら詳細の「＋ 働き方」）。
- **協会けんぽの支部**: 初めの値（東京支部）のまま作った期間に推定の印（根拠「既定の値（東京支部。勤め先の所在地の都道府県を選んでください。保険料率が支部ごとに違います）」。選び直すと外れる）。勤め先の従業員数・週の時間の印（0133 の7）と同じ所で付ける。
- **人の固定**: 定年・働く最後の年齢の欄は、その人の年齢だけで入れる（0131 の6 の `who: "fixed"`）。
- 「定年後の予定」の見出し・欄の名前は今のまま（利用者の判断。役員・自営業でも呼び分けない）。

### 3. 退職金・企業年金（`stages/retirement.ts`）

- **退職一時金の目安の前提の1行**（`amountHint`）: 目安のままの退職一時金の欄の横に「勤続38年（2006年4月〜2044年5月）・定年・制度のある会社の平均」（勤続と期間は目安の計算と同じ `spanOf`、辞め方は `endingOf`）。額を入れたら出さない。
- **役員退職慰労金の見込みの計算**: 欄の横に「120万円×在任24年×1.5倍＝4,320万円（見込みの計算）」（エンジンの `retirement.benefit` と同じく在任の月数を年に切り上げる）。公務員の退職手当は支給率の表で決まるので、今までどおり「見込みの計算で計算中（額は受け取りの並びに出ます）」。
- **勤め先に退職金の制度が無い**: 目安のままの退職一時金に1押しのボタン（外すと同じ動き。その人の退職給付が無くなれば該当なし。額を入れた退職金には出さない）。
- **種類の並び**: 勤め先の働き方でよく使う種類を先頭に（会社員「退職一時金・確定給付企業年金」、公務員「退職手当・年金払い退職給付」、役員「役員退職慰労金・退職一時金」、自営業「国民年金基金」）、ほかは「ほかの種類」の見出しの下（0131 の8 の `Option.group`）。世帯ファイルの種類は変えない。
- **「＋ 退職金・企業年金を足す」は種類を選んでから**: 1つのボタンの中の選択肢（0040 の追記の `choice`）。先頭は今までの既定の種類（鍵は前のボタンと同じ `retirement/<人>/add`）、ほかは `retirement/<人>/add/<種類>`。最初の1件で目安の種類を選んだら、今までどおり目安で入れる。
- **自営業の人**: 区画に読むだけの1行「小規模企業共済・iDeCo: 貯蓄・運用で入れます」。
- **勤続期間・在任期間の空欄の意味**: 空欄のとき使っている年月を添える（「2006年4月（勤め先の期間の始まり）」）。
- **万一亡くなったときの扱い**: 開いたままの説明の欄（「▾ たたむ」）をやめ、人の区画の「?」の中に入れる（0077 と言葉の決まり）。

### 4. 年金（`stages/pension.ts`・`pensionEstimate.ts`）

- **書類から写す額は円で入れる**（利用者の判断）: 老齢基礎年金・老齢厚生年金・経過的加算・特別支給の老齢厚生年金の額と、受け取っている遺族年金・障害年金の年額の欄の単位を円にした（`DOC_UNIT`。書類の数字をそのまま打つ。「78万」と打っても読む。0131 の `readYen`）。世帯ファイルは今までどおり円の整数。
- **推計のしかた**: 長い文（`ESTIMATE_HOW`）は入れ方の欄の「?」へ。欄の横は何から推計しているかの1行「推計: 2006年4月からの働き方（正社員→契約社員・嘱託（再雇用など））で計算しています」（働き方が無ければ「推計: 働き方の期間がまだありません…」。`estimateLine`）。
- **受け取り開始の灰色の文字**: 「空欄＝65歳から」（`blankMeans` と入力例。時点の部品は「空欄＝65歳から（標準）」が収まらないと入力例に戻るため、入力例にも同じ文）。
- **老齢厚生年金の受け取り開始**: 厚生年金に入った（入る）期間がある人だけ（働き方の期間の厚生年金の種別・書類の厚生年金の加入月数か額・加入歴の厚生年金の行。`hasEmployeePension`）。働き方をまだ入れていない人には出す（決められないため）。
- **年金の見込みの行**（`estimateView`）: 「推定」は推計（書類が無い）の人の分だけ（人ごとの行の後ろの「（推定）」、夫婦の合計・カードの要約の「・推定」は推計の人がいるときだけ）。受け取り開始を変えている人は、見込みの行を受け取り開始からの額にし、65歳からの額は「?」の中に。書類からの人（50歳以上の定期便・見込額・改定通知書）は「?」に内訳「書類の額 年205万円＋これからの加入・加給年金など 年44万円」（`documentAmount`。50歳未満の定期便は加入月数から計算するので出さない）。
- 推計が外れやすい人への「定期便の数字を入れてください」の知らせは出さない（利用者の判断。0133 と同じ）。

## 理由

- 打っている間に並び替えないのは、欄を離れたときに値を決める部品（0131 の2）で、Tab の次の欄が並び替えの後の別の子の欄になり、FP が気づかずに別の子の欄に打つため。保存のときに並べるのは、次に開いたときに生年月の順（呼び名の順）で見られるようにするため。
- 配偶者の続柄を選ばせないのは、続柄を変えると夫婦の関係と食い違い（見えない家族ができる）、選び直す意味のある選択肢が無いため。
- 加わる時期で配偶者の関係の始まりを合わせるのは、結婚の予定の月と入籍の月が同じことが多く、2か所に入れる手間と、片方だけ直したときのずれを防ぐため。FP が違う月を入れたら尊重する。
- ひとり親の1行を「計算に入れていない」にしたのは、確かめたら離婚・未婚のひとり親の控除を計算していなかったため（計算していると書くと誤り）。計算を足すのはエンジンの範囲で、この記録では見せ方だけ（下の未確定）。
- 今の期間の終わりを出さないかわりに働く最後の年齢を空にできるようにしたのは、0133 の5 の「終わりを決めていない」の形（注意と推定に戻すボタン）を入れられる道を残すため。
- 役員報酬の月額を世帯ファイルでは年額のまま持つのは、形式を変えずに済み、エンジン・ヒアリングシート・見本はそのまま読めるため。
- 年金の書類の額を円にしたのは利用者の判断（書類の数字をそのまま写せる。万円の欄に「478200」と打つと47億円になる誤りは読み取りの部品では防げない）。
- 年金の見込みの「推定」を推計の人だけにしたのは、書類からの人は書類の額が元で、推定の札が付くと書類を写した意味が見えなくなるため（0130 の推定の印は FP が入れていない値に付ける）。

## 代案（採らなかったもの）

- 子の並びを生年月の順のまま、打っている欄だけ動かさない: 並び替えのたびに Tab の行き先を直す仕組みが要り、部品が複雑になる。
- 「推計: 老齢基礎 年○万円・老齢厚生 年○万円（65歳から）」の人ごとの内訳: 見込みは計算の結果の表（行ごとの合計）から読むので、基礎と厚生の内訳が取れない。内訳のために計算を2回するか、エンジンの出力を足す必要がある（下の未確定）。
- 「＋ 世帯の外の家族」で介護・親の入力項目へ飛ぶボタン: 入力のパネルから別の入力項目を開く操作の部品が無い。読むだけの1行の「?」で入れる所を案内する。

## 影響
