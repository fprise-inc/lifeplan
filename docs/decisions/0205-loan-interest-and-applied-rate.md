# 0205. ローンごとの年ごとの利息とその年の金利をエンジンの要約に出し、AI接続口の主な数字・系列・グラフに使う（利息の合計・その年の金利）

- 状態: 採用（2026-11-11）
- 固定の強さ: エンジンの要約の欄 `summary.loans`（`object`・`kind`・`years[].interest`・`years[].rate`・`interestTotal`）と、部品の約束の欄（`debt.schedule` 約束の版 1.5 の `byYear`・`plan.cashflow` 約束の版 1.9 の `details.loans`）は足すだけの任意の欄（0005 の出力の形。前の出力を読む物は変わらない）。AI接続口の欄（`keyFigures.loanInterest`・`diff.loanInterest`・系列の `loanInterest`・`loanRate`・`omit` の `loanInterest`・`chart` の `interest`・`rate`・`figures` の `loanInterest`）は試験版（0015 と同じ）
- 前提にする記録: 0005（計算の実行環境と出力の形）、0008（負債の返済）、0015（AI接続口）、0028（年ごとの利息）、0136（5年ルール・繰上返済の未払利息）、0194（主な数字）、0198（比べる道具）、0202（感度）、0203（金利の見込みとグラフ）

## 背景

- 0203 で、AI接続口の比べる道具とグラフで、変動金利の上がり方を3通りにして比べられるようになった。しかし FP が知りたい「利息の合計は今のままで○万円、+2% で○万円」「10年後の金利は何%」は答えられなかった（0203 の未確定）。
- エンジンの負債の返済（`debt.schedule`）は、月ごとの利息（0028 の `interest`。かかった利息）を数えているが、表示の形の出力（表・要約）には無い。表の返済額から逆算すると、団信・借り換え・売ったときの返済・未払利息で合わなくなる。

## 決定

### 1. エンジン: ローンごとの年ごとの利息とその年の金利

- `debt.schedule`（改訂10・約束の版 1.5）: 年ごとの `byYear`（`year`・`interestPaid`・`rate`）を任意の欄で添える。計算基準月から・返済のある年だけ。計算は変えない。
  - **利息**は、返済のうち利息に充てた額: 毎月の返済とボーナス返済の利息（持ち越した未払利息を払った分を含む）、繰上返済・売ったときの返済で払った未払利息。返済額が利息に足りない月（125%ルール）は返済額の全部。借り換えで新しいローンに含めた未払利息は、新しいローンの元金として数える。団信で消えた未払利息は入れない。こうすると、その年の返済の行の合計＝元金に充てた額（年末の残高の減り）＋利息＋手数料・諸費用になる（テストで確かめる）。
  - **金利**は、その年の最後の返済に当てた金利（10進の文字）。金利の段階・変動金利の上乗せ（前提の `loanRateShifts`・ストレステスト `rateRise`）・借り換え後の金利を含む。
  - 0028 の `interest`（かかった利息。不動産所得の必要経費に使う）はそのまま。未払利息の無いローンでは同じ額になる。
- `plan.cashflow`（改訂28・約束の版 1.9）: 世帯の負債ごとに `details.loans`（`object`・`kind`・`years[]`〔`year`・`interest`・`rate`〕・`interestTotal`〔表の期間の合計〕）に写し、エンジンが要約 `summary.loans` に写す（0104 の `childScholarships` と同じ道）。ほかの部品が作る負債（自動車ローンのひな形・教育ローン・貸与の奨学金）は入れない（AI が ID で指せる世帯の負債だけ）。
- 計算の数字・表は変わらない。要約に欄が足されるだけで、Node・quickjs-ng・JavaScriptCore の出力は一致する（一致テストで確かめた）。

### 2. AI接続口

- 主な数字 `keyFigures.loanInterest`（住宅ローンの利息の合計）: 要約の住宅ローン（`kind` が `mortgage`）の利息を、`keyFigures.loanRepayment` と同じ年（画面の表に出す年）で足す（`connector/summary.ts`）。住宅ローンが無ければ 0。`compare` の `diff.loanInterest` が基本との差。
- 系列: `calculate` の `fields`・`compare` の `series` に `loanInterest`（住宅ローンの利息。年額）・`loanRate`（その年の住宅ローンの金利。10進の文字）を足す。選んだときだけ返す（既定の答えの大きさは変えない。0203 の住宅ローンの系列と同じ）。`loanRate` は、返済の無い年と、金利の違う住宅ローンを2本以上返している年は null（ローンごとの数字は `output: "table"` の `summary.loans`）。
- `omit` の `loanInterest`: 主な数字の利息の合計と、`output: "table"` の `summary.loans` を省く。
- `sweep`・`find_threshold` の `figures` に `loanInterest` を足す（選んだときだけ。既定の表の列は変えない）。
- `chart`: 種類 `interest`（住宅ローンの利息の推移。年額・万円）と `rate`（住宅ローンの金利の推移。縦の目盛りは %）を足し、棒の数字に `loanInterest` を足す。既定の種類（`assets`・`repayment`・`keyFigures`）と既定の棒は変えない。金利の目盛りは画面のグラフと同じ関数（`presentation/chart.ts` の `domainOf`・`scaleOf`）に、金利を 1億分の1 を1円とした整数で渡して作る（浮動小数点の掛け算をしない。`plans/decimal.ts` の `mulRate`）。使い方の例のプロンプト `chart_rate_paths` は、金利の推移と利息の合計も描くようにした。
- INSTRUCTIONS・道具の説明・`docs/ai-connector.md`（「住宅ローンの利息と金利」）に書いた。

### 3. 画面

- 画面の表・グラフは変えない（利息と金利の行は無い）。画面の関数で数える主な数字（`metricsOf`）とも別に、接続口の関数で数える。

## 見本の世帯での数字

`salariedCoupleTwoKids`（変動金利の住宅ローン1本・残高 2,240万円・今 0.65%・5年ルールと125%ルールあり・計算基準月 2026年10月）。表に出す年（2027年から）で数えた。

| 通り | 利息の合計 | 住宅ローンの返済の合計 | 2031年の金利 | 2036年の金利 |
|---|---|---|---|---|
| 今のまま | 約 181万円 | 約 2,400万円 | 0.65% | 0.65% |
| 10年で+1% | 約 335万円 | 約 2,554万円 | 1.15% | 1.65% |
| 10年で+2% | 約 505万円 | 約 2,724万円 | 1.65% | 2.65% |

## 理由

- エンジンが月ごとに数えている利息を、そのまま年に集めて出せば、団信・借り換え・繰上返済・売ったときの返済・未払利息のどれでも計算と合う（表から逆算しない）。
- 「返済のうち利息に充てた額」にすると、返済の合計＝元金＋利息（＋手数料）がどの年も成り立ち、FP がお客さまに説明しやすい。
- 金利は「その年の最後の返済の金利」にすると、年の途中で段が変わった年も1つの値に決まり、5年後・10年後の段の金利がそのまま読める。

## 代案（採らなかったもの）

- **表に利息の行を足す**: 表の行は収入・支出・残高の行で、利息は返済（支出）の内訳になる。合計の行が二重に数える。金利は円でないので表の行にできない。
- **かかった利息（0028 の interest）をそのまま使う**: 125%ルールで返済額が利息に足りない年に、返済額より大きい利息になる。返済の合計との関係が崩れる。
- **住宅ローンが2本のときの金利を残高で重みづけた平均にする**: エンジンの数字に無い値を作ることになる。2本の金利が違う年は null にし、ローンごとの数字を見せる。
- **利息と金利のグラフを足さず、数字だけ返す**: AI のアプリが描き直すことになる（0203 と同じ理由で採らない）。小さな足し算で済んだ。
