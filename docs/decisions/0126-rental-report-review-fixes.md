# 0126. 収益不動産の見え方の直し（キャッシュフロー表の抜粋の年・ライフイベント・住まいのローンと不動産のローンの行・根拠の内訳・減価償却が終わる年と残りの耐用年数・バランスシートの不動産のローン）と、収益不動産を持つ見本の世帯

- 状態: 採用（一部未確定）（2026-11-06）
- 固定の強さ: 内部（表の行の鍵 `realEstateLoan`・`realEstateDebt` とバランスシートの分け方 `propertyLoan` は、事務所の名前・独自帳票から使われるので名前は変えない。行の並び・言葉・色・グラフの系列・根拠の書き方は後から変えてよい。変えたら追記に書く）。世帯ファイルの形式の版は変えない
- 前提にする記録: 0006（根拠の記録と根拠の表示）、0009（提案書）、0016（提示層と帳票の約束・表の行の事務所の名前）、0027（資産と負債のタブ・分け方）、0028（住まい以外の不動産）、0068（ライフイベント）、0079〜0082（収益不動産）

## 背景

- 収益不動産を持つ架空の見本の世帯で、結果の画面と提案書を撮って、不動産に詳しい FP に見てもらう資料を作った。その途中で、FP に見せる前に直すべき見え方の食い違いが7つ見つかった（利用者の判断で、FP に送る前に直す）。
  1. 提案書のキャッシュフロー表（抜粋）の年を、提案のプランの出来事（ライフイベント表）だけで決めていたので、現状の表に現状のプランの退職・物件の売却の年が載らなかった。
  2. ライフイベント表に、物件の売却・大きな修繕が載らなかった。
  3. 表の「住宅ローン残高」に、住まい以外の不動産のローン（アパートローン）の残高も入っていた。アパートローンの返済は「その他の支出」に入り、収支の推移のグラフでは家賃が「その他の収入」、不動産の経費と返済が「その他（税・社会保険料など）」の色だった。
  4. 数字の根拠のパネルで、計算式の名前が無い計算（大きな修繕）に計算の部品の名前がそのまま出た。不動産の経費の根拠の「使った制度の値」に、譲渡所得の値（概算取得費の割合・長期の年数）が並んだ。2物件の分が1行にまとまった。
  5. 収益不動産のタブの「減価償却が終わる年」の札で文字が切れ（「建物 2031年・設備 2024」）、もう終わった設備の年も同じ書き方で並んだ。
  6. 「残りの耐用年数」を法定耐用年数−築年数で数えていたので、実際の償却（中古の簡便法）と食い違った（見本の木造アパートで、法定で数えると残り3年、実際の償却は5年残る）。
  7. バランスシートで、アパートローンの箱の名前が「不動産のローン」、横の見出し（分け方）が「その他の負債」で、呼び方がそろっていなかった。
- あわせて、見本の世帯（見本 3-4-05「収益不動産を持つ会社員の夫婦と子1人（見本）」）を、利用者が開発中のアプリで開けるようにアプリの見本の一覧に入れる。

## 決定

### 1. キャッシュフロー表の抜粋の年は、現状と提案の両方の出来事の年

- 帳票の入力に任意の欄 `cashflow.keyYears`（抜粋で必ず載せる年）を足した。現状と提案のそれぞれの出来事の年（ライフイベント表と同じ作り方の出来事: 入学・独立・退職・年金の受け取り開始・車・不動産の出来事〔2〕・ライフイベントの入力項目の行・住宅ローンの返済が終わる・FP顧問料の開始・金融資産の不足）を足し合わせた年。帳票（`pages/cashflow.typ` の `year-index`）は、最初と最後の年・5年ごと・この年を載せる。省略は前の版の入力で、今までどおりライフイベント表の年を使う。
- ライフイベント表そのものは、今までどおり提案のプランの出来事だけ（提案の前提の表なので）。
- 理由: 抜粋は現状と提案を同じ年で並べる表なので、どちらかのプランで大きなお金が動く年（退職金・売却・大きな修繕・住まいの購入）が抜けると、両方の表で比べられない。年は両方の和にし、表は1つの年の並びのまま（現状と提案で年を変えない）。

### 2. ライフイベント表と結果の画面の出来事に、不動産の出来事を足す

- 提案書（`report/src/build.ts` の `propertyEvents`）: 「住まいを購入」「住まいを売却」（キャッシュフロー表のマス: 購入の頭金などの行・売却の手取りの行があるその案の年）、「（物件名）を売却」（収益不動産。売却の手取りの行がある年）、「（物件名）を取得」（これから持ち始める物件）、「（物件名）の大きな修繕（名前 額）」（入れた大きな修繕のうち、分析の数字でその年に持っていて修繕の額がある物。売った後の修繕は載せない）。額は入れた額（エンジンも伸ばさない）。
- 結果の画面（`eventsOf`）にも、物件の売却と大きな修繕を足した（印は「不」）。物件名は 0082 と同じく画面・提案書に出す。持ち帰り用のレポートは物件名・修繕の名前を外した要求から作るので、「物件1を売却」「物件1の大きな修繕」になる（0079 の決まりのまま）。

### 3. 表の行: 住まいのローンと、住まい以外の不動産のローンを分ける

- 住まい以外の不動産を指す負債（`debts[].property`）を、負債の物の ID で見分ける。そういう負債があるときだけ、次の2つの行を出す（結果の画面・お客さまに見せる画面・提案書で同じ。事務所の名前の差し替えの鍵も同じ）。
  - 支出「不動産のローンの返済」（鍵 `realEstateLoan`）: その負債の返済のマス（毎月・ボーナス・繰上返済・手数料・売ったときの一括の返済）。「住居費」「その他の支出」から外す。
  - 貯蓄・資産「不動産のローン残高」（鍵 `realEstateDebt`）: その負債の年末の残高。「住宅ローン残高」から外す。
- 収支の推移のグラフ: 住まい以外の不動産（中身を入れた不動産の器）を持つ世帯だけ、収入に「不動産（家賃・売却）」（家賃収入と、その物件を売った手取り）、支出に「不動産（経費・ローン）」（不動産の経費〔大きな修繕を含む〕と、その物件のローンの返済）の系列を足し、「その他の収入」「住宅」「その他（税・社会保険料など）」から外す。色は収入の側が青緑、支出の側がくすんだ赤みの色（ほかの系列と色相で分ける）。
- 見分ける範囲は、家賃・経費・ローン（返済と残高）・売却の手取りまでにした。不動産所得にかかる所得税・住民税・保険料と、売ったときの譲渡所得の税は「税・社会保険料」のまま（税は人ごとにまとめて計算する物で、物件の分は収益不動産のタブの「増える税と社会保険料」の近似でしか分けられない。表の行を近似で分けない）。
- 表の「その他の収入」の売却の手取りは、行を分けない（売却は1回で、ライフイベントと収益不動産のタブで見える。グラフは不動産の系列に入れる）。
- 理由: 住宅ローン残高の行に事業の借入が入ると、住まいのローンの返し終わりが読めず、FP が家計の負債と事業の負債を分けて見られない。グラフは「その他」が大きく見えると、不動産の収支が家計の中でどれくらいかが分からない。

### 4. 数字の根拠のパネル

- 内訳の1行は「計算式×物件」: 住まい以外の不動産の物件と、その物件を指す負債のお金の動きは、物件ごとに分けて物件名を添える（「不動産の経費（見本ハイツ）」「大きな修繕（見本ハイツ）」）。物件名が無ければ「物件1」（収益不動産の並びの番号）。物件のローンの返済は住宅ローンの名前にせず「ローンの返済（元利均等）（物件名）」。
- 計算式の名前を足した: 大きな修繕・元金均等の返済・繰上返済の手数料・借り換えの費用。名前がまだ無い計算式は、計算の部品の名前（計算式 ID）の代わりに、そのお金の行の名前（登録簿の行の名前。無ければ「そのほかの計算」）を出し、式は「（行の名前）（式の説明はまだ載せていません）」と書く。
- 使った制度の値: 入力した値だけから出す計算式（家賃収入・不動産の経費・大きな修繕・不動産の売却の手取り・年末の借入の残高）は、根拠の記録で部品が読んだ制度の値を集めない（部品は譲渡所得などほかの計算のために制度の値を読むが、この数字には使っていない）。パネルは「この数字は制度の値を使わずに、入力した値から計算しています」と出す。
- 理由: 根拠の記録は部品の呼び出しごとに制度の値をつなぐので、1つの部品が複数の物を計算すると、関係しない値も並ぶ。お金の動きごとに使った値をつなぐのはエンジンの根拠の記録の形を変える大きな直しになるので、入力だけで出す計算式を画面の側で見分ける形にした。

### 5. 減価償却が終わる年の書き方と札の幅

- 計算基準年（計算の最初の年）までに終わった分は「設備は2024年に終わり」と書き、これから終わる分を先に置く（「建物 2031年・設備は2024年に終わり」。両方終わっていれば「建物は2020年、設備は2018年に終わり」、建物だけで終わっていれば「2020年に終わり」）。画面と提案書で同じ文（`depreciationEndText` に計算基準年を渡す。渡さなければ前の書き方）。
- 収益不動産のタブの指標の札は、値を札の幅で折り返す（切らない）。文で出す指標（減価償却が終わる年・元金の返済が減価償却費を上回る年）は字を少し小さくする。

### 6. 残りの耐用年数は、実際の償却の耐用年数で数える

- 分析の数字の `remainingLife` を「その年から建物の減価償却が終わる年までの年数（その年を含む。0より下げない）」にした（`asset.realEstateAnalysis` 改訂3）。実際に償却に使う耐用年数（中古は簡便法）と償却率の端数で決まる、建物の償却が終わる年（`depreciationEnd.building`。売る・貸し終わるまでに終わらなければ、貸し続けたら終わる年）から数える。償却していない建物（取得価額が無い・貸していない）は出さない（null）。
- 法定耐用年数は物件の欄 `legalLife` のまま（言葉は「法定耐用年数」）。画面の「?」に、法定耐用年数−築年数とは違うこと（中古は簡便法の耐用年数のほうが長いこと）を書いた。
- 理由: 画面に「残りの耐用年数」と「減価償却が終わる年」が並ぶので、同じ物差し（実際の償却）で数えないと、FP には食い違って見える。法定で数えた残りの年数は、融資の期間の目安などの別の意味で、要るなら別の言葉の欄にする（未確定）。

### 7. バランスシートの「不動産のローン」を分け方にする

- 負債の分け方を3つにした: 「住宅ローン」「不動産のローン」（`propertyLoan`。住まい以外の不動産を指す負債。種類が住宅ローンでも物件を指していればこちら）「その他の負債」（車のローン・奨学金・その他の借入・資金の不足）。箱の名前と横の見出しが同じ「不動産のローン」になる。資産と負債のタブの図・3時点を並べる・推移のグラフ・年の表、提案書の図と年の表（行「不動産のローン」）、持ち帰り用のレポート、会社と合わせたバランスシートの見本（`sdk/examples/extensions/combined-bs`）で同じ。
- 色は、住宅ローン（明るいキャラメル色）・その他の負債（暗い茶）・純資産（藍）のどれとも、ふつう・色覚の型・白黒の印刷で分かれる、いちばん暗い茶（`#4a2712`）。
- 家計の体力の目安（負債の重さ）は負債の合計のままで変わらない。
- 理由: 3 で表の行を分けたのと同じく、住まいのローンと事業の借入を分けて見せるのが FP の見方に合う。箱の中の項目の名前を見出しに合わせる（「その他の負債（不動産のローン）」など）より、分け方を分けるほうが、ほかの負債がある年とない年で見出しが変わらない。

### 8. 収益不動産を持つ見本の世帯

- `data/modelHouseholds/rentalSample.json`（架空）を足し、アプリの見本の一覧に見本 3-4-05（`#household=rentalSample`）として入れた。木造アパート1棟（2016年に中古で取得・2041年10月に売る予定・大きな修繕2回・アパートローン）と区分マンション1室（ローンなし）。プランは「65歳まで働く（60歳から再雇用）」「住宅ローンを300万円繰上返済」。
- 不動産の経費の費目を入れた物件に、費目の合計の年額（`expenses.annual`）も入れた（入力の画面の往復で同じ形になるように。計算は費目の合計を使うので変わらない）。

## 理由

- 決定の各項に書いた。どれも計算（表・税・お金の動き）は変えず、見せ方と分析の数字の1つの欄の意味だけを直す。

## 代案（採らなかったもの）

- 抜粋の年を、現状の表は現状の出来事、提案の表は提案の出来事で別々に決める: 2つの表の年が食い違い、同じ年で比べられない。
- アパートローンの返済を「不動産の経費」の行に入れる: 経費（不動産所得の必要経費）と元金の返済は意味が違い、収益不動産のタブの「経費」とも合わなくなる。
- バランスシートで、分け方が1つの項目だけのときに見出しを項目の名前にする: 3時点を並べると、時点によって見出しが変わる。
- 根拠の記録で、お金の動きごとに使った制度の値をつなぐ（エンジンの根拠の記録の形を変える）: 直しが大きく、ほかの部品にも及ぶ。入力だけで出す計算式を見分ける形で足りる。
