# 0218. 不動産の評価の土地の割合・建物の残りの価値の下限・売却の費用も、ほかの前提条件と同じく世帯に写す

- 状態: 採用（2026-11-16）
- 固定の強さ: 「作った世帯は黙って変えない」（0073 の3・0214 の5）をこの3つにも当てることは固定。事務所データの置き場所（事務所の推定の値 `preset.realEstate.landShare`・`residualFloor`・`saleCostRate`）と前提条件の id（`realEstateValuation.landShare`・`residualFloor`・`saleCostRate`）は 0214 のまま変えない。世帯ファイルの形式の版・事務所データの形の版は上げない。計算のお知らせを残すための計算の要求の直し（下の4）は内部
- 前提にする記録: 0214（前提条件の事務所の既定値）、0111（事務所の推定の値）、0073（事務所の既定値）、0025（持ち家の評価）、0028（収益不動産の土地と建物）

## 背景

- 0214 で、前提条件は事務所の既定値の画面で決め、新しい世帯を作るときに世帯へ値を写す形にした。事務所の値を後で変えても、すでにある世帯は写した値のまま残り、確かめの一覧に「事務所の既定値が変わりました（前→後）」と出て、「この世帯に当てる」の1押しで変えられる。
- ところが不動産の評価のうち、土地の割合・建物の残りの価値の下限・売却の費用の3つだけは、前からの事務所の推定の値（0111）の仕組みのまま世帯に写さず、計算のたびに事務所の値を読んでいた（0214 の1・5）。そのため事務所の値を変えると、物件ごとに値を入れていない物件では、すでにある全部の世帯の結果が知らせなしにすぐ変わっていた。
- 前提条件の決まりが欄によって2つあると、FP は「事務所の値を変えたら作った世帯も変わるのか」を欄ごとに覚えなければならない。お客さまに見せた結果が黙って変わるのは、0073 で避けた形そのもの。

## 決定

### 1. 3つもほかの前提条件と同じ決まりにする

- 新しい世帯: 作るときに、この3つの事務所の値（事務所で決めていなければ提供元の既定の値 30%・20%・4%）を世帯の前提条件（`assumptions.realEstateValuation.landShare`・`residualFloor`・`saleCostRate`）に書き、ほかの前提条件と同じ「事務所の既定値（年月）」の印（`assumed[<欄のキー>]`）を付ける（`office/settings.ts` の `applyOfficeDefaults`）。
  - ほかの前提条件は、事務所で決めていない欄を書かない（無いときの決まった値と同じなので）。この3つは、世帯に値が無いと計算がその場の事務所の値を使うので、事務所で決めていなくても書く。
- すでにある世帯（この3つを持っていない世帯）: 開いたときに、その時点の事務所の値を写し、同じ印を付ける（`input/premiseDefaults.ts` の `fillLivePremises`。画面が世帯を入れる所 `openedFrom` で当てる。見本の世帯・AI の候補から作った世帯も同じ）。保存した世帯は、写した値を自動保存で世帯に書く（書かないと、次に開いたときの事務所の値をまた写すことになる）。ほかの人が開いている・閲覧だけ・自分で作った見本を見るときは書かない（画面の中だけで写す）。
  - 値の無い欄は計算がその場の事務所の値を使っていたので、写しても計算の結果は変わらない（見本の世帯と前の形式の見本の全部で確かめる。下の5）。
  - 値のある欄（FP が打った値）は今までどおり。事務所の値と同じなら「事務所の既定値」、違えば「この世帯だけ」（0214 の6 の3）。
- 写した後に事務所の値を変えたとき: 世帯の値は変えず、ほかの前提条件と同じく、確かめの注意に「事務所の既定値が変わりました（45%→50%）。この世帯は前の値で計算しています」と出し、「この世帯に当てる」の1押しを置く（0214 の5）。
- 欄を空にしたとき・「事務所の既定値に戻す」: 値を外さず、事務所の今の値を書いて印を付ける（値を外すと、後で事務所の値を変えたときに黙って変わるため）。

### 2. 物件ごとの値が先に効く順は変えない

- 計算は今までどおり、物件ごとの値（住まいの `valuation.landShare`・`sale.costRate`、収益不動産の `property.landShare`・取得価額の内訳・`property.sale.costRate`、貸していない不動産の `sale.costRate`）→ 世帯の前提条件の値 → 目安（事務所の推定の値・公式の目安）の順に読む。計算エンジンは変えない。
- 変わるのは、世帯の前提条件の値がいつも入るようになったことだけ。目安の段は、前提条件の値を持たない要求（AI接続口で組み立てた入力など）のときだけ使う。

### 3. 事務所データの置き場所と画面の言葉

- 事務所データの置き場所は 0214 のまま（事務所の推定の値）。事務所の既定値の画面の「前提条件の既定値」の欄と「推定の値（統計・目安）」の区画は同じ値を読み書きする。事務所データの形の版は上げない。
- 画面の言葉を直した: 事務所の既定値の画面の不動産の評価の説明（「世帯に写さず、空欄の物件はその場の値で計算します」→「ほかの前提条件と同じく、これから作る世帯に写します」）、推定の値の区画の説明と、この3つの効く所（「どの世帯の計算にもすぐ効きます」→「前提条件の不動産の評価の事務所の既定値（これから作る世帯に写します。作った世帯は変わらず、確かめの一覧に『事務所の既定値が変わりました』と出ます）」）。AI接続口の説明（`docs/ai-connector.md`）も同じに直した。

### 4. 計算のお知らせ「土地と建物の割合が入っていない」を残す

- 計算エンジンは、物件にも世帯の前提条件にも土地の割合が無いとき、知らせ N_DEFAULT_USED（「土地と建物の割合が入っていないので、既定の割合で時価の変わり方を計算しています」）を出す。前提条件の値がいつも入ると、この知らせが出なくなる。
- そこで、エンジンへ渡す要求を作るとき（`engine/moneyRows.ts` の `forEngine`。画面と AI接続口で同じ関数）に、前提条件の土地の割合がエンジンの引く目安（事務所の推定の値、無ければ公式の目安）と同じ値なら、要求から外す（`withoutDefaultLandShare`）。同じ値なので計算の結果は変わらず、知らせは前と同じく出る。世帯ファイルは変えない。
  - 前提条件の土地の割合が目安と違う値（この世帯だけの値・事務所の値を変えた後の前の値）なら外さない（知らせは出ない。前と同じく「世帯で決めた割合」を使う）。前は FP が事務所の値と同じ値を世帯で打つと知らせが出なかったが、今は出る（事務所の既定値の割合で計算しているので、知らせのとおり）。
- 建物の残りの価値の下限・売却の費用には、目安を使ったときの知らせが無いので外さない。

### 5. 計算の結果が変わらないことの確かめ

- `app/test/realestate-premise-copy.test.ts`: 見本の世帯（`data/modelHouseholds` の全部）と前の形式の見本（`crates/household-store/tests/fixtures/household-format` の全部の版。同じ世帯は1つに）で、事務所の値が既定のまま・変えた後のそれぞれで、写す前と写した後の計算の結果（表・要約・相続税の目安・計算のお知らせ）が同じこと。写した後に事務所の値をもう一度変えても、お金の結果が変わらないこと。
- 境目: 建物の残りの価値の下限が効く古い建物（1995年の木造の持ち家）、売却する年がある持ち家と収益不動産、物件ごとに値を入れた物件（世帯の前提条件の値を変えても結果が同じ。物件の値を外すと世帯の値を使う）、新しい世帯で事務所の値が既定のまま・変えた後、写した値と印を世帯ファイルに書いて読み戻せること。

## 理由

- 前提条件の決まりを欄によって変えない。事務所の値を変えたときにどの世帯が変わるかを、FP が欄ごとに覚えなくてよい。
- 置き場所を2つにしない（0214 の理由）は、事務所データの側で守る（事務所の推定の値の1か所）。世帯に写すのは、ほかの前提条件と同じ「事務所の既定値（年月）」の写しで、二重の置き場所ではない。
- 写すのを「開いたとき」にしたのは、世帯ファイルを一度に書き換える道が無いため（世帯ファイルは開いた画面が読み書きする）。開くまでの間に事務所の値を変えると、その世帯は開いたときの事務所の値になる（前と同じく、その時点の値で計算している）。

## 代案（採らなかったもの）

- 世帯には写さず、事務所の値を変えたときに、すでにある世帯へ前の値を書いて回る: 開いていない世帯を書き換える道が無い（世帯ファイルは画面が開いて読み書きする）。
- 前の値を世帯ファイルの新しい欄（「事務所の既定値に従う」の印）で持つ: 世帯ファイルの形式の版を上げることになる。前からある仮の印と前提条件の欄で足りる。
- 計算エンジンの知らせを「物件に土地の割合が無ければ出す」に変える: エンジンの部品の改訂になり、世帯で決めた割合を使う世帯にも新しく知らせが出る。要求の側で同じ値を外せば、エンジンを変えずに前と同じ知らせになる。

## 影響

- `docs/ai-connector.md`（前提条件の id の説明）。
- 計算エンジン・世帯ファイルの形式の版・事務所データの形の版は変えない。見本の世帯の計算の結果は変わらない。
