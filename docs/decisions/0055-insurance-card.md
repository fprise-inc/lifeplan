# 0055. 保険のカードの中身（簡易の5欄とひな形・保険料と保障の額の未入力・証券どおりの詳細・保障の見え方・病気の想定）と世帯ファイルの形式 0.25

- 状態: 採用（一部未確定）（2026-10-27）
- 固定の強さ: β公開から変えない（骨格）。簡易を1契約5欄（種類・被保険者・保険料と払い方・主な保障の額・終わり）にすること、種類はひな形（種類の細目 `insurance.subtype`）で選び計算の型 `template` はひな形から決まること、保険料と保障の額は新しい契約でも目安を作らず未入力の警告にすること、ひな形の既定の値を推定（値の状態の行）で持ち推定のままの値だけを入れ直すこと、外貨建て・変額は円の目安の形だけにすること、病気の想定を万一の前提の大きな病気に持つことは骨格。ひな形の一覧と既定の値（終わりの年齢・払込の終わり・手術の倍率・入院の日数）・欄の並び・文言・保障の見え方の見せ方は後から変えてよい（変えたら追記に書く）

## 背景

- 入力のホームを14枚のカードに組み直した（0045）。保険のカードは今まで「種類・契約者・被保険者・契約年月・保険料・払い方・払込の終わり・死亡保険金」の簡易7欄で、保険料5,000円・死亡保険金1,000万円の決まった値が印なしで入っていた。収入保障保険の月額・医療保険の入院日額は簡易で入れられず、保障の推移や必要保障額との過不足もこのカードでは見えなかった。
- 計算の側（0054）で、医療・がんの給付を病気の想定で受け取る計算、保障の行ごとの被保険者、変額・外貨建の円の目安の形、保障ごとの数表、必要保障額の内訳を足した。この記録はその入力と見せ方。
- 前提にする記録: 0008 の10（保険契約）、0026（大きな病気の想定）、0035（足すだけの形）、0038（時点の部品）、0041（値の状態の操作）、0043（入力画面でプランを直す）、0044（お金の行）、0045（カード）、0054。

## 決定

### 1. 簡易と詳細

- 契約（まとまり）ごとに簡易（目安で）と詳細（証券どおり）。独自の区分（目安で／一覧から／証券どおり）は作らない（粗さの違いで、同じ契約の中で行き来できる。控除証明書などの取り込みは入口で、読んだ後は「保障が未入力」の契約になるだけ）。
- **簡易は5欄**: 種類・被保険者・保険料（払い方つき）・**主な保障の額**（種類で給付が変わる1欄）・**終わり**（保障の終わり。時点の部品で年齢・出来事・年月）。個人年金保険は「終わり」の代わりに受け取りの始まり、損害保険は主な保障が無く終わりは保険期間（払込の終わり）。
- 詳細: 契約の表示名（`insurance.label`。計算に使わない）・契約者・契約年月・受取人（死亡保険金。構成員か世帯の外の続柄。複数の割合の契約は読むだけ）・死亡保険金にかかる税（契約者・被保険者・受取人の組から読むだけ）・満期金などの受取人・保険料控除の区分と新旧の制度・払込の終わり・払込免除・解約の月・解約返戻率（貯蓄型）・解約の月の解約返戻金（数表のその保険年度の行）・更新（更新の月と更新後の保険料。くり返して足す）・保障の明細（被保険者〔家族特約〕・給付の種類〔三大疾病一時金を足した〕・額・始まり・終わり・推移の形〔一定／毎年同じ額ずつ減る〕・最低保証の月数・免責の月数・年金の年数・祝金の間隔・入院の1回の限度日数）。
- 簡易のまま詳細の値がある契約は、まとまりの説明に札を出す（特約 n件・更新 n回・解約 ○年・設計書の表・受取人・家族の保障あり）。

- 種類の細目の無い古い契約は計算の型から読む（逓減・団体保険・共済などは型が同じなので「定期保険」などで開き、FP が直す）。
- **種類を変えたとき**: 推定のまま（出どころ auto の行）の値（終わり・払込の終わり・控除の区分・被保険者・契約者）だけを新しい種類の既定に入れ直し、確定の値は変えない。主な保障は、新しい種類に同じ意味の給付があれば引き継ぎ（定期⇄終身の死亡保険金）、無ければ0円の主契約を未入力で置く。前の主な保障は、医療の給付なら特約に回して残し、新しい計算の型に無い計算に使う給付なら外す（医療保険に変えたときの死亡保険金など）。特約は残す。
- 医療保険は手術の特約を入院日額の10倍の推定で置く（推定のままなら入院日額を直すと入れ直す）。学資保険は被保険者を末の子・契約者を本人の推定にする。
- 新しい契約のボタン: 「＋ 保険契約（定期保険）」「＋ 医療保険」「＋ 学資保険」（子がいるとき）（簡易）、「＋ 損害保険」（詳細）。

### 3. 推定と未入力

- **保険料と主な保障の額は、新しい契約でも目安を作らない**（未入力の警告。値の状態の行の推定で根拠が「未入力」で始まるもの。0052 の2 と同じ読み方）。今までの決まった値（保険料5,000円・死亡保険金1,000万円）はやめた。空にしたときも0円の未入力に戻す。
- ひな形の既定（終わり・払込の終わり・控除の区分）と契約年月（1年前。新旧の制度の判定に効くと添える）・被保険者（本人）・契約者（被保険者、子なら本人）は推定で、根拠の文に「ひな形の標準の値（○○: 65歳）」のように値を入れる（値を変えて書き直した行が古い行として外れないように）。被保険者を直すと、推定のままの契約者・終わり・払込の終わりを入れ直す。契約年月を直すと、推定のままの新旧の制度を入れ直す。終わりを直すと、「保障の終わりと同じ」の推定のままの払込の終わりもいっしょに動く。
- 貯蓄型（終身・養老・学資・個人年金）は、保障の明細か数表のある契約で解約返戻率が空なら未入力の警告（解約返戻金を0円で数えている。解約の月が無くても）。計算エンジンの知らせと同じ決まり（保険料控除のためだけの契約には出さない）。
- 古い世帯を開いても書き換えない。前のボタンが入れた値（死亡保険金1,000万円・特約の入院日額5,000円・保険料5,000円）のまま記録の無い確定の欄は、確かめの一覧に「目安のボタンと同じ確定の値」として出す（0041 の5）。主な保障の無い古い契約（保険料控除のためだけに入れた終身保険・ヒアリングで取り込んだ医療保険など）は、主な保障の額が未入力の警告になる（カードの状態は「未入力」）。

### 4. 逓減定期・家族特約・外貨建て・変額・解約返戻金

- 逓減定期（推移の形「毎年同じ額ずつ減る」）は、保障の ID のある数表の死亡保障の行を保険年度ごとに作る（はじめの額から毎年同じ額ずつ減る）。はじめの額・終わりを直すと作り直し、一定に戻すと外す。
- 保障の行の被保険者を配偶者・子にできる（家族型の医療保険・家族特約）。契約の被保険者と同じにすると欄を消す。
- 外貨建て・変額は円の目安の形だけ（`insurance.simple.estimate`）。主な保障の欄は「死亡保険金（円の目安）」、まとまりの説明に「目安（為替・運用で変わります）」。積立金を前提の利回りで伸ばす前の入れ方の契約は、値を変えずに主な保障の欄に確かめの注意を出し、ボタン「円の目安の形に直す」で目安の形にする（資産クラス・積立に回らない割合の値は残す）。
- 解約の月の解約返戻金は、数表の解約の月の保険年度（契約の月から満の年数）の行に書く。

### 5. 保障の見え方（読むだけ。簡易にも出す）

- カードのパネルの欄の上に置く。入力は増えない。計算は万一のタブと同じ要求（大人ごとの必要保障額の推移・本人の大きな病気の想定）を画面の側で計算して読む（世帯は変えない）。
- 保険料: 月・年の合計（入力から）とこれから払う総額（計算の結果の保険料の行）、更新で上がる年、払込が終わる年。
- 被保険者ごとの**保障の階段**: 年ごとの死亡保険金を契約ごとの色で積み上げ（0054 の `coverageBy`）、必要保障額の線を重ねる。**既定の線は今の貯蓄を差し引いた必要保障額**（赤の実線。万一のタブの既定と同じ）、貯蓄を差し引かない線も点線で並べる。いちばん大きい不足とその年（無ければ、いちばん少ない余り）。
- 必要保障額の内訳（最初の年に亡くなった場合）: 必要な資金（毎年の分・一時の分）と準備できる資金（毎年の分・一時の分）、団信で消える返済。
- 保険料のうち貯まる分（貯蓄型・円の目安の形）: 年末の払った保険料の累計と解約返戻金と返戻率、元本割れの年（「2035年まで元本割れ」）。解約返戻金が0円なら入れるよう知らせる。
- **病気の想定で受け取る見込み**: 本人の大きな病気の想定（病気の種類・入院の日数・手術の回数）で、契約ごとに「入院 20日 20万円＋手術 1回 10万円＋がん一時金 100万円＝130万円（非課税）」。給付ごとの額は計算エンジンと同じ決まりで画面が出し、合計が計算の結果と違う（保障の期間の外など）ときは計算の結果の額だけを出す。
- 気づき: 保険が切れる年とその年の不足、同じ被保険者に医療保険・がん保険が2本以上。
- **必要保障額に合わせる**: 死亡保険金が未入力の契約に、その被保険者の最初の年の不足（今の貯蓄を差し引いた線−加入中の死亡保険金）を1万円単位に切り上げて入れるボタン（新しく入る保険のとき）。入れた値は推定（根拠「必要保障額に合わせた（○年の不足 ○万円）」）。統計の平均の保障額は使わない。

### 6. 病気の想定（万一の前提）

- 万一の前提の「大きな病気のときの前提」に、**病気の種類**（がん／心疾患・脳卒中／そのほか。既定はがん）・**入院の日数**（1回。空欄は病気の種類ごとの目安: がん20日・心疾患と脳卒中30日・そのほか10日。患者調査の平均在院日数の水準を丸めた仮の値）・**手術の回数**（既定1回）を足した（画面の側の `household.contingency.illness`）。大きな病気の想定の要求に病気の想定（0054 の `contingency.illness`）として入れる。

### 7. 世帯ファイルの形式 0.25

- 足すだけの MINOR（0035 の1）。足した欄: 保険の種類の細目 `insuranceContracts[].subtype`・名前 `label`、保障の行の被保険者 `coverages[].insured`・入院の1回の限度日数 `maxDays`・給付の種類 `threeMajorLump`、円の目安の形 `simple.estimate`（0054）、画面の側の万一の前提の病気の想定 `household.contingency.illness` の `disease`・`hospitalDays`・`surgeries`。どれも任意。
- `0.24` → `0.25` の変換の段は版だけを書き換える。見本 `crates/household-store/tests/fixtures/household-format/0.25/`（0.24 の見本に、種類の細目と名前のある医療保険〔三大疾病一時金・限度日数・配偶者の入院日額の特約〕、円の目安の形の変額保険〔解約の月の額の数表の行〕、逓減定期〔保障の ID のある数表の行〕、病気の想定を足した）。

### 8. プランと持ち帰り

- 欄はどれも当て先（0036 の2）を持つ（足した欄は `address`、前からの欄のキーは読み替え表）。プランを直しているときの書き方は 0043 のまま。前の欄のキー `ins/<契約>/death` は読み替え表で主契約の死亡保険金に当たる（新しい欄のキーは `ins/<契約>/main`）。
- 契約の表示名は持ち帰り用のレポートで外す（0054）。

## 理由

- **簡易を5欄にする**: 「保険料はだいたい月いくら・死亡はいくら・いつまで」なら書類なしで答えられ、種類から残りを推定できる。種類で主な保障の給付を切り替えるので、収入保障の月額・医療保険の日額も簡易で入る。
- **保険料と保障の額に目安を入れない**: 商品ごとの数字で目安が当たらず、外れても気づかないまま計算が誤る。新しく入る案は必要保障額に合わせるのが FP の考え方に合う。
- **推定のままの値だけを入れ直す**: 種類を試し直しても FP が入れた値は消えず、推定の値は新しい種類に合う。
- **見え方を画面の側の計算で出す**: 万一のタブと同じ前提・同じ計算なので数字が食い違わない。世帯の物を増やさない。

## 代案（採らなかったもの）

- **種類を変えたとき前の種類の値を閉じるまで残す**: 主な保障の給付が変わる種類の組み合わせが多く、残した値の見せ方が複雑になる。医療の給付は特約に回して残し、計算に使う給付で新しい型に無いものだけを外す。
- **解約返戻金の入れ方を3つから選ぶ選択の欄**: 返戻率と解約の月の額は同じ契約に両方入れられ、数表の行があればそれを使う（計算エンジンの決まり）。選択を増やさない。

## 影響

- **画面**: 保険のカード（`input/stages/insurance.ts`）、ひな形と推定（`input/insuranceKinds.ts`）、保障の見え方（`input/insuranceView.ts`・`input/InsuranceOverview.tsx`・パネル）、万一の前提の病気の想定（`contingency/inputs.ts`・`requests.ts`・`planData.ts`）、確かめの一覧の前のボタンの値、世帯ファイルの本文の版。
- **見本の世帯の結果**: 変わらない（開いただけでは書き換えない）。入力のホームのカードの状態は、主な保障の無い保険契約を持つ見本（会社員の夫婦と子2人など）で保険が「未入力」になる。万一のタブの大きな病気の想定は、医療・がんの給付のある世帯で給付の分だけ収入が増える（見本の世帯には医療保険の給付の明細が無いので変わらない）。
- **テスト**: `app/test/insurance-card.test.ts`、`app/test/housing-loan.test.ts`（種類を変えたときの保障をひな形に合わせた）、`app/test/items.test.ts`・`app/test/hearing.test.ts`（主な保障の未入力）、`app/test/store.test.ts`（0.25 の形）、`crates/household-store/tests/format_fixtures.rs`。
