# 0231. 相続税の試算（試算する世帯だけ）: 土地・建物の評価、貸家・貸家建付地、小規模宅地等の特例、2割加算・未成年者控除と、世帯ファイルの形式 0.86

- 状態: 採用（一部未確定）（2026-11-19）
- 固定の強さ: β公開から変えない（骨格）。要求と世帯の設定の欄（`input.inheritanceTax` の `detailed`・`lands[]`〔`object`・`area`・`method`・`routePrice`・`fixedValue`・`multiplier`・`adjustment`・`leaseholdRatio`・`buildingValue`・`buildingEstimate`・`rentalRatio`・`use`・`rentalContinued`・`primary`・`secondary`〕と `smallLandChoice`〔`acquirer`・`met`〕の名前と意味）、出力の任意の欄（`assets.smallLandReduction`・`surcharge`・`minorCredit`・`lands[]`・`byHeir[].surcharge`・`byHeir[].minorCredit`。約束の版 1.2）、制度の値ID（`inheritanceTax.smallLand.*`・`inheritanceTax.surcharge.rate`・`inheritanceTax.minorCredit.*`）、形式 0.86 は骨格。既定の値（借地権割合 D・8/7・賃貸割合の省略・配偶者が自宅を取得するとみなす決まり）、注意と含めていない決まりの一覧、画面の並び・文言は後から変えてよい（変えたら追記に書く）
- 前提にする記録: 0002（金額・率・丸め）、0005・0170（計算の速さ）、0007（制度データの形式）、0011・0035（世帯ファイルの形式の版の上げ方）、0028・0079〜0082（住まい以外の不動産・収益不動産）、0232（収益不動産の建てる・買う予定と相続税の評価の材料）、0039（相続税の目安）、0060・0061（相続・贈与の入力項目と世帯に保存する設定）、0112・0181（固定資産税の目安）、0135・0143・0173（相続・介護のつながり）

## 背景

- 相続税の目安（0039）は、入力を増やさずに出せる範囲（基礎控除・法定相続人・非課税・法定相続分で分けた速算表・配偶者の軽減・精算課税の足し戻し）で、不動産は時価の80%で見ていた。小規模宅地等の特例・土地の評価の細部・2割加算・未成年者控除は含めず、当たりそうなときは注意を出すだけだった。
- 持ち家と収益不動産のある世帯では、特例で課税価格が数千万円変わることがあり、「かかる・かからない」の答えが入れ替わる。一方で、特例の要件（取得する人・申告期限までの居住や事業の継続）と土地の評価（路線価・倍率）は、入力に無い情報で、相続税がかからない世帯の大半には要らない。
- 利用者の判断（2026-11-19）: 相続税を試算したい世帯だけが詳しく入れられるようにする（試算が要らない世帯の入力の手間を増やさないことが最重要）。年ごとの一次・二次の計算と画面（右の列の欄・比較の段・「相続税の推移」の見方）は次の回とし、この回はそれが乗る土台の形を決めて作る。

## 決定

### 1. 試算はする世帯だけ（`detailed`）

- 相続税の目安の設定（`input.inheritanceTax`。0061 で世帯に保存する欄）に `detailed`（真偽。省略は偽）を足した。相続・贈与の入力項目の区画「相続税の試算」の欄「相続税も試算する（土地の評価・小規模宅地等の特例）」。
- **チェックしない世帯は今までと同じ**: 区画は詳細の1つの欄だけ（標準の欄は増えない）。計算は改訂5と同じ結果（不動産は時価×評価の割合、`smallLandSpecial` などの注意、含めていない一覧も同じ）。`lands` が残っていても読まない。テストで確かめる（`engine/test/inheritance-land.test.ts`・`app/test/inheritance-land.test.ts`）。
- チェックした世帯: 区画が標準に出て、不動産ごとのまとまりが並ぶ。2割加算と未成年者控除も計算に入れる（7）。チェックを外しても入れた設定は消さない（チェックし直せば同じ値で計算する）。
- 目安でかかりそうな世帯（目安の時点のどれかが「かからない見込み」でなく、FP が入れた額でもなく、不動産を持つ）には、入力項目の下の「相続税の目安」に「相続税がかかりそうです。土地の評価（路線価など）と小規模宅地等の特例を入れて、詳しく試算しますか」と「詳しく試算する」（押すとチェックを入れる）を出す。不動産の無い世帯には出さない（土地の試算は要らない）。

### 2. 置き場所と世帯ファイルの形式 0.86

- 不動産ごとの設定は `input.inheritanceTax.lands[]`（`object` は持ち家 `residences[].id` か住まい以外の不動産の器 `accounts[].id`）。物の欄（`residences`・`accounts[].property`）には置かない: 相続税の試算の前提で、物の計算（評価額・家賃・固定資産税）には効かず、0061 の置き場所（時点の無い設定は毎回の計算の要求から外れる。`withoutStoredSettings`）とプランの差分（向き先 `{plan: "input"}`、欄の当て先は `["lands"]`）がそのまま使えるため。
- 一次と二次で要件を別に選べる形を最初から持つ: `primary`（いま亡くなったら・万一の想定。配偶者のいる人が先に亡くなる時点）と `secondary`（二人とも亡くなった後）。どちらも `{acquirer, met}`。二次の計算（年ごと）は次の回だが、欄と型はこの回で決めた。
- 形式の版を `0.86` に上げた（足すだけの MINOR。0035 の1・7。収益不動産の建てる・買う予定〔0232〕の `0.85` の後）。`0.85` → `0.86` の変換の段は版だけを書き換える（前の版の世帯は欄が無い＝相続税も試算しない）。前の版のアプリは知らない欄を読み落として書き戻すので、閲覧だけにする。見本 `crates/household-store/tests/fixtures/household-format/0.86/`（0.85 の見本〔建てる・買う予定の物件を1件持つ〕に、持ち家〔路線価・二次の取得する人〕と物件〔倍率・補正の率・建物の評価額・借地権割合 C・賃貸割合・貸付の取得する人〕の2件の設定を足した）。
- 物を外したら設定の行も消す（`refs.ts` の片付けの一覧に `inheritanceTax.lands[].object`）。
- 建物の固定資産税評価額の推定（4）は `buildingEstimate` として計算の要求にだけ入れ、世帯には保存しない。

### 3. 土地の評価（土地ごと。物件全体の値。亡くなる人の分は名義の割合で分ける）

| `method` | 式 | 要る値 |
|---|---|---|
| `routePrice`（路線価地域） | 路線価（1㎡あたり）×面積×補正の率 | 路線価・面積 |
| `multiplier`（倍率地域） | 土地の固定資産税評価額×倍率×補正の率 | 固定資産税評価額・倍率 |
| `fixedEstimate`（路線価が分からないときの推定） | 土地の固定資産税評価額×8/7×補正の率 | 固定資産税評価額 |
| `market`（省略。今の既定） | 土地の時価×評価の割合（省略 0.8）×補正の率 | — |

- 補正（奥行価格補正・間口狭小補正・不整形地補正など）は入れない概算で、補正したい人だけ「補正の率」（`adjustment`。省略は1）を入れる。
- 入れた値（路線価・固定資産税評価額）は計算基準年の値とみなし、ほかの年（二人とも亡くなった後・先の万一の想定）は、その物件の土地の評価額の推移（`housing.valuation`・`asset.realEstate` の年末の土地の額。持ち始めが後なら持ち始めの年の額が元）と同じ割合で動かす。
- 要る値が無い入れ方（路線価だけで面積が無いなど）は時価×評価の割合に戻し、注意 `landInputMissing` を出す。
- 中身の無い不動産の器（貸していない不動産の多く）と、計算基準年のうちに売る物件は、時価の全部を土地とみなす（土地と建物の分け方を持たないため）。建物があるなら、建物の固定資産税評価額を入れると足す（時価×評価の割合で見るときは、時価に建物も入っているので足さない）。
- 面積の省略は、住まい以外の不動産の中身の土地の面積（`property.area.land`。0079 の表示用の欄）。持ち家には面積の欄が無いので、この区画で入れる。

### 4. 建物の評価

- 建物の固定資産税評価額（`buildingValue`。課税明細書の家屋の価格）を入れていればその額。無ければ、画面が固定資産税の目安（0112・0181）と同じ式の建物の評価額を `buildingEstimate` に入れる（今住んでいる持ち家: 評価額×(1−土地の割合)×新築の評価額の割合×経年減点補正率と再建築費評点補正率の比〔`buildingValueRatio`〕。購入の予定: 価格×(1−土地の割合)×新築の評価額の割合。住まい以外の不動産: 時価×(1−土地の割合)×新築の評価額の割合×同じ比）。それも無ければ（AI接続口など画面を通らない要求）時価×評価の割合。
- **建てる・買う予定の物件**（`property.planned`。0232）は、`buildingValue` を入れていなければ、計算エンジンの `asset.realEstate` が出す評価の年（`valuationYear`）の `years[].assessed`（予定の欄の建物の固定資産税評価額〔画面が建物の価格×新築の評価額の割合で推定して入れるか、FP が入れる〕を、評価替えの年ごとに経年減点補正率・再建築費評点補正率で動かした額。0181 の式）を使う。画面は予定の物件に `buildingEstimate` を作らない（器の時価は予定の建物を含まないため）。`buildingSource` は予定の欄の箱が推定なら `estimate`、FP が入れた額なら `entered`。持っている土地に建てる予定は、建てる年の年末より前の姿では建物を数えない（`buildingValue` を入れていても）。
- 入れた値・推定は計算基準年の額とみなし、ほかの年は建物の評価額の推移と同じ割合で動かす（近似。次の回で経年減点補正率の動きにするか決める。予定の物件の `assessed` は既にその動き）。
- 出力 `lands[].buildingSource` に元（`entered`・`estimate`・`market`・`none`）を出し、内訳の行に「固定資産税評価額」「固定資産税評価額の推定」「時価×評価の割合」と書く。

### 5. 貸家・貸家建付地の減額

- 貸している物件（住まい以外の不動産の器で `property.rental` があり、評価の年〔`valuationYear`。評価額と同じ年末の姿〕の年末の月に貸している物件。計算エンジンの `asset.realEstate` の `years[].rentedShare` が0より大きい）: 建物＝建物の評価×(1−借家権割合30%×賃貸割合)、土地＝土地の評価×(1−借地権割合×借家権割合30%×賃貸割合)（財産評価基本通達26・93。国税庁 No.4614）。
- **賃貸割合の省略**は `asset.realEstate` の評価の年の `years[].rentedShare`（年末の月に貸している割合＝1−空室率〔`rental.vacancyRate`〕。今の実際の家賃収入で入れた物件〔`rentBy: actual`〕は1。0232）。家賃収入の計算（空室を見込んだ家賃）と同じ数なので矛盾しない。通達では一時的な空室は貸しているとみなせるので、空室の多くが一時的なら FP が賃貸割合を入れ直す（欄の説明に書いた）。評価の年の年末に貸していなければ0（減額しない・貸付の特例も使わない）。建てる・買う予定の物件は、予定の月より前は貸していない（`asset.realEstate` の読み方）。
- 近似: 貸しているかを亡くなる月でなく評価の年の年末で見る（評価額も年末の姿なので、そろえた）。いま亡くなったら（計算基準月）の時点で、計算基準年のうちに貸し始める・貸し終える物件は、年末の姿で見る。
- 民泊・宿（`property.lodging`）は貸家にしない（借家権が無い）。`asset.realEstate` の `years[].rentedShare` も民泊・宿には出さない（0232）。
- **借地権割合の既定は D（60%）**（利用者の判断で妥当な値を決める項目）。根拠: 路線価図の記号は A 90%〜G 30% で、貸家の建つ住宅地では C（70%）・D（60%）が多い。低い方の D にすると減額が小さく、税を少なく見すぎない（減額は 土地×60%×30%×賃貸割合＝最大18%。C なら21%）。路線価図で分かれば記号を選ぶ。

### 6. 小規模宅地等の特例（租税特別措置法69条の4。国税庁 No.4124）

- 種類（`use`）と上限・減額の割合（制度データ）: 自宅 `residence`（特定居住用 330㎡・80%）、貸付 `rental`（貸付事業用 200㎡・50%）、事業 `business`（特定事業用 400㎡・80%。自営の働き方のある世帯で選べる）、自分の会社に貸している土地 `familyCompany`（特定同族会社事業用 400㎡・80%。役員の働き方のある世帯で選べる）。事業と自分の会社は合わせて400㎡。省略は、持ち家なら自宅、亡くなる月に貸している物件なら貸付、ほかは使わない。
- **取得する人と要件は利用者が選ぶ**（要件を自動で判定しすぎない）: `acquirer` は配偶者 `spouse`・同居の親族 `cohabiting`・持ち家の無い親族 `noHome`（いわゆる家なき子）・事業や貸付や会社の役員を引き継ぐ親族 `successor`・要件を満たす人がいない `other`。`met` は「取得する人が要件を満たす（確かめた）」の印。配偶者が自宅を取得するときは要件が無いので `met` を読まない。ほかは `met` が無ければ使わない（`notMet`）。
- **一次で取得する人を選んでいない自宅は、法律婚の配偶者が生きていれば配偶者が取得するとみなす**（要件が無く、最も多い分け方。出力 `special.defaulted`、内訳に「配偶者が取得するとみなした」）。二次（二人とも亡くなった後）・配偶者のいない人・自宅以外は、選ぶまで使わない（`notSet`。注意 `smallLandNotSet`）。
- 自宅は亡くなる月に住んでいる持ち家だけ（住まい以外の不動産に自宅を選んでも使わない。`notLived`）。
- **貸し始めて3年以内の貸付**（貸し始めが亡くなる月の36か月前より後）は対象にしない（`within3Years`。注意 `smallLandRecentRental`）。貸し始めは `asset.realEstate` と同じ読み方: 省略は建てる・買う予定の月か取得の月、予定の月（無ければ持ち始める月）より前を入れていればその月（建てる・買う予定の物件は、前からの貸し始めを入れていても予定の貸し始めから数える）。亡くなった人が相続の日まで3年を超えて事業的規模の貸付を続けていた印（`rentalContinued`）があれば対象（措置法69条の4第3項4号）。ちょうど36か月前に貸し始めた物件は対象（テストで境目を確かめる。予定の物件も、買う月から35か月後は対象外・36か月後と37か月後は対象）。
- 面積は土地の面積×名義の割合（亡くなる人の分）。面積が無ければ使わない（`noArea`。注意 `smallLandAreaMissing`）。
- **面積の上限と組み合わせ**: 貸付を入れないとき、自宅330㎡・事業400㎡を別々に、1㎡あたりの減る額の大きい土地から。貸付を入れるとき「事業×200/400＋自宅×200/330＋貸付≦200㎡」を、換算した1㎡あたりの減る額の大きい土地から（分けられる量の詰め方なので、この順が最も多く減る）。2つのうち多く減る方を採る（同じなら貸付を入れない方）。上限を超えた分は減らさない（注意 `smallLandAreaLimit`、使えなかった土地は `limit`）。割り算の丸めが出ないよう、換算は上限の面積どうしの比で数える。
- 減る額＝土地の評価（貸家建付地の減額の後）×適用する面積÷面積×減額の割合（円未満切り捨て）。課税価格の財産から引き、出力 `assets.smallLandReduction` と土地ごとの `lands[].special`（`status`・`rate`・`acquirer`・`appliedArea`・`reduction`）に出す。
- 目安は法定相続分どおりに分けたとみなすので、特例で減った分は取得する人の取得額ではなく遺産の全体から引く（分け方を入れる回まで）。

### 7. 2割加算と未成年者控除（相続税も試算する世帯だけ）

- 2割加算（相続税法18条。No.4157）: 兄弟姉妹・祖父母、代襲でない孫養子（子の子を養子にした人）の税（税額控除の前）に20%を足す。配偶者・子・親・代襲の孫には足さない。
- 未成年者控除（同19条の3。No.4164）: 法定相続人で18歳未満の人の税から、満18歳になるまでの年数（1年未満は1年。年齢は月で数える）×10万円を引く。引ききれない分は扶養義務者の税から引く（配偶者、次に他の相続人の順）。
- 控除の順は 2割加算 → 配偶者の軽減 → 未成年者控除 → 精算課税で払った贈与税。法定相続人の数を直した世帯（人ごとの行が無い）では入れない。
- 障害者控除は入れない（世帯の人に障害者の区分の欄が無い。次の回）。

### 8. 注意・含めていない一覧

- 相続税も試算する世帯は、注意の `smallLandSpecial`・`twentyPercentSurcharge` を出さず（計算に入れた）、`smallLandNotSet`・`smallLandAreaMissing`・`smallLandAreaLimit`・`smallLandRecentRental`・`landInputMissing` を出す。
- 含めていない一覧（`notIncluded`）は、試算する世帯だけ `NOT_INCLUDED_DETAILED`（土地の評価の細部・小規模宅地等の特例・2割加算・未成年者控除を外し、「土地の補正（奥行・間口・形。補正の率を入れたときだけ）」`landCorrectionDetail` を足す）。チェックしない世帯は今までの一覧。

### 9. 制度データ（`regulation.tax` 2026.22.0）

- 足した値: `inheritanceTax.smallLand.residential.areaLimit`（330）・`.residential.reductionRate`（0.8）・`.business.areaLimit`（400）・`.business.reductionRate`（0.8）・`.rental.areaLimit`（200）・`.rental.reductionRate`（0.5）・`.rental.recentYears`（3）・`inheritanceTax.surcharge.rate`（0.2）・`inheritanceTax.minorCredit.perYear`（10万円）・`inheritanceTax.minorCredit.untilAge`（18。令和4年4月1日から）。
- 国税庁のタックスアンサー（No.4124・4157・4164。令和8年4月1日現在法令等）の本文の抜粋で読んだ。原本の指紋を取れなかったので、すべて原本での確認待ち（`pendingReview`）。
- 借家権割合30%・借地権割合の記号（A〜G）・8/7 は法令の値ではない（財産評価基準書・推定）ので、部品の定数（`TENANCY_RIGHT_RATIO`・`LEASEHOLD`・`FIXED_TO_ROUTE`）にした（0039 の評価の割合と同じ考え）。

### 10. 計算部品と速さ

- `inheritance.estimate` 改訂6・約束の版 1.2（出力の任意の欄を足す MINOR。0232 の改訂5〔土地ごと買う予定は買う月から持つ〕の後）。`asset.realEstate` の `years[].assessed`・`years[].rentedShare`（約束の版 1.7）を読む。時点ごとに1回だけ評価し、年ごとの再計算は増やさない（0005・0170）。見本の世帯の結果は変わらない（試算する世帯が無い）。一致テストに、試算する世帯（`rentalSample` に持ち家・物件2件の設定）`engine/test/fixtures/parity/inheritance-detailed.json` を足した（Node・quickjs・JavaScriptCore で一致）。
- 8/7 は割り算の丸めを避けて「固定資産税評価額×8÷7」で数える。

## 理由

- **チェックした世帯だけ**: 相続税がかかる世帯は一部で、路線価・面積・要件の確かめは手間がかかる。チェックしない世帯の計算と入力を変えないことで、今の目安の数字と使い方を守る。
- **設定を相続税の目安の設定の中に置いた**: 物の計算に効かない前提で、毎回の計算から外す決まり（0061）とプランの差分がそのまま使える。物の欄に置くと、物の入力項目（住まい・ローン、収益不動産）に相続税の欄が混ざる。
- **要件は利用者が選ぶ**: 要件（申告期限までの居住・保有・事業の継続、家なき子の3年の持ち家の有無）はライフプランの入力から決まらず、ソフトが判定すると誤った安心を与える。配偶者の自宅だけは要件が無いので既定にした。
- **入れた値を評価額の推移で動かす**: 先の年の路線価・評価額は分からない。物件の評価額の推移（前提条件の土地の上昇率・建物の下がり方）と同じ割合にすると、時価で見る既定と動きがそろい、二次の時点でも数字が飛ばない。

## 代案（採らなかったもの）

- 特例をいつも計算に入れる（配偶者が取得するとみなす）: チェックしない世帯の目安の数字が変わり、要件を確かめていない世帯に大きな減額を見せてしまう。
- 土地の面積・路線価を物の欄（住まい・収益不動産）に置く: 固定資産税の推定などに使える可能性はあるが、相続税の試算をしない世帯の入力項目にも欄が並ぶ。必要になったら物の欄から読む形を足せる（面積は既に収益不動産の欄から読む）。
- 組み合わせの上限を「自宅を先に」の決まった順で詰める: 貸付の1㎡あたりが大きい世帯（都心の収益不動産）で、実務の選び方より税が多く出る。

## 次の回（年ごとの一次・二次）への申し送り

- 部品の評価は1つの時点の関数（`evaluateLands`。不動産ごとの時価の部分〔物件全体と亡くなる人の分〕・時点・亡くなる人を受け取り、土地ごとの評価と特例を返す）にしてあるので、年ごとの一次・二次の推移は、時点の並びを増やしてこの関数を呼ぶ形にできる。年ごとに呼ぶと時点の数だけ重くなるので、速さの約束（0005・0170。Windows の quickjs-ng で3秒目安）の計測を一緒に入れる。
- 二次の時点は `secondary` を読む。一次で配偶者が取得した土地を二次で誰が取得するか（同居の子がいるか）は、二次の時点の家族（子の同居・持ち家）で選び直す形を画面に足す。二次で一次の配偶者の取得分（配偶者の軽減で税が0の分）が二次の遺産に乗る計算（一次の遺産の分け方を入れる）は、分け方の比較の回の主題。
- 収益不動産の「建てる・買う予定」（0232）が先に入ったので、この回は `inheritance.estimate` 改訂6・形式 0.86 にずらし（約束の版 1.2・制度データ 2026.22.0 は 0232 が使っていないのでそのまま）、賃貸割合の省略を `asset.realEstate` の `years[].rentedShare` に、予定の物件の建物の評価を `years[].assessed` に切り替えた（4・5）。
- 建物の評価額の先の年の動き（今は建物の評価額の推移と同じ割合）を、経年減点補正率の動き（`assessed` と同じ式）にするか。
- 法定相続分どおりの分け方のままでは、特例で減った分を取得する人に寄せられない（配偶者の軽減の計算に効く）。分け方を入れる回で、`lands[].special` の取得する人を人ごとの取得額に結ぶ。
