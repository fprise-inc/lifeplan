# 0225. 起動時の窓を、モニターの作業領域に収める

- 状態: 採用（2026-11-18）
- 固定の強さ: 内部（窓の大きさと位置の決め方。世帯ファイル・公開の約束には関わらない）
- 前提にする記録: 0016 の1（画面は本体で作る窓の中。窓は `create: false` で本体が作る）

## 背景

- 窓は `tauri.conf.json` で 1440×900（論理ピクセル）・最小 1024×700 の固定だった。
- Windows のノート PC（1920×1080・拡大150%＝論理で 1280×720、タスクバーを除くと高さ約672）では、窓が画面より大きくなり、入力のパネルの下のボタンやアプリの下の部分がタスクバーの裏に隠れた（利用者の実機で確認）。最小の高さ 700 も作業領域より大きく、利用者が縮めても収まらなかった。

## 決定

1. 窓は見えない状態（`visible: false`）で作り、本体の起動の流れ（`setup`）で大きさと位置を決めてから見せる（一瞬大きく出てちらつかない）。
2. 判断に使うのは、窓が出るモニター（`current_monitor`。取れなければ `primary_monitor`）の作業領域（`Monitor::work_area`。Windows はタスクバー、macOS はメニューバーと Dock、Linux はパネルを除いた領域）と、そのモニターの拡大率（`scale_factor`）。複数のモニターでは、窓が出る側のモニターだけを見る。
3. 窓の外側（タイトルバー・枠を含む。作った窓の外側と中身の差から求める）が作業領域に収まる大きさまで、中身の大きさを縮める。縮めるのは入らない向きだけ。収まる画面では、これまでどおり 1440×900。
4. 最小の大きさ（1024×700）が、縮めた後の大きさより大きいときは、最小の大きさも縮めた後の大きさまで下げる（最小の大きさのせいで、また画面からはみ出さない）。
5. 窓の外側が今の位置のままで作業領域に収まっていれば動かさない。はみ出していれば作業領域の中央に置く。
6. 最大化はしない。最大化すると、元に戻したときの大きさが 1440×900 のままで、また画面からはみ出すため。
7. モニターの情報が取れないとき・値がおかしいとき（作業領域が空・拡大率が正でない・枠だけで作業領域を超える）は何もしない（これまでどおりの大きさと位置で見せる）。
8. 計算は純粋な関数（`app/src-tauri/src/window_fit.rs` の `fit`）に分け、拡大率 100/125/150/175%・作業領域ちょうど・1px 足りない・縦長・小さい画面・2台目のモニター（負の座標を含む）・macOS の作業領域を単体テストで確かめる。

## 画面の側

- 狭い高さ（論理 1280×640・1000×560 で確認）でも、ページはスクロールでき、入力のパネルは画面の中に収まり、中身だけがスクロールして下の「キャンセル」「保存」は見えたまま。画面の側は変えない。

## 使わなかった案

- Tauri の設定 `preventOverflow`: 窓を作るときに作業領域に合わせて縮めるが、見るのは主モニター（位置を指定しないとき）で、最小の大きさは下げないので、最小の大きさが作業領域より大きい画面では収まらない。
