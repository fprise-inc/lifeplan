# 0256. 画面を指す言葉を「〇〇の確認画面」にそろえる

- 状態: 採用（2026-11-23）
- 固定の強さ: 内部（言葉だけ）。画面の動き・計算・世帯ファイルの形・接続口の道具の形は変えない。決まりとして残すのは「画面を指すときは『確かめの画面』『確かめる画面』『確認の画面』を使わず『確認画面』と書く」「必ず『〇〇の確認画面』とどの場面の画面か分かる形にする」「同じ画面は同じ名前で呼ぶ（下の表）」の3つ
- 前提にする記録: 0138（Web のヒアリングのお客さまの画面）、0148（書類の読み取りと確認画面の共通の部品）、0208（AI からの新しい世帯の候補）、0222（AI が発行した Web のヒアリングの URL）、0113（他のソフトからの移行）

## 背景

- 画面の文・知らせ・手引き（`docs/app-guide`）・AI への説明・コードのコメントで、値を見直して承認する画面を「確かめの画面」「確かめる画面」「確認の画面」と書き分けていて、どの場面の画面かも書かれていない所が多かった（例「確かめの画面で選びます」）。FP にもお客さまにも、どの画面のことか分かりにくい。
- 利用者の判断（2026-11-23）: 画面を指すときは「確認画面」に統一し、必ず「〇〇の確認画面」とどの場面か分かる形にする。動詞の「確かめる」（値を確かめる等）は対象外。

## 決定

### 1. 名前の一覧

| 名前 | どの画面か | 主な場所 |
|---|---|---|
| 書類の読み取りの確認画面 | 書類（保険証券・課税明細書・路線価図など）から読んだ値の候補を、FP が1つずつ承認する画面（見出し「書類の読み取りの確認」。0249 の変更〔#589〕で「書類の読み取りの確かめ」から直した） | `app/src/workspace/documents/*`・`app/src/styles/review.css`・`docs/app-guide/03-import.md`・`sdk/`・接続口の `propose_inputs` の答え（`crates/ai-share/src/registry.rs`） |
| AIからの新しい世帯の候補の確認画面 | AI が組み立てた新しい世帯の候補を見て「世帯として作る」を押す画面（見出し「AIからの新しい世帯の候補」） | `app/src/workspace/ai/AiHouseholdCandidates.tsx`・`ai/households.ts`・`App.tsx` |
| AI が発行した URL の確認画面 | AI が発行した Web のヒアリングの URL を見て、取り込み先を選ぶ画面（見出し「AI が発行した URL」） | `app/src/workspace/ai/AiHearingIssued.tsx`・`App.tsx` |
| 入力内容の確認画面 | Web のヒアリングで、お客さまが答えを送る前に見直す画面（見出し「入力内容の確認」。お客さまに見せる文もこの名前） | `app/src/hearingForm/Form.tsx`・`hearing/src/web/flow.ts`・依頼の文（`app/src/workspace/hearing/web.ts`） |
| 送る報告の確認画面 | 要望・不具合の報告を、送る前に FP が件ごとに確かめて直す・外す画面（見出し「送る報告の確認」。AI がまとめた報告と「報告の文を書いて送る」の両方。0259 で足した） | `app/src/workspace/notices/ReportConfirm.tsx`・`App.tsx`・接続口の `propose_issue_report` |
| 他のソフトからの移行の確認画面 | 他のソフトから移す値を承認する画面（0113 の9。まだ作っていない） | `app/src/workspace/review/*` のコメント |
| 確認画面の共通の部品 | 上の書類の読み取りと移行の確認画面が使う表の部品（画面の名前ではなく部品の名前） | `app/src/workspace/review/*` |
| 保存していない変更の確認画面 | 世帯を切り替える・閉じる前、プランを帯から外す前に、保存していない変更をどうするか選ぶ画面（保存できなかったときは「保存できなかった変更の確認画面」） | `docs/app-guide/00-overview.md`・テストの見出し |
| 公式の文の更新の確認画面 | カスタム層の文で、公式の文が変わったときに前の公式の文と並べて見る画面 | `crates/custom-layer/src/ledger.rs` のコメント |
| URL の取り消しの確認 | 発行した Web のヒアリングの URL を「取り消す」と押したときに、ボタンの下の段に出る確かめの吹き出し（読み上げ用の名前。AI が発行した URL の確認画面と、Web のヒアリングの依頼の一覧の両方） | `app/src/workspace/ai/AiHearingIssued.tsx`・`app/src/workspace/hearing/WebRequests.tsx` |
| URL の受け付けの終了の確認 | 答えが届いた依頼で「受け付けを終える」を押したときの同じ吹き出し（読み上げ用の名前） | `app/src/workspace/hearing/WebRequests.tsx` |
| 過ぎた予定の確認 | 面談の準備の見直しの流れの1つ（前は「過ぎた予定の確かめ」） | `app/src/workspace/tools/FpTools.tsx` |

- お客さまの画面の「入力内容の確認画面」は、画面の見出し「入力内容の確認」に合わせた。FP の側の文で書くときも同じ名前にする（必要なら「Web のヒアリングの」を前に付ける）。
- 画面の中に出る小さな確かめ（吹き出し・読み上げ用の名前）は、画面ではないので「〇〇の確認」と呼ぶ。何の取り消し・何の終了かが分かる名前にする（利用者の判断 2026-11-23。「取り消しの確かめ」→「URL の取り消しの確認」）。
- 同じ文の中で2回目に出るときは「その画面」と受けてよい（例「書類の読み取りの確認画面で承認したものだけが現状に入ります。書類の名義の人も、その画面で選びます。」）。

### 2. 直した所

- 画面の文: 入力のホームの書類の読み取りの説明（`DocumentStart.tsx`）・お客さまへの依頼の文（「送る前に、入力内容の確認画面で見直せます」）。

- コードのコメントとテストの見出し。

## 考えた別の案

- 「確かめの画面」にそろえる: 利用者の判断で「確認画面」にした。
- 場面の名前を付けず「確認画面」だけにする: どの画面か分からないので取らない。
