# 0158. Web のヒアリング: 書類は答えと別に何回でも送れる・期限は30日の決め打ちと延長（90日まで）・分岐の答えを FP に届ける

- 状態: 採用（一部未確定）（2026-11-07）
- 固定の強さ: 骨格（0125 の骨格の追記: 受け付けの API の道と体の形〔書類の送り・受け取った分を消す・延長〕・暗号の用途〔書類の送り状〕・届いた答えの中身の形 `fprise-lifeplan-hearing-web-answers` 0.2 と書類の送り状の形 `fprise-lifeplan-hearing-web-documents` 0.2・期限の決まり〔30日・延長は押した日から30日・作った日から90日まで〕）。お客さまの画面・FP の画面・言葉・上限の値・掃除の時刻は内部。世帯ファイルの形式の版は変えない（`hearing.web` の1件に任意の欄を足すだけ。本体は中身を読まない）
- 前提にする記録: 0016（画面の安全）、0018（ヒアリングシートの形式）、0074（面談の準備）、0102（書類のお願い）、0125（Web のヒアリング）、0138（お客さまの画面）

## 背景

- 0125 では、答えは1回だけ送れ、書類はその答えの中の一覧に載せて一緒に届けた。送った後は書類も足せず（409）、FP は受け取ると依頼をサーバーから丸ごと消した。期限は FP が7・14・30日から選び、延長は無かった。
- 発行から取り込みまで通して確かめたところ、次が見つかった。
  - 「あとで送る」の書類を、同じ URL で後から送る手段が無い（0125 の未確定）。事前のヒアリングの答えと書類は、そろう時期が違う。
  - 期限が過ぎそうなときに延ばせない。新しく発行すると URL が変わり、お客さまの端末の途中の答え（前の URL の鍵で暗号化）は引き継がれない。
  - 分岐の問い（配偶者の方がいるか・お子さまの人数・住宅ローンの本数・保険の件数・ご両親のことをうかがってよいか）の答えは答えの一覧に入れない決まりで、お子さまを「いない」と答えても FP に伝わらない（配偶者の方の「いらっしゃらない」だけは該当なしとして届く）。
- 利用者の判断（2026-11-06）:
  - **書類は答えと別に動く**: URL は1つ。答えは1回だけ。書類は期限まで何回でも、答えを送った後でも送れる。受け取ったら FP が自分で管理し、サーバーの分は消す。
  - **期限は選ばせず30日の決め打ち**。延長はできるようにする（押した日から30日。最初に作った日からの合計の上限は90日）。
  - **分岐の答えを FP に届ける**（答えの中身の形に足す。本番の受け付けはまだ公開していないので、前の形の受け入れは作らない）。

## 決定

### 1. 書類の送り（答えと別に、期限まで何回でも）

- お客さまは、書類のファイルを今までどおり1つずつ暗号化して置き（`PUT /requests/<名前>/files/<番号>`）、その後に**書類の送り状**（どの書類のどのファイルか・形・大きさ・指紋）を FP の公開鍵あてに暗号化して「書類の送り」として置く。
  - `PUT /requests/<名前>/batches/<送りの番号>`（送るときの合言葉）。体は `{"data": "<送り状の暗号文>", "files": ["<ファイルの番号>", …]}`。ファイルの番号は乱数なので中身を含まない。サーバーはこの番号で、送り状に載ったファイルを外せなくする（`E_RELAY_SEALED`）。
  - 送りの番号（16字）は、送るファイルの番号から決める（SHA-256 の前の12バイト）。つながりが切れて同じ送りを送り直すと同じ番号になり、サーバーは同じファイルの一覧なら受ける（200）。違えば断る（409）。
  - 送り状に載せられるのは、置いてあって、まだほかの送りに載っていないファイルだけ（1〜20）。サーバーに同時に置ける送りは30まで（FP が受け取ると消える）。ファイルは同じ番号に書き直せない（送り状に載せた後に中身を替えられないように）。
  - 暗号の用途は `batch:<送りの番号>`（AAD と鍵の導きに入れる。別の送りの番号の所へ移された送り状は開けない）。
- **答えの前でも後でも送れる**（下の「決めたこと」）。答えは今までどおり1回だけ（2回目は 409）。
- 送り状の中身は `fprise-lifeplan-hearing-web-documents` 0.2: 形式名・版・依頼番号・送りの番号・送った日時・書類ごとのファイルの申告（番号・形・大きさ・指紋）。答えの中身の書類の欄は、書類ごとの**状態だけ**（付けた・手元にない・あとで送る・まだ）にした。
- FP は、受け取るたびに、届いている答え（まだ受け取っていなければ）と、届いている送りを全部受け取る。送り状は依頼番号・送りの番号・頼んだ書類・サーバーの送りのファイルの一覧と照らし、頼んでいない書類・送りに載っていないファイル・重なり・形の違いは捨てて数える。ファイルは今までどおり指紋・形・大きさが合うものだけを受け取る。開けない送りは受け取らずに数え、サーバーに残す。
- 受け取って世帯ファイルに書けてから、**受け取った答えと送りだけ**をサーバーから消す（`DELETE /requests/<名前>/answers`・`DELETE /requests/<名前>/batches/<送りの番号>`。送りはファイルを先に、送り状を最後に消す）。依頼の記録と問いは期限まで残し、お客さまは同じ URL で書類を足せる。答えを消しても「答えは送った」の記録（日時）は残るので、2回目は断る。
- FP が依頼を消す（`DELETE /requests/<名前>`）と全部消える。答えを受け取る前は「取り消す」、受け取った後は「受け付けを終える」（URL はもう開けず、書類も届かない）。

### 2. 期限: 30日の決め打ちと延長

- 依頼を作ると、サーバーが期限を決める: **作った日から30日**。延長できる上限（`limitAt`）は**作った日から90日**。依頼を作る体から期限を外した（答えは `{"expiresAt", "limitAt"}`）。
- **延長**（`POST /requests/<名前>/extend`。受け取りの合言葉）: 期限を「押した日から30日」と「上限」の早い方にする。今の期限がもうそれより先なら変えない（200 で今の期限）。上限に達していれば断る（409 `E_RELAY_EXTEND_LIMIT`）。どこまで延びるかはサーバーの時計で決める（FP の PC の時計がずれても同じ）。
- 権限は受け取りの合言葉だけ（サーバーはハッシュと比べるだけ。お客さまの送るときの合言葉・別の依頼の合言葉では延ばせない）。期限を過ぎた依頼は延ばせない（見つけたときに消すので 410・404）。
- お客さまの画面の期限は、問いの中の値ではなく、問いを受け取るときのサーバーの値（延長を反映）を出す。
- 期限を過ぎた依頼は、見つけたときに消すほか、**毎日の掃除**（Workers の決まった時刻の呼び出し。`wrangler.toml` の `[triggers]`）で中身ごと消す。掃除のために依頼の記録の置き場を `m/<名前>` に分けた（中身は `r/<名前>/` の下）。
- **R2 の期限の決まり（ライフサイクル）は「置いてから91日で消す」**（バケット全体。0125 の31日を改めた）。理由: 依頼の記録と問いは作った日に置き、延長で最長90日まで要る。31日のままだと、延長した依頼の問いが期限より先に消える。91日なら、作った日に置いた物は最長の期限（90日）まで残る。延長で書き直す依頼の記録も、書き直した日から91日なので先に消えない。期限の後に残る物は毎日の掃除で消え、掃除が止まったときも、どの物も置いてから91日で消える。

### 3. 分岐の答えを届ける

- 答えの中身を `fprise-lifeplan-hearing-web-answers` **0.2** にした: `gates`（分岐の問いの答え。配偶者の方・ご両親のことは 1 か 0、お子さま・住宅ローン・保険は数）を足した。送るのは、今の答えで出た分岐の問いのうち答えたものだけ（賃貸と答えて住宅ローンの本数を聞かなかったなら送らない）。「0人」と答えたことも届く。
- FP の側は、知っている問いで、選んだ項目に関わり（例: お子さまの項目を選んだ依頼のお子さまの人数）、数が繰り返しの範囲の中のものだけを受け、ほかは捨てて数える。前の形（0.1）は受けない（本番の前のため）。
- FP の画面: 依頼の行に「分岐の答え: 配偶者の方 いらっしゃる・お子さま いない・ご両親のこと いいえ（今回は答えない）」。面談の準備（0074）の「前回から変わったこと」の「ヒアリングシートの見直し」の下に、いちばん新しく受け取った依頼の分岐の答えと、今の世帯との違い（「お子さま いないとのお答え・今の世帯は 2人」）を出す。読むだけで、世帯は変えない。
- **取り込みにはまだつながない**（取り込みの手順を直している別の変更と重なるため）。分岐の答えは依頼の記録の `received.gates` に入る。取り込みの候補（「お子さまは0人とのお答え（今は2人）」を要確認に出す など）は、その変更の後の別の変更でつなぐ。

### 4. お客さまの画面

- 書類の画面に「書類だけ先に送る」（付けた書類があるとき）。「この内容で送る」は、まだ送っていない書類を先に送ってから答えを送る（答えの送信に失敗しても、送った書類は送り直さない）。送ったファイルは「送りました」で外せない。
- 送った後の画面に「書類を続けて送る」。同じ URL を開き直すと、答えを送ってあれば「書類を送る」の画面（「お答えは〇月〇日に送っていただいています」・期限まで何回でも送れる・撮る・ファイルを選ぶ）。「手元にない」「あとで送る」は出さない。頼んだ書類が無い依頼は、今までどおり「お答えいただいています」だけ。
- この端末から送った書類の控え（送った日時・書類ごとのファイルの数。中身・ファイル名は残さない）を、依頼の鍵から導いた鍵で暗号化して端末に置き、「書類を送る」の画面に出す。
- 「あとで送る」にした書類は、送った後の画面で「用意できたら、届いたリンクを開き直して送ってください」と案内する（FP から別の送り方を知らせる、を改めた）。

### 5. FP の画面

- URL を作る画面から有効期限の選択肢を外し、「回答の期限は発行した日から30日。足りないときは依頼の一覧の『延長』で、押した日から30日に延ばせます（発行した日から90日まで）」と出す。
- 依頼の一覧: 期限と延長の上限、答えを受け取った日時・書類を何回受け取ったか、「届いたかを確かめる」（答え・新しい書類の送りの数）・「受け取る」（答えの後も、期限まで何回でも）・「延長」（上限なら押せず、理由を出す）・「取り消す」／「受け付けを終える」。書類の欄に「受け取った書類の送り」（送られた日時・受け取った日時・書類ごとの数）と、ファイルごとの受け取った日時。取り込み済みの依頼でも書類は受け取れる。
- 依頼の記録（`hearing.web` の1件）に足した欄: 依頼の記録の `limitAt`、受け取った答えの `gates`、受け取った送りの記録 `batches`（送りの番号・送った日時・受け取った日時・書類ごとの数・受け取れなかった数）、ファイルの `batchId`、受け付けを終えた日時 `closedAt`。前の記録に `limitAt` が無ければ発行の日時から90日とみなす。
- 本体の命令（`hearing_web_call`）が通す道に、書類の送りを読む・受け取った答えと送りを消す・延長を足した（FP の動きだけ。お客さまの動きは通さない）。

### 決めたこと（迷った所）

- **答えを送らずに書類だけ先に送れるようにした**。理由: 0125 の形では、書類のファイルと送り状は FP の公開鍵あてにそれぞれ暗号化して置く独立した物で、権限も同じ送るときの合言葉。答えと結びつける必要が無く、止めるにはサーバーに「答えの後だけ」の決まりを足すことになる。お客さまが書類だけ先に用意できたとき（答えに時間がかかるとき）にも送れ、答えに失敗しても書類は届く。FP の受け取りも答えと送りを別々に扱うので、順番を問わない。
- 延長は「押した日から30日」をサーバーの時計で決め、今の期限より延びないときは変えずに今の期限を返す（断らない）。FP の画面では上限のときだけ押せなくし、それ以外は押せる（押して延びなければ「今の期限のままです」と出す）。PC の時計とサーバーの時計がずれても、押せるのに延びない・押せないのに延びる、が起きないように。
- 答えを受け取った後も、依頼と問いは期限までサーバーに残る（書類を受けるため）。「確かめてもらう」項目の前回の値も問いと一緒に残るので、FP が早く閉じたいときのために「受け付けを終える」を置いた。
- お客さまの画面の書類の上限（1つの依頼で20ファイル・40MB・1通に6ファイル）は、1回の送りの上限として数える（FP が受け取ればサーバーの分は消えるため）。サーバーの上限（ファイル30・合計の大きさ・送り30）は、同時に置いてある分で数える。

## 理由

- **送り状を分ける**: 答えの中の書類の一覧を後から書き換える形にすると、「答えは1回だけ」（条件つきの書き込み）が崩れる。送りを足していく形なら、答えの決まりはそのままで、書類だけ何回でも届けられる。FP は送りごとに受け取り、何をいつ受け取ったかを残せる。
- **送りのファイルの番号をサーバーに見せる**: 送り状に載せたファイルを、URL を知った人が外せないようにするため。番号は乱数で中身を含まない（提供元が読めるものは増えない）。
- **送りの番号をファイルの番号から決める**: つながりが切れたときの送り直しで、同じ送りが2つにならない。
- **期限をサーバーが決める**: 決め打ちの30日・延長の上限90日を、FP のアプリの版や PC の時計に左右されずに守れる。
- **R2 の91日と毎日の掃除**: R2 の期限の決まりは置いた日からの日数だけで、依頼ごとの期限を知らない。掃除で期限どおりに消し、91日は掃除が止まったときの備え。
- **分岐の答えを答えの中身に入れる**: 届かなかった軸から推し量る形（取り込みの側）では、「答えなかった」と「0人と答えた」が見分けられない。

## 代案（採らなかったもの）

- **「あとで送る」の書類だけを頼む新しい URL を作る**: URL が2つになり、お客さまの途中の答え・端末の控えが引き継がれない。利用者の判断で、URL は1つ。
- **答えを何回でも上書きできるようにする**: 「答えは1回だけ」は、URL が漏れたときに後から別の人が書き換えるのを防ぐための決まり（0125 の影響）。書類は足すだけなので、何回でもでよい。
- **延長を「今の期限から30日」にする**: 利用者の判断は「押した日から30日」。今の期限から足すと、早めに押すほど長くなり、上限の90日に早く届く。
- **R2 の期限の決まりを依頼ごとに分ける（置き場の名前に期限の日付を入れる）**: 延長のたびに置き場を移すことになる。掃除と一律の91日で足りる。

## 追記
