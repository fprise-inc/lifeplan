# 0048. 基本生活費のカードの中身（総額と費目・段階の表・年払いの暮らしの支出・黒字の割合・答え合わせ・医療費の説明）

- 状態: 採用（一部未確定）（2026-10-26）
- 固定の強さ: 内部（画面の作り）。世帯ファイルの形・エンジンの入力は変えない（今ある欄 `livingExpenses`・`periodicExpenses` の種類 `livingAnnual`・`savingsChecks`・`assumptions.surplusSaving` を画面に出しただけ）。費目の按分の統計（マスタデータ `living.statistics.categoryMonthly.*`）は値の追加。欄の並び・文言・ひな形の額は後から変えてよい

## 背景

- 基本生活費のカードは、総額か内訳の切り替え（内訳は決まった4費目の割合で作り直し、総額に戻すと内訳を消した）、印の無い節目のボタン、黒字のうち貯まる割合だけだった。年1回・数年に1回の暮らしの支出はライフイベントのカードの行で、明細の年1回の支払いもそこに入った。現状の検算（`savingsChecks`）はヒアリングシートから入るだけで、画面に見る所が無かった。
- 前提にする記録: 0008（世帯のデータモデル・値の箱）、0031（黒字のうち貯金に回る割合）、0034（明細の取り込み）、0035（世帯ファイルの形）、0036・0043（プランの差分と入力画面でプランを直す）、0038（時点の部品）、0040（段階）、0041（値の状態）、0044（お金の行）、0045（14枚のカード）、0049（生活費の人数と推定の段階）。

## 決定

### 2. 総額と費目

- 総額と費目は同じ物の粗さの違いなので、入れ方の切り替え（`mode`）にする。**エンジンの `monthly` と `categories` を両方持ち、`mode` で使う方を選ぶ**（切り替えても片方を消さない。計算は今のまま）。
- 総額で → 費目で（費目がまだ無いか、按分の推定のまま）: 総額を家計調査の同じ人数の世帯の費目の割合で9費目に分ける（推定。出し方 `derived`、根拠「総額を費目に分けた目安（…）」）。仕送りは0円（子ども・教育、介護・親のカードで入れるので二重を避ける）、端は「その他の消費」。合計は総額と同じ。
- 費目で → 総額で: 総額が費目の合計と違えば、総額＝費目の合計（推定の費目があれば推定「費目の合計から」、無ければ確定）。
- 費目で入れた後に総額を直してから費目に戻す: 費目は前のまま。差は「その他の消費（まだ分けていない）」に置き、推定の印と「総額で月○万円に変えました。差の○万円を…」の文（比例で配り直さない）。
- 簡易の6つの束: 食費／水道・光熱費／日用品・衣服（家具・家事用品＋被服）／交通・通信費（車を除く）／趣味・旅行（教養娯楽）／医療・こづかい・その他（保健医療＋その他の消費＋仕送り）。1費目の束はその費目の欄。2費目以上の束は合計の欄で、直すと差を束の代表の費目（家具・家事用品／その他の消費）に置く（ほかの費目は今の値のまま。比例で配り直さない）。束の値の状態の操作は束をまとめた箱で受け、確定は束の中の推定の費目を今の値のまま確定にする。詳細では束の下に「うち …」で9費目を出す。
- 費目の欄の横に「同じ人数の世帯の平均 月○万円」（家計調査の同じ表）。空にした費目は外す（入れていない費目は物を持たない）。
- 人数が変わり、費目が按分の推定のまま・総額が統計の推定のままなら、総額と按分を入れ直す（`estimates.ts` の `refreshEstimates`）。
- 欄の当て先は、費目は要素の ID と `monthly`、総額・入れ方・伸び方・始まり・終わり・万一のときの扱いはそれぞれの入力項目ID。欄のキーは今の `living/<物>/cat/<番号>`・`stage/<番号>` のまま（読み替え表・動かす項目のキーと同じ。当て先は ID で持つので、並べ替えで別の要素に当たらない）。

### 3. 年払い・数年おきの暮らしの支出

- 行は 0044 のお金の行。表の行は「基本生活費に含める」「医療・介護」「その他の支出」から選ぶ（ほかの行の古い行は、その行も選べるまま）。
- 確かめの一覧（詳細）: 帰省・家電の買い替え・家具の買い替え・年会費とサブスクの年払い・冠婚葬祭のつきあい・お年玉と贈り物・通院と歯の治療・ペットの医療・旅行。名前が当たる行がどこかのカードにあれば「入れた（行の名前）」とそのカードを読むだけで出し、無ければひな形の目安の額で足すボタン（額は目安のボタンの値＝推定 `standard`。統計ではない）。ほかのカードで入れる物（固定資産税・修繕、自動車税・車検、保険の年払い）は、そのカードの物があるかを読むだけの1行で出す。
- 明細の年1回の支払いの候補（0034 の `statementAnnual`）は、車・住まいの修繕を除き、この区画の行（種類 `livingAnnual`、表の行は基本生活費に含める。医療は医療・介護）として承認する。承認した古い行は動かさない（ライフイベントの行のまま）。

### 4. 医療費の窓口負担

- 70〜74歳2割・75歳以上1割（所得で2〜3割）への切り替えは**自動にしない**。保健医療の費目・「医療・こづかい・その他」の束・年払いの区画の表の行の欄に「計算では自動で変えないので、額を変えるときは段階で入れてください」と書く。医療費だけ分けて伸ばすときは、年払いの区画に「医療・介護」の行を足し、行の伸び方・段階で変える。

### 5. 段階の表

- 段は何段でも。段ごとに節目・いつから（時点の部品）・入れ方（最初の額に対する割合で／月額で）・割合か月額（もう片方の目安を横に出す「＝月○万円」「今の額の○%」）・外す。表は詳細、簡易は札。
- 節目を足すボタン（子の独立の後・退職後・70歳から・80歳から・その他の節目）の割合は目安のボタンの値で、推定（出し方 `standard`）の行を割合に付ける（印の無い決まった値にしない。0041）。
- 推定の段階（人数の変化と年齢から作る段）は 0049。

### 6. 古い世帯

- 開いても何も書き換えない。費目の欄は今ある費目をそのまま読み、無い費目は空の欄（入れると物を作る）。今までの決まった4費目の内訳もそのまま。推定の段階は入れない（0049 の3）。

## 理由

- 総額と費目を両方持つ: 切り替えで FP が入れた値を消さない（前は総額に戻すと費目が消えた）。エンジンはもう `mode` で選んでいるので、計算は変わらない。
- 差を「その他の消費」に置き、比例で配り直さない: FP が直した費目を勝手に変えない。どこに差が行ったかを1つの欄と文で見せられる。
- 年払いを基本生活費のカードに置く: 聞き漏れの確かめ・明細の年1回の支払い・家計の答え合わせが、どれも暮らしの支出の確かめで、同じパネルで終えられる。
- 窓口負担を自動にしない: 自動にするには医療費の総額（10割）を入れる欄が要り、入力が増える。額の変わり目は段階で表せる。

## 代案（採らなかったもの）

- 費目を独自の入力形式（区分）にする: 同じ情報の粗さの違いで、形式を分ける理由が無い。
- 総額を直したら費目を比例で配り直す: FP が直した費目が黙って変わる。
- 確かめの一覧の「無い」「あとで」を記録する: 置き場所（世帯ファイルの形）が要る。今は入れた所を自動で見るだけ。

### 2026-10-27: 入れ方の言葉を「総額で／内訳で」に・内訳の行のアイコン

- 入れ方の「費目で」は使う人に分かりにくかったので「**内訳で**」に言い換える（「総額で」はそのまま）。人が見る所で、この入れ方の意味の「費目」を合わせる: 入れ方の選択肢、まとまりの名前「内訳（月額）」、欄の説明（束の合計・その他の消費）、まとまりの添え書き、総額の推定の根拠「内訳の合計から」、按分の推定の根拠「総額を内訳に分けた目安」、同じ人数の世帯の平均の根拠「…の世帯の内訳の割合」、入力項目の名前（`engine.input.json` の title と登録簿。プランの変えたことの一覧などに出る）「入れ方（総額／内訳）」「内訳の月額（計算基準年の価格）」。
- 変えないもの: 各行の名前（食費など）、コードの識別子、世帯ファイルの値（`mode` の `byCategory`、`category` の値）、マスタデータの表の名前（統計の区分の説明）。前に保存した世帯の推定の根拠の文（「総額を費目に分けた目安」）は書き換えず、按分のままかの判定（`isPureSplit`）は前の言い方も読む。
- 内訳の各行の名前の左に小さな線のアイコンを付ける（標準の6行と、詳細の「うち」の行。9つの内訳すべてと2つの束）。入力のホームのカードの絵に合わせ、黒い線（文字の色）にカードの色をごく一部だけ差す。ファイナンシアのために描いたもの（`app/src/workspace/input/fieldIcons.tsx`。リポジトリの MIT）で、外から読み込まない。

- 計算・世帯ファイルの形式・見本の世帯の結果は変わらない。テスト: `app/test/living-card.test.ts`。
