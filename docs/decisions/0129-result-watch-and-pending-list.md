# 0129. 単位の読み取りの表と、ありえない結果の見張り（直す待ちの一覧）

- 状態: 採用（一部未確定）（2026-11-06）
- 固定の強さ: 内部（テストだけ。画面・計算・世帯ファイルは変えない。世帯ファイルの形式の版は変えない。決まりの中身・世帯の並び・言葉は後から変えてよい。変えたら追記に書く）
- 前提にする記録: 0002（金額・率・入力欄の単位）、0008（値の箱と推定の印）、0033（見本の世帯）、0036（違いの一覧）、0041（推定の値の状態）

## 背景

- 入力項目を通しで入れて確かめたところ、結果を黙って誤らせる不具合がまとまって見つかった（円の欄の「15万」が15円、定年が過ぎた人に過去の退職一時金の推定、売った家の住宅ローンを返し続ける、亡くなった後も介護の費用が続く、資産配分の割合が計算に入らない、事業所得が表の「その他の収入」に入る など）。どれも単体のテストでは見ていない「入力の操作と結果の組み合わせ」で起きていた。
- 不具合を1つずつ直すだけでは、同じ種類の誤りが別の所でまた入っても気づけない。直す作業と並べて、同じ種類の誤りを毎回見張る点検を先に置く（利用者の判断）。

## 決定

### 1. 単位の読み取りの表（`app/test/units-table.test.ts`）

- 円の欄・万円の欄の両方で、よく打たれる書き方（「15万」「15万円」「4500円」「1,200」「1.5億」「1億2000万」「478,200円」「１５万」〔全角〕「0.5」「15.5万」「-3」「万」「abc」など）を `parseYen` で読み、読めた額（円の整数）か「読めない」（null）かを表で確かめる。
- 答えの決まり: 末尾の単位（円・万・万円・億）は欄の単位より優先して換算する（円の欄の「15万」は150,000円、万円の欄の「4500円」は4,500円）。単位の無い数は欄の単位で読む。1円未満は四捨五入（0002 のまま。円の欄の「0.5」は1円）。

### 2. ありえない結果の見張り（`app/test/result-watch.test.ts`・`app/test/watch/`）

- 見張る世帯（`watch/cases.ts`）: 見本の棚の全部の世帯、`data/modelHouseholds/` の世帯（見本の棚に無い物）、入力の操作で作る世帯。入力の操作は、画面の部品と同じ欄の定義とボタン（`buildStage`）をそのまま関数で呼び、欄・ボタンの後に推定を入れ直す（入力のパネルと同じ）。FP がよくする操作の後の形を選ぶ（新しい顧客を会社員・自営業として入れる、働き方の種類を変える、購入の予定を足す、住み終わり・売却を入れる、購入の時期を直す、亡くなる見込みを入れる、相続の相手を変える、退職後の割合を下げる、資産配分に切り替える、口座を足す、プランで介護の場所を変え家族を外す、ヒアリングシートを取り込む）。
- 見張りの決まり（`watch/rules.ts` の `WATCH_RULES`）: 1つの世帯（作業の層の世帯と計算の結果）を受け取り、おかしい所の文を返す。画面は描かない。
  1. 学校・進路を選んだ段の学費が0円（エンジンの「入力が要る」の知らせ・学費の年額0円）
  2. 受け取りが計算の基準の月より前の退職金を推定で足している
  3. 正社員・公務員でない今の働き方に定年の推定が残る・正社員の統計の年収の推定が残る
  4. 期間の終わりの無い働き方で、80歳を過ぎても給与・事業所得が入る
  5. 売らない持ち家が、住み終わりの後に資産から消える
  6. 売った家の住宅ローンを、売った後も返している
  7. 住まいが2つ重なる・最後の住まいの後に住まいが無いのに、住まい・ローンの入力項目に知らせが無い
  8. 購入の時期と、住み始め・購入の住宅ローンの借入の年月・控除の入居がずれている
  9. 今の年の純資産が1,000万円より大きくマイナス・今住んでいる持ち家が資産に入っていない
  10. 介護を受ける人が亡くなった後も介護の費用が続く・推定のままの受け取る相続の時期が相手の亡くなる見込みから外れる（前・2年より後）
  11. 推定のままの70歳・80歳の段の生活費の割合が、退職直後の段より高い
  12. キャッシュフロー表の行とグラフの系列で、同じお金の行き先が違う・事業所得と企業年金（`cf.income.business`・`cf.income.corporatePension`）が表の「その他の収入」に入る。表に行を足したら、グラフの系列との対応の表（`TABLE_TO_CHART`）に書く（書き忘れも見つける）
  13. 資産配分の入れ方で、割合・期待リターンが計算に渡っていない
  14. 残高のある課税口座・NISA の取得価額が0円
  15. 取り込んだ世帯で、世帯の外の家族に亡くなる見込みが無い（入力の画面では「入れない（表の最後まで）」を FP が選べるので、取り込んだ世帯だけを見る）
  16. 画面に出る文字（入力項目の欄の名前・?・選択肢・推定の根拠・知らせ・時点の読み、まとまり・区画の注記、ボタン、確かめの一覧、世帯の中身の一覧、プランの違いの一覧と「変えたこと」）に、英字のキー・小文字の英単語の生の値・JSON・内部の ID・「（4つ）」「12つ」の形の数え方が無い。文は、画面を描かずに文を作る関数（欄の定義・`checkList`・`objectCards`・`diffRows`・`changesOf`）を世帯ごとに呼んで集める。文の中の「1つにまとめる」「最初の1つ」のような言い方は数え方の表示でないので見ない。画面の言葉として使う英字（iDeCo）は許す
- 画面のキー入力で入れた世帯（通しの入力のテスト）にも同じ決まりを当てられるよう、`subjectOf`（世帯を計算して見張る形にする）と `watch`（決まりごとのおかしい所）を書き出す。

### 3. 直す待ちの一覧

- 今ある不具合で決まりに引っかかる物は、テストの中の表「直す待ちの一覧」（`PENDING`）に入れる。行は中身の言葉で書き、鍵（英字の短い名前）・決まり・当たる世帯・当たるおかしい所の文の形を持つ。
- 世帯ごとの見張りは、一覧の行に当たるおかしい所を除いて、残りが無いことを確かめる。一覧の行そのものは「まだおかしい所があること」を確かめる形（vitest の `test.fails`）で通す。単位の読み取りの表も同じ形（打った文字と欄の単位の組）。
- 直したら、その行を一覧から消す。消し忘れると、その行の `test.fails` が「直ったのに一覧に残っている」で落ちる。新しい不具合を見つけて直す前に見張りに足すときも、同じ形で一覧に入れてよい。
- 一覧が空になっても見張りが効くことを、わざと壊した世帯・結果（計算の結果の表を直接壊す・欄の後追いを通さずに値を書く）で確かめる。

### 4. 決めたこと

- 見張りは計算の結果と入力の形だけを見て、画面を描かない（速さと、画面の作りが変わっても決まりが変わらないため）。画面に出る文は、画面の部品が使うのと同じ文を作る関数から集める。
- 「大きくマイナス」の線は今の年の純資産で −1,000万円（住宅ローンのある若い世帯でも、持ち家の時価が入っていれば届かない。時価が抜けた世帯は ▲1,800万〜▲5,000万円になる）。
- 「○つ」は、数を見せる形（括弧の中の「○つ」・2桁以上の「○つ」）だけを見る。文の中の「1つ」「2つ重なる」のような言い方まで禁じると、言葉の決まりの外の文まで落ちるため。
- 受け取る相続の時期は、推定のまま（仮の印）のときだけ亡くなる見込みと比べる。FP が入れた時期は FP の判断として見張らない。
- 住まいの重なり・住まいの無い期間の「知らせ」は、住まい・ローンの入力項目の区画・まとまりの注記と確かめの一覧の文に「重な」「先の住まい」「住まいが入っていません」のどれかがあれば出ているとみなす。知らせを作るときに文の形を変えたら、決まりの言葉も合わせる。

## 理由

- 不具合は「入力の操作の後の形」と「結果」の組み合わせで起きていたので、操作を関数で再現した世帯と結果に、意味の決まりを当てるのがいちばん安く広く効く。画面のキー入力で通す点検（見えないブラウザ）は時間がかかるので、決まりは関数の側に置き、キー入力の点検からも呼べる形にした。
- 今ある不具合をすぐには直せないので、CI を落とさずに見張りを先に入れる必要がある。`test.fails` の行にすると、直った時点で行を消すことを強制でき、一覧が「まだ直っていない物の正」になる。

## 影響

- 画面・計算・世帯ファイルは変わらない。アプリの単体テストに約1,100件（世帯×決まり）と直す待ちの一覧の行が増える（ローカルで約25秒）。
- 不具合を直すまとまりは、直した物の行を直す待ちの一覧（`app/test/result-watch.test.ts`・`app/test/units-table.test.ts`）から消す。表の行を足すまとまりは `TABLE_TO_CHART` に対応を書く。
