# 0054. 保険の計算の足し（医療・がんの給付・保障の行ごとの被保険者・変額と外貨建の円の目安の形・保障ごとの数表・必要保障額の内訳）

- 状態: 採用（一部未確定）（2026-10-26）
- 固定の強さ: β公開から変えない（骨格）。入力の欄の名前と意味（病気の想定 `contingency.illness`、給付の種類 `threeMajorLump`、保障の行の `insured`・`maxDays`、円の目安の形 `insurance.simple.estimate`、種類の細目 `insurance.subtype` と名前 `insurance.label` は計算に使わないこと、保障の ID のある数表の死亡保障の行はその保障だけを置き換えること）と、出力の欄の名前と意味（受け取りの種類 `medical`、年の値の `paid`・`others`、必要保障額の `breakdown`・`coverageBy`）は骨格。既定の値（入院の1回の限度日数 60日）と、内訳の分け方の細かさは後から変えてよい（変えたら追記に書く）

## 背景

- 保険のカードを作り直す（入力の形は 0055）。カードで「保障の推移」と「必要保障額との過不足」を見せ、医療・がんの給付を「病気の想定のときに受け取るお金」として計算することにした。
- 今の計算は、医療保険・がん保険の給付（入院日額・手術・がん一時金）を保障内容の一覧に載せるだけで、受け取りを計算していなかった（知らせ `N_NOT_SUPPORTED` `insurance.medicalBenefit`）。大きな病気の想定（就業不能の想定に医療費を足した形。0026）には、病気の種類・入院の日数・手術の回数が無かった。
- 家族型の医療保険・家族特約（配偶者・子が被保険者の保障を1つの契約に付ける）は、保障の行に被保険者が無く、別の契約として入れるしかなかった。
- 変額・外貨建は、保険料のうち積立に回る分を前提の利回りで伸ばして積立金を出していた。最初の版では本格的に扱わず、保険料と円の目安の保険金額を手で入れる簡易の形にする（想定の利回りの数字が一人歩きしないように）。
- 逓減定期保険（住宅ローンの分など、毎年同じ額ずつ減る死亡保障）は、数表の死亡保障の行で表せるが、数表の行は保険年度の契約全体の額を置き換えるので、同じ契約の死亡の特約が消えていた。
- 必要保障額の推移（6.3）は、必要な資金・準備できる資金の合計だけで、内訳（生活費・住居費・教育費…、遺族年金・遺族の収入・死亡退職金…）と一時と毎年の分け方が無かった。保険のカードの過不足の見せ方に要る。
- 前提にする記録: 0006（部品の約束の版）、0008 の5・10（万一の想定・保険契約）、0026（大きな病気の想定）、0035（足すだけの形）。

## 決定

### 1. 医療・がんの給付（病気の想定のとき）

- 万一の想定（就業不能・障害）に**病気の想定** `illness` を足した: 病気の種類 `disease`（`cancer` がん／`heartStroke` 心疾患・脳卒中／`other` そのほか）、入院の日数 `hospitalDays`（1回の入院。省略は0日）、手術の回数 `surgeries`（省略は0回）。死亡の想定では使わない。部品 `contingency.event`（改訂3・約束の版 1.1）が判定の結果に添える。
- 給付の種類に**三大疾病一時金** `threeMajorLump` を足した。保障の行に**入院の1回の限度日数** `maxDays`（入院日額。省略は60日）を足した。
- 部品 `insurance.policy`（改訂2・約束の版 1.1）: 被保険者に病気の想定があり、起きる月に契約と保障が続いていれば、**起きる月の翌月に1回だけ**受け取る（受け取りの種類 `medical`、課税の区分は非課税 `none`、表の行は保険金の一時金 `cf.income.lumpSum.insurance`）。

| 給付 | 受け取る額 | 病気の種類 |
|---|---|---|
| 入院日額 `hospitalDaily` | 日額×min（入院の日数, 1回の限度日数） | どれでも |
| 手術 `surgery` | 1回の額×手術の回数 | どれでも |
| がん一時金 `cancerLump` | 1回の額 | がん |
| 三大疾病一時金 `threeMajorLump` | 1回の額 | がん・心疾患・脳卒中 |

- 2回目以降のがん一時金・通算の限度日数・日帰り入院・先進医療の実費・健保組合の付加給付・三大疾病の支払いの細かい条件は計算しない（カスタマイズ）。病気の想定が無い就業不能・障害の想定では、前のとおり受け取りを計算せず知らせを出す。
- 就業不能の給付・払込免除・団信の疾病の特約は前のまま（病気の種類で払込を止める・団信の残高を消すのは後の回）。

### 2. 保障の行ごとの被保険者（家族型の医療保険・家族特約）

- 保障の行に**被保険者** `insured` を足した（省略は契約の被保険者）。その保障の給付（死亡・収入保障・就業不能・高度障害・医療）は、その人の万一の想定で受け取る。保険料・保険料控除・払込免除・契約の終わり（契約の被保険者の死亡）は契約のまま。
- 契約の被保険者でない人が亡くなったときの死亡保険金は、**契約者**が受け取る（契約者が亡くなった人なら契約の被保険者）。課税の区分は前と同じ決まり（契約者が亡くなった人なら相続税の対象、受け取る人が契約者なら一時所得、ほかは贈与税）。契約は続き、その人の保障だけがその後は数えられない。
- 年ごとの値の死亡保障額 `deathBenefit` は**契約の被保険者の分だけ**にし、ほかの人が被保険者の保障の死亡保障額は `others`（人ごと。0の人は入れない）に出す。

### 3. 変額・外貨建の円の目安の形

- `insurance.simple` に `estimate`（真偽）を足した。真なら、変額・外貨建の契約でも積立金を前提の利回りで伸ばさず、**死亡保険金は保障の明細の額、解約返戻金は数表の行の額だけ**（行が無ければ0）で計算する。画面は円の目安の額と「目安（為替・運用で変わります）」の印で入れる（0055）。
- `estimate` の無い古い契約は前のまま（積立金を伸ばす）。値は書き換えない（画面の確かめの一覧で「目安の形に直しますか」と聞く。0055）。

### 4. 保障ごとの数表の死亡保障の行

- 数表の行のうち、**保障の ID（`coverage`）のある行の死亡保障 `deathBenefit` は、その保険年度のその保障の額だけを置き換える**。ID の無い行は前のとおり、その保険年度の契約全体（契約の被保険者の分）の死亡保障額。解約返戻金・年金・祝金・保険料の行は前のとおり行の合計。
- 画面の逓減定期保険は、主契約の死亡保障の行に保障の ID つきの行を保険年度ごとに作る（毎年同じ額ずつ減って保障の終わりに終わりの額）。同じ契約の死亡の特約は残る。

### 5. 払込保険料の累計

- 部品 `insurance.policy` の年ごとの値に、その年の年末までの**払込保険料の累計** `paid`（契約の月から。計算基準年より前の払込は契約の保険料から数える。解約返戻金の計算と同じ数え方）を足した。画面の「元本割れの表示」（払った保険料の累計と解約返戻金を並べる）に使う。
- 部品 `plan.cashflow`（改訂15・約束の版 1.5）の details の保険の一覧に、`paid`・`others`・保障の行の被保険者 `insured` を添えた（エンジンが要約 `summary.insurance` に写す）。

### 6. 必要保障額の内訳と契約ごとの死亡保険金

- 部品 `protection.need`（改訂5・約束の版 1.1）の年ごとの値に**内訳** `breakdown` を足した。合計は前からの `expenses`・`resources` と同じ（計算の結果は変わらない）。

| 区画 | 中身 |
|---|---|
| 必要な資金（毎年の分）`expenses` | 生活費 `living`（遺族の割合の後）・住居費 `housing`（団信で消える返済を除く）・教育費 `education`（保育料を含む）・保険料 `premiums`（亡くなった人が被保険者の契約を除く）・介護 `care`・遺族の税と社会保険料 `taxSi`・そのほか `other`（周期的な支出・FP顧問料・遺族の支出・車） |
| 必要な資金（一時の分）`lump` | 整理資金 `funeral`・予備の生活資金 `reserve` |
| 準備できる資金（毎年の分）`resources` | 遺族年金 `survivorPension`・遺族の収入 `survivorIncome`・児童手当と教育の公的支援 `publicSupport` |
| 準備できる資金（一時の分）`lumpResources` | 死亡退職金 `retirementAllowance`・確定拠出年金の死亡一時金 `dcLump`・弔慰金 `condolence` |
| 見せるだけ | 団信で消える住宅ローンの返済の額 `creditLife`（住居費から除いた額） |

- 加入中の死亡保険金 `coverage` の**契約ごとの内訳** `coverageBy`（0の契約は入れない）を足した。家族特約など、契約の被保険者でない人が被保険者の保障（2 の `others`）も、その人の死亡保障に数える。

### 7. 種類の細目と名前

- 保険契約に**種類の細目** `subtype`（画面のひな形: 定期・逓減定期・収入保障・終身・養老・医療・がん・就業不能・学資・個人年金・共済・団体保険・民間の介護保険・外貨建・変額・損害保険）と**名前** `label` を足した。どちらも計算には使わない（計算の型は `template` のまま）。名前は FP が書いた文なので、持ち帰り用のレポートでは外し、AI接続口の縮約版でも文章の項目として既定で外す。種類の細目と病気の想定は縮約版の許可リストに入れた（版 `reduced@16`。0015）。

## 理由

- **医療・がんの給付を起きる月の翌月に1回だけにする**: 病気の想定は1回の大きな病気（働けない期間と医療費）で、入院の日数・手術の回数もその1回の値。2回目以降の条件は商品ごとに違い、標準に持つと入力が増える（細かい条件はカスタマイズ）。
- **病気の想定を万一の想定に持たせる**: 就業不能の想定（働けない期間・医療費）と同じ「大きな病気」の前提で、医療費の自己負担と給付を同じ場面で並べられる。団信の疾病の特約・払込免除の条件を広げる回も同じ欄で動く。
- **家族特約の死亡保険金を契約者が受け取る**: 家族特約の受取人は多くが主たる被保険者か契約者で、受取人の欄は契約に1つ。契約者を既定にすると一時所得の区分になる（よくある組）。
- **`deathBenefit` を契約の被保険者の分だけにする**: 必要保障額の死亡保障は「亡くなる人が被保険者の保障」なので、家族特約の分を本人の保障に足すと多く見える。
- **円の目安の形で積立金を伸ばさない**: 前提の利回りで伸ばす計算は、想定の数字が一人歩きする点で為替・運用の想定と同じ。入れた円の目安だけなら、何を前提にしたかが FP に見える。
- **内訳を足すだけにする**: 合計は前と同じなので、見本の世帯の結果は変わらない。

## 代案（採らなかったもの）

- **医療の給付を医療費の月ごとに受け取る**: 入院の月数・手術の月が要り、病気の想定の欄が増える。翌月の1回で家計への効き方（一時の入金）は表せる。
- **家族特約を別の契約として入れる**: 保険料・控除を元の契約に寄せられず、保障の推移が契約ごとに分かれて見える。
- **逓減定期を保障の行の「終わりの額」で持つ**: 計算の型を増やすことになる。数表の行は前からあり、設計書の表を取り込む回とも同じ形になる。

## 影響

- **エンジン**: 入力のスキーマ（`contingency.illness`・保障の行の `insured`・`maxDays`・給付の種類 `threeMajorLump`・`insurance.simple.estimate`・`insurance.subtype`・`insurance.label`）、出力のスキーマ（受け取りの種類 `medical`・年の値の `paid`・`others`・必要保障額の `breakdown`・`coverageBy`・要約の保険の一覧の `paid`・`others`・`insured`）。部品: `contingency.event`（改訂3・1.1）、`insurance.policy`（改訂2・1.1）、`plan.cashflow`（改訂15・1.5）、`protection.need`（改訂5・1.1）。入力項目ID `contingency.illness`・`insurance.subtype`・`insurance.label` を足した。
- **持ち帰り用のレポート**: 保険の名前を外す。帳票の給付の名前に三大疾病一時金。
- **見本の世帯の結果**: 変わらない（足した欄を持たない。必要保障額の内訳と契約ごとの死亡保険金、年の値の払込保険料の累計が出力に増えるだけ）。数表の行に保障の ID を持つ世帯は見本に無い。
- **一致テスト**: 病気の想定（がん・入院・手術）と家族特約・円の目安の形の変額・逓減定期の世帯 `insurance-illness`、同じ契約で必要保障額の内訳を出す世帯 `insurance-protection` を足した。
