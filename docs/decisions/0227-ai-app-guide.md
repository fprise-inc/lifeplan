# 0227. AI接続口に、アプリの画面の操作の手引き（search_app_guide・get_app_guide・how_to_use）を足す

- 状態: 採用（一部未確定）（2026-11-19）
- 固定の強さ: 道具の名前と入出力・プロンプトの名前と引数は試験版（0015 と同じ。予告して変えることがある）。手引きの正本を `docs/app-guide/` の Markdown に置き、ビルドで同梱し、画面の文とのずれを試験で見つけることは内部の取り決め。手引きの中身・節の分け方・説明（INSTRUCTIONS）の文言はいつでも直す
- 前提にする記録: 0015（AI接続口）、0016（カスタム層の差し替えられる文の一覧）、0183（対応範囲の一覧。同じ同梱のしかた・探し方）、0199（使い方の例のプロンプト）

## 背景

- AI接続口で答えられるのは、計算の中身（`search_coverage`・`get_coverage`）・制度の値・入力の形（`get_input_guide`）・見本の世帯の計算までだった。FP が AI のアプリで「プランを保存するにはどこを押す？」「お客さまに URL でヒアリングを送るには？」「AI に世帯を渡すには？」のように**画面の操作**を聞くと、AI は推測で手順を作るしかなく、無いボタンの名前を答えることがあった。
- 画面の操作の説明は、画面の「?」の文・設計記録・`docs/ai-connector.md` に散らばっていて、FP に見せてよい形の手引きが無かった（設計記録は判断の経緯が多く、そのまま AI に渡す物ではない）。
- 利用者の判断（2026-11-19）: 手引きを同梱し、AI がそれを読んで手引きどおりに答えるようにする。手引きに無い操作は「手引きに無い」と言い、推測で手順を作らない。世帯の情報は使わない道具なので、`search_coverage` と同じく、いつでも（アプリが起動していなくてよい・AI接続がオフでもよい）使える群に入れる。

## 決定

### 1. 手引きの正本は `docs/app-guide/NN-<画面>.md`

- 画面ごと（かまとまりごと）に1ファイル、やりたいことごとの短い節で書く。今は10ファイル・77節（画面のつくり／世帯の一覧／入力のタブ／取り込む／結果のタブとプラン／資産と負債・収益不動産／万一のとき／控え・面談・書き出し／事務所の設定／AI と接続する）。
- 節の形: `## 題 {#画面.名前}`、続けて `探す言葉:`（FP が言いそうな言い方）・`要点:`（1〜2文の答え）・`関係:`（任意。関係する節の id）、空行のあとに本文。書き方は `docs/app-guide/README.md`。
- **画面のボタン・見出し・タブ・メニューの名前は、画面の文そのまま（一字一句）を「」で書く。「」はそれ以外に使わない。** 件数など画面で変わる所は、変わらない頭の部分だけを「」に入れる。
- 書くのは今の main の画面にある物だけ。今の画面に無い操作（世帯を閉じる・ゴミ箱・お客さまの世帯の複製・一覧の並べ替え・表の CSV や Excel の書き出し・印刷のボタン・暗い画面を選ぶ所・ほかのソフトのデータの取り込み・今は出していない Excel のヒアリングシート）は、節「アプリに無い操作」にまとめ、AI が別のボタンで代わりにできると推測しないようにした。
- 言葉: FP が読んで分かる です・ます の短い文。手引きの本文に「接続口」を書かない（「AI と接続」「AI接続」）。「当てる」「比べ」「札」「カード」も書かない（試験が止める）。
- 元にした物: 今の画面（`app/src`）の文と、`docs/ai-connector.md` の「アプリの画面」の説明。設計記録はそのまま写していない。
- 置き場所を `docs/` にしたのは、FP が GitHub でそのまま読める手引きでもあるため。CI の振り分け（`.github/scripts/ci-changes.sh`）で、`docs/app-guide/` の変更は app（ずれの試験）と host（同梱）のジョブを流す（ほかの `docs/` の変更は何も流さない）。

### 2. 道具 `search_app_guide`・`get_app_guide`（単体の群）

- `search_app_guide`（`query` 必須・`limit` 1〜10、既定5）: 問いに近い節の `id`・`title`・`screen`・`summary`・`score` を返す。探し方は対応範囲の一覧（0183）と同じ（全角・半角をそろえ、2文字の並びの重なりで点を付け、題と探す言葉がそのまま問いに入っていれば点を足す。いちばん近い節の4分の1未満は出さない）。当たらないときは `notInGuide`（推測で手順を作らず「手引きに見当たらない」と伝え、アプリの画面で確かめてもらう。欲しい操作は「要望・不具合を送る」から送れる）を返す。
- `get_app_guide`（`id` 任意）: 節の題・画面・要点・探す言葉・本文・関係する節を返す。`id` を省くと画面ごとの目次。知らない `id` は、近い節を添えて断る。答えの `note` で、「」の名前を言い換えずに伝え、本文に無い手順・ボタンを推測で足さないよう伝える。
- 答えの `appVersion` は接続口の版（アプリと同じ版。0015）で、その版の画面の手引きであることを示す。手引きだけの版の番号は持たない。
- 引数の名前の決まり（下線で区切る・知らない名前は近い名前を添えて断る）は、ほかの道具と同じ（呼ぶ前に入力の形と照らす）。
- 同梱: `crates/lifeplan/build.rs` が `docs/app-guide/` の `NN-*.md` を名前の順に `include_str!` で埋め込む（`APP_GUIDE`。README.md は入れない）。読み方は `crates/lifeplan/src/app_guide.rs`（起動して最初に使うときに1回読む）。形の誤り（`{#id}` が無い・id の形・探す言葉と要点の欠け・id の重なり・無い節を指す「関係:」）は、接続口の単体試験が落とす。
- 説明（INSTRUCTIONS）に、画面の操作を聞かれたら推測で答えず `search_app_guide` → `get_app_guide` で読んで手引きどおりに答えること、画面の名前を「」のまま伝えること、手引きに無い操作は「手引きに見当たらない」と伝えることを足した。いつでも使える道具の並びと、「この接続口で何ができる？」の場面にも足した。

### 3. プロンプト `how_to_use`（「ファイナンシアの使い方を聞く」）

- 引数 `want`（やりたいこと。省くと、目次から主な操作をひととおり紹介して、詳しく知りたい操作を FP に聞く）。進め方は、`search_app_guide` で探す → `get_app_guide` で読む → 本文の手順どおりに番号つきで答える（画面の名前は言い換えない・条件を添える）→ 手引きに無い操作は「手引きに見当たらない」。計算の中身は `search_coverage`、入力の形は `get_input_guide` に分ける。
- `what_can_you_do` の場面に、アプリの画面の操作の手引き（どこを押す？）を足した。

### 4. 画面の文とのずれを見つける試験（`app/test/app-guide.test.ts`）

- 手引きの「」の中（見出しの行を除く本文・要点）が、今の画面の文にそのまま（一字一句）あるかを確かめる。画面の文として読むのは、`app/src` の ts・tsx（コメントを外す）、prepare-assets が作る差し替えられる文と名前の一覧（`app/src/generated` の texts-catalog など）、提案書と持ち帰り用のレポートの文（`report/src`）、本体が決める AI のアプリの設定の文面の題（`app/src-tauri/src`）。JSX の行の折り返しは空白1つにも空白なしにも読む。
- 画面の言葉を変えて手引きを直し忘れると、app のジョブ（単体テスト）で落ちる。落ちたときの直し方（今の言葉に直す・画面の名前でない言葉なら「」を外す）は試験の中と README に書いた。
- 同じ試験で、手引きに書かない言葉と、節の形（`{#id}`・探す言葉・要点・id の重なり）も確かめる。
- 限り: 確かめるのは「その文字が画面のどこかにあるか」までで、手引きが書いた画面・手順の流れと合っているかは確かめない（「保存」「オン」のような短い名前は、どこかにあれば通る）。流れの正しさは、手引きを直すときに画面で確かめる。

## 未確定

- 画面の文の変更で、名前は残ったまま手順や場所だけが変わったときは、試験で見つけられない。画面の流れまで確かめる（通しの入力の試験の場面と合わせる）か。
- 手引きの絵（画面の切り抜き）を添えるか。AI の答えに画面の場所の絵を出せる AI のアプリが増えたら考える。
- 事務所がカスタム層で名前を変えた所（入力の欄の名前・結果の画面の名前）は、手引きは公式の名前で書いている。事務所の名前で答えるか（事務所の名前を接続口に渡すか）。
- AI が発行した URL の画面（「AI が発行した URL」）は、まだ見ていない URL があるときの上の帯からしか開けない。見た後の世帯の決まっていない依頼をどこから開くかは、画面に入口が無い（手引きには、帯はまだ見ていない URL があるときだけ出る、とだけ書いた）。
- 手引きの英語版は作らない（画面が日本語だけのため）。
