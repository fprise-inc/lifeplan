# 0207. AI接続口で、比較の道具のどの系列もグラフにし、支出の内訳を系列にする（「比較」への言い換え・3パターンのプロンプト・出典を選べるように）

- 状態: 採用（2026-11-12）
- 固定の強さ: 試験版（0015 と同じ）。系列の名前（`takeHome`・`pension`・`expenseLiving`〜`expenseOther`）・`chart` の `series`・`expenseBreakdown`・`credit`・プロンプト `chart_three_patterns` は、どれも足すだけの任意の欄。既定の答えの大きさは変えない（選んだときだけ返す）。画面の文の「比べ」→「比較」の言い換えは内部（いつでも直せる）
- 前提にする記録: 0015（AI接続口）、0194（主な数字）、0198（比較の道具）、0199（使い方の例）、0203（金利の見込みとグラフ）、0205（利息と金利）

## 背景

- 0203・0205 で、比較の道具（`compare`）の答えを画面と同じ見た目のグラフにできるようになったが、グラフにできるのは金融資産・住宅ローンの返済・利息・金利と主な数字の棒だけだった。FP がよく頼む「退職を60・65・70歳にして年間収支をグラフに」「進路を3通りにして教育費をグラフに」は、AI が数字を自分で描くしかなかった。
- `compare` の系列は、収入・税と社会保険料・支出・年間収支・金融資産・負債・不足と住宅ローンの数字だけで、支出の内訳（教育費・住居費・生活費など）・手取り・公的年金は無かった。
- グラフの注に「ファイナンシアで試算」の出典を必ず入れていたが、FP がブログ・セミナーの資料に自分の名前で使うときに、ソフトの名前を入れたくないことが多い。
- 画面・接続口の文に「比べる」「比べ」が混ざっていた。言葉を「比較」にそろえる。

## 決定

### 1. 系列の名前（`compare` の `series`・`calculate` の `fields`・`chart` の `series` で同じ）

- 今の名前（`income`・`taxSi`・`expense`・`net`・`financialAssets`・`debt`・`shortfall`・`loanRepayment`・`loanBalance`・`loanInterest`・`loanRate`）はそのまま。
- 足す名前（どれも選んだときだけ返す）:
  - `takeHome`: 手取り（`income` − `taxSi`）。表に出す年の合計が `keyFigures.lifetimeTakeHome`（画面の比較の表と同じ数え方）。
  - `pension`: 公的年金（世帯の合計。`cf.income.pension` の下の行。企業年金・個人年金は含まない）。
  - 支出の内訳（10個）: `expenseLiving`（生活費）・`expenseSurplus`（ゆとりの支出）・`expenseHousing`（住居費）・`expenseEducation`（教育費）・`expenseInsurance`（保険料）・`expenseLumpSum`（一時的支出）・`expenseCar`（車の費用）・`expenseCare`（医療・介護）・`expenseRealEstate`（住まい以外の不動産の経費・ローン）・`expenseOther`（その他の支出）。
- 支出の内訳は、画面のキャッシュフロー表の支出の行（`app/src/workspace/present.ts` の `rowDefs`）と同じ当て方で、接続口に同梱した関数（`app/src/connector/summary.ts` の `flowYearsOf`）が数える。画面の「その他の支出」から、医療・介護（`cf.expense.care` の下）だけを分けた。全部足すとその年の `expense` になる（どの見本の世帯の、どの年も合うことを、画面の側と接続口の側の両方のテストで確かめる）。
- 名前の一覧と中身は `docs/ai-connector.md` の「系列の名前」が正。ほかの道具（書き出しなど）も同じ名前を使う。

### 2. `chart`: どの系列も折れ線に、支出の内訳を棒に

- `series` に系列の名前を入れると、1つにつき1枚、通りごとの年ごとの推移の折れ線を作る（基本と8通りまで。`charts` と合わせて8枚まで）。`series` を書けば `charts` の既定は無し（書かなければ今までどおり `assets`・`repayment`・`keyFigures`）。今の種類（`assets`・`repayment`・`keyFigures`・`interest`・`rate`）はそのまま。
- 種類 `expenseBreakdown`: 支出の内訳の表の期間の合計を、内訳ごとに通りごとの横の棒で並べる（内訳が10個あっても名前と数が重ならないように横にした）。どの通りでも 0 の内訳は出さない。
- 見た目は画面のグラフと同じ（座標・目盛りの関数・線の色・暗い地の色・万円の単位・本人の年齢の段）。年額の系列は題に「（年額）」を添え、単位の注に中身を書く。年間収支は 0 未満の範囲に「0未満は赤字」、教育費・住宅ローンなど値の無くなる系列は、どの通りも値が無くなった後の年を描かない。
- 題・単位の注の言葉は `app/src/connector/chart.ts` の `SERIES` に持つ。

### 3. 出典は選べるように（既定は入れない）

- `credit: true` のときだけ、注に「ファイナンシアで試算（○年○月時点の入力による試算で、将来の結果を約束するものではありません）」を入れる。既定（`false`）は「○年○月時点の入力による試算で、将来の結果を約束するものではありません。」だけ。
- 前提の注はいつも入れる: 物価上昇率（入力に無ければ 0%）・運用利回り・相場の想定（重ねていなければ「相場の下落などは重ねていない」）・試算の時点・将来を約束しない旨。

### 4. 使い方の例のプロンプト `chart_three_patterns`（3パターンを比較してグラフに）

- 1つの項目を3通りにして比較し、グラフにする。`list_plan_items` で項目の ID を確かめ、`compare` で3通りとも計算できることを見てから、`chart` の `series` で描く。
- 例として、退職の年齢・子の進路（教育の目標の段の公立・私立）・家の値段（`get_input_recipe` の `buyHome`）・物価上昇率・運用の利回り・年金の受け取り開始・NISA の毎月の積立と、それぞれに合う系列を書いた。
- INSTRUCTIONS に「比較の答えはどの系列もグラフにできる」ことを1行足した。

### 5. 「比べ」→「比較」

- 接続口の INSTRUCTIONS・道具と引数の説明・プロンプトの名前と説明・グラフの題、画面の文、提案書の文、`docs/ai-connector.md` ほか今の文書で、「比べ」「比べる」「比べた」を「比較」「比較する」「比較した」に直した。見出し・ラベル・題は名詞の「比較」（例「プランを比較」「前回と比較」「主な数字の比較」）、文の中は「比較する」。
- 過去の設計記録の本文は、その時の記録なので直さない。コードの名前（識別子）は変えない。

## 見本の世帯での数字

`salariedCoupleTwoKids`（計算基準月 2026年10月。表に出す年は 2027年から）で、働く最後の年齢を 60・65・70歳にした3通り:

| 通り | 95歳時点の金融資産 | 資産が尽きる年 | 生涯の手取りの合計（`takeHome` の合計） |
|---|---|---|---|
| 60歳で退職 | ▲1,997万円 | 2058年（77歳） | 2億5,121万円 |
| 65歳で退職 | 1,704万円 | 尽きない | 2億7,471万円 |
| 70歳で退職 | 4,029万円 | 尽きない | 2億9,579万円 |

どの通りも、どの年も、支出の内訳の合計＝`expense`、`takeHome` の合計＝`keyFigures.lifetimeTakeHome`、`expense` の合計＝`keyFigures.lifetimeExpense`（接続口のテスト `chart_any_series_and_expense_breakdown`）。

子の進路を3通り（今の進路・すべて公立・中学から私立）にした教育費の表の期間の合計は 2,384万円・1,836万円・3,007万円。

## 考えた別の案

- グラフの種類を系列ごとに1つずつ足す（`net`・`education` …）: 種類が20を超え、`compare` の名前と別の名前を覚えることになる。系列の名前をそのまま使う `series` にした。
- 支出の内訳を1つの欄（`expenseBreakdown: {…}`）で返す: 1つの内訳だけを通りで比較するときに使いにくい。平らな名前にした。
- 支出の内訳を積み上げの棒にする: 通りの間の差が読みにくい。内訳ごとに通りの棒を並べた。
- 出典を必ず入れる（今まで）: FP が自分の資料に使いにくい。前提と将来を約束しない旨は残し、出典だけを選べるようにした。
