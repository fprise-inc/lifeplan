# 0010. 学費データ

- 状態: 採用（一部未確定）（2026-10-08）
- 固定の強さ: β公開から変えない（骨格）。学費データの形式は「マスタデータの形式」として「安定」の公開の約束に含める（互換を壊す変更は年1回まで、1年前に予告）

## 背景

- 教育費はライフプランの中で金額が大きく、学校・学部によって数倍の差がある（私立大学の医・歯学部は、文系の数倍）。「学校名を入れると学費が出る」ようにしたい。
- 一方で、全学校の学費を学校別に毎年正確に持つことはできない。学校別の実データを持つ範囲を絞り、それ以外は公的統計の平均で補い、補ったことを画面に出す。
- 学校名は表記揺れ・改称・統合があり、キーにできない。文部科学省の「学校コード」（13桁、全学校種、年1回更新）は、移行先のコードを属性に持つ。学部・学科のコードは公的には無い。
- 学費は「初年度の合計」だけでは足りない。6年制の学部、公立大学の地域内／地域外、入学前の1〜3月に払う入学金、2年次以降は入学金がかからないこと、を表せる必要がある。
- 公的支援（高校の就学支援金、大学の修学支援、多子世帯の支援など）は制度改正で頻繁に変わる。学校の請求額と混ぜると、支援の制度が変わるたびに学費データを直すことになる。
- 学費の数値は各校の公式ページ・公的統計から出典つきで取り出す。原本（ページやPDF）の写しは公開しない。

## 決定

### 1. パックの分け方

- 学費はマスタデータのパック（0007の骨格を使う）として、**提供元・利用条件ごと**に分ける:
  - `master.education.schools`: 学校の一覧（学校コード・名前・別名・学校種・設置者・所在地の都道府県・移行先コード）と、学部・学科の固定ID。
  - `master.education.tuition`: 各校の公式ページから取り出した学校別の学費。FPライズが整理した部分は CC0。
  - `master.education.statistics`: 公的統計の平均（系統別・都道府県別・学年別など）。出典と加工した旨を表示する。
  - 利用の許諾が必要なデータを使うことになった場合は、提供元の条件で**別のパック**にする（上の3つに混ぜない）。
- 正本はリポジトリ内の YAML（学校の一覧は機械で作る大きな表なので CSV でもよい）。配る形は正規化した JSON。

### 2. 学校の主キーと学部・学科のID

- 学校の主キーは**学校コード（13桁）**。名前はキーにしない。
- 学校の一覧に `successor`（移行先の学校コード）を持ち、統合・設置者の変更（例: 私立大学の公立化）でコードが変わっても、古いコードから新しいコードをたどれるようにする。
- 別名の辞書（略称・旧校名）を持ち、名前での検索とヒアリングシートの自由記述の照合に使う。
- 学部・学科・課程は、**学校コード＋自前の固定ID**で表す: `<学校コード>/<部局ID>`。部局IDは学校の中での通し番号（`d001`、`d002`…）で、使い回さない。廃止しても欠番として残す。
- 学部・学科には、文部科学省の**学部系統の区分**（平均で補うときに使う）と、修業年数（医・歯・薬・獣医は6年、短大2年など）を持たせる。

### 3. 学費の持ち方:「入学年度×年次×費目×支払月」

```yaml
school: "<学校コード13桁>"        # 学校コード
unit: "<学校コード13桁>/d003"     # 学部・学科（無い学校種では学校コードと同じ）
track: null                      # 区分（公立大学の地域内/地域外、課程など）。無ければ null
termStartMonth: 4                # 年次の始まりの月
rows:
  - entryYear: 2027              # 入学年度
    grade: 1                     # 在学年次
    item: tuition.admission      # 費目
    monthOffset: -2              # 支払月。その年次の始まりの月からのずれ（-2 = 入学前の2月）
    amount: 300000
    source: src_01
  - {entryYear: 2027, grade: 1, item: tuition.annual,   monthOffset: 0, amount: 450000, source: src_01}
  - {entryYear: 2027, grade: 1, item: tuition.annual,   monthOffset: 6, amount: 450000, source: src_01}
  - {entryYear: 2027, grade: 2, item: tuition.annual,   monthOffset: 0, amount: 450000, source: src_01}
sources:
  src_01: {url: "https://…", retrievedAt: "2026-10-20", sha256: "…", locator: "学費一覧 p.2", quote: "…"}
recordedIn: "2026.4.0"
```

（値は説明用の例）

- 1行は「ある入学年度の人が、ある年次の、ある月に、ある費目を、いくら払うか」。年額の分割払い（前期・後期）は月ごとの行に分ける。
- 支払月は**その年次の始まりの月からのずれ**（`monthOffset`）で書く。絶対の年月にしないのは、将来の入学年度へ同じ形を当てはめるため（0003の「お金が実際に動いた月」で集計する）。
- 1つの学校・学部・区分の中で、同じ入学年度について全年次の行がそろっていることをCIで確かめる（修業年数と合うこと）。
- 値の訂正は、0007と同じく古い行を消さずに、知った時点の時間軸（`recordedIn`・`supersededIn`）で残す。

### 4. 費目の3層と二重計上の防止

- 費目は3層に分け、IDを固定する:
  - `tuition.*`（学納金。学校が請求する額）: `tuition.admission`（入学金）、`tuition.annual`（授業料）、`tuition.facility`（施設設備費）、`tuition.lab`（実験実習料）、`tuition.other`（その他の学納金）。
  - `schoolRelated.*`（その他の学校関連費。制服・教材・修学旅行・通学など）。
  - `outOfSchool.*`（学校外費用。塾・習い事など）。
- **学校別のデータは学納金（`tuition.*`）だけを持つ**。その他の学校関連費と学校外費用は統計（`master.education.statistics`）から、学納金を除いた内訳で出す。統計の「学校教育費」をそのまま学校別の学納金に足すと二重に数えるため。
- 寄付金など任意の支払いは、既定では計上しない（FPが入力する欄にする）。

### 5. 公的支援と分ける

- 学費データには**学校が請求する額（支援を引く前の額）だけ**を持つ。
- 就学支援金・修学支援・多子世帯の支援・自治体の上乗せなどは、制度データ（`regulation.educationSupport`。0007）として持ち、計算のときに別の部品が世帯の所得・子の数などから計算して差し引く。
- 公的支援の多くは名目額で固定され、学費は上がりうるので、両者の関係（教育費の上昇率をかけるのは学費の側だけ）を計算で扱う。

### 6. 出典

- 学費の各行は出典（`sources` のID）を必須にする。出典は 0007 と同じ形（URL・取得日・原本の指紋・位置・短い引用）。
- 原本の写し（各校の学費ページ・PDF）は**非公開のリポジトリ**に置き、公開側には出典の情報だけを置く（0021）。
- 取り出し方は、各校の公式ページと公的統計からの**数値の取り出しだけ**とする。進学情報サイトや、学費を一覧にした第三者のデータベースからの一括取得はしない。

### 7. 平均で補う段と、その記録

- 学校別の実データが無いときは、上の段から順に探し、最初に見つかった値を使う:

| 学校種 | ①学校別 | ②次 | ③最後 |
|---|---|---|---|
| 私立大学 | 学部別の実データ | 学部系統の平均 | 私立大学の全平均 |
| 国立大学 | 例外の学校の実データ | 標準額 | ― |
| 公立大学 | 実データ（地域内/外） | 公立の平均（地域内/外） | ― |
| 私立高校・中学 | 学校別（公表がある都道府県） | 都道府県別の平均 | 全国平均 |
| 公立の幼〜高、その他 | ― | 学年別などの平均 | ― |

- どの段の値を使ったかを、計算結果の根拠の記録に必ず残し、画面に出す（例:「この学校の実データ（2027年度入学者向け）」「私立大学・理工系の全国平均（統計名・年度）」）。値の状態は、①なら `confirmed`、②③なら `estimated`（`method: statistic`、`basis` に統計名と年度。0008）。
- **データの最新の入学年度より先の入学**は、最新の入学年度の行に教育費の上昇率（プランの前提。0008）をかけて出し、「推計」の印を付ける。
- ある学校の新しい年度の値が確かめられなかったときは、前の年度の値のままにし、画面にその年度を表示する（古い値を新しい年度の値として書き込まない）。

### 8. 学校別の実データの範囲

- 最初の版で学校別の実データを持つのは、**私立大学の医・歯・薬・獣医学部**と、**東京都の私立中学・高校**、国立大学の標準額と例外の学校。ほかは平均で補い、FPが上書きできる。
- 範囲を広げても形式は変えない（全学校種で同じ形）。

### 9. 世帯の側

- 子の教育の目標（0008）は、`{school: 学校コード, unit: 部局ID, track, entryYear, pattern（進路パターン）}` を持つ。学校が決まっていなければ進路パターン（公立・私立×文系・理系×自宅・自宅外）だけで計算する。
- 計算に使った学費の行は、世帯ファイルに写して持つ（自己完結。0011）。学費データを更新しても、作業中のプランは「更新」を押すまで変わらない（0009）。
- ヒアリングシートで受けた学校名の自由記述は、元の文字列と、照合して確定した学校コードの両方を持つ。

## 理由

- **学校コードを主キーに**: 名前は揺れるが、コードは公的に管理され、移行先もたどれる。学部・学科は公的なコードが無いので、自前の固定IDにするしかない。
- **「入学年度×年次×費目×支払月」**: 初年度の合計だけで持つと、6年制・地域内外・2年次以降・入学前の支払いに後から対応できない。月まで持つのは、お金が実際に動いた月で年に集計する規約（0003）に合わせるため。
- **公的支援と分ける**: 支援の制度は毎年のように変わるので、学校のデータに触れずに済む形にする。支援の計算は制度データと同じ検証の流れに乗る。
- **学校別のデータは学納金だけ**: 費目の層を分けないと、統計と学校別の値を足すときに二重に数える。
- **平均の段を記録して見せる**: 補った値と実データを区別できないと、FPが顧客に誤った精度で説明してしまう。
- **原本の写しを非公開に**: ページやPDFの写しには、それぞれの著作権がある。公開側には事実としての数値と出典だけを置く。

## 影響

- 後から変えると: 学費データの全面的な作り直しと、教育費の計算部品・世帯の教育の目標の作り直しになる。
- 守るべき決まり:
  - 学校コードと部局IDを使い回さない。名前をキーにしない。
  - 学校別のデータに公的支援を差し引いた額を入れない。学納金以外の費目を入れない。
  - 平均で補った値に、使った段と統計名・年度を必ず付ける。
  - 原本の写しを公開リポジトリに入れない。
- テストで確かめること（CI）:
  - JSON Schema の検査、出典の必須項目。
  - 学校・学部ごとに、修業年数分の年次の行がそろっていること。
  - 学校コードの移行先をたどったとき、循環しないこと。
  - 取り込んだ学校別の値の平均と、公表されている平均との突き合わせ（例: 東京都の私立中学・高校は都の公表する平均と照合し、取り込みの誤りを見つける）。
  - 前の年度からの変化率が大きすぎる行、入学金が授業料を上回るなどの異常値の警告。
  - 代表的な学校の在学期間の総額を固定した回帰テスト。
  - 将来の入学年度の推計で、公的支援に上昇率がかからないこと。

## 未確定（11月以降に決めること）

- 学部系統の区分の対応表（学部・学科→系統）の作り方と、最初の版の範囲。
- `track`（区分）の正式な一覧（公立大学の地域内/外、夜間、通信など）。
- その他の学校関連費・学校外費用の統計の内訳をどの粒度で持つか（学年別・公私別・世帯年収別）。
- 自宅外の生活費（仕送り・家賃・初期費用）を学費データに入れるか、教育の目標の別の入力にするか。
- 専門学校・大学院・短大の扱いの細部。
- 学校の一覧の正本を CSV にするか YAML にするか。

## 追記

- 2026-10-09（学校の入力のしかた。構想書 D-72）: 学校の入力は、部分一致の検索と、学部・学科の選択の2段階にする。
  - 学校名の欄は、打つたびに候補が絞られる部分一致の検索にする。漢字・ふりがな・略称・旧校名のどれでも引ける（2 の別名の辞書を使う。学校の一覧にはふりがなを持たせる）。
  - 学校を選んだら、その学校の学部・学科（部局ID）を一覧から選ぶ。
  - 候補の一番上に、いつも「学校未定（平均で計算）」を置く。選ぶと `school` と `unit` を空にし、`pattern`（進路パターン）だけで計算する（9 のとおり）。
  - 学校を選んでも実データが無いときは、7 の段の順で自動で平均に下がり、使った段を統計名と年度つきで画面に出す（7 のとおり）。
- 2026-10-09（私学事業団から許諾を得た数値の配り方。構想書 D-71）: 1 の「別のパック」は、公開側のリポジトリにも公開の場所にも置かず、FPライズが署名して配る公式版に同梱するだけにする。利用は「ファイナンシアの中で、FPが提案のために使う場合（FPが自分のAIに試算を手伝わせる場合を含む）」に限り、パックそのものの再配布と、他のソフト・サイトへの転載を条件で禁じる。提案書・キャッシュフロー表に試算の結果として載るのは利用の範囲に入る。このパックは引き継ぎ（構想書 D-67）の対象外で、無くても 7 の平均で動く。許諾が得られるまでは、このパックは存在しない。
