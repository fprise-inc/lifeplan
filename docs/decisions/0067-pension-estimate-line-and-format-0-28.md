# 0067. 年金のカードの年金の見込み（計算の結果から読む・今の水準）と、世帯ファイルの形式 0.28

- 状態: 採用（一部未確定）（2026-10-27）
- 固定の強さ: 骨格（見込みは計算の結果を読むだけで世帯の物を変えないこと、今の水準の写しの要求の作り方、形式 0.28 で足した欄 `incomeFlows[].pensionType`・`household.pensionKept`）。見せる文言・年額を読む年・カードの要約の形は後から変えてよい（変えたら追記に書く）
- 前提にする記録: 0011（世帯ファイルの封筒と形式の変換）、0015（AI接続口の縮約版）、0035（形式 0.17 と足すだけの形）、0045（カードの要約）、0066（年金のカードの中身）。

## 背景

- 推計（書類が無い）の人の年金の額は、計算の結果にしか出ず、入力の画面では「働き方の期間から推計しています」としか分からなかった。書類からの人も、定期便の額にこれからの加入を足した65歳からの額は見えなかった。夫婦の合計の月額も無かった。
- カードの要約は入力の値から作っていて、推計の人・定期便の50歳未満の人は「n人分」だった。

## 決定

### 1. 年金の見込み（パネルの下・読むだけ）

- 年金のカードのパネルの下に「年金の見込み」を出す。人ごとに「65歳から 年170万円（月14.2万円）」、受け取り開始を変えていれば「受け取り開始（基礎70歳・厚生65歳）から 年…」、夫婦なら「夫婦で月24.1万円（65歳から・推定）」。もう受け取っている人は「今 年…」。
- 人ごとに出どころを1行で: 推計なら「推定（書類が無いので、働き方の期間から推計した額）。定期便があれば『書類の額で置き換える』で写せます」、書類からなら「書類の額に、これからの加入（働き方の期間）を足した額（推定）」、改定通知書なら「加給年金・振替加算・これからの加入を足した額」、加入歴からなら「加入歴に、これからの加入を足した額」。加入月数が0か月のままなら「少なく（50歳以上の定期便は0円で）出ています」。
- 求め方: 今の世帯の写しの要求で、賃金上昇率・物価上昇率・マクロ経済スライドの調整率を外し（0。定期便の額と同じ今の水準）、万一の想定・必要保障額の推移・相続税の目安を外す。65歳からの額は受け取り開始も外した写し、受け取り開始を変えている人がいれば、変えたままの写しも求める（多くて2回）。
- 年額は、受け取り開始の年の次の年（今受け取っていれば計算の基準の年の次の年）の、その人の老齢年金の行（物を持たない `cf.income.pension`）の合計。加給年金・振替加算・在職中の停止を含む結果の額。表の最後の年より後なら「計算の期間の外です」。
- プランを直しているときは、そのプランの中身で求める（そのプランの額）。計算の道が無い所（画面の確かめなど）では出さない。

### 2. カードの要約

- 入力のホームとパネルの見出しの年金のカードの要約は、1 の65歳からの額の合計の月額「夫婦で月24.1万円（65歳から・推定）」（1人なら「月…」、全員もう受け取っていれば「（今・推定）」）。加入月数が0か月のままの定期便の人がいれば、前からの「加入月数が未入力」。計算の結果がまだ無いときは前からの入力の値の要約。

### 3. 世帯ファイルの形式 0.28

- 入るお金の行に受給中の遺族年金・障害年金の種類 `incomeFlows[].pensionType`（0066 の5。入力項目ID `incomeFlow.pensionType`）と、画面の側の年金の入れ方を切り替えたときに残した前の記録 `household.pensionKept`（0066 の2。構成員の ID → 年金の記録の並び）を足した。どれも任意で、足すだけの MINOR。前の版のアプリは知らない欄を読み落として書き戻すので、版を上げて閲覧だけにする。`0.27` → `0.28` の変換の段は形式の版だけを書き換える。見本 `crates/household-store/tests/fixtures/household-format/0.28/`（0.27 の見本に、種類のある受給中の障害年金の行と、残した本人の定期便の記録を足した）。
- AI接続口の縮約版の許可リストに `incomeFlow.pensionType` を入れ、版を `reduced@19` にした（決まった値の一覧。文章の項目ではない）。残した記録は計算の入力ではないので渡さない。

## 理由

- **計算の結果を読む**: 年金の額はエンジンだけが正しく出せる（加給年金・在職中の停止・繰下げ）。画面で別に計算すると食い違う。
- **今の水準にする**: 定期便の額は今の水準の額で、結果の表の額（物価・賃金で伸ばした額）と並べると比べられない。伸びを外した写しなら、定期便の額と同じ物差しになる。
- **受け取り開始の次の年の額**: 偶数月に前2か月分を払うので、受け取りを始めた年は12か月分にならない。

## 代案（採らなかったもの）

- **結果の表の額（伸ばした額）をそのまま見せる**: 30年先の額は物価の分だけ大きく、定期便の額と比べられない。
- **エンジンに年金の要約（基礎・厚生の内訳）の出力を足す**: 出力の約束が増える。まずは表の行から読む（内訳は残した）。

## 影響

- **画面**: `input/pensionEstimate.ts`（写しの要求・年額の読み方・要約）、`input/PensionEstimate.tsx`（パネルの下の見込み）、入力のホームとパネルのカードの要約（`input/items.ts` の `pension`）。ホームとパネルで、計算の道があるとき写しの要求を1〜2回求める。
- **世帯ファイル**: 形式 0.28（3）。本体の変換の段（`migrate.rs`）と見本。
- **計算の結果**: 変わらない（読むだけ）。
