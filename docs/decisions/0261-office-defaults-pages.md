# 0261. 事務所の既定値の画面を7つの画面に分け、保存を1つにまとめる（左の目次・2か所で変えていた値を1か所に・入力項目の部品と文字の段）

- 状態: 採用（一部未確定）（2026-11-25）
- 固定の強さ: 内部（画面の分け方・保存の仕方・見せ方）。事務所データ（`defaults`・`branding`）と世帯ファイルの形・置き場所・計算は変えない。決まりとして残すのは「保存は全部の画面をまとめて1つ（下の帯）」「2か所で変えていた値は前提条件の既定値の画面だけで変える（置き場所は事務所の推定の値のまま）」「事務所の既定値の画面の欄は入力項目の部品（0236・0240）で描く」の3つ。画面の名前・並び・要約の文・文字の大きさの値は後から変えてよい
- 前提にする記録: 0073（事務所の既定値）、0111（事務所の推定の値）、0121（事務所の見た目）、0143（パネルの頭の目次）、0214（前提条件は事務所の既定値で決める）、0216（表示の設定の事務所の既定値）、0236（入力画面の部品をそろえる）、0240（ボタンの4段）、0243（取り消しの言葉）、0252（資産配分の割合と信託報酬）、0256（「〇〇の確認画面」）

## 背景

- 事務所の既定値の画面は、節を足すたびに1枚に積んできた。上から下まで約11,300px（画面の高さ900px で約12画面分）あり、パネルの幅は720px だった。
- 保存の仕方が節ごとに違った: 事務所の見た目は節の中の「この見た目にする」、入力の並びから FP顧問料の料金表までは画面の真ん中の「保存」、その下の推定の値は押すとすぐ保存、カスタム層は承認でファイル。1枚に並んでいて、どこまでが「保存」で決まるのか分かりにくかった。
- 同じ値を2か所で変えられた: 土地の割合・建物の残りの価値の下限・売却の費用（置き場所は事務所の推定の値 `preset.realEstate.*`。0214 の1）と、資産の種類の信託報酬（`preset.invest.<種類>.fee`。0252）は、「前提条件の既定値」と「推定の値（統計・目安）」の両方に欄があった。資産の種類の期待リターンの目安（`preset.invest.<種類>.return`）は推定の値の画面だけにあり、前提条件の「資産の種類ごとの利回り」と別の値なのに離れた所にあった。
- 入力の欄・選ぶ欄はブラウザの素の形で、入力項目の部品（0236）と枠・角・高さが違った。文字の大きさは16通り（11.2〜20px）、区画の説明は3〜6行の段落、欄ごとに範囲の注が並んでいた。
- 下調べと3つの分け方の模型を作り、利用者の判断（2026-11-25）で、左の目次で7つの画面に分ける形（分け方1）・保存は全部の画面で1つ・2か所の値は前提条件の既定値の画面だけで変える・入力項目の部品と文字の段にそろえる、に決めた。

## 決定

### 1. 7つの画面

| 画面 | 入れる区画 | 保存 |
|---|---|---|
| 前提条件の既定値 | 計算の期間（表を何歳まで見るか）・経済の前提・資産運用の利回り（資産の種類ごとの利回り・配分も利回りも入れていない運用の口座・資産配分の割合と目安）・不動産の評価・相続税の目安 | 下の帯の「保存」 |
| FP顧問料の料金表 | 料金（単発・継続の顧問料の払い方と額・料金の段階）・払う人などに万一があったとき | 〃 |
| 推定の値（統計・目安） | 値の一覧・推定で埋めない入力欄（2つのタブ）。公式の値の更新の知らせ | 〃（前はすぐ保存） |
| 入力の画面 | AI からのヒアリングのひな形の案・入力のホームの入力項目の並び・新しい世帯で出す入力項目と開いたときの入れ方・基本生活費の内訳の並べ方・ご本人と配偶者の介護の費用・受け取る予定の相続と贈与の見込み | 〃 |
| 結果と万一の画面 | AI からの表示の設定の案・対策に最初から出す項目・結果のタブと資産と負債のタブの表示の設定・万一のときのタブ | 〃 |
| 事務所の見た目と機能 | 事務所の見た目・法人経営者向けの機能・機能を有効にするコード | 〃（見た目は前は区画の中のボタン） |
| カスタム層 | 説明の文・名前・入力の欄の見せ方（カスタム層） | 承認でその場で効く（今のまま） |

- 画面の名前と並びは `app/src/workspace/office/pageNames.ts` の1か所（手引き・AI接続口の表示の設定の一覧も同じ名前で呼ぶ。接続口の側は名前を写し、テストで同じかを確かめる）。
- 左の目次: 上の3つ（よく変える前提条件・料金表・推定の値）の後ろに線を引き、ほかの4つを並べる。画面の名前の下に今の値の要約（「物価1%・賃金1%・100歳まで」「単発30万円・月1万円」「事務所で変えた値 0件／350件」。変えている途中の値で作る。ほかの画面は中身の一覧）。保存していない変更のある画面は名前の横に橙の点、直す所（読めない数・範囲の外）のある画面は赤の点。AI からの案・公式の値の更新・カスタム層の承認待ちは、名前の下に小さな印。
- 開く画面: 呼ぶ側の指定（AI の案の帯・知らせから開いたときはその画面: コードの候補は「事務所の見た目と機能」、ヒアリングのひな形の案は「入力の画面」、表示の設定の案は「結果と万一の画面」、カスタム層の知らせは「カスタム層」、推定の値の知らせは「推定の値（統計・目安）」）→ 前回の画面（アプリを開いている間だけ覚える。どこにも保存しない）→ 初めては「前提条件の既定値」。開発用の確かめは URL の `#officedefaults=<画面>`。
- パネルは約1,080px（文字「大」は約1,180px）・高さを決めて、目次と画面の中身をそれぞれ動かす。アプリの幅が狭いとき（860px 以下）は、左の目次を隠して上の1行の選ぶ欄（「画面」）にたたむ。
- 画面を移っても、変えた途中の値は残す（どの画面も描いたまま隠して持つ）。

### 2. 保存は全部の画面をまとめて1つ

- 下の帯（入力項目のパネルと同じ形）: 左に「保存していない変更: 前提条件の既定値（2か所）・入力の画面（1か所）」、右に「キャンセル」と「保存」（「?」に保存すると何が起きるか）。変えていなければ「閉じる」と押せない「保存」。直す所があれば「直す所があります: 〇〇（1か所）」（押すとその画面へ移る）で、保存は押せない。
- 1回の「保存」で、事務所の既定値（事務所データの `defaults`）と事務所の見た目（`branding`）に書く。中身の作り方は前と同じ（前提条件の欄の書き方・推定の値に置く前提条件は変えた物だけ・表の最後の年など。`pages.ts` の `settingsToSave`）。推定の値が変わったときは、保存のときに推定の目安と計算の要求に入れ直し、開いている世帯を計算し直す（前は推定の値を押すたびにしていた）。
- 「キャンセル」は、どの画面で変えた所も捨てて閉じる（見た目の見本も保存した見た目に戻す）。
- 保存していない変更があるのに右上の ×・Esc・背景を押したときは、下の帯で確かめる: 「保存していない変更があります（〇〇）。閉じると、この変更は消えます。」と「設定を続ける」「変更を捨てて閉じる」「保存して閉じる」。確かめを出しているときの Esc は変更を捨てて閉じる（入力項目のパネルと同じ）。世帯を切り替える・アプリを閉じる前も、同じ確かめで止める（入力項目のパネルの決まり 0131 を同じく使う）。
- 押すとすぐ効く物は今のまま: 機能を有効にするコードを入れる・外す（本体が確かめる。事務所の既定値の欄ではない）、AI からの案の「反映する」「ひな形として保存する」（承認待ちの候補を決める操作。反映した値と前の値は、変えている途中の欄にも写す）、カスタム層の承認（カスタム層のファイルと台帳）。どれも画面に「保存は要りません」と書く。
- 前の「全部を既定に戻す」（パネルの真ん中）は、画面ごとの「この画面を既定に戻す」（前提条件の既定値・FP顧問料の料金表・入力の画面・結果と万一の画面）にした。前提条件の既定値の画面では、置き場所が推定の値の欄（土地の割合など・資産の種類の目安）も空欄（公式の値）にする（前は推定の値の区画で戻した）。どれも「保存」で決まる。

### 3. 2か所で変えていた値は、前提条件の既定値の画面だけで変える

- 土地の割合・建物の残りの価値の下限・売却の費用、資産の種類の信託報酬と期待リターンの目安（期待リターンの目安の無い外貨預金は預金の利回り）。置き場所は事務所の推定の値（`preset.realEstate.*`・`preset.invest.<種類>.fee`・`.return`）のまま。
- 前提条件の既定値の画面の「資産配分の割合と目安」の表に、期待リターンの目安の列を足した（割合・期待リターン・信託報酬の3つ）。
- 推定の値の画面では、その行を読むだけにして、「変える」の代わりに「前提条件の既定値で変える」（押すと前提条件の既定値の画面のその欄へ移り、欄を選ぶ）。公式の値の更新の知らせの「公式に戻す」「値を入れ直す」も同じリンクにする（「このまま」は今のまま押せる）。どの値かは `pages.ts` の `premisePageField` の1か所。

### 4. 「運用利回り」の名前

- 事務所の既定値の画面では「配分も利回りも入れていない運用の口座」と呼び、前提条件の既定値の画面の「資産運用の利回り」の区画に置く（資産の種類ごとの利回りの下）。「?」に使い道（口座ごとの利回りも資産の配分も入れていない運用の口座、資産の種類ごとの利回りを空欄にした種類、必要保障額の逆算方式の遺族の資金）と前の名前を書く。置き場所（`defaults.assumptions.investmentReturn`）と写し方は変えない。資産の種類ごとの利回りの空欄の欄には、この率を薄く出す。
- 世帯の前提条件の入力項目・前提と推定の一覧での扱いは、別の変更（前提条件の入力項目の見直し）で決める。

### 5. 見せ方（文字の段・部品・説明・余白）

- 文字は5段＋印（事務所の既定値の画面の中だけ。`.os-panel` の `--os-1`〜`--os-5`）: 段1 パネル・画面の名前 1.25rem 太／段2 区画の見出し 1rem 太・左の線／段3 まとまり・表の見出し 0.92rem 太／段4 欄の名前・値・本文 0.9rem／段5 説明・空欄のときの値・例 0.8rem 灰／印 0.74rem 太。
- 欄は入力項目の部品をそのまま使う: 数の欄（`.fld`・`.fld-l`・`.fld-c`・`.fld-in`・`input.num`・`.suffix`）、選ぶ欄、区切りボタン（`.seg-g.fld-seg`。継続の顧問料の月額／年額・万一のときの止める／続ける・介護の費用・相続の見込みの確実／不確実）、チェック（`.fld.is-check`。対策・場面・想定の前提・推定で埋めない欄・合算BS）、小さなボタン（`.add-btn`）。ほかの文字の欄・選ぶ欄も入力項目の欄と同じ枠・角・高さにする（ブラウザの素の形にしない）。新しい世帯で出す入力項目の一覧は、入力のホームの「入力項目を選ぶ」と同じ部品（チェックと「標準」「詳細」）のまま。
- 説明: 画面・区画の頭に1文（段5）。長い説明・範囲・使い道は見出しや欄の名前の「?」の中。範囲は打ち間違えたときだけ欄の下に出す。欄の下は1行（空欄のときの値「空欄: 1%（提供元の既定）」・例・知らせのどれか）。欄の名前から「（年）」を外す（「物価上昇率（年）」→「物価上昇率」）。
- 余白: 区画の間 24px・見出しと中身 8px・欄の間 縦14px 横24px・枠の内側 12〜16px。率の欄は2〜4列（狭い幅では2列・1列）。
- 区画の見出しは「左の線＋太字」の1行（入力項目の区画の見出しと同じ形）。

## 理由

- 7つの画面にすると、前提条件の既定値の画面が約2,200px（前の1枚は約11,300px）になり、探す所が減る。左の目次なら、どの画面からも1回で移れ、要約で開かなくても今の値が分かる。タブ（7つでは名前が詰まる）・最初に一覧の画面（行き来が2回になる）より使いやすい。
- 保存を1つにすると、どの画面でも「下の帯の保存で決まる」と言える。推定の値・見た目だけ押すとすぐ保存する作りは、ほかの画面と並べると、保存したつもりで閉じる・保存されたのに気付かない、のどちらも起きる。
- 置き場所を変えずに変える所だけを1つにすると、事務所データの形と前の版のアプリでの読み方を変えずに、同じ値が2か所で食い違って見えることを無くせる。
- 入力項目の部品と同じ形にすると、FP が入力の画面で覚えた見方がそのまま使え、画面ごとのちぐはぐが無くなる。

## 代案（採らなかったもの）

- 上のタブで7つに分ける・最初の画面にリンクの一覧（下調べの分け方2・3）: 上の理由。
- 画面ごとに保存: 保存の場所が7つになり、画面を移るたびに保存するかを聞くことになる。
- 推定の値の画面はすぐ保存のまま（下の帯は「閉じる」だけ）: 下調べの案ではこの形だったが、利用者の判断で全部まとめて1つにした。
- 2か所で変えていた値の置き場所を前提条件の既定値（`defaults.realEstateValuation` など）に移す: 事務所データの形が変わり、前の版のアプリと推定の値の読み方（計算の要求に入れる値）も変わる。
