# 0233. 変額保険を「続ける」場合と「解約して、保障と運用に分ける」場合を並べる（比較の試算と、分けたプランを作るボタン）

- 状態: 採用（一部未確定）（2026-11-19）
- 固定の強さ: 内部。部品 `insurance.policy` の改訂7（円の目安の形の変額保険の死亡保険金の決まり。約束の版 1.3 は変えない）と、画面の側の B の組み立て方（解約の月・掛け捨ての保険・NISA への入れ方）・既定の値・表の列・言葉・プランの名前は後から変えてよい（変えたら追記に書く）。世帯ファイルの形式の版は変えない（足した入力の欄は無い。B はプランの差分で、今ある欄だけで表す）
- 前提にする記録: 0009（作業中のプラン）、0036・0043（プランの差分・入力画面でプランを直す）、0128（比較の行からプランを作るボタン）、0026（NISA の枠・受け取りを運用に回す近似）、0054・0055（変額保険の円の目安の形・保険の入力項目）、0179（変額・外貨建の積立金）、0044（一時所得の特別控除）

## 背景

- 変額保険に入っている世帯に、FP が「保障（掛け捨ての保険）と運用（NISA など）に分けるとこうなる」を一目で示したい。今の作りでは、解約の月・掛け捨ての保険・NISA の積立を FP が別々の入力項目で入れ、プランを手で作るしかなかった。
- 商品を特定しない・おすすめを出さない方針は変えない。並べるのは比較の試算として。
- 変額保険の設計書は、運用実績の例（年3%・6%・10% など）ごとの解約返戻金を載せる。高い利回りの例の数字と、NISA を前提条件の利回りで伸ばした数字を並べると、保険と運用の違いではなく利回りの前提の違いで差が出てしまう。

## 決定

### 1. 今のエンジンで表せるか（最初に確かめた）

- 表せた。足す入力の欄は無い。
  - 解約: 保険契約の解約の月 `insurance.surrender`（`insurance.term` がその月で保障と払込を終わらせ、`insurance.policy` がその月に、その月までに終わった保険年度の解約返戻金を受け取りにする）。
  - 税: 解約返戻金は受取人＝契約者の一時所得で、必要経費はその時までの払込保険料の累計。50万円の特別控除の後の2分の1を総所得金額に入れる（`insurance.income`）。払込総額を下回れば一時所得は出ない。
  - 保障の買い直し: 定期保険・収入保障保険の保険契約（契約の月＝解約の月）。
  - 運用: NISA の器の積立（`contributions`。1か月だけの期間で一時の額も入れられる）。年間の枠・生涯の枠・つみたて投資枠を超えた分を成長投資枠へ、それも超えた分の扱いは今の NISA の部品のまま（`plan.cashflow`）。
- 足したのは1つだけ: 円の目安の形の変額保険の死亡保険金（下の2）。

### 2. A（続ける）

- 今の契約のまま。毎月の保険料を払い続け、解約返戻金は数表（今ある保険の取り込み・マイ商品集の年次の数表）どおり。数表が無ければ今の「変額保険（目安）」の円の目安の形（0054 の3）。
- **死亡保険金の最低保証**（`insurance.policy` 改訂7）: 円の目安の形の変額保険（`insurance.variable` で `simple.estimate`）の契約の被保険者の死亡保険金は、基本保険金額（主契約の死亡保障の額）・数表の死亡保障・その時に解約したときの解約返戻金の多い方。前は、数表の死亡保障の行があればその額（基本保険金額を下回る行でもそのまま）、無ければ基本保険金額のままで、数表の解約返戻金が基本保険金額を超えた年も死亡保険金が基本保険金額だった（変額保険の死亡保険金は基本保険金額と積立金の多い方で、積立金は解約返戻金を下回らない）。外貨建て保険の目安の形・前の入れ方（積立金を伸ばす形）は変えない。

### 3. B（分ける）

画面の側で、見ているプランの要求に次を足した要求を作る（`app/src/workspace/input/variableSplit.ts`）。

- **解約する月**: 選んだ年（既定は計算基準年）の1月。計算基準年は計算基準月（必要保障額の「その年の最初の月」と同じ決まり。0170）。解約返戻金は、その月までに終わった保険年度の数表の額（エンジンと同じ数え方）。数表にその保険年度の行が無ければ（数表の無い目安の形・前の入れ方）、FP が解約返戻金を入れる欄を出し、その額を **B のプランだけ**その保険年度の数表の行として足す（現状は変えない）。
- **保障**: 掛け捨ての保険（定期保険か収入保障保険。既定は定期保険）を、解約の月に、契約者・被保険者・受取人を変額保険と同じにして入れる。保険料は FP が入れる（月払い。入れるまで表を出さず、プランも作れない。目安は作らない＝保険のひな形の「保険料は目安を作らない」と同じ。0055）。保障の額の既定は今の死亡保険金（計算の結果の計算基準年の年末の額。2 の最低保証の後）、収入保障保険は今の死亡保険金を保障の終わりまでの月数で割った年金月額（千円単位に切り上げ）。保障と払込の終わりは被保険者の年齢（既定は65歳。今の年齢＋10歳が65歳より上ならその年齢）。名前は「分けた保障（掛け捨て）」。
- **浮いた保険料**: A の月の保険料（解約の月の、更新を入れた額。年払いは12で割る。一時払い・払込が終わっていれば0）−掛け捨ての保険料。プラスなら、解約の月から A の払込が終わる前の月まで、毎月 NISA のつみたて投資枠に積み立てる。マイナス（掛け捨ての保険料のほうが高い・払込が終わった契約）なら積み立てない（差は保険料の行どおり家計から払う）。
- **解約返戻金**: 税を引く前の額を運用に回す（一時所得の税は翌年までに預金から払う。iDeCo の受け取りを運用に回すとき〔0026 の4〕と同じ近似）。NISA の成長投資枠に、年ごとの枠の残り（成長投資枠の年240万円・成長の生涯1200万円・生涯1800万円から、名義の人の今の NISA の使った枠・その年の積立と、浮いた保険料の積立〔つみたて投資枠の120万円を超えた分は成長投資枠〕を引いた分）まで入れる。解約の年は解約の月、次の年からは1月。入れる前の分は預金に置く。生涯の枠に入らない分は、解約の月に課税口座へ入れる。
- **運用の口座**: 契約者の名義の NISA の器（「分けた運用（NISA）」）と、要るときだけ課税口座（「分けた運用（課税口座）」）を足す。残高0円から、利回りは下の4の B の利回り（器の利回り `expectedReturn`。資産配分の入れ方でも、この器はこの利回り）。取り崩しの順番は世帯の前提のまま（家計が足りない年は B の運用からも取り崩す。A の解約返戻金は取り崩さない）。
- 合計の入れ方（`investment.method` が `total`）では口座に分けて計算できないので、区画にその旨を出し、作れないようにした。

### 4. 運用の利回り（A と B を同じ前提にそろえる）

- B の利回りは3つから選ぶ: 「A の数表（設計書）と同じ」（数表がどの運用実績の例の数字かを FP が入れる。前の入れ方の変額保険は、エンジンが積立金を伸ばす利回り）・「資産クラスの前提」（前提条件の資産の種類ごとの利回り。無ければ運用利回り。エンジンが資産の配分で使う値と同じ。運用の費用は引かない）・「ほかの利回り」。
- 既定: 円の目安の形は「資産クラスの前提」（数表の利回りはまだ分からないため）で、資産クラスは変額保険の資産クラスがあればそれ、無ければ外国株式。前の入れ方は「A と同じ」。
- 区画に並べて出す: A の数表の利回り（例の利回り。未入力ならその旨、数表が無ければ A のこれからの解約返戻金は出せないこと）・資産クラスの前提の利回り・B に使う利回り。A と B の利回りが違えば「前提がそろっていません」。いつも「設計書の利回りは運用の例で、約束された値ではありません。高い利回りの例だけで判断しないでください」。

### 5. 入れ方と表

- 保険の入力項目の、保険料と解約返戻金の区画の下に「変額保険: 続ける（A）と、解約して保障と運用に分ける（B）の比較」の区画（変額保険で解約の予定が無い契約があるときだけ）。変額保険の行の「解約して分けたら」で開く。欄は、解約する年・解約返戻金（数表に無いときだけ）・掛け捨ての保険の種類・保険料・保障の額・保障の終わり・B の利回り。
- 開いた区画で、A（見ているプランのまま）と B を画面の側で1回ずつ計算し（万一の場面を外した要求。保険料と解約返戻金の区画と同じ）、年ごとの小さな表を出す: 年（被保険者の年末の年齢）・A の解約返戻金（数表の無い目安の形は「—」）・B の運用残高（NISA・課税口座の年末の残高と、まだ NISA に入れていない解約返戻金）・亡くなったときに家族に入る額（A は死亡保険金、B は掛け捨ての保険金〔収入保障保険は残りの受け取りの合計〕＋運用残高）。年は、解約の年・5年ごと・A の払込が終わる年・掛け捨ての保険が終わる年・最後の年。表の上に浮く保険料の1行と、解約返戻金の行き先の1行。
- 必ず出す注意（区画の中にいつも）: 健康状態によっては新しい保険に入れないことがある・早い時期の解約には解約控除がかかる・年齢が上がると保険料が上がる・保険の募集人が乗り換えを勧めるときには説明の決まりがある。

### 6. プランを作る

- 区画の「このプランを作る」で、入力で編集の対象にしているプラン（現状なら現状）を写して新しいプランを作り（帯の「＋ このプランを元に作る」と同じ `savePlan`）、そのプランに、3 の B の差分を入力画面でプランを直したときと同じ記録（`recordPlanEdit`。直す前はそのプランの中身）で足す。0128 の売る年のプランと同じ作り方。元のプランは変えない。
- 作ったプランを帯に足して選び、元のプランを比較の基準にして、結果のタブに移る（結果のプランの比較で A と B が並ぶ）。パネルに保存していない変更があれば、先に保存してから作る。
- 名前は帯の「＋」と同じ頭に「（契約の名前）を解約して分ける」（例: 「プランC 変額保険 1を解約して分ける」）。

## 理由

- **エンジンに解約したお金の行き先を持たせない**: 解約・掛け捨ての保険・NISA の積立はどれも今の欄で表せ、B は FP がプランを直して作るのと同じ差分になる。行き先の欄を足すと世帯ファイルの形式が変わり、プランで直せる欄も増える。作ったプランは入力画面でふつうに直せる。
- **解約返戻金を年ごとに成長投資枠へ**: 1回で入れると、その年の枠を超えた分が世帯の前提（既定は預金に残す）で扱われ、B が利回りの前提と関係なく不利に見える。現実にも年ごとに入れる。
- **税を引く前の額を運用に回す**: 一時所得の税は総所得金額の中で決まり、解約の前に画面で正しく出せない。0026 の4 と同じ近似にそろえた。
- **利回りの既定を「資産クラスの前提」にし、A と同じにも選べるようにする**: 数表がどの利回りの例かは設計書を見ないと分からない。「A と同じ」を選べば保険と運用の違いだけが見え、並べた利回りで、高い例の設計書の数字だけで判断していないかも見える。
- **死亡保険金の最低保証を部品で直す**: A の「亡くなったときに家族に入る額」を表に出すので、数表の解約返戻金が基本保険金額を超えた年に死亡保険金のほうが少ないのは、比較をゆがめる。

## 代案（採らなかったもの）

- **B を画面の側の単純な計算（複利の式）で出す**: プランの結果と表の数字が食い違う（0128 と同じ理由で採らない）。
- **既存の NISA の器に積立を足す**: B の運用残高を分けて見られず、B の利回りが今の NISA の残高にもかかる。
- **B の運用を取り崩さないにする**: 取り崩しの順番は世帯の前提で、B だけ変えると現金の動きの比較がゆがむ。家計が足りないときに使えることは B の性質として見せる。
