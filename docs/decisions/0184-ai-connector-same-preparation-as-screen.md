# 0184. AI接続口の計算にも、画面が計算の前に当てる処理を同じ関数で当てる

- 状態: 採用（一部未確定）（2026-11-10）
- 固定の強さ: 道具の答えの `preparation` は試験版（0015 と同じ。予告して変えることがある）。作り（画面の関数を同梱して当てる・事務所の推定の値はアプリ本体が計算に使う読み取りにだけ添える）とアプリ本体と接続口の取り決め（`getShare` の `forCalc`・返事の `officeEstimates`）は内部
- 前提にする記録: 0005（計算の実行環境）、0014（AIに渡した記録）、0015（AI接続口）、0016（画面の安全）、0035 の7・0036 の6・0044（基本の計算に入れない物と結果の見方）、0060（世帯に保存した表示だけの設定）、0103（夢プラン）、0111（事務所の推定の値）、0183（数字の根拠）

## 背景

- 画面は、計算の要求をエンジンへ渡す直前に、`app/src/engine/moneyRows.ts` の `forEngine` を当てる（画面の速い計算・本体の計算・根拠の計算・提案書・持ち帰りのどれも同じ1か所）。接続口の `calculate`・`explain_value` は、世帯の入力のまま計算していた（0183 の未確定）。そのため、FP が渡した世帯でも、計算に入れない物や事務所の推定の値があると、画面と接続口で数字がずれた。
- 利用者の判断（2026-11-10）: 当てる。画面の関数を同梱して当て、画面とそろえる。

## 決定

### 1. 画面が計算の前に世帯・入力に当てている処理の洗い出しと、接続口で当てるか

| 処理（画面の場所） | 何をするか | 世帯の数字を変えるか | 接続口 |
|---|---|---|---|
| 基本の計算に入れない物を外す（`forEngine`。0035 の7・0044） | 見込みが「当てにしない」の受け取る相続・遺贈・贈与と、相続で受け継ぐ借金を、要求から外す（`includeInBase` で入れた物は残す） | 変える | **当てる** |
| 「計算に入れない」夢を外す（`forEngine`。0103） | `dream.include` が false の夢を要求から外す | 変える | **当てる** |
| 事務所の推定の値を足す（`forEngine` の `withOfficeEstimateValues`。0111） | 事務所の既定値の画面で変えた値を `estimateValues`、推定で埋めない目安を `estimateNoFill` として足す（要求がもう持っていれば足さない） | 変える | **当てる**（渡された世帯のときだけ値が届く。2） |
| 表示だけの設定を外す（`forEngine` の `withoutStoredSettings`。0060） | 時点の無い相続税の目安の設定と、遺したい額を外す | 変えない | 当てる（`forEngine` に入っているので同じ関数のまま。答えの印には出さない） |
| 結果の見方（`applyRowsView`。0044 の追記） | 「確実な分だけ」・物ごとの入れ外し | 画面の見方だけ（保存しない。既定は何も変えない） | 当てない |
| 比べるための別の枠（`withoutDreams`・相場が下がった場合・FP顧問料の有無・扶養の境目の参考の行） | 選んだプランと比べる別の計算 | 主の数字は変えない | 当てない（接続口は `changes`・`stress_test` で同じことを頼める） |
| プランの値を当てる（`applyValues`） | 保存したプランの差分を現状に当てる | 変える | 当てない（渡すのは現状。プランは AI が `changes` で当てる。0015） |
| 推定の入れ直し・事務所の既定値を空の世帯に写す・仮の住まい（`withRefreshedEstimates`・`applyOfficeDefaults`・`withProvisionalHousing`） | 入力を直したとき・世帯を作ったときに世帯そのものを直す | 世帯に保存される | 当てない（保存した世帯にもう入っている） |
| 拡張の束（0114） | 資産と負債のタブ・提案書の章の見せ方 | 計算の要求に触れない | 当てない |

### 2. 作り: 画面の関数を同梱して当てる

- 入口 `app/src/connector/prepare.ts` の `prepare(要求, 事務所データの defaults.estimates)`: 画面と同じく、事務所データを `readOfficeEstimates` で読み、`publishOfficeEstimates` で今の事務所の値にしてから、画面と同じ `forEngine` を当てる。返すのは当てた要求と、当てた物（外した入るお金・受け継ぐ借金・夢の ID、足した事務所の値の値ID と推定で埋めない目安）。画面の関数は1文字も直していない（画面の答えは変わらない）。
  - 0183 の読み方と同じ1つの JS（`crates/lifeplan/dist/explain.js`。グローバル `FinanciaExplain`）に入れる（`explain.ts` から `prepare` も出す）。lint で、接続口の入口が作業の層のうち読めるのを `evidence`・`present`・`office/estimates` だけにした。まとめた JS は約 0.21MB から約 0.30MB になった（推定の目安の統計の写しが入るため）。
  - 接続口（`crates/lifeplan/src/engine.rs` の `prepare`）は、計算と同じ固めた新しい実行環境で、呼ぶごとに読み込んで呼ぶ（事務所の値はモジュールの中に入れるが、呼び出しをまたいで残らない）。1回およそ 10ms（計算の約 1%）。
- `calculate`・`explain_value` は、見本の世帯・渡された世帯・AI が組み立てた入力のどれにも、`changes`・`stress_test` を当てた後に `prepare` を当ててから計算する。
  - `explain_value` は、画面の根拠のパネル（`App.tsx` の `showEvidence`）と同じく、根拠の記録「全部」で計算するのは処理の後の要求、根拠の読み方に渡すのは処理の前の要求。
  - 見本の世帯・AI の入力には事務所の値が無いので、計算に入れない物を外すだけ（画面で事務所の値が無いときと同じ）。見本の世帯（`data/modelHouseholds`）はどれも当てても要求が1文字も変わらない（計算に入れない物も事務所の値も無い）ことを、テストで確かめる。AI の入力にも当てるのは、同じ入力の意味をアプリと同じにするため（当てにしない相続を AI が入れても、画面と同じく計算に入れない）。
- 事務所の推定の値の受け渡し: 事務所の値は世帯ファイルに入らない（0111）ので、アプリ本体が渡す。
  - 接続口は、計算に使う読み取り（`calculate`・`explain_value` の `share_id`）だけ、アプリ本体への `getShare` に `forCalc: true` を付ける。アプリ本体は同じ返事・同じ記録に、そのときの事務所データの `defaults.estimates`（無ければ null）を `officeEstimates` として添える（`crates/ai-share` の `handle_get_for_calc`。読む所は `ShareRegistry::set_office_estimates` でアプリ本体〔`app/src-tauri/src/ai.rs`〕が起動のときに入れる。共有の台帳のロックを放してから読む）。共有した後に事務所の値を変えても、次の計算から今の値になる（画面と同じ）。
  - 事務所の値の元をそのまま渡し、読み方（使える値の確かめ・エンジンへ渡す形）は画面と同じ関数に任せる。アプリ本体は `defaults.estimates` を切り出すだけ（ほかの既定値は渡さない）。画面が計算した値を本体に送る形は採らなかった（代案）。
  - AI には見せない: `get_shared_household` は `forCalc` を付けず、返事は今までと1文字も変わらない。`calculate`・`explain_value` の答えに出すのは、足した値の値ID と推定で埋めない目安だけ（値・FP が書いた根拠の文は出さない）。
- 渡されるのは保存した世帯（今までどおり）。FP が画面でまだ保存していない変更・選んでいる結果の見方は、接続口の数字に入らない（INSTRUCTIONS に書いた）。

### 3. 答えの印 `preparation`

- AI が「アプリの画面と違う」「入力にある相続が表に無い」と言い出さないように、何かを当てたときだけ、`calculate`・`explain_value` の答えに `preparation` を添える。
  - `note`: 画面と同じく計算の前に当てたこと・世帯のデータは変えていないこと・各欄の意味。
  - `notInCalculation`: `incomeFlows`（当てにしない受け取る相続・遺贈・贈与）・`inheritedDebts`（当てにしない受け継ぐ借金）・`dreams`（計算に入れない夢）。`calculate` は ID の並び（渡された世帯は共有の仮の ID）、`explain_value` は数だけ（数字の根拠は世帯の物の ID を返さない。0183）。
  - `officeEstimates`: `values`（足した事務所の推定の値の値ID）・`noFill`（推定で埋めない目安）。
- 何も当てなければ添えない（見本の世帯の答えは今までと同じ）。
- INSTRUCTIONS と `calculate`・`explain_value` の説明に、画面と同じ処理を当てること・`preparation` に出ること・保存していない変更と結果の見方は入らないことを足した。

### 4. AIに渡した記録（0014）は変えない

- 計算に使う読み取りも、今までと同じく読んだ道具の名前（`calculate`・`explain_value`）で `reads` に残る。渡した項目・中身の指紋は縮約版から作り、事務所の値を入れない（世帯の中身ではない）。同じ共有を `get_shared_household`・`calculate`・`explain_value` で読んでも、項目と指紋は同じ。共有が使えない（期限切れ・取り消し・同意の撤回）ときは今までと同じ答えで、事務所の値も読まない。

### 5. テスト

- 画面の側（`app/test/connector-prepare.test.ts`）: 前処理が効く世帯（親の介護の見本に、当てにしない相続・当てにする相続・当てにしない受け継ぐ借金・計算に入れない夢・入れる夢を足した物）と事務所の推定の値（介護の期間と在宅の月額・推定で埋めない目安1つ）で、`prepare` の要求が、画面が事務所データを読んでから `forEngine` で作る要求と同じこと、前処理で数字が変わること、事務所の値が無いとき・要求がもう値を持つとき、どのモデル世帯にも当てても要求が変わらないことを確かめ、画面の数字（年ごとの年間収支・金融資産と合計。事務所の値ありと無し）と根拠（3つのマス）を見本（`crates/lifeplan/tests/fixtures/prepare/expected.json`）に書く（`LIFEPLAN_UPDATE_FIXTURES=1` で作り直す）。
- 接続口の側（`crates/lifeplan/tests/mcp_connector.rs` の `calculation_matches_the_screen_after_preparation`）: 本物の接続口を起動し、その世帯を渡された世帯（縮約版を通る）として `calculate`・`explain_value` を MCP で呼び、見本の画面の数字・根拠と同じこと、`preparation`、AI の入力では事務所の値の無い画面と同じこと、`get_shared_household` の答えに事務所の値と根拠の文が無いこと、記録の道具・項目・指紋、アプリ本体が値を添えないときを確かめる。
- `crates/ai-share/tests/sharing.rs` の `calc_reads_carry_the_office_estimates_and_record_the_same`（添える値・ふつうの読み取りと同じ中身と記録・取り消した共有では読まない）、`crates/ai-ipc` の取り決めの形、`app/src-tauri/src/ai.rs` の `office_estimates_are_cut_from_the_office_defaults`（`defaults.estimates` だけを切り出す）。

## 理由

- 画面の `forEngine` は、画面のすべての計算が通る1か所。これを同梱して当てれば、画面と接続口で前処理がずれない（直すのは1か所。0183 の2と同じ考え）。
- 事務所の値の読み方（使える値か・公式の値の形が変わったか）も画面の関数のまま使うので、接続口に読み方を書き直さない。
- 計算に使う読み取りにだけ事務所の値を添えれば、AI に見せる答え（`get_shared_household`）と AIに渡した記録の中身は変わらない。

## 代案（採らなかったもの）

- **前処理を Rust で書き直す**: 外す物の決まり（種類・見込み・`includeInBase`・夢）と事務所の値の確かめを二重に持つことになり、ずれる。
- **アプリ本体が共有の縮約版を作るときに前処理を当てる**: アプリ本体は計算の要求の読み方を持たない（JS の関数）。縮約版を AI が `input` に写して計算し直すときにも、前処理を当てた後の入力になり、外した物が AI に見えなくなる（`preparation` で説明できない）。
- **画面が計算した事務所の値をアプリ本体に送り、本体が添える**: 本体の命令が1つ増え、画面（WebView）から届いた値をそのまま AI の計算に使う経路ができる（AI まわりの記録の区画も、画面から届いた物は使わず本体が持つ物で作っている。`app/src-tauri/src/ai.rs`）。事務所の値の元は本体の事務所データにあるので、元を渡して同じ関数で読むほうが筋がよい。
- **事務所の値を `get_shared_household` の答えにも入れる**: FP が書いた根拠の文が包まずに AI に渡る。値そのものも、計算に要らない AI には見せる理由が無い。
- **結果の見方（確実な分だけ）も当てる**: 保存しない画面の見方で、アプリ本体は知らない。AI が同じ見方を見たいときは `changes` で外せる。

## 未確定

- **事務所の行の名前**（0183 の未確定のまま）: 接続口の根拠の見出しは公式の名前。
- **保存していない変更**: 共有するのは保存した世帯なので、FP が画面で直して保存していない間は、画面と接続口の数字が違う。共有中に保存を促すか、画面の作業中の世帯を渡すか。
- **事務所で共有しているときの事務所の値**: アプリ本体は、この PC が持っている事務所データの値を添える。もう1台の PC が事務所の値を変えた後、この PC の画面と本体の値が同じ時点で入れ替わるか（画面は事務所の既定値を読み直したときに入れ替わる）は確かめていない。
- **`preparation` の形**: 何を当てたかの名前（`notInCalculation` など）と、外した物の見出し（縮約版では見出しが外れているので ID だけ）は、FP の使い方を見て直す。
