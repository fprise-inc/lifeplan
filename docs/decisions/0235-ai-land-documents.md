# 0235. 書類の読み取りに、固定資産税の課税明細書と路線価図を足す（相続税の試算の土地・建物の欄。書類の土地を今ある不動産に入れる・伏せる情報・路線価図の記号の読み方）

- 状態: 採用（一部未確定）（2026-11-20）
- 固定の強さ: 骨格（書類の種類 `propertyTaxStatement`・`routePriceMap`、値の候補の入力項目 `plan.inheritanceTax` と場所 `["lands", "area" | "fixedValue" | "buildingValue"]`〔課税明細書〕・`["lands", "routeMark"]`〔路線価図〕、書類の土地の物の種類 `land:site`〔今ある不動産に入れるだけで、足さない〕、路線価図の記号の読み方〔数は千円単位・記号 A〜G は借地権割合〕）。答えの形 `document-candidates@1` は足すだけ（0148 の固定の強さのとおり）。世帯ファイルの形式の版・区画 `documents` の形は変えない。画面の言葉・手引きの文・理由の文は内部（後から変えてよい）
- 前提にする記録: 0148（書類の読み取りの土台）、0151（`propose_inputs`・貼り付けの入口）、0152（AI 向けの説明書と手引き）、0154（今ある物に入れる・時点の欄）、0157（外部AIへの提供の同意の説明文の版2）、0159（読み取りを保険の書類に絞った）、0221（明細の写真の読み取り）、0226（事務所のプライバシーポリシーによる共有・`ai_documents_use`）、0231（相続税の試算の土地・建物の評価と `lands[]`）

## 背景

- 0231 で、相続税も試算する世帯だけ、不動産ごとに土地の面積・評価の入れ方（路線価・倍率・推定）・固定資産税評価額・建物の固定資産税評価額・借地権割合を入れられるようにした。土地の評価を自動で取りに行くこと（路線価の地図の検索など）はしない方針。
- 現場では、この値を2つの書類から写す: 固定資産税の課税明細書（土地の地積・価格、家屋の価格。筆が何行も並ぶ）と、国税庁の路線価図（路線価の数字と借地権割合の記号。例「250C」）。どちらも、打つ数は多くないが**読み方が難しい**（課税明細書は価格と課税標準額を取り違えやすく、複数の筆を足す・共有の持分の扱いで迷う。路線価図は千円単位と記号の意味を知らないと読めない）。
- 利用者の判断（2026-11-20）: この2つを AI で読み取れるようにする。既存の書類の読み取り（0148・0151）と同じ流れ（読み方の手引き・AI の道具・FP が画面で確かめてから入れる）にする。

## 決定

### 1. 0159 との関係（ものさしに当たる書類として足す）

- 0159 は、取り込みが割に合う書類を「打つ数が多い・読み方が難しい・行が多いデータ」のどれかに当たる物に絞った。課税明細書と路線価図は「**読み方が難しい**」に当たる（下の 4〜6 の取り違え）。数字が数個で書類のどこを見ればよいかが決まっている書類（源泉徴収票など）を外した判断は変えない。
- 0159 の骨格の「読み口が受ける書類の種類は `insurancePolicy`、値の候補は `insurance.` だけ」を、**書類の種類ごとに受ける欄を決める**形に広げる: 保険の書類は今までどおり保険の契約の欄（`insurance.`）だけ、課税明細書・路線価図は相続税の試算の不動産ごとの欄（`plan.inheritanceTax` の `lands`）だけ。書類の種類と欄を混ぜた答え（保険の書類に土地の欄、課税明細書に保険の欄）は読まない（0159 の 8「値の候補も保険の契約の欄だけにする」と同じ考え）。
- 取り込みを外した書類の前の記録の扱い（0159 の 5）は変えない。

### 2. 読む欄と入れ先

| 書類 | 書類の欄 | 候補の場所（`item` は `plan.inheritanceTax`） | 入れ先（0231 の `lands[]`。画面の欄） |
|---|---|---|---|
| 課税明細書 | 土地の地積（㎡。現況地積があれば現況、無ければ登記地積。同じ敷地の筆の合計） | `["lands", "area"]` | `area`（「土地の面積」） |
| 課税明細書 | 土地の価格（固定資産税評価額。同じ敷地の筆の合計） | `["lands", "fixedValue"]` | `fixedValue`（「土地の固定資産税評価額」。評価の入れ方が倍率・推定のときの欄） |
| 課税明細書 | 家屋の価格（固定資産税評価額） | `["lands", "buildingValue"]` | `buildingValue`（「建物の固定資産税評価額」） |
| 路線価図 | 指した土地の前の道路の路線価と記号（例「250C」） | `["lands", "routeMark"]`（印字のまま） | 読み口が3つに分ける: `method` を `routePrice`（「土地の評価の入れ方」）・`routePrice` を 250×1,000円（「路線価（1㎡あたり）」）・`leaseholdRatio` を `C`（「借地権割合（路線価図の記号）」） |

- 読まない欄: 地目（入力の欄が無い。宅地でない筆は合計に入れず、添え書きに書く）・課税標準額・税額・都市計画税・負担調整・住宅用地の区分・家屋の構造と床面積と建築年（入力の欄が無い）・評価倍率（評価倍率表はこの記録の対象外。FP が打つ）。
- **土地の所在**は読まない・入れない: 0231 の `lands[]` に所在の欄は無く、計算にも使わない。AI は同じ敷地の筆をまとめるために所在を見るが、値・元の場所・添え書きに書かない。
- 家屋は固定資産税評価額がそのまま相続税の評価額（倍率 1.0。財産評価基本通達 89）なので、家屋の価格をそのまま `buildingValue` に入れる（計算は 0231 の 4 のまま）。
- 相続税の倍率方式に使うのは固定資産税評価額（価格）で、課税標準額（住宅用地の特例などで減らした額）ではない。読み口は、見出しに「課税標準」「税額」「負担調整」「負担水準」「軽減」がある土地・家屋の候補を読まずに理由を出す（`land.ts` の `NOT_VALUE_WORDS`）。

### 3. 書類の土地（`land:site`）を今ある不動産に入れる

- 答えの `objects` に、**書類の土地のまとまり**（課税明細書の同じ敷地の筆と家屋・路線価図の1つの土地）を `{"key": "s1", "kind": "land:site"}` で書き、値の候補の `newObject` でその鍵を指す。
- 確かめの画面では、まとまりごとに「どの不動産の値として入れますか」と出し、相続税の試算の対象の不動産（持ち家・住まい以外の不動産。0231 の `landTargets` と同じ並び）の名前のボタン（「『持ち家』に入れる」）と「入れない」を出す。**新しく足すことはできない**（不動産を書類から作らない。`objects.ts` の `linkOnly`。`createObject` は null）。選ぶまでは、その中の値の行は「先に、どの不動産の書類かを選んでください」で承認できない。
- 物の候補の仕組み（0154 の3 の今ある物に入れる仕組み）をそのまま使う。持ち家と住まい以外の不動産の2つの集まりにまたがるので、`collection`・`sameKind` の代わりに `linkOnly` で入れられる物を返す。
- AI接続で世帯を受け取り、どの不動産か FP が言ったときは、`objects` を書かずに値の候補の `object` に不動産の ID を書いてよい（その不動産の欄に入る）。どちらも書かない候補は、どの不動産の欄かを FP が選ぶ（1つしか無くても選ぶ。0152 の3 と同じ）。

### 4. 複数の筆・共有の持分

- `lands[]` は不動産1つに1行（物件全体の値）なので、**同じ敷地の筆は AI が足して1つの値にする**。足したことと筆ごとの地積は添え書きに、筆ごとの価格は照合だけの値（`references`）に1筆1つ書く（FP が書類と比較できる）。離れた土地は別のまとまりにする。
- 共有の持分:
  - **家族（夫婦など）の共有**は、持分をかけずに物件全体の地積・価格を書き、添え書きに持分を書く。亡くなる人の分は、アプリが持ち家・不動産の名義の割合で分ける（0231 の 3「亡くなる人の分は名義の割合で分ける」）。名義の割合は FP が持ち家の欄で確かめる（課税明細書から名義の割合には入れない。宛名の人がどの構成員かを書類から決めないため）。
  - **マンションなどの敷地権**は、敷地全体の地積・価格に持分の割合をかけた値（その部屋の分。0231 の面積の欄の説明「敷地全体の面積×敷地権の割合」と同じ）を書き、添え書きに式を書く。明細書の価格がもう持分の分なら、かけずに書く。
  - どちらか分からないときは物件全体の値を書き、確かさを中にする。
- 地積は小数2桁まで（0231 の `landArea` の形）。読み口は、3桁目から先を切り捨て、添え書きに「小数3桁目から切り捨てました」と足す（持分をかけた地積など）。全角・桁区切り・「㎡」は読む。0 ㎡は読まない。
- 価格は円の整数（全角・桁区切り・「円」は読む）。**価格0円**（非課税の土地など）は読むが、添え書きを足し、確かさを中にする（まとめての承認に入れない。FP が1つずつ確かめる）。

### 5. 路線価図の記号

- 値は路線価図に**印字されたままの文字**（例 `"250C"`）を `["lands", "routeMark"]` に書く。読み口が分ける（`land.ts` の `parseRouteMark`）:
  - 数は千円単位（250 → 1㎡あたり 250,000円）。1〜999,999（千円）まで。0・小数・桁の多すぎる数は読めない。
  - 記号は借地権割合（国税庁の決まり。A 90%・B 80%・C 70%・D 60%・E 50%・F 40%・G 30%。0231 の `LEASEHOLD` と同じ）。
  - 全角・小文字・前後の空白・桁区切り・「千円」は読む（「２５０ｃ」も 250,000円・C）。
- 1つの記号から、「土地の評価の入れ方」を路線価×面積にする候補・路線価の候補・借地権割合の候補の3つを作る。路線価図を読んだことが路線価地域の印なので、評価の入れ方の候補も作る。路線価の欄は評価の入れ方が路線価×面積のときだけあるので、確かめの画面では評価の入れ方の行を先に承認してもらう（そう理由を出す）。
- 数で書いた路線価（`250000`・`250`）は、千円か円か分からないので読まずに理由を出す。路線価・借地権割合の場所を直接書いた候補も読まない（記号を分けるのは読み口の1か所）。
- **読めなかったとき**（値が null・記号として読めない）は、評価の入れ方の候補のほか、路線価と借地権割合を読めなかった欄にする（推測で埋めない。FP が路線価図を見て「直す」で入れる）。記号の無い路線価は、借地権割合だけ読めなかった欄にする。
- **2つ以上の道路に面する土地**: 0231 の欄は路線価1つだけなので、路線価の高い方（奥行が同じくらいならふつう正面の路線）の記号を1つ書き、ほかの路線は添え書きに書く。側方路線影響加算・二方路線影響加算はアプリが計算しない。FP が要るときは「補正の率」に加算を含めた率を入れる（手引きに書いた）。
- 借地権割合の欄は貸している物件だけにある（0231 の 5。貸家建付地の減額に使う）。持ち家に入れた路線価図の借地権割合の行は「借地権割合は、貸している物件だけに入れます」と出し、入れない。

### 6. 伏せる情報

- 課税明細書: 所有者・納税義務者・共有者の名前と住所、通知書番号・納税義務者番号・宛名番号・物件番号・家屋番号、土地・家屋の所在と地番、税額。AI に読まない・書かないよう手引き・頼み方・道具の説明に書き、読み口も次のとおり落とす（既存の番号を落とす決まり〔`privacy.ts`〕に足す。土地・建物の書類だけ）:
  - 見出しが所在・地番・家屋番号・所有者・納税義務者・宛名・住所・氏名・名称・共有者・通知書番号・物件番号・図番の候補と照合の値は、候補ごと落とす（`PLACE_FIELD_WORDS`。数だけ残す）。
  - 元の場所の文字・添え書き・照合の値の名前の中の地番らしい所（「123番4」「12番地の3」「1丁目2番3号」）は「●●●●」に伏せる（`maskPlace`）。値そのものが地番らしい文字なら、候補ごと落とす。
- 路線価図は公開の資料で、お客さまの情報は含まない。ただし、指した土地の場所からお住まいが分かるので、図の番号（ページの番号）・地名・町名・道路の名前・住所の検索欄の文字は書かない。読み口は、路線価図の答えの**ページの番号を残さない**（候補・物・照合の値の `source.page` を消す）。地番らしい所の伏せ方は課税明細書と同じ。
- 書類そのもの（写真・画面の写し）は、今までどおりアプリに入らない（AI の答えだけを読み口で読む）。

### 7. AI に渡す条件と記録

- **路線価図も、ほかの書類と同じ条件で AI に渡す**: 書類を AI に渡すことを含む外部AIへの提供の同意（0157 の版2〜）がある世帯、事務所のプライバシーポリシーを確かめていてお客さまが断っていない世帯（0226 の `ai_documents_use`）、架空の世帯だけ。貼り付けの入口の判定（`pasteGate`）も AI接続の `propose_inputs` の判定も、書類の種類で分けない。
  - 理由: 路線価図そのものは公開の資料だが、FP は「この世帯の土地はここ」と示して AI に渡すので、AI のサービスには世帯と場所の組み合わせが送られる。お客さまの住まいの場所は個人の情報なので、課税明細書・保険の書類と同じ扱いにする（条件を分けると、FP が書類ごとに判断することになり、取り違えやすい）。
  - 同意の説明文（0157 の版2）の3段落目の例示「保険証券やねんきん定期便などの書類」は変えない（例示で、書類を AI に渡すことの説明として正しい。変えると版を上げて同意を取り直す必要がある。0159 の未確定と同じく、次に説明文を直すときに合わせる）。
- 記録: 読み取りの記録（区画 `documents`）には、読み口を通った候補（場所・地積・価格・記号を分けた値）と、伏せた後の元の場所の文字だけが入る。所在・図の番号は入らない。承認の記録（`decided.to`）は、入れ先 `lands` の後に不動産の ID と欄の名前を足して書く（例 `["lands", <持ち家の ID>, "area"]`。値の状態の行の鍵ではない）。

### 8. FP の確かめと、値の状態の行を書かないこと

- FP が確かめの画面で値ごとに承認するまで、世帯は変わらない（0148 の2 のまま）。土地・建物の欄は時点の無い設定（0231 の 2。`input.inheritanceTax`）なので、承認は現状に入る（プランの差分にはならない）。
- 0231 の不動産ごとの欄は、どれも同じ入れ先（`plan.inheritanceTax` の `["lands"]`）を使う（プランの差分の入れ先がそのまま使えるため。0231 の 2）。そのため、書類の読み取りの欄の探し方（`fieldPlaces` は入れ先で欄を1つにまとめる）と承認の印（値の状態の行は入れ先ごとに1つ）がそのままでは使えない。次のようにした:
  - 欄の定義に任意の `docPlace`（書類の候補の場所と不動産の ID）を足した（`form.ts`）。0231 の不動産ごとの欄（面積・評価の入れ方・路線価・土地の固定資産税評価額・建物の固定資産税評価額・借地権割合）だけが持つ。書類の読み取りは、この欄を入れ先でなく `docPlace` で分けて探す（`resolve.ts`）。
  - `docPlace` の欄は、承認しても**値の状態の行を書かない**（`apply.ts` の `writeFromDocument`）。行を書くと、同じ入れ先の全部の欄（ほかの不動産の欄も）に「書類で確認」の印が付いてしまうため。どの書類から入れたかは、読み取りの記録の承認の記録に残る。
  - 世帯ファイルの形式・入れ先・プランの差分の形は変えない。

### 9. 欄が無いときの理由

0231 の欄は「相続税も試算する」・評価の入れ方・不動産の種類で出る・出ないが決まるので、「この世帯に、この値を入れる欄がありません」の代わりに、何をすれば入れられるかを出す（`land.ts` の `landMissingReason`）:

| とき | 理由の文 |
|---|---|
| 相続税も試算しない世帯 | 相続・贈与の入力項目の「相続税も試算する（土地の評価・小規模宅地等の特例）」にチェックすると入れられます |
| 不動産が無い | 持ち家・住まい以外の不動産がありません。不動産を入れると入れられます |
| 路線価で、評価の入れ方が路線価でない | 「土地の評価の入れ方」を「路線価×面積（路線価地域）」にすると入れられます（この書類の「土地の評価の入れ方」の行を先に承認してください） |
| 土地の固定資産税評価額で、評価の入れ方が倍率・推定でない | 「土地の評価の入れ方」を「固定資産税評価額×倍率（倍率地域）」か「固定資産税評価額から推定（×8/7）」にすると入れられます（入力の「相続税の試算」で選びます） |
| 借地権割合で、貸している物件でない | 借地権割合は、貸している物件だけに入れます（貸家建付地の減額に使います）。自宅などの土地では使いません |
| 建物の価格で、建物の欄の無い不動産 | この不動産には建物の欄がありません（貸していない土地だけの不動産など） |

- 課税明細書の土地の価格は、評価の入れ方を FP が選ぶまで入らない（課税明細書からは路線価地域か倍率地域か分からない。評価の入れ方を書類から決めない）。

### 10. 画面・手引き・AI接続

- 入口の見出しには書類の種類を書かない: 入力のホームの「取り込む」の見出しは「書類の読み取り」、AI の入口（「取り込む」・FP のメニュー）は「AI で書類を読み取る」。見出しのすぐ下に、今読める書類を1行で添える（「読める書類: 保険の設計書・証券、固定資産税の課税明細書、路線価図」。書類の種類の一覧 `DOC_TYPES` の短い名前 `short` から作る `readableDocsLine`。種類を足せば一緒に増える）。説明の文に、土地の所在を読まないことを足した（下の追記 2026-11-20）。
- 貼り付けの画面の「書類の種類」は、読める書類が3つになったので選ぶ欄に戻した（0159 の 6 で1つのときは出さなかった）。「伏せるもの」の文に、課税明細書の納税義務者の番号と所在（地番）、路線価図の住所の検索欄と図の番号を足した。
- 相続・贈与の入力項目の区画「相続税の試算」の説明（相続税も試算する世帯）に、課税明細書と路線価図を「書類の読み取り」から入れられることを足した。
- 読み方の手引き: SDK フォルダに `sdk/skills/read-documents/guides/property-tax-statement.md`・`route-price-map.md` を足し、説明書 `sdk/docs/document-reading.md`・スキル `SKILL.md`・`sdk/README.md` を3つの書類にした。貼り付けで写す手引き（`guides.ts`）は、土地・建物の書類では説明書とその書類の手引きだけ（読む欄は手引きの表に全部あるので、保険の欄の一覧 `fields.md` は写さない）。
- AI接続: 道具 `propose_inputs` の書類の種類に2つを足し（`server.rs` の `DOC_TYPES`）、道具・物・値の候補の説明と全体の説明（`INSTRUCTIONS`）に、土地・建物の欄・書類の土地・書かないものを足した。使い方の例（プロンプト）に `read_property_tax_statement`（課税明細書を読み取る）と `read_route_price_map`（路線価図を読み取る）を足した。AI接続には SDK の手引きを同梱していないので、読み方の決まり（まとまり・地積・価格と課税標準額・家屋の倍率 1.0・持分・読めない欄・書かないもの、記号の書き方・2つの路線・倍率地域）は頼み方の文に書いた。
- 手引き（`docs/app-guide/03-import.md`）に「課税明細書と路線価図を読み取る」の節（`import.documentLand`）を足した。`docs/ai-connector.md` の道具の一覧・使い方の例の表・書類の候補の説明に足した。

## 理由

- **ものさしの「読み方が難しい」に当たる**: 価格と課税標準額の取り違えは、相続税の評価を数分の1にする（住宅用地の特例の 1/6）。路線価図の千円単位・記号の意味は、慣れない FP が間違えやすい。数は少なくても、取り違えの大きさで割に合う。
- **記号の換算を読み口で行う**: AI に円や割合に直させると、千円単位の掛け忘れ・記号の対応の取り違えが AI ごとにばらつく。印字のまま受け取り、決まった表で直せば、テストで確かめられる。
- **書類の土地を今ある不動産に入れるだけにする**: 不動産（持ち家・収益不動産）は時価・ローン・家賃など多くの入力の元で、課税明細書から作ると中身の無い物ができる。相続税の試算の欄は不動産ごとの設定なので、今ある不動産に入れる形が合う。
- **AI が筆を足す**: `lands[]` は不動産1つに1行（0231 の骨格）で、筆ごとの行を持たない。足す前の値を照合の値と添え書きに残せば、FP が書類と比較できる。
- **値の状態の行を書かない**: 入れ先を不動産ごとに分ける（0231 の入れ先を変える）と、プランの差分・形式の版に響く。書類の読み取りの記録に出どころが残るので、欄の印が無くても FP は後でたどれる。
- **路線価図も同意の条件を同じにする**: 7 の理由。

## 代案（採らなかったもの）

- 0231 の入れ先を不動産ごとに分ける（`["lands", <ID>, "area"]`）: 欄ごとに値の状態の行を持てるが、プランの差分（0061 の向き先）と読み替え表の入れ先の作りを変えることになり、0231 の骨格に触れる。
- 筆ごとの候補をアプリが足す: 足すかどうか（同じ敷地か）はアプリに分からない（所在を読まないため）。足す判断は書類を見ている AI と FP に任せる。
- 課税明細書の持分を名義の割合に入れる: 宛名の人がどの構成員かを書類から決めないので、FP が持ち家の欄で確かめる方が確か。
- 路線価図は公開の資料なので、同意の無い世帯でも渡せるようにする: 7 の理由（場所と世帯の組み合わせが送られる）。
- 課税明細書の土地の価格を入れたら、評価の入れ方を自動で「固定資産税評価額から推定」にする: 路線価地域なら路線価の方が確かで、書類から決められない。
