# 0097. 世帯を開き直したときの元に戻すの履歴（続ける・続けないの決まり）

- 状態: 採用（2026-10-31）
- 固定の強さ: 内部（画面の側の決まりと文言。世帯ファイルの形式・本体の命令は変えない）
- 前提にする記録: 0011（世帯ファイル）、0033（見本の棚）、0096（保存できていない変更を黙って捨てない）

## 背景

- 元に戻す・やり直す（↶↷）の履歴は世帯ごとに持ち、アプリを開いている間だけ残す。ほかの世帯へ切り替えて戻ってきたとき、中身が前と同じなら続きから使う、違えば空から、と決めていた。
- 「同じか」は、画面が最後に保存した本文と、開き直して読んだ本文を**文字列のまま**比べていた。本体は保存した本文を読み直して書き戻すので、開き直すと欄の並びが名前の順になる。画面の側の読み方（`fromBody`）も、世帯の欄を決まった順に並べ直す。中身が同じでも文字列は違い、履歴が空になっていた（見本から作ったばかりの世帯・入力を足した後の世帯で、ほぼ毎回起きる）。
- 見本から「この見本をもとに顧客を作る」で作った世帯は、履歴を見本の名前のまま持ち続けていたので、作った後の操作も、作った世帯を開き直すと見えなかった。
- 履歴を空にしたときに、そのことが画面に出なかった。↶ が押せなくなるだけで、前の操作に戻れない理由が分からなかった。

## 決定

### 1. 続けるのは、中身が同じとき（並びは見ない）

- 開き直したときは、この画面でその世帯を最後に持っていた本文（保存した・読んだ本文）と、今読んだ本文を**中身で**比べる（`app/src/workspace/undo/reopen.ts`）。両方に読むときの整え（`fromBody`）を当ててから、欄の並びを見ずに比べる。値の無い欄は無いのと同じ。数は読み直したときの最後の桁の違いを許す。
- 同じなら続きから、違えば空から。

### 2. 続けないのが正しいとき

- ほかの PC・ほかの人が直した・分岐を選んで相手の内容にした・同期の写しを今の内容にした: 中身が違うので空から。
- 世帯を離れるときに、画面の中身が最後に保存した本文と違うとき（保存できなかった変更を捨てた〔0096〕・ほかの人が開いていて保存を止めていた・自分で作った見本を見るだけで開いていた）: 履歴は世帯ファイルに無い中身を指しているので、離れるときに覚えていた本文を忘れ、開き直したら空から。
- アプリの見本・空の世帯: 保存しないので、開くたびに最初の中身から。履歴も空から。
- アプリを閉じた: 履歴はアプリを開いている間だけ。

### 3. 空にしたら知らせる

- 開き直して、戻せる・やり直せる履歴を捨てたときだけ、知らせを出す:
  - 保存した世帯: 「前にこの世帯を開いていたときと中身が違うため、元に戻す（↶）の履歴はここから始めます」
  - 見本: 「見本は開くたびに最初の中身から始まります。元に戻す（↶）の履歴も、ここからです」
- 分岐を選んだときなどは、その操作の知らせが後から出る（そちらを見せる）。

### 4. 見本から作った世帯は、履歴をその世帯のものにする

- 見本（や保存していない世帯）を新しい世帯として保存したときは、今の履歴をその世帯の履歴として持ち直す（中身は同じなので、作る前の操作にも戻れる）。見本の名前には残さない。

## 他の案

- 文字列で比べるまま、本体が並びを変えないようにする: 本体は読み直した値に `meta` を書き足して返す。並びを保つと本体の JSON の扱いを変えることになり、世帯ファイルの互換の確かめも要る。画面の側で中身を比べれば足りる。
- 履歴を世帯ファイルに保存する: 履歴は画面の操作の記録で、世帯の中身ではない（持たない情報を増やさない）。
