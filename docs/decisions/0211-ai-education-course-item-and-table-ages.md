# 0211. 子の進路の型を「動かす項目」にし、AI接続口の表を本人の年齢で選べるようにする（収入の内訳・NISA の行・年を列にする向き）

- 状態: 採用（一部未確定）（2026-11-13）
- 固定の強さ: 合成の対策の名前 `educationCourse`（プランの差分の向き先。0036 の3）は骨格（名前は使い回さない）。`list_plan_items` の `kind: "choice"`・系列の名前（`incomeSalary`〜`incomeOther`・`nisaContribution`・`nisaBalance`）・`table` の `from_age`・`to_age`・`orientation`・`incomeBreakdown` は試験版（0015 と同じ。予告して変えることがある。どれも足すだけの任意の欄で、既定の答えは変えない）。作り（入力の欄の定義をそのまま動かす項目に使う・表の向きは縦と横を入れ替えるだけ）は内部
- 前提にする記録: 0015（AI接続口）、0036（プランの差分）、0062（教育の推定）、0195（動かす項目）、0201（場所つきの動かす項目）、0203（金利の見込みを動かす項目にした前例）、0204（感度・境目探しの場所）、0207（系列の名前・3パターンのプロンプト）、0209（表の道具）

## 背景

- FP は「子の進路を今のまま・すべて公立・中学から私立の3通りにして比較し、グラフにして」とよく頼む。入力の子ども・教育には「進路の型」の欄（段ごとの公立・私立を一度に決める）があるが、動かす項目（0195）には無かった。そのため AI は教育の目標の段の `sector` を `changes`（JSON Pointer）で直に書き換えていた。数字は合うが、グラフの注の「通りの違い」（当てたプランの変更の文。0203）に進路の違いが出ず、型の後始末（前の学校の推定の額を外す）も通らなかった。
- 0209 の表の道具 `table` は年で選ぶだけで、「60〜90歳を5年ごとに」は AI が年に直して頼んでいた。行は収入の合計だけで、給与・年金・退職金の内訳と NISA の行が無かった。年を列にする向き（画面のキャッシュフロー表と同じ向き）も無かった（0209 の未確定）。
- 表の注には、通りの違い（どの通りで何を変えたか）が無かった。表だけがファイルになると、列の名前（通りの名前）しか手がかりが無い。

## 決定

### 1. 動かす項目「進路の型」（子ごと）

- 入力の「進路の型」の欄が出る子（教育の目標があり、教育の段が全部は過ぎていない子）のうち、型が決める段（幼稚園〜大学）でまだ終わっていない段がある子ごとに、結果のタブの動かす項目 `edu:<教育の目標の ID>:course` を足す（`plans/items.ts` の `courseItems`。まとまりは「よく使う」）。入力項目ID は欄と同じ `goal.education`、対象は教育の目標。名前は「第1子の進路の型」（呼び名を入れない。グラフ・表の注に出るため）。
- 値は型の名前（`allPublic`＝すべて公立（国公立大）・`univPrivate`＝大学だけ私立・`highPrivate`＝高校から私立・`juniorPrivate`＝中学から私立・`allPrivate`＝すべて私立。入力の欄の `COURSE_PRESETS` と同じ）。今の段が型に当たらなければ `null`（段階ごとに選んだ進路。そのまま）。
- 当てるのは入力の欄そのもの: 欄の定義を `courseField`（`input/stages/education.ts`）に切り出し、入力の画面も動かす項目もこれを読み書きする（型の当て方は `setCoursePreset`。今と同じ型なら変えない・公立・私立が変わった段は前の推定の額をそのまま入れた年額・入学金を外す・値の状態の行の後始末も欄と同じ）。欄で同じ型を選んだときと、教育の段・計算の数字が同じ（テストで確かめる）。
- 動かす項目の値の形に、決まった選択肢から1つ選ぶ `choice`（`options` に値と言葉）を足した。画面は選択の欄（`ItemControls.tsx` の `ChoiceRow`）。型でない今の進路は、その値の行として残す。プランの名前の例の文は「第1子の進路を中学から私立に」。
- AI の値の形（`plans/candidates.ts` の `coerce`）: 型の名前・型の言葉（「中学から私立」）・`{preset: 名前}`。知らない型は取り込まない。
- プランの持ち方: 合成の対策 `educationCourse`（向き先 `{lever, object}`。物は教育の目標）の `set` で持つ（`store/readings.ts` の後から足した合成の対策。0203 の `loanRateOutlook` と同じ）。当て先の `set` にしないのは、1つの値で複数の段の公立・私立と推定の額をまとめて変えるため。前の版のアプリは、この名前を知らないので当てない（要確認の差分として残す）。形式の版は変えない。
- 事務所の既定値の「対策に最初から出す項目」の種類に `edu:course`（子の進路の型）を足した（既定では出さない）。
- 型と段の並び: もう過ぎた段がある子（高校生など）では、型が違っても段の並びが同じになることがある（高校生に「中学から私立」を当てると「高校から私立」と同じ段になり、読み直すと「高校から私立」）。入力の欄と同じ読み方のまま（計算は同じ）。

### 2. AI接続口で使える所

- `list_plan_items` は `kind: "choice"`・`options`（型の名前と言葉）を返す。同じ対象・同じ入力項目ID の項目（教育の段階ごとの欄）があるので、0201 の場所 `lever: "educationCourse"` を添えて選ぶ。見本の世帯では `proposable` が true（プランの候補 `propose_scenario` にもそのまま出せる）。
- `calculate`・`explain_value`・`compare`・`chart`・`table` の `plan_changes`、`sweep` の `vary`（`values` に型の名前を並べる。範囲 `from`・`to` では振れない）で、ほかの動かす項目と同じく使える。`sweep` の答えの `vary` に `options` を添え、値の文は型の言葉にした（`sweep.rs` の `value_text`）。境目探し（`find_threshold`）は、値に大小の無い項目なので使わない（範囲を書くと `values` を使うよう理由を返す。今までの `toggle` などと同じ）。
- グラフ（`chart`）と表（`table`）の注の「通りの違い」に、当てた変更の名前と後の値の文が出る（「中学から私立: 第1子の進路の型 中学から私立・第2子の進路の型 中学から私立」）。表にも、グラフと同じ書き方の「通りの違い」の注を足した（どの通りにもプランの変更が無ければ書かない。今と同じ値の変更は書かない。`chart.rs` の `plan_of` を共有）。
- INSTRUCTIONS・`list_plan_items`・`chart`・`table` の説明に、進路の比較は `changes` で段を書き換えず「進路の型」を使うことを書いた。使い方の例 `chart_three_patterns` の子の進路の例を「今のまま・すべて公立・中学から私立」にし、「進路の型」を子の数だけ `plan_changes` に入れる書き方にした。

### 3. 表（`table`）を本人の年齢で選ぶ

- `from_age`・`to_age`（0〜120）: 本人がその年齢になる年から・までの年を選ぶ。年齢は画面の表の年齢の行と同じ（その年に迎える年齢。本人が世帯にいない年は入らない）。通りに別の世帯があれば、通りごとにその世帯の本人の年齢で選ぶ。何年おき（`every_years`）は今までどおり、選んだ年の最初の年から数える（60〜90歳を5年ごとなら 60・65…90歳の年）。
- 年（`from_year`・`to_year`）と年齢を両方書いたときは、どちらに合わせるか決まらないので、表を作らずに理由を返す。`from` が `to` より大きいとき・選んだ範囲に表の年が無いときも理由を返す（後者は表の年の範囲を添える）。

### 4. 収入の内訳と NISA の行（系列の名前）

- 0207 の支出の内訳と同じ名付けで、収入の内訳を足す: `incomeSalary`（給与）・`incomeBusiness`（事業所得）・`incomePension`（公的年金）・`incomeCorporatePension`（企業年金・個人年金）・`incomeRetirement`（退職金）・`incomeBenefit`（給付・手当）・`incomeRealEstate`（家賃収入・不動産の売却）・`incomeOther`（その他の収入）。画面のキャッシュフロー表の収入の行（`present.ts` の `rowDefs`）と同じ当て方で、人ごとの行（給与・事業所得・年金）は世帯の合計、家賃収入と不動産の売却は1つ（支出の `expenseRealEstate` と同じ考え）。全部足すとその年の `income`。`incomePension` は収入の内訳としての名前で、数は `pension` と同じ。
- NISA: `nisaContribution`（NISAへの積立。年額。画面の表の「NISAへの積立」の行＝`cf.transfer.nisa` の下）・`nisaBalance`（NISA の残高。年末。資産運用のタブの「NISA」のまとまり〔NISA・こどもNISA・ジュニアNISA・旧NISA〕の器の残高の合計）。エンジンは前から表に出していた（新しい計算はしない）。
- 名前は `compare` の `series`・`calculate` の `fields`・`chart` の `series`・`table` の `rows` で同じ（0207 の決まり）。どれも選んだときだけ返す。数えるのは接続口に同梱した画面の関数（`connector/summary.ts` の `flowYearsOf`）。`table` の `incomeBreakdown` は、収入の内訳のうちどれかの通りに値のある物をまとめて選ぶ（`expenseBreakdown` と同じ）。グラフの題・単位の注の言葉は `connector/chart.ts` の `SERIES`。
- 表の注に、選んだ行の意味（収入の内訳の分け方・NISA の積立と残高の中身）を足した。

### 5. 年を列にする向き（`orientation`）

- `yearsDown`（年を行に。既定。今までどおり）と `yearsAcross`（年を列に、数字と年齢を行に。画面のキャッシュフロー表と同じ向き）。`yearsAcross` は、作った表の縦と横を入れ替えるだけ（`table.ts` の `transpose`）で、マスの文字・並べ方（`layout`）・注は同じ。通りごとに縦に積んだ CSV（`byVariant`）を入れ替えると、見出しの行が「通り」、次の行が「年」になる。
- BOM の既定（付けない）・注を必ず入れることは変えない。

## 見本の世帯での数字

`salariedCoupleTwoKids`（計算基準月 2026年10月。第1子は今「大学だけ私立」、第2子は「高校から私立」）で、2人の子の進路の型を今のまま・すべて公立・中学から私立にした3通り:

| 通り | 教育費の表の期間の合計 | 95歳時点の金融資産 | 資産が尽きる年 |
|---|---|---|---|
| 今のまま | 2,384万円 | ▲1,997万円 | 2058年（77歳） |
| すべて公立 | 1,816万円 | ▲1,302万円 | 2064年（83歳） |
| 中学から私立 | 3,007万円 | ▲2,736万円 | 2053年（72歳） |

0207 に書いた「すべて公立」の 1,836万円は、`changes` で大学を公立（`public`）にした数。進路の型の「すべて公立」は大学を国公立大（`national`）にする（入力の欄と同じ）ので 1,816万円。

同じ世帯の60〜90歳を5年ごとにした表（基本だけ）は 2041〜2071年の7行。60歳の2041年は収入合計 2,380万円（給与 580万円・退職金 1,800万円）、NISA の残高 681万円。どの年も収入の内訳の合計＝収入合計（接続口のテスト `table_by_age_with_income_breakdown`）。

## 理由

- **入力の欄の定義をそのまま使う**: 動かす項目に別の型の当て方を書くと、欄と項目で後始末（推定の額を外す・値の状態の行）がずれる。0203 で金利の見込みの欄の処理を関数に切り出したのと同じ考えで、欄の定義そのものを共有した。
- **合成の対策で持つ**: 1つの値で複数の段を変えるので、当て先の `set`（1つの欄の値）では持てない（0036 の3・0203 と同じ）。
- **子ごとの項目**: 型は子ごとの欄。2人の子を一度に変える項目を作ると、片方の子だけを変える比較ができない。
- **収入の内訳を世帯の合計にする**: 系列は通りの比較に使うので、人の数で名前が変わらないようにした（人ごとの数字は `calculate` の表の行）。
- **年を列にする向きは入れ替えだけ**: 数え方・注を2つ持たない。画面のキャッシュフロー表と同じ見た目（区切り・行の見出しの階層）までは作らない。

## 代案（採らなかったもの）

- **`changes` のままにして、注に段の `sector` の変更を言葉にして出す**: 型に当たらない書き換えも言葉にすることになり、画面のプランにも出せない。
- **進路の型を接続口だけの項目にする**: 画面の「AIからの候補」で取り込めず、プランに残せない（0195 の「画面と同じ項目」の決まりに合わない）。
- **年齢で選ぶ年を `compare`・`calculate` にも足す**: 今回は表だけ（頼まれることが多いのは表）。系列は `every_years` と年で足りている。
- **収入の内訳を人ごとにする（`incomeSalarySelf` など）**: 名前が増え、家族の形で行が変わる。
- **年を列にする向きで、画面の表と同じ行の階層・区切りまで作る**: CSV・Markdown では表せない。
