# 0040. 段階と例外の年、働き方の期間ごとの伸び（計算エンジンの側）

- 状態: 採用（一部未確定）（2026-10-26）
- 固定の強さ: β公開から変えない（骨格）。エンジンの入力の形（段 `stages`・例外の年 `exceptions`・器の `returnStages`・`returnExceptions`・資産配分の `allocation.stages`・段の欄 `id`・`at`・`amount`・`ratio`・`rampYears`・`expectedReturn`・`assetMix`・`mix`、例外の年の欄 `id`・`year`・`amount`・`expectedReturn`、給与の `growth.rate`・事業所得の `growth.rate`）、入力項目ID（`periodicExpense.stages`・`periodicExpense.exceptions`・`account.returnStages`・`account.returnExceptions`・`employment.business.growth`）、段の当て方（段の時点の月から・年ごとの物はその時点の属する年から・同じ時点は後の段が勝つ）、元の欄の伸び方をそのまま重ねること、少しずつ移す形（ここから n 年かけて次の段へ、1年ごとに同じ幅）、例外の年は段の額の代わり、伸びの率は賃金上昇率の代わり、段階も例外も無ければ今と同じ結果は骨格。丸めの規約 `conv.stage.value` の向き、画面の見せ方は後から変えてよい（変えたら追記に書く）

## 背景

- 金額が時期で変わる入力が多い。家賃の値上げ・下げ、修繕費の段階、固定資産税の軽減の終わり、不動産の家賃の下落、周期的な支出の額の変化、「55歳から株を減らす」資産配分の変化などで、これまでは1つの額と1つの変化率しか持てず、行を時期で分けて重ねる工夫で代えていた（生活費だけは段階 `livingExpense.stages` を持つ。0008 の追記）。
- 給与の昇給の仕方 `salary.growth` は昇給カーブの値ID（`curve`）だけで、働き方の期間ごとに自分の率を置けなかった。事業所得には伸びの欄が無く、いつも前提の賃金上昇率で伸びた。
- 世帯ファイルの形式 0.17（0035）は、これらを「足すだけの形」とし、計算を入れる回に MINOR で足すと決めた（0035 の1・2・7）。段の形は生活費の段階と同じ考え（ID・時点・額か今の額に対する割合・次の段まで何年かけて変えるか）、例外の年は ID・年・額。
- この記録は、まず**計算エンジンの側**（エンジンの入力のスキーマ・部品・テスト）を決める。世帯ファイルに足す形（形式の MINOR を1つ上げる）と入力画面の欄は、次の回に入れる（5）。
- 前提にする記録: 0002（金額・率・丸め）、0003（時点の型と年齢の規則）、0006（部品の改訂）、0008（世帯のデータモデル）、0026（資産運用）、0028（住まい以外の不動産）、0035・0036（世帯ファイルの形と差分の当て先）。

## 決定

### 1. 段と例外の年の形（エンジンの入力。任意の欄）

- **額の段**（`$defs/amountStage`）: `{ "id", "at", "amount" | "ratio", "rampYears"? }`。
  - `id` は要素の ID（UUID 第4版。0035 の5。差分・値の状態の欄が1件ずつ指す）。必須。
  - `at` は時点の型（0003 の6）。年月・人の年齢・出来事からのずらしのどれでも書ける（入力画面の時点の部品がそのまま書く形）。
  - `amount`（値の箱。元の額の欄と同じ基準＝同じ単位・同じ価格の時点）と `ratio`（元の額に対する割合）は、どちらか一方だけ。
  - `rampYears`（1〜50）: ここから何年かけて次の段の値へ移すか（2）。
- **例外の年**（`$defs/amountException`）: `{ "id", "year", "amount" }`。その年だけ、段の額の代わりに `amount`（元の額の欄と同じ基準）を使う。0円はその年に払わない・受け取らない。
- **器の利回りの段**（`$defs/returnStage`）: `{ "id", "at", "expectedReturn" | "assetMix", "rampYears"? }`。その時点の属する年から、器の利回りか資産の配分のどちらか一方に置き換える（もう片方は使わない）。**器の利回りの例外の年**は `{ "id", "year", "expectedReturn" }`。
- **資産配分の入れ方の段**（`assumptions.investment.allocation.stages[]`）: `{ "id", "at", "mix", "rampYears"? }`。
- 持たせる物と欄（項目を増やさないため、要望のあった物だけ）:

| 物 | 段 | 例外の年 | 段の単位 | 入力項目ID |
|---|---|---|---|---|
| 周期的な支出 | `periodicExpenses[].stages` | `periodicExpenses[].exceptions` | 1回の額（計算基準年の価格）。支払いの月で段を決める | `periodicExpense.stages`・`periodicExpense.exceptions`（新） |
| 家賃 | `residences[].rent.stages` | `residences[].rent.exceptions` | 月額。月ごと | `residence.rent` の中 |
| 修繕費・管理費 | `residences[].maintenance.stages` | `.exceptions` | 月額。月ごと | `residence.maintenance` の中 |
| 固定資産税・都市計画税 | `residences[].propertyTax.stages` | `.exceptions` | 年額。年ごと | `residence.propertyTax` の中 |
| 住まい以外の不動産の家賃 | `accounts[].property.rental.stages` | `.exceptions` | 月額（空室を見込む前）。月ごと | `account.property` の中 |
| 住まい以外の不動産の経費の年額 | `accounts[].property.expenses.stages` | `.exceptions` | 年額。年ごと | `account.property` の中 |
| 器の利回り・資産の配分 | `accounts[].returnStages` | `accounts[].returnExceptions` | 年率・配分。年ごと | `account.returnStages`・`account.returnExceptions`（新） |
| 資産配分の入れ方の共通の配分 | `assumptions.investment.allocation.stages` | — | 配分。年ごと | `assumptions.investment` の中 |

- 入力項目ID を持つ欄の中の段（家賃・修繕費・固定資産税・不動産・前提の投資）は、新しい入力項目ID を作らない。差分の当て先は、その欄の入力項目ID と欄の中の場所で書く（0036 の2。例: 家賃の段の額は `{"object": "<住まい>"}`・`residence.rent`・`["stages", "<段>", "amount"]`）。周期的な支出と器は欄ごとに入力項目ID を持つので、段と例外の年の並びに入力項目ID を足した。

### 2. 段の当て方

- 段の時点を月に解き、月の順に並べる。同じ月の段は、後に書いた段が勝つ。段より前の月は元の額。
- **月ごとの物**（家賃・修繕費・不動産の家賃・周期的な支出の支払い）は、その月の段を使う（段の時点の月から変わる）。**年ごとの物**（固定資産税・不動産の経費の年額・器の利回りと資産の配分）は、その年の12月の段を使う（段の時点の属する年から変わる）。
- **割合の段**は、元の額×割合（各部品の丸めの規約。周期的な支出は `conv.expense.share`、住まいは `conv.housing.growth`、不動産は `conv.realEstate.rent`）。
- **元の欄の伸び方をそのまま重ねる**: 段・例外の額は元の額の欄と同じ基準として、元の欄の伸び方を同じ回数だけ当てる。周期的な支出は計算基準年からの物価上昇率（または固定の率）、家賃は住み始めからの更新の回数、修繕費・固定資産税は計算基準年からの年数、不動産の家賃は貸し始めの年（計算基準年より前なら計算基準年）からの年数、不動産の経費は計算基準年からの年数。割合の段は「その時点に伸びた額の割合」とほぼ同じになる。
- **少しずつ移す**（`rampYears` = n）: 段 k の月から1年たつごとに、段 k の値から次の段の値へ同じ幅で移す。j 年たった月の額は「段 k ＋（次の段 − 段 k）× j ÷ n」（差に掛けた額を `conv.stage.value` で円未満切り捨て。0に向けて）。n 年たつと次の段の値に届き、次の段の月まではその値のまま。次の段の月が先に来たら、その月から次の段の値（途中で打ち切る）。年ごとの物は年の差で数える。最後の段の `rampYears` は使わない。
  - 率の段（器の利回り）は、前後の段のその年の利回りを同じ式で按分する（率は 0002 の正確な10進）。資産の配分どうしの段は、利回りが配分に比例するので、配分を按分したのと同じになる。
- **例外の年**は、その年だけ段の額の代わりに例外の額を使う（同じ年は後に書いたものが勝つ）。周期的な支出では、その年の支払いの額だけを変え、支払いの無い年に支払いを足さない。家賃の更新料は、更新の前の月の段の額（例外の年は当てない）× 月数。
- 元の額が0円でも、段か例外の年に0円より大きい額があれば計算する。
- **段階も例外の年も無ければ、今と同じ計算の道を通る**（空の並びも同じ）。見本の世帯の結果は変わらない。

### 3. 器の利回りと資産の配分

- 器の利回り（`accountReturnRate`）は、その年の例外の年があればその利回り、無ければその年の12月の段（器の利回りか資産の配分。段より前の年は器の欄の `expectedReturn`・`assetMix`）で決める。運用の費用（`fee`）と利回りの書き換え（`returnShifts`）は、その後にいつも当てる。
- 資産配分の入れ方でリバランスしないとき（0026）の配分のずれは、段の始まりの年（計算基準年より前なら計算基準年）から数え直す（段が変わる年に配分を組み直したとみなす）。
- 資産クラスを書いた時価の下落（0026）は、その年の段の配分で割合を出す（器の利回りの段の年は配分が無いものとして扱う）。
- 資産配分の入れ方（`method: allocation`）では、計算の前に、運用する器の利回りの段階と例外の年を外し、共通の配分の段（`allocation.stages`）を器の資産の配分の段に写す（0026 の「FP が入れた器の利回りは使わない」と同じ）。
- 読む部品: `plan.cashflow`・`account.ideco`（`account.returnStages`・`account.returnExceptions` を reads に足した）。小規模企業共済（`account.mutualAid`）は資産の配分だけを読み、段を持たない。

### 4. 働き方の期間ごとの伸び（年率）

- 給与の `employment.salary.growth` を、**昇給カーブの値ID か年率のどちらか一方**を持つ形に広げた: `{"curve": "<値ID>"}`（今までどおり。賃金上昇率に年齢の係数の比を掛ける）か `{"rate": "0.02"}`（この期間の伸び。賃金上昇率の代わりに暦年ごとに当てる。マイナスも書ける）。両方は書けない。今の形はそのまま読める（型を広げただけ）。
- 事業所得に `employment.business.growth`（`{"rate": "…"}`）を足した。書いたときは賃金上昇率の代わりにその率で伸ばす。
- 空欄は前提の賃金上昇率（今と同じ）。伸ばし方は今と同じ（期間の最初の年〔計算基準年より前なら計算基準年〕の額から、翌年から1年ごとに `conv.salary.growth`）。
- ストレステストの「賃金も下げる」（前提の賃金上昇率を変える）は、率を書いた期間には当たらない（自分の率が前提に代わるため）。収入の減少（`incomeShocks`）は今までどおり当たる。

### 5. 世帯ファイルと入力画面（次の回）

- この回は、エンジンの入力に任意の欄を足しただけで、世帯ファイルの形式の版と入力画面は変えない（形式 0.17 の段と並びの要素の ID の直しを先に取り込むため）。
- 次の回に入れるもの:
  - 世帯ファイルの形式の MINOR を1つ上げる（0035 の1。足すだけの形なので変換の段は版だけを書き換える）。足す欄は1の表のとおり（エンジンの入力と同じ名前）。0035 の追記に欄の名前を書く。
  - 段・例外の年・器の利回りの段・資産配分の段の要素の ID を、並びの要素の ID の一覧（0035 の5）に足す（新しい要素は乱数。変換で振る古い要素は無い）。
  - 入力画面の欄: 段階の表（時点の部品・額か割合・「ここから○年かけて次の段へ」）、例外の年の表（年・額）、給与・事業所得の「この期間の伸び（年率）」1欄（空欄は前提の賃金上昇率）、口座の利回りの段階と例外の年、資産配分の段階。
  - 差分の当て先（0036 の2）と、画面の側の型（`app/src/engine/types.ts`）。
- AI接続口の縮約版（0015 の6）には、この回で足した入力項目ID（計算に要る数の項目）を入れ、版を `reduced@9` にした。

## 理由

- 段の額を「元の額の欄と同じ基準」とし、元の欄の伸び方を重ねるのは、生活費の段階（計算基準年の価格の月額を物価上昇率で伸ばす）と同じ考えにそろえ、物ごとに「この段の額はいつの価格か」を変えないため。割合の段が、その時点の伸びた額の割合とほぼ同じになる。
- 年ごとの物を「その時点の属する年から」にするのは、年額・年利は年の途中で分けて持たないため（0003 の3）。12月の段を見れば、段の時点の属する年から当たり、移す年数も年の差になる。
- 「ここから n 年かけて次の段へ」を段の欄にしたのは、0035 の7（次の段まで何年かけて変えるか）に合わせ、毎年少しずつ変える形を年の数だけ行を置かずに書けるようにするため。次の段の時点を正にし、届くのが早ければその値のまま、遅ければ打ち切るので、段の時点が後から動いても（出来事を指す時点）表が壊れない。
- 例外の年を段の額の代わりにし伸び方を重ねるのは、元の額の欄と同じ基準で書けるようにするため（0円はどの基準でも0円）。
- 給与の伸びを値ID か率の一方にしたのは、昇給カーブ（年齢の係数）は賃金上昇率に掛ける形で、自分の率と同時に書くと何に掛けるかが分かりにくいため。
- 段階も例外も無いときに元の計算の道を通すのは、見本の世帯と既存の世帯の結果を1円も変えないため。

## 追記
- 2026-10-26（世帯ファイルと入力画面。5 の次の回）: 世帯ファイルの形式を `0.18` に上げ（足すだけ。0011・0035 の追記）、カードの中の欄を入れた。
  - **段階の表**（住まい・ローンの家賃・修繕費・固定資産税、ライフイベントの n 年ごとの支出〔1回だけの支出には出さない〕、貯蓄・運用の不動産の家賃と経費の年額。どれも詳細）: 段ごとに「いつから」（時点の部品。0038。年ごとの物は「いつから（その年から）」）・入れ方（額で／今の額に対する割合で）・額か割合・「ここから次の段まで何年かけて移すか」（次の段がある段だけ）・この段を外す。例外の年は 年・その年の額・外す。足すボタン「＋ ○○の段階」「＋ ○○の例外の年」。簡易では、住まいと n 年ごとの支出のまとまりの説明に「この後 n段・例外の年 n件」の札を出す。
  - **利回りの段階・例外の年**（貯蓄・運用の詳細の区画）: 口座ごとに、段（いつから・入れ方〔利回りで／資産の配分で〕・利回りか資産の配分の行・何年かけて移すか）と例外の年（年・その年の利回り）。資産配分の入れ方では、運用する口座の代わりに共通の「資産配分の段階」（いつから・割合の行・何年かけて移すか）を出す（運用しない口座は口座ごと）。合計の入れ方では、まとめた金融資産の器だけ。
  - **この期間の伸び（年率）**（働き方と収入の、給与と事業所得の働き方の期間。詳細）: 空欄は前提条件の賃金上昇率（欄の横にその率）。給与で昇給カーブを持つ期間は空欄の意味を「昇給カーブと前提条件の賃金上昇率」と見せ、率を入れると昇給カーブの代わりになる。
  - **値の状態**（0041）: 足した段の額は「元の額と同じ」の推定（出し方 `standard`）、足した例外の年は「その年だけ0円」の推定で入れ、確定は明示の操作だけ。欄はどれも当て先（0036 の2）を持つ（向き先は物、前提の資産配分は `{"plan": "assumptions"}`）。プランの選択・印・戻す・違いの一覧はこの回では作っていない（入力画面でプランを直す回）。
