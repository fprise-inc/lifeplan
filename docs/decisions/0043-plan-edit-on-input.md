# 0043. 入力画面でプランを直す（編集の対象・作業中の世帯の違いを差分にする・印と戻す・違いの一覧）

- 状態: 採用（一部未確定）（2026-10-26）
- 固定の強さ: 骨格は 0036 の8 のとおり（画面の部品は現状の編集とプランの編集で同じ・違いは書く先だけ・取り込みは現状へ・結果のタブと同じ差分）。ここで決めるのは画面の側の作り方で、内部（世帯ファイルの形は変えない）。編集の対象の選び方・印の色と文言・違いの一覧の並びは後から変えてよい

## 背景

- 0036 で差分の型（値を変える `set`・物を足す `add`・物を外す `remove`、当て先、置き換えの組、連鎖）と当て方を作り、0041 で値の状態の操作をプランの差分にする関数（`planStateOp`・`setPlanValue`）を作った。入力画面でプランを選んで直す画面はまだ無かった。
- 入力の欄は、欄ごとに世帯を読む `get` と新しい世帯を返す `set` を持つ（`input/form.ts`）。欄・まとまり・カードの数は多く、欄ごとに「この欄を直したらこの差分」と書くと、欄を足すたびに差分の書き方も足すことになる。並べて別の回が欄を足している（段階と伸びの欄・世帯の外の家族の欄）。

## 決定

### 1. 作業中の世帯を部品に渡し、前後の違いを差分にする

- プランを選んでいるとき、カードとパネルには、そのプランの中身（現状に土台から順に差分を当てた作業中の世帯。0036 の6）を渡す（`plans/planEdit.ts` の `planView`）。部品（欄・まとまり・区画・カード）は変えない。
- 部品が返した新しい作業中の世帯と、直す前の作業中の世帯を比べ、違いをそのプランの差分にする（`recordPlanEdit`）。比べ方:
  - 物の集まりの1件（構成員を含む）を ID で比べる。後にだけある物は `add`（物の集まりへ）、前にだけある物は `remove`（`before` に現状の物の全体）。
  - 両方にある物は、入力項目ID（エンジンの入力のスキーマから作った場所の表）ごとに値を比べ、値の中を歩いて違う所を当て先にする（0036 の2 の「いちばん内側の入力項目ID・場所」）。ID を持つ並びは要素の `add`・`remove` と要素の中の値、ID を持たない並び・並びの順が変わった所は入力項目の値の全体（か並びの全体）の `set`。
  - 値の状態の行（`valueStates`）だけが変わった所も、その当て先の `set`（値の箱は、欄の値と行から組み立てる）。
  - 物の種類を決める欄（物の上の `kind`・`type`）が変わった物、どの入力項目にも入らない欄が変わった物、現状にある値を省いた物（省くことは `set` で書けない）は、置き換えの組（同じ `pair` の `remove` と `add`。同じ ID の物）。同じ物の集まりで1件外して1件足したときも組にする。組の足す物は、外した物のあった所に入れる（並びの順を変えない）。
  - 前提条件・表の最後の年は、要求の入力の項目として同じに比べる（計算の基準の月はプランで変えない）。
- 違いを差分にする決まりは 0036 の8 のとおり:
  - このプランで足した物の中・足した並びの要素の中を直したら、その `add` の物を直す（`set` を重ねない）。
  - このプランで足した物を外したら、その `add` を消す。このプランで外した物を作業中の世帯に戻したら、その `remove` を消す。
  - 現状の物を外したら、その物への自分の差分（値を変える・中の要素を足す外す）を消す。
  - 値を変える差分は `setPlanValue`（土台・現状と同じ値の箱に戻したら自分の差分を消す）。値の全体の差分があれば、その中の値を直しても全体の差分を直す（全体と中の値を重ねない）。全体の差分を作ったら、その中の値の差分は消す。
- 差分にしてから当て直し、まだ違えばもう一度（最大4回。足した物を戻した後の中の値など）。
- **欄の値が土台・現状と同じに戻ったら差分を消す**（`settleFields`）: 欄が省いた値を既定の値で見せる所（土地の割合など）は、既定の値を打ち直すと世帯の値は「省いた」から「既定の値」に変わる。欄の見え方と状態が同じで、同じ差分を指すほかの欄も変わらないなら、その欄を指す自分の差分を消す。パネルは直すたびに、開いているカードの欄でこれを行う。
- 画面の側の値: 定年後の予定（`postRetirement`）は、プランで働き方の期間を変えた人だけ、作業中の世帯の期間から読み直す。プランで足した構成員の呼び名と、足した項目のカードの記録は世帯に1つ（現状の側）に入れる（物はプランの差分）。仮の印（`assumed`）は、プランか土台で値を変えた欄の印を外して見せる。
- 値の状態の操作（確定・推定に戻す・わからない・該当なし）は、0041 の7 のとおり `planStateOp` を欄の部品に渡す（部品は変えない）。

### 2. 編集の対象

- 入力のホームの上に「編集の対象」（現状・保存したプラン）と「＋ 現状から新しいプラン」「このプランを複製」「このプランを土台に」。プランを選ぶと、入力のホームとパネルがそのプランの色の帯になり「プラン○を編集中（現状は変わりません）」と出る。
- 結果のタブで選んでいるプランと入力画面の編集の対象はそろえる: 入力で選んだプランは結果のタブでも選ぶ（帯に無ければ足す）。入力で「現状」を選ぶと、結果のタブも現状を選ぶ。結果のタブの「このプランを入力で開く」・プランの一覧の「入力で直す」でも開く。世帯を開いたとき・入力のタブを開いただけのときは現状（結果のタブでプランを選んでいても、入力で選ぶまでは現状を直す）。
- 結果のタブに、そのプランの保存していない変更があるときは、入力では直さない（先に上書き保存か取り消しをする）。結果のタブの下書きは動かす項目の値の全部を持つので、入力で直した後に上書きすると入力の変更が戻るため。

### 3. 印と戻す

- 欄: 現状と違う欄に、プランの色の縦線と「現状: ○○」と「↺ 現状に戻す」（欄の部品の外側の印。`FieldViews.tsx` の `PlanMarksContext`）。戻すと、その欄を指す自分の差分を消し、まだ現状と違えば（土台のプランで変えた）現状の値の差分を作る。土台のプランから来た差分は「土台（プラン○）で変更」。合成の対策（0036 の3）で変わっている欄は「結果のタブの対策で変わっています」（ここでは戻さない。結果のタブで動かす）。
- まとまり: このプランで足した物は「このプランで足した」、土台で足した物は「土台（プラン○）で足した」。
- 外した物: パネルの上に、薄く消し線で「このプランで外した ↺」（土台なら「土台（プラン○）で外した ↺」、置き換えなら「このプランで置き換えた ↺」）。
- カード: 「プラン○: nか所」（オンの差分の行の数）。

### 4. 外したときの連鎖

- 外す物を指す物（物の中のどこかの値が外す物の ID）が作業中の世帯に残るとき、パネルに並べ、一緒に外す物を選ばせる（既定はすべて選ぶ）。選んだ物の `remove` に、きっかけの物の `remove` の ID を `cause` に書く。部品が一緒に外した物（子を外すと関係も外れるなど）も、外した物がほかの外した物を指していれば同じく `cause` を書く。

### 5. 違いの一覧

- 入力のホームの「違いの一覧」: 差分1件ずつ（置き換えの組は1件）に「何を・現状 → プラン」・オン／オフ・戻す・要確認・出どころ（入力で直した・結果のタブで動かした・AIの候補）。要確認を上に、カードごとに並べる。オフにした差分と、連鎖で一緒に外す差分（「一緒に外す」の印、きっかけの行に「ほか n 件を一緒に外す」）も出す。
- 戻すは自分の差分を消す（組は組ごと、連鎖で一緒に外した差分も）。土台のプランから来た差分は、このプランに現状へ戻す差分を作る（`dropChange`）。オン・オフは自分の差分だけ（連鎖で一緒に外した差分もいっしょに）。土台の差分は土台のプランで直す。
- 同じ当て先の差分が土台とこのプランにあれば、後のプランの1行。

### 6. 現状にだけ入れるもの

- 取り込み・ヒアリング・明細の承認・確かめの一覧（「推定で埋める」を含む）は、プランを選んでいても現状を直す。プランを直しているときは、基本生活費のパネルの「明細から出す」を出さない。確かめの一覧は「現状の確かめの一覧」と出す。

### 7. 結果のタブとの関係

- 入力で作った値を変える差分も、当て先が動かす項目の一覧の欄と同じなら、結果のタブではその項目として見える（`diffKey`）。結果のタブで動かして上書きしても、同じ差分（同じ ID）が変わる。入力でもう一度直しても同じ差分。
- 結果のタブで動かした差分の出どころは `result`（0036 の4）。上書きで値が同じままの差分は、値の箱（入力で付けた状態を含む）と出どころを引き継ぐ。
- 結果のタブとの橋渡し（動かす項目のキー・`@plan`）は変えずに使う。

### 8. カードに読むだけで出す値

- 推計の年金・退職金の見込み・推定の値など、カードとパネルが世帯から計算して見せる値は、プランを直しているときは作業中の世帯から読む（部品に渡す世帯がプランの中身なので、そのまま）。基本生活費のパネルの控えから見た貯まり方も、作業中の世帯で計算する。

## 理由

- **前後の違いを差分にする**: 欄の部品をそのまま使え、欄を足しても差分の書き方を足さなくてよい（並べて欄を足す回と重ならない）。当て先はエンジンの入力のスキーマから作った場所の表で決まり、欄のキーを使わない（0036 の2）。モデル世帯 50 件のすべての数・選択・オンオフ・年月の欄で、直す → 差分 → 戻すの往復を確かめた。
- **欄の値で差分を消す**: 省いた値と既定の値は世帯の値として違うが、FP には同じに見え、計算も同じ。値で比べるだけでは、現状に戻したのに差分が残る。
- **入力のタブを開いただけでは現状**: 結果のタブでは、世帯を開くと帯の最初のプランを選ぶ。入力のタブに移っただけで、気づかずにプランを直さないようにする（帯の色と「編集中」で見分けられるが、事実を入れる画面なので既定は現状）。
- **結果のタブの下書きがあるときは直さない**: 下書きは動かす項目の値の全部で、上書きするとその値で差分を作り直す。入力で直した差分が、知らないうちに戻るのを避ける。

- 定年後の予定（画面の側の値）を、作業中の世帯の期間から読み直せない形に変えたとき（読み直しが無い人）の見せ方。
