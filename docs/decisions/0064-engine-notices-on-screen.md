# 0064. 計算の知らせを画面に出す（エンジンの知らせを FP 向けの行に・種類・まとめ方・確かめの一覧）

- 状態: 採用（一部未確定）（2026-10-27）
- 固定の強さ: 内部（エンジンの出力の形は変えない。文の表・種類の分け方・並び・見せ方は変えてよい）

## 背景

- 計算エンジンは、計算に反映していないこと・既定の値や推定で計算したこと・先の年の値を延ばしたことなどを、結果の見出しの `notices` に「コードと ID だけ」で出す（0005 の8・0006・0007 の追記）。
- 画面はこれまで、遺族年金の見直しの知らせ（万一のときのタブ）だけを文にしていて、ほかの知らせ（短大・専門学校の修学支援はまだ計算していない、口座の間の移し替えは計算に入れていない、専門学校の学費が無いので0円、住宅ローン控除の率が無いので控除を計算していない など）はどこにも出ていなかった。FP が気づけないまま、計算に入っていない所が結果に残る。

## 決定

### 1. 知らせを FP 向けの行にする（`app/src/workspace/engineNotices.ts`）

- 知らせ1件の ID を、部品の ID（先頭。エンジンの全体の段が出す `N_PARAM_EXTENDED`・`N_PARAM_RECORDED_LATER` と積立の終わりの知らせは付かない）、話題（物の ID でも年でもない最初の文字）、物の ID（対象）、年（4桁の年・年月）に分ける。
- 文の表を「コード|部品|話題」「コード|話題」「コード|部品」「コード」の順に引く。表に無い知らせも、コードごとの決まりの文で出す（捨てない）。制度の値の名前は登録簿の名前（`PARAM_LABELS`。後ろの括弧の注は省く）。
- 文には物の ID・値の ID・コードを出さない。対象は呼び名（人・子の教育・退職金・保険・口座・住まい・介護・働き方の期間）で出す。

### 2. 種類（上から）

| 種類 | 何か | 主なコード |
|---|---|---|
| 入力が足りないため、計算できていない所 | 入れれば計算に入る所 | `N_INPUT_REQUIRED`、持ち家の住み終わりに売るかが無い |
| 計算に入れていないもの | まだ計算しない制度・お金の流れに入れない税 | `N_NOT_SUPPORTED`、`N_INHERITANCE_TAX`、`N_GIFT_TAX_BY_RECIPIENT` |
| 制度の決まり・前提の外で変えた所 | 上限・受給資格・打ち切り・見直し前の制度 | `N_LIMIT_APPLIED`、`N_NOT_ENTITLED`、`N_NOT_ELIGIBLE`、`N_PROTECTION_TRUNCATED`、`N_REFORM_NOT_REFLECTED`、`N_RECONCILE_SURPLUS`、`N_NOT_DEDUCTIBLE` |
| 仮の値・推定で計算した所 | 既定の値・推定・近い値・前提を置いた所 | `N_DEFAULT_USED`、`N_ESTIMATED`、`N_ASSUMED`、`N_APPROXIMATED`（住民税の標準の税率の知らせもここ） |
| 制度データの確認待ち・先の年の値 | 制度データに無い値・先の年に延ばした値・架空のデータ | `N_PARAM_MISSING`、`N_PARAM_PROJECTED`、`N_PARAM_EXTENDED`、`N_PARAM_RECORDED_LATER`、`N_FICTIONAL_DATA` |

### 3. まとめ方

- 同じ文の知らせは1行にまとめ、対象（呼び名。構成員の順）・年の範囲・内訳・出たプランを足す。
  - 先の年の値（`N_PARAM_PROJECTED`・`N_PARAM_EXTENDED`）は1行にまとめ、内訳に値の名前と年の範囲（例: 年金額の改定率〔2027〜2081年〕）。
  - 介護の費用の既定（月々の費用・始めにかかる費用・介護の期間）、土地と建物の割合の既定、相続税の対象の受け取りも、それぞれ1行に。
- 帯のプランの全部の結果の知らせを集め、一部のプランだけに出た行は「プランB・Cだけ」と出す（全部に出た行・プランが1つのときは出さない）。
- 子の年金の加入記録の推計と受給資格の知らせは出さない（子は働き方を入れないので、記録が推計で受給資格が無いのが当たり前。FP が直す所でない）。大人の分は出す。

### 4. どこに出すか

- **結果のタブ**: グラフのカードの下（FP顧問料の一文・入力の確認の下）に「計算の知らせ」の1行（種類ごとの数）。「見る」で種類ごとの行を開く。入力が足りない・計算に入れていない知らせがあるときは枠を強くする。入力で直せる行は「入力で開く」でそのカードを開く（開くだけ）。URL の `#notices` で開いた状態にできる（画面の確かめ用）。
- **確かめの一覧**: 現状の計算結果の知らせのうち、入るカードを持つ行を「計算の知らせ（入力で直せる所）」として、確かめの注意と推定の間に出す（「開く」でそのカードへ。行の操作は無い）。
- 万一のときのタブの遺族年金の見直しの一文は、同じ文（`REFORM_TEXT`）をこの表から使う。

### 5. 提案書・持ち帰り用のレポート（この回は画面だけ）

- 案: 顧客向けには「計算に入れていないもの」と「入力が足りない所」だけを、前提の章の注に短く載せる（「この試算に入っていないもの」）。仮の値・推定・制度データの知らせは FP 向けの内部の情報なので載せない（必須の記載の「前提条件にもとづく試算」で足りる）。載せるかは FP が選べるようにする（提案書の章の選択と同じ形）。

## 理由

- エンジンが知らせを ID だけで出すのは、出力を言語・言い回しから切り離すため（0005 の8）。文は画面の側で持ち、同じ知らせが部品・構成員・年度ごとに何件も出るのを、FP が読む単位（同じ文）にまとめる。
- 種類で分けるのは、FP が直せる所（入力が足りない）と計算に入っていない所を先に見て、仮の値・先の年の値は確かめるだけにできるようにするため。
- 一部のプランだけに出る知らせ（FP顧問料・繰上げ・NISA の枠など）は、プランを比べるときに差の理由になるので、プランを出す。

## 代案（採らなかったもの）

- **エンジンが文を出す**: 出力の形が変わり、言い回しの直しでエンジンの版が上がる。
- **知らせを全部そのまま並べる**: 見本の世帯でも先の年の値だけで十数件になり、大事な知らせが埋もれる。
- **確かめの一覧に全部の知らせを出す**: 入力で直せない知らせ（制度の決まり・データ）は一覧の目的（入力を確かめる）に合わない。

## 影響

- **画面**: 結果のタブに計算の知らせ（`CalcNotices.tsx`）、確かめの一覧に「計算の知らせ」の種類（`checkRows.ts` の `calc`）。入力のホームの確かめの一覧の入口の数にも足す（知らせがあるときだけ）。
- **世帯ファイルの形・エンジン・計算の結果**: 変えない。
- **テスト**: `app/test/engine-notices.test.ts`（分け方、見本の世帯の知らせがすべて文の表の文で出ること、エンジンの部品のソースの話題がすべて文の表にあること、文に ID を出さないこと、まとめ方、プランの出し方、子の知らせ、確かめの一覧、結果のタブの部品）。
