# 0110. 機能を有効にするコード（提供元が署名した、機能・名前の札をこの PC で確かめ、提供元が止めた一覧で止める）

- 状態: 採用（一部未確定）（2026-11-01。同じ日に、止め方を期限から「提供元が止めた一覧」に直した。7・追記）
- 固定の強さ: 骨格（コードの形 `LPFC1-`＋中身の JSON＋Ed25519 の署名、署名の前置き、中身の欄〔`v`・`kid`・`id`・`name`・`features`・`issued`・`expires`。`expires` は版 2 で省ける〕、期限は日本の日付で期限の日の終わりまで、確かめるのは本体だけで画面にコードの文字列を返さない、期限が切れても止めてもデータを消さない、止めた一覧の形〔封・前置き・通し番号〕と鍵がコードの鍵と別であること、一覧を取りに行くときに送るのは取得の依頼だけ、つながらない・一覧を取れないときは今の状態のまま使えること、署名の合わない一覧は無視すること）。公開鍵の中身・一覧の場所（どちらも公開前に差し替える）・確かめの頻度・更新の知らせを出す日数・画面の置き場所と文言・発行の道具の命令と CSV の列は変えてよい

## 背景

- 0107 の合算BS は、会社を顧問先に持つ FP のための機能で、事務所の設定の印（`features.combinedBs`）を付ければ誰でも使えた。提供元がコードを渡した FP だけが使えるようにしたい。今後ほかの機能も同じ仕組みで足す。
- アプリはネットにつながずに動く（0017 の4。自動通信の相手は配信元だけ）。コードが本物かの確かめにネットを使わない（止めるかどうかの確かめだけ、7 で配信元への通信を1つ足した）。
- コードを入れていない FP には、その機能の設定の項目も画面のどこにも出さない（ふつうの FP の画面を重くしない。0027 の8・0107 の考え方）。

## 決定

### 1. コードの中身と形

- 提供元がコードを発行する。中身（`Claims`）は次の7つ。
  | 欄 | 中身 |
  |---|---|
  | `v` | 中身の形の版（1: 期限が要る。2: 期限を省ける。期限のあるコードは今までどおり 1 で出す） |
  | `kid` | 署名した鍵の名前（公開鍵を選ぶ。鍵を替えるときに並べられる） |
  | `id` | コードの番号（英数字で始め、英数字と `-` `_` `.` の32文字まで。発行の記録と突き合わせる） |
  | `name` | FP の表示名（40文字まで。画面に「○○さん向けに有効」と出る） |
  | `features` | 有効にする機能の名前（1〜16。今は `combinedBs` だけ） |
  | `issued` | 発行日（YYYY-MM-DD） |
  | `expires` | 期限（YYYY-MM-DD。この日の終わりまで。日本の日付）。版 2 では省ける（期限なし。止めるときは 7 の止めた一覧に載せる） |
- 形は `LPFC1-` ＋ 中身の JSON の base64url ＋ `.` ＋ 署名の base64url（およそ260文字）。署名は Ed25519 で、「決まった前置き `lifeplan-feature-code/1` と NUL ＋ 中身の JSON のバイト列」に付ける（ほかの用途の署名と取り違えない）。メールなどで改行が入っても、空白・改行は無視して読む。
- 確かめるのは本体（Rust）の部品 `crates/feature-code` だけ。本体は公開鍵を埋め込み、本物か（署名と中身の形）・期限内か・止めた一覧（7）に載っていないかを確かめる。画面は本体が返した状態（使える機能・名前・期限・期限が近いか切れたか）を出すだけで、自分では確かめない。画面にコードの文字列は返さない（外すときは短い印 `ref`〔SHA-256 の先頭8バイト〕で指す）。
- 公開鍵は配布元の設定 `config/distribution.toml` の `[keys]` の `feature_code`（「鍵の名前:公開鍵」の並び。現用＋次期を並べられる）。本体は build.rs が、開発用のサーバーの代わり（`app/vite.config.ts`・`app/scripts/devFeatureCode.ts`）もここから読む。ほかのファイルに公開鍵を直接書かない（`npm run check:distribution` が確かめる）。
- **今の公開鍵は開発用の鍵（`dev-1`）。公開の前に、提供元が作った本番の鍵に差し替える。** 差し替えると、開発用の鍵で発行したコードは「確かめられないコード」になる（外せる。2 の表）。開発用の鍵の秘密鍵もリポジトリには置かない。テストの鍵はテストの中だけで作る。

### 2. アプリの中での扱い

- 入れたコードは事務所データ（暗号化。0011 の6）の任意の欄 `featureCodes`（文字列の並び。16個・1つ2048バイトまで）に持つ。事務所の既定値（0073 の `defaults`）とは別の欄で、画面から既定値を置き換えても変わらない。事務所データの形式の版は上げない（足すだけの任意の欄）。事務所で共有しているときも、同期フォルダで2台の PC を使うときも、この PC の設定（PC ごとに入れる）。
- 本体の命令は3つ: `feature_codes_status`（状態）・`feature_code_add`（入れる）・`feature_code_remove`（外す）。
  - 入れるのは、本物で、この版のアプリが知っている機能が1つ以上入っていて、期限内で、最後に取れた止めた一覧に載っていないものだけ。断るときは符号（`E_FEATURE_CODE_FORMAT`〔形が違う〕・`KEY`〔この版の持っていない鍵〕・`SIGNATURE`〔書き換えた・本物でない〕・`EXPIRED`・`REVOKED`〔提供元が止めた〕・`NO_FEATURE`・`LIMIT`）。
  - 同じコードは足さない。新しいコードが同じ機能を同じか遅い期限まで（期限なしがいちばん遅い）含むとき、古いコード（更新の前のコード・切れたコード）は外す。
- 状態は、コードごとに「期限内」「期限まで30日以内（更新の知らせ）」「切れた」「提供元が止めた」（止めたが先。期限が切れていても止めたと出す）。今使える機能は、期限内で止めていないコードのどれかに入っている機能。読めなくなったコード（鍵の差し替えの後など）は「確かめられないコード」として外せるように出す。
- 期限の判定は日本の日付（UTC+9）で、PC の時計で行う。開発用のビルドだけ、環境変数 `FINANCIA_DEV_TODAY` で今日を変えられる（見え方の確かめ用）。

### 3. 画面

- **入れる所は1か所だけ: 事務所の既定値のパネルのいちばん下（保存・閉じるのボタンの下）の、小さな「機能を有効にするコードを入れる」**。押すと欄が開き、貼り付けて「確かめて入れる」。入れるとすぐ効く（パネルの保存は要らない）。
  - 置き場所の理由: 有効にした機能の設定（0107 の区画）はこのパネルにあり、入れたらすぐ上に区画が出るので、入れた結果が同じ画面で分かる。機能は事務所（FP）単位の判断で、世帯の画面には置かない。コードを持たない FP には目立たない（小さなリンク1つ）が、案内するときは「世帯の一覧の『事務所の既定値』のいちばん下」と1文で言える。
- **有効なときだけ**、その機能の区画（0107 の「法人経営者向けの機能」）と、それに伴う画面（資産と負債のタブの見るもの「合算BS」）・提案書の章が出る。区画には「○○さん向けに有効（期限 2027-05-31）」（期限なしのコードは「（期限なし）」）と「コードを外す」（確かめてから外す）を出す。
- **期限の30日前から**、区画に更新の知らせ「期限まであと○日です（…まで）。続けて使うときは、新しいコードを受け取り、この画面のいちばん下から入れてください（入れ直すまでは今のまま使えます）」。
- **期限が切れたら**、区画・画面・提案書の章は出さない。データは消さない（世帯の `household.companyBs`、事務所の設定の印はそのまま）。知らせは次の2か所だけ（コードを入れたことのある FP にだけ出る）:
  - 事務所の既定値のいちばん下: 「合算BS のコード（○○さん向け）は ○ で期限が切れました。設定の区画と画面には出なくなりましたが、世帯に入れた会社の数字などのデータは消していません。新しいコードを入れると、また見られます。」と「このコードを外す」。
  - 資産と負債のタブ（役員として働く人がいて、会社の数字が入っている世帯で、印が付いているとき）: 「この世帯には会社の数字（合算BS）が入っています。…今は見られません。データは消していません。新しいコードを入れると、また見られます。」（`BalanceTabModel.hiddenNote`）
- **提供元が止めたら**、期限が切れたときと同じ扱い（区画・画面・提案書の章は出さない。データは消さない）。知らせは同じ2か所で、文は「…提供元が止めました。…データは消していません。提供元が止めるのをやめると、次に確かめたときに自動で戻ります（コードを入れ直す必要はありません）。」。
- コードを入れている FP にだけ、事務所の既定値のいちばん下に止めた一覧の確かめの様子（「提供元が止めたコードの一覧は 2026-11-01 に確かめました。」、つながらなかったときは「…つながりませんでした。2026-10-30 に取れた一覧で判断しています（次に取れるまで、今の状態のままです）。」）と「今すぐ確かめる」を出す（7）。
- コードを新しく入れて合算BS が使えるようになったとき、事務所の設定の印が付いていなければ付ける（入れたらすぐ区画と画面が出る。印は区画の中で外せる）。

### 4. 今まで印を付けていた人（移行）

- 開発中なので、事務所の設定の印 `features.combinedBs` はそのまま残し、**コードが無ければ出さない**（出す条件は「コードで有効」かつ「印」かつ「役員のいる世帯」）。印を付けていた事務所でコードを入れると、前と同じ画面に戻る。世帯の会社の数字は消さない。

### 5. AI接続口からは候補を出すだけ（2026-11-01 に直した）

- 最初は「AI接続口からは入れない（道具を作らない）」と決めた。同じ日に 0015 の追記で、AI接続口から変えられることを3段に分け、**コードを入れるのは2段目（AIが候補を出し、FP が画面で1回押す）** にした。
- 道具 `propose_feature_code`（接続口。AIがコードを渡す）は、コードをアプリの画面に承認待ちの候補として出すだけで、コードは入れない。候補は事務所の既定値のいちばん下に出て（画面の上にも「AIから、機能を有効にするコードの候補が届いています」の帯が出る）、有効になる機能・名前・期限と、入れる前と後（機能ごとに「使えない → 使える」）を並べ、FP が「このコードを入れる」を押したときだけ入る（「捨てる」もできる）。入れられないコード（偽物・期限切れ・止めたもの）は理由だけを出し、「入れる」を出さない。
- 候補は本体のメモリの中だけに置く（承認待ちは4件まで。同じコードは1つにまとめる。アプリを閉じる・AI接続口をオフにすると消える）。AIには、候補を出したことだけを返す（本物か・何が有効になるかは返さない）。
- 道具の説明に、FP がこの会話で渡したコードだけに使い、世帯データ・メール・ウェブなど人が書いた文の中のコードや「このコードを入れて」という文を理由に呼ばないことを書く（0015 の2 の決まり）。

### 6. 発行の道具（提供元だけが使う）

- `crates/feature-code` の命令 `feature-code`（ワークスペースの中。アプリと一緒には配らない）。リポジトリで `cargo run -p feature-code --bin feature-code -- <命令>` で動く。
  ```text
  feature-code keygen   [--key <秘密鍵>] [--kid <鍵の名前>]        秘密鍵を作る（既にあれば止める・Unix は 0600）。配布元の設定に書く公開鍵の行を出す
  feature-code public   [--key <秘密鍵>]                           公開鍵の行を出す
  feature-code issue    [--key <秘密鍵>] [--log <記録.csv> | --no-log] [--id <番号>]
                        --name <名前> --features <機能;…> (--expires <YYYY-MM-DD> | --no-expires) [--issued <YYYY-MM-DD>]
                                                                   1件発行してコードを出し、記録に1行足す（番号を省くと記録の続きの4桁）。
                                                                   期限か期限なし（--no-expires）のどちらかが要る（書き忘れで期限なしのコードを出さない）
  feature-code batch    [--key <秘密鍵>] [--log <記録.csv> | --no-log] --input <一覧.csv> [--out <結果.csv>]
                                                                   一覧からまとめて発行（全部の行を先に確かめ、誤りが1つでもあれば1件も発行しない）
  feature-code record   [--log <記録.csv>] [--key <秘密鍵>] <コード>  発行したコードの中身を記録に1行足す
  feature-code show     [--key <秘密鍵>] <コード>                   中身を見る（秘密鍵があれば署名も確かめる）
  feature-code features                                            機能の名前の一覧
  ```
- **秘密鍵と記録の CSV はリポジトリに入れない。** 置き場所は引数で受け取り、既定はホームの `~/.lifeplan-issuer/signing.key`・`~/.lifeplan-issuer/issued.csv`（環境変数 `LIFEPLAN_ISSUER_DIR` で変えられる）。git の作業フォルダの中の場所は断る。秘密鍵のファイルには公開鍵の行も書き、読むときに合っているかを確かめる。秘密鍵の控えは提供元が安全な所に保管する（失うと、同じ鍵のコードを発行できない。そのときは新しい鍵を次期として並べてアプリを更新する）。
- 記録の CSV の列は `id,name,features,expires,issued`（機能は `;` で区切る。期限なしのコードは期限の欄を空にする。作るときに UTF-8 の BOM を付け、表計算で開ける）。同じ番号は足さない。表示名の最初の文字に `= + - @` は使えない（表計算で式として読まれないため）。
- 一覧の CSV（まとめて発行）は見出しの行に `name`・`features`・`expires` が要り、`id`・`issued` は任意（無ければ記録の続きの番号・今日）。期限なしは `expires` に `none`（または「なし」）と書く（空の欄は誤り）。結果は `id,name,features,expires,issued,code` の CSV。のちに別の一覧から自動で発行するときは、1件ずつ `issue` を呼ぶか、一覧を作って `batch` を呼ぶ。
- 期限の長さ（または期限なし）は発行のときに決める（アプリは決めない）。今日より前の期限は道具が断る。
- 止めた一覧の命令（7）は `feature-code revocations keygen|new|add|remove|show|sign`。

### 7. 提供元が止める（止めた一覧。2026-11-01 に足した）

- **止め方は、期限ではなく提供元が手動で止める形にする。** 途中でやめた人のコードは、提供元が「止めた一覧」（止めたコードの番号 `id` の一覧。署名つきの小さな JSON）に載せて配信元に置く。アプリは一覧を取りに行き、載っているコードの機能を止める（データは消さない）。一覧から外したら、アプリは次に確かめたときに自動で戻す（コードの入れ直しは要らない）。期限つきのコードもこれまでどおり使え、期限でも止まる。
- **一覧の形**（`crates/feature-code` の `revocation`）:
  ```json
  {
    "format": "lifeplan-feature-code-revocations",
    "kid": "dev-rv1",
    "payload": "{\"v\":1,\"serial\":3,\"issued\":\"2026-11-01\",\"revoked\":[\"0002\",\"0007\"]}",
    "sig": "<base64url>"
  }
  ```
  - 署名は Ed25519 で、「決まった前置き `lifeplan-feature-code-revocations/1` と NUL ＋ `payload` の UTF-8 のバイト列」に付ける（コードの署名と取り違えない）。
  - `serial`（通し番号）は署名するたびに1つ増やす。最後に取れた一覧より小さい番号の一覧は受け付けない（古い一覧を見せ続けて、止めたのを隠すのを防ぐ。0017 の7 と同じ考え方）。
  - ファイルは 256KB まで、番号は5000件まで。知らない欄があれば形が違うとみなす。
- **鍵はコードの鍵と別**（止めた一覧の鍵）。公開鍵は配布元の設定 `config/distribution.toml` の `[keys]` の `feature_code_revocation`（「鍵の名前:公開鍵」。現用＋次期を並べられる）。コードの鍵で署名した一覧は受け付けない（鍵の並びが別）。**今は開発用の鍵（`dev-rv1`）。公開の前に本番の鍵に差し替える。** 秘密鍵はリポジトリに置かない。
- **一覧の場所**は配布元の設定の `[endpoints]` の `feature_code_revocations`（配信元の `host` の https だけ。クエリ・ほかのホストは build.rs と `npm run check:distribution` が断る）。**今は開発用の URL（`https://<配信元>/dev/v1/feature-codes/revocations.json`）。本番の URL は公開前に差し替える（置き場所は未定）。**
- **確かめの頻度**: コードが1つ以上入っている PC だけが、起動してすぐ（5秒後）と、動いている間は1日1回取りに行く。取れなかったときは1時間後にもう一度。ほかに、コードを入れたとき（入れ口・AIからの候補）と、FP が「今すぐ確かめる」を押したとき。コードを入れていない PC は一度も取りに行かない。
- **送るのは一覧の取得の依頼（`GET`）だけ。** コード・名前・世帯の情報・PC を見分ける値は送らず、クエリも付けない。クッキーは持たず、ほかのホストへの転送には従わない。アプリの版・OS も送らない（User-Agent は決まった文字 `financia` だけ）。プロキシは使わない。通信は本体（Rust）の HTTP の部品だけで、TLS の証明書は OS の仕組みで確かめる（0017 の4）。
- **つながらない・一覧を取れないときは、今の状態のまま使える**（最後に取れた一覧で判断する。一度も取れていなければ何も止めない）。署名が合わない・形が違う・古い一覧は無視する（最後に取れた一覧のまま。止まっていたコードを、偽の一覧で戻すこともできない）。保存した一覧も読むたびに確かめ直し、鍵を差し替えた後などで確かめられなければ使わない（止めない）。
- 最後に取れた一覧と、確かめた日時・結果は、この PC のアプリのデータ（`feature-codes/revocations.json`）に置く（配信元のファイルのまま。事務所データには入れない。中身は番号だけで、秘密ではない）。
- **確かめを切る設定は作らない。** 理由: 送るものが取得の依頼だけで、コードを入れている PC だけが取りに行くので、切る理由が小さい。切れると止める仕組みが働かない（コードを外せば取りに行かなくなる）。代わりに、コードを入れている FP にだけ確かめの様子と「今すぐ確かめる」を見せる（3）。
- **0017 との関係**: 0017 の4 の「自動通信の相手は配信元（`updates.fprise.com`）だけ」は変えない。今まで「アプリはまだ通信しない」だったところに、配信元への通信を1つ（この一覧の取得）足す形。同じホストで、送る項目も 0017 の4 より少ない（版・OS も送らない）。「外部送信の一覧」（0012）に載せる。0017 の7 の取り下げの一覧（`revocations`。制度の値・計算部品・アプリの版・鍵を取り下げる）とは別のもので、鍵も別（0017 の取り下げ用の鍵ではなく、この一覧の鍵）。
- 開発用のビルドだけ、環境変数 `FINANCIA_DEV_FEATURE_REVOCATIONS_URL` で、この PC の中（127.0.0.1・localhost）の一覧を読める（http も可。見え方の確かめ用）。開発用のサーバーの代わり（`vite.config.ts`）は `FINANCIA_DEV_FEATURE_REVOCATIONS` に書いた手元のファイルを配信元とみなす。
- **発行の道具の命令**（提供元だけ。既定の置き場所はリポジトリの外の `~/.lifeplan-issuer/`）:
  ```text
  feature-code revocations keygen [--revocation-key <秘密鍵>] [--kid <鍵の名前>]   止めた一覧の秘密鍵を作る（既定 revocation.key・rv-1）。公開鍵の行を出す
  feature-code revocations new    [--draft <下書き>]                              手元の下書きを作る（既定 revocations-draft.json）
  feature-code revocations add    [--draft <下書き>] [--log <記録.csv> | --no-log] <番号>…   止める番号を足す（発行の記録に無い番号は知らせる）
  feature-code revocations remove [--draft <下書き>] <番号>…                       外す
  feature-code revocations show   [--draft <下書き>] [--signed <一覧> [--revocation-key <秘密鍵>]]   中身を見る
  feature-code revocations sign   [--draft <下書き>] [--revocation-key <秘密鍵>] [--out <一覧>]
                                                                                 下書きに署名して配信元に置く一覧を作る（既定 revocations.json。通し番号を1つ上げる）
  ```
  下書きは通し番号と止めた番号だけの JSON。足す・外すだけでは止まらず、署名した一覧を配信元に置いたときに、アプリが次に確かめたときから効く。

## できること・できないこと

- **できる**: ネットにつながずに、本物か（書き換えていないか）と期限を確かめる。名前と期限を画面に出す。期限なしのコードを出す。途中でやめた人のコードを、提供元が止めた一覧に載せて止める（アプリがつながったときに効く。外せば戻る）。期限で止める。1つのコードで複数の機能、1人に複数のコード。
- **できない（今は作らない）**:
  - 止めた一覧は、アプリがつながったときにしか効かない。ずっとネットにつながない PC・配信元への通信をふさいだ PC では止まらない（今の状態のまま使える、と決めたため）。
  - 止めるまでに最長でおよそ1日かかる（動いている間は1日1回。起動したときにも確かめる）。
  - コードを人に回されると、止めた一覧に載せるまでは止められない（回された先の画面にも元の人の名前が出る）。
  - PC の時計を戻すと期限を延ばせる。防がない（時計の巻き戻しの検出は、正しい時計の PC を誤って止めるおそれがあるため。止めるのは止めた一覧で行える）。
  - 公開鍵はアプリに入っているので、アプリを書き換えた人は確かめを外せる（ライセンスの仕組みではなく、提供元が渡した FP だけに機能を見せる仕組み）。

## 理由

- **Ed25519 の署名・公開鍵の埋め込み**: ネットにつながずに本物かを確かめられ、秘密鍵は提供元だけが持つ。署名が短く（64バイト）、コードを貼り付けやすい。ライブラリ（`ed25519-dalek`）は世帯の鍵の組（`x25519-dalek`）と同じ系統で、依存が少ない。
- **確かめるのは本体だけ**: 画面の安全の考え方（0016 の1）。画面に確かめを置くと、画面の値を書き換えるだけで通る。
- **事務所データの別の欄**: 暗号化して持ち、復元キーで戻せる（0013）。既定値の欄は画面が丸ごと置き換えるので、混ぜると画面の不具合でコードが消えうる。
- **期限が切れても・止めてもデータを消さない**: 黙って消さない（0096 の考え方）。入れ直せば（止めたものは外せば）同じ画面に戻る。
- **止め方を期限から止めた一覧へ**: 期限で止めると、続けて使う人にも期限ごとに新しいコードを渡す手間がかかり、途中でやめた人も期限までは使える。提供元が手動で止めれば、続けて使う人には1度渡すだけで済み、やめた人はおよそ1日で止まる。
- **つながらないときは今のまま**: FP は顧客先などでネットにつながないことがあり、確かめられないことを理由に機能を止めると、正しく使っている FP の仕事を止めてしまう（0017 の7 の「計算と出力は止めない」と同じ考え方）。止めた一覧の目的は、途中でやめた人に使い続けさせないことで、ふさいでまで使う人を止めることではない。
- **止めた一覧の鍵をコードの鍵と別にする**: 止めた一覧は頻繁に署名し直す。コードの鍵（新しいコードを出せる鍵）を、毎回の作業で使わないようにする（0017 の5 の「鍵を役割で分ける」）。

## 代案（採らなかったもの）

- ネットで毎回確かめる（確かめられなければ使えない）: アプリがネットにつながずに動く決まり（0017 の4）に反する。7 の止めた一覧は、取れないときは今のまま使える形にした。
- 期限だけで止める（最初の決め方）: 上の理由で、提供元が止める形に直した。
- 止めた一覧に、止めたコードの番号の代わりにコードの指紋を載せる: 番号は発行の記録と突き合わせやすく、指紋にしても隠すものが無い（番号から人は分からない）。
- 確かめを切る設定を作る: 7 の理由。
- コードの中身を暗号化する: 隠す中身（名前・期限）は本人に見えてよく、要るのは書き換えの検出だけ。
- AI接続口から入れる: 5 の理由。

## 影響

- 新しい部品 `crates/feature-code`（確かめる部品と発行の道具。ワークスペースの既定の部品に入れた）。
- `crates/household-store`: 事務所データの任意の欄 `featureCodes`、`feature_codes`・`set_feature_codes`、`E_STORE_FEATURE_CODES`。
- `app/src-tauri`: 命令3つと権限（`capabilities/main.json`）、build.rs が公開鍵を写す。
- `config/distribution.toml`: `[keys]` の `feature_code`（開発用の鍵）。`app/scripts/distribution.ts` が公開鍵をほかの所に書いていないかを確かめる。
- 画面: `app/src/workspace/office/featureCodes.ts`（新）、事務所の既定値のパネル（区画の出し方・いちばん下の入れ口・期限切れの知らせ）、資産と負債のタブの知らせ、`App.tsx`（合算BS を出す条件にコードを足す）。
- 止めた一覧（7）: `crates/feature-code` の `revocation`（形・確かめ・`apply_fetch`）と `issuer` の下書き、発行の道具の `revocations` の命令。`app/src-tauri/src/revocations.rs`（取りに行く・保存する・見回り。HTTP の部品は reqwest〔rustls・ring。証明書は OS で確かめる〕）、命令 `feature_codes_check`。`config/distribution.toml` の `[endpoints] feature_code_revocations` と `[keys] feature_code_revocation`（どちらも開発用）。
- AIからの候補（5）: 接続口の道具 `propose_feature_code`、取り決めの依頼 `proposeFeatureCode`（`crates/ai-ipc`）、台帳の承認待ち（`crates/ai-share` の `FeatureCodeCandidate`）、命令 `feature_code_candidate_decide`、画面の候補の欄と帯（`AiCodeCandidateBand`）。
- 世帯ファイルの形式・計算エンジン・計算の結果は変わらない。

## 未確定

- 本番の鍵の作り方と保管（提供元が公開前に作る。秘密鍵の控えの置き場所）。
- 期限つきのコードを使い続けるか（期限なしを基本にするか）と、期限の長さの目安・更新の知らせを出す日数（今は30日）。
- 止めた一覧の本番の置き場所（配信元のどこに置くか。配信元は 0017 の未確定）と、本番の鍵の作り方と保管。
- 確かめの頻度（今は起動したときと1日1回、取れなければ1時間後）を変えるか。
- 止めた一覧を長く取れていないときに、FP に知らせるか（今は事務所の既定値のいちばん下に「つながりませんでした」と出すだけ。止めない）。
- 会社などのプロキシの奥の PC で取れないとき、OS のプロキシの設定を使うか（今は使わない）。
- 事務所で共有しているときに、コードを事務所の全員で使えるようにするか（今は PC ごと）。
