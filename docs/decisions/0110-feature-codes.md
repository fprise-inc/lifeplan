# 0110. 機能を有効にするコード（提供元が署名した、機能・名前の札をこの PC で確かめ、提供元が止めた一覧で止める）

- 状態: 採用（一部未確定）（2026-11-01。同じ日に、止め方を期限から「提供元が止めた一覧」に直した。7・追記。2026-11-04 に、鍵を配布の鍵の体系にそろえ、止める一覧を配布の取り下げの一覧に一本化し、コードの形を固めた。同じ日に、コードを止めるだけの手軽な鍵と小さな一覧を足した。追記・追記の2）
- 固定の強さ: 骨格（コードの形 `LPFC1-`＋中身の JSON＋Ed25519 の署名、署名の前置き、中身の欄〔`v`・`kid`・`id`・`name`・`features`・`issued`・`expires`。`expires` は版 2 で省ける〕と鍵の名前・番号の決まり、見本のコード〔`crates/feature-code/tests/feature_code.rs` の `code_format_is_fixed`〕がこれからの版でも確かめられること、期限は日本の日付で期限の日の終わりまで、確かめるのは本体だけで画面にコードの文字列を返さない、期限が切れても止めてもデータを消さない、コードの鍵は配布の鍵の束の役割 `feature_code`〔現用＋次期の2本まで。開発用の鍵 `dev-` は開発用のビルドだけ〕、止めるのは配布の取り下げの一覧〔0117 の3 (3)。取り下げ用の鍵〕の `revoked.featureCodes`〔番号〕と `revoked.keys`〔漏れたコードの鍵〕、およびコードを止めるだけの鍵〔`feature_code_revocation`〕で署名した小さな一覧の `featureCodes`〔2つの和。追記の2〕、一覧を取りに行くときに送るのは取得の依頼だけ、つながらない・一覧を取れないときは今の状態のまま使えること、署名の合わない・古い一覧は無視すること）。公開鍵の中身（公開前に差し替える）・確かめの頻度・更新の知らせを出す日数・画面の置き場所と文言・発行の道具の命令と CSV の列は変えてよい

## 背景

- 0107 の合算BS は、会社を顧問先に持つ FP のための機能で、事務所の設定の印（`features.combinedBs`）を付ければ誰でも使えた。提供元がコードを渡した FP だけが使えるようにしたい。今後ほかの機能も同じ仕組みで足す。
- アプリはネットにつながずに動く（0017 の4。自動通信の相手は配信元だけ）。コードが本物かの確かめにネットを使わない（止めるかどうかの確かめだけ、7 で配信元への通信を1つ足した）。
- コードを入れていない FP には、その機能の設定の項目も画面のどこにも出さない（ふつうの FP の画面を重くしない。0027 の8・0107 の考え方）。

## 決定

### 1. コードの中身と形

- 提供元がコードを発行する。中身（`Claims`）は次の7つ。
  | 欄 | 中身 |
  |---|---|
  | `v` | 中身の形の版（1: 期限が要る。2: 期限を省ける。期限のあるコードは今までどおり 1 で出す） |
  | `kid` | 署名した鍵の名前（公開鍵を選ぶ。鍵を替えるときに並べられる） |
  | `id` | コードの番号（英数字で始め、英数字と `-` `_` `.` の32文字まで。発行の記録と突き合わせる） |
  | `name` | FP の表示名（40文字まで。画面に「○○さん向けに有効」と出る） |
  | `features` | 有効にする機能の名前（1〜16。今は `combinedBs` だけ） |
  | `issued` | 発行日（YYYY-MM-DD） |
  | `expires` | 期限（YYYY-MM-DD。この日の終わりまで。日本の日付）。版 2 では省ける（期限なし。止めるときは 7 の止めた一覧に載せる） |
- 形は `LPFC1-` ＋ 中身の JSON の base64url ＋ `.` ＋ 署名の base64url（およそ260文字）。署名は Ed25519 で、「決まった前置き `lifeplan-feature-code/1` と NUL ＋ 中身の JSON のバイト列」に付ける（ほかの用途の署名と取り違えない）。メールなどで改行が入っても、空白・改行は無視して読む。
- 鍵の名前（`kid`）は配布の鍵の束と同じ決まり（英小文字・数字・「-」の32文字まで、「-」で始めない。2026-11-04 に16文字までから広げた）。本番の鍵は `dev-` で始めない（開発用の鍵の名前。追記 2026-11-04）。
- 確かめるのは本体（Rust）の部品 `crates/feature-code` だけ。本体は公開鍵を埋め込み、本物か（署名と中身の形）・期限内か・取り下げの一覧（7）に載っていないかを確かめる。画面は本体が返した状態（使える機能・名前・期限・期限が近いか切れたか）を出すだけで、自分では確かめない。画面にコードの文字列は返さない（外すときは短い印 `ref`〔SHA-256 の先頭8バイト〕で指す）。
- 公開鍵は配布元の設定 `config/distribution.toml` の `[keys]` の `feature_code`（「鍵の名前:公開鍵」の並び。現用＋次期の2本まで）。配布の鍵の束（`crates/distribution` の `keys`。0117 の2）の5つ目の役割で、同じ公開鍵をほかの役割に使えない。本体は build.rs が、開発用のサーバーの代わり（`app/vite.config.ts`・`app/scripts/devFeatureCode.ts`）もここから読む。ほかのファイルに公開鍵を直接書かない（`npm run check:distribution` が確かめる）。
- **本番の鍵（`[keys]`）は、公開の前に提供元が作って書く（手順は `docs/feature-codes-operations.md`）。それまで製品のビルドではどのコードも使えない。** 開発用の鍵（`dev-1`）は `[dev_keys]` に置き、開発用のビルド（debug・開発用のサーバーの代わり）だけが受け付ける。製品のビルド（release）には build.rs が開発用の鍵を入れないので、**試しの鍵で発行したコードは製品では「確かめられないコード」になる**（外せる。2 の表）。開発用の鍵の秘密鍵もリポジトリには置かない。テストの鍵はテストの中だけで作る。

### 2. アプリの中での扱い

- 入れたコードは事務所データ（暗号化。0011 の6）の任意の欄 `featureCodes`（文字列の並び。16個・1つ2048バイトまで）に持つ。事務所の既定値（0073 の `defaults`）とは別の欄で、画面から既定値を置き換えても変わらない。事務所データの形式の版は上げない（足すだけの任意の欄）。事務所で共有しているときも、同期フォルダで2台の PC を使うときも、この PC の設定（PC ごとに入れる）。
- 本体の命令は3つ: `feature_codes_status`（状態）・`feature_code_add`（入れる）・`feature_code_remove`（外す）。
  - 入れるのは、本物で、この版のアプリが知っている機能が1つ以上入っていて、期限内で、最後に取れた止めた一覧に載っていないものだけ。断るときは符号（`E_FEATURE_CODE_FORMAT`〔形が違う〕・`KEY`〔この版の持っていない鍵〕・`SIGNATURE`〔書き換えた・本物でない〕・`EXPIRED`・`REVOKED`〔提供元が止めた〕・`NO_FEATURE`・`LIMIT`）。
  - 同じコードは足さない。新しいコードが同じ機能を同じか遅い期限まで（期限なしがいちばん遅い）含むとき、古いコード（更新の前のコード・切れたコード）は外す。
- 状態は、コードごとに「期限内」「期限まで30日以内（更新の知らせ）」「切れた」「提供元が止めた」（止めたが先。期限が切れていても止めたと出す）。今使える機能は、期限内で止めていないコードのどれかに入っている機能。読めなくなったコード（鍵の差し替えの後など）は「確かめられないコード」として外せるように出す。
- 期限の判定は日本の日付（UTC+9）で、PC の時計で行う。開発用のビルドだけ、環境変数 `FINANCIA_DEV_TODAY` で今日を変えられる（見え方の確かめ用）。

### 3. 画面

- **入れる所は1か所だけ: 事務所の既定値のパネルのいちばん下（保存・閉じるのボタンの下）の、小さな「機能を有効にするコードを入れる」**。押すと欄が開き、貼り付けて「確かめて入れる」。入れるとすぐ効く（パネルの保存は要らない）。
  - 置き場所の理由: 有効にした機能の設定（0107 の区画）はこのパネルにあり、入れたらすぐ上に区画が出るので、入れた結果が同じ画面で分かる。機能は事務所（FP）単位の判断で、世帯の画面には置かない。コードを持たない FP には目立たない（小さなリンク1つ）が、案内するときは「世帯の一覧の『事務所の既定値』のいちばん下」と1文で言える。
- **有効なときだけ**、その機能の区画（0107 の「法人経営者向けの機能」）と、それに伴う画面（資産と負債のタブの見るもの「合算BS」）・提案書の章が出る。区画には「○○さん向けに有効（期限 2027-05-31）」（期限なしのコードは「（期限なし）」）と「コードを外す」（確かめてから外す）を出す。
- **期限の30日前から**、区画に更新の知らせ「期限まであと○日です（…まで）。続けて使うときは、新しいコードを受け取り、この画面のいちばん下から入れてください（入れ直すまでは今のまま使えます）」。
- **期限が切れたら**、区画・画面・提案書の章は出さない。データは消さない（世帯の `household.companyBs`、事務所の設定の印はそのまま）。知らせは次の2か所だけ（コードを入れたことのある FP にだけ出る）:
  - 事務所の既定値のいちばん下: 「合算BS のコード（○○さん向け）は ○ で期限が切れました。設定の区画と画面には出なくなりましたが、世帯に入れた会社の数字などのデータは消していません。新しいコードを入れると、また見られます。」と「このコードを外す」。
  - 資産と負債のタブ（役員として働く人がいて、会社の数字が入っている世帯で、印が付いているとき）: 「この世帯には会社の数字（合算BS）が入っています。…今は見られません。データは消していません。新しいコードを入れると、また見られます。」（`BalanceTabModel.hiddenNote`）
- **提供元が止めたら**、期限が切れたときと同じ扱い（区画・画面・提案書の章は出さない。データは消さない）。知らせは同じ2か所で、文は「…提供元が止めました。…データは消していません。提供元が止めるのをやめると、次に確かめたときに自動で戻ります（コードを入れ直す必要はありません）。」。
- コードを入れている FP にだけ、事務所の既定値のいちばん下に止めた一覧の確かめの様子（「提供元が止めたコードの一覧は 2026-11-01 に確かめました。」、つながらなかったときは「…つながりませんでした。2026-10-30 に取れた一覧で判断しています（次に取れるまで、今の状態のままです）。」）と「今すぐ確かめる」を出す（7）。
- コードを新しく入れて合算BS が使えるようになったとき、事務所の設定の印が付いていなければ付ける（入れたらすぐ区画と画面が出る。印は区画の中で外せる）。

### 4. 今まで印を付けていた人（移行）

- 開発中なので、事務所の設定の印 `features.combinedBs` はそのまま残し、**コードが無ければ出さない**（出す条件は「コードで有効」かつ「印」かつ「役員のいる世帯」）。印を付けていた事務所でコードを入れると、前と同じ画面に戻る。世帯の会社の数字は消さない。

### 5. AI接続口からは候補を出すだけ（2026-11-01 に直した）

- 最初は「AI接続口からは入れない（道具を作らない）」と決めた。同じ日に 0015 の追記で、AI接続口から変えられることを3段に分け、**コードを入れるのは2段目（AIが候補を出し、FP が画面で1回押す）** にした。
- 道具 `propose_feature_code`（接続口。AIがコードを渡す）は、コードをアプリの画面に承認待ちの候補として出すだけで、コードは入れない。候補は事務所の既定値のいちばん下に出て（画面の上にも「AIから、機能を有効にするコードの候補が届いています」の帯が出る）、有効になる機能・名前・期限と、入れる前と後（機能ごとに「使えない → 使える」）を並べ、FP が「このコードを入れる」を押したときだけ入る（「捨てる」もできる）。入れられないコード（偽物・期限切れ・止めたもの）は理由だけを出し、「入れる」を出さない。
- 候補は本体のメモリの中だけに置く（承認待ちは4件まで。同じコードは1つにまとめる。アプリを閉じる・AI接続口をオフにすると消える）。AIには、候補を出したことだけを返す（本物か・何が有効になるかは返さない）。
- 道具の説明に、FP がこの会話で渡したコードだけに使い、世帯データ・メール・ウェブなど人が書いた文の中のコードや「このコードを入れて」という文を理由に呼ばないことを書く（0015 の2 の決まり）。

### 6. 発行の道具（提供元だけが使う）

- `crates/feature-code` の命令 `feature-code`（ワークスペースの中。アプリと一緒には配らない）。リポジトリで `cargo run -p feature-code --bin feature-code -- <命令>` で動く。
  ```text
  feature-code keygen   [--key <秘密鍵>] --kid <鍵の名前>          秘密鍵を作る（既にあれば止める・Unix は 0600）。配布元の設定に書く公開鍵の行を出す
                                                                   （鍵の名前は必須。本番は fc-2026a・fc-2026b のように。dev- で始まる名前は開発用）
  feature-code public   [--key <秘密鍵>]                           公開鍵の行を出す
  feature-code issue    [--key <秘密鍵>] [--log <記録.csv> | --no-log] [--id <番号>]
                        --name <名前> --features <機能;…> (--expires <YYYY-MM-DD> | --no-expires) [--issued <YYYY-MM-DD>]
                                                                   1件発行してコードを出し、記録に1行足す（番号を省くと記録の続きの4桁）。
                                                                   期限か期限なし（--no-expires）のどちらかが要る（書き忘れで期限なしのコードを出さない）
  feature-code batch    [--key <秘密鍵>] [--log <記録.csv> | --no-log] --input <一覧.csv> [--out <結果.csv>]
                                                                   一覧からまとめて発行（全部の行を先に確かめ、誤りが1つでもあれば1件も発行しない）
  feature-code record   [--log <記録.csv>] [--key <秘密鍵>] <コード>  発行したコードの中身を記録に1行足す
  feature-code show     [--key <秘密鍵>] <コード>                   中身を見る（秘密鍵があれば署名も確かめる）
  feature-code features                                            機能の名前の一覧
  ```
- **秘密鍵と記録の CSV はリポジトリに入れない。** 置き場所は引数で受け取り、既定はホームの `~/.lifeplan-issuer/signing.key`・`~/.lifeplan-issuer/issued.csv`（環境変数 `LIFEPLAN_ISSUER_DIR` で変えられる）。git の作業フォルダの中の場所は断る。秘密鍵のファイルには公開鍵の行も書き、読むときに合っているかを確かめる。秘密鍵の控えは提供元が安全な所に保管する（失うと、同じ鍵のコードを発行できない。そのときは新しい鍵を次期として並べてアプリを更新する）。
- 記録の CSV の列は `id,name,features,expires,issued`（機能は `;` で区切る。期限なしのコードは期限の欄を空にする。作るときに UTF-8 の BOM を付け、表計算で開ける）。同じ番号は足さない。表示名の最初の文字に `= + - @` は使えない（表計算で式として読まれないため）。
- 一覧の CSV（まとめて発行）は見出しの行に `name`・`features`・`expires` が要り、`id`・`issued` は任意（無ければ記録の続きの番号・今日）。期限なしは `expires` に `none`（または「なし」）と書く（空の欄は誤り）。結果は `id,name,features,expires,issued,code` の CSV。のちに別の一覧から自動で発行するときは、1件ずつ `issue` を呼ぶか、一覧を作って `batch` を呼ぶ。
- 期限の長さ（または期限なし）は発行のときに決める（アプリは決めない）。今日より前の期限は道具が断る。
- 止めるコードの命令（7）は `feature-code revocations new|add|remove|show`（配布の取り下げの一覧の下書きを直す）。署名は配布の道具 `dist-keys revocations sign`。

### 7. 提供元が止める（取り下げの一覧。2026-11-01 に足し、2026-11-04 に配布の取り下げの一覧へ一本化した）

- **止め方は、期限ではなく提供元が手動で止める形にする。** 途中でやめた人・返金した人のコードや漏れたコードは、提供元が配布の取り下げの一覧（0117 の3 (3)。取り下げ用の鍵で署名した封筒）の `revoked.featureCodes` に番号（`id`）で載せて、配信元に置く。アプリは一覧を取りに行き、載っているコードの機能を止める（データは消さない）。一覧から外したら、アプリは次に確かめたときに自動で戻す（コードの入れ直しは要らない）。期限つきのコードもこれまでどおり使え、期限でも止まる。
- **コードの鍵が漏れたとき**は、同じ一覧の `revoked.keys` に鍵の名前を載せる。アプリはその鍵を束から外し、その鍵で発行したコードは「確かめられないコード」になる（データは消さない。次期の鍵で発行し直したコードを渡す）。
- **一覧の形**は 0117 の3 (3) のまま（封筒 `fprise-lifeplan-revocations-envelope`・中身 `fprise-lifeplan-revocations`。署名は封筒の `payload` のバイト列への Ed25519）。中身の `revoked` に任意の欄 `featureCodes`（番号の並び。名前の順・重なりなし。番号の形は 1 の `id` と同じ）を足した。
  ```json
  {
    "format": "fprise-lifeplan-revocations",
    "formatVersion": "1.0",
    "serial": 3,
    "issuedAt": "2026-11-04T00:00:00Z",
    "expiresAt": "2027-02-02T00:00:00Z",
    "minAppVersion": null,
    "revoked": { "regulationValues": [], "componentRevisions": [], "packs": [], "appVersions": [], "keys": [], "featureCodes": ["0002", "0007"] }
  }
  ```
  - `serial`（通し番号）は署名するたびに1つ増やす。最後に取れた一覧より小さい番号の一覧は受け付けない（古い一覧を見せ続けて、止めたのを隠すのを防ぐ。0017 の7 と同じ考え方）。
  - 期限（`expiresAt`）の切れた一覧も、載っている取り下げは当て続ける（0117 の3 (3)）。期限の前に出し直す（初期値90日。0117 の影響）。
- **鍵は取り下げ用の鍵**（配布元の設定の `[keys]` の `revocation`。オフラインで保管。コードの鍵とは別）。コードの鍵・データ用の鍵で署名した一覧は受け付けない（役割が違う）。開発用の取り下げ用の鍵（`dev-rv2`）は `[dev_keys]` に置き、開発用のビルドだけが受け付ける。
- **一覧の場所**は配布元の設定の `[endpoints]` の `revocations`（配信元の `host` の https だけ。クエリ・ほかのホストは build.rs と `npm run check:distribution` が断る）。
- **確かめの頻度**: コードが1つ以上入っている PC だけが、起動してすぐ（5秒後）と、動いている間は1日1回取りに行く。取れなかったときは1時間後にもう一度。ほかに、コードを入れたとき（入れ口・AIからの候補）と、FP が「今すぐ確かめる」を押したとき。コードを入れていない PC は一度も取りに行かない（アプリ本体の更新のつなぎ〔0117 の未確定〕を入れる回に、取り下げの一覧をどの PC も取りに行くかを決め直す）。
- **送るのは一覧の取得の依頼（`GET`）だけ。** コード・名前・世帯の情報・PC を見分ける値は送らず、クエリも付けない。クッキーは持たず、ほかのホストへの転送には従わない。アプリの版・OS も送らない（User-Agent は決まった文字 `financia` だけ）。プロキシは使わない。通信は本体（Rust）の HTTP の部品だけで、TLS の証明書は OS の仕組みで確かめる（0017 の4）。
- **つながらない・一覧を取れないときは、今の状態のまま使える**（最後に取れた一覧で判断する。一度も取れていなければ何も止めない）。署名が合わない・形が違う・古い一覧は無視する（最後に取れた一覧のまま。止まっていたコードを、偽の一覧で戻すこともできない）。保存した一覧も読むたびに確かめ直し、鍵を差し替えた後などで確かめられなければ使わない（止めない）。確かめと当て方は配布の部品（`distribution::revocations` の `verify`・`apply_fetch`）。
- 最後に取れた一覧と、確かめた日時・結果は、この PC のアプリのデータ（`feature-codes/revocations.json`）に置く（配信元のファイルのまま。事務所データには入れない。中身は番号だけで、秘密ではない）。一覧のほかの欄（最低版・取り下げた版・制度の値など）は、まだ当てない（0117 のアプリ本体のつなぎの回）。
- **確かめを切る設定は作らない。** 理由: 送るものが取得の依頼だけで、コードを入れている PC だけが取りに行くので、切る理由が小さい。切れると止める仕組みが働かない（コードを外せば取りに行かなくなる）。代わりに、コードを入れている FP にだけ確かめの様子と「今すぐ確かめる」を見せる（3）。
- **0017 との関係**: 0017 の4 の「自動通信の相手は配信元（`updates.fprise.com`）だけ」は変えない。外部送信の一覧（0012 の5）の「取り下げの一覧の取得」の行。
- 開発用のビルドだけ、環境変数 `FINANCIA_DEV_FEATURE_REVOCATIONS_URL` で、この PC の中（127.0.0.1・localhost）の一覧を読める（http も可。見え方の確かめ用）。開発用のサーバーの代わり（`vite.config.ts`）は `FINANCIA_DEV_FEATURE_REVOCATIONS` に書いた手元のファイルを配信元とみなす。
- **発行の道具の命令**（提供元だけ。既定の置き場所はリポジトリの外の `~/.lifeplan-issuer/`）:
  ```text
  feature-code revocations new    [--draft <下書き>]                                 取り下げの一覧の下書きを作る（既定 revocations-draft.json。通し番号 0）
  feature-code revocations add    [--draft <下書き>] [--log <記録.csv> | --no-log] <番号>…   止める番号を足す（発行の記録に無い番号は知らせる）
  feature-code revocations remove [--draft <下書き>] <番号>…                          外す
  feature-code revocations show   [--draft <下書き>]                                 止める番号を見る
  dist-keys revocations sign <取り下げ用の秘密鍵> <下書き> <一覧> [--days <日数>]        通し番号を1つ上げ、有効期限（既定90日）を入れて署名し、配信元に置く一覧を書く
  dist-keys revocations show <下書き>                                               下書きの全体（通し番号・期限・載っている数）を見る
  ```
  下書きは取り下げの一覧の中身（署名の前の JSON）そのもの。`feature-code` はその `featureCodes` だけを直し、ほかの欄はそのまま残す。足す・外すだけでは止まらず、署名した一覧を配信元に置いたときに、アプリが次に確かめたときから効く。

## できること・できないこと

- **できる**: ネットにつながずに、本物か（書き換えていないか）と期限を確かめる。名前と期限を画面に出す。期限なしのコードを出す。途中でやめた人・返金した人のコードや漏れたコードを、提供元が取り下げの一覧に載せて止める（アプリがつながったときに効く。外せば戻る）。漏れたコードの鍵を一覧で外す。期限で止める。1つのコードで複数の機能、1人に複数のコード。試しの鍵のコードを製品のビルドで受け付けない。
- **できない（今は作らない）**:
  - 止めた一覧は、アプリがつながったときにしか効かない。ずっとネットにつながない PC・配信元への通信をふさいだ PC では止まらない（今の状態のまま使える、と決めたため）。
  - 止めるまでに最長でおよそ1日かかる（動いている間は1日1回。起動したときにも確かめる）。
  - コードを人に回されると、止めた一覧に載せるまでは止められない（回された先の画面にも元の人の名前が出る）。
  - PC の時計を戻すと期限を延ばせる。防がない（時計の巻き戻しの検出は、正しい時計の PC を誤って止めるおそれがあるため。止めるのは止めた一覧で行える）。
  - 公開鍵はアプリに入っているので、アプリを書き換えた人は確かめを外せる（ライセンスの仕組みではなく、提供元が渡した FP だけに機能を見せる仕組み）。

## 理由

- **Ed25519 の署名・公開鍵の埋め込み**: ネットにつながずに本物かを確かめられ、秘密鍵は提供元だけが持つ。署名が短く（64バイト）、コードを貼り付けやすい。ライブラリ（`ed25519-dalek`）は世帯の鍵の組（`x25519-dalek`）と同じ系統で、依存が少ない。
- **確かめるのは本体だけ**: 画面の安全の考え方（0016 の1）。画面に確かめを置くと、画面の値を書き換えるだけで通る。
- **事務所データの別の欄**: 暗号化して持ち、復元キーで戻せる（0013）。既定値の欄は画面が丸ごと置き換えるので、混ぜると画面の不具合でコードが消えうる。
- **期限が切れても・止めてもデータを消さない**: 黙って消さない（0096 の考え方）。入れ直せば（止めたものは外せば）同じ画面に戻る。
- **止め方を期限から止めた一覧へ**: 期限で止めると、続けて使う人にも期限ごとに新しいコードを渡す手間がかかり、途中でやめた人も期限までは使える。提供元が手動で止めれば、続けて使う人には1度渡すだけで済み、やめた人はおよそ1日で止まる。
- **つながらないときは今のまま**: FP は顧客先などでネットにつながないことがあり、確かめられないことを理由に機能を止めると、正しく使っている FP の仕事を止めてしまう（0017 の7 の「計算と出力は止めない」と同じ考え方）。止めた一覧の目的は、途中でやめた人に使い続けさせないことで、ふさいでまで使う人を止めることではない。
- **止める一覧の鍵をコードの鍵と別にする**: コードの鍵（新しいコードを出せる鍵）を、止める作業で使わないようにする（0017 の5 の「鍵を役割で分ける」）。2026-11-04 からは配布の取り下げ用の鍵（オフライン）で署名する（追記）。

## 代案（採らなかったもの）

- ネットで毎回確かめる（確かめられなければ使えない）: アプリがネットにつながずに動く決まり（0017 の4）に反する。7 の止めた一覧は、取れないときは今のまま使える形にした。
- 期限だけで止める（最初の決め方）: 上の理由で、提供元が止める形に直した。
- 止めた一覧に、止めたコードの番号の代わりにコードの指紋を載せる: 番号は発行の記録と突き合わせやすく、指紋にしても隠すものが無い（番号から人は分からない）。
- 確かめを切る設定を作る: 7 の理由。
- コードの中身を暗号化する: 隠す中身（名前・期限）は本人に見えてよく、要るのは書き換えの検出だけ。
- AI接続口から入れる: 5 の理由。

## 追記（2026-11-02）: 止めた・期限切れの知らせは7日で消える

- **知らせを出すのは、止めた・期限が切れたと分かった日から7日間だけ**（分かった日を1日目として7日目まで。8日目からは出さない）。3 の知らせの2か所（事務所の既定値のいちばん下・資産と負債のタブの一文）は、同じ条件で一緒に消える。事務所の既定値の知らせには「閉じる」を付け、押したら7日の内でも2か所とも出さない（「このコードを外す」はそのまま並べる）。知らせの文には「この知らせは7日たつと消えます。」を添える。
- **「分かった日」は、本体がその状態（止めた・切れた）を初めて見た日**（画面が状態を読んだとき。日本の日付）。期限切れは、期限の翌日以降に初めて見た日になる（しばらく開いていなかった PC でも、開いてから7日は出る）。分かった日が今日より後のとき（PC の時計を戻した後など）は今日に直す。
- 記録はコードの印（`ref`）と状態ごと。**使える状態に戻ったら記録を消す**ので、再び止められたら新しい日付で、閉じた印も無しで出直す。止めた ↔ 切れた が入れ替わったときも出直す（文とすることが違うため）。外したコードの記録も消す。
- **知らせが消えても、コードは外さない**（止めたコードはアプリの中に残り、止めるのをやめたら次の確かめで自動で戻る）。止めた一覧の確かめ（起動したときと1日1回）も続ける。世帯のデータは消さない。
- 記録（分かった日・閉じた印）は、止めた一覧と同じこの PC のアプリのデータ（`feature-codes/revocations.json` の `notices`）に置く。PC をまたいで同期しない（事務所データには入れない）。出すかどうかは本体が決め（`crates/feature-code` の `notice`。状態のコードごとの `notice`・`noticeSince`）、画面はそれに従うだけ。閉じる命令は `feature_code_notice_dismiss`（コードは外さない）。
- 理由: 止めた・切れたの知らせがずっと出ていると、続けて使わないと決めた FP の画面に残り続ける。データを消していないこと・戻り方は、7日あれば伝わる。

## 追記（2026-11-04）: 本番の鍵と保管を配布の鍵の体系にそろえ、止める一覧を配布の取り下げの一覧に一本化し、コードの形を固めた

- **背景**: 配布の仕組み（0117）で、鍵の束（役割ごとに現用＋次期の2本まで・取り下げた鍵を外す）・封筒・取り下げの一覧・配布元の設定の1か所化ができた。機能を有効にするコードは別の鍵の書き方・別の止めた一覧（別の封・別の鍵・別の場所）を持っていて、同じ仕組みを重ねていた。また、世帯ファイルなどの形式を 1.0 に固める前に、β で配ったコードを正式版でも使える約束（コードの形）を固める。
- **決めたこと**
  1. **鍵の体系**: コードの鍵を配布の鍵の束の5つ目の役割 `feature_code` にした（`[keys] feature_code`。現用＋次期の2本まで・ほかの役割と同じ公開鍵を使えない・取り下げの一覧の `revoked.keys` で外せる）。確かめは束から取り出した鍵で行う（`feature_code::keys_from_ring`）。鍵の名前の決まりも束にそろえた（32文字まで。今までの16文字までの名前はそのまま使える）。
  2. **本番と開発用を分けた**: 配布元の設定に `[dev_keys]`（開発用の鍵。名前は `dev-` で始める）を足し、`[keys]`（本番）の名前は `dev-` で始めない。開発用のビルド（debug）と開発用のサーバーの代わりだけが `[dev_keys]` を足して受け付け、製品のビルド（release）は build.rs が入れない（本体の側でも debug のときだけ足す）。今まで `[keys] feature_code` にあった開発用の鍵 `dev-1` は `[dev_keys]` に移し、`[keys] feature_code` は空にした（本番の鍵を書くまで、製品のビルドではどのコードも使えない）。形は配布の部品（`KeyRing::from_config`・`with_dev`）が本体の build.rs で、`npm run check:distribution` が CI で確かめる。
  3. **止める一覧を一本化した**: 7 の別の止めた一覧（`lifeplan-feature-code-revocations`・鍵 `feature_code_revocation`・場所 `feature_code_revocations`）をやめ、配布の取り下げの一覧（0117 の3 (3)）の中身 `revoked` に任意の欄 `featureCodes` を足した。署名は取り下げ用の鍵。漏れたコードの鍵は同じ一覧の `revoked.keys` で外す。取り下げの一覧の形式の版は `1.0` のまま（配る前に任意の欄を足すだけ。番号が無いときは欄を書かない）。
  4. **コードの形を固めた**（骨格。β で配ったコードを正式版でも使う約束）: `LPFC1-`・中身の JSON の base64url・`.`・署名の base64url。署名は Ed25519 で「`lifeplan-feature-code/1` と NUL ＋中身の JSON のバイト列」。中身の欄は7つ（1 の表）で、版 1（期限が要る）と版 2（期限を省ける）。決まった種の使い捨ての鍵で作った見本のコード2つ（期限あり・期限なし）を `crates/feature-code/tests/feature_code.rs` に置き、形が変われば落ちるようにした。**これからの足し方**: 知らなくても安全な欄（表示だけに使う欄など）は同じ版のまま足せる（前の版のアプリは無視する）。知らないと誤って使えてしまう欄（使える範囲を狭める欄など）を足すときは中身の版 `v` を上げる（前の版のアプリはそのコードを「形が違う」として入れない＝使える範囲を広げない側に倒れる）。前置き・署名の方式を替えるときは `LPFC2-` にする。
  5. **発行の道具**: `feature-code keygen` は鍵の名前（`--kid`）を必須にした（現用と次期の名前を分けるため）。止めるコードは `feature-code revocations new|add|remove|show` で配布の取り下げの一覧の下書きを直し、署名は配布の道具 `dist-keys revocations sign`（通し番号を上げ、有効期限〔既定90日〕を入れる）。`feature-code revocations keygen|sign` はやめた。手順は `docs/feature-codes-operations.md`。発行と取り下げの自動化は β の後に決める。
- **理由**
  - 鍵の束と取り下げの一覧をそろえると、鍵の入れ替え・漏れたとき・失くしたときの手順（0117 の2）がコードの鍵にもそのまま使え、取り下げ用の鍵（オフライン）1本の作業で、鍵・アプリの版・制度の値・コードをまとめて止められる。確かめる部品・発行の道具・設定の検査が重ならない。
  - 取り下げ用の鍵はオフラインなので、返金のたびに取り出す手間はかかる。ただし返金はまれで、止めるのを急ぐものでもない（最長およそ1日で効く）。一覧は期限（90日）の前に出し直す作業がもともとあり、そこにまとめられる。止める作業にコードの鍵（新しいコードを出せる鍵）を使わない、という 7 の理由はそのまま満たす。
  - 試しの鍵を名前の前置きと別の欄で分けると、本番の欄に試しの鍵を書き間違えても検査で止まり、製品のビルドには開発用の鍵が入らない。コードの中身に「開発用か」の欄を足さずに済み、コードの形を変えない。
- **影響**
  - 世帯ファイル・事務所データの形式の版は変わらない（事務所データの `featureCodes` はコードの文字列のまま）。計算エンジン・計算の結果は変わらない。
  - 開発用の鍵 `dev-1` で発行したコードは、開発用のビルドではこれまでどおり使え、製品のビルドでは「確かめられないコード」になる。β の FP には本番の鍵で発行したコードを渡す。
  - 前の形の止めた一覧（`lifeplan-feature-code-revocations`）・その下書き・`dev-rv1` の鍵は使わなくなった。この PC に保存してあった前の形の一覧は確かめられないので使わない（何も止めない）。開発用の止める一覧は `[dev_keys] revocation` の `dev-rv2` で署名する。
  - 外部送信の一覧（0012 の5）の行を「取り下げの一覧の取得（`revocations`）」に直した。送る中身・相手・いつは変えていない。

## 追記（2026-11-04 の2）: コードを止めるだけの手軽な鍵と小さな一覧（利用者の判断）

- **背景**: 上の追記で止めるのを取り下げの一覧（オフラインの取り下げ用の鍵）に一本化したが、返金などで止めるたびにオフラインの鍵を出すのは手間になる。利用者の判断で、機能を有効にするコードを止めるだけの手軽な鍵を別に持つ（CI の秘密の値などオンラインに置ける）。
- **決めたこと**（形と理由は 0117 の追記 2026-11-04 の2）
  1. 鍵の束の役割 `feature_code_revocation`（現用＋次期の2本まで。開発用は `dev-fr1`）。この鍵で署名できるのは、コードを止めるだけの一覧（`/v1/revocations/feature-codes.json`。中身は止める番号 `featureCodes` だけ）だけ。漏れても、できるのはコードを止める・この一覧で止めたのを戻すことだけで、鍵・アプリの版・データパックの取り下げや、ほかの鍵の取り外しはできない。この鍵は取り下げの一覧（オフラインの取り下げ用の鍵）の `revoked.keys` で外せる。
  2. 7 の止め方: アプリは取り下げの一覧と小さな一覧の2つを続けて取りに行き（どちらも配信元。コードが入っている PC だけ・同じ頻度・送るのは取得の依頼だけ）、**どちらかに載っている番号を止める**。小さな一覧から外せば戻る。取り下げの一覧に載せた番号は、小さな一覧からは戻せない。事務所の既定値のいちばん下の確かめの様子は2つをまとめる（2つとも取れたときだけ「確かめました」。片方でも取れなければ「つながりませんでした」）。
  3. 6・7 の道具: 止めるコードの命令 `feature-code revocations new|open|add|remove|show` は、ふだんは小さな一覧の下書きを直す（`open` は配信元の一覧を確かめて下書きにする。`--draft` に取り下げの一覧の下書きを渡せばそちらを直す）。署名は `dist-keys revocations sign`（下書きの種類に合う鍵）。ふだんの止め方は GitHub の Actions（`.github/workflows/feature-code-revocations.yml`）。手順は `docs/feature-codes-operations.md`。
  4. 取り下げの一覧に知らない欄があると一覧ごと受け付けない作りをやめた（知らない欄は無視する。0117 の追記の2 の5）。
- **影響**: 開発用のビルドは `FINANCIA_DEV_FEATURE_CODE_REVOCATIONS_URL`、開発用のサーバーの代わりは `FINANCIA_DEV_FEATURE_CODE_REVOCATIONS`（手元のファイル）で小さな一覧を読める。世帯ファイル・事務所データの形式の版、計算エンジン・計算の結果は変わらない。外部送信の一覧（0012 の5）の行に `feature_code_revocations` を足した。
