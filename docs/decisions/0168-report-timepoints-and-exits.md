# 0168. 帳票の中の時点を、年月・年齢・出来事のどの形でも同じに解く（提案書と画面の出口をそろえる）

- 状態: 採用（一部未確定）（2026-11-08）
- 固定の強さ: 内部（帳票の材料の組み立ての実装の決まり。帳票の入力の形〔JSON Schema〕・世帯ファイルの形式は変えない）

## 背景

- 提案書の材料を作る `report/src/build.ts` の一部は、時点を年月の形 `{at}` でしか読まなかった（`atOf`・`leaveYear`）。アプリが標準で書く年齢の形の時点（子を足したときの独立 `standardLeavesPoint`、保険のひな形の払込の終わり、働き方の詳細の「終わり」の欄）や、出来事の形の時点が、提案書から落ちていた（子の独立が出来事に出ない・独立の後も子の年齢を出す・払込の終わりが出ない・退職が消える）。同じファイルには年齢・出来事も解く `monthOfTimepoint` があり、夢・修繕・車などはそちらで解いていて、読み方が混ざっていた。お金の3つの分け方（`moneyThree.ts`）の車の最初の購入と、収益不動産の売る年の案（`rentalSale.ts`）も年月の形だけを読んでいた。
- 家族の年齢の行は、結婚の予定の配偶者（加わる時点のある人）を加わる前の年から出していた（画面は加わる年から）。
- 年金の受け取り開始は年金の記録の `claim` だけを読み、記録の無い人（働き方の期間からの推計）で打ち手が書く構成員の `pensionClaim`（0078）を読まなかった。受け取り開始を変えた提案のライフイベント表が「65歳」のままだった。
- 年金の章の開始の年と年額を「年金のある最初の年」と「その翌年の額」で決めていたため、特別支給の老齢厚生年金を受けている人で受け取り開始を遅らせると、特別支給の数か月分を開始の年・年額と書いた（「70歳から受け取る 年額11.8万円」など）。
- 表示の設定の「○歳時点」が本人の今の年齢より前だと、提案書の目標の年が表より前になり、目標の金融資産を0円と書いた（画面は `atAgeIn` で表の最初の年に寄せる）。
- 提案書の万一の章は、全プラン共通の前提で計算していた（プランごとの上書き〔0071〕を当てていなかった）。万一のタブでそのプランを見たときと数字が違った。
- 画面の出来事の文に、大学の系統の「医歯系」が出なかった（提案書は出る）。

## 決定

1. 帳票の部品で時点を読む所は、すべて `report/src/timepoint.ts` の `monthOfTimepoint`（計算エンジンの `time/timepoint.ts`・アプリの `workspace/timepoint.ts` と同じ決まり。年月・構成員の年齢〔年齢の切り替えの規則つき〕・名前つきの出来事〔＋ずらし〕）で解く。年月の形だけを読む関数は持たない。対象: 子の独立・加わる時点（家族の年齢の行・表の年齢の段・ライフイベント表）、働き方の期間の終わり（退職の月）、年金の受け取り開始、保険料の払込の終わり、FP顧問料の始まり・終わり・単発・料金の段階、黒字のうち貯まる割合の変わる時期、お金の3つの分け方の車の最初の購入、収益不動産の売る年の案（今の予定の売却・持ち始める月）。
2. その年に世帯にいるか（年齢を出すか）: 生まれていて、加わる年から抜ける年まで（どちらもその年を含める。アプリの `roles.ts` の `presentInYear` と同じ）。構成員の時点は提案の世帯で解く。
3. 年金の受け取り開始の月: 年金の記録があれば記録の `claim.basic`、記録が無ければ構成員の `pensionClaim.basic`（エンジンの `sdk/pension.ts` の `claimInput`・アプリの打ち手と同じ）。省略は65歳に達した月の翌月。
4. 年金の章の「受け取りの開始」の年は、受け取り開始の月の年から後で、老齢年金のある最初の年（受け取り開始が表より前なら、表の中の最初の年金の年）。年額はその翌年の額（翌年が表に無ければその年の額）。受け取り開始の比べ（65歳・70歳）も同じ決め方。特別支給の老齢厚生年金で開始の年・年額を決めない（年金の表の行には今までどおり入る）。
5. 目標の年は、本人のその年齢の年を、表の最初の年から最後の年の間に寄せる（アプリの `present.ts` の `targetYearOf` と同じ）。名前も寄せた年の年齢にする（例: 「ご本人77歳（2027年）」）。
6. 万一の章（場面・必要保障額）は、提案のプランの前提（`premiseFor`。共通の前提に、そのプランの上書きを当てたもの）で計算する。前提の注の遺族の生活費の割合も、同じ前提から出る。
7. 黒字のうち貯まる割合の変わる時期は、どの形でも解いた年で書く（「2041年から80%」）。年齢の形は「60歳から」と書いていたが、だれの年齢か分からず、年月の形と書き方が違ったので、年にそろえた。解けない時点は「途中から」。
8. 画面の出来事の文の大学の系統に「医歯系」を足す（提案書の表と同じ言い方）。

## 理由

- 時点の形は入れ方の違いで、同じ月なら帳票も同じになるべき。形ごとに読む所を足すと、新しい欄を足すたびに同じ抜けが起きるので、解き方を1つの関数にまとめ、帳票の部品の全部がそれを使う形にした。
- 年金の受け取り開始・世帯にいる年・目標の年は、画面の側に決まりがあり、提案書はそれと同じ数字・文を出す約束（帳票の行の決め方は画面の提示の値と同じ）なので、画面の決まりに合わせた。
- 特別支給の老齢厚生年金は65歳より前の別の年金で、受け取り開始（繰り下げ）の比べの対象ではない。開始の年は受け取り開始の月で決めるのが自然。

## 影響

- 計算の結果（キャッシュフロー表の数字）は変わらない。変わるのは提案書の文・出来事・年齢の表示、年金の章の開始の年と年額、目標の年の金融資産（本人が目標の年齢より年上の世帯）、万一の章の数字（万一の前提をプランごとに変えた世帯だけ）。
- 収益不動産の売る年の案は、アプリの収益不動産のタブも同じ部品を使うので、年齢・出来事の形で売る予定を入れた物件にも「5年前に売る」「5年後に売る」の案が出る。
- テスト: `report/test/timepoints.test.ts`（形ごとに同じ帳票になる）・`app/test/report-exits.test.ts`（画面と提案書の一致）。
