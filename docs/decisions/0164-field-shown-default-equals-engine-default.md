# 0164. 欄に見せる値と計算に使う値をそろえる（配偶者の退職と生活費の節目・空欄の既定の値・保障の給付の種類を年金に変えたとき）

- 状態: 採用（2026-11-08）
- 固定の強さ: 内部（世帯ファイルの形・形式の版は変えない。部品の約束の版も変えない。省略のときの値を3つの部品で直した〔改訂〕）
- 前提にする記録: 0049（生活費の人数と推定の段階。退職後の節目は本人の退職の月）、0050（貯蓄・運用のカード。併用の一時金の割合は空欄なら半分）、0059（介護・親のカード）、0080（収益不動産の取得価額の内訳と建物附属設備）、0025（持ち家の評価）、0132（欄ごとの効き目の点検）、0041（値の状態と推定の印）

## 背景

入力の効き目の点検（全部の欄を動かして、結果が正しい向き・人・年に動くかを見た）で、欄に見せている値と計算に使う値が食い違う物が見つかった。

- 配偶者の「働く最後の年齢」を直すと、世帯の生活費の「退職後」の節目が配偶者の退職の月に動いた（0049 では本人の退職の月）。配偶者が早く辞めると、生活費が増えることもあった。
- 中古の収益不動産の「建物附属設備の耐用年数」は、空欄のとき「15年」と見せるが、計算は中古の簡便法の年数（例: 8年）だった。15と打つと「見せている既定と同じ」として空欄（省略）に戻るので、15年で計算させる方法が無かった。
- 保障の給付の種類を「年金」に変えると、受け取りの始まりは契約の月（過去）のまま確定の印で残り、今年から一生分の年金が入った。死亡保障を年金に変えると、死亡保険金の額がそのまま年金の年額になった。

## 決定

### 1. 退職後の生活費の節目は、ご本人の退職だけで動かす

- 働く最後の年齢・年月を直す共通の処理（`app/src/workspace/levers.ts` の `retireAt`）は、生活費の段の節目「退職後」をご本人（`kind: self`）の退職のときだけ動かす。NISA の積立の終わりは今までどおり持ち主の分を合わせる。
- 配偶者の「働く最後の年齢」の欄の説明（ほかの値もいっしょに変える欄の説明）は「NISA の積立の終わりも、この年齢に合わせます」だけにした。
- 結果の画面の対策（働く最後の年齢）と持ち帰りの対策は、もともとご本人に当てているので変わらない。

### 2. 空欄に見せる既定の値＝エンジンが省略のときに使う値

箱でない値の欄（`plain`）の「空欄のときに見せる値」（`fallback`）は、見せている値を打つと省略に戻す決まり（同じ意味の値を二重に持たない）。このため、見せる値とエンジンの省略のときの値が違うと、計算が見せている値と違ううえに、見せている値で計算させられない。全部の欄（約100の形）を、モデル世帯と各入力項目の「＋ 足す」で足した物で、見せている値を世帯に直接書いた計算と空欄の計算で比べた（`app/test/walkthrough/field-fallback.test.ts`）。食い違った物と、そろえた側:

| 欄 | 見せていた値 | エンジンの省略 | そろえた値 | 根拠 |
|---|---|---|---|---|
| 収益不動産の建物附属設備の耐用年数（土地だけの種類の「設備の耐用年数」も） | 15年 | 法定15年、中古は簡便法 | **エンジン**（画面が簡便法の年数を見せる。15と打てば15年で計算） | 耐用年数省令3条1項2号（中古の簡便法）、0080、スキーマの説明 |
| iDeCo・企業型DC・小規模企業共済の併用の一時金（一括）の割合 | 半分 | 0（全額を年金） | **画面**（エンジンを半分にした。`account.idecoPayout` 改訂2・`account.mutualAid` 改訂3） | 0050（空欄は半分）。併用を選んだときに画面は半分を書き、受け取る額の概算も半分で出していた |
| 介護の費用の在宅か施設か（額が空欄で統計の目安を使うとき） | 在宅 | 在宅と施設を合わせた平均の月額（表の行は在宅） | **画面**（エンジンを在宅の月額にした。`care.expense` 改訂6） | 0059（見出し・目安は在宅）。表の行はもともと在宅の行で、エンジンの中でも食い違っていた |
| 持ち家の評価の「その額の時点」と「建物が完成する年」（購入の時点が空で、住み始めの出来事で決まる購入の予定） | 計算の基準の月・その年 | 購入の月（購入の時点が空なら住み始め） | **エンジン**（画面の空欄の読みを住み始めの月にした） | スキーマの説明（省略は購入の月）、0025 |

食い違っても良いとした物（見せている値を書く道が無いか、書いても同じ意味になる物）: 選択肢の「指定しない」「（世帯の）」（空の文字は書かない）、扶養・同居の欄（支えの欄の物をまとめて作る）、貸していない不動産・その他の資産の中身の「その他」（省略として書く）、内訳から出した土地の割合（見せる値を小数6桁に丸める。打つと省略に戻る）。

### 3. 保障の給付の種類を変えたときの始末

- 額の意味（一時金・年額・月額・日額）が変わる種類に変えたら、額を0円にして未入力の印を付ける（「＋ 保障」で足したときと同じ）。死亡保険金→がん一時金のように意味が同じなら額は残す。
- 年金に変えたら、受け取りの始まりを被保険者の65歳、年数（空なら）を10年にして、推定の印を付ける（個人年金保険のひな形と同じ）。入れ直せば確定になる。
- 年金から戻したら、保障の始まりを契約の月に戻し、推定の印を外す。
- 受け取りの始まりの欄に、推定の印を出す当て先を付けた。

## 理由

- **配偶者の退職で節目を動かさない**: 0049 で、退職後の水準（0.8）はご本人の年齢と退職で決める目安にした。配偶者の退職で動かすと、配偶者が早く辞めると生活費が増える逆向きの動きになる。推定の段（`livingStages.ts`）も本人の退職だけを見ているので、それに合わせた。
- **どちらにそろえるか**: 制度（法令）か設計記録で決まっている側にそろえた。設備の耐用年数は法令どおりのエンジンが正しく、画面の15年は見せ方の誤り。併用の割合と介護の場所は、設計記録と画面が同じ既定を決めていて、エンジンだけが違った（どちらも、省略のままではありえない扱い〔併用なのに全額年金〕か、エンジンの中で行と額が食い違う扱いだった）。持ち家の評価の時点はスキーマとエンジンが正しく、画面の読みが購入の時点の空を見ていなかった。
- **給付の種類を変えたら額を未入力にする**: 死亡保険金500万円を年金の年額500万円として毎年入れると、数千万〜億の誤りになる。意味の違う額は使い回さず、0円の未入力にして知らせる方が安全。年金の受け取りの始まりは、契約の月（過去）では「今年から一生分」になるので、ひな形と同じ推定にする。

## 影響

- 画面: `app/src/workspace/levers.ts`（`retireAt`）、`app/src/workspace/input/stages/work.ts`（欄の説明）、`app/src/workspace/input/stages/rental.ts`（`usedLife`・`equipmentLifeDefault`。空欄の読み）、`app/src/workspace/input/stages/housing.ts`（評価の時点の省略）、`app/src/workspace/input/stages/insurance.ts`（`refitBenefit`・受け取りの始まりの欄の当て先）。
- 部品: `engine/src/components/account.idecoPayout/index.ts`（改訂2）、`engine/src/components/account.mutualAid/index.ts`（改訂3）、`engine/src/components/care.expense/index.ts`（改訂6）。約束の版・出力の形は変えていない。
- テスト: `app/test/field-effects.test.ts`（節目・設備の耐用年数・併用の割合・介護の場所・評価の時点・給付の種類）、`app/test/walkthrough/field-fallback.test.ts`（空欄の既定の見張り。通しの入力のジョブで流す）。
- 計算の結果が変わる所:
  - 配偶者の働く最後の年齢を一度でも直した世帯は、直した後の退職後の節目が配偶者の退職の月だった（見本で −356万〜＋204万円）。これからは直しても節目が動かない。保存済みの世帯の節目は、保存したときの月のまま（自動では戻さない）。
  - 中古の収益不動産で設備の耐用年数を空欄にしている世帯は、計算は変わらない（欄の見え方だけ）。15年のつもりで15と打っていた世帯は空欄（簡便法）のままなので、打ち直せば15年になる。
  - 併用で一時金の割合が空の iDeCo・企業型DC・小規模企業共済は、全額年金→半分一時金になる。画面から併用を選ぶと半分を書くので、空になるのは前の欄で50%を打ち直した世帯だけ。
  - 介護の費用で在宅か施設かが空の世帯（画面・ヒアリングの取り込みは必ず入れるので、手で作った世帯ファイルだけ）は、額の目安が合わせた平均から在宅の平均になる。
  - モデル世帯の結果は変わらない（どれも該当しない）。
