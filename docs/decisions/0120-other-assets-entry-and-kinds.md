# 0120. その他の資産の入れ口と中身の細目（貴金属・暗号資産・会員権など）と世帯ファイルの形式 0.59

- 状態: 採用（一部未確定）（2026-11-05）
- 固定の強さ: 骨格は、その他の資産の細目 `accounts[].subtype` に足した6つの値（`preciousMetal` 貴金属・`cryptoAsset` 暗号資産・`art` 美術品や骨董品・`membership` 会員権・`securityDeposit` 敷金や保証金・`businessAsset` 事業用の資産）の名前と意味、細目の無いその他の資産を「その他」と読むこと、細目を計算に使わないこと、形式 0.59 の変換の段。欄の名前・選択肢の言葉・「?」の説明・バランスシートの行の名前と並び・箱の色・区画の置き場所は後から変えてよい（変えたら追記に書く）
- 前提にする記録: 0008 の9（資産の器）、0011（形式の版と変換の段）、0025（全資産・全負債のバランスシート）、0027（資産と負債のタブ）、0045・0077（入力のホームと「?」の決まり）、0078（標準と詳細）、0079（収益不動産の入力項目）、0105（役員として働く人の細目）、0112（固定資産税の推定）

## 背景

- 家計のバランスシート（0025・0027・0105）を正確にするには、住まい・金融資産・車・保険のほかの資産（貴金属・暗号資産・会員権・敷金など）も入れてもらう必要がある。
- 今までは「貯蓄・運用」の区画「その他の資産」（器の種類 `realEstate`＝貸していない不動産、`otherAsset`＝その他の資産）で入れられたが、何も入れていない世帯では区画が詳細の欄に隠れ、標準の入れ方では入口が見えなかった。中身の種類も選べず、資産と負債のタブ・提案書のバランスシートでは、どれも「その他の資産」の1行にまとまっていた。
- 細目 `subtype` は役員として働く人の自社株（出資額）・会社への貸付金（0105）だけだった。
- 利用者の判断: 住まい以外の資産を入れやすくする。補足的な機能なので、大げさにしない（入力項目を増やしすぎない。何も入っていない世帯で画面がうるさくならない）。

## 決定

### 1. 入口: 貯蓄・運用の中で隠さず見せる（入力項目は足さない）

- 独立の入力項目にはしない。今の入力項目は16（0079 で収益不動産を足した）で、見出しで区切る数（16）に届いている。その他の資産は1世帯に数件で、欄も評価額・時点・増減率だけなので、収益不動産のように物件ごとの欄と一覧表が要る物ではない。0045 の「1つの物は1つのカード」と、0077 の「画面に常に出すのは名前・値・印・操作の名前まで」に合わせて、貯蓄・運用の中で見せる。
- 区画「その他の資産」を、何も無い世帯でも**標準で出す**（今までは物があるか役員がいる世帯だけ標準）。何も無いときは、見出し（説明は「?」の中）と足すボタン2つだけ:「＋ 貸していない不動産（土地・別荘など）」「＋ その他の資産（貴金属・会員権など）」。足すボタンも標準で出す（今までは詳細だけ）。
- 貯蓄・運用の説明の文（パネルの見出しの下）に「貸していない不動産・貴金属などのその他の資産も。」を足した。
- 入力のホームの貯蓄・運用のカード: 不動産・その他の資産を入れていれば、要約の下の小さな1行に「うち不動産・その他の資産 ○万円」を出す（入れていなければ出さない）。要約の額は今までどおり両方を含む。
- 探して開く（`searchWords.ts`）: 金地金・プラチナ・絵画・骨董品・コレクション・ビットコイン・会員権・ゴルフ会員権・リゾート会員権・敷金・保証金・差入保証金・事業用の資産をその他の資産へ、山林・農地・田畑を貸していない不動産へ足した。

### 2. 中身の細目

- その他の資産（`otherAsset`）のまとまりに、欄「中身」（入力項目ID `account.subtype`。標準）を置く。選択肢は「貴金属（金・プラチナなど）」「暗号資産（ビットコインなど）」「美術品・骨董品」「会員権（ゴルフ・リゾートなど）」「敷金・保証金」「事業用の資産（設備・在庫など）」「その他」。
  - 「その他」は細目を書かない（`subtype` が無い）。今までのその他の資産は、そのまま「その他」になる。値 `other` は世帯に書かない。
  - 選んだ中身の説明（評価額の入れ方の目安）を欄の「?」に出す。まとまりの見出しは中身の短い名前（「貴金属（ご本人）」など）。
  - 種類を「その他の資産」から変えたら、細目を外す（細目は種類 `otherAsset` だけ）。
- 役員の細目（自社株〔出資額〕・会社への貸付金。0105）はこの欄に出さない。役員の細目の器は今までどおり、種類と中身の欄を出さず、名前が細目で決まる。
- 役員の区画の「その他の資産（○件）」の件数は、役員の細目だけを数える（中身の細目を数えない）。

### 3. バランスシートの行

- 分け方の部品（`report/src/bsGroups.ts`）: その他の資産の器は、細目ごとの換金しにくい資産の項目にする（同じ細目は1つの項目にまとめる）。項目の名前は「貴金属」「暗号資産」「美術品・骨董品」「会員権」「敷金・保証金」「事業用の資産」、細目の無いもの・知らない細目は「その他の資産」。並びは車・保険の解約返戻金の後に、中身の6つ → その他の資産 → 自社株（出資額）・会社への貸付金。4つの分け方と足し算は変えない（額はエンジンの行のまま）。
- 同じ部品を使う所（資産と負債のタブ・提案書のバランスシートの図・お金の3つの分け方）は、そのまま中身ごとになる。提案書の図の箱は今までどおり「車・その他」にまとめる。
- 提案書の年の抜粋の表と「基本項目」の現状のバランスシート（`report/src/build.ts` の `sheetOf`）も、世帯を渡して同じ名前の行に分ける（今までは役員の細目も含めて「その他の資産」の1行だった）。世帯を渡さない呼び方（現状の純資産を出すだけの所）は今までどおり1行。
- 資産と負債のタブの箱の色は、中身ごとに灰色がかった青の仲間で明るさを交互にした（`app/src/styles/balance.css`。白い文字との差はどれも 5.8:1 以上）。

### 4. 計算は変えない

- 細目は表示とバランスシートの行の名前だけで、計算部品は読まない。評価額・時点・増減率（`valueGrowth`。入れなければ評価額のまま）、金融資産に入れないこと、取り崩さないこと、時価の下落（ストレステスト）の対象から外すこと、相続税の目安でその他の資産として額のまま数えること（0039）は、細目で変わらない。
- 計算エンジンの部品と改訂は変えない。入力のスキーマ（`engine/schemas/engine.input.json`）の `subtype` の値の一覧に6つを足しただけ。

### 5. 世帯ファイルの形式 0.59

- 細目の値を足したので、形式の版を `0.59` に上げた（0011 の5。足すだけの MINOR）。前の版のアプリは入力の検査で知らない細目を通さないので、版を上げて閲覧だけにする。変換の段（0.58 → 0.59）は形式の版だけを書き換える（前の世帯のその他の資産は細目なし＝「その他」のまま）。
- 見本 `crates/household-store/tests/fixtures/household-format/0.59/` は、0.58 の見本に、中身の細目6つの器（1件ずつ）と細目の無い器を足した物。

### 6. 合わせた所・合わせなかった所

- AI に渡す縮約版の許可の一覧（0015）: `account.subtype` は 0105 で入れてあり、値は決まった一覧の記号（文章ではない）なので、一覧も版も変えない。
- ヒアリングシート: シートにその他の資産の欄が無い（役員の自社株・貸付金の欄だけ）。欄を足すとシートの版が上がるので、この記録では足さない（未確定）。
- 入力項目ID の登録簿（`registry/items.yaml`）の `account.subtype` の名前に、足した細目を書き足した。

## 理由

- **入力項目を足さず、区画を標準で出す**: 入口が見えないことが問題で、入力項目が足りないのではない。何も無い世帯でも見出しと2つのボタンだけなので、画面は重くならない。入力のホームのカードを1枚増やすより、FP が貯蓄・運用を入れる流れの中で目に入るほうが書き漏れが減る。
- **細目を表示だけにする**: 中身ごとの値動き・税は物ごとに大きく違い、目安の数字で一律に動かすと根拠を示しにくい。増減率は FP が入れられるので、まず見分けられるようにすることを先にした。
- **「その他」を細目にしない**: 今までの世帯をそのまま読めて、同じ意味の書き方が2つにならない。
- **バランスシートの行を細目ごとに分ける**: 顧客に家計の全体を説明するとき、「その他の資産」の1行では中身が伝わらない。同じ部品で分けるので、タブ・図・表の名前と額は必ずそろう。

## 代案（採らなかったもの）

- 入力項目「その他の資産」を独立させる（収益不動産と同じ形）: 上の理由。物件ごとの欄・一覧表の要る収益不動産と違い、欄が少なく、入力項目を増やすほどの量が無い。
- 細目ごとに既定の増減率を置く（貴金属は物価上昇率、会員権はマイナスなど）: 根拠を示せる数字が無く、計算の結果が黙って変わる。
- 細目に `other` を足す: 今までの細目の無い器と意味が重なる。

## 影響

- 画面: `app/src/workspace/input/stages/savings.ts`（区画の見せ方・中身の欄）・`labels.ts`（中身の一覧）・`items.ts`（カードの1行）・`searchWords.ts`・`stages/work.ts`（役員の件数）・`styles/balance.css`、`app/src/workspace/store/body.ts`（形式の版）。
- 帳票の入力: `report/src/bsGroups.ts`・`build.ts`。中身の細目を入れた世帯と役員の細目のある世帯では、年の抜粋の表のその他の資産が中身ごとの行に分かれる（合計・純資産は変わらない）。
- 本体: `crates/household-store/src/migrate.rs`（0.59 の段）と見本。
- モデル世帯の計算の結果は変わらない（細目は計算に使わない。テストで細目を全部入れ替えても表が同じことを確かめる）。

## 調べたこと（作っていない。案と、作ったときに計算の結果が変わる所）

### 1. 貸していない不動産（別荘・土地・空き家）の固定資産税・管理費などの支出

- **今の扱い**: 中身 `property` の無い不動産の器（貯蓄・運用の「貸していない不動産」）は、評価額（`valueGrowth`、入れなければ前提条件の不動産の利回り）だけで、毎年の費用を入れる欄が無い。計算エンジンも何も払わない。FP が入れるなら、ライフイベントなどの出るお金の行（その他の支出・毎年）で手で入れるしかなく、物件とつながらない（売った・手放した後も払い続ける）。
- 0112 の固定資産税の推定は、住まいの持ち家（購入の予定と今住んでいる家。欄は `residences[].propertyTax`）だけ。収益不動産の経費の費目 `propertyTax` への推定は 0112 の未確定のまま。
- エンジンは、中身を持つ不動産の器なら、貸していなくても（`rental` が無くても）経費の年額・費目（`property.expenses.items.propertyTax`・`management` など）を持っている間払う。ただし画面は「中身を持つ不動産の器＝収益不動産」（0079 の骨格）と読むので、貸していない物件で使うと収益不動産の項目に移り、家賃が未入力の印で始まる。
- **案**（自然な順）:
  1. 貸していない不動産のまとまりに「毎年かかる費用（固定資産税・管理費など）」の年額の欄を1つ置き、出るお金の行（物の ID でその器を指す）として持つ。手放す予定を入れたら、その月で止める。計算エンジンは変えない（固定資産税を計算しない 0112 の骨格のまま）。
  2. 目安のボタン: 0112 の式（`propertyTax.ts`）を流用し、評価額×土地の割合×土地の評価額の割合（70%）×1.4%＋建物×建物の評価額の割合（60%）×1.4%、都市計画税は 0.3% を上限に。住宅用地の特例（1/6・1/3）は、空き家（住宅が建っている）には当て、別荘（特例の対象外）と更地には当てない。中身の種類（土地・別荘・空き家）を選ぶ欄が要る（今は無い。足すなら形式の版を上げる）。管理費（別荘地の管理費・空き家の管理委託）は目安を置かず FP が入れる。
- **計算の結果が変わる所**: 費用の分だけ毎年の支出（その他の支出）が増え、金融資産が減る（資産が尽きる年が早まることがある）。バランスシートの評価額は変わらない。目安を推定で入れるので、何も入れていない世帯の結果は、FP が欄を開いて目安を押すまで変わらない。

### 2. その他の資産・貸していない不動産を売る時期・手取り・売ったときの税

- **その他の資産（`otherAsset`）**: 売る時期の欄が無い。評価額は計算の最後まで残る（増減率で動くだけ）。売る予定は、FP が入るお金の行（「動産の売却（車以外）」＝課税の扱いは非課税）で手取りを入れるしかなく、器の評価額も残るので、バランスシートでは二重に数える。税は計算しない。
  - 実際の税: 貴金属・美術品・会員権の売却は総合課税の譲渡所得（5年を超えて持つと長期で2分の1、譲渡所得の特別控除50万円）。暗号資産の売却は雑所得。事業用の資産は事業所得か譲渡所得。敷金・保証金は返ってくるだけで課税しない。生活に使う動産は非課税だが、1個（1組）30万円を超える貴金属・美術品などは課税（所得税法9条1項9号・施行令25条）。
  - エンジンの入るお金の課税の扱いには、分離課税の譲渡所得（一般株式等の税率。事業・出資持分の売却）・一時所得・雑所得・非課税はあるが、**総合課税の譲渡所得**（長期の2分の1・50万円の特別控除）の区分が無い。「動産の売却（車以外）」の説明は貴金属・美術品を挙げて非課税の扱いなので、30万円を超える物の扱いを説明に書き足す必要がある。
- **貸していない不動産（中身の無い `realEstate`）**: 売却の欄が無く、評価額は最後まで残る。「収益不動産へ移す」で中身を持たせれば、売却の予定 `property.sale`（時期・価格〔省略はその年の評価額〕・費用の割合〔省略は4%〕）から手取りを一時金の収入にし、評価額をその年から消し、土地建物等の分離課税の譲渡所得の税（`tax.realEstateSale`。取得の入力が無ければ概算取得費5%・長期とみなす）を計算する。ただし収益不動産として扱われ、貸していない期間の建物の減価（非業務用の償却）を取得費から引かない知らせが出る。
- 住まいの持ち家は、住み終わりの「売る」・売却価格・譲渡所得の税の額の口（`sale.tax`）がある（0025・0052・0053）。
- **案**:
  1. その他の資産と貸していない不動産のまとまりに「売る予定」（時期・売却の価格〔省略はその年の評価額〕・売却の費用の割合・税の額）を足す。税はまず住まいと同じ**額の口**（FP が額を入れる。0053 の形）にし、総合課税の譲渡所得の計算は後にする。計算エンジンの変更（`plan.cashflow` の器の評価額をその月で止め、手取りを一時金の収入の新しい行に出す。部品の改訂と行の追加）と、世帯ファイルの形式の版が要る。
  2. 貸していない不動産は、中身 `property` の「貸さない」形（`rental` の無い中身）を貯蓄・運用に置いたまま使えるようにすれば、エンジンの今の売却・譲渡所得の税・年の経費（調べの1）がそのまま使える。ただし「中身を持つ＝収益不動産」の読み方（0079 の骨格）を「家賃 `rental` を持つ＝収益不動産」に変えることになるので、利用者の判断が要る。
  3. 「動産の売却（車以外）」の説明に、30万円を超える貴金属・美術品は課税（譲渡所得）になることと、その他の資産に入れた物を売るときは評価額を外すことを書き足す（すぐできる。文だけ）。
- **計算の結果が変わる所**: 売る年に手取りが金融資産に入り（資産が尽きる年が延びることがある）、その年から評価額が消える。純資産は売却の費用と税の分だけ下がる（評価額と売却の価格の差も動く）。税（額の口・譲渡所得）は翌年の支出に出る。売る予定を入れない世帯の結果は変わらない。
