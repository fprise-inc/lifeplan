# 0163. 外した物を指す欄の片付けと、指す先の無い欄の知らせ

- 状態: 採用（一部未確定）（2026-11-08）
- 固定の強さ: 内部（片付けの決まり・欄の一覧・画面の言葉）。計算エンジンの知らせ `N_INPUT_REQUIRED` の ID の形 `reference.<欄>` は、エンジンの出力の知らせの ID の決まり（0005 の8・0064）のまま。部品 `retirement.benefit` は改訂3（約束の版 1.0 のまま）。世帯ファイルの形式の版は変えない
- 前提にする記録: 0004（ID 体系）、0008（世帯のデータモデル）、0036 の8（外したときの連鎖）、0046（家族のカード）、0064（計算の知らせ）、0150（退職給付の既定の勤め先）

## 背景

- 世帯の物（人・働き方の期間・口座・保険・ローン・住まい・退職金・お金の行・出来事）は ID で互いを指す。物を「外す」操作は、外す物そのものと、その物の持ち主の物（人の口座・保険など）は一緒に外していたが、外した物を**指す欄**の片付けは操作ごとにばらばらだった。
- 入力の効き目の点検で、次が見つかった。
  - 死亡保険金の受取人になっている配偶者を外すと、受取人の欄に配偶者の ID が残り、計算エンジンが `E_ARGUMENT household.member` で止まる。止まらない世帯でも、持ち家の名義と持分に外した人の持分が残る。子を外すと、休業の対象の子・育児の短時間勤務の子・必要保障額の対象の人なども同じく残り、計算が止まる。
  - 働き方の期間を外すと、その期間を勤め先にしていた退職金は、勤め先が見つからないので受け取る時期が決まらず、計算エンジンが知らせなしに払わない（見込み額は入力に出たまま、表は0円）。同じ人に働き方を足し直しても、勤め先は外した期間を指したまま。
  - 持ち家を外すと、住宅ローンの住まいの欄が外した家を指したまま残る。
- プランを直すときは、外した物を指す物を並べて一緒に外すかを選ぶ（0036 の8）が、選ばなかった物の欄は指したまま残る。現状を直すときは、この確かめも無い。

## 決定

### 1. 物の ID を指す欄を1か所にまとめる（`app/src/workspace/input/refs.ts`）

- 計算エンジンの入力のスキーマで物の ID を指す欄（`id` の欄を除く）を全部、欄ごとの片付けの決まりと一緒に1か所に書く（`refSites`）。スキーマの欄の一覧（`SCHEMA_REF_FIELDS`）とスキーマを突き合わせるテストを置き、欄が増えたら決まりを決めないと通らないようにする。
- 片付けるのは「その操作で無くなった物」を指す欄だけ。前から指す先の無い欄は触らない（下の 3 の知らせで出る）。片付けで外れた物を指す欄も続けて片付ける（人を外す → その人の口座 → その口座への移し替え、など）。
- 欄ごとの決まり（主な物）:

| 欄 | 指す先が無くなったら |
|---|---|
| 死亡保険金の受取人 | その人の行を外し、残りの受取人で割合を分け直す（外す前の合計に合わせる。例: 配偶者50%・子50% → 子100%）。残りが無ければ受取人を省く（エンジンの既定: 死亡の当時の配偶者、いなければ子） |
| 持ち家の名義と持分・住宅ローン控除の持分 | 同じく分け直す（夫婦の共有から配偶者を外すと、ご本人100%）。名義の人が誰もいなくなったら、ご本人100%（新しい持ち家の既定と同じ） |
| 満期金・年金の受取人、介護の払う人、お金の行の受け取る人・払う人・相手、援助の贈与する人、休業の対象の子、贈与者の家族の続き | 欄を空にする（どれも省略に意味がある欄） |
| 育児の短時間勤務の子 | 短時間勤務の欄ごと外す（子は欠かせない欄） |
| 保障の被保険者（家族特約など） | その保障ごと外す。年次の数表の、その保障の行も外す |
| 教育ローンの借り手、住宅資金の援助を受け取る人、移し替えの元・先、取り崩しの順序の口座、万一の想定・働き方の置き換え・収入の減り方の人 | その行ごと外す |
| 団信の対象の人・必要保障額と相続税の目安の対象の人 | 並びから外す（団信は対象が無くなったら団信の欄ごと外す） |
| 人の年齢・外した出来事で決めた時点 | 外す前の世帯で解いた年月に直す（0038。今までの「人を外す」と同じ） |
| 退職金の勤め先、住宅ローンの住まい、不動産の借入の不動産（指す先に付いている物） | 欄を空にする（退職金・ローンそのものは残す）。下の 2 のとおり、操作の中ではなく、連鎖の確かめの後に |
| 住宅ローン控除の入居（出来事） | 片付けない（出来事は、指されている間は外せない） |

### 2. いつ片付けるか

- **ボタンの操作の中**（段の組み立て `buildStage` が、どのボタンの操作も包む。人を外す `removeMember` も同じ）: 指す先に付いている物の欄（dependent）を除いて片付ける。人を指す欄は全部ここで片付くので、操作だけの世帯でも計算は止まらない。
- **入力のパネルが書き込むとき**: 現状を直すときは、そのまま全部（dependent も）片付ける。プランを直すときは、外したときの連鎖の確かめ（0036 の8。持ち家 → その住宅ローンなど）で一緒に外す物を選んだ後に、残った欄を片付ける（dependent を操作の中で片付けると、連鎖の確かめに出なくなるため）。
- 現状を直すときに連鎖の確かめ（一緒に外す物を選ぶ画面）は出さない。持ち家を外しても住宅ローンは残し（住まいの欄だけ空にする）、ローンは住まい・ローンのカードで外す。

### 3. 指す先の無い欄は、計算エンジンが知らせる

- 古いファイル・取り込み・ほかの道で指す先の無い欄が残ったときのため、計算エンジンは、指す先が無いと黙ってその欄が無いものとして計算する欄（退職金の勤め先、ローンの債務者・団信の対象・持分、借入の不動産・ペアの相手、保障の被保険者・数表の保障、お金の行の人・つながる物、教育・目標の子、車の持ち主、顧問料を払う人、取り崩しの順序の口座など）を、`N_INPUT_REQUIRED`（ID は `["reference.<欄>", 欄を持つ物の ID]`）で知らせる。重ねる前の入力（FP が入れた世帯）で見る。人を指す欄のうち計算の前提になる欄（働き方の期間・口座・保険の当事者・関係など）は、今までどおり `E_ARGUMENT` で止める。
- 画面（`engineNotices.ts`）は「外した物を指したままの欄があります…」の1行を、入るカードごとにまとめ、欄の名前を内訳にする（入力が足りない所）。
- 退職給付の部品（`retirement.benefit` 改訂3）: 受け取る時期が決まらない（受け取る時期・勤続期間が無く、勤め先の期間が無いか終わりが無い）一時金・年金は、黙って払わずにいたのを、`N_INPUT_REQUIRED`（`retirementBenefit.paidAt`）で知らせる。金額は今までと同じ。

### 4. 退職金の勤め先

- 受け取る時期の欄は、空欄でも勤め先の期間の終わり（か勤続期間の終わり）が無く受け取る時期が決まらないときは、未入力の印にする（標準に上がる）。
- 働き方を足したとき（今の働き方を入れる・働き方の期間を足す）、その人の勤め先の無い退職金（勤め先が指す先の無い物と、勤め先も勤続期間も受け取る時期も無い物）を、退職給付を足すときと同じ既定の勤め先（0150 の `benefitPeriod`）に付ける。外して入れ直すと、退職金は足した期間を勤め先にして元の額で戻る。

## 理由

- 指す欄の一覧を1か所に置けば、外す操作を足すたびに片付けを書き足さなくてよく、スキーマとの突き合わせで欄の見落としも見張れる。操作ごとに片付けを書く形（今までの形）は、受取人・持分・休業の子のように書き漏れた所から止まっていた。
- 「その操作で無くなった物」を指す欄だけを片付けるので、前から指す先の無い欄を勝手に書き換えない（知らせで FP に見せる）。
- 割合の欄を残りで分け直すのは、外した人の分がどこへも行かない（合計が100%にならない）形を残さないため。受取人の割合はエンジンでは比で分けるので、計算の結果は分け直しても同じ。
- 指す先に付いている物（住宅ローン・退職金）を外すかは FP が決めることなので、勝手に外さない。プランでは今の連鎖の確かめに任せ、現状では欄を空にして残す。
- エンジンが知らせるのは、片付けを通らない道（古いファイル・取り込み）でも、黙って結果が変わる形を残さないため。止めない（`E_ARGUMENT` にしない）のは、今まで計算できた世帯を開けなくしないため。

## 代案（採らなかったもの）

- **エンジンが指す先の無い欄をすべて `E_ARGUMENT` で止める**: 古い世帯ファイルが開けなくなる。
- **外す前に、付け替える先を毎回聞く**: 受取人・持分・お金の行の相手など、ほとんどの欄は空にするか分け直すかで決まり、毎回の確かめは多すぎる。指す先に付いている物だけは、プランを直すときの連鎖の確かめで今までどおり選ぶ。
- **働き方の期間を外したら、同じ人の残りの期間に退職金を付け替える**: 別の勤め先の退職金になりうる。空にして未入力の印と知らせを出し、働き方を足したときだけ既定の勤め先に付ける。

## 影響

- **画面**: 入力のパネルの書き込み（`InputPanel.tsx`）、段の組み立て（`stages/index.ts`）、家族を外す（`stages/family.ts`）、働き方を足す（`stages/work.ts`・`fill.ts` の `adoptBenefits`）、退職金の受け取る時期の欄（`stages/retirement.ts`）、計算の知らせの文（`engineNotices.ts`）。
- **計算エンジン**: `engine/src/engine/refs.ts`（指す先の無い欄の知らせ）、`retirement.benefit` 改訂3（知らせだけ。金額は同じ）。
- **計算の結果**: 人を外した後に計算が止まっていた世帯は計算できるようになる。持ち家の共有から配偶者を外した世帯は、持家の評価額・住宅ローン控除の持分がご本人100%になる。働き方を外して入れ直した世帯は、退職金が元の額で戻る。外していない世帯の結果は変わらない。
- **世帯ファイルの形式**: 変えない。
- **テスト**: `app/test/remove-refs.test.ts`（受取人・持分・退職金の再現、見本の全世帯で全部の「外す」の後に指す先の無い欄が増えないことと計算が止まらないこと、スキーマとの突き合わせ、エンジンの知らせ）。

## 未確定

- 現状を直すときにも、持ち家 → 住宅ローンのような指す先に付いている物を、一緒に外すかを確かめる画面を出すか（今は欄を空にしてローンを残す）。
- 離婚などで配偶者を外したときの死亡保険金の受取人を、世帯の外の受取人（元の配偶者）として残す形（今は外して残りで分け直す）。関係の終わりの名義の物の選び方（0046 の未確定）と合わせて決める。
- 画面の側の、物の ID を鍵にした値（ローンの入れ方・呼び名・確かめた記録など）の片付け（計算には使わない）。
