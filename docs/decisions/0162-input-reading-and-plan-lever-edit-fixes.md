# 0162. 入力の欄の読み取りの直し（時点の欄の人・終わりと始まり・生年月の範囲と日つき・割合の欄の範囲・率の全角）と、既定の値の欄の確定・プランの対策で動かした欄の直し

- 状態: 採用（一部未確定）（2026-11-08）
- 固定の強さ: 内部（画面の欄の読み取り・言葉・プランの差分の作り方。後から変えてよい。変えたら追記に書く）。既定の値の欄の確定に値を書くこと（2）は 0041「確定は明示の操作だけ」の読み方。世帯ファイルの形式の版・計算エンジンは変えない
- 前提にする記録: 0038（時点の部品）、0041（値の状態の操作）、0098（率の欄の範囲）、0131（欄の読み取り）、0145（既定の値の推定の印）、0150（推定と同じ値を打っても確定）、0036（プランの差分）・0043（入力の画面でプランを直す）

## 背景

画面を実際に触る点検と、最近取り込んだ変更の組み合わせの点検で、次のことが分かった。

- 時点の欄で、横の「誰の年齢で」で人（例: 第3子）を選んでから年齢を数字だけ打つと、選んだ人でなく欄の既定の人（ご本人など）の年齢として読んだ。手当・養育費の終わりが黙って過去になり、手当が1円も入らなかった。欄の部品が読み取りに渡す物差しの人が、欄の既定の人のままだった。
- 終わりが始まりより前の期間（入るお金・出るお金・住まい・保険の保障など）を、注意なしに保存できた（その期間は計算に入らない）。
- 既定の値で埋まる欄（収益不動産の土地の割合・建物が建った年・売却の費用など。0145）を「この値にする」・推定と同じ値を打つ（0150）・推定の値をまとめて使うで確定にしても、確定の行だけを書き、値は省略のままだった。既定の元（前提条件の不動産の評価・物件の取得の年月）を直すと、確定の印のまま値がついていった（土地の割合が 30% から 50% に変わり、減価償却・税・評価額が変わるなど）。
- プランで、結果のタブの対策（生活費・働く最後の年齢・年金の受け取り開始など）で動かした欄を、入力のパネルで打ち直しても、対策が欄の差分の後に当たって打った値を上書きし、黙って前の値に戻った。
- ご本人の生年月に未来の年月を入れられ、結果に「-1歳で不足」が出た。生年月日を日つき（1980-02-29・昭和55年2月29日）で打つと受け付けなかった。
- 収益不動産の空室率・持分に 100% を超える値を入れられた（一覧は「月の収入 ▲1.6万円」、計算は 100% と同じ）。
- 事務所の既定値の画面の率の欄が全角の数字を読まなかった（同じ画面の額の欄は読む）。入力の画面の率の欄は全角の数字は読むが、全角の「％」を読まなかった。

## 決定

### 1. 時点の欄は、選んでいる人の年齢で読む

- 打った文字を読む物差し（`when.ts` の `typingCtx`）の人は、横の「誰の年齢で」に見せている人（今の時点が年齢の形ならその人、ほかは欄の既定の人）にする。「20」と打つと選んでいる人の20歳。人の名前を書いて打てば（「第1子20歳」）、書いた人。欄に見せる文字（人の名前を添えるか）は今までどおり欄の既定の人で決める。
- 時点の部品を使う欄はすべて `FieldViews.tsx` の `WhenField` を通るので、人を選べる時点の欄の全部に効く（見本の棚の全部の世帯の、人を選べる時点の欄で確かめる。`test/input-reading-fixes.test.ts`）。

### 2. 既定の値で埋まる欄を確定にしたら、その値を書く

- `defaultMark.ts` の欄の、同じ値の確かめをしない書き方（`write`。値の状態の操作が使う）は、空でない値なら既定の値と同じでも世帯に書く。「この値にする」・推定と同じ値を打つ・推定の値をまとめて使うのどれでも、確定にした値を世帯に持つ。既定の元を直しても、確定した値は変わらない。
- 欄を空にすると、値を外して既定の値の推定に戻る（前は確定の行が残って推定に戻らなかった）。
- 値の箱でない推定の欄で「この値にする」を押すと欄の当て先に値が入ることを、見本の棚の全部の世帯・全部の入力項目で確かめる（当たっていたのは `defaultMark.ts` の欄だけ）。

### 3. プランで対策が動かした欄を直したら、打った値をプランの中身にする

- 入力の画面でプランを直したとき（`planEdit.ts` の `recordPlanEdit`）、直した所のうちプランの中身でまだ打った値になっていない所を動かしている対策について、
  1. 対策の値を、直した後の中身から読んだ値にする（このプランの対策なら直す。土台のプランの対策なら、このプランで同じ対策を上書きする。土台のプランは変えない）。対策の値で打った値になり、ほかの所が崩れなければこれで決める。同じ所の欄の差分は作らない（違いの一覧に同じ変更を2行出さない）。
  2. 対策の1つの値で言えない形（退職後の生活費の始まりだけを動かす・基礎と厚生の受け取り開始を別々にするなど）なら、このプランの対策を外し、外した後の違い（働き方の期間の終わりなど、対策が動かしていた所も）を欄の差分にする。プランの中身は打った後のまま。
- 決めたこと: 欄を読み取り専用にして「対策を外すと直せます」と出す案もあったが、入力の画面で直せる方が FP の手間が少なく、対策の値を直すだけで済む場合が多いので、打った値を勝たせる。

### 4. 終わりが始まりより前を止める・知らせる

- 始まりのある終わりの欄（`ctx.start`）に、始まりより前の時点を打ったら、理由を出して書かない（「終わり（2020年4月）が始まり（2026年11月）より前です。始まりの月か、それより後の時点を入れてください」）。同じ月は1か月の期間なので入れられる。
- すでに入っている終わりが始まりより前なら、欄の下と確かめの一覧（確かめの注意）に「この期間は計算に入りません。終わりを直してください」を出す（`form.ts` の `timepointField` の始まりの場所 `startPath` を持つ欄）。

### 5. 生年月の範囲と日つきの入れ方

- 家族の生年月（これから生まれる子を除く）は、今月まで・120歳まで（年月の欄の範囲 `earliest`・`latest`）。今月より後は「これから生まれる子は、家族の『＋ これから生まれる子』で足します」と出して書かない。
- 年月の欄に日つき（1980-02-29・1980/2/29・1980年2月29日・昭和55年2月29日・S55.2.29）を打ったら、日を落として年月で入れ、「1980年2月として入れました（日は入れません）」と知らせる。生年月の欄で1日なら「1日生まれなら、詳細の『1日生まれ』をオンにしてください」（決めたこと: 1日生まれの印は年金・定年の時期を1か月動かすので、自動では付けず知らせるだけにする）。ありえない日（平年の2月29日・2月30日・6月31日）は理由を出して止める。
- 書類の読み取りとヒアリングの取り込みの年月の読み方（`parseYearMonth`）は変えない（日つきの読み取りは別の関数 `parseDatedYearMonth`）。

### 6. 割合の欄の範囲と、率の全角

- 収益不動産の空室率・持分・売却の費用と、前提条件の不動産の評価の売却の費用は 0〜100%（0098 の範囲の決まり。範囲の外の値が古い世帯に入っていれば、欄の下で知らせる）。
- 率の欄は、どの画面も全角の数字・小数点・マイナス（－・−・ー）と「％」を読む（入力の画面の `rateFromPct`、事務所の既定値の `pctToRate`、事務所の推定の値の `parseNumber`。どれも `units.ts` の `normalizeNumberText` で半角にしてから読む）。

## 理由

- 欄の横に見せている人と、打った数字を読む人が違うと、FP は気づけない（画面には「第3子」と出ている）。
- 確定は FP が値を決めたこと。値を書かずに印だけを付けると、確定の印のまま値が変わり、0041 の「確定は明示の操作だけ」に反する。
- プランの入力の画面は、プランの中身を直す所（0043）。打った値が黙って消えるのは、保存が壊れるのと同じ。
- 範囲の外・ありえない日・終わりが始まりより前の値は、入れ間違いなので、打ったときに止めるのがいちばん手間が少ない。

## 影響

- 計算の結果: 今の世帯をそのまま開いて計算した結果は変わらない（値を書き換えない）。次の操作をした世帯だけ変わる。
  - 時点の欄で人を選んでから年齢を数字だけ打った世帯（前はご本人などの年齢になっていた。手当なら月額×年数が入るようになる）。
  - 既定の値の欄を確定にしてから既定の元を直した世帯（前は確定した値から黙って変わっていた）。
  - プランで対策が動かした欄を入力で直した世帯（前は打った値が消えていた）。
- 世帯ファイル: 既定の値の欄の確定は、値と確定の行を持つ（前は行だけ）。前の版で行だけを持つ欄は、開いても書き換えない（値は既定の値のまま、印は確定。打ち直すか空にすると直る）。
