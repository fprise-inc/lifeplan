# 0106. 基本生活費の内訳: 迷いやすい物の入れ先・内訳から仕送りを外す・合計の行・目安からほかの入力項目の物を除く・答え合わせの説明・「年1回・数年に1回の支出」

- 状態: 採用（2026-11-01）
- 固定の強さ: 内部（世帯ファイルの形式・エンジンの入力は変えない。内訳の値 `allowance` は前の世帯のために残す〔0100 の骨格のまま〕）。説明の文・並び・合計の行の見せ方・知らせの文は後から変えてよい。統計の目安の値は 0007 の決まり（rev を足し、前の rev に `supersededIn`）で直す

## 背景

- 基本生活費の内訳（0048 の2・0100）の「?」には、どの内訳に何が入るかの説明が無く、仕送り・保険料・車の費用・習い事など、ほかの入力項目で入れる物をどこに入れるか迷いやすかった。
- 内訳には「仕送り」（`allowance`。推定は0円）があったが、仕送りは子ども・教育（在学中の自宅外の仕送り）・家族（離れて暮らす子）・介護・親（親への仕送り）の入力項目で入れる物で、両方に入れると二重に数えていた。
- 内訳の合計は、まとまりの「?」の中に「合計 月○万円」と書くだけで、画面には出ていなかった。
- 内訳の推定（家計調査の同じ人数の世帯の平均。0100 の2）には、仕送り金と家庭用耐久財のほかにも、アプリでほかの入力項目・ひな形で入れる物が残っていた。欄の説明は「ほかの入力項目で入れる物と少し重なることがあります」と断っていたが、重なりそのものは直していなかった。
- 「実際に貯められている額」（答え合わせ。0008 の追記の現状の検算）の欄の説明は、入れると何が起き、何が確かめられ、入れないとどうなるかを書いていなかった。
- 前提にする記録: 0007（制度の値・統計の形）、0008（世帯のデータモデル・推定・現状の検算）、0031（黒字のうち貯まる割合）、0041（値の状態）、0044（お金の行）、0048（基本生活費の入力項目）、0049（生活費の段階）、0100（内訳の10費目）。

## 決定

### 1. 内訳のまとまりの「?」に、推定の作り方と迷いやすい物の入れ先

- まとまり「内訳（月額）」の「?」の始めに、推定の作り方（同じ人数の世帯の平均から、ほかの入力項目で入れる物を除いた額）と、迷いやすい物の入れ先を箇条書きで書く（`stages/living.ts` の `CATEGORY_GROUP_HELP`）。入れ先は、アプリにある入力項目と、統計の区分（下の2の表）に合わせた:
  - 子の下宿・一人暮らしへの仕送り → 子ども・教育（在学中）、家族（在学でない子）
  - 親への仕送り・介護の費用 → 介護・親
  - 生命保険・医療保険・火災保険などの保険料 → 保険
  - 家賃・住宅ローン・管理費・修繕積立金・固定資産税 → 住まい・ローン
  - ガソリン・駐車場・自動車税・車検・車の保険、通勤・ふだんの高速代 → 車
  - 学費・給食費・塾・子の習い事・保育料 → 子ども・教育
  - 家電・家具・スマホ・パソコンの買い替え、ペットの病気・けが、年払いの物 → この入力項目の「年1回・数年に1回の支出」
  - 結婚・葬儀・お墓 → ライフイベント
  - ネット回線 → 通信費、新聞・NHK受信料・ペットのえさ・ペット保険、旅行の高速代 → 趣味・娯楽、たばこ → その他
- 「?」の中の文は、改行で区切った行のうち「・」で始まる行を箇条書きに、ほかの行を段落にする（`FieldViews.tsx` の `helpBlocks`。欄・まとまり・区画の「?」のどれも）。
- 各内訳の欄の説明も、直した目安の中身に合わせて書き直した（「重なることがあります」の断りはやめた。除いた物は「同じ人数の世帯の平均からも除いています」と書く）。迷いやすい細かい例（飛行機の運賃・寝具・カーテン・紙おむつ・シャンプー・歯みがき）は書かない。
- 高速代: 通勤・ふだんの車の高速代は「車」の入力項目（明細の取り込みも車に分ける）、旅行の高速代は旅行と一緒に「趣味・娯楽」。交通費の目安からは有料道路料を除いた（下の2）。
- 医療費の説明の「窓口負担が下がるので段階で入れてください」はやめた。生活費の段階は生活費の全体に掛かる割合で、内訳ごとには変えられないため。年をとった後は、70歳・80歳の推定の段階（0049）で生活費の全体が下がるので、それで足りるとし、説明は「70歳・80歳からは、推定の段階で生活費の全体が下がります」の1文にした。「医療・介護」の行の「キャッシュフロー表の行」の説明も、窓口負担の文（`MEDICAL_HELP`）を外し、結果の表で医療費として分けて見られることだけにした。
- 年払い・数年おきの暮らしの支出の区画とお金の行の種類（`livingAnnual`）の名前を「年1回・数年に1回の支出」にそろえ、中の確かめの一覧の見出しは「入れ忘れがないか」、ひな形に無い行を足すボタンは「＋ その他の年1回・数年に1回の支出」にした。ひな形「ペットの医療」は「ペットの病気・けが」にし、説明に「ペット保険に入っているなら、保険料は毎月の生活費の『趣味・娯楽』に入れます」と書いた（行の見分け方〔ペット・動物病院〕は今のまま。前に入れた「ペットの医療」の行もペットの行と読む）。
- 画面の文の「知らせ」は「お知らせ」にそろえた（「計算のお知らせ」「計算の前提についてのお知らせがあります」など7か所。コードのコメントと設計記録の言い方は変えない）。

### 3. 内訳から仕送りを外す（前の世帯の仕送りは「仕送り（前の内訳）」）

- 内訳の並び（`LIVING_CATEGORY_ORDER`）から仕送りを外した。新しく内訳に分けるときは仕送りを作らない（明細の取り込みの並び `LIVING_ORDER` からも外した）。
- 前の世帯で仕送りに値がある（0円より大きい）ときは、**値を書き換えずに**「仕送り（前の内訳）」として内訳の最後（合計の行の前）に出し、そのまま計算に使う（結果は変わらない）。欄の説明に「子の在学中の仕送りは子ども・教育、親への仕送りは介護・親の入力項目に移し、移したらこの欄を空にしてください」と書く。空にすると内訳から外れる（今までの空にした内訳の決まり）。0円・空の仕送りは出さない。
- 内訳で入れている基本生活費に値のある仕送りがあれば、開いたときの知らせ `livingAllowance`（数・月額の合計。同じ数と額なら同じ ID で、2度は足さない）を足す（`input/livingAllowance.ts`。読むときに足す。押すと基本生活費の入力項目を開く）。
- 按分のまま（推定）の内訳の0円の仕送りは、推定の入れ直しで今の並びに分け直すときに外れる（合計は変えない）。
- 計算エンジンの内訳の値 `allowance` と行 `cf.expense.living.allowance` は残す（前の世帯をそのまま計算するため。0100 の骨格）。明細の取り込みでは、前の内訳の仕送りは前の分け方の内訳として扱い（`LegacyLivingCategory`）、明細のどの内訳でも置き換えない（明細に出てこない内訳として残す）。
- 家族の入力項目の出るお金の区画の説明は、内訳の「仕送り」ではなく「仕送り（前の内訳）」を移すよう書き直した。ヒアリングシートは基本生活費の内訳を持たないので変えない（シートの版も上げない）。
- 世帯ファイルの形は変えないので、形式の版は上げない（値を移す変換の段も作らない）。

### 4. 内訳の合計の行

- 内訳の最後に「合計」の行（読むだけ。`ro/living/<id>/categories/total`）を出す。値は内訳の月額の合計で、欄の横に小さく年額（「年 ○万円」）。内訳の欄を直すとすぐ変わる。入力項目ID を持たないので、確かめの一覧・値の状態の操作・プランの違いの一覧には出ない。
- まとまりの「?」の「合計 月○万円」は外した（合計は合計の行だけに出す）。総額で入れているときの「基本生活費（月額）」の欄は今のまま（内訳で入れているときは出ない）。

### 5. 実際に貯められている額（答え合わせ）の説明

- 計算エンジン `expense.reconcile` の決まり（0008 の追記）のとおりに、区画の説明と、まだ入れていないときの欄・入れた後の「実際の年間の貯蓄額」・「計算との差の扱い」の欄の説明を書いた（`CHECK_NOTE`・`CHECK_NEW_HELP`・`CHECK_ACTUAL_HELP`・`CHECK_TREATMENT_HELP`）:
  - 入れると: 計算の年間収支（その年の黒字。器の間の移動〔積立・iDeCo など〕は貯蓄に含む）と比べ、足りない分を使途不明金として、確かめる年から「差を見込む終わり」（既定は最後まで）まで毎年の支出に入れる（物価上昇率で伸ばす）。今年の途中から計算するときは、12か月そろう翌年と比べる。実際のほうが多いときは差を入れず、知らせだけ出す。
  - 結果の表では「使途不明金として残す」（既定の値）なら「その他の支出」、「生活費に足す」なら「基本生活費」の行に入る。どちらも年間収支と金融資産への効き方は同じ。実際のほうが多いときは、差を入れずお知らせだけ出す。
  - 入れないと: 計算の黒字はすべて貯蓄に回る前提（「毎年の黒字のうち貯金に回る割合」を入れていれば、その割合。0031）。

## 理由

- 入れ先を内訳の「?」に1か所でまとめる: 迷うのは「どの内訳か」より「生活費に入れてよいか」なので、内訳ごとの説明に散らすより、まとまりの「?」で一覧できるほうが早い。
- 目安からほかの入力項目の物を除く: 推定のままの世帯で、保険・保育料・給食・子の習い事などを二重に数えていた（4人の世帯で月2万円ほど）。0100 で仕送り金と家庭用耐久財を除いたのと同じ考え方で、アプリに入れる所がある物はすべて目安から除く。
- 仕送りをその他に足し込まない: その他に足すと、FP が仕送りをほかの入力項目に移したときにその他から引き忘れ、二重に数えやすい。前の内訳として額をそのまま見せ、移したら空にするほうが確かめやすい。形も変えずに済む。
- 合計の行: 内訳で入れたときに、今いくらになっているかを「?」を開かずに見られる。

## 代案（採らなかったもの）

- 前の世帯の仕送りを変換の段でその他に移す（形式の版を上げる）: 上の理由で採らない。
- 前の世帯の仕送りを、介護・親や家族の出るお金の行に自動で移す: 相手（親か子か・どの人か）が分からず、子の在学中の仕送りは子ども・教育の進路の欄で持つので、FP が移す。
- 世帯人員別の値が無い品目を、世帯人員ごとの割合で引く: 表に無い数を作ることになる（0100 の代案と同じ）。
- 月謝類のうち大人の分を残す: 表に子と大人の分け方が無い。全部除き、大人の習い事は FP が趣味・娯楽に足すと説明に書いた。
