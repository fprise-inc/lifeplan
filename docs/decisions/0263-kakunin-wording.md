# 0263. 画面に出る「確かめ」を「確認」系の言葉に言い換える（確認の一覧・注意・書類待ちにする・次の面談で確認）

- 状態: 採用（2026-11-27）
- 固定の強さ: 内部（言葉だけ）。画面の動き・計算・世帯ファイルの形・接続口の道具の名前と入出力の形は変えない。決まりとして残すのは「画面・提案書・手引き・AI 接続口の説明に『確かめ』を書かず『確認』系の言葉にする（下の例外を除く）」「名前は下の表のとおり」「お客さまの同意の説明文は、版を上げるときまで変えない」の3つ
- 前提にする記録: 0016（カスタム層）、0041（値の状態・確認の一覧の注意）、0048（基本生活費の答え合わせ）、0157・0172（同意の説明文の版と記録）、0210（AI 接続口の入力の確認 check_inputs）、0243（取り消しの言葉）、0256（「〇〇の確認画面」）

## 背景

- 画面の文に「確かめ」と「確認」が混ざっていた。入力のホームの「確かめの一覧」の中に、確かさの絞り込み「書類で確認」・注意を隠すボタン「確認した」・絞り込み「確認した注意」がもうあり、同じ一覧の中で言葉がそろっていなかった。
- 画面・提案書・手引き・AI 接続口に出る「確かめ」は約750回（コードの注釈・設計の記録・テストを除く）。下調べで場所と言い換えの案を一覧にし、名前の案を3つ模型で比較した。
- 利用者の判断（2026-11-27）: 案1（「確認の一覧」と「注意」）。欄のボタンは「書類待ちにする」、注意の行の印は「次の面談で確認」、確認画面を開くボタンは「〇〇の確認画面を開く」にそろえる。お客さまの同意の説明文は変えない。

## 決定

### 1. 名前

| 前 | 後 | 理由 |
|---|---|---|
| 確かめの一覧 | 確認の一覧 | いちばん素直な言い換え。一覧であって画面の名前ではないので「〇〇の確認画面」（0256）とぶつからない |
| 確かめの注意 | 注意（ほかの画面・手引き・AI 接続口から呼ぶときは「確認の一覧の注意」） | 一覧の中の種類の並び（未入力・まだ入れていない項目・書類待ち・注意・計算のお知らせ・推定）では1語で足りる。説明の文の「確認した注意」とそろう |
| 欄のボタン「書類で確かめる」 | 書類待ちにする | 「書類で確認する」にすると、確かさの「書類で確認」（書類で確認済みの値）と同じ言葉になり紛れる。押した後の印「書類待ち」と対にする。説明の文の「書類で確かめるまで代わりの値で計算」は「書類で確認するまで」 |
| 年金の「加入月数を書類で確かめる」 | 加入月数を書類待ちにする | 上と同じ |
| 注意の行の印「次回確かめる」・「次回確かめることを写す」 | 次の面談で確認・次の面談で確認することを写す | 「次回確認する」にすると、隣の「確認した」（注意を隠す）と意味が逆に見える |
| 基本生活費の欄「確かめる年」 | 比較する年 | 実際の貯蓄の増え方と計算を比較する年。「確認する年」では意味が分かりにくい |
| 出典の「確かめ前」「原本での確かめ前」・「確かめ待ち」「確かめ済み」「確かめ用」 | 確認前・原本での確認前・確認待ち・確認済み・確認用 | 画面にもうある「制度データの確認待ち」「原本での確認待ち」とそろえる |
| AI 接続口の check_inputs の呼び方「入力の確かめ」 | 入力の確認 | 画面の言葉と同時に変える（AI が「確かめの一覧」と言うと画面と食い違う） |

### 2. 確認画面を開くボタン

開く先が確認画面のボタンは、押してもすぐ何かが決まらないことが分かるように、開く画面の名前にそろえた（0256 の名前）。

| 前 | 後 |
|---|---|
| 書類の候補の帯の「確かめる」・取り込みの「読んだ書類を確かめる」 | 書類の読み取りの確認画面を開く |
| 新しい世帯の候補の帯の「候補を確かめる」 | 新しい世帯の候補の確認画面を開く |
| AI が発行した URL の帯の「確かめる」・依頼の「AI が発行した URL で確かめる」 | AI が発行した URL の確認画面を開く |

- 見に行くだけのリンク（「事務所の既定値で確認する」「結果のタブで確認する」「対策で確認する」「届いたかを確認する」など）は「確認する」にした。
- ボタンの下の段に出る1行の確認の文（「外しますか？ 外す／キャンセル」。0243）は画面ではないので、手引きでは「押すと確認の文が出ます」と書く（「確認画面」と書かない）。

### 3. そのまま言い換えると不自然な所

- 「提供元が止めたコードの一覧を確かめに行きました」→「一覧を取りに行きました」。
- 「押すと確かめの1行が出ます」→「押すと確認の文が1行出ます」。
- 「面談の確かめの一覧や見直しの準備に貼り付けてください」→「面談で確認することの一覧や…」。
- 「事務所のプライバシーポリシーも確かめられていません」→「…も確認していません」。「…が確かめられていなければ受け付けません」→「…が確認されていなければ…」。
- 「確かめられません」は「確認できません」、「確かめさせていただけますか」は「確認させていただけますか」。
- 「「わからない」は「書類で確かめる」になり」→「「わからない」は書類待ちになり」。前の画面で「書類で確かめる」にした、これから買う車のローンの値の根拠の文は「書類待ちの間に代わりに使っていた値（…）」（読むときに書く文。前に書いた世帯の文はそのまま）。

### 4. 変えなかった所

- お客さまの同意の説明文（`crates/ai-share/src/consent.rs` の版1〜3）。説明文は指紋で記録していて、お客さまが同意した文そのもの。版1・版2は書き換えない。今の版3を直すと版4になり、同意を取り直す世帯が出る。言い換えるなら、次に説明文を直すときに一緒に。
- 公開したヒアリングシートの版（`hearing/sheets/basic/2.json`・`3.json` の「生年月は面談で確かめます」）。公開した版は書き換えない（新しい版を作るときに直す）。
- コードの注釈・設計の記録・テスト・データの出典のメモ・開発と配布元の道具の文（`src/bin`・コードの発行）。画面に出ないため。ただし道具の引数の説明になる `///`（AI 接続口の道具の入力の JSON Schema の description）は画面に出るので直した。

### 5. 前の名前で探せるようにする

- 手引きの「探す言葉:」の行には前の名前を残し、新しい名前を足した（確認の一覧・確かめの一覧・注意・確かめの注意・次の面談で確認・次回確かめる・書類待ちにする・書類で確かめる・届いたかを確認する・書類の読み取りの確認画面を開く）。
- 入力のホームの「探して開く」（`app/src/workspace/input/searchWords.ts`）に、入力項目の中のボタン・欄の前の名前「加入月数を書類で確かめる」「確かめる年」を足した。確認の一覧そのものは「探して開く」の行き先（入力項目）ではないので足していない。

### 6. カスタム層

- 言い換えで公式の文が変わるので、その文を事務所で書き換えている（カスタム層）事務所には、更新のときに公式の文が変わった知らせ（公式の文の更新の確認画面）が出る。これは出てよい（利用者の判断）。手引き（`docs/app-guide/08-office.md`）に書いた。

### 7. 試験

- `app/test/terms.test.ts` に、画面に出る文字列（`app/src`・`hearing/src`・`statement/src`・`report/src`・`engine/src` の文字列、アプリ本体と `crates` の Rust の文字列〔試験の部分と配布元の道具を除く〕、手引き・AI 接続口の説明・対応範囲の一覧・ヒアリングの公開ページ〔手引きの探す言葉の行を除く〕）に「確かめ」が無いことを足した。例外はファイルの単位で、同意の説明文と探す言葉の辞書の2つだけ。同意の説明文が前の言葉のままであること（例外が本当に要ること）と、手引きの探す言葉に前と後の名前が両方あることも確認する。
