# 0128. キャッシュフロー表の「不動産の売却」の行と、収益不動産のタブの「年ごとの手残りとローン残高」のグラフと、売る年を変えた比べからプランを作るボタン

- 状態: 採用（一部未確定）（2026-11-06）
- 固定の強さ: 内部（表の行の鍵 `realEstateSale` は、事務所の名前・独自帳票から使われるので名前は変えない。行の並び・言葉・グラフの色・形・高さ・ボタンの言葉・プランの名前の付け方は後から変えてよい。変えたら追記に書く）。世帯ファイルの形式の版は変えない
- 前提にする記録: 0127（不動産のローンの行・収支の推移の「不動産」の系列・ライフイベントの不動産の出来事）、0082（収益不動産のタブ・売る年を変えた比べ）、0016（提示層と帳票の約束・表の行の事務所の名前）、0036・0043（プランの差分・入力画面でプランを直す）、0068（ライフイベント）

## 背景

- 収益不動産を売った年の手取り（見本 3-4-05 の見本ハイツは 2041年に 5,632万円）が、キャッシュフロー表では「その他の収入」の行に入り、結果のタブの収支の推移のグラフでは「不動産（家賃・売却）」の系列に入っていた。表とグラフで振り分けがそろっていなかった（0127 の 3 では「売却は1回なので表の行は分けない」としていた）。利用者の判断で、表にも行を足してそろえる。
- 収益不動産のタブは数字の表だけで、年ごとの手残りの増減（大きな修繕の年のマイナス・売った年）とローンの減り方が一目で分からなかった。利用者の判断で、結果のタブのグラフと同じ見た目のグラフを足す。
- 売る年を変えた比べの表で良さそうな売り方が見つかっても、それをプランにするには、帯の「＋」でプランを作り、入力画面で売る時期を直す必要があった。利用者の判断で、比べの行から直接その売り方のプランを作れるようにする。

## 決定

### 1. キャッシュフロー表の「不動産の売却」の行（鍵 `realEstateSale`）

- 収入の側、「家賃収入」のすぐ下に「不動産の売却」の行を足す。中身は、住まい以外の不動産（中身 `property` を入れた不動産の器）を売った手取りのマス（`cf.income.lumpSum.realEstateSale` で、物の ID がその器のもの）。「その他の収入」から外す（二重に数えない）。収入合計・年間収支は変わらない。
- 出す条件は、売る予定（`property.sale`）を入れた物件があること（ほかの不動産の行と同じく、条件を満たす物が無ければ行の定義を作らない。どの年も 0 の行は今までどおり出さない）。
- 住まい（自宅）の売却の手取り（`housing.valuation` の同じ行で、物の ID が住まい）と、中身を入れていない不動産の器の売却（`asset.heldSale`）は「その他の収入」のまま。収支の推移のグラフの「不動産（家賃・売却）」と同じ範囲にした（判定は同じ関数 `propertySaleCell`）。
- 同じ行の並びを使う所すべてに入れた: 結果のタブの表・お客さまに見せる画面・持ち帰り用のレポート（`app/src/workspace/present.ts` の `rowDefs`）、提案書（`report/src/build.ts` の `rowDefs` と帳票 `pages/cashflow.typ`。帳票は行の鍵で並べるだけなので Typst は変えない）、事務所の名前の差し替えの表（`report/src/rowNames.ts`）。数字の根拠のパネルも出せる（売却の手取りは 0127 の 4 の「入力した値だけから出す計算式」）。
- Excel への書き出しは、キャッシュフロー表を書き出す所が今は無い（ヒアリングシートだけ）ので、変える所が無かった。

### 2. 収益不動産のタブの「年ごとの手残りとローン残高」のグラフ

- 置き場所: 全体の画面は「{年}年の物件ごとの数字」の表と「全物件の合計の年ごとの数字」の表のあいだ（見出し「全物件の年ごとの手残りとローン残高」）。物件ごとの画面は「{年}年の指標」と「年ごとの数字」の表のあいだ（見出し「年ごとの手残りとローン残高」）。
- 中身: 年ごとの手残り（税引前・税引後）を2本並べた棒（左の目盛り）、年末のローン残高を破線（右の目盛り）。年は下の表と同じ。マイナスの年の棒は 0 の線より下に伸び、結果のタブの「赤字の年」と同じ赤い斜線を重ねる（凡例「手残りがマイナスの年（▲）」）。物件の売却・大きな修繕の年に、結果のタブと同じ「不」の丸（出来事の作り方は結果のタブの `eventsOf` から `propertyEvents` に切り出して共通にした。物件ごとの画面はその物件の分、全体は全物件の分）。
- ローン残高の右の目盛りは、0 を手残りの 0 の線にそろえ、上の端までを使う（0 の線を2本にしない）。目盛りの数は 0 の線から上の端までの高さで減らす（手残りのマイナスが大きい年があっても数字を重ねない）。ローンの無い物件（全物件でローンが無いとき）は線・右の目盛り・凡例を出さない。
- 部品は結果のタブのグラフの物を使う: 枠と出来事の丸の置き方（`MainChart.tsx` の `frameOf`・`eventLayout`）、座標（`chart.ts`）、丸と説明（`EventDot.tsx`）、年と年齢の目盛り（`AgeAxis.tsx`）、年を指したときの札（`yearPick.ts` と `.year-tip`）、棒の塗りと凡例の見本（`StackChart.tsx`）、文字の大きさ（ルートの文字の大きさに比例するので、中・大の切り替えで一緒に大きくなる）。新しく書いたのは、この組み合わせ方の部品 `RentalChart.tsx` だけ。
- 色: 手残りの棒は収支の推移の「不動産（家賃・売却）」の青緑の濃淡（税引前が明るい側、税引後が濃い側）、ローン残高は「不動産（経費・ローン）」に近いくすんだ赤みの色。
- 操作: カーソルを合わせるとその年の札（家族の年齢・手残り2つ・ローン残高・その年の出来事）。押すか左右のキーで、その年を指標の年にする（下の表の行を押したのと同じ）。指標を見ている年に細い縦の線を引く。
- 高さは結果のタブのグラフより低い（画面の高さに合わせ、300〜440px を文字の大きさに比例させる）。下に表があるため。

### 3. 提案書の収益不動産のまとめにも同じグラフ

- 入れることにした。全体の1枚は物件ごとの表と合計の年ごとの表のあいだ、物件ごとの1枚は指標の札と年ごとの数字の表のあいだ（画面と同じ並び）。中身・色・「不」の印（大きな修繕の年と売った年）・右の目盛りの決め方は画面と同じ。グラフは表と違い間引かず、表に載る全部の年（帳票の入力 `rental` の年の並び）を描く。
- 帳票の入力（`rental` の年ごとの数字と売却）だけで描けるので、帳票の入力のスキーマは変えない（Typst の `pages/rental.typ` に `rental-chart` を足しただけ）。
- 理由: 提案書の収益不動産のまとめは画面の収益不動産のタブを紙にした物で、FP が不動産に詳しいお客さまに見せるときに、修繕の年のマイナスと売った年が表より先に目に入るほうがよい。高さを 64pt に抑え、見出しを小さくして、見本 3-4-05 の物件ごとの1枚（指標・グラフ・15年分の表・売る年を変えた比べ・注記）が1ページに収まることを確かめた。

### 4. 売る年を変えた比べの行から、その売り方のプランを作る

- 物件ごとの画面の「売る年を変えた比べ」の表の、今の予定の行以外（5年前に売る・5年後に売る・持ち続ける。売る予定の無い物件なら5年後・10年後に売る）に「この売り方でプランを作る」のボタンを置く。
- 押すと、帯の「＋ このプランを元に作る」と同じ作り方（見ているプランを土台にし、保存していない変更も写す `savePlan`）で新しいプランを作り、そのプランに、入力画面でプランを直したときと同じ差分の記録（`recordPlanEdit`。直す前はそのプランの中身 `planView`）で、その物件の売り方だけを変えた差分を足す。現状（入力）は変えない。作ったプランを帯に足して選ぶ（帯が5つを超えるときの扱い・知らせも「＋」と同じ `placeNew`）。
- 売り方の中身は、比べの行の計算に使った写しの要求と同じ（`saleVariantRequest`）: 売る年月を変える（持ち続けるなら売却の予定を外す）、売却価格は外してその年の評価額で売る、売却の費用の割合と「売ったときにこの物件のローンを返す」は今の予定のまま。ローンの一括の返済は、入力画面で売る時期を変えたときと同じく、エンジンが売る月に合わせて計算し直す（売る月に付いてくる設定は「ローンを返す」の1つだけで、それは引き継ぐ）。
- プランの名前は、帯の「＋」と同じ頭（「プランC」のような次の文字）に、物件名と売り方を続ける（「プランC 見本ハイツ（架空）を2046年10月に売る」「プランC 見本ハイツ（架空）を持ち続ける」）。
- 押せないときの決まり: 帯の「＋」に押せない決まりは無い（保存できるプランの数に上限は無く、帯は5つまでで、超えたら古いプランを帯から外して知らせる）ので、同じにした。比べの計算がまだの間・できなかったときは、表が出ないのでボタンも出ない。
- 理由: 比べの行の数字（税引後の手取り・最後の金融資産）は、作ったプランの結果とそのまま一致する。入力画面で売る時期だけを変えた場合は売却価格を入れていればその額が残るが、比べの表は「その年の評価額で売る」と書いているので、表で見た数字のプランにするほうを採った。

## 理由

- 表とグラフの振り分けがそろっていないと、FP が「その他の収入」の大きな額の出どころを説明しにくい。売却の年は家計の中で最も大きなお金が動く年の1つで、行で見えるほうがよい。
- グラフは結果のタブの部品を組み合わせて作り、見た目・文字の大きさ・出来事の印・年の札を結果のタブとそろえた（別の見た目のグラフを増やさない）。
- 比べからプランを作るのは、比べの写しの要求とプランの差分の記録という既にある2つの仕組みをつなぐだけにし、別の書き方を作らない。

## 代案（採らなかったもの）

- 「不動産の売却」の行を、住まいの売却も含めた「不動産の売却」にする: 住まいの売却は住み替えの出来事で、収支の推移のグラフでも「その他の収入」に入れている。グラフとそろえるため、住まい以外の不動産だけにした。
- ローン残高を別のグラフにする: 縦に2つ並ぶと画面が長くなり、修繕の年とローンの減り方を同じ年で見比べにくい。右の目盛りの線にした。
- 比べの行から、プランを作らずに見ているプランを直す: 見ているプランが基準や現状のこともあり、元のプランを残して比べられるほうがよいので、帯の「＋」と同じく新しいプランにした。

## 未確定・後の段階に回したこと

- 中身を入れていない不動産の器（`asset.heldSale`）を売った手取りも「不動産の売却」の行に入れるか（今は「その他の収入」。グラフの系列と一緒に決める）。
- 比べの行から作るプランで、今の予定に売却価格を入れていたとき、その額を残す選び方を出すか（今は比べの表と同じくその年の評価額で売る）。
- 提案書のキャッシュフロー表の抜粋に、売却の手取りの行を必ず載せる年（売った年）として足すか（今は 0127 の `keyYears` に売却の年が入るので載っている）。
- グラフに家賃収入・経費の内訳を重ねるか（今は手残りの2本とローン残高だけ）。
