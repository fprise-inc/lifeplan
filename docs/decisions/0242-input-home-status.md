# 0242. 入力のホームの状態の見せ方を直す（入力済みは緑・状態の行を横にそろえる・未入力は点線の枠をやめて絵の左上の印に）

- 状態: 採用（一部未確定）（2026-11-22）
- 固定の強さ: 内部（画面の見せ方だけ。CSS と、入力項目の中の印1つ）。状態の決め方（`items.ts` の `statusOf`・`startedOf`）・状態の名前の言葉・読み上げ用の名前・世帯ファイルの形・計算は変えない。決まりとして残すのは「入力済みは緑」「状態の行は横の並びでそろえる（そろえる決まりは `@supports` の中）」「未入力（0円の所あり）とまだ入れていないに点線の枠を使わない」「印『未入力』は絵の左上（右上はプランで直した所の数）」。余白の数字・絵の薄さは後から変えてよい（変えたら追記に書く）。
- 前提にする記録: 0045（入力のホームの入力項目と状態。2026-10-27 の追記の「まだ入れていない」）、0041（2026-11-06 の追記の入力のホームの状態の印と推定の吹き出し）、0077（状態の印は丸の印と色の付いた文字だけ）、0072（進み具合の絞り込み）、0236・0240（藍は主の操作・選んでいる状態の色）、0043（プランの編集中に入力項目に出す、プランで直した所の数）

## 背景

- 「入力済み」の印と、進み具合の帯の四角が藍だった。ほかの画面では「済」は緑（`--good`）で、藍は主の操作と選んでいる状態の色にそろえてきた（0236・0240）。入力のホームだけ「済」と「押す所」が同じ色に見えた。
- 入力項目ごとに、名前・数字・状態の行・案内の文の高さがばらばらで、横に並んだ入力項目どうしで状態の行の位置がそろっていなかった（幅 1440・文字「中」で、同じ段の中で最大 71px のずれ）。
- 未入力（0円の所あり）は赤い点線の枠、まだ入れていないは灰色の点線の枠だった。点線の枠が並ぶと画面がざわつき、枠の太さの分だけほかの入力項目と大きさも違って見えた。
- 見せ方の案を同じ場面（新しい世帯・入れ始めた世帯・中身の入った世帯・プランの編集中）の写真で比較し、利用者の判断で次の形に決めた。

## 決定

### 1. 「入力済み」は緑

- 状態の印（`.ih-st.done`。入力のホームの入力項目・ピン・入力項目のパネルの見出し）と、進み具合の帯の四角（`.ih-prog-bar i.done`）を `--good`（緑）にする。印の形（✓ の丸と文字）は変えない。
- 進み具合の数字（「入力済み 3」の数）は、押すと絞り込むボタンの中の数なので藍のまま。

### 2. 状態の行を横にそろえる

- 入力項目を2段にする。1段目＝絵・名前・数字（と下の小さな1行）・状態の行、2段目＝案内の文と「推定で入れる」「該当なし」。段の高さを、横に並んだ入力項目どうしで共有する（CSS の subgrid。`.ih-cards` の子の入力項目が2段分を取り、`grid-template-rows: subgrid`）。
- 状態の行は1段目の下端に置く。数字の行数が少ない入力項目では、数字と状態の行の間が空く（許す）。案内の文は2段目の上端にそろう。ボタンは、それぞれの案内の文のすぐ下（文の行数が違えば、ボタンの位置は違う）。
- 段の高さは中身で決まる。ボタンや文の高さを数字で持たないので、ボタンの大きさ（0240）や文字の大きさが変わっても崩れない。案内の無い並びでは2段目の高さは 0。
- 「推定で計算中」の印（押すと推定の一覧が出る。開くボタンの外に置く。0041 の追記）は、1段目の下端に重ねて、ボタンの中の状態の行と同じ位置に置く。印のほかの所は押すと入力項目が開く（重ねた箱は `pointer-events: none`、印だけ `auto`）。
- 開くボタンは1段目だけになるので、押せる所を入力項目の全体に広げる（ボタンの `::after` を入力項目の枠いっぱいに）。案内の無い入力項目の2段目の空き・下の色の帯を押しても開く。案内の文とその中のボタンは、今までどおり開くボタンの上にある（案内の文を押しても開かない）。
- フォーカスの黄色い枠は、入力項目の側に描いて全体を囲む（開くボタンが1段目だけなので）。今までは開くボタンの枠で、絵と下の帯に隠れる所があった。Tab の順は変えない。
- 広い画面（5列）で、案内の文の左端を名前・数字と同じ位置にした（2px 右にずれていた）。
- **subgrid を知らない環境**: そろえる決まりは `@supports (grid-template-rows: subgrid) and selector(:has(*))` の中にだけ書く。知らない環境では今までの並び（入力項目は縦に積む・開くボタンが伸びる。そろえないだけ）のまま。1・3 の色と枠と印は `@supports` の外なので、どの環境でも同じ。

### 3. 未入力・まだ入れていないの点線の枠をやめる

| 状態 | 今まで | これから |
|---|---|---|
| 未入力（0円の所あり） | 赤い点線の枠・影なし・絵は灰色・状態の行「未入力（0円の所あり）」 | 枠・地・影はほかの入力項目と同じ。絵の所を灰色の地（`--base-bg`）に、絵は色を抜いて薄く。**絵の左上に小さな印「未入力」**（薄い赤の地・赤い文字・赤い枠）。状態の行は出さない |
| まだ入れていない | 灰色の点線の枠・影なし・絵は灰色 | 枠・地・影はほかの入力項目と同じ。絵の所を灰色の地に、絵は色を抜いて薄く。印は付けない（「まだ入っていません」の文だけ） |
| 進み具合の帯の「まだ入れていない」の四角 | 灰色の点線 | 細い実線（`--line`） |

- 印「未入力」は右上に置かない。右上は、プランの編集中に出る「プランB: 2か所」（プランで直した所の数。`.plan-count.on-card`）の場所で、重なるため。
- 印の言葉は `StatusBadge.tsx` の `MISSING_MARK`。画面の要素として置く（CSS の `content` で描かない）。
- 印の要素は、開くボタンの中の最後（名前・数字の後ろ。状態の行のあった所）に置く。左上に見せるのは CSS の置き場所だけ。開くボタンの中の文字は、どの状態でも入力項目の名前から始まる（「保険 1件 未入力」。画面の文字で入力項目を探して押す通しの操作のテストが、この順に頼っている。絵のすぐ後ろに置くと「未入力 保険 …」になり、名前で探せなくなる）。
- 印が状態を伝えるので、未入力の入力項目の中の状態の行は出さない。すぐ下の案内の文（「0円で計算している所があります」など）は残す。未入力の入力項目には、いつも案内の文がある（`items.ts` の `hint`）。
- 読み上げ用の名前（開くボタンの `aria-label` の「保険（未入力（0円の所あり））を開く」）は変えない。
- 未入力・まだ入れていないの下の色の帯は出さない（今までと同じ）。
- **変えない所**: 該当なし（入力項目の全体が灰色）、事務所の既定値どおり、いちばん下の「探して開く」の点線の枠（入力項目ではない道具）、進み具合の左の「未入力（0円の所あり）n 項目」の赤い枠、進み具合の帯の未入力の四角（赤い枠・薄い赤の地）、ピンの見せ方、入力項目のパネルの見出しの状態の印（色のほかは同じ）、状態の名前の言葉。

## 動く環境と subgrid

- アプリの画面は OS の WebView で動く。`app/src-tauri/tauri.conf.json` に最小の OS の指定は無く、Tauri の既定（macOS 10.13 以上）のまま。Windows は WebView2（自動で新しくなる。無い PC にはインストーラーが入れる）、Linux は WebKitGTK。
- subgrid が使えるのは、Safari（WKWebView）16.0 以上・Chromium（WebView2）117 以上・WebKitGTK 2.38 以上。`:has()` は Safari 15.4・Chromium 105 以上、`@supports selector()` は Safari 14.1・Chromium 83 以上。
- macOS では WKWebView は OS に付いている物なので、subgrid が使えるのは macOS 13 以上の見込み。macOS 12 以前では `@supports` の外の今までの並びになる（そろえないだけ。確かめは下）。
- ただし、この画面はすでに `color-mix()`（Safari 16.2・Chromium 111 以上。入力項目の絵の地の色など）と、`@supports` なしの subgrid（バランスシートの明細・運用の内訳）を使っている。今の実質の下限は macOS 13.1・Chromium 111 で、その範囲では subgrid はどこでも使える。最小の OS を設定に書くかは未確定（配布の記録の側）。

## 入れなかったもの

- **未入力に下の赤い帯だけを付ける案・印を右上に置く案・まだ入れていないにも印を付ける案**: 写真で比較して採らなかった（赤い帯は目立たない・右上はプランの数と重なる・印が増えると新しい世帯で画面が印だらけになる）。
- **状態の行を開くボタンの外に出して3段にする案**: 状態の行だけの段ができ、入力項目の間隔の分（18px）が段の間に入って間延びする。読み上げと今までの並び（知らない環境）の形も変わる。
- **入力項目の高さを数字で決めてそろえる案**: 文字の大きさ・ボタンの大きさ・文の行数で崩れる。
- **推定の印の場所を、見えない同じ文字で空けておく案**: 画面の文字が二重になる。印の1行分の高さを文字の大きさの単位（rem）で空ける今までのやり方を続けた。

## 影響

- **CSS**（`app/src/styles/app.css`）: `.ih-st.done`・`.ih-prog-bar i.done`（緑）、`.ih-prog-bar i.empty`（実線）、`.ih-card.s-missing`・`.ih-card.s-empty`（枠の指定を消し、絵の地と薄さだけ）、`.ih-miss`（印）、`@supports` のまとまり（2段と横そろえ）、`.ih-hint` の左右の余白（広い画面）。
- **画面**: `app/src/workspace/input/InputView.tsx`（`Card` に印を足し、未入力では状態の行を出さない）、`StatusBadge.tsx`（`MISSING_MARK`）。
- **手引き**: `docs/app-guide/02-input.md`（入力のホームの見え方に、状態ごとの見た目の1行）。
- 段の高さを共有するので、入力項目の高さは今までと少し変わる（同じ段でいちばん高い1段目＋いちばん高い2段目。幅 1440・文字「中」の入れ始めた世帯で、入力のホームの入力項目の並びの高さの合計は 1110px → 1158px）。
- 世帯ファイルの形式・計算・文言の一覧（差し替えられる文）は変えない。
