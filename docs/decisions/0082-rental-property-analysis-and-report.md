## 背景

- 収益不動産を、不動産を専門とする FP が整理・分析できる中身にする段階の4つ目（β 前の最後）。0079〜0081 で物件の入力・お金の欄・税と出口ができ、表と税には物件の数字が入るようになったが、FP が物件を見比べるときの数字（利回り・返済比率・返済余裕率・手残り・デッドクロスなど）と、売る年を動かしたときの違いを見る場所が無かった。
- 提案書には、独自帳票（カスタム層）の見本「収益不動産のまとめ」（0009 の追記）だけがあり、公式の帳票には物件のページが無かった。

## 決定

### 1. 分析の数字はエンジンの新しい部品で出す（`asset.realEstateAnalysis`。約束の版 1.0）

- 根の部品 `plan.cashflow`（改訂18・約束の版 1.7）が、中身を入れた不動産があるときだけ呼び、`details.realEstateAnalysis` に写す。エンジンが出力の `summary.realEstateAnalysis` に写す（先出しの結果にも入る）。**表・税・お金の動きは変えない**（物件の無い世帯は欄が無く、ある世帯でも表・税は前と同じ。前と後のエンジンで、見本の世帯と一致テストの要求を比べて確かめた）。
- 材料は `asset.realEstate`（改訂6・約束の版 1.2。任意の出力 `cash`〔年ごとの表に載る月の、貸している月数・満室のときの収入・受け取った収入・大きな修繕を除く経費・大きな修繕〕と `facts`〔取得価額の合計・諸費用・自己資金・建った年・法定耐用年数・減価償却が終わる年・民泊・宿の1泊の単価など〕を足した。計算は変えていない）、`debt.schedule`（返済の計算式IDで毎月・ボーナスの返済と、繰上返済・手数料・売ったときの一括の返済を分ける）、`tax.realEstateSale`、税と社会保険料の部品。
- 年は計算基準年から、持っている月が表にある年（売った年まで）。**金額は表に載る月（計算基準月から）の分**で、キャッシュフロー表の行のその物件の分と同じ。画面と提案書は、ほかの表と同じ年の並び（計算基準月が1月でなければ翌年から）で見せる。

### 2. 式（物件ごと・年ごと）

| 欄（画面の言葉） | 式 |
|---|---|
| 満室のときの収入 `gross` | 空室を見込む前の家賃と家賃以外の月の収入（共益費・駐車場など）。礼金・更新料は入れない。民泊・宿は「1泊の単価×営業日数」で入れたときの稼働率100%の売上（月の売上で入れたときは無い） |
| 実際に入る収入 `rent` | 家賃収入の行のこの物件の分（空室を見込んだ後。礼金・更新料を含む） |
| 経費 `expenses`・大きな修繕 `repairs` | 不動産の経費の行のこの物件の分を、大きな修繕とそれ以外に分けたもの |
| 年の返済 `repayment`・約定の返済 `debtService`・元金 `principal` | 年の返済はこの物件を指す負債の返済（毎月・ボーナス・繰上返済・手数料。売ったときの一括の返済は除いて売却に入れる）。約定の返済は毎月とボーナスの返済だけ。元金＝約定の返済−利息 |
| 税引前の手残り `cashBeforeTax` | 実際に入る収入−経費−大きな修繕−年の返済 |
| 増える税と社会保険料 `tax`・税引後の手残り `cashAfterTax` | 4 の近似。税引後＝税引前−その額 |
| 表面利回り `grossYield` | 満室のときの収入（年換算）÷取得価額（内訳があれば内訳の合計） |
| 実質利回り（NOI 利回り）`netYield` | （実際に入る収入−経費）（年換算）÷（取得価額＋取得時の諸費用）。大きな修繕・ローン・税は入れない |
| 損益分岐の入居率 `breakEven` | （経費＋約定の返済）÷満室のときの収入。民泊・宿は損益分岐の稼働率 |
| 返済比率 `repaymentRatio` | 約定の返済÷実際に入る収入 |
| 返済余裕率（DSCR）`dscr` | （実際に入る収入−経費）÷約定の返済 |
| 借入の割合（LTV）`ltv` | 年末のローン残高÷年末の評価額（ローンのある物件だけ） |
| 自己資金に対する手残りの割合（CCR）`ccr` | 税引前の手残り（年換算）÷自己資金（入れたときだけ） |
| ローン残高・評価額・含み益 `equity` | 年末の値。含み益＝評価額−ローン残高 |
| 築年数 `age`・残りの耐用年数 `remainingLife` | その年−建った年、法定耐用年数−築年数（0より下げない） |
| 減価償却が終わる年 `depreciationEnd` | 建物・建物附属設備の帳簿の残りが1円になる年。表の最後まで貸していれば表の期間の後の年も同じ年額で数える。売る・貸し終わるまでに終わらなければ無い |
| 元金の返済が減価償却費を上回る年 `deadCross` | 貸している年で、元金＞減価償却費（建物と建物附属設備）になる最初の年。計算基準年は減価償却費を表に載る月の分にそろえて比べ、そこで上回っていれば「もう上回っている」 |

- 率は10進の文字列（0002 の2。小数12桁・銀行丸め）。**分母が0・無いときは出さない**（null）。年換算は「額×12÷貸している月数」（円未満切り捨て。規約 `conv.realEstate.analysis`）で、返済比率・返済余裕率・損益分岐の入居率は同じ月の額どうしの比なので年換算しない。
- 返済比率・返済余裕率・損益分岐は約定の返済で見る（繰上返済の年に数字が跳ねないように）。手残りは実際に出ていくお金なので、繰上返済・手数料を含む。

### 3. 民泊・宿

- **表面利回りは出さず、稼働率・1泊の単価・営業日数・年の売上（年換算）を並べる**。実質利回り・手残り・返済余裕率などは同じ式で出す。損益分岐は、稼働率100%の売上に対する割合（損益分岐の稼働率）。
- 理由: 民泊・宿には「満室」の考えが無く、稼働率100%の売上で割る表面利回りは実際の売上とかけ離れる。売上と経費の比べ（実質利回り）と稼働率のほうが、民泊・宿を扱う FP が見慣れた物差し。

### 4. その物件で増える税と社会保険料（近似）

- **物件が無い場合との差を出す（物件を外して計算し直す）のはやめ、物件の所得の分だけ課税所得を下げたときの差で近似する**。
  - 物件の所得: その年の不動産所得（民泊・宿は雑所得・事業所得）。不動産所得の損失は土地の取得のための借入の利息の分を除く（0028 の4）。雑所得の損失は0（ほかと通算しない。0081 の6）。青色申告特別控除は、その人の不動産所得の黒字の物件に黒字の割合で分けて引く。
  - 所得税: 合計所得金額（純損失の分を戻し、繰越控除を引いた額）−所得控除の合計を課税所得として、税率の表（復興特別所得税・防衛特別所得税を含む）で、その額と「物件の所得を引いた額」の税の差。
  - 住民税: 同じ課税所得の差×所得割の率（市町村民税と道府県民税）。
  - 国民健康保険・後期高齢者医療: 翌年度に入っている月数の分、（合計所得金額＋分離課税の所得−基礎控除）の差×所得割の率の合計（料率の入力が無ければ全国の目安。介護の区分は40〜64歳）。
  - 所得の年に置く（払う月のずれは見ない）。計算基準年は、所得のうち表に載る月の分（受け取った収入の割合）に按分する。
  - 見ないもの: 所得控除の段の変わり方（基礎控除・配偶者控除など）、賦課限度額、保険料の軽減、繰越控除の額の変わり方、住民税の調整控除・均等割、配偶者の扶養の判定。
- 理由: 物件ごとに物件を外した計算を1回ずつ足すと、物件の数だけ計算が増え、毎回の計算（スライダーの先出しを含む）に入れられない。分析の数字は毎回の計算の結果に入れたいので、エンジンの中で軽く出せる近似にした。限界の率を掛けるだけの近似より、税率の段をまたぐときと、赤字で課税所得が0になるときに差が出にくい。

### 5. 売る年を変えた比べ

- 物件ごとに、売る予定があれば「今の予定・その5年前・その5年後・持ち続ける」、無ければ「持ち続ける（今の予定）・5年後に売る・10年後に売る」。計算基準月より前・持ち始める前・表の最後の年より後になる案は作らない。5年前・5年後・新しく売る案は、その年の評価額で売るとする（売却の費用の割合と「売ったときにローンを返す」は今の予定のまま）。部品は `report/src/rentalSale.ts`（画面と提案書で同じ）。
- **1案ずつ全部を計算し直す**（物件の分だけを計算する軽い形にしない）。売る年だけを変えた写しの要求（0075）を、画面は収益不動産のタブでその物件を見ている間だけ、提案書は収益不動産のまとめの章を載せるときだけ求める。毎回の計算には入れないので、ふだんの計算の重さは変わらない。
- 見せる数字: 税引後の手取り（手取り−売ったときの一括の返済−譲渡所得の税。分析の数字の売却 `exit.net`）、表の最後の年の金融資産と今の予定との差、表の最後の年に持っている物件の評価額−ローン残高（持ち続ける案で、金融資産の差だけで比べないように）。

### 6. 入力項目の一覧表

- 段階1・2の「物件の一覧」に、表面利回り・実質利回り・月の手残り（税引前）と合計の行を足した。数字は世帯の今の入力の写しの要求を1回求めた結果の、表の最初の年の分析の数字（入力のパネルは結果を持たないので）。求めている間は「—」。月の手残りは年の手残り÷貸している月数。

### 7. 結果の画面の収益不動産のタブ

- **新しいタブ「収益不動産」**を「資産と負債」と「万一のとき」の間に置き、収益不動産のある世帯だけ出す。理由: ほかのタブは家計の全体を見るもの（結果は世帯の年の表、資産と負債はバランスシート、万一のときは想定ごとの比べ）で、物件ごとの年の表と指標・物件ごとの売る年の比べは、見る単位も中身も違う。資産と負債のタブの「見るもの」はバランスシートの図の切り替えで、物件の表を入れると図のタブの作りが崩れる。
- 中身: 見るもの（全体〔物件が2件以上〕・物件ごと）、プランの帯、物件の見出しの1行、選んだ年の指標、年ごとの表（家賃収入・経費・大きな修繕・減価償却・利息・不動産所得・返済・手残り〔税引前・税引後〕・ローン残高・評価額。元金の返済が減価償却費を上回る年に印）、売る年を変えた比べ。説明は「?」の中。

### 8. 提案書の収益不動産のまとめ（公式の帳票の章 `rental`）

- 独自帳票の見本（0009 の追記）を公式の帳票に上げた: 章「収益不動産のまとめ」（住宅ローンの後）。提案のプランの貸している物件ごとに1枚（見出し・指標・年ごとの表・売却・売る年の比べ）、物件が2件以上なら全体の1枚（物件ごとの指標と合計・合計の年ごとの表）を前に置く。物件が無ければ章ごと出さない。帳票の入力は `rental`（`report/schema/proposal-input.schema.json`。率は書式を当てた文字列）。
- **物件名・種類を提案書の PDF に載せる**。0079 の考え（物件名・所在地・メモは FP が書いた文で個人に近いので、AI に渡す縮約版では既定で外し、持ち帰り用のレポートでは外す）に沿って、提案書は対面で顧客本人に渡す紙で、宛名（顧客の名前）も載る（0009）ので、本人の物件の名前を載せても外に出る情報は増えない。**所在地・メモは載せない**（所在地は家族の情報と合わせると世帯を絞り込みやすく、提案書で物件を見分けるのは物件名と種類で足りる）。帳票の入力には物件名（`rental.properties[].label`、独自帳票の材料の `realEstate.*[].name`）と種類だけを入れる。持ち帰り用のレポート・縮約版の決まりは変えない。
- 独自帳票の見本（`sdk/examples/reports/rental-property-summary/`）は、独自帳票の作り方の見本として残す。

## 理由

- **分析の数字をエンジンで出す**: 画面・提案書・持ち帰り用のレポート・AI で同じ数字にし、根拠の記録（0006）に乗せるため。式を画面の側に持つと、表示ごとに食い違う。
- **新しい部品にする（`asset.realEstate` に足さない）**: 税引後の手残りは税の部品を読むが、税の部品（`tax.totalIncome`）は `asset.realEstate` を読むので、同じ部品に入れると循環する。分析は表を変えない読むだけの部品にした。
- **表に載る月の分にそろえる**: キャッシュフロー表・提案書の表の物件の行と同じ数字にする。率は年換算で、年の途中から貸す・売る年でも比べられる。
- **約定の返済で比べる率と、繰上返済を含む手残り**: 返済余裕率などは金融機関が見る物差しで、約定の返済が基本。手残りは手元のお金の動きなので実際の返済で見る。

## 代案（採らなかったもの）

- 税引後の手残りを、物件を外した写しの要求との差で出す: 正確だが、物件の数だけ計算が増え、毎回の結果に入れられない（4）。売る年の比べ（全部を計算し直す）は、見ている物件・載せる章だけなので、こちらは写しにした。
- 売る年の比べを物件の分だけの軽い計算にする: 表の最後の年の金融資産（運用・税・取り崩しの順序の影響）が出せない。
- 収益不動産を資産と負債のタブの見るものにする・結果のタブの表に物件の行を足す: 7 の理由。
- 提案書に物件名を載せない（持ち帰り用のレポートと同じく外す）: 対面で渡す紙で物件を見分けられず、物件が2件以上の世帯で読みにくい。
