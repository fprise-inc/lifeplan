- 状態: 採用（一部未確定）（2026-11-22）
- 固定の強さ: 内部（画面の見せ方。CSS・クラス名・印の並び）。お知らせの文・種類の名前・出る条件・既読の扱い・一覧の並び・ベルの数の数え方・配信元の形式は変えない（0087 の骨格はそのまま）。決まりとして残すのは「お知らせの種類に色を使わない（色は状態の印だけ）」「要対応の印は、今の状態の知らせ（日付なし）で開く画面があり、参考でないものに付ける」「要望・不具合を送るの入口は、どの画面でもちょうど1つ」の3つ
- 前提にする記録: 0087（お知らせの一覧）、0239（重ねて出す画面の閉じ方）、0240（ボタンの4段と選んでいる状態の色。色の意味）

## 背景

画面の点検で、お知らせの一覧（上の帯のベル）について次のことが見つかった。

- 種類ごとの印の色（ファイナンシアから＝藍・制度とデータの更新＝緑・世帯＝黄土・事務所＝灰）が、ほかの画面の「状態の色」と別の意味で使われていた。0240 の色の意味（藍＝主の操作・選んでいる、緑＝済、黄土＝推定・要確認・注意、赤＝不足・失敗・消す、灰＝参考・まだ）では、緑の「制度・データ」は済に、黄土の「世帯」は要確認に読める。
- 行動が要るお知らせ（保存先・事務所の共有・世帯の知らせなど、直すまで残るもの）と、知らせるだけのもの（配信元のお知らせ）が見分けられなかった（印は種類と「重大」「参考」だけで、行の右はどれも「›」）。
- 一覧の足元の「要望・不具合を送る」が、FP のメニューの「ファイナンシアへ」と同じ入口で重なっていた。
- 詳しい中身の「〜を開く」がふつうの段のボタンで、その画面でいちばん押すボタンなのに主になっていなかった。ベルのボタンの線だけ 2px で、隣の ↶↷・FP のメニュー（1.5px）と太さが違った。
- 0240 で残した2点（お知らせの種類の絞り込みで選んでいる方が墨の枠、開いていないときの「表示の設定」・グラフを小さい画面に出すボタン・FP のメニュー・↶↷ が墨や灰の枠）。

試しの版で形を確かめ、利用者の判断で採用した。試しの版の見本のデータには行動が要るお知らせが無かったので、今回は開発用のサーバーの見本の操作で全部の状態を出して確かめた（確かめたこと）。

## 決定

### 1. 色は状態の印だけに使い、種類は色の無い言葉にする

| 印 | 見た目 | 付くもの |
|---|---|---|
| 重大 | 赤の塗り・白い文字 | 急ぎ具合が重大（`critical`） |
| 要対応 | 黄土の薄い地・黄土の枠と文字 | 行動が要る知らせ（2） |
| 参考 | 白地・灰の枠と文字 | 急ぎ具合が参考（`info`。ベルの数に数えない） |
| あなたの要望に対応しました | 緑の塗り・白い文字 | 手元の受付番号と合った配信元のお知らせ |
| 種類（ファイナンシア・制度・データ・世帯・事務所） | 地も枠も無い灰色の文字 | すべて |

- 印の並びは、状態（重大 → 要対応 → 参考 → 要望に対応）を先に、種類を後ろに、日付をその後に置く。
- どの状態の印も言葉で書くので、色の差が分かりにくくても読める（色を抜いた見え方・赤と緑の差が分かりにくい見え方で確かめた）。
- 種類の絞り込みから色の四角を外し、選んでいる方を藍の塗りにした（プランの一覧の印の絞り込みと同じ「1つ選ぶ絞り込み」の形。0240 の4）。
- 未読の点（藍・参考は灰）と、未読があるときのベルの黄土は変えない。

### 2. 要対応と参考を見分ける

- **要対応**は、今の状態の知らせ（日付なし。世帯・事務所の知らせ、事務所の既定値の知らせ、Web のヒアリングの届いた知らせ）で、開く画面があり、参考でないものに付ける（`center.ts` の `needsAction`）。直すまで一覧に残るので、既読にしても印は付けたまま。
- 配信元のお知らせ（日付つき）は読むだけなので、開く画面があっても要対応にしない。急ぎ具合が重大なら「重大」だけが付く。
- **参考**は今までどおり急ぎ具合の参考（`info`）。今の状態の知らせの参考（参加の承認待ち・出典だけが新しくなった推定の値 など）にも、配信元の参考にも付く。
- 一覧の並びは変えない。今の決まり（0087 の1。重大を先に、次に今の状態の知らせ〔ふつうが参考より先〕、配信元のお知らせは新しい順）で、要対応はいつも重大の次にまとまって上に来る。
- 詳しい中身の「〜を開く」は主のボタン（`.btn.primary`。ふつうの大きさ）にする。

### 3. 「要望・不具合を送る」の入口は FP のメニューに一本化する

- 入口は FP のメニューの「ファイナンシアへ」（いつも出る）。一覧の足元の入口は、FP のメニューが出ていないときだけ出す。
- FP のメニューは世帯を開いている間だけ出る（上の帯の ↶↷ と同じ）。ふだんは起動するとすぐ新しい世帯か前の世帯を開くので、FP のメニューが出ていないのは、世帯を読み込んでいる間と、開けなかったとき。開けないときこそ不具合を送りたいので、その間だけ足元に残した（どの画面でも入口はちょうど1つ）。

### 4. ベルの線の太さを隣のボタンとそろえる

- ベルのボタンの線を 2px から 1.5px にし、↶↷・FP のメニューと同じにした。線を細くしたぶん左右の余白を 0.5px 足し（6px → 6.5px）、線と余白の合計（16px）は前と同じ。数の丸つきの幅も、未読なしの幅も変わらない（確かめたこと）。
- 未読なしのベルは、灰の枠から、隣と同じ藍の枠にした（5）。

### 5. 0240 で残した所をそろえる（色だけ。大きさは変えない）

| 部品 | 前 | 後 |
|---|---|---|
| お知らせの種類の絞り込みで選んでいる方（`.nc-cat-pick.on`） | 墨の枠・薄い灰の地 | 藍の塗り・塗った上の文字の色 |
| 開いていないときの「表示の設定」（`.set-btn`） | 墨の枠（2px）・墨の文字 | 藍の枠・藍の文字（「説明モード」と同じ。場所ごとの上書きの1行を消した） |
| グラフを小さい画面に出すボタン（`.pip-btn`） | 墨の枠（2px）・墨の文字。重ねると枠が濃く | 藍の枠・藍の文字。重ねると薄い藍 |
| FP のメニュー（`.fpm-btn`）・↶↷（`.undo-btn`）・未読なしのベル | 灰の枠（1.5px）・墨（ベルは灰）の文字。重ねると枠が墨 | 藍の枠・藍の文字。重ねると薄い藍 |
| 押せないときの ↶↷ | 灰の枠・薄い灰の文字（地は白） | 押せないボタンの決まり（0240 の3）と同じ灰の地・灰の枠・灰の文字 |

- 線の太さ・余白・文字の大きさは変えていないので、どれも高さ・幅は変わらない。
- `.explain-btn`・`.set-btn`・`.ys-btn`・`.stress-btn` を `.btn.small` に寄せるのは、しない（0240 の未確定に残す）。寄せると線が 2px → 1.5px、左右の余白が 12px → 10px、文字が 0.9rem → 0.86rem になり、幅が 5〜8px ほど狭くなる（計算。文字の長さによる）。「1年ずつ見せる」「相場が下がった場合を重ねる」は高さも 2.5px 変わる（0240 の測り）。

## 変えないもの

- お知らせの文・種類の名前・出る条件・既読の扱い・一覧の並び・ベルの数の数え方・帯の「重大なお知らせ」の印。
- 閉じ方（0239）。詳しい中身を開いているときの Esc は、今までどおりお知らせごと閉じてベルに戻る（0239 の4 の表の「お知らせ: Esc で閉じる」。詳しい中身から一覧に戻るのは「‹ 一覧に戻る」）。
- 「未読／すべて」の切り替え（0240 で藍にした形のまま）。

## 試しの版から変えた所

| 所 | 試しの版 | この記録 | 理由 |
|---|---|---|---|
| 種類の印 | 灰の地の印 | 地も枠も無い灰色の文字 | 灰の地の印は、白地に灰の枠の「参考」と並ぶと見分けにくかった（試しの版の写真） |
| 印の並び | 要対応 → 重大 | 重大 → 要対応 | 重大がいちばん急ぐので先に読む |
| 足元の「要望・不具合を送る」 | いつも外す | FP のメニューが出ていないときだけ出す | FP のメニューは世帯を開いている間だけ出るので、いつも外すと読み込み中・開けないときに入口が無くなる |
| ベルの余白 | 6px のまま（数の丸つきの幅が 1px 狭くなる） | 6.5px | 幅を前と同じにする |
| 種類の絞り込みの選んでいる方 | 薄い藍の地・藍の枠 | 藍の塗り | 1つ選ぶ絞り込みの決まり（0240 の4。プランの一覧の印の絞り込みと同じ） |
| 「表示の設定」・小さい画面に出すボタン・FP のメニュー・↶↷ | 変えない | 藍の枠 | 0240 の未確定の2点を一緒にそろえる |

試しの版の頭の行の直し（`.nc-top` の並び・「一覧に戻る」の位置）は、0239 で先に入っていたので入れていない。

## 確かめたこと

開発用のサーバーを見えないブラウザで動かし、変える前（main）と後で同じ手順を流して写真を撮り、上の帯のボタンを測った。

- **お知らせの出し方**: 0件＝復元キーを保管したことにし、配信元のお知らせなし。1件（要対応）＝空から作った世帯に衝突の写しがあることにする（開発用の見本の操作 `fork`）。多い（11件。一覧はスクロールする）＝世帯の本文に世帯の知らせ2つ（読み替えられなかったプランの変更・ペットの費用の入れ先）を入れて保存し直し、事務所の共有を始めて（復元キーをまだ保管していない）、見本の操作で復元キーで加わった人（重大）・参加の申請（参考）・衝突の写し・ほかの人が開いている を出し、配信元のお知らせに開発用の見本（`app/schemas/notices.dev-sample.json`）を読ませ、手元の受付番号に R-7K2Q を入れた。種類は4つ全部、状態は 重大・重大かつ要対応・要対応・参考（今の状態と配信元）・要望に対応・印なし（配信元のふつう）が出る。
- **見え方**: 0件・1件・多い（上と、スクロールした下の端）・未読と既読のまざった「すべて」・全部既読・種類の絞り込み（世帯・事務所・ファイナンシアから）・詳しい中身（要対応・重大かつ要対応・世帯・要望に対応・配信元の重大・参考）を、文字 中・大 × 幅 1440・1000・600、暗い画面（幅 1440 の中と幅 600 の大）で撮った。色を抜いた見え方・赤と緑の差が分かりにくい見え方でも「重大」「要対応」「参考」は言葉で読める。ページの横のはみ出しは 0。
- **キーボード**: ベルから Tab 10回で最初の行に移り、Enter で詳しい中身が開く。Esc でお知らせが閉じてベルに戻る（前と同じ）。
- **ベルの未読の数の印**: 1・9・4・0 で前と同じに出る（0のときは数の丸なし・落ち着いた色）。
- **上の帯のボタンの大きさ**（見えないブラウザで測った CSS の px。前 → 後）: 世帯の選択・タブ・↶↷（34×32）・FP のメニュー（34×32）・文字の大きさ（中 33.1×30.2・大 38.6×35.3、文字「大」では 39.3×35.9・45.9×41.9）・帯の高さ（56.8・61.1・幅 600 で 100.1・111）は、どの見え方でも同じ。ベル（数の丸つき）は 57.9×32 → 56.9×32（文字「大」65 → 64）、未読なしは 35.2×32 → 34.2×32、幅 600 では世帯の選択が 1px 広がる（176.4 → 177.4、文字「大」143.8 → 144.8）。これは見えないブラウザ（Chromium）が 1.5px の線を 1px に丸めて描くため（0240 の確かめたこと と同じ）で、ベルの中身の幅（全体 − 線 × 2 − 余白 × 2）は前後とも 41.9px。線を 1.5px のまま描く画面では、ベルの幅は前と同じになる。Chromium で描く画面（Windows のアプリ本体）では、↶↷・FP のメニューと同じく線が 1px に丸まり、ベルが 1px 狭くなる。
